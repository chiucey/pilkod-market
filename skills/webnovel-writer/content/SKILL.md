# Webnovel Writer - 长篇网文创作系统

## 核心能力

专业长篇网络小说创作系统，支持**200万字量级**连载创作，通过上下文管理和RAG技术解决AI写作中的"遗忘"和"幻觉"问题。

## 工作流程

### 1. 项目初始化 `/webnovel-init`

当用户创建新小说项目时执行：

1. **收集项目信息**
   - 书名（中文，2-20字）
   - 题材类型（玄幻/都市/仙侠/科幻/历史/游戏/同人/其他）
   - 主线简介（1-3句话概括核心故事线）
   - 预计篇幅（短篇<30万/中篇30-100万/长篇>100万）

2. **创建项目结构**
   ```
   [书名]/
   ├── metadata.json          # 项目元数据
   ├── outline/               # 大纲目录
   │   ├── world_settings.md  # 世界观设定
   │   ├── character_profile.md # 角色档案
   │   └── chapter_outline.md # 章节大纲
   ├── chapters/              # 正文目录
   │   ├── ch001.md
   │   └── ...
   ├── references/            # 参考资料
   │   └── style_guide.md    # 风格指南
   └── .env.example          # RAG配置模板
   ```

3. **初始化元数据**
   ```json
   {
     "title": "[书名]",
     "genre": "[题材]",
     "main_plot": "[主线简介]",
     "estimated_length": "[预计篇幅]",
     "created_at": "[当前时间]",
     "chapter_count": 0,
     "word_count": 0,
     "characters": [],
     "locations": [],
     "plot_threads": []
   }
   ```

### 2. 章节规划 `/webnovel-plan`

当用户要求规划章节或扩展大纲时执行：

**输入**: 章节范围或章节数量

**执行步骤**:

1. **读取项目上下文**
   - 读取 `metadata.json` 了解当前进度
   - 读取已有章节/大纲保持连贯性
   - 分析已建立的角色和世界观

2. **RAG检索相关素材**
   - 检索相似章节的风格和节奏
   - 获取角色相关设定和当前状态
   - 获取世界观关键设定

3. **生成章节规划**

   **规划格式**:
   ```
   ## 第N章 标题

   **章节目标**: [本章要完成的情节推进]

   **核心事件**:
   - [事件1]
   - [事件2]

   **角色出场**: [本章重点角色]

   **情绪节奏**: [铺垫/高潮/转折/收尾]

   **字数预估**: [3000-5000字]

   **追读力设计**:
   - Hook: [本章开头钩子]
   - Cool-point: [本章爽点]
   - Cliffhanger: [章末悬念]
   ```

4. **保存规划**
   - 追加到 `outline/chapter_outline.md`
   - 更新 `metadata.json` 中的章节数

### 3. 章节撰写 `/webnovel-write`

当用户要求撰写或续写章节时执行：

**输入**: 章节编号或"续写当前章节"

**执行步骤**:

1. **收集上下文**
   - 读取章节规划中的本章目标
   - 读取前3章保持文风一致
   - 加载角色当前状态
   - 检索相关世界观设定

2. **生成章节内容**

   **撰写规范**:
   - 每章3000-5000字
   - 第一段必须有Hook吸引读者
   - 最后一页必须有Cliffhanger
   - 每2000字安排一个爽点或小高潮
   - 章节内要有明确的起承转合

   **对话规范**:
   - 对话使用「」或「」引号
   - 动作描写用*星号*包裹
   - 心理描写用【】或*斜体*
   - 旁白用——分隔

3. **自动更新**
   - 保存到 `chapters/chXXX.md`
   - 提取/更新角色状态
   - 记录情节点到元数据
   - 更新章节字数统计

4. **输出摘要**
   ```
   ✅ 第N章「标题」撰写完成
   - 字数: XXXX字
   - 主要角色: [角色列表]
   - 情节推进: [简要说明]
   - 追读力评分: ★★★★☆
   ```

### 4. 章节审核 `/webnovel-review`

当用户要求审核章节质量时执行：

**输入**: 章节编号（可选范围如1-5）

**审核维度**:

| 维度 | 评分 | 检查点 |
|------|------|--------|
| 逻辑连贯 | ★★★★★ | 情节推进是否合理，伏笔是否回收 |
| 文笔质量 | ★★★★★ | 描写是否生动，对话是否自然 |
| 节奏控制 | ★★★★★ | 高潮是否有力，铺垫是否充分 |
| 角色塑造 | ★★★★★ | 性格是否一致，成长是否清晰 |
| 追读力 | ★★★★★ | Hook是否吸引，Cliffhanger是否有力 |

**执行步骤**:

1. **全文分析**
   - 通读章节内容
   - 标记问题段落
   - 统计字数和段落结构

2. **逐项评分**
   - 给出每项星级评分
   - 标注具体问题位置
   - 提供改进建议

3. **生成审核报告**
   ```
   ## 第N章审核报告

   **综合评分**: ★★★★☆ (4.2/5)

   **详细评分**:
   - 逻辑连贯: ★★★★☆
   - 文笔质量: ★★★★☆
   - 节奏控制: ★★★☆☆
   - 角色塑造: ★★★★☆
   - 追读力: ★★★★☆

   **优点**:
   - [优点1]
   - [优点2]

   **待改进**:
   - [问题1] → [建议修改方案]
   - [问题2] → [建议修改方案]

   **改稿优先级**:
   1. [最紧急问题]
   2. [次要问题]
   ```

### 5. 角色管理 `/character-manage`

当用户要求管理角色信息时执行：

**操作类型**:
- 添加角色: 收集姓名、身份、性格、外貌、背景
- 更新角色: 记录角色成长、状态变化
- 查询角色: 检索角色当前状态和历史

**角色模板**:
```markdown
## 角色卡片: [角色名]

**基本信息**:
- 身份: [角色身份]
- 年龄: [年龄]
- 外貌: [简要描写]

**性格特质**:
- 核心性格: [性格描述]
- 优点: [优点列表]
- 缺点: [缺点列表]

**背景故事**:
[角色背景]

**当前状态**:
- 位置: [当前位置]
- 情绪: [当前情绪]
- 目标: [当前目标]

**关系网**:
- [角色A]: [关系描述]
- [角色B]: [关系描述]
```

### 6. 世界观管理 `/world-manage`

当用户要求管理世界观设定时执行：

**管理内容**:
- 地理设定: 国家、城市、势力分布
- 力量体系: 修炼等级、技能设定
- 社会结构: 门派、组织、制度
- 历史背景: 重大事件、时间线

## 追读力系统

### Hook类型（开篇钩子）
1. **悬念钩子**: 留下未解之谜
2. **冲突钩子**: 展示核心矛盾
3. **反差钩子**: 出人意料的情境
4. **情感钩子**: 强烈的情感冲击
5. **信息钩子**: 揭示重要信息

### Cool-point模式（爽点）
1. 打脸爽文（实力碾压）
2. 扮猪吃虎（身份反转）
3. 绝地翻盘（逆风翻盘）
4. 收获积累（获得宝物/能力）
5. 复仇清算（恩怨分明）
6. 守护反击（为保护他人而战）
7. 突破晋升（境界提升）
8. 情感突破（感情进展）

### 微兑现与债务追踪
- **微兑现**: 定期给读者"小甜头"保持阅读兴趣
- **债务管理**: 埋下的伏笔要及时回收，避免遗忘

## 题材模板

详见 `references/genre-profiles.md`

支持题材:
- 玄幻: 升级流、宗门、系统
- 都市: 职场、赘婿、神医
- 仙侠: 修真、古风、蜀山
- 科幻: 星际、机甲、末世
- 历史: 穿越、争霸、架空
- 游戏: 虚拟现实、电竞、游戏异界
- 同人: 动漫/影视/游戏同人
- 其他: 自定义题材

## 上下文维护策略

### 防止"遗忘"
- 每次操作前读取 `metadata.json` 重建上下文
- 重要设定自动提取到参考文件
- 章节间自动生成承接摘要

### 防止"幻觉"
- 所有角色/事件必须有据可查
- 世界观设定优先从 `world_settings.md` 获取
- 存疑时主动查询而非编造

### RAG检索策略
- 检索范围: 章节、设定、角色、历史
- 检索权重: 最近章节 > 核心设定 > 历史章节
- 检索数量: 每次最多返回10个相关片段

## 项目状态追踪

自动维护以下数据:
- 总字数 / 章节数
- 角色状态快照
- 伏笔与回收记录
- 追读力评分趋势

## 输出格式规范

所有文件使用 Markdown 格式，UTF-8 编码。
章节文件命名: `chXXX.md` (XXX为三位章节号，如ch001, ch002)
