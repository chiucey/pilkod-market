## 3. 评估维度

### 3.1 项目复杂度评估

| 复杂度因素 | 低（1分） | 中（2分） | 高（3分） |
|------------|----------|----------|----------|
| 技术难度 | 成熟技术，标准化方案 | 需要一定定制开发 | 全新技术或复杂集成 |
| 需求明确度 | 需求清晰文档完整 | 部分需求待确认 | 需求模糊范围未定 |
| 客户成熟度 | 客户有经验，配合好 | 客户有一定经验 | 客户缺乏经验需引导 |
| 时间要求 | 时间充裕 >2个月 | 时间一般 1-2个月 | 时间紧迫 <1个月 |
| 团队熟悉度 | 完全熟悉同类项目 | 部分熟悉类似项目 | 全新的业务领域 |

### 3.2 工作量构成分解（全生命周期）

| 工作阶段 | 主要任务 | 权重建议 |
|----------|----------|----------|
| 需求与分析 | 需求调研、业务分析、需求文档编写、原型设计 | 10-15% |
| 架构设计 | 技术方案设计、架构设计、接口设计、数据库设计 | 10-15% |
| 开发/编码 | 前端开发、后端开发、算法实现、接口开发 | 35-45% |
| 测试验证 | 单元测试、集成测试、系统测试、验收测试 | 15-20% |
| 部署上线 | 环境部署、数据迁移、系统配置、上线切换 | 5-10% |
| 运维支持 | 试运行支持、问题修复、性能优化、知识移交 | 5-10% |

### 3.3 调整系数

| 调整因素 | 系数说明 |
|----------|----------|
| 团队能力 | 精英团队 0.9x，普通团队 1.0x，新手团队 1.15x |
| 技术成熟度 | 成熟技术栈 0.9x，一般技术 1.0x，新兴技术 1.15x |
| 需求稳定性 | 需求明确稳定 0.9x，部分变更 1.0x，需求频繁变化 1.2x |
| 质量要求 | 标准质量 0.9x，高质量要求 1.1x，顶级质量要求 1.2x |
| 集成复杂度 | 少量第三方集成 0.95x，中等集成 1.0x，大量集成 1.15x |

### 3.4 经验修正系数（避免低估）

> ⚠️ **重要**：实际项目经验表明，功能点评估往往低估实际工作量。本系数用于修正这一偏差。

| 评估方法 | 经验修正系数 | 说明 |
|----------|--------------|------|
| 功能点法（FP） | 1.25-1.35 | 功能点法估算通常低估20-35% |
| 类比法 | 1.15-1.25 | 类比历史项目时容易忽略差异 |
| 三级模块法 | 1.20-1.30 | 模块分解时容易遗漏边界工作 |
| 专家判断法 | 1.10-1.20 | 专家估算受自信偏差影响 |

**推荐默认值**：1.25（保守估计），1.30（激进项目）

## 4. 评估公式

### 4.1 基础工作量计算

```
基础工作量(人天) = Σ(各阶段工作量 × 调整系数) × 经验修正系数
```

### 4.2 标准人天参考

| 项目类型 | 典型规模 | 标准人天范围 |
|----------|----------|--------------|
| 小型项目 | 合同额 <50万 | 20-50 人天 |
| 中型项目 | 合同额 50-200万 | 50-150 人天 |
| 大型项目 | 合同额 200-500万 | 150-300 人天 |
| 超大型项目 | 合同额 >500万 | 300-600+ 人天 |

> 📌 **注**：以上为含经验修正后的实际工作量参考值

### 4.3 最终评估

```
评估工作量 = 基础工作量 × 复用系数 × 复杂度系数 × 调整系数 × 安全系数
```

**复杂度综合系数** = 各因素得分平均值 / 1.5（标准化后）

> ⚠️ **重要提示**：以上公式中已隐含 1.25 倍的经验修正系数，无需重复乘算。

## 7. 评估流程

### 7.1 标准流程

1. **🔍 信息收集与检查**
   - 收集项目基本信息
   - 检查信息完整度
   - 若完整度 < 80%，要求补充缺失信息
   - 获得用户确认后进入下一步

2. **📊 复杂度评分**
   - 对5项复杂度因素进行1-3分评分
   - 计算综合得分

3. **📐 工作量估算**
   - 按合同额确定基准人天
   - 按工作阶段分解预估工作量
   - 应用调整系数修正

4. **📋 生成报告**
   - 输出完整评估报告
   - 提供资源建议和风险提示

## 8. 使用指南

### 8.1 评估流程

1. **🔍 收集信息**：了解项目背景、客户情况、竞争状态
2. **✅ 检查完整度**：确认信息完整度 > 80%
3. **📊 评分**：对各复杂度因素进行1-3分评分
4. **📐 分解任务**：按工作阶段分解预估工作量
5. **🔧 应用系数**：计算调整系数并修正
6. **📋 生成报告**：输出完整评估报告

### 8.2 注意事项

- 所有评分应基于实际收集的项目信息
- 对于边界值，参考历史项目数据调整
- 首次评估后应根据实际执行情况修正模型
- 跨行业项目需特别关注客户熟悉度和技术适配性

### 9.3 三级功能模块结构

| 层级 | 定义 | 示例 |
|------|------|------|
| **一级模块** | 业务域/大功能模块 | 订单管理、用户管理、数据分析 |
| **二级模块** | 功能子系统 | 订单管理 > 订单创建、订单查询、订单变更 |
| **三级模块** | 具体功能点 | 订单创建 > 基础信息录入、商品选择、价格计算 |

### 9.4 模块分解规则

1. **命名规范**：采用 `一级模块 / 二级模块 / 三级模块` 格式
2. **粒度控制**：三级模块应可独立估算工作量（建议 0.5-3 人天）
3. **归属判断**：无法归类的模块标记为"新需求"并高亮显示
4. **复用标注**：可复用的模块需标注来源产品/组件
