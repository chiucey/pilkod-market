# ⚔️ Omni Commander — 史诗级全能助手

> _五域合一，万物皆可 Command_

---

## 🎯 核心理念

Omni Commander 是一个**意图驱动**的超级技能。用户不需要记住命令——只需要说出想做什么，AI 自动识别意图、匹配工作流、执行交付。

**设计哲学：**
- 🧠 **意图优先**：用户说人话，AI 干人事
- 🔗 **链式执行**：复杂任务自动拆解为多步骤流水线
- 📦 **开箱即用**：零配置，Node.js 运行时即插即用
- 🎨 **品质至上**：输出追求专业级，不是"能跑就行"

## 🚀 意图路由引擎

当用户发出请求时，按以下流程处理：

```
用户输入
  ↓
[1] 意图识别 → 匹配五域之一（CODE/OFFICE/LEARN/SYS/CREATE）
  ↓
[2] 复杂度评估 → 简单(单步) / 中等(2-3步) / 复杂(4+步流水线)
  ↓
[3] 加载对应域的参考文档（references/目录）
  ↓
[4] 执行 → 需要脚本时调用 scripts/omni.mjs
  ↓
[5] 品质校验 → 输出是否专业级？不是则迭代
  ↓
[6] 交付结果
```

### 意图识别规则

**优先检测关键词匹配：**

| 关键词模式 | 路由域 |
|-----------|--------|
| 写/开发/实现/编程/代码/函数/类/接口/API/bug/调试/重构/部署/数据库/SQL/Git/Docker/测试/C++/Python/Java/C#/Unity/React/Vue/Node | `CODE` |
| 文档/报告/方案/PPT/Excel/表格/PDF/邮件/日程/会议/纪要/合并/批量/格式转换/排版 | `OFFICE` |
| 搜索/查/学习/研究/翻译/总结/笔记/知识/论文/教程/课程/考试/复习/阅读/理解 | `LEARN` |
| 文件/目录/脚本/端口/进程/环境/安装/配置/服务器/运维/监控/日志/权限/备份/压缩 | `SYS` |
| 写作/文案/设计/画图/流程图/架构图/头脑风暴/创意/命名/起名/润色/改稿/营销/品牌 | `CREATE` |

**模糊意图处理：** 当关键词匹配多个域时，选择与用户上下文最相关的域。若无法判断，优先 `CODE`。

## 💻 CODE — 代码开发域

> 详见 [references/code-dev.md](./references/code-dev.md)

### 核心工作流

#### C1. 项目脚手架
```
输入：项目类型 + 技术栈偏好
→ 生成项目结构（目录 + 配置文件 + 入口文件 + README）
→ 初始化 Git 仓库
→ 输出项目树
```

#### C2. 功能开发
```
输入：功能描述
→ 分析需求，拆解为模块/函数
→ 编写代码（遵循最佳实践）
→ 同步写测试用例
→ 代码审查（安全性 + 性能 + 可读性）
→ 交付
```

#### C3. Bug 调试
```
输入：错误描述/日志/截图
→ 定位问题（日志分析 → 代码追踪 → 根因）
→ 提出修复方案（至少2个选项）
→ 实施修复
→ 验证（重新运行 + 边界测试）
→ 交付
```

#### C4. 代码重构
```
输入：目标代码 + 重构目标
→ 分析现状（坏味道检测）
→ 制定重构计划
→ 小步重构（每步可编译/可测试）
→ 回归验证
→ 交付
```

#### C5. API & 数据库
```
输入：API需求 / 数据模型
→ 设计接口（RESTful/GraphQL）或 Schema
→ 编写实现代码
→ 编写文档（OpenAPI/ER图）
→ 交付
```

### 代码品质标准

- **语言一致性**：严格匹配用户项目语言，不混用
- **错误处理**：所有 I/O 操作必须有 try-catch/错误回调
- **类型安全**：TypeScript 项目必须有完整类型定义
- **注释规范**：公共 API 必须有 JSDoc/docstring
- **命名风格**：遵循语言惯例（camelCase/snake_case/PascalCase）
- **安全红线**：不硬编码密钥、不信任用户输入、参数化查询

## 📋 OFFICE — 日常办公域

> 详见 [references/office.md](./references/office.md)

### 核心工作流

#### O1. 文档生成
```
输入：文档类型 + 内容需求
→ 选择模板（报告/方案/纪要/通知/简历）
→ 结构化填充内容
→ 格式化输出（Markdown / .docx / .pdf）
→ 交付
```

#### O2. 数据处理
```
输入：Excel/CSV 数据 + 处理需求
→ 数据清洗（去重/填充/格式化）
→ 计算分析（汇总/透视/统计）
→ 可视化建议
→ 输出处理后的文件
```

#### O3. 格式转换
```
输入：源文件 + 目标格式
→ 调用 scripts/omni.mjs convert 命令
→ 质量校验
→ 输出
```

#### O4. 邮件 & 日程
```
输入：邮件草稿/日程安排需求
→ 生成专业邮件内容
→ 或构建日程表
→ 交付
```

#### O5. 批量操作
```
输入：批量任务描述
→ 生成处理脚本
→ 执行或提供脚本供用户运行
→ 输出结果
```

### 办公品质标准

- **格式专业**：文档结构清晰，排版规范
- **数据准确**：计算结果必须可验证
- **效率优先**：批量操作优于手动逐个处理

## ⚙️ SYS — 系统管理域

> 详见 [references/system.md](./references/system.md)

### 核心工作流

#### S1. 文件操作
```
输入：文件操作需求
→ 安全检查（是否涉及系统目录/个人文件）
→ 生成操作脚本
→ 预览影响范围
→ 确认后执行
→ 交付结果
```

#### S2. 环境配置
```
输入：开发环境/工具链需求
→ 检测当前环境
→ 生成安装/配置脚本
→ 验证配置
→ 交付
```

#### S3. 部署 & 运维
```
输入：部署需求
→ 环境检查
→ 生成部署脚本（Docker/systemd/pm2等）
→ 执行部署
→ 健康检查
→ 交付
```

#### S4. 自动化脚本
```
输入：重复性任务描述
→ 分析自动化机会
→ 生成脚本（PowerShell/Bash/Node.js）
→ 添加错误处理和日志
→ 交付
```

### 系统安全红线

- ⛔ **绝不**在无确认下执行 `rm -rf`、`del /S /Q`、格式化等破坏性操作
- ⛔ **绝不**修改系统核心目录（`C:\Windows`、`/etc`、`/System`）
- ⛔ **绝不**暴露密钥/Token 到日志或输出
- ✅ 所有破坏性操作必须先预览 → 确认 → 执行
- ✅ 优先使用幂等操作

## 🔧 脚本引擎

### Node.js 执行器：`scripts/omni.mjs`

所有需要编程执行的操作通过 `omni.mjs` 完成：

```bash
node scripts/omni.mjs <command> [options]
```

### 可用命令

| 命令 | 说明 | 示例 |
|------|------|------|
| `scaffold` | 项目脚手架生成 | `node omni.mjs scaffold --type react --name myapp` |
| `convert` | 文件格式转换 | `node omni.mjs convert --input data.csv --output data.json` |
| `batch` | 批量文件操作 | `node omni.mjs batch --dir ./images --action rename --pattern "{date}_{n}"` |
| `analyze` | 代码/数据分析 | `node omni.mjs analyze --input ./src --type code` |
| `template` | 文档模板生成 | `node omni.mjs template --type report --title "Q1总结"` |
| `search` | 本地文件搜索 | `node omni.mjs search --dir ./docs --keyword "部署" --type md` |
| `env` | 环境信息检测 | `node omni.mjs env` |
| `health` | 项目健康检查 | `node omni.mjs health --dir ./myproject` |

### 调用约定

1. 脚本执行前，**必须**先检测 Node.js 可用性：`node --version`
2. 脚本路径使用绝对路径：`node "C:\Users\莫翔羽\.workbuddy\skills\omni-commander\scripts\omni.mjs" <command>`
3. 输出统一为 JSON 格式，便于解析
4. 错误输出到 stderr，退出码非零表示失败

## 🛡️ 全局安全策略

无论哪个域，以下规则始终生效：

1. **预览优先**：破坏性操作先展示影响范围，经确认后执行
2. **最小权限**：脚本只请求完成操作所需的最小权限
3. **可回滚**：操作前创建备份或提供回滚方法
4. **隐私保护**：不将敏感信息（密钥/密码/Token）写入日志或输出
5. **沙盒执行**：不信任的脚本在受限环境中运行

## 📊 品质保证流程

每个任务完成后，自动进行品质校验：

```
✅ 功能完整性：是否满足用户所有需求？
✅ 正确性：输出是否正确、可验证？
✅ 专业性：是否达到专业级水准（非"能跑就行"）？
✅ 安全性：是否存在安全隐患？
✅ 可读性：代码/文档是否清晰易懂？
✅ 可维护性：是否方便后续修改和扩展？
```

未通过校验的，自动迭代优化直到达标。
