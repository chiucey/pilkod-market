# /reduce — 洞见提取模块

## 功能说明
将 inbox 中的原始材料转化为结构化的原子笔记。

## 使用方式
```
/reduce
```
或
```
/reduce [文件名]
```

## 执行步骤

### Step 1: 检查 inbox
列出 `vault/notes/inbox/` 下所有 `.md` 文件。

**若 inbox 为空：**
```
⚗️ /reduce 完成
━━━━━━━━━━━━
inbox 为空，没有需要处理的内容
提示：使用 /capture 添加原始材料
```

### Step 2: 分析源文件
对每个 inbox 文件：
- 通读全文
- 识别核心观点、关键概念、重要术语
- 判断可拆分为几条原子笔记

### Step 3: 生成原子笔记

**文件命名规范：**
```
{YYYY-MM-DD}-{kebab-case-title}.md
```

**保存位置：**
- 通用洞见 → `vault/notes/atomic/`
- 领域特定 → `vault/notes/domains/`

**笔记 Schema（必须包含）：**
```yaml
---
title: "原子笔记标题"
created: "YYYY-MM-DD"
tags: [标签1, 标签2]
status: draft
description: "一句话精准描述核心观点"
---

# 标题

正文内容...

## 相关笔记
- [[关联笔记]] — 关联原因
```

### Step 4: 建立链接
使用 Grep 工具搜索相关笔记：
```
rg "关键词" vault/notes/atomic/ --glob "*.md"
```

在笔记末尾添加"相关笔记"区块：
- 至少关联 1 条已有笔记
- 若无关联，标注：`（暂无关联，待 /review 发现）`

### Step 5: 归档源文件
将已处理的 inbox 文件移动到 `vault/notes/archive/`

### Step 6: 输出报告
```
⚗️ /reduce 完成
━━━━━━━━━━━━
处理文件：{N} 个
生成笔记：{M} 条
建立连接：{K} 条

新笔记列表：
- [[笔记标题1]]
- [[笔记标题2]]

提示：运行 /graph 查看图谱状态
```

## 原子性原则

| ✅ 正确 | ❌ 错误 |
|--------|--------|
| 一条笔记 = 一个核心观点 | 一条笔记 = 多个不相关主题 |
| 标题简洁精准 | 标题过于宽泛 |
| description 完整概括 | description 缺失或不准确 |

## 拆分标准

### 保留单条笔记
- 核心观点可在一段话内说清
- 与其他笔记的关联清晰
- 可以独立被引用

### 需要拆分
- 一个文件包含多个独立主题
- "另外..."、"此外"、"还有"等转折
- 长度超过 500 字
