# /review — 知识回顾模块

## 功能说明
检查图谱健康度，发现孤立节点，更新过期内容，维护知识网络。

## 使用方式
```
/review
```

## 执行步骤

### Step 1: 图谱扫描
运行 /graph 获取当前状态，识别：
- 孤立节点列表
- 过时笔记（created > 90 天，status = draft）
- 矛盾笔记（同一主题有多个 needs-review）

### Step 2: 孤立节点处理

对每个孤立节点：
1. 读取笔记内容
2. 搜索相关关键词：
   ```
   rg "关键词" vault/notes/ --glob "*.md"
   ```
3. 建立至少 1 条链接
4. 若确实无关联，更新为 `status: needs-review`

### Step 3: 过时笔记更新

检查 draft 笔记：
- 阅读内容
- 判断是否仍有价值
- 更新为 `status: evergreen` 或 `status: archive`

### Step 4: MOC 更新

检查 MOC 文件：
- 新增笔记是否已引用
- 已有引用是否仍有效
- 补充缺失的领域覆盖

### Step 5: 输出报告

```
🔍 /review 完成
━━━━━━━━━━━━━━━━━━━━━━
📊 图谱扫描：
  • 总笔记：{N} 条
  • 孤立节点：{E} 个（已处理 {X} 个）
  • 过时笔记：{O} 个

🔗 连接更新：
  • 新增链接：{L} 条
  • 更新笔记：{U} 条

📋 状态变更：
  • draft → evergreen：{A} 条
  • draft → archive：{B} 条
  • → needs-review：{C} 条

🏥 最终健康度：{分数}/10 [{状态}]

💡 下一步建议：
  • {建议1}
  • {建议2}
━━━━━━━━━━━━━━━━━━━━━━
```

## 维护频率

| 笔记数量 | 建议频率 |
|----------|----------|
| < 50 条 | 每 2 周 |
| 50-200 条 | 每周 |
| > 200 条 | 每 3-4 天 |

## 质量标准

### 优秀笔记
- ✅ 有精准的 description
- ✅ 有至少 1 条 wiki 链接
- ✅ tags 准确分类
- ✅ status 正确标记

### 需改进笔记
- ⚠️ description 模糊或不准确
- ⚠️ 无任何链接
- ⚠️ tags 缺失或错误
- ⚠️ status 与内容不符

### 归档标准
- 内容已过时且无参考价值
- 被新笔记完全覆盖
- 重复内容（合并后保留一条）
