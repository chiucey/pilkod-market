# Ars-Contexta 知识图谱系统

Ars-Contexta 是一个结构化的知识管理系统，采用 Zettelkasten 方法论，帮助你在会话中积累、组织和检索知识。

## 核心原则

### 1. 原子性原则
- **一条笔记 = 一个核心观点**
- 避免信息冗余，每个文件专注单一主题
- 允许笔记之间通过链接形成复杂知识网络

### 2. 渐进披露原则
- `description` 字段是读者决定是否深入的唯一入口
- 描述必须精准，用一句话概括核心观点
- 正文内容支持深度展开

### 3. 链接优先原则
- 使用 `[[笔记标题]]` wiki 链接连接相关笔记
- 让图谱结构自己"说话"
- 链接优于内联解释

### 4. 三空间架构

| 空间 | 位置 | 用途 | 变化频率 |
|------|------|------|----------|
| **自我空间** | `vault/self/` | 身份、目标、方法论 | 慢变 |
| **知识空间** | `vault/notes/` | 原子笔记、MOC、领域 | 稳定增长 |
| **操作空间** | `vault/ops/` | 任务队列、会话记录 | 波动 |

## 核心命令

### /init — 初始化知识系统
```
执行 /init 启动对话式引导，配置你的工作域和偏好
```

### /capture [内容] — 快速捕获
```
将想法写入 inbox，不追求完美格式
/capture 需要添加关于AI伦理的思考到我的 inbox
```

### /reduce — 洞见提取
```
处理 inbox 中的原始材料，生成原子笔记
```

### /graph — 图谱概览
```
查看笔记数量、连接关系、孤立节点、MOC 覆盖
```

### /remember — 会话持久化
```
从当前会话中提取可复用的操作原则，写入 methodology.md
```

### /review — 知识回顾
```
检查图谱健康度，发现孤立节点，更新过期内容
```

## 工作流程

```
捕获 → inbox/
   ↓
/reduce → vault/notes/atomic/
   ↓
/graph → 建立 wiki 链接
   ↓
/review → 更新 MOC、发现孤立节点
   ↓
健康图谱
```

## 方法论 Claims

### 认知科学基础
1. **生成效应**: 主动提取比被动阅读记忆更深刻
2. **间隔重复**: 分散学习优于集中学习
3. **情境记忆**: 与已有知识关联的新信息更易记住

### 网络结构理论
1. **小世界网络**: 适度链接实现高效信息传播
2. **弱联系优势**: 弱连接往往带来新洞见
3. **介数中心性**: 高介数节点是知识传播的关键枢纽

### 知识管理方法论
1. **原子笔记**: 最小知识单元，支持灵活组合
2. **常青笔记**: 持续迭代而非一次性文档
3. **渐进式披露**: description 是注意力门户

## 最佳实践

1. **零摩擦捕获**: 想法先进 inbox，不追求完美格式
2. **及时 reduce**: inbox 积累不超过 10 条时处理
3. **主动链接**: 每条笔记至少尝试关联 1 条已有笔记
4. **定期 review**: 每周运行 /review 检查图谱健康度
5. **关注孤立节点**: 无链接的笔记需要补充上下文

## 健康评分标准

| 评分 | 状态 | 说明 |
|------|------|------|
| 9-10 | 🟢 优秀 | 图谱结构健康，持续增长 |
| 7-8 | 🟡 良好 | 有改进空间，关注孤立节点 |
| 5-6 | 🟠 一般 | 需要主动维护，运行 /review |
| <5 | 🔴 需修复 | 图谱退化风险，运行 /pipeline |

## 注意事项

- **首次使用**: 运行 /init 完成初始化配置
- **Git 版本控制**: 建议对 vault 目录初始化 git
- **会话持久化**: 重要洞见使用 /remember 写入 methodology
- **定期归档**: inbox 和 archive 定期清理
