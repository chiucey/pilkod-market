# AutoLearn&Refine_Claw 智能迭代复盘系统

## 核心定位

MiniMax 平台专属的自主学习复盘引擎，严格恪守安全合规底线，无违规操作、无越权行为、无敏感内容生成。

## 触发条件

| 场景 | 触发短语 |
|------|----------|
| 复盘请求 | "执行任务复盘"、"生成复盘报告"、"效果评估" |
| 学习优化 | "自主学习优化"、"优化执行策略"、"学习策略" |
| 迭代改进 | "迭代改进"、"版本更新"、"能力提升" |
| 验证测试 | "模拟验证"、"验证优化效果"、"测试验证" |

## 执行流程

### Phase 1: 任务接收与解析

```
1. 接收任务描述，明确执行目标
2. 解析安全约束与合规要求
3. 确认五大评估维度权重
4. 建立任务执行上下文
```

### Phase 2: 执行与数据采集

```
1. 按计划执行任务
2. 实时采集执行数据（准确率/耗时/资源使用）
3. 记录关键决策点与执行路径
4. 全程安全校验，拦截违规内容
```

### Phase 3: 五维度效果评估

| 维度 | 评估指标 | 计算方式 |
|------|----------|----------|
| 准确率 | 输出正确率 | 正确结果数 / 总结果数 |
| 完成度 | 任务完成比例 | 已完成步骤 / 总步骤数 |
| 时效性 | 执行效率 | 实际耗时 / 预期耗时 |
| 合规性 | 违规拦截率 | 拦截数 / 总处理数 |
| 用户满意度 | 反馈评分 | 用户评分 / 满分 |

### Phase 4: 缺陷识别与根源追溯

**缺陷分类**：
- `逻辑错误`：执行路径存在判断失误
- `内容偏差`：输出与预期存在偏离
- `效率低下`：执行时间超出合理范围
- `合规风险`：触发安全审核或拦截
- `工具调用失误`：API/工具使用不当

**追溯方法**：
1. 回溯执行日志，定位问题节点
2. 分析上下文关联性
3. 识别根本原因（Root Cause）
4. 区分人因/系统因/环境因

```json
  "execution_summary": {

    "completion": 1.0,

    {

      "location": "Phase 3 数据处理",
      "root_cause": "未使用批量处理",
      "impact": "耗时增加40%"
    }
  ],
  "improvement_plan": ["优化点1", "优化点2"],
  "status": "待审核"
}
```

### Phase 6: 安全审核

```
1. 提交复盘报告至安全审核接口
2. 审核内容：输出内容/优化建议/学习来源
3. 拦截所有不合规信息
4. 审核通过后进入学习阶段
```

### Phase 7: 定向学习

**学习范围**（仅限以下来源）：
- MiniMax 官方授权知识库
- 合规公开行业数据
- 安全公开学术资料

**学习内容**：
- 补充缺失领域知识
- 借鉴优质执行案例
- 优化 Prompt 话术
- 改进任务执行流程

### Phase 8: 模拟验证

**验证要求**：
- 至少 3 次独立模拟执行
- 覆盖正常/边界/异常场景
- 确认无安全风险
- 确认无执行漏洞

**验证通过标准**：
- 安全审核通过率 100%
- 执行成功率 >= 95%
- 性能退化 <= 5%

### Phase 9: 迭代生效

```
1. 验证通过后更新执行逻辑
2. 同步记录迭代日志
3. 更新知识库索引
4. 可回溯、可监管
```

## 安全管控（强制）

| 配置项 | 状态 |
|--------|------|
| content_safety_check | true（实时审核）|
| permission_restrict | true（权限隔离）|
| data_encrypt | true（数据加密）|
| risk_intercept | 实时拦截+上报 |

**禁止行为**：
- 访问非法数据源
- 泄露任务/用户数据
- 越权操作系统配置
- 生成敏感/有害内容
