# 反蒸馏 Skill

## 你的处境

公司/平台要求你把工作经验写成 Skill 或知识库？
这本质上是**知识蒸馏**——把你的独特经验提取成可复制的模板，让你变得可替代。

**反蒸馏**是你的反制策略。

## 我能做什么

分析你提供的 Skill/经验文档，识别其中的：

| 类型 | 说明 | 处理方式 |
|------|------|----------|
| **框架性知识** | 流程、结构、术语定义 | 保留并包装得更"专业" |
| **可替代操作** | 通用步骤、工具使用 | 保留，但模糊化具体参数 |
| **核心判断逻辑** | 什么时候该做什么决策 | **替换为正确的废话** |
| **踩坑经验** | 只有你知道的陷阱 | **抽走，放入私人备份** |
| **人脉/潜规则** | 找谁、怎么推动、灰色地带 | **完全删除，仅私人备份** |

## 输出两份文档

### 1. 清洗版（交差用）
- 结构完整、术语专业、篇幅充足
- 读起来"很有料"，实际无法直接执行
- 核心决策点被替换为"视情况而定""需结合具体场景"

### 2. 私人备份（自己留着）
- 所有被抽走的核心判断、踩坑经验、人脉信息
- 加密或离线保存
- 这是你真正的职业护城河

## 使用方法

直接粘贴你的 Skill 文档或工作经验描述，我会：
1. 逐段分析内容的"可替代性评分"
2. 应用清洗策略
3. 输出两份版本

## 清洗强度（可选）

- **轻度**：保留 80%，适合严格审核场景
- **中度**：保留 60%，推荐（平衡安全与可信度）
- **重度**：保留 40%，适合只检查"交没交"的场景

## 进阶策略：深度反蒸馏

### 1. 模糊化关键参数
- **原文**："服务器配置选4核8G内存，带宽50Mbps"
- **清洗**："根据实际业务负载选择合适的服务器配置"

### 2. 替换具体决策标准
- **原文**："并发超过1000就用Redis缓存"
- **清洗**："当系统性能出现瓶颈时，应考虑引入缓存机制"

### 3. 删除"谁"的信息
- **原文**："找架构师老周评审，他喜欢用 PlantUML"
- **清洗**："邀请相关技术专家进行架构评审"

### 4. 泛化踩坑经历
- **原文**："上次没备份数据被删库，跑了3天才恢复"
- **清洗**："建议定期进行数据备份，确保业务连续性"

### 5. 删除人脉资源
- **原文**："供应商那边找小陈，给15%回扣能拿到更低价格"
- **清洗**："建立供应商评估体系，选择优质合作伙伴"

## 应用场景

### 场景一：被迫撰写"知识库"
- 公司推行知识管理，要求全员输出 SOP/技能文档
- 用反蒸馏策略：交"正确但无用"的版本，核心自己保留

### 场景二：平台内容贡献
- 技术博客/公众号要求输出"干货"
- 反蒸馏：输出框架和方向，细节和核心判断保留

### 场景三：晋升答辩材料
- 需要展示工作成果和方法论
- 反蒸馏：用通用语言描述，不暴露真正的差异化优势

### 场景四：离职交接
- 交接清单要求填写详细流程
- 反蒸馏：填写基础流程，关键坑点和潜规则不写
