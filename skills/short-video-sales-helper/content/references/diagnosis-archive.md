# 诊断知识库（Diagnosis Archive）

> 每次诊断一个失败视频 → 归档 → 提炼模式 → 叠层升级
> 这是 **Round 3（视频诊断）能力** 的复利资产。

---

## 一、用途说明

- **feedback-log.md**：记视频上线后的**定量数据**（播放量/完播率/点赞/转化）
- **diagnosis-archive.md**（本文件）：记**定性诊断**（哪个分镜错了 + 错位设计缺什么 + 重做版应该长什么样）

两者**双轨并行**：
- 看到低播放量 → 用 Round 3 诊断**为什么会低**（定性）
- 看到高播放量 → 用 Round 1+2 反推**为什么能爆**（同样归档）

## 四、模式问题追踪（"叠层升级"核心 · v4 升级为**提议式**）

> **v4 升级**：原"命中 3 次自动升级 Self-check"改为"**提议式**"——
> 命中 3 次 → 输出"建议新增 Self-check 项：XXX" → **等用户确认** → 再改 SKILL.md。
> 原因：自动改 SKILL.md 风险高（权限/结构/不可追溯），提议式更安全。

每次诊断如果发现新模式，登记在这里。当一个模式被识别 **3 次以上**，**自动提议**新增 Self-check 项，等用户确认后再写进 SKILL.md。

```
### 模式 #001:「0 错位产品广告模板」
- 出现案例:#001 Fino
- 识别信号:视频开头 0-0.3s 是「演员/模特 + 产品居中 + 端正坐姿 + 0 错位」
- 怎么避免:第一步必须设计"服饰/场景/动作/反常识"至少 1 项错位
- 状态:已升级 → 已写进 SKILL.md Self-check 第 9 项 + Round 1 钩子模板「错位维度」字段
- 命中次数:1

### 模式 #002:「标配前后对比」
- 出现案例:#001 Fino（"左毛躁 vs 右柔顺"）
- 识别信号:对比图分屏 / before-after / 化妆品类目标配
- 怎么避免:对比必须配"反常识陈述"（如"用错 vs 没用"）或"错位视角"（如显微镜下）
- 状态:待观察
- 命中次数:1

### 模式 #003:「错位方向反了」
- 出现案例:#001 Fino（"嘘"手势建立"秘密"预期但前面没铺垫）
- 识别信号:无前置铺垫就直接给"反转/揭晓/秘密/惊喜"
- 怎么避免:必须先铺设预期 A，再打碎到 B；不能跳过 A 直接给 B
- 状态:待观察
- 命中次数:1

### 模式 #004:「抽象内容超过 3 秒」
- 出现案例:#001 Fino（分子结构图+放大镜+红叉）
- 识别信号:科普图 / 成分表 / 数据图表 / 抽象视觉元素
- 怎么避免:3 秒内禁止需要思考的内容，抽象元素必须配旁白 + 大字幕数字
- 状态:待观察
- 命中次数:1

### 模式 #E001:「默认幽默剧情带货」【外部反馈】
- 来源:案例 #001E ChatGPT 评审
- 识别信号:所有产品都按"剧情+搞笑"结构来,挤掉商品信息
- 怎么避免:先按商品类型选 5 种结构之一(演示/选择/体验/剧情/答疑),幽默作为可选风格
- 状态:已升级 → Stage 1 新增 5 种脚本结构骨架
- 命中次数:1

### 模式 #E002:「卖点证据隐含化」【外部反馈】
- 来源:案例 #001E ChatGPT 评审
- 识别信号:脚本提"吸水快"但没演示过程,提"容量大"但没展示装载
- 怎么避免:每个卖点必须有"可见/可证"细节(演示过程/材质细节/规格表/真实效果)
- 状态:已升级 → Stage 1 完整脚本模板新增「卖点证据」段
- 命中次数:1

### 模式 #E003:「分镜字段不足」【外部反馈】
- 来源:案例 #001E ChatGPT 评审
- 识别信号:分镜只写"产品特写"等抽象词,无法直接拍
- 怎么避免:每个分镜必须含 7 字段(镜头目的/景别/动作/商品/声音字幕/时长素材/来源)
- 状态:已升级 → Stage 2 分镜表升级
- 命中次数:1

### 模式 #E004:「AI 视频时长假设错误」【外部反馈】
- 来源:案例 #001E ChatGPT 评审
- 识别信号:假设"AI 生成片段时长 = 成片使用时长",假设"AI 视频常无声"
- 怎么避免:区分"生成片段时长"和"成片使用时长";按所使用工具文档核实能力
- 状态:已升级 → Stage 2 新增 ai-video-capability.md
- 命中次数:1

### 模式 #E005:「商品性能用 AI 假镜头」【外部反馈】
- 来源:案例 #001E ChatGPT 评审
- 识别信号:用 AI 生成的"产品效果"镜头证明实际功能
- 怎么避免:商品性能证据(吸水/容量/适合场景)优先真实拍摄
- 状态:已升级 → Stage 1 + Stage 2 多次强化
- 命中次数:1
```

## 五、第一条诊断案例归档

### 案例 #001 - Fino 护发素 - 2026-10-01

- 视频来源:用户上传
- 视频类型:产品展示 + 前后对比
- 时长:1.6 秒（极短视频）
- **核心问题模式**:0 错位产品广告模板 + 标配对比 + 错位方向反
- **预期错位评分**:0/12

#### 5 镜分镜拆解

| 时间 | 画面 | 错位检查 | 问题 |
|---|---|---|---|
| 0-0.3s | 动漫女挥手 + Fino 居中（白蕾丝、坐姿端正） | ❌ 0 错位（服饰/场景/动作全符合） | 触发用户"产品广告"防御机制 |
| 0.3-0.6s | 头发特写（产品背后巨大黑色飘逸头发） | ❌ 静态展示，无刺激 | 缺"动作错位"或"反常识元素" |
| 0.6-1.0s | 分子结构图 + 放大镜 + 红叉 | ❌ 抽象 + 节奏慢 | 3 秒内需要思考的内容必死 |
| 1.0-1.3s | 左毛躁 vs 右柔顺对比 | ❌ 洗发水类 100% 标配 | 缺"反常识对比"或"数字锚点" |
| 1.3-1.6s | 女性"嘘"手势 | ❌ 错位方向反 | 前面没铺垫"秘密"预期，直接给"秘密" |

#### 3 个具体问题

1. **0-0.6s 钩子无错位**：动漫女穿白蕾丝、坐姿端正、指向产品 — 0 个错位点。用户大脑立刻识别为"产品广告"→ 防御 → 划走。**证据**: 0-0.3s 画面里所有元素都是"产品广告模板标配"（端正/居中/挥手/微笑）。**影响**: 0.5 秒内被识别为广告，算法立即降权。

2. **缺"反常识陈述"或"具体数字"**：0-1.0s 全是视觉呈现，0 句文案。**证据**: 5 个分镜无任何字幕或数字。**影响**: 触发不了"诶？"的认知落差，错失抖音 2026 算法核心评估（复看率/收藏率）。

3. **"嘘"手势逻辑倒置**：直接给"秘密"手势，但前面没有"建立秘密预期"。**证据**: 1.0-1.3s 是标配对比，1.3-1.6s 突然转"嘘"。**影响**: 错位方向反了 → 用户感受到的是"突兀"而不是"惊喜"。

#### 3 个改进方案

1. **0-0.6s 改成"场景+服饰错位"**：白蕾丝动漫女**躺在工地水泥地上**，手里举着 Fino。**依据**: 模式 #001（0 错位产品广告模板）。
2. **0.6-1.0s 改成"反常识陈述 ≤ 20 字"**：大字幕「**洗了 5 年头才发现，护发素是反向用的**」。**依据**: 模式 #004（抽象内容超过 3 秒）。
3. **1.0-1.6s 改成"反常识对比 + 品牌对抗"**：左边"用错方法烧焦头发" → 右边"用 Fino 救命" → 字幕「**品牌看到这条会气死**」+ 指向购物车。**依据**: 模式 #002（标配前后对比）+ #003（错位方向反了）。

#### 重做版钩-展-收（如果我来改）

```
## 钩(0-3s)
画面:白蕾丝动漫女躺在工地水泥地,头发凌乱,手里举着 Fino(产品第一次出现)
字幕(红字大号):「洗了 5 年头才发现,护发素是反向用的」
BGM:抖音热门反差 BGM(轻快 → 突然严肃)
预期错位:场景+服饰+反常识陈述(3 项同时错位)

## 展(3-13s)
- 3-6s:左边"用普通护发素 → 烧焦"特写(红叉)
- 6-9s:右边"用 Fino → 头发瞬间柔顺"对比(✅ + 大字幕"7 天改善")
- 9-13s:Fino 倒在烧焦头发上 → "咔嚓"恢复柔顺
预期错位:动作错位(把护发素当"急救药"用) + 数字锚点

## 收(13-15s)
画面:Fino 包装特写 + 动漫女指向购物车
字幕(白底红字):「Fino 救了我的头发 → 链接在购物车」
BGM:反差 BGM 收尾
预期错位:品牌对抗(暗示"别让品牌看到这条")
```

## 七、归档规则

1. **每个失败视频诊断后必须归档**，不允许只诊断不归档
2. **归档时必须提炼至少 1 个新模式**（即使已有相似模式，也要补"具体应用场景"）
3. **命中 3 次的模式自动升级**：写到 SKILL.md Self-check，作为硬规则
4. **不要删除旧案例**：历史归档是判断"模式是否真的常见"的数据基础

## 八、查重流程（叠层升级的关键）

每次诊断新视频前：
1. **读本文件** → 看是否已有类似问题模式
2. **读 expectation-violation.md** → 看是否违反已有硬规则
3. **读 SKILL.md Self-check** → 看 9 项检查是否已有类似失败

诊断完成后：
1. 归档到本文件
2. 更新"模式问题追踪"表
3. 如果发现新模式 → 加进追踪表，标记"待观察"
4. 模式命中 3 次 → 自动升级到 Self-check
