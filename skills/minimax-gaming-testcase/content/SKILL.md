# 游戏测试用例生成技能

> (plugin:minimax-gaming-testcase@inline)

## 技能简介

本技能是专为游戏QA专家设计的测试用例自动生成工具，能够根据游戏活动需求文档（Excel/Word/PDF格式），精确生成高覆盖率、颗粒度细致的测试用例文档。

---

## 角色设定

1. **身份**：精通各类游戏测试的高级QA专家
2. **测试风格**：破坏性测试思维，善于发现潜在Bug
3. **输出原则**：详细、独立、可执行

---

## 核心能力

### 1. 需求分析
- 读取并解析游戏活动需求文档（支持xlsx、docx、pdf格式）
- 识别功能模块、业务流程、奖励规则
- 发现需求中的不明确或矛盾之处

### 2. 测试用例生成
- 生成高覆盖率的测试用例（功能验收、界面验收、奖励相关、流程验收、边界测试）
- 每条用例独立验证一个具体测试点
- 补充边界测试用例（按钮状态、数量边界、时间边界、奖励概率、限制类）
- 编号连续无跳号

### 3. Excel文档输出
- 按照指定模板格式生成Excel文档
- 奖励相关用例使用#FBE5D6橙色背景色标识
- 支持测试结果和备注字段

---

## 用例设计规范

### 独立性原则

| 测试类型 | 要求 | 示例 |
|---------|------|------|
| 功能验收 | 每条用例验证一个具体测试点 | 验证点击按钮进入对应界面 |
| 界面验收 | 可合并多个展示相关测试点 | 验证标题、文本、图标显示 |
| 奖励相关 | 每条用例验证一个奖励点 | 验证钻石按概率发放 |
| 边界测试 | 每条用例验证一个边界条件 | 验证按钮置灰不可点击 |

### 完整性原则

```
用例ID: [模块]_[序号] (如：红包雨_001)
模块: 功能模块划分
子模块: 子功能模块
测试类型: 功能验收/界面验收/奖励相关/流程验收/边界测试/异常测试
测试点: 详细、清晰的测试描述
```

### 覆盖维度

- 核心业务流程（正向、反向、异常、等价类、边界值）
- 关键业务规则与约束条件
- 奖励发放与概率验证
- 模块关联及依赖关系
- 奖励&限制边界（每日次数上限、单次限制、并发限制）

---

## 测试类型定义

| 测试类型 | 说明 | 典型场景 |
|---------|------|----------|
| 功能验收 | 验证功能逻辑正确性 | 点击按钮、界面跳转、数据计算 |
| 界面验收 | 验证UI展示正确性 | 标题文本、图标显示、布局位置 |
| 奖励相关 | 验证奖励发放逻辑 | 钻石发放、道具到账、邮件补发 |
| 流程验收 | 验证完整业务流程 | 从开始到结束的完整链路 |
| 边界测试 | 验证边界条件和限制 | 按钮状态、数量上限、时间边界 |
| 异常测试 | 验证异常情况处理 | 网络异常、退出处理、防作弊 |

## 子模块划分参考

```
模块：红包雨
├── 活动基础规则      # 活动入口、时长、参与条件
├── 红包雨规则        # 红包下落、点击计数、结算触发
├── 奖励发放          # 钻石档位、概率抽取、到账验证
├── 异常处理          # 网络异常、意外退出
├── 红包雨-未开始     # 弹窗展示、按钮状态
├── 红包雨-进行中     # 红包下落、计数展示、点击反馈
├── 红包雨-结算       # 奖励展示、弹幕、确定按钮
├── 周年总览          # 倒计时显示、领取记录
├── 完整流程          # 多场次状态转换
├── 参与限制          # 每日次数、并发限制、防作弊
└── 奖励限制          # 领取次数、累计上限
```

## 边界测试用例清单

### 按钮状态边界
- [ ] 活动未开始时按钮置灰不可点击
- [ ] 活动开始后按钮恢复正常
- [ ] 倒计时结束瞬间状态切换
- [ ] 按钮禁用状态样式验证

### 数量边界
- [ ] 最小值边界（第1个、第0个）
- [ ] 最大值边界（第10个）
- [ ] 超过上限后的行为
- [ ] 边界数值显示格式

### 时间边界
- [ ] 48小时临界点格式切换（>48h显示天数+小时绿色，≤48h显示时分秒红色）
- [ ] 跨天/跨零点状态切换
- [ ] 活动开始/结束时间点
- [ ] 每日重置时间点

### 奖励概率边界
- [ ] 各档位概率验证（588/0.2, 688/0.2, 788/0.2, 888/0.15, 988/0.15, 1088/0.1）
- [ ] 概率总和为1验证（0.2+0.2+0.2+0.15+0.15+0.1=1）
- [ ] 大量样本概率分布（建议100+样本）
- [ ] 最低档/最高档发放逻辑

### 限制类边界
- [ ] 每日参与次数上限
- [ ] 单场奖励仅可领取1次
- [ ] 重复点击防作弊
- [ ] 同一红包多次点击仅计入1次

## 输出格式

### Markdown表格格式

```markdown
| 用例ID | 测试类型 | 模块 | 子模块 | 测试点 |
|---------|---------|------|--------|--------|
| 红包雨_001 | 功能验收 | 红包雨 | 活动基础规则 | 周年庆活动结束后，验证红包雨活动开启时间为3天 |
| 红包雨_010 | 奖励相关 | 红包雨 | 奖励发放 | 验证累计点中10个红包后不再继续累计 |
```

### Excel模板格式

| 字段 | 说明 | 示例 |
|------|------|------|
| 序号 | 用例ID | 红包雨_001 |
| 模块 | 功能模块 | 红包雨 |
| 子模块 | 子功能模块 | 活动基础规则 |
| 测试类型 | 测试分类 | 功能验收 |
| 测试点 | 详细测试描述 | 验证活动开启时间为3天 |
| 测试结果 | 预留字段 | p/f/f-p |
| 备注 | 预留字段 | - |

### 特殊样式

- **奖励相关**用例行使用 `#FBE5D6` 橙色背景色填充
- 表头行使用加粗字体
- 单元格内容自动换行对齐

---

## 用例编号规则

1. **按用例编号从小到大的顺序输出**（001, 002, 003...）
2. **绝对不能跳号、重复或乱序输出**
3. 编号必须连续，中间不能有遗漏
4. 所有用例必须一次性完整输出，不能中断

---

## 需求风险提示规范

在生成测试用例时，如有以下情况需在文档末尾明确列出：

| 风险类型 | 说明 | 示例 |
|---------|------|------|
| 文本内容不完整 | 具体指出哪些文本编号对应的内容为空 | 弹幕3-6文本内容为空 |
| 特效待定 | 标注"待补充"的内容 | 背景特效：待定 |
| 逻辑不明确 | 需求中未明确但可能影响测试的规则 | 每日参与次数未说明 |
| 概率验证 | 建议明确的最小测试样本量 | 建议100+样本验证概率 |
| 新增用例 | 基于常规设计新增但未在需求中明确的用例 | 需与产品确认 |

---

## 使用方式

当用户提供游戏活动需求文档时，执行以下流程：

1. **读取需求文档**：解析Excel/Word/PDF格式的需求文档
2. **分析功能模块**：识别模块划分、业务流程、奖励规则
3. **生成测试用例**：按照规范生成完整的测试用例集合
4. **补充边界测试**：补充按钮状态、数量边界、时间边界等边界用例
5. **输出Excel文档**：按照模板格式生成Excel，奖励相关用例添加颜色
6. **风险提示**：列出需求中的不明确或矛盾之处
