# 相片整理技能

## 核心能力

### 1. 废片筛选

**质量问题检测**
- **模糊检测**：基于拉普拉斯算子/边缘检测评估清晰度
- **曝光检测**：分析直方图，识别严重欠曝(黑色块过多)或过曝(白色块过多)
- **噪点检测**：识别高ISO噪点过多的照片
- **构图分析**：检测严重倾斜、意外遮挡等

**检测阈值**
| 问题类型 | 默认阈值 | 可调范围 |
|---------|---------|---------|
| 模糊度 | 拉普拉斯方差 < 50 | 30-100 |
| 欠曝 | 黑色像素 > 60% | 50%-80% |
| 过曝 | 白色像素 > 50% | 40%-70% |
| 最小尺寸 | 宽度 < 300px | 可自定义 |

**处理方式**
- 废片直接移动到「废片」文件夹
- 提供缩略图预览和质量问题标注

### 2. 重复照片检测

**组群前提条件**
判定为重复/相似照片必须满足以下任一条件：
- **时间条件**：拍摄时间相差 ≤ 30 秒
- **序号条件**：文件名中的序号数字相差 ≤ 5

**检测方法**
- 精确匹配（MD5/SHA 哈希）
- 相似度匹配（感知哈希）
- 模糊匹配（尺寸相似 + 满足前提条件）

**处理方式**
- 将满足前提条件的重复/相似照片建立相似组
- 按质量排序（分辨率、清晰度、文件大小）
- 每组保留前 2 张质量最佳的照片
- 其余移入「重复相片」文件夹

### 3. 照片分类整理

**默认：按时间整理**
- 读取 EXIF 日期信息
- 处理无 EXIF 信息的照片（根据文件名推断或询问用户）
- 自动创建 年/月/日 文件夹结构

**可选分类方式**
- **按地点整理**：读取 GPS 信息，按国家/城市/具体地点分类
- **按人物整理**：人脸识别分类，创建人物相册
- **按事件整理**：分析文件夹名称识别事件，根据时间聚类识别连续拍摄

### 4. 批量重命名

**命名规则**
- 支持模板变量：`{date}`, `{time}`, `{location}`, `{index}`, `{original}`
- 日期格式自定义：`YYYY-MM-DD`, `YYYYMMDD`, `YYYY_MM_DD`
- 序号自动递增

**示例规则**
```
生日派对_2024_0205_{index:03}.jpg
旅行_{location}_{date}_{index}.jpg
```

### 5. 小文件过滤（可选功能）

**识别目标**
- 手机截图（通常带有 "Screenshot"、"截图" 标记）
- 应用图标、表情包、小图
- 微信/QQ 等即时通讯的图片缩略图
- 网站缓存的小图

**检测策略**
- **文件名识别**：Screenshot, screen_shot, 截图, thumb, thumbnail, icon, emoji
- **尺寸识别**：宽度 < 500px 且 高宽比 16:9 或 9:16（移动端截图）
- **内容识别**：纯色背景、简单几何图形、聊天界面布局

**处理方式**
- 移动到「小文件待审」文件夹供用户确认
- 按类型分组展示

### 6. HTML 整理报告

**报告内容**
- 整理概览（总照片数、废片数、重复照片数、整理后照片数）
- 废片清单（含缩略图和判定原因）
- 重复照片处理记录（每组的保留照片和移出照片）
- 整理后的文件夹结构
- 整理时间线

**报告格式**
- HTML 单文件，可浏览器直接打开
- 响应式布局，支持手机和电脑查看
- 内嵌缩略图或缩略图链接

## 执行流程

### 标准整理流程

```
1. 扫描照片库
   ├── 检测支持格式：JPG, PNG, RAW, HEIC, WEBP
   ├── 读取 EXIF 元数据
   ├── 提取尺寸/文件名等基础信息
   └── 统计照片数量

2. 废片判定 [第一轮筛选]
   ├── 模糊度分析（拉普拉斯算子）
   ├── 曝光度分析（直方图统计）
   ├── 噪点检测
   └── 构图问题检测
   └── 废片 → 移动到「废片」文件夹

3. 重复照片检测 [第二轮筛选，仅非废片参与]
   ├── 前提条件过滤
   │   ├── 时间条件：拍摄时间相差 ≤ 30秒
   │   └── 序号条件：文件名序号相差 ≤ 5
   ├── 哈希比对（精确匹配）
   ├── 感知哈希（相似匹配）
   └── 建立相似组
       ├── 按质量排序（分辨率、清晰度、文件大小）
       ├── 每组保留前 2 张
       └── 其余 → 移动到「重复相片」文件夹

4. 分类整理 [仅保留的好照片参与]
   ├── 读取日期/时间信息
   ├── 读取地理位置（如有）
   ├── 用户指定分类方式（默认按时间）
   └── 按年/月/日创建文件夹结构

5. 批量重命名（可选）
   ├── 应用用户指定的命名模板
   └── 实时预览

6. 生成 HTML 整理报告
   ├── 整理统计概览
   ├── 废片清单
   ├── 重复照片处理记录
   ├── 最终文件夹结构
   └── 保存到输出目录
```

### 用户确认节点

- 废片筛选结果展示后确认
- 重复照片处理建议展示后确认
- 分类方案预览确认
- 大规模移动前提供摘要
- 整理报告预览

## 注意事项

1. **数据安全**
   - 默认复制而非移动（保留原文件）
   - 执行前创建备份索引
   - 记录所有操作日志
   - 废片和重复照片有独立的确认步骤

2. **流程优化**
   - 废片先行筛选，减少后续处理量
   - 仅对非废片进行重复检测，节省时间
   - 相似组保留前2张，平衡存储与安全

3. **格式兼容**
   - 优先使用原始格式
   - HEIC/HEIF 自动转换选项
   - RAW 文件保留元数据

4. **性能考虑**

**复杂度分析**
| 步骤 | 复杂度 | 说明 |
|-----|-------|------|
| 扫描+EXIF | O(N) | IO + 元数据解析 |
| 废片筛选 | O(N) | 并行图像处理 |
| 重复检测 | O(N) | 时间窗口分区优化 |
| 分类整理 | O(N) | 文件操作 |

**重复检测优化策略**

*前提条件预过滤（时间窗口分区）*
```
1. 按拍摄时间排序
2. 30秒滑动窗口分组
3. 只在窗口内进行哈希比对
效果：从 O(N²) 降至接近 O(N)
```

*多层检测加速*
| 层级 | 方法 | 速度 | 作用 |
|-----|------|-----|------|
| L1 | 尺寸比较 | 微秒级 | 快速排除 |
| L2 | aHash (64位) | 毫秒级 | 初筛 |
| L3 | pHash (1024位) | 十毫秒级 | 精确匹配 |

**预估处理时间**

| 照片数量 | 处理时间 | 推荐策略 |
|---------|---------|---------|
| < 1,000 | < 30秒 | 全量哈希 |
| 1,000~10,000 | 30秒~5分钟 | 时间窗口 + pHash |
| > 10,000 | 5分钟~30分钟 | LSH分区 + 多进程 |

**优化措施**
- 多进程并行计算哈希
- 首次扫描缓存哈希值，增量检测新照片
- 大型库分批处理 + 进度显示
- 支持中断恢复（保存中间状态）

5. **元数据保护**
   - 保留完整 EXIF 信息
   - 必要时嵌入新文件名信息
