# 需求刚性等级评估矩阵

## 使用说明

本矩阵用于评估需求的重要性/紧迫性，帮助确定需求处理的优先级。刚性等级分为**高刚性**、**中刚性**、**低刚性**三个等级。

---

## 评估维度

### 维度一：不解决的影响

| 影响程度 | 描述 | 等级 |
|----------|------|------|
| 致命影响 | 导致核心业务无法运行、数据丢失、重大安全事故 | **高** |
| 显著影响 | 造成业务效率大幅下降、用户体验严重受损、客户流失风险 | **高** |
| 中度影响 | 业务有替代方案但效率降低、用户体验下降、部分用户投诉 | **中** |
| 轻微影响 | 优化性质，不解决无明显后果 | **低** |

### 维度二：紧迫程度

| 紧迫程度 | 描述 | 等级 |
|----------|------|------|
| 紧急 | 有明确时间节点，延迟会导致损失 | **高** |
| 一般 | 无强制时间点，但越早解决越好 | **中** |
| 规划中 | 可纳入后续版本规划 | **低** |

### 维度三：用户覆盖面

| 覆盖范围 | 描述 | 等级 |
|----------|------|------|
| 核心用户群 | 影响产品/服务的核心用户群体 | **高** |
| 多数用户 | 影响大多数用户的使用体验 | **中** |
| 少数用户 | 仅影响少量用户或边缘场景 | **低** |

### 维度四：发生频率

| 频率 | 描述 | 等级 |
|------|------|------|
| 日常高频 | 每天/每次使用都会遇到 | **高** |
| 中等频率 | 每周/定期会遇到 | **中** |
| 低频偶发 | 很少发生或特殊情况下发生 | **低** |

## 评估矩阵

### 4x4 综合评估表

| 影响 \ 紧迫 | 高紧迫 | 中紧迫 | 低紧迫 |
|-------------|--------|--------|--------|
| **致命影响** | **S级** | **A级** | **B级** |
| **显著影响** | **A级** | **B级** | **C级** |
| **中度影响** | **B级** | **C级** | **D级** |
| **轻微影响** | **C级** | **D级** | **D级** |

### 等级对照表

| 刚性等级 | 定义 | 处理策略 | SLA |
|----------|------|----------|-----|
| **S级（极高）** | 核心功能崩溃、业务停摆 | 立即处理，热修复 | ≤24h |
| **A级（高）** | 重要功能受限、影响显著 | 优先排期，快速迭代 | ≤1周 |
| **B级（中）** | 功能有缺陷但有替代方案 | 正常排期，纳入迭代 | ≤1月 |
| **C级（低）** | 体验优化型需求 | 低优先级，批次处理 | ≤3月 |
| **D级（可忽略）** | 锦上添花型需求 | 按需处理或取消 | 待定 |

## 评估决策树

```
开始评估
    │
    ▼
┌─────────────────────────────┐
│ 不解决会有什么影响？           │
└─────────────────────────────┘
    │
    ├─► 致命影响 → 影响=高 ──┐
    │
    ├─► 显著影响 → 影响=中 ──┼──► 进入紧迫度评估
    │
    ├─► 中度影响 → 影响=低 ──┤
    │
    └─► 轻微影响 → 影响=极低─┘

┌─────────────────────────────┐
│ 是否有硬性时间要求？           │
└─────────────────────────────┘
    │
    ├─► 是，有明确deadline → 紧迫=高
    │
    └─► 否，可灵活安排 → 紧迫=中/低

┌─────────────────────────────┐
│ 影响多少用户？               │
└─────────────────────────────┘
    │
    ├─► 核心/大多数用户 → 覆盖=高
    │
    └─► 少数/边缘用户 → 覆盖=中/低

┌─────────────────────────────┐
│ 发生频率如何？               │
└─────────────────────────────┘
    │
    ├─► 日常高频 → 频率=高
    │
    ├─► 定期中等 → 频率=中
    │
    └─► 偶发低频 → 频率=低

最终刚性 = 影响×紧迫×覆盖×频率 综合判定
```

## 应用场景

1. **需求评审会**：作为需求优先级的客观依据
2. **迭代规划**：指导迭代计划排期
3. **资源调配**：帮助管理层决策资源投入
4. **跨部门沟通**：向业务方/管理层说明优先级依据

---

## 注意事项

1. **客观评估**：避免因提出方职级高低影响判断
2. **数据支撑**：每个维度的判定尽量有数据支撑
3. **定期复盘**：需求解决后复盘评估准确性
4. **动态调整**：如实际情况变化，及时重新评估
5. **对齐标准**：团队内统一评估标准，减少主观差异
