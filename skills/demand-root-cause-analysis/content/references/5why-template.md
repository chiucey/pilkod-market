# 5Why 根因拆解模板

## 使用说明

本模板用于结构化执行 5Why 追问分析，帮助定位需求/问题的底层根因。

## 填写示例

```
需求/问题名称：用户要求增加"一键已读"功能
提出方：企业版客户（运营负责人）
拆解人：张三
拆解日期：2024-03-15

┌─────────────────────────────────────────────────────────┐
│ Why 1：为什么会提出这个需求？                              │
│ 回答：用户觉得消息太多，看不过来                            │
│ 锁定诉求：减少查看消息的负担                               │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│ Why 2：为什么查看消息会成为负担？                           │
│ 回答：每天有几百条消息，很多是系统通知                      │
│ 锁定诉求：区分重要消息和一般通知                             │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│ Why 3：为什么要区分重要消息和一般通知？                      │
│ 回答：担心错过关键的业务协作消息                            │
│ 锁定诉求：不错过需要即时响应的消息                           │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│ Why 4：为什么会担心错过消息？                               │
│ 回答：之前的协作延误导致了客户投诉                          │
│ 锁定诉求：保障协作时效，避免业务损失                         │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│ Why 5：这是不可分割的最底层吗？                            │
│ 回答：是，这是业务连续性的核心诉求                          │
│ ★ 根因锁定：保障业务协作的即时响应能力                       │
└─────────────────────────────────────────────────────────┘

【根因结论】
主路径根因：保障业务协作的即时响应能力

【验证方案】
→ 不做"一键已读"，而是实现"消息分级 + 重点提醒"
→ 验证用户是否真正解决了"不错过关键消息"的问题
```

---

## 注意事项

1. **逐层递进**：每一层 Why 必须基于上一层的回答推导
2. **客观陈述**：避免使用"因为用户想要..."这种预设答案
3. **多分支同步**：发现分支时立即并行拆解
4. **触底判断**：第5层后判断是否触达不可分割的本质
5. **交叉验证**：多分支时确认各根因之间的关系
