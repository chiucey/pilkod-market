# Obsidian 文档整理技能

## 核心功能

整理 Obsidian 笔记库中同主题文件夹的文档，实现：
- 智能分批处理与 token 容量估算
- MECE 原则重组文档结构
- 标准化 YAML frontmatter 属性
- 图片资源统一管理
- 完整过程日志记录

## 工作流程

### 第一步：环境检查与依赖确认

#### 1.1 询问目标文件夹

**必须**：在开始整理前确认目标文件夹路径。

**询问模板**：
> 请提供要整理的 Obsidian 文件夹路径（例如：`/path/to/vault/KIMI/`）
>
> 如果当前对话已提供路径，请跳过此步骤。

**路径验证**：
- 检查路径是否存在
- 确认路径指向有效的 Obsidian 笔记库文件夹
- 如果路径无效，提示用户重新输入

#### 1.2 依赖技能检查

**检查以下技能是否已安装**：
- `obsidian-cli` - Obsidian 笔记基础操作
- `obsidian-markdown` - Obsidian Markdown 格式处理
- `obsidian-bases` - 数据库视图处理

**安装提示模板**：
> 为获得最佳整理效果，建议安装以下技能：
> - `obsidian-cli`
> - `obsidian-markdown`
> - `obsidian-bases`
>
> 安装路径：https://github.com/kepano/obsidian-skills
>
> - 输入「继续」：在不安装的情况下继续整理
> - 输入「安装」：帮您安装这些技能后再整理
> - 输入其他：取消操作

**用户选择处理**：
- **选择继续**：跳过依赖安装，直接进行整理
- **选择安装**：调用 skill-creator 技能帮用户安装依赖后再整理
- **其他输入**：结束本次任务

---

### 第二步：目录结构初始化

在目标目录创建标准文件夹结构：

```
{目标目录}/
├── 已处理/          # 原始文档归档（内容不修改）
├── images/          # 图片资源统一存储
└── log/            # 详细过程记录
```

---

### 第三步：资源预扫描

执行以下扫描任务：
1. 统计所有 Markdown 文档数量
2. 扫描所有文档的图片引用
3. 识别文档间的关联性和重复内容
4. 记录文档基本信息（文件名、大小、类型）
5. 提取文件夹名称用于后续处理

---

### 第四步：Token 容量分析与分批决策

#### 4.1 容量估算流程

**步骤1：统计文档行数**
```bash
wc -l {目标目录}/*.md | grep -v total
```

**步骤2：Token 估算规则**
| 内容类型 | 估算标准 |
|---------|---------|
| 普通文本行 | 1行 ≈ 4 tokens |
| 代码行 | 1行 ≈ 2-3 tokens |
| 图片引用 | 每个 ≈ 10 tokens |
| YAML 头部 | 固定 ≈ 20 tokens |

**步骤3：容量阈值与分批策略**

| 估算总量 | 风险等级 | 分批策略 |
|---------|---------|---------|
| < 8,000 tokens | 安全范围 | 每批 3-4 个文档 |
| 8,000-12,000 tokens | 警告范围 | 每批 2-3 个文档 |
| > 12,000 tokens | 危险范围 | 必须循环分段处理 |

---

### 第五步：智能分批执行

#### 5.1 单批处理流程

**步骤1：文档读取与理解**
- 完整读取当前批次所有文档
- 提取核心内容：概念定义、操作步骤、代码示例、图表
- 分析内容结构和逻辑关系

**步骤2：新文档结构设计**

序号规则：
- 主主题：`【01】标题`、`【02】标题`
- 子主题：`【01a】标题`、`【01b】标题`
- 细分内容：`【01a-1】标题`、`【01a-2】标题`

**步骤3：YAML Frontmatter 标准化**

每个整理后的文档必须包含：
```yaml
---
description: 少于50字的一句话简介
source_url: 原文来源链接
github_url: 相关GitHub项目链接（如有）
images_folder: images/
original_topic: 来源文档名称1、来源文档名称2
---
```

**步骤4：内容重组与整合**
- 按 MECE 原则重新组织内容
- 消除重复信息，保持逻辑连贯
- 添加必要的过渡说明和上下文

**步骤5：图片资源管理**
- 将图片复制/移动到 `images/` 目录
- 更新文档中的图片引用为 Obsidian 格式：`![[images/文件名.扩展名]]`

**步骤6：原始文档归档**
- 将被整合的原始文件**完整移动**到 `已处理/` 文件夹
- **禁止任何内容修改**，保持原文件名和格式
- 记录归档位置便于追溯

---

### 第六步：README 文档生成

#### 6.1 README 命名与内容

**保持原文件名**：README.md（不做重命名）

**YAML 属性（必需）**：
```yaml
---
description: 不超过50字的一句话描述当前文件夹核心内容
tags: [index, 标签1, 标签2, ...]
---
```

#### 6.2 README 八部分结构

按以下结构组织 README 内容：

1. **目录概览** `## 📁 目录概览`
   - 树状结构展示文件夹组织架构
   - 清晰标注主要文档位置和层级关系

2. **文档主题注释** `## 📝 文档主题注释`
   - 为每个文档提供 1-2 句话的注释说明
   - 按文档序号顺序排列

3. **复杂文档专项说明** `## 🔍 复杂文档专项说明`
   - 对主题内容复杂的文档提供额外说明
   - 涉及多个概念、交叉主题时使用

4. **知识边界范围** `## 🎯 知识边界范围`
   - 定义文件夹涵盖的知识范围
   - 说明哪些内容包含/不包含

5. **主题分类体系** `## 📊 主题分类体系`
   - 建立清晰的主题分类层次
   - 说明文档间逻辑关系和学习路径

6. **快速入门指南** `## 🚀 快速入门指南`
   - 针对不同用户提供快速上手建议
   - 推荐不同学习路径

7. **相关资源链接** `## 🔗 相关资源链接`
   - 汇总所有外部资源链接
   - 按资源类型和重要性排序

8. **更新与维护信息** `## 🔄 更新与维护信息`
   - 说明版本更新策略
   - 引导查看 log 文件夹详情

---

### 第七步：日志记录

**日志文件**：
- `整理日志_YYYY-MM-DD_HH-MM.md`
- `图片迁移记录.md`
- `token容量分析.md`

**必须记录**：
- 处理时间戳（开始/结束）
- 处理的文档清单（原文件→新文件）
- YAML 属性变更记录
- Token 使用情况估算
- 特殊情况与处理方式

---

### 第八步：整理完成与用户提示

#### 8.1 成功指标检查

- ✅ 所有原始文档完整归档到「已处理」文件夹
- ✅ 图片资源 100% 正确迁移
- ✅ README.md 包含必需的 YAML 属性
- ✅ 整理日志详细完整
- ✅ 新文档结构清晰，符合 MECE 原则

#### 8.2 完成提示

整理完成后，向用户显示：

> ---
> **整理完成！**
>
> 已生成文件：
> - `README.md` - **导航文件**，可通过它快速了解当前文件夹内容结构
> - `已处理/` - 原始文档归档目录
> - `log/` - 整理过程日志
>
> **下一步建议**：
> 1. 打开 `README.md` 检查整理效果
> 2. 确认无误后，可手动删除「已处理」文件夹以释放空间
>
> ---

## 原文档保护机制

| 原则 | 说明 |
|-----|------|
| 绝对不改动 | 原始文档内容不做任何修改 |
| 完整归档 | 整理完成后完整移动到 `已处理/` |
| 保持原貌 | 文件名、内容、格式、编码全部保持原状 |
| 可恢复性 | 任何时候可从 `已处理/` 恢复原始状态 |
