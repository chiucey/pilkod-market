# POT 文件翻译器（pot-translator）

将 GNU gettext POT 模板文件中的 `msgid`（源字符串）按用户指定的目标语言翻译，填入对应的 `msgstr`，输出保持完整 POT 格式的翻译后文件。

## 核心原则

1. **翻译由大模型自身完成**：严禁调用外部翻译工具、简繁转换库（如 OpenCC）、机器翻译 API 或任何第三方转换软件。所有翻译必须基于大模型自身的语言能力与知识完成。
2. **语境驱动翻译**：翻译前必须收集用户提供的语境信息，确保译文准确、一致、符合使用场景。
3. **严禁逐字替换式翻译**（最高优先级约束）：
   - **绝对禁止**将源文本逐字映射为目标语言词汇后不做语法重组
   - **绝对禁止**输出"字典里有就换、没有就保留"的暴力套娃式结果
   - **必须**先理解源文本的完整语义，再按目标语言的语法规则重新组织句子
   - **必须**进行真正的语序调整、时态转换、语态转换、格变化等语法操作
   - **错误示例**（严禁出现）：
     - 中文"天天向上" → 越南语 "#chiều đại a"（逐字替换，无语义）
     - 中文"天天向上" → 英语 "day day up"（逐字替换，非英语语法）
     - 中文"连接失败" → 越南语 "kết nối thất bại" 后不做任何语法检查直接输出
   - **正确示例**：
     - 中文"天天向上" → 越南语 "cố gắng tiến bộ mỗi ngày"（语义等价，符合越南语语法）
     - 中文"连接失败" → 越南语 "Không thể kết nối"（符合越南语表达习惯）

## 必填语境（翻译前必须向用户收集）

开始翻译前，必须向用户确认以下信息（若用户未主动提供，则主动询问）：

| 语境项 | 说明 | 示例 |
|:---|:---|:---|
| **目标语言** | 翻译为哪种语言（必填） | 繁体中文（台湾）、日语、法语 |
| **语言变体** | 同一语言的不同地区/风格变体 | 台湾正体 / 香港繁体 / 大陆简体 |
| **使用场景** | 软件界面、技术文档、错误提示、日志消息等 | 工业机器人控制软件 UI |
| **目标受众** | 终端用户、技术人员、开发者等 | 工厂操作员、维护工程师 |
| **术语偏好** | 特定行业术语、公司术语表 | "机械臂" vs "机器人手臂"、"点动" vs "寸动" |
| **风格要求** | 正式/口语、简洁/详细、技术文档风格 | 简洁的命令式按钮文案 |
| **语法偏好** | 时态、语态、敬语级别、性别处理等 | 日文使用です/ます体、英文使用被动语态 |
| **语法偏好** | 时态、语态、敬语级别、性别处理等 | 日文使用です/ます体、英文使用被动语态 |
| **格式约束** | 是否保留占位符格式、长度限制等 | 按钮文字不超过 6 字 |

**若用户未提供语境，必须先询问，不得自行假设。**

## 工作流程

1. **获取输入**：读取用户上传的 `.pot` 文件内容（路径通常在 `/mnt/agents/upload/`），或直接读取用户粘贴的文本内容。
2. **收集语境**：按上表向用户确认目标语言、语言变体、使用场景、目标受众、术语偏好、风格要求、格式约束。若用户已提供则跳过。
3. **解析条目**：逐条解析 POT 内容，识别每个翻译条目（entry），包括：
   - 注释行（`#` 开头）：`#:` 源文件引用、`#.` 提取注释、`#,` 标志（如 fuzzy、c-format）、`#|` 前一条 msgid
   - `msgctxt "上下文"`（可选）
   - `msgid "源字符串"`（可能为多行字符串）
   - `msgid_plural "复数形式源字符串"`（可选）
   - `msgstr ""` / `msgstr[0] ""` / `msgstr[1] ""`（要填入翻译的位置）
   - 文件头条目（第一个 msgid 为空的条目，其 msgstr 包含元数据如 `Content-Type`、`Plural-Forms` 等）
4. **翻译**：对每个非空的 `msgid` / `msgid_plural` 进行翻译：
   - **由大模型自身完成翻译**，基于用户提供的语境进行准确、自然的翻译
   - 将译文写入对应的 `msgstr` / `msgstr[n]`
   - **保留所有注释、标志、上下文、源文件引用原样不动**
5. **更新文件头**：在头部条目的 msgstr 元数据中：
   - 设置/更新 `Language: <目标语言代码>\n`（如 zh_TW、ja、fr）
   - 保留 `Content-Type: text/plain; charset=UTF-8\n`
   - 根据目标语言设置正确的 `Plural-Forms`（如中文：`nplurals=1; plural=0;`；日语：`nplurals=1; plural=0;`；法语：`nplurals=2; plural=(n > 1);`；英语：`nplurals=2; plural=(n != 1);`）
   - 可更新 `PO-Revision-Date`、`Last-Translator` 等字段
6. **输出文件**：根据运行环境选择合适的输出方式（见下方"环境适配"章节），确保用户可下载。

## 大文件处理策略（关键！）

当 POT 文件包含 **超过 500 个条目** 或 **超过 50KB** 时，必须采用分批处理，严禁一次性翻译全部内容。

### 分批策略

| 文件规模 | 策略 | 每批大小 |
|:---|:---|:---|
| < 500 条 / < 50KB | 单批处理 | 全部 |
| 500-2000 条 | 手动分批 | 每批 300-500 条 |
| 2000-5000 条 | 自动分片 + 进度追踪 | 每批 300-500 条 |
| > 5000 条 | **强烈建议 subagent 并行** | 每批 500-800 条 |

### 手动分批执行流程

```
第 1 批：条目 1-500    → 翻译 → 追加到输出文件 → 报告进度 "已完成 500/4008"
第 2 批：条目 501-1000  → 翻译 → 追加到输出文件 → 报告进度 "已完成 1000/4008"
...
最后一批 → 翻译 → 追加 → 验证完整性 → 输出最终文件
```

**每批之间必须：**
1. **追加写入**（而非覆盖）到输出文件
2. **报告进度**（已完成/总数）
3. **简要自检**（占位符数量、明显错误）

### 自动分片执行流程（推荐）

```
1. 解析全部条目，记录总数 N
2. 按每批 500 条切分为 ceil(N/500) 个分片
3. 逐片处理：
   - 提取该分片的 msgid 列表
   - 翻译该分片
   - 将译文写入对应 msgstr
   - 追加到输出文件
   - 输出进度："分片 3/9 完成，已处理 1500/4008 条"
4. 全部完成后，验证输出文件条目数 = N
```

### Subagent 并行处理（>5000 条时强烈推荐）

当条目数超过 5000 时，建议启动 subagent 并行翻译：

```
主 agent 职责：
  1. 解析 POT 文件，提取所有条目
  2. 按每批 500-800 条切分为 M 个分片
  3. 启动 M 个 subagent，每个负责一个分片
  4. 收集各 subagent 的翻译结果
  5. 合并、验证、输出最终文件

subagent 职责：
  1. 接收分片数据（条目列表 + 语境）
  2. 翻译该分片的所有 msgid
  3. 返回翻译后的 msgstr 列表
  4. 报告该分片的占位符统计
```

**subagent 启动模板：**
```
请翻译以下 POT 条目（第 X/Y 分片，共 Z 条）：

【语境】
- 目标语言：繁体中文（台湾）
- 使用场景：工业机器人控制软件 UI
- 术语偏好：机械臂、点动

【条目列表】
1. msgid "小数" → msgstr "?"
2. msgid "布尔" → msgstr "?"
...

【要求】
- 保留所有占位符（{}、%s、{0:.2f} 等）
- 按目标语言语法调整语序
- 返回格式：编号 + 译文
```

### 上下文保护机制

无论采用哪种策略，必须：

1. **每批独立上下文**：每批翻译时，只携带该批的条目 + 固定语境，不携带历史批次详情
2. **术语表持久化**：将关键术语翻译写入独立文件（如 `glossary.zh_TW.txt`），每批前读取
3. **进度持久化**：每批完成后更新进度文件（如 `progress.txt`），记录已处理条目数
4. **输出文件追加**：使用追加模式写入，避免内存中保留全部译文

### 进度报告格式

每批完成后必须报告：
```
【进度】分片 3/9 | 已处理 1500/4008 条 | 当前批次占位符 45/45 保留 ✅
```

### 完整性验证（最后一批后必须执行）

```python
# 伪代码
源条目数 = 解析(源文件).条目数
输出条目数 = 解析(输出文件).条目数
assert 源条目数 == 输出条目数, "条目数不一致！"

for 条目 in 输出文件:
    assert 条目.msgstr != "", f"条目 {条目.msgid} 未翻译"
    assert 占位符数量(条目.msgid) == 占位符数量(条目.msgstr), f"占位符丢失"
```

## 环境适配：文件输出与下载

不同部署环境下，文件输出路径和下载方式不同。必须根据当前环境选择合适的方式，**确保用户能够下载最终文件**。

### 环境检测

执行输出前，先检测当前环境：

| 检测项 | 方法 | 说明 |
|:---|:---|:---|
| 是否有 `/mnt/agents/output/` | 检查目录是否存在 | Kimi 桌面/Agent 环境 |
| 是否有 `show_widget` 工具 | 检查工具列表 | 支持 widget 的环境 |
| 是否有文件上传/下载 API | 检查可用工具 | 云服务 Agent 环境 |
| 是否只能返回文本 | 无文件工具 | 纯文本环境 |

### 输出策略（按优先级）

#### 策略 A：标准文件输出（Kimi 桌面/Agent 环境）

```python
# 检测到 /mnt/agents/output/ 存在时
output_path = '/mnt/agents/output/<原文件名>.<语言代码>.pot'
with open(output_path, 'w', encoding='utf-8') as f:
    f.write(translated_content)
```

回复末尾附加：
```
<REF>file✦sandbox:///mnt/agents/output/<文件名></REF>
```

#### 策略 B：分片文本返回（纯文本环境，无文件工具）

当无法写入文件时，将翻译结果按批次直接返回给用户：

```
【第 1/5 批翻译结果】
msgid "小数" → msgstr "小數"
msgid "布尔" → msgstr "布林"
...

【第 2/5 批翻译结果】
...
```

用户可自行复制合并为完整文件。

#### 策略 C：Base64 编码返回（需要单条消息传输）

```
【文件内容 Base64 编码】
H4sIAF...（编码内容）
```

用户可解码保存为 `.pot` 文件。

#### 策略 D：云服务 API 上传（有文件上传接口时）

若环境提供文件上传/存储 API（如 S3、OSS、临时文件服务）：
1. 调用 API 上传翻译后的文件
2. 获取下载链接
3. 将链接返回给用户

### 环境适配决策树

```
开始输出
  │
  ├─ /mnt/agents/output/ 存在？
  │     ├─ 是 → 策略 A（标准文件输出 + REF 标签）
  │     └─ 否 → 继续检测
  │
  ├─ 有文件上传 API？
  │     ├─ 是 → 策略 D（API 上传 + 返回链接）
  │     └─ 否 → 继续检测
  │
  ├─ 文件 < 100KB 且可单条消息传输？
  │     ├─ 是 → 策略 C（Base64 编码返回）
  │     └─ 否 → 策略 B（分片文本返回）
  │
  └─ 默认 → 策略 B（分片文本返回）
```

### 分片文本返回格式

当使用策略 B 时，按以下格式返回，便于用户合并：

```
===== POT 翻译结果 =====
【元数据】
Language: zh_TW
Plural-Forms: nplurals=1; plural=0;

【条目 1-500】
msgid "小数"
msgstr "小數"

msgid "布尔"
msgstr "布林"
...

【条目 501-1000】
...
===== 结束 =====
```

### 关键原则

1. **用户可下载是第一优先级**：无论采用哪种策略，必须确保用户最终能获得完整文件
2. **明确告知输出方式**：在回复开头说明当前采用的输出策略及原因
3. **提供备选方案**：若当前策略不适用，主动建议替代方案
4. **分片时提供合并指引**：告知用户如何合并分片结果为完整 POT 文件

## 翻译规则（必须严格遵守）

1. **只翻译文本内容**，绝不修改文件结构、关键字（`msgid`、`msgstr`、`msgctxt`、`msgid_plural`）、注释行、标志位。
2. **占位符必须原样保留**（重点覆盖 C++ 日志库常见格式）：
   - **printf/sprintf 风格**：`%s`、`%d`、`%f`、`%x`、`%p`、`%c`、`%u`、`%ld`、`%lld`、`%zu`、`%02d`、`%-10s`、`%+.3f` 等，含全部 flags/width/precision/length 修饰符
   - **fmt/spdlog 风格**：`{}`、`{0}`、`{1}`、`{:.3f}`、`{:>10}`、`{:x}`、`{:02x}`、`{:#06x}`、`{:>+8.2f}` 等，含全部 format spec
   - **命名参数**：`%(name)s`、`{name}`、`%<name>s` 等
   - **转义序列**：`\n`、`\t`、`\\`、`\"` 等
   - **特殊标记**：`{0:#06x}`、`{:04X}` 等大小写敏感的十六进制格式
   - 以上所有占位符**一个都不能改、不能丢、不能增**。翻译时调整语序即可，占位符保持原样嵌入译文。
3. **目标语言语法适配**（核心要求，严禁逐字替换）：

   **翻译前必须执行的三步思考：**
   ```
   第 1 步：理解源文本的完整语义（谁、做什么、什么时候、怎么样）
   第 2 步：确定目标语言中表达该语义的标准句式（语序、时态、语态、格位）
   第 3 步：按目标语言语法规则重新组织句子，而非逐词映射
   ```

   **语序（主谓宾）**：
   - 中文 SVO："我吃饭" → 越南语 SOV："Tôi ăn cơm"（我-饭-吃）
   - 中文修饰语前置 → 英文修饰语后置："红色的车" → "the car that is red"
   - 中文无主语 → 英文必须补主语或变被动："连接失败" → "Connection failed" / "Failed to connect"

   **时态**：
   - 中文"了/过" → 英文过去时/完成时："完成了" → "has completed"
   - 中文"正在" → 英文进行时 / 越南语 đang + 动词
   - 中文无标记 → 按语境判断英文现在/过去/将来

   **语态**：
   - 中文主动表被动 → 英文正式被动："连接被拒绝" → "Connection was refused"
   - 中文无主语 → 英文被动或泛指主语："未找到文件" → "File not found" / "The file was not found"

   **性/数/格**（印欧语言）：
   - 越南语：无性别/格，但有量词和语气词
   - 法文：名词阴阳性、形容词配合、动词变位
   - 德文：名词四格、动词框架结构

   **敬语/礼貌级别**（东亚语言）：
   - 日文：です/ます 调、谦让语、尊敬语
   - 韩文：습니다/해요 体、敬语后缀
   - 越南语：anh/chị/em 称谓、xin/vui lòng 礼貌用语

   **软件 UI 特殊语法**：
   - 按钮：英文动词原形 "Save"、越南语 "Lưu"、日文 "保存"
   - 错误提示：英文名词短语 "Connection error"、越南语 "Lỗi kết nối"
   - 状态标签：形容词/分词，保持简洁

   **逐字替换检测清单**（输出前自检）：
   - [ ] 译文是否符合目标语言的基本语序？
   - [ ] 译文是否包含目标语言必需的语法标记（时态/语态/格/助词）？
   - [ ] 若将译文回译，语义是否等价？
   - [ ] 译文是否读起来像目标语言的母语者写的，而非外语学习者写的？

4. **多行字符串保持多行格式**：源字符串若由多行引号片段组成（`msgid ""` 后跟多个 `"..."` 行），译文也应按相似方式折行，每行以 `"` 包裹，保持可读性。
5. **转义序列保留**：`\"`、`\\`、`\n` 等在译文中对应位置保留。
6. **上下文（msgctxt）不翻译**：如 `msgctxt "Actions"` 保持原样，但翻译时应参考上下文确保译文准确（例如 "Close" 在动作语境下译为"关闭"而非"近的"）。
7. **复数形式**：`msgid_plural` 也要翻译；`msgstr[0]`、`msgstr[1]` 等按目标语言的复数规则填写全部形式（如中文只需 `msgstr[0]`，俄语需要 3 个形式）。
8. **fuzzy 标志**：若条目带 `#, fuzzy` 标志，可翻译但保留标志，或提示用户该条目为模糊匹配。
9. **空 msgid 不翻译**：头部条目的空 `msgid ""` 保持为空，只更新其 msgstr 中的元数据。
10. **译文风格**：准确、自然、符合软件界面用语习惯；术语保持一致。
11. **大模型自主翻译**：严禁调用 OpenCC、cconv、Google Translate、DeepL 等任何外部工具或 API。所有翻译必须基于大模型自身的语言理解与生成能力完成。

## 语境驱动的翻译示例

**用户提供的语境**：
- 目标语言：繁体中文（台湾）
- 使用场景：工业机器人控制软件 UI
- 目标受众：工厂操作员
- 术语偏好："机械臂"（非"機器人手臂"）、"点动"（非"寸動"）
- 风格要求：简洁、命令式

**输入片段**（C++ 日志库风格）：
```
#: src/robot.cpp:42
#, c-format
msgid "Joint {} velocity {:.2f} rad/s exceeds limit {:#06x}"
msgstr ""

#: src/logger.cpp:88
msgid "Failed to connect to %s:%d, error code %04X"
msgstr ""

#: src/fmt_logger.cpp:15
```

**语法适配示例**（同一源文本，不同目标语言）：

**逐字替换 vs 真正翻译对比**（最高优先级示例）：

| 源文本 | 逐字替换（严禁） | 真正翻译（正确） | 说明 |
|:---|:---|:---|:---|
| 中文"天天向上" | 越南语 "#chiều đại a" | 越南语 "cố gắng tiến bộ mỗi ngày" | 逐字替换无语义；真正翻译语义等价 |
| 中文"天天向上" | 英语 "day day up" | 英语 "strive for progress every day" | 逐字替换非英语；真正翻译符合英语习惯 |
| 中文"连接失败" | 越南语 "kết nối thất bại"（无语法检查） | 越南语 "Không thể kết nối" | 逐字替换生硬；真正翻译符合越南语表达 |
| 中文"未找到文件" | 越南语 "chưa tìm thấy tệp"（无主语） | 越南语 "Không tìm thấy tệp" | 逐字替换缺主语；真正翻译补主语 |
| 中文"保存"（按钮） | 越南语 "bảo tồn" | 越南语 "Lưu" | 逐字替换选词错误；真正翻译用 UI 标准词 |
| 中文"取消"（按钮） | 越南语 "hủy bỏ"（过长） | 越南语 "Hủy" | 逐字替换冗长；真正翻译简洁 |

**逐字替换的识别特征**：
- 译文与源文本字数/词数几乎一一对应
- 译文读起来像"用目标语言单词套中文语法"
- 缺少目标语言必需的语法标记（时态/语态/格/助词）
- 专业术语选词明显错误（如"保存"译为"bảo tồn"而非"Lưu"）

**真正翻译的验证方法**：
1. **回译测试**：将译文翻译回源语言，语义是否等价？
2. **母语者测试**：译文是否像目标语言母语者写的？
3. **语法完整性**：译文是否包含目标语言必需的所有语法标记？
