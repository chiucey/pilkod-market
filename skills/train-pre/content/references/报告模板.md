# 《训前思考整理》报告规则与模板

## 证据规则

| 字段 | 最低证据要求 | 是否需要学员确认 |
| --- | --- | --- |
| 基础背景 | 学员提供的去标识化地域/部门/管理层级/团队规模区间/协作部门 | 不需要；缺项留空 |
| 具体事件 | 学员表达的工作事件、冲突、行动或可观察结果 | 直接表达即可，但须处理前后矛盾 |
| 深层原因 | 有事实或多种解释比较支持的原因 | 需要 |
| 可迁移经验 | 学员主动表达，或明确接受的可复用认识或行动 | 需要 |
| 课程期待 | 学员表达的一项具体学习需要 | 不需要；未表达则留空 |

探索性判断只用于帮助思考，未被确认时不得写入报告。具体事件、深层原因和可迁移经验均满足要求时生成完整草稿；任一项不足时生成未完成草稿，不为完整率继续追问。

## 成稿模板

```markdown
# 训前思考整理：我的问题与经验

**草稿状态：** 完整草稿 / 未完成草稿

## 基础背景（去标识化，缺项留空）
- 地域 / 单位 / 部门：某地区 · 某公司 · 某部门
- 管理层级：
- 团队规模区间：
- 经常协作的部门：
- 本轮培训主题：

## 1. 我最希望破解的一个业务难题

[聚焦一个具体场景、冲突和卡点；不使用“协同难”等表层标签代替事件。]

## 2. 这个难题背后的深层症结

[仅填写有对话依据且经确认的原因；可并列一至两条，可注明属 资源／技术／专业能力／流程／权责 哪类。]

## 3. 我从中沉淀的一条可迁移经验

[填写经确认、可复用的认识或行动。]

## 4. 我对本次课程的一个具体期待

[填写学员明确表达的课程需要，落到一个具体的点。]
```

栏目缺乏依据时保持明显空白，仅添加：

> 这部分尚未充分讨论，您可以继续对话，也可以自行补充。

## 写作与展示

1. 在不改变学员原意的前提下压缩重复内容、优化书面表达；不得新增事实、因果、动机、评价或管理概念。
2. 删除或概括姓名、工号、精确岗位、精确人数、项目名称、具体地点及其他可识别信息；**组织背景只保留到“某地区·某公司·某部门”级别**，真实人名一律写成“某领导”“某部门”，不写入对话记录。
3. 以学员确认或修正为准；不将技术或专业需求未经确认地描述为管理问题。
4. 报告后仅说：

   > 请您检查这份草稿是否准确。您可以直接修改、继续讨论尚未明确的部分，或者确认当前版本。

5. 不代替学员提交，也不声称报告已保存、加密或删除。
