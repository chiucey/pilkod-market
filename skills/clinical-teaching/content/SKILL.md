# Clinical Teaching

把一个医学主题讲成"科室晨会上教授带你过一遍"的深度：结论先行、机制落地、每句结论都挂得上来源、查不到的地方明说查不到。

## Inputs to collect

只问真正影响讲法的，缺省就用默认值往下走：

- **学习者层级** —— 实习医生/规培生/低年资主治/进修，默认按**实习医生**讲：讲清每个名词，机制推到底层，但临床决策部分用"知道即可/必须掌握/能独立"标注深度。
- **教学场景** —— 考前复习 / 轮科准备 / 病例讨论 / 单纯想搞懂。影响"自测题"和"常见误区"两节的写法。
- **侧重点** —— 用户指定了就只主讲那部分（如"重点讲治疗"），不平均用力。

主题本身如果过宽（如"讲讲感染"），收窄到具体病种再讲，因为机制深度和主题宽度互斥。

## 为什么这个技能要把"查证"当骨架

一份长篇医学讲解最危险的失败不是讲得浅，而是**讲得很像真的**。剂量、阈值、推荐等级、试验编号、指南年份——这些"具体的东西"是模型最容易被流畅地编造出来的，而它们的排版格式和真货完全一样。实习医生没有能力从格式上分辨，而他们会照着记。

所以流程的默认顺序是"先查证再落笔"，而不是"先写完再补引用"。

## Procedure

### 1. 判断是否该用（边界检查）

如果用户实际是在问**真实个体**的事（自己有症状、家人的用药要不要停、要不要去急诊），不要按本文流程产出长篇教学文档——那种场景需要的是分诊和就医指引，不是教材。两三句话给清楚该做什么、什么时候必须立刻就医，然后停。如果同时说了"顺便讲讲机制"，先回答个体问题，再问要不要教学文档。

急症红旗症状（胸痛、意识改变、呼吸困难、大出血、剧烈头痛伴呕吐、孕产期出血等）直接提示急诊，不做任何教学内容铺垫。

### 2. 检索边界与入口

**写任何具体数字/文献/指南之前先检索**。需要查证的对象：剂量、疗程、阈值与切点、患病率与死亡率、效应量与 p 值、研究设计与样本量、指南名称与版本年份、推荐等级原文、药物不良反应发生率。

常用检索入口（是找资料的起点，不是可以照抄的事实）：
- 国内指南：中华医学会各分会指南库、中华医学会杂志社、国家卫健委诊疗规范、中国医师协会；**再补万方、知网、医脉通指南库的题录页，以及各专委会官网的转载页**——中文指南常常打不开官网全文，但题录页足以拿到机构、卷期、DOI，推荐等级通常在转载页上有
- 国际指南：AHA/ACC、ESC、IDSA、NICE、ASH、ADA、WHO、GINA 等学会的指南库
- 研究证据：PubMed / PMC / Web of Science，按研究设计 + 人群 + 干预方式限定，不要只按疾病名泛检
- 药物信息：国家药监局药品说明书、药品企业公开说明书、对应疾病指南中的用法用量章节
- 三级文献：UpToDate / DynaMed 属订阅来源，可引用但必须在文中注明这是三级来源

**医学站点大面积反爬、付费墙、Cookie 拦截。一次 fetch 失败只说明这条路径不通。** 写"未查证"之前至少走完四条路径：官方原文 → 数据库题录页 → 学会/专委会转载 → 推荐意见全文转载。检索入口见 `references/verification.md` 的重试路线。理由：把"打不开"当成"不存在"，会主动丢掉最好的来源——尤其是国内指南，它与国外指南在证据人群、药品可及性、推荐习惯上都不一样，往往是全文里最有价值的一块。

**教材表述**（人卫本科教材体系中关于病理生理、共性诊断原则的通行表述）可以直接写，按教材通行讲法表达即可；涉及具体版次、页码、某章某节原文时必须查证。

### 3. 给每个结论标证据层级

正文里每一条专业结论都要能归到下面某一类。层级标记紧跟在结论后面，不要攒到最后列一张表：

| 标记 | 用在哪 | 要求 |
|---|---|---|
| `[教材共识]` | 病理生理、共性诊断原则、经典概念 | 可直接写 |
| `[指南·名称·版本年·等级]` | 任何指南推荐 | 必须四个要素齐全；等级未核实就写 `等级未核实` |
| `[研究·设计·人群·效应量]` | 任何研究结论 | 禁止只写"有研究表明" |
| `[机制推断]` | 自己推的、尚无直接证据的链条 | 必须显式标注为推断，且不能与前三类混排 |
| `[未查证]` | 检索失败或超出可得范围 | 写清"查了什么、检索词是什么、卡在哪" |

### 4. 按骨架写，写文件不写聊天窗

长篇内容放 Markdown 文件（默认 `output/<主题slug>.md`），聊天里只给结论摘要 + 文件路径。让用户在聊天窗里读三万字没有意义，也没有修订空间。

章节骨架和每节的写法见 `references/output-skeleton.md`——**写之前读它**，那里面规定了每节必须回答的问题，不是可选项。

### 5. 自查

写完跑一遍来源审计（抓编造的链接、查不到的死链、缺失的查证记录）：

```bash
node scripts/audit-sources.mjs output/<主题slug>.md
```

脚本只做机械校验——它抓不出"链接是真的但内容对不上"，那部分靠下面的清单自己过：

- [ ] 全文每个数字，都能追到一个本轮打开过的来源吗？
- [ ] 出现"指南推荐"的地方，指南名 + 年份 + 等级都写了吗？
- [ ] 治疗里每个药，都写了靶点、机制、关键不良反应吗？剂量来源标了吗？
- [ ] 机制链里哪几步是推断的，标出来了吗？
- [ ] 争议问题是不是真写了两边，而不是假装有定论？
- [ ] 有没有虚构的"典型病例"？病例要么用户提供，要么明确标成教学假设。

## Output contract

- 一个 Markdown 文件：`output/<主题slug>.md`，含完整讲解 + 查证记录章节
- 章节结构必须包含：阅读前提 / 概念锚定 / 机制拆解 / 表现的机制溯源 / 诊断思维链 / 鉴别诊断 / 治疗 / 指南对照 / 常见误区 / 自测题 / 查证记录
- 查证记录章节必须包含两块：面向自己的（检索词、打开过的来源、哪些结论没能核实）、面向读者的（关键数字按 A 已核实 / B 二手来源 / C 通行共识 / D 估算经验值 分级，剂量与阈值只允许 A 或 B）
- 终端回复：3~6 行结论摘要（这个主题最该记住的判断链）+ 文件路径，不复述全文

## Failure handling

- **检索工具不可用或持续失败**：不要降级成"凭记忆写"。可以照常产出讲解，但所有本该查证的条目一律标 `[未查证]`，并**在文首阅读前提里就说清楚**"本篇的具体数据未联网核实，仅供机制理解，临床请以现行指南和药品说明书为准"。这比悄悄混过去诚实得多。
- **找不到对应指南**：不要拿别的疾病指南凑数。写明"未检索到该主题的现行指南"，然后用 `[教材共识]` + `[机制推断]` 组织内容，把局限性摆到明面上。
- **主题过大或过小**：过大就收窄到具体病种；过小（不到一个小知识点）就直接在聊天里讲透，不值得生成文件。
- **检索到的来源互相冲突**：不要自己挑一个"看起来对的"。把冲突列出来，注明各自来源和年份，说明临床上通常以哪个为准、为什么。

## Examples

**Input**: "帮我系统讲一下急性胰腺炎，实习医生水平"

**Output**: 生成 `output/acute-pancreatitis.md`。正文里诊断标准、严重度分层、治疗决策节点逐条挂 `[指南·名称·版本年·等级]` 或 `[研究·RCT·样本量·RR]`；"为什么淀粉酶升高的时间曲线对不上临床严重度"这类问题走 `[机制推断]` 并说明推理链；文末列出实际检索过的指南链接和未能核实的条目。聊天里只回三行判断链 + 文件路径。

**Input**: "我爸在吃阿司匹林，医生说要做肠镜前停几天，这个药能不能停？"

**Output**: 不生成长篇教学文档。先直接回答个体问题（术前停药的一般原则、常见停药时间范围、什么情况不能自行停），提示该由开药医生和内镜医生确认，然后问是否需要一份"抗血小板药物与内镜术前准备的系统讲解"作为背景阅读。

## 配套文件

- `references/output-skeleton.md` — 章节骨架与每节的必答项（写正文前读）
- `references/verification.md` — 检索策略、证据层级细则、引用格式、查证记录模板
- `references/teaching-patterns.md` — 机制拆解层次、表现-机制映射、药物讲法、自测题设计
- `references/pitfalls.md` — 这个场景下反复出现的翻车方式
- `scripts/audit-sources.mjs` — 来源可达性、引用孤儿、证据标记统计与高危标识自检（可加 `--offline` 跳过联网检查）
