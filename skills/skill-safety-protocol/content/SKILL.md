# Skill安全操作规程 v1.0

> **定位**：所有skill扩充/修改操作的前置规程。任何skill写入操作前，必须先读本文件并遵守。  
> **触发**：用户要求"扩充"、"更新"、"追加"、"修改"任何skill时激活。

---

## 一、铁律：永远以备份为基准

**第一条规则**：
> 任何skill的扩充，以用户上传的备份文件为**唯一基准版本**。

**正确做法**：
```
备份文件 + 新内容 → 融合 → 最终版本 → 写入磁盘
```

**禁止做法**：
```
当前磁盘文件 + 追加内容 → 写入磁盘   ← 这会覆盖原始内容
```

**原因**：当前磁盘文件可能已被污染（部分写入/重复膨胀/被覆盖），以它为基础会导致污染扩散或内容丢失。

---

## 二、操作前：必须读取并确认磁盘内容

**每次写入前，必须执行以下两步（顺序不可颠倒）**：

### 步骤1：读取磁盘文件
```
读取 /workspace/skills/{skill_name}/SKILL.md 的全部内容
```
- 不能假设"文件内容=聊天记录里说的内容"
- 不能假设"上次操作后文件没变"
- 必须用read工具实际读取

### 步骤2：对比备份
```
对比 备份文件行数 vs 当前磁盘文件行数
```
- 如果磁盘文件行数 < 备份行数 → 文件已被污染，停止操作，汇报用户
- 如果磁盘文件行数 > 备份行数 → 可能存在污染内容，保留备份中的纯净版本
- 如果行数相同 → 可以继续

---

## 三、操作中：小步快跑，单文件完成写盘

**每次只处理1个文件，完成后再处理下一个。**

### 单文件操作流程：

```
1. 读取备份文件（user_input_files/）
2. 读取当前磁盘文件（如存在）
3. 读取本次要追加的新内容（如有）
4. 融合：备份 + 当前磁盘（取两者更丰富版本）+ 新内容
5. 写盘：一次性写入最终结果
6. 验证：写入后立即用 exec(wc -l) 验证行数
7. 确认OK后，再处理下一个文件
```

### 关于write工具：
- write工具是**覆盖写入**，不是追加写入
- 不能依赖"先读取再写入"来追加，必须把完整内容一起写入
- 写入时提供完整的最终内容（包含旧内容+新内容）

### 关于exec追加内容：
- exec里用Python追加内容时，必须用**多行字符串**，不要用单行`\n`拼接
- 正确：`content += "\n\n## 新章节\n\n内容"`（多行字符串）
- 错误：`content += "中文内容\n中文内容"`（\n在shell里是字面量）

---

## 四、验证：写完必须验证，以磁盘为准

**验证不是可选项，是必选项。**

### 验证方法：
```python
import os
path = '/workspace/skills/{skill}/SKILL.md'
size = os.path.getsize(path)
lines = len(open(path).read().split('\n'))
print(f"行数:{lines} 大小:{size}字节")
```

### 验证标准：
| 指标 | 安全线 |
|------|--------|
| 融合后行数 | ≥ 备份行数 |
| 融合后行数 | ≥ 当前磁盘行数 |
| 融合后字节 | ≥ 10000（正常skill应≥10KB） |

**任意一项不达标 → 立即停止，汇报用户，手动检查。**

---

## 五、禁止行为

| 禁止 | 原因 |
|------|------|
| 不读磁盘就写入 | 可能覆盖有效内容 |
| 批量操作多个文件 | 出错时难以定位 |
| 依赖session汇报 | session可能与磁盘不一致 |
| 依赖聊天记录 | 历史记录可能被截断 |
| exec里用单行`\n`追加中文 | 中文内容会串成一行 |
| 跳过验证步骤 | 无法发现写入失败 |

## 六、融合算法规则

### 正确去重策略：
```python
def merge(bk_lines, cur_lines):
    # 1. 备份内容优先，保留所有备份独有的段落
    # 2. 当前磁盘内容独有的段落也保留
    # 3. 两版共有的段落，取较长版本
    # 4. 不完全相同的表达都要保留（防误删）
    seen = {}
    for line in bk_lines + cur_lines:
        key = line.strip()
        if not key:
            continue
        if key not in seen:
            seen[key] = line
        elif len(line) > len(seen[key]):
            seen[key] = line
    # 保留顺序（备份在前，新增在后）
    result = list(seen.values())
    return '\n'.join(result)
```

### 禁止：
- 不能简单`set()`去重（会丢失不同表达）
- 不能以后期版本完全覆盖早期版本
- 不能只保留"看起来更丰富"的版本（要逐段比对）

## 七、出错时的应对

### 发现磁盘文件比备份少
→ **立即停止所有操作**
→ 汇报用户："检测到文件被污染，停止操作，请重新上传备份"

### 写入后验证失败
→ **不要重试写入**
→ 先读磁盘确认实际状态，再决定如何处理

### Loop detection触发
→ **停止执行，等待用户指令**
→ 不要反复尝试同一个操作

## 八、操作员的话术规范

每次操作前汇报：
> "已读取磁盘内容，与备份对比中……"  
> "检测到：磁盘行数xxx，备份行数xxx，状态：[正常/异常]"  
> "融合后行数：xxx，验证通过 ✅"  
> "下一个：[文件名]，是否继续？"

用户确认后再操作下一个，不要自动批量执行。

---

## 九、本规则的适用范围

- `/workspace/skills/` 目录下所有skill的写入操作
- 扩充、更新、追加、修改、重写、融合
- 新建skill时推荐参考

**本规则优先级最高**：即使其他指令要求"直接扩充"，也必须先遵守本规程。
