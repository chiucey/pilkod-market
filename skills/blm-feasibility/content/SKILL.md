# BLM 业务领先模型 v3.0 — 新项目可行性研究技能

## 模型溯源

- **IBM 起源**：BLM（Business Leadership Model）由 IBM 于 1990 年代末至 2003 年前后开发，与哈佛、斯坦福学者（Tushman、O'Reilly 等）合作形成，核心哲学是"工程化的社会过程"——战略必须由通用经理人亲自参与对话，而非委派幕僚。
- **华为优化**：华为自 2008 年起引入 BLM，将其纳入 DSTE（Develop Strategy to Execute）年度管理流程，配套"五看三定"工具集与 BEM 战略解码工具，从定性框架升级为数据驱动体系。
- **本技能定位**：在 IBM 经典闭环上叠加华为五看三定与轻度业务层合规提示（AI/数据合规、供应商锁定、地缘政治），适配 2026 年实战环境。

### 0.2 意图澄清（用户描述不足 150 字 OR 关键信息缺失时强制触发）

**① 项目类型**（决定 Unit Economics 模板分支）

| 类型 | 分析重点 | UE 指标分支 |
|---|---|---|
| ToB 产品/服务 | 销售周期、标杆客户、决策链 | 客户毛利率 / 回款周期 / 客户集中度 (HHI) |
| ToC 产品/服务 | 流量、转化漏斗、留存、LTV | LTV / CAC / 回本周期 |
| 技术/硬件型 | 研发周期、量产壁垒、技术护城河 | BOM 成本占比 / 量产良率 / 库存周转率 |
| 平台/生态型 | 网络效应、双边市场、冷启动 | Take Rate / MAU 货币化率 / 双边匹配效率 |
| SaaS/订阅 | ARR、NDR、Churn、Payback | LTV/CAC > 3 / Payback < 18 个月 |

**② 分析深度**

- 🚀 **快速评估**：500-800 字，红绿灯结论 + 3 条核心判断
- 📋 **完整可研**：**5000-8000 字**（v3.0 扩容，解决 v2.0 P0 字数冲突），完整九步分析

```
  1. [最大支撑理由 + 客观证据]

  3. [关键前提假设 + 验证方法]

```

**红绿灯—决策动作映射表**（v3.0 新增橙灯，解决 v2.0 P1 偏差）：

| 灯色 | 触发条件 | 决策动作 |
|---|---|---|
| 🟢 绿灯 | 逻辑自洽 + 壁垒可识别 + 团队基本匹配 + UE 健康 | **推进**：立项并配置完整资源 |
| 🟡 黄灯 | 市场有机会，但 Top 3 关键假设有 1 个未验证 | **小步验证**：MVP / 灰度试点 |

| 🔴 红灯 | 满足任一：市场天花板极低 / 无任何战略控制点 / 核心团队能力严重不匹配 / 关键假设已被证伪 / UE 模型崩塌 | **放弃**：明确止损 |

## 第二步：差距分析（动态锚定起点）

### 条件判断逻辑

**新项目（从 0 到 1）→ 重点审视"机会差距"**

- 业绩差距重定义为"战略野心与现状的落差"
- **机会差距**：赛道天花板（市场总规模）vs 当前团队资源能力可触达的份额 → 识别"因能力不足而可能错失"的机会

**现有业务扩张 → 重点审视"业绩差距"**

- 实际经营结果 vs 预期目标
- 量化维度：财务、市场份额、运营效率、客户满意度
- 核心判断问题：这是"能力不足"还是"方向偏差"？两者修复路径截然不同

## 第三步：市场洞察（华为"五看"+ 强制 PESTEL）

### 3.1 五看（Look at Five）

详细工具集见 `references/wukan-sanding.md`。

| 维度 | 核心问题 | 必答内容 |
|---|---|---|
| **看趋势** | 长期演进规律是什么？ | 技术、宏观经济、监管政策、AI/数字化重塑路径 |
| **看市场** | 市场结构如何？ | TAM/SAM/SOM 三层拆分、成熟度、集中度 |
| **看客户** | 客户为什么买？ | 画像、痛点、决策路径、TCO 视角 |
| **看对手** | 我们如何活下来？ | 玩家盘点、护城河、能力差距、切入缝隙、生存压力测试 |
| **看机会** | 爆发点在哪里？ | 痛点未满足、模式转变、技术拐点、政策窗口 |

### 6.3 单位经济模型（Unit Economics，按项目类型分支）

**v3.0 强制按 0.2 步识别的项目类型选用对应模板**：

#### 模板 A：ToC / SaaS / 订阅

```

```

#### 模板 C：硬件 / 制造
```
BOM 成本占比：____% （健康基准 < 60%）
量产良率：____% （行业基线对标）
库存周转率：____ 次/年

```

#### 模板 D：平台 / 双边市场
```
Take Rate：____%
MAU 货币化率（ARPU）：¥____
双边匹配效率：____%
冷启动 CAC（双边）：¥____
网络效应阈值：____ 用户数
```

⚠️ **崩塌警示**：
- 模板 A：LTV/CAC < 1 → 业务模式不成立
- 模板 B：订单毛利率 < 20% → 业务模式不成立

### 8.3 氛围与文化适配性（新项目高频失败原因）

| 新项目需要 | 母体组织现状 | 冲突程度 (高/中/低) | 应对方案 |
|---|---|---|---|

| 扁平决策效率 | 多级审批制度 | | |
| AI 流利度 / 数字原生 | 传统流程主导 | | |

### 8.4 双元性组织（Ambidexterity）诊断（v3.0 新增）

回答两个问题：
1. **结构性双元**：是否需要为新项目设立独立的业务单元（独立子公司 / 事业部）以避免母体排异？
2. **情境性双元**：现有管理机制能否引导员工在创新与效率之间自主切换？

⚠️ 若 8.3 中冲突程度有任一为"高"，且为"革命性变革"项目 → **强制建议**：将新项目隔离运营（独立子公司/事业部），不得嵌入母体组织。这是传统企业孵化创新业务失败的首要原因。

### 9.3 决策门（Stage-Gate 机制，v3.0 锚点修正）

**标准定义**：Gate N 在 Phase N **结束时**评估，决定是否进入 Phase N+1（参照 Robert Cooper Stage-Gate 行业标准）。

| 决策门 | 触发时机 | 通过标准 | 未通过则 |
|---|---|---|---|
| Gate 1 | Phase 1 结束 | [PMF 验证指标] | 终止 / 重大调整 |
| Gate 2 | Phase 2 结束 | [规模化复制指标] | 暂停 / 不扩大投入 |
| Gate 3 | Phase 3 中段 | [领导地位指标] | 维持现状 / 出售 / 退出 |

### 9.4 止损条件（满足任一，建议主动叫停）

- ☐ 市场机会窗口已实质性关闭（强劲对手已占据主导）
- ☐ Top 3 关键假设中有 2 个以上被证伪
- ☐ 所需资源超出当前承受能力 3 倍以上
- ☐ 核心执行团队无法在 Phase 1 内到位
- ☐ 单位经济模型崩塌（按 6.3 各模板崩塌阈值）且无清晰改善路径
- ☐ 发现重大法律 / 合规障碍（含 EU AI Act / 数据安全法）且无可行解决方案
- ☐ 地缘政治风险触发关税 / 出口管制变更，超过财务承受能力
- ☐ AI 模型供应商单点故障 / 价格暴涨，且无开源 / 平替方案

## 分析原则（v3.0 强化）

1. **执行顺序刚性**：信息澄清 > 假设补齐 > 结论前置 > 九步分析。信息缺失时严禁输出红绿灯。
2. **结论前置**：信息齐备后，第一屏必须是决策建议，不要让决策者翻页找答案。
3. **假设显性化**：所有未经验证的判断必须标注 `[假设：XXX | 来源：YYY | 待验证]`。无数据时不伪造数据，不把模型推断伪装成事实。
4. **事实/洞见/影响三部曲**：每个核心发现遵循 `事实（Data）+ 洞见（Insight）+ 商业影响（Impact）` 结构。
5. **差异化优先**：核心要回答"为什么我们能赢"，而不只是"市场有多大"。
6. **资源约束视角**：路线图必须在真实资源约束下制定，避免理想化规划。
7. **动态预案**：针对 Top 3 风险，必须给出触发条件与应对机制。

## 常见陷阱提示

### 经典陷阱

- ❌ 市场够大就能做（忽略竞争强度和进入壁垒）
- ❌ 技术领先就能赢（忽略商业化能力和市场教育成本）
- ❌ 参考竞争对手定价（忽略自身成本结构差异）
- ❌ 高估第一年收入（忽略销售周期）
- ❌ 组织能力评估过于乐观（人才到位需要时间）
- ❌ 只有生意，没有壁垒（为行业探路，为对手作嫁衣）
- ❌ 战略意图与业务设计脱节（想做高端，成本结构只支撑低端）
- ❌ 关键任务没有责任人和时间表（无效战略解码）
- ❌ 把母体组织文化套用到新项目（"母体排异"导致夭折）

### AI 时代陷阱（v3.0 扩展）

- ❌ 假设 AI 能力可以快速商业化（忽略用户接受度与部署成本）
- ❌ 忽略数据合规风险（GDPR / 个人信息保护法 / 数据安全法 / EU AI Act）
- ❌ 高估模型准确性（模型幻觉风险影响产品可靠性）
- ❌ 忽视推理 / 算力成本对利润的持续侵蚀
- ❌ 低估竞争窗口收窄速度（大模型能力迭代极快）
- ❌ **依赖单一闭源大模型供应商，缺乏开源 / 多模型平替方案（Vendor Lock-in 风险）**
- ❌ **依赖通用模型 + 公开数据建立护城河（垂直数据质量才是真正的 AI 项目护城河）**
- ❌ **将训练数据合规风险下沉到执行阶段，错过立项期的合规成本评估（占预算 10-25%）**

### 地缘政治陷阱（v3.0 新增）

- ❌ 假设当前贸易关系会持续（忽视关税突变与出口管制风险）
- ❌ 单一供应链节点依赖（缺乏 ASEAN / 印度等备选路径）
- ❌ 忽视数据出境合规（中国 / 欧盟 / 美国三地数据本地化要求）
- ❌ 财务模型未做地缘压力测试（关税跳变 20% 时的现金流模拟缺失）
