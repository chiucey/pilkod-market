## 概览
本文档定义了游戏策划文档的写作规范和标准，确保文档的专业性、一致性和可执行性。

## 文档结构规范

### 标准文档结构
```
1. 文档头部
   - 文档标题
   - 版本记录表格

2. 系统概述（可选）
   - 功能简介：简要介绍系统的核心功能和包含的主要模块

3. 正文内容
   - 功能模块描述
   - 交互逻辑说明
   - 规则与约束定义

4. 附录
   - 术语表
   - 参考资料
```

### 章节编号规范
- 一级标题：1、2、3...
- 二级标题：1.1、1.2、1.3...
- 三级标题：1.1.1、1.1.2、1.1.3...
- 列表项：使用 ◦、▪、• 进行层次区分

## 内容组织原则

### 功能描述标准格式（灵活选择）

根据功能复杂度灵活选择组织方式，**禁止生搬硬套固定模板**：

**简单功能**：无需副标题，直接用段落描述
```
对话框：包含对话文本和角色头像，头像根据表格配置显示对应表情。
```

**中等复杂度功能**：使用单个副标题
```
对话框：界面元素
对话框包含对话文本和角色头像，头像根据表格配置显示对应表情。
```

**复杂功能**：根据实际情况选择必要的副标题
- **功能描述**：描述功能的目的和作用（功能复杂时使用）
- **交互逻辑**：描述用户操作和系统响应（交互复杂时使用）
- **状态定义**：明确功能的不同状态及其特征（状态变化时使用）
- **规则约束**：列出功能执行的限制条件和规则（规则复杂时使用）

**副标题选择原则**：
- 根据功能实际复杂度选择合适的副标题
- 不要为了追求格式统一而强制使用固定副标题
- 副标题应准确反映内容的性质
- 禁止每个功能都使用"功能描述、触发流程、交互逻辑"这种固定模板
- 可选的副标题类型：功能描述、功能概述、UI元素、界面元素、交互逻辑、状态定义、规则定义、数据说明

### 列表使用规则
- **单行内容**：内容不超过50字，直接使用段落，不使用列表
- **多行内容**：内容超过50字，使用列表提升可读性
- **多要点内容**：包含多个独立要点，使用列表组织
- **避免冗余**：不要为追求视觉工整而对单行内容强制使用列表
5. **异常处理**：描述异常情况的处理方案

### 层次组织原则
- **总到分**：先概述，再细节
- **主到次**：先核心功能，再辅助功能
- **常到特**：先常规流程，再特殊情况
- **简到繁**：先简单场景，再复杂场景

## 表达方式标准

### 描述性表达
- 使用"功能描述"作为功能说明的标题
- 使用简洁准确的语言概括功能
- 避免使用模糊词汇（如"可能"、"大约"）

### 逻辑性表达
- 使用条件语句描述规则："当...时，则..."
- 使用顺序词描述流程："首先...然后...最后..."
- 使用对比词描述差异："与...不同，..."

### 可读性表达
- 避免过长句子，每句不超过50字
- 使用列表组织并列内容
- 使用表格展示对比关系
- 使用示例辅助说明抽象概念

## 图表使用规范

### 表格使用场景
- **状态定义表**：列出所有状态及其属性
- **参数配置表**：列出可配置参数及默认值
- **映射关系表**：明确数据之间的对应关系
- **优先级表**：定义规则或事件的执行顺序

### 表格格式规范
```
字段1 | 字段2 | 字段3
值1   | 值2   | 值3
```

### 流程图使用场景
- 复杂业务逻辑流程
- 多分支判断逻辑
- 状态转换流程
- 数据流转过程

### 流程图绘制规范
- 使用标准流程图符号（开始/结束、处理、判断、输入/输出）
- 明确标注决策节点的判断条件
- 标注关键数据的流转
- 确保流程图的完整性和准确性

## 术语与命名规范

### 术语使用原则
- **一致性**：同一概念使用同一术语
- **准确性**：术语应准确反映概念含义
- **简洁性**：避免冗长或复杂的术语
- **标准化**：优先使用行业通用术语

### 命名规范
- **界面元素**：使用中文名称，加引号标注（如"开始按钮"）
- **系统功能**：使用动词+名词结构（如"用户登录"）
- **数据字段**：使用下划线命名法（如 user_id）
- **状态值**：使用明确的中文描述（如"在线"、"离线"）
