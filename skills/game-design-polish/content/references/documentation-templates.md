# 游戏策划文档模板集

## 目录
1. 系统设计文档模板
2. 功能说明文档模板
3. 界面交互文档模板
4. 规则配置文档模板

## 概览
本文档提供不同类型游戏策划文档的标准模板，供文档生成和润色时参考。

## 1. 系统设计文档模板

### 文档头部
```
【系统名称】系统设计
版本号 | 修改内容 | 修改人 | 修改日期
1.0 | 创建文档 | 姓名 | YYYY.MM.DD
```

### 系统概述（可选）

根据系统复杂度灵活调整：

**简单系统**：一段话概括
```
【系统概述】

本系统用于实现[核心功能]，包含[主要功能模块]等核心能力。
```

**复杂系统**：分点列举
```
【系统概述】

本系统用于实现[核心功能]，主要包含以下功能模块：

1. [模块一]：描述模块功能
2. [模块二]：描述模块功能
3. [模块三]：描述模块功能
```

**编写原则**：
- 简要介绍系统的核心功能和作用
- 列出系统包含的主要功能模块
- 根据系统复杂度调整详细程度
- 避免过度详细，保持简洁

### 功能模块
```
2. 功能模块

2.1 模块一：[模块名称]

根据功能复杂度和实际情况灵活选择组织方式，**禁止生搬硬套固定模板**：

**示例1：简单功能（无副标题）**
```
对话框：包含对话文本和角色头像，头像根据表格配置显示对应表情。
```

**示例2：纯UI元素（使用单个副标题）**
```
对话框：界面元素
对话框包含对话文本和角色头像，头像根据表格配置显示对应表情。
```

**示例3：有明确状态的UI（使用状态副标题）**
```
电量显示：状态定义
- 满电：电量 >= 65%，显示绿色图标
- 中电：20% <= 电量 < 65%，显示黄色图标
- 低电：电量 < 20%，显示红色图标
```

**示例4：复杂交互功能（根据实际需要选择副标题）**
如果功能确实需要详细说明，根据实际情况选择必要的副标题，不要为了格式统一而强制使用所有副标题。

**重要原则**：
- 根据功能实际需要选择副标题，不要生搬硬套
- 简单功能直接描述，无需副标题
- 只在必要时使用副标题，副标题应准确反映内容性质
- 禁止每个功能都使用"功能描述、触发流程、交互逻辑"这种固定模板
- 文档观感应自然流畅，符合实际功能需求
```

## 使用说明

### 模板选择
- **系统设计文档**：用于描述完整的系统或功能模块
- **功能说明文档**：用于描述具体的功能点
- **界面交互文档**：用于描述界面布局和交互
- **规则配置文档**：用于描述复杂的业务规则和配置

### 模板定制
- 根据实际需求调整模板结构
- 保留核心章节，删除不需要的内容
- 补充特定项目的特殊要求

### 注意事项
- 模板是参考，不是强制要求
- 保持文档的一致性和规范性
- 确保内容的完整性和准确性
