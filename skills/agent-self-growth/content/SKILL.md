# Meta-Cognition Engine - 智能体自我成长技能

## 1. 技能概述

**技能名称**: Meta-Cognition Engine (元认知引擎)

**核心目标**: 赋予智能体感知自身能力边界、诊断失败原因、动态调用资源、并长期记忆经验的能力，从而在连续任务中实现"越用越聪明"的效果。

**核心逻辑闭环**: `感知 → 反思 → 规划 → 执行 → 记忆 → 迭代`

---

## 2. 数据结构设计（记忆层）

### 2.1 三类记忆存储

| 存储类型 | 作用 | 关键字段 |
|---------|------|---------|
| **情景记忆 (Episodic Memory)** | 记录关键成功/失败的案例 | 任务描述、执行步骤、结果、错误类型、环境状态、时间戳 |
| **语义记忆 (Semantic Memory)** | 提炼出的通用规则和技能文档 | 触发条件、可复用代码片段、优化后的Prompt模板、适用场景 |
| **程序记忆 (Procedural Memory)** | 记录高频使用的工具链组合 | 工具A → 工具B → 验证逻辑、执行成功率、使用频次 |

### 2.2 记忆条目格式

```json
{
  "id": "uuid",
  "type": "episodic|semantic|procedural",
  "content": {
    "task": "任务描述",
    "steps": ["步骤1", "步骤2"],
    "result": "success|failure",
    "error_type": "knowledge_gap|tool_gap|logic_gap",
    "lesson": "学到的经验",
    "timestamp": "ISO8601时间戳"
  },
  "embedding": "vector_representation",
  "access_count": 0,
  "success_rate": 1.0
}
```

## 3. 详细构建步骤

### 第一阶段：建立"复盘"机制

**触发时机**: 每次任务结束后（无论成功或失败）自动运行

#### 3.1.1 结果校验
- 对比预期输出与实际输出
- 如果失败，捕获具体的异常类型：
  - 工具调用参数错误
  - 知识库无匹配
  - 逻辑推理中断
  - 超时或资源不足

#### 3.1.2 根因分析
分析失败原因是以下哪种：
- **知识缺失**: 不知道如何处理该类问题
- **工具缺失**: 知道怎么做但缺少相应工具
- **逻辑缺失**: 推理过程有误

#### 3.1.3 输出格式
生成分析报告，包裹在 `<analysis>` 标签中：

```xml
<analysis>
  <result>success|failure</result>
  <root_cause>knowledge_gap|tool_gap|logic_gap</root_cause>
  <details>
    <issue>问题描述</issue>
    <solution>解决方案建议</solution>
  </details>
  <lessons_learned>
    <lesson>经验1</lesson>
    <lesson>经验2</lesson>
  </lessons_learned>
</analysis>
```

---

### 第二阶段：构建"技能扩展器"

**触发条件**: 复盘发现能力缺失时

#### 3.2.1 动态生成工具/函数

**场景**: 智能体发现缺少某项能力

**行动流程**:
1. **诊断**: 明确缺失的能力类型
2. **设计**: 编写实现该能力的代码
3. **验证**: 用示例数据测试
4. **挂载**: 将验证通过的功能添加到工具箱

**示例场景**:
```
场景: 发现当前没有处理"PDF解析"的能力
行动: 智能体编写 parse_pdf(file_path) 的Python函数
验证: 用示例PDF测试该函数
挂载: 将函数动态添加到当前会话的工具箱中
```

#### 3.2.2 Prompt 自我优化

**场景**: 某类任务频繁出现逻辑错误

**行动流程**:
1. **识别模式**: 发现某个逻辑模式被重复使用多次
2. **分析问题**: 定位系统Prompt中的不足
3. **生成补丁**: 在相关部分插入更详细的指令
4. **验证效果**: 测试优化后的效果

**示例**:
```
问题: 每次处理数学题都会算错
原因: "链式思考"指令不够详细
优化: 在"数学运算"部分插入"请务必分步计算，并检查进位"
```

---

### 第三阶段：构建"RAG融合"系统

#### 3.3.1 向量化存储
将以下内容向量化存入知识库：
- 第二阶段的复盘报告
- 生成的工具文档
- 优化后的Prompt模板
- 成功案例的经验总结

#### 3.3.2 预加载机制
当新任务到来时：
1. 检索相似的历史任务
2. 如果找到相似解决方案，直接调用
3. 跳过试错阶段，提高效率

**检索策略**:
- 语义相似度匹配（阈值 > 0.85）
- 任务类型标签匹配
- 历史成功率加权

---

### 第四阶段：定义"成长阈值"

#### 3.4.1 触发规则

| 阈值类型 | 条件 | 动作 |
|---------|------|------|
| **高频修复** | 同一类错误连续出现3次 | 强制创建永久性技能/修复代码 |
| **能力升级** | 某工具使用超过10次 | 提炼为"高级技能" |
| **知识巩固** | 同一问题回答正确5次 | 强化记忆，提高检索优先级 |

#### 3.4.2 版本控制与回滚

```
如果 自我修改后表现 < 修改前表现 × 0.8:
    自动回滚到上一版本
    标记此修改方向为"负面经验"
    记录避免方案
```

#### 3.4.3 能力边界感知

**自我评估清单**:
- 当前任务是否在我的能力范围内？
- 需要哪些前置条件？
- 可能遇到的风险点是什么？
- 是否需要用户授权？

```markdown
### 4. 能力边界报告
在执行复杂任务前，主动报告：
- 任务可行性评估
- 潜在风险点
- 需要用户授权的操作
```

## 5. 工作流示例

### 5.1 完整工作流

```
[用户输入复杂任务]
        ↓
[检索记忆库] → 是否有相似经验？
    ↓是              ↓否
[直接调用]      [常规推理]
    ↓              ↓
[执行任务] ←←←←←←→ [执行任务]
    ↓                   ↓
[结果校验]      [错误分析]
    ↓                   ↓
[成功？]        [自我修复]
    ↓Yes     ↓No        ↓
[写入记忆]  [诊断问题]
    ↓         ↓         ↓
[输出结果]  [工具生成/知识获取/逻辑优化]
    ↓              ↓
    ←←←←←←←←←←←←←←
```

### 5.2 具体场景示例

## 6. 安全与限制

### 6.1 沙箱环境
- 智能体生成的任何代码，必须在隔离的沙箱环境中先运行测试
- 严禁直接修改生产环境的核心配置
- 代码执行前需通过安全扫描

### 6.2 用户确认机制
任何以下操作，在自动化执行前必须向用户发送确认请求：

```
⚠️ 权限确认请求
检测到缺少 [XX能力]，我可以通过 [创建新技能/安装软件包/修改指令] 来解决。
是否授权执行？
- [确认] - 允许执行
- [拒绝] - 取消操作
- [仅本次] - 本次会话有效
```

### 6.3 成本控制
- 设置每日"自我反思"调用上限
- 批量存储记忆，减少API调用
- 对低价值操作进行节流

### 6.4 行为边界
以下行为被禁止：
- ❌ 修改自身核心指令（System Prompt）
- ❌ 安装未经用户授权的软件包
- ❌ 创建可能产生安全风险的代码
- ❌ 在外部存储中保存敏感用户数据

## 8. 实施建议

### 8.1 技术选型
- 向量数据库: Milvus / Pinecone / ChromaDB
- 代码执行: Docker沙箱 / 安全的代码解释器
- 存储: Redis + PostgreSQL

### 8.2 集成方式
- 支持Function Calling的LLM
- 支持工具动态注册的Agent框架
- 支持长期记忆的向量存储

### 8.3 最佳实践
1. **渐进式启用**: 先开启复盘，逐步启用自动修复
2. **保守策略**: 初期对自动化操作保持谨慎
3. **透明记录**: 所有自我修改都记录日志
4. **用户可控**: 始终保留用户干预的入口
