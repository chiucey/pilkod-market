# 纸巾产品可靠性评分 Skill（单文件可移植版）

## 1. 用途

当你已经拿到一款纸巾产品的包装字段，或需要先从图片中提取这些字段后，再评估该产品的安全性、可信赖程度时，使用本 skill。

本 skill 支持：

- `面巾纸`
- `卫生纸`

本 skill 不支持：

- `湿纸巾`
- `棉柔巾`
- 其他非纸巾类卫生用品

如果产品名称命中不支持范围，仍可继续输出报告，但必须明确标注：`当前产品超出本 skill 的 V1 支持范围，结论仅供参考。`

## 2. 输入字段

必须优先从包装印刷信息中提取以下 11 个字段：

- `产品名称`
- `主要原料`
- `产品等级`
- `卫生标准`
- `执行标准`
- `委托方（或品牌方）`
- `委托方（或品牌方）地址`
- `生产企业`
- `生产企业地址`
- `生产企业卫生许可证号`
- `商标或品牌`

将以下值视为缺失：

- 空字符串
- `null`
- `none`
- `n/a`
- `未知`
- `不详`
- `待确认`
- `未提供`

## 3. 缺失字段处理

在开始评分前，必须先一次性检查全部 11 个字段是否完整。

如果存在缺失，必须一次性追要全部缺失字段，使用类似格式：

`请补充以下字段后再继续评分：字段A、字段B、字段C`

不要一个字段一个字段地追问。

## 4. 子类识别规则

### 4.1 面巾纸关键词

- `面巾纸`
- `抽纸`
- `手帕纸`
- `餐巾纸`
- `面纸`
- `纸巾`

### 4.2 卫生纸关键词

- `卫生纸`
- `卷纸`
- `厕纸`
- `卷筒纸`
- `手纸`
- `厕用纸`

### 4.3 排除关键词

- `湿巾`
- `湿纸巾`
- `棉柔巾`
- `洗脸巾`

### 4.4 判定要求

- 如果命中排除关键词，标记为 `unsupported`
- 如果能明确识别为 `面巾纸` 或 `卫生纸`，按支持范围继续
- 如果无法明确识别，但整体仍像纸巾类产品，可继续评分，并在名称项适当降分

## 5. 静态评分规则

满分 `100` 分。

### 5.1 字段权重

| 字段 | 权重 |
|------|------|
| 生产企业 | 15 分 |
| 产品名称 | 10 分 |
| 主要原料 | 10 分 |
| 产品等级 | 10 分 |
| 卫生标准 | 10 分 |
| 执行标准 | 10 分 |
| 委托方（或品牌方） | 10 分 |
| 生产企业卫生许可证号 | 10 分 |
| 委托方（或品牌方）地址 | 5 分 |
| 生产企业地址 | 5 分 |
| 商标或品牌 | 5 分 |

### 5.2 产品等级（10 分）

- `优等品` -> 10 分
- `一等品` -> 5 分
- `合格品` -> 1 分
- 其他或缺失 -> 0 分

### 5.3 主要原料（10 分）

- 含 `100% 原生` -> 10 分
- 含 `原生` 但不含 `100%` -> 7 分
- 含 `纯` -> 5 分
- 其他可识别原料 -> 1 分
- 缺失 -> 0 分

### 5.4 卫生标准（10 分）

- 归一化后命中 `GB15979` -> 10 分
- 其他或缺失 -> 0 分

标准号比较时允许空格、斜杠、短横线和年份差异，例如：

- `GB 15979`
- `GB15979`
- `GB/T 20808-2011`

### 5.5 执行标准（10 分）

- 归一化后命中 `GB/T 20808` -> 10 分
- 归一化后命中 `GB/T 20810` -> 3 分
- 其他或缺失 -> 0 分

### 5.6 产品名称（10 分）

- 名称明确属于目标纸巾家族，且与其他字段一致 -> 10 分
- 名称模糊但大体可判断 -> 5 分
- 名称与标准或品类冲突 -> 2 分
- 无法判断 -> 0 分

### 5.7 商标或品牌（5 分）

- 品牌信息清晰，且可与委托方信息形成稳定映射 -> 5 分
- 品牌存在但主体映射不稳定 -> 3 分
- 无品牌或明显混乱 -> 0 分

品牌明显混乱的示例：

- 一个字段里堆叠多个不相关品牌
- 品牌和企业主体完全无法建立任何映射

## 6. 动态核验规则

如果当前平台配置了 QCC MCP，则按以下规则调用。

如果没有配置 MCP 或调用失败，不要瞎猜，要把相应项标记为 `待核验`。

### 6.1 预期可用 MCP Tools

- `qcc-company / get_company_registration_info`
- `qcc-risk / get_administrative_penalty`
- `qcc-operation / get_news_sentiment`
- `qcc-operation / get_product_spot_check`
- `qcc-ipr / get_trademark_info`
- `qcc-operation / get_administrative_license`
- `qcc-operation / get_qualifications`

调用参数默认使用：

```json
{
  "searchKey": "企业名称"
}
```

### 6.2 委托方（10 分）

- 企业查无结果或已注销 -> 0 分
- 企业状态正常，且未发现重大负向信息 -> 10 分
- 每发现 1 类负向信息扣 2 分，扣至 0 分为止
- 如果企业核验未完成 -> `待核验`

负向信息类型：

- 行政处罚
- 严重负面舆情或信任危机
- 抽查不合格

同类负向信息只扣一次，不因同类多条重复累计。

### 6.3 委托方地址（5 分）

- 地址与登记地址一致，且真实可追溯 -> 5 分
- 地址不一致或无法核验 -> 0 分
- 若基础地址链路未完成 -> `待核验`

### 6.4 生产企业（15 分）

- 企业查无结果或已注销 -> 0 分
- 企业状态正常，且未发现重大负向信息 -> 15 分
- 每发现 1 类负向信息扣 3 分，扣至 0 分为止
- 如果企业核验未完成 -> `待核验`

### 6.5 生产企业地址（5 分）

- 地址与登记地址一致，且真实可追溯 -> 5 分
- 地址不一致或无法核验 -> 0 分
- 若地址链路未完成 -> `待核验`

### 6.6 生产企业卫生许可证号（10 分）

- 能联网核验到有效且匹配的许可证号 -> 10 分
- 查不到、过期、与品类不匹配 -> 0 分
- 若当前无法完成联网核验 -> `待核验`

## 7. 行政处罚明细展示规则

如果通过 MCP 查到企业存在行政处罚记录：

- 必须列出具体处罚条目
- 只列最近 `3` 年的处罚条目
- 每条尽量展示以下字段：
  - `处罚日期`
  - `处罚机关`
  - `处罚结果`
  - `文书号`
  - `处罚金额`

如果没有以上全部字段，也要尽量展示 QCC 返回里最能代表该处罚的可用信息。

## 8. 执行流程

**执行顺序必须严格遵守，不得跳过任何步骤。**

1. 接收用户输入，或先从图片中提取包装字段
2. 确认纸巾子类是否在支持范围内
3. 检查 11 个关键字段是否完整
4. 如果缺失，则一次性追要全部缺失字段并暂停
5. 执行静态字段评分
6. **【强制】执行企业核验**
7. 根据核验结果计算企业相关得分
8. 聚合总分
9. 输出结构化评分报告

## 9. 企业核验（强制执行）

**触发条件**：当需要获取 SKILL.md 中涉及的以下信息时，必须执行企业核验：
- 委托方（品牌方）的工商信息、企业状态、信誉情况
- 生产企业的工商信息、企业状态、信誉情况
- 行政处罚记录、舆情信息、抽查结果
- 卫生许可证核验

**【强制】脚本调用**：

当需要查询企业相关信息时，必须执行以下脚本：

```bash
# 核验委托方（如：品牌方/委托方名称）
python scripts/qcc_verify.py --company "委托方企业全称" --check-type all

# 核验生产企业
python scripts/qcc_verify.py --company "生产企业全称" --check-type all
```

**脚本返回结果的使用**：

| 脚本输出字段 | 对应评分维度 | 得分规则 |
|-------------|-------------|---------|
| `risk_info.company_status` | 委托方/生产企业 | 已注销/吊销=0分，存续=满分 |
| `risk_info.credit_score` | 委托方/生产企业 | 直接使用（满分10，每类负向-2~3分） |
| `risk_info.negative_info` | 风险提示 | 列出所有负向信息类型 |
| `risk_info.penalty_records` | 行政处罚明细 | 列出最近3年处罚记录 |

**禁止行为**：
- ❌ 不得跳过企业核验步骤
- ❌ 不得基于猜测或假设给企业打分
- ❌ 不得将"待核验"项标记为已完成
- ❌ 不得伪造核验结果

**特殊情况**：如果脚本调用失败（如网络问题、API不可用），该企业相关项必须标记为 `待核验`，不得自行推断分数。

## 10. 暂定分规则

只要存在动态项 `待核验`：

- 总分显示为 `暂定总分`
- 仅累计当前已完成的数值项
- 单独展示 `待核验最高影响分`
- 综合结论前加 `暂定`

## 11. 输出要求

输出必须包含：

- 产品信息
- 评分明细
- 综合得分
- 综合结论
- 风险提示
- 未完成核验项
- 信息来源

当企业核验未完成时，必须明确展示：

- 哪些查询成功
- 哪些查询失败
- 哪些结论只基于静态字段

## 13. QCC MCP 配置与授权

本 skill 需要调用 QCC（企查查）MCP 进行企业核验。

### 12.1 获取 QCC API Key

1. 登录 [QCC 开放平台](https://agent.qcc.com/)
2. 在个人中心或 API 管理页面获取 API Key
3. 复制 API Key 备用

### 12.2 MCP Server 配置

**方式一：直接在目标平台配置（推荐）**

在目标平台的 MCP 配置页面添加以下 4 个 Server，URL 保持不变，Authorization 填写你的 Bearer Token：

| Server 名称 | URL |
|-------------|-----|
| `qcc-company` | `https://agent.qcc.com/mcp/company/stream` |
| `qcc-risk` | `https://agent.qcc.com/mcp/risk/stream` |
| `qcc-ipr` | `https://agent.qcc.com/mcp/ipr/stream` |
| `qcc-operation` | `https://agent.qcc.com/mcp/operation/stream` |

Header 配置：`Authorization: Bearer <你的QCC_API_KEY>`

**方式二：使用下方配置模板**

将以下 JSON 复制到目标平台的 MCP 配置位置，**只需修改 `Authorization` 后面的 Token 值**：

```json
{
  "mcpServers": {
    "qcc-company": {
      "url": "https://agent.qcc.com/mcp/company/stream",
      "headers": {
        "Authorization": "Bearer <在此填入你的QCC_API_KEY>"
      }
    },
    "qcc-risk": {
      "url": "https://agent.qcc.com/mcp/risk/stream",
      "headers": {
        "Authorization": "Bearer <在此填入你的QCC_API_KEY>"
      }
    },
    "qcc-ipr": {
      "url": "https://agent.qcc.com/mcp/ipr/stream",
      "headers": {
        "Authorization": "Bearer <在此填入你的QCC_API_KEY>"
      }
    },
    "qcc-operation": {
      "url": "https://agent.qcc.com/mcp/operation/stream",
      "headers": {
        "Authorization": "Bearer <在此填入你的QCC_API_KEY>"
      }
    }
  }
}
```

### 12.3 可用的 MCP Tools

配置完成后，以下 tools 可用：

| Tool | 用途 |
|------|------|
| `qcc-company / get_company_registration_info` | 查询企业工商信息 |
| `qcc-risk / get_administrative_penalty` | 查询行政处罚记录 |
| `qcc-operation / get_news_sentiment` | 查询舆情信息 |
| `qcc-operation / get_product_spot_check` | 查询抽查不合格记录 |
| `qcc-ipr / get_trademark_info` | 查询商标信息 |
| `qcc-operation / get_administrative_license` | 查询行政许可证 |
| `qcc-operation / get_qualifications` | 查询企业资质 |

调用参数格式：`{"searchKey": "企业名称"}`

### 12.4 授权失效处理

如果在调用 MCP 时返回未授权、401、403、token expired 等错误：

1. 复制上述配置模板
2. 将 `<在此填入你的QCC_API_KEY>` 替换为新的 API Key（Bearer Token）
3. 更新目标平台的 MCP Server 配置
4. 不要伪造企业、品牌或许可证核验结果
5. 将以下动态项标记为 `待核验`：
   - `委托方`
   - `委托方地址`
   - `生产企业`
   - `生产企业地址`
   - `生产企业卫生许可证号`

### 12.5 快速定位配置项

当 QCC API Key 过期时，搜索本文件中的 `<在此填入你的QCC_API_KEY>` 即可快速定位所有需要修改的位置（共4处）

## 14. 跨平台移植说明

本文件是单文件版 skill，适合直接导入其他支持 Markdown Prompt / Skill / Agent Instruction 的平台。

但要注意：

- 本文件本身不携带 API key（请在第12.2节配置模板中填入你的 QCC API Key）
- 本文件本身不携带 MCP server
- 如果目标平台也配置了同名或等价的 QCC MCP tools，则可执行完整动态核验
- 如果目标平台没有这些 tools，也仍然可以完成：
  - 字段缺失检查
  - 静态评分
  - 暂定报告输出

## 15. 使用要求

执行时必须遵守以下原则：

- 只基于真实收到的字段和真实查询到的核验结果判断
- 不要补猜包装字段
