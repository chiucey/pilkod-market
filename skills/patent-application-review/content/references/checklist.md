# 专利申请文本校核 — 详细检查规则

## 1. 说明书摘要

### 1.1 字符数检查
- 统计摘要全文的总字符数（包括汉字、标点符号、英文字母、数字）
- 上限为300字
- 如果超过300字，指出具体超出多少字，并建议精简方向（通常可精简冗余描述或重复内容）

### 1.2 内容覆盖与禁止内容
- 摘要应涵盖所有独立权利要求的主题名称（方法、装置、系统等）
- 摘要中**不应出现**"其特征在于"这一表述——这是权利要求书的专用语，不应出现在摘要中
- 检查方法：搜索"其特征在于"关键词

---

## 2. 摘要附图

### 2.1 附图来源
- 摘要附图必须是说明书附图中的一张
- 特别注意：如果说明书附图曾经进行过修改，需确认摘要附图引用的是最终版本
- 检查方法：确认摘要附图编号存在于说明书附图列表中

### 2.2 与独立权利要求的对应性
- 摘要附图最好能与独立权利要求对应
- 具体标准：附图中应能覆盖独立权利要求中提到的所有附图标记
- **分层检查策略**：
  1. **优先 — OCR 识别**：使用 Read 工具读取摘要附图，提取图中所有可见的数字标记（阿拉伯数字），与独立权利要求中出现的附图标记做包含关系检查。若独权中的所有标记均在图片中出现 → 通过；若有缺失 → 报告具体差异
  2. **降级 — 人工确认**：若 Read 工具无法从图片中识别文字内容（如图片为照片、分辨率过低、工具不支持 OCR），则不进行自动判断，在报告中标注"需人工确认"，并在 Word 批注中提醒用户核对

## 3. 权利要求书

### 3.1 编号检查
- 各权利要求应按自然数顺序连续编号：1、2、3……
- 不能跳号、重号

### 3.2 引用关系检查
- 从属权利要求的引用关系必须正确
- 不能自己引用自己（如"根据权利要求1所述的..."出现在权利要求1中）
- 从属权利要求只能引用在前的权利要求
- 多项从属权利要求不能引用另一多项从属权利要求
- 引用格式应为"根据权利要求X所述的..."

### 3.3 主题名称一致性
- 每条权利要求的主题名称（如"一种XXX的方法"）应与发明创造总名称保持一致
- 如果发明名称为"一种智能控制系统及方法"，则权利要求中的主题名称应涵盖"智能控制系统"和"智能控制方法"

### 3.4 句号检查
- 每条权利要求的全文应只有一个句号，且位于权利要求的结尾处
- 如果权利要求中间出现句号，说明可能存在断句错误
- 权利要求内部各技术特征之间通常用分号或逗号分隔

### 3.5 "所述"引用基础检查
- 权利要求中每次使用"所述"时，前文必须已经引入过该技术特征
- 检查方法：对每个"所述XXX"，向前追溯是否已出现"XXX"或"一个/一种XXX"的首次引入
- 如果"所述"无引用基础，属于严重问题

### 3.6 术语一致性
- 相同的技术术语在权利要求书和说明书中应采用完全相同的表述
- 例如不能一处写"连接件"另一处写"联接件"，一处写"控制模块"另一处写"控制器模块"
- 检查方法：提取所有技术术语，比对是否存在同义不同形的情况

### 3.7 附图标记一致性
- 每个附图标记应唯一对应一个技术特征
- 不能出现多个不同技术特征使用同一附图标记的情况
- 检查方法：建立"附图标记→技术特征"的映射表，检查是否有冲突

### 3.8 错别字与语句通顺
- 逐句检查是否有明显错别字（包括英文词汇拼写）
- 检查是否有明显不通顺的语句
- 注意中英文标点混用问题

### 3.9 模糊词汇检查
- 权利要求中不应出现使保护范围不清楚的词汇
- 禁止词汇列表："例如"、"约"、"大概"、"大致"、"左右"、"基本上"（除非有明确定义）、" preferably"等
- 检查方法：关键词搜索

### 3.10 括号使用检查
- 权利要求中只允许在以下情况使用括号：
  - 附图标记后的括号，如"连接件(1)"
  - 公式中的括号
- 其他情况下不应出现括号
- 检查方法：找出所有括号，逐一判断是否属于允许的用途

### 3.11 权要与说明书一致性
- 权利要求复制到说明书（发明/实用新型内容部分）后，如果对其中一处进行了修改，另一处必须同步修改
- 检查方法：将权利要求书文本与说明书对应段落进行逐字比对

### 3.12 公式与化学式完整性
- 涉及公式或化学式的权利要求，检查是否有乱码、空白或缺失
- 公式中的上下标是否正确显示
- 化学式中的元素符号是否正确

### 3.13 全文错别字检查
- **与 3.8 的区别**：3.8 关注"明显"错别字的人工可感知错误；3.13 尽可能利用语言模型的语义理解能力，识别更隐蔽的拼写异常
- 检查范围：全文（包括摘要、权利要求书、说明书各子段落——技术领域、背景技术、发明内容、附图说明、具体实施方式），不限于某一板块
- 检查方法：
  1. 逐句审读全文文本，对具体实施方式等长篇段落需逐字深度检查
  2. 识别以下类型的错误：
     - 同音错字（如"在"与"再"、"的"与"地"、"做"与"作"、"转交"与"转角"、"宗华"与"综合"等）
     - 形近错字（如"未"与"末"、"已"与"己"、"人"与"入"等）
     - 英文拼写错误（即使非技术术语也应指出）
     - 多字/漏字导致的语义异常
     - **冗余字词**：多余的"给""的"等影响语义通顺的字词（如"以给NOx的排放量"中"给"字冗余）
  3. 对每个发现的可疑字词标注具体位置（段落/行号）和建议修正
- 严重程度：一般

### 3.14 全文标点全角检查
- 检查范围：全文所有中文内容区域，包括说明书摘要、权利要求书、说明书各子段落（技术领域、背景技术、发明内容、附图说明、具体实施方式）——不限于权利要求书
- 要求：中文文档中的标点符号应使用全角形式
- 全角标点示例：，（逗号） 。（句号） ；（分号） ：（冒号） ""（引号） （ ）（括号） ！（感叹号） ？（问号）
- 半角标点（应避免）：, . ; : \" ( ) ! ?
- 检查方法：
  1. 逐字符扫描全文所有子段落
  2. 区分中文内容区域与英文/数字区域（英文术语、数字编号、网址、邮箱等允许半角标点）
  3. 在中文上下文中发现半角标点 → 报告位置并建议替换为全角
  4. 特别注意括号：中文中的括号应为全角"（）"，而非半角"()"
  5. **特别注意引号**：中文语境中的引号应为全角""（U+201C/U+201D），而非半角英文双引号""（U+0022）；pandoc 转换后 markdown 中表现为 `\"` 的即为半角引号
  6. **特别注意逗号**：中文语境中的逗号应为全角"，"（U+FF0C），而非半角","（U+002C）
- 严重程度：建议

### 3.15 权利要求书公式字符解释检查
- 适用条件：权利要求书中出现公式（以图片 `media/imageX.png` 或 LaTeX `$...$` / `$$...$$` 形式）
- **分层检查策略**：
  1. **优先 — 公式读取与字符提取**：使用 Read 工具读取公式图片，或直接解析 LaTeX 代码，提取公式中每一个独立字符/变量（如 `F=ma` 提取出 F、m、a；`E=mc²` 提取出 E、m、c）
  2. 在包含该公式的权利要求范围内，搜索是否逐一出现对各字符的解释性文字（如"其中，F为作用力，m为质量，a为加速度"）
  3. 若存在未被解释的字符 → 列出"公式中字符 X 未在权利要求中得到解释"
  4. **降级**：若无法读取公式内容（图片模糊、格式不兼容等），标注"需人工核实"，不做自动判断
- 严重程度：严重（权利要求中公式参数无定义将导致保护范围不清）

### 3.16 全文上下标格式一致性检查
- 检查范围：全文（摘要、权利要求书、说明书）
- 检查目标：同一字符序列在全文各处的上下标格式是否保持一致
- 上下标存在形式：
  - Unicode 上下标字符（如 H₂O 中的 ₂、CO₂ 中的 ₂、m² 中的 ²、10³ 中的 ³ 等）
  - 原文中通过 `<sub>`/`<sup>` 或 markdown `~...~`/`^...^` 标记的上下标
  - 常见易出现不一致的字符序列：H2O/CO2/SO2/NO2（化学式中的下标数字）、m2/m3/cm2/mm2（单位中的上标数字）、10-3/10-6（负指数）等
- 检查方法：
  1. 在全文范围内搜索所有包含潜在上下标位置的字符序列（如字母后紧跟数字的模式 `[A-Za-z]\d+`）
  2. 对每个独特序列（如"H2O"），收集其在全文每一处出现时的具体形式（是"H₂O"还是"H2O"）
  3. 若同一序列存在不一致（如摘要用"H₂O"而具体实施方式用"H2O"）→ 报告"全文上下标格式不一致"，列出各处具体形式和位置
  4. 不应简单判定"有上下标"或"无上下标"谁对谁错，而是报告不一致本身，由人工决定以哪个为准
- 严重程度：一般

## 4. 说明书

### 4.1 发明名称长度
- 非化学类申请的发明名称不应超过25个汉字
- 化学类申请可适当放宽
- 检查方法：统计名称字符数

### 4.2 名称覆盖独权主题
- 发明名称应涵盖所有独立权利要求的主题名称
- 例如：如果独权包括"方法"和"装置"两个主题，名称中应同时体现

### 4.3 主题名称全文一致
- 在技术领域、背景技术、发明内容、具体实施方式等各部分中出现的主题名称，应与标题完全一致
- 检查方法：全文搜索主题名称，比对各处表述

### 4.4 子标题检查
- 说明书应包含以下标准子标题（顺序不可变）：
  - 技术领域
  - 背景技术
  - 发明内容（或"实用新型内容"）
  - 附图说明
  - 具体实施方式
- 特别注意"发明内容"与"实用新型内容"不要混用

### 4.5 附图说明与附图一致性
- 附图说明中列出的附图数量和编号，应与说明书附图部分实际包含的附图完全一致
- 不能出现"附图说明"中提到图5，但实际没有图5的情况
- 反之亦然

### 4.6 附图标记格式
- 附图说明中，附图标记的格式应规范
- 不应出现多余的连字符"-"、顿号"、"、逗号"，"等
- 标准格式示例："图1为本发明实施例提供的结构示意图；"

### 4.7 附图标记与"其特征在于"
- **发明/实用新型内容部分**：技术特征后通常**不带**附图标记
- **具体实施方式部分**：技术特征后通常**带**附图标记
- 从权利要求复制粘贴时常见问题：
  - 发明内容部分残留了附图标记和括号
  - 发明内容部分残留了"其特征在于"（这是权利要求专用语）

### 4.8 表格空白项
- 说明书中的表格不应存在未做任何文字说明的空白单元格
- 如果某项无数据，应填写"无"或做适当说明

### 4.9 乱码与错别字
- 逐段检查是否出现不明的"？"或乱码字符
- 特别关注公式区域，公式转换时容易出现乱码
- 检查是否有明显错别字和不通顺的语句
- **同音错字排查**：特别注意同音错字（如"转交"→"转角"、"宗华"→"综合"等），这类错误在快速扫描中容易遗漏，需逐字深度审读
- **冗余字词排查**：注意多余的"给""的"等影响语义通顺的字词（如"以给NOx的排放量"中"给"字冗余，应为"以NOx的排放量"）
- **不明符号排查**：检查段落中（特别是段尾、公式与正文交界处）是否出现不应存在的特殊符号，如箭头（→←↔）、数学运算符（∈∉∑∏等）或其他非中文标点、非正常文本字符。此类符号可能是公式转换残留或编辑器自动插入，在专利正式文本中不应出现
- **形近符号排查**：系统性检查全文中AI常用生成的形近异体字符是否替代了正确符号。此类问题视觉上不易察觉，但属于Unicode编码错误，可能导致显示异常或检索困难。以下为完整对照表，检查时应逐字符扫描全文，对每个字符判断是否属于下表中的"错误"列：

  |------|----------------------|---------|------|
  | 度符号 | º U+00BA（阳性序数指示符） | ° U+00B0（度符号） | 视觉相似但语义完全不同 |
  | 度符号 | ˚ U+02DA（上方圆环） | ° U+00B0（度符号） | 修饰符，非度符号 |

  | 间隔号 | ∙ U+2219（圆点运算符） | · U+00B7（间隔号/中点） | 数学运算符非间隔号 |

- **用语一致性**：比对摘要、发明内容、具体实施方式中相同技术表述是否统一（如"减少"与"减小"不应混用）
- **注意**：空格不应视为换行或断句依据，文档中的空格可能是排版需要，不应据此判定段落断裂

### 4.10 附图提及完整性
- 说明书附图中的每一张图都应在具体实施方式中被提及和描述
- 检查方法：提取所有附图编号（图1、图2...），在具体实施方式中逐一搜索

### 4.11 附图标记反向核查
- 说明书文字部分提到的所有附图标记，都应能在说明书附图中找到对应
- 检查方法：提取文字中所有附图标记，与附图列表比对

### 4.12 段落结尾标点
- 说明书中每个段落结尾应有适当的标点符号（句号、分号、冒号等）
- 不应出现段落以无标点结尾的情况
- **冒号"："也视为合法结尾标点**：常见于引出后续列表或说明的段落（如"包括以下内容："）

### 4.13 多主语主题全名称位置检查
- **适用条件**：专利名称包含两个或两个以上主语，即标题中出现"及""和""、"等连接词分隔多个主体，如：
  - "一种xxx设备及方法"
  - "一种xxx方法及工件"
  - "一种x，一种包含x的A，一种包含A的B"
  - 其他类似多主语表述
- 若标题为单一主语（如"一种池子液位变送器固定装置"），此项自动跳过（标注"不适用"）
- **允许位置**（全名称仅可在以下位置各出现一次）：
  - 说明书摘要
  - 说明书首行标题（通常紧随"说明书"之后的第一行）
  - 技术领域部分（通常为"本实用新型涉及xxx技术领域，具体而言，涉及一种xxx"）
- **禁止位置**（全名称不应在以下位置出现）：
  - 发明内容/实用新型内容子标题之后的段落
  - 权利要求书中的任何位置
  - 具体实施方式中的任何位置
  - 说明书其他任何不在允许列表中的位置
- **检查方法**：
  1. 首先判断标题是否为多主语（搜索"及""和""、"等连接词）
  2. 若为多主语，以专利全名称作为搜索关键词全文检索
  3. 列出全名称在文中每次出现的位置（所属章节/段落）
  4. 逐一判断每个出现位置是否在"允许位置"列表中
  5. 若存在禁止位置的全名称出现 → 报告"全名称在不应出现的位置（xxx）出现"，建议删除或替换为主题简称
- **严重程度**：一般（多主语案件中格式常见错误，可能导致补正）

### 4.14 说明书公式字符解释检查
- 适用条件：说明书中出现公式（以图片 `media/imageX.png` 或 LaTeX `$...$` / `$$...$$` 形式），且该公式未在权利要求书中出现
- **注意**：已在 3.15 中检查过的权利要求公式，不重复检查；此项仅针对说明书独有的公式
- **分层检查策略**：
  1. **优先 — 公式读取与字符提取**：使用 Read 工具读取公式图片，或直接解析 LaTeX 代码，提取公式中每一个独立字符/变量
  2. **逐一枚举**：对每个公式逐字列出所有独立字符，包括微分/积分符号中的变量（如 `dQ/dθ` 中的 Q 和 θ，`dp/dθ` 中的 p 和 θ，`dV/dθ` 中的 V 和 θ），**不因看似标准 notation 而跳过**
  3. 在说明书的"具体实施方式"部分中，搜索是否逐一出现对各字符的解释性文字（如"其中，F为作用力，m为质量，a为加速度"）
  4. 若存在未被解释的字符 → 列出"公式中字符 X 未在具体实施方式中得到解释"
  5. **降级**：若无法读取公式内容（图片模糊、格式不兼容等），标注"需人工核实"，不做自动判断
- 严重程度：一般

### 4.15 子标题位置检查
- 说明书中的各标准子标题（技术领域、背景技术、发明内容/实用新型内容、附图说明、具体实施方式）应为所在段落的起始文本，即子标题前不应有其他文字内容
- 各子标题的起始位置（缩进量）应对齐于同一竖线，在 docx 中表现为段落缩进一致
- **检查方法**：
  1. 列出说明书中各子标题"技术领域""背景技术""发明内容"或"实用新型内容""附图说明""具体实施方式"
  2. 检查每个子标题是否为该段落的**首部文本**（子标题前不应有其他文字，允许前导空格/缩进）
  3. **使用 python-docx 读取各子标题段落的 `first_line_indent` 和 `left_indent` 属性**，逐个比对是否一致（pandoc 转出的 markdown 丢失缩进信息，不可仅依赖 markdown 文本判断格式一致性）
  4. 若子标题不在段落首部 → 报告"子标题'xxx'不在段落首部位置"
  5. 若子标题缩进不一致 → 报告"子标题'xxx'与其他子标题起始位置不对齐"，列出各子标题的 indent 属性值
- **注意**："发明内容"与"实用新型内容"为互斥关系，实用新型用后者，不检查缺失的另一方
- 严重程度：建议（格式规范问题，不影响保护范围）

### 4.16 全文语意理解校核
- **与3.13/4.9的区别**：3.13检查"错别字"（字符层面的拼写错误），4.9检查"乱码与不通顺语句"（表面层面的语句问题）；本项检查"语意正确性"——即基于对段落含义的深度理解，判断字词句是否能够正确表达对应的技术意思
- 检查范围：全文（说明书摘要、权利要求书、说明书各子段落——技术领域、背景技术、发明内容、附图说明、具体实施方式），重点为具体实施方式
- 检查方法：
  1. 逐段阅读全文，理解每个段落要表达的技术含义和逻辑关系
  2. 在理解含义的基础上，检视该段落中每个关键词语是否准确传达了该含义
  3. 识别以下类型的语义问题：
     - **用词与语境不符**：词语本身无拼写错误，但在该语境下无法正确表达技术含义（如应说"提高效率"却写"降低效率"）
     - **因果逻辑倒置**：因果关系表述与实际技术逻辑相反（如A导致B误写为B导致A）
     - **修饰对象歧义**：句子结构导致修饰关系不明确，可能产生多种理解
     - **技术动作主体/客体错位**：描述中动作的发出者或承受者与实际技术方案不符
     - **语义断层**：前后句之间逻辑不连贯，缺少必要的过渡或说明
  4. 对每个发现的语义问题标注具体位置、说明问题所在并给出修改建议
- 严重程度：一般（语义错误可能导致技术方案理解偏差，影响审查和保护范围）

## 5. 说明书附图

### 5.1 附图标记一致性
- 附图中的数字标记（阿拉伯数字）应与说明书"附图标记说明"段落中声明的标记一一对应
- **分层检查策略**：
  1. **优先 — OCR 识别与标记比对**：使用 Read 工具逐张读取说明书附图，提取每张图中所有可见的数字标记（阿拉伯数字，如 1、2、3、11、12 等），汇总为"图片中出现数字集合"。将该集合与说明书"附图标记说明"段落中声明的数字标记进行一一比对：
     - 图片有而文本无的数字 → 报告"图片中存在文本未声明的标记 X"
     - 文本有而图片无的数字 → 报告"文本声明的标记 X 在所有图片中均未出现"
     - 完全一致 → 通过
  2. **降级 — 人工确认**：若 Read 工具无法从图片中识别文字内容（如图片为实物照片而非技术线条图、分辨率过低、工具不支持 OCR、提取结果置信度过低），则不进行自动判断，在报告中标注"需人工确认"

### 5.2 附图编号与数量
- 附图编号应从"图1"开始，按自然数顺序连续
- 附图总数量应与说明书"附图说明"部分描述的数量一致
- 不能有多余或缺失的附图
