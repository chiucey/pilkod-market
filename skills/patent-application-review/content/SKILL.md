# 专利申请文本校核

## 概述

对中国专利申请文本进行系统性形式校核，覆盖五大板块：说明书摘要、摘要附图、权利要求书、说明书、说明书附图。共38项检查规则，逐项审查并输出结构化问题报告。校核完成后，还可在源 .docx 文件中以 Word 批注形式标注问题位置，生成带批注的副本文件，不修改原文任何内容。

## 工作流程

### 步骤1：读取文件

1. 用户上传的专利申请文件通常为 `.docx` 或 `.doc` 格式
2. 使用 pandoc 转换为 markdown 以便文本分析：
   ```bash
   pandoc input.docx -o output.md
   ```
3. 如果用户提供了多个文件（如权利要求书、说明书、附图分开），全部读取
4. 如果附图以图片形式提供，使用 Read 工具查看图片内容
5. **同时使用 python-docx 读取 .docx 原始段落格式属性**（如 first_line_indent、left_indent、style 等），用于 4.15 子标题位置等需要格式级检查的项目。pandoc 转出的 markdown 丢失了段落缩进等格式信息，不可仅依赖 markdown 文本判断格式一致性

### 步骤2：识别文档结构

从文本中识别以下部分（按常见顺序）：

- **说明书摘要**：通常以"摘要"或"说明书摘要"开头
- **摘要附图**：指定的一张附图编号（如"摘要附图：图1"）
- **权利要求书**：以"权利要求书"开头，包含多条编号的权利要求
- **说明书**：包含以下子标题——技术领域、背景技术、发明/实用新型内容、附图说明、具体实施方式
- **说明书附图**：图片文件，编号从图1开始

### 步骤3：逐项校核

按以下5大板块依次检查。详细规则见 [references/checklist.md](references/checklist.md)。

### 图片内容检查策略（分层执行）

涉及需查看图片内容的检查项（2.2 摘要附图与独权对应性、5.1 附图标记一致性）采用分层策略，优先尝试从图片中自动提取信息，非直接放弃。

**第一优先度 — OCR 识别与交叉比对**：
1. 使用 Read 工具读取每张附图（.png/.jpg 等），从中提取所有可见的文字信息，包括：
   - **数字**（阿拉伯数字，即各附图中的附图标记如 1、2、3、11、12、21…以及外围标记和尺寸标注中的数字）
   - **语言文字**（英文单词和中文汉字，如部件名称标注、图名、注释文字等）
2. 将从图片中提取的数字标记集合，与说明书中"附图说明"及"附图标记说明"段落中声明的标记进行一一比对：
   - 图片中出现的数字标记 → 全部应在文本中找到对应声明
   - 文本中声明的数字标记 → 全部应在至少一张图片中找到对应
   - 若存在图片有而文本无、或文本有而图片无的数字 → 判定为不一致，在报告中列出具体差异
   - 若完全一致 → 通过
3. 对于检查项 2.2（摘要附图与独权对应性）：从摘要附图中提取数字标记，与独立权利要求中出现的附图标记做包含关系检查

**第二优先度 — 降级处理**：
- 若 Read 工具无法从图片中识别出文字内容（如图片为实物照片而非技术线条图、分辨率过低、工具不支持 OCR 等），或提取结果置信度过低无法用于判断，则降级为不检测图片内容，仅在报告中标注"需人工确认"，并在源文件中对应附图的附图说明文字处添加 Word 批注提醒

### 公式内容读取策略（分层执行）

涉及公式的检查项（3.15 权利要求书公式字符解释、4.14 说明书公式字符解释）采用分层策略。

**第一优先度 — 公式识别与字符提取**：
1. 识别文档中的公式。公式可能以以下形式存在：
   - 图片形式（.png/.jpg 嵌入在文档中，常见于 pandoc 转换后的 markdown 中的 `media/imageX.png`）
   - LaTeX 代码形式（如 `$F=ma$`、`$$E=mc^2$$`）
   - 其他文本形式（MathType、OMML 等转换后的表示）
2. 对图片形式的公式，使用 Read 工具读取并提取公式中的每一个独立字符（变量名、运算符、上下标等）
3. 对 LaTeX 或其他文本形式的公式，直接解析提取各字符

**第二优先度 — 降级处理**：
- 若无法读取公式内容（如公式图片过于模糊、格式不兼容、工具不支持等），降级为标注"需人工核实"，不对公式内容做自动判断

**检查逻辑**：
- 从公式中提取每一个独立字符/变量（如公式 `F=ma` 提取出 F、m、a）
- **逐一枚举**：对每个公式逐字列出所有独立字符，包括微分/积分符号中的变量（如 `dQ/dθ` 中的 Q、θ；`dp/dθ` 中的 p、θ），不因看似标准 notation 而跳过
- 在目标文本（权利要求书或具体实施方式）中搜索是否逐一出现对该字符的解释性文字（如"F为作用力""m为质量""a为加速度"）
- 若存在未被解释的字符 → 标记为问题

#### 板块1：说明书摘要（2项）

| 编号 | 检查项 | 检查方法 |
|------|--------|----------|
| 1.1 | 总字符数（含标点与英文）是否超过300字 | 统计字符数 |
| 1.2 | 是否涵盖所有权利要求主题名称；是否误复制了"其特征在于" | 文本比对 |

#### 板块2：摘要附图（2项）

| 编号 | 检查项 | 检查方法 |
|------|--------|----------|
| 2.1 | 是否为说明书附图中的一张（特别注意曾修改过的附图） | 附图编号比对 |
| 2.2 | 是否能与独立权利要求对应（覆盖独权中所有附图标记） | 分层策略：优先OCR提取摘要附图中的数字标记→与独权标记比对；若无OCR能力则标注"需人工确认" |

| 编号 | 检查项 | 检查方法 |
|------|--------|----------|
| 3.1 | 各权利要求编号是否正确（连续） | 编号序列检查 |
| 3.2 | 是否存在引用关系错误（如自己引用自己） | 引用链分析 |
| 3.3 | 各权利要求主题名称是否与发明创造名称一致 | 文本比对 |
| 3.4 | 各权利要求是否只有结尾处一个句号 | 标点检查 |
| 3.5 | "所述"是否具有引用基础（前文是否已引入该特征） | 逐项追溯 |
| 3.6 | 相同技术术语是否采用了不同表述 | 术语一致性检查 |
| 3.7 | 是否出现多个技术特征指向同一附图标记 | 标号一致性检查 |
| 3.8 | 是否有明显错别字（含英文）和不通顺语句 | 逐句审读 |
| 3.9 | 是否出现"例如""约""大概/大致"等模糊词汇 | 关键词搜索 |
| 3.10 | 除附图标记和公式括号外，是否出现其他括号 | 括号使用检查 |
| 3.11 | 权要复制到说明书后修改了一处，另一处是否同步修改 | 交叉比对 |
| 3.12 | 涉及公式或化学式的，是否有乱码或空白 | 公式完整性检查 |
| 3.13 | 全文错别字检查：是否存在 AI 可识别的拼写错误、同音错字、形近错字 | 逐字检查，覆盖全文所有段落（权利要求书+说明书各子段落），特别注意同音错字（如"转交"→"转角"、"宗华"→"综合"）和冗余字词（如多余的"给""的"等影响语义通顺的字词），不限于"明显"错字 |
| 3.14 | 全文标点符号是否为全角（中文标点），是否存在半角标点混用（如半角逗号,、半角句号.、半角括号()、半角引号""等） | 逐字符扫描全文所有子段落（说明书摘要、权利要求书、说明书各子段落——技术领域、背景技术、发明内容、具体实施方式等），区分中文内容区域与英文/数字区域；特别注意中文语境中使用的半角引号（""）和半角逗号（,） |
| 3.15 | 权利要求书中的公式（图片或 LaTeX 形式）的每个字符变量是否在权利要求中逐一得到解释（如公式 F=ma 中 F、m、a 是否分别有文字定义） | 分层策略：优先读取公式提取字符→校对权要解释；无法读取则标注"需人工核实" |
| 3.16 | 全文中出现上下标（如 H₂O、CO₂、m²）时，同一字符串在全文各处的上下标格式是否一致，是否存在有的位置用了上下标而有的位置未用 | 全文搜索，对比同一字符串（如"H2O""CO2"等易含上下标的字符序列）的各处出现形式，识别不一致处 |

#### 板块4：说明书（16项）

| 编号 | 检查项 | 检查方法 |
|------|--------|----------|
| 4.1 | 非化学类申请的名称是否超过25字 | 字符统计 |
| 4.2 | 名称是否涵盖所有独权主题名称 | 文本比对 |
| 4.3 | 各处（技术领域等）出现的主题名称是否与标题一致 | 全文搜索 |
| 4.4 | 各子标题是否正确（特别是发明/实用新型内容） | 结构检查 |
| 4.5 | 附图说明中附图数量与编号是否与说明书附图部分一致 | 交叉比对 |
| 4.6 | 附图说明中附图标记格式是否正确（无多余"-""、""，"等） | 格式检查 |
| 4.7 | 技术特征后附图标记是否有多余括号；是否误复制了"其特征在于"（发明内容处通常不带标记，具体实施方式处通常带标记） | 分段检查 |
| 4.8 | 表格中是否存在未做文字说明的空白项 | 表格检查 |
| 4.9 | 文字中（特别是公式中）是否出现不明"？"或乱码、错别字、不通顺语句、不明符号（如箭头→←↔等非正常文本字符）、形近异体符号（如º代°等）；各处用语是否一致 | 逐段审读，对具体实施方式的每一段进行深度逐字检查，特别注意同音错字（如"转交"→"转角"）和冗余字词（如多余的"给""的"等影响语义通顺的字词）；**不明符号排查**：检查段落中（特别是段尾、公式与正文交界处）是否出现不应存在的特殊符号，如箭头（→←↔）、数学运算符（∈∉∑∏等）或其他非中文标点、非正常文本字符，此类符号可能是公式转换或编辑器残留；**形近符号排查**：系统性检查全文中AI常用生成的形近异体字符是否替代了正确符号（完整对照表见 references/checklist.md 4.9节"形近符号排查对照表"），涵盖度符号系列（º/˚/∘/◦→°）、摄氏度系列（°C/ºC/˚C→℃）、波浪号系列（~/∼→～）、破折号系列（–/―→—）、乘号系列（x/✕→×）、希腊字母系列（µ→μ、Ω(U+2126)→Ω(U+03A9)、∆/△→Δ、∑→Σ）、间隔号系列（∙/•→·）、素数符号系列（'/"→′/″）、比较号系列（﹥/﹤→>/<）等，此类问题视觉上不易察觉但属编码错误；空格不应视为换行或断句依据 |
| 4.10 | 每张附图是否都在具体实施方式中提及 | 附图编号覆盖检查 |
| 4.11 | 说明书文字中的附图标记是否都出现在说明书附图中 | 标记反向核查 |
| 4.12 | 每段结尾是否有分号/句号/冒号或类似标点结尾 | 标点检查（冒号"："也视为合法结尾标点，常见于引出列表或说明的段落） |
| 4.13 | 多主语主题（含"及""和""、"等连接词，如"一种xxx设备及方法"）的全名称是否仅出现在指定位置（摘要、说明书首行标题、技术领域各一次），而未出现在发明内容子标题后、权利要求书、具体实施方式等位置 | 全文搜索专利全名称，校核出现位置是否超出允许范围 |
| 4.14 | 说明书中出现的公式（图片或 LaTeX 形式）的每个字符变量是否在具体实施方式中得到逐一解释（如公式 F=ma 中 F、m、a 是否分别有文字定义）；仅检查权要中未出现的公式 | 分层策略：优先读取公式→**逐一枚举公式中每个独立字符（包括微分/积分符号中的变量，如 dQ/dθ 中的 Q 和 θ，不因看似标准 notation 而跳过）**→在"式中"说明中逐核是否每个字符均有定义→无法读取则标注"需人工核实" |
| 4.15 | 各子标题（技术领域、背景技术、发明内容/实用新型内容、附图说明、具体实施方式）是否均位于所在段落的首部位置，以及各子标题的起始位置是否对齐于同一竖线（即缩进一致） | 检查标题是否段首；**使用 python-docx 读取各子标题段落的 first_line_indent 和 left_indent 属性进行比对**（pandoc 转出的 markdown 丢失缩进信息，不可仅依赖 markdown 文本判断）；若所有子标题 indent 属性一致则为通过 |
| 4.16 | 全文语意理解校核：基于对每段话/每个句子含义的理解，校核该段落中的字词句是否可以正确表达对应意思；是否存在语义层面的用词不当、逻辑错误或表述歧义 | 逐段阅读全文（摘要、权利要求书、说明书各子段落），理解每个段落要表达的技术含义，然后检视该段落中每个关键词语是否准确传达了该含义；特别注意：用词与语境不符（如应说"提高"却写"降低"）、因果逻辑倒置、修饰对象歧义、技术动作的主体/客体错位等语义层面问题 |

### 步骤5：源文件批注（可选）

校核完成后，将发现的问题以 Word 批注形式写入源 .docx 文件，生成一份带批注的副本。**不修改原文任何内容**，仅在对应文字位置插入批注。

#### 5.1 构造批注 JSON

根据步骤4的校核结果，为每个"问题"和"建议"项构造一条批注记录。每条记录包含：

- `target_text`：在文档中定位的原文片段（尽量短且唯一，取问题所在的关键短语）
- `comment_text`：批注内容（描述问题和修改建议）
- `severity`：严重程度（严重/一般/建议）

将批注列表写入 JSON 文件，格式示例：

```json
[
  {
    "target_text": "大于/等于",
    "comment_text": "权利要求10中\"大于/等于\"表述不规范，建议改为\"大于或等于\"。",
    "severity": "一般"
  },
  {
    "target_text": "图1为本实用新型立体结构示意图",
    "comment_text": "附图均为实物照片而非技术线条图，建议重新绘制。",
    "severity": "一般"
  }
]
```

**选取 target_text 的原则：**
- 取问题所在位置附近的一小段原文，确保在文档中唯一可定位
- 对于附图相关问题（板块5），可定位到附图说明中的对应文字
- 对于跨段问题，定位到问题起始处的关键短语

#### 5.2 运行批注脚本

使用技能自带的 `scripts/add_docx_comments.py` 脚本：

```bash
PYTHONIOENCODING=utf-8 python scripts/add_docx_comments.py <源文件.docx> <输出文件.docx> <comments.json>
```

脚本工作原理：
- 使用 python-docx 读取源文件
- 在文档中搜索每条 `target_text`，定位到对应的 run 元素
- 在该位置插入 Word 批注标记（commentRangeStart/End/Reference）
- 创建 comments part 存储批注内容
- 保存为新文件，原文内容完全不变

#### 5.3 验证输出

脚本执行后应验证：
1. 所有批注成功添加（检查输出中的 `[OK]` 计数）
2. 未找到目标文本的数量为 0（检查 `[WARN]` 输出）
3. 输出文件可正常用 Word 打开，批注显示在对应位置

### 严重程度分类

- **严重**：影响专利保护范围或导致形式审查不合格的问题（如"所述"无引用基础、主题名称不一致、权利要求无句号等）
- **一般**：可能导致补正通知的问题（如摘要超300字、附图编号不连续、错别字等）
- **建议**：不影响合规但建议优化的问题（如术语表述可更统一、语句可更通顺等）

## 注意事项

1. **文本类检查**（板块1-4）可自动化完成，直接基于文本内容分析
2. **图片内容检查**（2.2 摘要附图与独权对应性、5.1 附图标记一致性）采用分层策略：优先使用 Read 工具对图片进行 OCR 识别，提取数字标记后与文本交叉比对；若 OCR 不可用或识别失败，则降级为标注"需人工确认"，不再做自动判断
3. 部分检查项需要**跨板块交叉比对**（如权利要求书与说明书的一致性），需完整读取所有部分后再执行
4. 对于无法从纯文本判断的项目（如附图清晰度），明确告知用户需人工核查
5. 如果文档中某些部分缺失，跳过对应检查项并在报告中注明
