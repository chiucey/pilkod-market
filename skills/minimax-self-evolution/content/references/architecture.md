# MiniMax Agent 自进化系统架构设计

## 1. 系统整体架构

### 1.1 架构原则

本系统采用分层架构设计，遵循以下核心原则：

- **模块化**：每个组件职责单一，可独立测试和部署
- **可扩展性**：支持自定义组件和扩展点
- **容错性**：具备完善的错误处理和恢复机制
- **自我优化**：内置学习和进化能力

### 1.2 架构层次

```
┌────────────────────────────────────────────────────────────────────┐
│                         用户交互层                                   │
│                    MaxHermes (赫尔墨斯)                             │
├────────────────────────────────────────────────────────────────────┤
│                         任务编排层                                   │
│                    DeerFlow (鹿流)                                  │
├────────────────────────────────────────────────────────────────────┤
│                         执行控制层                                   │
│                    MaxClaw (爪子)                                   │
├────────────────────────────────────────────────────────────────────┤
│                         进化引擎层                                   │
│               SuccessTracker · PatternExtractor                    │
├────────────────────────────────────────────────────────────────────┤
│                         记忆存储层                                   │
│               L1-L5 五层记忆体系统                                   │
└────────────────────────────────────────────────────────────────────┘
```

## 2. 组件详细设计

### 2.1 MaxHermes 组件

**职责定位**：用户交互的统一入口

**核心功能**：
- 意图识别：识别用户表达的七大类意图
- 上下文管理：维护对话状态和上下文
- 响应生成：根据意图生成结构化响应
- 偏好学习：记录和学习用户偏好

**输入输出**：
```
输入: 用户消息 (String)
输出: 意图 + 上下文 + 响应数据 (Dict)
```

**状态管理**：
- 对话历史：最近 100 条消息
- 当前意图：当前识别的用户意图
- 上下文栈：多轮对话上下文

### 2.2 DeerFlow 组件

**职责定位**：复杂任务的协调与编排

**核心功能**：
- 任务分解：将复杂目标分解为可执行子任务
- 依赖管理：构建和管理任务依赖图
- 流程控制：拓扑排序执行子任务
- 状态同步：维护任务执行状态

**任务图结构**：
```python
TaskGraph = {
    'nodes': [
        {
            'id': 'task_1',
            'type': 'atomic|composite',
            'action': '具体动作',
            'status': 'pending|running|completed|failed',
            'prerequisites': []
        }
    ],
    'edges': [
        {
            'from': 'task_1',
            'to': 'task_2',
            'type': 'depends_on'
        }
    ]
}
```

### 2.3 MaxClaw 组件

**职责定位**：底层执行的实施者

**核心功能**：
- 工具选择：根据任务选择合适的工具
- 代码生成：生成可执行代码
- 错误处理：捕获和处理执行错误
- 结果聚合：整合多步执行结果

**执行策略**：
- 串行执行：适用于有依赖关系的任务
- 并行执行：适用于独立任务
- 重试策略：指数退避，最多重试 3 次

## 3. 数据流设计

### 3.1 标准处理流程

```
用户输入
    │
    ▼
┌──────────────┐
│ MaxHermes    │ ──► 意图识别
│ 意图解析      │ ──► 上下文构建
└──────┬───────┘
       │ Intent + Context
       ▼
┌──────────────┐
│ DeerFlow     │ ──► 任务分解
│ 任务编排      │ ──► 依赖分析
└──────┬───────┘
       │ Subtask Graph
       ▼
┌──────────────┐
│ MaxClaw      │ ──► 工具选择
│ 执行控制      │ ──► 代码生成
└──────┬───────┘
       │ Results
       ▼
┌──────────────┐
│ 进化引擎     │ ──► 经验记录
│ 结果学习      │ ──► 模式提取
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 五层记忆体   │ ──► 分层存储
│ 经验持久化   │ ──► 语义索引
└──────────────┘
       │
       ▼
   响应输出
```

### 3.2 错误处理流程

```
执行错误
    │
    ▼
┌──────────────┐
│ 错误分类     │
└──────┬───────┘
       │
       ├──────► 可重试错误 ──► 指数退避重试
       │
       ├──────► 不可重试 ──► 记录失败教训
       │
       └──────► 能力边界外 ──► 记录能力缺口
                   │
                   ▼
            触发自我进化检查
```

### 4.2 记忆体后端

支持替换不同存储后端：

- L1/L2: 内存 → Redis
- L3: JSON → PostgreSQL
- L4: JSON → Pinecone/Milvus
- L5: JSON → PostgreSQL + Redis

## 5. 性能考虑

### 5.1 延迟优化

- L1 记忆：O(1) 访问
- L2 记忆：O(1) 访问
- L3-L5：异步加载，缓存热点

### 5.2 内存管理

- L1 大小限制：100 条
- L2 历史限制：50 项
- L3-L5：无硬限制，定期清理

### 5.3 并发处理

- 使用 asyncio 异步处理
- 任务图并行执行独立节点
- 记忆体访问加锁保护
