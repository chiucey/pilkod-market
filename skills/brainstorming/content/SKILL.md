# 头脑风暴 / Brainstorming

## Overview

围绕用户提供的任意主题，进行系统性的思维拓展和头脑风暴。输出包含多层级的 Mermaid 可视化图表（思维导图、关系图、流程图等），覆盖范围尽可能广泛，内容尽可能详细，并为每个维度标注明确的上限（最大范围/极端情况）与下限（最小单元/基础情况）。

## Workflow

1. **理解主题** — 明确用户输入的核心主题，识别其所属领域与关键属性
2. **维度拆解** — 从多个正交维度对主题进行拆解（见下方「拓展维度框架」）
3. **广度拓展** — 在每个维度上尽可能向外延伸，追求覆盖范围最大化
4. **深度挖掘** — 在每个分支上逐层深入，追求细节最大化
5. **上下限标注** — 为每个重要维度/分支标注明确的上限与下限
6. **可视化输出** — 使用 Mermaid 语法绘制图表，选择最适合的图表类型
7. **补充说明** — 对图表中的关键节点提供文字解释

## 拓展维度框架

对任意主题，从以下维度进行系统性拓展（根据主题相关性选择适用维度）：

### 核心维度（必选）

| 维度 | 说明 | 上限示例 | 下限示例 |
|------|------|----------|----------|
| **定义与本质** | 是什么？核心特征？ | 最广义的定义 | 最狭义的定义 |
| **组成与结构** | 由什么构成？内部结构？ | 最复杂的完整系统 | 最小不可分单元 |
| **分类与类型** | 有哪些种类？如何分类？ | 最全面的分类体系 | 最基础的二分法 |
| **功能与用途** | 能做什么？用在哪里？ | 最广泛的应用场景 | 最基本的单一用途 |

### 扩展维度（按相关性选用）

| 维度 | 说明 | 上限示例 | 下限示例 |
|------|------|----------|----------|
| **历史与演变** | 从哪来？如何发展？ | 最久远的起源 | 最近的变化 |
| **因果与影响** | 为什么？影响什么？ | 最深远的连锁效应 | 最直接的单一因果 |
| **关联与对比** | 与什么相关？有何异同？ | 最广泛的跨领域关联 | 最紧密的近似概念 |
| **规模与量级** | 有多大/多小？多快/多慢？ | 理论/物理上限 | 理论/物理下限 |
| **利弊与风险** | 优点？缺点？风险？ | 最理想情况 | 最恶劣情况 |
| **人物与角色** | 谁参与？谁受影响？ | 全人类/所有利益相关者 | 单个个体 |
| **流程与方法** | 怎么做？有什么方法？ | 最复杂的完整流程 | 最简单的一步操作 |
| **未来与趋势** | 将会怎样？可能的方向？ | 最乐观/最激进的预测 | 最保守的渐进变化 |

## 可视化图表规范

### 图表类型选择

根据主题内容特点，选择最合适的 Mermaid 图表类型：

| 场景 | 推荐图表类型 | Mermaid 语法 |
|------|-------------|-------------|
| 层级结构、分类体系 | 思维导图 | `mindmap` |
| 概念间关系、关联网络 | 关系图 | `graph TD` 或 `graph LR` |
| 时间顺序、步骤流程 | 流程图 | `flowchart TD` |
| 历史演变、阶段划分 | 时间线 | `timeline` |
| 对比分析、多维评估 | 象限图 | `quadrantChart` |
| 状态变化、条件转移 | 状态图 | `stateDiagram-v2` |

### 图表绘制规则

1. **每次输出至少包含 2 张不同类型的图表**，从不同角度呈现主题
2. **节点数量**：每张图的节点数建议在 15-60 个之间（下限：保证信息量；上限：保证可读性）
3. **层级深度**：建议 3-5 层（下限：至少 3 层保证深度；上限：不超过 5 层保证清晰度）
4. **使用中文标签**，专有名词可附英文
5. **用颜色/样式区分不同维度或层级**（使用 Mermaid 的 style/class 语法）
6. **在图表中明确标注上限与下限节点**，使用特殊样式（如加粗、不同颜色）突出显示

### 上下限标注规范

在图表和文字说明中，对每个重要维度明确标注：

- **上限 (Upper Bound)** 🔺：该维度能达到的最大范围、最极端情况、理论天花板
- **下限 (Lower Bound)** 🔻：该维度的最小单元、最基础情况、不可再分的底线

标注格式示例：
```
📊 规模维度
  🔺 上限：全球市场规模 $X万亿
  🔻 下限：单个用户最小使用单元
```

## 输出结构模板

对用户输入的主题，按以下结构输出：

```
## 🧠 [主题] — 头脑风暴

### 1. 主题概述
[一段话概括主题的本质、范围和重要性]

### 2. 思维导图：整体结构
[Mermaid mindmap — 展示主题的全景结构]

### 3. 关系图/流程图：核心关系
[Mermaid graph/flowchart — 展示关键概念间的关系]

### 4. 维度深度分析

#### 4.1 [维度名称]
- 🔺 上限：...
- 🔻 下限：...
- 关键要点：...

#### 4.2 [维度名称]
...

### 5. [可选] 附加图表
[根据主题特点选择的其他类型图表：时间线/象限图/状态图等]

### 6. 关键洞察与意外发现
[头脑风暴过程中发现的非显而易见的关联、矛盾或机会]

### 7. 进一步探索方向
[建议用户可以继续深入的 3-5 个子方向]
```

## 质量标准

- **广度**：至少覆盖 6 个不同维度的拓展
- **深度**：每个维度至少展开 3 层细节
- **上下限**：至少为 4 个核心维度标注明确的上限与下限
- **可视化**：至少输出 2 张不同类型的 Mermaid 图表
- **洞察性**：至少包含 2 个非显而易见的关联或发现
- **可操作性**：至少提供 3 个可继续深入的方向

## Common Mistakes to Avoid

1. **避免泛泛而谈** — 每个节点都应包含具体信息，而非空洞的类别名
2. **避免遗漏上下限** — 每个重要维度必须标注上限与下限，这是本技能的核心特色
3. **避免单一视角** — 必须从多个正交维度拓展，不能只沿一个方向深入
4. **避免图表过于简单** — 节点数不应少于 15 个，层级不应少于 3 层
5. **避免图表过于复杂** — 单张图节点数不应超过 60 个，否则拆分为多张图
6. **避免纯文字输出** — 可视化图表是必选项，不是可选项
7. **避免重复信息** — 不同图表应从不同角度呈现，而非重复相同内容
