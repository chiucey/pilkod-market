# 第一步 · 图像增强服务

> **职责边界（先读这一段）**
> 本包**只做一件事**：把一份原始图像或扫描 PDF，处理成「档案级可用」的增强结果，并给出**可被下游归档消费的标准化报告**。
> 本包**不做归档**：不建分类目录、不按档案命名、不写索引台账、**不持有任何既有档案信息**。每次收到输入即是一次性处理。
> 处理完成后，将结果目录整体交回调用方，由下游决定如何归档。

---

## 0. 接口契约（先定死，否则下游接不上）

**输入**

```jsonc
{
  "input": "C:/path/to/图.jpg 或 C:/path/to/dir",   // 单文件或目录
  "purpose": "证件卡 | 文档 | 票据 | 图片",          // 用途标签，缺省 auto
  "outdir": "C:/path/to/_out"                       // 结果目录，必须先创建
}
```

**输出**（全部落在 `outdir`）

```
_out/
├── enhanced/            增强后图像（未上云时为源件副本，并在报告中注明）
├── result.json          标准化报告（下游据此归档）
├── mcp_raw/             每次调用的原始响应 JSON（成本纪律：留档可复用）
└── run.log              过程日志
```

**`result.json` 字段**

```jsonc
{
  "source": { "path": "...", "md5": "...", "size": 0,

              "edge_white": true, "edge_min": 255,
              "kind": "扫描件|拍摄件", "exif": {...} },

  "verdict":  { "level": "A|B|C",
                "note": "达标/需补扫/需人工确认",
                "todo": ["..."] }
}
```

## 1. 你必须先回答的问题：这份输入要不要上云？

**第一刀：先分「扫描件」还是「拍摄件」——不要先看分辨率。**

| 类型 | 特征 | 路径 |
|---|---|---|
| **扫描件** | 正射、无背景、光照均匀 | 看 DPI：`≥300` 走**本地**（0 计费）；`<300` 视情况上云 |
| **拍摄件** | 有透视、有环境背景、光照不均 | **一律上云做几何校正，无论分辨率多高** |

> 反例警告：一份 3000×4000 的手机拍摄件按 A4 折算约 316 DPI，表面已越 300 DPI 线。若照搬 DPI 判据走本地，**畸变与木桌背景会一并入档**，达不到档案级。
> **分辨率只决定「扫描件内部」的处理路径，不能替代「这张图要不要做几何校正」的判断。**

**第二刀：判断它是否其实是「文档类图像」**

快速判据（可程序化）：

> **四缘纯白（rgb ≥ 252）＋ 宽高比 ≈ 标准纸幅（A4 0.7071 / A5 0.7071 / 横向 1.4142）⇒ 文档类图像（非拍摄件）**

命中即可走本地，0 计费。实测覆盖 797×1045、554×800 一类导出图（截图、打印转图）。

**第三刀：值得上云吗（成本闸门）**

| 情况 | 处置 |
|---|---|
| 源件折算 ≥300 DPI 的扫描件 | 本地，不要上云（云处理只会引入重编码损失且计费） |
| 属「旁证级」材料（非权属/身份/履历核心件） | 可原样装箱 0 计费，如实标注保真等级与待定项 |
| 含须原样保留的要素（见 §3） | 上云，且**禁用** `scan_image_to_pdf` |
| 纯文字、无任何图像要素 | 才可考虑 `scan_image_to_pdf` |

## 2. 标准动线（四段，逐段可回退）

```
⓪ 体检  probe.py       免费  判件体、DPI、四缘、比例、EXIF、锐度、判重
① 预处理 prepare.py    免费  摆正方向 → 剥离 EXIF → 压缩到限内 → 生成 @args.json
② 上云  call_mcp.js    计费  选工具 → 调用 → 图像落盘 → 原始响应落盘
③ 核验  verify.py      免费  几何变化率、尺寸、四缘、锐度、达标判定
④ 报告  run_step1.py   免费  汇总 result.json + run.log
```

**顺序纪律：先免费后付费。** 摆正 → 压缩 → 校验 → 上云 → 核验。摆正做错等于付费调用白跑。

用法（一站式）：

```bash
python scripts/run_step1.py --input "C:/path/图.jpg" --outdir "./_out" [--purpose 证件卡] [--cloud auto|yes|no]
```

分步用法见 `docs/操作手册.md`。

## 3. 判据速查

### 3.1 上云三条件（任一不满足，调用必失败或损坏）

1. **载荷 ≤ 1.4 MB**（base64 会膨胀 4/3；实测请求体上限约 2 MB，超限返回 HTTP 413）
2. **含防伪底纹/网纹的文档不要转 JPEG**——有损压缩会破坏细密网纹，削弱防伪可核验性
3. **大 base64 必须走 `@args.json` 文件传参**——命令行参数上限约 32 KB，一张 1440×1920 的图 base64 就有约 160 KB，必然截断

### 3.2 哪些要素必须原样保留（决定工具选择与是否禁用 OCR 重建）

> **人像 / 国徽 / 防伪底纹 / 印章 / 手写签名 / 照片** —— 任一项存在，**禁用 `scan_image_to_pdf`**。

理由（实测）：

| 要素 | 走 OCR 重建（`scan_image_to_pdf`）的后果 |
|---|---|
| 人像、国徽 | 直接丢弃（身份证正面实测只剩一张 541×126 碎片图） |
| 细密防伪网纹 | 高频纹理经矢量重建必然丢失 |
| 手写签名 | 手写体丢失或变乱码——**签名＋印章共同构成签署效力，丢了签名这份件就失去替代原件的资格** |
| 印章 | 能保留但降质为约 321px 小图嵌入 |

**注意：「通篇机打、无底纹」不等于可以走 OCR 重建**——必须检查有无手写签名。

### 3.3 工具选择

见 `docs/工具选择表.md`。速查：

| 输入 | 工具 |
|---|---|
| 证件卡/证明/票据（含人像、国徽、底纹、印章、签名） | `scan_certificate_invoice_enhance` |
| 纯文字文档，且确认无上述任何要素 | `scan_image_to_pdf`（OCR 重建，可搜索） |
| 需要去屏幕纹 / 去阴影 / 去底色 / 裁正 | `scan_remove_screen_pattern` / `scan_remove_shadow` / `scan_remove_background_color` / `scan_crop_rectify` |
| 只要超分提清晰度，不要几何校正 | `scan_image_hd_enhance` |
| 整图取文字，**免费** | `scan_general_ocr`（0 计费，可用于独立复核读数） |

### 3.4 上云前必做（否则结果不可用）

- **剥离 EXIF**：iPhone 拍摄件的 `Orientation` 标记**可能是错的**，且增强工具可能据此误旋。**以存储像素为准，不得按 EXIF 旋正。**
- **摆正方向**：横拍证件常见整体旋转 90 度且 **EXIF 无标记**，任何基于 EXIF 的自动矫正都抓不到。稳妥做法是**两向都生成、目视比对后再定**，不要赌一次。
- **建好落盘目录**：避免调用成功后存盘失败导致重调（多花一次计费）。

### 3.5 增强结果的固有特性（必须在报告中如实标注）

- **增强会改变纵横比**。同一工具、同一批次，几何校正结果**逐件不同**——不可整批假定，须逐件量化标注。
- 增强会统一漂白底衬，**印章饱和度略降**；另注意五角星等处的真实印油肌理不要误判为算法伪影（须与原图对照）。
- 云增强的输出尺寸通常约 2400×1520 一类，**未必等于标准纸幅**。不要为了凑 A4 比例而拉伸。

## 4. 红线（不可越）

| 编号 | 红线 |
|---|---|
| R1 | **API Key 绝不硬编码进任何文件，绝不写入会外传的产物**。运行时从环境变量 `QUARK_AI_API_KEY` 或调用方指定的密钥文件路径读取。 |
| R2 | **计费纪律**：每图 1 次调用；**跨页图不拆分**（一页多件时合并为一次）；调用前先建落盘目录；每次调用的原始响应必须落盘复用。 |
| R3 | **不臆测**：所有输出字段必须来自实测（像素、字节、md5、算术）。判断不了的写"需人工确认"，不得填写推测值。 |
| R4 | **敏感件提示**：身份证、护照、病历、银行凭证等，上云即等于把图像交给第三方云服务。若调用方未明确授权，**应选择本地路径或先向调用方确认**。 |
| R5 | **不落持久副本**：本包处理完即交回结果，不保留输入图像于任何长期位置。 |

## 5. 失败与回退

| 现象 | 原因 | 处置 |
|---|---|---|
| HTTP 413 | 载荷超限 | 回到 ① 压缩到长边 ≤800px、JPEG q85 |
| 返回图像是碎片、人像丢失 | 误用了 `scan_image_to_pdf` | 改用 `scan_certificate_invoice_enhance` 重调（会多一次计费，记入报告） |
| 增强后内容躺倒 | 源件方向未摆正，或按 EXIF 误旋 | 用存储像素重新摆正后重调 |
| 校验位/字段对不上 | 可能只是读数问题 | 先用免费 `scan_general_ocr` + 放大目视做三方独立读数，**再**考虑证件本身是否有瑕疵 |
| 几何变化率 > 5% | 拍摄角度残余或纸张非标准 | 如实写入报告，**绝不拉伸修正** |

## 6. 本包不做什么（避免越界）

- 不判断文书的法律效力、不做家族关系推断、不做事件链组织——**那是下游归档的职责**。
- 不同一命名规范、不建分类目录、不写索引与台账。
- 不替换、不删除任何源文件。源件一律只读。
