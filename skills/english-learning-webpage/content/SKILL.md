# 英语精听学习网页制作

目标：交付一个可直接打开的英语精听单文件 HTML。页面应使用准确文本、词级时间戳、自然中文翻译和稳定交互，让学习者能按完整句子听、看、标记进度，也能选择任意连续单词进行目标播放和复制。

## 总原则

- 始终把任务产物放入素材所在目录的 `work` 子文件夹；不要把中间文件散落在根目录。
- 创建 `work` 后，第一步就建立固定 step 子文件夹：`step01-inputs`、`step02-subtitle-alignment`、`step03-learning-data`、`step04-audio-slicing`、`step05-template-html`。每一步产物放入对应文件夹。
- 创建 `work` 后，第一步同时创建 `task.yaml` 任务进度标记文件；每完成、暂停或失败一个步骤都要更新它，让用户能直接查看当前进度、输入输出和错误状态。
- 输入素材完全由用户提供：本地视频或音频、word-level 字幕，以及可选的同名官方字幕。
- 始终使用用户提供的本地 word-level 字幕作为时间基准；如果有同名官方字幕，则用官方字幕校准文本。
- 官方字幕只允许在 `references/02-subtitle-alignment.md` 描述的字幕对齐阶段使用；对齐完成后，后续翻译、音频切片、模板注入和验证都只读取校准后的中间 JSON，不再直接读取官方字幕。
- 流程不得越级推进：Step 03 未生成并校验 `work/step03-learning-data/learning_data.json` 前，不允许执行 Step 04；Step 04 只能读取这个正式文件，不得直接读取 Step 02 的 `aligned.json` 或 Step 03 的草稿文件。
- 最终学习页只保留父句级学习单元；不要生成子字幕、子句、按逗号拆分 UI 或子句音频入口。
- 通用处理逻辑优先直接调用本技能目录下的 `scripts/*.py`，不要把通用脚本复制到项目 `work` 目录；只有项目专用的一次性修复、补翻译或异常处理脚本才放入对应 step 文件夹，便于追溯。
- 生成 HTML 时优先使用 `templates/listening_page_template.html`，只注入标题、页面 ID 和数据 JSON。需要改样式时先改模板，再用同一模板生成页面。
- 所有正文、翻译和提示内容使用自然中文说明；代码、字段名和文件名保持英文，便于脚本处理。

## 分支选择

根据当前任务只读取必要分支，避免一次性加载所有细节：

- 素材文件放置、同名匹配、输入判断：读取 `references/01-inputs-and-workspace.md`。
- 词级字幕与官方字幕对齐、纠错、断句：读取 `references/02-subtitle-alignment.md`。
- 翻译、固定搭配、连读弱读提示、JSON 瘦身：读取 `references/03-learning-data.md`。
- 需要专门生成或优化连读弱读提示时：读取 `references/rh-subagent-prompt.md`，作为子 agent 提示词使用。
- 音频切片、Base64 嵌入、相对时间轴：读取 `references/04-audio-slicing.md`。
- 模板、视觉、交互、移动端规则：读取 `references/05-template-and-ui.md`。

可复用脚本：

- 有官方字幕校准：直接调用 `scripts/01_align_with_official.py`。
- 没有官方字幕：直接调用 `scripts/02_build_from_wordlevel.py`。
- 父句音频切片与 Base64 嵌入：直接调用 `scripts/03_embed_sentence_audio.py`。
- 注入 HTML 模板：直接调用 `scripts/04_inject_html_template.py`。
- 只有当项目存在无法泛化的特殊修复时，才在 `work/stepXX-*` 中创建项目专用临时脚本；通用修复应回写到本技能 `scripts` 目录。
- 官方字幕异常词 Excel 报告模板：使用 `templates/alignment_anomalies_template.xlsx`。
- 任务进度 YAML 模板：使用 `templates/task_progress_template.yaml`。

## 标准流程

1. 盘点输入文件：找出用户提供的本地视频或音频、word-level 字幕、可选的同名官方字幕、已有翻译或学习资料。
2. 建立 `work` 目录、固定 step 子文件夹和 `task.yaml`：所有解析结果、批量翻译文件、音频切片、项目专用临时脚本和最终数据都放入对应 step 文件夹；通用脚本直接从技能 `scripts` 目录调用，`task.yaml` 保持最新进度。
3. 生成校准字幕数据：这是唯一直接使用官方字幕的阶段；用词级字幕提供时间，有官方字幕时用官方字幕校准文本，若没有官方字幕则用词级字幕文本并保留质量风险说明。
4. 生成父句学习数据：从第 3 步产出的校准 JSON 继续处理，只按完整句子边界分割，并补充自然中文翻译、`rh` 连读弱读提示和 `c` 固定搭配；正式产物必须是 `work/step03-learning-data/learning_data.json`。
5. 校验 Step 03：确认 `learning_data.json` 使用顶层 `sentences` 数组、每句翻译非空、`rh/c` 字段已按规则生成或明确为空；只有通过后才能把 `task.yaml` 中 Step 03 标为 `done`。


## 输出数据契约

最终注入模板的数据应为数组，每个元素代表一个父句：

```json
{
  "t": "Official English sentence.",
  "z": "自然中文翻译。",
  "s": 12.34,
  "e": 15.67,
  "a": "data:audio/mp3;base64,...",
  "w": [
    {"t": "Official", "s": 0.08, "e": 0.42},
    {"t": "English", "s": 0.43, "e": 0.80}
  ],
  "rh": [
    {"from": 0, "to": 1, "t": "safe ‿ outside"}
  ],
  "c": [
    {"p": "key phrase", "z": "中文含义"}
  ]
}
```

字段说明：

- `t`：校准后的英文父句；有官方字幕时采用官方文本，没有官方字幕时采用 word-level 字幕文本。
- `z`：自然中文翻译，不得为空或使用占位文本。
- `s/e`：父句在原音频中的绝对起止时间，保留 2 位小数。
- `a`：父句音频切片的 Base64 MP3。
- `w`：词级数组，词的 `s/e` 必须是相对父句音频切片起点的时间。
- `rh`：可选，局部连读、弱读、失爆/不完全爆破、闪音 T 提示。优先使用 `from/to` 词组范围；提示文本只写发音标注，不写中文解释。
- `c`：可选，固定搭配或高价值短语，每句 0 到 3 个。

## 关键偏好

- 父句只能在句号、问号、感叹号或明确标题结尾处分割；不要因为字幕换行、停顿或逗号切断完整句子。
- 选中目标播放依赖词级 span：桌面端可拖选连续词，手机端点首词再点尾词。
- 选中目标后必须能复制纯英文文本；自动复制失败时提供手动复制面板。
- 当前播放词使用明黄色高亮，选中目标使用淡绿色高亮，播放高亮优先级更高。
- 支持选中单词后设置持久化的自定义底色（无底色、蓝、紫、橘、绿、红），并通过下拉菜单选择；移动端菜单自动向上弹出防止遮挡。
- Header 必须 sticky，包含收起/展开、进度文本、批量完成/重置和绿色进度条。
- 按钮文案保持 Daniel 风格：`▶ 全句播放`、`全句字幕`、`全句中文`、`固定搭配`、`完成`、`▶ 播放选中目标`、`复制选中目标`、`清除`。

## 发音标注格式

`rh[].t` 只使用以下符号化标注，不要写中文解释：

- 连读：使用 `‿`，如 `safe ‿ outside`。
- 弱读：使用 `_斜体_` 形式，如 `_to_`。
- 失爆/不完全爆破：使用括号包住弱化音，如 `righ(t)`。
- 闪音 T：使用 `t[d]`，如 `wa t[d] er`。

## 完成定义

任务完成时应交付：

- 一个最终 HTML 文件，文件名尽量无空格。
- 必要时同时交付 ZIP。
- `work` 目录中保留可追溯的中间数据，如校准后的 JSON、翻译批次、音频切片检查结果。
- 简短说明已完成的输入处理、输出位置和关键数据数量。
