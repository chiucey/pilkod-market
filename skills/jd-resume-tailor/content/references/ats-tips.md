# ATS简历优化技巧参考

## ATS（Applicant Tracking System）工作原理

### 关键词匹配
- ATS扫描简历中的关键词
- 匹配JD中的术语和短语
- 通常权重：技能词 > 行业词 > 软技能

### 常见ATS系统
- Workday（大量企业使用）
- Greenhouse
- Lever
- Taleo（Oracle）
- BambooHR

## 关键词提取策略

### 硬技能（必须匹配）
```
技术栈：Python, Java, SQL, AWS, Docker, Kubernetes
工具：Jira, Git, Jenkins, Figma
认证：PMP, AWS Certified, CPA, CFA
```

### 软技能（可选但加分）
```
领导力：mentored, led, coached, managed
成就：achieved, improved, increased, reduced
协作：collaborated, partnered, coordinated
```

### 行业术语
- 不同行业有特定表达方式
- 参考JD中的行业黑话
- 使用原词而非同义词

## 量化数据指南

### 常见量化维度
| 类型 | 示例 |
|------|------|
| 规模 | 100+人团队，1000万用户 |
| 效率 | 提升30%性能，降低50%成本 |
| 收入 | 年营收增长200万 |
| 时间 | 缩短项目周期2周 |
| 质量 | 缺陷率降低至0.1% |

### 量化表达模板
- "负责X，实现Y%提升"
- "带领X人团队，完成Y项目"
- "优化流程，节省X小时/周"
- "管理$X预算，成功交付"

## 简历改写技巧

### 动词升级表
| 低权重词 | 高权重词 |
|----------|----------|
| 做 | 主导/负责/推动 |
| 参与 | 协作/贡献/支持 |
| 学习 | 掌握/精通/运用 |
| 知道 | 了解/熟悉/理解 |

### 前后对比示例

**Before:**
```
负责公司网站开发工作
```

**After:**
```
主导企业官网全栈开发（React + Node.js），日活10万+，首屏加载优化至1.5s
```

### 简历结构优化

#### 信息密度原则
- 每份经历3-5个要点
- 每个要点1-2行
- 使用bullet points

#### 关键词布局
```
┌─────────────────────────────────┐
│ 姓名                            │
├─────────────────────────────────┤
│ 核心技能（高权重关键词放这里）    │
├─────────────────────────────────┤
│ 工作经历（关键词融入描述）       │
├─────────────────────────────────┤
│ 项目经验（具体技术栈）           │
├─────────────────────────────────┤
│ 教育背景                        │
└─────────────────────────────────┘
```

## 常见错误

### ATS不友好格式
- ❌ 图片/图标
- ❌ 复杂表格（多列合并）
- ❌ 文本框
- ❌ 页眉页脚（可能被截断）
- ❌ 两列布局（常见于设计师简历）

### 关键词堆砌
- ❌ 同一关键词重复5次以上
- ❌ 强行插入无关关键词
- ⚠️ 适度密度：15-25%

### 数据造假
- ❌ 虚构项目、职位、团队规模
- ❌ 夸大业绩比例
- ✅ 可以估算（合理范围内）
