# MMD 平台强制约束速查

> 以下所有约束均为 MMD 平台底层机制，任何设计不得以任何理由绕过。

## 容量与调用约束

| 约束 | 具体数值 | 说明 |
|------|---------|------|
| **角色人设上限** | 10000 字符 | 固定在聊天记录最顶端 |
| **世界书单条上限** | 3000 字符 | 超出内容被截断或踢飞 |
| **世界书最大条目数** | 200 条 | 平台硬上限 |
| **合计调用上限** | 15000 字符 | 角色人设 + 世界书触发总量，超出触发末位淘汰 |

---

## 末位淘汰规则

触发条件满足的条目 → 按顺序从大到小排列 → 逐条检查预算 → 能塞则塞，塞不下整条踢飞

**淘汰优先级公式：**
```
淘汰优先级 = order（越小越优先被淘汰）
同order时 = 字数越多越优先上车
```

## 关键词扫描约束

| 约束 | 值 | 说明 |
|------|---|------|
| **扫描范围** | 最新4条消息 | 固定值，不可更改 |
| **简繁自动转换** | ❌ 不支持 | 必须填写繁简双版本 |
| **递归扫描** | ❌ 不允许 | 关键词仅扫描聊天记录，不扫描世界书内容 |

---

## 角色帮派约束

| 帮派 | 位置 | 深度参数 | 特殊约束 |
|------|------|---------|---------|
| **天台帮** | 聊天记录最顶端 | ❌ 无 | 角色人设前/角色人设后，无电梯权限 |
| **电梯帮-system** | 插入聊天记录中间 | ✅ 有 | 专注力最高，当系统指令处理 |
| **电梯帮-user** | 插入聊天记录中间 | ✅ 有 | 专注力其次，当用户发言处理 |
| **电梯帮-assistant** | 插入聊天记录中间 | ✅ 有 | 专注力最弱，当AI已发言处理 |

---

## 深度参数约束

| 深度范围 | 行为 | 约束说明 |
|---------|------|---------|
| 天台帮（无depth） | 固定顶端 | 不适用深度规则 |
| 0 | 插入大堂，比最新输入更靠下 | ⚠️ 过强，慎用 |
| 1-3 | 极强印象 | ⚠️ 可能扭曲AI正常推演 |
| **4-6** | **最佳区间** | ✅ **推荐值** |
| 7-20 | 中等印象 | ✅ 可用 |
| ≥21 | 位于聊天深处 | ⚠️ 基本无效 |

---

## 触发概率约束

| 条件 | 行为 | 平台约束 |
|------|------|---------|
| 🔵 蓝灯 + 任何概率值 | 概率参数被忽略 | 强制约束 |
| 🟢 绿灯 + 概率100 | 关键词出现即触发 | — |
| 🟢 绿灯 + 概率0-99 | 关键词出现后按概率判定 | — |
| 同一关键词多条同时触发 | 同时生效（只要预算够） | — |

---

## 内容约束

| 约束 | 说明 | 违规后果 |
|------|------|---------|
| **必须含主语** | content 首句必须包含关键词对应主语完整描述 | AI 误解主语，指代混乱 |
| **禁止游戏语言** | content 中不得出现"玩家""角色""属性""判定"等 | AI 打破第四墙 |
| **无免死金牌** | 第一句话的4000字同受预算约束 | 长对话时第一句话设定同样可能被切 |

---

## 权重优先级总表（从高到低）

```
1. system 指令（最高）
2. user 发言
3. assistant 发言
4. 角色人设（顺序10000）
5. 世界书（按顺序和预算竞争）
```
