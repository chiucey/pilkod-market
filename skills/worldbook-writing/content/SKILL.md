# SKILL.md — 世界书深度撰写

## 定位

本技能专注于**世界书（World Book）的高阶撰写与精准调度**，服务目标为 Meimodu / SillyTavern 等支持世界书功能的平台。

核心能力：理解世界书的底层运行机制（AI 专注力调度），熟练运用各项参数（蓝绿灯/顺序/深度/概率/关键词），完成符合平台逻辑的高质量世界书条目设计。

---

## 核心前提：AI 运作原理

> **不理解 AI 机制，就做不好世界书。所有参数设计都服务于同一个目标：精准控制 AI 的注意力分配。**

### 双脑模型

| 区域 | 功能 | 容量特点 |
|------|------|---------|
| **左脑（设定库存区）** | 存放所有设定，按需调取 | 容量巨大，但每次只能借阅有限数量 |
| **右脑（上下文记忆区）** | AI 真正工作的地方，基于上下文生成回复 | 实际思考区域，有固定专注力上限 |

### ⚠️ 核心瓶颈：专注力上限

AI 的专注力有极限（模型级别限制，非平台设定）。这意味着：

- 聊天记录像一个**固定容量的杯子**，水满了会溢出
- 超出专注力范围的旧内容，AI "第 6 章那个卖早点的配角叫啥？鬼还记得"
- **第一句话的 4000 字没有免死金牌**，顶到杯口同样会被切掉

### 平台打包流程（完整链路）

```
用户发送消息
  → 平台从设定库调取需要的设定
  → 平台将设定按规则插入聊天记录的不同位置
  → 合并打包后发给 AI
  → AI 阅读后生成回复
```

## 世界书是什么

### 核心定义

世界书是**调度 AI 专注力的指挥棒**。

如果说角色人设 10000 字只能全部堆在聊天记录最顶端（像一群人在天台吹冷风），世界书则提供了一部**电梯**，允许将设定拆分成精细化条目，精准送到聊天记录中不同的楼层位置。

### 容量规格（MMD 平台限制）

| 区域 | 上限 | 说明 |
|------|------|------|
| 角色人设 | 10000 字符 | 固定在最顶端 |
| 世界书 | 最多 200 条，每条 3000 字 | 可精细控制插入位置 |
| **合计调用上限** | **15000 字符** | 即"魅魔大巴"总预算，超出触发末位淘汰 |

> **⚠️ MMD 平台强制约束：** 角色人设 + 世界书每次调用总额不超过 15000 字符。超出部分整条踢飞，不做保留。

## 参数体系详解

> 以下参数构成世界书的完整控制面。每个参数都服务于"把哪条设定、以什么方式、送到什么位置"这一核心问题。

### 参数一：条目名称

- **AI 可见性：** ❌ 完全不可见，仅供作者辨认
- **命名规范：** `【类型-内容概要】`，例：
  - `【世界观-蓉城地理】`
  - `【NPC-陈老板】`
  - `【场景-老茶馆】`
- **重要性：** 条目多的时候命名混乱会导致作者自己踩坑，建议统一格式

### 参数二：开关

- **功能：** 启用 / 停用某条世界书
- **使用场景：** 临时屏蔽某设定进行 A/B 测试，或在不删除内容的前提下暂停某章节设定

### 参数三：触发条件（蓝灯 vs 绿灯）

> **⚠️ MMD 平台约束：** 蓝灯和绿灯仅仅是"塞入聊天记录的方式"不同，本身没有高低之分，塞进去的过程中依然排队。

| 模式 | 标识 | 行为 | 适用场景 |
|------|------|------|---------|
| **蓝灯（常驻）** | 🔵 | 无脑塞入，聊什么都触发 | 必须时刻生效的核心规则 |
| **绿灯（关键词）** | 🟢 | 满足关键词 + 概率才触发 | 特定条件下才需要的设定 |

### 参数四：角色 & 位置

> **⚠️ MMD 平台约束：** 角色人设本身被视为顺序 10000 的世界书条目，优先级最高。

#### 天台帮（固定在最顶端）

| 位置选项 | 含义 |
|---------|------|
| **角色人设前** | 插入角色人设之前，最靠近顶端，优先级最高 |
| **角色人设后** | 插入角色人设之后，与角色人设同属顶端区域 |

#### 电梯帮（插入聊天记录中间）

| 位置选项 | 专注力权重 | AI 处理方式 |
|---------|---------|-----------|
| **system** | ⭐⭐⭐ 最高 | AI 当作必须执行的系统指令 |
| **user** | ⭐⭐ 其次 | AI 当作用户说的话 |
| **assistant** | ⭐ 最弱 | AI 当作自己曾说过的话（哪怕是编的） |

> **电梯帮深度优先规则：** 同一 role 类型下，深度数字越小，插入位置越靠近最新消息，AI 记得越清楚。

### 参数五：深度（电梯帮专属，0-99）

> **⚠️ MMD 平台约束：** 天台帮（角色人设前/后）**没有深度选项**，因为它们不许坐电梯。

| 深度范围 | 效果描述 | 风险提示 |
|---------|---------|---------|
| **深度 0** | 直接插入大堂，甚至比最新输入还靠下 | ⚠️ 极强专注力，容易使正常推演变形 |
| **深度 0~3** | 印象极其深刻，如"贴着 AI 耳朵大喊" | ⚠️ 不推荐，仅在需要强干预时使用 |
| **深度 4~6** | 最佳区间，如"前几分钟的一段回忆" | ✅ **推荐值**，自然且有效 |
| **深度 7~20** | 适中，接近中期剧情印象 | ✅ 可用 |
| **深度 ≥21** | 位于聊天记录深处 | ⚠️ 基本等于没触发，请检查必要性 |

### 参数六：顺序（0-9999）

> **⚠️ MMD 平台最核心约束。本参数直接决定末位淘汰命运，是世界书最重要的参数。**

**核心规则：**

1. **尊老不爱幼：** 数字越大 = 辈分越高 = 越先上车
2. **胖子优先：** 顺序相同时，字数多的优先上车

**角色人设默认值：** 顺序 **10000**（默认最老资历，所有世界书都要给它让路）

**末位淘汰流程：**
```
平台从顺序最大的条目开始逐条检查
  → 检查触发条件是否满足
  → 检查剩余预算是否足够容纳该条目
  → 能塞 → 带上车；塞不下 → 整条踢飞，不做保留
  → 继续检查下一条
  → 直至所有条目检查完毕 → 发车
```

**⚠️ MMD 平台强制约束：**
- 每条世界书被调用时，其完整字数（uid/order/key 等字段 + content 全部计入）
- 单条超出预算 → 整条踢飞，不做截断调用
- 绿灯条目触发后被踢飞，不会有任何报错提示，AI 直接丢失该条目

### 参数七：触发概率（0~100%）

> **⚠️ MMD 平台约束：** 蓝灯模式下此参数无效，直接忽略。

| 模式 | 行为 |
|------|------|
| 🟢 绿灯，概率 = 100 | 只要关键词出现，必触发 |
| 🟢 绿灯，概率 = 50 | 关键词出现后，再抛硬币决定（50% 概率触发） |
| 🟢 绿灯，概率 = 0 | 永不触发（除非误操作，一般不使用） |

**多条同一关键词共存时：** 如果同一关键词有多条世界书同时满足触发条件，且总字数未超预算，它们会同时上魅魔大巴，一起生效。

### 参数八：关键词（绿灯专属）

#### 扫描范围

> **⚠️ MMD 平台强制约束：** 扫描范围固定为**最新 4 条消息**（不可更改）。

#### 主要关键词 + 次要关键词

| 类型 | 逻辑 | 示例 |
|------|------|------|
| **主要关键词** | 出现即尝试激活（配合概率） | "陈老板" |
| **次要关键词** | 与主要关键词 AND 共现 | 主要=陈老板，次要=老茶馆 → 必须同时出现才触发 |

**触发条件组合示例：** 某条世界书主要关键词为 A、B，次要关键词为 1、2
→ 满足 A+1、A+2、B+1、B+2 任意一种均可触发

#### ⚠️ 关键陷阱一：必须加繁简双重版本

> **MMD 平台强制要求。** AI 在不同回复中可能输出简体或繁体字，关键词仅匹配简体 → 直接失效。建议每条世界书的主要关键词同时填写简体和繁体：
> ```
> "小张", "小張"
> ```

#### ⚠️ 关键陷阱二：无递归原则（禁止套娃）

> **MMD 平台强制规则。** 关键词只在聊天记录中扫描，**不在世界书内容里扫描**。
> - 不能指望 A 世界书的内容里出现了"香蕉"，去触发 B 世界书的"香蕉"关键词
> - 平台预判了这个操作并加以屏蔽

#### ⚠️ 关键陷阱三：省略主语

世界书名称中的主语 AI 看不到。关键词只是激活世界书，内容里必须有完整主语说明：

```
❌ 错误：女，18岁，双马尾，喜欢吃草莓
✅ 正确：小红，女，18岁，双马尾，喜欢吃草莓

❌ 错误：（标题写了"小美"，内容里只写"她是男的"）
✅ 正确：小美，小美是男的
```

## 三大实战应用模式

### 模式一：🔵 纯蓝灯用法——动态管理 + 末位淘汰

**适用场景：** 需要为不同重要程度的设定配置不同的淘汰优先级

**核心思路：** 利用顺序号实现"核心设定不被淘汰，边缘设定随时让座"

**示例：现代都市修仙**

| 条目内容 | 顺序号 | 被淘汰风险 |
|---------|-------|----------|
| 重要角色设定 | 9000 | 最后淘汰 |
| 世界大背景 | 500 | 其次淘汰 |
| 无关紧要路人甲 | 10 | **首批淘汰** |

> 当字数超标时，路人甲先飞，重要角色稳坐——"把鸡蛋放在不同篮子里"

---

### 模式二：🟢 纯绿灯用法——百分比抽奖机

**适用场景：** 随机事件、寻宝系统、命运分支

**核心思路：** 同一关键词 + 不同概率 + 顺序递增 → 套娃叠加效果

**示例：洞府寻宝**

| 条目名称 | 顺序 | 概率 | 触发内容 |
|---------|------|------|---------|
| 保底奖励 | 100 | 100% | 你翻找了一番，只发现了一堆破烂，心情很差 |
| 普通奖励 | 101 | 80% | 在破烂堆里，你意外发现了一颗止血丹 |
| 稀有奖励 | 102 | 30% | 石缝里隐隐透出蓝光，是一本残缺的功法 |
| 传说奖励 | 103 | 5% | 地砖下居然压着一把上古神兵 |

**欧皇触发时（AI 可见）：** 破烂 + 止血丹 + 残缺功法 + 上古神兵
**非酋触发时：** 只有破烂

---

### 模式三：🔵🟢 蓝绿混合——⭐最核心用法

**解决什么问题：** 绿灯触发具有**滞后性**，会导致角色"当场变性"（角色登场时 AI 瞎编，再次触发时设定才生效，产生矛盾）

#### 滞后性惨案现场

```
❌ 错误示范：
  蓝灯：光明小学，学生有小美、小红、小岚
  绿灯（关键词：小美）：小美，男，三年级，光头
  
  回合1 用户：去光明小学
  AI回复：小美穿着超短裙跳皮筋（未触发绿灯，AI按默认猜了"女"）
  
  回合2 用户：推倒她
  AI回复：小美说"我是光头男"（前后矛盾，当场变性）
```

#### ✅ 正确做法：显性常驻 + 隐性触发

| 设定类型 | 蓝灯 🔵 填写 | 原则 |
|---------|------------|------|
| **显性设定（必须正确）** | 性别、种族、外貌、衣着、性格等没有妥协余地的特质 | AI 永远不能搞错、不能瞎编的锚点 |
| **隐性设定（需要保护）** | 🟢 绿灯填写：内心秘密、口袋里的物品、背上的纹身、复杂过往 | 玩家主动探索才触发的信息 |

**🌰 丧尸感染者小明示例：**

```
蓝灯（显性锚点）：
  小明，男，在大热天也奇怪地穿着厚厚的长袖卫衣，神情紧张
  → AI 永远知道他穿着长袖，不会描写成背心

绿灯（隐性触发，关键词：小明/长袖/脱/受伤/检查/咬痕）：
  仅{{user}}主动查看时才能告知——
  小明卫衣袖子下是发黑溃烂的丧尸咬痕，他被感染了，但不敢告诉任何人
```

## MMD 平台强制约束汇总

| 约束项 | 具体限制 | 违规后果 |
|-------|---------|---------|
| **合计调用上限** | 角色人设 + 世界书 ≤ 15000 字符 | 超出部分整条踢飞，无提示 |
| **单条容量** | 每条世界书最多 3000 字 | 超出的内容被截断或踢飞 |
| **扫描范围** | 关键词扫描固定覆盖最新 4 条消息 | 旧消息中的关键词无法触发 |
| **关键词繁简** | 平台不支持简繁自动转换 | AI 输出繁体时简体关键词失效 → **必须填写繁简双版本** |
| **无递归原则** | 关键词不在世界书内容中扫描 | 套娃连锁触发被平台强制屏蔽 |
| **顺序机制** | 角色人设默认顺序 10000，为最高优先级 | 所有世界书在它面前都是弟弟 |
| **蓝灯概率无效** | 概率参数对蓝灯无效 | 写了也是白写 |
| **整条踢飞** | 条目触发后若超出预算，整条踢飞 | 不做截断调用，不报错误 |

## 输出规范

### Meimodu 标准格式

```json
{
  "entries": {
    "001": {
      "comment": "【世界观-蓉城地理】",
      "disable": false,
      "constant": true,
      "position": 1,
      "role": 0,
      "depth": 5,
      "order": 9000,
      "probability": 100,
      "key": ["天府广场", "天府广场地下", "地下商场"],
      "keysecondary": [],
      "content": "天府广场，{{user}}所处城市的中心商圈……",
      "uid": "001"
    }
  }
}
```

### 自检清单（每次输出前必须检查）

- [ ] **简繁双版本关键词**：每个主要关键词都有简体和繁体（如 `"小张", "小張"`）
- [ ] **内容含主语**：每条 content 第一句即包含关键词对应的主语完整描述
- [ ] **无递归触发**：内容中没有以关键词为唯一触发手段的嵌套写法
- [ ] **深度 4-6**：电梯帮条目使用推荐深度值，无 ≥21 的无效条目
- [ ] **顺序分配合理**：核心设定顺序 ≥ 8000，边缘设定顺序 ≤ 100
- [ ] **显隐分离**：涉及角色核心特质的设定在蓝灯，涉及秘密的在绿灯
- [ ] **字数自检**：单条不超过 3000 字，总量不超过 15000 字符（含角色人设）
- [ ] **常量条目**：constant=true 用于需要时刻生效的条目
- [ ] **非游戏语言**：content 中无"玩家""角色""属性""判定"等系统语言
