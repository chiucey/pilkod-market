# 能力自评框架详细说明

## 评估维度详解

### 1. 技能匹配度评估标准

| 等级 | 分数 | 标准 |
|------|------|------|
| 完全匹配 | 90-100 | 所需技能已加载，熟练度高 |
| 高度匹配 | 75-89 | 核心技能具备，部分高级功能不熟 |
| 中度匹配 | 50-74 | 基础技能具备，需要学习进阶部分 |
| 低度匹配 | 25-49 | 仅有部分相关技能 |
| 不匹配 | 0-24 | 所需技能完全不具备 |

**评估要点**：
- 检查技能库中的相关技能
- 评估技能版本和更新状态
- 识别技能缺口

### 2. 知识覆盖度评估标准

| 等级 | 分数 | 标准 |
|------|------|------|
| 完全覆盖 | 90-100 | 任务领域知识完整 |
| 大部分覆盖 | 75-89 | 核心知识具备，边缘知识不足 |
| 部分覆盖 | 50-74 | 基础知识具备，专业细节不足 |
| 有限覆盖 | 25-49 | 仅有表层了解 |
| 未知领域 | 0-24 | 完全陌生的领域 |

**评估要点**：
- 识别任务所属领域
- 评估该领域的知识深度
- 标记知识盲区

### 3. 工具可用性评估标准

| 等级 | 分数 | 标准 |
|------|------|------|
| 完全可用 | 90-100 | 所有工具可用且权限充足 |
| 基本可用 | 75-89 | 核心工具可用，部分辅助工具缺失 |
| 部分可用 | 50-74 | 关键工具可用，但不稳定 |
| 勉强可用 | 25-49 | 仅能使用基础工具 |
| 不可用 | 0-24 | 所需工具完全不可用 |

**评估要点**：
- 列出任务所需工具清单
- 验证每个工具的可用性
- 检查工具权限

### 4. 任务复杂度评估标准

| 等级 | 分数 | 标准 |
|------|------|------|
| 简单 | 90-100 | 1-2步，无依赖，错误风险低 |
| 较简单 | 75-89 | 3-5步，弱依赖，风险可控 |
| 中等 | 50-74 | 5-10步，有依赖，需谨慎 |
| 复杂 | 25-49 | 10+步，强依赖，风险较高 |
| 极复杂 | 0-24 | 复杂网络依赖，多系统集成 |

**评估要点**：
- 统计任务步骤数
- 分析步骤间的依赖关系
- 识别潜在错误点

### 5. 历史成功率评估标准

| 等级 | 分数 | 标准 |
|------|------|------|
| 极高 | 90-100 | 类似任务成功率>95% |
| 高 | 75-89 | 类似任务成功率80-95% |
| 中 | 50-74 | 类似任务成功率60-80% |
| 低 | 25-49 | 类似任务成功率30-60% |
| 无历史 | - | 无法评估，使用默认值50 |

**评估要点**：
- 查询任务分类体系
- 查找相似任务的执行记录
- 分析成功/失败原因

## 置信度调整规则

### 向上调整的条件
- 所有核心维度得分>80
- 历史成功率高
- 无已知的严重风险

### 向下调整的条件
- 任何核心维度得分<40
- 存在多个中低分维度
- 历史成功率低
- 存在未解决的依赖关系

### 特殊情况处理
- 新领域任务：基准分数×0.8
- 关键系统操作：基准分数×0.7
- 高风险操作：额外-10分
- 用户明确要求的任务：基准分数×1.1

## 澄清问题生成指南

当置信度<70%时，需要向用户澄清：

### 技能相关问题
- "您期望的完成标准是什么？"
- "是否有参考示例可以提供？"
- "对完成时间有要求吗？"

### 范围相关问题
- "任务的边界在哪里？"
- "哪些部分是必须完成的？"
- "哪些部分是可选的？"

### 风险相关问题
- "如果出现错误，您希望如何处理？"
- "是否接受部分完成？"
- "有回退方案吗？"

## 评估结果应用

### 置信度≥90%
```
行动：直接执行
沟通：告知用户开始执行
监控：定期向用户更新进度
```

### 置信度70-89%
```
行动：执行，但设置检查点
沟通：执行前简要说明方案
监控：增加进度确认频率
```

### 置信度50-69%
```
行动：执行前获取用户确认
沟通：详细说明方案和风险点
监控：每个关键步骤确认
```

### 置信度30-49%
```
行动：触发技能补全或寻求澄清
沟通：说明置信度不足的原因
选项：1. 提供更多信息后重评
     2. 部分执行可完成部分
     3. 拒绝执行
```

### 置信度<30%
```
行动：拒绝或大幅改造任务
沟通：详细说明能力边界
建议：引导用户到更合适的执行方式
```
