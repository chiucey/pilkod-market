# Product Idea Brainstorming Skill

This skill integrates product requirement research methods and creative analysis techniques to help users conduct systematic product idea brainstorming.

## Core Workflow

### Phase 1: Requirement Research & Information Collection

**Objective**: Collect product idea directions and market demand information through multiple channels

**Execution Steps**:

1. **User Requirement Mining**
   - User interviews: 10-15 target users for in-depth communication
   - Survey research: 500+ samples to validate hypotheses
   - Behavior data analysis: Mine existing product user behavior logs

2. **Market Analysis**
   - Industry trend research: Market size, growth rate, penetration rate
   - Competitor analysis: Direct + indirect competitor feature matrices
   - SWOT analysis: Strengths, Weaknesses, Opportunities, Threats

3. **Idea Source Channels**
   - User feedback: Customer service tickets, social media comments, app store reviews
   - Cross-domain inspiration: Similar scenario solutions from other industries
   - Team brainstorming: 6-3-5 method (6 people, 3 minutes per round, 5 rounds = 90 ideas)

### Phase 2: Idea Screening & Evaluation

**Objective**: Filter high-value directions from mass ideas

**Scoring Matrix** (1-5 scale):
| Dimension | Weight | Scoring Criteria |
|-----------|--------|------------------|
| User Value | 25% | Does it solve core pain points |
| Business Value | 25% | Does it align with profit goals |
| Technical Feasibility | 25% | Can existing technology implement it |
| Strategic Fit | 25% | Does it match company long-term strategy |

**Retention Criteria**: Total score >= 12 points

### Phase 3: Deep Requirement Analysis & Definition

**Objective**: Transform vague ideas into actionable product requirements

**User Persona Construction**:
```
Demographics: Age, occupation, location, income
Behavior habits: Usage scenarios, frequency, preferences
Core pain points: Most urgent problems to solve
Real scenarios: When, where, why to use
```

**User Story Format**:
```
As a [User Persona]
I want [Function Goal]
So that [Value Proposition]
```

**Requirement Classification (KANO Model)**:
- Basic Requirements (Must-have): Must have, or user churns
- Performance Requirements (Should-have): Can improve satisfaction
- Delighters (Could-have): Exceed expectations, create surprise

### Phase 4: Priority Ranking

**Method Selection**:

1. **MoSCoW Model**
   - Must-have: Must have
   - Should-have: Should have
   - Could-have: Could have
   - Won't-have: Won't have this time

2. **Value/Cost Matrix**
   | | Low Cost | High Cost |
   |---|---|---|
   | **High Value** | Execute immediately | Plan resources |
   | **Low Value** | Iterate later | Abandon |

3. **KANO Priority**
   - Prioritize basic requirements
   - Then develop delighter requirements (increase loyalty)
   - Finally consider performance requirements

### Phase 5: Design Validation

**Prototype Testing Process**:
1. Low-fidelity prototype → 5-8 user testing
2. High-fidelity prototype → 10-20 user testing
3. Gradual rollout → 10-20% user verification

**Validation Metrics**:
- Feature usage rate
- User dwell time
- Conversion rate
- Satisfaction score

## Recommended Tools

**Requirement Collection**:
- Surveys: SurveyMonkey, Google Forms, SurveyStar
- Interviews: Zoom (recording), Otter.ai (transcription)

**Data Analysis**:
- Product analytics: Amplitude, Mixpanel, Google Analytics
- BI tools: Tableau, Power BI

**Collaboration & Visualization**:
- Whiteboards: Miro, Mural
- Prototyping: Figma, Sketch
- Mind mapping: XMind, MindManager

**Requirement Management**:
- Jira, Azure DevOps, Productboard

## Key Notes

1. **Avoid Pseudo Requirements**: Use 5Why analysis to ask "Why does the user need this"
2. **Cross-validate Data**: Combine survey data with behavioral data
3. **Continuous Iteration**: Collect-Analyze-Implement-Validate-Iterate loop
4. **Cross-team Alignment**: Standardize language, define acceptance criteria
