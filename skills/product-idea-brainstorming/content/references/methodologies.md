# Product Idea Brainstorming Methodology Reference

## 1. Requirement Analysis Methodologies

### 1.1 User Requirement Mining Methods

#### User Interviews
- **Purpose**: Deep understanding of user pain points and motivations
- **Techniques**:
  - Select representative user samples (cover different types)
  - Prepare open-ended questions, avoid leading questions
  - Emphasize listening and observation, capture implicit needs
- **Sample size**: 10-15 target users

#### Surveys
- **Purpose**: Large-scale hypothesis validation and preference data collection
- **Design Principles**:
  - Questions should be clear and concise, avoid leading
  - Include both open-ended and closed-ended questions
  - Set screening conditions to ensure sample quality
- **Sample size**: 500+ coverage

#### User Personas
- **Construction Elements**:
  - Demographics: Age, occupation, location, income
  - Behavior habits: Usage scenarios, frequency, preferences
  - Core pain points: Most urgent problems to solve
  - Real scenarios: When, where, why to use

### 1.2 Market Analysis Methods

#### Industry Trend Analysis
- Industry penetration and user growth curves
- Technology-driven emerging segment needs
- Impact of regulations and policies on market

#### Competitor Analysis Dimensions
- Core feature comparison
- User experience flow
- Pricing strategy and business model
- Community sentiment and public opinion

#### SWOT Analysis Framework
- Strengths
- Weaknesses
- Opportunities
- Threats

## 2. Creative Analysis Techniques

### 2.1 Brainstorming

**Founder**: Alex Osborn (1938)

**Four Principles**:
1. **Defer Judgment**: Delay criticism, don't immediately reject
2. **Encourage Wild Ideas**: Quantity improves quality
3. **Stay Focused**: Build on the ideas of others
4. **One Conversation at a Time**: No interrupting

**6-3-5 Brainwriting Method**:
- 6 participants
- 3 minutes per round
- 5 rounds
- = 90 ideas

### 2.2 Reverse Brainstorming
- Allows criticism and questioning
- Discovers creative weaknesses through questions
- Further improves and refines ideas

### 2.3 Design Hackathon
- Team collaboration + brainstorming
- Generates large volume of ideas in short time
- Suitable for rapid innovation scenarios

## 3. Requirement Classification Models

### 3.1 KANO Model

| Type | Characteristic | When Not Satisfied | When Satisfied |
|------|----------------|-------------------|----------------|
| Basic Needs | Pain points | User churn | Satisfaction stable |
| Performance Needs | Itch points | Satisfaction decreases | Satisfaction increases |
| Delighters | Wow factors | No impact | Unexpected surprise |

### 3.2 Maslow's Hierarchy of Needs

1. Physiological needs (basic functions)
2. Safety needs (data security, stability)
3. Social needs (community, sharing)
4. Esteem needs (achievement, status)
5. Self-actualization (personalization, creativity)

## 4. Priority Ranking Methods

### 4.1 MoSCoW Model

- **Must-have**: Must have (core functions)
- **Should-have**: Should have (important functions)
- **Could-have**: Could have (desired functions)
- **Won't-have**: Won't have this time (future considerations)

### 4.2 Value/Cost Matrix

```
              High Cost
        ┌─────────────┬─────────────┐
        │   Plan      │   Abandon   │
 High   │   Resources │             │
Value───┼─────────────┼─────────────┤
        │   Execute   │   Iterate   │
        │   Now       │   Later     │
        └─────────────┴─────────────┘
              Low Cost        High Cost
```

### 4.3 Priority Evaluation Dimensions

| Dimension | Weight | Evaluation Content |
|-----------|--------|-------------------|
| Relevance | 20% | Fit with product positioning |
| Logic | 15% | Dependencies between requirements |
| Intensity | 25% | Necessity, frequency, continuity |
| Breadth | 20% | Target user proportion |
| Frequency | 20% | Occurrences per time unit |

## 5. User Stories & Journey Maps

### 5.1 User Story Format

```
As a [User Role]
I want [Achieve some goal]
So that [Gain some value/Solve some problem]
```

### 5.2 User Story Mapping Structure

- **Horizontal axis**: Main steps for users to achieve goals (user journey)
- **Vertical axis**: User stories supporting each step, arranged by priority

### 5.3 Journey Map Elements

- Actions (what users do)
- Thoughts (what users think)
- Emotions (how users feel)
- Touchpoints (interactions with product)
- Pain points (problems encountered)

## 6. Validation & Iteration Methods

### 6.1 Prototype Testing Process

1. **Low-fidelity prototype**: Paper prototypes, 2-3 user testing
2. **High-fidelity prototype**: Interactive prototypes, 5-8 user testing
3. **Gradual rollout**: 10-20% user verification

### 6.2 Validation Metrics

- Feature usage rate
- User dwell time
- Conversion rate
- Satisfaction score (NPS)
- Net Promoter Score (NPS)

### 6.3 5Why Analysis

Questioning example:
- User says "I want more features" → Why?
- Because "I can't find what I need" → Why?
- Because "Navigation is complicated" → Why?
- Because "Information architecture is unclear" → Core problem
