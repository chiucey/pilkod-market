# 自动化规则详解

## 三大核心规则

### 规则 1: 文件修改联动

```javascript
// IF 修改了核心代码文件
// THEN 自动检查：
//   - 相关文档是否需要同步
//   - 配置文件是否需要更新
//   - 测试用例是否需要调整

// 检测模式
const fileChangePatterns = [
  'core/**/*.js',
  'routes/**/*.js',
  'middleware/**/*.js'
];

// 关联检查项
const relatedChecks = {
  '*.md': '文档同步',
  'config/**/*': '配置更新',
  'test/**/*.js': '测试调整',
  'package.json': '依赖检查'
};
```

### 规则 2: 依赖变更通知

```javascript
// IF 修改了 package.json（依赖库）
// THEN 自动检查：
//   - README.md 中的依赖说明
//   - 导入语句是否需要更新
//   - 是否有编译/构建脚本需要调整

// 检测模式
const dependencyChangePatterns = [
  'better-sqlite3 -> sql.js',
  'lodash -> lodash-es',
  'axios -> fetch'
];

// 关联检查项
const dependencyChecks = {
  'README.md': '依赖说明更新',
  'import/**/*.js': '导入语句更新',
  'build/**/*.js': '构建脚本调整',
  'docker-compose.yml': '容器配置调整'
};
```

### 规则 3: 数据格式变更追踪

```javascript
// IF 修改了数据格式（如 ID 从字符串改为 UUID）
// THEN 自动检查：
//   - 所有使用该数据的模块
//   - 序列化/反序列化逻辑
//   - API 接口兼容性
//   - 前端显示逻辑

// 检测模式
const dataFormatPatterns = [
  'ID 格式变更 (tenant_xxx -> UUID)',
  '时间格式变更 (Date -> ISO8601)',
  '加密方式变更 (MD5 -> SHA256)'
];

// 关联检查项
const dataFormatChecks = {
  'models/**/*.js': '数据模型检查',
  'serializers/**/*.js': '序列化逻辑检查',
  'api/**/*.js': '接口兼容性检查',
  'frontend/**/*.js': '前端显示逻辑检查',
  'database/**/*.sql': '数据库字段检查'
};
```

## 影响分类标准

### 直接影响（必须更新）

| 变更类型 | 影响范围 | 检查项 |
|---------|---------|--------|
| 核心代码修改 | 内部模块 | 函数调用、参数传递 |
| API 修改 | 路由层 | 请求/响应格式 |
| 数据库修改 | 数据层 | Schema、索引 |
| 配置文件修改 | 运行环境 | 环境变量、启动参数 |

### 间接影响（可能需要更新）

| 变更类型 | 影响范围 | 检查项 |
|---------|---------|--------|
| 依赖库替换 | 相关模块 | 导入语句、API 调用 |
| 数据格式变更 | 上下游模块 | 序列化/反序列化 |
| 接口签名变更 | 调用方 | 请求参数、错误处理 |

### 潜在影响（未来需要）

| 变更类型 | 影响范围 | 检查项 |
|---------|---------|--------|
| 安全加固 | 合规相关 | 审计日志、报告 |
| 性能优化 | 扩展性 | 文档、容量规划 |
| 架构调整 | 部署运维 | 部署脚本、监控配置 |

## 任务优先级判断

### 高优先级（必须完成）

- 核心功能受影响
- 直接影响用户体验
- 存在安全风险
- 导致编译/运行错误

### 中优先级（应该完成）

- 非核心功能受影响
- 文档与代码不一致
- 测试覆盖不完整
- 潜在兼容性问题

### 低优先级（可以稍后）

- 用户手册更新
- 示例代码调整
- 内部注释更新
- 次要文档同步
