# 智能任务关联识别

让 AI 从"被动响应"转变为"主动思考"，真正理解任务的因果关系和潜在影响。

## 核心目标

自发关注事件的牵连因果关系，对相关和可能相关的事情进行思考，然后作出任务清单并执行。

## 核心组件

### 1. MCP 服务（上下文感知）

跨文件、跨模块的上下文感知能力：

| 工具 | 功能 |
|------|------|
| `search_codebase` | 语义搜索代码库 |
| `search_symbol` | 符号关系查询 |
| `grep_code` | 正则表达式搜索 |
| `read_file` | 文件内容读取 |
| `list_dir` | 目录浏览 |

### 2. 记忆回溯

通过历史经验和教训避免重复错误：

| 记忆类别 | 内容 |
|---------|------|
| `history_task_workflow` | 历史任务流程 |
| `learned_skill_experience` | 学到的技能经验 |
| `common_pitfalls_experience` | 常见陷阱经验 |
| `important_decision_experience` | 重要决策经验 |
| `development_code_specification` | 开发规范 |

### 3. 智能思考模式

#### 因果推理
```
原因：修改了数据库驱动
结果：需要更新依赖文档
连锁反应：
  - db.js 需要修改 ✅
  - README.md 需要更新 ✅
  - 迁移工具需要适配 ✅
  - 部署脚本需要检查 ⏳
```

#### 类比推理
```
历史经验：上次修改认证方式时，忘了更新 API 文档
当前情况：这次修改了数据库驱动
类比结论：一定要记得更新 README.md 和 API 文档
```

#### 预防性思维
```
当前操作：修改数据库驱动
潜在风险：
  - 现有数据可能不兼容 → 提前准备迁移脚本
  - 性能可能下降 → 提前准备性能测试
  - 用户可能困惑 → 提前准备升级指南
```

## 任务识别流程

### 阶段 1: 事件触发

**触发条件**：
- 用户提出新需求
- 检测到代码变更
- 文件修改完成

### 阶段 2: 关联分析

**思考维度**：

| 影响类型 | 说明 | 示例 |
|---------|------|------|
| **直接影响** | 必须更新的文件 | 核心代码文件、配置文件 |
| **间接影响** | 可能需要更新 | README.md、部署脚本、测试脚本 |
| **潜在影响** | 未来可能需要 | API 文档、用户手册、迁移指南 |

### 阶段 3: 任务生成

**优先级分类**：

```
## 任务清单

### 高优先级（必须完成）
- [ ] 更新 README.md 中的依赖说明
- [ ] 验证所有引用模块
- [ ] 测试核心流程

### 中优先级（应该完成）
- [ ] 更新 API 文档
- [ ] 编写迁移指南

### 低优先级（可以稍后）
- [ ] 更新用户手册
- [ ] 准备发布公告
```

### 阶段 4: 执行策略

| 任务类型 | 执行方式 |
|---------|---------|
| 简单、明确 | 立即执行 |
| 复杂、有风险 | 询问确认 |
| 需要更多上下文 | 计划延后 |

## 自动化规则

### 规则 1: 文件修改联动

```
IF 修改了核心代码文件
THEN 自动检查：
  - 相关文档是否需要同步
  - 配置文件是否需要更新
  - 测试用例是否需要调整
```

### 规则 2: 依赖变更通知

```
IF 修改了 package.json（依赖库）
THEN 自动检查：
  - README.md 中的依赖说明
  - 导入语句是否需要更新
  - 是否有编译/构建脚本需要调整
```

### 规则 3: 数据格式变更追踪

```
IF 修改了数据格式（如 ID 从字符串改为 UUID）
THEN 自动检查：
  - 所有使用该数据的模块
  - 序列化/反序列化逻辑
  - API 接口兼容性
  - 前端显示逻辑
```

## 学习进化

### 经验积累

每次任务完成后，将经验写入记忆：

```javascript
update_memory({
  category: "common_pitfalls_experience",
  content: "修改数据库驱动时，务必同步更新 README.md 和所有相关文档",
  keywords: "数据库驱动、文档同步、README"
})
```

### 模式识别

识别重复出现的问题模式：

```
发现规律：3 次都忘了更新文档
生成规则：以后修改代码时，强制检查文档
```

## 适用场景

### 应该使用
- 代码变更后检查相关影响
- 完成重构后验证完整性
- 修改依赖库后同步文档
- 数据格式变更后追踪影响

### 不应该使用
- 纯计算任务（无关联影响）
- 独立模块修改（已确认无关联）
- 简单文本编辑（无代码逻辑变更）
