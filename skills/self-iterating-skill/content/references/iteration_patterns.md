# 迭代模式参考

## 成熟迭代模式

### 模式 1: 增量改进

**适用场景**：识别到明确但局部的改进点

**步骤**：
1. 精确识别问题点
2. 设计最小改动
3. 实施并验证
4. 记录学习

**示例**：
```
问题：某类任务边界情况处理不当
改进：在 SKILL.md 添加边界情况指导
验证：执行同类任务验证改进效果
```

### 模式 2: 重构升级

**适用场景**：多次小改进累积导致结构性问题

**信号**：
- 多个改进点涉及相同区域
- 维护成本显著增加
- 出现重复代码

**步骤**：
1. 完整备份
2. 理解现有结构
3. 设计新架构
4. 逐步迁移
5. 并行验证

### 模式 3: 能力扩展

**适用场景**：新任务类型出现，现有能力不足

**步骤**：
1. 分析新任务特征
2. 设计扩展方案
3. 实现新模块
4. 集成测试
5. 逐步上线

## 风险控制

### 回滚策略

1. **版本化备份**：每次升级前完整备份
2. **增量更新**：每次只做一个维度的修改
3. **验证门控**：验证通过后再合并

### 异常处理

- 单次执行失败：记录并继续
- 升级后验证失败：自动回滚
- 数据损坏：使用最新备份恢复

## 成功标准

### 量化指标

- 成功率提升 ≥ 5%
- 平均响应时间降低 ≥ 10%
- 边界情况覆盖率 ≥ 80%

### 定性指标

- 用户反馈改善
- 维护成本降低
- 自我改进效率提升
