# Changelog

## [v3.1] 2026-04-19 — 多格式 HTML 兼容性

### 新增能力

- **支持微信 新版/96编辑器 格式**：新增 `extractPlainHtmlFormat()` 解析器，专门处理 `<p><span style="">...</span></p>` 格式（旧版 `<span leaf="">` 格式继续兼容）
- **attribution 保护机制**：正文与"撰稿/编辑/审核/终审"等元信息不会被错误合并——attribution 行强制独立分段
- **装饰内容过滤**：自动过滤 SVG 装饰图、空白分隔符、emoji 装饰等无意义内容

### HTML 格式兼容性矩阵

| 格式 | HTML 特征 | 解析器 |
|------|----------|--------|
| 旧版微信编辑器 | `<span leaf="">` | `extractLeafFormat()` |
| 新版微信编辑器 | `<p><span style="">` | `extractPlainHtmlFormat()` |
| 96编辑器等 | `<section data-tpl-id>` | `extractPlainHtmlFormat()` |

### 测试案例

- 文章：用绘画减压 为成长赋能（罗山县第四实验小学心理健康公开课）
- 格式：96编辑器（`<section data-tpl-id>` + 纯 HTML）
- 验证：14个文字节点（10段正文 + 4项元信息）全部正确提取
- 22张图片全部正确下载嵌入

## [v3] 2026-04-19 — 排版优化

### 核心修复

- **修复文字碎片化**：旧版 `<span leaf="">` 每个碎片都是独立节点，导致67个文字节点混乱。改用 DOM 顺序遍历，同属性相邻文字自动合并为清晰段落（降至32个）
- **修复含图片的 span 处理**：`leafRe` 把含 `<img>` 的 `<span leaf="">` 当纯文字处理，导致图片丢失或文字错位。新逻辑先识别 img 再提取文字
- **标题层级保护**：新增字号差异检测（≥4px），字号差异大的相邻节点不再被合并，防止正文/小标题被吞
- **作者信息拆分**：识别文稿/编辑/一审/二审/三审等 attribution 行，按关键字拆成独立段落

### 验证

- 测试文章：https://mp.weixin.qq.com/s/-vopw5W_xkBgfnPYAZ-itQ（罗山县第四实验小学家长会纪实）
- 18个关键内容节点全部 ✅ 正确提取
- 节点结构：61节点（32文字+29图片），结构清晰
