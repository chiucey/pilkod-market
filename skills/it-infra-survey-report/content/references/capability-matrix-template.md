# 能力需求矩阵模板

## 模板说明

本模板用于结构化记录能力需求的详细信息。调研方应根据委托方的需求文档填充具体内容，不局限于以下示例。

## 能力需求条目格式

每项能力需求应包含以下三个维度：

| 维度 | 说明 |
|------|------|
| 我需要什么 | 具体的能力描述、技术要求、性能指标 |
| 当前实现 | 委托方目前使用的工具或平台能力 |
| 调研重点 | 需求文档中明确的调研方向和关注点（用于提取 checklist） |

### 示例：互联网搜索

| 维度 | 说明 |
|------|------|
| 我需要什么 | 按关键词搜索互联网，返回标题、URL、摘要。需要支持三种模式：通用搜索、新闻搜索（可限定时间范围如past_day）、学术/深度搜索。需要支持中英文。每次搜索期望返回5-10条结果。 |
| 当前实现 | Manus search工具，支持type: info / news / research，支持time参数 |
| 调研重点 | 是否有搜索类的MCP服务或Skill？特别关注：是否支持时间过滤、是否支持多语言、返回结果的结构和数量、调用成本。也关注是否有专门面向AI Agent生态领域的垂直搜索服务。 |

## 覆盖等级定义

| 等级 | 说明 | 使用条件 |
|------|------|----------|
| 完全覆盖 | 该资源能够100%满足该能力的所有需求 | 仅限 ✅ 已验证资源 |
| 部分覆盖 | 该资源能够满足该能力的部分需求 | ✅ 或 ⚠️ 资源均可，需说明限制 |
| 部分覆盖（需XX） | 该资源有条件限制 | 必须标注具体限制条件 |
| ⚠️ 待验证 | 资源本身未验证，覆盖能力未知 | 仅限 ⚠️ 待验证资源 |
| — | 不覆盖该能力 | |

**规则：⚠️ 待验证的资源不得标注为"完全覆盖"。**

## 矩阵模板

根据委托方需求调整列名。以下为示例：

| 资源名称 | 来源市场 | 验证状态 | 能力A | 能力B | 能力C | ... |
|----------|----------|----------|-------|-------|-------|-----|
| 资源X | OpenClaw | ✅ 已验证 | 完全覆盖 | — | — | ... |
| 资源Y | 第三方 | ⚠️ 待验证 | — | ⚠️ 待验证 | — | ... |
| 资源Z | Anthropic | ✅ 已验证 | — | — | 部分覆盖 | ... |

## 低活跃度资源标注规则

| 条件 | 标注 |
|------|------|
| Stars < 50 或 commits < 10 | 备注中标注"活跃度较低，生产环境慎用" |
| 最近更新超过 6 个月 | 备注中标注"长期未更新，可能已停止维护" |
| 仓库无法访问 | 验证状态标 ⚠️，建议降级到待验证附录 |
