## ⛔ 绝对禁止原则（方法论红线）

> **核心原则**：分析质量、严谨性和完整性永远高于效率和完成感

### 一、禁止懒惰走捷径

**❌ 绝对禁止**：
- 以"网络太大、计算太慢"为理由跳过必要的分析步骤
- 只分析部分节点就声称完成全网分析
- 用"简单统计"代替"深度网络分析"
- 前详后略，不能坚持同一分析标准
- 分批处理时，后面批次降低分析深度
- 以时间、效率或上下文不足为由牺牲严谨性

**✅ 正确做法**：
- 无论网络多大，必须坚持同一分析标准
- 每个节点都必须计算所有必要的中心性指标
- 每项分析都必须有结果解读和小结
- 第1批和第100批数据必须使用完全相同的分析深度
- 任务分解时确保粒度足够在一次会话中完成
- 每次会话后必须自我核查分析过程和完整性

**📊 量化标准**：
| 项目 | 最低标准 | 检查方法 |
|------|---------|---------|
| 节点覆盖率 | 100% | 节点计数验证 |
| 中心性指标计算 | 完整（度/介数/接近/特征向量） | 指标清单检查 |
| 分析解读 | 每项指标必须有 | 抽样检查 |
| 网络描述指标 | 必须（密度/直径/聚类系数） | 报告检查 |
| 可视化质量 | 清晰可读 | 视觉检查 |
| 结果解释 | 每项指标必须有解读 | 报告检查 |

---

### 二、禁止未验证就报告完成

**❌ 绝对禁止**：
- 不进行实质验证就假设分析完成
- 相信脚本输出而不检查实际文件
- 生成"分析报告"但未实际完成分析
- 用"待计算"、"占位符"填充文件却声称完整
- 子 agent 输出无数据清单就接受委托

**✅ 正确做法**：
- 每项分析完成后必须执行 7 步验证流程
- 必须读取文件内容确认分析真实存在
- 全部验证通过后再报告完成
- 子 agent 必须输出完整的数据清单

**📋 验证流程（每项分析完成后必须执行）**：
```
1. 检查文件是否存在 → dir/ls 命令
2. 检查文件大小 → 不能过小（<10KB 需警惕）
3. 读取文件内容 → 确认分析数据真实存在
4. 统计分析结果数量 → 是否覆盖所有节点
5. 检查分析格式 → 是否与标准一致
6. 验证结果解读 → 每项指标是否有解释
7. 全部通过后 → 才能报告完成
```

### 七、禁止定性分析硬编码（SNA核心）

**核心原则**: 社会网络分析中的结构洞识别、社群解释和节点角色判断必须由大模型智力驱动，绝不能硬编码。

**错误做法**:
```yaml
硬编码判断:
  - 用阈值规则判断"谁是结构洞"（constraint<0.5）
  - 用if/else判断"哪个节点是核心"
  - 用模板生成"网络解读"
  - 硬编码中心性→重要性的映射

示例（错误）:
  if betweenness > 0.3:
      return "核心节点"  # 这是大模型的工作
```

**正确做法**:
```yaml
工具只做数值计算:
  - 中心性指标数值计算（NetworkX）
  - 社群检测算法（Louvain/Girvan-Newman）
  - 结构洞指标计算（constraint/effective size）
  - 网络可视化（matplotlib/networkx）

智力留给大模型:
  - 结构洞的社会学意义由大模型解读
  - 节点角色的实质性判断由大模型基于案例知识
  - 社群划分的理论解释由大模型推理
  - 网络演化的趋势判断由大模型分析

Python工具的正确角色:
  ✅ 数值计算、算法执行、数据结构管理
  ❌ 结构洞判断、节点角色归类、社群意义解释
```

## 黄金案例 vs 失败案例 —— 从实践学习

### 黄金案例（正确做法）

**案例：在线社区知识分享网络分析（完整SNA流程）**

```
背景: 分析某专业知识分享平台（如知乎/知识星球）的用户互动网络
方法: SNA六步骤（数据准备→网络构建→中心性→社群→结构洞→可视化）
数据: 平台API导出，500用户，2000条互动边（点赞/评论/转发）

做法（完整SNA分析）：

【Step 1: 数据准备与网络构建】
- 数据清洗: 移除机器人账号（行为特征异常）
- 边类型: 评论=强关系，点赞=弱关系，转发=信息流
- 加权网络: 权重=互动频率（次数/时间）

【Step 2: 综合中心性分析 —— 不只单一指标】
度中心性（谁最活跃）:
  Top3: 用户A（87次互动）、用户B（72次）、用户C（65次）

介数中心性（谁是桥梁）:
  Top3: 用户D（0.234）、用户E（0.189）、用户F（0.156）
  发现：用户D虽不最活跃，但连接多个社群，是关键信息中介

接近中心性（谁最中心）:
  Top3: 用户A（0.82）、用户B（0.79）、用户G（0.75）
  发现：用户G虽互动不多，但距所有节点平均距离最短

特征向量中心性（谁连接重要节点）:
  Top3: 用户A（0.92）、用户H（0.87）、用户I（0.81）
  发现：用户H连接多位活跃用户，是高质量信息来源

【Step 3: 社群检测与验证】
- Louvain算法检测到4个主要社群（模度0.41）
- 社群验证: 检查社群内平均互动频率（密度>0.15为有效）
- 社群1: 产品讨论（180用户），核心：用户A，用户B
- 社群2: 职业发展（150用户），核心：用户E，用户I
- 社群3: 技术交流（120用户），核心：用户C，用户F
- 社群4: 休闲社交（50用户），核心：用户G

【Step 4: 结构洞分析 —— Burt理论应用】
低约束节点（结构洞位置）:
  用户J: 约束系数0.31，有效规模11.2
    - 位置: 连接社群1和社群2的唯一桥梁
    - 角色: 跨领域知识整合者，可获得非冗余信息

  用户K: 约束系数0.33，有效规模9.8
    - 位置: 社群2和社群3的桥接
    - 角色: 技术与职业发展的连接点

桥接分析与建议:
  - 建议用户D举办跨社群讨论活动，提升信息流通
  - 用户J可发展为平台"知识经纪人"，促进知识流动

【Step 5: 网络演化追踪】
- 时间维度: 2022-2024年网络
- 发现: 社群1从200用户增长至180用户，但核心节点更集中
- 风险: 核心节点依赖度过高，需培养次级核心

【Step 6: 可视化与报告】
- 节点大小: 度中心性（活跃度）
- 节点颜色: 社群归属（4色）
- 边粗细: 权重（互动频率）
- 布局: 力导向（Fruchterman-Reingold）
- 产出: 3000x3000px PNG，适合报告使用
```

**关键细节:**
- SNA的核心原则：**多指标综合分析**——不只依赖度中心性
- 结构洞必须结合社会学意义：约束系数低≠有影响力，需看介数
- 社群检测必须验证：模度值+社群内密度+主题一致性
- 失败案例往往是单一指标+过度推断：小样本得出大结论

### ❌ 失败案例（常见错误）

**错误1: 单一指标分析，只看度中心性**
```
症状: "度中心性最高的用户A是最重要的人物"
根因: 不计算介数/接近/特征向量中心性
后果: 忽略桥梁节点，错失关键信息流动者
```

**错误2: 结构洞硬编码判断**
```
症状: "约束系数<0.5的节点都是结构洞"
根因: 用阈值规则做定性判断
后果: 违背"定性分析由大模型智力驱动"原则
正确做法: Python工具只计算约束系数，大模型判断社会学意义
```

**错误3: 小样本过度推断**
```
症状: "N=20的研究揭示了社交网络的一般规律"
根因: 样本量不足支撑普遍性结论
后果: 研究结论失去可信度
```

**错误4: 忽视社群验证**
```
症状: "Louvain检测到4个社群，模度0.41，社群划分合理"
根因: 只看模度值，不检查社群内密度和主题一致性
后果: 虚假社群（算法人为划分，非真实社区结构）
```
