# Code Cleanup Skill

## 一、目标

每次编码完成后，自动扫描代码库中的冗余代码并直接清理掉，防止垃圾代码越堆越多。

## 二、触发时机

当用户说出以下类似语句时触发本技能：

- "帮我清理一下代码"
- "检查有没有多余的代码"
- "cleanup"、"clean up my code"
- "有没有死代码"、"有没有没用到的变量"
- 编码完成后说 "done"、"写完了"、"帮我检查一下"

## 三、输入处理

### 3.1 输入来源

| 来源 | 处理方式 |
|------|---------|
| 指定路径 | 用户直接给出文件或目录 |
| Git diff | 无指定时，默认扫描本次改动文件（`git diff HEAD`）|
| 全扫描 | 用户明确说"整个项目"时，递归扫描所有源码文件 |

### 3.2 扫描范围

根据输入确定扫描文件列表：

1. **指定文件/目录** - 直接扫描用户指定的路径
2. **Git diff** - 执行 `git diff HEAD --name-only` 获取本次改动的文件
3. **全项目扫描** - 递归扫描所有源码文件（排除 node_modules、dist、build 等）

## 四、检测规则

### 4.1 三类垃圾代码

#### 1. Unused Code（未使用的代码）

- 声明了但从未被调用的函数
- 赋值了但从未被读取的变量
- 导入了但未使用的 import / require

#### 2. Dead Code（注释掉的旧代码）

- 被注释掉超过 1 行的代码块（非说明性注释）
- 例如 `// console.log(...)` 或整段被 `/* */` 包起来的旧逻辑

#### 3. Duplicate Logic（重复逻辑）

- 两处以上出现高度相似的代码段（copy-paste 痕迹）
- 相似度阈值：结构和变量名 80% 以上相同

### 4.2 语言差异化规则

根据检测到的语言，加载对应的规则文件：

- **Python** - 加载 `references/rules-python.md`
- **TypeScript/JavaScript** - 加载 `references/rules-ts-js.md`
- **Go/Rust/Java** - 加载 `references/rules-general.md`

### 4.3 安全边界（不乱删的规则）

以下情况**只标注提示，不删除**：

| 规则 | 说明 |
|------|------|
| export / public | 导出函数或类可能被外部引用 |
| 带注释 | 带有 `// keep`、`// TODO`、`// FIXME`、`// NOTE` 的代码 |
| 测试文件 | `*.test.*`、`*.spec.*` 文件中的 mock / stub |
| 生命周期函数 | 框架约定的生命周期函数（如 `componentDidMount`、`__init__`）|

## 五、执行流程

### 5.1 第一步：扫描报告

1. 遍历目标文件列表
2. 对每个文件应用对应语言的检测规则
3. 生成问题清单，按文件分组

输出格式：
```
## 扫描报告

### 文件: path/to/file.py

| 行号 | 问题类型 | 说明 |
|-----|---------|------|
| 42  | Unused Import | 导入了 but never used: `os` |
| 128 | Dead Code | 被注释掉的旧函数 `old_function` |
| ... | ... | ... |
```

### 5.2 第二步：直接修改

1. 对每项可安全删除的问题调用 Edit 工具
2. 只删除冗余代码，不改业务逻辑
3. 记录修改结果

### 5.3 第三步：修改摘要

1. 汇总删除结果
2. 列出安全边界命中的项目（用户决定）

输出格式：
```
## 修改摘要

✅ 已删除: X 处
- file1.py:42 - 删除了未使用的 import `os`
- file2.js:128 - 删除了注释掉的旧代码

⚠️ 安全边界（需用户决定）: Y 处
- file3.ts:64 - 未使用的函数 `export function unused()` [建议保留，因为是导出函数]
```

## 六、输出规范

### 6.1 成功输出示例

```markdown
## 清理完成

### 扫描结果
- 扫描文件: 12 个
- 发现问题: 8 处

### 已处理
✅ 删除未使用 import: 3 处
✅ 删除死代码: 4 处
✅ 删除未使用变量: 1 处

### 安全边界（保留）2 处
- src/utils.ts:42 - `export function internalUse()` 是导出函数
- tests/mock.js:20 - 测试文件的 mock

### 修改文件
- [src/index.py](src/index.py)
- [src/utils.py](src/utils.py)
```

### 6.2 无问题输出

```markdown
## 清理完成

✅ 代码库很干净，没有发现冗余代码
```

## 七、错误处理

| 情况 | 处理 |
|------|------|
| 扫描目录为空 | 返回"未找到需要扫描的源码文件" |
| 文件权限问题 | 跳过该文件并标注，继续处理其他文件 |
| 语言无法识别 | 使用通用规则检测 |
