# 行动计划技能

从今天开始，制定可执行的行动计划并跟踪完成。

## 核心流程

```
目标设定 → 任务拆解 → 优先级排序 → 执行跟踪 → 复盘优化
```

## 任务拆解方法

### 1. 使用 Spec-Kit 拆解

```bash
# 创建规范文档
cat > .specify/project/spec.md << 'EOF'
# 项目规范

## 目标
[清晰描述项目目标]

## 当前状态
- ✅ 已完成
- ❌ 待完成

## 验收标准
1. 标准一
2. 标准二
EOF

# 生成执行计划
specify plan create \
  --name "项目名称" \
  --spec ".specify/project/spec.md" \
  --strategy chain
```

### 2. 任务清单格式

```yaml
tasks:
  - id: T1
    name: 任务名称
    duration: 30min
    skill: 对应技能
    output: 输出产物

dependencies:
  T2: [T1]  # T2 依赖 T1

quality_gates:
  - task: T2
    check: 验收条件
```

## 优先级管理

### 优先级矩阵

| 优先级 | 说明 | 策略 |
|--------|------|------|
| P0 | 必须完成 | 到期自动执行 |
| P1 | 应该完成 | 尽快处理 |
| P2 | 可以完成 | 有余力时处理 |
| P3 | 暂不处理 | 以后再说 |

## 关键成功因素

### DO's（应该做的）

- ✅ **从小处着手**: 先试点 1-2 个任务，成功后再推广
- ✅ **快速迭代**: 每周回顾，及时调整策略
- ✅ **强制执行为主**: P0 任务到期自动执行
- ✅ **激励驱动**: 成果计入绩效
- ✅ **工具优先**: 能自动化的绝不手动

### DON'Ts（不应该做的）

- ❌ **完美主义**: 不要等所有条件都完美才开始
- ❌ **一刀切**: 允许不同角色采用不同策略
- ❌ **只建不用**: 计划不是摆设，必须执行
- ❌ **忽视反馈**: 定期收集意见，持续改进
- ❌ **单打独斗**: 需要全员参与

## 风险与应对

| 风险 | 表现 | 应对措施 |
|------|------|----------|
| 抵触情绪 | "太麻烦了" | 展示ROI，降低门槛 |
| 形式主义 | 计划漂亮执行差 | 质量门禁，自动化检查 |
| 难以坚持 | 使用率下降 | 正反馈，排行榜 |
| 范围蔓延 | 任务越来越多 | 严格控制范围 |

## 预期成果衡量

| 指标 | 基线 | 目标 |
|------|------|------|
| 任务完成时间 | 3天/任务 | 1天/任务 |
| 交付延期率 | 60% | 10% |
| 文档同步率 | 40% | 95% |
| 计划执行率 | 50% | 90% |
