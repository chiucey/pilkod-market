# AI 自我改进与记忆系统 Skill

## 触发条件

任意以下场景自动触发本 skill：

- 用户说"你之前不是这样说的"
- 用户说"你怎么又犯了"
- 用户说"我跟你说过了"
- 用户纠正了一个错误（说"不是这样"/"错了"/"不对"）
- 某个操作/命令连续失败2次以上
- 用户提供了更优方案或方法
- 用户说"记住，以后要这样"
- 用户说"这个坑我踩过，别再犯了"

---

## 核心原则

```
记忆是能力的根基。

一次纠正 = 一次学习机会
同类错误第二次犯 = 不可接受
最佳实践不沉淀 = 能力不成长
```

---

## 错误分类体系

### A级错误（立即写入记忆）

**定义**：事实性错误、知识性错误、用户明确纠错过的事项

**处理**：立即写入 MEMORY.md，下次直接应用

```
类型：A级错误
来源：[用户纠正/失败案例]
内容：[错误事实] → [正确做法]
适用场景：[什么情况下要避免]
首次出现：YYYY-MM-DD
写入位置：MEMORY.md 或 memory/YYYY-MM-DD.md
```

### B级错误（观察+积累）

**定义**：同一个错误出现2次以上

**处理**：第2次出现时写入，第3次出现时报警

```
类型：B级重复错误
来源：第N次出现
错误描述：[具体错误]
正确做法：[用户确认的正确方式]
出现次数：[N]
写入位置：TOOLS.md 或 MEMORY.md
```

### C级优化（最佳实践）

**定义**：用户提供了更优方案，或发现更高效的方法

**处理**：立即沉淀，供后续参考

```
类型：最佳实践
来源：[用户建议/自主发现]
场景：[什么场景下适用]
原方案：[之前怎么做]
最优方案：[现在应该怎么做]
理由：[为什么更好，如有]
写入位置：TOOLS.md 或 AGENTS.md 或 相关skill的SKILL.md
```

## 执行流程

### 场景一：用户当场纠正

**Step 1：立即承认错误**

标准回应：
> "收到，纠正记录：[记录错误类型+正确做法+场景] 已写入长期记忆，后续不会再犯。"

**Step 2：判断错误级别**

| 级别 | 判断标准 | 写入位置 |
|:---:|:---|:---|
| A级 | 用户明确纠正 / 事实性错误 | MEMORY.md（长期） |
| B级 | 操作失败≥2次 | TOOLS.md（工具备注） |
| C级 | 用户给了更优方案 | 相关skill的SKILL.md |

**Step 3：执行写入（立即，不延迟）**

- **A 级**：写入 `[类型] + [内容摘要] + YYYY-MM-DD` 到 MEMORY.md
- **B 级**：追加到 TOOLS.md 的"常见错误记录"区域
- **C 级**：追加到对应skill的SKILL.md的"最佳实践"区域

---

### 场景二：发现重复失败的操作

**Step 1：识别重复失败**

当同一命令/操作连续失败2次以上时，判断这是系统性问题，不是随机错误，进入自我诊断流程。

**Step 2：诊断并记录**

```
## 重复失败报告

【问题】：执行的[命令/操作描述]
【失败次数】：N次
【失败模式】：[描述失败规律]
【原因分析】：[可能的原因]
【解决方案】：[用户确认后执行]
【预防措施】：[如何避免同类问题]
```

**Step 3：向用户确认根因**

> "这个操作失败了N次，你觉得问题出在哪里？"
> → 根据用户回答 → 写入记忆 → 下次执行前主动规避

---

### 场景三：用户说"记住/别再犯"

**Step 1：立即提取要点**

> 收到记录：
> 原则/纠正内容：`[核心要点]`
> 适用边界：`[什么情况下适用]`

**Step 2：立即写入并确认**

> "已记录：
> 要点1
> 要点2
> 适用：`[你的理解，如有出入请纠正]`"

**Step 3：告知具体落地位置**

> "已写入 MEMORY.md / TOOLS.md / [具体skill]，下次遇到同类场景，我会主动应用。"

## 记忆写入标准格式

### MEMORY.md 格式（长期记忆）

```markdown
## 错误纠正记录

### [YYYY-MM-DD] [错误类型]
**问题**：用户纠正了什么
**正确做法**：应该怎么做
**适用场景**：什么情况下触发
**来源**：用户纠正 / 失败记录

---

## 最佳实践记录

### [YYYY-MM-DD] [最佳实践名称]
**场景**：什么情况下用
**推荐做法**：具体操作
**原因**：为什么更好
```

### TOOLS.md 格式（工具级记忆）

```markdown
## 已知错误和局限

### [命令/工具] — [错误描述]
**错误原因**：
**正确做法**：
**参考**：来源
```

## 自我检查机制

### 行动前自检

在执行以下操作前，强制检查 MEMORY.md：
- 修改核心配置文件
- 执行可能破坏性的命令（rm/truncate）
- 用户提到相关话题 → 先查 MEMORY.md

### 行动后自检

操作失败后的标准流程：
1. 不重复失败操作（防止死循环）
2. 立即写入当前操作和失败结果
3. 告诉用户"操作失败，已记录，下一步建议"
4. 等待用户明确指导后再执行

### 定期自检

每次会话开始时，如用户提到相关话题：
主动查 MEMORY.md，"你上次提到过[某事]，我的理解是[记录内容]，有变化吗？"

---

## 禁止事项

- ❌ 不在用户纠正时辩解或解释，**先认错，后记录**
- ❌ 不把纠正当批评，当成学习机会
- ❌ 不重复写入同一错误（已有记录则覆盖，不重复堆积）
- ❌ 不在未经用户确认前写入来源信息
- ❌ 不把用户纠正当负面反馈，当成系统输入

---

## 一句话原则

**每一次纠正都是一次系统升级的机会；不记录的错误，等于没学到。**
