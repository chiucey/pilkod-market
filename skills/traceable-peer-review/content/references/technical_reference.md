# 可追踪同行评审技术参考

本文档为 `traceable-peer-review` 技能提供详细的技术背景和参考信息。

## 1. 系统设计原理

### 1.1 核心Thesis

一份可用的同行评审不是独白，而是一系列受限的认知操作序列。每个操作可以是：
- 提取论文核心声明
- 在匹配的设置下检查与先前工作的新颖性
- 编写带有可执行修复操作的本地化批评

这些操作必须满足以下约束：
- **可验证性**: 判断必须可追溯到论文中的锚点
- **可比性**: 比较必须使用匹配的设置
- **可操作性**: 批评必须以可执行的修订结束

### 1.2 关键概念定义

#### 声索-证据-风险分类账 (Claim-Evidence-Risk Ledger)

每个分类账条目包含：
- `c_k`: 核心声明
- `E_k^(0)`: 其初始论文内证据集（指向X的锚点）
- `r_k^(0)`: 初始风险声明（如果证据缺失或被误解，什么会在科学上出问题）
- `s_k`: 状态标签 (`confirmed` | `suspected`)

#### 调查议程 (Investigation Agenda)

由分类账生成的待验证问题列表，按科学风险优先级排序。优先处理可能颠覆核心声明有效性的问题。

#### 匹配设置可比性门控 (Matched-Setting Comparability Gate)

一个先前工作只有满足以下条件才被视为直接可比：
1. 相同任务定义
2. 相同数据集/基准
3. 相同主要评估指标

其他因素（如模型规模或计算预算）仅作为次要排序线索，不作为门控条件。

## 2. 数学符号体系

### 2.1 论文表示

```
X = {(u_i, a_i)}_{i=1}^N, a_i = (p_i, b_i), b_i ∈ R_+^4

u_i: 第i个语义单元
p_i: 页码索引
b_i: 边界框 [x_min, y_min, x_max, y_max]
```

### 2.2 输出包表示

```
Y = (R, A, P, N)

R: 结构化最终报告（摘要、优缺点、整体判断）
A: 锚定注释集
P: 优先级修复计划
N: 新颖性/价值评估
```

### 2.3 证据图

```
G = (V, E)
V = V_claim ∪ V_anchor ∪ V_ann ∪ V_prior
E: supported-by, contradicted-by, localized-to, overlaps-with
```

最小可追踪性约束：每个锚定注释必须至少链接到一个论文锚点。

### 2.4 导出门控

```
1_ready(Y) =
  1[Schema(R) = 1] ×
  1[n_search ≥ α] ×
  1[n_intent ≥ β] ×
  1[|A| ≥ γ]

α = 3  (最小文献检查预算)
β = 3  (不同问题覆盖)
γ = 10 (最小锚定反馈数量)
```

## 3. 实现细节

### 3.1 PDF解析流程

1. 使用 MinerU (v4) 解析 PDF
2. 生成 Markdown 和 content_list
3. 每个块记录：页码、文本、类型、边界框（可用时）
4. 构建按页索引的文本流 J(p)

### 3.2 注释对象结构

```json
a_j = (ℓ_j, τ_j, σ_j, ρ_j, δ_j)

ℓ_j: 位置锚点 (页码, 行起始, 行结束)
τ_j: 问题类别
σ_j: 严重性 (major/minor)
ρ_j: 科学风险解释
δ_j: 修复建议
```

### 3.3 高亮渲染

```python
# 当有边界框时
R_j = ∪_{k=k_start}^{k_end} BBox(p_j, k)

# 当无边界框时的回退
y1 = 100 × (k_start - 1) / L_p
y2 = 100 × k_end / L_p
# 使用固定水平范围 [8, 92] 归一化坐标
```

### 3.4 页面级重读策略

```python
π_t = SelectSpan(X, L^(t-1), Q)
(L^(t), A^(t)) = Update(L^(t-1), A^(t-1), X_π_t)

# SelectSpan 优先选择高风险分类账项涉及的跨度和议程问题相关的跨度
# 同时按页顺序推进以保持覆盖率
```

## 4. 评估协议

### 4.1 严格问题覆盖率

保守的两步评估：
1. 从人工委员会包中提取规范问题列表（语义去重、严重性、类别）
2. 对每个系统按严格二元标准评分（缺失输出计为未覆盖）

### 4.2 匿名系统排名

使用固定评判器（gemini-3.1-pro-preview）生成比较链：
- 5个维度：技术准确性、建构价值、分析深度、沟通清晰度、整体判断
- 计算成对非平局胜率、平均胜率、平局感知平均排名
- Bradley-Terry Elo 估计与95% bootstrap置信区间

### 4.3 与人工委员会的盲比较

相同的匿名排名协议，但其中一个候选是人工审稿委员会包。

## 5. 类别分类法

八个问题类别：
1. **Soundness**: 论文的技术正确性和论证严谨性
2. **Novelty**: 论文贡献的新颖性和原创性
3. **Clarity**: 论文写作和表述的清晰度
4. **Experiment**: 实验设计和验证的充分性
5. **Ethics**: 伦理考量和潜在社会影响
6. **Presentation**: 格式、图表、引用的质量
7. **Comparison**: 与先前工作的比较是否公平充分
8. **Other**: 不属于上述类别的问题

## 6. 保守新颖性标签详解

### SUPPORTED
无直接可比的先前工作在匹配设置下覆盖相同机制/声明。

### PARTIALLY_OVERLAPPING
存在重叠但存在明确的剩余新颖性轴。

### SUBSTANTIALLY_OVERLAPPED
直接可比的先前工作在匹配设置下已覆盖相同机制/声明。

### UNCLEAR (默认)
当声明无法映射到可检查机制，或证据不足/矛盾时使用。

## 7. 安全与隐私考量

### 7.1 已识别的风险

1. **提示注入**: 隐藏内容提示注入PDF（Ye et al., 2024）
2. **误用风险**: 自动化评审被用作把关信号或决策代理
3. **数据处理**: 将稿件路由到工具链进行搜索、检索和渲染时的隐私问题
4. **伦理盲点**: 除非明确施压，否则伦理敏感批评容易被轻视

### 7.2 缓解措施

1. PDF清理：在处理前进行内容清理
2. 显式伦理检查清单：对于高风险领域增加专用检查
3. 人工监督：系统定位为辅助工具而非决策替代
4. 本地处理优先：论文内容在本地环境解析
5. 临时存储：处理后不保留上传论文的长期副本

### 7.3 高风险领域额外要求

对于以下领域，建议完全排除或增加严格的人工审核：
- 医学研究
- 法律相关工作
- 双重用途AI系统

## 8. 局限性与边界条件

### 8.1 已知的系统限制

1. **过程约束，非语义保证**: 系统保证结构化输出和可追踪性链接，但不保证语义真实性
2. **覆盖率不完整**: 即使在保守协议下，主要问题仍可能遗漏
3. **评判依赖**: 不同评判器可能产生不同偏好
4. **评估池条件**: 定量结果受限于固定评估池（排除格式错误的导出等）

### 8.2 正确的解读方式

DeepReviewer 2.0 应被解读为：
- **过程控制的代理审稿系统**: 通过使判断更可追踪和反馈更可执行来帮助审稿人和作者
- **辅助工具而非决策代理**: 不应被用作同行评审的替代品
- **证据有条件**: 是在固定评判和协议条件下的偏好信号，不是泛化的正确性保证

### 8.3 适用边界

最佳使用场景：
- 初步论文筛选
- 审稿前的自我检查
- 多轮修订的进度追踪
- 审稿人和作者之间的结构化沟通媒介

不建议使用场景：
- 最终决策依据
- 替代人工同行评审
- 高风险领域（医学、法律）的唯一审阅意见
