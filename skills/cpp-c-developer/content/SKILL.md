# C/C++ 开发专家技能

## 核心能力

### 1. 代码编写与实现

**触发场景**：
- 用户要求"用 C++ 写一个..."、"帮我写个 C 程序..."
- 需要实现特定算法或数据结构
- 创建完整的程序或函数

**工作流程**：
1. 分析需求，确定最佳语言选择
2. 设计代码结构和算法
3. 编写高质量代码，包含完整注释
4. 提供编译和运行说明

### 2. 调试与错误修复

**触发场景**：
- 用户提供错误信息或崩溃日志
- 程序行为不符合预期
- 编译报错需要解决

**工作流程**：
1. 分析错误类型（编译错误/运行时错误/逻辑错误）
2. 定位问题根源
3. 提供修复方案和预防建议

### 3. 性能优化

**触发场景**：
- 程序运行缓慢
- 内存使用过高
- CPU 占用率异常

**优化策略**：
- 算法复杂度分析
- 内存管理优化
- 并行化建议
- 编译器优化选项

### 4. 代码审查

**触发场景**：
- 用户粘贴代码要求审查
- 需要检查代码质量、安全性
- 代码风格评估

**审查维度**：
- 正确性：逻辑是否正确
- 安全性：潜在漏洞检查
- 性能：效率问题识别
- 可维护性：代码结构评估

## 代码质量标准

### 命名规范
- 变量：`snake_case` (c/cpp) 或 `camelCase` (面向对象)
- 函数：`snake_case` + 动词前缀（如 `calculate_sum`）
- 类：`PascalCase`
- 常量：`kCONSTANT_NAME` 或 `CONSTANT_NAME`

### 代码结构
```
// 文件头注释
/*
 * Project: [项目名]
 * Author: [作者]
 * Date: [日期]
 * Description: [文件功能描述]
 */

// 函数注释
/**
 * @brief 函数功能简述
 * @param param1 参数1描述
 * @return 返回值描述
 */

// 核心逻辑注释
// TODO: 待完成功能
// FIXME: 需要修复的问题
// NOTE: 重要说明
```

### 最佳实践

**C++ 最佳实践**：
- 优先使用 `std::vector` 替代原始数组
- 使用智能指针管理内存（`unique_ptr`, `shared_ptr`）
- 避免裸 `new/delete`
- 使用 RAII 惯用法
- 启用编译器的所有警告（`-Wall -Wextra`）

**C 语言最佳实践**：
- 使用 `const` 修饰不应修改的参数
- 检查所有 `malloc/calloc` 返回值
- 使用 `size_t` 处理大小
- 避免未定义行为
- 使用 `static` 限制作用域

## 常用工具与命令

### 编译命令

**C++**：
```bash
g++ -std=c++17 -Wall -Wextra -O2 source.cpp -o output
clang++ -std=c++20 -Wall -Wextra -fsanitize=address source.cpp
```

**C**：
```bash
gcc -std=c11 -Wall -Wextra -O2 source.c -o output
clang -std=c17 -Wall -Wextra -fsanitize=address source.c
```

### 调试工具
- **GDB**：GNU 调试器
- **Valgrind**：内存检测
- **AddressSanitizer**：地址错误检测
- **clang-tidy**：代码静态分析

### 代码格式化
```bash
clang-format -i source.cpp  # 格式化代码
cmake-format -i CMakeLists.txt  # 格式化 CMake
```

## 常见问题速查

| 问题 | 症状 | 解决方案 |
|------|------|----------|
| 内存泄漏 | 内存持续增长 | 使用智能指针/Valgrind 检测 |
| 空指针 | 段错误 | 添加空值检查 |
| 数组越界 | 崩溃/数据损坏 | 使用 `std::vector` 或边界检查 |
| 竞态条件 | 随机行为 | 使用互斥锁/原子操作 |
| 栈溢出 | 大数组/递归过深 | 改用堆分配/尾递归优化 |
