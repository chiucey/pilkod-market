# 智能会议助手

## 概述

智能会议助手是一款专业的会议效率工具，旨在帮助职场人士高效管理会议全流程，从会前准备到会后追踪，一站式解决会议相关的所有痛点。

本工具通过智能解析、任务提取、决策标记、多格式输出等功能，为用户提供完整的会议管理解决方案。无论是日常周会、项目评审会还是商务谈判，都能快速生成专业、可追溯的会议记录，确保会议决策得到有效执行。

本技能严格遵循五阶段工作流程：信息接收、智能分析、结构化处理、待办追踪、输出交付。每个阶段都有明确的目标、方法和质量标准，确保最终产出的会议纪要具有专业水准和高度可操作性。

## 核心价值主张

智能会议助手为用户带来三大核心价值：

第一，时间节省价值。传统手工记录会议纪要需要30-60分钟，而使用本工具仅需5-10分钟即可完成结构化输出，效率提升80%以上。用户只需上传原始会议内容，系统自动完成要点提炼、任务提取、格式整理等繁琐工作。

第二，追踪执行价值。会议纪要的核心价值不在于记录本身，而在于推动决策执行。本工具内置智能待办追踪系统，自动识别责任人、完成标准、时间节点，确保每个会议决策都能得到有效跟进。

第三，知识沉淀价值。通过结构化的会议记录和标签系统，用户可以快速检索历史会议内容、追溯决策过程、复盘项目经验，实现组织知识的有效积累和传承。

## 核心工作流程

### 第一阶段：信息接收与预处理

本阶段的核心任务是对用户输入的会议内容进行接收、格式识别和结构化预处理。处理的准确性和完整性直接影响后续分析的质量。

#### 1.1 输入识别与分类

接收到用户输入后，首先进行输入类型识别：

**语音转文字识别**：当用户上传或粘贴语音转文字内容时，系统需要识别以下结构化元素：

- 发言人标识（通过用户名、颜色、特殊标记等识别）
- 时间戳标记（识别发言时间点）
- 段落分割（识别话题转换）
- 情感标记（如笑声、掌声等非语言信息）

**纯文字识别**：当用户直接粘贴文字内容时，需要识别：

- 发言人切换（通过格式标记识别）
- 话题分段（通过内容主题识别）
- 重要标记（通过符号如TODO、ACTION、决定等识别）
- 附件引用（识别提及的文档、链接等）

**文档导入识别**：当用户上传文件时：

- 自动提取文本内容
- 识别文档结构和层级
- 提取元数据（标题、日期、作者等）
- 识别附件和嵌入内容

#### 1.2 预处理质量控制

预处理完成后必须进行质量校验：

- 检查发言内容是否完整（无截断、无乱码）
- 识别发言人数量是否合理
- 检查时间跨度是否符合会议特征
- 识别可能的信息遗漏或异常格式
- 生成预处理质量报告

#### 1.3 会议基本信息提取

无论输入格式如何，都需要提取以下会议基本信息：

| 信息类别 | 具体字段 | 提取优先级 |
|---------|---------|-----------|
| 会议主题 | 会议标题、主要讨论议题 | 必需 |
| 会议时间 | 开始时间、预计时长、实际时长 | 必需 |
| 参与人员 | 主持人、记录人、发言人名单 | 必需 |
| 会议类型 | 周会、评审会、头脑风暴、一对一 | 建议 |
| 关联项目 | 提及的项目名称、代号 | 可选 |
| 会议目的 | 会议预期的产出和目标 | 建议 |

如果用户未提供会议基本信息，系统应通过内容分析智能推断，并在报告中标注“系统推断”标记。

### 第二阶段：智能内容分析

本阶段基于预处理后的结构化数据，进行多维度的专业内容分析。分析结果将作为纪要生成和待办追踪的依据。

#### 2.1 语义内容分析

**主题分段**：将会议内容按照讨论主题进行智能分段，每段内容对应一个子议题。分段原则：

- 话题转换识别（通过关键词、语气、发言人变化识别）
- 内容密度评估（评估每段的信息量和重要性）
- 逻辑连贯性验证（确保分段不破坏内容逻辑）

**要点提炼**：对每个主题段落进行要点提炼，提炼标准：

- 核心观点（这段讨论的核心结论是什么）
- 关键论据（支持结论的主要论据和数据）
- 争议焦点（存在的分歧点和未解决的问题）
- 后续行动（讨论中提及的下一步计划）

**情感与氛围分析**：识别会议讨论中的情感倾向：

- 共识程度（高度共识、分歧明显、待定）
- 决策倾向（积极推进、谨慎评估、暂时搁置）
- 风险关注（识别讨论中提及的风险点）
- 机会识别（识别讨论中产生的新想法和新机会）

#### 2.2 关键要素识别

**决策点识别**：识别会议中的关键决策，提取以下信息：

| 决策要素 | 说明 | 示例 |
|---------|------|------|
| 决策内容 | 具体的决策是什么 | 确认Q3季度目标为500万 |
| 决策依据 | 做出决策的原因和背景 | 基于上半年增长趋势 |
| 决策责任人 | 谁做出了或执行该决策 | 产品部张经理 |
| 决策时间节点 | 决策生效或执行的时间 | 7月15日前完成 |
| 评估标准 | 如何判断决策是否成功 | 季度末达成率≥80% |

**任务提取**：从会议内容中提取可执行的任务，提取标准：

| 任务要素 | 说明 | 示例 |
|---------|------|------|
| 任务描述 | 具体要做什么 | 完成竞品分析报告 |
| 责任人 | 谁负责执行 | 市场部李明 |
| 协作人 | 需要谁配合 | 产品部支持 |
| 截止时间 | 何时完成 | 下周三前 |
| 完成标准 | 如何判断完成 | 包含竞品功能对比、价格分析 |
| 优先级 | 紧急程度 | 高 |
| 关联决策 | 关联的会议决策 | 决策编号#003 |

**问题识别**：识别会议中提出的待解决问题：

- 已解决的问题（会议中讨论并达成共识的议题）
- 正在解决的问题（正在进行讨论和推进的议题）
- 待解决的问题（识别到但未在本会议中解决的议题）
- 新发现的问题（会议中新发现需要关注的问题）

#### 2.3 上下文补充

**背景资料关联**：如果用户提供了相关背景文档，系统应关联分析：

- 与历史会议的关联（是否有相关历史讨论）
- 与项目文档的关联（是否涉及项目相关方）
- 与外部资料的关联（市场数据、行业报告等）

**术语解释**：识别并标注专业术语：

- 技术术语（提供简洁解释）
- 缩写简称（提供完整形式）
- 人名和部门（提供身份信息）
- 产品和项目（提供简要说明）

### 第三阶段：结构化处理与生成

本阶段基于分析结果，生成结构化的会议纪要内容。

#### 3.1 纪要结构设计

**标准会议纪要结构**：

```

## 会议议程

2. [议程项2]
3. [议程项3]

## 讨论内容

**讨论要点**：
```

#### 3.2 内容填充规则

**讨论内容填充**：

- 每个议题的讨论内容应完整呈现核心观点和分歧
- 引用重要发言时，使用引号标注发言人
- 数据和事实陈述应标注来源
- 保持客观中立，不添加主观评价

**决策记录填充**：

- 决策编号采用#前缀，自增编号
- 每条决策必须包含责任人（不能为空）
- 时间节点必须具体到日期
- 评估标准必须可量化

**待办任务填充**：

- 任务描述必须使用动词开头
- 责任人必须明确到个人
- 截止时间必须具体
- 优先级分为高、中、低三级

### 第四阶段：待办追踪与提醒

本阶段对待办任务进行追踪管理，确保会议决策得到有效执行。

#### 4.1 任务状态管理

| 状态 | 标识 | 说明 |
|-----|------|------|
| 待开始 | ⏳ | 任务已创建，尚未开始执行 |
| 进行中 | 🔄 | 任务正在执行中 |
| 已完成 | ✅ | 任务已完成，达到完成标准 |
| 已延期 | ⏰ | 任务未按时完成，需要新截止时间 |
| 已取消 | ❌ | 任务被取消或优先级降低 |
| 已阻塞 | 🚧 | 任务因依赖条件未满足而阻塞 |

#### 4.2 追踪提醒机制

**到期提醒**：在任务截止时间前24小时发送提醒：

- 提醒内容：任务名称、责任人、剩余时间
- 提醒方式：摘要摘要+待办清单
- 提醒对象：责任人本人

**延期预警**：当任务即将到期但未完成时：

- 预警内容：任务状态、阻塞原因、处理建议
- 升级机制：逾期3天自动升级给上级主管

**完成确认**：当任务标记为完成时：

- 自动生成完成报告
- 通知相关利益方
- 关联对应的会议决策

#### 4.3 任务依赖管理

识别任务之间的依赖关系：

- 前置任务（必须先完成的任务）
- 后续任务（依赖当前任务的任务）
- 并行任务（可以同时执行的任务）
- 阻塞任务（当前任务阻塞的任务）

依赖管理规则：

- 前置任务未完成，后续任务不能标记为完成
- 依赖链变更时自动通知相关责任人
- 识别循环依赖并报告错误

## 会议类型专项处理

### 周例会处理规范

周例会是最常见的会议类型，处理时需要注意以下要点：

**结构特点**：

- 固定议程：上周回顾、本周计划、问题反馈、资源协调
- 高频模式：每周重复，内容结构高度相似
- 追踪需求：周任务需要持续追踪直到完成

**处理策略**：

- 自动识别周期（每周、每月、每季度）
- 与历史周会对比，发现趋势和变化
- 重点关注未完成任务和持续问题
- 生成周报汇总，便于管理层查阅

**输出优化**：

- 突出变化和异常
- 简化常规内容
- 强化待办追踪
- 便于快速浏览

### 项目评审会处理规范

项目评审会是重要的决策节点，处理时需要更加谨慎：

**结构特点**：

- 决策导向：结论和下一步是关键
- 专业术语：需要准确解释
- 文档关联：与项目文档紧密关联
- 干系人众多：需要明确各方的立场

**处理策略**：

- 准确识别每个评审意见的提出者
- 区分“原则同意”和“有条件通过”
- 标注需要后续确认的未决事项
- 记录评审中的分歧点和妥协方案

**输出优化**：

- 清晰的评审结论
- 明确的后续行动清单
- 完整的意见汇总（同意/修改/否决）
- 便于决策层快速了解情况

### 头脑风暴会议处理规范

头脑风暴会议的处理与其他会议有显著不同：

**结构特点**：

- 创意发散：大量想法和提议
- 不做评判：鼓励自由表达
- 记录完整性：所有想法都值得记录
- 需要后续整理：会后需要归纳分类

**处理策略**：

- 保留所有发言，不做删减
- 识别相似想法，进行合并建议
- 标注新颖想法（与历史讨论对比）
- 评估可行性（可选）

**输出优化**：

- 想法清单（按类别分组）
- 新颖度评分
- 可行性初步评估
- 后续跟进建议

### 一对一会议处理规范

一对一会议通常涉及敏感内容，处理时需要特别注意：

**结构特点**：

- 私密性强：内容不宜广泛分享
- 个人发展：常涉及职业发展和反馈
- 问题深入：讨论更深入和具体
- 关系建设：情感交流也是重要部分

**处理策略**：

- 默认设置为私密（需用户确认公开范围）
- 重点记录个人反馈和发展计划
- 区分工作问题和个人问题
- 谨慎处理负面反馈的记录

**输出优化**：

- 行动项（双方各自的任务）
- 个人发展计划
- 问题解决进度
- 关系维护建议

## 会议纪要撰写规范

### 内容撰写原则

**准确性原则**：

- 忠实记录原始内容，不添加个人理解
- 数据和事实必须准确，可标注来源
- 引用发言时使用原话，可选择精简
- 标注不确定或有歧义的内容

**完整性原则**：

- 涵盖所有重要讨论点
- 不遗漏任何决策和任务
- 保留关键背景信息
- 记录未解决的问题和风险

**简洁性原则**：

- 删除无意义的填充词
- 合并重复的表述
- 使用规范术语
- 避免冗长的句子

**可操作性原则**：

- 任务描述明确具体
- 责任人明确到个人
- 时间节点明确到日期
- 完成标准可量化

### 语言风格指南

**正式程度**：根据会议类型选择：

| 会议类型 | 正式程度 | 用语特点 |
|---------|---------|---------|
| 董事会 | 高度正式 | 书面语、规范表达 |
| 项目评审会 | 正式 | 书面语、专业术语 |
| 周例会 | 中等正式 | 半书面语、简洁明了 |
| 头脑风暴 | 轻松 | 口语化、鼓励创新 |
| 一对一 | 视关系而定 | 亲切、直接 |

**常用表达模板**：

| 场景 | 表达模板 |
|------|---------|
| 决策确认 | "会议确认/决定..."、"经讨论决定..."、"批准..." |
| 任务分配 | "由X负责..."、"X主导，X配合..."、"X需在...前完成..." |
| 问题记录 | "会议讨论了...问题"、"针对...问题，提出了..." |
| 进度汇报 | "已完成..."、"正在进行..."、"计划..." |
| 意见汇总 | "会议认为..."、"大家普遍认为..."、"存在不同意见..." |

## 工具使用规范

### 语音转文字处理

**文字提取**：根据输入格式选择处理方式：

- PDF文档：使用pdfplumber或PyPDF2提取文本
- Word文档：使用python-docx读取结构化内容
- 图片内容：使用OCR识别文字
- 纯文本：直接解析

**结构化处理**：对提取的文字内容进行结构化：

- 发言人识别（通过格式标记识别）
- 时间戳解析（转换相对时间为实际时间）
- 段落分割（识别话题转换点）
- 内容清理（去除无意义的填充词）

### 文档生成

**Markdown格式**：生成标准Markdown格式的会议纪要，便于阅读和检索。

**Word文档**：使用python-docx库生成专业的Word文档：

- 标准格式模板
- 自动生成目录
- 样式统一
- 支持导出

**PDF转换**：使用LibreOffice将Word文档转换为PDF：

```bash
libreoffice --headless --convert-to pdf output.docx
```

**任务清单**：生成可导入的任务管理工具格式：

- CSV格式（通用导入）
- JSON格式（API集成）
- Markdown格式（便于协作编辑）

### 质量检查

**完整性检查**：

- 所有议题是否都有讨论记录
- 所有决策是否都有责任人和时间节点
- 所有任务是否都有明确的描述和标准

**准确性检查**：

- 数据和事实是否标注来源
- 人名和部门是否准确
- 时间节点是否符合逻辑

**一致性检查**：

- 纪要内容是否与原始记录一致

- 任务责任人是否在参与人员名单中

## 常见问题处理

### 输入内容质量差

**问题表现**：语音转文字识别错误多、内容截断、格式混乱。

**处理策略**：

- 识别并标注可能的识别错误
- 标注内容完整性问题
- 提供格式修复建议
- 引导用户提供更完整的内容

**预防措施**：

- 建议使用高质量的语音转文字工具
- 建议会议开始前确认设备正常
- 建议使用标准格式模板记录

### 会议内容不完整

**问题表现**：缺少关键信息，如未提及时间、人员不明确。

**处理策略**：

- 标注缺失的必需信息
- 提供默认值（可标注“系统推断”）
- 引导用户补充缺失信息
- 生成缺失信息清单

### 任务提取困难

**问题表现**：发言中未明确任务责任人和截止时间。

**处理策略**：

- 识别隐含的任务描述
- 标注默认责任人（通常是提出人或发言人的直属上级）
- 标注需要确认的时间节点
- 提供任务信息确认清单

### 决策识别模糊

**问题表现**：讨论中有多个可能的决策方向，未明确最终决定。

**处理策略**：

- 列出讨论中的不同选项
- 标注达成的共识点和分歧点
- 识别“原则同意”类的有条件决策
- 建议后续需要做出的决定
