# 人才画像 Skill 需求文档（修订版 V2.1）

## 一、产品定位与核心价值

### 1.1 产品定位

人才画像 Skill 是一款面向企业管理者、HR 负责人和创业者的智能化人才画像生成工具。通过**"系统推测 → 用户确认"**的对话模式，系统性地采集岗位需求信息，结合行业最佳实践与冰山模型方法论，输出结构化、可操作的人才画像文档。

### 1.2 核心价值

| 价值维度 | 描述 |
|---------|------|
| **从被动问答到主动推断** | 系统基于用户提供的初始线索主动推断公司信息，用户只需确认修正，而非从头回答大量问题，大幅降低用户输入负担 |
| **降低招聘试错成本** | 通过清晰的人才画像定义，在简历筛选、面试评估、试用期考核等环节提供统一标准，减少因人岗不匹配导致的试用期离职和时间浪费 |
| **打通招聘-绩效-晋升全链路** | 人才画像不仅服务于招聘，还为入职后的绩效目标设定、能力评估、晋升决策提供锚点，实现人才管理闭环 |

### 1.3 目标用户

- 初创企业创始人或 CEO，需要系统化招聘核心团队
- HR 负责人或招聘经理，需要建立岗位人才标准
- 业务部门负责人，需要明确招聘需求并参与面试评估
- 人力资源顾问或猎头，需要快速了解客户需求并输出候选人画像

## 二、核心交互模式

### 2.1 设计理念

采用**"智能预判 + 确认修正"**的对话模式，区别于传统的"一问一答"式信息采集：

| 传统模式 | 创新模式（本产品） |
|---------|------------------|
| 系统提问 → 用户回答 → 重复直到完成 | 系统预判 → 用户确认/修正 → 补充追问 |
| 用户需回忆并组织大量信息 | 用户只需"是/否"或"改一下" |
| 信息采集效率低，用户疲劳感强 | 减少80%的问题数量，用户体验更优 |

## 三、功能架构与详细设计

### 3.1 第一阶段：公司信息采集确认

#### 3.1.1 设计原则

**核心调整**：此阶段采用"问全名 → 搜索 → 确认"的流程，确保公司信息准确无误。

#### 3.1.2 信息采集流程

```
┌─────────────────────────────────────────────────────────────┐
│                    公司信息采集流程                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  [Step 1] 系统询问公司全称                                   │
│     ↓                                                        │
│  [Step 2] 用户输入公司全称                                   │
│     ↓                                                        │
│  [Step 3] 系统基于公司全称进行网络搜索                        │
│     ↓                                                        │
│  [Step 4] 两种情况处理：                                     │
│     • 搜索成功 → 推送搜索结果，用户确认/修改                  │
│     • 搜索失败 → 提示用户手动输入公司基本信息                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 3.1.3 Step 1 - 询问公司全称

**系统询问话术**：

```
🎯 请告诉我您所在公司的全称（尽量完整准确，便于我搜索核实公司信息）

示例：
• "北京字节跳动科技有限公司"
• "深圳市腾讯计算机系统有限公司"
• "特斯拉（上海）有限公司"

请直接输入公司全称：
```

**设计要点**：
- 明确说明"请输入公司全称"
- 提示用户说明原因："便于搜索核实公司信息"
- 提供1-2个示例作为参考
- 公司全称与品牌名可能不同（如：品牌名"华米" vs 全称"安徽华米信息科技有限公司"）

#### 3.1.4 Step 2-3 - 网络搜索与信息获取

**系统行为**：
- 用户输入公司全称后，系统自动进行网络搜索
- 搜索维度：公司基本信息、发展历程、业务范围、组织规模、融资情况等

**搜索优先级**：

| 信息维度 | 来源优先级 | 说明 |
|---------|-----------|------|
| 官方公告/财报 | P0 | 上市公司年报、招股书 |
| 权威媒体/官网 | P1 | 百度百科、官网、公司公告 |
| 行业资讯 | P2 | 36氪、虎嗅、亿欧等科技媒体 |
| 招聘平台 | P3 | 拉勾、Boss直聘上的公司介绍 |

#### 3.1.5 Step 4a - 搜索成功时

**系统推送格式**：

```
📋 已基于您提供的公司名称"华米科技"，搜索到以下信息，请确认：

【公司基本信息】
• 公司全称：安徽华米信息科技有限公司（Huami Corporation）
• 成立时间：2013年
• 总部位置：安徽省合肥市
• 所处行业：智能可穿戴设备 / 健康科技
• 发展阶段：成熟期（2018年纽交所上市，代码ZEPP）
• 商业模式：B2C（小米品牌）+ 自有品牌（Amazfit/Zepp）

【组织规模】
• 员工数量：约1200人
• 办公室：北京、合肥、深圳、上海、南京、北美、欧洲

【核心技术】
• 自研芯片：黄山系列AI芯片
• 核心传感器：BioTracker PPG传感器
• 健康算法：心率、睡眠、血氧等AI引擎

【市场地位】
• 全球智能手环出货量前三
• Amazfit智能手表全球前四
• 小米生态链核心企业

【使命愿景】
• 使命："科技连接健康"
• 愿景：构筑全球健康生态

⚠️ 请确认以上信息是否准确，如需修改请直接指出。
```

#### 3.1.6 Step 4b - 搜索失败时

**触发条件**：网络搜索未找到有效信息，或搜索结果置信度低于阈值

**系统推送格式**：

```
⚠️ 未能在网上找到"XXX公司"的相关信息，可能是以下原因：
• 公司名称不完整或有误
• 公司规模较小，公开信息较少
• 公司是内部项目或子公司

【请选择处理方式】
A. 修改公司名称（请提供更完整的全称）
B. 手动输入公司基本信息（我会引导您填写）
C. 跳过公司确认，直接描述岗位需求

请回复选项或直接描述您的选择：
```

**手动输入模式**：

如果用户选择B，系统引导用户输入基本信息：

```
📋 请告诉我贵公司的基本情况（至少提供前3项）：

1. 公司名称：_______________
2. 所在行业：_______________
3. 当前团队规模：_______________（如：10人/50人/200人）
4. 发展阶段：_______________（如：初创/成长期/成熟期）
5. 主营业务/产品：_______________
6. 当前面临的核心挑战（可选）：_______________

请填写以上信息，或用一段话描述公司情况：
```

#### 3.1.7 用户确认与修正

**用户确认方式**：

| 场景 | 用户操作 | 系统响应 |
|------|---------|---------|
| 信息准确 | 回复"确认"或"没问题" | 进入下一阶段 |
| 部分需要修改 | 回复"XX需要改成YY" | 更新对应信息，重新推送确认 |
| 补充信息 | 回复"补充：XX" | 将补充信息加入画像 |
| 全部不准确 | 回复"重新搜索"并提供新公司名 | 重新执行搜索流程 |

#### 3.1.8 搜索结果置信度标注

系统对推送的推断信息标注置信度：

| 标注 | 含义 | 视觉提示 |
|------|------|---------|
| "✅ 已确认" | 用户明确确认的信息 | 绿色标识 |
| "（推测）" | 基于公开信息推断，逻辑可靠 | 蓝色标注 |
| "（未确认）" | 无法核实，需要用户补充 | 灰色标注 |

### 3.2 第二阶段：部门与业务场景选择

#### 3.2.1 设计原则

**核心调整**：部门确认不强制选择预设选项，允许用户自由描述部门职责。重点看"部门做什么"而非"部门叫什么名字"。

#### 3.2.2 部门职责确认流程

```
┌─────────────────────────────────────────────────────────────┐
│                   部门职责确认流程                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  [Step 1] 系统询问该岗位所属的部门职责                       │
│     ↓                                                        │
│  [Step 2] 用户可选：                                         │
│     • 直接描述部门职责                                       │
│     • 选择预设选项 + 补充说明                                │
│     • 上传/粘贴已有JD                                        │
│     ↓                                                        │
│  [Step 3] 系统确认理解，进入下一问题                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 3.2.3 Step 1 - 询问部门职责

**系统询问话术**：

```
📌 请描述一下这个岗位所在的部门，主要做什么业务？

【回答方式】请选择最方便的方式：

A. 直接描述（请用2-3句话描述部门核心业务）
   示例："负责公司数据平台建设和业务数据分析，支持产品、运营、销售等部门"

B. 选择关键词（可多选）+ 补充说明
   • 数据分析/BI
   • 技术研发/算法
   • 产品运营/增长
   • 市场销售/客户
   • 职能支持（HR/财务/行政）
   • 其他：_______________

C. 我有现成的JD，直接粘贴给我
   （支持文本粘贴，我会提取关键信息）

请选择A/B/C，或直接描述您的答案：
```

#### 3.2.4 Step 2 - 用户回答方式

**方式A - 直接描述**：

用户直接用文字描述部门职责，系统理解并确认：

```
系统："您描述的是：负责公司数据平台建设和业务数据分析，支持产品、运营、销售等部门。我理解这个部门的核心职责是：
1. 数据平台搭建与维护
2. 业务数据分析与洞察
3. 支持各业务部门的数据需求

是否准确？如果准确我将基于这些理解继续下一个问题。"
```

**方式B - 选择关键词 + 补充**：

用户选择预设关键词，系统组合理解：

```
用户选择：B（数据分析/BI）+ E（职能支持）+ 其他：直接汇报给高管

系统："我理解这个部门是数据团队，负责数据分析和BI建设，同时直接汇报给高管，对吗？"
```

**方式C - 粘贴JD**：

用户粘贴现有JD文本，系统提取关键信息（详见3.3.4节）

#### 3.2.5 信息采集维度

| 维度 | 采集内容 | 提示选项示例 |
|------|---------|-------------|
| **部门职责** | 需要招聘的部门名称 | 产品部 / 技术部 / 运营部 / 市场部 / 销售部 / 职能部（HR/财务/行政）/ 其他 |
| **岗位层级** | 中低端 or 高端 | 高层管理（VP、CFO等）/ 中层管理（总监、经理）/ 基层执行（专员、助理） |
| **岗位类型** | 核心岗位 or 支持性岗位 | 核心业务岗 / 支持性岗位 / 中台岗位 / 管理岗 |
| **紧迫程度** | 招聘的紧急程度 | 紧急（2周内到位）/ 正常（1个月内到位）/ 储备（3个月以上） |
| **招聘渠道偏好** | 期望的候选人来源 | 社招为主 / 校招为主 / 内推优先 / 猎头渠道 |

#### 3.2.6 业务场景深入提问

在确定部门后，系统通过**引导式选择 + 开放式补充**的方式采集业务场景信息：

**问题模板（含选项）**：

```

【核心业务场景】请选择最符合的 1-2 项：

○ 销售获客 - 渠道拓展 / 客户开拓 / 业绩增长
○ 运营增长 - 用户增长 / 留存提升 / 变现探索
○ 技术支撑 - 系统架构 / 运维保障 / 安全合规
○ 市场品牌 - 品牌建设 / 市场推广 / 公关传播
○ 职能支持 - HR管理 / 财务合规 / 行政后勤

【补充说明】（可选）
如果以上选项不能准确描述，请简要说明该部门的核心业务：
```

#### 3.2.8 产出痛点收集

【产出维度】请选择该岗位最重要的产出（最多3项）：

【具体描述】

### 3.3 第三阶段：岗位要求确认与画像生成

#### 3.3.1 设计原则

**核心调整**：
1. 增加"文本粘贴JD"功能，用户可直接粘贴已有职位描述
2. 最终输出**两个版本**——完整版与精缩版，满足不同使用场景

#### 3.3.2 岗位要求确认流程

```
┌─────────────────────────────────────────────────────────────┐
│                  岗位要求确认流程                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  [Step 1] 系统询问岗位要求                                    │
│     ↓                                                        │
│  [Step 2] 用户可选：                                         │
│     • 直接回答引导问题（继续对话式）                          │
│     • 粘贴已有JD文本                                         │
│     • 以上都有                                               │
│     ↓                                                        │
│  [Step 3] 系统整合信息，生成人才画像                          │
│     ↓                                                        │
│  [Step 4] 输出双版本，用户确认/调整                           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 3.3.3 Step 1 - 询问岗位要求

**系统询问话术**：

```
🎯 现在我们来确认岗位的具体要求。

【回答方式】请选择最方便的方式：

A. 继续回答引导问题（我会一步步问您）
   • 该岗位需要解决什么问题？
   • 岗位的核心产出是什么？
   • 对候选人的基本要求？

B. 我有现成的JD，直接粘贴给我
   （支持文本粘贴，我会提取关键信息并确认）

C. 以上都有（我先粘贴JD，再补充回答引导问题）

请选择A/B/C：
```

#### 3.3.4 Step 2 - JD文本粘贴功能

**系统询问话术**：

```
📋 请粘贴您现有的职位描述（JD）或岗位要求说明。

【输入要求】
• 格式：支持纯文本粘贴（不需要排版）
• 来源：招聘网站JD、内部招聘文档、邮件内容等均可
• 内容：至少包含岗位职责和任职要求

【示例格式】
岗位职责：
1. 负责公司数据平台搭建
2. 输出业务数据分析报告
3. 支持各业务部门的数据需求

任职要求：
1. 3年以上数据分析经验
2. 精通SQL和Python
3. 有互联网公司经验优先

请直接粘贴：
```

**系统解析与确认**：

用户粘贴后，系统提取关键信息并确认：
