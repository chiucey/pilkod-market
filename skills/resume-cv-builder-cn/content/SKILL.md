## 写作指南

### 个人简介公式

```
[职位名称]，拥有[X]年[领域]经验。
成功实现[关键成就]，擅长[核心技能]。
寻求在[公司类型/领域]发展。
```

**示例：**
```
高级软件工程师，拥有7年前后端开发经验。
成功将系统延迟降低40%，带领5人以上技术团队。
精通Java、Spring Boot和微服务架构。寻求在互联网金融领域深耕发展。
```

### 要点描述公式（CAR法则-中文版）

```
[动作动词] + [任务/项目] + [量化成果]
```

**强动作动词分类：**

| 领导管理 | 技术开发 | 业务增长 | 效率优化 |
|---------|---------|---------|---------|
| 主导 | 设计 | 提升 | 降低 |
| 带领 | 开发 | 增长 | 优化 |
| 管理 | 构建 | 拓展 | 精简 |
| 指导 | 实现 | 推动 | 自动化 |
| 协调 | 搭建 | 创造 | 整合 |

**示例对比：**
```
❌ 弱：负责团队管理工作
✅ 强：带领跨职能团队8名工程师，提前2周交付3个核心功能模块

❌ 弱：负责网站性能优化
✅ 强：优化数据库查询策略，页面加载时间降低65%，用户留存率提升23%

❌ 弱：协助处理客户问题
✅ 强：月均处理500+客户工单，客户满意度达98%，问题升级率降低40%
```

### 量化成果的重要性

| 避免写 | 改为写 |
|-------|-------|
| 管理团队 | 管理跨3个时区的12人技术团队 |
| 业绩提升 | 提升销售额230万元（同比增长34%） |
| 提高效率 | 将处理时间从4小时缩短至15分钟 |
| 负责预算 | 管理年度预算50万元，执行率100% |
| 用户众多 | 平台日活用户5万+ |

## ATS优化（中文简历）

### 应该做 ✅

- 使用标准板块标题（工作经历、教育背景、技能特长）
- 包含岗位描述中的关键词
- 使用常见的职位名称
- 首次提及英文缩写时标注中文：如"搜索引擎优化（SEO）"
- 使用标准字体（微软雅黑、宋体、黑体）
- 保存为.docx或.pdf格式（非扫描图片）

### 避免做 ❌

- 不使用复杂表格、多栏布局
- 不使用页眉页脚（ATS可能无法读取）
- 不使用图片、Logo或图形元素
- 不使用创意板块名称（"我的成长历程" → "工作经历"）
- 避免特殊字符和图标
- 避免使用图片扫描生成的PDF

### 关键词优化

从岗位描述中提取关键词的方法：
1. 仔细阅读JD，标记出现2次以上的词
2. 注意职位要求的硬技能（技术栈、工具）
3. 识别软技能关键词（领导力、沟通能力等）

## 导出命令

> ✅ Pandoc 已安装（v2.17.1.1），支持 PDF/HTML/DOCX 导出。PDF 使用 wkhtmltopdf 生成。

### Markdown转HTML
```bash
pandoc resume.md -o resume.html --standalone --css="https://cdn.jsdelivr.net/npm/water.css@2/out/water.css"
```

### Markdown转PDF
```bash
# 先转HTML，再转PDF（推荐，中文支持更好）
pandoc resume.md -o resume.html --standalone
wkhtmltopdf resume.html resume.pdf

# 或直接用 pandoc（需要xelatex）
pandoc resume.md -o resume.pdf --pdf-engine=xelatex -V mainfont='Microsoft YaHei'
```

### Markdown转DOCX
```bash
pandoc resume.md -o resume.docx
```

### 快捷导出脚本
```bash
# 使用附带的 export.sh 脚本
./export.sh resume.md html   # 导出HTML
./export.sh resume.md pdf    # 导出PDF
./export.sh resume.md docx   # 导出DOCX
```

## 针对特定岗位优化

### 步骤流程

1. **提取关键词** 从岗位描述中提取高频词汇
2. **匹配技能** 确保技能板块体现JD要求
3. **重新排序** 将最相关的经历放在前面
4. **镜像语言** 使用与JD相同的术语
5. **定制简介** 提及目标公司和具体职位

### 优化示例

**岗位描述要求：**
> "要求React、TypeScript和云服务开发经验，有团队管理经验优先。"

**优化前：**
```
• 开发Web应用程序，使用多种技术栈
```

**优化后：**
```
• 主导4人小组使用React/TypeScript构建企业管理系统，部署至阿里云，日活用户5万+
```

## 常见错误避免

| 错误做法 | 正确做法 |
|---------|---------|
| 包含"简历后附"或"面议" | 删除 - 这些信息已过时 |
| 使用人称代词（我、本人） | 以动作动词开头 |
| 罗列工作职责而非成就 | 聚焦成果和影响力 |
| 列出过时技能 | 保持技能新鲜度和相关性 |
| 超过2页 | 10年以下经验1页，10年以上最多2页 |
| 使用泛泛的求职目标 | 用针对性简介替代 |
| 格式不一致 | 统一日期格式、符号风格 |
| 错别字和语法错误 | 多次校对检查 |

## 快速检查清单

```
□ 联系方式准确且专业
□ 邮箱地址正式（如非 zhangsan@email.com）
□ 个人简介针对目标职位定制
□ 所有要点以动作动词开头
□ 成就包含具体数据和指标
□ 技能与岗位描述关键词匹配
□ 教育背景只包含相关内容
□ 无错别字或语法错误
□ 格式统一规范
□ 保存为ATS友好格式
□ 文件命名专业（如：张三_软件工程师_简历.pdf）
```
