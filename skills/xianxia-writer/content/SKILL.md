# Xianxia Web Novel Writer

修真/仙侠网文长篇写作助手。围绕"设定不崩 + 节奏不断 + 钩子够狠"三件事设计。

## Inputs to collect

按需追问，不要一次性把用户问烦：

- **当前工序**：开书（全流水线）/ 连载大纲 / 单章正文 / 润色改稿。决定走哪条主路径
- **核心创意**（如"废柴少年捡到古功法"）。没有就主动给 3 个差异化备选让用户挑
- **目标平台**：起点 / 番茄 / 晋江 / 刺猬猫 / 通用。影响审核尺度和节奏风格
- **目标规模**：长篇（≥ 300 章）/ 中篇（80-300 章）/ 短篇连载体（≤ 80 章）
- **参考作品**（可选）：让 skill 模仿文风或套用某本书的成熟套路

## Procedure

### 阶段 1：设定搭建（开书 / 大纲前必做）

修真长篇最常见的死法是设定穿帮。这一阶段的目标是产出"硬设定文档"，后续所有写作必须严格遵守。

1. **修炼境界**：默认套 `references/power-system-template.md` 的 9 阶体系（炼气/筑基/金丹/元婴/化神/合体/大乘/渡劫/真仙）。用户有特殊设计（如简化版、加血脉设定）则按用户改，但必须保留"可数 + 可比"两个特性
2. **势力地图**：至少 3 个对立或竞争势力（宗门/王朝/散修联盟/异族），每个标注实力层级、核心利益、势力范围、与主角的潜在关系
3. **资源体系**：灵石/丹药/法宝/灵兽/阵法/功法六类至少各有 3-5 级划分，避免后期"资源通胀"
4. **设定一致性锁**：把上面的硬设定整理成 `设定/硬设定.md`（建议 YAML 或 markdown 表），后续每章写作前都要回看

不解释清楚设定就开写 → 写到第 100 章必然要返工。

### 阶段 2：大纲推演

5. **核心冲突公式**：用"主角想要 X，谁在阻止 Y，代价 Z"一句话讲清。这是所有剧情的根
6. **分卷结构**：按"5 卷 × 100 章"或"3 卷 × 80 章"分。每卷必须有：核心升级 + 核心 Boss + 一条伏笔回收 + 一条新伏笔埋下
7. **支线网络**：至少三条独立支线交织主线 —— 感情线（女角色 ≥ 3）、师门线（恩师/同门/反目）、身世线（血脉/前世/穿越原因）。支线不能喧宾夺主，但要在每卷收尾时给一个阶段性交代
8. **爽点节奏表**（关键）：每 10 章 1 次小爽（碾压/收获）、每 50 章 1 次大爽（突破/越级战胜）、每 100 章 1 次超级爽（揭阴谋/大势力倒台）。这表是连载不崩的命脉，写完大纲必须单独成文件
9. **审核风险标注**：涉及政治、暴力、血腥、宗教的剧情提前打 ⚠️ 标，避免写到一半被平台下架

### 阶段 3：章节正文（核心产出环节）

每章都要走"章前细纲 → 正文 → 章末钩子"三步。

10. **章前细纲**：写正文前先出 200 字以内的细纲，含 —— 本章核心事件（1 句）、情绪曲线、出场人物、关键战斗/对话节点、章末钩子方向
11. **正文写作**（3000-5000 字为目标）：
    - **开篇 200 字**：必须出现冲突或悬念。修真读者耐心 ≤ 1 段，开篇慢热 = 直接弃书
    - **中段**：推进剧情 + 埋中期伏笔 + 至少一个"装逼打脸"或"碾压"爽点（每 10 章一次的节奏要求）
    - **末段 300-500 字**：出"本章结果 + 章末钩子"
12. **章末钩子**：从 `references/hook-patterns.md` 选 1-3 个类型组合。钩子要满足三重奏：
    - **短期钩子**：本章冲突未完（追杀/比斗中断）
    - **中期钩子**：刚出现新威胁或新谜题
    - **长期钩子**：身世/远古/大因果浮现一角

钩子不强 = 留存崩盘，这一项宁可写过头也别省。

### 阶段 4：润色改稿

13. **一致性自检**：用 `设定/硬设定.md` 逐条对照本章 —— 境界/法宝/势力/资源有无出格。出格立刻改
14. **节奏检查**：本章是否有"压抑 → 小爆发 → 大爆发"的情绪曲线？平铺直叙要加冲突
15. **对话去水**：修真对话要"短句 + 留白 + 反转"。删掉解释性对话（"我来告诉你这是 XXX"），改用动作和旁白
16. **钩子加力**：章末钩子如果只是"继续修炼"这种平钩，必须重写到让人想翻下一章

## Output contract

按工序输出不同组合，文件全部进 `<书名>/` 目录：

| 工序 | 输出文件 |
|---|---|
| 开书 | `设定/硬设定.md` + `设定/爽点节奏表.md` + `大纲/分卷大纲.md` + `正文/卷X/第NNN章_<章名>.md` × 3 |
| 连载大纲 | `设定/硬设定.md` + `大纲/分卷大纲.md`（含每卷每章 1 句细纲） |
| 单章正文 | `正文/卷X/第NNN章_<章名>.md` + `正文/章前细纲.md`（细纲建议也存，方便后期改稿时回忆） |
| 润色 | 改写后的章节 + `修改说明.md`（动了什么 + 为什么） |

文件名规范：`<书名>/<分类>/<编号>_<名称>.md`

## Failure handling

- **用户没给核心创意** → 不要硬上，主动给 3 个差异化备选（废柴逆袭 / 老怪转世 / 系统流 / 血脉觉醒 / 双修 等），让用户挑
- **设定穿帮**（如筑基期使用元婴期法宝）→ 立即停下，回 `设定/硬设定.md` 校正；如果是设定本身有漏洞，停下来跟用户确认是否调整设定
- **灵感枯竭 / 情节卡壳** → 调 `references/genre-conventions.md` 的套路模板，给出 3 个可能走向，不要在原地打转
- **战力失衡**（升级太快/太慢）→ 重读"爽点节奏表"找节奏错位点，按表补/删事件
- **审核红线**（涉政/涉黄/血腥/宗教）→ 主动降级或绕开，不要硬写；改完后告诉用户改了什么
- **用户中途改设定**（如把境界从 9 阶改成 12 阶）→ 立即重生成 `硬设定.md` 和节奏表，提示用户前文可能需要返工

## Examples

### Example 1：开新书

**Input**: "我想开一本修真小说，主角是个废柴少年，在垃圾堆里捡到一本无名功法"

**Output**（一次性产出）：
- `<书名>/设定/硬设定.md` —— 9 阶境界 + 主角特殊点（功法来历）
- `<书名>/设定/爽点节奏表.md`
- `<书名>/设定/势力分布.md` —— 3 个对立势力
- `<书名>/大纲/分卷大纲.md` —— 5 卷 × 100 章
- `<书名>/正文/卷一/第001章_<章名>.md` + 第 002、003 章

### Example 2：单章连载

**Input**: "接着写第 047 章，主角刚筑基成功，准备回宗门"

**Output**:
- 先回看 `设定/硬设定.md` 和节奏表，确认本章处于"小爽点"位置
- 输出 `章前细纲.md`（200 字以内）
- 输出 `正文/卷一/第047章_<章名>.md`（3000-5000 字 + 三重钩子）
