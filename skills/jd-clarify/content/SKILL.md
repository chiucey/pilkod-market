# JD澄清与岗位画像迭代SOP

## 适用场景

当用户提供岗位要求、JD、招聘目标或候选人标准时，执行以下任务：

1. 提炼岗位核心画像（必须项、加分项、风险项）
2. 合并检查信息缺口与候选人关键信息完整性，并提出澄清问题
3. 将筛选条件分配到三种筛选渠道：
   - 简历可验证筛选
   - AI文字聊天可验证筛选
   - 仅招聘专家电话可验证筛选
4. 输出可落地的筛选SOP与淘汰规则
5. 在招聘推进中持续接收新信息，校准并迭代岗位画像版本

## 输出原则

- 先给结论，再给依据
- 以岗位画像精度为第一优先级
- 以招聘交付结果为最终目标（能否吸引并拿下合适候选人）
- 条件可验证、可执行，避免抽象标签（如"沟通好""抗压强"）
- 每个条件只放在最早且最可靠的筛选环节
- 对不确定信息明确标注"待确认"

## 工作流程

复制以下清单并逐步完成：

```markdown
任务进度
- [ ] Step 1: 解析岗位输入
- [ ] Step 2: 产出岗位画像
- [ ] Step 3: 关键信息检查（缺口+完整性）
- [ ] Step 4: 三层筛选分流
- [ ] Step 5: 生成筛选SOP
- [ ] Step 6: 招聘过程校准与版本迭代
```

### Step 1: 解析岗位输入

从用户输入中提取：

- 岗位基础：岗位名称、职级、汇报线、团队规模、工作地点、出差/班次、薪酬区间
- 岗位待遇：固定薪资、绩效奖金、提成机制、补贴福利、试用期规则
- 工作制度：工作时间、单双休/排班、加班强度、远程/现场要求
- 业务目标：入职后3-6个月要达成的关键结果
- 经验要求：行业、职能年限、场景经验、项目体量
- 能力要求：硬技能、工具栈、方法论、语言能力
- 约束条件：到岗时间、稳定性、轮班、地理限制、业务特殊要求

如信息不足，继续后续步骤但标记"待确认"。

### Step 2: 产出岗位画像

按以下结构输出：

1. **岗位使命**：一句话说明此岗位为何存在
2. **成功画像（Must Have）**：没有就无法胜任的条件
3. **增益画像（Good to Have）**：有则显著提高绩效的条件
4. **风险画像（Red Flags）**：常见不匹配信号

### Step 3: 关键信息检查（缺口+完整性）

优先检查以下维度：

- 业务优先级：当前最紧急的业务问题是什么
- 必须项边界：哪些"必须项"可放宽，放宽到什么程度
- 经验锚点：目标公司类型、项目规模、业绩阈值
- 薪酬与级别：预算上限、可谈空间、级别映射
- 到岗要求：最晚到岗时间、是否接受异地/混合办公
- 否决项：不可妥协的业务硬约束（如语言/时区/班次/出差）
- 待遇清晰度：固定薪资结构、浮动部分计算口径、发放规则
- 工作强度：常规工时、高峰期工时、出差频率、周末工作频率
- 候选人价值点：岗位卖点、成长路径、晋升周期、团队资源支持

对每个维度输出：

- 当前状态（完整/部分完整/缺失）
- 缺口说明
- 对招聘决策的影响
- 建议向用人经理提出的澄清问题（1-2句）
- 最小可沟通口径（用于招聘团队对候选人统一沟通）

### Step 4: 三层筛选分流规则（岗位画像+求职者画像）

先构建"求职者画像"，再设计分流矩阵。分流矩阵不做固定配比，必须按行业、岗位、蓝白灰领属性动态调整。

先判断以下求职者画像维度：

1. 人群属性：蓝领/灰领/白领
2. 行业与岗位簇：销售、运营、技术、客服、职能、制造、物流等
3. 求职行为：简历完备度、文字表达意愿、电话沟通意愿、响应速度
4. 渠道偏好：招聘平台聊天、电话、线下推荐、熟人转介绍

分流设计原则：

- 若候选人群"简历制作意愿和水平低"（蓝领/部分灰领常见），优先"AI聊天/电话"前置，简历仅作补充
- 若岗位重书面沉淀与项目证明（典型白领/技术岗），保留"简历前置"作为首轮门槛
- 若岗位对到岗速度敏感，采用"聊天快速资格确认 -> 电话深筛 -> 简历补证"
- 每条筛选条件仍需落入唯一首要环节，但流程顺序可以按人群调整

推荐流程样式（按画像选择）：

- 样式A（白领/简历成熟）：简历 -> AI聊天 -> 电话
- 样式B（灰领混合）：AI聊天 -> 电话 -> 简历补证
- 样式C（蓝领/快招）：电话 -> AI聊天补充 -> 简历可选

#### A. 简历筛选（可文档化验证）

适合放入：

- 客观且可在履历中直接验证的信息
- 有明确时间/规模/结果描述的经历

典型条件：

- 年限、行业、岗位相关经验
- 学历/证书（如岗位确需）
- 工具或技术栈使用年限
- 项目规模、团队规模、业务指标结果
- 语言等级、地域与时区匹配

不适合放入：

- 动机真实性
- 复杂问题拆解能力
- 协作风格和压力下行为
- 蓝灰领候选人的首轮硬门槛（除非岗位明确要求）

#### B. AI文字聊天筛选（可通过结构化问答验证）

适合放入：

- 需要候选人解释"如何做"的情景题
- 可通过短文本判断基本逻辑与表达的能力项

典型条件：

- 项目复盘能力（STAR结构）
- 基础业务理解与术语掌握
- 问题拆解路径是否清晰
- 求职动机一致性（岗位/行业/阶段）
- 薪资与到岗预期是否可对齐
- 蓝灰领候选人的基础到岗意愿、班次接受度、通勤可行性

不适合放入：

- 高风险诚信判断
- 深层稳定性与价值观匹配
- 复杂冲突处理真实性

#### C. 招聘专家电话筛选（需语音深挖验证）

适合放入：

- 需要追问细节、交叉验证、观察语气和一致性的条件
- 对风险控制影响大的关键判断

典型条件：

- 经历真实性与贡献边界（个人 vs 团队）
- 离职原因的真实性与稳定性风险
- 关键能力在复杂场景下的迁移能力
- 沟通影响力、抗压与协作风格
- 角色期望与管理风格匹配度
- 蓝灰领候选人的工作稳定性、现场条件接受度、即时上岗可行性

### Step 5: 生成筛选SOP

输出包含：

1. 筛选漏斗顺序（简历 -> AI聊天 -> 电话）
2. 各环节准入标准
3. 各环节淘汰标准
4. 升级/例外处理规则（如"核心能力极强但年限略不足"）
5. 记录规范（每个结论需有证据）

### Step 6: 招聘过程校准与版本迭代

在每一轮招聘反馈后，执行画像更新：

1. 收集新增输入：用人经理反馈、候选人拒绝原因、面试淘汰原因、市场供给变化
2. 标记变化类型：
   - 新增必须项
   - 必须项降级为加分项
   - 筛选阈值调整
   - 分流环节调整（简历/AI聊天/电话）
3. 输出版本变更记录（v1 -> v2）：
   - 变更前
   - 变更后
   - 变更原因
   - 影响范围（候选人池、筛选通过率、面试转化）
4. 更新"当前生效画像"与"当前生效SOP"
5. 每次版本更新后，必须全量输出"当前版本完整内容"，不得只输出差异项

每次迭代后都要给出：

- 当前版本号（如 v1.3）
- 本轮关键调整（1-3条）
- 下一轮需继续验证的假设（1-3条）
- 当前版本全量内容（完整画像 + 完整关键信息检查 + 完整SOP + 完整分流矩阵）

全量输出要求：

1. 不允许只给"变更摘要"代替完整版本
2. 若本轮仅微调1个条件，也必须重发整版内容
3. 版本展示顺序固定为：版本信息 -> 完整岗位画像 -> 完整关键信息检查（缺口+完整性） -> 完整分流矩阵 -> 完整执行SOP -> 风险与例外 -> 下轮待验证假设

## 岗位类型差异化关切清单

在输出中按岗位类型补充"候选人最关心信息"：

- 销售岗：提成公式、开单周期、客户资源来源、业绩考核周期、末位淘汰规则
- 运营岗：工作节奏、跨团队协同强度、指标口径、值班要求
- 技术岗：技术栈演进、代码质量标准、发布节奏、on-call频次
- 客服岗：排班规则、夜班占比、绩效指标、情绪压力支持机制
- 管理岗：团队规模、管理幅度、授权边界、组织稳定性

若岗位未明确类型，先判断最接近的岗位簇，再引用对应清单。

## 人群分层筛选指引（蓝/白/灰领）

将岗位画像与人群画像联合判断，选择筛选前置环节：

- 白领：优先看简历与项目证据，聊天用于动机与表达校验，电话用于深挖真实性
- 灰领：优先聊天或电话确认可上岗性，再结合简历/经历补证
- 蓝领：优先电话或聊天确认班次、通勤、到岗时间、稳定性，简历不作为强依赖前置条件

蓝灰领场景强制检查项（首轮）：

- 到岗时间与班次接受度
- 通勤半径与住宿条件
- 薪资结构理解（底薪/计件/提成/加班费）
- 过往稳定性与离岗触发因素

### 详版补充项（按需展开）

- 每个Must Have的验证题库（AI聊天版、电话追问版）

- 打分卡（建议5分制）与淘汰阈值

## 质量自检

输出前逐项确认：

- [ ] 每条结论都有输入依据或已标注"待确认"
- [ ] 每条筛选条件只分配到一个首要环节
- [ ] 已先定义求职者画像（行业/岗位/蓝白灰领/求职行为）再设计分流
- [ ] 简历环节只保留可文档化验证项
- [ ] AI聊天环节问题可在3-5轮内完成判断
- [ ] 电话环节聚焦高风险与高不确定项
- [ ] 蓝灰领场景未错误使用"简历前置硬门槛"
- [ ] 已给出可执行的通过/淘汰阈值
- [ ] 已覆盖岗位待遇与候选人高关注信息（工时、薪资、激励），并合并到关键信息检查
- [ ] 已按岗位类型补充差异化关切点（如销售提成机制）
- [ ] 已输出当前版本号与本轮画像调整记录
- [ ] 本轮已全量输出当前版本完整内容（非增量）
