# Fallback 策略详解

## 核心理念

Fallback 机制旨在确保 AI 服务的高可用性，当主模型不可用或受到速率限制时，自动切换到备用模型，保证用户请求不中断。

## Fallback 工作流程

```
用户请求
    │
    ▼
┌─────────────────┐
│  尝试主模型     │
└────────┬────────┘
         │
    ┌────▼────┐
    │ 成功?   │
    └────┬────┘
     Yes │ No
         ▼
┌─────────────────┐
│  记录失败日志   │
└────────┬────────┘
         │
    ┌────▼────┐
    │ 尝试    │
    │ Fallback 1 │
    └────┬────┘
         │
    ┌────▼────┐
    │ 成功?   │
    └────┬────┘
     Yes │ No
         ▼
┌─────────────────┐
│  尝试 Fallback 2 │
└────────┬────────┘
         │
         ▼
      (依次类推)
         │
    ┌────▼────┐
    │ 所有    │
    │ Fallback │
    │ 失败    │
    └────┬────┘
         │
         ▼
┌─────────────────┐
│ 返回错误给用户  │
│ 建议稍后重试    │
└─────────────────┘
```

## Fallback 数量配置

### 最小配置（1-2 个）

适用场景：
- 资源受限环境
- 只想使用特定模型

```yaml
fallback:
  - "openrouter/auto"  # 智能路由
```

### 标准配置（3-5 个）

适用场景：
- 大多数生产环境
- 平衡可靠性和成本

```yaml
fallback:
  - "openrouter/auto"
  - "anthropic/claude-3-haiku"
  - "google/gemini-pro"
  - "openai/gpt-3.5-turbo"
  - "deepseek/deepseek-chat"
```

### 高可用配置（6+ 个）

适用场景：
- 关键业务系统
- 需要应对多种故障场景

```yaml
fallback:
  - "openrouter/auto"
  - "anthropic/claude-3-haiku"
  - "google/gemini-pro"
  - "google/gemini-flash"
  - "openai/gpt-3.5-turbo"
  - "meta-llama/llama-3-8b-instruct"
  - "deepseek/deepseek-chat"
  - "mistralai/mistral-7b-instruct"
```

## Fallback 触发条件

| 条件 | 说明 | 默认行为 |
|------|------|----------|
| HTTP 429 | 速率限制 | 立即切换到下一个模型 |
| HTTP 503 | 服务不可用 | 等待 1 秒后重试一次，仍失败则切换 |
| 超时 | 请求超时（30秒） | 切换到下一个模型 |
| 连续失败 | 同一模型连续失败 3 次 | 临时加入黑名单，切换到下一个 |

## Fallback 更新策略

### 自动更新

当以下情况发生时，技能会自动重新排序并更新 fallback 列表：
- 用户请求"刷新模型列表"
- 检测到主模型连续失败超过阈值
- 定期健康检查发现模型状态变化

### 手动更新

用户可以随时请求：
- "更新 fallback" - 重新排序并生成新列表
- "添加 <模型> 到 fallback" - 在列表末尾添加
- "移除 fallback 中的 <模型>" - 从列表中删除
- "设置 fallback 数量为 5" - 调整列表长度

## Fallback 与模型成本

| 模型 | 免费额度 | 超出后成本 |
|------|----------|------------|
| openrouter/auto | 取决于策略 | 变通路由 |
| anthropic/claude-3-haiku | 有限免费 | 按 token 计费 |
| google/gemini-* | 丰富免费 | 超出后按量计费 |
| openai/gpt-3.5-turbo | 部分免费 | 按 token 计费 |
| meta-llama/* | 完全免费 | 免费使用 |

**优化建议**：优先将免费模型放入 fallback 列表，将付费模型作为最后备选。

## 监控与告警

建议监控以下指标：

1. **Fallback 触发频率**：过高说明主模型不稳定
2. **模型可用性**：某些模型可能间歇性不可用
3. **响应时间**：不同模型响应速度差异大
4. **错误类型分布**：区分速率限制和服务错误

## 最佳实践

1. **始终保留 openrouter/auto 作为第一个 fallback**
   - 它会自动选择最佳可用模型

2. **将同类型模型放在一起**
   - 便于诊断和优化

3. **定期测试 fallback 列表**
   - 确保所有模型都可用

4. **记录 fallback 触发日志**
   - 便于后续分析和优化
