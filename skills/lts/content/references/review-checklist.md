# 定期回顾检查清单

## 回顾频率

| 问题类型 | 建议频率 |
|---------|---------|
| 活跃开发中，每周有推进 | 每次会话自动检查 |
| 阶段性卡住，等待外部输入 | 等外部信号来了再更新 |
| 长期搁置 | 每月检查一次，评估是否继续或归档 |

---

## 回顾三步

### 1. 进展盘点
- 上次记录的行动项完成了吗？
- 没完成的原因是什么？（阻塞 / 优先级变化 / 预估不足）

### 2. 状态更新
- 这个问题现在的状态是什么？（进行中 / 阻塞 / 暂停 / 已有解决方案）
- 有没有出现新的信息或变量？
- 已知约束有没有变化？

### 3. 下一步决策
- 下一步最该做什么？（一个行动项）
- 需不需要调整拆解方案？
- 预计什么时候能有实质性突破？

---

## 状态标签

在问题文件顶部用标签注明当前状态：

```
状态: 🔴 进行中 / 🟡 阻塞 / ⏸ 暂停 / ✅ 已解决 / 📦 已归档
```

---

## 完成宣告机制

问题在以下情况下判定为完成：

- **用户明确宣告**：「搞定了」「已解决」「完成了」
- **目标达成**：核心交付物已交付并被用户确认
- **用户决定停止**：主动表示不再继续

处理方式：
1. 将问题文件移至 `archive/` 目录
2. 更新 `README.md` 索引（移至「已归档」）
3. 在原文件中加一行「## 归档原因 + 日期」

**每次回顾时多问一句**：
- 「这个问题还在推进吗？还是可以归档了？」

---

## 归档流程（统一执行）

1. 将问题文件移至 `archive/` 目录
2. 更新 `README.md` 索引（移至「已归档」，注明归档日期和原因）
3. 在原文件中不加任何内容（保持原文件不变）
