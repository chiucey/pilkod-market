# 适用边界与触发条件

## 这个 Skill 适合什么？

满足以下任意条件时，应触发此 skill：

- 问题需要**跨多次会话**才能解决
- 问题有**多个未知依赖**，无法一次性拆完
- 用户表达了**持续跟进的意愿**（「先记下来」「之后再说」「长期关注」）
- 问题有**多个子方向**，需要按优先级逐个击破
- 需要追踪**外部依赖**（等待队友、等待工具、等待信息）

## 这个 Skill 不适合什么？

以下情况不触发或慎用：

- **单一可回答的问题**：用户问一个已有明确答案的问题 → 直接回答，不需要追踪
- **即时任务**：用户要求在当前会话完成一件事 → 立即执行，不需要创建记录
- **闲聊或无特定目标**：没有具体问题要解决 → 不触发
- **用户已明确表达「一次搞定」**：用户说「帮我把这个做完」而非「先记一下」→ 询问是否要创建追踪记录

## 触发判断流程

```
用户提出问题
    ↓
需要跨多次会话完成？
  是 → 触发 long-term-problem-solver
  不确定 → 先问用户：「这个想一次解决，还是需要持续追踪？」
  否 → 直接回答或执行
```

## 追问标准模板

触发后，第一句话用以下方式确认（根据情况选一句）：

- 「先确认一下——你说的「做 XX」，是想一次做完，还是先记下来慢慢推进？」
- 「这个问题涉及 YY，在你开始之前，想确认它的最终目标是什么？」
- 「听起来需要分几步，先记下来。你希望第一步先做什么？」
