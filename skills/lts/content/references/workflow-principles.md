# 开发原则（用户制定）

## 原则一：Plan 模式

每次开始一个任务，先完整回答：

```
1. 计划：要做的事，列出步骤
2. 拆解模块：每个模块是什么，负责什么
3. 文件路径：具体写到哪个文件
4. 验证步骤：怎么确认这个模块工作正常
```

→ 不跳步，不脑补，先把计划写清楚再动手。

---

## 原则二：最小闭环

每次只做一个最小可运行闭环，能跑通了再加功能。

- ❌ 「一起写完所有模块再测试」
- ✅ 「先跑通一个最小路径，剩下的逐步接入」

**判断标准**：能否在 48 小时内完成一个完整闭环并验证？

---

## 原则三：问题排查步骤

遇到 bug 或问题时，按此顺序排查：

1. **现象**：实际发生了什么（控制台错误？白屏？行为不对？）
2. **日志**：查看相关日志，找到第一行报错
3. **定位**：用「控制变量」思路逐个排除，找出根因
4. **修复**：只改最小必要代码，不碰其他正常部分
5. **验证**：确认问题消失，再跑一遍完整流程

→ 不靠猜测，靠证据。不改无法证明坏了的代码。
