# 预算看板生成器 (Budget Dashboard Generator)

## Overview

本技能将预算数据（来自Excel或手动输入）转化为专业的交互式Web看板。生成的看板包含部门汇总视图和4位客户成功经理的独立视图，支持预算/收款明细管理、数据持久化。

---

## 核心能力

1. **数据分析**：解析Excel文件，提取预算明细、实际收款、商机列表
2. **看板生成**：创建React+TypeScript+Tailwind的交互式Web看板
3. **视图设计**：部门汇总 + 4个经理独立视图，支持指标切换
4. **明细管理**：预算明细和收款明细的添加/编辑/删除（CRUD）
5. **数据持久化**：localStorage存储，支持数据导出

## 数据结构

### 预算数据模型

```
部门汇总
├── 整体指标 (年度18M)
├── 订阅指标 (年度13M)
└── 服务指标 (年度5M)
    │
    ├── 每月数据
    │   ├── 月指标
    │   ├── 月预算
    │   ├── 月实际收款
    │   ├── 完成率
    │   └── 差距
    │
    ├── 年度累计
    │   ├── 累计指标
    │   ├── 累计收款
    │   └── 完成率
    │
    └── 季度推测
        ├── Q1-Q4指标占比
        └── 季度完成率推测

客户成功经理 (4位)
├── 田旭财
├── 杨洋
├── 于德鹏
└── 文德超
    └──每位经理数据 = 部门汇总结构
```

### 关键指标计算

| 指标 | 计算公式 | 关注点 |
|------|---------|--------|
| 月预算完成率 | 月实际收款 / 月指标 | 反映当月完成情况 |
| 月差距 | 月实际收款 - 月指标 | 正值=超额，负值=缺口 |
| 年累计完成率 | 年累计收款 / 年指标 | 反映年度进度 |
| 年预测完成率 | 年预测收款 / 年指标 | 预估年度达成 |
| 季度占比 | 季度指标 / 年度指标 | 各季度分配比例 |

## 执行流程

### Phase 1: 数据分析

1. 接收Excel文件或需求描述
2. 解析sheet结构：
   - '01-预算明细' / '01-预算明细-{经理名}'
   - '02-实际收款明细'
   - '03-商机列表'
3. 提取关键字段：
   - 客户名称、产品、金额、类型、服务类型、月份
4. 处理特殊sheet名称（如于德鹏的'01-预算明细-于德鹏'）

### Phase 2: 数据建模

1. 创建 data/budgetData.ts
   - ManagerData 接口
   - 月度/年度数据结构
   - formatCurrency 等工具函数

2. 创建 data/detailData.ts
   - 预算汇总（订阅/服务分项）
   - 实际收款汇总
   - 服务类型分类

3. 创建 data/customerDetails.ts（可选）
   - BudgetItem / CollectionItem 接口
   - localStorage 操作函数

### Phase 3: 组件开发

1. **MetricCard**: 通用指标卡片
2. **SimpleBarChart**: 简单柱状图
3. **SimpleProgress**: 进度条
4. **SummaryDashboard**: 部门汇总视图
5. **ManagerDashboard**: 经理视图（含CRUD）
6. **TeamComparison**: 团队对比
7. **DetailDashboard**: 预算明细视图

### Phase 4: 集成部署

1. App.tsx 整合所有组件
2. Sidebar 导航
3. 构建：`npm run build`
4. 部署：`deploy` tool

## 常见问题处理

### Excel解析问题

| 问题 | 解决方案 |
|------|---------|
| sheet名称不同 | 检测并使用正确的sheet名称 |
| 列名差异 | 如'预计收款份'改为'预计收款月份' |
| 经理名不匹配 | 使用经理名作为sheet后缀 |

### 图表显示问题

| 问题 | 解决方案 |
|------|---------|
| Recharts TS错误 | 使用自定义SimpleBarChart组件 |
| 柱状图高度为0 | 检查maxValue计算 |

### localStorage问题

| 问题 | 解决方案 |
|------|---------|
| 数据丢失 | 验证saveToLocalStorage调用 |
| 跨页面不共享 | 检查STORAGE_KEY一致性 |

## 数据安全说明

### 当前架构

```
用户浏览器 (localStorage)
    ↑ 保存数据
网页代码
    ↓ 获取数据
云端服务器 (仅存储静态代码)
```

### 安全特性
- 数据存储在用户浏览器本地
- 服务器不存储任何业务数据
- 不同用户数据完全隔离

### 向领导汇报要点
> "纯前端数据看板，所有数据存储在员工个人浏览器。服务器只存储网页代码，无业务数据。数据完全由员工自行管理。"
