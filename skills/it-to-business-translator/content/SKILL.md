# IT-to-Business Translator

## 核心能力

将IT专业人士的技术表述转化为管理层和非技术决策者能够理解的语言，同时保持信息的准确性和商业价值。

## 翻译策略

### 目标受众映射

| 受众 | 关注重点 | 翻译风格 |
|------|---------|---------|
| **CEO** | 战略价值、竞争优势、风险与机遇 | 用商业影响说话，关联公司使命和目标 |
| **CFO** | 成本效益、投资回报、预算影响 | 用数字和ROI表达，强调财务影响 |
| **HR总监** | 团队能力、人才影响、组织文化 | 关注人员技能、工作方式、团队协作 |
| **董事会** | 合规风险、长期价值、公司治理 | 聚焦风险控制和战略方向 |
| **业务部门负责人** | 业务协同、效率提升、客户价值 | 强调对业务的直接支持 |

### 技术概念翻译对照

| IT术语 | CEO版本 | CFO版本 | HR总监版本 |
|--------|--------|--------|-----------|
| 系统迁移 | 核心系统升级换代，保持技术领先 | 预计节省XX%运营成本，提升投资回报率 | 团队获得新技术能力，吸引顶尖人才 |
| API集成 | 建立数据高速公路，提升业务敏捷性 | 消除重复投入，年化节省XX万元 | 打破数据孤岛，改善协作流程 |
| 服务器宕机 | 服务中断，影响客户体验和收入 | 每小时损失约XX万元，需要投资高可用方案 | 影响员工工作效率，需要应急响应机制 |
| 网络安全加固 | 保护公司数字资产和客户信任 | 避免潜在巨额罚款和安全事故损失 | 提升团队安全意识，改善工作习惯 |
| 云计算部署 | 灵活的IT基础设施，支持快速扩展 | 降低初始投资XX%，转为按需付费模式 | 提供更灵活的工作方式选择 |
| 数据中台建设 | 统一数据资产，支撑数据驱动决策 | 消除数据重复建设，节省XX%开发资源 | 建立统一数据标准，减少沟通成本 |
| 敏捷转型 | 快速响应市场变化，加速产品迭代 | 缩短交付周期XX%，提高资源利用率 | 改善团队协作，提升员工参与度 |
| 人工智能应用 | 智能化升级，打造差异化竞争优势 | 自动化替代人工，预计年化节省XX人天 | 重塑工作模式，员工转向高价值工作 |

## 执行流程

### 1. 理解原始表述

- 识别核心IT概念和技术术语
- 理解技术背景和上下文
- 确定技术决策的商业意义

### 2. 确定目标受众

- 询问或推断主要读者/听众
- 了解他们的背景、关注点和决策偏好
- 选择最合适的翻译风格

### 3. 翻译与重构

**原则**：
- 从"做什么"转向"为什么重要"
- 用业务语言替代技术术语
- 强调影响、价值和风险
- 保持信息准确性，避免过度简化

**翻译技巧**：
- 替换法：用商业等效物替代技术术语
- 比喻法：用生活化的类比解释复杂概念
- 量化法：将技术指标转化为商业价值
- 关联法：将技术与公司战略目标挂钩

### 4. 输出格式

根据场景选择输出格式：

**即时翻译**：
```
【原始表述】
"我们需要在生产环境中部署Kubernetes集群来实现容器化编排"

【CFO视角】
此投资将把我们部署周期从平均2周缩短至2天，资源利用率提升40%。
按当前项目频率计算，每年可节省约120人天的运维工作量，
相当于每年减少约36万元的运维成本，同时大幅降低因部署失误导致的业务风险。
```

**汇报材料格式**：
```
技术方案：XX系统升级项目
商业价值摘要：[2-3句话的核心价值主张]
对各利益相关方的影响：
- CEO：...
- CFO：...
- 业务部门：...
风险与机遇：...
建议决策：...
```

## 示例场景

### 场景1：向CEO汇报系统迁移

**原始**：我们需要把核心数据库从Oracle迁移到PostgreSQL，这样可以节省80%的 licensing成本。

**翻译**：
建议将核心数据库从Oracle迁移到开源数据库PostgreSQL。此举将：
- **立即节省**：年度软件许可费用约400万元
- **战略价值**：降低对单一厂商依赖，技术自主可控
- **风险可控**：采用双轨并行策略，确保业务连续性
- **建议**：批准此项目，项目周期6个月，预计ROI超过300%

### 场景2：向HR总监解释DevOps转型

**原始**：我们要推行DevOps文化，打破开发和运维的壁垒，实现持续集成和持续部署。

**翻译**：
建议推行DevOps工作方式变革，主要变化包括：
- **工作模式**：开发与运维团队打破壁垒，协作更加紧密
- **效率提升**：代码从开发到上线从2周缩短至2天
- **团队成长**：工程师技能更全面，职业发展路径更清晰
- **人才吸引**：先进的工作方式有助于吸引和保留优秀技术人才
- **需要支持**：希望在绩效考核和岗位职责上做相应调整

### 场景3：向CFO说明网络安全投资

**原始**：我们需要部署零信任架构，这是目前最安全的网络安全模型。

**翻译**：
建议投资建设零信任安全体系：
- **投资额**：预计总投入约150万元
- **直接收益**：避免潜在数据泄露风险（行业平均损失约800万元/次）
- **合规要求**：满足等保三级和GDPR合规要求，避免违规处罚风险
- **间接收益**：提升客户信任，有助于获取更多企业客户订单
- **ROI结论**：1-2年内可通过避免风险和合规收益收回投资

## 注意事项

1. **避免过度简化**：保持技术准确性，不要误导管理层
2. **量化优先**：尽可能用具体数字支持表述
3. **关联战略**：将技术与公司战略和业务目标关联
4. **平衡风险与机遇**：既展示风险，也强调机遇
5. **考虑受众决策框架**：用他们熟悉的决策语言表达
