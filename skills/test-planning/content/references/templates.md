## 模板2：测试用例模板

### 表格格式

```markdown
| 用例编号 | 模块 | 子模块 | 功能点 | 用例标题 | 前置条件 | 测试步骤 | 预期结果 | 优先级 | 测试类型 | 关联需求 |
|---------|------|--------|--------|----------|----------|---------|---------|--------|---------|----------|
| TC-001 | 登录 | - | 用户登录 | 正常登录 | 用户已注册 | 1. 打开登录页<br>2. 输入正确账号<br>3. 输入正确密码<br>4. 点击登录 | 登录成功，跳转首页 | P0 | 功能测试 | REQ-001 |
```

### 详细格式

```markdown
## 用例编号: TC-001

**模块**: 用户登录
**用例标题**: 正常登录成功

### 基本信息
| 项目 | 内容 |
|------|------|
| 创建日期 | - |
| 创建人 | - |
| 优先级 | P0 |
| 测试类型 | 功能测试 |

### 用例详情

**前置条件**:
- 用户已完成注册
- 用户状态为正常
- 系统正常运行

**测试数据**:
- 用户名: test@example.com
- 密码: Test@123456

**测试步骤**:
1. 打开浏览器，访问登录页面
2. 在用户名输入框输入 test@example.com
3. 在密码输入框输入 Test@123456
4. 点击"登录"按钮

**预期结果**:
1. 页面跳转到首页
2. 右上角显示用户头像
3. 显示登录成功提示（可选）

**后置条件**:
- 用户登录状态已建立
- Session已创建

**测试环境**:
- 浏览器: Chrome最新版本
- 网络: 正常网络环境
```

## 模板4：测试策略文档

```markdown
# 测试策略

## 1. 测试整体策略

### 1.1 测试阶段划分
- **单元测试**: 开发负责，覆盖率>80%
- **集成测试**: 测试负责，接口级验证
- **系统测试**: 测试负责，功能全覆盖
- **验收测试**: 客户/产品负责，业务验收

### 1.2 测试方法选择
| 测试类型 | 方法 | 工具 | 覆盖率目标 |
|----------|------|------|-----------|
| 功能测试 | 黑盒 | 手工/自动化 | 100%核心 |
| 接口测试 | 黑盒 | Postman | 100%接口 |
| 性能测试 | 负载/压力 | JMeter | 关键场景 |
| 安全测试 | 渗透测试 | 手工 | 重点防护 |

## 2. 测试优先级策略

### 2.1 优先级定义
- **P0**: 核心功能，影响主流程
- **P1**: 重要功能，影响主要业务
- **P2**: 一般功能，影响辅助流程
- **P3**: 边缘功能，不影响使用

### 2.2 执行策略
1. P0用例优先执行，100%通过
2. P1用例全面执行，通过率>95%
3. P2用例按计划执行，通过率>80%
4. P3用例探索性执行

## 3. 回归测试策略

### 3.1 触发条件
- 需求变更
- 重大缺陷修复
- 版本发布前

### 3.2 回归范围
- 最近版本变更涉及的模块
- 与变更模块有数据交互的模块
- 核心业务流程

### 3.3 自动化策略
- 核心流程自动化覆盖
- 回归测试自动化>70%
- 每日构建自动执行
```
