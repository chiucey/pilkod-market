# Changelog

## v1.0

- 新建 `jd-clarify-new`，采用主技能 + 子技能结构。
- 将能力拆分为 `profile-sop`、`jd-rewrite`、`consultant-brief` 三个子模块。
- 新增 `common/` 统一约束、输入输出契约与质量自检。

## v1.1

- 新增子模块 `sub_skills/resume-fit/`，用于按岗位画像做简历匹配分析。
- 主路由新增模式D触发词与冲突处理规则。
- 新增“禁止评分”约束：仅输出“合适的地方/不合适的地方”。

## v1.2

- 调整 `resume-fit`：当判断为“整体合适”时，新增推荐语输出。
- 新增判断结论字段：`整体合适 / 暂不合适 / 信息不足`。
- 补充“整体合适并生成推荐语”示例。

## v1.3

- 新增模式E `sub_skills/screening-pack/`，用于生成平台筛简历要求与AI文字初面信息包。
- 模式E新增能力：基于岗位画像输出“筛选要求 + 求职者关心信息”。
- 将打招呼话术与AI初面内容从模式B迁移至模式E。
- 模式B边界收敛为“仅JD文案重构”。

## v1.4

- 调整模式编号顺序：A画像SOP、B顾问简版、CJD重构、D平台筛选与AI初面包、E简历匹配分析。
- 同步更新主路由、主说明和各子技能文件中的模式标识。
- 同步修正模式边界描述：打招呼话术与AI初面由模式D统一输出。

## v1.5

- 路由策略调整为“每次仅触发一个模式”。
- 移除多模式命中冲突处理描述，改为按主诉求单模式执行。
- 输出契约改为统一单模块结构，不再定义多模块分块输出。

## v1.6

- 调整模式C（JD重构）合规约束：JD正文禁止出现用工模式与需求方公司名称。
- 增加输入清洗要求：若原始输入包含上述信息，重构时统一移除或泛化表达。
- 同步更新模式C模板与示例说明，确保输出口径一致。

## v1.7

- 调整模式A检查模块：由“关键信息检查”改为“ITO招聘需求检查表”。
- 要求检查结果必须同时输出“已有信息”和“缺失信息”。
- 同步更新模式A的执行目标、流程、模板与示例。

## v1.8

- 模式A的ITO检查表格式升级为 v1.1 表头：模块、检查项、当前信息、状态、最小可沟通口径（建议）、优先级。
- 新增状态标准：已提供/缺失/待规范/部分。
- 新增优先级标准：P0/P1，并更新示例为表格化输出。

## v1.9

- 调整模式A输出格式：正文直接输出，不使用代码块。
- 保留并强化Markdown表格输出要求（ITO检查表、分流矩阵）。

## v1.10

- 模式A新增工作地点校验规则：Base地址未到详细地址时必须提醒补齐。
- 明确口径：至少包含城市+区县/园区/办公点，否则不得按“已提供”处理。

## v1.11

- 模式D联动模式A：默认读取 ITO招聘需求检查表（v1.1）作为输入依据。
- 新增ITO映射规则：检查表中 `缺失/部分/待规范` 项自动进入模式D待确认项。
- 增加兜底策略：若未提供A结果，模式D先生成简版ITO检查表再继续输出。

## v1.12

- 模式D新增“平台筛选信息（按模板）”三段式输出：岗位职责盘点、门槛条件、补充关键信息。
- 门槛条件新增限定词规范：必须/只要/仅限，便于AI识别。
- 同步保留合规约束：不输出歧视性限制，相关条件改写为能力要求。

## v1.13

- 模式D新增“门槛条件因子规则”：按职位因子定义支持类型（硬性/优先/不限）。
- 新增门槛条件因子清单与写法规范，并补充合规约束。
- 模板与案例新增“门槛条件因子表（用于AI识别）”。

## v1.14

- 模式D调整因子清单输出格式：由表格改为纯文本列表。
- 同步更新模板与示例，确保因子清单不使用表格。

## v1.15

- 模式D进一步简化因子清单：移除“支持类型”展示，仅保留“因子名称 + 规则写法”。
- 同步更新规则、模板与示例文本。

## v1.16

- 模式D删除“残疾人”因子。
- 同步更新规则、模板与示例，确保因子清单保持一致。

## v1.17

- 每个因子新增关键词输出格式：`关键词=[...]；规则=...`。
- 同步更新模板与示例，保持纯文本输出。

## v1.18

- 模式D合并第二部分输出：移除独立“门槛条件”段，仅保留“门槛条件因子关键词清单”。
- 同步更新规则、模板与示例，避免重复表达。
