# Examples (Mode A)

## 示例：技术岗位

- Must Have：Java后端3年以上、可独立负责核心模块、有高并发接口优化经验
- Good to Have：电商交易链路经验
- Red Flags：仅做维护无核心交付、无法说明个人贡献边界

## 示例：写实美术 Icon 岗

岗位画像：

- Must Have：
  - 可独立完成 icon 资材设计与细化。
  - 写实向美术基础扎实（透视、结构、体块、材质表达）。
  - 能把抽象需求转成可落地图标方案。
- Good to Have：
  - 有成熟游戏或写实道具类图标项目案例。
- Red Flags：
  - 作品长期偏 Q 版、扁平风且无法切换写实方向。

ITO招聘需求检查表中的缺口示例：

- 模块：候选人画像；检查项：风格边界；状态：部分。
- 当前信息：希望写实风格；缺少可验证锚点。
- 最小可沟通口径：首轮按“写实可验证作品”执行，不接受纯扁平风作品。

## 示例：蓝领快招（分流前置调整）

岗位画像：

- Must Have：可接受班次、通勤可达、一周内到岗。
- Good to Have：有同岗位稳定任职记录。
- Red Flags：频繁短期离岗且无法解释原因。

分流顺序：

- 推荐样式：电话 -> AI聊天补充 -> 简历可选。
- 电话首问：班次接受度、通勤半径、到岗时间。
- AI补充：薪资结构理解、稳定性触发因素。

用工关系口径：

- 对外说明：岗位由招聘服务团队招募，录用后与实际签约主体建立劳动关系。
