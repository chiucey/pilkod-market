# Examples (Mode E)

## 示例：Java后端岗位

岗位画像摘录：

- Must Have：Java 3年以上、独立模块交付、MySQL/Redis实战
- Good to Have：电商交易链路经验
- Red Flags：无法说明个人贡献边界

简历摘录：

- Java开发4年，负责订单与库存模块
- 参与接口性能优化，P95 从 320ms 降到 180ms
- 使用 MySQL、Redis；未明确说明电商交易链路深度

输出示例：

- 合适的地方：
  - 年限匹配：岗位要求 Java 3年以上，简历显示 4 年相关经验。
  - 交付匹配：简历有订单与库存模块负责经历，可对应独立模块交付。
  - 技术栈匹配：简历明确有 MySQL 与 Redis 实战。
- 不合适的地方：
  - Red Flags 风险：简历未清晰区分个人贡献与团队贡献，存在边界不清风险。
  - 加分项不足：电商交易链路的完整闭环经验未明确体现。
- 待确认项：
  - 是否主导过高峰流量场景的稳定性方案。
  - 交易链路中是否负责过核心环节（如下单、支付、履约）。

## 示例：整体合适并生成推荐语

岗位画像摘录：

- Must Have：Java 3年以上、独立模块交付、MySQL/Redis实战
- Good to Have：有交易链路经验、有稳定性优化案例
- Red Flags：近两年频繁短期离职且无法解释

简历摘录：

- Java开发5年，主导订单结算模块，负责需求评审到上线全流程
- 有 Redis/MySQL 调优经验，核心接口 P95 从 280ms 降到 140ms
- 最近两段任职分别为2年和2.5年，离职原因一致且可解释

输出示例：

- 合适的地方：
  - Must Have覆盖完整：年限、独立交付、核心技术栈均有直接证据。
  - 业务相关性好：有订单结算场景经验，可快速迁移到交易链路岗位。
  - 结果导向明确：性能优化有量化指标，能支撑能力判断。
- 不合适的地方：
  - 业务规模信息不完整：未体现峰值QPS与日单量，短期无法判断承压上限。
- 判断结论：
  - 整体合适。
- 待确认项：
  - 历史项目中的峰值流量规模与故障处置职责边界。
- 推荐语（仅整体合适时输出）：
  - 候选人与岗位核心要求匹配度高，Java年限、独立交付和数据库缓存实战均有明确证据。  
  - 在交易相关模块有可量化优化结果，具备较强落地能力。  
  - 当前风险主要是业务规模信息需进一步核验，建议进入下一轮技术面或电话深聊。
