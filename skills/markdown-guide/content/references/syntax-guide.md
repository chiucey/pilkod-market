## 标题

### 语法说明

Markdown 支持 6 级标题，使用 `#` 符号标记：

```markdown
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题
```

### 规范要求

1. **层级连贯**：不要跳级使用标题（如 H1 直接到 H3）
2. **数量限制**：一个文档通常只有一个 H1 标题
3. **空格要求**：`#` 与标题文本之间必须有空格
4. **闭合可选**：ATX 风格不要求闭合，但 Setext 风格需使用 `===` 或 `---`

### 示例

**正确示例：**
```markdown
# 项目名称

## 功能特性

### 核心功能

#### 用户管理
```

**错误示例：**
```markdown
# 项目名称

### 功能特性  ← 错误：跳过了二级标题

#另一个标题  ← 错误：缺少空格
```

## 段落与换行

### 段落

段落由一个或多个连续的文本行组成，段落之间使用**空行**分隔。

```markdown
这是第一段。

这是第二段。
```

### 换行

- **方式一**：行末添加两个或多个空格，然后回车
- **方式二**：使用 HTML 标签 `<br>`

```markdown
第一行  
第二行（使用两个空格换行）

第一行<br>第二行（使用 HTML 标签）
```

### 规范要求

1. 段落之间使用**一个空行**分隔
2. 不要使用连续多个空行
3. 行末双空格换行在多数编辑器中不可见，建议使用 `<br>` 或保持段落独立

## 文本格式

### 强调

```markdown
**粗体文本**
__粗体文本__

*斜体文本*
_斜体文本_

***粗斜体文本***
___粗斜体文本___

~~删除线~~
```

### 规范要求

1. 推荐使用 `*` 和 `**`（一致性）
2. 符号必须成对使用
3. 符号与文本之间不能有空格

### 示例

**正确示例：**
```markdown
这是**重要**的内容，请*仔细*阅读。
```

**错误示例：**
```markdown
这是** 重要**的内容  ← 错误：符号内有空格
这是*重要的内容      ← 错误：符号未闭合
```

## 列表

### 无序列表

使用 `-`、`*` 或 `+` 标记：

```markdown
- 项目 1
- 项目 2
  - 子项目 2.1
  - 子项目 2.2
- 项目 3
```

### 有序列表

使用数字加点标记：

```markdown
1. 第一项
2. 第二项
   1. 子项 2.1
   2. 子项 2.2
3. 第三项
```

### 列表嵌套

嵌套列表需要缩进 2-4 个空格或 1 个 Tab：

```markdown
1. 主项目
   - 嵌套无序项目
   - 另一个嵌套项
2. 另一个主项目
```

### 规范要求

1. 同级列表使用相同的标记符号（统一使用 `-` 或 `*`）
2. 列表项之间不需要空行（除非段落式列表项）
3. 嵌套列表必须正确缩进
4. 列表标记后必须有一个空格

### 示例

**正确示例：**
```markdown
- 用户管理
  - 注册
  - 登录
  - 权限设置
- 数据管理
  - 导入
  - 导出
```

**错误示例：**
```markdown
-项目 1  ← 错误：缺少空格
- 项目 2
 * 项目 3  ← 错误：混用标记符号
```

## 链接

### 基本语法

```markdown
[链接文本](URL)
[链接文本](URL "标题")
```

### 引用式链接

```markdown
[链接文本][引用标识]

[引用标识]: URL "标题"
```

### 示例

**行内链接：**
```markdown
访问 [GitHub](https://github.com) 获取更多信息。
```

**引用式链接：**
```markdown
请参考 [官方文档][docs] 和 [API 参考][api]。

[docs]: https://docs.example.com "官方文档"
[api]: https://api.example.com "API 参考"
```

### 规范要求

1. URL 中包含空格或特殊字符时，使用 `< >` 包裹
2. 链接文本要简洁明确
3. 引用式链接定义统一放在文档末尾

## 图片

### 基本语法

```markdown
![替代文本](图片URL)
![替代文本](图片URL "标题")
```

### 示例

```markdown
![项目架构图](./images/architecture.png "系统架构")

![Logo](https://example.com/logo.png)
```

### 规范要求

1. **替代文本必须提供**：用于图片无法显示时的说明
2. 图片路径使用相对路径或 CDN 链接
3. 大图片建议使用 `<img>` 标签控制尺寸：

```markdown
<img src="./image.png" alt="描述" width="600">
```

## 引用

### 基本语法

```markdown
> 引用内容
> 
> 多行引用
```

### 嵌套引用

```markdown
> 第一层引用
> 
> > 第二层引用
```

### 引用中使用其他元素

```markdown
> ### 引用中的标题
> 
> - 引用中的列表项 1
> - 引用中的列表项 2
```

### 示例

```markdown
> **注意**：这是一个重要的提示信息。
> 
> 请务必仔细阅读相关文档。
```

## 分隔线

### 语法

使用三个或更多的 `-`、`*` 或 `_`：

```markdown
---

***

___
```

### 规范要求

1. 符号前后需要空行
2. 推荐使用 `---`（一致性）
3. 避免与标题语法混淆（Setext 风格标题下一行使用 `===` 或 `---`）

## 表格

### 基本语法

```markdown
| 列 1 | 列 2 | 列 3 |
|------|------|------|
| 数据 1 | 数据 2 | 数据 3 |
| 数据 4 | 数据 5 | 数据 6 |
```

### 对齐方式

```markdown
| 左对齐 | 居中 | 右对齐 |
|:-------|:----:|-------:|
| 内容   | 内容 | 内容   |
```

### 示例

```markdown
| 功能 | 状态 | 说明 |
|:-----|:----:|-----:|
| 用户注册 | 完成 | 支持邮箱验证 |
| 数据导入 | 进行中 | 预计下周完成 |
| 权限管理 | 计划中 | 待需求确认 |
```

### 规范要求

1. 表格前后需要空行
2. 分隔行的 `|` 与 `-` 数量不影响渲染
3. 单元格内容过长时可以换行（但部分渲染器不支持）

## 任务列表

### 语法

```markdown
- [ ] 未完成任务
- [x] 已完成任务
```

### 示例

```markdown
## 开发计划

- [x] 需求分析
- [x] 架构设计
- [ ] 编码实现
  - [x] 用户模块
  - [ ] 订单模块
- [ ] 测试部署
```

## 转义字符

### 使用场景

需要显示 Markdown 语法字符本身时，使用反斜杠 `\` 转义：

```markdown
\* 不是斜体 \*
\# 不是标题
\[ 不是链接
```

### 可转义字符

```
\ ` * _ { } [ ] ( ) # + - . ! |
```

### 示例

```markdown
显示星号：\*
显示反引号：\`
显示方括号：\[文本\]
```

## 最佳实践总结

1. **标题层级**：保持连贯，不跳级，H1 唯一
2. **空行使用**：段落、列表、表格前后使用空行分隔
3. **一致性**：统一使用相同的符号标记（如都用 `-` 表示无序列表）
4. **可读性**：源代码也要保持良好的可读性
5. **链接规范**：确保链接有效，提供有意义的链接文本
6. **图片优化**：提供替代文本，控制图片尺寸
7. **嵌套层级**：不超过 3-4 层，保持结构清晰
