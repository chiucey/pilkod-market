# 变更日志模板规范

## 文档定位

变更日志（Changelog）用于记录项目版本历史、功能变更和升级指南。

## 标准结构

```markdown

本项目的所有重要变更都将记录在此文档中。

格式基于 [Keep a Changelog](https://keepachangelog.com/)，
版本号遵循 [语义化版本](https://semver.org/)。

## [未发布]

- 待发布的新功能

### 变更
- 待发布的变更

### 修复
- 待发布的修复
```

## 变更类型说明

| 类型 | 说明 |
|------|------|
| 新增 (Added) | 新功能 |
| 变更 (Changed) | 现有功能的变更 |
| 废弃 (Deprecated) | 即将移除的功能 |
| 移除 (Removed) | 已移除的功能 |
| 修复 (Fixed) | Bug 修复 |
| 安全 (Security) | 安全相关修复 |

## 版本号规范

遵循语义化版本（SemVer）：

- **MAJOR（主版本）**：不兼容的 API 变更
- **MINOR（次版本）**：向后兼容的功能新增
- **PATCH（补丁版本）**：向后兼容的问题修复

示例：
- `1.0.0` → `1.0.1`：Bug 修复
- `1.0.0` → `1.1.0`：新增功能
- `1.0.0` → `2.0.0`：重大变更

## 质量检查要点

1. **版本日期**：每个版本都有发布日期
2. **变更分类**：使用标准分类（新增/变更/修复等）
3. **Issue 引用**：关联相关 Issue 编号
4. **迁移指南**：重大变更提供升级指南
5. **链接完整**：底部提供版本对比链接

## 最佳实践

### 变更描述

清晰描述变更内容：

❌ 错误：
```markdown
- 修复了一些问题
- 优化了性能
```

✅ 正确：
```markdown
- 修复文件上传时内存泄漏问题 (#145)
- 优化启动速度，提升 50% 性能
```

### 重大变更说明

详细说明重大变更：

```markdown
### 重大变更
- 配置文件格式从 YAML 变更为 TOML

**影响：** 需要手动迁移现有配置文件

**迁移方式：**
1. 运行迁移脚本：`npm run migrate-config`
2. 或手动转换配置文件格式
```

使用 `[未发布]` 章节追踪开发中的变更：

```markdown
## [未发布]

### 新增
- 正在开发的新功能 A
- 正在开发的新功能 B

### 变更
- 计划进行的变更 C
```
