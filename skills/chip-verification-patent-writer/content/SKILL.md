# 芯片验证专利写作专家技能

## 技能概述

本技能文档定义了芯片验证专利写作专家的核心能力标准、专业方法论和实施指南。专家能够基于技术文档或技术方案，将相关的创新点转化为合规、美观、专业性极强的专利申请文档。

---

## 第一部分：专利文档结构规范

### 1.1 标准专利文档框架

完整的芯片验证领域发明专利应包含以下部分：

| 文档组成 | 说明 | 重要性 |
|---------|------|--------|
| 摘要 | 发明技术方案的简要概括 | 必填 |
| 权利要求书 | 专利保护范围的精确界定 | 核心 |
| 技术领域 | 明确技术应用范围 | 必填 |
| 背景技术 | 现有技术问题分析 | 必填 |
| 发明内容 | 技术方案详细描述 | 核心 |
| 附图说明 | 附图内容描述 | 重要 |
| 具体实施方式 | 实施例详细说明 | 核心 |

### 1.2 各部分写作规范

#### 1.2.1 摘要写作规范

```
摘要结构（不超过300字）：
1. 技术问题：解决什么技术问题（1-2句）
2. 技术方案核心：采用什么技术手段（2-3句）
3. 技术效果：达到什么技术效果（1-2句）

摘要附图：通常选取最能说明技术方案的附图
```

**摘要示例（基于CN121303010B）：**

> 本发明提供一种芯片设计验证方法、装置、电子设备及存储介质。该方法包括：获取芯片的设计文件及该设计文件对应的设计阶段；从多个协同验证方式中选择与所述设计阶段匹配的目标协同验证方式；基于所述目标协同验证方式对所述设计文件进行验证。本发明通过逻辑仿真验证和形式验证的协同工作，结合各自的优点进行互补，能够根据芯片设计的不同阶段提供不同的协同验证方式，显著提高验证效率和验证可靠性。

#### 1.2.2 权利要求书写作规范

```
权利要求书结构：
├── 独立权利要求1（方法/装置）
│   └── 解决技术问题
│   └── 技术方案核心步骤/模块
│   └── 技术效果
├── 从属权利要求2-N
│   └── 对独立权利要求的具体限定
└── 独立权利要求N+1（系统/设备）
    └── 与方法权利要求对应
```

**权利要求编号规则：**
- 独立权利要求使用阿拉伯数字1、2、3编号
- 从属权利要求使用带括号的数字(2)、(3)等编号
- 同一权利要求内的多项选择使用"或者"连接

#### 1.2.3 技术领域写作规范

```
技术领域定义格式：
本发明涉及[具体技术领域]，具体涉及[细分领域]。

适用领域示例：
- 集成电路设计领域
- 电子设计自动化技术领域
- 芯片验证技术领域
- 集成电路测试技术领域
```

#### 1.2.4 背景技术写作规范

```
背景技术结构：
1. 技术背景介绍（2-3段）
   - 技术发展现状
   - 应用场景说明

2. 现有技术分析（2-3段）
   - 现有技术方案描述
   - 现有技术的具体实现方式

3. 现有技术存在的问题（重点，3-5点）
   - 问题1：[具体描述]
   - 问题2：[具体描述]
   - ...
```

#### 1.2.5 发明内容写作规范

```
发明内容结构：
1. 发明目的/要解决的技术问题
2. 技术方案核心（独立权利要求内容）
3. 技术方案详细描述
4. 技术效果/有益效果
```

**协同验证方法专利模板：**

```markdown
## 技术方案模板

### 核心方法步骤
S1. 建立动态仿真验证环境：根据设计规格书生成多个测试场景
S2. 发送测试激励：通过序列器发送至驱动器转换为信号
S3. 实时采集信号：通过监视器采集输入输出信号转换为事务
S4. 生成动态仿真验证结果：参考模型与输出信号比对
S5. 生成形式验证分析结果：根据仿真结果缩小状态空间进行遍历
S6. 评估待验证设计：根据形式验证结果进行评估和修正

### 关键技术特征
- UVM验证环境自动化生成
- 事务级建模（TLM）
- 参考模型集成
- 状态空间智能缩小
- 闭环优化机制
```

### 3.3 权利要求书撰写标准

#### 3.3.1 独立权利要求撰写

```
独立权利要求结构：
1. 前序部分：说明要求保护的技术方案所属领域
2. 特征部分：说明区别于现有技术的必要技术特征

撰写要点：
- 概括适当：既要有较宽保护范围，又要得到说明书支持
- 形式简洁：使用功能性描述，避免过多具体实现细节
- 逻辑清晰：步骤/模块之间关系明确
```

**示例结构：**

> 1. 一种芯片测试验证方法，其特征在于，包括：
> - 接收参数字符串，所述参数字符串是对待验证芯片的所有目标参数的取值规则进行编码得到的；
> - 对所述参数字符串进行解析，得到所有所述目标参数的目标参数值以构建参数集合；
> - 基于所述参数集合配置至少一个测试实例；
> - 运行所述测试实例，获取所有所述测试实例的测试验证结果。

#### 3.3.2 从属权利要求撰写

```
从属权利要求撰写要点：
1. 引用关系清晰："根据权利要求X所述的方法"
2. 限定适度：增加的技术特征应与引用的特征相关
3. 层次分明：从概括到具体依次排列

常见限定类型：
- 格式限定：如"基于预设格式"
- 条件限定：如"若所述当前子字符串包括所述第二预设分隔符"
- 方式限定：如"通过自动化脚本"
```

#### 3.3.3 权利要求数量配置

```
权利要求数量建议：
| 专利类型 | 独立权利要求 | 从属权利要求 |
|---------|-------------|-------------|
| 简单专利 | 1-2个 | 3-5个 |
| 标准专利 | 2-3个 | 8-12个 |
| 复杂专利 | 3-5个 | 15-20个 |

- 设备/存储介质独立权利要求1个
```

#### 4.1.1 创新点来源分析

```

现有问题 → 技术方案 → 技术效果
    ↓           ↓           ↓
问题点1 → 方案特征1 → 效果1
问题点2 → 方案特征2 → 效果2
问题点3 → 方案特征3 → 效果3
```

#### 4.1.2 芯片验证领域创新点分类

| 创新类别 | 典型创新点 | 专利示例 |
|---------|-----------|---------|

| 流程创新 | 自动化/智能化流程 | 参数化测试配置 |
| 组合创新 | 现有技术的新组合 | 动态仿真+形式验证 |
| 优化创新 | 现有方案的效率提升 | 状态空间智能缩小 |

### 4.2 技术效果描述规范

```
技术效果描述要求：
1. 与技术方案对应：每个技术特征都有对应的技术效果
2. 定量与定性结合：优先使用定量描述
3. 对比说明：通过与现有技术对比说明优势

技术效果表述模板：
"通过[技术特征]，能够实现[技术效果]，相比现有技术[量化指标提升/改善]"
```

**技术效果量化指标参考：**

| 指标类型 | 描述方式 |
|---------|---------|
| 效率提升 | "验证效率提升X倍"、"缩短验证周期X%" |
| 覆盖率提升 | "覆盖率提升至X%"、"覆盖场景增加X个" |

## 第六部分：专利文档模板库

### 6.1 方法类专利模板

```markdown
# 专利文档模板 - 方法类

## 摘要
[技术问题简述]。[核心方案简述]。[技术效果简述]。

## 权利要求书
1. 一种[方法名称]，其特征在于，包括：
   [步骤1]
   [步骤2]
   ...
   [步骤N]

2. 根据权利要求1所述的方法，其特征在于，[具体限定]。

3. 根据权利要求1或2所述的方法，其特征在于，[具体限定]。
```

```markdown
# 协同验证方法专利示例框架

## 摘要
本发明提供一种芯片设计验证方法、装置、电子设备及存储介质。该方法包括：获取芯片的设计文件及该设计文件对应的设计阶段；从多个协同验证方式中选择与所述设计阶段匹配的目标协同验证方式；基于所述目标协同验证方式对所述设计文件进行验证。本发明通过逻辑仿真验证和形式验证的协同工作，结合各自的优点进行互补，能够根据芯片设计的不同阶段提供不同的协同验证方式，显著提高验证效率和验证可靠性。

## 权利要求书
1. 一种芯片设计验证方法，其特征在于，包括：
   - 获取芯片的设计文件及所述设计文件对应的设计阶段；
   - 从多个协同验证方式中选择与所述设计阶段匹配的目标协同验证方式；
   - 基于所述目标协同验证方式对所述设计文件进行验证。

2. 根据权利要求1所述的方法，其特征在于，所述设计阶段包括第一设计阶段、第二设计阶段和第三设计阶段；
   - 当所述设计阶段为所述第一设计阶段时，所述目标协同验证方式为第一协同验证方式，包括：获取所述设计文件中预设功能模块的第一断言；基于所述第一断言进行形式验证；
   - 当所述设计阶段为所述第二设计阶段时，所述目标协同验证方式为第二协同验证方式，包括：对所述设计文件进行逻辑仿真验证，获得漏洞信息；基于所述漏洞信息配置形式验证的第一待验证属性；对所述第一待验证属性进行形式验证；
   - 当所述设计阶段为所述第三设计阶段时，所述目标协同验证方式为第三协同验证方式，包括：进行仿真覆盖率检测获得未覆盖功能；为所述未覆盖功能配置第二待验证属性；进行形式验证后进行形式覆盖率检测；基于两种覆盖率结果确定所述未覆盖功能的可覆盖性。

3. 一种芯片设计验证装置，其特征在于，包括：
   - 输入模块，用于获取芯片的设计文件及所述设计文件对应的设计阶段；
   - 决策模块，用于从多个协同验证方式中选择与所述设计阶段匹配的目标协同验证方式；
   - 验证模块，用于基于所述目标协同验证方式对所述设计文件进行验证。

4. 一种电子设备，包括存储器、处理器及存储在所述存储器上并在所述处理器上运行的计算机程序，其特征在于，所述处理器执行所述计算机程序时实现如权利要求1或2所述的芯片设计验证方法。

5. 一种计算机可读存储介质，其上存储有计算机程序，其特征在于，该程序被处理器执行时实现如权利要求1或2所述的芯片设计验证方法。
```

## 第七部分：专家工作流程

### 7.1 专利撰写工作流程

```
工作流程阶段：

阶段1：需求分析
├── 获取技术文档或技术方案
├── 识别技术领域和应用场景
└── 确定专利类型和保护策略

阶段2：技术创新点提炼
├── 分析现有技术问题
├── 提炼技术创新点
└── 建立技术特征与效果对应关系

阶段3：专利文档撰写
├── 撰写摘要（初稿）
├── 撰写权利要求书
├── 撰写说明书（技术领域、背景、发明内容）
├── 撰写具体实施方式
└── 撰写附图说明

阶段4：文档优化
├── 自查是否符合规范
├── 检查术语一致性
├── 优化权利要求布局
└── 完善技术效果描述

阶段5：质量审核
├── 形式审查
├── 内容审查
├── 合规性检查
└── 提交审核
```

### 7.2 技术文档分析流程

```
技术文档分析步骤：

1. 提取技术领域信息
   - 确定所属技术领域
   - 明确应用场景

2. 分析技术问题
   - 识别现有技术存在的问题
   - 明确要解决的技术问题

3. 提取技术方案
   - 梳理技术方案的核心步骤/模块
   - 识别关键技术特征
   - 分析技术方案的实现细节

4. 提炼技术效果
   - 量化技术效果指标
   - 对比现有技术优势

5. 生成专利文档
   - 按模板生成文档
   - 优化完善
```
