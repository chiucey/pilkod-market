# 调研QA Skill

将需求材料转化为结构化的调研问题清单。

## 工作流程

### Step 1 — 接收与解析需求

接受用户上传的任意格式需求材料，支持：

| 格式 | 解析方式 |
|------|---------|
| `.docx` | 解压 XML，提取 `word/document.xml` 中的段落文本 |
| `.xlsx` / `.csv` | 使用 Node.js `xlsx` npm 包读取单元格内容 |
| `.pptx` | 解压 XML，提取 `ppt/slides/*.xml` 中的 `<a:t>` 文本 |
| `.pdf` | 使用 `extract_pdfs_key_info` 工具读取文本 |
| `.txt` / 纯文本 | 直接以换行符分段处理 |

注意：
- 优先解析用户提供的内容，而非自行搜索补充信息
- 如果用户同时提供了需求文档和解决方案文档，先读需求，再读方案
- 若文档中有「开放问题清单」或「To Do List」章节，优先提取这些未决问题

### Step 2 — 方案分析

若用户提供了解决方案文件（PPT/PDF），分析以下维度：

- **系统架构**：系统边界、功能模块、数据流向
- **对接系统**：涉及的外部系统（Xstore/PIM/Reva/BI等）及对接方式
- **用户角色**：后台管理端、导购端（toB）、用户端（toC）的功能差异
- **优先级说明**：文档中标注的 P0/P1/P2 及上线计划
- **未解决问题**：文档中已有的开放问题（Q1/Q2/...）需要重点追问

若只提供需求文档无方案文档，跳过此步，直接从需求文本中提取功能模块。

### Step 3 — 生成调研问题清单

从以下三大维度生成问题：

1. **历史数据**（数据资产管理与质量基线）
   - 数据完整度、准确度评估
   - 图片缺失比例、价格/库存历史记录
   - 现有知识库文档体量与结构化程度

2. **数据对接**（系统集成细节）
   - 各外部系统的 API 规格、同步频率、字段映射
   - 数据冲突处理优先级、告警重试机制
   - 权限与安全合规（GDPR等）

3. **需求明确**（功能、体验与交付）
   - 后台管理范围、权限体系
   - 前端小程序/H5 功能边界（搜索/拍照/分享/AI问答）
   - 上线计划、SLA 要求、运营支持机制

问题数量要求：**不少于50问**，维度分布合理，P0/P1/P2 优先级标注清晰。

### Step 4 — 输出 Excel

使用 Node.js `exceljs` 包构建 Excel 文件：

- 工作表：`封面` / `问题总表` / `历史数据` / `数据对接` / `需求明确`
- 优先级用颜色区分：🔴 P0（红色）/ 🟠 P1（橙色）/ 🔵 P2（蓝色）
- 每行包含：序号、维度（总表）、问题内容、优先级、状态、备注/负责人

> **注意**：Exceljs 的 color `{argb}` 需要 8 位 ARGB 格式（如 `'FF1B3A5C'`），
> 6 位 hex（如 `'1B3A5C'`）会被截断导致文件损坏。

参考 `scripts/build_questions.js` 了解完整的颜色定义和问题数据结构。

## 输出规范

- 文件保存路径：`/workspace/商品信息管理系统需求调研问题清单_v1.0.xlsx`
- 文件名按实际项目动态命名（不含特殊字符）
- 交付前用 `MiniMaxXlsx check` 工具验证文件格式

## 已知约束

- Exceljs 颜色必须是 8 位 ARGB（`FF` + RRGGBB），不接受 6 位或 `#` 格式
- docx 解析：读取 `word/document.xml` 中的 `<w:t>` 标签内容
- pptx 解析：读取 `ppt/slides/slide*.xml` 中的 `<a:t>` 标签内容
- xlsx 解析：`const X=require('xlsx'); X.utils.sheet_to_json(ws)`
