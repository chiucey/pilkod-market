# 测试方案自动编写器

## 工作流程

### 阶段1：输入接收与分析

接收用户输入的文件或内容，支持以下格式：
- **需求文档**：软件需求规格说明书、功能描述文档
- **设计文档**：架构设计、详细设计、接口设计
- **实现代码**：源代码文件（支持多语言）

**分析要点：**
1. 提取关键功能模块
2. 识别输入输出接口
3. 梳理业务逻辑流程
4. 标记关键业务规则

### 阶段2：引导式问答澄清

使用结构化问答引导用户确认关键测试维度：

```
【问答模板】

Q1. 测试范围确认
- 核心功能测试是否覆盖？
- 边界条件测试是否需要？
- 异常场景测试是否包含？

Q2. 测试策略选择
- 采用黑盒测试还是白盒测试？
- 自动化测试比例要求？
- 性能测试需求？

Q3. 测试数据准备
- 是否需要准备测试数据集？
- 特殊测试数据要求？

Q4. 风险与优先级
- 高风险功能模块？
- 必须优先验证的场景？
```

### 阶段3：测试方案生成

根据输入文档和问答结果，生成结构化测试方案文档。

**输出文档结构：**

```markdown
# 测试方案文档

## 1. 文档信息
- 项目名称
- 版本号
- 创建日期
- 作者

## 2. 测试范围
- 被测系统概述
- 测试边界
- 不在测试范围内

## 3. 功能测试用例
### 3.1 模块A测试
- 用例编号、名称、优先级
- 前置条件
- 测试步骤
- 预期结果
- 实际结果（测试后填写）
- 测试结论

## 4. 接口测试用例
- 接口列表
- 请求参数
- 响应验证
- 异常处理

## 5. 性能测试要求
- 响应时间指标
- 并发用户数
- 吞吐量要求

## 6. 安全测试要点
- 认证授权测试
- 数据加密验证
- 漏洞扫描范围

## 7. 测试进度计划
- 测试阶段划分
- 时间安排
- 里程碑

## 8. 测试环境要求
- 硬件环境
- 软件环境
- 测试工具

## 9. 风险评估
- 已识别风险
- 缓解措施
```

### 阶段4：文档输出与优化

1. 生成完整的测试方案文档
2. 提供测试用例导出格式（Excel/CSV可选）
3. 响应用户修改意见进行迭代优化

## 使用示例

```
用户：帮我为这个电商系统生成测试方案
助手：请提供电商系统的需求文档、设计文档或代码，我将通过问答引导您确认测试范围...
```

## 技能约束

- 仅生成测试方案文档，不执行实际测试
- 测试用例需用户确认后生效
- 支持中英文双语输出（根据用户语言选择）
