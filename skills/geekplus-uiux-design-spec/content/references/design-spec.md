# Geekplus 系统UI/UX设计规范

统一B端系统的视觉、交互与开发落地标准，保障产品体验的一致性、易用性与可扩展性。

## 一、规范概述

### 1.1 规范目的

1. 统一产品全链路视觉设计语言，降低团队沟通成本与设计重复劳动

2. 对齐设计与开发的落地标准，保障设计还原度，提升研发效率

3. 建立可复用的设计体系，支撑业务快速迭代与功能扩展

4. 保障B端产品核心的操作效率与用户体验一致性

### 1.2 适用范围

本规范适用于公司内部所有B端业务系统、UI设计与前端开发环节，所有相关产出物均需遵循本规范标准。

### 1.3 设计基准

- 组件底层：基于 Element Plus 组件库进行主题定制与规范对齐

- 基础分辨率：1920*1080 桌面端设计基准

- 设计软件：Figma

- 浏览器兼容：Chrome 主流现代浏览器

## 二、核心设计原则

1. **一致性**：全局视觉、交互、组件、文案保持统一，同一场景同一种元素仅有一种表达形式

2. **高效性**：以B端用户操作效率为核心，简化操作路径，降低用户认知成本与学习成本

3. **易用性**：贴合业务场景，功能层级清晰，状态反馈明确，保障不同熟练度的用户均可顺畅操作

4. **可扩展性**：设计体系支持业务灵活迭代，组件与规范可复用、可扩展，兼容不同业务场景

5. **严谨性**：数据展示清晰准确，操作逻辑严谨，具备完善的容错机制与操作可逆设计

### 3.3 间距系统

#### 3.3.1 基础间距单位

全局基础间距单位为 **4px**，所有间距必须为4px的整数倍，禁止出现奇数间距、非4倍数的间距值，保障界面视觉节奏统一。

间距Token与数值映射规则：

|Token 名称|数值|常用场景|
|---|---|---|
|spacing-1|4px|元素内边距、紧凑场景内间距、图标与文字间距|
|spacing-2|8px|小型元素间距、标签间距、紧凑模块内间距|
|spacing-3|12px|表单元素间距、列表项内间距、次要模块间距|
|spacing-4|16px|页面左右边距、卡片内边距、模块内元素间距、栅格gutter|
|spacing-5|20px|标题与内容间距、分组元素间距|
|spacing-6|24px|模块之间间距、页面上下边距、大卡片内边距|
|spacing-8|32px|大模块间距、页面区块间距、一级内容间距|
|spacing-10|40px|页面顶级区块间距、大标题与内容间距|
|spacing-12|48px|页面顶部与内容间距、超大模块间距|
#### 3.3.2 间距应用规则

1. **内外间距区分**：元素内部间距使用内边距(padding)，元素之间间距使用外边距(margin)，禁止混用

2. **统一间距方向**：全局统一使用「margin-bottom」控制纵向间距，「margin-right」控制横向间距，避免相邻元素双向margin造成的间距重叠

3. **层级匹配原则**：间距大小与信息层级正相关，信息层级越高，间距越大；同层级元素使用相同间距

4. **紧凑场景适配**：表格内、表单内、工具栏等紧凑场景，优先使用8px、12px、16px间距；页面级模块使用24px、32px间距

### 3.4 圆角规范

全局圆角基准值统一为 **6px**，基于Element Plus默认圆角进行全量覆盖，规则如下：

1. 所有可交互组件（按钮、输入框、选择器、开关、标签等）默认圆角统一为6px

2. 所有容器组件（卡片、弹窗、抽屉、下拉菜单、气泡框等）默认圆角统一为6px

3. 特殊场景例外规则：

    - 无边框分割线、直角容器、全屏组件可使用0px圆角

    - 特殊场景2px圆角（仅顶部导航页签）

    - 圆形头像、圆形按钮、角标等圆形元素使用50%圆角

4. 禁止使用规范外的圆角值，保障全局视觉圆角风格统一

### 3.5 尺寸规范

#### 3.5.1 组件基础尺寸

全局组件常规（默认）尺寸高度统一为 **32px**，基于Element Plus组件尺寸体系定制，全量尺寸规则如下：

|尺寸等级|Token 名称|高度值|适用场景|
|---|---|---|---|
|大号(Large)|size-large|40px|特殊关键流程节点、主要行动点|
|常规(Default)|size-default|32px|页面主操作按钮、全局默认组件尺寸，绝大多数按钮、输入框、选择器、下拉框等表单组件|
|小号(Small)|size-small|24px|表格内操作按钮、紧凑布局表单、标签栏操作、次要功能组件|
#### 3.5.2 尺寸应用规则

1. 同一页面、同一模块内的同类型组件，必须使用统一尺寸，禁止混用不同尺寸

2. 主操作按钮尺寸≥次要操作按钮尺寸，突出核心操作优先级

3. 表单内所有组件必须使用同一尺寸，保障表单视觉对齐与一致性

## 四、组件设计规范

### 4.1 规范说明

1. 组件视觉样式必须严格遵循上述基础规范（色彩、字体、间距、圆角、尺寸、阴影），禁止私自修改

2. 业务定制组件需基于本规范进行设计，保持与基础组件视觉、交互风格统一

### 4.2 基础组件

#### 4.2.1 Button 按钮

1. 尺寸：遵循全局尺寸规范，常规高度32px，大号40px，小号24px

2. 圆角：统一6px

3. 类型与样式规范：

    - 主按钮：常规填充blue-1，文字text-5，hover填充blue-2，active填充blue-3，禁用填充blue-4，

    - 次要按钮：填充fill-5-light，blue-1描边，文字blue-1；hover fill-5-light，blue-2描边，文字blue-2；active fill-5-light，blue-3描边，文字blue-3；禁用白底+blue-4描边，文字blue-4

    - 幽灵按钮：填充fill-5-light，line-3描边，文字text-3；hover fill-5-light，blue-3描边，文字text-2；active fill-5-light，blue-3描边，文字text-3；禁用白底+line-3描边，文字text-4

    - 文字按钮：无背景无描边，文字blue-1；hover背景blue-5；active背景浅蓝加深；禁用文字blue-4

    - 功能按钮（成功/危险/警告）：对应功能色规范，交互状态匹配对应色系梯度

4. 通用规则：

    - 常规按钮内左右内边距统一为12px，图标与文字间距8px，同一行按钮间距8px/16px

    - 大号按钮内左右内边距统一为16px，图标与文字间距8px，同一行按钮间距16px

    - 小号按钮内左右内边距统一为8px，图标与文字间距4px，同一行按钮间距8px

## 五、页面布局规范

### 5.1 栅格系统

1. 基于24等分栅格体系，1个单位=1/24页面宽度，适配不同分辨率

2. 栅格gutter（槽宽）默认16px，紧凑布局使用8px，宽松布局使用24px，同一行栅格gutter统一

3. 响应式断点规则：

    - xl：≥1920px，使用24栅格完整布局

    - lg：≥1200px，适配笔记本分辨率，栅格可合并调整

    - md：≥992px，最小适配分辨率，核心功能可正常展示

4. 禁止在栅格内直接设置margin，所有间距通过gutter和padding实现

### 5.2 页面结构规范

标准B端页面从上到下结构层级固定，禁止随意调整：

1. 页面标题区：标题+页面主要操作按钮区，标题左对齐，操作按钮右对齐

2. 筛选区：与标题区间距16px，非卡片展示，仅展示筛选项本身，查询按钮使用次要按钮，重置按钮是幽灵按钮

3. 工具栏区：按钮组+搜索框，左对齐功能按钮，右对齐搜索/批量操作，与筛选区间距16px

4. 内容区：表格/卡片列表/数据看板，与工具栏间距16px

5. 分页区：右对齐分页组件，与内容区间距16px

6. 页面底部：距离最后一个元素间距16px

7. 页面主操作按钮，在页面标题区，在同一行的右侧，操作按钮右对齐

8. 列表页表格填充页面，分页区始终在页面的右下角，无太多内容可留白填充

### 5.3 响应式适配规范

1. 核心适配分辨率：1920*1080（基准）、1366*768、1600*900、2560*1440

## 六、通用交互规范

### 6.1 交互设计原则

1. 操作可预期：用户操作前可预判操作结果，无意外操作

2. 反馈及时：所有用户操作均有即时视觉反馈，无操作无响应情况

3. 操作可逆：支持撤销、返回、取消操作，避免不可逆的危险操作

4. 减少重复操作：保留用户操作习惯，支持批量操作、快捷键操作，提升效率

5. 容错性：提供输入校验、错误提示、操作确认，降低用户出错概率

### 6.2 通用状态交互规则

1. 可交互元素必须具备4种基础状态，禁止缺失：

    - 常规态(normal)：元素默认展示状态

    - 悬浮态(hover)：鼠标移入元素的状态，必须有明确视觉变化

    - 点击态(active)：鼠标按下未松开的状态，视觉变化强于hover态

    - 禁用态(disabled)：不可操作状态，视觉置灰，禁止点击与事件触发

2. 聚焦态(focus)：所有可输入、可键盘导航的元素，必须有明确的聚焦状态，使用主色描边+主色阴影

3. 加载态(loading)：操作后加载过程中，必须展示加载状态，同时禁用重复点击，加载时长超过2s需展示进度提示

### 6.3 表单交互规范

1. 输入校验：

    - 实时校验：输入过程中实时校验，失焦后展示错误提示

    - 提交校验：表单提交前全量校验，错误项自动定位到第一个错误位置

    - 校验规则：必填项、格式校验、长度校验、范围校验，错误提示需明确告知用户修正方式

2. 操作规则：

    - 按Enter键可提交表单，Tab键可按顺序切换表单项

    - 表单提交后按钮置为加载态+禁用态，防止重复提交

    - 表单重置后清空所有输入内容，恢复初始状态，校验提示同步清空

3. 联动规则：表单项联动需即时响应，无延迟，禁用项同步置灰，清空联动项内容

### 6.4 数据操作交互规范

1. 列表操作：

    - 单选/多选操作即时响应，选中项高亮展示，批量操作按钮仅在选中后可点击

    - 行内操作hover行时展示，移出隐藏，核心操作固定展示

    - 排序、筛选操作后自动刷新列表，回到第一页

2. 增删改操作：

    - 新增/编辑操作：提交成功后关闭弹窗，刷新列表，给出成功提示

    - 删除操作：单条删除需二次确认，批量删除需明确告知删除数量与风险，危险操作需输入验证码/二次校验

    - 操作失败后给出明确错误原因，保留用户已输入内容，无需重复填写

3. 分页操作：切换页码、调整每页条数后，自动回到列表顶部，刷新数据

### 6.5 层级与反馈状态验收点
1. z-index 分层（从低到高）：基础 `0`；下拉/浮层 `1000`；加载遮罩 `1500`；弹窗遮罩 `1900`；对话框/抽屉 `2000`；消息/通知 `3000`。实现中要求所有遮罩/弹层 z-index 必须落在对应区间，禁止"魔法数字"。
2. Loading 规则：Loading 遮罩使用 `mask-black3`（遮罩 30% 黑）并禁用重复点击；加载时长超过 `2s` 必须展示进度提示（或进度条）。
3. Empty 状态规则：空状态不得作为页面级遮罩覆盖；默认居中展示（图标/说明文案），主说明文案使用 `text-2`，辅助说明使用 `text-3`，如需操作按钮使用次要按钮样式（白底描边 `blue-1`）。
4. 动效验收：进入/退出动效时长优先控制在 `200ms~400ms`（全局上限仍遵守 `<=500ms`），hover/微交互不超过 `150ms`，缓动函数统一为 `cubic-bezier(0.4, 0, 0.2, 1)`。

## 七、无障碍设计规范

1. 对比度规范：所有文本与背景的对比度需符合WCAG 2.1 AA标准，正文文本对比度≥4.5:1，大文本（≥18px）对比度≥3:1，禁用状态文本除外

2. 键盘导航：所有可交互元素支持Tab键顺序导航，导航顺序与视觉顺序一致，聚焦元素有明确的聚焦状态，支持Enter键触发点击，Esc键关闭弹窗/下拉面板

3. 信息传递：禁止仅通过颜色传递信息，所有状态需同时搭配图标、文字说明，例如错误状态不仅用红色，还要搭配错误图标与错误文案

4. 屏幕阅读器适配：所有图片、图标需添加alt属性说明，表单元素需绑定label标签，非装饰性元素添加aria-label属性说明功能

5. 动画规范：界面动画时长不超过500ms，支持关闭动画效果，避免闪烁、频闪内容引发不适

6. 操作容错：所有重要操作支持撤销，输入内容支持自动保存，避免用户误操作导致内容丢失
