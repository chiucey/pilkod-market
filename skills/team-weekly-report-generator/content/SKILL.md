# 团队周报生成技能

## 技能目的

将团队各成员的周报合并为一份结构化的项目管理团队周报，并同步生成邮件正文。

## 适用场景

- 用户提供了团队各成员的周报文件路径，希望合并生成团队周报
- 用户说"生成团队周报"、"合并周报"、"生成本周团队工作汇报"等
- 用户已有周报文件，需要整合输出

## 配置说明

首次使用前，请编辑 `references/team_members.md`，填入你的团队信息：

1. **团队基本信息**：团队名称、负责人姓名、所属部门
2. **成员清单**：每个成员的姓名、负责项目、角色、备注
3. **项目与客户对应关系**（可选）：项目名称、客户联系人、系统模块
4. **输出路径**：周报文件存放的目录路径

> **注意**：以上为当前已知成员。如用户提供的周报中出现了新成员，应将其加入对应项目章节，不得遗漏。

## 输出文件命名规范

```
<输出路径>/<YYYYMMDD>/<团队名称>_项目管理团队周报_<周期>.md
```

邮件正文另存为：
```
<输出路径>/<YYYYMMDD>/<团队名称>_团队周报_<周期>_邮件正文.md
```

其中 `<YYYYMMDD>` 为报告生成日期，`<周期>` 格式如 `0428-0505`。

## 周报合并标准结构

按以下章节顺序输出，成员章节顺序应与概况表保持一致：

1. **封面信息**：报告周期、汇报人（团队负责人）、报告日期
2. **一、团队整体概况**：概述句 + 成员×项目×亮点汇总表
3. **二～N、各项目分章**：每个成员占一章，章节标题格式为 `## 二、项目X：<项目名称>（<成员>）`
   - 每章包含：报告周期、本周数据概览、关键进展、未关闭/待处理事项、下周计划
4. **风险汇总章**：所有跨项目风险统一列表，等级从🔴→🟠→🟡排列
5. **下周全团队重点章**：优先级矩阵，格式 `| ⭐/🔴/🟠/🟡 | 工作事项 | 责任人 |`
6. **邮件正文**（单独文件）：结论先行、分项目摘要、关键节点、下周重点

## 数据处理原则

- **底稿编号以 @ 符号标注**：🔶 = 本周新增
- **逾期/超时问题**：明确标注"已逾期""已超时"并用🔴标识
- **进度状态规范**：✅已解决 🔄处理中 ⚠️阻塞 ⚙️开发中
- **章节数据来源**：以各成员周报原始数据为准，不自行推断
- **如原周报中使用了其他状态符号，保留原始用法**

## 邮件正文写作规范

- 开头：时间范围 + 一句话整体成效
- 各项目摘要：每项目 1-3 句，**结论先行**，数据支撑
- 下周重点：不超过 4 条，含关键时间节点
- 结尾：引导阅读附件，署名团队负责人姓名

## 执行步骤

1. 读取 `references/team_members.md` 获取团队配置信息
2. 读取用户提供的所有周报文件（@文件路径）
3. 按"周报合并标准结构"整理各成员内容
4. 按命名规范写入主周报文件（Markdown）
5. 生成配套邮件正文（单独文件）
6. 调用 `open_result_view` 展示主周报文件

## 常见问题处理

- **成员遗漏**：主动确认是否有遗漏的周报，如发现新成员周报应补充合并
- **周期不一致**：以负责人周报周期为准，其他成员超出的部分截取
- **新成员加入**：首次出现的新成员，按其周报内容直接新增章节，同时更新 `references/team_members.md`
- **周报格式不统一**：尽量从自由文本中提取结构化信息（进展、问题、计划），无法提取的保留原文
