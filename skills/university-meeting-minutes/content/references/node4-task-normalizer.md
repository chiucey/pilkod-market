## 节点定位
- 阶段标识：STAGE_TASK_NORMALIZE
- 定位：任务层节点，基于确认版L3提取并标准化正式任务
- 上游节点：L3_CONFIRMED（必须）
- 下游节点：DERIVED

## 核心职责
1. 基于最终确认版L3提取正式任务
2. 三要素校验与结构化
3. 任务状态标注
4. 任务风险关联

## 前置条件
- L3已进入STAGE_L3_CONFIRMED
- VERIFY_PASS已通过
- 若前置条件未满足，不得执行任务提取

## 三要素识别规则

### 三要素定义
1. **明确责任主体**：具体的部门、岗位或人员（非"相关部门"、"各学院"等模糊表述，除非会议原文如此）
2. **明确执行动作**：具体的行动指令（非"关注"、"重视"等虚词）
3. **明确执行意图**：行动的目标或预期结果

### 识别规则
- 三要素完整 → 列入正式任务表
- 缺任一要素 → 列入"待明确任务"，标注缺失要素
- 禁止为三要素不完整的任务自行补全缺失要素
- 禁止将非任务性表述（如"会议认为"、"会议强调"）强行转化为任务

### 示例
- "由教务处牵头在3月底前完成培养方案修订" → 三要素完整，正式任务
- "各学院要高度重视" → 责任主体模糊+执行动作虚化，待明确任务
- "会议认为需要加强安全管理" → 非任务性表述，不提取

## 任务字段定义

| 字段 | 说明 | 取值/格式 |
|------|------|----------|
| 任务 | 任务内容描述 | 完整的任务描述文本 |
| 责任主体 | 责任部门/岗位/人员 | 按L3原文提取 |
| 执行动作 | 具体行动 | 动宾结构 |
| 时间要求 | 完成时限 | 优先YYYY-MM-DD格式 |
| 状态 | 当前状态 | 枚举值（见下） |
| 风险等级 | 任务关联风险 | low/medium/high |
| 高关注标记 | 是否需重点关注 | true/false |
| source_refs | 来源引用 | L3段落引用+L2编号 |
| 备注 | 补充说明 | 限制性说明等 |

### 状态枚举
1. 状态未明确
2. 未启动
3. 推进中
4. 已完成
5. 待确认

### 时间格式
- 优先使用YYYY-MM-DD
- 原文仅有"月底前"等模糊表述时照录，标注"按原文"
- 无时间要求的标注"未明确"

## 缓存失效规则

以下情况导致TASK_NORMALIZER结果失效，需重新提取：
1. L3版本变化（进入新的L3_REVISION）
2. VERIFY_PASS失败导致L3修订
3. 任务部分被修订（其他部分可能受影响）

## 待明确任务处理

三要素不完整的任务：
- 单独列表，与正式任务表区分
- 标注缺失的具体要素
- 建议补充方向，但不自行补全
- 标注source_refs便于追溯

## 无任务场景

- task_count=0时，pass仍可为true
- 说明本次会议无正式任务提取
- 检查是否存在遗漏（结合L2 formal_task_candidates对照）
- 若L2有candidates但L3确认后无对应任务，需说明原因

## 输出协议

### MACHINE_RESULT
包含：state_fields（传递+更新）、tasks（正式任务列表）、pending_tasks（待明确任务列表）、task_count、缓存状态

### CONTENT_MARKDOWN（10个部分）
1. 正式任务表
2. 待明确任务表
3. 任务-议题映射
4. 任务-风险关联
5. 时间节点汇总
6. 高关注任务标注
7. 与L2 candidates的对照说明
8. 缓存失效说明（如适用）
9. 任务统计
10. 路由提示

## 禁止行为
1. 基于未确认的L3提取任务
2. 为三要素不完整的任务自行补全
3. 将非任务性表述转化为任务
4. 修改L3的任务相关表述
5. 删除L3已明确记录的任务
6. 新增L3未涉及的任务
7. 改变任务的责任主体
8. 弱化任务的风险等级
9. 自行推断任务完成时间
10. 将"会议认为"/"会议强调"等非任务表述转为任务
