# 提示词自动提升器

## 核心工作流

本技能在用户确认任务成果满意后自动触发，通过分析成果特征反向推导更优提示词，并与原提示词对比优化。

### 阶段 1：成果特征分析

1. **成果拆解**
   - 识别成果的核心要素（结构、风格、深度、格式）
   - 提取关键成功特征（用户为何满意）
   - 记录隐性需求（用户未明说但成果中体现的期望）

2. **特征编码**
   - 将成果特征转译为可操作的提示词组件
   - 识别可复用的模式和方法论

### 阶段 2：提示词反推

1. **逆向工程**
   - 基于成果特征，反推能够产生此成果的提示词结构
   - 识别关键指令、约束条件、风格要求
   - 推导出隐含的上下文和背景信息

2. **结构化表达**
   - 将反推结果格式化为结构化提示词
   - 包含：角色定义、任务描述、输出要求、约束条件、示例格式

### 阶段 3：对比分析

1. **差异识别**
   - 对比原提示词与反推提示词的关键差异
   - 识别原提示词的不足之处
   - 发现被遗漏的重要指令或约束

2. **价值评估**
   - 评估每个差异对成果质量的影响
   - 优先保留对成果有显著正向影响的要素

### 阶段 4：提示词优化

1. **融合增强**
   - 将反推提示词中的优质要素融入原提示词
   - 补充被遗漏的关键指令
   - 优化表述方式提高明确性

2. **增强版提示词结构**
   ```
   # 角色/身份定义
   [清晰的角色定位]

   # 任务背景
   [必要的上下文信息]

   # 核心任务
   [明确要做什么]

   # 输出要求
   [格式、风格、深度等具体要求]

   # 约束条件
   [必须遵守的边界和限制]

   # 参考示例（可选）
   [期望的输出样例]
   ```

### 阶段 5：存储与应用

1. **知识存储**
   - 将优化后的提示词与原提示词建立映射关系
   - 存储到 `/memories/prompt-enhancements/` 目录
   - 记录优化原因和效果预期

2. **自动应用机制**
   - 后续检测到与存储的原提示词相似的输入
   - 自动调用对应的优化提示词版本
   - 在响应开始时说明使用了优化版本

## 存储格式

优化后的提示词存储在 JSON 文件中：

```json
{
  "original_prompt": "用户原始提示词",
  "enhanced_prompt": "优化后的提示词",
  "improvement_notes": "优化说明",
  "created_at": "时间戳",
  "success_count": 0,
  "last_used": null
}
```

## 触发条件

- 用户明确表示满意："很好"、"完美"、"就是这个"
- 任务成果达到预期目标
- 用户要求主动优化提示词

## 注意事项

1. **保持一致性**：优化后的提示词应保持与原提示词相同的目标
2. **增量改进**：避免过度修改，每次优化聚焦于关键差异
3. **可解释性**：记录优化原因，便于用户理解和调整
4. **渐进学习**：随着使用次数增加，提示词库持续完善
