# 洞察提取方法论参考

## 1. 用户目标提取

### 提取原则
- **显性目标**：受访者直接表达的目标（"我想..."、"我要..."）
- **隐性目标**：通过行为推断的目标（做了某事说明想达成某结果）
- **层级分析**：区分战略目标、战术目标、操作目标

### 标注规范
```
目标类型：[战略/战术/操作]
验证强度：[高/中/低]（基于原话数量和行为印证）
出现频次：X次
```

## 2. 痛点分析框架

### 痛点分类
| 类型 | 描述 | 关键词 |
|------|------|--------|
| 功能痛点 | 功能无法满足需求 | 无法、不能、缺少 |
| 体验痛点 | 使用过程不顺畅 | 麻烦、复杂、费时 |
| 流程痛点 | 流程设计不合理 | 要走、审批、等待 |
| 情绪痛点 | 使用时情绪负面 | 烦躁、失望、愤怒 |

### 严重程度评估
| 等级 | 描述 | 表现 |
|------|------|------|
| P0 | 阻断性问题 | 直接导致放弃使用 |
| P1 | 严重痛点 | 显著影响效率或体验 |
| P2 | 一般痛点 | 有影响但可克服 |
| P3 | 微小不便 | 可忽略或用户已适应 |

## 3. 行为模式识别

### 模式类型
- **使用路径**：完成任务的操作序列
- **习惯行为**：反复出现的无意识操作
- **决策模式**：做选择时的判断依据
- **异常行为**：与常规不同的做法

### 模式提炼
```
模式：[简洁描述]
特征：[关键特征1、2、3]
典型场景：[在什么情况下出现]
覆盖用户：[X/Y受访者]
```

## 4. 机会点发现

### 来源分类
| 来源 | 说明 | 可信度 |
|------|------|--------|
| 痛点推导 | 基于痛点的解决方案 | 高 |
| 未满足需求 | 访谈中表达的需求 | 高 |
| 行为洞察 | 从行为模式发现 | 中 |
| 竞品启示 | 受访者提及的竞品优点 | 中 |
| 趋势外推 | 行业趋势启发 | 低 |

## 5. 置信度评估

### 单条洞察置信度
| 评级 | 条件 |
|------|------|
| 高 | 原话确认 + 行为印证 + 多处佐证 |
| 中 | 原话确认 + 1项佐证 |
| 低 | 单一来源 |

### 综合置信度（合并报告）
| 评级 | 条件 |
|------|------|
| 高 | 3+访谈印证，核心洞察一致 |
| 中 | 2+访谈印证，主要洞察一致 |
| 低 | 仅1份访谈或存在明显分歧 |

## 6. 知识库融合规则

### 冲突类型判定
| 类型 | 判定条件 | 处理方式 |
|------|---------|---------|
| 一致 | 新访谈信号 = 历史结论 | 置信度提升 |
| 补充 | 新信号扩展历史结论 | 合并输出 |
| 冲突 | 新信号 ≠ 历史结论 | 并列展示 + 差异分析 |
| 矛盾 | 新信号否定历史结论 | 高亮警告 + 需验证 |

### 融合步骤
1. 提取知识库中的"已知假设"列表
2. 将访谈信号逐一比对
3. 判定关系类型
4. 生成融合洞察
5. 识别待验证问题
