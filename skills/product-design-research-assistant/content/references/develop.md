# 发展阶段 (Develop) 参考模板

## 1. 头脑风暴组织指南

### 准备阶段
- **议题明确**：提前向参与者清晰阐述要解决的问题（HMW）
- **人数控制**：5-10人为佳
- **时间分配**：每人2分钟想法陈述 + 5分钟自由联想
- **规则宣读：**
  - 数量优于质量，先发散后收敛
  - 禁止批评，所有想法都有价值
  - 鼓励"yes,and"式延展
  - 欢迎跨领域组合创新

### 记录模板

| # | 创意描述 | 核心原理 | 可行性 | 创新性 | 备注 |
|---|---------|---------|--------|--------|------|
| 1 | | | ★★★/★★/★ | ★★★/★★/★ | |

### 收敛决策——SCAMPER法则

对每个候选方案应用SCAMPER检查：
- **S**ubstitute（替代）：能用什么替代？
- **C**ombine（组合）：能和什么组合？
- **A**dapt（改编）：能做什么改编？
- **M**odify（修改）：能做什么修改？
- **P**ut to other use（其他用途）：还有别的用途吗？
- **E**liminate（消除）：能去掉什么？
- **R**everse/Rearrange（反转/重排）：能反转什么？

## 2. 方案多维评估矩阵

### 评估维度与权重

| 维度 | 权重 | 说明 |
|------|------|------|
| 用户价值 | 30% | 解决痛点的有效程度 |
| 技术可行性 | 20% | 现有技术能否实现 |
| 商业可行性 | 20% | 成本、收益、可持续性 |
| 创新性 | 15% | 与竞品的差异化程度 |
| 用户体验 | 15% | 交互流畅度、学习成本 |

### 打分标准（1-5分）

| 分值 | 用户价值 | 技术可行性 | 商业可行性 | 创新性 | 用户体验 |
|------|---------|-----------|-----------|--------|---------|
| 5 | 完全解决痛点 | 无技术障碍 | 高ROI | 颠覆性创新 | 极流畅直观 |
| 4 | 大部分解决 | minor问题 | 较好 | 显著改进 | 较流畅 |
| 3 | 部分解决 | 中等难度 | 中等ROI | 有所改进 | 一般 |
| 2 | 改善有限 | 较大难度 | 较低ROI | 微创新 | 较复杂 |
| 1 | 无改善 | 难以实现 | 负ROI | 无新意 | 难以使用 |

### 综合得分计算

> **综合得分 = Σ(维度得分 × 权重)**

## 3. 低保真原型制作指南

### 原型类型选择

| 类型 | 适用阶段 | 保真度 | 制作工具 |
|------|---------|--------|---------|
| 纸质原型 | 初期概念验证 | 极低 | 纸笔 |
| 轮廓图（Wireframe） | 功能流程验证 | 低 | Figma/Sketch/Axure |
| 灰模（Clickable Prototype） | 可用性测试 | 中 | Figma/Axure/ProtoPie |
| 数字高保真原型 | 利益相关者展示 | 高 | Figma/Sketch |

### 纸质原型制作步骤

1. 打印或手绘关键界面（每个关键流程至少3个核心页面）
2. 标注页面状态（默认、加载、空状态、错误）
3. 用便签标注交互热区
4. 用另一个颜色的便签标注页面跳转逻辑
5. 进行" думаю think-aloud测试"：让用户边操作边说出想法

### 可用性测试脚本模板

**开场（5分钟）**
- 欢迎并自我介绍
- 说明测试目的（非测试用户，是测试产品）
- 介绍测试任务和规则

**任务执行（30-40分钟）**

| 任务 | 期望行为 | 备选提示（用户卡住时） |
|------|---------|----------------------|
| | | 1. 请问你在想什么？ |
| | | 2. 你现在在做什么？ |
| | | 3. 有什么困惑的地方吗？ |

**收尾（5分钟）**
- "你对这个流程有什么建议？"
- "如果满分10分，你给这个功能打几分？"
- "还有什么想补充的吗？"

## 4. 设计原则清单

### 尼尔森十大可用性原则

1. **系统状态可见**：及时反馈操作结果
2. **系统与现实匹配**：使用用户语言，而非技术术语
3. **用户控制自由**：提供"紧急出口"（撤销、返回）
4. **一致性与标准化**：同类操作保持一致
5. **防错优于纠错**：在错误发生前预防
6. **识别而非回忆**：可见选项，减少记忆负担
7. **灵活高效**：同时满足新手和专家用户
8. **美观简洁**：去除冗余不必要信息
9. **帮助识别和恢复**：错误信息要友好，提示解决方案
10. **帮助文档**：提供必要的帮助说明

### 设计检查清单

- [ ] 用户能在3秒内理解界面主要功能？
- [ ] 核心操作步骤是否不超过3步？
- [ ] 是否有防错机制？
- [ ] 错误提示是否有用且友好？
- [ ] 加载状态是否有反馈？
- [ ] 空状态是否有引导？
- [ ] 是否适配不同屏幕？
- [ ] 关键操作是否有二次确认？
