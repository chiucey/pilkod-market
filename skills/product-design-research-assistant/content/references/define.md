## 2. 核心问题定义——HMW句式

**How Might We (HMW) 句式生成法：**

将痛点转化为设计机会：
- "用户抱怨X" → "我们如何能让用户在使用X时感到更Y？"

**示例：**
- 痛点：用户反映在外卖App上选餐太费时间
- HMW：我们如何能帮助用户在30秒内做出满意的点餐决策？

### HMW候选问题库（至少产出3个）

| # | HMW问题 | 对应洞察 | 潜在影响力 | 可行性 |
|---|---------|---------|-----------|--------|
| 1 | | | ★★★/★★/★ | 高/中/低 |
| 2 | | | ★★★/★★/★ | 高/中/低 |
| 3 | | | ★★★/★★/★ | 高/中/低 |

**筛选标准：**
- 影响力：解决这个问题能带来多大用户价值？
- 可行性：在现有技术和资源下能实现吗？
- 差异化：竞品是否已充分解决？

## 3. 需求优先级排序

### MoSCoW法则

| 优先级 | 定义 | 需求 |
|--------|------|------|
| **Must have**（必须有） | 缺了产品无法上线 | |
| **Should have**（应该有） | 很重要，但不是致命缺失 | |
| **Could have**（可以有） | 锦上添花 | |
| **Won't have this time**（这次不做） | 未来可能考虑 | |

### Impact-Effort矩阵

```
                    高Impact
                      ↑
                 ┌────┼────┐
                 │  快速胜出 │  重大策略  │
                 │(小投入   │(大投入    │
                 │ 大产出)  │ 大产出)   │
Effort           ├──────────┤
                 │  填充功能 │  长期项目  │
                 │(小投入   │(大投入    │
                 │ 小产出)  │ 小产出)   │
                 └────┼────┘
                      ↓
                    低Impact
          ←低Effort                高Effort→
```

### 推荐优先级（Kano模型视角）

| 需求类型 | 说明 | 优先级 |
|---------|------|--------|
| 基本型需求 | 必须有，没有用户会极度不满 | P0 |
| 期望型需求 | 越多越满意 | P1 |
| 兴奋型需求 | 超预期，带来惊喜感 | P2 |

## 4. 问题陈述 (Problem Statement) 模板

> **对于** [目标用户群]
> **谁在** [特定场景/情境]
> **[产品名]** 是一个 [产品类别]
> **它能够** [核心功能]
> **我们的产品** [解决什么问题/满足什么需求]
> **区别于** [竞品/现有方案]
> **因为它** [差异化优势]
> **从而帮助用户** [最终价值/目标]

### 示例：
> **对于** 都市通勤的上班族
> **谁在** 每天花费1小时以上在地铁/公交上
> **"地铁伴"** 是一个通勤娱乐App
> **它能够** 利用离线缓存提供个性化音频内容
> **我们的产品** 解决了在地铁无信号时内容中断的问题
> **区别于** 喜马拉雅等需要持续联网的音频App
> **因为它** 智能预测用户偏好并提前缓存内容
> **从而帮助用户** 在无网环境下也能享受不间断的沉浸式音频体验
