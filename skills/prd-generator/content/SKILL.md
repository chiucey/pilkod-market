# PRD 生成器 | PRD Generator

将产品想法/需求描述转化为结构化 PRD（含范围、用户故事、功能需求、验收标准、里程碑、风险与问题清单）。

---

## When to Use

当用户出现以下意图时启用：
- "帮我写 PRD / 需求文档 / 产品需求"
- "把这个想法整理成 PRD"
- "把功能需求结构化、给验收标准/里程碑/风险"
- "给研发可执行的需求说明"

**不适用**：
- 用户仅要一句话介绍、营销文案
- 纯技术方案（应切换到对应 skill）

---

## 输入要求 | Inputs

### 必填（缺失时允许追问或使用默认）

| 字段 | 说明 |
|------|------|
| 产品一句话描述 | 是什么、为谁、解决什么问题 |
| 目标用户 | 典型用户/角色（至少 1 个） |
| 核心目标 | 成功的衡量方式（至少 1 条） |

### 选填

- 现状与痛点
- 范围边界（明确"不做什么"）
- 平台与约束（Web/iOS/Android/小程序/后台）
- 竞品/参考
- 数据/埋点
- 集成依赖
- 上线时间

### 默认假设

- 默认输出 **MVP 版本** + **后续迭代建议**
- 默认至少 **3 个用户故事**、**10 条功能需求**、**6 条验收标准**
- 若缺少指标：给出 **北极星指标 + 2~4 个辅助指标**

---

## 工作流程 | Process

1. **复述需求**：用 3~6 句确认理解了什么
2. **补齐缺口**：只问最关键的 3 个问题；否则用合理默认并标注"假设"
3. **拆分用户与场景**：角色 → 任务 → 痛点 → 期望结果
4. **定义范围与 MVP**：Must-have / Should-have / Could-have
5. **输出结构化 PRD**
6. **质量门槛自检**

## 质量门槛 Checklist

输出前必须满足：
- [ ] 目标清晰且可量化（至少 1 个指标 + 口径）
- [ ] 有明确的 MVP 范围 + Out of scope
- [ ] 需求条目可执行：包含规则/边界/权限或状态
- [ ] 至少 6 条可测试的验收标准
- [ ] 明确依赖与风险（至少各 2 条）
- [ ] 开放问题真实存在且足够关键

---

## 追问策略 | Clarification

最多问 3 类问题：
1. **目标与成功标准**：上线后什么指标变好算成功？
2. **用户与场景**：最重要的 1 个用户是谁？最频繁的 1 个场景是什么？
3. **范围边界**：有什么明确"不做"的？有什么硬性约束？

不回答时：用默认假设继续，并在 PRD 里标注。

## 禁忌与注意事项

- 使用**明确、可测试、无歧义**的语言
- 避免"尽量/可能/感觉更好"等模糊词汇
- 对不确定内容用"假设：…"标注
- 不编造具体法律条款编号
- 不写死实现细节
