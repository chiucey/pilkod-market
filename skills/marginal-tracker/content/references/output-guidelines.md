# 平台中立的输出规范

## 需求确认

- 用户明示了格式、深度、受众、重点 → 直接照做。
- 只有当缺失信息会**实质性**改变分析时,才用一个简短问句向用户追问。
- 无法交互时,采用本技能规定的默认产物:调用 `visual-page` 生成 GUI/HTML 审查页,并在交付说明里写清楚假设。
- 不要依赖特定平台的表单 / 计划模式 / 专有 UI / 内部渲染工具。

## 输出格式

- 轻量请求:直接给结构化 Markdown 即可。
- 完整报告 / 跟踪器 / 表格型产物:默认整理为 `visual-page brief`,调用 `visual-page` 生成 GUI/HTML 页面,需保证能在普通浏览器里直接打开。
- Excel / CSV:仅在用户明确要求、需要导入外部系统、或作为审计支持附件时输出;不得作为默认面向读者的主产物。
- 结构化数据:按需给 JSON,但**不得把 JSON 当成默认的面向读者的主产物**。

## 可移植性

- 引用技能内部资源时用相对路径。
- GUI/HTML 必须通过 `visual-page` skill 生成,不要引用不存在的父插件、内部路由器或某家供应商的渲染器。
- 视觉约定:冰白纸背景、液态玻璃风格;不要使用 `visual-page` 默认配色方案;上涨、好事、强调色统一用中国红 `#c0322f`;下跌、坏事统一用稳绿 `#15803d`。
- 宿主平台不支持某种文件格式时,回退到 Markdown,同时保留同样的分析结构与来源标注。
- 任何输出都要保留数据截至时间、来源、口径、假设、缺失项。
