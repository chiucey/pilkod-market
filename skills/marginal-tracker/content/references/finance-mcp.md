# MiniMax Finance Data MCP 使用规范

## 主体解析

1. 根据市场为 `resolve_entity` 选择 `entity_type`:
   - A股 → `a_stock`
   - 港股 → `hk_stock`
   - 美股 → `us_stock`
   - 基金 / 债券 / 指数 → `fund` / `bond` / `index`
   - A股行业与概念 → `industry` / `sw_industry` / `concept`
   - 港股行业 → `hk_industry`
2. 用公司名称、简称或证券代码作查询条件,获取候选列表。
3. 根据交易所、证券代码、公司全称、行业描述定位正确的内部 `code`——**不要猜**。

## 数据调用

- 公司、财务、行情、估值、事件、股东、分红 / 融资、基金、债券、指数、行业等数据,统一走 `call_api(api_id=..., params=...)`。
- 宏观与产业指标:先用 `query_macro(keyword=...)` 搜索,拿到 `indicId` 与明细参数后再取时序数据。
- `call_api` 返回业务枚举错误时,先用 `enum_candidates` 修正参数再重试。
- 大表用 CSV;关键结论所需的小表用 Markdown 或 JSON。

## 口径与来源

- 必须留存:市场、交易代码、内部 `code`、数据截至时间、报告期、单位、币种、会计准则、复权口径。
- 跨市场分析必须统一币种与期间,或明确保留不可比差异。
- 最新价格、估值、事件、宏观数据必须记录查询时间戳。
- MCP 没返回的数据标"缺失",**不得编造或推测**。

来源优先级:

1. 监管机构、交易所、上市公司的正式披露
2. MiniMax Finance Data MCP 的结构化数据
3. 用户提供的模型、跟踪器、研究资料
4. 其他可核验的公开来源

结构化数据与正式披露冲突时,以正式披露为准,并把差异落到日志里。
