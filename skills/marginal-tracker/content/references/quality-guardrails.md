# 质量护栏

## PM 级检查清单

交付前回答以下问题:

- 我们原先信什么?市场信什么?发生了什么?
- 公司论点状态如何?证券论点是否够格用于投资决策(这是两个**分开的**判断)?
- 公司论点汇总状态是否与核心支柱状态对齐?任何覆盖理由是否有明确证据支撑?
- 受影响的是哪个支柱?信号是确认、反驳、混合、不相关,还是未检验?
- 这个变化是临时、周期、结构性、时点问题,还是早已被计入?
- 模型、估值、下行、确信度、规模、对冲、决策时点哪些会变?
- 下一步行动是什么?什么会让我们错?下一个验证点是什么?

## 市场数据与就绪度

- 重大证券论点更新前,尽量取当前公开价与基本市场背景;记录来源与截至时间戳。
- 缺失的:当前价、估值模型、一致预期、仓位规模、基准 / 主动权重、风险预算——若会改变行动,**必须以显性决策缺口形式出现**。
- 不要在缺失证券论点所需输入时,把一个走弱的公司论点变成估值驱动的 `trim` / `exit` / `add` 结论。该用 `Re-underwrite` / `Conditional` / `Not decision-grade`。

## 可证伪性与漂移

每个跟踪器都需要:论点、差异化认知、市场已计入预期、有优先级的支柱、KPI、确认 / 警告 / 失效阈值、催化剂、终止标准、行动阈值、待解尽调。缺失就提出并打标。数值权重 / 评分仅在继承既有跟踪方法或用户明确要求时保留;**不要为了展示而制造汇总得分或评分图**。

每条新的行动阈值在 PM 批准前一律标为 `Draft threshold for PM confirmation`;`Inherited threshold` 与 `Approved monitoring rule` 各自保留独立标签,带来源与状态。

继承的核心支柱被标为 `Impaired` 时,除非给出有证据支撑的覆盖理由,汇总状态不应停留在 `Watch`。多个核心支柱 `Impaired` 通常应汇总为 `Impaired`。

**论点漂移**的识别信号:看多 / 看空的理由变了、失败催化剂被模糊的定性理由替换、估值支撑顶替了原本的增长 / 利润率论点、反驳证据被"长期看"反复无视、下行保护变成了上行仓位的新理由。

标签:`thesis intact`、`thesis evolved`、`thesis changed`、`thesis broken`、`thesis retired`。

## 证据质量

- "头条 beat / miss"不够:要拆出收入、组合、价格、降本、税、回购、汇率、一次性项目、KPI 质量、指引、FY2 / 长期修正、现金转化、管理层可信度、买方预期。
- 管理层评论的可信度,要看是否量化、连贯、有来源支撑、具体、坦诚。模糊的乐观、KPI 定义变化、选择性披露、无解释的宏观甩锅——**打折**。
- 价格走势必须拆解为:基本面、预测、倍数 / 利差 / 利率、行业 / 因子 beta、仓位 / 拥挤 / 空头逼仓、流动性 / 资金流、期权 / 波动率、宏观 / 政策。

## 红旗

KPI 定义 / 披露变化、非 GAAP 调整上升、收入确认方法变化、应收 / 库存堆积、现金转化弱、资本化成本激增、分部变更、审计师 / CFO / 控制人离职、关联交易、激进加回、反复出现的"一次性"费用。

## 合规与敏感

标注可能的 MNPI、跨墙 / 限制名单材料、专家网络敏感性、券商再分发限制、传闻、无引用主张。敏感信息不得用于公开股票交易建议;建议交合规审查或出"对外干净版"。

## 相邻路由

主要诉求是:业绩前 / 后分析、模型细更新、新推介、调仓 / 对冲、事件情景树、独立信用分析流程移交、宏观影响、委员会备忘录、报告 / 演示文稿质检——分别路由到相邻技能。

## 终检

确认:原始论点已保留,证据为追加而非覆盖,来源 / 截至日期可见,正反两面都被考虑,KPI 与预期 / 阈值有对照,公司论点状态与证券论点就绪度分开陈述,拟定阈值未被冒充为已批准规则,建议包含时点 / 阈值 / 行动,红队有可信度。

## GUI / XLSX 呈现 QA

默认面向读者交付物是 `visual-page` 生成的 GUI/HTML 页面:

- 使用冰白纸背景、液态玻璃风格。
- 不要使用 `visual-page` 默认配色方案。
- 上涨、改善、确认、利好、增持等好事，以及所有强调色，统一用中国红 `#c0322f`;下跌、恶化、削弱、利空、减持/退出等坏事统一用稳绿 `#15803d`。
- 首屏必须读出公司论点状态、证券论点就绪度、仓位行动、市场数据截至时间、下一个催化剂、最大证据缺口。
- 用 KV cards、支柱表、事件 timeline、KPI 表、决策日志表和红队矩阵表达;不要把 GUI 退化成下载工作簿说明。

用户明确要求时才输出工作簿;工作簿交付物:

- `Cover` 选项卡要面向决策、常规缩放下无需横向滚动即可读。
- 支柱表保持紧凑;扩展阈值、引用、模型影响放到专属选项卡。
- 完整的行动规则与尽调 / 缺口登记表留在专属选项卡;`Cover` 仅展示行动立场摘要、主要阻碍、下一道关口。
- 冻结关键标识列,使用有界列宽;交付前对每个工作表渲染并在常规缩放下检查。
- 修复:截断的表头、过宽的监控表、不可读的来源路径、需要大量横向滚动的决策关键文本。
- 除非评分方法继承或用户明确要求,不要包含加权评分图。

## PM 监控护栏

每次更新都把公司论点、股票论点、组合角色、市场走势设置分开陈述。可选决策行动:`add` / `press` / `hold` / `trim` / `exit` / `hedge` / `wait for proof` / `re-underwrite`。在相关时纳入基准 / ETF 含义、流动性、拥挤度、以及"什么证据会迫使做不同决策"。
