# 信息收集与来源优先级

适用场景:上下文缺失、不完整、相互冲突、时效性存疑或来源敏感。

## 上下文规则

- **无上下文**:不要发明一份公司论点。产出空白的机构级跟踪表,并向用户索要最小输入。
- **仅股票代码**:可用已连接 / 公开来源补客观事实;论点、授权、成本基础、目标价、风险容忍、内部观点均标为初步 / 缺失。
- **部分上下文**:能提取的提取,能露出的缺口露出。具体处理:
  - 备忘录 → 论点 / 支柱 / 催化剂 / 风险
  - 模型 → 驱动因素 / 假设
  - 跟踪器 → 保留结构,陈旧 / 缺失字段打标
  - 公告 / 文字稿 → 仅作证据,除非用户提供了原始论点
  - 持仓清单 → 分流出复核优先级
- **完整上下文**:追加一条新更新,保留原承销研究与既往条目,只更新状态、追加变更日志。

最小信息收集集合:发行人 / 代码 / 证券、方向、角色 / 授权、期限、论点、仓位 / 评级、原始材料、输出格式。

## 来源层级

1. 用户的提示与明示指令
2. 用户提供的文件、跟踪器、模型、备忘录、笔记——视为内部"事实底本",除非陈旧或被驳
3. 可调用的已连接路由 / 用户提供的内部系统导出
4. 公司 / 监管机构的正式披露
5. 市场数据与一致预期供应商
6. 业绩会、行业会议、投资者开放日
7. 卖方 / 第三方研究、专家访谈、另类数据(附许可与偏差标签)
8. 新闻 / 网络——用于当下公开事实与来源发现
9. 假设 / 推断(明确标出)

可靠性标签:**高**(一手 / 用户 / 来源文件)、**中**(可信文字稿 / 供应商 / 新闻 / 研究)、**低**(传闻 / 谣言 / 模糊 / 陈旧)、**未知**(无引用 / 不可核查)。

## 时效性

跟踪所有时间戳:来源日期、报告期、模型版本、一致预期截至时间、市场数据截至时间、上一份跟踪器截至日、是否纳入截至日之后发生的事件。关键事实可能已变化而当前来源不可得时,标为陈旧 / 不可用。

## 追问策略

当一份带标签的有用输出已经可行时,**不要**用宽泛的问题阻塞。只问关键阻塞项,比如:方向、追加 vs 改写、模型事实底本、期望输出格式。

## 保留原则

追加行 / 章节、创建版本标签、维护变更日志,陈旧 / 被超越 / 重复 / 被驳条目打标而非删除。除非明确授权直接删除,否则清理前先展示拟删除 / 合并项。

## 标签

涉及来源边界时,使用以下五类标签:`Fact`、`Assumption`、`Judgment`、`Open question`、`Sensitive`。
