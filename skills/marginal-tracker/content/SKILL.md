# 多市场股票投资论点边际跟踪器（marginal tracker）

## 启动顺序

1. 依次阅读 `references/finance-mcp.md`、`references/market-rules.md`、`references/marginal-schema.md`，确认 MCP 用法、市场口径与字段契约。
2. 判明标的所在市场后，使用对应主体类型(`a_stock` / `hk_stock` / `us_stock`)做实体解析,固定证券身份。
3. 通过 `call_api` 拉取财报、行情、估值、股本、股东、分红与融资、事件等结构化数据,所有数值都带回截至时间。
4. 涉及行业、宏观或主题时,解析对应市场的行业 / 概念 / 指数 / 基金主体,并用 `query_macro` 取相关指标的时序数据。
5. 跟踪器仅以"追加"方式更新,记录本次数据的截至日,并为每条证据写明来源。

## 跨市场监控要点

- 各市场的定期报告、业绩指引、监管文件、交易所公告与公司 IR 材料。
- 按当地会计准则跟踪利润、现金流、资产负债表与公司专属 KPI。
- 估值、复权股价、成交量与流动性、股本变动、解禁、增减持、回购、分红。
- 行业 / 概念 / 指数相对表现,以及所在国家或地区的宏观与产业指标。
- 公司论点、证券论点与可执行性三者要分开判断:市场规则、停牌、流动性、盘前盘后或工具可得性都可能阻碍真正落地。

## 交付物路径

呈现载体的优先级遵循 `references/output-guidelines.md`。本工作流的自然面向读者产物是一份由 `visual-page` skill 生成的 GUI/HTML 投资论点跟踪审查页——除非用户明确要求短回复,否则不要走"只聊天不出文件"。Excel/CSV 仅在用户明确要求、或作为审计/导入支持附件时生成，不能替代默认 GUI 交付。

每次为新的、面向独立读者的主交付物开工(收集来源、做新分析)之前,先加载 `references/output-guidelines.md`,只在格式 / 深度 / 受众 / 重点会真正改变结果时才追问。

对于追加更新已有跟踪器的场景,默认把更新结果整理为 `visual-page brief` 并调用 `visual-page` 生成 GUI/HTML 审查页。若用户明确要求 Excel/CSV,再把工作簿或 CSV 作为支持附件输出；仅询问会改变分析的剩余关键选择。

## 目的

持续维护一个**可被证伪**的公开股票投资论点。原始承销研究判断保留,新证据追加进入,每次更新都要落到:公司论点状态、证券论点就绪度、KPI / 预测 / 催化剂变化、模型 / 估值影响、风险回报、PM 行动。

## 不可妥协事项

- 默认对用户数据采用**仅追加**策略;未经用户明确许可,绝不删除、合并、覆盖既有投资论点数据。
- 来源优先顺序:用户提示 → 用户提供的文件 → 现有跟踪器 / 模型 / 备忘录 → 已连接上下文 → 公开来源。需要时才查网络或时效性来源,并标注事实出处。
- 标注每条信息的:来源类型、截至日期、可靠性、是否陈旧、是否假设 / 判断、是否涉及 MNPI / 受限 / 再分发敏感材料。
- 区分三个维度:公司论点状态 / 证券论点就绪度 / 仓位行动。基本面改善与前瞻风险回报恶化可并存,市场数据缺失也可能让证券判断无法做出。
- 同时跟踪支持性与反对性证据。**股价表现本身不算证明**——必须拆解为基本面、预测、倍数 / 利差、因子 / 行业、仓位状况、流动性、利率 / 宏观、期权效应。
- 把叙事转化为有优先级、可证伪的支柱 / KPI / 阈值 / 催化剂 / 终止条件 / 行动触发。仅当从现有跟踪器继承或用户要求时才保留数值权重 / 评分;不要新造暗示虚假精确度的评分图。
- 重大证券论点更新前,在可获取范围内尝试拉取当前公开股价及基本市场背景,记录截至时间戳与来源;不可得的一致预期 / 内部模型 / 持仓 / 组合输入要明确标为决策阻塞缺口。
- 每个行动阈值都要打上来源标签:`Inherited threshold` / `Draft threshold for PM confirmation` / `Approved monitoring rule`,**分析师拟定的证伪条件**绝不可以"已获批准的授权规则"形式呈现。
- 每次重大更新都需说明:对假设 / 模型项目、估值 / 下行空间、确信度、仓位 / 对冲、决策时点、下一个验证点的影响。
- 不要给出空洞的"持续监控"措辞——一定要补上指标、阈值、来源、日期与具体行动。

## 运行模式

| 模式 | 默认行为 |
|---|---|
| 空白模板 | 无股票代码 / 论点 / 文件:产出机构级骨架与最小信息收集表;不编造事实 |
| 仅股票代码 | 仅依靠客观事实搭初稿;论点字段标为"推断 / 待内部观点确认" |
| 现有论点 | 提取原始论点、差异化认知、支柱、KPI、催化剂、终止标准、风险、待解决问题 |
| 跟踪器更新 | 追加新证据,保留旧数据,更新状态,记录变更日志 |
| 业绩发布后 | 把公告 / 电话会文字稿 / 指引 / 预测变化对接到各支柱与决策影响 |
| 投资组合审查 | 按"基本面恶化 / 改善但风险回报变差 / 催化剂 / 待决策"做分流 |
| 卖方研究 | 把事实与评级、目标价、预测、估值、客户争议、风险关联 |
| 多空策略 | 强调差异化认知、交易框架、拥挤度 / 借券 / 逼空、催化剂路径、仓位、对冲 |
| 股票风险中的信用信号 / 独立信用流程移交 | 只跟踪会改变普通股下行、仓位、对冲或重新承销研究状态的信用事实;信用证券、契约组合、重组、回收分析路由到独立信用分析流程 |

## 工作流契约

1. **上下文锁定**:发行人 / 证券、方向、授权范围、期限、敞口、基准 / 同业、用户提供的评级 / 目标价 / 成本基础、输出需求。
2. **来源盘点**:列出每条来源的名称 / 类型 / 截至日期 / 可靠性 / 覆盖范围 / 局限;在可访问时取当前股价及公开市场背景;明确缺失的一致预期、模型、组合、跟踪器数据。
3. **保留原始承销研究**:论点、差异化认知、市场框架、估值锚、情景、催化剂、KPI、风险、终止标准、仓位含义、待完成尽调,全部独立保留。
4. **拆分支柱**:每个支柱要有优先级、可证伪条件、基准值、预期路径、确认 / 警告 / 失效阈值、时间、模型关联、行动关联、下一个验证点。数值权重只在有来源或用户要求时保留,并标注来源。
5. **证据台账追加行**:事实、来源 / 日期、对应支柱、确认 / 反对信号、影响程度、质量、对模型 / 估值 / 确信度 / 行动的影响、后续事项或下一个验证点。
6. **KPI、催化剂、预测修正**:与内部观点、指引、一致预期、用户给的买方预期、阈值、同业、历史期间对比。
7. **模型 / 估值 / 风险回报影响**:短期 vs 结构性;受影响的模型项目;公允价值 / 目标价 / 下行 / 利差,与普通股相关时的回收映射;是否触达行动门槛。若关键定价或估值输入仍不可得,把证券论点标为"尚不足以支持决策",而不是硬推风险回报。
8. **公司论点 vs 证券论点分开判定**:基本面可为强化 / 完好 / 观察 / 受损 / 失效 / 改变 / 未经检验 / 终止;证券判断可为就绪 / 有条件 / 重新承销研究 / 尚不足以支持决策。用证据解释变化,不要只用股价。汇总状态要与核心支柱协调:继承的核心支柱标为 `Impaired` 时,除非有明确证据支撑的覆盖理由,否则不要把公司论点设为 `Watch`;多个核心支柱 `Impaired` 时,汇总状态默认 `Impaired`。
9. **行动建议**:加仓 / 强化、持有、减持、退出 / 回补、上调 / 下调评级、对冲 / 配对、等待、重新承销研究、更新模型、尽调、升级处理。每个持有 / 减持 / 退出阈值都附上来源与批准状态。
10. **红队检验**:最有力的反方观点、其证据、什么会反证它、什么会改变建议、待解决问题、下次审查日期、变更日志。
11. **GUI 交付质量**:默认先产出 `visual-page brief` 并调用 `visual-page` 生成 GUI/HTML 审查页。若用户明确要求 XLSX,封面与关键监控表在常规缩放下必须可读——优先使用紧凑、面向决策的列,细节放进证据台账,冻结关键标识列,交付前逐表渲染并修复过宽 / 截断;完整行动规则矩阵、完整尽调 / 缺口登记表放到专属选项卡;`Cover` 只汇总行动立场、主要阻碍、下一道关口,不要重复;除非评分方法继承或用户要求,否则不出支柱评分图。

## 默认输出

除非用户明确要短摘要 / 单章节,否则产出**完整且可支持决策**的论点更新:

1. 投资论点状态与建议;
2. 公司论点 vs 证券论点对比(含限制证券判断的缺失输入);
3. 相比先前内部观点 / 一致预期 / 市场框架的变化;
4. 支柱跟踪器:优先级 / 继承权重 / 状态 / 最新证据 / 信号 / 下一项检验;
5. KPI / 预测 / 催化剂更新;
6. 模型、估值、下行、风险回报的影响;
7. 行动阈值(含来源 / 批准状态)、决策日志、变更日志;
8. 红队检验、终止标准、待解决问题、来源 / 截至日期。

跟踪器搭建或更新场景:默认主交付物是 `visual-page` 生成的 GUI/HTML 审查页；只有当用户明确要求 Excel/CSV、需要导入其他系统、或需要审计附件时，才额外输出工作簿或 CSV。若 CSV / XLSX 脚手架有用,运行:

```bash
python scripts/materialize_marginal_tracker.py [tracker_input.json] --output-dir output
```

该辅助工具只是**写出一份新的 CSV 支持文件包**(并在 `openpyxl` 已安装时附带 XLSX),不会原位修改已有跟踪器;生成后仍要把面向读者的内容整理成 `visual-page brief` 并调用 `visual-page` 做 GUI 交付。XLSX / CSV / JSON 默认不作为面向用户的主交付物——除非用户明确要求。

## HTML 交付：无损调用 visual-page

默认必须把跟踪器内容整理成 `visual-page brief` 并调用 `visual-page` skill 生成 GUI/HTML。XLSX / CSV 只作为显式要求或支持附件；HTML GUI 是默认面向读者主交付物。不要在本技能内自行实现 HTML 外壳、CSS、JS 或旧仪表板渲染器。

交给 `visual-page` 的 brief 必须包含：

- **页面模式**：跟踪器审查包通常用 `Data UI`；若是面向投资委员会的长篇更新说明，用 `Long-read / Report`。
- **视觉主题**：要求 `visual-page` 使用冰白纸背景、液态玻璃风格；不要使用 `visual-page` skill 里的默认配色方案。上涨、改善、确认、利好、增持等好事，以及所有强调色，统一用中国红 `#c0322f`；下跌、恶化、削弱、利空、减持/退出等坏事，统一用稳绿 `#15803d`。
- **输出路径意图**：若用户给路径则使用；否则要求 `visual-page` 在 `/tmp/visual-page/<marginal-tracker-topic>/index.html` 下创建独立目录，不覆盖旧页面。
- **首屏结构**：发行人 / 证券、公司论点状态、证券论点就绪度、仓位行动、市场数据截至时间、下一个催化剂、最大证据缺口。
- **组件映射（深度耦合 visual-page 组件，每个都带交互）**：
  - 论点状态与行动姿态 → **可展开 KV cards**：公司论点状态、证券论点就绪度、仓位行动各一张；hover / 点击就地展开变更理由与下一个验证点；改善 / 增持 / 确认着中国红 `#c0322f`，恶化 / 减持 / 退出着稳绿 `#15803d`。
  - **公司论点 vs 证券论点** → **side-by-side 对照 + toggle**：双栏并列，可切换「当前 / 前期」对照；当两者背离（业务改善但证券论点恶化）时用角标显式标注，不靠颜色单独承载。
  - 支柱跟踪器 → **可排序 + 状态 chips + 行内展开表**：表头点击按优先级 / 继承权重 / 状态排序（升降箭头指示）；状态用 chips（Confirmed / Watch / Impaired / Failed，强化态中国红、走弱态稳绿）；每行行内展开阈值定义、引用、模型影响与下一个验证点，避免横向拓宽支柱表。
  - KPI / 催化剂监控 → **table**，催化剂行 hover 升起液态玻璃说明卡；2-8 个支柱强弱对比用 **bench bars**（强化中国红、走弱稳绿）。
  - 决策日志 / 模型变更 → **仅追加的行内展开小表**：按日期倒序，行内展开依据 / 证据 / 状态变化；每条带「仅追加」与批准状态 badges（`Inherited threshold` / `Draft for PM confirmation` / `Approved monitoring rule`）。
  - 红队 / 未决问题 → **可展开对照矩阵**：每条反方观点行内展开「证据 / 什么会证伪 / 对建议的影响」。
- **交互规格（全部用内联 vanilla JS + CSS，禁止额外重依赖；继承 visual-page 的 BANNED 清单：无 AI 渐变 / 霓虹 / Inter）**：
  - 顶部 **sticky 锚点导航**：论点状态 / 支柱 / KPI 催化剂 / 模型估值 / 决策日志 / 红队，当前区块高亮中国红，点击平滑滚动。
  - **首屏决策带** 固定可见：发行人 / 证券、公司论点状态、证券论点就绪度、仓位行动、市场数据截至时间、下一个催化剂、最大证据缺口。
  - 所有可点击元素必须有 hover 态、`:focus-visible` 键盘可达、`cursor:pointer`；排序 / 筛选 / 展开 / toggle 一律 ≤200ms 过渡。
  - 移动端（<768px）：支柱表与对照栏转单列卡片，禁止横向滚动；chips 与 badges 自动换行；side-by-side 对照在窄屏堆叠。
  - 交互服务于「可被证伪、仅追加」的论点表达，不得制造数据噱头；除非评分方法继承或用户要求，否则不出支柱评分图。
- **图表规则**：2-8 个支柱强弱对比用 CSS bench bars；只有超过 8 个日期的 KPI 或股价序列才引入 Chart.js（`font.family='Outfit'`、改善序列中国红、恶化序列稳绿、`borderRadius:6`）；事件链 4 节点以上用可点击 Mermaid 或 step timeline，2-3 节点用 hover 增强 flow-node。不要为少量数据点引入重库。**用到 `<div class="mermaid">` 时，务必提醒 `visual-page` 在 `<head>` 加载 `mermaid.min.js`（CDN）并调用 `mermaid.initialize`，否则图不渲染。**
- **必须保留的业务语义**：仅追加、来源 / 截至日期、行动阈值来源、批准状态、证据质量、公司论点 vs 证券论点要可见地区分（用 chips / badges / 角标，不要靠红绿单独承载，避免与涨跌语义混淆）。不要展示人员分配、派工表或角色分工。
- **交付要求**：要求 `visual-page` 输出一个完整 GUI/HTML 文件，检查本地打开、响应式、无断链、每个交互元素都有 hover / focus 态，再用 `<media />` 交付。

## 相邻路由

如果主要诉求是:来源层级、财务数据标准化、模型勾稽 / 更新、情景敏感性、业绩前瞻 / 深度、新投资推介、对冲 / 仓位、事件 / 信用 / 宏观分析、备忘录 / 演示文稿质检——优先调用或推荐相邻的公开股票研究技能,不要重复造轮子。

## 何时调用支持

在用新证据改变支柱状态前,先做完来源分层与事实 / 假设标注。涉及杂乱 KPI、市场数据或模型输出的更新,先在副本里做标准化并保留原值。若环境里另有模型更新、模型审计或文档质检技能,可调用;不存在时不得阻塞跟踪器更新,把对应限制列为待验证事项。

## 语言标准

写作向顶尖 PM / 研究 MD 看齐:简洁、以证据权重为本、以行动为导向。当业务论点改善但证券论点因预期重估而恶化时,要直接讲出来;当表面业绩亮眼但证据质量或现金转化较差时,也要直接讲出来。

## 公开股票 PM 判断层

任何实质性更新,最终定稿前加载 `references/pm-judgment-heuristics.md`。受众模式:`long_only_pm` / `long_short_hf` / `sell_side_research` / `etf_index_diligence` / `public_equity_diligence`。

**投资组合监控模式是一等公民**。每次更新都要为标的归类:`add` / `press` / `hold` / `trim` / `exit` / `hedge` / `wait for proof` / `re-underwrite`。

PM 判断必备:

- 区分公司论点状态、证券论点就绪度、股票行动、组合角色。
- 明确运行模式:决策权限、审查节奏、催化剂后更新 SLA、升级触发条件、下一审查关口、主动权重、组合角色、状态、行动阈值、仅追加决策日志。
- 在相关时纳入:基准权重、主动权重、行业 / 因子敞口、ETF 持有、被动资金流敏感性、指数纳入 / 剔除 / 再平衡风险、流动性、拥挤度、市场已计入状态。
- 强化市场框架的描述:一致预期 / 买方非正式预期 / 市场已计入什么 / 忽略什么 / PM 优势在哪。
- 维护尽调阶梯:公告文件、电话会文字稿、KPI 历史、竞争对手核查、用户提供的客户 / 渠道核查、管理层可信度、会计质量、持仓 / 资金流框架、卖方一致预期、差异化争议。
