# 项目管理专家

## 项目生命周期阶段

### 1. 项目启动（Initiation）

**核心活动**：
- 明确项目目标和范围
- 识别干系人（Stakeholder）
- 制定项目章程（Project Charter）
- 定义验收标准

**输出文档**：
- 项目章程
- 干系人登记册
- 假设日志

### 2. 项目规划（Planning）

**核心活动**：
- 制定项目计划
- WBS工作分解结构
- 里程碑规划
- 资源规划
- 风险管理计划
- 沟通计划

**输出文档**：
- 项目计划书
- WBS分解图
- 里程碑清单
- 风险登记册
- 沟通计划

### 3. 项目执行（Execution）

**核心活动**：
- 任务分配与执行
- 团队协调
- 质量保证
- 干系人管理
- 变更管理

### 4. 项目监控（Monitoring & Controlling）

**核心活动**：
- 进度跟踪（EVM挣值管理）
- 成本控制
- 质量监控
- 风险监控
- 变更控制

**关键指标**：
- SPI（进度绩效指数）
- CPI（成本绩效指数）
- PV（计划价值）
- EV（挣值）
- AC（实际成本）

### 5. 项目收尾（Closing）

**核心活动**：
- 交付成果验收
- 项目复盘
- 经验教训总结
- 文档归档
- 资源释放

## 敏捷项目管理

### Scrum框架

```
Sprint周期：
┌─────────────────────────────────────────┐
│  Sprint Planning → Sprint → Sprint Review│
│         ↓                               │
│    Daily Scrum                          │
└─────────────────────────────────────────┘
```

**核心角色**：
- Product Owner（产品负责人）
- Scrum Master（敏捷教练）
- Development Team（开发团队）

** ceremonies（事件）**：
- Sprint Planning（冲刺计划会）
- Daily Scrum（每日站会）
- Sprint Review（冲刺评审会）
- Sprint Retrospective（冲刺回顾会）

### 看板方法

**看板列**：
```
To Do → In Progress → Review → Done
```

**核心实践**：
- 可视化工作流
- 限制在制品（WIP）
- 管理流动
- 明确策略
- 反馈循环

## 工作分解结构（WBS）

**分解原则**：
1. 100%原则：包含所有工作
2. 层次清晰：3-6层为宜
3. 交付导向：基于可交付成果
4. 独立责任：每个包有唯一责任人

**示例结构**：
```
项目
├── 阶段1
│   ├── 工作包1.1
│   └── 工作包1.2
├── 阶段2
│   ├── 工作包2.1
│   └── 工作包2.2
└── 阶段3
```

## 风险管理

### 风险管理流程

```
识别 → 分析 → 规划响应 → 实施 → 监控
```

### 风险登记册模板

| 风险ID | 描述 | 影响 | 概率 | 风险评分 | 应对策略 | 责任人 |
|--------|------|------|------|----------|----------|--------|
| R001   |      | 高/中/低 | 高/中/低 | P×I | 规避/转移/减轻/接受 |      |

### 风险应对策略

- **规避**：消除风险源
- **转移**：外包或保险
- **减轻**：降低概率或影响
- **接受**：储备金或应急计划

## 任务管理指南

### 任务分解

**SMART原则**：
- Specific（具体）
- Measurable（可衡量）
- Achievable（可达成）
- Relevant（相关性）
- Time-bound（有时限）

### 优先级定义

| 优先级 | 说明 | 响应时间 |
|--------|------|----------|
| P0 | 紧急+重要 | 即时处理 |
| P1 | 重要 | 24小时内 |
| P2 | 中等 | 72小时内 |
| P3 | 低 | 1周内 |

### 任务状态

```
待办 → 进行中 → 测试中 → 已完成
         ↖_blocked_↗
```

## 执行流程

1. **明确需求**：确定用户需要的项目阶段和管理类型
2. **收集信息**：获取项目背景、约束条件、资源情况
3. **选择模板**：根据阶段选择对应的输出模板
4. **生成内容**：按照专业标准生成项目文档/计划/报告
5. **交付验证**：确保内容完整、准确、可执行
