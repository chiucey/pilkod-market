# 需求文档撰写技能

## 核心能力

根据用户提供的想法、需求描述或对话内容，生成结构完整、专业规范的**需求文档**。

## 支持的文档类型

| 类型 | 适用场景 | 核心章节 |
|------|----------|----------|
| **PRD** (产品需求文档) | 新产品/功能规划 | 概述、用户故事、功能需求、非功能需求、UI/UX 概述、风险评估 |
| **SRS** (软件需求规格) | 正式软件开发 | 引言、总体描述、功能需求、外部接口需求、性能需求、设计约束 |
| **功能规格说明书** | 具体功能开发 | 功能描述、用例图/流程、输入输出、边界条件、异常处理 |
| **技术方案** | 技术实现规划 | 背景、目标、技术选型、系统设计、接口设计、部署方案 |

## 输出格式

所有文档均包含以下**标准结构**：

### 需求编码规则

**格式**：`REQ-[YYYYMMDD]-[序号]`

- `YYYYMMDD`：需求提出日期（8位数字）
- `序号`：当日需求编号，从001开始（例如：REQ-20260508-001）

**示例**：
- 第一个需求：`REQ-20260508-001`
- 第二个需求：`REQ-20260508-002`
- 跨日连续编号：`REQ-20260509-001`

### 单条需求核心结构

每条需求必须包含以下核心内容：

```markdown
### REQ-[日期]-[编号] [需求标题]

**需求背景**
[说明提出此需求的原因、业务场景、解决的问题]

**功能描述**

**[新增表单字段详情]**（如涉及表单）
| 字段名称 | 字段类型 | 长度限制 | 必填 | 校验规则 | 默认值 |
|----------|----------|----------|------|----------|--------|
| 字段1    | varchar  | 50       | 是   | 非空、唯一性校验 | - |
| 字段2    | int      | -        | 否   | 范围校验(1-100) | 0 |

**业务规则与校验关系**
- [详细列出字段间的关联校验逻辑]
- [异常场景处理]

**页面原型/交互说明**
[描述页面布局、用户操作流程、交互细节]
[可附加Mermaid流程图或ASCII示意图]

**验收标准**
- [ ] [可验证的验收条件1]
- [ ] [可验证的验收条件2]

**优先级**
- `[P0]` 紧急重要（必须本次上线）
- `[P1]` 重要（计划本次上线）
- `[P2]` 优化（可排期后续迭代）

**依赖关系**
- 前置需求：REQ-XXX
- 关联需求：REQ-XXX
```

## 工作流程

### 步骤1：信息收集

向用户确认以下信息（如未提供）：

1. **文档类型**：PRD / SRS / 功能规格 / 技术方案 / 其他
2. **目标用户**：谁会使用/阅读此文档
3. **核心需求**：要解决什么问题
4. **优先级**：哪些功能是高优先级

### 步骤2：结构化生成

根据文档类型选择对应的模板结构，填充内容：

- 保持语言简洁、明确
- 使用"应/必须/可以"等RFC 2119关键词表达需求级别
- 功能点使用 `[P0/P1/P2]` 标注优先级

### 步骤3：用户确认

生成后询问：
- 是否需要补充特定章节
- 是否有需要调整的内容
- 是否需要导出特定格式

## 示例

**输入**："我想做一个在线投票系统，用户可以创建投票、分享链接、查看实时结果"

**输出**：生成完整需求文档，采用标准编码规则：

```markdown
# 在线投票系统需求文档

## 1. 文档信息
- 版本号：v1.0.0
- 作者：产品经理
- 创建日期：2026-05-08
- 状态：草稿

## 4. 需求列表

### REQ-20260508-001 创建投票功能

**需求背景**
用户需要能够创建投票活动，设定投票主题、选项和截止时间。

**功能描述**

**[新增表单字段详情]**
| 字段名称 | 字段类型 | 长度限制 | 必填 | 校验规则 | 默认值 |
|----------|----------|----------|------|----------|--------|
| 投票标题 | varchar  | 100      | 是   | 非空、去除首尾空格 | - |
| 投票选项 | text     | -        | 是   | 至少2个选项，最多10个 | - |
| 截止时间 | datetime | -       | 否   | 必须晚于当前时间 | 7天后 |

**业务规则与校验关系**
- 投票标题不能与现有投票重复
- 截止时间必须晚于当前时间
- 每个选项内容不能为空且长度≤200字符

**页面原型/交互说明**
```
┌─────────────────────────────────┐
│  创建投票                        │
├─────────────────────────────────┤
│  投票标题：[________________]   │
│                                 │
│  选项：                         │
│  1. [________________]  [+删除] │
│  2. [________________]  [+删除] │
│              [+ 添加选项]        │
│                                 │
│  截止时间：[____年__月__日__时] │
│                                 │
│  [取消]        [创建投票]        │
└─────────────────────────────────┘
```

**验收标准**
- [ ] 用户可输入投票标题并通过校验
- [ ] 用户可添加/删除投票选项
- [ ] 系统正确校验截止时间晚于当前时间
- [ ] 创建成功后跳转至投票详情页

**优先级**
`[P0]`

**依赖关系**
无
```

## 最佳实践

1. **MUST** 为每条需求分配唯一编码 `REQ-[日期]-[序号]`
2. **MUST** 涉及表单时详细列出字段信息（类型、校验、默认值）
3. **SHOULD** 为每条需求提供可验证的验收标准
4. **SHOULD** 使用页面原型或流程图辅助说明
5. **SHOULD** 明确标注需求间的依赖关系
