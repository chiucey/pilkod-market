# 4S Framework - 四维完善框架

## Overview

4S 框架是一套系统化的 Skill 完善方法论，通过 Structure（结构）、Strategy（策略）、System（系统）、Ship（交付）四个维度，全面提升 Skill 的质量和可用性。

---

## 1. Structure - 结构

### 1.1 YAML 头部检查

| 字段 | 检查要点 | 优化标准 |
|------|----------|----------|
| `name` | 简洁性、唯一性、命名规范 | 小写字母 + 连字符分隔，不超过 64 字符 |
| `description` | 功能描述清晰度、使用场景、触发关键词 | 150 字以内，包含 "Use when..." 触发短语 |
| `AIGC` | 数字签名字段完整性 | 包含 ContentProducer、Label、ProduceID 等 |

### 1.2 Markdown 正文结构

标准章节顺序：

```
# Skill Title                    ← H1: 技能名称
## Overview                      ← 一句话使命宣言
## Welcome                       ← 首次交互欢迎语（详细模式）
## Workflow                      ← 核心工作流程
   ├── Step 1: ...
   ├── Step 2: ...
   └── Step 3: ...
## 核心方法论                    ← 可复用框架/技术
## 系统机制                      ← 评估/监控/反馈/安全
## 输出格式                      ← 交付物规范
## 重要提醒                      ← 边界条件和注意事项
## 目录结构                      ← 文件组织说明
## 常见问题                      ← FAQ 和解决方案
## 最佳实践                      ← 优化建议
```

### 1.3 结构诊断清单

- [ ] 是否包含所有必需章节？
- [ ] 章节顺序是否符合逻辑？
- [ ] 标题层级是否正确（H1 → H2 → H3）？
- [ ] 是否有冗余或缺失的内容模块？
- [ ] 每个章节是否有实质内容？
- [ ] 代码块是否有语言标识？

## 2. Strategy - 策略

### 2.1 方法论设计原则

| 原则 | 说明 | 验证方法 |
|------|------|----------|
| **可复用性** | 方法能在类似场景中复用 | 检查通用性指标 |
| **可操作性** | 步骤具体、可直接执行 | 验证步骤完整性 |
| **可验证性** | 结果有明确评估标准 | 检查验收条件 |

### 2.2 策略优化维度

#### 2.2.1 角色设定

**检查要点：**
- AI 身份是否清晰定位？
- 专业度是否足够支撑任务？
- 语气风格是否一致？

**优化方向：**
- 添加角色定位语句
- 明确专业背景和要求
- 统一语言风格

#### 2.2.2 任务拆解

**检查要点：**
- 复杂任务是否分步骤？
- 步骤是否有明确编号？
- 每个步骤是否有输入输出？

**优化方向：**
- 使用流程图可视化
- 编号列表结构化
- 添加步骤间的依赖说明

#### 2.2.3 决策逻辑

**检查要点：**
- 分支判断条件是否明确？
- 不同情况是否有对应处理？
- 边界条件是否覆盖？

**优化方向：**
- 添加条件判断表格
- 明确路径选择规则
- 补充异常处理流程

#### 2.2.4 技术框架引入

推荐框架：

| 框架 | 适用场景 | 核心价值 |
|------|----------|----------|
| **4D** | 描述类、分析类任务 | 维度思考 |
| **5W1H** | 信息收集、问题分析 | 全方位分析 |
| **PDCA** | 迭代优化任务 | 持续改进 |
| **STAR** | 案例分析、经验总结 | 情境还原 |
| **CRISPDM** | 数据科学任务 | 标准化流程 |

## 3. System - 系统

### 3.1 评估机制

#### 多角色评估体系

| 角色 | 职责 | 评估维度 |
|------|------|----------|
| 📋 **规范审查员** | 检查格式合规 | YAML 规范、Markdown 结构 |
| 🎯 **精准度审查员** | 检查意图匹配 | 原意传达、核心功能 |
| 🔍 **完整性检查员** | 确认信息完备 | 必需章节、示例覆盖 |
| ⚡ **效率优化师** | 评估简洁性 | 无冗余、逻辑清晰 |
| 🛡️ **风险评估师** | 识别潜在问题 | 歧义、矛盾、安全 |

#### 质量标准

**格式标准：**
- YAML frontmatter 完整且格式正确
- Markdown 标题层级正确
- 代码块有语言标识
- 表格格式规范

**内容标准：**
- 指令清晰、无歧义
- 示例具体、可执行
- 边界条件明确
- 错误处理完整

#### 自检清单

```
基础检查：
[ ] YAML frontmatter 在第一行
[ ] 包含 name 和 description 字段
[ ] description 包含触发短语
[ ] _meta.json 存在且有效

内容检查：
[ ] 所有章节有实质内容
[ ] 示例完整可执行
[ ] 边界条件已覆盖
[ ] 无占位符残留

逻辑检查：
[ ] 流程无矛盾
[ ] 条件判断清晰
[ ] 错误处理完善
[ ] 输出格式规范
```

### 3.2 监控机制

#### 关键节点检查点

| 阶段 | 检查点 | 验证内容 |
|------|--------|----------|
| 接收输入 | 输入有效性 | 技能内容完整性 |
| 分析阶段 | 结构诊断 | 章节完整性 |
| 优化阶段 | 质量门槛 | 逐项验证 |
| 输出阶段 | 最终检查 | 格式+内容 |

#### 异常处理流程

```
检测到问题 → 分类问题类型 → 应用修复规则 → 验证修复结果
     ↓              ↓              ↓              ↓
  记录日志    P0/P1/P2分级    确定性修复    通过则继续
                                                  ↓
                                            失败则回滚
```

#### 用户反馈收集

- 任务完成后询问满意度
- 收集改进建议
- 记录常见问题

### 3.3 安全机制

#### 敏感信息处理

| 类型 | 处理方式 | 示例 |
|------|----------|------|
| API 密钥 | 环境变量引用 | `${API_KEY}` |
| 密码凭证 | 明确提示用户配置 | `配置指引` |
| 个人信息 | 脱敏或移除 | `***` |
| 文件路径 | 使用变量或示例 | `/path/to/...` |

#### 边界条件说明

```
输入边界：
- 空输入处理
- 超长内容截断
- 非法格式提示

输出边界：
- 内容长度限制
- 格式一致性保证
- 错误状态码定义

环境边界：
- 必需工具声明
- 版本兼容性说明
- 权限要求说明
```

#### 风险提示和免责声明

- 明确操作不可逆性
- 提示潜在风险
- 说明免责条款

### 3.4 反馈机制

#### 用户澄清问题设计

```
标准澄清问题集：
1. "请提供 Skill 的文件路径或完整内容"
2. "这个 Skill 的主要使用场景是什么？"
3. "目标用户群体是谁？"
4. "是否有特定的平台限制？"
5. "期望的输出格式是什么？"
```

#### 迭代优化入口

```
初次优化 → 评估反馈 → 二次优化 → 最终交付
    ↓           ↓           ↓
  基础版本   问题识别    针对性修复
```

#### 模式切换选项

| 模式 | 适用场景 | 执行深度 |
|------|----------|----------|
| **BASIC** | 简单任务、快速迭代 | 核心优化 |
| **DETAIL** | 复杂任务、企业级 | 全面分析 |

## 4. Ship - 交付

### 4.1 格式规范

#### Kimi Agent Skill 标准格式

```yaml
---
name: skill-name
description: 功能描述。Use when 用户要求...
---

# Skill Title

## Overview
一句话使命宣言

## Workflow
详细流程...

## 输出格式
交付物规范...
```

#### YAML 头部规范

```yaml
---
# 必填字段
name: skill-name                    # 小写+连字符
description: 功能描述...           # 触发短语

# 可选 AIGC 元数据
AIGC:
    ContentProducer: Minimax Agent AI
    Label: AIGC
    ProduceID: xxx
---

# 正文内容
```

#### Markdown 排版规范

- 标题层级：H1 → H2 → H3，最多 4 层
- 列表：使用 - 或 1.，保持一致
- 表格：添加表头，对齐清晰
- 代码块：标注语言
- 链接：相对路径优先

### 4.2 内容完整性

#### 必需章节检查

| 章节 | 必要性 | 最小字数 |
|------|--------|----------|
| Overview | 必填 | 20 字 |
| Workflow | 必填 | 100 字 |
| 输出格式 | 必填 | 50 字 |
| 目录结构 | 推荐 | 30 字 |
| 常见问题 | 推荐 | 100 字 |

#### 示例丰富度

| 类型 | 数量建议 | 覆盖场景 |
|------|----------|----------|
| 代码示例 | 2-3 个 | 核心功能 |
| 表格示例 | 1-2 个 | 配置项说明 |
| 流程示例 | 1 个 | 典型流程 |

### 4.3 可用性验证

#### 首次交互测试

```
验证点：
[ ] 欢迎语正常显示
[ ] 角色定位清晰
[ ] 指令可被理解
[ ] 示例可执行
```

#### 逻辑自洽检查

```
验证点：
[ ] 流程图与文字描述一致
[ ] 表格数据与文字说明匹配
[ ] 边界条件覆盖完整
[ ] 错误处理逻辑正确
```

#### 输出格式验证

```
验证点：
[ ] 输出可直接复制使用
[ ] 代码块可运行
[ ] 格式保持一致
[ ] 无遗漏章节
```

## 运行模式

### DETAIL MODE - 详细模式

**适用场景：**
- 复杂 Skill 设计
- 多模块系统
- 企业级应用
- 首次优化未知 Skill

**执行流程：**

```
1. 深入分析
   └── 全面读取 Skill 内容
   └── 结构诊断
   └── 问题识别

2. 澄清提问
   └── 3-5 个针对性问题
   └── 等待用户回复

3. 全面优化
   └── 4S 框架全面执行
   └── 多角色评估

4. 输出报告
   └── 优化说明
   └── 改进对比
   └── 质量验证结果
```

### BASIC MODE - 基础模式

**适用场景：**
- 简单 Skill 优化
- 快速迭代
- 个人使用
- 已知 Skill 改进

**执行流程：**

```
1. 快速分析
   └── 核心问题识别
   └── 快速诊断

2. 应用优化
   └── 结构补全
   └── 策略强化
   └── 系统完善

3. 直接输出
   └── 优化后 Skill
   └── 简要说明
```

## Skill 类型特化指南

### 工具型 Skill

**特征：** 功能明确、步骤精确、输出规范

**优化重点：**
- 输入输出格式标准化
- 错误处理完善
- 边界条件明确

**关键要素：**
- 命令参数说明
- 返回值定义
- 错误码对照表

### 知识型 Skill

**特征：** 体系完整、逻辑严密、易于检索

**优化重点：**
- 知识架构清晰
- 分类体系合理
- 关联引用准确

**关键要素：**
- 概念定义表
- 分类层次图
- 引用索引

### 创意型 Skill

**特征：** 激发灵感、提供框架、保留自由度

**优化重点：**
- 创意触发点设计
- 约束条件明确
- 多样性引导

**关键要素：**
- 灵感来源库
- 约束边界说明
- 创意扩展提示

### 分析型 Skill

**特征：** 方法论严谨、推理链完整、结论可靠

**优化重点：**
- 分析框架完善
- 数据来源标注
- 验证机制健全

**关键要素：**
- 分析步骤清单
- 数据质量标准
- 结论可靠性评估

### 对话型 Skill

**特征：** 人设一致、情感连贯、上下文管理

**优化重点：**
- 角色背景丰富
- 语气风格统一
- 记忆机制设计

**关键要素：**
- 人物设定卡
- 对话风格指南
- 上下文边界

### 代码型 Skill

**特征：** 语法准确、示例丰富、环境适配

**优化重点：**
- 代码示例可运行
- 依赖说明完整
- 环境配置清晰

**关键要素：**
- 环境要求
- 依赖列表
- 运行指南
