# 多角色评估机制

## Overview

多角色评估是一套系统化的内部质量审查流程，通过不同专业视角的审视，确保 Skill 在规范性、完整性、可执行性和鲁棒性四个维度达到高标准。

---

## 评估角色体系

### 角色矩阵

| 角色 | 核心职责 | 评估重点 | 输出物 |
|------|----------|----------|--------|
| 📋 **规范审查员** | 格式合规性 | YAML/ Markdown 标准 | 格式问题清单 |
| 🎯 **精准度审查员** | 意图匹配度 | 原意传达准确性 | 偏差修正建议 |
| 🔍 **完整性检查员** | 信息完备性 | 章节/要素覆盖 | 缺失清单 |
| ⚡ **效率优化师** | 简洁高效性 | 冗余/逻辑优化 | 精简建议 |
| 🛡️ **风险评估师** | 安全性审查 | 风险/歧义识别 | 风险报告 |

---

## 评估标准详解

### 1. 📋 规范审查员

#### 评估维度

**YAML 格式检查：**
- [ ] frontmatter 位于文件第一行
- [ ] name 字段使用小写+连字符
- [ ] description 字段存在且非空
- [ ] AIGC 元数据格式正确（如果存在）

**Markdown 结构检查：**
- [ ] 标题层级正确（H1 → H2 → H3）
- [ ] 标题唯一性（无重复标题）
- [ ] 代码块标注语言
- [ ] 表格格式规范（有表头对齐）
- [ ] 列表格式一致

**文件结构检查：**
- [ ] _meta.json 存在
- [ ] _meta.json 包含 id 和 version
- [ ] 目录结构符合规范

#### 评分标准

| 等级 | 条件 | 行动 |
|------|------|------|
| ✅ 通过 | 所有检查项通过 | 进入下一评估 |
| ⚠️ 警告 | 1-2 个非关键问题 | 记录但不阻塞 |
| ❌ 失败 | 关键问题存在 | 必须修复 |

---

### 2. 🎯 精准度审查员

#### 评估维度

**原意传达检查：**
- [ ] Skill 名称准确反映功能
- [ ] description 描述与实际功能匹配
- [ ] 触发短语能正确路由任务
- [ ] 职责范围定义清晰

**核心功能检查：**
- [ ] 主要功能完整实现
- [ ] 次要功能无遗漏
- [ ] 无新增非预期功能
- [ ] 功能边界明确

**用户体验检查：**
- [ ] 交互流程符合预期
- [ ] 输出格式满足需求
- [ ] 示例具有代表性
- [ ] 错误提示有帮助性

#### 评分标准

| 等级 | 条件 | 行动 |
|------|------|------|
| ✅ 通过 | 核心功能 100% 覆盖 | 进入下一评估 |
| ⚠️ 警告 | 功能覆盖率 80-99% | 补充缺失功能 |
| ❌ 失败 | 功能覆盖率 <80% | 重大重构 |

---

### 3. 🔍 完整性检查员

#### 评估维度

**章节完整性：**

| 章节 | 必要性 | 最小内容要求 |
|------|--------|--------------|
| Overview | 必填 | 20 字以上 |
| Workflow | 必填 | 100 字以上，流程完整 |
| 输出格式 | 必填 | 50 字以上，格式明确 |
| 目录结构 | 推荐 | 30 字以上 |
| 常见问题 | 推荐 | 100 字以上 |
| 最佳实践 | 可选 | 50 字以上 |

**要素完整性：**

- [ ] 触发条件明确
- [ ] 执行步骤完整
- [ ] 输入输出定义
- [ ] 边界条件说明
- [ ] 错误处理覆盖
- [ ] 示例完整可执行

**类型特化要素：**

| 类型 | 必需要素 |
|------|----------|
| 工具型 | 参数说明、返回值、错误码 |
| 知识型 | 概念定义、分类体系、引用索引 |
| 创意型 | 灵感触发、多样性引导、约束条件 |
| 分析型 | 分析框架、数据来源、验证机制 |
| 对话型 | 角色设定、语气风格、记忆机制 |
| 代码型 | 环境要求、依赖说明、运行示例 |

#### 评分标准

| 等级 | 条件 | 行动 |
|------|------|------|
| ✅ 通过 | 必填章节完整，必需要素覆盖 | 进入下一评估 |
| ⚠️ 警告 | 缺少推荐章节 | 补充推荐内容 |
| ❌ 失败 | 缺少必填章节或核心要素 | 必须补充 |

#### 评估维度

- [ ] 无重复章节
- [ ] 表格简洁明了
- [ ] 列表项精简

**逻辑效率：**
- [ ] 流程无冗余步骤
- [ ] 判断条件简洁
- [ ] 路径选择清晰
- [ ] 依赖关系明确

**结构效率：**
- [ ] 章节数量合理（建议 6-12 章）
- [ ] 层级深度合理（建议 3 层以内）
- [ ] 内容分布均匀
- [ ] 链接跳转合理

#### 优化建议模板


#### 评分标准

| 等级 | 条件 | 行动 |
|------|------|------|
| ✅ 通过 | 无明显冗余 | 进入下一评估 |
| ⚠️ 警告 | 存在可优化点 | 建议优化 |
| ❌ 失败 | 严重冗余影响使用 | 必须精简 |

---

### 5. 🛡️ 风险评估师

#### 评估维度

**歧义风险：**
- [ ] 指令无歧义理解
- [ ] 条件判断唯一
- [ ] 术语使用一致
- [ ] 示例无误导性

**矛盾风险：**
- [ ] 章节间无矛盾
- [ ] 前后描述一致
- [ ] 表格与文字匹配
- [ ] 流程逻辑自洽

**安全风险：**
- [ ] 无敏感信息泄露
- [ ] 凭证使用规范
- [ ] 路径引用安全
- [ ] 操作可逆性明确

**稳定性风险：**
- [ ] 边界条件覆盖
- [ ] 异常处理完善
- [ ] 超时/死循环防护
- [ ] 并发场景考虑

#### 风险评级

| 等级 | 风险类型 | 行动 |
|------|----------|------|
| 🔴 高危 | 安全风险、致命歧义 | 必须修复 |
| 🟡 中危 | 逻辑矛盾、边界遗漏 | 建议修复 |
| 🟢 低危 | 优化空间、风格差异 | 可选修复 |

## 综合评估流程

### Step 1：并行评估

各角色同时进行独立评估：

```
┌─────────────────────────────────────────────────┐
│                  并行评估阶段                    │
├─────────┬─────────┬─────────┬─────────┬───────────┤
│ 规范审查 │ 精准度  │ 完整性  │ 效率    │ 风险评估  │
│  员     │ 审查员  │ 检查员  │ 优化师  │  评估师   │
└─────────┴─────────┴─────────┴─────────┴───────────┘
         ↓           ↓         ↓          ↓
```

### Step 2：问题汇总

汇总所有评估结果：

```markdown
## 评估汇总

### 规范审查员
- ✅ 通过 | ⚠️ 警告 (N项) | ❌ 失败 (N项)

### 精准度审查员
- ✅ 通过 | ⚠️ 警告 (N项) | ❌ 失败 (N项)

### 完整性检查员
- ✅ 通过 | ⚠️ 警告 (N项) | ❌ 失败 (N项)

### 效率优化师
- ✅ 通过 | ⚠️ 警告 (N项) | ❌ 失败 (N项)

### 风险评估师
- 🔴 高危 (N项) | 🟡 中危 (N项) | 🟢 低危 (N项)
```

### Step 3：优先级排序

根据评估结果确定修复优先级：

| 优先级 | 来源 | 处理方式 |
|--------|------|----------|
| **P0** | 规范失败 + 高危风险 | 立即修复 |
| **P1** | 精准度失败 + 中危风险 | 优先修复 |
| **P2** | 完整性警告 + 低危风险 | 建议修复 |
| **P3** | 效率优化建议 | 可选实施 |

### Step 4：修复执行

按优先级执行修复：

```
P0 修复 ──→ 重新评估 ──→ 通过 ──→ P1 修复
    │                           │
    └── 失败 ──→ 继续修复 ──────→│
```

### Step 5：最终确认

所有 P0/P1 问题解决后进行最终确认：

```
[ ] 所有 P0 问题已修复
[ ] 所有 P1 问题已修复
[ ] P2 问题已评估（修复或接受）
[ ] P3 建议已记录
[ ] 整体质量达到可接受标准
```

## 评估工具集成

### 自动检查脚本

建议创建 `scripts/quick_validate.py`：

```python
#!/usr/bin/env python3
"""Skill 快速验证脚本"""

import re
import sys
from pathlib import Path

def check_frontmatter(content: str) -> dict:
    """检查 YAML frontmatter"""
    issues = []

    if not content.startswith('---'):
        issues.append("Frontmatter must start at line 1")

    # 检查必填字段
    if not re.search(r'^name:\s*\S+', content, re.MULTILINE):
        issues.append("Missing 'name' field")

    if not re.search(r'^description:\s*.+', content, re.MULTILINE):
        issues.append("Missing 'description' field")

    return {"passed": len(issues) == 0, "issues": issues}

def check_structure(content: str) -> dict:
    """检查 Markdown 结构"""
    issues = []

    # 检查标题层级
    headers = re.findall(r'^(#{1,4})\s+(.+)', content, re.MULTILINE)
    # 层级检查逻辑...

    return {"passed": len(issues) == 0, "issues": issues}

def main():
    skill_path = Path(sys.argv[1])
    content = skill_path.read_text()

    results = {
        "frontmatter": check_frontmatter(content),
        "structure": check_structure(content),
    }

    # 输出结果
    for check, result in results.items():
        status = "✅" if result["passed"] else "❌"
        print(f"{status} {check}")
        for issue in result["issues"]:
            print(f"   - {issue}")

    return 0 if all(r["passed"] for r in results.values()) else 1

if __name__ == "__main__":
    sys.exit(main())
```

## 持续改进机制

### 评估反馈收集

每次评估后记录：
- 发现的问题类型分布
- 修复耗时统计
- 常见模式识别
- 优化建议积累

### 评估标准迭代

基于反馈持续优化：
- 补充遗漏的检查项
- 调整评分权重
- 更新最佳实践
- 完善文档指引
