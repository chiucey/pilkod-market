# 会议纪要生成器 (Meeting Minutes Generator)

## 输入

用户提供以下内容之一：
- 会议录音文件路径（.mp3/.m4a/.wav 等）
- 会议文字记录（原始文本）
- 会议要点（自由格式）

> AI 自动识别：会议类型、参会人员、关键决策、待办事项、风险项。

## 项目背景

使用本技能前，先读取 `references/project-context.md` 了解当前项目术语和团队成员映射，供姓名归一化和术语统一使用。

## 输出格式

用户可通过指令指定格式：

| 指令 | 格式 |
|------|------|
| `/纪要 标准` 或留空 | 标准会议纪要（完整表格） |
| `/纪要 简报` | 群聊简报（精简版，适合发群） |
| `/纪要 飞书` | 飞书云文档格式（左对齐，紧凑表格） |
| `/纪要 详细` | 包含讨论过程的完整版 |

未指定时默认输出**标准格式**。

## 格式1：标准会议纪要

```markdown
# [会议主题]会议纪要

## 会议基本信息
| 项目 | 内容 |
|------|------|
| 会议主题 | [提取的主题] |
| 会议时间 | [标准化后的日期/时间] |
| 参会人员 | [提取的参会人 + 角色标注] |
| 会议主持 | [提取的主持人] |

## 核心决议
1. [决议1]
2. [决议2]
3. [决议3]

## 待办事项
| 负责人 | 待办事项 | 截止时间 |
|--------|----------|----------|
| [姓名] | [任务描述] | [时间] |

## 下次会议
- [下次会议信息]

## 关键词
[关键词1、关键词2、关键词3]
```

## 处理原则

### 时间标准化
| 口语时间 | 转换规则 |
|----------|----------|
| 今天 | 转换为实际日期 |
| 明天 | 转换为实际日期 |
| 下周 | 转换为实际日期范围 |
| 周三 | 转换为具体日期 |
| 待定 | 保留"待定" |

### 人员归一
- 统一姓名写法，以正式姓名为准
- 首次出现时标注角色（参考 project-context.md）
- 别名修正映射：
  - 咏哥 → 孟勇
  - 郭飞 → 国飞
  - 洪广 → 宏广
  - 张李阳 → 张李杨
  - 李阳 → 李杨
  - 金院 → 进院

### 术语统一
- OpenCloud → openclaw
- 使用 `references/project-context.md` 中的项目标准术语

### 信息完整
- 待办必须标注负责人，不明确写"待定"
- 待办必须标注截止时间，不明确写"待定"
- 识别风险项并用 ⚠️ 标注

### 简洁清晰
- 删除重复内容
- 合并相似事项
- 仅保留核心信息

## 智能识别规则

自动识别并填充：
- **会议类型**：晨会、周会、专项会议、复盘会等
- **参会人员**：从文本提取姓名，自动匹配角色
- **关键决策**：识别"决定"、"通过"、"同意"等表述
- **待办事项**：识别"负责"、"跟进"、"完成"等动作
- **风险项**：识别"担心"、"风险"、"问题"、"可能延误"等

## 质量检查

生成纪要后自检：

- [ ] 是否有遗漏的待办事项？
- [ ] 负责人是否明确？
- [ ] 截止时间是否清晰（截止时间不确定写"待定"）？
- [ ] 术语是否已统一为项目标准？
- [ ] 下次会议时间是否标注？

## 常见问题

**Q: 会议内容不完整怎么办？**
A: 提取可识别的信息，缺失部分标注"待确认"，并在纪要末尾列出无法确认的信息清单。

**Q: 同一个人有多个名字怎么办？**
A: 以正式姓名为主，别名在首次出现时括号标注（如"孟勇（咏哥）"）。

**Q: 待办没有明确截止时间怎么办？**
A: 标注"待定"，必要时主动询问用户。

**Q: 如何处理风险项？**
A: 在待办事项中用 ⚠️ 标注，并在末尾"风险说明"节单独列出。
