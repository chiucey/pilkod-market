# 软件测试与产品实验设计

> 适用于 A/B 测试、灰度发布、功能验证等

---

## A/B 测试设计

### 实验设计要素
```
□ 实验假设：清晰陈述
□ 随机化单元：用户 / 会话 / 页面
□ 分流比例：50/50 或不对称
□ 运行时间：基于功效分析
□ 主要指标（Primary）
□ 护栏指标（Guardrail）
```

### 指标选择原则
```
主要指标：
□ 直接衡量实验目标
□ 对业务价值敏感
□ 可在实验周期内观察到变化

护栏指标（必须保持稳定）：
□ 核心功能可用性
□ 关键业务流程转化
□ 用户体验指标
□ 系统性能指标
```

### 常见指标类型
```
业务指标：
| 指标 | 定义 | 监控理由 |
|------|------|---------|
| 转化率 | 完成目标用户/总用户 | 核心 KPI |
| 点击率 | 点击/曝光 | 用户参与度 |
| 留存率 | N日后仍活跃 | 长期价值 |
| ARPU | 平均收入/用户 | 变现能力 |

技术指标：
| 指标 | 定义 | 监控理由 |
|------|------|---------|
| 延迟 | 响应时间 | 性能 |
| 错误率 | 失败请求/总请求 | 稳定性 |
| 崩溃率 | 崩溃会话/总会话 | 质量 |
```

## 流量分配设计

### 分流策略
```
□ 用户级分流：同一用户始终看到同一版本
  - 优点：用户体验一致
  - 实现：基于 user_id 哈希

□ 会话级分流：同一会话内版本一致
  - 优点：简单
  - 缺点：同一用户不同会话体验不同

□ 页面级分流：不推荐
  - 缺点：用户体验混乱
```

### 分流质量检查
```
□ 基线流量相等（无偏差）
□ 用户特征分布一致（AA 测试）
□ 时间分布均匀
□ 无新奇效应干扰
```

### AA 测试
```
目的：验证分流随机性

方法：
1. 实验前运行 AA 测试
2. 检查各组指标无显著差异
3. 确认后开始 AB 实验

时间：通常 1-2 个周期
```

## 样本量计算

### 计算公式
```python
# 转化率比较
from statsmodels.stats.proportion import samplesize_proportions_2indep

effect_size = proportion_effectsize(0.12, 0.10)  # 10% vs 12%
n = samplesize_proportions_2indep(
    effect_size=effect_size,
    alpha=0.05,
    power=0.80
)
```

### 最小可检测效应 (MDE)
```
MDE 选择原则：
□ 业务有意义的变化（不只是统计显著）
□ 考虑实现成本与收益
□ 平衡检验力与运行时间

典型 MDE：
- 转化率：相对提升 5-10%
- 留存率：绝对提升 1-2%
- 延迟：增加 < 5ms
```

### 运行时间估算
```
每日流量 = 10000 用户
每组每日样本 = 5000
需要样本 = 10000 每组
运行天数 = 10000 / 5000 = 2 天

考虑周日波动：至少运行 7 天
考虑新奇效应：通常预热 3-5 天
```

## 统计检验设计

### 检验方法选择
```
□ 两比例比较：Z 检验 / 卡方检验
□ 均值比较：t 检验 / Mann-Whitney
□ 多变体比较：卡方检验 + 多重比较校正
□ 序贯检验：α 消耗函数（O'Brien-Fleming）
```

### 多重检验控制
```
问题：多个指标同时检验

方案：
1. 一个主要指标 + 几个护栏指标
2. 护栏指标用宽阈值（如 ±5%）
3. Bonferroni 校正（保守）
4. Benjamini-Hochberg FDR 控制

警告：避免 "p-hacking"
```

## 灰度发布策略

### 灰度阶段
```
阶段 1：内部用户（5-10%）
  → 快速发现问题

阶段 2：选中的外部用户（10-30%）
  → 验证真实用户体验

阶段 3：全量发布（100%）
  → 确认无负面效果

回滚条件：任一护栏指标恶化超过阈值
```

### 金丝雀发布
```
特点：逐步将流量从旧版本迁移到新版本

策略：
□ 线性增长：5% → 10% → 20% → 50% → 100%
□ 自适应：基于护栏指标自动调整
□ 特征开关：独立控制各功能
```

## 实验结果分析

### 分析报告模板
```
## 实验报告

### 实验信息
- 实验 ID：
- 运行时间：
- 样本量：对照组 N= / 实验组 N=

### 核心结果
| 指标 | 对照组 | 实验组 | 变化 | p-value | 显著性 |
|------|--------|--------|------|---------|--------|
| 转化率 | 10.2% | 10.8% | +5.9% | 0.023 | * |

### 护栏指标
| 指标 | 状态 | 说明 |
|------|------|------|
| 延迟 | ✓ | 无显著变化 |
| 错误率 | ✓ | 无显著变化 |
| 留存 | ✓ | 无显著变化 |

### 分段分析
| 维度 | 对照组 | 实验组 | 变化 |
|------|--------|--------|------|
| 新用户 | ... | ... | ... |
| 老用户 | ... | ... | ... |

### 结论
□ 实验成功，建议全量发布
□ 实验无显著效果，建议下线
□ 实验有风险，需进一步分析
□ 实验失败，建议回滚
```

### 常见陷阱
```
□ 新奇效应：用户因新鲜感改变行为
□ 首因效应：用户注意力在变化点
□ 外部干扰：促销活动等影响
□ 季节性：周末/节假日差异
□ 网络效应：用户间相互影响
```

## 实验治理

### 实验评审清单
```
发布前：
□ 实验假设明确
□ 样本量计算记录
□ 指标选择有据可查
□ 护栏指标定义
□ 回滚方案准备
□ 实验委员会评审（重大变化）

发布后：
□ 每日监控报告
□ 异常告警设置
□ 结果分析文档化
□ 决策记录归档
```

### 实验文化
```
□ 所有变更都应通过实验验证
□ 阴性结果同样有价值
□ 实验结果公开透明
□ 禁止 cherry-picking
□ 预注册关键实验
```
