# 平台中立输出规范

## 需求确认

- 用户明确给出格式、深度、受众或重点时，直接照做。
- 只有缺失的信息会显著改变分析结论时，才在普通对话中追问一个简短问题。
- 无法交互时按技能默认产物输出:调用 `visual-page` 生成 GUI/HTML 事件报告，并在交付说明里披露假设。
- 不依赖特定平台的表单、计划模式、专有 UI 或内部渲染工具；GUI/HTML 必须使用 `visual-page` skill 生成。

## 输出格式

- 轻量请求：直接给结构化 Markdown。
- 完整报告 / 表格型读者产物：优先整理为 `visual-page brief`，调用 `visual-page` 生成 GUI/HTML 页面，要能在普通浏览器里直接打开。
- XLSX / CSV：仅在用户明确要求、需要导入外部系统或作为审计支持附件时输出。
- 结构化数据：按需用 JSON，但 JSON 不得作为面向读者的默认主产物。

## 可移植性

- 用相对路径引用技能内部资源。
- 不要引用不存在的父插件、内部路由器或特定供应商的渲染器；GUI/HTML 交付一律调用 `visual-page`。
- 视觉约定：冰白纸背景、液态玻璃风格；不要使用 `visual-page` 默认配色方案；上涨、好事、强调色统一用中国红 `#c0322f`；下跌、坏事统一用稳绿 `#15803d`。
- 宿主平台不支持某种格式时回退到 Markdown，保持同样的分析结构与来源标注。
- 所有输出都要保留数据截至时间、来源、口径、假设与缺失项。
