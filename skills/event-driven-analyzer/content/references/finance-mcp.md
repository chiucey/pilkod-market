# MiniMax Finance Data MCP 使用规范

## 主体解析

1. 根据所在市场选择 `resolve_entity` 的 `entity_type`：
   - A股：`a_stock`
   - 港股：`hk_stock`
   - 美股：`us_stock`
   - 基金、债券、指数：`fund`、`bond`、`index`
   - A股行业与概念：`industry`、`sw_industry`、`concept`
   - 港股行业：`hk_industry`
2. 用公司名称、简称或证券代码作为关键词列出候选。
3. 通过交易所、证券代码、公司全称、行业描述确定正确的内部 `code`；不要凭印象猜。

## 数据调用

- 调用 `call_api(api_id=..., params=...)` 获取公司、财务、行情、估值、事件、股东、分红融资、基金、债券、指数和行业数据。
- 调用 `query_macro(keyword=...)` 检索宏观与产业指标，再依据返回的 `indicId` 与明细参数取时间序列。
- `call_api` 报业务枚举错误时，借助 `enum_candidates` 校准参数后再试。
- 大体量数据用 CSV；关键结论所需的小表用 Markdown 或 JSON。

## 口径与来源

- 把市场、交易代码、内部 `code`、数据截至时间、报告期、单位、币种、会计准则、复权口径都保留下来。
- 跨市场分析必须统一币种和期间，或者明确保留不可比差异。
- 最新价格、估值、事件、宏观数据都要带查询时间戳。
- MCP 没有返回的数据标记为缺失，禁止推测或编造。

来源优先级（从高到低）：

1. 监管机构、交易所与上市公司的正式披露。
2. MiniMax Finance Data MCP 的结构化数据。
3. 用户提供的模型、跟踪器、研究资料。
4. 其他可核验的公开来源。

结构化数据与正式披露冲突时，以正式披露为准，并把差异记录在案。
