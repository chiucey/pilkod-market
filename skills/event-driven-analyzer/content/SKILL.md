# 多市场事件驱动股票分析器

## 启动顺序

1. 先打开 `references/finance-mcp.md` 与 `references/market-rules.md`，再按已识别的事件类型选取对应 playbook。
2. 在调用任何数据接口之前确认所在市场，并以 `a_stock`、`hk_stock` 或 `us_stock` 之一锁定证券主体。
3. 通过 `call_api` 拉取事件、公告、复权行情、停复牌、股本、估值、行业等结构化数据。
4. 事件条款、时间和状态以交易所及上市公司公告为准；MCP 数据用于计算与交叉印证。
5. 时间线必须基于目标市场的交易日历来构建，并明示涨跌停、T+1、盘前盘后、停牌、流动性、融券等执行约束。

## 覆盖的事件范围

- A股：重大资产重组、要约收购、定向增发、配股、回购、解禁、监管、指数调整。
- 港股：并购、私有化、供股、配售、回购、控制权变更、停牌、上市规则相关事件。
- 美股：现金/换股并购、分拆、激进主义、监管与诉讼、回购、二次发行、指数事件。
- 跨市场：A/H 双重上市、ADR、双重主要上市、私有化回归、同一发行人多券种联动。
- 当事件条款主要写在公告原文里时，禁止只凭 MCP 的摘要字段下承销结论。

## 交付物前的需求确认

呈现载体优先级以 `references/output-guidelines.md` 为准。本工作流的默认产物是一份独立、可在浏览器中直接打开的 GUI/HTML 事件分析报告；除非用户明确要求"仅聊天"或"轻量回复"，否则不得退化为纯文本输出。GUI/HTML 产物必须通过 `visual-page` skill 完成，本技能只负责事件研究、计算、页面 brief 与证据边界。

在为一份新的、面向读者的核心交付物正式开始取数或分析之前，载入 `references/output-guidelines.md`；只针对真正会改变结论的格式、深度、受众或重点提问，其余按默认走。

## 工作目标

把上市股票的具体催化剂转化为一条路径依赖的承销链：

`event -> conditions -> timing -> scenarios -> payoffs -> probabilities -> expected return -> trade expression -> monitoring plan`

本技能负责并购、分拆、换股分拆、激进主义、监管/诉讼、要约收购、指数事件、供股、限售期解除、de-SPAC、存根股、认股权证、优先股，以及其他有明确日期的上市股票特殊情形。

边界说明：本技能覆盖上市股票端的事件路径、概率树、回报、期望值、时点、表达式与监控；信用工具、信用资质、债务重组、困境证券、回收率、信用利差、收益率、契约、债务证券选择属于 独立信用分析流程 的工作。如果一项困境/重组事件同时涉及股票和债权两侧，本技能负责股权路径，并把资本结构、契约、回收输入交由 独立信用分析流程 提供。

## 不要在以下场景使用本技能

- 没有明确驱动事件的一般多/空论点：改用 `long-short-pitch`。
- 仅做日历/观察清单而不做承销分析：改用 `catalyst-calendar`。
- 信用工具、信用资质、债务重组、困境证券、回收、利差、收益率、契约、债券选择、资本结构、优先级、流动性、关键债权层级、回收瀑布等：改用 独立信用分析流程。
- 投资组合敞口、对冲、仓位规模：改用 `portfolio-risk-management`。
- 宏观、利率、外汇、大宗商品的传导图谱：改用 `economic-impact-report`。
- 承销结论之后的论点持续跟踪：改用 `thesis-tracker`。

## 必须遵守的立场

- 不得编造事件。如果没有给出公司/证券/事件且也找不到活跃事件，应返回需求确认或事件扫描框架，而不是凭空展开。
- 对市场敏感数据加时间戳：价格、价差、融券、债券/贷款价、期权价格、监管状态、开庭日期。
- 一手文件优先：并购协议、8-K、S-4/F-4、委托书、Schedule TO/14D-9、Form 10、13D/G、契约、法院/监管记录、上市公司公告。
- 关键输入要明确标注是 `Fact`、`Assumption` 还是 `Judgment`。
- 在给出概率加权结论之前，各情景概率必须加总到 100%。
- 措辞强度要与证据强度匹配。如果做出可执行 `Buy`、`Own`、`Initiate` 所需的实时价、价差、融券、流动性、分拆证券预交易、指数处理或对冲输入暂缺，应改用 `Wait`、`Monitor`、`Diligence to initiate` 等口径，并以承销框架或建仓筛选呈现。
- 如果用户提供的信息有重大非公开信息嫌疑，不得据此给出交易建议；应提示走合规/法律审查。

## 主工作流

1. **判定事件与证券。** 给出事件类型、子类型、合适的证券或价差表达，并指明需要哪些 playbook。
2. **构建事实包。** 录入各方、条款、当前价、未受影响价、时点、最晚截止日、审批、条件、诉讼/监管状态、融券、流动性及来源。
3. **构建时间线。** 区分确认日期与估计窗口，标注下一个真实催化剂。
4. **在有依据时计算市场定价。** 仅当输入有来源支持时，给出毛价差、年化、隐含概率、下行价、分红/融券/融资调整、对冲比率与期望收益。否则列出缺哪些就绪输入，再以承销框架或关键问题视图呈现。
5. **定义终局情景。** 以未受影响价、经同业调整的未受影响价、独立估值、诉讼/监管结果、SOTP，或由 独立信用分析流程 输入的回收价值作为各种终值锚点。
6. **构建有依据的事件路径。** 仅当必要输入有来源时才上完整情景树（概率、时点、终值、回报、理由、信号）；否则展示机制、估值筛选、证据缺口与达到交易就绪所需输入，避免假精确。
7. **指认关键问题。** 写明谁掌控、看什么证据、下一个信号是什么、决策阈值在哪。
8. **建议表达式与监控。** 说明买入/回避/观察、实施方式、规模注意事项、复核阈值与监控计划。
9. **红队检验。** 解释这笔交易如何亏钱、市场可能已经知道什么、哪些信息陈旧或缺失、什么会推翻结论。

## 输出模式

- **完整事件报告**（默认）：适用于内容较厚、可复用、含较多日期/来源/表格的请求。将事件机制、估值或定价（当数据可支撑）、交易或建仓立场、监控、红队、未决问题与来源整理成 `visual-page brief`，交给 `visual-page` 制作独立 GUI/HTML。
- **标准化仪表板**：仅当用户明确要求标准化仪表板、可复用仪表板模板或基于结构化载荷的渲染时使用。本技能负责事件事实、情景计算、时点、概率/回报、表达式与监控判断；HTML 外壳、图表排版、响应式布局、验证与 `<media />` 交付仍由 `visual-page` 完成。
- **明确的 PM 快速阅读**：仅在用户明确说"快速"、"简短"、"摘要"、"单页"、"简报"、"TL;DR"时使用；内容应包括建议、交易构建、定价、隐含概率、关键事项、下行、期望收益、下一个催化剂与终止标准。
- **模型/数学模式**：确定性价差、年化、隐含概率、对冲比率、CVR、分拆、情景 EV、有明确日期的事件概率与回报。计算口径参见 `references/scenario_math.md`；资本结构、契约、债务证券、回收等走 独立信用分析流程。
- **红队模式**：集中攻击下行、概率、关键风险、来源质量、时点、拥挤度、流动性、融券、仓位规模。
- **监控/更新模式**：说明发生了什么变化，以及概率、规模或建议是否随之改变。

不要因为上下文稀薄就退到快速模式；上下文薄时输出的是一份带证据缺口、假设与缺失输入的"筛选级完整事件报告"。

## HTML 交付：无损调用 visual-page

输出实质性 HTML 完整事件报告时，必须把下列内容作为完整设计 brief 交给 `visual-page`，不要在本技能内直接写 HTML：

- **页面模式**：事件备忘录用 `Long-read / Report`；定价表、情景 EV、价差监控、指数流向面板用 `Data UI`。
- **视觉主题**：要求 `visual-page` 使用冰白纸背景、液态玻璃风格；不要使用 `visual-page` skill 里的默认配色方案。价差收窄、概率上升、审批推进、利好、上涨等好事，以及所有强调色，统一用中国红 `#c0322f`；价差扩大、概率下降、审批受阻、利空、下跌等坏事，统一用稳绿 `#15803d`。
- **输出路径意图**：若用户给路径则使用；否则要求 `visual-page` 在 `/tmp/visual-page/<event-driven-topic>/index.html` 下创建独立目录，不覆盖旧页面。
- **首屏结构**：与证据阶段匹配的建议标题、决策/行动立场卡、事件状态、研究截止时间、三到五块事件特定证据图块、对应事件类型的主要分析对象。
- **组件映射（深度耦合 visual-page 组件，每个都带交互）**：
  - 事件时间线 → **可点击 step timeline**：节点点击就地展开该里程碑的条款 / 审批 / 状态与来源；确认日期与估计窗口用实线 / 虚线区分；hover 升起液态玻璃说明卡。
  - 条件 / 审批路径 → **带状态色的 flow-node / Mermaid**（4 节点以上用 Mermaid，可点击节点跳到对应分析）：已推进 / 已获批节点描中国红 `#c0322f`，受阻 / 被否节点描稳绿 `#15803d`（遵循本技能事件语义：审批推进 = 好 = 红）。
  - 价差 / 下行 / 隐含概率 / 期望收益 → **可展开 KV cards**：默认显示关键数字，hover / 点击就地展开计算口径（毛价差、年化、对冲比率、分红 / 融券调整）；价差收窄、概率上升着中国红，价差扩大、概率下降着稳绿。
  - 情景树 / 概率路径 → **可点击 Mermaid 概率树**：每条分支标概率 + 终值 + 回报，点击分支高亮对应情景行；概率必须先归一化到 100% 再渲染。
  - 交易条款桥 / 分拆价值桥 / CVR payoff → **带切换的 table / bench bars**：分配股权 / 保留股权 / 现金或债务转移可分段切换查看，bench-fill 过渡 200ms。
  - 监控计划 → **可筛选表**：按催化剂类型 / 窗口 chips 筛选（激活态中国红），bull / bear 信号列分别着红 / 绿。
  - 红队 / 关键问题 → **可展开对照矩阵**：每条反方论点行内展开「证据 / 什么会证伪 / 对建议的影响」。
- **交互规格（全部用内联 vanilla JS + CSS，禁止额外重依赖；继承 visual-page 的 BANNED 清单：无 AI 渐变 / 霓虹 / Inter）**：
  - 顶部 **sticky 锚点导航**：决策立场 / 时间线 / 定价 / 情景树 / 监控 / 红队，当前区块高亮中国红，点击平滑滚动。
  - **决策立场卡** 固定在首屏：Buy / Avoid / Watch / Wait 等立场措辞不得领先证据成熟度；定价 / 执行输入暂缺时，显眼标注「承销框架 / 入场筛选」。
  - 所有可点击元素必须有 hover 态、`:focus-visible` 键盘可达、`cursor:pointer`；timeline 展开 / 排序 / 筛选 / Mermaid 节点点击一律 ≤200ms 过渡。
  - 移动端（<768px）：Mermaid 情景树 / 审批图可横向 pan 但页面不横向滚动；监控表与条款桥转单列卡片；chips 自动换行。
  - 交互服务于「路径依赖的承销链」表达，不得制造数据噱头；首屏一屏内给出决策立场、事件状态、研究截止时间、对应事件类型的核心对象（并购：价差与隐含概率；分拆：价值分配桥）。
- **图表规则**：2-8 个情景 payoff 用 CSS bench bars；只有超过 8 个价格 / 价差时间点才引入 Chart.js（`font.family='Outfit'`、价差收窄序列中国红、扩大序列稳绿、`borderRadius:6`）；情景树 / 审批路径 4 节点以上用可点击 Mermaid，2-3 节点用 hover 增强 flow-node。不要为少量节点引入重库。**用到 `<div class="mermaid">` 时，务必提醒 `visual-page` 在 `<head>` 加载 `mermaid.min.js`（CDN）并调用 `mermaid.initialize`，否则图不渲染。**
- **必须保留的业务语义**：`Fact`、`Assumption`、`Derived Calculation`、`PM Judgment` 必须可见地区分（用 chips 或角标，不要靠红绿单独承载，避免与价差 / 概率涨跌语义混淆）；概率加总、下行、时点、来源状态与缺失输入要在页面上清楚呈现。
- 若定价或执行输入暂缺，应在显眼处说明该报告是承销框架或建仓筛选，列出要把结论升级为可执行所需的证据，且标题措辞不得超过证据支持范围。
- 分拆/换股分拆：首屏给出分配机制与确定日期、把分配股权/保留股权/现金或债务转移分开列示的价值分配桥、SpinCo 与 RemainCo 起点、已确认证据与技术性供给论点的对比、建仓筛选、表达式、监控、红队情景。
- 并购套利或要约收购：在来源可支持时首屏放价差、下行、隐含概率与情景树；诉讼/监管事件首屏放程序路径、救济风险与回报影响；资金流/技术性事件首屏放确认的流向机制、流动性、执行证据与退出路径。
- 仅当输入有来源可支撑时才出概率加权情景、期望收益与交易执行模块；否则以事件机制、估值筛选、证据缺口与关键输入替代。
- **交付要求**：要求 `visual-page` 输出一个完整 GUI/HTML 文件，检查本地打开、响应式、无断链，再用 `<media />` 交付。

## 确定性计算纪律

涉及价差、年化、隐含概率、情景 EV、CVR 等确定性算术时,按 `references/scenario_math.md` 的口径手算或借助通用计算器;不引入额外的项目内脚本。情景 EV 的概率必须先归一化到 1.0,未归一化的输入不得作为加权结论写进面向读者的产物。

## 终稿 QA

定稿前请确认：事件/证券明确、市场数据带时间戳或有缺失说明、Fact/Assumption/Judgment 区分清楚、一手来源优先、概率加总为 100%、下行方法明确、关键事项具体、监控计划可执行、报告含红队章节。

## Public Equity PM 判断层

对于内容较厚的事件工作，定稿前加载 `references/pm-judgment-heuristics.md`。受众模式取值：`long_only_pm`、`long_short_hf`、`sell_side_research`、`etf_index_diligence`、`public_equity_diligence`。

指数/ETF/被动资金流事件分析属于本技能覆盖的事件驱动路径之一。

必须包含的 PM 判断：
- 写明优势类型：承销分析、时点、资金流、法律/流程、错误定价的可选性。
- 给出基准概率认知：这一类事件通常如何收场，本案与典型有何不同。
- 列出表达式菜单：普通股、配对、价差、期权、存根股、分拆证券预交易、权利、认股权证、一篮子对冲，或回避。
- 必须考察路径风险：按市值计价的痛苦、流动性、融券、拥挤度、事件延迟、融资成本、退出流动性。
- 资金流事件还要包含：资金流相对 ADV、价格/成交量时间戳、流通股、市场规模、融券、ETF/指数 AUM 假设、退出计划。
