# 知识蒸馏 · Knowledge

> 「信息过载？知识蒸馏帮你抽走骨架，让AI替你记住关键框架。」

## 核心理念

知识蒸馏不是「把资料变成另一份摘要」，是**从任意信息源中抽出一套认知识蒸馏架**——去掉血肉（冗余细节、重复论述、装饰性内容），留下可运行的结构。

好的一份资料 Skill 是一套可操作的思维工具箱：
- 这个主题/领域用哪些**心智模型**来理解？（镜片）
- 存在哪些可操作的**方法论/检查清单**？（操作步骤）
- 有哪些**关键概念**定义了该领域的讨论边界？（词汇表）
- 这个框架**适用和不适用**什么场景？（边界）

**关键区分**：捕捉的是HOW to think about this topic，不是WHAT the materials say。

## 输入模式

| 模式 | 触发条件 | 说明 |
|------|---------|------|
| **本地文件** | 用户提供单个文件路径 | 直接读取文件内容进行分析 |
| **本地文件夹** | 用户提供文件夹路径 | 扫描文件夹，识别并读取关键文件 |
| **网络搜索** | 用户提供主题/关键词 | 通过网络搜索获取核心内容 |
| **混合模式** | 用户同时提供本地+主题 | 本地文件为主，网络搜索补充缺口 |

## 执行流程

### Phase 0: 确认主题与资料来源

收到用户输入后，确认以下信息：

| 确认项 | 说明 |
|--------|------|
| **主题/领域** | 要蒸馏的知识领域是什么？（如"Rust异步编程""行为经济学""K8s运维"） |
| **资料来源** | 本地文件？文件夹？网络搜索？混合？ |
| **输入详情** | 文件路径 / 文件夹路径 / 搜索关键词 / 组合 |
| **蒸馏目标** | 框架？方法论？案例？思维方式？全面覆盖？ |
| **深度偏好** | 快速概览 or 深度分析？ |
| **新建 or 更新** | 检查工作目录下 `skills/` 是否已有该主题 Skill |

**本地文件夹处理策略**：

| 文件量 | 策略 |
|--------|------|
| ≤10个文件 | 全部读取分析 |
| 10-50个文件 | 按文件名/类型筛选关键文件，其余抽样 |
| 50+个文件 | 先列出目录结构，请用户确认范围，或自动识别核心文件 |

**网络搜索策略**：
1. 根据主题生成3-5组搜索关键词
2. 每组关键词覆盖不同角度（概念定义、方法论、案例、批评/局限、最新发展）
3. 优先收录权威来源（学术论文、官方文档、行业标准、高质量长文）

确认后 → Phase 0.5 创建目录。

### Phase 0.5: 创建Skill目录

```
./skills/[主题名]/
├── SKILL.md                          # 最终产物
└── references/
    └── material-analysis.md          # 资料分析记录
```

**完成检查**：
- [ ] 目录已创建
- [ ] material-analysis.md 已创建（空文件，等待Phase 1填充）
- [ ] 如果是更新模式：已读取现有SKILL.md，标注哪些信息需要刷新

**命名规范**：目录名使用中文，直接以主题/书名/领域名命名（如 `行为经济学`、`Rust异步编程`、`K8s运维实战`），保持可读性。

**关键规则**：所有分析文件必须存在skill目录内部，Skill必须是自包含的。

### Phase 1: 资料收集与分析

根据输入模式选择策略：

**本地文件模式**：
1. 读取文件内容（支持 .md / .txt / .pdf / .rst / .json / .yaml 等常见格式）
2. 生成结构化分析记录，写入 `references/material-analysis.md`

**本地文件夹模式**：
1. 列出文件夹结构，识别文件类型和重要性
2. 按优先级读取（README/索引文件优先 → 核心内容文件 → 示例/补充文件）
3. 汇总分析结果

**网络搜索模式**：
1. 执行多角度搜索（概念定义 → 核心方法论 → 实践案例 → 争议/局限 → 前沿发展）
2. 筛选高质量内容，提取关键信息
3. 在诚实边界中标注「基于网络搜索，可能存在信息偏差」

**混合模式**：
1. 先读取本地文件作为基础
2. 识别信息缺口（哪些方面缺失或不足）
3. 定向网络搜索补充缺口
4. 标注各部分的来源（本地 / 网络搜索）

### 资料来源交叉比对（多源时必须执行）

当资料来源≥2个时，必须在进入结构化分析前执行交叉比对，去除冲突、不合规、不道德的资料来源。

**比对维度**：

| 维度 | 操作 | 不通过处理 |
|------|------|-----------|
| **事实一致性** | 同一事实在不同来源中是否一致 | 标注差异，优先采信更权威来源 |
| **观点收敛/发散** | 不同来源对同一问题的观点是收敛还是发散 | 收敛→记录为共识；发散→记录为争议并查证 |
| **合规性** | 来源是否违反版权、许可协议或服务条款 | 剔除不合规来源，记录原因 |
| **伦理性** | 内容是否涉及歧视、偏见、误导或有害信息 | 剔除不道德来源，记录原因 |
| **时效性** | 信息是否已过时（技术类>3年需标注） | 标注时效风险，降权处理 |
| **利益冲突** | 来源是否存在商业/政治/宗教利益关联 | 标注潜在偏见，降权但不剔除（除非内容本身不合规） |

**比对流程**：
1. 列出所有来源及其基本属性（类型、作者/机构、发布时间、权威评级）
2. 提取每个来源的核心主张（3-5条）
3. 构建「主张-来源」矩阵，找出矛盾点
4. 对矛盾点：查证第三来源裁决，或标注为「待证实争议」
5. 剔除不合规、不道德的来源，记录剔除原因
6. 输出交叉比对报告，追加到 material-analysis.md

**交叉比对报告格式**：

```markdown
## 来源交叉比对报告

### 来源可靠性评级
| 来源 | 类型 | 权威度 | 时效 | 利益关联 | 判定 |
|------|------|--------|------|---------|------|
| ... | ... | 高/中/低 | 新鲜/可接受/过时 | 无/有(说明) | 采纳/降权/剔除 |

### 共识点
- [主张] — 来源A、B、C 一致确认

### 争议点
- [主张] — 来源A vs 来源D 矛盾，来源C 支持A → 待证实

### 剔除记录
- [来源X] — 剔除原因：[不合规 / 不道德 / 信息已被证伪 / ...]
```

**分析维度**（写入 material-analysis.md 的结构）：

```markdown
# [主题名称] · 资料分析

## 主题概览
- 主题名称、分析时间
- 核心问题：这个领域试图回答什么？
- 核心共识/主要论点（200字以内）
- 目标受众：谁需要这个框架？

## 资料来源清单
- 逐源列出：名称、类型（文件/网页/文档）、质量评估
- 标注「高信息密度来源」

## 内容摘要
- 按主题/子领域提取核心论点（每部分3-5行）
- 标注「高信息密度内容块」

## 关键概念/术语
- 领域特有的术语
- 被重新定义或存在争议的术语
- 每个术语的定义 + 出现来源

## 方法论/框架
- 资料中明确提出的方法论、检查清单、决策树
- 每个框架的输入、过程、输出

## 核心案例/数据点
- 资料中反复引用的关键案例（3-5个）
- 每个案例说明了什么框架

## 局限与争议
- 资料中明确承认的局限
- 不同来源之间的观点冲突
- 未覆盖的重要子领域
- 可能的批评角度

## 与其他领域的关系
- 引用了哪些重要文献/思想
- 该主题在更大知识体系中的位置
```

**Phase 1 完成检查**：
- [ ] 所有关键来源都已被分析
- [ ] 来源交叉比对已完成（多源时强制），剔除记录已写入
- [ ] 关键概念列表完整
- [ ] 方法论/框架已提取
- [ ] 高信息密度内容块已标注
- [ ] 信息缺口已识别并记录

展示分析摘要给用户确认 → 进入 Phase 2。

### Phase 2: 框架提取

读取 `references/material-analysis.md`，执行结构化提炼。

先读取 `references/extraction-methodology.md` 获取三重验证方法论。

#### 2.1 心智模型提取（3-7个）

**三重验证**（详见 extraction-methodology.md）：
- **跨源复现**：同一框架在至少2个不同来源/上下文中出现
- **生成力**：能推断该领域未直接讨论问题的答案
- **排他性**：不是该领域的常识或标配视角

操作步骤：
1. 扫描 material-analysis.md，列出所有候选论点（通常10-20个）
2. 对每个候选执行三重验证
3. 按排他性强度排序，取top 3-7个
4. 记录格式：名称、一句话、原文定义、证据（引用来源）、应用方式、局限性

#### 2.2 方法论/检查清单提取（3-8条）

- 资料中提出的可操作步骤、检查清单、决策规则
- 可执行标准：能转化为具体步骤（不只是抽象原则）
- 可验证标准：有案例或数据支撑
- 可迁移标准：能应用于资料未提及的新场景

#### 2.3 核心概念词汇表（5-15个）

- 领域特有的术语
- 被特定来源重新定义的常见术语
- 在资料中结构性重要的术语

#### 2.4 案例模式（3-5个）

- 资料中反复使用的论证模式/案例类型
- 每个模式：模式名称、典型案例、说明了什么

#### 2.5 应用范围与边界

- 这个框架适合解决什么问题？
- 不适合解决什么问题？
- 盲区在哪里？

#### 2.6 表达风格（可选）

- 仅对风格特征明显的资料提取
- 对技术文档/教科书类可跳过

### Phase 2.5: 提炼确认检查点

Phase 2 完成后，展示提炼摘要：

```
提炼结果摘要：
- 心智模型：N个（列出名称）
- 方法论/检查清单：N条
- 关键概念：N个
- 案例模式：N个
- 表达风格：[已提取/跳过]
```

用户确认OK → 进入Phase 3。
用户觉得不对或缺少 → 回到Phase 2调整。

### Phase 3: Skill构建

将Phase 2结果组装为可运行的SKILL.md。

#### Step 1: 读取模板
读取 `references/template.md` 获取标准结构。

#### Step 2: 填充内容

| 模板Section | 填充来源 |
|------------|---------|
| frontmatter description | 来源数量+模型数量+触发词 |
| 使用说明 | Phase 2.5 应用范围 |
| 回答工作流 | 根据心智模型自动推导研究维度 |
| 核心心智模型 | Phase 2.1 提取结果 |
| 方法论与检查清单 | Phase 2.2 提取结果 |
| 关键概念词汇表 | Phase 2.3 提取结果 |
| 案例模式 | Phase 2.4 提取结果 |
| 应用范围 | Phase 2.5 结果 |
| 资料元信息 | Phase 1 主题概览 + 来源清单 |
| 诚实边界 | Phase 1 + Phase 2.5 结果 |
| 附录 | 来源分析明细 |

**回答工作流生成**：
1. 判断问题是否落入本Skill应用范围
2. 从心智模型和方法论中选择最相关的2-3个框架
3. 用选定框架分析问题，引用概念和案例

#### Step 3: 输出
将完成的SKILL.md写入 `./skills/[主题名]/SKILL.md`。

---

### Phase 4: 质量验证

#### 4.1 框架覆盖测试
选3个资料中明确讨论过的问题，用新Skill分析，结果应与资料中的核心结论一致。

#### 4.2 迁移测试
选1个资料未直接讨论但属于应用范围内的问题，用Skill的方法论框架推导出合理分析。
期望结果：基于框架X和方法论Y的推断，可能...但不确定。

#### 4.3 来源归因测试
抽查3个关键论断，确认能追溯到具体来源（本地文件 or 网络搜索结果）。

#### 4.4 交叉比对复查
- 确认被剔除的来源有明确的剔除原因
- 确认标注为「争议」的观点未在Skill中被当作确定结论
- 确认降权来源的观点未在Skill中被过度依赖

#### 4.5 通过标准

| 检查项 | 通过标准 | 不通过信号 |
|--------|---------|-----------|
| 心智模型数量 | 3-7个，每个有来源证据 | <3或>10 |
| 方法论/清单数量 | 3-8条，可操作 | <3或全是泛泛原则 |
| 概念词汇表 | 5-15个，有定义 | 只列术语不给定义 |
| 应用边界 | 明确写适用范围和局限 | 只写优点不写局限 |
| 案例模式 | 至少3个，有来源支撑 | 无案例或案例不准确 |
| 来源覆盖 | 关键来源都被分析到 | 遗漏了高信息密度来源 |
| 交叉比对 | 剔除原因明确，争议已标注 | 不合格来源未剔除，争议被当作事实 |
| 表达风格（如适用） | 保留了资料的整体特征 | 像通用AI味 |

**迭代上限**：Phase 2→4最多循环2次。如果2轮后仍有不通过项，在诚实边界中标注薄弱维度，交付当前最优版本。

**展示验证结果给用户确认后才算完成。**

## 更新已有Skill

当用户说「更新XX的skill」「有新资料了」「补充XX主题」时：
1. 读取现有SKILL.md，找到分析时间和来源清单
2. 确认新增资料与现有资料的互补关系
3. 增量更新——只更新变化的部分，不重写整个Skill
4. 更新分析时间和来源清单

## 品味守则

| 原则 | 一句话 |
|------|--------|
| 框架 > 摘要 | 反复出现的核心论点比内容摘要更有价值 |
| 方法论 > 感悟 | 可操作的步骤比「XX认为...很重要」更有用 |
| 边界 > 优点 | 知道这框架不能干什么，比知道它能干什么更重要 |
| 来源标注 > 假装全知 | 明确信息的出处和可靠度，比假装全部来自一手的幻觉强 |

### 绝不做的事
- 把通用道理包装成该领域的「独特见解」
- 忽略资料中明确指出的局限和争议
- 在信息不足时强行生成完整框架
- 把某一来源的观点当成该领域的唯一真理
- 混淆不同来源的可靠度（维基百科 ≠ 学术论文 ≠ 个人博客）
- 保留已知不合规、不道德或已被证伪的资料来源
- 对存在利益冲突的来源不做标注直接当客观事实使用

## 特殊场景

### 资料来源类型差异

| 资料来源类型 | 心智模型 | 方法论 | 概念表 | 案例模式 | 表达风格 | 诚实边界 |
|------------|---------|--------|--------|---------|---------|---------|
| 书籍/专著 | 3-7个 | 3-8条 | 5-15个 | 3-5个 | 可选 | 标准 |
| 系列文章/博客 | 3-5个 | 3-5条 | 5-10个 | 2-4个 | 提取 | 加注「单一作者视角」 |
| 技术文档/规范 | 2-4个 | 5-8条 | 10-20个 | 1-2个 | 跳过 | 加注「版本/时效」 |
| 研究论文合集 | 3-5个 | 3-5条 | 5-10个 | 3-5个 | 跳过 | 加注「学术争议」 |
| 网络搜索聚合 | 3-5个 | 3-5条 | 5-10个 | 2-4个 | 跳过 | 加注「来源可靠性差异」 |
| 混合来源 | 4-6个 | 4-6条 | 8-15个 | 3-5个 | 可选 | 标注每部分的来源类型 |

### 书籍作为核心来源

书籍是信息密度最高、结构最完整的来源类型。当主要来源包含书籍时，启用增强分析框架。

**书籍特有的分析增强**（叠加到Phase 1分析模板）：

| 增强维度 | 说明 |
|---------|------|
| **作者立场识别** | 作者所属学派、核心关切、与谁对话/反驳了谁 |
| **章节结构分析** | 逐章提取核心论点，标注高信息密度章节 |
| **版次差异** | 确认具体版次，新版与旧版的关键差异（第二版可能推翻了第一版的结论） |
| **思想谱系** | 作者引用了谁、发展了谁的理论、在学术脉络中的位置 |
| **术语一致性** | 作者是否重新定义了常见术语？是否创造了新术语？ |

**书籍+补充资料模式**：
- 以书籍框架为主干，网络搜索/其他资料为枝叶
- 补充方向：书评、作者访谈、相关论文的引述与批评、该领域后续发展
- 交叉比对时，书籍观点作为高权重锚点，外部资料用于验证和补充盲区

**书籍来源的诚实边界增量**：
- 标注「基于第N版（出版于[年份]），可能与旧版/新版有差异」
- 标注「反映作者立场，不一定是该领域共识」
- 标注「出版于[年份]，该领域此后可能有重要新发展未被本书覆盖」

**书籍系列处理**：
- 逐本蒸馏：每本书生成独立Skill，标注系列关系
- 合并蒸馏：提取贯穿系列的核心框架 + 每本书的独特贡献
- 合并蒸馏时诚实边界标注：「系列合并可能丢失单本书的细微视角差异」

### 大文件夹处理

当文件夹包含50+文件时：
1. 先输出目录树，标注推测的文件重要性
2. 请用户确认分析范围（全部 / 指定子目录 / 指定文件类型）
3. 优先分析：README、index、目录/索引文件、命名含"core/main/key"的文件
4. 其他文件抽样分析，在诚实边界中标注「大文件夹抽样分析，可能遗漏细节」

### 信息不足的主题

当网络搜索和本地资料都无法提供足够信息时：
1. 告知用户「该主题的公开信息有限，生成质量会受限」
2. 心智模型减至2-3个，每个标注「基于有限信息推测」
3. 诚实边界加大篇幅，明确列出信息缺口

### 信息冲突的处理

当不同来源对同一问题有矛盾观点时：
1. 不在Skill中强行统一——记录分歧本身
2. 在概念词汇表或应用边界中标注「存在争议」
3. 列出各方的核心论据
4. 不选边站（除非用户明确要求）

### 多主题/系列资料

当用户说「把这些都蒸馏了」或涉及多个子主题时：
1. 确认是逐主题蒸馏还是合并蒸馏
2. 合并蒸馏时：提取贯穿全局的核心框架 + 每个子主题的独特贡献
3. 在诚实边界中说明「多主题合并可能丢失单主题的细微差异」

---

## 最后

一份好资料的价值不在于它写了什么，而在于它**揭示了什么思维结构**。

知识蒸馏抽走的不是摘要，是框架。信息过载时代，好的读者不需要记住每一条信息，只需要记住框架。
