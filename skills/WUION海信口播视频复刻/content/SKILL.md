# WUION 海信口播视频复刻

把参考视频反推成可直接贴入 AI 视频工具的结构化提示词，全程使用"图1"指代模特、"图2"指代场景，**禁止复用原视频或参考 MD 的具体内容**（口播文本、动作描述、脸型/发型/服装/家具细节必须从视频本体重新提取）。

## Inputs to collect

用户上传三个文件。如果任一缺失，先问，不要硬上：

- **模特参考图**（图1 / @Image1）：胸像/半身像，包含清晰面部与服装
- **场景参考图**（图2 / @Image2）：9:16 竖屏，无模特，仅场景（电视+客厅+家具）
- **参考视频**（.mp4 / .mov）：包含人物口播，电视画面在画面内（典型电商种草/产品解说场景）

> 额外信息默认不需要：机型、品牌、字幕原文等。如果用户提供了可以引用，但绝不能从原片示例文档里抄。

## Output contract

- **唯一交付物**：`/<video_basename>_直贴版提示词.md`（保存到 workspace 根目录）
- **音频**：本任务**不**保留 .wav 文件；分离音轨仅用于转录口播
- **字符数**：中文字符 ≤ 6800
- **结构**：7 段式（见 references/prompt-template.md）
- **引用文件**：`@Image1` 模特图 + `@Image2` 场景图 + 参考音频（在提示词里提及，不上传文件）

## Procedure

按顺序执行 6 步，每步标"为什么"。

### Step 1｜ffprobe 读视频元数据

```bash
ffprobe -v error -show_format -show_streams <video>
```

记录：duration（秒，精确到 0.01）、width×height、fps、codec、总帧数。
**为什么**：duration 是全篇的"时长锚点"，所有分镜/口播/动作锁死这一刻度。视频流 duration（`duration_ts / time_base`）和容器 duration 取较准的那个，0.01s 精度四舍五入。

### Step 2｜抽帧分析（0.2s 间隔）

```bash
mkdir -p frames_200ms
ffmpeg -i <video> -vf "select='isnan(prev_selected_t)+gte(t-prev_selected_t\,0.2)',showinfo" \
  -vsync vfr frames_200ms/f_%03d.jpg
```

从 0.2s 间隔的帧里**逐帧观察**并记录：
- 模特站位（横向：左/中/右/居中略偏左/居中略偏右/正中；纵向：前景/中景/远景；朝向：正对/侧对/斜对镜头；与图2 关键家具的相对位置）
- 模特动作变化（每 0.20s 标注一次）
- 电视画面切换点（与 Step 3 口播时间戳对齐）
- 模特口型/手势关键时刻

**为什么**：站位是 Step 4.5 强制要求的"实测复刻"；不观察就硬编码"电视正前方、居中略偏右"是反例。

### Step 3｜音频转录与时间戳

```bash
ffmpeg -i <video> -vn -acodec pcm_s16le -ar 44100 -ac 2 /tmp/_ref_audio.wav
# 上传到 mcode-tools 拿临时 URL
mcode-tools upload_temp_url /tmp/_ref_audio.wav
# 调用 connector 转录
mcode-tools connector call connector__matrix__audios_understand --args '{
  "audio_info":[{"url":"<temp_url>","prompt":"逐字转录中文口播，句级时间戳精确到 0.01s。格式：开始秒-结束秒: 文本。"}]
}'
```

句数 N = 分镜数。**不要沿用任何示例/MD/历史口播文本**。转录结果与 Step 2 抽帧的口型对一遍，确认分段准确。

**为什么**：音频是"唯一口播时序基准"；视觉字幕可能与音频不一致（常见），以音频为准。

### Step 4｜生成 7 段式结构

按 references/prompt-template.md 写文件，**复用章节骨架与表格样式**，**禁止复用**：
- ❌ 任何具体口播文本（必须用 Step 3 转录）
- ❌ 任何具体动作描述（必须从 Step 2 帧观察）
- ❌ 任何具体人设（脸型/发型/服装/配饰）——统一用"图1"指代
- ❌ 任何具体场景描述（家具/品牌/赛事）——统一用"图2"指代
- ❌ 任何示例时长（如 5.50s、6.00s、10.00s）——必须用 Step 1 实测

**站位强制项（Step 4.5）**：在"画面内容"和"人物动作时间线"0.00s 起点行，必须用 Step 2 观察到的实测站位（含横向位置、纵向位置、朝向、与图2 关键元素相对位置）。后续时间点只写动作变化，不再重复站位。

### Step 5｜字数自检

```bash
python3 -c "
import re
with open('output.md','r',encoding='utf-8') as f: c=f.read()
n=len(re.findall(r'[\u4e00-\u9fff]',c))
print(n)
assert n<=6800, f'中文字符 {n} > 6800'
"
```

超 6800：精简"二、镜头与电视内容拆解"里重复的描述性字段，**保留所有时间点与口播文本**。

**为什么**：硬约束，超出会被判定为生成失败。

### Step 6｜交付检查清单（19 项）

按下表逐条勾选，全过才交付。详见 references/prompt-template.md 第五节。

关键必检：
- 时长锁死 0.01s ✓
- 5 段口播与字幕起止完全对齐 ✓
- 模特动作每 0.20s 一个时间点 ✓
- 全程用"图1"/"图2"指代 ✓
- 0 文字/字幕/水印/Logo ✓
- 电视外观无反光/倒影/文字 ✓
- 固定机位，无推拉/环绕/旋转/变焦 ✓
- 站位写进"画面内容"和"人物动作时间线"0.00s 起点行 ✓
- 中文字符 ≤ 6800 ✓

## Failure handling

- **ffprobe 失败 / 视频损坏** → 报错给用户，不猜测时长
- **音频转录失败** → 改用 `connector__matrix__listen_audio` 重试一次；再失败则提示用户音频质量可能有问题
- **口播转录与视觉字幕不一致** → 以音频转录为准（音频是唯一口播时序基准），但提示用户
- **抽帧发现模特完全不在画面里** → 走 video-storyboard-prompt 路径，不该用本 skill
- **视频时长 < 2s 或 > 30s** → 提示用户：本 skill 适合 3-15s 电商口播；超长视频建议先剪辑
- **字符数超 6800** → 精简描述性字段，绝不删时间点和口播
- **站位与图2 严重不匹配**（如人物在场景外） → 提示用户检查输入的视频与场景图是否对应同一个场景

## 关键约束（违反任一 = 任务失败）

1. 时长必须用 ffprobe 实测，**不得沿用任何示例值**
2. **必须用 ffmpeg 分离音频**做语音识别（不保存）
3. **必须**用语音识别转录口播取 0.01s 时间戳，**禁止沿用任何示例口播**
4. 分镜数 = 真实口播段数（5 段口播 = 5 镜，不固定 N 镜）
5. 全程 0.01s 精度，每 0.20s 一个时间点标注模特动作
6. 全程使用"图1"指代模特、"图2"指代场景，**禁止描述脸型/发型/服装/家具细节**
7. 全程**无任何文字/字幕/标题/水印/Logo/赛事标志/贴纸/角标**
8. 电视外观**全程无反光/倒影/文字**
9. 全程**固定机位**，**无推拉/环绕/旋转/倾斜/变焦**
10. 中文字符数 ≤ 6800
11. 站位从参考视频**逐帧观察**后复刻，写进 0.00s 起点行
