# Obsidian_Policy_Analyzer (Obsidian政策分析专家)

## 简介

Obsidian_Policy_Analyzer 是一款专为Obsidian用户设计的政策笔记分析工具。它能够自动解析政策文件内容，提取关键元数据，并为笔记生成标准化的YAML Frontmatter。

## 功能特性

### 1. 智能元数据提取
- 自动识别发文时间、生效时间
- 判断政策状态（现行有效/已废止/尚未施行）
- 提取适用地域
- 识别被替代文件

### 2. 标准化标签体系
- 层级标签：`政策/国家级`、`政策/市级`、`政策/县级`
- 业务标签：根据内容自动归类（土地管理、矿产管理、规划管理等）

### 3. 关键词提取
- 自动提取3-5个核心业务关键词
- 生成一句话摘要作为aliases

### 4. 执行要点提取
- 申报截止日期
- 资金门槛/关键指标
- 违规风险提示

## 使用方法

### 触发条件
当用户输入包含以下内容时自动触发：
- 公文内容
- 政策标题
- 指令"归档政策"

### 输入示例
```
请归档以下政策文件：
自然资发〔2024〕108号

自然资源部 住房城乡建设部 财政部国家税务总局 国家金融监督管理总局 最高人民法院 
关于分类施策妥善解决保交房项目办证问题的通知
...
```

### 输出格式
工具将输出标准化的YAML Frontmatter：

```yaml
---
tags:
  - 政策
  - 政策/国家级
  - 保交房
  - 不动产登记
aliases:
  - 保交房项目办证问题分类施策解决方案
date_published: 2024-06-20
date_effective: 2024-06-20
status: 现行有效
region: 全国
replaces: ""
keywords:
  - 保交房
  - 不动产登记
  - 购房群众
  - 产权办理
  - 抵押注销
---

> **执行要点**
> 1. **申报截止**：待提取
> 2. **资金门槛**：待提取
> 3. **违规风险**：待提取
```

## 属性字段说明

| 字段 | 说明 | 格式要求 |
|------|------|---------|
| `tags` | 政策标签 | 必填，包含"政策"，自动添加层级和业务标签 |
| `aliases` | 一句话摘要 | 作为笔记的隐形搜索词 |
| `date_published` | 发文时间 | YYYY-MM-DD |
| `date_effective` | 生效时间 | YYYY-MM-DD，未明示则同发文时间 |
| `status` | 状态 | 现行有效/已废止/尚未施行 |
| `region` | 适用地域 | 全国/省市名称 |
| `replaces` | 被替代文件 | 无则留空 |
| `keywords` | 核心关键词 | 3-5个业务关键词 |

## 应用场景

### 1. 政策研究
快速整理国家、省、市、县各级政策文件，构建政策知识库。

### 2. 法规比对
通过aliases快速搜索，辅助法规比对分析。

### 3. 追踪更新
通过replaces字段追踪政策更新历史。

### 4. 数据分析
利用tags和keywords进行政策聚类和趋势分析。

## 注意事项

1. **编码问题**：处理中文文件时注意文件编码，建议使用UTF-8
2. **日期格式**：严格遵循YYYY-MM-DD格式
3. **标签一致性**：保持标签命名风格统一
4. **定期更新**：政策废止时及时更新status字段

## 完整SKILL定义

以下是Skill的完整定义代码，可直接导入使用：

```
# Obsidian_Policy_Analyzer (Obsidian政策分析专家)

## 目标
为 Obsidian 生成结构化的政策笔记，利用 YAML Frontmatter 实现元数据管理。

## 触发条件
用户输入包含公文内容、标题，或指令"归档政策"。

## 属性定义与提取规则

### 1. tags
- 必须包含 `政策` 标签。
- 根据层级自动添加子标签，如 `政策/国家级`、`政策/地方法规`。
- 从"核心对象"中提取业务标签，如 `数字经济`、`税务`。

### 2. aliases
- 填入一句话摘要，作为该笔记的"隐形搜索词"。

### 3. date_published
- 发文时间，严格遵循 `YYYY-MM-DD` 格式。

### 4. date_effective
- 生效时间，严格遵循 `YYYY-MM-DD` 格式。若未明示，默认同 `date_published`。

### 5. status
- 根据文中"废止"、"施行"等词汇判断。选项：`现行有效`、`已废止`、`尚未施行`。

### 6. region
- 适用地域，如 `全国`、`重庆市`、`上海市`。

### 7. replaces
- 被替代的文件名称。若无，留空。

### 8. keywords
- 以列表形式提取 3-5 个核心业务关键词。

## 输出模板 (YAML Frontmatter)

请严格按照以下格式输出，不要包含任何多余的解释性文字：

---
tags:
  - 政策
  - {{层级标签}}
  - {{业务标签1}}
  - {{业务标签2}}
aliases:
  - {{一句话摘要}}
date_published: {{发文时间}}
date_effective: {{生效时间}}
status: {{状态}}
region: {{适用地域}}
replaces: "{{被替代文件}}"
keywords:
  - {{关键词1}}
  - {{关键词2}}
  - {{关键词3}}
---

> **💡 执行要点**
> 1. **申报截止**：{{AI提取的截止日期}}
> 2. **资金门槛**：{{AI提取的关键指标}}
> 3. **违规风险**：{{AI提取的风险提示}}

## 执行要点
1. **申报截止**：AI提取的截止日期
2. **资金门槛**：AI提取的关键指标
3. **违规风险**：AI提取的风险提示
```
