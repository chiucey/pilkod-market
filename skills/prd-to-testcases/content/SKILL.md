# PRD → 测试用例生成器

根据需求文档或PRD生成**生成Excel**的测试用例。

## 核心流程

1. **输入解析**：读取 `requirements/` 下的需求文档或用户提供的内容。
2. **中间件生成 (Markdown)**：
   - 必须以 `# [产品名称]测试用例` 作为第一行。
   - 深度提取 PRD 细节：包含所有**数值指标**（频率、延迟、精度）、**验收标准**、**异常边界**，以及业务的一些其它可操作场景或者需求未考虑全的操作。
   - 格式：`## 模块` -> `- #用例名` -> `tpP0` -> `tt类型` -> `步骤` -> `预期结果`。
3. **输出用例**：调用 `scripts/` 下的 Python 脚本，默认生成的测试用例模板参照 `references/` 目录下的 `template.xlsx`。
4. **交付统计**：提供用例总数、优先级（P0-P3）及模块分布报告、excel测试用例文件。

## 关键约束 (Mandatory)

- **格式清理**：
  - Excel 中的“预期结果”字段**禁止**出现前导横杠 `-`。
  - Excel 需自动调整列宽并启用自动换行，字段居中，但是对应的字段内容靠左居中对齐。
  
- **通用覆盖要求**：
  - 完全覆盖prd所有需求，另外根据业务特性或参考 `general-testcases-standard.md` 文档遍历对应的测试方法场景，另外结合常规的理解补充一些测试用例以及易出错的场景。
  - 必须包含**异常场景**（断网、断电、故障、非法指令、电量低）。
  - 数值必须量化（例如：`≤3秒` 而非 `快速`）。
  - 非功能性需求下的各指标要求：“例如 性能、兼容性、安全性、易用性”等文档明确要求的需要遍历各需求，对数值类的要求要敏感。
  
- **个性化业务用例覆盖**：
  - 权限类：首次使用权限申请、权限拒绝后的引导等。
  - 传感器类：传感器读值范围，频率，异常值处理（未读取到或者断开，损坏），长时间读取稳定性。


- **易错点**：
  1. **用例模板**：输出的测试用例模板字段以及内容要求约束需要严格参照模板 `template.xlsx`，如与用户新的要求冲突按照用户要求生成。
  2. **用例字段**：用例“模块1”、“模块2”字段对应的内容不要带编号，例如“1.0登录”直接写“登录”。
     - “用例类型”严格遵循 `general-testcases-standard.md` 中提到的，默认“功能测试”，不确定的直接使用“功能测试”。
     - 用例的“优先级”与需求的优先级无对应关系，严格遵循 `general-testcases-standard.md` 文档描述分配。
     - 用例的“步骤”与“预期结果”需要一一对应，数量一致。
     - 生成的测试用例文件名称带下时间戳，例如“web平台系统测试用例_20260416”。
  3. **需求问题**：如果需求前后矛盾或者缺少一些必要的业务逻辑形成闭环，测试用例“备注”字段里面可以说明。
  4. **用例覆盖**：需要尽可能覆盖更多的场景，包括不限于 `general-testcases-standard.md` 提到的，也可以补充一些其它场景。

- 「生成Excel测试用例」
