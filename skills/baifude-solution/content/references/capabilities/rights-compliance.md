# 权益合规

- **能力 ID**：BFD-006
- **所属模块**：商城交付 / 合规与风控
- **适用场景**：
  - 不同员工/部门/职级享受不同权益池（如管理层可见高端商品，普通员工不可见）
  - 部分频道是 H5 引入的三方供给（如外部品牌商入驻），需要控制"所见即所购"的合规风险
  - 员工福利涉及税务合规（个税申报、福利费 vs 工资科目）
  - 个保法（PII 数据保护）下的权益可见性管理
- **核心功能**：
  权益合规分为 **2 个层面**：
  1. **商城所见权益管控** — 客户可在百福得后台配置不同员工群体可见的权益/商品/品牌
     - 自有商品池：所见即所购，权益完全可控
     - **H5 引入的三方供给**：所见层面**存在漏出可能**（即员工可能看到不在权益范围内的商品）
     - 建议对三方供给频道做"白名单 + 关键词过滤"双重管控
  2. **开票所得合规管控** — 双保险机制：
     - **支付环节校验**：即便员工看到了非权益商品，支付资金会被再次校验是否允许消费该商品品类
     - **开票环节兜底**：若支付环节也漏过，最终在开票环节可申请**财务调整账单**变更为合规的开票信息
- **客户价值**：
  - 业务价值：避免"员工看到不该看的商品""购买不该买的品类"带来的合规纠纷和员工投诉
  - 数字化价值：所见 → 支付 → 开票三层兜底，最大限度降低合规风险
- **对接要求**：
  - 单点登录：与 BFD-002 组织管理联动（权益可见性依赖员工身份/部门/职级）
  - 数据接口：客户需提供权益分层规则（如"管理层 / 骨干员工 / 普通员工"三档）
  - 实施周期：1-2 周（规则配置 + 三方频道审核）
- **典型客户场景**：
  - 场景 1：某金融企业要求"管理层可见高端体检套餐，普通员工不可见" → **商城所见权益管控** + 员工职级字段
  - 场景 2：客户部分频道接入三方品牌商 H5，担心员工看到非权益商品后投诉 → 启用 H5 频道白名单 + 支付环节校验
  - 场景 3：某集团客户曾出现员工用福利积分购买非福利类商品，引发财务合规问题 → 启用支付环节校验 + 开票调整
- **注意事项 / 限制**：
  - **H5 三方供给的所见漏出是已知技术限制**，无法完全消除，只能通过"白名单 + 关键词过滤 + 支付校验 + 开票兜底"组合降低风险
  - 客户必须在合同/管理后台明确三方频道的合规责任划分
  - "开票调整账单"需要客户财务团队介入，**不是自动调整**，需要人工审核
  - 权益分层越细（员工/部门/职级/入职年限/绩效等级等），配置工作量越大；建议早期聚焦 2-3 个核心分层维度
- **关联能力**：
  - 强关联：BFD-003 多终端交付（H5 三方供给是漏出风险源头）
  - 强关联：BFD-002 组织管理（权益分层依赖组织数据）
  - 关联：BFD-008 售后（合规争议场景下的售后处理需走特殊流程）
  - 关联：BFD-009 结算开票（开票环节的合规调整能力，特别是 BFD-009 §开票所得合规管控）
