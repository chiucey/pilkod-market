# 基础数据管理（商品输出）

- **能力 ID**：BFD-104
- **所属模块**：商品输出 / 数据
- **父能力**：BFD-099 商品输出
- **适用场景**：
  - 客户需要统一管理商品输出模式下的**基础映射数据**（分类/品牌/地址库等）
  - 这些映射数据是 BFD-100/101 等能力的"**前置数据**"——没有这些映射，下游的订单、履约、售后都无法正确流转
  - 客户需要查看"我司和百福得之间所有映射数据的总览"
  - 新项目需要新增映射数据域（如新增 SKU 编码映射、税务编码映射等）
- **核心功能**：
  集中管理商品输出模式下的**基础映射数据**，确保：
  1. **数据一致性** — 双方系统对同一映射的认知一致
  2. **数据变更可追溯** — 所有变更留有日志，可回溯
  3. **数据同步有明确规则** — T+1 同步、变更生效时间等规则明文约定
- **对接要求**：
  - 数据接口：取决于各数据域
  - 实施周期：与各子能力同步上线
  - 客户需提供：自有体系数据（分类树、品牌清单、地址库等）

## 3. 两种维护模式（通用约定）

**所有映射数据域都遵循这两种维护模式**：

### 3.1 标准化对接（轻量）
- 客户根据百福得的数据**自己做映射管理**
- 适合：客户 IT 能力强、映射关系稳定
- 百福得提供数据接口，客户调用并维护映射关系
- 维护责任：**客户侧**

### 3.2 定制对接（重）
- 由**百福得维护**双方映射关系
- 适合：客户自有体系复杂、变动频繁、想减少对接工作量
- 维护责任：**百福得侧**

**售前必讲**：
- 售前阶段与客户 IT 评估选择哪种模式
- 模式选定后写入对接方案
- 后续模式升级需双方确认

---

## 4. 同步与变更规则

### 4.1 同步时效
- 所有映射数据同步有 **T+1 缓存延迟**（不是实时）
- 即：客户或百福得变更映射 → 次日生效

### 4.2 变更生效
- 任何映射变更需**双方约定生效时间**
- 变更前需充分沟通（避免影响在途订单）
- 大批量变更建议**灰度**（先 10% 流量，再全量）

### 4.3 历史追溯
- 所有映射变更需保留**变更日志**（谁、何时、改了什么）
- 历史数据保留**建议 ≥ 1 年**（满足审计需要）

### 4.4 数据导出
- 支持客户导出当前全量映射数据
- 用途：客户内部对账、合规审计

- 场景 1：客户 IT 想查看"我们和百福得之间所有映射数据的总览" → **BFD-104 数据看板**

## 6. 注意事项 / 限制

- **T+1 缓存延迟**：映射变更不是实时生效，紧急改映射无法秒级生效
- **维护责任划分**：标准化对接下客户自维护；定制对接下百福得维护——**售前必须明确**
- **历史数据回溯**：已发生的订单用"**下单时点的映射**"为准，事后修改映射**不影响历史订单**
- **跨系统同步**：映射数据需在客户系统、百福得系统双方一致，**任何单方变更无效**
- **多套映射体系**：客户可能同时有多套（如商品分类 + 业务分类），需分别建立映射
- **数据安全**：映射数据可能涉及敏感信息（地址、品牌授权），需评估数据安全等级
