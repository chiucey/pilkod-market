# 商品输出（核心能力）

- **能力 ID**：BFD-100
- **所属模块**：商品输出 / 核心能力
- **父能力**：BFD-099 商品输出（本文件是其核心子能力详细规范）
- **适用场景**：
  - 客户有自己的商品分类/品牌体系，需要百福得输出的商品能归类到客户的体系下
  - 客户需要百福得按"一口价"或"原价打折"两种定价方式供货
  - 客户需要灵活管理"百福得供给什么商品"，按客户/渠道差异化选品
- **核心功能**：
  百福得提供 3 大子能力：
  1. **客户分类体系管理** — 完成客户商品分类与百福得商品分类的关联映射
  2. **客户品牌管理** — 完成客户品牌体系与百福得商品品牌的映射
  3. **客户选品池管理** — 选品 + 定价管理
- **对接要求**：
  - 实施周期：1-2 周（标准化对接）；2-4 周（定制对接）
  - 客户需提供自己的商品分类体系与品牌体系清单

---

## 1. 客户分类体系管理

**用途**：百福得的商品同步给客户后，能归属到客户对应的分类下。

> **数据管理层归口**：本节定义的"分类映射数据"实际存储与管理在 **BFD-104 基础数据管理** 中；本文件仅描述"分类对接"的业务逻辑与对接模式。

**两种对接模式**：
- **标准化对接**（轻量）：
  - 客户根据百福得的分类，**自己做类目映射管理**
  - 适合客户有较强技术能力、自有分类体系稳定
  - 百福得提供分类树接口，客户调用并维护映射关系
- **定制对接**（重）：
  - 由**百福得维护管理**双方的分类映射关系
  - 适合客户自有分类体系复杂、变动频繁、且希望减少对接工作量
  - 维护责任在百福得侧

**典型用法**：
- 客户 A 的分类是"美食 / 数码 / 家居 / 服饰"
- 百福得分类是"食品生鲜 / 3C数码 / 家居日用 / 服装鞋包"
- 双方需要建立映射："美食" → "食品生鲜"、"数码" → "3C数码" 等

---

## 2. 客户品牌管理

**用途**：同"客户分类体系管理"，需要百福得输出商品能对应到客户的品牌下。

> **数据管理层归口**：本节定义的"品牌映射数据"实际存储与管理在 **BFD-104 基础数据管理** 中。

**两种对接模式**：与"客户分类体系管理"一致
- **标准化对接**：客户自己做品牌映射
- **定制对接**：百福得维护映射

**典型用法**：
- 客户自有品牌体系（如"严选 / 自营 / 第三方"）
- 百福得商品挂的是"百福得自营 + 合作品牌商"
- 需映射：百福得自营 → 客户自营、合作品牌商 → 客户第三方

---

## 3. 客户选品池管理

**用途**：给每个客户选定需要输出的商品范围，并管理价格。

**两大职能**：

### 3.1 选品
- **每个客户独立选品**：通过系统给每个客户管理商品信息
- **对客输出同步管理**：客户选定的商品池，**自动同步**到客户的商品库
- 常见选品维度：
  - 客户类型（如 VIP 客户 vs 普通客户）
  - 渠道（线上商城 vs 线下门店）
  - 节日/活动（中秋商品池、春节商品池）

### 3.2 定价
支持 **2 种定价规则**：
- **一口价**：每个 SKU 固定一个对客售价
- **原价打折**：基于百福得原价，按折扣率计算对客售价
  - 例：原价 100 元，折扣率 0.8 → 对客售价 80 元

**注意事项**：
- 同商品对不同客户可以**配置不同价格**（差异化定价）
- 定价调整后，**对客输出同步**有缓存延迟（参考 BFD-099 一般约定）

---

## 4. 典型客户场景

- 场景 1：某连锁便利店自营商城，商品分类是"美食/数码/家居/服饰"，需要百福得商品归类 → **客户分类体系管理（标准化对接）**
- 场景 2：某高端百货自营平台，有"严选/自营/第三方"品牌分级 → **客户品牌管理（定制对接）**
- 场景 3：某集团多子公司，不同子公司要不同商品池 + 不同价格 → **客户选品池管理（差异化选品 + 差异化定价）**

---

## 5. 注意事项 / 限制

- **标准化 vs 定制对接**的选择，建议售前阶段与客户 IT 评估：
  - 客户分类/品牌体系稳定 → 标准化对接（成本低、维护灵活）
  - 客户分类/品牌体系复杂、变动频繁 → 定制对接（百福得兜底维护）
- **分类/品牌映射变更**的同步：通常有 T+1 缓存延迟，需提前与客户确认
- **多套分类体系**：如客户有"商品分类 + 业务分类"两套，需要分别建立映射
- **跨类目商品**：部分商品同时属于多个类目，映射时需明确主类目和副类目关系
- **品牌授权**：品牌映射涉及品牌方授权，**需提前确认客户是否取得品牌方授权**

---

## 6. 关联能力

- 父能力：BFD-099 商品输出
- 强关联：BFD-101 分销订单（分类/品牌映射结果是订单流转的前置）
- 强关联：BFD-104 基础数据管理（待补充，分类/品牌映射数据需要同步到数据看板）
- 联动：BFD-009 结算开票（不同品牌/分类的商品可能有不同税率）
