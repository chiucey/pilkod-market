# 商城交付

- **能力 ID**：BFD-001
- **所属模块**：交付方式（顶层）
- **适用场景**：
  - 客户希望员工在一个完整商城内浏览、自选、兑换福利商品的场景
  - 客户有持续的福利发放节奏（节日/季度/年度），需要一个长期运营阵地而非一次性活动
  - 客户希望 HR / 福利管理员有统一的后台进行预算分配、订单管理与数据复盘
- **核心功能**：
  1. 提供完整的福利商城交付能力，覆盖员工从领取 → 选品 → 下单 → 履约 → 售后的全链路
  2. 支持企业根据自身组织架构、预算规则、权益政策灵活配置商城内容与可用人群
  3. 员工在多终端（App / 小程序 / H5）登录后按权限看到对应的商品与权益
- **客户价值**：
  - 业务价值：把"发什么福利"的选择权部分交给员工，提升员工满意度；同时 HR 端有统一管理台，运营效率高
  - 数字化价值：福利发放数据全链路留痕，可对账、可审计、可量化效果
- **对接要求**：
  - 单点登录：取决于"组织管理"能力的对接方案（人工 / SSO / OpenAPI / 客制化）
  - 数据接口：员工花名册、组织架构、预算总额、权益规则
  - 实施周期：标准方案 2-4 周上线；客制化方案 6-12 周
- **典型客户场景**（1-2 个）：
  - 场景 1：某 2000 人互联网公司，需要覆盖入职-在岗-离职全周期员工福利，选择"商城交付"作为统一阵地，配合"节日福利 + 弹性福利"组合
  - 场景 2：某 500 人制造企业，中秋节需要快速上线福利发放，选择"商城交付"标准方案，1 周内开通，员工在小程序内自选月饼礼盒
- **注意事项 / 限制**：
  - 商城交付 vs 商品输出：前者是完整商城（含运营管理后台、订单管理、对账），后者偏向纯商品供应，无商城运营阵地
  - 涉及个保法的客户，建议提前梳理 PII 数据流转范围
  - 客户组织架构频繁变动（> 每月一次）建议优先用 OpenAPI / SSO 自动同步，而非人工入离调转
- **关联能力**：
  - 强关联：BFD-002 组织管理（商城前必须解决"谁能进商城"）、BFD-003 多终端交付（员工从哪个入口访问）、BFD-004 资金形式（员工用什么资产下单）
  - 兄弟能力：BFD-099 商品输出（另一种顶层交付方式，已落库）
