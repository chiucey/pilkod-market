# 商品输出

- **能力 ID**：BFD-099
- **所属模块**：交付方式（顶层）
- **适用场景**：
  - 客户已有自己的电商/福利平台，希望百福得仅提供**商品供应能力**，无需百福得提供完整商城
  - 客户作为分销商/渠道商，希望通过百福得供货（采购/履约），自行承担订单管理与客户运营
  - 客户希望以"**商品采购 + 履约**"的轻模式合作，避免商城运营复杂度
  - 客户希望快速触达商品资源（如节日礼品集采），无需长期运营阵地
  - 客户需要稳定的供应链支撑（如员工节日福利的实物采购），不需要完整的数字化福利平台
- **核心功能**：
  百福得作为**商品供应商 + 履约方**，提供以下 5 大子能力：
  1. **商品输出**（BFD-100）— 客户分类/品牌/选品定价管理，详见 `product-output-core.md`
  2. **分销订单**（BFD-101）— 地址库/下单校验/预下单/正式订单/多主体拆账单，详见 `distribution-orders.md`
  3. **发货物流**（BFD-102）— 发货通知/物流轨迹/妥投拒收状态，详见 `shipping-logistics.md`
  4. **售后**（BFD-103）— 4 种售后场景（仅退款/退货退款/换货/补发），**必须签收后才能售后**，详见 `after-sales-product-output.md`
  5. **基础数据管理**（BFD-104）— 分类/品牌/地址库等映射数据集中管理，详见 `basic-data-management.md`
- **客户价值**：
  - 业务价值：客户无需自建商品供应链，即可快速触达大量优质福利商品；运营复杂度大幅降低
  - 数字化价值：商品/订单/履约数据标准化输出，便于客户对接自有系统
- **对接要求**：
  - 单点登录：**通常不需要**（商品输出模式不涉及百福得员工账号体系）
  - 数据接口：取决于具体子能力（分销订单、履约跟踪、售后等需要客户与百福得约定 API）
  - 实施周期：取决于合作深度；轻量合作 1-2 周，深度对接 4-8 周
- **典型客户场景**：
  - 场景 1：某集团 HR 部门希望为员工采购中秋福利礼盒，但不想运营完整商城 → **商品输出**模式，百福得提供礼盒 + 履约 + 基础订单数据
  - 场景 2：某电商平台已自营员工福利频道，需要稳定的福利商品供应链 → **商品输出**模式，百福得供货 + 履约，订单走电商平台
  - 场景 3：某连锁企业每年节日需采购大量员工礼品，需要长期稳定的供应商 → **商品输出**模式，按需集采 + 履约
- **注意事项 / 限制**：
  - **商品输出 vs 商城交付 是两种不同的顶层模式**，二选一（或组合）：
    - 商城交付（BFD-001）：百福得提供完整商城 + 履约 + 售后 + 数据
    - 商品输出（BFD-099）：百福得仅提供商品 + 履约，**不提供商城阵地**
  - 客户选择商品输出时，**员工账户、组织架构、预算发放、权益合规**等"商城运营"相关能力（BFD-002/005/006/010）**不适用**
  - 售后的责任划分取决于具体合作模式（BFD-103 待补充）
  - 商品输出涉及税务合规（百福得作为供应商开具发票），与商城交付的资金流向不同
- **关联能力**：
  - 兄弟能力：BFD-001 商城交付（另一种顶层交付方式）
  - 子能力：
    - BFD-100 商品输出（核心能力）✅
    - BFD-101 分销订单 ✅
    - BFD-102 发货物流 ✅
    - BFD-103 售后（商品输出上下文）✅
    - BFD-104 基础数据管理 ✅
  - 强关联：BFD-009 结算开票（商品采购对账与开票依赖此能力，BFD-099 模式下开专票是默认模式）
  - 不适用：BFD-002/003/004/005/006/010/011/012/013（这些都是"商城运营"相关能力，商品输出模式不需要）
