# 三方积分转福豆

- **能力 ID**：BFD-013
- **所属模块**：商城交付 / 支付与资产 / 资金形式变体
- **父能力**：BFD-004 资金形式（4 种形式之一）
- **适用场景**：
  - 客户有自有积分体系，希望员工通过"三方积分兑换福豆"路径在百福得商城消费
  - 客户希望规避"退款反向回退到客户积分体系"的复杂性（一旦兑换**不可逆**）
  - 适合福利场景相对简单、不涉及复杂多次退款的客户
  - 客户研发投入有限，不希望实现 4 个完整 API
- **核心功能**：
  复用 BFD-011 三方积分对接规范的 **3 个 API**（余额查询 / 余额扣减 / 支付结果查询），**省略退款接口**。
  业务流程：员工把客户三方积分兑换为福豆 → 福豆充值到员工百福得账户 → 员工用福豆在商城消费 → 退款时福豆退回员工福豆账户（**不退回客户三方积分**）。
- **对接要求**：
  - 单点登录：与 BFD-002 组织管理联动
  - 数据接口：复用 BFD-011 的 3 个 API，**不实现积分退款接口**
  - 兑换比：客户与百福得商务约定（通常 1:1，部分客户按 1 积分 = X 福豆）
  - 实施周期：**1-2 周**（比完整 BFD-011 短，因为少了退款接口的开发与联调）
- **典型客户场景**：
  - 场景 1：某零售客户希望员工用会员积分兑换福豆后消费，担心会员积分体系对接退款接口的复杂度 → 推荐**三方积分转福豆**
  - 场景 2：某银行客户已有信用卡积分，希望员工兑换成福豆后用于节日福利购买，兑换单向不可逆 → 推荐**三方积分转福豆**
  - 场景 3：客户福利发放流程简单（一年 1-2 次），不需要精细化多次退款 → 推荐**三方积分转福豆**（实施更轻）
- **注意事项 / 限制**：
  - ⚠️ **兑换不可逆**：员工通过此路径兑换的福豆**不能反向退回到客户的三方积分**
  - ⚠️ **退款只能走"福豆退到福豆账户"路径**，**不能退到客户积分体系**
  - ⚠️ **客户积分扣减 = 客户积分"消耗"**：扣减接口触发后，客户积分被实际扣减，**不再属于员工**（这与 BFD-011 的"代扣代付"语义不同）
  - ⚠️ **多类型积分场景**：如客户有多种积分，建议**每种积分单独对接**（不要混在一起转福豆），便于后续对账
  - ⚠️ **兑换汇率风险**：如客户积分有通胀/贬值风险，建议在兑换时锁定汇率
  - 适合福利场景简单、不涉及复杂多次退款的客户；**多次退款场景强烈建议升级到完整 BFD-011**
  - 客户已实现的 BFD-011 退款接口**可后续追加**（不破坏既有对接）
- **与 BFD-011 完整三方积分的差异**：

| 维度 | BFD-011 完整三方积分 | BFD-013 三方积分转福豆 |
| --- | --- | --- |
| API 数量 | 4 个（必选） | **3 个**（必选） |
| 退款路径 | 福豆退 → 客户三方积分 | **仅福豆退 → 福豆账户**（不退回客户积分） |
| 客户积分体系状态 | 积分始终在客户系统内，扣减/退还都在客户侧 | 兑换后积分**永久消耗**，不再属于客户系统 |
| 适用退款复杂度 | 高（支持多次部分退款 + 复杂对账） | 低（福豆账户内部对账即可） |
| 实施周期 | 2-3 周 | **1-2 周** |
| 联调复杂度 | 高 | 中 |

- **关联能力**：
  - 强关联：BFD-004 资金形式（业务定位为第 4 种资金形式）
  - 复用：BFD-011 三方积分对接规范（3 个 API 的技术实现细节）
  - 适用：BFD-008 售后的"福豆退款"路径（福豆内部账户的退款仍走标准售后）
  - 关联：BFD-002 组织管理（账号体系一致是前置）
