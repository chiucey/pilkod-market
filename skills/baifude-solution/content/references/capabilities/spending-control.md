# 费控管理

- **能力 ID**：BFD-010
- **所属模块**：商城交付 / 消费控制
- **适用场景**：
  - 食堂/餐补类福利：限制员工每天只能在指定时间段（如 11:00-14:00）使用餐补，避免乱用
  - 加班餐补：限制每次消费金额，避免单次突击消费
  - 福利预算分摊：避免员工在月初突击用完全月福利
  - 现金+福利混合支付场景：要求每笔订单必须含一定比例的现金支付，避免"全额福利支付"的合规风险
  - 福利积分"留底保护"：要求员工消费后账户里必须保留最低额度的福利积分，避免积分被一次性耗尽或被套利
- **不在费控范围内**（属于商城通用 UI 功能，不算费控规则）：
  - 员工下单前看到"今天还能消费多少""这个月剩余多少"等**余额展示**——这是商城默认提供的可视化能力，与上述 6 条费控规则无直接关系
- **核心功能**：
  支持 **6 种费控规则**，可按客户需求灵活组合：
  1. **限次消费** — 每日或指定时间段内，限制消费次数（如"午餐时段最多刷 1 次"）
  2. **每单消费限额** — 单笔订单最高金额限制
  3. **每日消费限额** — 当日累计消费上限
  4. **每月消费限额** — 当月累计消费上限（按自然月或按发放周期）
  5. **每笔消费的最低现金占比** — 每笔订单中现金支付必须占一定比例（合规/反套利场景）
  6. **每笔消费的最低剩余积分** — 每笔消费使用福利积分后，账户剩余积分**必须不低于**此阈值，否则**不允许消费支付**
     - 性质：**控制型规则**（强制拦截），不是单纯的展示
     - 典型用法：设置最低留底 100 积分，员工有 500 积分 → 想花 450 → 消费后剩余 50（< 100）→ **拦截，不允许支付**
     - 员工需调整消费金额（如改成花 400）使剩余 ≥ 100 → 才允许支付
     - 业务目的：保护性留底，避免员工一次性耗尽所有积分/被套利路径用尽
- **客户价值**：
  - 业务价值：精细化管控福利资金使用节奏，避免"月初秒光、月底没福利"的尴尬，也避免员工突击套现；规则 6 进一步防止积分被一次性耗尽
  - 数字化价值：所有规则配置化，无需研发改代码即可调整；规则触发有日志可审计
- **对接要求**：
  - 单点登录：与 BFD-002 组织管理联动（费控规则通常按员工/部门/职级差异化配置）
  - 数据接口：无需外部接口，所有规则在百福得后台配置
  - 实施周期：1-2 周（规则配置 + 灰度上线）
- **典型客户场景**：
  - 场景 1：某制造企业发放员工餐补，要求每天最多刷 1 次、单笔不超过 50 元、每月不超过 800 元 → 启用规则 1+2+4
  - 场景 2：某互联网公司发放"弹性福利积分"，要求每笔订单至少含 20% 现金支付（合规要求福利不能全额覆盖消费）→ 启用规则 5
  - 场景 3：某集团统一发放月度福利（如每人 1000 积分/月），要求员工不能把当月积分一次性花光（保留至少 100 积分）→ 启用规则 6
  - 场景 4：某金融客户担心员工通过"小额多次刷光积分 → 套利"路径，要求账户最低保留 50 积分 → 启用规则 6
- **注意事项 / 限制**：
  - 6 种规则**可任意组合**（勾选式配置），不强制全部启用
  - "指定时间段"由客户在后台配置，**常见用法是午晚餐时段**，但也支持自定义（如"夜班补贴仅 22:00-02:00 可用"）
  - "最低现金占比"通常配合"三方收银台"或"现金+福豆混合支付"场景，纯福豆支付场景下不适用
  - **规则 6（最低剩余积分）是"控制型"规则**，与展示类规则不同：
    - 下单时强制校验：消费后剩余积分 < 阈值 → 拦截支付
    - 员工需调整消费金额使剩余 ≥ 阈值 → 才允许支付
    - 阈值建议设置在月额度的 5-15%（如月 1000 积分 → 阈值 50-150），过高会显著限制消费体验
  - 规则按**员工 / 部门 / 职级** 三个维度可差异化配置，配置工作量与组织规模正相关
  - 规则触发后**实时生效**，但有 1-2 分钟的缓存延迟（非秒级）
- **关联能力**：
  - 强关联：BFD-004 资金形式（费控规则作用于实际支付行为）
  - 强关联：BFD-005 福利预算发放管理（费控是"发出去之后怎么花"的控制）
  - 适用边界：目前主要应用于"商城交付"场景；"商品输出"场景是否适用待补充
