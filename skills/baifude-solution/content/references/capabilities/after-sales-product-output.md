# 售后（商品输出）

- **能力 ID**：BFD-103
- **所属模块**：商品输出 / 售后
- **父能力**：BFD-099 商品输出
- **兄弟能力**：BFD-008 售后（商城交付上下文，本文件是商品输出上下文）
- **适用场景**：
  - 员工/客户在客户商城下单后，发起售后（仅退款/退货退款/换货/补发）
  - 客户需要将售后单同步给百福得执行
- **核心功能**：
  百福得支持 **4 种售后场景**：
  1. **仅退款** — 不退货直接退款
  2. **退货退款** — 客户退货，百福得退款
  3. **换货** — 客户换同款/不同款
  4. **补发** — 漏发/丢失的补发
- **对接要求**：
  - 数据接口：售后单创建、售后单状态同步
  - 实施周期：1-2 周

---

## 1. 4 种售后场景

### 1.1 仅退款
- **场景**：商品问题但不要求退货（如发错货但客户不想换）
- **流程**：客户发起仅退款 → 百福得审核 → 退款给客户
- **典型**：发错口味但客户不想要、轻微瑕疵但不影响使用

### 1.2 退货退款
- **场景**：商品有问题需要退回
- **流程**：客户发起退货退款 → 百福得审核 → 客户退货 → 百福得收货验收 → 退款给客户
- **典型**：商品质量问题、商品损坏

### 1.3 换货
- **场景**：客户想换成同款或不同款
- **流程**：客户发起换货 → 百福得审核 → 客户退回原商品 → 百福得发出新商品
- **典型**：尺码不对换尺码、颜色不喜欢换颜色

### 1.4 补发
- **场景**：商品漏发/丢失需要补发
- **流程**：客户发起补发 → 百福得审核 → 重新发出商品
- **典型**：快递丢失、漏发

---

## 2. ⚠️ 关键约束：必须签收后才能售后

**硬性限制**：
- **现阶段，百福得售后单提交有条件限制——必须要求签收后才能进行售后**
- **未签收的订单无法在线对接进来售后单**

**业务原因**：
- 避免客户在快递途中发起售后，导致履约与售后冲突
- 避免重复发货/退款争议

**售前必须告知客户**：
- 客户 IT 在设计售后流程时，**必须校验订单是否已签收**（通过 BFD-102 物流状态查询）
- 未签收订单不向用户展示"申请售后"按钮
- 特殊紧急场景（如快递明显丢失超过 X 天）需走人工流程

---

## 3. 典型客户场景

- 场景 1：客户自营商城，员工申请"商品质量问题退货退款" → **退货退款**（订单已签收）
- 场景 2：员工收到礼盒发现破损，发起"换货"→ **换货**（订单已签收）
- 场景 3：员工订单显示已签收但实际未收到，客服核查后发起"补发" → **补发**（订单已签收）
- 场景 4：员工不想要某件商品但已签收，发起"仅退款"（协商） → **仅退款**（订单已签收）

---

## 4. 注意事项 / 限制

- **必须签收后才可售后**（硬性限制）：
  - 售前必须明确告知客户 IT
  - 客户系统需对接 BFD-102 物流状态，签收后才显示"申请售后"入口
- **4 种场景不能同时发起**：
  - 一次只能选一种售后类型
  - 部分退款 vs 整单退款：商品输出模式下通常按**单 SKU 维度**发起售后（参考 BFD-008 的"分批退款"机制）
- **退货运费**：
  - 质量问题：百福得承担
  - 客户原因（如不喜欢）：客户承担
  - 具体由商务合同约定
- **补发时效**：
  - 补发与正常发货流程相同，受发货时效约束
- **退款路径**：
  - 商品输出模式下，资金走"客户→客户收银台→百福得"或类似路径
  - 退款原路返回（联动 BFD-101 订单状态）
- **跨境/特殊品类**：
  - 跨境商品退货涉及海关，限制较多
  - 食品/化妆品/定制商品通常不支持退货（只能补发或仅退款）

---

## 5. 售前必讲清单

- [ ] 客户 IT 是否已实现订单签收状态校验（依赖 BFD-102 物流状态）
- [ ] 客户是否接受"必须签收后才能售后"的限制
- [ ] 4 种售后场景是否都需要支持（部分客户可能只用其中 1-2 种）
- [ ] 退货运费承担方（质量原因 vs 客户原因）
- [ ] 单 SKU 维度发起售后的实现方式
- [ ] 跨境/特殊品类的售后限制
