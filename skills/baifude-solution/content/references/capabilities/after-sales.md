# 售后

- **能力 ID**：BFD-008
- **所属模块**：商城交付 / 售后
- **适用场景**：
  - 员工下单后，部分商品缺货/需要分批发货
  - 员工对部分商品不满意，需要部分退款（非整单取消）
  - 客户财务与百福得对账时，需要按 SKU 维度核对退款
- **核心功能**：
  百福得售后的核心约束：
  1. **不支持整单退款** — 订单一旦生成，**不能整单取消/全退**
  2. **必须支持分批多次退款** — 客户方系统**必须**具备按 SKU 维度**分批多次退款**的能力
- **客户价值**：
  - 业务价值：避免"员工下单后整单退掉、把福豆提现"的套利路径
  - 数字化价值：每笔退款有独立记录，便于财务对账
- **对接要求**：
  - 单点登录：与 BFD-002 组织管理联动（售后发起人 = 下单人 / HR）
  - 数据接口：客户侧系统必须支持按 SKU 调用百福得退款 API（**这是前置硬性要求**）
  - 实施周期：上线前需确认客户侧退款接口，1-2 周联调
- **典型客户场景**：
  - 场景 1：员工下了 5 件商品，其中 1 件缺货 → HR 通过客户系统发起该 SKU 的单独退款，不影响其他 4 件履约
  - 场景 2：员工对某件商品不满意 → 发起单 SKU 退款
  - 场景 3：客户财务月末对账 → 汇总当月所有 SKU 维度退款明细
- **注意事项 / 限制**：
  - ⚠️ **硬性限制**：客户系统**必须**支持分批多次退款，否则无法接入百福得售后流程
  - 售前阶段必须明确告知客户此限制；客户侧若无该能力，需先建设
  - 退款涉及的支付通道：福豆退款直接退回福豆账户；现金/三方收银台退款走原通道
  - 退款时效：福豆实时退回；现金/三方收银台按支付通道正常时效（一般 1-7 个工作日）
  - 售后与权益合规（BFD-006）联动：合规争议场景下的售后处理需走特殊审批流程
- **关联能力**：
  - 强关联：BFD-004 资金形式（退款路径依赖资金形式）
  - 强关联：BFD-006 权益合规（合规争议下的售后处理）
  - 关联：BFD-009 结算开票（退款后需调整开票信息，专票场景下需重新出票）
