# Baifude Solution

## Inputs to collect
- 客户问题原文（必填）
- 客户所属行业 & 员工规模（售前/方案类问题建议追问，否则只能给通用方案）
- 已知技术约束或合规要求（技术对接类问题需要，例如"已用飞书"、"需要等保三级"）
- 是否需要落地为方案书文档（默认在对话中输出结构化方案；如客户要留存/分发，再生成 .md 文件）

## Procedure
1. **分类问题类型**：售前咨询 / 技术支持 / 方案设计
   原因：三类问题使用的输出模板分支不同，先分类才能选对模板；售前侧重能力匹配与价值，技术侧重排查路径与对接方式，方案侧重组合设计与落地步骤。
2. **提取客户需求关键词**：行业、规模、痛点、场景、合规要求、技术栈
   原因：关键词决定下一步检索哪些能力条目；写不清关键词就只能给空泛回答。
3. **读 `references/capabilities/_index.md`** 获取当前能力清单
   原因：先看清单再决定要不要读详情，避免把整个知识库塞进 context。
4. **匹配 1-3 个最相关的能力**，按需读 `references/capabilities/<name>.md` 详情
   原因：能力详情可能很长（每个能力几百到上千字），按需读取能省 context 也更精准。
5. **按 `references/solution-template.md` 对应分支**生成结构化方案
   原因：保持输出一致性，方便销售/客户成功复用，也方便后续沉淀为案例库。
6. **标注匹配置信度**：高（能力库明确覆盖）/ 中（能力库部分覆盖，需补充信息）/ 低（能力库未覆盖，需澄清或升级）
   原因：避免在不靠谱的匹配上过度承诺；低置信度时要主动说"当前能力库未覆盖，建议补充能力条目或转人工"。

## Output contract
- 在对话中直接输出结构化方案（markdown）
- 必须包含：客户诉求理解、推荐能力（标注来源能力 ID）、推荐理由、落地/排查步骤、风险或前提
- 售前/方案类必须包含"下一步行动建议"（演示/POC/商务对接/签约）
- 技术类必须包含"升级路径"（如需研发介入该找谁）
- 如果用户要求落盘：用 `write` 工具保存为 `方案_<客户或场景名>_<YYYYMMDD>.md`

## Failure handling
- **知识库无匹配** → 明确告诉用户"当前能力库中未覆盖 XX 场景，建议补充能力条目或转人工"，不要硬凑
- **客户问题模糊** → 追问关键信息（行业/规模/核心痛点），不假设前提硬给方案
- **多能力组合存在矛盾** → 在方案中加"约束与权衡"一节，说明取舍
- **问题不在百福得能力范围** → 礼貌告知不适用，并给出 1-2 个一般性建议作为兜底
- **能力库信息过期或缺失** → 在方案末尾标注"⚠️ 本方案基于现有能力库，平台能力以最新产品文档为准"

## Examples

**Input 1（售前类）**：
> 我们公司 500 人，想给员工发中秋福利礼品，有没有合适的方案？

**Output 1**：售前模板分支，匹配"节日福利"+"礼品卡券"等能力，输出含客户背景、推荐能力组合、推荐理由、预期效果、下一步（演示/试用）。

**Input 2（技术类）**：
> 我们接入了百福得的 SSO，登录一直报 401，怎么排查？

**Output 2**：技术模板分支，匹配"SSO 对接"能力，输出含问题描述、涉及能力、排查路径（参数/证书/回调）、常见原因、升级路径（找谁）。

**Input 3（方案类）**：
> 客户是一家互联网公司，2000 人，想要一套覆盖入职-在岗-离职全周期的员工激励方案，怎么设计？

**Output 3**：方案模板分支，匹配多个能力组合（如入职礼包+弹性福利+长期激励+离职关怀），输出含架构示意、落地步骤、约束与权衡、预估投入。
