# WBS生成器

从项目文本描述中提取关键信息，生成符合行业标准的项目工作分解结构。

## 输入要求

用户提供包含以下信息的项目描述文本：
- 项目名称和目标
- 项目范围和交付物
- 时间约束（如有）
- 资源约束（如有）
- 行业领域

## 核心流程

### 1. 信息提取

从输入文本中提取以下关键要素：

| 要素类型 | 说明 |
|---------|------|
| 项目元数据 | 名称、类型、行业领域、生命周期阶段 |
| 范围边界 | 包含内容、不包含内容 |
| 交付物 | 可交付成果、中间产物 |
| 约束条件 | 时间、资源、技术、质量 |
| 利益相关方 | 客户、团队、供应商 |

### 2. WBS层次结构设计

遵循行业标准的WBS设计原则：

```
Level 1: 项目 (Project)
├── Level 2: 项目阶段/工作包组 (Phase/Work Package Group)
│   ├── Level 3: 可交付成果 (Deliverable)
│   │   ├── Level 4: 工作包 (Work Package)
│   │   │   └── Level 5: 活动/任务 (Activity/Task)
```

### 3. 工作包定义

每个工作包应包含：

```yaml
工作包标识: [WBS编码]
工作包名称: [描述性名称]
工作包描述: [详细说明]
负责角色: [执行责任人]
前置条件: [依赖关系]
交付物: [可交付成果]
估计工时: [估算值]
验收标准: [完成标准]
```

## WBS设计原则

### 必须遵循

1. **100%原则**: 包含所有项目工作，子层次之和完整覆盖父层次
2. **功能导向**: 按交付物/功能分解，而非按组织或日程
3. **可管理单元**: 工作包建议工时 4-80 小时
4. **唯一归属**: 每个工作包有且只有一个责任人
5. **独立可交付**: 工作包应产生明确的交付物

### 建议遵循

1. **编码一致性**: 采用等长数字编码 (1, 1.1, 1.1.1)
2. **命名规范**: 使用动词+名词结构 ([动词] + [对象])
3. **层次合理**: 一般不超过5层，核心3-4层
4. **平行结构**: 同级工作包应有类似的颗粒度

## 行业适配

根据不同行业，自动应用相应的标准模板：

| 行业 | 标准/规范 | 特殊考虑 |
|------|----------|---------|
| 软件开发 | PMBOK, 敏捷实践 | Sprint周期、迭代交付 |
| 工程建设 | PMBOK, FIDIC | 里程碑、验收节点 |
| 制造业 | APQP, PMBOK | 质量控制点 |
| 咨询项目 | PMBOK | 阶段交付、文档交付 |
| 研发项目 | PMBOK, 门径流程 | 阶段门、技术评审点 |

## 触发方式

使用以下方式激活此技能：

1. 用户粘贴项目描述文本并要求生成WBS
2. 用户要求"分解项目工作"
3. 用户要求"制定项目计划任务清单"
4. 用户要求"生成项目里程碑"
5. 用户要求"规划项目阶段"

## 输出交付

完成处理后，提供：

1. **WBS总体视图**: Markdown格式的完整分解结构
2. **工作包详情表**: 每个工作包的详细定义
3. **任务清单**: 可直接用于项目管理的任务列表
4. **参考规范**: 所采用行业标准的说明

## 注意事项

- 若项目描述信息不足，标注需要补充的信息点
- 对于模糊的约束条件，使用合理的行业默认值
- 保持分解结构的逻辑一致性和可追溯性
