# 用例生成工作流

**触发关键词**：`生成测试用例`、`生成用例`、`根据测试点生成用例`、`根据需求生成用例`

**工作流简介**：支持两种场景生成测试用例：1. 根据需求直接生成用例；2. 根据测试点生成用例（以测试点为主，参考文档为辅）

## 执行清单规划

在开始执行前，工作流需要：
1. 使用 `todo_write` 工具创建执行清单，将下述执行步骤转化为 TODO 列表
2. 执行应该按照列表的顺序进行执行，禁止跳过步骤
3. 每完成一个步骤后，需检查步骤是否执行，检查通过后更新对应 TODO 的状态为 `completed`
3. 开始新步骤时，将对应 TODO 状态更新为 `in_progress`

**标准 TODO 清单模板**：

Demo:
```json
[
  {"id":"1", "status":"pending", "content":"step1"},
  {"id":"2", "status":"pending", "content":"step2"},
  ...
]
```

## 执行流程

**步骤 1：确认输入内容类型**

**重要**：需要识别用户的意图，确定是用例生成的场景

**场景识别**：
- **场景1：根据需求直接生成用例**
  - 用户输入：`生成需求ID为XXX的测试用例`
  - 用户输入：`根据需求生成测试用例`
  - 用户提供：需求ID、需求文档、需求内容

- **场景2：根据测试点生成用例**
  - 用户输入：`根据测试点生成测试用例`
  - 用户输入：`生成测试用例，测试点文件：XXX`
  - 用户提供：测试点文件路径、测试点内容

**识别方式**：
- 关键词识别：`测试点`、`测试点文件`
- 文件路径识别：用户提供了测试点文件路径（`.md`文件）

**步骤 2：获取需求信息**

**2.1 识别需求类型**
- **主需求**：用户明确要求生成测试用例的需求
- **参考需求**：用户提供作为参考的其他需求（关键词：`参考需求`、`参考`、`类似需求`）

**2.2 获取主需求内容**
- **方式一**：从对话上下文中读取（SKILL加载时已执行 load_session，结果在上下文中）
- **方式二**：使用 `load_session` 工具（位于 `tools/load_session.md`）读取会话信息
- **方式三**：使用 `search_nodes` 工具（位于 `tools/search_nodes.md`）从脑图查询 STORY 或 BUG 类型节点
- **方式四**：用户直接提供了TAPD需求ID或需求文档路径
  - **TAPD需求ID**：使用 `fetch_tapd_issue.py` 脚本获取需求内容
    - 执行：`python scripts/fetch_tapd_issue.py --issue-id <需求ID> --save --output markdown`
    - 保存位置：`.testbuddy/md/STORY-<需求ID>.md`
  - **需求文档路径**：直接读取用户提供的文档
    - 文本文件：直接读取内容
    - Excel文件：使用 `parse_excel.py` 解析
    - XMind文件：使用 `parse_xmind.py` 解析
- 如未找到主需求信息：
  - 如果用户提供了TAPD ID，使用方式四获取
  - 否则提示用户并终止

**2.3 获取参考需求内容（如有）**
- **重要**：必须主动识别用户是否提供了参考需求，如有则必须获取
- **识别方式**：
  - 关键词识别：`参考需求`、`参考`、`类似需求`、`参照需求`
  - TAPD需求ID识别：用户提到其他需求ID
  - 文件路径识别：用户提供了其他需求文档路径
- **获取方式**：
  - **TAPD需求ID**：使用 `fetch_tapd_issue.py` 脚本获取
  - **需求文档路径**：直接读取用户提供的文档
- **输出**：`reference_requirements` 列表

**2.4 获取参考用例内容（如有）**
- **重要**：必须主动识别用户是否提供了参考用例，如有则必须获取
- **识别方式**：
  - 关键词识别：`参考用例`、`参考测试用例`、`类似用例`
  - 文件路径识别：用户提供了用例文档路径
- **获取方式**：
  - **用例文档路径**：直接读取用户提供的文档
    - Excel文件：使用 `parse_excel.py` 解析
    - XMind文件：使用 `parse_xmind.py` 解析
- **输出**：`reference_cases` 列表

**步骤 3：需求分析**
- **使用工具**：`select_rule`（位于 `tools/select_rule`），传入关键词"需求分析"
- **根据返回结果**：
  - 如果返回自定义规则路径（`.codebuddy/rules/xxx`）：使用 `read_rules` 读取规则内容
  - 如果返回默认Generator路径（`generators/xxx`）：使用 `read_file` 读取 Generator 内容
- **执行方式**：按获取到的规则/Generator定义执行需求分析
- **标准输入参数**
  ```python
  {
    "issue_uid": "{需求节点的uid}",
    "issue_kind": "STORY 或 BUG",
    "raw_issue": "{需求详情内容或文件路径 @file:xxx}"
  }
  ```
- **输出**：需求分析文档结果
- **复用逻辑**：如该需求已分析过，直接使用历史分析文档

**步骤 4：获取测试点信息（如有）**

**重要**：如果用户提供了测试点文件，需要读取测试点内容

**识别方式**：
- 关键词识别：`测试点`、`测试点文件`
- 文件路径识别：用户提供了测试点文件路径（`.md`文件）

**获取方式**：
- **测试点文件路径**：直接读取用户提供的测试点文件（Markdown格式）
- **解析方式**：从Markdown表格中提取测试点信息
  - 表格格式：`| 序号 | 测试点名称 | 测试点描述 | 优先级 |`
  - 提取字段：`name`（测试点名称）、`description`（测试点描述）、`priority`（优先级，可选）

**输出**：`test_points` 列表
```python
{
  "test_points": [
    {
      "name": "验证登录页面正常显示",
      "description": "验证登录页面能够正常加载，包含用户名、密码输入框和登录按钮",
      "priority": "高"  # 可选
    }
  ]
}
```

**步骤 5：生成测试用例（JSON格式）**
- **使用工具**：`select_rule`（位于 `tools/select_rule`），传入关键词"用例生成"
- **根据返回结果**：
  - 如果返回自定义规则路径（`.codebuddy/rules/xxx`）：使用 `read_rules` 读取规则内容
  - 如果返回默认Generator路径（`generators/xxx`）：使用 `read_file` 读取 Generator 内容
- **执行方式**：按获取到的规则/Generator定义执行用例生成

**场景1：根据需求直接生成用例**
- **标准输入参数**:
  ```python
  {
    # 需求分析内容（提供业务背景和规则）
    "issue_analysis": "{步骤3生成的需求分析文档完整内容}",
    # 参考内容：参考需求和参考用例（作为辅助参考）
    "reference_requirements": ["参考需求1内容", "参考需求2内容"],  # 可选
    "reference_cases": ["参考用例1内容", "参考用例2内容"]  # 可选
  }
  ```
- **生成策略**：
  - 基于需求分析生成全面的测试用例
  - 参考需求和参考用例作为辅助参考，补充用例设计思路

**场景2：根据测试点生成用例**
- **标准输入参数**:
  ```python
  {
    # 主要内容：测试点（作为生成用例的主要输入）
    "test_points": [  
      {
        "name": "验证登录页面正常显示",
        "description": "验证登录页面能够正常加载，包含用户名、密码输入框和登录按钮",
        "priority": "高"  # 可选
      }
    ],
    # 需求分析内容（提供业务背景和规则）
    "issue_analysis": "{步骤3生成的需求分析文档完整内容}",
    # 参考内容：参考需求和参考用例（作为辅助参考）
    "reference_requirements": ["参考需求1内容", "参考需求2内容"],  # 可选
    "reference_cases": ["参考用例1内容", "参考用例2内容"]  # 可选
  }
  ```
- **生成策略**：
  - **优先级1（最高）**：基于测试点生成用例，确保每个测试点都有对应的测试用例
  - **优先级2（次要）**：参考需求分析，补充测试点未覆盖的场景
  - **优先级3（最低）**：参考参考需求和参考用例，补充用例设计思路

- **输出要求**：
  - ✅ **必须输出JSON数组格式**
  - ✅ 每个用例必须包含以下字段：
    - **name**：用例名称
    - **preconditions**：前置条件
    - **steps**：用例步骤（数组格式）
    - **expected_result**：预期结果
    - **priority**：用例等级（高/中/低）
  - ✅ 用例步骤要详细、可执行
  - ✅ 预期结果要明确、可验证
  - ✅ 根据测试点复杂度灵活生成用例数量
  - ❌ 禁止输出Excel/CSV格式
  - ❌ 禁止添加到脑图

**步骤 6：生成Excel文件**
- **目的**：将JSON格式的测试用例转换为Excel格式，便于导入用例管理系统
- **执行方式**：调用 `generate_testcase_excel.py` 脚本
- **执行命令**：
  ```bash
  python scripts/generate_testcase_excel.py --testcases <JSON文件路径> --requirement-id <需求ID>
  ```
- **输入**：步骤5生成的JSON文件
- **输出**：Excel文件（.xlsx格式）
- **保存位置**：`.testbuddy/md/testcases_{需求ID}_{时间戳}.xlsx`
- **Excel格式**：
  ```
  | 用例名称 | 需求ID | 前置条件 | 用例步骤 | 预期结果 | 用例等级 |
  |---------|--------|---------|---------|---------|---------|
  | {用例名称} | {需求ID} | {前置条件} | {用例步骤} | {预期结果} | {用例等级} |
  ```
- **用例步骤格式**：
  ```
  步骤1：{步骤描述}
  预期：{预期结果}
  步骤2：{步骤描述}
  预期：{预期结果}
  ...
  ```
- **输出提示**：保存成功后，在对话中提示用户文件路径
  ```
  测试用例已生成并保存到: .testbuddy/md/testcases_{需求ID}_{时间戳}.xlsx
  ```
