# 测试失败分析与修复技能

## 核心能力

本技能帮助软件测试工程师系统化地处理测试失败，通过智能分组、根因分析和结构化修复方案来提升测试效率。

## 工作流程

### 步骤 1：解析测试失败信息

解析用户提供的测试失败信息，包括：
- 测试框架输出（如 pytest、JUnit、Mocha 等）
- 测试日志和堆栈跟踪
- CI/CD 测试报告
- 测试覆盖率报告

**提取的关键信息：**
- 失败的测试用例名称
- 失败类型（断言失败、超时、异常、跳过等）
- 失败消息和堆栈跟踪
- 失败时间戳和环境上下文

### 步骤 2：智能分组错误

对失败进行语义分组，基于以下策略：

| 分组策略 | 适用场景 |
|---------|---------|
| **错误类型分组** | 断言错误、异常错误、超时错误、权限错误等 |
| **模块/组件分组** | 同一模块的测试失败 |
| **根因相似性分组** | 共享相同根本原因的失败 |
| **时间相关性分组** | 依赖执行顺序的失败 |

**输出格式：**
```json
{
  "groups": [
    {
      "group_id": "G1",
      "group_type": "assertion_failure",
      "pattern": "Expected .*, got .*",
      "test_count": 5,
      "tests": ["test_login_failed", "test_checkout_failed", ...],
      "confidence": 0.85
    }
  ]
}
```

### 步骤 3：根因分析

对每个分组进行深度分析：

1. **提取堆栈跟踪特征**
   - 识别重复的错误模式
   - 定位首次出现的失败点
   - 追踪异常传播路径

2. **识别根因类型**
   - 环境问题（配置、依赖、网络）
   - 数据问题（测试数据、边界条件）
   - 代码缺陷（逻辑错误、空指针、资源泄漏）
   - 测试设计问题（依赖、隔离、并发）

3. **计算根因相似度**
   - 使用文本相似度匹配
   - 基于堆栈跟踪的结构化匹配
   - 考虑错误消息模式

### 步骤 4：生成修复方案

为每个失败分组生成结构化修复建议：

```markdown
## 修复方案：断言失败组（G1）

### 问题描述
5 个测试因数据库连接池耗尽导致断言失败

### 根本原因
测试结束后未正确释放数据库连接

### 修复建议

#### 方案 A：使用 Fixture 自动清理（推荐）
```python
@pytest.fixture(autouse=True)
def cleanup_db():
    yield
    db.close_all_connections()
```

#### 方案 B：添加显式清理
在每个测试后添加 `db.reset_pool()`

### 修复优先级
- 优先级：高
- 影响范围：5 个测试
- 预估工时：30 分钟

### 验证方法
运行测试套件确认所有相关测试通过
```

### 步骤 5：优先级排序

基于以下因素排序修复任务：

| 因素 | 权重 | 说明 |
|-----|-----|------|
| 影响测试数 | 30% | 修复可解决的失败数量 |
| 业务重要性 | 25% | 测试对应的功能模块 |
| 修复复杂度 | 25% | 实现修复的难易程度 |
| 根因确定性 | 20% | 根因分析的置信度 |

## 输出格式

完整分析报告包含：

1. **执行摘要**
   - 总失败数、已分组数、待分析数
   - 根因类型分布
   - 修复优先级建议

2. **分组详情**
   - 每个分组的特征和置信度
   - 包含的测试列表

3. **根因分析**
   - 每个根因的详细描述
   - 支持证据（堆栈跟踪片段）

4. **修复方案**
   - 代码级别的修复示例
   - 测试数据修复建议
   - 环境配置调整

5. **行动计划**
   - 按优先级排序的修复任务
   - 预估工时和风险评估

## 使用示例

### 示例 1：分析 pytest 输出

**输入：**
```
FAILED test_auth.py::test_login_timeout - TimeoutError: Connection timed out
FAILED test_auth.py::test_logout - TimeoutError: Connection timed out
FAILED test_checkout.py::test_payment - TimeoutError: Connection timed out
```

**分析输出：**
- 分组：3 个测试因网络超时失败
- 根因：支付网关连接超时配置过短
- 修复：增加超时阈值或实现重试机制

### 示例 2：分析 CI 测试报告

**输入：** JUnit XML 报告或测试日志文件

**分析输出：**
- 按失败类型分组
- 识别共享相同 fixture 的失败
- 提供批量修复建议

## 最佳实践

1. **批量处理优先**：先修复高优先级根因，再处理具体测试
2. **验证修复**：每个修复后运行相关测试确认
3. **记录模式**：为常见问题建立知识库
4. **预防措施**：建议添加回归测试防止复现

## 限制与注意事项

- 需要完整的错误信息进行准确分析
- 堆栈跟踪的深度影响分析质量
- 并发测试失败可能需要额外上下文
- 跨平台问题需要环境信息辅助
