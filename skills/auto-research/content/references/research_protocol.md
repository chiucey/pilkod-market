# 研究迭代协议

改编自 Karpathy AutoResearch 的循环验证思想，应用于信息研究场景。

## 核心类比

| AutoResearch (ML) | 研究迭代 |
|-------------------|---------|
| `train.py` | 搜索策略 + 发现积累 |
| `program.md` | 本协议 |
| val_bpb（越低越好） | 置信度分数（越高越好） |
| `results.tsv` | 核心发现日志 |
| 5分钟训练预算 | 每轮搜索/阅读时间预算 |
| 只改 train.py | 只积累发现，不改已输出的结论 |

## 研究目标定义

用户课题 → 拆解为 3-5 个子方向 → 每轮覆盖部分子方向 → 多轮覆盖全部

格式：
```
研究课题：[课题]
轮次：[N]
子方向：
  1. [子方向A]
  2. [子方向B]
  ...
```

## 搜索策略

### 广度优先（Round 1）
- 用多个不同维度的 query 覆盖课题全局
- 目的：建立整体认知，找到最相关的信息源

### 深度优先（Round 2+）
- 基于上轮发现，锁定最 promising 的方向
- 目的：深化高价值线索

### 迭代调整原则
- 本轮发现指向哪个子方向 → 下轮优先深挖该方向
- 发现矛盾点 → 下轮专项验证
- 某方向已充分 → 减少该方向投入，转向其他

## 评分标准

每条发现按三维评分（0-10），综合分 = 加权平均：

| 维度 | 权重 | 说明 |
|------|------|------|
| 相关性 | 40% | 与课题直接关联程度 |
| 新颖性 | 30% | 提供新视角/独家内容/非常识 |
| 可信度 | 30% | 来源权威性 × 信息一致程度 |

**一致性惩罚**：多个来源说法矛盾 → 可信度下调1-3分

## 置信度等级

| 等级 | 要求 | 标注 |
|------|------|------|
| 高置信度 | 3+来源一致，综合分≥7 | ⭐⭐⭐⭐⭐ |
| 中高置信度 | 2+来源一致，综合分≥6 | ⭐⭐⭐⭐ |
| 中置信度 | 1+来源，单一分来源 | ⭐⭐⭐ |
| 低置信度 | 综合分4-6，单一来源 | ⭐⭐ |
| 存疑 | 综合分<4 或来源矛盾 | ⭐ |

## 核心发现积累规则

- 每轮最多向积累区添加 **5条** 核心发现
- 新发现与已有发现重复 → 合并，不重复计数
- 多轮出现的线索 → 升置信度等级
- 发现矛盾 → 标注"争议点"，不删除，任留待验证区

## 输出质量标准

每条发现必须包含：
1. **标题**（<20字，概括核心）
2. **来源**（URL，非网页描述）
3. **摘要**（<100字，说清发现了什么）
4. **置信度**（⭐等级）
5. **与课题的关联方式**

## 轮次终止条件

提前终止（如课题已充分研究）：
- 3轮内核心发现已达15+条，且高置信度≥5条
- 各子方向均已有充分覆盖

强制完成（课题复杂，需深挖）：
- 达到预设轮次上限（默认4轮）时必须输出报告
- 明确标注"未充分覆盖"的子方向

## 与传统研究的本质区别

- **传统研究**：收集→整理→一次性输出，容易遗漏和偏差
- **AutoResearch**：迭代→验证→积累，每轮有评分、每轮有方向调整，不依赖单一搜索路径
