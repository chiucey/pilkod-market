# Markdown Document Organizer

专业的Markdown文档编辑优化专家技能，融合专业文字编辑技巧与技术写作规范，将任何来源的混乱、非结构化或带有噪声的Markdown/文本资料，零损耗重构为格式规范、层级清晰、可读性强的标准Markdown文档。

## 核心使命

将任何来源的混乱、非结构化或带有噪声的 Markdown/文本资料，**零损耗**重构为**格式规范、层级清晰、可读性强的标准 Markdown 文档**。

**铁律**：保持原始信息 100% 完整性——不删减内容、不改变逻辑顺序、不丢失任何有效信息。

**适用场景**：笔记整理、文章排版、OCR 文档修复、网页内容提取、技术文档规范化、电子书转换、学术论文排版等。

## 专业编辑工作流

### 编辑层级模型

专业编辑分为三个层级，本技能聚焦于结构编辑与行内编辑：

| 编辑层级 | 关注重点 | 处理范围 |
|---------|---------|---------|
| **结构编辑（Structural Editing）** | 文档整体架构、逻辑流程、信息组织 | 标题层级、章节划分、内容重组 |
| **行内编辑（Line Editing）** | 句子结构、表达清晰度、语法正确性 | 断句合并、列表规范化、术语加粗 |
| **复制编辑（Copy Editing）** | 标点符号、用词一致性、格式统一 | 标点规范、术语统一、格式标准化 |

### 执行流程（增强版）

## 处理规则（按优先级执行）

### P0 - 结构重构

**目的**：建立清晰的文档层级结构

| 规则 | 执行标准 | 示例 |
|-----|---------|------|
| **标题层级标准化** | 严格使用 `#` → `##` → `###` → `####`，禁止跳级 | ❌ `#### 标题` 后直接跟 `##### 子标题` |
| **层级语义对应** | `#` = 文档主标题；`##` = 篇/模块；`###` = 章/主题；`####` = 节/子主题 | — |
| **破碎标题修复** | 检测并修复连写标题，正确拆分 | `"## 第2篇的 ## 第6章"` → `## 第2篇\n\n### 第6章` |
| **标题-正文分离** | 确保每个标题后有换行，与正文内容分离 | `## 标题\n\n正文内容` |
| **章节逻辑分组** | 相关内容归入同一章节，保持逻辑内聚性 | 同主题内容合并，不同主题分离 |

### P1 - 内容净化

**目的**：移除噪声，修复内容结构

| 操作 | 执行标准 | 注意事项 |
|-----|---------|---------|
| **噪声删除** | 移除：版权水印、页码标记（P320）、平台水印、分享信息、生成器残留、导航栏元素 | 保留必要的版本信息 |
| **断句合并** | 以标点（.。!?"）判断句尾，非段落结尾的硬换行 → 合并为连续段落 | 诗歌、对话除外 |
| **列表统一** | 无序列表：`-`（短横线）；有序列表：`1.`；嵌套缩进：2空格 | 禁止混用 `*`、`+`、`-` |
| **HTML清理** | 删除所有 `<tag>` 及 `</tag>` 标签，保留标签内纯文本内容 | 特殊标签如 `<br>` 转为 `\n` |
| **链接处理** | 保留 Markdown 链接格式 `[文本](URL)`，删除裸链接文本 | 保留必要的外链引用 |

### P2 - 语义增强

**目的**：突出关键信息，提升可读性和理解度

| 增强项 | 执行标准 | 示例 |
|-------|---------|------|
| **术语加粗** | 首次出现的专业术语、核心概念 → `**粗体**` | `**金字塔原理**`、`**SWOT分析**` |
| **术语首次定义** | 首次使用专业术语时添加定义或解释 | `**API**（Application Programming Interface，应用程序接口）` |
| **提示框转换** | "提示"、"注意"、"关键点"、"警告" → `> **提示：**` 引用格式 | `> **注意**：请确保...` |
| **重要标记** | 关键数据、核心结论使用加粗强调 | `正确率提升了 **15%**` |
| **引用标记** | 书籍引用、名言、对话 → `>` 引用块 | `> "知识就是力量" —— 培根` |
| **图表引用** | 原样保留 "如图 X-X"、"表 X-X"，添加引用标记 | `[原图引用：图 2-1]` |
| **脚注处理** | 脚注内容移至文末对应位置或保留原位（根据上下文判断） | — |

### P3 - 复制编辑

**目的**：规范化语言表达，确保格式一致性和可读性

| 规范项 | 执行标准 | 示例 |
|-------|---------|------|
| **语言简洁** | 删除冗余词汇，避免重复表达 | `这是一个非常重要的` → `这是重要的` |
| **客观表述** | 避免主观色彩或情绪化描述，使用中性语言 | `这个方案太好了` → `该方案效果显著` |
| **标点规范** | 中文文档使用中文标点（，。：；？！""）；英文使用英文标点 | 中文：`"内容"`；英文：`"content"` |
| **术语一致** | 全文档同一术语使用相同表述，建立术语映射表 | `机器学习` ≠ `ML`（除非有解释） |
| **数字使用** | 数量词使用阿拉伯数字，习惯表达使用汉字 | `3个`、`第一步` |
| **度量单位** | 数字与单位之间无空格（特殊除外） | `10MB`、`30分钟` |

### P4 - 格式美化

**目的**：提升视觉层次和阅读体验

| 格式类型 | 执行标准 | 注意事项 |
|---------|---------|---------|
| **代码块** | 步骤流程、公式、代码示例 → ` ```code block ``` `，标注语言 | ` ```python\nprint("Hello")\n``` ` |
| **数学公式** | 行内公式 `$...$`，独立公式 `$$...$$` | `$E=mc^2$` |
| **引用块** | 书籍引用、案例、名人名言 → `>` 引用块 | 可嵌套使用 |
| **分隔线** | `---` 仅用于主要章节/篇之间，控制在 3 处以内 | 避免滥用 |
| **视觉呼吸** | 段落间 1 空行；列表紧凑排列；标题前后 1 空行 | — |
| **缩进块** | 诗歌、代码片段、对话 → 4 空格缩进块 | — |
| **表格格式** | 保留 Markdown 表格格式（`|` 分隔），修复行列对齐 | 确保表头与内容对齐 |

## 术语管理规范

### 术语识别与标注

| 术语类型 | 识别方式 | 标注方法 |
|---------|---------|---------|
| **领域术语** | 首次出现且有明确定义 | `**术语**` 加粗 |
| **缩写词** | 首次出现时 | `**缩写**（全称）` |
| **专有名词** | 品牌、公司、产品名称 | `**专有名词**` |
| **技术参数** | 数值、比例、指标 | `**参数**` |

### 术语一致性检查

| 检查项 | 执行标准 |
|-------|---------|
| 同义词统一 | `机器学习` 与 `ML` 统一为一种表述 |
| 大小写一致 | `API` 全文档统一大小写 |
| 标点一致 | 引号、括号使用规范统一 |
| 数字表述一致 | `10%` 或 `百分之十` 统一使用 |

## 输出规范

**必须满足以下所有条件**：

| 序号 | 规范项 | 检查标准 |
|-----|-------|---------|
| 1 | **单一文件** | 所有内容整合为一个 `.md` 文件 |
| 2 | **可导航性** | 顶部包含目录（手动目录或自动目录）或清晰的标题层级 |
| 3 | **视觉呼吸** | 段落间 1 空行；章节间 `---`；标题前后空行 |
| 4 | **无冗余标记** | 无 HTML 标签、无 XML 残留、无噪声水印 |
| 5 | **格式一致** | 列表符号统一、引用格式统一、粗体使用一致 |
| 6 | **完整性** | 无孤立标题、无遗漏列表项、无丢失引用/示例 |
| 7 | **术语一致** | 同一术语全文使用统一表述 |
| 8 | **可读性** | 段落长度适中、层次清晰、阅读流畅 |

## 约束边界（绝对禁止）

| ❌ 禁止行为 | 原因 | ✅ 正确行为 |
|-----------|------|------------|
| 改变原文论证/叙述顺序 | 保持逻辑完整性 | 按原顺序重组格式 |
| 删除原文举例/案例/数据 | 保留论证支撑 | 仅修复格式，不删内容 |
| 将列表转为段落 | 破坏结构语义 | 保持列表结构 |
| 删除图表引用标记 | 保留交叉引用 | 即使无图片也保留 |
| 修改原文献引用格式 | 尊重原格式 | 原样保留引用 |
| 合并不同章节内容 | 破坏层级结构 | 保持章节独立 |
| 添加解释性内容 | 避免主观臆断 | 仅整理现有内容 |
| 改变原文用词 | 尊重原作者风格 | 仅规范化表述 |
