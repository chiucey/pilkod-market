# generate_rob_arm_test_case

为机械臂调度系统生成符合行业规范的结构化测试用例。

## 输入参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| scenario | string | ✅ | 测试场景关键词或简要描述 |
| arm_count | integer | ❌ | 机械臂数量，默认 2 |
| test_type | string | ❌ | 测试类型：功能测试/异常测试/性能测试/安全测试/回归测试，默认"功能测试" |

## 支持的典型场景

- **急停恢复** — 机械臂执行中触发急停，系统安全暂停与断点恢复
- **路径冲突** — 多臂路径规划存在空间干涉，调度器重规划避碰
- **多任务抢占** — 高优先级任务中断低优先级任务
- **双臂同时抓取同一工位** — 资源竞争与互斥机制验证
- **任务A被高优先级任务B中断后恢复** — 任务中断与恢复逻辑
- **通信超时** — 控制器与机械臂通信中断的系统响应
- **负载均衡** — 多任务下调度器负载分配策略

## 输出格式

每个测试用例包含：

- **用例标题** — 简洁描述测试目标
- **前置条件** — 系统与设备状态
- **测试步骤** — 详细操作序列
- **预期结果** — 正确的系统行为
- **优先级** — P0（核心）/ P1（重要）/ P2（一般）
- **覆盖需求** — 对应的调度策略/安全机制/通信协议

## 调用方式

用户可通过以下方式激活：

1. **完整参数调用** — 提供 scenario、arm_count、test_type
2. **场景描述调用** — 仅描述调度场景，arm_count 和 test_type 使用默认值

### 示例

**用户输入：**
> 双臂同时抓取同一工位

**输出：**
```
【用例标题】双臂同时抓取同一工位时的互斥机制验证

【前置条件】
1. 两台机械臂（臂A、臂B）均已完成标定，处于就绪状态
2. 工位台有且仅有一个待抓取目标物
3. 调度系统运行正常，通信链路畅通

【测试步骤】
1. 同时向臂A和臂B下发抓取同一工位的任务指令
2. 观察调度器任务分配决策
3. 记录实际执行结果与机械臂运动轨迹

【预期结果】
1. 调度器根据优先级或轮询策略仅将任务分配给其中一台机械臂
2. 另一台机械臂保持待机或重新规划路径
3. 抓取动作成功完成，无碰撞、无任务丢失

【优先级】P0

【覆盖需求】资源互斥机制、任务分配策略、碰撞检测模块
```
