# 新产品假设识别

系统性地识别和评估新产品构想中的风险假设，确保在投入开发资源前验证关键不确定性。

## 8大风险类别

### 1. 价值风险 (Value Risk)
**定义**: 用户是否真正需要这个解决方案？

| 假设类型 | 描述 | 验证方式 |
|---------|------|---------|
| 问题存在 | 用户确实面临这个问题 | 用户访谈、调查 |
| 问题重要 | 问题足够重要值得解决 | 排序测试、意向调查 |
| 解决方案匹配 | 我们的方案确实解决问题 | 原型测试 |
| 时机合适 | 现在是解决问题的好时机 | 市场趋势分析 |

### 2. 可用性风险 (Usability Risk)
**定义**: 用户能否轻松使用我们的解决方案？

| 假设类型 | 描述 | 验证方式 |
|---------|------|---------|
| 可学习性 | 用户能学会使用 | 新手测试 |
| 效率 | 用户能高效使用 | 任务时间测量 |
| 错误率 | 用户操作错误率低 | 可用性测试 |
| 满意度 | 用户使用后满意 | SUS 评分 |

### 3. 可行性风险 (Feasibility Risk)
**定义**: 我们能否构建这个解决方案？

| 假设类型 | 描述 | 验证方式 |
|---------|------|---------|
| 技术可行性 | 现有技术能实现 | 技术原型 |
| 资源充足性 | 有足够的人力/时间 | 估算验证 |
| 基础设施 | 基础设施能支持 | 架构评审 |
| 扩展性 | 能支持未来增长 | 压力测试 |

### 4. 商业化风险 (Business Viability Risk)
**定义**: 这个解决方案能否为我们带来商业价值？

| 假设类型 | 描述 | 验证方式 |
|---------|------|---------|
| 商业模式 | 存在可持续的盈利方式 | 财务建模 |
| 定价合理性 | 用户愿意为此付费 | 价格实验 |
| 单位经济 | LTV > CAC | 数据分析 |
| 可持续性 | 能在市场上持续运营 | 竞争分析 |

### 5. 市场吸引力风险 (Market Risk)
**定义**: 是否有足够大的市场机会？

| 假设类型 | 描述 | 验证方式 |
|---------|------|---------|
| 市场规模 | TAM/SAM/SOM 足够大 | 市场规模估算 |
| 市场时机 | 现在进入市场时机合适 | 趋势分析 |
| 市场趋势 | 市场规模会增长 | 行业报告 |
| 细分市场 | 有可服务的细分市场 | 用户研究 |

### 6. 竞争优势风险 (Competitive Risk)
**定义**: 我们能否在竞争中胜出？

| 假设类型 | 描述 | 验证方式 |
|---------|------|---------|
| 差异化 | 我们的方案有独特价值 | 差异化分析 |
| 护城河 | 能建立可持续的壁垒 | 战略分析 |
| 先发优势 | 先行者优势存在 | 市场验证 |
| 响应速度 | 能在竞争中快速响应 | 能力评估 |

### 7. 团队风险 (Team Risk)
**定义**: 我们的团队能否执行这个计划？

| 假设类型 | 描述 | 验证方式 |
|---------|------|---------|
| 技能匹配 | 团队具备必要技能 | 技能盘点 |
| 执行能力 | 能按时交付 | 历史表现 |
| 适应能力 | 能适应变化 | 敏捷评估 |
| 决策效率 | 决策链路清晰高效 | 组织诊断 |

### 8. GTM 风险 (Go-to-Market Risk)
**定义**: 我们能否有效地触达用户？

| 假设类型 | 描述 | 验证方式 |
|---------|------|---------|
| 获客渠道 | 存在有效的获客渠道 | 渠道测试 |
| 转化漏斗 | 转化路径清晰高效 | 漏斗分析 |
| 激活率 | 用户激活路径顺畅 | 行为分析 |
| 推荐机制 | 用户愿意推荐 | NPS/推荐率 |

## 假设识别流程

### 第一步：陈述假设

将模糊的假设转化为具体的、可验证的陈述。

```
❌ 模糊假设: "用户会喜欢这个功能"
✅ 清晰假设: "目标用户每周至少会遇到3次这个痛点"
✅ 清晰假设: "用户愿意为解决方案支付X元/月"
```

### 第二步：风险评估

使用 2x2 矩阵评估每个假设。

```
                    假设为真的可能性
                        高     低
                ┌─────────┬─────────┐
假设失败       高│  🔴     │  🟠     │
的影响程度     │ 关键风险 │  重要风险 │
                ├─────────┼─────────┤
假设失败       低│  🟡     │  🟢     │
的影响程度     │ 低优先级│  不紧急  │
                └─────────┴─────────┘
```

### 第三步：优先级排序

| 优先级 | 风险等级 | 行动 |
|-------|---------|------|
| P0 | 🔴 高风险 × 高影响 | 必须立即验证 |
| P1 | 🟠 高风险 × 低影响 | 尽快验证 |
| P2 | 🟡 低风险 × 高影响 | 适当验证 |
| P3 | 🟢 低风险 × 低影响 | 视情况验证 |

## 精益验证实验类型

### 1. 访谈验证
- **适用**: 价值风险、GTM风险
- **成本**: 低
- **时间**: 1-2周
- **方法**: 深度访谈用户

### 2. 虚假门 (Wizard of Oz)
- **适用**: 价值风险、商业化风险
- **成本**: 中
- **时间**: 2-4周
- **方法**: 人为模拟功能测试用户反应

### 3. 预购/众筹
- **适用**: 商业化风险、市场吸引力
- **成本**: 低
- **时间**: 2-6周
- **方法**: 收集付费意向

### 4. 概念测试
- **适用**: 价值风险、可用性风险
- **成本**: 中
- **时间**: 2-4周
- **方法**: 用原型测试用户反应

### 5.  landingspage 测试
- **适用**: GTM风险、市场吸引力
- **成本**: 低
- **时间**: 1-2周
- **方法**: 投放广告测试转化

### 6. 视频演示
- **适用**: 价值风险
- **成本**: 低
- **时间**: 1-2周
- **方法**: 展示产品概念视频

### 7. 纸质原型
- **适用**: 可用性风险
- **成本**: 低
- **时间**: 1-2周
- **方法**: 纸质原型用户测试

## 风险缓解策略

### 构建-测量-学习循环

```
    ┌─────────────────────────────────────┐
    │                                     │
    ▼                                     │
构思 ──→ 构建 ──→ 测量 ──→ 学习           │
              │       │                   │
              │       └───────────────────┘
              │              │
              └──────────────┘
                   迭代
```

### 快速验证原则
1. **从最风险开始**: 优先验证高风险假设
2. **最小可行实验**: 用最小成本验证假设
3. **二元决策**: 验证结果明确，不模糊
4. **快速迭代**: 快速调整，快速验证
