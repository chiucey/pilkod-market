# 新产品头脑风暴

多角度创意生成框架，从产品经理、设计师和工程师三个视角系统性地探索产品可能性。

## 核心原则

### 创意生成规则
1. **数量优先**: 先追求数量，再追求质量
2. **延迟评判**: 创意阶段不批评，评估阶段再筛选
3. **构建而非否定**: 在他人创意上改进，而非说"但是"
4. **大胆想象**: 鼓励突破性想法，边界条件可以突破
5. **多元视角**: 融合不同背景的观点

### 禁用语录
- ❌ "这不行，因为..."
- ❌ "我们以前试过..."
- ❌ "技术上太难了..."
- ❌ "用户不会想要..."

### 鼓励语录
- ✅ "如果...会怎样？"
- ✅ "可以借鉴..."
- ✅ "最简单的版本是..."
- ✅ "也许可以..."

## 三视角创意框架

### 视角一：产品经理 (Product Manager)

关注价值、可行性和市场契合度。

#### 价值维度
- 这个功能解决什么核心问题？
- 用户真正需要的是什么？
- 我们的差异化在哪里？

#### 市场维度
- 目标用户是谁？
- 市场规模有多大？
- 竞争格局如何？

#### 商业模式维度
- 如何衡量成功？
- 盈利模式是什么？
- 如何获取用户？

#### PM 视角问题清单

| 类别 | 问题 |
|-----|------|
| 需求 | 用户最痛的点是什么？ |
| 需求 | 我们的解决方案比现有方案好多少？ |
| 市场 | 目标用户的决策链条是什么？ |
| 市场 | 如何让用户知道这个功能？ |
| 商业 | 付费意愿如何验证？ |
| 商业 | CAC 和 LTV 如何平衡？ |

---

### 视角二：设计师 (Designer)

关注用户体验、情感连接和交互创新。

#### 体验维度
- 如何让用户感到愉悦？
- 第一次使用的体验如何？
- 如何减少用户认知负担？

#### 情感维度
- 用户完成目标后会有什么感受？
- 如何创造"惊喜时刻"？
- 什么样的细节会打动用户？

#### 交互维度
- 核心操作路径如何简化？
- 如何让复杂功能看起来简单？
- 反馈机制如何设计？

#### 设计师视角问题清单

| 类别 | 问题 |
|-----|------|
| 体验 | 用户第一次如何使用？ |
| 体验 | 如何降低学习曲线？ |
| 体验 | 最关键的 3 个操作是什么？ |
| 情感 | 用户在什么时刻会感到惊喜？ |
| 情感 | 如何让产品"懂"用户？ |
| 交互 | 能否减少点击次数？ |
| 交互 | 错误状态如何处理？ |

---

### 视角三：工程师 (Engineer)

关注技术可行性、创新实现和系统扩展性。

#### 可行性维度
- 现有技术栈能否支持？
- 需要多长时间 MVP？
- 依赖关系有哪些？

#### 创新维度
- 有没有更聪明的实现方式？
- 能否复用现有能力？
- 开源/第三方方案有哪些？

#### 扩展维度
- 系统能承受多少用户？
- 如何设计以支持未来增长？
- 技术债务风险如何？

#### 工程师视角问题清单

| 类别 | 问题 |
|-----|------|
| 可行性 | MVP 需要什么？ |
| 可行性 | 最大风险点在哪里？ |
| 可行性 | 需要哪些外部依赖？ |
| 创新 | 有没有"作弊"方案？ |
| 创新 | 能否分阶段实现？ |
| 扩展 | 能支持 10x 用户增长吗？ |
| 扩展 | 如何监控和回滚？ |

## 头脑风暴流程

### 第一步：定义边界 (5分钟)

明确讨论范围和约束条件。

```
产品: [产品名称]
阶段: [概念/验证/增长]
目标: [本次头脑风暴要解决的问题]
约束: [时间/资源/技术限制]
```

### 第二步：发散阶段 (20分钟)

每个视角独立生成创意。

**方法**: 每人用便签写下 5-10 个想法，每张便签一个想法

**格式**:
```
[功能名称]: [一句话描述解决什么问题]
```

### 第三步：展示与构建 (15分钟)

每人展示想法，其他人构建。

**规则**:
- 不批评，只构建
- "这个想法让我想到..."
- "如果加入...会更好"

### 第四步：收敛阶段 (15分钟)

筛选和归类创意。

**分类矩阵**:

| | 高影响 | 低影响 |
|---|---|---|
| **易实现** | ⭐ 优先做 | 🔄 以后做 |
| **难实现** | 🎯 重点攻克 | ❌ 暂不做 |

## 创意记录模板

### 创意卡片格式

```markdown
## 创意编号: IDE-001

**功能名称**: [名称]
**所属视角**: PM / Designer / Engineer / 融合

**一句话描述**:
[用一句话描述这个功能做什么]

**解决的问题**:
- 用户痛点: [具体痛点]
- 出现场景: [何时需要]

**价值预估**:
- 用户价值: ⭐⭐⭐⭐⭐
- 商业价值: ⭐⭐⭐⭐⭐
- 差异化: ⭐⭐⭐⭐⭐

**实现复杂度**:
- 技术难度: 🔴高 🟡中 🟢低
- 资源需求: [人/天或人/月]
- 依赖项: [外部依赖]

**初步评估**:
- 优先级: P0 / P1 / P2 / P3
- 建议方向: 继续深入 / 探索验证 / 暂缓

**备注**:
[补充说明或关联创意]
```

## 创意组合策略

### 基础组合
- 功能 + 功能 = 组合功能
- 功能 + 痛点 = 差异化点
- 痛点 + 新场景 = 新产品

### 跨域启发
- 竞品: 做了什么？为什么？
- 跨行业: 类似问题其他行业怎么解决？
- 历史: 以前失败案例的教训？
- 趋势: 新技术能解锁什么？

### "如果...会怎样"游戏

```
如果用户不用注册就能使用...
如果完全免费...
如果只需要 3 步就能完成...
如果可以分享给朋友...
如果失败了也不损失任何东西...
```
