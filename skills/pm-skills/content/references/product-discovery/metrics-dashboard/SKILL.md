# 产品指标仪表板

系统性地设计产品指标体系，从战略层面的北极星指标到执行层面的健康指标，形成完整的指标漏斗。

## 指标层级架构

```
         北极星指标 (North Star Metric)
                   ↓
              滞后指标 (Lag Indicators)
              /            \
             /              \
       结果指标          里程碑指标
    (Outcome)          (Milestone)
            \              /
             \            /
              输入指标 (Input Indicators)
                         ↓
                   健康指标 (Health Indicators)
```

---

## 第一层：北极星指标 (North Star Metric)

### 定义标准

北极星指标是衡量产品为用户创造核心价值的单一指标。

**选择标准**:
1. ✅ 反映用户价值
2. ✅ 反映商业价值
3. ✅ 可衡量且可归因
4. ✅ 短期内可通过行动影响
5. ✅ 团队能理解和聚焦

### 常见北极星指标

| 产品类型 | 北极星指标示例 |
|---------|---------------|
| 社交 | 日活用户 (DAU)、分享次数 |
| 电商 | GMV、订单数、复购率 |
| SaaS | MRR、付费转化率、续费率 |
| 内容 | 内容消费量、创作者数 |
| 工具 | 关键功能使用率、完成任务数 |

### 指标陈述模板

```
"[用户] 通过 [核心行为] 来实现 [期望结果]"
"每 [时间段], [X%] 的 [用户群] 完成 [关键动作]"
```

## 第二层：结果指标 (Outcome Metrics)

### 指标类型

#### 1. 价值指标
衡量用户从产品中获得的价值。

| 指标 | 定义 | 计算方式 |
|-----|------|---------|
| 用户价值实现 | 用户达成目标的程度 | 任务完成率 |
| 效率提升 | 帮用户节省的时间 | 操作时间差值 |
| 成本节省 | 帮用户节省的费用 | 成本对比 |

#### 2. 参与度指标
衡量用户与产品的互动深度。

| 指标 | 定义 | 计算方式 |
|-----|------|---------|
| 活跃率 | DAU/MAU | DAU/MAU |
| 会话时长 | 单次使用时长 | 平均会话时长 |
| 会话频次 | 使用频率 | 每周会话数 |
| 深度使用 | 核心功能使用 | 核心动作数 |

#### 3. 商业指标
衡量商业价值创造。

| 指标 | 定义 | 计算方式 |
|-----|------|---------|
| 收入 | 收入金额 | ARPU × 用户数 |
| 转化率 | 完成目标用户比例 | 转化数/访客数 |
| 留存 | 用户持续使用 | 特定周期留存率 |
| 推荐 | 用户推荐意愿 | NPS/推荐率 |

## 第三层：输入指标 (Input Metrics)

### 定义

输入指标是团队可以直接影响的指标，代表了达成北极星指标的前置行为。

### 因果关系

```
输入指标 ──→ 结果指标 ──→ 北极星指标
(可控制)    (可观察)    (最终目标)
```

### 示例映射

**北极星**: 每日内容发布量
↓
**结果指标**: 创作者活跃率
↓
**输入指标**: 新手创作者首次发布完成率

### 输入指标设计原则

1. **可归因**: 明确归因到团队/个人
2. **即时反馈**: 短期能看到变化
3. **可控制**: 团队能直接影响的
4. **可预测**: 能预测对结果的影响

## 第四层：健康指标 (Health Metrics)

### 系统健康

| 指标 | 描述 | 告警阈值 |
|-----|------|---------|
| 错误率 | 请求失败比例 | >1% 告警 |
| 响应时间 | API 响应时长 | >500ms 告警 |
| 可用性 | 系统正常运行时间 | <99.9% 告警 |
| 容量 | 系统承载能力 | >80% 告警 |

### 业务健康

| 指标 | 描述 | 告警阈值 |
|-----|------|---------|
| 新用户激活 | 激活流程完成率 | <40% 告警 |
| 转化漏斗 | 各阶段转化率 | 环比下降20% |
| 流失率 | 用户流失比例 | 环比增加10% |
| 客服工单 | 问题反馈量 | 突增50% |

## 告警机制设计

### 告警层级

| 级别 | 名称 | 响应时间 | 通知方式 |
|-----|------|---------|---------|
| P1 | 严重 | 15分钟 | 电话+短信+邮件 |
| P2 | 紧急 | 1小时 | 短信+邮件 |
| P3 | 一般 | 4小时 | 邮件 |
| P4 | 提示 | 24小时 | 邮件+仪表板 |

### 告警规则示例

```
规则1: DAU 告警
  IF DAU < 昨日 × 0.8
  THEN P2 告警

规则2: 错误率告警
  IF 错误率 > 1%
  THEN P1 告警

规则3: 转化率下降
  IF 转化率 < 周均值 × 0.85
  THEN P3 告警
```

## 指标迭代原则

1. **从少到多**: 先建立核心指标，再逐步扩展
2. **从粗到细**: 先全局视角，再细分维度
3. **可操作性**: 每个指标都应有明确的行动对应
4. **避免虚荣**: 关注可归因、有意义的指标
5. **定期回顾**: 每季度审视指标体系的有效性
