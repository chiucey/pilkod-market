# music-prompt

通过多轮对话对齐用途、节奏与音乐风格，输出一段中文 music generation prompt，并调用内置 `batch_text_to_music` 工具生成 mp3。

重点生成**节奏清晰、结构有变化、便于画面同步**的音乐。不要设计视频分镜，不要选择或引用视频模板，也不要生成额外交接文件。

## 流程总览

```text
收集 context → 补齐关键问题 → 推导音乐参数 → 拼 prompt + preview → 用户确认 → 调工具 → 时长核对 + 剪辑决策 → 反馈修改路由
```

## 第一步：收集 context

让用户自由描述用途、文字内容、场景、氛围或参考曲。从中提取已经明确的信息，避免重复提问。

如果用户提供文字内容，只提取：

- 视频或音乐用途；
- 核心情绪；
- 是否需要突出某个能量峰值；
- 内容整体是短促有力、逐步推进，还是舒缓流动。

不要在本 skill 中拆分镜、配画面或选择视觉模板。

## 第二步：补齐关键问题（一次一问）

一次只问一个问题。每题给出一个推荐答案和一句理由。已从 context 确定的字段直接跳过。

按以下顺序补齐：

1. **时长**（必填，必问）
   - 形如“30 秒”“90 秒”；
   - 依据用途推荐合理值。

2. **用途/内容**
   - 例如品牌短片、产品预告、活动片头、Vlog、演示视频、纯背景音乐；
   - 用户已描述清楚时跳过；
   - 若用户给了文字，只需理解其整体节奏和核心信息，不拆分镜。

3. **节奏方式**
   - `强节拍`：鼓点明确、重音清晰，适合快速同步；
   - `逐步推进`：从克制到强烈，有蓄力和能量峰值；
   - `舒缓流动`：按乐句与能量变化推进，不追求密集鼓点；
   - 默认根据用途推荐，不要求用户理解专业术语。

4. **能量曲线**
   - `快速进入 → 持续推进 → 最终重拍`；
   - `安静铺垫 → 逐层增强 → 强烈爆发 → 收束`；
   - `高能推进 → 中段骤停 → 二次爆发`；
   - `舒缓展开 → 情绪抬升 → 温和结束`；
   - 只选择一个简单结构。不要要求精确到第几秒，因为生成模型不能保证事件落在指定时间。

5. **情绪**
   - 1–3 个中文形容词，如“自信且未来感”“激烈且驱动”“温暖且治愈”。

6. **歌词**
   - 默认推荐“否”；
   - 选“否” → prompt 末尾必须固定加 `没有人声`，工具调用传 `is_instrumental: true`；
   - 选“是” → 让用户给歌词内容（10–600 字符），prompt 末尾加 `含歌词: <歌词内容>`，工具调用时不传 `is_instrumental`。

### 流派、乐器与 BPM 的处理

不要默认把流派、乐器、BPM 分成三轮追问。根据用途、节奏方式、能量曲线和情绪生成一组推荐值，在 preview 中展示并允许用户修改。

只有在用户明确表示有偏好，或现有信息无法推导时，才单独追问其中一个字段。

推荐原则：

- 强节拍：优先使用明确鼓组、低音与清晰瞬态，通常约 110–145 BPM；
- 逐步推进：使用分层加入、短滚奏、riser、drop 或重拍收束，通常约 90–130 BPM；
- 舒缓流动：使用清晰乐句、长音色与较少打击乐，通常约 60–100 BPM；
- BPM 是建议值，不要仅靠提高 BPM 表达“更有节奏感”；节拍清晰、重音和结构变化更重要。

## 第三步：生成 prompt

按以下优先级组织成一行中文：

```text
用于{用途}的{时长}秒配乐，{节奏方式}，{能量曲线及关键节奏事件}；{流派}，{乐器}，约{BPM} BPM，{情绪}，{歌词决策}
```

节奏描述要具体但简洁，优先使用：

- 开头快速进入主题；
- 鼓点与重音清晰；
- 中段持续推进；
- 能量峰值前短滚奏或蓄力；
- 强烈重拍爆发；
- 中段短暂停顿后再次进入；
- 最终重拍收束；
- 温和尾音结束。

根据所选能量曲线取必要项，不要堆叠所有描述。不要承诺精确时间点。

歌词决策规则：

- 选否 → `没有人声`，必须固定写在 prompt 末尾；
- 选是 → `含歌词: <歌词>`；
- 用户额外要求“无鼓”“无贝斯”等负向约束，追加到尾部。

**preview 输出格式：**

```text
音乐用途：品牌短片
目标时长：30 秒
节奏方式：逐步推进
能量曲线：安静铺垫 → 逐层增强 → 强烈爆发 → 收束

音乐建议：
  流派：cinematic electronic
  乐器：合成器、鼓机、低音贝斯
  BPM：约 124
  情绪：自信、未来感、驱动
  歌词：没有人声

Prompt:
  `用于品牌短片的30秒配乐，节奏清晰、逐步推进；开头克制，中段分层增强，能量峰值前短滚奏蓄力，随后强烈重拍爆发并收束；cinematic electronic，合成器、鼓机和低音贝斯，约124 BPM，自信、未来感、驱动，没有人声`

字符数：112 / 300 ✓
```

**字符数约束：** prompt 必须为 10–300 字符。超出时按以下顺序压缩：

1. 合并重复的情绪词；
2. 缩短乐器列表；
3. 压缩用途描述；
4. 保留时长、节奏方式、能量曲线、BPM 和歌词决策。

用户确认 preview 后才能调用工具。

## 第四步：用户确认 → 调工具

用户确认后，调用 `batch_text_to_music`。

**纯器乐：**

```js
batch_text_to_music({
  requests: [{
    prompt: "<完整中文 prompt>",
    output_file_path: "music/<建议的文件名>.mp3",
    is_instrumental: true
  }]
})
```

**含歌词：**

```js
batch_text_to_music({
  requests: [{
    prompt: "<完整中文 prompt>",
    output_file_path: "music/<建议的文件名>.mp3",
    lyrics: "<歌词内容，用 \n 分行>"
  }]
})
```

- `is_instrumental: true` = 纯器乐；
- 不传 `is_instrumental` = 默认 false，可能含人声；
- `output_file_path` 建议放在工作区的 `music/` 子目录。

工具返回 mp3 后，必须用 `audios_understand` 听一遍并核对：

- 文件是否正常；
- 实际时长；
- 目标时长；
- 文件大小；
- 节拍、推进和能量峰值是否大致符合 prompt。

向用户报告以上结果，并询问“听着怎么样？”

### 时长核对规则（默认不剪）

工具对时长控制非常不稳定，同一 prompt 跑两次可能差 20–50 秒，绝不能信 prompt 中的目标时长，以实测为准。

- 若 `|实际时长 - 目标时长| ≤ 2 秒` → 时长基本正确，直接询问反馈；
- 若 `|实际时长 - 目标时长| > 2 秒` → 明确告知并询问：

  ```text
  实际 X 秒 vs 目标 Y 秒（差 Z 秒）。要不要自动剪辑？
  - 剪（取前 Y 秒）
  - 不剪（保留原始 X 秒，默认）
  - 重新生成（使用相同 prompt 再跑一次）
  - 剪到其他秒数（用户指定）
  ```

必须由用户明确选择“剪”后才能执行 ffmpeg，不要主动剪辑。

```bash
ffmpeg -y -i music/<原文件>.mp3 -t <目标秒数> -acodec libmp3lame -b:a 192k music/<原文件名>-<秒数>s.mp3
```

- 取前 N 秒；
- 重新编码，不使用 `-acodec copy`；
- bitrate 192k；
- 文件名增加 `-<秒数>s` 后缀，保留原版不覆盖。

## 第五步：反馈修改路由

- **剪辑**（“剪到 30 秒”“自动剪一下”）→ 按第四步规则执行；
- **重新生成**（“再跑一遍”“重生一次”）→ 使用相同 prompt 再调用工具，不重走提问；
- **节奏不够明显** → 优先增强鼓点、重音、瞬态和段落对比；必要时再提高 BPM；
- **推进不足** → 调整能量曲线，增加分层进入、滚奏蓄力、drop 或最终重拍；
- **太密/文字没空间** → 降低鼓点密度，增加重音间隔或改为舒缓流动；
- **改字段**（“BPM 改 110”“换 jazz”“不要骤停”）→ 直接修改对应字段并重新 preview；
- **整体不对**（“完全不对”“换方向”“重新来”）→ 回到第一步；
- **满意**（“OK”“可以”）→ 结束。

反馈模糊时只问一个澄清问题。例如用户说“节奏感不对”，询问：“是鼓点不够明显，还是音乐缺少推进和能量峰值？”

## 工具调用规范

- 必传字段：`prompt`, `output_file_path`；
- 可选字段：`lyrics`, `is_instrumental`, `sample_rate`, `bitrate`, `format`；
- prompt 长度 10–300 字符；
- 纯器乐时 prompt 末尾固定写 `没有人声`，同时传 `is_instrumental: true`；
- 含歌词时传 `lyrics`，不传 `is_instrumental`；
- 时长和 BPM 写入 prompt 控制，不是工具参数；
- 同一 prompt 多次生成的结果可能不同，需告知用户。

## 注意事项

- 必含目标时长、节奏方式、能量曲线和歌词决策；
- “有节奏感”首先意味着清晰鼓点、重音、推进和段落对比，不等于单纯提高 BPM；
- 用“约 124 BPM”等软表达，不承诺模型严格遵守；
- 对关键音乐事件描述相对位置，不要求精确秒点；
- 纯器乐使用 prompt 与 API 参数双保险；
- 时长不符时默认不剪，只有用户明确确认后才剪；
- 用户提到参考曲时，将意图转写为流派、情绪、乐器、节奏和能量结构，不尝试传参考音频；
- 不设计视频分镜，不使用视频内置模板，不生成额外文件。
