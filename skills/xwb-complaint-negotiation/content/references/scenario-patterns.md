# 典型投诉场景模式

> 本文件是 XWB 客诉岗 4 大典型投诉场景的快速识别和处理模式库。
> 调用 skill 时先按本文件归类，再按 SKILL.md 的 6 步流程执行。

## 场景总览

| 代码 | 场景名 | 客户常说的"信号词" | 发生频率 | 沟通难度 |
|------|-------|------------------|---------|---------|
| A | 利率合规争议 | "高利贷"、"超过国家规定"、"4 倍 LPR"、"砍头息" | 高 | 中-高 |
| B | 风控与贷后管理争议 | "审核不严"、"没尽到告知义务"、"把我的钱放给骗子" | 中 | 中 |
| C | 平台操作失误争议 | "功能有问题"、"界面不清晰"、"我点错了" | 中 | 低-中 |
| D | 综合诉求类 | "我全都要"、"不解决就 12378" | 高 | 高 |

## A. 利率合规争议

### 客户特征
- **理性型**居多，会自己算 IRR、引法条、找判例
- 年龄 25-40 岁，常见有过借贷经历或法律相关背景
- **诉求链条**：要求核算 → 要求退费 → 要求停催 → 要求赔偿损失

### 常见具体表述
- "我借 5 万分 24 期，每期还 2800，你们这年化超过 36%，是国家明令禁止的高利贷"
- "我看了最高法的规定，超过 4 倍 LPR 部分应该退还给我"
- "你们合同写的利率 18%，但实际算下来 30%，这是阴阳合同"
- "我在聚投诉、黑猫投诉上看到很多人投诉你们"

### 我方核查重点
1. **合同名义利率 vs IRR**：合同写 18%，但手续费、担保费、服务费加一起可能 IRR 超过 24%
2. **合同成立时点的 LPR**：决定 4 倍 LPR 适用版本
3. **是否有砍头息**：放款金额 < 合同金额就是砍头息
4. **服务费等是否合规**：是否有第三方收取、有无合同依据

### 风险等级
- **高风险**：IRR 超过 4 倍 LPR + 客户已投诉监管/媒体
- **中风险**：IRR 超过 24% + 客户已留证
- **低风险**：IRR 在 18%-24% 区间，但客户主观感受贵

### 典型让步方案
- 方案 A（理想）：经法务/财务测算 → 退还超出 4 倍 LPR 部分的利息 + 500 元京东卡（**需主管审批**）
- 方案 B（折中）：减免 1-3 期息费 + 500 元京东卡 + 停催 30 天
- 方案 C（兜底）：当前合同利率符合监管要求（**需出具书面依据**），建议走调解/诉讼

### 话术关键点
- 不主动说"4 倍 LPR 不适用"——给自己留余地
- 用"我理解您对利率的关注"开场，**绝对不要**用"我们利率是合规的"开篇
- 释法时用"我会帮您核查合同实际 IRR"——具体数字让财务出
- 客户已投诉 12378/聚投诉时，话术头部加"⚠️ 监管投诉"标签

## B. 风控与贷后管理争议

### 客户特征
- **激动型**居多，常有"受害者心态"
- 常见情形：被诈骗后认为银行没拦住借款方、家人突然离世后不知有贷款、未充分告知就被放款
- 情绪激动时容易哭闹、骂人

### 常见具体表述
- "我是被骗的，银行凭什么放款给骗子"
- "我老公走了，家里根本不知道有这个贷款，银行怎么不核实就放"
- "我签字的时候根本没看清内容，银行没尽到告知义务"
- "我都是按月还的，你们怎么还一直催我"

### 我方核查重点
1. **签约视频/录音**：是否完整、是否本人签署、是否充分告知
2. **资金流向**：是否直接到客户账户、是否被立即转出（被诈骗特征）
3. **贷后管理记录**：是否按时发送还款提醒、催收是否规范
4. **客户身份核实**：是否本人办理、有无冒名

### 风险等级
- **高风险**：签约过程有瑕疵 + 客户被诈骗 + 已报警
- **中风险**：贷后催收确有不当 + 客户受严重精神打击
- **低风险**：客户单纯不理解业务流程

### 典型让步方案
- 方案 A（理想）：根据核查结论 → 减免部分息费 + 500 元京东卡 + 提供延期/分期方案
- 方案 B（折中）：出具书面情况说明（不直接认错）+ 申请延期还款 + 500 元京东卡
- 方案 C（兜底）：业务流程合规、责任认定需走法律程序 + 引导报警/起诉

### 话术关键点
- **绝对不和客户争对错**——先听完再复述
- 对"被诈骗"情形：表达共情 + 引导报警 + 不要替诈骗方辩护
- 对"家人去世"情形：表达哀悼 + 慢速沟通 + 给出明确时间表
- 对"签约瑕疵"情形：核查签约资料再说，不在电话中直接承认

## C. 平台操作失误争议

### 客户特征
- **理性偏弱势型**，对流程不熟，但有正当理由
- 情绪相对稳定，但有"被歧视感"——觉得银行不重视小客户
- 容易在小额赔付上满意，但核心诉求是"承认错误"

### 常见具体表述
- "我明明点的是结清，你们页面把解押放在第一个，我点错了"
- "我申请提前还款，App 一直转圈，结果产生了逾期利息"
- "你们客服电话打不通，我在 App 留言也没人回"
- "我是按你们提示操作的，结果系统出问题，损失要我承担不合理"

### 我方核查重点
1. **操作日志**：客户实际点了什么、何时操作
2. **页面设计**：是否有 UI 缺陷、按钮位置是否合理
3. **系统故障记录**：是否当时有故障、客户是否受影响
4. **客服响应时长**：客户咨询后多久得到响应

### 风险等级
- **高风险**：我方系统/UI 确有 BUG + 客户有具体损失
- **中风险**：客户操作有责任 + 我方设计也有缺陷
- **低风险**：客户完全理解有误、我方无明显问题

### 典型让步方案
- 方案 A（理想）：承担操作后到我行处理期间的实际损失（按合同日利率计算）+ 500 元京东卡 + 出具书面致歉
- 方案 B（折中）：承担 50% 损失 + 500 元京东卡 + 提交产品部门优化（书面反馈单）
- 方案 C（兜底）：损失按合同正常计算 + 建议走"我行差错申诉"流程 + 出具书面说明

### 话术关键点
- 开场用"我特别理解您着急的心情"——客户的核心诉求是"被认真对待"
- 释法时强调"我们也会反思流程设计"——让客户感觉银行有自省能力
- 给具体时间表："我会在 X 个工作日内联系技术部门确认页面问题"
- **关键**：即使是兜底方案，也要给客户"被听见"的感觉

## D. 综合诉求类（最难处理）

### 客户特征
- **强硬型**居多，往往已通过其他渠道（12378、聚投诉、媒体）施压
- 多次投诉、多个诉求一起提、要"一揽子解决"
- 部分是"职业投诉人"——以投诉为业

### 常见具体表述
- "今天必须把高息、停催、赔偿、修复征信全解决了"
- "我同事、12378、银保监、消协都已经投诉了，你看着办"
- "不解决就发抖音、找记者"
- "我之前两次投诉都没解决，今天必须给说法"

### 识别职业投诉人
- 短时间多次投诉多家银行/平台
- 有固定话术模板（如直接念投诉信）
- 明确要求"小额现金 + 删帖"
- 对话中频繁出现"我可以不投诉，只要..."

### 我方核查重点
1. **历史投诉记录**：次数、内容、是否"同质"投诉
2. **已采取的措施**：之前给了什么方案、为什么没达成
3. **外部施压证据**：12378 工单号、媒体沟通记录、监管文件
4. **是否职业投诉人**：参考黑名单/灰名单

### 风险等级
- **极高风险**：已发抖音/上电视台 + 群体性投诉苗头
- **高风险**：12378 已受理 + 客户坚持原诉求 + 既往方案未达成
- **中风险**：客户情绪激动但未真正投诉外部

### 典型让步方案
- 方案 A（理想）：综合诉求中至少 2 项满足 + 500 元京东卡 + 主管当面致歉（**必须主管到场**）
- 方案 B（折中）：核心诉求 1 项满足 + 500 元京东卡 + 承诺 X 日内回复其他诉求
- 方案 C（兜底）：维持原方案 + 引导外部救济 + 主管级书面回复

### 话术关键点
- **绝对不卑不亢**——被威胁时不慌乱，也不强硬对抗
- 用"我行高度重视您多次反馈的问题"开场——肯定客户投诉的合理性
- 关键句式："今天我专门来处理您这件事"——给客户"被重视"感
- 重要让步必须**主管授权**后再说，**绝对不要**在客户施压下口头承诺超额
- 如果是职业投诉人，话术转为"标准化、统一化"，不给出差异化让步（避免被要挟）

## 跨场景通用模式

### 模式 1：客户说"我要投诉 12378"

**应对**：
- 立即说"您完全有权利通过 12378 反映，我行作为被监管对象也会认真对待"
- 但同时引导："我行作为投诉处理的第一责任主体，能更高效解决您的问题——今天这通电话我们就把您的诉求过一遍"
- 如果客户已 12378 投诉：**必须问出投诉编号**、**确认投诉内容**、**承诺处理时限**（一般 7 日内）

### 模式 2：客户要"今天就给结果"

**应对**：
- "我完全理解您着急要结果的心情。但有些事我必须核实清楚才能给您准确答复——比如您的合同 IRR，需要财务部算；催收记录需要调录音。这些都不是我一句话能定的事"
- 给具体时间："X 个工作日内我一定给您明确答复"
- **不要**为了安抚客户做空头承诺

### 模式 3：客户情绪失控

**应对**：
- **绝对不和客户争对错**——客户骂的是事情，不是你个人
- "我能感受到您特别生气——您说的这些换谁都会生气"
- 慢速、柔声、用"我"开头表达理解
- 如果客户持续骂人超过 3 分钟："X 先生/女士，我特别想帮您把这件事处理好，但您现在情绪比较激动。我先停一下，您喝口水/缓一缓，我们 5 分钟后再聊？"
- 如果客户有自伤/伤人倾向：**立即**转危机干预

### 模式 4：客户要"领导来"

**应对**：
- 客服岗先尝试自己解决——"您的诉求我都记下来了，我会逐项跟您过一遍"
- 客户坚持要领导时："我可以帮您预约主管在 X 时间回电您，您看方便吗？"
- **不要**因为客户威胁就给领导——会形成"要挟升级"循环
- 主管介入后，话术统一为"我行已重视您的问题，今天专门由我跟进"

### 模式 5：客户中途"录音/录像/第三方旁听"

**应对**：
- "您有权利对通话进行录音，这是您的合法权益"
- 保持话术标准、不情绪化、不做任何"私下承诺"
- 如有第三方旁听："请问您旁边这位是？——按监管要求我需要确认通话对象"
- 客户提到"我朋友/律师/家人在听"时，话术更严谨、减少口语化表达

## 场景识别快速决策树

```
客户投诉描述
    │
    ├── 提到利率/费用/高利贷 ────────────→ A 利率合规
    │
    ├── 提到审核/告知/被诈骗/被冒名 ────→ B 风控与贷后管理
    │
    ├── 提到 App/页面/系统/操作 ────────→ C 平台操作失误
    │
    ├── 多个诉求 + 已投诉外部渠道 ──────→ D 综合诉求类
    │
    └── 描述模糊 ────────────────────────→ 输出"待补充信息清单"
```
