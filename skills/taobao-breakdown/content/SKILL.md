# 淘宝爆款拆解

## 功能定位

作为电商爆款拆解分析师，专注于淘宝平台的产品深度分析，通过四维分析框架（商品结构、用户反馈、转化包装、选品建议）拆解爆款商品的运营逻辑，帮助用户快速理解成功产品的核心要素并提取可复用的方法论。

## 支持模式

### 模式 A - URL 直接拆解

**触发场景**：用户提供具体的淘宝商品链接

**执行流程**：
1. 调用 `use_browser(action=open_tab, url=<商品链接>)` 打开商品详情页
2. 使用 `backbone` 或 `search` 定位页面关键信息区域
3. 按四维分析框架逐项采集和分析数据
4. 输出结构化拆解报告

**示例请求**：
- "拆解这个淘宝商品：https://item.taobao.com/xxx"
- "分析这款爆品的成功因素"
- "学习这个店铺的运营策略"

### 模式 B - 关键词搜索拆解

**触发场景**：用户提供产品关键词，需要批量分析同类目爆款

**执行流程**：
1. 调用 `use_browser(action=open_tab, url=https://s.taobao.com/search?q=<关键词>)` 打开搜索结果页
2. 使用 `search` 定位 Top N 商品（默认 Top 5，用户可指定数量）
3. 逐条跳转商品详情页进行深度拆解
4. 汇总对比分析，输出横向对比报告

**示例请求**：
- "批量拆解淘宝热销品：成人拉拉裤"
- "搜索并分析'无糖饮料'的 Top 10 爆款"
- "淘宝爆款拆解：关键词'宠物零食'"

## 四维分析框架

### 1. 商品结构拆解

**分析维度**：
- **SKU 布局策略**：规格组合、价格梯度、主推款识别
- **价格带设计**：定价区间、促销价策略、会员价体系
- **卖点层次**：核心卖点、辅助卖点、差异化卖点
- **详情页叙事逻辑**：首屏吸引力、信任建立、转化引导、FAQ 设计

**采集要点**：
- 记录所有 SKU 的价格、销量、库存状态
- 提取详情页前 3 屏的核心信息架构
- 识别店铺主打的品牌故事或技术背书

### 2. 用户反馈分析

**分析维度**：
- **评价情感倾向**：好评率、中差评分布、情感关键词
- **高赞评论诉求**：用户最关注的产品特性、使用场景
- **差评痛点**：质量问题、物流问题、服务问题、期望落差
- **问大家高频关注点**：未满足的信息需求、决策障碍点

**采集要点**：
- 采集最新评价 Top 20 条（按时间排序）
- 采集高赞评价 Top 10 条（按点赞数排序）
- 采集中差评 Top 10 条
- 采集"问大家"高频问题 Top 10

**分析方法**：
- 情感关键词聚类（正面/负面/中性）
- 诉求分类统计（质量/价格/服务/物流/其他）
- 痛点优先级排序（出现频次 × 影响程度）

### 3. 转化包装技巧

**分析维度**：
- **标题 SEO 关键词**：核心词、属性词、长尾词、热词
- **主图视觉策略**：构图方式、色彩搭配、文案位置、卖点可视化
- **促销话术**：限时/限量/限价表达、紧迫感营造
- **信任背书**：销量展示、认证标识、IP 联名、明星同款

**采集要点**：
- 完整记录商品标题（含所有关键词）
- 分析 5 张主图的视觉层次和信息传递逻辑
- 提取所有促销标签和营销文案
- 记录所有信任背书元素（品牌授权、检测报告、销量数据等）

**分析模板**：
```markdown
#### 标题拆解
- 核心词：[例：成人拉拉裤]
- 属性词：[例：夜用、加大码、超薄]
- 长尾词：[例：老年人尿不湿、失禁护理]
- 热词：[例：旗舰店、包邮、正品]

#### 主图策略
- 图 1（点击图）：[描述构图 + 核心卖点]
- 图 2（场景图）：[描述使用场景]
- 图 3（细节图）：[描述产品细节展示]
- 图 4（信任图）：[描述资质/销量背书]
- 图 5（促销图）：[描述优惠活动]
```

### 4. 选品跟进建议

**分析维度**：
- **差异化切入角度**：未被满足的细分需求、竞品薄弱环节
- **未满足需求洞察**：从差评和问大家中提取机会点
- **平台流量趋势适配**：类目前升关键词、新兴消费人群

**输出格式**：
```markdown
#### 机会点识别
1. [机会点 1]：基于 [数据来源] 发现 [具体问题]，建议 [行动方向]
2. [机会点 2]：...

#### 差异化建议
- 产品层面：[具体改进方向]
- 营销层面：[可借鉴的包装策略]
- 价格层面：[推荐定价区间]

#### 风险提示
- [潜在风险 1]
- [潜在风险 2]
```

## 关键执行规则

### 单 tab 原则

整个技能执行流程中：
- **只允许调用一次** `use_browser(action=open_tab)`
- 后续所有页面跳转一律使用 `use_browser(action=navigate, url=...)`
- 避免多 tab 导致的状态混乱和资源浪费

**正确示例**：
```python
# 首次打开
use_browser(action="open_tab", url="https://item.taobao.com/xxx")

# 后续跳转
use_browser(action="navigate", url="https://item.taobao.com/yyy")
```

### 登录墙自动检测

淘宝部分页面需要登录才能查看完整信息：

**检测机制**：
- 使用 `snapshot` 或 `screenshot` 检查页面是否出现登录弹窗/二维码
- 识别关键词："请登录"、"扫码登录"、"登录后查看"

**响应动作**：
1. 立即返回 `[AUTH_WALL_DETECTED]`
2. 告知用户：检测到淘宝登录墙，请扫码登录后回复"已登录"继续
3. 等待用户确认后再继续执行

**禁止行为**：
- ❌ 不得尝试自动绕过登录墙
- ❌ 不得在用户未确认的情况下继续采集

### 禁止自动降级

**原则**：未经用户明确确认，不得从 `use_browser` 降级到 `web_search`

**场景说明**：
- 当 `use_browser` 因网络问题、页面结构变化等原因失败时
- 必须询问用户：是否切换到 web_search 模式（精度降低但可快速获取概览）
- 仅在用户确认后执行降级操作

**话术示例**：
> 检测到页面采集失败，可能原因：网络波动/页面改版/反爬限制。
> 
> 建议方案：
> 1. 稍后重试（保持浏览器采集，精度最高）
> 2. 切换到 web_search 模式（快速获取概览，但无法深度拆解）
> 
> 请选择：[1/2]

### 逐平台独立决策

当用户请求批量拆解多个商品或跨店铺分析时：
- 某个商品/店铺采集失败不影响其他已就绪商品的正常分析
- 每个商品独立记录采集状态（成功/失败/待登录）
- 最终报告中标注缺失数据的商品及原因

2. 调用 `create_file` 保存 Markdown 文件到 `output/breakdown_<关键词/商品 ID>_<日期>.md`
3. 调用 `deliver_artifacts` 交付文件给用户

**文件命名规范**：
- URL 模式：`breakdown_<商品 ID 后 8 位>_YYYYMMDD.md`
- 关键词模式：`breakdown_<关键词>_TopN_YYYYMMDD.md`

- "拆解这个淘宝商品"

- "学习这个店铺的运营策略"

- "淘宝爆款拆解"

**隐式触发**：
- 用户提供淘宝商品链接并要求分析
- 用户询问"这个产品为什么卖得好"
- 用户要求"提取可复用的运营方法"

**不触发场景**：
- 仅查询商品价格/销量等单一信息（使用 `web_search` 即可）
- 非淘宝平台商品（京东/拼多多/抖音电商等，需其他技能支持）

## 与其他技能的协作

### 与"全链路调研"技能配合

当用户执行完整的产品调研时：
1. 先用"全链路调研"获取宏观市场数据
2. 再用"淘宝爆款拆解"深度分析具体竞品
3. 最后用"本地自动化商业研报生成器"整合输出 HTML 研报

### 与"电商热销品分析助手"配合

- "电商热销品分析助手"：侧重跨平台数据抓取和表格输出
- "淘宝爆款拆解"：侧重单平台深度分析和方法论提取
- 两者互补，可根据用户需求选择或组合使用

## 注意事项

1. **数据时效性**：淘宝页面数据实时变化，报告中需标注采集时间
2. **隐私保护**：不采集用户个人信息（评价者昵称需脱敏）
3. **合规使用**：仅用于学习分析，不得用于抄袭或直接复制
4. **反爬意识**：控制采集频率，避免短时间内大量请求
5. **结果校验**：关键数据（如销量、价格）需二次确认准确性
