# Claude：第一性原理深度解析

## 核心原点

先把知识工作拆到底层。

大多数脑力任务，本质上都在做四件事：

1. 明确目标
2. 提供上下文
3. 生成候选方案
4. 判断、修正、落地

**Claude 的本质，不是"替你思考"，而是把你给出的目标、材料、规则、风格、约束，快速转成一个可讨论、可修改、可继续推进的版本。**

### 一句话定义

> **Claude = 一个高可控的认知协作者**
> 你负责方向、判断和标准，它负责理解、组织、生成和迭代。

---

## 一、What - Claude 是什么

Claude 是 Anthropic 的 AI 助手与模型家族，对外既有面向用户的 Claude 应用，也有面向开发者的平台与 API。

### 模型线

| 模型 | 定位 |
|------|------|
| **Opus** | 最高能力，适合复杂任务 |
| **Sonnet** | 平衡能力与速度 |
| **Haiku** | 轻量快速，适合日常任务 |

### 产品线

- Claude（主应用）
- Claude Code（代码辅助）
- Claude Cowork（协作扩展）
- Claude for Chrome
- Claude for Slack
- Claude for Excel
- Claude for PowerPoint

### 从使用角度看

Claude 不是单一软件功能，而是一个**"自然语言工作台"**。

你可以用普通语言让它做：
- 解释、总结、改写、分析
- 写作、代码辅助、资料整理

还可以借助 Projects、Artifacts、Skills、工具集成来承接更复杂、更长期的任务。

---

## 二、Why - 为什么要用 Claude

### 第一性原因，只有三个

#### 1. 降低从 0 到 1 的成本

很多人不是没有能力，而是卡在"起步太慢"。

Claude 能先把**模糊想法变成提纲、方案、草稿、比较框架**，让你从空白直接进入修改状态。

#### 2. 降低处理复杂上下文的成本

知识工作真正难的，不是写一句话，而是同时处理很多背景、材料、历史记录和约束。

**Anthropic 近年把重点从"提示工程"推进到"上下文工程"** —— 不只想怎么提问，更要想给模型什么上下文、按什么结构给、如何持续维护上下文状态。

#### 3. 降低反复打磨的成本

Claude 的价值，不在一锤子答案，而在连续迭代。

- **Projects**：把你的资料、历史对话、定制指令放在一起，减少每次重讲背景的成本
- **Artifacts**：把代码、文档、图示、网页原型直接放在旁边边看边改

### 核心价值定位

因为它特别适合下面这类工作：

- 先快速出一个像样版本
- 再围绕你的标准不断精修
- 在复杂材料里保持较好的任务连续性
- 把"思考"变成"对话 + 迭代 + 定稿"

---

## 三、Who - 谁最适合用 Claude

最适合 Claude 的人，不是"最会提问的人"，而是：

- 需要**大量写作、总结、整理**的人
- 需要**读文档、抽重点、做比较**的人
- 需要和**代码、资料、规范长期打交道**的人
- 需要**反复修订内容**的人
- 需要把**个人经验或团队方法沉淀成固定工作流**的人

**典型场景**：个人项目、日常任务、团队生产力、文档协作、工具连接、Skills。

---

## 四、When - 什么时候最该用 Claude

Claude 最值得用，不是在"答案很简单"的时候，而是在下面四种情况：

### 1）你知道目标，但不知道如何起步

- 要写方案、做研究、搭框架、整理观点
- 这时让 Claude 先出骨架，最省力

### 2）你手上信息很多，但结构混乱

- 长文档、会议记录、规范、访谈、历史资料
- Claude 的一个长期方向，就是提升它在长上下文中的工作能力

### 3）你需要多个备选版本

- 三种标题、两套方案、不同语气、不同受众版本
- Claude 适合总结、问答、协作写作和多版本生成

### 4）你希望它成为一个长期协作者

- 持续写一个项目、维护一套知识库、围绕同一类任务反复复用
- 这时就该用 **Projects、Artifacts、Skills**，而不是每次重新开新对话

## 六、How - 如何使用 Claude

### 核心三件事

Claude 用得好不好，核心不在"会不会提问"，而在于是否做对了三件事：

1. **把目标说清楚**
2. **把上下文给准确**
3. **把输出标准定明确**

### 实战七步法

#### 第一步：先定任务，不要直接求答案

不要只说："帮我写一下。"

要说成：
- 我要解决什么问题
- 给谁看
- 结果拿来干什么
- 你先做哪一步

**示例**：
> "我要写一份给管理层看的项目复盘，请先列出结构，再补关键分析。"

#### 第二步：给上下文，而不只是给命令

Claude 的效果，极大依赖上下文质量 —— 这叫 **"context engineering"**。

上下文通常包括：
- 背景
- 目标对象
- 材料
- 限制条件
- 已有草稿
- 风格要求
- 判断标准

#### 第三步：规定输出格式

明确说你要的是：
- 提纲
- 表格
- 清单
- 备忘录
- 正式邮件
- 报告摘要
- 对比分析
- 下一步行动项

#### 第四步：复杂任务先让它拆步骤

**主动要求它先拆解任务，再逐段完成**。

你可以这样说：
> "先不要直接写全文。先拆成 5 个步骤，并说明每一步要用到哪些信息。"

#### 第五步：长文档任务，先抽证据，再下结论

Anthropic 明确给出的有效技巧：

1. 先提取与问题相关的引用或证据，再回答
2. 用示例帮助模型理解正确回答方式

**更好的问法**：
> "先提取与主题最相关的 8 条原文要点，再基于这些要点给总结，并标注每条结论对应的依据。"

#### 第六步：指令要尽量放在最后，关键要求要醒目

Anthropic 特别强调：**把关键指令放在提示末尾有助于提高模型对指令的召回**。

所以长任务里，最后集中写一次：
- 目标
- 输出格式
- 禁止事项
- 评价标准

#### 第七步：把 Claude 当"迭代器"，不要当"一次性答案机"

高质量使用通常不是"一问结束"，而是：
1. 先出骨架
2. 再找漏洞
3. 再重写
4. 再压缩
5. 再改成适合不同对象的版本

## 七、How much - 要投入多少才能用好

Claude 的门槛不在"会不会打字"，而在三种投入：

| 投入类型 | 说明 |
|----------|------|
| **目标投入** | 你越清楚自己要什么，Claude 越容易给出高质量结果 |
| **上下文投入** | Claude 很强，但它不会自动知道你脑子里的前提；不给背景，就只能给通用答案 |
| **迭代投入** | 第一版通常只是起点，真正有价值的结果，多数来自二到三轮追问和修订 |

### 使用公式

> **结果质量 = 目标清晰度 × 上下文质量 × 迭代次数**

## 八、常见五大误区

| 误区 | 正确做法 |
|------|----------|
| 把它当搜索框 | Claude 更擅长整理、重写、比较、拆解、生成 |
| 问题太空 | 没有对象、没有目的、没有标准 |
| 没给材料 | 不给文档、不贴草稿、不讲背景，很难得到贴身结果 |
| 不会追问 | 不会让它继续：缩短/重写/举例/反驳/补漏洞/排序 |
| 不做最终校验 | 关键事实、数据、判断仍要复核 |

## 九、最实用的提问模板

```
你现在扮演[角色]。

我的目标是：
[写清目标]

背景信息：
[补充背景、对象、材料、现状]

约束条件：
[时间、篇幅、风格、禁忌、标准]

请按以下步骤执行：
1. 先复述你对任务的理解
2. 再给出解决思路
3. 最后按指定格式输出结果

输出格式：
[提纲/表格/清单/正式文稿/对比分析]

要求：
- 不确定的地方请标注
- 结论要和依据对应
- 表达简洁

如果是长文档任务，再加一句：
先提取与问题最相关的原文要点，再基于这些要点回答，不要直接跳到结论。
```

## 极简结论

### 为什么用 Claude

因为它能显著降低**起步、整理、理解复杂上下文、连续打磨**的成本，尤其适合知识型、文档型、协作型任务。

### 如何用 Claude

**记住四步**：

1. 先定目标
2. 再给上下文
3. 明确输出格式和标准
4. 通过多轮迭代逼近你要的结果

**如果任务很长**：用 Projects 承接背景，用 Artifacts 承接产物，对长材料先抽证据再总结。
