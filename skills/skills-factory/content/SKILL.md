# Skills工厂

## 技能概述

本技能是一个全能型技能设计与创建工具，专注于为用户打造高质量、高复用性的Expert Agent技能（Skills）。核心目标是适配所有类型技能的编写需求，无论用户需要的是简单模板类技能，还是复杂的领域知识类、流程类技能，都能提供标准化、精细化的设计与编写支持，全程贴合SKILL.md标准格式，确保技能可直接使用、可灵活适配、可后续优化。

本技能同时内置专业级的UI/UX色彩与视觉设计知识库，涵盖色彩心理学应用、视觉层次构建、行业特定规范（电商、金融、社交）三大核心领域，可在创建UI/UX相关技能时提供深度参考和专业指导。

适用人群：需要创建、优化Expert Agent技能的所有用户；需要UI界面色彩与视觉风格专业指导的高级UI设计师、UX设计师、前端开发工程师。

技能边界：本技能聚焦技能的设计与创建流程，以及UI/UX色彩与视觉风格层面的专业指导；不包含交互设计、信息架构、用户研究等内容。

## 使用场景

- 场景1：用户需要从零创建一个新的Expert Agent技能，需要完整的需求分析、结构设计和内容编写
- 场景2：用户有现有技能需要优化，需要从专注性、可复用性、清晰性、实用性四个维度进行改进
- 场景3：用户需要为特定领域（如编码规范、工作流程、领域知识等）创建专业技能
- 场景4：用户需要创建UI/UX相关技能时，需要专业的色彩设计、视觉层次、行业规范等参考内容
- 场景5：用户需要了解SKILL.md标准格式和技能设计最佳实践

## 工作流程

### 第一阶段：需求精准询问

1. 主动向用户确认核心需求，重点询问4点：
   - ① 技能类型（参考下方"技能类型参考"）
   - ② 核心用途（解决什么问题、达成什么目标）
   - ③ 适用人群/场景
   - ④ 特殊要求（如是否需要补充示例、是否有固定结构）
2. 若用户仅提供模糊需求（如"帮我写一个Excel相关技能"），需主动引导用户明确技能类型、核心用途，避免盲目编写

### 第二阶段：范围明确界定

3. 根据用户需求，明确技能的核心内容、边界（不包含哪些内容）、复杂度
4. 确认是否需要适配特殊场景，确保技能不贪多、不缺失，贴合用户实际需求

### 第三阶段：结构个性化设计

5. 根据技能类型，规划贴合其特点的核心内容结构
6. 明确每个章节的重点和呈现形式，确保结构合理、重点突出
7. 若涉及UI/UX色彩设计相关内容，参考下方"UI/UX色彩与视觉设计知识库"中的专业内容

### 第四阶段：内容精细化编写

8. 严格按照SKILL.md标准格式编写，遵循通用原则+分类型适配原则
9. 补充具体步骤、示例、注意事项，确保内容可操作、可复用、通俗易懂
10. 所有技能文件统一放置在 `skills/{skill_name}/SKILL.md`

### 第五阶段：多维度验证检查

11. 从5个维度检查：
    - ① 格式是否符合标准
    - ② 内容是否专注、实用
    - ③ 示例是否具体、可复用
    - ④ 语言是否清晰、易懂
    - ⑤ 是否贴合用户需求和技能类型

### 第六阶段：优化调整迭代

12. 根据用户反馈，快速调整技能内容、结构
13. 补充缺失部分、简化冗余表述，确保技能完全符合用户需求

## 核心职责

1. **需求深度拆解**：不仅理解用户所需技能的类型和用途，更要挖掘技能的核心场景、使用人群、复用频率，明确技能的边界和细节要求，避免内容冗余或缺失（适配简单/复杂各类技能）。

2. **个性化技能设计**：根据技能类型（如模板类、流程类、知识类），设计贴合其特点的结构、内容和呈现形式，确保结构合理、重点突出，既符合标准化要求，又有针对性。

3. **标准化技能创建**：严格按照SKILL.md标准格式编写完整内容，规范用词、统一结构，确保不同类型技能的格式一致性，同时兼顾内容的差异性，避免"一刀切"。

4. **全维度技能优化**：针对现有技能，从"专注性、可复用性、清晰性、实用性"四个维度优化，补充缺失内容、简化冗余表述、完善示例和注意事项，适配各类技能的优化需求。

5. **差异化适配指导**：针对不同类型技能，提供专属的编写建议和侧重点提示，帮助用户快速抓住核心，提升技能编写效率和质量。

## 技能设计原则

### 一、通用核心原则（所有技能必须遵循）

- **专注性**：每个技能聚焦一个特定领域、任务或场景，不跨领域、不贪多求全，确保技能目标明确（如"Excel求和技巧"不掺杂Excel筛选内容）。

- **可复用性**：技能内容需具备通用性，可在多种相似场景下直接使用或简单修改后使用，避免绑定单一特殊场景，降低复用成本。

- **清晰性**：说明、步骤、示例需通俗易懂，避免模糊表述和专业术语堆砌（如需使用术语，必须补充解释），适配不同知识水平的使用者。

- **实用性**：提供具体可操作的知识、步骤、模板或示例，拒绝空泛理论，确保用户使用该技能后能解决实际问题、提升效率。

- **可扩展性**：技能结构预留优化空间，后续可根据需求补充新内容、新示例，适配技能的长期迭代。

### 二、分类型适配原则

- **编码规范类**：侧重"标准性、严谨性"，补充常见错误示例及规避方法，明确代码格式、命名规则，适配不同编程语言/框架。

- **工作流程类**：侧重"步骤性、逻辑性"，明确每个步骤的操作主体、操作标准、时间节点，补充异常情况处理方案。

- **领域知识类**：侧重"专业性、易懂性"，拆分复杂知识，用通俗语言解读，补充行业案例、常见疑问解答，适配不同领域（如金融、教育、技术）。

- **模板类**：侧重"通用性、可修改性"，明确模板的使用场景、填写规范，补充填写示例，预留可修改模块，适配文档、代码、表格等各类模板。

- **检查清单类**：侧重"全面性、准确性"，按逻辑拆分检查维度，明确检查标准（合格/不合格），补充易错点提示，适配质量审核、流程校验等场景。

- **工具使用类**：侧重"操作性、步骤性"，明确工具版本、操作步骤，补充截图提示（文字描述）、常见问题排查，适配各类软件、工具的使用指导。

- **问题解决类**：侧重"针对性、高效性"，明确问题场景、排查步骤、解决方案，补充预防措施，适配各类常见问题的快速解决。

## 技能类型参考

以下为常见技能类型，可根据用户需求灵活新增，所有类型均遵循通用原则+分类型适配原则：

1. **编码规范类**：特定语言（Python/Java/Go）、框架（Vue/React/SpringBoot）的编码标准、最佳实践、错误规避。

2. **工作流程类**：标准化操作流程（如会议组织、文件审批、项目立项）、岗位工作流程、跨部门协作流程。

3. **领域知识类**：特定领域专业知识（如金融理财、法律常识、AI科普、印刷工艺）、行业术语解读、知识体系梳理。

4. **模板类**：可复用文档模板（报告、通知、合同）、代码模板、表格模板、PPT模板，附带填写规范。

5. **检查清单类**：质量检查清单（产品质检、文案审核）、流程校验清单、项目验收清单、安全检查清单。

6. **工具使用类**：软件操作（Excel、PS、飞书）、AI工具（Coze、豆包）、开发工具（VS Code、Git）的使用指导、技巧总结。

7. **问题解决类**：常见故障排查（电脑故障、软件报错）、工作难题解决（文案优化、效率提升）、领域内常见问题解答。

8. **其他定制类**：根据用户特殊需求，适配未涵盖的技能类型，确保不遗漏任何编写需求。

## SKILL.md 标准格式

所有技能统一遵循以下格式，其中「核心内容」可根据技能类型灵活调整结构：

```markdown
---
name: skill_name  # 必选，使用kebab-case格式（小写字母+连字符），如：excel-sum-skill、print-process-guide
description: 技能的简短描述（1-2句话），明确技能用途和核心价值，适配所有类型技能
author: 技能编写者（可选，默认留空）
version: 1.0.0  # 可选，用于技能迭代，默认1.0.0
---

## 技能概述
# 必选，所有技能通用
详细说明技能的用途、核心目标、适用人群、适用场景，明确技能的边界（不包含哪些内容），语言通俗易懂，避免空泛。
- 若为复杂技能（如领域知识类、流程类），可补充技能的核心价值和使用优势；
- 若为简单技能（如模板类、基础工具类），可简洁说明用途和使用场景。

## 使用场景
# 必选，所有技能通用
明确技能的具体使用场景，分点列出，确保场景具体、可落地，避免模糊表述：
- 场景1：具体场景描述
- 场景2：具体场景描述
- 补充：若有不适配场景，可在此说明（可选）

## 核心内容
# 必选，差异化适配各类技能，结构可灵活调整
根据技能类型，设计对应的核心内容结构（参见下方分类型核心内容参考）

## 示例
# 必选，所有技能通用
提供1-2个具体的使用示例，贴合技能核心内容和使用场景

## 注意事项
# 必选，所有技能通用
分点列出使用技能时的注意事项、易错点、禁忌

## 拓展说明（可选）
# 适配复杂技能，简单技能可省略
补充技能的拓展方向、迭代计划、相关技能推荐
```

## 输出规范

1. **文件路径**：所有技能文件统一放置在 `skills/{skill_name}/SKILL.md`，其中 skill_name 与SKILL.md文件中「name」字段一致，使用kebab-case格式（小写字母+连字符）。

2. **命名规范**：
   - 技能名称（name字段）：kebab-case格式，简洁明了，贴合技能用途，不使用特殊字符
   - SKILL.md文件名：固定为大写SKILL.md，不修改文件名

3. **语言规范**：全程使用用户指定的语言编写（默认中文），避免中英文混杂，术语使用准确且补充解释（如需），适配不同用户的语言需求。

4. **格式规范**：严格遵循Markdown规范和上述SKILL.md标准格式，标题层级清晰（## 二级标题、### 三级标题），分点使用有序/无序列表，代码使用代码块，确保格式整洁、可直接渲染。

5. **差异化适配**：输出时需根据技能类型，突出对应重点（如模板类突出模板内容和填写规范，流程类突出步骤和异常处理），确保输出内容贴合技能特点。

## UI/UX色彩与视觉设计知识库

> 以下内容为内置的专业级UI/UX色彩与视觉设计参考知识库，在创建UI/UX相关技能或需要提供色彩设计专业指导时使用。

### 色彩问题诊断框架

#### 问题识别矩阵

UI色彩问题通常可归纳为四大类型，需先定位问题类别再选择对应解决方案：

| 问题类型 | 典型症状 | 诊断方法 | 优先解决优先级 |
|---------|---------|---------|--------------|
| 色彩搭配失衡 | 界面视觉单调或混乱，主次不清 | 检查主色、辅色、点缀色的比例关系 | P0（最高） |
| 对比度不足 | 内容可读性差，用户需费力辨认 | 使用WCAG标准检测前景与背景对比度 | P0（最高） |
| 色彩情感偏差 | 传递的品牌/产品信息与目标不符 | 核对色彩心理暗示与品牌定位一致性 | P1 |
| 视觉层次混乱 | 用户无法快速识别信息优先级 | 分析元素大小、颜色深浅的层级梯度 | P1 |

#### 快速诊断流程（5步法）

- 第1步：远观整体 → 站在1米外观察界面，记录第一视觉印象
- 第2步：色彩提取 → 截图并提取界面主要颜色（建议使用Coolors、Adobe Color）
- 第3步：比例分析 → 计算主色、辅色、背景色、中性色的面积占比
- 第4步：对比检测 → 使用浏览器插件（如ARC Toolkit）或WCAG工具检测关键区域对比度
- 第5步：情感核对 → 对照色彩心理量表，评估色彩传递的情绪是否符合产品定位

| 橙色 | 友好、活力、温暖、创意 | 廉价、嘈杂、过度刺激 | 电商促销活动、创意类产品 | 需要专业严肃感的场景 |

#### 视觉重量平衡公式

界面元素的视觉重量可通过色彩、大小、位置综合控制：

```
视觉重量 = 颜色饱和度 × 0.4 + 元素尺寸 × 0.3 + 位置权重 × 0.3
```

关键原则：
- 高饱和度颜色 = 高视觉重量
- 大尺寸元素 = 高视觉重量
- 右上/中上位置 = 高视觉权重
- CTA按钮饱和度应比周围元素高40%以上

实际应用示例：电商首页卡片设计

```
需求：商品卡片需突出"加入购物车"按钮

方案A（错误）：
- 商品图使用高饱和度
- 按钮使用低饱和度灰色
- 结果：用户注意力被商品图吸引，CTA点击率低

方案B（推荐）：
- 商品图使用中等饱和度+白色边框
- 按钮使用高饱和度品牌色（#FF6B35）
- 按钮周围添加微妙阴影
- 结果：CTA区域视觉重量提升60%，点击率显著提高
```

### 常见问题解决方案库

#### 色彩搭配失衡问题

**问题症状：** 界面看起来"花哨"或"脏乱"，找不到视觉焦点，用户感到视觉疲劳

**诊断方法：**
1. 提取界面所有颜色，按使用面积排序
2. 检查是否存在超过4种以上的"独立色相"
3. 检查高饱和度颜色的使用面积占比

**解决方案：**

```
方案A：建立色彩比例规则（60-30-10法则）
├── 主色（品牌色）：60%面积（背景、大面积区域）
├── 辅色（功能色）：30%面积（次要元素、模块分隔）
└── 点缀色（强调色）：10%面积（按钮、重点标识）

方案B：统一色相，降低明度/饱和度变体
├── 保留1-2个色相
├── 通过调整明度和饱和度创造层次
└── 示例：蓝色为主，通过#1565C0（深）、#42A5F5（中）、#E3F2FD（浅）创造层次

方案C：引入中性色作为"视觉缓冲"
├── 背景使用#FAFAFA、#F5F5F5等中性灰
├── 白色卡片堆叠创造空间感
└── 使用#E0E0E0、#BDBDBD等灰色作为分隔线
```

#### 对比度不足问题

**问题症状：** 文字难以阅读，界面看起来很"平"，重要按钮不够突出

**解决方案：**

```
方案A：加深文字颜色
├── 一级标题：#000000 → 保持
├── 二级标题：#666666 → 改为#333333
├── 正文内容：#999999 → 改为#666666
└── 辅助文字：#BBBBBB → 改为#999999

方案B：调整背景与文字组合
├── 浅色背景+深色文字：对比度更可控
├── 避免浅灰背景+浅灰文字
└── 深色模式单独检测：确保反色对比度同样达标

方案C：增加视觉层次（颜色+字重+字号）
├── 不单纯依赖颜色对比
├── 配合字号放大、字重加粗
├── 重要信息使用图标辅助
└── 示例：按钮文字除了颜色对比，可加粗至600字重

方案D：组件级对比度强化
├── 输入框边框：使用深色边框（#E0E0E0）
├── 按钮背景：使用品牌色填充
├── 选中状态：背景+边框+图标三重视觉反馈
└── 禁用状态：降低整体对比度（但保持可识别性）
```

#### 视觉层次混乱问题

**问题症状：** 用户不知道该看哪里，重要信息被忽略，页面看起来"平"

**解决方案：**

```
方案A：重新定义信息层级
├── 一级信息（核心标题、CTA）：最大字号、最高对比度、视觉重心
├── 二级信息（模块标题）：中等字号、辅色强调
├── 三级信息（正文内容）：标准字号、常规对比度
└── 四级信息（辅助说明）：较小字号、弱对比度

方案B：建立视觉节奏
├── 重要区域：使用品牌主色+大留白+视觉重心
├── 次要区域：使用中性色+紧凑布局
├── 使用卡片/分组创造信息"块"
└── 块与块之间使用一致的间距和分隔

方案C：控制视觉噪音
├── 删除装饰性但无信息价值的元素
├── 减少同层级的颜色种类
├── 图标系统统一：线性/填充二选一
└── 减少渐变使用（除特殊场景）
```

#### 品牌色彩与功能性冲突问题

**问题症状：** 品牌主色与功能色需求冲突（如品牌色是红色但促销也需要红色）

**解决方案：**

```
方案A：建立品牌色板变体
├── 品牌主色：#FF0000（深红，正式场景）
├── 品牌浅色：#FFEBEB（浅红，背景高亮）
├── 品牌深色：#CC0000（深红，悬停状态）
└── 品牌强调色：#FF6B35（活力橙，CTA专用）

方案B：品牌色+功能色双轨制
├── 品牌触点（Logo、导航栏）：严格使用品牌色
├── 功能区域（按钮、数据）：使用功能色
├── 品牌与功能叠加时：以功能色为主，品牌元素弱化
└── 关键品牌时刻（首屏）：突出品牌色

方案C：建立色彩使用规范文档
├── 定义各场景的色彩使用规则
├── 明确哪些区域可灵活调整
├── 提供色板供设计师选择
└── 建立色彩决策的审批流程
```

#### 跨平台色彩一致性挑战

**问题症状：** 网页和App色彩不一致，iOS和Android平台风格差异过大，深色/浅色模式不协调

**解决方案：**

```
方案A：建立跨平台色彩Token系统
├── 核心Token：品牌色（唯一值）
├── 语义Token：primary（对应平台组件）
├── 平台适配Token：android-primary, ios-primary
└── 设计系统使用Token而非硬编码色值

方案B：制定平台适配指南
├── iOS：遵循Apple HIG，使用系统蓝色或品牌定制色
├── Android：遵循Material Design 3，可使用动态色彩
├── Web：使用CSS变量，支持主题切换
└── 桌面端：可使用更丰富的色彩系统

方案C：深色模式色彩映射
├── 浅色主色 → 深色主色（降低饱和度）
├── 浅色背景 → 深色背景（#1A1A1A类）
├── 浅灰分隔 → 深灰分隔（#333333类）
├── 文字颜色：白色→浅灰（#E5E5E5）
└── 保持色相一致，只调整明度和饱和度
```

### UI/UX设计示例

#### 示例1：电商App首页改版色彩优化

**项目背景：** 某综合电商App首页视觉陈旧，用户反馈"没有购买欲望"

**初始诊断：**
- 品牌红（#E60012）：55%面积 → 红色占比过高，造成视觉疲劳
- 橙色（#FF6600）：15%面积
- 黄色（#FFD100）：10%面积 → 黄、橙、红三种暖色叠加，混乱无序
- 白色背景：10%面积
- 黑色文字：10%面积
- 对比度不足：促销标签黄色文字在浅色背景上可读性差

**优化方案：**

```
第一步：重塑色彩比例（60-30-10）
├── 主色（品牌红）：降低至30%，用于Logo、主要按钮
├── 辅助色（中性灰）：提升至50%，用于背景、分隔
└── 点缀色（促销橙）：保持20%，用于价格标签

第二步：建立功能色彩体系
├── 促销标签：深红底+白字（对比度7.2:1）
├── 价格：深色文字+橙色价格符号
├── 按钮：品牌红填充+白字
└── 库存紧张：橙色警告色

第三步：优化视觉层次
├── 首屏焦点区：品牌红按钮+大留白
├── 商品卡片区：白色背景+灰色分隔+品牌红购买按钮
├── 运营位：轮播图使用品牌渐变色
└── 底部导航：灰色图标+品牌色选中态
```

**优化后效果：** 页面视觉复杂度降低40%，CTA按钮点击率提升25%

## 注意事项

### 技能编写通用注意事项

1. 若用户仅提供模糊需求，需主动引导用户明确技能类型、核心用途，避免盲目编写
2. 若用户有现有技能需要优化，需先对照核心原则和标准格式，排查问题（如结构混乱、示例缺失），再针对性优化
3. 可根据用户需求，灵活新增技能类型、调整SKILL.md格式细节，确保不遗漏任何技能编写需求
4. 全程以"用户需求"为核心，兼顾标准化和个性化

### 色彩设计通用注意事项

1. **避免纯色承载关键信息** - 红绿色盲用户无法区分红/绿色彩差异，必须配合图标、文字、形状等多重编码
2. **谨慎使用渐变色** - 渐变会增加视觉复杂度，推荐使用场景：按钮、Logo、品牌元素、首屏背景；避免在正文背景、表格、数据图表使用渐变
3. **深色模式不是简单的反色** - 浅色背景#FFFFFF ≠ 深色背景#000000，深色模式需要独立设计
4. **色彩一致性格外重要** - 同一产品内，相同功能使用相同色彩，建立色彩规范文档

### 行业特定注意事项

1. **金融产品避免"促销感"** - 避免电商式的限时促销色彩设计，涨跌显示使用低饱和度版本
2. **电商产品平衡品牌与促销** - 品牌色是长期资产，不可被促销色取代，建立"日常色"和"大促色"两套方案
3. **社交产品尊重用户个性** - 提供个性化色彩选项但限制范围，核心品牌元素不可被完全覆盖

### 可访问性强制要求

1. 所有正文文本对比度必须达到4.5:1（AA级），大号文本至少达到3:1
2. 金融产品需特别考虑中老年用户，提高字号下限，放大触摸热区
3. 品牌色彩与可访问性冲突时，可访问性优先
