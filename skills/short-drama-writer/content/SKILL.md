# Short Drama Writer · 短剧编剧助手

基于多项目实战沉淀的短剧创作方法论，覆盖从立项到交付的全流程。
**通用设计：适用于任何题材（重生/甜宠/复仇/悬疑/家庭），数值追踪系统可按项目类型自定义。**

---

## 核心工作流（确认制迭代流水线）

```
① 收集立项信息    ← 用户填写briefing
② 确认基本信息    ← 用户确认
③ 编写剧本大纲    ← 不限字数，直到确认
④ 用户反馈修改    ← 反复迭代，直到大纲确认
⑤ 编写分集大纲    ← 根据确认版大纲
⑥ 自检自优        ← 我方内部质量审核
⑦ 确认分集大纲    ← 用户确认
⑧ 逐集写正文      ← 一集确认后，再写下一集
⑨ 交付归档        ← 全部集数确认后交付
```

**核心原则：剧本大纲是最重要的环节——大纲不清，后续全歪。大纲未确认，不进入分集大纲阶段。正文未确认，不进入下一集。**

## 第一阶段：收集立项信息

### ① 收集立项信息

> 💡 **策划/编辑/编剧可以直接使用 `项目启动briefing.md` 模板，填写后发给AI即可。**
> 模板位置：`skills/short-drama-writer/项目启动briefing.md`

**【用户填写项目启动briefing.md后，发给AI，AI自动整理成立项清单】**

收到用户填写的briefing后，AI整理成以下立项清单结构（供用户确认）：

```
【立项清单确认版】

剧名：
题材：
类型：
集数：
时代背景：
金手指：（类型 + 核心机制）
核心设定：（一句话概括）
核心主角：（姓名/年龄/身份）
数值系统：（类型/起点/目标/变化规则）
受众平台：
敏感元素：
```

> ⚠️ **数值系统（金手指/好感度/功德值等）是所有后续阶段的前置条件，必须明确定义。**
> 有数值系统才有约束力，没定义则后续创作自由度过高，容易烂尾。

## 第二阶段：确认基本信息

### ② 用户确认立项清单

> ⚠️ **【强制卡口】基本信息未经用户书面确认，不得进入剧本大纲阶段。**

AI整理好立项清单后，等待用户确认。用户有权修改任何一项。确认后，AI方可进入剧本大纲编写阶段。

## 第三阶段：编写剧本大纲（迭代确认）

### ③ 编写剧本大纲

> ⚠️ **【核心原则】剧本大纲是整个项目最重要的环节。大纲未确认，不得进入分集大纲阶段。**
> 剧本大纲字数不限（通常500-1500字，视复杂度而定），直到用户确认满意为止。

收到立项清单确认后，AI根据用户提供的briefing内容，编写完整剧本大纲，包含：

```
【剧本大纲 · 确认稿】

一、核心主线（一句话概括）
二、故事起点（开篇处境）
三、核心冲突（核心矛盾是什么）
四、关键情节点（按时间线列出主要情节点，涵盖起点→终点）
  - 第X集：……
  - 第X集：……
  - ……
五、结局落点（故事终点，情绪落点）
六、金手指运作（若有）——如何驱动剧情？
七、人物关系走向（主要人物关系的变化轨迹）
八、参考元素（若有）——参考了什么/避免了什么
```

### ④ 等待用户反馈

> ⚠️ **【迭代规则】剧本大纲阶段是迭代最密集的环节，可能反复多次，直到用户确认。**

**用户有权：**
- 修改任何情节点
- 调整人物设定
- 增减角色
- 改变结局方向
- 重新定义金手指机制
- 提出全新思路

**用户确认后，剧本大纲锁版，方可进入分集大纲阶段。**

## 第四阶段：编写分集大纲

### ④ 人物小传七要素

```
1. 姓名 + 年龄 + 身份标签
2. 家庭出身（父母/成长背景）
3. 性格底色（不是形容词，是行为模式）
4. 核心缺陷（原罪）
5. 人物弧光（这一部里他要改变什么）
6. 代表性台词（2-3句，必须能说出人物声音）
7. 与其他人物的核心关系张力
```

> **人物弧光不只是"他变好了"，而是"他因为什么事件、经历了什么阶段，才变好的"。**
> 同时，每份人物小传写完后，必须对照**人物关系进展追踪表**（见下方），确认：
> - 该角色与其他角色的关系初始状态是否与人物小传一致？
> - 该角色在推动关系变化时，行为是否在性格允许范围内？
> - 该角色的改变是否会导致其他人产生相应的反应？（因果链完整）

**反派写法铁律：** 不能写"我要毁了你"，要写"我是为你好"。坏人不知道自己坏。

---

### ④b 人物关系进展追踪表（立项后、大纲前必填）

> ⚠️ **【强制前置步骤】** 人物小传完成后，进入分集大纲前，必须建立关系追踪表。
> 表中每一对重要关系都要回答：初始状态 → 触发因果 → 分集演变 → 终局状态。
> 详见 `references/methodology.md` 第四章。

```
【人物关系进展追踪表 · [项目名称] · v1】

关系对A ↔ B：
  初始状态：____
  变化触发事件：____
  集数演变：
    第X集：A做____ → B感受/回应：____
    第Y集：关系出现转折/倒退：____
    第Z集：关系最终状态：____
关系对C ↔ D：（同上）
```

**第一步：先规划七要素（每集一句话）**

写正文之前，先为本剧17集各自规划一句话版本的七要素：

| 集数 | 【事件】 | 【开头发吸引】 | 【爆点】 | 【反转转折】 | 【高潮结尾】 | 【结尾钩子】 | 【搞笑点】 |
|:----:|---------|------------|---------|------------|------------|------------|---------|
| 1 | … | … | … | … | … | … | … |
| 2 | … | … | … | … | … | … | … |
| … | … | … | … | … | … | … | … |

> **为什么先规划七要素：** 防止写到第10集才发现"开头没钩子"或"这集没有搞笑点"——到那时改大纲成本极高。

**第二步：展开每集正文（一段式）**

在七要素框架基础上，展开每集完整内容：

```

**【开头发吸引】** 前三秒留住观众的内容，要有画面感

**【爆点】** 本集情绪最高点的具体场景

**【反转转折】** 观众意想不到的反转（1-2句）

**【高潮结尾】** 本集情绪落点（具体台词+动作）

**【结尾钩子】** 强钩子，能吸引点下一集的内容

**【搞笑点】** 融合在以上要素中，或单独标注1处

**【标注】** 数值：+X，当前XX | 本集关键关系/情感进展
```

### ⑤ 自检自优（我方内部审核）

> ⚠️ **【内部流程】分集大纲完成后，先由我进行自检自优，通过后才提交用户确认，不得跳过。**

**数值专项检查：**
- [ ] 数值追踪表v1.0是否已建立？每集数值变化是否已规划？
- [ ] 每集数值变化与追踪表完全一致（精确到数字）
- [ ] 钱/债/资产变动与追踪表一致（精确到集数）

**人物关系专项检查：**
- [ ] 每对重要关系的初始状态→触发→演变→终局，四项齐全
- [ ] A改变→B回应，因果链条完整
- [ ] 关系变化有足够集数铺垫（至少2-3集，不能跳级）
- [ ] 关系倒退/危机是否暴露了初始状态中埋下的旧有问题

**结构专项检查：**
- [ ] 全部集数已完成七要素框架规划，无遗漏
- [ ] 每集【搞笑点】有标注（每集必须有1处）
- [ ] 第一个付费节点有强钩子（关系转折点）
- [ ] 第二个付费节点有强钩子（深层转变点）
- [ ] 七要素格式完整，无缺项

自检通过后，输出"自检通过 ✓"，方可提交用户确认。

## 第四阶段：正文与交付

### ⑦ 单集正文格式规范

详见 `references/format.md` — 包含完整格式模板、台词创作方法论、闪回规范。

**每集正文写作时，对照追踪表v1.0：**
- 在对应场次嵌入系统VO（功德值/好感度/等数值变化提示）
- 每集数值VO不超过2次，避免刷屏
- 数值VO格式：`（VO）【系统名称】触发事件，数值+X/-X。当前：XX/100。`

**人物关系专项检查（每集正文写完后必做）：**
```
□ 本集A对B做了什么具体行动？是否符合关系进展追踪表中的阶段？
□ B对本A的行动做出了什么回应？是否在关系进展追踪表中有记录？
□ 如果本集A突然对B特别好/特别差，行为是否有足够的前置铺垫？
□ 关系倒退时，矛盾是否暴露了初始状态中埋下的旧有问题？
```

### ⑧ 五维自检（每集写完后必查）

详见 `references/methodology.md` 第一章 — 五维清单：时间轴 / 空间轴 / 人物状态轴 / 逻辑轴 / 格式轴。

**数值类专项检查：**
- [ ] 本集系统VO中的数值变化量，是否与追踪表v1.0一致？
- [ ] 钱的变动（收入/支出），是否与追踪表一致？
- [ ] 数值是否在合理范围内？（未超限、未为负）
- [ ] 任意一处不一致 → 立即修正，不得进入下一集

## 复盘机制（每剧完成后必做）

完成一个剧本后，执行项目复盘，写入 `methodology.md` 第八章：
1. 列出本剧发现的bug/数值错误
2. 分析根因（流程缺失？规则不清晰？执行不到位？）
