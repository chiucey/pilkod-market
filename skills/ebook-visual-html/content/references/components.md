# 结构判定与组件选择

从扫描页 / PDF 提取文字之后，真正的活在判定：**这段是什么**。判定错了，后面所有排版都跟着错。
下面按判定顺序给出规则和反例。

## 判定顺序

1. **是不是新的一章？** 页首独立成行的短标题 + 其后有正文换行间距 → 新章，建 `chapter`。
   章内的小标题通常顶格、字号略小、后面紧跟正文 → `h3`。
2. **是不是正文？** 连续多行、字号统一、无缩进强调 → `prose`。默认绝大多数块都是它。
   **原文里断开的地方，就是段落边界**——扫描页上每段第一行缩进两字或段间有空隙，按那个断。
3. **是不是原话引用？** 独立成段、字号更大或带引号、作者本人的判断 → `pull`。
4. **是不是并列结构？** 三到五条同构要点、带序号或小标题 → `cards` 或 `list`。
5. **是不是数据？** 数字与标签成对、能排序 → `bars`；是多行多列对照 → `table`；
   是带年份的先后事件 → `timeline`。
6. **是不是原文之外的东西？** 编者按、术语解释、数据来源、延伸阅读 → `callout`。
7. **是不是配图？** 整页或页中大块图 → `figure`；暂时没有干净切图 → `slot`。

## 组件选择要点

- **正文别滥用加粗。** `prose` 里的强调留给真正的判断句；一段里超过两处强调等于没有强调。
- **`pull` 是稀缺资源。** 一章最多一两条。全都变引文，页面就失去呼吸。
- **`cards` 只在真的并列时用。** 两句话不必做卡片；卡片之间靠 1px 线分隔，多了会碎。
- **表格不是万能容器。** 两列三行的东西用 `cards` 或 `list` 更耐看；
  表格一多，纸感立刻变成 Excel 感。
- **`bars` 的 `value` 是比例不是原始数值。** 显示值放 `display`（如 `1.2 万`），条长用 `value`（0–100）。
- **`callout` 分两种**：`tone: amber` 放需要读者注意的补充，`tone: note` 放延伸材料与出处。
- **`divider` 是结构信号**，只在两章之间或大段落切换处用，不要每几段就放。

## 反例

- 把同一章的多个段落并进一个 `<p>` —— 段落是书最基本的节奏单位，
  合段之后页面会变成一堵密实的字墙，扫两行就想走。宁可多花一轮把段断对。
- 从配图里 OCR 出文字混进正文 —— 除非用户明确要求。书里的插图文字往往是装饰性排版，
  OCR 出来是断句错误的长串，塞进正文比没有更糟。
- 素材里没写副标题，却自己编一句填上去 —— 电子版会被人当成原书信息转述，错的东西传得比空白更远。
- 章节号用 `第一章` 又在 `no` 字段里写 `Chapter 01`，页面上出现两套编号 —— 二选一。
- 目录项数量与章节数不一致 —— `verify.mjs` 会报错，不要靠手改 HTML 对齐。
