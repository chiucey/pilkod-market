# 文档追溯性规范

## 概述

追溯性确保文档之间的关联关系清晰可查，是实现自校验、自测试、自验收的基础。

## 追溯关系模型

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   SC-001 ─────────────────────────────────────────── OBS-001   │
│     │                                                   ▲       │
│     │                                                   │       │
│     ▼                                                   │       │
│   UC-001 ──────────┬─────────┐                          │       │
│     │              │         │                          │       │
│     ▼              ▼         │                          │       │
│   REQ-001        REQ-002     │                          │       │
│     │              │         │                          │       │
│     ▼              ▼         │                          │       │
│   TC-001 ──┬── TC-002 ──┐   │                          │       │
│     │      │      │     │   │                          │       │
│     ▼      ▼      ▼     ▼   │                          │       │
│   AC-001  AC-002  ...  ...  ─┴──────────────────────────┘       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## ID 命名规范

### ID 格式

| 文档类型 | ID 前缀 | 格式 | 示例 |
|:---------|:--------|:-----|:-----|
| 场景 | SC | SC-NNN | SC-001, SC-002 |
| 用例 | UC | UC-NNN | UC-001, UC-002 |
| 需求 | REQ | REQ-NNN | REQ-001, REQ-002 |
| 测试用例 | TC | TC-NNN | TC-001, TC-002 |
| 验收标准 | AC | AC-NNN-1 | AC-001-1, AC-001-2 |
| 验收报告 | ACC | ACC-NNN | ACC-001 |
| 观测指标 | OBS | OBS-NNN | OBS-001, OBS-002 |
| 告警规则 | ALT | ALT-NNN | ALT-001, ALT-002 |
| 业务规则 | BR | BR-NNN | BR-001, BR-002 |
| 问题 | ISS | ISS-NNN | ISS-001, ISS-002 |
| 缺陷 | BUG | BUG-NNN | BUG-001, BUG-002 |

### ID 分配规则

1. **按顺序分配**：NNN 为三位数字，从 001 开始
2. **全局唯一**：同一项目内 ID 不能重复
3. **不可重用**：删除的 ID 不能重新分配

## 追溯关系定义

### 正向追溯（自顶向下）

| 源文档 | 目标文档 | 关系类型 | 必须性 |
|:-------|:---------|:---------|:-------|
| 场景 | 用例 | derives | 必须 1:N |
| 用例 | 需求 | requires | 必须 1:N |
| 需求 | 测试用例 | verified-by | 必须 1:N |
| 需求 | 验收标准 | satisfied-by | 必须 1:N |
| 验收标准 | 测试用例 | tested-by | 必须 1:1 |
| 场景 | 观测指标 | measured-by | 推荐 1:N |

### 逆向追溯（自底向上）

| 源文档 | 目标文档 | 关系类型 | 用途 |
|:-------|:---------|:---------|:-----|
| 测试用例 | 需求 | traces-to | 变更影响分析 |
| 需求 | 用例 | traces-to | 变更影响分析 |
| 用例 | 场景 | traces-to | 变更影响分析 |
| 观测指标 | 场景 | traces-to | 业务关联分析 |

## 追溯矩阵

### 矩阵结构

| 需求 | TC-001 | TC-002 | TC-003 | TC-004 | 覆盖率 |
|:-----|:-------|:-------|:-------|:-------|:-------|
| REQ-001 | ✓ | ✓ | - | - | 100% |
| REQ-002 | - | - | ✓ | ✓ | 100% |
| REQ-003 | - | ✓ | ✓ | - | 100% |

### 覆盖率计算

```
需求覆盖率 = 已追溯的需求数 / 总需求数 × 100%
测试覆盖率 = 已追溯的测试数 / 总测试数 × 100%
验收覆盖率 = 已追溯的验收标准数 / 总验收标准数 × 100%
```

## 追溯性校验规则

### 完整性校验

| 规则 | 说明 | 严重程度 |
|:-----|:-----|:---------|
| SC-TR-001 | 每个用例必须追溯到场景 | Error |
| UC-TR-001 | 每个需求必须追溯到用例 | Error |
| REQ-TR-001 | 每个需求必须至少有一个测试用例 | Error |
| REQ-TR-002 | 每个需求必须至少有一个验收标准 | Error |
| AC-TR-001 | 每个验收标准必须至少有一个测试用例 | Warning |

### 一致性校验

| 规则 | 说明 | 严重程度 |
|:-----|:-----|:---------|
| ID-UNIQUE-001 | ID 必须全局唯一 | Error |
| ID-FORMAT-001 | ID 格式必须符合规范 | Error |
| REF-EXIST-001 | 引用的 ID 必须存在 | Error |

### 冗余校验

| 规则 | 说明 | 严重程度 |
|:-----|:-----|:---------|
| REQ-ORPHAN-001 | 孤立需求（无来源用例） | Warning |
| TC-ORPHAN-001 | 孤立测试（无追溯需求） | Warning |

```markdown
- 总场景数: 5
- 总用例数: 12
- 总需求数: 25
- 总测试用例数: 48

## 覆盖率

| 维度 | 覆盖率 | 状态 |
|:-----|:-------|:-----|
| 场景→用例 | 100% | ✓ |
| 用例→需求 | 100% | ✓ |
| 需求→测试 | 96% | ⚠ |
| 需求→验收 | 100% | ✓ |

## 问题清单

| 问题ID | 类型 | 描述 | 影响 |
|:-------|:-----|:-----|:-----|
| TR-001 | Missing | REQ-015 缺少测试用例 | High |

## 建议

1. 为 REQ-015 补充测试用例
2. ...
```

## 工具支持

### 追溯性校验脚本

```bash
# 校验所有文档的追溯关系
npx ts-node scripts/validate-traceability.ts ./docs

# 生成追溯矩阵
npx ts-node scripts/generate-trace-matrix.ts ./docs --output ./trace-matrix.md

# 检查代码覆盖
npx ts-node scripts/validate-coverage.ts ./src --docs ./docs
```
