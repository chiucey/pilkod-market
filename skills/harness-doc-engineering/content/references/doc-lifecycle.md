# 文档生命周期详解

## 概述

文档生命周期定义了从场景到观测的完整闭环，确保每个阶段都有明确的输入、处理和输出。

## 生命周期阶段

### 阶段一：场景(Scenario)

**目的**：描述业务场景，建立业务上下文

**输入**：
- 业务需求
- 用户调研
- 竞品分析

**处理**：
1. 识别目标用户
2. 描述用户环境
3. 定义业务目标
4. 分析当前痛点
5. 设定成功标准

**输出**：
- 场景文档（SC-NNN）
- 观测指标定义（OBS-NNN）

**质量门禁**：
- [ ] 角色定义完整
- [ ] 业务目标可量化
- [ ] 成功标准明确
- [ ] 审批通过

### 阶段二：用例(Use Case)

**目的**：从场景提炼具体使用场景

**输入**：
- 场景文档
- 用户故事

**处理**：
1. 分析用户操作流程
2. 识别主流程和异常流程
3. 定义前置条件和后置条件
4. 提取业务规则

**输出**：
- 用例文档（UC-NNN）
- 业务规则（BR-NNN）

**质量门禁**：
- [ ] 主流程完整
- [ ] 异常流程覆盖
- [ ] 业务规则明确
- [ ] 审批通过

### 阶段三：需求(Requirement)

**目的**：从用例抽取可实现的规格

**输入**：
- 用例文档
- 业务规则
- 技术约束

**处理**：
1. 提取功能需求
2. 定义非功能需求
3. 编写验收标准
4. 设计接口定义
5. 建立数据模型

**输出**：
- 需求文档（REQ-NNN）
- 验收标准（AC-NNN）
- 接口定义

**质量门禁**：
- [ ] 需求可测试
- [ ] 验收标准符合 Given-When-Then
- [ ] 接口定义完整
- [ ] 审批通过

### 阶段四：代码实现(Code)

**目的**：根据需求实现功能

**输入**：
- 需求文档
- 接口定义
- 数据模型

**处理**：
1. 编写代码实现
2. 在代码注释中标记需求 ID
3. 编写单元测试

**输出**：
- 源代码
- 单元测试代码

**质量门禁**：
- [ ] 代码覆盖所有需求
- [ ] 单元测试通过
- [ ] 代码审查通过

### 阶段五：测试(Test)

**目的**：验证需求是否正确实现

**输入**：
- 需求文档
- 验收标准
- 测试用例模板

**处理**：
1. 执行测试用例
2. 记录测试结果
3. 报告缺陷

**输出**：
- 测试报告
- 缺陷列表

**质量门禁**：
- [ ] 测试覆盖率达标
- [ ] 无阻塞性缺陷
- [ ] 测试报告完成

### 阶段六：验收(Acceptance)

**目的**：确认满足验收标准

**输入**：
- 测试报告
- 验收标准

**处理**：
1. 核对验收标准
2. 评估遗留问题
3. 签署验收报告

**输出**：
- 验收报告（ACC-NNN）
- 遗留问题清单

**质量门禁**：
- [ ] 所有验收标准满足或有条件通过
- [ ] 遗留问题有解决计划
- [ ] 签署完成

### 阶段七：部署(Deploy)

**目的**：将功能部署到生产环境

**输入**：
- 验收通过的功能
- 部署配置

**处理**：
1. 准备部署清单
2. 执行部署
3. 验证部署结果

**输出**：
- 部署记录
- 部署验证结果

**质量门禁**：
- [ ] 部署成功
- [ ] 冒烟测试通过
- [ ] 监控正常

### 阶段八：观测(Observability)

**目的**：监控运行状态，收集反馈

**输入**：
- 观测指标定义
- 监控配置

**处理**：
1. 收集指标数据
2. 分析趋势
3. 收集用户反馈
4. 识别改进机会

**输出**：
- 监控数据
- 用户反馈
- 改进建议

**质量门禁**：
- [ ] 监控配置正确
- [ ] 告警规则生效
- [ ] 反馈渠道畅通

### 阶段九：迭代(Iteration)

**目的**：基于观测结果持续改进

**输入**：
- 监控数据
- 用户反馈
- 改进建议

**处理**：
1. 分析问题根因
2. 评估改进优先级
3. 创建新的场景/需求

**输出**：
- 新场景文档
- 新需求文档

**触发条件**：
- 用户满意度下降
- 性能指标不达标
- 新的业务需求

## 阶段转换规则

### 正向转换

| 当前阶段 | 下一阶段 | 触发条件 |
|:---------|:---------|:---------|
| 场景 | 用例 | 场景审批通过 |
| 用例 | 需求 | 用例审批通过 |
| 需求 | 代码 | 需求审批通过 |
| 代码 | 测试 | 代码审查通过 |
| 测试 | 验收 | 测试通过率达标 |
| 验收 | 部署 | 验收通过 |
| 部署 | 观测 | 部署成功 |

### 回退规则

| 当前阶段 | 回退阶段 | 触发条件 |
|:---------|:---------|:---------|
| 测试 | 代码 | 发现阻塞性缺陷 |
| 验收 | 测试 | 验收标准不满足 |
| 部署 | 验收 | 部署失败 |
| 观测 | 需求 | 严重生产问题 |

## AI Agent 执行指导

### 自校验能力

```
代码实现 ──→ 扫描需求 ID
              │
              ↓
需求文档 ──→ 获取需求清单
              │
              ↓
          对比覆盖情况
              │
              ↓
          输出未覆盖需求
```

### 自测试能力

```
验收标准 ──→ 解析 Given-When-Then
              │
              ↓
          生成测试用例
              │
              ↓
          执行测试
              │
              ↓
          输出测试报告
```

### 自验收能力

```
验收标准 ──→ 解析验收条件
              │
              ↓
测试报告 ──→ 匹配测试结果
              │
              ↓
          评估验收状态
              │
              ↓
          输出验收结论
```

### 自分析能力

```
测试失败 ──→ 收集错误信息
              │
              ↓
          分析失败原因
              │
              ↓
          定位问题根源
              │
              ↓
          生成修复建议
```

### 自重构能力

```
代码问题 ──→ 分析代码结构
              │
              ↓
          识别重构点
              │
              ↓
          生成重构方案
              │
              ↓
          执行重构
              │
              ↓
          验证重构结果
```
