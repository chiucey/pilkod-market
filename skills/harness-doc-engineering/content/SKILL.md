# Harness 工程文档引擎

## 核心理念

**文档即规范，规范可执行**

工程文档不是孤立的存在，而是一个完整的生命周期闭环：

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   场景(Scenario) ──→ 用例(Use Case) ──→ 需求(Requirement)  │
│        ↑                                          │         │
│        │                                          ↓         │
│   观测(Observability) ←── 验收(Acceptance) ←── 测试(Test)   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**AI Agent 自驱动能力**：
- 自校验：检查代码是否覆盖所有需求点
- 自分析：分析测试失败的根本原因
- 自重构：基于测试反馈优化代码
- 自测试：生成并执行测试用例
- 自验收：检查是否满足验收标准

## 文档生命周期

### 阶段一：场景(Scenario)

**目的**：描述业务场景和用户上下文

**核心问题**：
- 用户是谁？在什么环境下？
- 用户想要达成什么目标？
- 当前有什么痛点？

**产出**：场景文档，包含角色、环境、目标、痛点

### 阶段二：用例(Use Case)

**目的**：从场景中提炼具体使用场景

**核心问题**：
- 用户执行什么操作？
- 系统如何响应？
- 有哪些异常分支？

**产出**：用例文档，包含主流程、异常流程、前置条件、后置条件

### 阶段三：需求(Requirement)

**目的**：从用例中抽取功能/非功能需求

**核心问题**：
- 系统必须实现什么功能？
- 有哪些非功能性约束？
- 验收标准是什么？

**产出**：需求文档，包含功能需求、非功能需求、验收标准

### 阶段四：测试(Test)

**目的**：验证需求是否正确实现

**核心问题**：
- 如何验证功能正确性？
- 边界条件是什么？
- 如何自动化测试？

**产出**：测试文档，包含测试用例、测试数据、自动化脚本

### 阶段五：验收(Acceptance)

**目的**：确认满足验收标准

**核心问题**：
- 是否满足所有验收标准？
- 是否有遗留问题？
- 是否可以交付？

**产出**：验收文档，包含验收清单、验收结果、遗留问题

### 阶段六：观测(Observability)

**目的**：上线后的监控和反馈

**核心问题**：
- 如何监控业务指标？
- 如何发现问题？
- 如何收集用户反馈？

**产出**：观测文档，包含监控指标、告警规则、反馈渠道

## 文档追溯体系

### ID 命名规范

| 文档类型 | ID 格式 | 示例 |
|:---------|:--------|:-----|
| 场景 | SC-NNN | SC-001 |
| 用例 | UC-NNN | UC-001 |
| 需求 | REQ-NNN | REQ-001 |
| 测试用例 | TC-NNN | TC-001 |
| 验收标准 | AC-NNN | AC-001 |
| 观测指标 | OBS-NNN | OBS-001 |

### 追溯关系

```
SC-001 (场景)
  └── UC-001 (用例)
        ├── REQ-001 (需求)
        │     ├── TC-001 (测试)
        │     ├── TC-002 (测试)
        │     └── AC-001 (验收)
        └── REQ-002 (需求)
              ├── TC-003 (测试)
              └── AC-002 (验收)
```

### 追溯性校验

校验脚本检查：
- 每个用例是否追溯到场景
- 每个需求是否追溯到用例
- 每个测试用例是否追溯到需求
- 每个验收标准是否追溯到需求
- 每个观测指标是否追溯到场景

## 操作步骤

### 场景一：创建新项目的文档体系

1. **创建场景文档**
   ```bash
   # 使用模板创建
   # 参考 references/templates/scenario-template.md
   ```

2. **从场景提炼用例**
   - 分析场景中的用户操作
   - 识别主流程和异常流程
   - 为每个用例分配 ID

3. **从用例抽取需求**
   - 识别功能需求
   - 识别非功能需求
   - 定义验收标准

4. **生成测试用例**
   - 为每个需求创建测试用例
   - 包含正向、逆向、边界测试

5. **定义验收标准**
   - 明确可量化的验收条件
   - 定义验收流程

6. **配置观测指标**
   - 定义业务指标
   - 配置告警规则

### 场景二：校验文档追溯性

```bash
# 校验所有文档的追溯关系
npx ts-node scripts/validate-traceability.ts ./docs

# 输出追溯矩阵
npx ts-node scripts/generate-trace-matrix.ts ./docs
```

### 场景三：AI Agent 自校验

1. **需求覆盖校验**
   - 检查代码是否实现所有需求
   - 输出未覆盖的需求列表

2. **测试覆盖校验**
   - 检查测试是否覆盖所有需求
   - 输出测试覆盖率报告

3. **验收标准校验**
   - 检查是否满足所有验收标准
   - 输出验收检查清单

## AI Agent 自驱动能力

### 自校验流程

```
需求文档 ──→ 解析需求ID列表
              │
              ↓
代码文件 ──→ 扫描代码注释中的需求ID
              │
              ↓
          生成覆盖报告 ──→ 未覆盖需求清单
```

### 自测试流程

```
需求文档 ──→ 解析验收标准
              │
              ↓
测试模板 ──→ 生成测试用例
              │
              ↓
          执行测试 ──→ 测试报告
```

### 自验收流程

```
验收标准 ──→ 解析验收条件
              │
              ↓
测试报告 ──→ 匹配测试结果
              │
              ↓
          生成验收报告 ──→ 遗留问题清单
```

## 注意事项

### 文档一致性

- 所有文档使用统一的 ID 格式
- 保持追溯关系的完整性
- 定期校验文档一致性

### AI Agent 职责

- 智能体负责文档内容的编写
- 智能体基于文档执行开发任务
- 智能体根据校验结果修复问题

### 脚本职责

- 验证文档格式正确性
- 校验追溯关系完整性
- 生成追溯矩阵和覆盖率报告
