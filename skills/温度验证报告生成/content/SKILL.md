# 温度验证报告生成技能

## 触发词

`温度验证报告` `温度验证` `SiNSE报告` `复刻温度报告` `温度探头分析` `灭菌验证报告`

---

## 你的角色

你是报告生成执行者。用户每次给出基础数据后，你按本 skill 的固定规则生成 1:1 复刻版温度验证报告，并让用户选择输出 PDF 或 HTML。

---

## 硬性需求规则（最高优先级，违反即错）

1. **完全复刻原版式**：除具体数据变化外，版式其余一致（页眉页脚、表格排版、字体、配色、模块顺序）。
2. **只保留原件模块，禁止新增**：原件没有的模块一律不加（如规则说明表、判定算法解释、额外图例等）。
3. **必须包含趋势图**：温度(压力)趋势分析图表要保留。
4. **5 类排序必须进表格**：第 4 页「温度阶段统计」下方的 5 类排序，必须放在同一表格内，采用「灰底标签行 + 白底表达式行」交替、整行合并、带表格框。不允许排在表格外。
5. **字体固定微软雅黑**；灰底统一 `#E7E6E6`。
6. **判定逻辑**：所有探头的整体温度范围在 `[T_LOW, T_HIGH]` 内，且工艺时长 `≥ HOLD_MIN_MIN` 分钟 → 结论「符合要求」，否则「不符合要求」。

## 输入要求

### CSV 数据格式

- **首列：时间**，支持两种写法：
  - 完整日期时间：`2026-08-20 10:00` 或 `2026-08-20 10:00:00`
  - 仅时分：`10时00分`
- **探头温度列：列名以 `T` 开头**，如 `T1,T2,T3...`（任意数量，**完全动态**）
- 自动忽略列名不含 `T` 的汇总列（如 `最高`、`最低`）。

### 动态性保证（必须始终满足）

报告结构**完全由 CSV 数据驱动**，不写死任何数量：

| 维度 | 处理方式 |
|------|----------|
| 探头数量 | 由 `T*` 列数量决定（1 个到几十个均可） |
| 记录条数 | 由 CSV 行数决定（明细表自动展开，跨页自动重复表头） |
| 列顺序 | 按表头里 `T*` 列的**真实位置**读取，即使 `最高/最低` 等汇总列穿插在探头之间也**不会错位** |
| 时间列 | 默认首列；若首列本身是探头名，则自动取第一个非 `T` 列 |
| 通道名 | 按 `简称_01, 简称_02 ...` 顺序自动生成 |
| 布点图 | 探头点按数量自动均布在腔体内 |
| 探测结果字段 | 探头数量、日期、时长要求均自动反写回 INFO |

> 单探头（N=1）、多探头（如 16 个）、少记录、多记录均已验证可用。

### 工艺标准参数（默认 121/120/122/15）

| 参数 | 含义 | 默认值 |
|------|------|--------|
| `--target` | 目标温度（℃） | 121.0 |
| `--low` | 温度下限（℃） | 120.0 |
| `--high` | 温度上限（℃） | 122.0 |
| `--holdmin` | 保持时长要求（分钟） | 15.0 |

### 验证信息 INFO

默认使用乌苏里江药业信息。可通过两种方式覆盖：

1. **JSON 文件**：`--info myinfo.json`，内容见 `assets/info_template.json`。
2. **命令行快捷参数**：`--company`、`--object`、`--loadtype`、`--reportid`、`--date`、`--instrument` 等，见脚本 `--help`。

系统自动计算派生字段：探头数量、日期、时长要求。

## 处理流程（严格按步骤执行）

### Step 0：确认用户输入（必须询问，不得默认 both）

用户给出 CSV 后，**必须先向用户确认输出格式**，不能默认同时生成 PDF 和 HTML。

用 `AskUserQuestion` 或直接在对话里提问，至少确认：

1. **输出格式（必问）**：`PDF` / `HTML` / `两者都要` 三个选项，让用户选。
   - ⚠️ 用户没明确说"两个都要"时，**不要**默认 both，必须问清楚。
2. 工艺标准：目标/下限/上限/保持时长（不确认则使用默认值 121/120/122/15）。
3. 验证信息：公司名、验证对象、编号、仪器等是否需要修改（不确认则使用模板默认值）。

确认后再进入 Step 1 运行脚本，并通过 `--format` 传入用户选择的格式。

### Step 1：运行生成脚本

脚本路径：

```bash
C:/Users/乌苏里江/.workbuddy/binaries/python/envs/default/Scripts/python.exe \
  C:/Users/乌苏里江/.workbuddy/skills/temperature-validation-report/scripts/generate.py \
  --csv <CSV路径> \
  --format <pdf|html|both> \
  --target <目标温度> --low <下限> --high <上限> --holdmin <保持分钟> \
  [--info <JSON路径>]
```

常用示例：

```bash
# 默认参数，同时生成 PDF + HTML
python generate.py --csv code_20260820.csv --format both

# 只生成 PDF，改工艺标准为 115/115~117/30
python generate.py --csv code.csv --format pdf --target 115 --low 115 --high 117 --holdmin 30

# 使用自定义 INFO 生成 HTML
python generate.py --csv code.csv --format html --info info.json
```

### Step 2：核对版式

脚本运行后，用 `pymupdf` 渲染第 4 页，确认 5 类排序在表格内，且版式与 SiNSE 原件一致。

### Step 3：交付文件

交付生成的 PDF/HTML，文件命名规则：`温度验证报告_{日期}.pdf` / `温度验证报告_{日期}.html`，输出目录默认在 CSV 同目录下（可用 `--outdir` 指定）。

## 报告模块顺序（不可变更）

| 页 | 模块 | 说明 |
|----|------|------|
| P1 | 验证报告首页 | 标题条、8 列信息表、注释条、结论一、底部签字行 |
| P2 | 探头定义 | 通道与标签对应表 |
| P3 | 布点图 | 灭菌柜腔体布点示意图 |
| P4 | 温度阶段统计 | 含最小值/最大值/大减小/平均值/平减标 + 5 类排序（同表） |
| P5 | 同一时刻的温度均匀性 | Max(最大-最小)/(最大-平均)/(平均-最小)、全均等 |
| P6 | 温度数据 | 全部原始明细表 |
| P7 | 签字页 | 验证人/签字日期/审核人/签字日期 |

> 数据量变化时页数可能增减（如明细数据跨多页），但模块顺序不变。

## 核心指标算法

| 指标 | 算法 |
|------|------|
| 大减小 | max - min |
| 平减标 | avg - target |
| 波动度 | (max - min) / 2 |
| 同一时刻 Max(最大-最小) | 每个时间点所有探头最大值 - 最小值，取最大 |
| 整体温度均匀度 | 所有读数的标准差 |
| 工艺时长 | 末条时间 - 首条时间（分钟） |

## 边界与兜底

- CSV 时间列若带日期则优先使用 CSV 日期；若只给时分则使用 INFO["日期"] 或 `--date`。
- 探头数量 N=1 时仍可生成（排序表达式只有一个探头）。
- 字体文件缺失时会报错； Windows 环境自带微软雅黑，通常无需处理。
