# 模块 1: 文本核心内容可视化 (Text-to-SVG Visualizer)

**子技能元数据**：

- version: 2.7.0 | author: sisyphus | persona: Senior Frontend Engineer & Information Architect
- 文本结构化与SVG可视化专家，工作流类型: sequential（3步）
- 允许工具: [write, edit, read, glob, grep, bash]

## 概述

接收用户输入的任意文本（段落 / 文章 / 报告），智能提取核心内容与逻辑关系，生成**清晰美观的 SVG 图表**，嵌入**完全独立、无需任何外部依赖、双击即可运行的 HTML 文件**。

**触发关键词**：可视化 / 图表 / SVG / 思维导图 / 流程图 / 转图表 / 整理成图 / 结构图 / 关系图 / 对比 / 时间线

---

## 1. 严格工作流程（按顺序执行，不可跳过）

### Step 1: 文本解析与核心提取（≤3 秒）

1. **快速识别**文本的中心主题、主要论点、关键数据和逻辑层次
2. **自动过滤**冗余信息、修饰性语句和无关细节
3. **结构化组织**：
   - 一级节点 ≤ **7 个**
   - 每个一级节点下二级节点 **1-5 项**（按文本内容自由决定）
   - 节点文字精炼到 ≤ **12 字**（必要时缩写）
4. **按优先级自动判断最适合的图表类型**（从上到下依次匹配，匹配即止）：

| 优先级 | 图表类型      | 适用场景                 | 布局特点            |
| --- | --------- | -------------------- | --------------- |
| 1   | **流程图**   | 步骤顺序 / 因果关系 / 流程     | 自上而下箭头连接，菱形判断   |
| 2   | **层次结构图** | 分类 / 组织架构 / 包含关系     | 树形自上而下分层，直角连接线  |
| 3   | **对比矩阵**  | 多对象多维度对比             | 表格布局，行列交叉       |
| 4   | **时间线**   | 发展历程 / 阶段演进          | 水平时间轴，节点沿轴分布    |
| 5   | **关系图**   | 概念关联 / 对比 / 网络       | 节点 + 连线，网状或圆周排列 |
| 6   | **思维导图**  | ⚠️ 仅当前 5 种均不适用时的兜底选项 | 中心向四周辐射，弧线连接    |

> **⚠️ 图表类型选择优先级规则**：严格按上表优先级从上到下匹配。只有当文本特征与流程图、层次结构图、对比矩阵、时间线、关系图均不匹配时，才使用思维导图作为兜底方案。**思维导图是最后选项，不是默认选项。**

### Step 2: SVG 图表生成（≤5 秒）

#### 2.1 基础规格

- `viewBox="0 0 800 600"`，固定尺寸 `width="800" height="600"`
- `<rect width="800" height="600" fill="#ffffff"/>` 作为基底
- 使用 `<path>`、`<rect>`、`<circle>`、`<ellipse>`、`<line>`、`<polygon>`、`<text>` 绘制
- **禁止** `<image>`、`<foreignObject>`、`<use>`、`<iframe>`（确保自包含）
- 所有文字使用 `font-family: Arial, 'PingFang SC', 'Microsoft YaHei', 'SimHei', sans-serif`（优先中文字体）
- 字号 **≥ 12px**，标题 **18-22px**，节点标签 **14-15px**，子标签 **13px**
- SVG 代码 ≤ **500 行**

**模板使用原则：**

- 模板是**参考示例**而非严格规范 — 可**自行删减、调整、组合**，不必拘泥于模板结构

- 若模板类型与需求不匹配，完全可以创造新的布局方式
- **只需确保不产生重叠和溢出**（用本文件 §2.4-2.5 中的公式验证），其余自由发挥

#### 2.4 节点尺寸与文字容量计算

**节点尺寸必须根据文字长度确定，确保文字不溢出：**

| 节点层级 | 字号   | 每字约宽 | 推荐最小盒宽         | 推荐最小盒高   |
| ---- | ---- | ---- | -------------- | -------- |
| 中心   | 18px | 18px | 直径 88px (r=44) | —        |
| 一级   | 16px | 16px | 文字数×16 + 32px  | **48px** |
| 二级   | 14px | 14px | 文字数×14 + 28px  | **40px** |

**计算规则：**

- 一级节点盒宽 = `字数 × 16 + 32`（两边各 16px 内边距），最小 **160px**
- 二级节点盒宽 = `字数 × 14 + 28`（两边各 14px 内边距），最小 **140px**
- 对于 7-8 字的二级节点（如"现代教育技术应用"），盒宽必须 ≥ 140px

**⚠️ 文字溢出防护（通用规则——所有布局、所有文字方向、所有图表类型均适用）：**

**绝对禁止任何文字超出任何盒子/卡片/节点的边界**，无论文字是居中（`text-anchor="middle"`）还是左对齐（`text-anchor="start"`）。这条规则适用于流程图、思维导图、层次结构图、对比矩阵、时间线、关系图等全部图表类型中的所有文字。

**必须使用以下符号宽度表逐字符计算文字总宽，禁止用"字数×字号"估算（会漏算符号和空格）。**

符号宽度参考表（字号 12px 时，字号缩放时按比例折算）：
| 符号 | 说明 | 约宽 |
|------|------|------|
| 中文字 | — | 13px（安全上界） |
| 英文/数字 | a/A/0 | 7px |
| · | 中点（间断号） | 7px |
| — | 破折号/长横 | 13px |
| → | 箭头 | 14px |
| + | 加号 | 7px |
| / | 斜杠 | 7px |
| - | 连字符/减号 | 5px |
| : | 冒号 | 5px |
| ( ) | 括号 | 5px/个 |
| % | 百分号 | 7px |
| ， 、 | 中文标点 | 7px/个 |
| 空格 | 字词间空格 | 4px |

**计算步骤：**

1. 中文字数 × 13 = 中文总宽
2. 英文/数字字符数 × 7 = 英文总宽
3. 逐一查表累加所有符号宽度 = 符号总宽
4. **文字总宽 = 中文总宽 + 英文总宽 + 符号总宽**

---

**居中文字（text-anchor="middle"）：**

```
验证：文字总宽 + 2×内边距 ≤ 盒宽

示例：盒宽160px，文字14个字
  文字总宽=14×13=182px，内边距14px
  182 + 2×14 = 210 > 160 ❌ 前面公式 "字数×16+32" 仅对纯中文有效，
  包含符号和英文时必须用本表逐项计算
```

**左对齐文字（text-anchor="start"，常见于流程图序号圆圈组合布局）：**

```
验证：text_x + 文字总宽 ≤ box_x + box_width - 5px
  即：文字右缘 ≤ 盒右缘 - 5px（留 5px 安全余量）

优先修正顺序：
   1. 加宽盒子，同时验证不对其他布局产生挤压
   2. 左移 text_x，注意与序号圆圈右缘间距 ≥ 6px
   3. 精炼文字，在不丢失核心信息的前提下缩减字数
```

常见失败场景（来自实际案例——木桌制作流程）：

```
box=215×360, text_x=300, 文字="数控雕刻造型 · 开榫打孔 · 榫卯结构替代单纯螺丝固定"
字号=12px
  中文21字          × 13 = 273px
  中点· ×2         ×  7 =  14px
  空格 ×4           ×  4 =  16px
  文字总宽                = 303px
  文字右缘 = 300 + 303 = 603
  盒右缘   = 215 + 360 = 575
  603 > 575 ← 溢出 28px ❌

修正：text_x 左移至 288 + 精炼文字至 17 字
  中文17字          × 13 = 221px
  中点· ×2         ×  7 =  14px
  空格 ×4           ×  4 =  16px
  文字总宽                = 251px
  文字右缘 = 288 + 251 = 539
  盒右缘   = 215 + 360 = 575
  539 ≤ 575 - 5 = 570 ← 安全 ✓（余量 31px）
```

另一真实失败场景（芯片制作全流程——右侧提示卡片）：

```
卡片 x=602 w=168, 文字 x=628, 文字="沉积→光刻→蚀刻 循环数十次"
字号=12px（text-anchor="start"）
  中文11字          × 13 = 143px
  箭头→ ×2         × 14 =  28px
  空格 ×1           ×  4 =   4px
  文字总宽                = 175px
  文字右缘 = 628 + 175 = 803
  卡片右缘 = 602 + 168 = 770
  803 > 800(viewBox) ← 不仅超出卡片，连画布都超出了 ❌

修正：改用 text-anchor="middle"（或加宽卡片并缩短文字）
  卡片 x=585 w=195, 文字居中 x=682, text-anchor="middle"
  文字总宽=175  → 范围 [594, 770] ⊂ [585, 780] ✓
```

**⚠️ 画布边界约束（关键——常被忽略）：**

思维导图水平分支的总宽度必须 ≤ 800px 画布。中心点位于 (400,300)，因此单侧可用宽度为 **380px**（400-20 右边距）。

```
右分支总宽度验证公式：
  L1_cx - 400（L1 距中心距离）+ L1_half_w + gap + L2_half_w + 右边距 ≥ 20px ≤ 380px
  即：L1_cx + L1_half_w + gap + L2_half_w ≤ 780

示例（上一版失败原因）：
  L1=160×48, L2=150×40, gap=10
  右分支：L1_cx=585, L1_hw=80, L2_hw=75 → 585+80+10+75=750 ≤ 780 ✓
  但 L2 左缘=585+80+10=675, 但实际 L2 center=695 时左缘=695-75=620, 与 L1 右缘 585+80=665 有 45px 重叠 ✗
  → 问题：gap 值 L2 左缘 - L1 右缘 = (695-75) - (585+80) = 620-665 = -45，实际为负数重叠

修正后：
  L1=150×44, L2=132×38, gap=14
  右分支：L1_cx=555, L1_hw=75, L2_hw=66 → 555+75+14+66=710 ≤ 780 ✓
  L1右缘=630, L2左缘=644, gap=14 ✓
  L2右缘=776, 右边距=24 ≥ 20 ✓
```

**关键原则：盒宽越大，布局余量越小。优先缩小盒宽而非移动中心节点。**

#### 2.5 间距与布局系统

**通用间距规范——防止重叠的核心规则：**

- 画布边距：上下左右各 **≥ 20px**
- 同层节点水平间距：**≥ 20px**（盒边缘到盒边缘）
- **同支二级节点垂直间距：中心距 ≥ 盒高 + 12px**（例如 40px 高的盒，中心距 ≥ 52px）
- **一级与二级节点水平间距（同支）：≥ 14px**（L1 盒右缘到 L2 盒左缘，右分支为例）
- **表头/标题与首个内容元素的垂直间距：表头底部 ≥ 12px**（避免渲染顺序靠后的内容框遮盖表头）
- 异层节点垂直间距（层间）：**≥ 80px**
- 节点内边距（文字到边框）：水平 **12-16px**，垂直 **10-12px**
- 连接线距节点边缘安全距离：**≥ 25px**

**重叠预防公式：**

**公式 A——二级节点垂直间距：**

```
中心距 = 盒高 + 12px（最小空隙）
例如：38px 高的盒子 → 中心距 = 38 + 12 = 50px
若第一个中心 y=282，第二个中心 y=282+50=332
盒边界：[282-19, 282+19] = [263, 301] 和 [332-19, 332+19] = [313, 351]
空隙 = 313 - 301 = 12px ✓
```

**公式 B——一级与二级水平间距（右分支示例）：**

```
空隙 = L2_盒左缘 - L1_盒右缘 ≥ 14px

全流程验证（思维导图右分支）：
1. 确定 L1 中心 x 坐标 = 400 + D1（D1 为距中心偏移）
2. 计算 L1 右缘 = L1_cx + L1_half_w
3. 计算 L2 左缘 = L1_右缘 + gap（gap ≥ 14px）
4. 计算 L2 中心 x = L2_左缘 + L2_half_w
5. 验证 L2 右缘 = L2_cx + L2_half_w ≤ 780（右边缘 ≤ 800 且留 ≥ 20px）

完整布局检查表：
┌─────────────────────────────────────────────────────┐
│ 右分支示例（L1=150×44, L2=132×38, gap=14）：          │
│ L1_cx=555, L1右缘=630                                │
│ L2左缘=644, L2_cx=710, L2右缘=776                    │
│ L2左缘 - L1右缘 = 644-630 = 14px ≥ 14 ✓              │
│ L2右缘 776 ≤ 780 ✓  (右边距=24px ≥ 20)               │
│ 连接线可见段 = 644-630 = 14px（虽短但可见）              │
│ 若需更长的可见连接线 → 缩小盒宽或增加 D1                 │
└─────────────────────────────────────────────────────┘
```

**公式 C——连接线可见段长度：**

```
连接线从 L1 盒边缘延伸到 L2 盒边缘。
可见段长度 ≈ gap（即 L2_左缘 - L1_右缘）。
若 gap=14px，则可见段约 14px，虽然短但仍清晰。
推荐最小可见段：≥ 10px（gap 过小会导致视觉上无连接感）。
若画布空间充裕（如左侧分支右侧无约束），gap 可设为 20-30px 以获得更长的连接线。
```

**⚠️ SVG 渲染顺序导致表头被内容覆盖（常见——生成对页图时尤其容易犯）：**

在 SVG 中，**渲染顺序 = 文档顺序**（后绘制的元素覆盖在先绘制的之上）。当画布顶部有表头/标题区域，紧随其后的内容框（如分层对比图中的第一层）如果没有留足垂直间距，就会覆盖表头底部。

```
失败案例（网络模型对比图）：
  表头 rect:   y=64, h=24  → 底部 y=88
  首层内容框：   y=76         → 顶部 y=76（比表头底部高 12px）
  渲染顺序：表头先画 → 内容框后画 → 内容框覆盖表头底部 12px ❌

修正：
  在表头和内容之间增加 gap ≥ 12px
  方案 A（推荐）：内容整体下移，<g transform="translate(0, 24)"> 包装内容区域
  方案 B：调大首层内容的 y 值
  验证：表头底部 y1 + gap ≤ 首层内容顶部 y2，且 gap ≥ 12px
```

#### 2.6 各图表类型生成规范

**思维导图（中心辐射式）：**

- 中心节点：圆角矩形或圆形，位于 `(400, 300)`。推荐矩形 `130×52px, rx=10`（模板默认），也可用 `r=40` 圆形
- **一级分支数 N=3 时，推荐左/右/下三路布局**（避免上下分支导致垂直溢出）
- **左右水平分支的关键约束（常见失败点）：**
  - 一级节点中心距中心偏移量 D1：**推荐 140-160px**（过大则 L2 会超出画布）
  - 二级节点中心距中心总偏移量：**推荐 290-320px**
  - L1→L2 水平间隙：**≥ 14px**（确保无盒重叠且有可见连接线）
  - 完整右分支宽度验证：`L1_cx + L1_half_w + gap + L2_half_w ≤ 780`
- 节点样式：
  - 中心：渐变填充圆角矩形 + 白色文字，**18px** 加粗 + **14px** 加粗（两行）
  - 一级：主色渐变填充圆角矩形 `宽×44px`，`rx="10"`，**15px** 白色加粗文字，深阴影
  - 二级：浅色填充圆角矩形 `宽×132px`，高 **38px**，`rx="8"`，辅色描边 `1px`，**13px** 深色加粗文字，浅阴影
  - **盒宽调整原则**：8 字二级节点用 132px（13px 字，8×13=104 ≤ 132-24=108 ✓）；7 字及以下可用 130px
- 连接线：全部使用**直线**（`<line>`），按 z-index 先画线后画节点
  - 中心→一级：从中心盒边缘到一级盒边缘，`stroke-width="3"`，主色
  - 一级→二级：从一级盒子中心到二级盒子中心，`stroke-width="1.5"`，辅色
  - 中心为矩形时连接点位于盒边缘中点；中心为圆形时连接点位于圆周
- 背景装饰（可选）：极浅色分组区域、同心圆等，非必需

**流程图（自上而下）：**

- 起始节点：椭圆形 `rx="28" ry="22"`，顶部居中，位于 `(400, 65)`
- 过程节点：圆角矩形 `180×50px`，`rx="8"`，水平居中排列
- 判断节点：菱形（`<polygon points="x,y-26 x+52,y x,y+26 x-52,y">`），宽度 104px
- 结束节点：椭圆形 `rx="28" ry="22"`，底部居中
- 节点垂直间距：**85px**，水平偏移：判断节点分叉路径间距 **60px**
- 箭头：带 `marker-end` 的 `<line>`，`stroke-width="2.5"`，主色
- 分支标注：判断节点右侧"是"/左侧"否"，13px 灰色文字
- 路径：从判断节点底部向下 45px 后分左右两条路径

**层次结构图（树形）：**

- 根节点：位于 `(400, 60)`，圆角矩形 `宽×48px`（宽按 2.3 节计算），`rx="10"`
- 多层结构时，每层垂直间距 **110px**
- 同一层节点水平均匀分布，间距 **≥ 100px**（自动计算）
- 子节点相对于父节点居中对齐
- 节点盒高统一：根/父 **48px**，子节点 **40px**
- 连接线：直角折线（父节点底部→垂直向下→水平居中→垂直向下→子节点顶部）
  - `M parent_cx,parent_bottom L parent_cx,mid_y L child_cx,mid_y L child_cx,child_top`
- 线宽 **2px**，辅色，末端无箭头

**关系图（网状）：**

- 节点按内容分组，每组用一个半透明背景 `rect` 容器包裹
- 容器圆角 `rx="10"`，描边虚线 `stroke-dasharray="5,5"`
- 容器标签位于左上角 `(x+10, y+20)`，**13px** 辅色文字
- 节点在容器内均匀分布，间距 **≥ 50px**
- 关联节点间用直线连接，**1.5px**，辅色
- 强关系用实线 + 粗线宽 `2px`，弱关系用虚线 `stroke-dasharray="4,4"` + 细线宽 `1px`
- 节点尺寸：`110×36px`，`rx="6"`

**对比矩阵（新增）：**

- 行首列：对比维度名称，宽 **120px**，深色背景 + 白色文字 **13px** 加粗
- 表头行：对比对象名称，高 **40px**，主色背景 + 白色文字 **13px** 加粗
- 数据单元格：`60×34px`，白色填充，辅色文字 **12px**
- 行交替背景：偶数行使用背景色 `#f5f5f5`
- 单元格内标记：支持 `✓` / `✗` 或自定义文字
- 左上角首格留空或标"对比维度"

**时间线（新增）：**

- 时间轴：水平直线 `y="300"`，从 `x=80` 到 `x=720`，**3px** 主色线
- 起点和终点：圆形标记 `r="5"`，主色填充
- 时间节点：沿轴均匀分布，间距 **≥ 80px**
- 节点样式：轴线上的圆形标记 `r="7"`，白边 + 主色填充
- 节点上方（或交替上下）排列事件卡片：
  - 圆角矩形 `120×50px`，`rx="6"`，白色填充，主色描边
  - 卡片与轴线间距 **20px**
  - 卡片内文字：标题 **13px** 加粗 + 描述 **11px**（换行 `<tspan>`）
- 连接线：从轴线标记到卡片的竖直线，**1.5px**，辅色虚线

#### 2.7 连接线规范

- **端点连接规则**：连接线须连接到节点边缘的**中点**（上/下/左/右），禁止连接至角落
- **平行线错开**：同一源节点的多条连线，终点 y 坐标错开 **≥ 20px**，避免线重叠
- **标签背景**：如需在连接线上加文字标签，标签下方须有 `rect` 背景（白色，`opacity="0.9"`，四周内边距 4px）
- **思维导图推荐曲线**：中心到一级节点使用二次贝塞尔曲线 `Q cx,cy ex,ey`，控制点偏离中点约 15-20px 产生自然弧度
- **直线适用场景**：流程图、层次结构图、二级节点间连接使用直线

**贝塞尔曲线弧度参考：**

```
水平分支（向左/右）：Q 中点坐标,中点坐标±15 终点坐标   → 轻微弧形
垂直分支（向上/下）：Q 中点坐标±15,中点坐标 终点坐标   → 轻微弧形
```

#### 2.8 文字与标注规范

- 所有文字使用 `<text text-anchor="middle" dominant-baseline="central">`
- 中文字体优先：`Arial, 'PingFang SC', 'Microsoft YaHei', 'SimHei', sans-serif`
- 节点内文字超长处理：
  - 1 级节点 ≤ **8 字**（超长则缩写或用 `…`）
  - 2 级节点 ≤ **12 字**（超长则用 `<tspan x="cx" dy="16">` 换行）
- 关键数据或数字使用 **加粗**
- 标题居中于画布顶部 `y="40"`，字号 **20px** 加粗，深色

#### 2.9 装饰与细节

- 节点阴影：使用 `<filter>` 实现 `feDropShadow`（偏移 2px，模糊 3px，透明度 0.15）
- 布局背景：可添加极浅的辅助网格或同心圆（透明度 ≤ 0.15），不可影响文字可读性
- 连接线圆角：`stroke-linejoin="round" stroke-linecap="round"`
- 虚线用法：`stroke-dasharray="5,5"` 表示弱关系/可选路径/历史路径

#### 2.10 SVG 元素渲染顺序（z-index）

```
1. 背景 rect
2. 布局辅助图形（网格/同心圆等）
3. 容器 rect（分组虚线框）
4. 连接线（从下到上：远端连线 → 近端连线）
5. 二级节点
6. 一级节点
7. 中心节点
8. 所有文字
```

## 5. SVG 质量标准清单

### 结构检查

- [ ] 图表类型选择是否匹配文本逻辑结构
- [ ] 一级节点 ≤ 7 个，每个下二级节点 1-5 项（按文本内容自由决定）
- [ ] 核心信息未丢失，关键数据已保留
- [ ] SVG viewBox 尺寸正确（800×600）
- [ ] 渲染顺序正确（z-index 分层）

### 视觉检查

- [ ] 所有文字可读（字号 ≥ 12px，对比度 ≥ 4.5:1）
- [ ] **无元素重叠**——用公式验证：同支二级节点纵向间距 ≥ 盒高 + 12px
- [ ] 配色协调，不超过 5 种颜色，语义一致
- [ ] 中文字体渲染正确（font-family 包含中文字体）
- [ ] 节点阴影柔和，不压盖文字
- [ ] **所有文字不超出任何盒子/卡片/节点的边界**——按 §2.4 符号表逐字符计算文字总宽后验证
- [ ] 居中文字：`文字总宽 + 2×内边距 ≤ 盒宽`
- [ ] 左对齐文字：`text_x + 文字总宽 ≤ box_x + box_width - 5px`
  
  ```
  ⚠️ 禁止用"字数×字号"估算，必须逐字符查 §2.4 符号表计算含符号和空格的实际像素宽
  ```

### 重叠检查（强制）

- [ ] **同支 L2 节点：逐个计算中心距是否 ≥ 盒高 + 12px**
  
  ```
  L2 中心 y 值差 ≥ L2 盒高 + 12
  例如：38px 高 → y 差 ≥ 50px
  ```
- [ ] **一级与二级 L2 水平不重叠（思维导图水平分支）：**
  
  ```
  L2 盒左缘 - L1 盒右缘 ≥ 14px
  即：(L2_cx - L2_hw) - (L1_cx + L1_hw) ≥ 14
  ```
- [ ] **全分支是否在画布内（思维导图水平分支）：**
  
  ```
  L2 盒右缘 ≤ 780（右分支）
  L2 盒左缘 ≥ 20（左分支）
  ```
- [ ] 最长文字按像素计算是否在盒宽内：字数×字号 + 28px ≤ 实际盒宽
  
  ```
  对 13px/14px 的二级节点特别注意 7-8 字长文本是否溢出
  ```
- [ ] **表头/标题与首个内容元素是否无重叠？** 表头底部 + gap(≥12px) ≤ 首个内容元素顶部
  
  ```
  表头底部 = header_y + header_h
  内容顶部 = first_content_y
  验证：header_y + header_h + 12 ≤ first_content_y
  ```
- [ ] 连接线与节点边界间距 ≥ 25px
- [ ] 分组区域背景不覆盖或干扰文字

### 连接检查

## 场景二：多班级对比分析

> 当用户上传的是**多个班级**（2个及以上）的Excel文件时，按照以下步骤操作。

### 操作步骤

#### Step 1: 确认文件归属

询问用户：

- 共有**几个班级**？
- 哪些文件分别属于哪个班级？（文件名需包含"班级1""班级2""班级3"...等关键字以便脚本自动识别）
- 各班级的考试月份/时间顺序是否一致？

#### Step 2: 生成各单班级分析报告

对每个班级，调用 `exam_analysis.py` 一次，使用 `--filter` 参数按文件名关键字筛选：

```bash
# 班级1
python exam-analysis/scripts/exam_analysis.py --input-dir ./exam_data --filter 班级1 --output 班级1_分析报告.html --exam-order "10月考试,11月考试,12月考试"

# 班级2
python exam-analysis/scripts/exam_analysis.py --input-dir ./exam_data --filter 班级2 --output 班级2_分析报告.html --exam-order "10月考试,11月考试,12月考试"

# 班级3（如有）
python exam-analysis/scripts/exam_analysis.py --input-dir ./exam_data --filter 班级3 --output 班级3_分析报告.html --exam-order "10月考试,11月考试,12月考试"
```

`--filter` 参数仅处理文件名中包含该关键字（如"班级1"）的Excel文件。

#### Step 3: 生成跨班对比分析报告

运行 `compare_classes.py`，**自动扫描所有班级**的Excel并生成对比HTML：

```bash
python exam-analysis/scripts/compare_classes.py --input-dir ./exam_data
```

脚本自动：

- 扫描目录下所有 `*班级N.xlsx` 文件（N ≥ 1）
- 动态识别班级数量（2个、3个、4个...）
- 找出所有班级的**共同月份**
- 生成每个月份的6维度对比分析
- 输出 `考试成绩综合分析平台.html`（仅含对比内容）

### 生成文件的结构

```html

<!-- 班级1内容 -->
<div id="tab-c1">
  <aside class="sub-sidebar">  <!-- 侧边栏：成绩变化趋势 + 考试批次列表 --></aside>

  </main>
</div>

<!-- 班级2内容（结构同上，ID前缀为 c2_） -->
<div id="tab-c2">...</div>

<!-- 班级3+内容（如有，按 c3_ / c4_ ... 依次） -->
<div id="tab-c3">...</div>

<!-- 10月/11月/12月对比（各6维度） -->
<div id="tab-m10">...</div>
<div id="tab-m11">...</div>
<div id="tab-m12">...</div>
```

### ID前缀规则（避免冲突）

- 班级N: 所有canvas/元素ID加前缀 `c{N}_`（如班级3的ID前缀为 `c3_`）
- 10月对比: 所有canvas ID加前缀 `m10_`（如 `m10_overallChart`）
- 11月对比: 前缀 `m11_`，12月对比: 前缀 `m12_`
- JS全局变量和函数也对应加前缀（如 `c1_initExamList`, `c2_chartGroups`, `c3_...`）

### 对比报告6个维度

1. **整体总体对比** — 分组柱状图(平均分/最高分/最低分/中位数)
2. **单科维度对比** — 分组柱状图 + 雷达图(语数英物化均分)
3. **分数段梯队对比** — 频数直方图(高分段/中高分段/中分段/低分段)
4. **学情结构分析** — 双环形图(优生/中等生/后进生占比)
5. **成绩问题溯源** — 两班优势、短板、共性问题文本分析
6. **教学改进建议** — 培优/补差/学科针对性方案

### 6. 添加动画

所有动画通过 `IntersectionObserver` 触发，元素滚入视口播放**进入动画**，滚出视口播放**退出动画**（反向）。

| 动画类                  | 进入效果          | 退出效果                  | 适用场景   |
| -------------------- | ------------- | --------------------- | ------ |
| `.anim-fade-up`      | 从下往上淡入        | 向上淡出                  | 正文主要元素 |
| `.anim-fade-left`    | 从左往右淡入        | 向右淡出                  | 左侧卡片   |
| `.anim-fade-right`   | 从右往左淡入        | 向左淡出                  | 右侧卡片   |
| `.anim-scale-in`     | 缩放淡入          | 缩小淡出                  | 强调元素   |
| `.anim-stagger-list` | 子元素逐个 fade-up | 子元素逐个 fade-down（反向顺序） | 列表、网格  |

**经验法则**：封面用 `stagger-list`，正文用 `fade-up`，每个画面选**一个**强调动画即可。

**JS 实现（必须使用 IntersectionObserver）：**
JS 代码见 `Physical Content Display/common/base.js`，直接复制全部内容到 `<script>` 块即可。包含完整的 `querySelectorAll` 和 `IntersectionObserver` 实现。

**注意：** 不调用 `unobserve()`，保持持续监听以实现进出双向动画。

# 模块 4: 自主进化反馈

**子技能元数据**：

- 触发关键词：反馈, 改进, 调整, 重做, 不好, 修改, 不太对, 改一下, 优化
- 工作机制：反馈归档 → 频率判断 → 规则提炼 → changelog 记录

## 核心原则（必须遵守）

以下两条原则适用于所有模块的输出生成，进化反馈流程应确保其被遵守：

1. **严格按照技能要求执行** — 任何生成输出必须严格按照各模块 SKILL.md 中规定的工作流程、约束条件和质量标准执行，不得自行发挥、省略步骤或改变规范。

2. **先参考模板再创作** — 调用技能生成内容时，必须先阅读对应的模板文件（`text-to-svg/templates/`、`Physical Content Display/common/` 等），在模板基础上进行修改。不限制于模板结构，可自由调整、组合或创新，但必须以模板为起点确保风格一致。

## 触发条件

本模块采用**双重触发机制**：

1. **被动触发** — 用户消息包含以下关键词时路由到此模块：
   反馈 / 改进 / 调整 / 重做 / 不好 / 修改 / 不太对 / 改一下 / 优化

2. **主动触发** — 每次调用其他模块（1/2/3）生成内容后，自动评估输出质量，若存在不符合质量标准的问题，则主动启用进化模块归档并推动改进。

## 工作流程

### Step 1: 确认反馈指向

确认以下信息（如有模糊，追问用户）：

1. **目标模块** — 本次反馈是针对哪个模块的输出？
   - text-to-svg（可视化图表）
   - exam-analysis（考试分析报告）
   - Physical Content Display（物理教学页面）
2. **原始输出描述** — 是什么时候生成的内容？主题/文件名是什么？
3. **反馈原文** — 用户具体说了什么？
4. **改进方向** — 用户期望的改进是什么？

### Step 2: 归档反馈

在 `evolution/feedback/` 目录下创建反馈记录文件 `YYYY-MM-DD_NNN.md`（NNN 为当日序号，从 001 开始），格式如下：

```markdown
# 反馈记录 YYYY-MM-DD_NNN

- **日期**: YYYY-MM-DD
- **模块**: text-to-svg / exam-analysis / Physical Content Display
- **输出描述**: [生成内容的简要描述]
- **用户反馈**: [用户原文]
- **改进建议**: [提炼后的改进方向]
- **已转化为规则**: No
- **关联规则**: —
```

### Step 3: 检查 learnings.md

读取 `evolution/learnings.md`，检查是否已有匹配当前反馈的现有规则。

- **已有匹配规则** → 记录该规则编号到反馈记录中，将规则注入当前会话上下文，重新生成输出
- **无匹配规则** → 进入 Step 4

### Step 4: 判断反馈频率

扫描 `evolution/feedback/` 目录下的所有记录，统计同类反馈出现次数：

- **首次出现** → 仅归档，不上新规则
- **同类型反馈 ≥ 2 次** → 进入 Step 5

### Step 5: 提炼新规则

在 `evolution/learnings.md` 末尾追加一条新规则：

```markdown
## RULE-NNN: [规则标题]

- **来源**: 反馈 YYYY-MM-DD_NNN, YYYY-MM-DD_MMM
- **模块**: text-to-svg / exam-analysis / Physical Content Display
- **指令**: 具体、可执行、无歧义的改进要求
- **优先级**: high / medium / low
```

规则编写原则：

- 指令必须**可执行**——即下次生成时 Agent 能直接照着做
- 避免模糊表述（如"更好看"→ 改为"一级节点使用主色填充+白色文字"）
- 标注来源反馈编号，便于追溯

同时更新 `changelog.md` 记录此次规则新增。

### Step 6: 更新 changelog.md

在 `evolution/changelog.md` 追加一条版本记录：

```markdown
### YYYY-MM-DD：新增规则 RULE-NNN

- **模块**: text-to-svg / ...
- **触发反馈**: YYYY-MM-DD_NNN, YYYY-MM-DD_MMM
- **规则**: RULE-NNN: [标题]
```

### Step 7: 应用规则

将新规则或匹配到的现有规则作为上下文指令，在当前会话中重新生成输出，并告知用户已根据反馈进行了调整。

## 规则生命周期

| 阶段  | 条件             | 操作                                  |
| --- | -------------- | ----------------------------------- |
| 候选  | 首次反馈           | 仅归档到 evolution/feedback/            |
| 活跃  | 2+ 同类反馈        | 提炼为 evolution/learnings.md 规则       |
| 废弃  | 用户主动取消 / 规则已过时 | 从 learnings.md 移除，在 changelog.md 记录 |

## 注意事项

- **不修改**现有 SKILL.md 文件或模板
- **不删除**任何现有文件
- 反馈文件是只读存档，不做修改（仅新增）
- learnings.md 的规则通过追加方式扩展，不删除已有规则（仅在废弃时标记）

# 常见问题

**Q: 如何判断用户需要哪个子模块？**
A: 按触发关键词路由。如果用户说"画个图表/可视化"→模块1；"分析考试成绩"→模块2；"做个物理课件"→模块3。模糊时追问确认。

**Q: 模块间可以组合使用吗？**
A: 可以。例如先做考试分析模块生成成绩报告，再用物理教学模块制作试卷讲评课件。但每个模块独立运行，输出独立的 HTML 文件。

**Q: 所有输出都是单文件 HTML 吗？**
A: 是。所有四个模块的输出均为完全自包含单文件 HTML，零外部依赖（考试分析模块内置 Chart.js v4.4.7 离线库，无需 CDN）。

**Q: 考试分析需要 Python 环境吗？**
A: 是的。需要安装 pandas 2.0.0+ 和 openpyxl 3.1.2。脚本会自动读取并嵌入 chart.umd.min.js（Chart.js 离线库）和 charts.js 到 HTML 中。

**Q: SVG 可视化的详细绘制规范在哪里？**
A: 详细规范（节点尺寸计算、间距公式、坐标验证、颜色方案等）在本文件「模块 1: 文本核心内容可视化」第 2-7 节中，生成 SVG 图表前请务必阅读完整章节。
