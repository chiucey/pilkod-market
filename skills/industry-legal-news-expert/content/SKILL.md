# 行业资讯与法务合规专家整合版 (Industry & Legal Compliance News Expert)

本技能整合了三项原技能的能力：**行业新闻汇编专家**（行业资讯 / 司法案例 / AI大模型动态三板块）、**互联网法务合规专家**（新法新规检索与合规方向分析）、以及 **网页文章提取工具**（从网页源码批量提取文章元数据，作为检索阶段的辅助能力）。三项原技能的检索类核心要求（数量要求、URL链接验证、权威来源规范、时效性要求、飞书云文档自动输出等）**全部保留、不作删减**。

**在此基础上，「司法案例」与「新法新规」两个板块的解读方式已参照 `regulation-interpreter` 技能的方法论做了改进**：不再以固定字数分配（如"约400字+约200字+每项约100字"）和"业务影响与合规方向指引表格"为默认写法，而是改用**贴原文/报道、不自行延伸、摘录与编者判断严格分开、每条（版）正文≤1000字**的解读方法——司法案例采用"基本案情概要／案件定性·司法认定／业务注意要点·风险"三段固定结构，新法新规采用"主要内容（据原文梳理）／业务关注要点（编者提示）"结构并按目标读者产出业务/专业版与非业务/非专业版。检索来源、URL验证、数量要求等**不受影响，维持不变**。

## 运行模式识别 (Mode Detection)

**第一步：判断运行模式**。根据用户请求中的关键词自动识别运行模式。五种模式共用同一套质量标准（URL验证、权威来源、时效性、飞书云文档输出），互不降级。

1. **完整模式优先词**（行业资讯+司法案例+AI大模型三板块）：用户请求中出现以下任一关键词 → 直接进入完整模式：

2. **单板块 / 单能力关键词匹配**：若未命中完整模式优先词，则按下表检测：

| 模式 | 触发关键词（满足任一即可） | 输出内容 |

### 判断规则

1. 先检查是否命中**完整模式优先词**，命中则直接进入完整模式（仅含行业资讯/司法案例/AI大模型三板块，不含新法新规、不含网页提取）。
2. 未命中优先词时，依次检查各单板块/单能力关键词。
3. 同时命中"行业资讯/司法案例/AI大模型"中的多个关键词 → 进入完整模式。
4. 同时命中"新法新规"关键词与"行业资讯/司法案例/AI大模型"关键词 → 视为用户需要两份内容，分别按各自模式独立执行、独立验证、独立生成飞书文档（不得混合成一份文档）。
5. "网页文章提取"关键词一旦命中，优先于其他所有模式：该请求视为纯工具调用，不进入月刊分析流程，不生成飞书文档，除非用户额外要求。
6. 仅命中一个板块/能力关键词 → 进入对应单一模式。
7. 未命中任何关键词 → 默认进入完整模式。
8. **单板块/单能力模式下，输出质量不得降级**，保持与完整模式同等的深度和标准。

## 核心工作流 (Core Workflow)

### 通用步骤（月刊类模式共用：完整模式 / 行业资讯 / 司法案例 / AI大模型 / 新法新规）

1. **确定检索范围**：明确当前月份（或用户指定的时间范围），并针对目标板块制定检索关键词。
2. **执行权威检索**：优先访问 `references/sources.md`（行业资讯/司法案例/AI大模型来源）或 `references/regulation-output-guide.md`（新法新规官方渠道）中列出的权威媒体、法院官网、监管部门官网、专业公众号、律所案例分析。
   - 当检索到的目标网页是列表页/搜索结果页、需要从大量 HTML 源码中批量提取文章标题、链接、时间、来源时，调用"辅助工具：网页文章提取"中的流程与脚本，以提高检索效率与信息完整性。
3. **信息筛选与整合**：剔除重复或非权威来源的信息，保留具有典型性、影响力的案例/资讯/法规，重点筛选互联网 TOP 大厂（如苹果、华为、米哈游、字节跳动、京东、阿里巴巴、宇树科技等各行业TOP厂商及同等地位的行业厂商）及数字经济领域的典型内容。
4. **深度分析与解读**：按对应板块的模板要求进行深度分析（详见各板块模板）。
5. **内容质量验证**：执行对应板块的验证检查清单（`references/validation-checklist.md`）。
6. **按规范格式输出**：确保输出内容符合用户要求的结构化模板。
7. **自动转为飞书云文档**：使用 `larksuite-cli docs +create` 命令创建飞书云文档（"网页文章提取"模式除外）。

### 3. 司法案例解读模板 (Judicial Case Interpretation Template)

**解读方式（已按 `regulation-interpreter` 技能升级）**：不再采用固定字数分配写法，改为**案件解读三段法**——忠于原文/报道、概要只白描、定性贴原话、风险给方向不出处方，每条案例正文合计 **≤1000字**。

| 字段 | 内容说明 | 验证要求 |
| :--- | :--- | :--- |
| **案例标题** | 一句话点出争议或违法核心 | - |
| **发布时间** | YYYY-MM-DD | 必须为当前/指定月份或近2个月内 |
| **内容出处** | 法院官网/公众号或权威律所分析（**必须附带可直接访问的 URL 链接**） | **必须验证链接有效性** |
| **一、基本案情概要** | 四要素白描（主体/背景/关键行为/结果），案型自适应标签，当事人称谓随原文/报道，**不下判断** | 只白描，不出现定性词 |
| **二、案件定性/司法认定** | 贴原文/报道原话的法院/监管定性与说理，写明具体法条（第几条第几款），可重组为"一是/二是/三是" | 忠于原文，不自造评价 |
| **三、业务注意要点/风险** | 从个案外推可迁移的合规红线，只用"需关注/需评估/建议梳理/警惕"类方向性动词 | 只给方向，不出处方（无SKU/动作/时限/优先级） |

完整的角色定位、忠于原文铁律、四要素写法、抽象化与锚点保留规则、输出模板与定稿核验清单，见 `references/case-analysis-guide.md`。

### 4. 新法新规解读模板 (Regulation Interpretation Template)

**解读方式（已按 `regulation-interpreter` 技能升级）**：不再以"业务影响与合规方向指引整合表格"为默认唯一产出，改为**贴原文、不延伸、按目标读者分双版本**的法规解读轨道。对于检索到的每一条新法新规，先读原文抓准事实字段，再按以下模板输出（不明确目标读者时，业务/专业版与非业务/非专业版**同时产出**）：

```
《X》标题
发布日期：__　实施日期：__（过渡期__）　标签：__ | __
[背景导语：谁发布、何时通过/施行、替代了什么，一段]

主要内容（据原文梳理）
1.〔一句话陈述，保留关键限定与标志性例子〕
2. ……

业务关注要点（编者提示）
〔只点方向/影响面，方向性动词；如需按业务线细分可标注电商/内容/广告/数据/其他〕
（注：具体落地清单另行梳理。）

内容出处：__（权威官方渠道 + 可直接访问的URL链接）
```

**核心铁律**：只写原文有的、不编造规则；贴着原文用词，不脱离原文自造术语或近义替换；**摘录（主要内容）与编者提示严格分开**，业务判断/风险排序不得混入摘录；解读是导引、不出处方，不给SKU/动作/时限/优先级级别的具体整改；每版正文 **≤1000字**，输出前必须完成字数核对与原文引用核对。**若用户明确要求**按业务线拆分的"主要影响/合规方向/关联业务"对照表格，可在"业务关注要点"之后追加作为补充产出，但不作为默认格式。

**若某条法规仅涉及特定领域（如仅影响金融科技），需在解读开头明确注明适用范围；跨领域法规需分别提示对各领域业务的关注点；语言需专业、清晰，避免过度法律术语。**

**当检索时间段内无相关新规时**，按以下格式输出：
```
经检索[当前年份]年[当前月份]官方权威渠道，本月无新发布互联网行业相关法规。
```

完整的角色定位、铁律、双受众写法、输出前检查与校验清单，见 `references/regulation-interpretation-guide.md`；官方渠道分级列表、禁止引用来源，见 `references/regulation-output-guide.md`；默认格式示例见 `assets/regulation-example-interpretation.md`，业务线对照表格补充产出示例见 `assets/regulation-example-output.md`。

## 验证检查清单 (Validation Checklist)

**在最终输出前必须逐项检查。根据运行模式选择对应检查项：**

### 通用检查项（所有月刊类模式必查）
1. ✅ 每个资讯/案例/法规的"内容出处"是否包含有效URL链接
2. ✅ 所有URL链接是否可访问（格式正确，包含http://或https://开头）
3. ✅ 所有内容是否为当前/指定月份或近2个月内发布
4. ✅ 所有来源是否来自权威渠道
5. ✅ 【飞书云文档】文档标题是否符合规范
6. ✅ 【飞书云文档】文档结构是否包含对应板块的一级标题
7. ✅ 【飞书云文档】所有内容是否已正确写入飞书云文档
8. ✅ 【飞书云文档】文档链接是否已返回给用户

### 行业资讯板块专项检查
9. ✅ 行业资讯数量是否不少于10项
10. ✅ 每条资讯核心内容是否为200~300字

### 司法案例板块专项检查（按案件解读三段法，见 `references/case-analysis-guide.md`）
11. ✅ 司法案例数量是否不少于10项
12. ✅ 是否按"基本案情概要／案件定性·司法认定／业务注意要点·风险"三段固定顺序输出，且每条正文合计 ≤1000字
13. ✅ 基本案情概要是否只白描四要素（主体/背景/关键行为/结果），未混入定性评价；当事人称谓是否与原文/报道一致
14. ✅ 案件定性/司法认定是否贴原文/报道原话、写明具体法条，未由编者自造评价；业务注意要点/风险是否只给方向性提示，未出现SKU/动作/时限/优先级等处方式内容

### AI大模型板块专项检查
15. ✅ 【业内AI大模型发展动态】每条新闻是否为当前月份内发布
16. ✅ 【业内AI大模型发展动态】核心内容是否参考原文总结，未过度扩展（100~200字）
17. ✅ 【业内AI大模型发展动态】出处是否来自权威媒体或品牌官网（优先：新华社、人民日报、36氪、阿里云、字节跳动seed、Google等）
18. ✅ 【业内AI大模型发展动态】数量是否不少于10项

### 新法新规板块专项检查（按法规解读轨道，见 `references/regulation-interpretation-guide.md`）
19. ✅ 每条法规是否来自一级/二级/三级官方渠道（见 `references/regulation-output-guide.md`），未引用自媒体、商业财经网站、个人网盘等禁止来源
20. ✅ 是否已抓准发布日期、实施日期、过渡期、文号、发布机关等事实字段
21. ✅ "主要内容（据原文梳理）"与"业务关注要点（编者提示）"是否严格分开，摘录中是否混入了主观定性
22. ✅ 业务关注要点是否只给方向（需关注/需评估/建议梳理），未出现具体到SKU/动作/时限/优先级的整改内容
23. ✅ 是否已按目标读者产出业务/专业版与非业务/非专业版（不明确时是否两版都产出）
24. ✅ 每版正文是否 ≤1000字，是否已完成字数核对与原文引用核对
25. ✅ 内容出处是否为官方可公开访问链接；若当月无相关新规，是否使用统一的"无相关法规"输出格式

**单板块/单能力模式检查规则**：只检查该板块对应的专项检查项 + 通用检查项。未运行的板块不检查。
**完整模式检查规则**：第1-18项全部执行（不含新法新规专项，因完整模式不含该板块）。

## 辅助工具：网页文章提取 (Auxiliary Tool: Web Article Extractor)

该能力用于从网页源代码中高效提取文章的结构化信息（链接、标题、发布时间、来源），既可作为**独立工具**响应"网页链接提取"类请求，也可在上述任一月刊类模式的"执行权威检索"步骤中被**调用以辅助检索**（例如从行业门户网站、法院公告列表页、政策发布列表页批量获取候选内容，再进入后续筛选与深度分析环节）。

### 使用场景
- **新闻采集**：从行业门户网站（如知产财经）批量获取最新动态。
- **舆情监控**：提取特定关键词搜索结果中的文章列表。
- **学术研究**：从案例库或论文列表中提取元数据。
- **月刊检索辅助**：为行业资讯/司法案例/AI大模型/新法新规板块批量获取候选文章线索，之后仍需按各板块要求做权威性、时效性核验与深度分析，不可跳过验证直接采用提取结果。

### 核心工作流
1. **获取源代码**：使用浏览器工具访问目标网页。对于动态加载页面，**必须先向下滚动页面**以触发异步加载，然后再获取完整的 HTML 源代码。
2. **识别列表容器**：定位包含文章列表的 HTML 元素（如 `div.re_conl_con`、`ul.news-list` 等）。
3. **提取元数据**：
   - **链接 (URL)**：提取 `<a>` 标签的 `href` 属性，并转换为绝对路径。
   - **标题 (Title)**：提取链接文本或 `title` 属性。
   - **发布时间 (Time)**：在链接邻近元素中查找符合日期格式（如 `YYYY-MM-DD HH:MM`）的文本。
   - **来源 (Source)**：从页面元数据（如 `<meta name="author">`）或固定标识中提取。
4. **格式化输出**：按照以下标准格式输出结果：
   `链接地址：[URL] |标题名称：[Title] |发文时间：[Time] |来源于 [Source]`

### 提取完整性保障
- **动态加载处理**：如果首次提取数量较少，建议使用 `browser_scroll` 滚动到底部后再重新提取。
- **多容器兼容**：`scripts/extract_articles.py` 支持多种常见的列表容器选择器，并具备正则降级提取能力。
- **智能过滤**：自动过滤导航链接、分类链接等非文章内容。

### 示例解析

**输入 HTML 片段：**
```html
<div class="re_conl_con">
    <p><a href="/casereport/10440.html"> 3.8亿精雕案再审视：100%技术贡献率的认定之思┃附判决 </a></p>
</div>
```

**提取输出：**
链接地址：https://www.ipeconomy.cn/casereport/10440.html |标题名称：3.8亿精雕案再审视：100%技术贡献率的认定之思┃附判决 |发文时间：2026-03-17 09:47 |来源于 知产财经

### 脚本工具
- 路径：`scripts/extract_articles.py`
- 功能：基于正则表达式的结构化提取，支持自动补全 URL、智能识别文章路径特征、就近匹配发布时间，并自动去重。

### 注意事项
- 如果源代码中未直接包含时间或来源，应尝试访问文章详情页获取，或根据页面上下文进行推断。
- 确保处理相对路径 URL，将其与网站 Base URL 拼接。
- 提取结果仅为候选线索，**不能替代**各板块要求的权威性核验、时效性核验与深度分析步骤。

## 注意事项 (Precautions)

- **时效性**：必须确保资讯、案例和法规为"当前月份"或者"指定月份"或者"近2个月内"发布的最新内容。
- **权威性**：严禁引用自媒体、非专业论坛、商业财经自媒体或未经证实的传闻。
- **准确性**：法律条款的引用和司法认定/法规条款的描述必须严谨准确，一律**贴原文/报道所载**，不自行改写、不脱离原文自造术语或近义替换、不补充原文/报道之外的内容。
- **针对性**：重点关注互联网 TOP 大厂及数字经济、运动科技、AI智能领域。
- **单板块/单能力质量不降级**：单板块或单能力模式下，输出深度、字数要求、权威性标准均与完整模式保持一致，不得因板块少而降低质量。
- **多模式并行时不得混合**：若同一请求同时命中"新法新规"与"行业资讯/司法案例/AI大模型"关键词，须分别独立完成检索、验证与飞书文档生成，不得合并为一份内容不一致的文档。

### 强制性要求

1. **数量要求**：
   - 完整模式：行业资讯不少于10项 + 司法案例不少于10项 + AI大模型不少于10项
   - 行业资讯/司法案例/AI大模型单板块：对应板块不少于10项，数量不足时扩大检索范围确保满足要求
   - 新法新规单板块：无固定最低条数要求，以检索期间实际发布的法规数量为准；若当月确无相关新规，按统一格式说明，不得虚构
   - 数量不足（行业资讯/司法案例/AI大模型）认定为任务失败

2. **司法案例解读要求**（司法案例板块运行时，按 `references/case-analysis-guide.md`）：
   - 固定按"基本案情概要／案件定性·司法认定／业务注意要点·风险"三段输出，顺序不变，职责分离（判断评价只留到第二、三段）
   - 案由、法条依据、定性评价、处罚/赔偿金额、原被告一律**照原文/报道所载引用**，不自行改写、不反向重新定性、不补充素材之外的内容；当事人称谓随原文/报道
   - 业务注意要点/风险只给方向性提示（需关注/需评估/建议梳理/警惕），不出具体到SKU/动作/时限/优先级的处方
   - 每条案例正文合计 **≤1000字**

3. **所有内容出处必须包含有效URL链接，缺少有效链接的内容不得输出**。

4. **【业内AI大模型发展动态】**（AI大模型板块运行时）：
   - 每条新闻**必须为当前月份内发布**的新闻。
   - 核心内容**重点参考原文总结，不要过度扩展**。
   - 出处**优先官方优质媒体**（新华社、人民日报、36氪等）**及各大模型品牌官网**（阿里云、字节跳动seed、Google等），**2026-07-01 起新增 AITNT（[https://aitntnews.com/](https://aitntnews.com/)）作为 AI 大模型动态专项数据源**。
   - 链接**必须有效可点击直达**。

5. **【新法新规】**（新法新规板块运行时，按 `references/regulation-interpretation-guide.md`）：
   - 必须**严格按照官方权威数据源**检索（见 `references/regulation-output-guide.md` 中一级/二级/三级官方渠道），**严禁**引用抖音/快手/微博非政务号、财经类自媒体、商业财经网站（如36氪、虎嗅等）、个人网盘或临时链接、未经核实的社交媒体信息。
   - 只写原文有的，不编造规则；贴着原文用词，不脱离原文自造术语或近义替换；原文限定适用范围/前提的词句须完整保留。
   - "主要内容（据原文梳理）"与"业务关注要点（编者提示）"**严格分开**，编者提示只用方向性动词，**不出具体到SKU/动作/时限/优先级的处方**；用户明确要求业务线对照表格时可作为补充追加，不作默认格式。
   - 不明确目标读者时，**业务/专业版与非业务/非专业版同时产出**。
   - 每版正文 **≤1000字**，出正文前必须完成字数核对与原文引用核对。
   - 若链接失效，需注明并尝试寻找替代官方链接。

6. **【飞书云文档自动输出】**（"网页文章提取"独立工具模式除外）：
   - 完成内容检索、分析和验证后，必须将所有内容自动转为飞书云文档。
   - 文档标题格式按运行模式确定（见上文"各模式文档标题规范"）。
   - 文档结构按运行模式确定对应一级标题。
   - 使用 `larksuite-cli docs +create` 命令创建文档，使用 `--title` 指定标题，使用 `--content` 指定 Markdown 内容。
   - 文档创建成功后，**必须将文档链接返回给用户**，格式：`> [文档标题](文档链接)`。
   - **禁止**仅输出 Markdown 内容而不创建飞书云文档。
