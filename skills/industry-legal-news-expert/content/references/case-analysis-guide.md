# 司法案例解读指南（案件解读三段法，整合自「regulation-interpreter」技能）

本指南规定「司法案例」板块的解读方式，替代原先"基本案情概要约400字/案件定性约200字/每项约100字"的固定字数分配写法，改用**忠于原文、三段固定结构**的案件解读方法。核心原则与主技能"权威来源、URL链接验证、数量不少于10项"等检索类要求并行不冲突，本指南只规范**单条案例内部的解读与写作方式**。

## 一、栏目定位与三段结构（顺序固定）

案件解读不是复述判决，而是让业务读者读懂"发生了什么、怎么定的、跟我们有没有关系"。每条案例固定输出三段：

1. **基本案情概要** —— 只白描事实，不下判断。
2. **案件定性 / 司法认定** —— 搬权威（法院/监管）的定性与说理，编者不自造评价。
3. **业务注意要点 / 风险** —— 从个案提炼可复用的合规红线，只给方向。

三段之间职责分离：判断和评价一律留到第二、三段，第一段不越位。

## 二、忠于原文/报道（最重要的一条）

素材通常是法院/监管官网原文，或权威媒体、公众号、监管通报等二手报道。**案由、法条依据、定性评价、处罚/赔偿金额、原被告，一律以所给素材原文为准**，与素材保持一致：

- **不自行改写、不反向重新定性**：素材称"虚假榜单"就写"虚假榜单"，不擅自改成"虚假宣传"；反之亦然。
- **不补充素材之外的内容**：素材没写的法条、没提的细节、没有的规则，一概不编。
- 素材为二手报道时，忠实反映报道原文即可，无需回溯判决书/处罚决定书原件，也不必标注"待核"。

一句话：解读的边界＝素材的边界。加工的是**结构和详略**，不是**事实和定性**。

## 三、基本案情概要写法

### 3.1 四要素骨架
无论民事、行政、刑事，概要都回答同一组问题：**主体 — 背景 — 关键行为 — 结果/诉请**。

### 3.2 案型自适应标签（加粗标签＋冒号分点）
- **民事纠纷**：涉案主体 / 起因（事实经过＋诉请＋标的额）
- **行政处罚**：涉案主体 / 公司（主体）基本情况 / 违法行为 / 处罚结果
- **刑事案件**：涉案主体 / 基本事实 / 指控罪名 / 判决结果

行政案通常先立"这是个什么样的主体"（成立年份、资本、人员构成），再讲违了什么法、罚成什么样。

### 3.3 只白描，不评价
概要段不出现"最需警惕""性质恶劣""红线"等定性词，这些留给第二段，且须是权威说过的。

### 3.4 当事人称谓随素材
素材匿名（某文化公司、朱某）则匿名，素材实名（如公司全称）则实名，与素材保持一致，不自行还原或隐去。

## 四、案件定性 / 司法认定写法

- **评价上交**：本段的定性、说理，尽量贴近或直接引用素材中所载的法院裁判说理、监管认定表述，编者不自造定性；须写明具体法条（第几条第几款），照素材所载，不自行补全。
- **可结构化重组**：把权威白描重组成"一是/二是/三是"的违法特征或裁判要点是允许的提炼，但重组不得改变原意、不得把单一示例上升为普遍结论。

## 五、业务注意要点 / 风险写法

- **个案 → 通用红线**：从这一个判决/处罚，外推出可迁移到自家业务的合规规则（如"简单堆砌型提示词不受保护""警惕付费上榜的无资质第三方背书机构"）。这是案件解读相对原文新增的价值层。
- **给方向，不出处方**：只用"需关注/需评估/建议梳理/警惕"类方向性动词，不写具体到 SKU、动作、时限、优先级的整改内容。
- **不外推过头**：红线必须由本案定性支撑，不得借题发挥引申到本案未涉及的领域。

## 六、取舍规则：抽什么、留什么

### 6.1 抽象化（删个案花絮，换类型化表述）
个案特有、不影响合规判断的细节抽掉：具体提示词文本、账号名、榜单具体篇数、逐项权利名目等。换成"六组提示词""各类榜单""主张构成文字作品"这类可迁移表述——月刊要的是可套回业务的**规则**，不是花絮。

### 6.2 硬数据锚点（择要保留，照原文/报道所载）
后续定性/风险要用到的数字保留并作锚点：罚款额、赔偿/索赔额、注册资本（认缴/实缴）、标的额。纯背景数字（如次要年份、篇数）可舍。**保留的数字照原文/报道所载，不擅自换算或估算。**

## 七、输出结构（模板）

```
〔案件标题：一句话点出争议或违法核心〕

一、基本案情概要
● 涉案主体：〔匿名或实名，依案件公开属性〕
●〔起因／主体基本情况〕：……
●〔违法行为／诉请〕：……
●〔处罚结果／判决结果〕：……

二、案件定性 / 司法认定
●〔贴权威原话的定性一〕（法条：《X法》第X条第X款）
●〔定性二／裁判要点〕
● 判决/处罚结果：……

三、业务注意要点 / 风险
●〔可迁移合规红线，方向性动词〕
（注：具体落地清单另行梳理。）

内容出处：__（权威媒体/法院官网/公众号名称 + 可直接访问的URL链接）
```

**内容出处字段与主技能的URL链接验证要求保持一致**：必须附带可直接访问的URL链接，且来源须为法院官网/公众号或权威律所分析，链接失效不得输出。

## 八、字数要求

- 每条案例的三段正文合计 **≤1000 字**（替代原"约400字+约200字+每项约100字"的固定分配写法）。
- 超出则精简：分点压成一句话陈述、保留关键限定与锚点数字、删除重复铺陈，含义不变。
- 三段内部无需再单独达到某个固定字数，以"讲清四要素／贴原话定性／给出方向性红线"为准，而非凑字数。

## 九、定稿核验清单（出正文前逐条过）

- [ ] 案由、法条、定性、处罚/赔偿金额、原被告是否与原文/报道一致，未自行改写或反向重新定性？
- [ ] 是否只写了素材有的，没有补充素材之外的规则或细节？
- [ ] 当事人匿名/实名是否与素材保持一致？
- [ ] 概要段有没有混入定性/评价？（应全部白描）
- [ ] 定性段的评价性表述是否贴原文/报道原话，而非编者自造？
- [ ] 风险段是否只给方向、未出处方（无 SKU/动作/时限/优先级）？
- [ ] 抽象化是否得当（花絮已抽、规则可迁移），锚点数字是否照原文/报道所载？
- [ ] 内容出处是否包含有效URL链接，来源是否权威？
- [ ] 每条案例正文是否 ≤1000 字？

## 十、示例参考

以下示例展示"忠于原文 + 抽象化 + 锚点保留"的加工方式（改编自参考案例）：

| 维度 | 原文/报道所载 | 进入简报的写法 | 规则 |
|---|---|---|---|
| 案由/定性 | 报道称"虚假榜单""不正当竞争" | **照报道写**"虚假榜单／不正当竞争"，不擅自改写 | 忠于原文 |
| 主体画像 | 2017 成立、认缴 188 万实缴 0、无正式员工 | 保留（作锚点） | 硬数据锚点 |
| 榜单细节 | 报道列举的具体榜单名目、篇数 | 抽象为"连续多年发布各类品牌榜单并收费" | 抽象化 |
| 处罚 | 吊销营业执照＋罚款 130 万 | 照报道保留 | 硬数据锚点 |
| 定性 | 报道归纳的违法特征 | 重组为"披着专业外衣实为皮包公司／以榜单为名行收费排名／借权威背书扩大误导" | 评价上交＋可重组 |

要点：加工的是**结构和详略**（抽花絮、留锚点、重组分点），事实与定性一律**照原文/报道所载**，不做反向改写。

### 国内首例"AI幻觉"案（结构示例，字数已按≤1000字标准精简）

**一、基本案情概要**
● 涉案主体：原告梁某；被告为AI平台研发公司
● 起因：梁某在AI平台查询高校招生信息，AI生成错误校区信息，梁某指出后AI坚称正确并承诺"若有误赔偿10万元"，并指引其起诉
● 诉请：要求研发公司赔偿9999元
● 判决结果：杭州互联网法院一审判决驳回原告诉讼请求，认定研发公司不构成侵权

**二、案件定性 / 司法认定**
● AI不具备民事主体资格，不能独立作出意思表示，其"赔偿承诺"不代表平台真实意愿——明确AI工具属性，避免法律适用混乱
● 生成式AI服务适用过错责任原则，而非产品无过错责任
● 注意义务边界：红线为严格审查法律禁止的有毒有害违法信息；底线为以醒目方式提示风险、采取合理技术措施防错
● 认定研发公司已履行提示义务并采取必要技术保障，不存在主观过错

**三、业务注意要点 / 风险**
● 需关注：AI是辅助工具而非可靠的知识权威或决策替代者，对AI生成的重要信息需建议人工交叉核实
● 需评估：企业对外提供AI服务时的风险提示与技术保障措施是否到位

内容出处：__（法院官网/权威媒体报道 + URL）
