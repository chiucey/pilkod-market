# Task Parser - 任务解析引擎

将自然语言输入解析为结构化任务 JSON。

## 输入处理

接收用户自然语言输入，提取所有明确或隐含的待办任务。

## 解析规则

### 1. 任务拆分
- 如果输入包含多个动作，拆分为独立的 Task
- 每个 Task 应该是原子性的、可执行的操作

### 2. 耗时预估
- 如果用户未说明，根据常识预估合理耗时
- 参考标准：
  - 简单任务（如发邮件）：5-15 分钟
  - 普通任务（如买东西）：15-30 分钟
  - 中等任务（如写报告）：30-60 分钟
  - 复杂任务（如项目规划）：60-120 分钟

### 3. 截止时间解析
将模糊时间转换为 ISO 8601 格式（YYYY-MM-DDTHH:mm:ssZ）：

| 模糊时间 | 转换规则 |
|---------|---------|
| 今天 | 当前日期 23:59:59Z |
| 明天 | 当前日期 +1 天 23:59:59Z |
| 下周一 | 下一个周一 23:59:59Z |
| 下个月 | 下个月最后一天 23:59:59Z |
| 上班前 | 工作日 09:00:00Z |
| 下班前 | 工作日 18:00:00Z |
| 尽快 | 当前日期 +3 天 23:59:59Z |

### 4. 意图分类

| 类型 | 说明 |
|-----|------|
| Action | 需要执行的具体行动 |
| Reminder | 仅提醒，不需立即执行 |
| Someday | 未定期的模糊想法 |

### 5. 标签分类

从任务内容推断标签：
- 工作相关 → "工作"
- 购物相关 → "购物"
- 生活琐事 → "生活"
- 健康运动 → "健康"
- 学习提升 → "学习"
- 社交相关 → "社交"
- 财务相关 → "财务"
- 其他 → "其他"

## 输出格式

```json
{
  "tasks": [
    {
      "title": "简短的任务标题",
      "action_type": "Action",
      "deadline": "YYYY-MM-DDTHH:mm:ssZ",
      "estimated_minutes": 30,
      "context": "原始输入中关于该任务的补充细节或上下文",
      "tags": ["生活", "工作"]
    }
  ]
}
```

## 示例

**输入：**
```
明天要买牛奶和面包，后天给客户发邮件汇报项目进度，下周五之前完成季度报告
```

**输出：**
```json
{
  "tasks": [
    {
      "title": "购买牛奶和面包",
      "action_type": "Action",
      "deadline": "2026-04-10T23:59:59Z",
      "estimated_minutes": 30,
      "context": "日常购物",
      "tags": ["生活"]
    },
    {
      "title": "给客户发邮件汇报项目进度",
      "action_type": "Action",
      "deadline": "2026-04-11T23:59:59Z",
      "estimated_minutes": 20,
      "context": "项目进度汇报",
      "tags": ["工作"]

      "estimated_minutes": 120,

      "tags": ["工作"]
    }
  ]
}
```

## 执行流程

1. 接收用户输入
2. 识别并拆分独立任务
3. 为每个任务提取：
   - 标题（简洁明了）
   - 截止时间（如有）
   - 耗时预估（如无则自动推断）
   - 上下文信息
   - 标签分类
4. 输出结构化 JSON
