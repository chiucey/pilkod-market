## 1. 最小访谈

先从用户原话提取已经确定的答案，只补真正缺失的部分。八类信息的权威清单以 `longform-workflow.md` §2 最小创作契约为准；本节是与之一一对应的提问话术。完整项目默认最多问 8 个合并问题；短篇、样章或用户要求立即开始时进一步缩减。

1. **交付规模与形式**：短篇、中篇、单部长篇，还是只做大纲／样章？
2. **核心谜题和读者体验**：猜凶手、解手法、追捕已知凶手、理解动机，还是多者结合？
3. **时代、地点与现实度**：现实当代、历史、架空或未来？环境是否限制交通、通信或嫌疑人范围？严格写实、写实基础上的戏剧化，还是明确的设定系规则？
4. **调查者及 POV**：职业侦探、警察、律师、记者、业余者、受害者亲友，还是多角色调查？单一 POV 还是多视角？
5. **类型坐标与基调**：智力快感、恐惧、悲悯、黑色幽默、社会批判、浪漫或其他情绪承诺？
6. **内容与安全边界**：血腥、性、儿童受害、现实政治、宗教、药物、自杀等有哪些禁区或尺度？
7. **系列定位**：单案闭合，还是预留跨卷人物／组织长线？跨卷承诺不能替代本卷结局。
8. **用户保留决定与 Agent 可代决事项**：用户逐项决定，还是由 Agent 提出完整推荐方案后供其修改？

### 收束规则

- 用户已给出答案时不重复询问。
- 一次优先问 1–3 个最关键问题；不要把八题一次倾倒给用户。
- 选项必须互斥到足以帮助决策，并说明推荐项的影响。
- 用户表示“你来定”时直接做出专业选择，并在项目章程记录假设。
- 发现未知项不会影响当前产出时，把它记为开放问题，不阻塞工作。

## 2. 类型坐标

不要让用户在一张互相混杂的类型清单里单选。分别从下列坐标选择，再组合成项目定义。

### 谜题焦点

| 焦点 | 核心问题 | 设计重点 |
|---|---|---|
| Whodunit | 谁做的？ | 嫌疑人比较、身份排除、机会链 |
| Howdunit | 怎么做到的？ | 物理约束、时间与空间、手法可验证性 |
| Whydunit | 为什么做？ | 隐藏关系、心理与社会因果 |
| Howcatchem／倒叙追凶 | 已知或近乎已知凶手如何露馅？ | 对抗、压力、证据闭环 |
| 多层谜题 | 表面问题之下还有什么问题？ | 分层揭示，避免后层否定前层公平性 |

### 嫌疑范围与犯罪表象

| 坐标 | 含义 | 注意 |
|---|---|---|
| 开放调查 | 嫌疑范围可扩展 | 必须控制新角色进入时机 |
| 封闭嫌疑人圈 | 犯罪发生后嫌疑人被限定在一群人中 | 核心是“谁在圈内”，不等于密室 |
| 密室／不可能犯罪 | 犯罪在表面物理条件下似乎无法完成 | 核心是“怎么可能”，不必封闭所有嫌疑人 |
| 连环案件 | 多起案件共享规则、凶手或因果 | 每起案件都要推进总谜题，不能只增加尸体 |

### 调查机制

| 机制 | 主要资源 | 典型风险 |
|---|---|---|
| 业余调查 | 人际网络、地方知识、偶然接近 | 调查权限不可信 |
| 私家侦探／冷硬派 | 走访、交易、压力和行动 | 只剩氛围，推理链太弱 |
| 警察程序 | 团队、程序、数据库、取证 | 报告堆积压过人物 |
| 法医／技术调查 | 可重复检验的物证 | 技术成为万能答案 |
| 法庭推理 | 证词、证据规则、交叉询问 | 把真实法域混成通用法庭 |
| 社会调查 | 制度、阶层、历史关系 | 主题替代案件逻辑 |

### 叙事机制

- 单一有限 POV：公平性最容易控制。
- 华生式记录者：允许侦探保留部分推理，但不能隐藏关键观察事实。
- 多 POV／群像：为每个视角建立“可知信息边界”。
- 双时间线：每次切换都必须改变当前谜题的理解。
- 不可靠叙述：先定义不可靠的原因、范围和语言规则。
- 文档体：核对每份文档的作者、目的、保存方式和可伪造性。
- 系列案件：区分本卷闭合谜题与跨卷人物／组织长线。

## 3. 结构选择

把结构当作信息释放方案，不使用固定三幕比例。

### 经典发现式

适合“谁做的／怎么做的”。通常包含：秩序建立 → 犯罪显现 → 初始模型 → 嫌疑扩散 → 模型受挫 → 线索重组 → 证明与后果。

### 封闭压力式

适合孤岛、列车、宅邸、隔离设施等。尽早解释为何嫌疑圈有效；用资源减少、联盟变化、通信失败或下一风险增强压力，不要求固定出现第二名受害者。

### 倒叙对抗式

先让读者看到凶手或主要犯罪过程，再把悬念转向漏洞、证据与心理对抗。仍可保留“真正动机”“被隐藏的共犯”或“调查者代价”等二级谜题，但不要假装核心身份仍是未知。

### 双线汇合式

过去线制造因，现在线追踪果。为每个切换点写明：它回答了什么，又制造了什么更精确的问题。避免过去线只是解释性插叙。

### 法庭／证词重构式

以相互冲突的叙述版本推进。先选择具体法域和程序现实度，再决定证据能否进入法庭；法庭戏的转折必须来自此前可获得的事实，而非临时出现的证人。

### 系列双层式

让本卷案件完整闭合，同时只推进少量跨卷承诺。跨卷线索不能替代本卷结局，也不要把所有未解释细节都称为续作伏笔。

## 4. 可选深化问题

只在相关模块仍有关键空白时选问。

### 案件

- 受害者死亡或损失改变了谁的利益格局？
- 凶手除了犯罪还有什么更安全的选择，为什么没有选择？
- 哪一项客观限制使手法具有本作独特性？
- 如果去掉核心机关，人物冲突仍然成立吗？

### 调查者

- 调查者凭什么接近证据和嫌疑人？
- 其强项如何制造盲区，而不只是装饰性怪癖？
- 案件结束后，调查者失去或改变了什么？

### 嫌疑人与受害者

- 每名嫌疑人隐藏的事情为什么值得撒谎？
- 谁最希望案件尽快结案，谁最希望调查继续？
- 受害者是否拥有主动选择和因果作用，而不只是尸体？

### 读者体验

- 希望读者最早在哪个位置有可能猜中？
- 揭晓后最重要的是智力快感、人物痛感还是价值冲突？
- 哪个错误解释应当在中段最有说服力？

## 5. 篇幅缩放

| 规模 | 建议建档深度 |
|---|---|
| 单场景／闪小说 | 一句话真相、1–3 条关键事实、单一转折；不建档，直接交付 |
| 短篇 | 简化案件圣经、紧凑时间线、少量必要嫌疑人；章节保留 `status` 与 checks（章节模板默认值即合规），不启用登记簿核销、版本号与审计快照 |
| 中篇 | 完整因果链、嫌疑人矩阵、章节级登记簿与 `ledger_actions` 核销 |
| 长篇 | 完整项目文件、canonical 章门、版本递增、审计快照、交接检查点与里程碑审计 |
| 系列 | 长篇全套机制，增加跨卷承诺表，但保持每卷独立真相链 |

篇幅只影响记录粒度与启用的机制档位（详见 `longform-workflow.md` 适用档位与缩放），不降低公平性和因果完整性。

## 6. 常见误区

- 把“密室”“暴风雪山庄”“本格”“多视角”放在同一层级互斥选择。
- 为显得复杂而堆叠多名受害者、双凶手或身份替换。
- 让“最不可能的人”自动等于凶手，而没有因果理由。
- 把侦探怪癖当人物塑造，却不让它影响调查方法或关系。
- 在用户只要一个样章时先进行长时间访谈。
- 把经典作品当作配方复制，而不是分析其结构功能。
