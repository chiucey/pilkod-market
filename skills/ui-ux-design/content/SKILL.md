# UI/UX 设计 (User Interface & Experience Design)

## 核心理念

**Max-De$ign 主张：要么设计，要么被设计。**

UI/UX 设计是以用户为中心的系统性设计方法，通过理解用户需求、优化交互流程、创造直观界面，实现产品价值与用户体验的双重提升。

### 用户旅程图 (Journey Map)

| 阶段 | 触点 | 行为 | 想法 | 情感 | 痛点 | 机会点 |
|------|------|------|------|------|------|--------|
| 认知 | 搜索/广告 | 发现产品 | 是否有用 | 好奇 | 信息杂乱 | 精准呈现 |
| 考虑 | 详情页/评价 | 对比选项 | 哪个更好 | 犹豫 | 信息不足 | 真实案例 |
| 注册 | 表单 | 填写信息 | 流程复杂吗 | 期待 | 步骤繁琐 | 一键登录 |
| 首次使用 | 核心功能 | 体验主要服务 | 能否解决我的问题 | 兴奋/失望 | 学习成本高 | 引导设计 |
| 复访 | 推送/提醒 | 再次使用 | 还值得用吗 | 习惯/疲劳 | 价值递减 | 个性化推荐 |

## 3. 信息架构 (Information Architecture)

### 导航结构类型

| 类型 | 说明 | 适用场景 | 示例 |
|------|------|----------|------|
| 层级结构 | 父-子页面关系 | 内容较多、分类清晰 | 电商、官网 |
| 线性结构 | 步骤引导流程 | 任务流、教程 | 注册向导、结账流程 |

| 辐射结构 | 中心+周边 | 功能模块化 | 仪表盘、控制台 |

## 4. 交互设计

### 交互设计原则

| 原则 | 说明 | 应用示例 |
|------|------|----------|
| 一致性 | 同类操作保持一致 | 按钮风格、导航位置 |
| 反馈 | 操作后及时响应 | 加载状态、成功提示 |
| 可控 | 用户掌控节奏 | 可取消、可返回 |
| 容错 | 预防并帮助恢复 | 表单校验、错误提示 |
| 效率 | 减少操作步骤 | 快捷键、默认值 |
| 映射 | 操作与结果对应 | 拖拽方向、滚动方向 |

### 手势交互规范

| 设备 | 手势 | 含义 |
|------|------|------|
| 移动端 | 单指点击 | 选择/确认 |
| 移动端 | 单指滑动 | 滚动/切换 |
| 移动端 | 双指缩放 | 放大/缩小 |
| 移动端 | 长按 | 唤起上下文菜单 |
| 移动端 | 边缘滑动 | 返回上一级 |
| PC端 | 悬停 | 显示更多信息 |
| PC端 | 右键 | 上下文菜单 |
| PC端 | 拖拽 | 移动/排序 |

## 6. 原型设计

### 原型分级

| 等级 | 形式 | 工具 | 用时 | 适用阶段 |
|------|------|------|------|----------|
| L1 纸质 | 手绘草图 | 纸笔 | 分钟 | 概念探索 |
| L2 线框 | 灰度低保真 | Balsamiq, Axure | 小时 | 流程验证 |
| L3 可交互 | 黑白原型 | Figma, Axure | 天 | 测试迭代 |
| L4 高保真 | 视觉+动效 | Figma, Sketch | 周 | 客户演示 |

### 高保真原型规范

| 元素 | 规范 |
|------|------|
| 尺寸 | 移动端 375×812 (iPhone X) / 桌面端 1440×900 |
| 状态 | Default / Hover / Active / Disabled / Loading |
| 交互 | 页面跳转 / 弹窗 / 抽屉 / 微交互 |
| 标注 | 标注设计说明、异常状态 |
| 命名 | 页面命名、组件命名统一规范 |

### 响应式断点

| 设备 | 断点 | 布局 |
|------|------|------|
| 手机 | < 640px | 单列 |
| 平板竖屏 | 640-768px | 单列/双列 |
| 平板横屏 | 768-1024px | 多列 |
| 桌面 | 1024-1280px | 固定宽度 |
| 大屏 | > 1280px | 居中最大宽度 |
