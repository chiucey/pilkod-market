# 医疗器械产品开发多智能体角色定义技能

## 概述

本技能基于多智能体协作架构（Multi-Agent System），为医疗器械产品开发提供系统化的角色定义和协作机制设计。

## 核心概念

### 什么是多智能体协作

多智能体系统（Multi-Agent）不是简单的"多个AI同时工作"，而是多个智能体（Agent）各自拥有明确的**角色**、**目标**和**工具**，通过结构化的**协作机制**共同完成复杂任务。

**关键特征**：
- **分工明确**：每个智能体承担特定职责
- **协作机制**：智能体间通过消息传递进行协商
- **专业分工**：每个智能体只处理其擅长领域的任务
- **可追溯性**：每个步骤都有明确记录，便于审计

### 三种主流协作架构

1. **角色导向架构（Role-Based Orchestration）**
   - 代表框架：CrewAI
   - 特点：确定性高、可审计性强
   - 适合：需要合规审批的生产环境

2. **对话式架构（Conversational Orchestration）**
   - 代表框架：Microsoft AutoGen
   - 特点：灵活性高、支持动态涌现
   - 适合：开放式研究和复杂问题解决

3. **图状态架构（Graph-Based State Machine）**
   - 代表框架：LangGraph
   - 特点：支持循环、条件分支、状态持久化
   - 适合：复杂任务依赖关系

## 医疗器械产品开发角色定义

### 核心角色矩阵

| 角色 | 职责 | 核心能力 | 典型应用场景 |
|------|------|----------|--------------|
| **产品经理（Product Manager）** | 需求定义、项目规划 | 法规解读、市场分析、风险意识 | 产品立项、需求评审 |
| **系统架构师（System Architect）** | 架构设计、技术选型 | IEC 62304、FDA 21 CFR Part 820 | 系统架构评审、技术方案 |
| **质量工程师（Quality Engineer）** | 质量保证、验证确认 | ISO 13485、GB/T 42061 | 验证计划、确认文档 |
| **安全专家（Safety Expert）** | 风险管理、合规审查 | IEC 62366、ISO 14971 | 风险管理报告、安全评估 |
| **临床专家（Clinical Expert）** | 临床评价、可用性 | IEC 62366、ISO 14155 | 临床评估、可用性测试 |
| **合规专家（Compliance Expert）** | 注册申报、监管对接 | NMPA、FDA、CE认证要求 | 型检、注册申报 |

### 协作流程设计

#### 1. 顺序执行流程（Sequential Flow）

适用于：任务有明确先后依赖关系

```
需求定义 → 架构设计 → 详细设计 → 编码实现 → 单元测试 → 集成测试 → 系统测试 → 验证确认
```

#### 2. 并行执行流程（Parallel Flow）

适用于：独立子任务可同时进行

```
┌─────────────────┬─────────────────┬─────────────────┐
│  软件需求规格   │   硬件需求规格   │   机械需求规格   │
└────────┬────────┴────────┬────────┴────────┬────────┘
         │                 │                 │
         ▼                 ▼                 ▼
┌─────────────────┬─────────────────┬─────────────────┐
│  软件架构设计   │   硬件架构设计   │   机械架构设计   │
└────────┬────────┴────────┬────────┴────────┬────────┘
         │                 │                 │
         └─────────────────┼─────────────────┘
                           ▼
                   系统集成与验证
```

#### 3. 层级委托流程（Hierarchical Delegation）

适用于：需要多级审核和决策

```
用户请求
    │
    ▼
路由智能体（Router Agent）
    │
    ├──▶ 研究员智能体（Researcher）
    │        │
    │        ▼
    │    执行任务 ──▶ 返回结果
    │
    ├──▶ 设计师智能体（Designer）
    │        │
    │        ▼
    │    执行任务 ──▶ 返回结果
    │
    └──▶ 审核员智能体（Reviewer）
             │
             ▼
         汇总整合 ──▶ 返回用户
```

### 角色交互协议

#### 消息传递机制

```
发送者 ──▶ [消息类型] ──▶ 接收者

消息类型：
- REQUEST: 请求执行某项任务
- RESPONSE: 返回任务结果
- APPROVAL: 请求审批
- REJECTION: 拒绝请求并说明原因
- ESCALATION: 升级到上一级决策
```

#### 决策规则

| 场景 | 决策机制 | 适用角色 |
|------|----------|----------|
| 需求变更 | 评审委员会投票 | 产品经理、安全专家、质量工程师 |
| 技术方案 | 架构委员会审查 | 系统架构师、技术专家 |
| 风险超标 | 升级机制 | 安全专家 → 合规专家 → 管理层 |
| 质量问题 | 质量门禁 | 质量工程师 → 项目经理 |

## 技能使用指南

### 触发条件

当用户提供以下类型的请求时触发本技能：

1. **角色定义类**
   - "为XXX器械开发项目定义团队角色"
   - "建立AI辅助的开发团队角色体系"
   - "设计多智能体协作的职责分工"

2. **流程设计类**
   - "设计XXX项目的协作流程"
   - "建立角色间的交互协议"
   - "制定决策机制和升级路径"

3. **框架选择类**
   - "推荐适合医疗器械开发的智能体框架"
   - "选择多智能体架构方案"
   - "评估AutoGen/CrewAI/LangGraph的适用性"

4. **合规映射类**
   - "将IEC 62304活动映射到团队角色"
   - "建立法规要求与角色职责的对应关系"
   - "设计符合ISO 14971的风险管理角色"

## 技术选型建议

| 需求场景 | 推荐框架 | 原因 |
|----------|----------|------|
| 确定性流程 + 合规审计 | CrewAI | 角色导向、高可审计性 |
| 开放式研究 + 动态推理 | AutoGen | 对话式、高灵活性 |
| 复杂状态机 + 人工审批 | LangGraph | 图状态、支持循环分支 |
| 混合需求 | 组合框架 | 根据子任务特点选择 |
