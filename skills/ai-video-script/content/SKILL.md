# AI 视频剧本（段式）

## Inputs to collect

问用户或从上下文里读，缺哪项补哪项，不要用假设硬上：

- **故事/情节** —— 最低要求是"谁，在哪，想干什么"。只有一句抽象主题（如"展示友情的伟大"）就先请用户给具体事件，因为抽象主题无法拆成可拍动作。
- **总时长或总段数** —— 用户不给就自己估，但要在交付时说明"共 N 段、约 M 秒"，因为段数直接决定切分粒度。
- **画风/受众/平台** —— 影响角色档案的写法（写实风写厘米和疤痕，动画风写比例和色号）。用户没说就按写实风处理，不必追问。
- **是否续写已有剧本** —— 是的话先读原剧本，逐段对齐角色基本信息和段号续编，不要重新设计角色。

## Procedure

1. **拆段**。按「场景切换」和「时长上限」两个硬边界切：一段只一个场景，超过 15 秒必须拆开。时长判断表见 `references/cross-segment.md`。先列段号清单再填内容，因为段号错了后面全错。
2. **建角色卡**。基本信息（年龄、体型、外观、默认服装）写一次就固定，跨段原样复制；本段状态（服装状态、情绪、姿势、位置）每段重写。这两类混在一起是段自包含的前提——视频模型只看得到当前段，看不到 S001。
3. **填场景档案**。先列 3-5 个主要物体（从左到右、从上到下），再以主要物体为参照挂 5-10 个次要物体。参照物挂载而不是凭空描述，模型才知道空间关系。
4. **写正文四块**，顺序固定：初始状态 → 对话 → 动作序列 → 镜头提示。
   - 初始状态只写「开始时」的样子，不写变化过程——过程属于动作序列。
   - 动作序列按时间顺序编号，**只写起点和结果，不写中间过渡**。写「手从 A 移到 B」而不是「手经过 C 移到 B」，因为中间态会挤占时长预算。
   - 镜头提示每个镜头必须用 `→ 动作 X, Y` 回指动作编号。没有回指的镜头等于凭空多出的画面，视频模型会生成没被写进动作里的内容。
   - **可动物体要在段内走完一条有终态的轨迹**。门、窗、伞、帘子、杯子这类东西一旦进了动作序列，它的运动方向和停下时的状态必须写死（见原则 15）。
5. **回读自查可拍性**。每句问自己：这个能被摄像机拍到或麦克风录到吗？抽象形容词单独成句是这套格式最常见的失败模式——「美丽的森林」拍不出来，「金色光斑透过树叶落在地面苔藓上」能。抽象情绪要落到身体动作上：「紧张」写成「单手握酒杯，指节发白」。
6. **跑校验**：`node scripts/validate.js <剧本文件>`。校验器检查段号递增、时长边界、区块完整、动作编号连续、镜头-动作编号对应、对话括号非空。按它的报错改，改完再跑一次。校验器只管格式，可拍性得你自己判断。
7. **交付**。用 `<deliver-assets>` 附上 `.md` 文件，并在正文外用一两句话说明段数、总时长、以及你替用户做的假设。

## Output format

严格使用以下结构。区块名、缩进、字段名都不要改写，视频模型的 prompt 解析对格式敏感。

```text
段号: [S + 三位数字]
时长: [4-15秒；超过15秒必须拆段]

[场景]
名称: [场景名]
档案: |
  类型: [室内/室外/特殊]
  主要物体（从左到右、从上到下，3-5 个）:
  1. （[位置]）[物体] - [状态]
  2. （[位置]）[物体] - [状态]
  次要物体（以主要物体为参照，5-10 个）:
  - [主要物体] 旁/前/后/上/下: [次要物体]
  光线: [光源 + 颜色 + 方向]
  氛围: [环境整体感]
  环境音: [持续背景声]

[角色]
- [角色名]: [基本信息（年龄、职业、外观、默认服装）]，[本段服装状态]，[本段情绪]，[本段姿势]，[本段位置]

[音乐]
风格: [音乐类型]
节奏: [BPM 或 缓/中/快]
情绪: [音乐情绪]
参考: [可选 @Audio 编号]

[正文]
[环境与人物初始状态]
[人物 A 名字]:
  身体姿势: [躯干/手/脚/头的位置]
  关键物品: [手握/背靠/身上有什么]
  视线方向: [看向哪里]
[人物间关系]: [谁看谁/谁背对谁/谁靠近谁]

[对话]
说话人（语气/动作）: 内容。

[动作序列]
1. [主体] + [动作] +（[音效]）
2. [主体] + [动作] +（[音效]）

[镜头提示]
- 镜头 1: [景别] / [角度] / [运镜] → 动作 [X, Y]（[聚焦目标]）
```

两处容易写错的地方：

- `[人物间关系]:` 是**字段**不是子块——它后面跟内容，不构成区块边界，别给它单独起一行区块。
- 无台词的段落，`[对话]` 整块写 `（无台词）`。校验器认这个标记。硬凑台词是给格式上供，模型会照着演一段没必要的旁白。

角色只局部入画时（只出现一双手、半个肩膀），基本信息可精简到能定位身份的程度，再在「本段服装状态」里写明入画范围，例如「仅右肩与小臂入画，袖口滴着水」。

## 关键原则

每条都附了原因——遇到边界情况按原因判断，别按字面硬套。

1. **每句话必须可视/可听/可拍**。理由：写进 prompt 的每个词都会被当作画面约束去渲染，抽象描述浪费时长预算还污染画面。
2. **抽象形容词不单独成句**。改为具象替代：情绪落到身体（见 Procedure 步骤 5）。
3. **动作必须主动语态、主体明确**。主语缺失时模型会把动作错误分配给在场角色。
4. **段自包含**。每段独立，场景档案完整 + 角色含基本信息 + 本段状态。理由：视频模型逐段生成，缺上下文会画出不存在的服装或陈设。
5. **角色 5 要素**。基本信息 + 本段服装状态 + 情绪 + 姿势 + 位置，五项缺一项都会让模型自由发挥。
6. **正文 4 子字段**。初始状态 + 对话 + 动作 + 镜头提示，缺镜头提示等于没做分镜。
   - `[人物间关系]:` 写在初始状态里，**它是字段不是子块**（后面跟内容，所以不构成区块边界）。
   - 无台词的段落，整块写 `（无台词）` 即可。不要为了填满格式给沉默的猫编台词。
7. **动作按时间顺序写，不写中间状态**。只写「开始」和「结果」。
8. **对话格式 `说话人（语气/动作）: 内容`**，括号里语气和动作至少给一个。空括号等于没说这句话该怎么说、怎么做。
9. **一段 4-15 秒**，超出必须拆段。
10. **一段只一个场景**。两处地点就必须切段，否则切场时机由模型随意决定。
11. **动作粒度**。每个动作含身体部位 + 力度 + 速度，否则生成的动作幅度随机。
12. **关键动作后附音效**，写进括号。给音轨切分点，也让静默段落的取舍有依据。
13. **非人类主体按形状决定动作逻辑**。独角兽用「伸舌头」而不是「张嘴」，因为它的口部结构与人类不同；主体形状不支持某个动作时就换一个同类动作，不要硬套人类动词。
14. **镜头与动作对应**。`[镜头提示]` 每个镜头必须用 `→ 动作 X, Y` 标注对应动作编号，且编号必须在动作序列范围内。
15. **可动物体必须闭合**。门、窗、伞、帘子、水杯、手机——凡是能被推动、拉动、开合的物体，在动作序列里必须满足三条：
    - **单一状态**：同一段里这物体在档案、初始状态、人物间关系里的描述不能互相打架。「半掩」和「还没推开」不能同时出现。
    - **方向明确**：写「往门厅内侧推开」而不是「推开」。中文的推/拉本身不携带方向，省略方向模型就自己选，选错会连带改写角色走位。
    - **终态写死**：运动发生后必须交代它停在哪、停成什么样（转到九十度停住 / 敞开后静止不动），并且让后续动作都发生在它静止的状态下。没写终态的物体会被模型补一个回弹或关闭动作，于是观众看到「先是往里走，接着又往外走」。

    理由：模型只会渲染你写下的东西。你留空的地方，它会用最省事的物理补全——而「让门晃回去」恰好就是最省事的一种。

跨段编号、时长判断表、切场方式、一致性规则见 `references/cross-segment.md`。写多段剧本时先读它。

## Output contract

- 一个 `.md` 文件，含若干段，每段结构如上
- 段号 `S001` 起连续递增，全书唯一
- 交付前 `node scripts/validate.js <文件>` 退出码为 0
- 交付消息里说明：总段数、总时长、替用户做的假设

## Failure handling

- **校验器报 ERROR** —— 按提示改，别改校验器。校验规则是格式契约的一部分，放宽它等于交付一份视频模型读不进去的剧本。
- **用户给的故事撑不起时长**（比如一句话硬要 60 秒）—— 告诉用户需要补哪些事件或接受压缩，给具体缺口而不是只说"内容不够"。
- **角色太多，一段塞不下** —— 按「同框角色不超过 3 个」拆段，多出来的角色移到新段。这是硬约束，不是风格偏好。
- **用户明确要改格式** —— 先确认会破坏与视频模型的兼容性，得到确认后再改；改完记得同步更新 validate.js 的对应规则，否则校验器和实际格式会各说各话。
- **只给了剧情梗概就要镜头** —— 直接拆，缺的信息用合理默认补齐并在交付时列出，不必逐项追问。梗概阶段的信息不足通常不值得打断用户。

## Examples

Input: 「9 秒：少女在森林空地给受伤的独角兽喂水」

Output（节选，完整段结构见上方 Output format）:

```text
段号: S001
时长: 9秒

[场景]
名称: 森林空地
档案: |
  类型: 室外森林空地
  主要物体（从左到右、从上到下，3-5 个）:
  1. （左侧）古树 - 苔藓覆盖
  2. （中间）独角兽 - 趴卧
  3. （右侧）少女 - 蹲在独角兽旁
  次要物体:
  - 独角兽 背上: 一道伤口
  - 少女 脚下: 紫色野花
  光线: 金色光斑 + 树荫绿
  氛围: 神秘、温柔
  环境音: 鸟鸣，风吹树叶

[角色]
- 少女: 16岁，165cm 纤瘦，棕色长发，绿色猎人装。温柔关怀蹲在独角兽头部旁。
- 独角兽: 神话兽形，170cm，银白皮毛，金色螺旋角，前腿有蹄，背部受伤。放松接受趴卧草地伸出舌头。

[音乐]
风格: 竖琴 + 长笛
节奏: 60 BPM
情绪: 温柔

[正文]
[环境与人物初始状态]
少女蹲在独角兽头部旁，身体前倾。
双手合拢捧着一捧清水，弯腰靠近独角兽嘴边。
独角兽趴卧在草地，呼吸平稳。
少女视线: 看向独角兽。
独角兽视线: 看向清水。
[人物间关系]: 少女俯身靠近，独角兽仰头朝向少女，鼻尖相距约一掌。

[对话]
少女（轻声、温柔）: 喝点水吧。

[动作序列]
1. 少女双手缓缓倾斜，清水从指缝流出。（水声）
2. 清水缓缓流到独角兽嘴边。（滴落声）
3. 独角兽伸出舌头，轻舔清水。（舔水声）
4. 少女左手轻抚独角兽银白鬃毛。（毛发摩擦声）
5. 独角兽眼中恐惧渐退，安静下来。

[镜头提示]
- 镜头 1: 中景，侧面，缓推 → 动作 1, 2（聚焦少女捧水靠近）
- 镜头 2: 特写，俯视，静态 → 动作 2, 3（聚焦清水流入独角兽嘴边）
- 镜头 3: 中景，正面，缓推 → 动作 4, 5（聚焦少女抚摸独角兽）
```
