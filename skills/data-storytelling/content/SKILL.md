# Data Storytelling 技能

将原始数据转化为有说服力、可行动的叙事，让受众在 3 分钟内理解核心洞察并做出决策。

## 核心原则（5 条金律）

1. **功能决定形式** — 先想清楚要传达什么，再选择怎么呈现
2. **简洁是最高级的复杂** — 每消除一个视觉元素，都在为认知减负
3. **受众不是你自己** — 用受众的语言和关切点构建叙事
4. **没有行动的洞察是噪音** — 每个数据故事必须以明确的 Call to Action 结尾
5. **故事需要被检验** — 用四重逻辑检验确保叙事自洽

## 执行流程：REACT 框架

### R - Receive (接收)

明确以下要素：
- **Who**: 受众是谁？他们的角色、痛点、决策权限是什么？
- **What**: 希望受众知道什么或做什么？
- **How**: 用什么数据支撑这个目标？

使用 `受众-目标-数据三角检查单` 进行验证。

### E - Explore (探索)

进行探索性分析，清洗数据，发现关键洞察和异常。

**注意**：永远不要把探索过程直接展示给决策层——探索是"后台工作"，解释性呈现才是"前台交付"。

### A - Architect (架构)

**1. 提炼 Big Idea**

整个数据故事必须能浓缩为一句话：
```
[结论]，因为 [数据证据]，因此建议 [行动]
```

**2. 选择叙事路径**

| 路径 | 适用场景 | 结构 |
|------|----------|------|
| 时间顺序法 | 建立可信度、方法论重要、受众需理解推理过程 | 问题 → 证据收集 → 发现 → 结论 |
| 行动优先法 | 与受众已有信任关系、时间有限、关注结果 | 推荐行动 → 数据支撑 → 执行方案 |

**3. 构建三幕式结构**

使用 `三幕式故事板` 模板，先写标题后做图表。

### C - Craft (制作)

**1. 图表选择**

根据要展示的信息类型选择图表：

| 信息类型 | 推荐图表 |
|----------|----------|
| 单一数值强调 | 简单文本（直接写数字） |
| 类别比较 | 条形图（水平/垂直） |
| 时间趋势 | 折线图 |
| 变量关系 | 散点图 |
| 前后变化 | 斜率图 |
| 密度/强度 | 热力图 |
| 部分-整体 | 堆叠条形图（避免饼图） |

**2. 视觉降噪**

消除一切不服务于核心信息的视觉元素：
- 移除多余网格线
- 移除/弱化图表边框
- 移除不必要的背景色/渐变
- 移除 3D 效果/阴影装饰
- 确保图例靠近数据

**3. 前注意属性引导注意力**

| 属性 | 应用场景 |
|------|----------|
| 颜色 | 高亮关键数据点，用对比色标记异常 |
| 大小 | 放大核心指标，缩小辅助信息 |
| 位置 | 将最重要的图表放在视觉中心（通常左上或中心） |
| 形状 | 用不同形状区分数据类别 |

**4. 4A 设计原则**

| 原则 | 含义 | 检验问题 |
|------|------|----------|
| Affordances | 设计要暗示其用途 | 受众能否在 3 秒内理解这个图表在展示什么？ |
| Accessibility | 色盲友好、对比度足够、文字可读 | 黑白打印后是否依然清晰？ |
| Aesthetics | 专业、整洁、有品牌感 | 这个图表你愿意放在 CEO 面前吗？ |
| Acceptance | 符合组织文化和受众预期 | 受众是否信任这个数据呈现方式？ |

### T - Test (检验)

使用 `四重逻辑检验表` 进行校验：

1. **水平逻辑**：只看每页标题，是否能串成完整、连贯的故事？
2. **垂直逻辑**：单页内所有内容（图表、注释、数据）是否都在强化该页标题？
3. **反向故事板**：给每页写下核心要点，然后打乱顺序重新排列，验证结构是否依然成立
4. **新鲜视角**：让不熟悉材料的人审阅，发现"专家盲区"

## 典型应用场景

### 场景 A：HR 薪酬结构分析报告

**叙事路径**：行动优先法

**Big Idea**：建议将研发序列薪酬带宽上调 15%，因为市场对标显示当前 P50 分位已落后行业 20%，若不调整预计 Q3 核心人才流失率将升至 18%。

| 幕次 | 标题 | 图表 |
|------|------|------|
| 第一幕 | 研发序列面临薪酬竞争力危机 | 市场对标散点图（当前 vs 行业 P50/P75） |
| 第二幕 | 带宽不足导致高潜人才流失加速 | 离职人员薪酬分位分布 + 流失成本测算 |
| 第二幕 | 上调 15% 带宽可在 18 个月内实现正向 ROI | 投资回报率折线图 |
| 第三幕 | 建议分三阶段执行，Q2 启动试点 | 执行路径图 |
| 第三幕 | **Call to Action** | 批准 Q2 试点预算，指定试点部门 |

### 场景 B：产品功能渗透率复盘

**叙事路径**：时间顺序法

**Big Idea**：排班日历功能渗透率仅 12% 的核心瓶颈在于入口过深 + 缺乏场景化引导，建议重构入口路径并增加智能推荐。

| 幕次 | 标题 | 图表 |
|------|------|------|
| 第一幕 | 排班日历上线 6 个月，渗透率远低于预期 | 功能使用漏斗图 |
| 第二幕 | 用户调研揭示两大核心障碍 | 用户反馈词云 + 入口点击热力图 |
| 第二幕 | 竞品同类功能渗透率已达 35% | 竞品功能对比条形图 |
| 第三幕 | 建议重构入口并增加 AI 智能推荐 | 原型设计图 |
| 第三幕 | **Call to Action** | 批准 Q3 产品迭代排期 |

## 视觉陷阱清单（绝对避免）

| 陷阱 | 问题 | 替代方案 |
|------|------|----------|
| 饼图 | 人眼不擅长判断角度和面积差异 | 条形图或堆叠条形图 |
| 3D 图表 | 扭曲数据比例，增加认知负荷 | 2D 平面图 |
| 双 Y 轴 | 容易误导关联性判断 | 拆分为两个独立图表 |
| 无意义装饰 | 分散注意力，降低信噪比 | 极简主义，数据墨水最大化 |

## 使用限制

- 本技能适用于解释性分析场景，不适用于原始数据探索阶段
- 当数据质量不足（缺失率高、样本量小、来源不可靠）时，应先解决数据问题，再谈叙事
- 叙事不能替代逻辑严谨性——故事必须建立在真实、完整的数据基础之上
