# 信息化项目可研及估算自动化评审

## 用途

对南网信息化项目的**可研报告**（docx）与**可研估算书**（xls/xlsx）进行自动化评审，识别送审稿中的常见问题并按统一格式输出评审意见文档。本 skill 聚焦"评审前期"——识别问题清单（送审前），与 `feasibility-review-report` skill（评审后生成正式评审意见报告）配合使用。

## 触发场景

- 用户说"评审一下这份可研报告/估算书"、"出可研评审意见清单"、"送审前问题识别"
- 用户提供了可研报告 docx + 可研估算书 xls/xlsx，希望自动发现"漏写、错写、前后不一致、五点法计列不合理"等问题
- 用户提到"南网信息化项目评审"、"软件造价五点法"、"集成工作量计列"、"表三附1"、"表三附2"

## 输入文件（2 个必需）

| 编号 | 文件 | 用途 |
|---|---|---|
| 1 | 可研报告 docx（部分项目为"工单方案"docx） | 评审：文本规范、逻辑一致性、建设内容合理性、投资估算一致性、风险效益一致性 |
| 2 | 可研估算书 xls/xlsx **或 PDF（概算书）** | 评审：计算公式合规性、表格关联性、五点法计列合理性 |

> 实际送审资料中**估算书经常是 PDF（文件名含"概算书"）**，而非 xls/xlsx。此时不要调用
> `audit_run.py`（它按 xls/xlsx 结构解析），改走 `scripts/parse_estimate_pdf.py`（见下文"变体"）。

## 输出

**一份 Word 评审意见文档**（`<项目名>可行性研究报告评审意见.docx`），结构：

```
<项目名>可行性研究报告评审意见
1、可研报告"X.X.X" <章节>：<问题>。建议核实/建议修改。
2、可研估算书 表X(XXX) 序号N：<问题>。建议核实/建议修改。
3、...
```

每条意见 3 段式：**问题位置**（报告章节 / 估算书 sheet+序号）+ **具体问题**（含可佐证的关键字）+ **处置建议**（建议核实 / 建议修改）。

## 执行流程

### 第 1 步：定位输入文件

向用户索取或识别两个输入：
- 可研报告（docx，文件名通常含"可行性研究报告"）
- 可研估算书（xls/xlsx，文件名通常含"可行性研究投资估算书"）

如果只有一个文件（如"工单方案"），先告诉用户本 skill 需要两份材料。

### 第 2 步：运行评审脚本

执行 `scripts/audit_run.py`，自动解析两份输入文件并产出问题清单 JSON + Markdown：

```bash
python scripts/audit_run.py \
  "<可研报告.docx>" "<可研估算书.xls>" "<输出目录>"
```

依赖：`pandas`、`xlrd`（读 .xls）、`openpyxl`（读 .xlsx）、`python-docx`、`pymupdf`（读 PDF 概算书）。
若缺依赖先安装：`pip install pandas xlrd openpyxl python-docx pymupdf`。

> **换机/共享提示**：脚本内不写死解释器路径。本机默认使用 `~/.workbuddy/binaries/python/envs/default/Scripts/python.exe`；
> 若该路径不存在（例如同事的机器），改用当前环境可用的 `python` / `python3` 即可。
> `pandas` 读 `.xls` 需 `xlrd`、读 `.xlsx` 需 `openpyxl`，两者都装才稳。

脚本会自动：
1. 解析可研报告 → 抽取章节结构、关键需求、应用交互、风险效益段落
2. 解析可研估算书 → 抽取封面、表一/二/三、表三附1/2、计算参数表
3. 跑完 17 类自动检查（详见 `references/audit_checklist.md`），生成结构化问题列表
4. 写出 `audit_results.json` 与 `审计清单.md`

### 第 3 步：人工补充 + 修正

自动化检查能识别**确定性模式**的问题（如 ILF/EIF/EO 重复、功能描述重复、调整因子不一致、新增功能零功能点、跨表金额不一致），但需要大模型逐条理解上下文的问题必须在此时补充。**尤其估算书五点法评审**，必须由大模型逐条读表三附1 的功能描述做语义判断：

读取 `审计清单.md`，对每条问题确认：
- **位置是否准确**（章节号、sheet 名、序号）—— 不准确就修正
- **建议用"核实"还是"修改"**：
  - **建议核实** = 可疑但需作者进一步确认（如描述含糊、与多份资料口径冲突）
  - **建议修改** = 明显违反标准/南网规定/前后矛盾
- 补充大模型识别的额外问题（错别字、语病、跨项目残留、无关域建设内容等）

**五点法深度评审要点**（见 `references/five_point_method.md`）：
1. 逐条读表三附1 各功能子项的"功能描述"，判断 ILF/EIF/EI/EO/EQ 计列是否合理——哪些功能只是展示/查询（应计 EQ/EO），哪些真正维护数据（应计 ILF+EI）
2. 核查功能描述是否存在高度重复（属性列表几乎一样却分别计列独立 ILF）
3. 核查 ILF/EIF 名称是否存在重复计取（同一名称多行均按新增计列）
4. 核查计算参数表、功能点调整因子是否取值正确、是否一致

### 第 4 步：生成评审意见 docx

执行 `scripts/build_report.py`，把最终问题列表渲染成评审意见 docx：

```bash
# 注意参数顺序：json 在前，项目名在后（argv[1]=json, argv[2]=项目名, argv[3]=输出docx）
python scripts/build_report.py \
  "<含问题列表的 json>" "<项目名>" "<输出.docx>"
```

JSON 格式：
```json
{
  "项目名": "深圳供电局有限公司电网管理平台（…）建设项目",
  "可研报告文件名": "...",
  "可研估算书文件名": "...",
  "意见列表": [
    {
      "序号": "1",
      "来源": "可研报告",
      "位置": "2.2.4 非功能需求-系统特性",
      "问题": "系统特性表描述与项目范围不一致，'PC和移动双端需要支撑全南网30万员工的高并发业务请求场景'与1.4应用范围（6000人）冲突",
      "建议": "建议核实"
    },
    {
      "序号": "2",
      "来源": "可研估算书",
      "位置": "表三附1甲 序号11",
      "问题": "'获取主题党日记录信息'不涉及内部逻辑文件变化，不应计列外部输入（EI）",
      "建议": "建议修改"
    }
  ]
}
```

### 第 5 步：交付评审意见

向用户展示生成的 docx，并附带简明摘要：
- 共发现 N 条问题，其中"建议核实" X 条、"建议修改" Y 条
- 主要问题分类（可研报告/估算书）
- 提示人工复核

## 自动化检查覆盖范围

详见 `references/audit_checklist.md`。17 类核心检查：

**反算校验（第 18 类，PDF/xlsx 通用，见效最快）**：
- ①`功能点数 /(1.39×通用度因子)` 反算 UFP，与"新增数×复杂度(10/7/4/5/4)"或"更改数×调节系数×复杂度"比对，识别**要素计列与计算口径不符**的行（典型：建设类型写"新增功能"却按"更改数×0.4"计列，导致规模低估）；
- ②`开发(集成)工作量 ÷ 功能点法预算工作量` 反算系数（开发类应≈0.7＝9/10×7/9；集成类≈0.35＝0.7×0.5），据此识别**集成工作量调整系数**取值是否与部署方式匹配（全网统一部署 0.75 / 分级部署 1 / 省市自建 0.5）；
- ③新增行的"调节系数"列是否被预填为修改类默认值（ILF 0.4、EIF 0.5、EI/EO/EQ 0.4）——填表说明要求新增类取 1，填报与计算口径不一致；
- ④逐行校验 `功能点数×耗时率/8 = 功能点法预算工作量`；
- ⑤"总计"行与分项累加比对（功能点数、功能点法预算工作量、开发(集成)工作量三列分别核）。

**可研报告侧**：
- 1. 项目范围一致性（章节间"应用范围/用户规模"数字是否前后一致）
- 2. 非功能需求逻辑矛盾（如 99.9% 可用性与 < 3 小时停机时间是否匹配）
- 3. 应用交互需求与功能需求对应（功能需求提到的外部系统是否在应用交互列出）
- 4. 建设内容与项目域相关性（是否存在与项目域无关的内容；跨域监测平台自动跳过）
- 5. 投资估算章节与估算书一致性
- 6. 风险与效益章节与建设内容相关性
- 7. 旧项目模板残留识别（如出现与本项目无关的关键词）

**可研估算书侧**：
- 8. 整体计算公式合规性（与南网标准《预算编制与计算方法 2024 修订版》是否一致）
- 9. 表三附1（开发/集成工作量）与表三项目分项表一致性
- 10. 表三项目分项表实施工作量与表三附2一致性
- 11. 表三附1五点法计列合理性（ILF/EIF/EI/EO/EQ 是否合理）
- 12. 计算参数表与可研报告一致性（部署方式、用户规模、项目类型等）
- 13. 跨表金额合理性（如分项金额与汇总、资本性/成本性比例）
- 14. 表三附1 ILF/EIF/EO 名称重复计取
- 15. 表三附1 功能描述高度重复（属性列表相似度比对）
- 16. 新增/集成功能功能点数=0 + 展示类主题模块误计 ILF
- 17. 功能点调整因子（VAF）一致性

## 注意事项

- **不要照抄**示例项目的问题清单到新项目——每个项目的范围、域、功能都不同，必须基于真实数据。
- **"建议核实" vs "建议修改"** 的分界要谨慎：只有当问题明显违反南网标准/前后文白纸黑字矛盾时才用"修改"。
- **五点法评审必须先理解功能描述**：表三附1 的 ILF/EIF/EI/EO/EQ 计列是否合理，取决于功能描述语义（本系统是否维护数据、是否跨系统、是否纯展示），不能只看关键词。脚本只做确定性检查（去重/一致/零功能点），语义判断由大模型在第 3 步完成。
- **域相关性/模板残留检查**对跨域监测平台（运监/全景/驾驶舱/大屏类）自动跳过——这类项目监测财务、营销、基建等多业务域属正常，不是模板残留。
- 项目名称应使用**正式名称**（去除"工单方案"后缀按需追加），并保留括号内的特殊字符（如""）。
- 中文字符路径需用引号包起来；脚本已使用 `pandas`/`xlrd` 自动处理。
- 如可研报告含目录（toc 样式），脚本会自动跳过目录行。
- 估算书 sheet 命名可能因版本微调（如"表三附1甲"vs"表三附1"），脚本会模糊匹配前缀。

## 变体：可研估算书为 PDF（概算书）时

云南评审等项目中，送审资料常为 `…概算书.pdf`（含表一~表五 + 表三附1 + 表三附2）。
此时**不要**调用 `audit_run.py`（按 xls/xlsx 结构解析会失败），改走 `scripts/parse_estimate_pdf.py`：

```bash
python scripts/parse_estimate_pdf.py "<概算书.pdf>" "<输出目录>"
# 依赖 pymupdf；输出 pdf_tables.json / t3_rows.json / pdf_check.txt
```

- PDF 版表三附1 为 **33 列**（c0~c32），列映射见 `references/five_point_method.md` 第 2 节"PDF 版列结构"——
  与 35 列 xlsx 版的差异在于：`建设类型`（c7）之后直接是 `内部逻辑文件清单`（c8），
  五要素各占 4 列（清单/更改数/调节系数/新增数）。
- 用 `page.find_tables()` 按坐标抽取，**不要**用 `page.get_text()` 行文本硬切列——PDF 文本流会打乱列序。
- 表三附1 的"应用交互/系统集成"行存在合并单元格（组名、一级模块只在首行），
  续行 `应用组名称` 为空属正常，不要判为填报缺失。
- 脚本已内置第 18 类反算校验（见上），可直接`t3_rows.json` 做逐条语义评审。
- 顺带核查：`表一/表五` 资本性与费用性划分及分年度、`表四` 其他费用列项是否有计算式但无金额
  （常见漏项：基本预备费 5%、项目管理费 2%、技术服务费、等保测评费）、`表三` 分项序号是否跳号、
  `表三附2` 是否缺"项目管理工作（P01/P02/P03）"任务域、"系统集成调试"说明中的逻辑文件数与表三附1
  计列的 EIF 数是否一致。

## 变体：只给"功能点法开发工作量测算"单表时

用户有时只提供一张"功能点法开发工作量测算"表（单个 sheet，表头形如
`序号|应用组名称|一级应用模块|二级应用模块|功能项|功能子项|功能描述|内部逻辑文件清单|外部接口文件清单|操作项（EI）|操作项（EO）|操作项（EQ）`，
**没有**建设类型/数量/复杂度/VAF/耗时率/功能点数/工作量等列）。此时：

1. 不要调用 `audit_run.py`（它按完整估算书结构解析，会失败或空转）。
2. 直接用 pandas/openpyxl 读单表，逐行抽出 `功能描述 + ILF/EIF/EI/EO/EQ` 五个要素名称，拼成可读文本后**由大模型逐条语义评审**。
3. 首条意见应先说明"该表未列功能点数与工作量列，无法核验金额计算过程"，再列五点法要素计列问题。
4. 若同时给了文件名含"功能重构"但表内无建设类型列，需提示"重构部分工作量是否计列无法判断"。

### 单表变体追加的确定性检查（脚本化，见效快）

在 `five_point_method.md` 六类问题之外，对这 12 列表再跑以下模式检查：

| 检查 | 规则 | 输出 |
|---|---|---|
| 引用规则违反 | 该行有 EI/EO/EQ 但 ILF 与 EIF 均空 | 列序号+子项名，通常几十条，归并为 1 条意见 |
| 纯查询无来源 | 该行仅 EQ，ILF/EIF/EI/EO 全空 | 列序号，提示应标注共用 ILF |
| 全空行 | 五项要素全空 | 多为"扩展功能预留"占位行，提示不应计列工作量 |
| 描述高度重复 | `difflib.SequenceMatcher(None,a,b).ratio() >= 0.72` | 输出相似度+两序号，≥0.9 时基本可判定重复功能 |
| ILF/EIF/EI/EO/EQ 名称重复 | 同名在 ≥2 行出现 | 注意区分"共享去重"（仅计一次）与"重复计取" |
| 提醒/推送类缺 EO | 描述含"提醒/推送"，但该行无 EO | 提醒推送本质是 EO，漏计输出类工作量 |
| 分类口径跨行矛盾 | 同一"功能分类/属性分类"在多行给出不同枚举 | 前后矛盾，建议统一 |

> 阈值经验：`ratio>=0.72` 对本类文本有效；`>=0.90` 可判重复功能。

## 变体：可研报告为"工单方案"（docx）、估算书为 xls 的云南类项目

云南评审项目常见形态：可研报告实为 **`…工单方案YYYYMMDD.docx`**（章节号与标准可研不同），
估算书为 **`…概算书YYYYMMDD.xls`**（同时附 PDF）。此时仍可调用 `audit_run.py`，但需注意：

1. **章节号不同**：工单方案的"应用交互"在 **4.3.3**（不是 2.2.3），"非功能需求"在 2.2.3，
   "投资估算"在 **7**（不是 4），"效益分析"在 8、"风险"在 9、"结论"在 11。
   写意见"位置"时务必按实际章节号核对，不要沿用标准可研的编号。
2. **表三附1 为 36 列**（比 35 列 xlsx 版多一列末位"建设内容"标签，如"前台功能新增与优化/后台管理模块/各智能体优化/数据采集"），
   列映射与 `five_point_method.md` 第 2.C 节一致，末列 C35 为建设内容分组标签，可作为**表三分项明细应按建设内容分列**的依据。
3. 必须**逐行反算**：`功能点数 ÷ (规模变更因子 × VAF × 通用度因子)` 反推 UFP，
   与 `新增数×复杂度` / `更改数×调节系数×复杂度` 比对。实测一套表可据此确认"调节系数列虽被预填 0.4/0.5，实际计算仍按新增类取 1"。
4. 必查的**填报口径一致性**（本项目实测命中率极高）：
   - 计算参数表"变更阶段"（决策/设计）与"规模变更因子"取值是否匹配（可研 2.0 或 1.85 / 概设 1.5 或 1.39）；
   - "功能点耗时率"取值是 2020 版（13.4/9.1/24.8/3）还是 2024 版（10.16/6.90/18.80/2.27），与所引标准版本是否一致；
   - 通用度因子 0.6/0.8/1.0 与功能性质（跨行业通用 / 电力专有 / 全新开发）是否匹配；
   - 全表耗时率是否**未区分集成/接口类**（数据采集、调用外部分析软件等应取应用集成类）。
5. 必查的**其他费用漏项**：表四常"保留条目名称+编制依据"但"合计"列为空。

   - 同一文件在"项目背景/项目依据"处出现两个不同文号（如国能发科技〔2025〕73号 vs 75号）；

### 本版必查的关键公式（已实测验证，可直接用于反算）

```
功能点数        = UFP × 功能点调整因子(VAF) × 规模变更因子 × 通用度因子
功能点法预算工作量 = 功能点数 × 耗时率 / 8
开发(集成)工作量  = 功能点法预算工作量 × 开发工作量系数(0.7)      # 0.7 = 9/10 × 7/9
集成类          = 功能点法预算工作量 × 0.7 × 集成工作量调整系数   # 省市自建 0.5 → 0.35
```
- UFP 按要素复杂度：ILF 中10/高15、EIF 中7/高10、EI 中4/高6、EO 中5/高7、EQ 中4/高6；**按「新增数×复杂度」或「更改数×调节系数×复杂度」**。
- 反算示例（实测序号1）：ILF新增1＋EI新增1＋EQ新增1 → UFP=10+4+4=18；
  `18 × 1.32 × 1.39 × 0.8 = 26.42112`（=表内功能点数）；`26.42112×10.16/8 = 33.55`；`33.55×0.7 = 23.49` ✓ 三列全部对上。
- 于是 `bud ÷ 0.7 ≠ dev` 的行即为**集成类**（比值 0.35），应核实是否确属系统间接口。

## 变体：货物采购类项目（安全设备采购 / 软硬件购置）——"设备数量前后一致性"专项

可研报告是**标准可研结构**（2.x 各单位需求分析、3.1.x 各单位建设方案、4 投资），但项目性质是
**设备采购**（建设费=0、无开发费/集成费/五点法、表三附1/附2 为空模板、全部为购置费且 100% 资本性），
典型如"云南电网公司2027年安全设备采购"（18 个建设单位）。此时评审重点不是五点法，而是
**同一设备在"报告需求分析表 ↔ 报告建设方案表 ↔ 估算书表三 ↔ 估算书表六"四处的名称/单位/数量是否一致**。

直接跑本 skill 的专项脚本：

```bash
python scripts/check_quantity_consistency.py "<可研报告.docx>" "<可研估算书.xls>" "<输出目录>"
```

脚本输出 A~H 八段报告（同时写 `<输出目录>/quantity_check.txt`）：

| 段 | 内容 |
|---|---|
| A | 各单位 需求分析表 / 建设方案表 行数与数量合计（**行数或合计不一致即高风险**） |
| B | 报告内部 需求分析表 vs 建设方案表 逐项比对（仅需求分析表有 / 仅建设方案表有 / 单位数量不符 / 名称近近似提示） |
| C | 估算书表三 各单位"（一）硬件+（二）软件"小计 vs 明细累加 vs 单位行合计 |
| D | 估算书表六 同上 |
| E | 表二 / 表三 / 表六 三方逐单位金额比对 |
| F | 表一单位数、资本性合计、其他费用合计 vs 表四(一)合计 |
| G | 表三/表六 明细中"单位"列为空的行（易漏填） |
| H | 表六/表三 表格列之后的**越界残留内容**（比价数字、重复说明文字等） |

### 表识别规则（脚本已内置，改版报告需先核对）

- 需求分析表：表头同时含 **「设备名称」+「建设类型」**（仅含"设备名称"会把"现状授权到期明细表"误判进来）；
- 建设方案表：表头含 **「采购内容」且含「设备参数」或「部署地点」**（仅含"采购内容"会把"现状详细清单表"误判进来）；
- 单位归属：取**最近一个名称形似建设单位的 Heading2 或 Heading3** —— 因为有的报告是
  `H2=单位名 / H3=需求分析`，有的报告是 `H2=建设方案 / H3=单位名`，只认 Heading2 会全部错配。

### 本项目实测的高频缺陷模式（同类项目务必逐条核）

1. **整表复制粘贴**：某单位的建设方案表内容与另一单位**逐行完全相同**，连"部署地点"列都写着对方单位名
   （实测：德宏供电局建设方案表＝保山供电局表的原样复制，6 项设备全错，与本单位需求分析表、估算书表三/表六均不符）。
   识别技巧：先比各单位表的**行数**，行数相同的再逐行比"采购内容+数量+部署地点"，一眼可辨。
2. **估算书表六小计漏项**：某单位"（一）硬件设备购置"小计填 0，明细却有金额（实测：文山供电局漏计"基线核查设备"282,582 元）。
   C/D 两段脚本自动比对即可命中。
3. **单位量词不一致**："台 / 套 / 套（授权）"在不同表之间串用（实测：人才发展中心建设方案表写"台"，其余三处写"套"）。
4. **越界残留单元格**：表六右侧第 9 列及以后残留比价数字、重复的设备名称与规格说明。
5. **辅助工作表未随汇总更新**：多单位汇总版估算书的"投资汇总表"仍只有单单位 1 行，且"结算编审费"取了**全项目**合计。
6. **其他费用仅计 1 项**：表四只填"结算编审费"，而"计算参数表（其他费用）"已算出招标费/监理费/软硬件监造费/
   文件评审费/等保测评费/风险评估费；设备保险费（购置费×1%）、基本预备费（×5%）也常整体漏计 → 列为**建议核实**。
7. **建设周期口径**：报告实施计划写"共 16 个月"，估算书"建设周期T（月）"却取"一年内"，影响监理费等挂钩取费。
8. **法规/标准时效**：报告"项目依据"不注版本的法律需联网核实是否已修正
   （实测：《中华人民共和国网络安全法》已由 2025-10-28 十四届全国人大常委会第十八次会议修正，主席令第六十一号，2026-01-01 施行）。


## 变体：多单位"子估算书 ↔ 整体汇总估算书"核对

**触发**：用户一次性给出 N 本**各单位子估算书**（xls，每本 1 个单位）+（或只要）整体**汇总估算书**，
或给若干单位"单局可研报告 PDF"，要求核对"子估算书的设备数量能不能和整体对得上"。

**路由**：跨文件比对属**数据依赖型**表格任务 → **必须走 `tencent-docs-sheetagent`**，
把汇总表 + 全部子书路径、用户原话、当前时间、期望返回一次性交给 `sheet-agent` 子代理；
不要自己先读再委派。单局报告是 PDF 时，用 PyMuPDF（`import fitz`）抽文本，
按 `2.x 需求分析表` / `3.1.x 建设方案表` 逐项读"单位/数量"（PDF 无表格结构，文本逐行可靠）。

**必查 8 层**（脚本 `scripts/check_subbook_vs_master.py` 已覆盖 A~G 七段）：

| 层 | 内容 |
|---|---|
| 1 | 表三 / 表六 逐项：名称、单位、**数量**、单价、金额 |
| 2 | 表一（项目估算汇总表）：资本性、购置费、其他费用、合计（万元） |
| 3 | 表二、表五（分阶段）、投资汇总表 |
| 4 | 表四其他费用构成 + "计算参数表（其他费用）"已算但未计列的费用项 |
| 5 | 子书**内部自洽**：表三小计↔明细↔表二↔表一↔投资汇总表是否一条链 |
| 6 | 汇总书表六"小计/单位合计"↔明细（多单位汇总表最容易在这层漏计） |
| 7 | **性能参数**：表六"规格型号"列 ↔ 报告"需求分析表/设备参数"列 ↔ 报告"建设方案表/设备参数"列，**逐字比对**（归一化空白与换行后比较；另比对字符长度，长度不同必有问题） |
| 8 | **价格合理性**：① 单价 ↔ "询价结果"表三/五家报价算术平均值；② 把汇总书表六全部明细按【名称+规格型号】归并，检查跨单位同规格是否同价 |

**两种表版式都要认**（同一项目内不同单位报的本子可能不一样，脚本已兼容）：
- 版式①：`一|大理供电局` → `（一）硬件设备购置` → `1|设备名…`（汇总本、大理本）
- 版式②：`一|建设费` → `(一)开发费` → `二|购置费` → `(一)硬件设备购置` → `1|设备名…`（昆明、楚雄、文山、电科院本）
- 判别方法：看"中文序号"后面跟的是**单位名**还是**费用类别**；括号 `(一)`/`（一）` 要归一。
- 版式②的表三还带"硬件运维费/软件运维费/基础环境运维费/IT服务运维费"4 行模板占位（单价与金额均空），
  **必须按"单价与金额同时为空/0"过滤掉**，否则会被误报成"子书有/汇总无"。
- 表六也可能整表没有任何中文序号块（昆明本直接从"（一）硬件设备购置"开始），需有"整表归入单单位"的兜底。

**实测缺陷模式（同类项目逐条核）**：

1. **同一项软件授权"名称+单价"两种口径并存**——最隐蔽，数量一致但金额差。
   实测：云南电科院子书为"入侵防御系统**特征库**授权（启明星辰）4 套 × 25,896 = 103,584 元"，
   汇总书为"入侵防御系统**规则库**授权（启明星辰）4 套 × 17,430 = 69,720 元"，差 **33,864 元**；
   且汇总书内"人才发展中心"用 25,896、"昭通供电局"用 17,430，两种口径同时存在 → 列为**建议核实**。
   检法：把全部单位同名牌号的授权项按"名称+单价"聚类，单价不唯一即报警。
2. **子书表六末行遗留无数据设备名**（实测：文山"奇安信网神新一代安全感知系统 TSS10000-GM-WS"，单位/数量/金额全空，不影响小计）。
3. **表三"单位"列空白**（实测：临沧"网络流量控制分析系统（APT）"）。
4. **跨单位同名称+同规格而单价不同**——把汇总书表六全部明细（本项目 175 行）按
   【名称+规格型号】完全相同的口径归并，只报"规格逐字相同但单价不同"的组合，报警极准。
   实测：**防火墙授权（启明星辰 USG-FW-18600-T-NF13600-YN）**，规格完全一致，
   红河供电局 1 套 × 38,604.96 元，而怒江 10 套、迪庆 6 套 × 25,896 元，**单价差 12,708.96 元/套（≈49%）**。
   同名不同价的其余组合（第一/第二档防火墙、数据库审计设备、APT、山石网科 IPS 等）
   经核对**规格型号均不同**（配置差异），属合理，不要误报——所以归并键必须带上规格。
5. **报告"项目现状"表混入当年新增设备**（实测：大理）。大理 2.5 节"项目现状"表列 9 项，
   但同节"与上年度项目差异分析"表把其中"积羽流量分析系统软件 1 年升级授权"与
   "高级持续性威胁（APT）监测设备"记为**2026 年 0、2027 年新增**；即新增设备被列入"现状"。
   按差异表口径现状应为 8 项/13 套，现状表实为 9 项/15 台·套 → 前后矛盾，**建议修改**。
   检法：拿"现状表行数/数量合计"与"差异分析表上年度列合计"对一遍。
6. **同一台设备"台/套"混用**（实测：大理 APT 设备，现状表与差异表写"1 台"，
   需求分析表/建设方案表/估算书表三表六写"1 套"）。
7. **单位覆盖不全要显式声明**：本项目 18 个建设单位，分批报送（先 11 个、后补大理；
   仍缺红河、德宏、怒江、迪庆、丽江、数智运营中心），报告中必须写明"已提供/未提供"清单，
   说明未提供的缺乏"子书"这一层交叉验证。
8. **体例提示（低优先级，但用户偏好文字类问题优先）**：报告"部署地点"列内
   "III区IDC"（拉丁字母 I）与"Ⅳ区IDC"（罗马数字 Ⅳ）**同一张表内混用**；
   型号列"积羽流量分析系统**系统** AF-NTA-7000"（"系统"重复）、"病 毒防护"（夹多余空格）。
   全项目还有"安全III区"（拉丁）与"生产域Ⅲ区"（罗马）混用数十处，建议统一为罗马数字。

**输出**：单独出《…各单位（子）估算书设备数量核对报告.docx》，**不要与《评审意见》合并**。建议结构：
核对对象与范围 → 核对结论 → 逐单位汇总结论表（明细项数/数量合计/子书合计/汇总合计/差额/结论）→
差异清单（每条含"建议修改/建议核实"）→ 投资口径核对表（表一三项逐单位）→ 其他核对发现 →
核对方法 → **附件：逐单位设备明细对照表**（逐项列出子书名称/单位/数量/单价/金额 + "汇总核对"列）。

**踩坑**：`sheet-agent` 回报的"某列为空/需倒推"类结论**必须与自己 pandas/xlrd 的直读交叉验证**。
实测出现过误判——子代理称汇总书表一"其他费用"整列为空、需用"合计−购置费"倒推，
而 xlrd 直读该列**全部有值**（且倒推值与直读值恰好相等，故结论数字仍可用，但"为空"的判断是错的）。

## 可研及估算自动化评审检查清单

本文档定义 `audit_run.py` 执行的 17 类自动检查的**触发条件、判断规则、典型反例**。大模型在补充人工识别的额外问题时也应参考本清单。

### 检查 1：项目范围一致性

**目标**：可研报告内"建设单位 / 应用范围 / 用户规模 / 部署方式"在多章节应前后一致。

**触发条件**：
- 在 1.4 项目范围、2.2.4 非功能需求（用户规模）、3.6.1 部署方式、计算参数表等多处出现"用户数 / 范围 / 部署"等关键词

**判断规则**：
- 提取 1.4 项目范围中的应用范围（"深圳供电局本部及下属单位"、"南网全网"、"广东电网公司本部及 21 地市"等）
- 提取 2.2.4 中最大用户数、最大并发用户数
- 若用户规模出现在多处但数字不同 → 提示核实
- 若应用范围提到"深圳供电局本部及下属单位"但系统特性/部署章节写"全网统一部署"且面向"30 万员工" → 提示核实

**典型反例**：
> §1.4 项目范围：深圳供电局本部及下属单位、用户 6000 人
> §2.2.4 系统特性：PC 和移动双端需要支撑全南网 30 万员工的高并发业务请求场景
> 评审建议：建议核实（与 1.4 应用范围、用户规模前后不一致）

### 检查 2：非功能需求逻辑矛盾

**目标**：可用性、性能、可靠性等指标不应自相矛盾。

**触发条件**：
- 在 2.2.4 非功能需求章节出现"可用率 / 停机时间 / 并发 / 用户数"等关键词

**判断规则**：
- "年可用率 99.9%"对应年停运上限 8.76 小时；若同时声明"系统年度非计划停运时长 < 3 小时"，< 8.76 小时说明实际可用率高于 99.9% → 提示核实
- "7×24 不间断"与"年度非计划停运 < 3 小时"通常不矛盾（< 8.76h），但若写"7×24 不间断运行"又同时声明"计划性停机"等需关注
- "CPU<80% 且内存<80%"若同时声明"CPU<65% 且内存<70%" 两者只能取其严

**典型反例**：
> §2.2.4.6 其他需求：可用性满足年可用率不低于 99.9%，系统年度非计划停运时长小于 3 小时
> 评审建议：建议核实（99.9% 对应 8.76h，< 3h 实际可用率更高）

### 检查 3：应用交互需求与功能需求对应

**目标**：功能需求中提到的外部数据来源应在 2.2.3 应用交互需求中列出。

**触发条件**：
- 功能需求章节提到"对接 X 系统"、"获取 X 数据"、"接入 X 平台"等关键词
- 2.2.3 应用交互需求章节列出对接系统清单

**判断规则**：
- 收集 2.2.2 / 3.2.2 应用功能中所有外部系统/数据来源（"南网 X 平台"、"小数叶"、"人资域"、"AI 平台"等）
- 收集 2.2.3 应用交互需求中实际列出的对接系统
- 求差集：功能需求中有但应用交互没有 → 提示核实

**典型反例**：
> §2.2.2 功能需求：智聚人心功能需对接南网心理咨询平台和心理测评工具
> §2.2.3 应用交互需求：仅列从人资域获取人员数据 + 对接"小数叶"专题
> 评审建议：建议核实（应用交互未覆盖功能需求提到的外部系统）

### 检查 4：建设内容与项目域相关性

**目标**：避免"跨项目模板拼接痕迹"——建设内容、功能列表中出现与本项目域无关的内容。

**触发条件**：
- 抽取 1.4 项目范围中的"业务域"（如"党建域"、"计财域"、"基建域"、"营销域"）
- 在 3.2 应用功能、3.3 数据架构、3.7 安全方案、7 项目可研结论等章节扫描关键词

**判断规则**：
- 域关键词集合（南网常用）：
    - 党建域：党组织、党员、团组织、党支部、党建驾驶舱、区岗队
    - 计财域：财务、预算、成本、资金、报销
    - 基建域：工程、项目管理、基建、进度、安全质量
    - 营销域：客户、电费、报装、用电、计量
    - 数字化域：数据治理、数据标准、AI 平台、大模型
  - 若项目域是党建域，章节中出现"计财域/营销域/营销风险防控/客户分群/电费回收/线损率"等明显跨域关键词 → 提示核实
  - 反之亦然

**典型反例**：
> 党建项目 §3.2 应用功能：企业经营业绩评价、一流企业指标、安风体系等级、五级及以上事件、违章作业比、第三方客户满意度、用电报装服务质量、百万客户投诉率、配电自动化应用率、10kV 线损率、当年电费回收率……
> 评审建议：建议核实（出现大量与党建域无关的经营/营销指标）

### 检查 5：投资估算章节与估算书一致性

**目标**：可研报告 §4 项目投资估算章节的总投资金额应与估算书表一合计一致。

**触发条件**：
- 可研报告 §4.2 总投资 出现具体数字（X.XX 万元 / 元）
- 估算书表一合计可读

**判断规则**：
- 从可研报告 §4.2 抽取总投资（注意单位"万元"vs"元"）
- 从估算书表一抽取合计（统一换算为元）
- 若数字差异 > 1% → 提示核实

### 检查 6：风险与效益章节与建设内容相关性

**目标**：风险与效益章节的论述应围绕本项目建设内容。

**触发条件**：
- §5 项目效益分析 / §6 项目风险分析 / §7 项目可研结论 出现关键词

**判断规则**：
- 抽取 §5/6/7 中关键词，扫描是否含与项目域无关的关键词（参考检查 4 域关键词）
- 抽取 §6 风险章节是否出现"财务月结"、"电力营商环境"、"可信能源数据空间"、"能源数据价值"等与党建/本项目无关的关键词
- 若出现 → 提示核实

**典型反例**：
> §7 项目可研结论：南方电网公司可信能源数据空间领域应用、优化电力营商环境、提升能源数据价值……
> §6.4 沟通的风险：财务月结等关键节点时间压力大
> 评审建议：建议核实（与本项目无关，属旧项目模板残留）

### 检查 7：旧项目模板残留识别

**目标**：识别"换项目不换文字"的模板残留。

**触发条件**：
- 整篇扫描以下关键词集合：
  - 强相关关键词（本项目）：从 §1.4 项目范围抽取的"应用范围"、"建设单位"、"业务域"关键词
  - 弱相关关键词（其他域）：从检查 4 域关键词集合中排除本项目域后的所有关键词

**判断规则**：
- 若弱相关关键词出现 ≥ 3 次且不在 §1.4 项目范围中 → 提示核实（可能模板残留）
- 若 §7 项目可研结论出现与本项目完全无关的关键词 → 提示核实

### 检查 8：整体计算公式合规性

**目标**：估算书计算公式应符合《南方电网公司信息化项目预算编制与计算方法（2024 年修订版）》。

**触发条件**：
- 估算书 §编制说明 含"费用划分和取费标准"、"计算公式"等说明
- 表三附1/表三附2 表头含计算字段（功能点、调节系数、耗时率、人天成本等）

**判断规则**：
- 计算公式参考：
  - **开发费** = 软件开发费 + 软件集成费
    - 软件开发费 = 功能点法预算工作量(不含集成) × 9/10 × 开发工作量系数 × 开发人员人天成本
    - 软件集成费 = 功能点法预算工作量(集成部分) × 9/10 × 集成工作量系数 × 集成工作量调整系数 × 开发人员人天成本
  - **实施费** = 实施工作量 × 实施人员人天成本 × 调节系数
  - **开发工作量系数**：技术支持平台 7/9、应用系统 7/9、数据分析类 5.5/9、移动应用类 7/9
  - **集成工作量系数**：7/9
  - **集成工作量调整系数**：全网统一部署=0.75、分级部署=1、各省市自建=0.5
- 若表三附1未按上述公式计算（如缺少 9/10 折算、调整系数错误） → 提示核实
- 若计算参数表"系统部署方式"为"全网统一部署"但集成工作量调整系数不是 0.75 → 提示核实

### 检查 9：表三附1 与表三项目分项表一致性

**目标**：表三项目分项表的开发人天合计 = 表三附1 的开发工作量合计。

**触发条件**：
- 表三"项目分项估算表"中有"开发费"明细项（如"功能开发/党员队伍建设/.../人天"）
- 表三附1 有"开发工作量（人天）"列

**判断规则**：
- 收集表三中"人天"列、"单价"列、"合计"列（= 人天 × 单价）
- 收集表三附1 中各功能项"开发工作量（人天）"
- 比较两类合计：差异 > 5% → 提示核实
- 比较各应用组（功能开发-党员队伍建设-...）级别的人天：差异 > 10% → 提示核实

### 检查 10：表三项目分项表实施工作量与表三附2 一致性

**目标**：表三的"实施费"明细人天 = 表三附2 工作量合计。

**触发条件**：
- 表三有"实施费"明细项
- 表三附2 有"工作量（人天）"列

**判断规则**：
- 收集表三附2 各任务域的合计（项目管理工作 P01+P02+P03、项目实施工作 T1+T2 等）

### 检查 11：表三附1 五点法计列合理性

**目标**：表三附1 的 ILF/EIF/EI/EO/EQ 计列应符合软件造价五点法。**评审必须逐条理解功能描述，再判断五要素计列是否合理**，而非只看关键词。

详细规则（列结构、公式、六类必查问题）见 `references/five_point_method.md`。

**五点法要素定义**：
- ILF（内部逻辑文件）：本系统内维护的数据集（增删改）
- EIF（外部接口文件）：被引用但不在本系统维护的数据集
- EI（外部输入）：维护 ILF 的数据来自外部 → 增/删/改
- EO（外部输出）：含计算逻辑的数据输出
- EQ（外部查询）：检索 ILF，不修改

**判断规则（典型反例）**：
1. 纯查询/列表展示/页面展示类 → 只应有 EQ，无 EI
2. 新增/修改/删除本系统数据 → EI + ILF
3. 导入/批量导入 → EI + ILF（模板下载是 EO）
4. 跨系统数据流转（从 X 系统获取数据）→ 计 EIF，不计 ILF/EI
5. 展示类"XX主题模块"（展示业务数据统计）→ 应计 EQ/EO，不应每个主题模块独立新增 ILF

**操作项计列模板**：
| 操作描述关键词 | ILF | EIF | EI | EO | EQ |
|---|---|---|---|---|---|
| 通过列表/详情页面构建 XX | ✓ | | | ✓ | ✓ |
| 新增/保存/修改/删除 XX | ✓ | | ✓ | | |
| 导入/批量导入 XX | ✓ | | ✓ | | ✓ |
| 流程流转/审核/退回 | ✓ | | ✓ | | ✓ |
| 从外部系统获取数据 | | ✓ | | | ✓ |

**建议核实/修改判定**：明显违反规则（纯查询计 EI、跨系统计 ILF）→ 建议修改；描述含糊不易判定 → 建议核实。

### 检查 12：计算参数表与可研报告一致性

**目标**：估算书计算参数表的关键参数应与可研报告对应章节一致。

**触发条件**：
- 计算参数表有"项目类型 / 系统类型 / 部署方式 / 用户规模 / 等保级别 / 行政区域"等参数
- 可研报告 §1.4 / 2.2.4 / 3.6 / 3.7 章节有对应描述

**判断规则**：
- 系统用户数量：可研报告 §2.2.4 vs 计算参数表
- 系统部署方式：可研报告 §3.6.1 vs 计算参数表（"全网统一部署 / 分级部署 / 各省市自建"）
- 系统等保级别：可研报告 §3.7.2 vs 计算参数表
- 建设性质：可研报告 §1 项目背景 vs 计算参数表（"新建 / 升级改造"）
- 行政区域：建设单位 vs 计算参数表
- 是否有互联网用户：可研报告 §3.5 安全架构 vs 计算参数表

**典型反例**：
> 计算参数表：系统部署方式 = 全网统一部署
> 可研报告 §1.4：本期面向深圳供电局本部及下属单位，实际用户约 6000 人
> 评审建议：建议核实（部署方式与实际范围不符）

### 检查 13：跨表金额合理性

**目标**：分项金额与汇总应一致，资本性/成本性比例应符合"信息系统建设与升级改造项目一般全额列为资本性"。

**触发条件**：
- 表一合计（万元）
- 表二开发费/实施费/咨询服务费（元，÷10000 转万元）
- 表三各分项金额（元）

**判断规则**：
- 表二开发费合计（元/10000）vs 表三开发费小计 ÷ 1万：差异 > 1% → 提示核实
- 表一资本性 + 成本性 = 合计：必须严格相等 → 若不等 → 提示核实
- 信息系统建设与升级改造项目：资本性应 ≥ 95%（允许少量咨询费/技术服务费列为成本性）；若成本性 > 5% → 提示核实
- 表三"实施费/咨询服务费"等成本性明细 vs 表一费用性：差异 > 5% → 提示核实

### 检查 14：表三附1 ILF/EIF/EO 名称重复计取

**目标**：同一 ILF/EIF 名称被多个功能子项重复按"新增"计列，属重复计费。

**判断规则**：
- 扫描表三附1 所有行的 C10（ILF清单）/C14（EIF清单）/C22（EO操作项）
- 同一名称出现多行，且这些行的"新增数/更改数"均 > 0 → 重复计取
- **关键区分**：多个子项共享同一 ILF、仅首行计新增（其余行新增数=空且功能点数=0）属**正常去重**，不算问题

**典型反例**：
- ILF"负荷情况主题模块配置信息"在序号 21、86 均按新增计列 → 重复
- EO"省级指标体系计算"在序号 157（省级）、158（地市）、159（县级）均计列，且 158/159 的 EO 名称与功能子项层级不符 → 复制粘贴错误 + 重复计费

### 检查 15：表三附1 功能描述高度重复

**目标**：两个功能子项功能描述几乎一样（属性列表高度重叠），却分别计列独立 ILF，属重复计费。

**判断规则**：提取"具有……等属性"的属性列表，计算两两相似度（交集/并集）≥ 60% → 提示。

**典型反例**：序号 73「负荷趋势主题模块」与序号 86「负荷情况主题模块」，属性均为「供电负荷、发电负荷、统调负荷、黔电送粤、计划值、实际值」（相似度 100%），却分别计列独立 ILF。

### 检查 16：新增/集成功能功能点数=0 + 展示类主题模块误计 ILF

**目标**：
- (a) 建设类型="新增功能"且为集成/应用交互类，但功能点数=0 → 疑似漏列集成工作量
- (b) 大量"XX主题模块"展示类功能重复计列 ILF → 应拆分为 EQ/EO 计列

**判断规则**：
- (a) 应用组含"交互/集成"或已列 EIF 名称，但功能点数=0、开发工作量=0 → 提示核实漏列
- (b) 功能描述匹配"新增XX主题模块，具有……属性，用户可新增/修改/删除并保存查询"，且同模式 ≥ 5 个 → 提示核实

**典型反例**：
- (a) 序号 160 应用组"应用交互"，已列 6 类 EIF 名称但功能点数=0
- (b) 某项目 99 个"XX主题模块"均按新增 ILF 计列

### 检查 17：功能点调整因子（VAF）一致性

**目标**："功能点调整因子取值说明"Sheet 计算的 VAF 与"计算参数表"取值应一致。

**判断规则**：
- 从取值说明 Sheet 读"影响调整因子（VAF）"计算值
- 从计算参数表读"功能点调整因子"取值

**典型反例**：取值说明 Sheet 算出 VAF=1.03，但计算参数表取 1.0，表三附1 也按 1.0 计算。

## 软件造价五点法详细说明（表三附1 深度评审）

> 本文档是评审可研估算书「表三附1(开发、集成工作量测算)」五点法计列合理性的核心依据。
> 评审时要**先理解每个功能子项的功能描述**，再判断 ILF/EIF/EI/EO/EQ 的计列是否合理，
> 并核查是否存在功能描述重复、ILF/EIF/EO 重复、调整因子不一致等计费问题。

### 1. 什么是五点法

"五点法"是国际标准 NESMA/IFPUG 功能点分析法（FPA）的 5 类功能点：

| 中文 | 英文缩写 | 全称 | 说明 |
|---|---|---|---|
| 内部逻辑文件 | ILF | Internal Logical File | 在本系统边界内被维护的数据集，可增删改 |
| 外部接口文件 | EIF | External Interface File | 在其他系统被维护、本系统仅引用的数据集 |
| 外部输入 | EI | External Input | 维护 ILF 的数据来自外部，触发增/删/改 |
| 外部输出 | EO | External Output | 呈现给用户的、含计算逻辑的数据 |
| 外部查询 | EQ | External Inquiry | 检索 ILF 内容，不修改 |

### 2.A PDF 版列结构（33 列，序号从 0 起）—— 概算书为 PDF 时用

### 2.B 反算校验（PDF/xlsx 通用，确定性、见效最快）

拿到逐行数据后先跑这 5 项反算，比纯文本比对命中率高得多：

```
① UFP 反算：UFP需 = 功能点数 ÷ (规模变更因子 × 通用度因子)
   规模变更因子：见到最多的是 1.39（部分版本为 1.85，需以项目所引版本为准，无参数表时写"建议核实"）
   通用度因子：常见 0.6（已有基础·跨行业通用）/ 0.8（已有基础·电力专有）/ 1.0（全新开发）
   对照值A（新增口径）= 10×ILF新增数 + 7×EIF新增数 + 4×EI新增数 + 5×EO新增数 + 4×EQ新增数
   对照值B（修改口径）= 10×ILF更改数 + 7×EIF更改数 + 4×EI更改数 + 5×EO更改数 + 4×EQ更改数
                       其中五要素复杂度"中"取值；"高/低"分别为 ILF15/7、EIF10/5、EI6/3、EO7/4、EQ6/3
   两者都对不上 → 该行要素计列与计算口径不符
② 工作量系数反算：开发(集成)工作量 ÷ 功能点法预算工作量
   开发类 ≈ 0.70（= 9/10 × 7/9）；集成类 ≈ 0.35（= 0.70 × 集成工作量调整系数 0.5）
   集成工作量调整系数：全网统一部署 0.75 / 分级部署 1 / 各省市自建其它系统 0.5
   → 若可研报告写"网级集中部署"却按 0.5 计，取值依据需说明
③ 调节系数列比对：新增行的"调节系数"若被预填成 0.4（ILF）/0.5（EIF）/0.4（EI/EO/EQ），
   与填表说明"新增类取值 1"不符 → 填报与计算口径不一致（真正计算时仍按 1 取，属填表不规范）
④ 逐行校验：功能点数 × 耗时率 ÷ 8 = 功能点法预算工作量（8 小时/人天）
⑤ 合计核对：总计行的"功能点数/功能点法预算工作量/开发(集成)工作量"分别与分项累加比对
   （常见现象：工作量合计吻合，功能点数合计差 0.1 左右 → 合计单元格取值与分项不一致）
```

| C6 | 功能描述 | **评审核心**，逐条理解 |
| C7 | 建设类型 | 新增功能 / 功能改进 |
| C10 | 内部逻辑文件清单 | ILF 名称 |
| C11/C12/C13 | ILF 更改数/调节系数/新增数 | **新增数>0 表示计列了该 ILF** |
| C14 | 外部接口文件清单 | EIF 名称 |
| C15/C16/C17 | EIF 更改数/调节系数/新增数 | 新增数>0 表示计列了该 EIF |
| C18/C19/C20/C21 | EI 操作项/更改数/调节系数/新增数 | |
| C22/C23/C24/C25 | EO 操作项/更改数/调节系数/新增数 | |
| C26/C27/C28/C29 | EQ 操作项/更改数/调节系数/新增数 | |
| C30 | 通用度因子 | 0.6/0.8/1.0 |
| C31 | 耗时率 | 10.16(应用/分析决策)、6.9(集成)、2.27(移动) |
| C32 | 功能点数 | = UFP × 规模变更因子 × VAF × 通用度因子 |
| C33 | 功能点法预算工作量(人天) | = 功能点数 × 耗时率 / 8 |
| C34 | 开发(集成)工作量(人天) | = 功能点法人天 × 9/10 × 开发工作量系数(7/9) |

**表头填表说明（重要约束）**：
- "内部逻辑文件清单中有重复内容，需要在模块间进行去重。" → 多个功能子项共享同一 ILF 时，仅计一次新增。
- "0≤功能点调节系数≤1，修改变更类文件 ILF 取值 0.4、EIF 取值 0.5、EI/EO/EQ 取值 0.4，新增类取值 1。"
- "功能点耗时率对应一级功能；五要素复杂度高中低对应不同一级功能。"

### 3. 五点法核心规则

1. **ILF 与 EI/EO/EQ 是配对关系**：一个 ILF 通常有对应的 EI（维护）、EO（呈现）、EQ（查询）。
2. **EI/EO/EQ 至少引用一个 ILF 或 EIF**。
3. **EIF 由其他系统维护**，本系统只引用 → 跨系统数据流转计 EIF，不计 ILF/EI。
4. **EI 强调增/删/改；EQ 强调查询检索；EO 强调计算/派生数据**。
5. **展示类/统计类功能**：只是展示电网运行、财务、设备、指标等业务数据，本质是统计展示，**不涉及 ILF 变化**，应计 EQ（查询）或 EO（复杂计算输出），而非每个主题模块独立新增 ILF。

### 4. 关键公式（用于验证功能点数计算）

```
UFP（未调整功能点） = ILF×复杂度 + EIF×复杂度 + EI×复杂度 + EO×复杂度 + EQ×复杂度
  其中复杂度默认：ILF=10、EIF=7、EI=4、EO=5、EQ=4（计算参数表"中"级别取值）

功能点数 = UFP × 规模变更因子 × 功能点调整因子(VAF) × 通用度因子
  规模变更因子：可研阶段默认 1.39（旧标准 2.0）
  功能点调整因子 VAF = (SUM of DI × 0.01) + 0.65，通常取值 1.0~1.05
  通用度因子：全新开发(电力专有)=1.0、已有基础(电力专有)=0.8、已有基础(跨行业通用)=0.6

功能点法预算工作量(人天) = 功能点数 × 耗时率 / 8
开发(集成)工作量(人天)   = 功能点法人天 × 9/10 × 开发工作量系数(7/9) = 功能点法人天 × 0.7
```

### 5. 六类必查计费问题（按优先级）

#### 5.1 ILF 名称重复计取

**判断**：同一 ILF 名称在多行出现，且这些行的"新增数"(C13) 均 > 0 → 重复计取。

**关键区分**（避免误报）：
- **正常去重**：多个功能子项共享同一 ILF，仅首行"新增数=1.0"，其余行"新增数=空"且功能点数=0。例："统计图表信息"被柱状图/折线图/饼图等 8 个图表共享，仅柱状图计新增，其余 7 个功能点数=0 → **正确，不算问题**。
- **重复计取**：同一 ILF 名称，多行"新增数"都 > 0。例：序号 21 与序号 86 均"负荷情况主题模块配置信息"，均新增=1.0 → **重复计取，建议核实删减**。

#### 5.2 功能描述高度重复（但 ILF 名称不同）

**判断**：两个功能子项的功能描述几乎一样（属性列表高度重叠），但分别计列独立 ILF。

**方法**：提取功能描述中"具有……等属性"之间的属性列表，计算两两相似度（交集/并集）。相似度 ≥ 60% 即高度重叠。

**典型反例**：
- 序号 73「负荷趋势主题模块」vs 序号 86「负荷情况主题模块」：属性均为「供电负荷、发电负荷、统调负荷、黔电送粤、计划值、实际值」，相似度 100%，却分别计列"负荷趋势主题模块配置信息"和"负荷情况主题模块配置信息"。
- 序号 106/107/108「省级/地市级/区县级指标监控主题模块」：描述仅行政区划级别不同，其余属性相同，却分别计列 3 个独立 ILF。

#### 5.3 EO 名称重复计取 + 层级不符

**判断**：同一 EO 名称在多行出现且均计列更改/新增数 → 重复计费；且注意 EO 名称是否与功能子项层级相符。

**典型反例**：序号 157/158/159 功能子项分别为「省级/地市/县级」，但 EO 名称均为「省级指标体系计算」，明显是复制粘贴错误（地市、县级应写"地市级/区县级指标体系计算"）。

#### 5.4 展示类"XX主题模块"大量误计 ILF

**模式**：功能描述匹配 `新增XX主题模块，具有……属性，用户可新增/修改/删除模块并保存查询`，且均按新增 ILF 计列。

**判断**：这类主题模块本质是展示电网运行/财务/设备/指标等业务数据的统计功能，**不涉及本系统内部逻辑文件变化**（数据来自外部系统，本系统仅展示/查询），应拆分为 EQ（查询）/EO（涉及复杂计算）计列，而非每个主题模块独立新增一个 ILF。

**触发阈值**：同一模式出现 ≥ 5 个功能子项时提示（例：某项目出现 99 个"XX主题模块"）。

#### 5.5 新增/集成功能但功能点数=0

**判断**：建设类型="新增功能"，且为集成/应用交互类（应用组含"交互/集成"，或已列 EIF 名称），但功能点数=0、开发工作量=0 → 疑似漏列集成工作量。

**典型反例**：序号 160 应用组"应用交互"，功能描述"从数据中心获取财务数据、资产设备数据……推送至运营监控平台"，已列 EIF 名称但新增数=空、功能点数=0 → 集成工作量漏列。

**注意区分**：共享 ILF 已去重的行（功能点数=0 但属正常去重）不应误报——判断依据是该行是否"应用交互/集成"组或有 EIF 名称。

#### 5.6 功能点调整因子（VAF）不一致

**判断**：对比三处取值是否一致：
1. 「功能点调整因子取值说明」Sheet 的"影响调整因子（VAF）"计算值
2. 「计算参数表」的"功能点调整因子"取值
3. 表三附1 实际参与计算的 VAF（即 C32 功能点数所采用的因子）

**典型反例**：取值说明 Sheet 按 14 项 DI 合计 38 分算出 VAF = 38×0.01+0.65 = 1.03，但计算参数表取 1.0，表三附1 也按 1.0 计算 → 前后不一致，建议核实统一。

#### 5.7 语义重复（能力碎片化）排查 —— 文本相似度不够用

**经验**：表三附1 的功能描述多为逐条原创撰写，纯文本相似度只能命中极少数（实测 174 条仅命中 1 对达到 0.98）。**真正的重复是"同一能力被拆成多个功能子项分别计列 ILF/EI/EO"**，必须按"能力主题"做语义聚类，不能只靠 `difflib`。

排查方法：按下面 7 类"碎片化模式"逐类扫，每类列出候选后人工判定：

| 碎片化模式 | 识别特征 | 真实案例（某项目 174 条） |
|---|---|---|
| ① 同一引擎拆多个入口 | 多条描述句式完全相同，仅"对象/范围"不同；EI/EO 措辞模板化 | 智能问答拆 4 条（条款/参数/试验/多规范书对比），各计 EI+EO |
| ② 同一数据拆多张表 | 相邻序号子项名近似，ILF 名同构（…信息表／…记录表） | 列项维护（条款列项内容表 vs 列项信息表）、个人偏好（视图偏好 vs 个人偏好设置）、常用模板（模板收藏 vs 常用模板记录） |
| ③ 同构台账/记录表泛滥 | 大量"XX记录表/XX台账表"且字段描述雷同 | 提醒记录表 3 套、权限配置表 6 套、归档表 3 套、操作日志 4 处 |
| ④ 配置项被"分类枚举"重复实现 | 一条做"统一配置"，另若干条恰为该配置的每个枚举值各做一遍 | 1 条"条款功能分类+属性分类配置" vs 8 条"说明类/技术类/试验类/服务类+陈述性/强制性/评价性/承诺性条款" |
| ⑤ 展示层与数据层各计一次 | 一条 EO 做归集重组，下一条做该结果的分区/分区展示 | 按属性归集重组 → 强制项/评价项/承诺项分区展示 |
| ⑥ 校验规则库碎片化 | 多条"XX完整性/合规性校验"，各建"规则表+结果表" | 提交完整性校验 vs 资料完整性校验；章节完整性/层级/格式规则 |
| ⑦ 同一数据来源两处计列 | 两条都描述"跨系统对接获取同一类数据" | 招投标平台数据同步 vs 投标数据自动汇总 |

**判定口径**：
- 同一能力拆成 N 条 → 只应计 1 条（或按真实 EIF/EI 差异计）；意见写"建议核实"并**列出全部序号**，便于作者一次性合并。
- 若两条仅"数据来源不同"（如一条用投标数据、一条用运行数据）但算法逻辑与输出物相同 → 判为重复。
- 项目名/模块名不同不构成不重复的理由（模块是组织维度，不是功能边界）。

**输出建议**：这类问题常成批出现（实测 174 条中可判 23 组），单独成节输出效果最好，不要混在零散意见里。

### 6. 评审意见措辞规范

- **建议修改**：明显违反五点法规则（如 EO 名称层级明显写错、同一 ILF 明显重复新增）。
- **建议核实**：因描述含糊、或需作者确认是否去重/漏列（如功能描述高度重叠、新增功能零功能点、调整因子不一致）。
- 估算书意见位置格式：`可研估算书 表三附1(开发、集成工作量测算) 序号X、Y`。
- 意见要**列出具体序号和功能子项名**，便于作者定位。

### 7. 基于中台开发的特殊规定

依据《2024 修订版》4.2.1.2 注 3：

> 基于中台模式开发的系统功能，采用功能点法测算工作量时，如不涉及拓展开发，统一按照集成接口类处理，仅识别计算外部接口文件（EIF）对应的工作量。

- 中台已实现的标准功能 → 不计 ILF，仅计 EIF，耗时率按集成类 6.90。

|---|---|---|

### 2. 开发费计算（最常用，重点审核）

**总公式**：

```

```

```
软件开发费 = 功能点法预算工作量(不含集成) × 9/10 × 开发工作量系数 × 开发人员人天成本
```

#### 软件集成费

```
软件集成费 = 功能点法预算工作量(集成部分) × 9/10 × 集成工作量系数 × 集成工作量调整系数 × 开发人员人天成本
```

| 参数 | 取值 |
|---|---|

### 13. 资本性/成本性划分原则

- 信息系统建设与升级改造项目：开发费、实施费（部分）、购置费 → **资本性**
- 运维费、咨询服务费（部分）、技术服务费 → **费用性（成本性）**
- **一般全额列为资本性，成本性为 0**（信息系统建设与升级改造项目）

### 14. 项目分摊原则（开发费用）

总部及分子公司分摊可按：
1. 试点单位/推广应用单位分摊
3. 上年度营业收入比例分摊
4. 所辖二级单位数量分摊
5. 各单位管理资产范围和规模分摊

def _num(v):
    """把值安全转 float，失败返回 None。"""
    if v is None:
        return None
    if isinstance(v, (int, float)):
        return float(v)
    s = str(v).strip().replace(',', '').replace('，', '')
    s = re.sub(r'[^\d.\-]', '', s)
    if s in ('', '-', '.'):
        return None
    try:
        return float(s)
    except ValueError:
        return None


def _extract_user_num(text):
    """从可研报告文本中精确提取用户规模（人），支持'约3万'、'30000人'、'3万左右'等，避免误读章节号/页码。"""
    # 优先："约 X 万" / "大约 X 万"
    m = re.search(r'(?:约|大约|约为|共计|共|达)\s*(\d+(?:\.\d+)?)\s*万', text)
    if m:
        return float(m.group(1)) * 10000
    # "X 万人 / X 万名 / X 万用户"
    m = re.search(r'(\d+(?:\.\d+)?)\s*万\s*(?:人|名|用户)', text)
    if m:
        return float(m.group(1)) * 10000
    # "X 人 / X 名用户 / X 个用户"（X >= 3 位，排除章节号）
    m = re.search(r'(\d{3,})\s*(?:人|名|个)\s*(?:用户|员工)?', text)
    if m:
        return float(m.group(1))
    return None

def parse_docx(path):
    """解析可研报告，返回 {标题列表, 段落列表, 章节映射}。"""
    doc = Document(path)
    headings = []   # (段落索引, 样式名, 文本)
    paragraphs = []  # (段落索引, 样式名, 文本)
    for i, p in enumerate(doc.paragraphs):
        t = (p.text or '').strip()
        if not t:
            continue
        style = p.style.name if p.style else ''
        is_heading = ('Heading' in style) or ('标题' in style) or (style in ('toc 1', 'toc 2', 'toc 3'))
        paragraphs.append((i, style, t))
        if is_heading:
            headings.append((i, style, t))
    return {"headings": headings, "paragraphs": paragraphs, "doc": doc}


def extract_section_text(parsed, start_idx, end_idx):

        if re.search(r'-\s*\d+\s*-$', t):

    return texts

def _extract_attrs(desc):
    """从功能描述中提取'具有…等属性'的属性集合，用于功能描述相似度比对。"""
    m = re.search(r'具有(.*?)(?:等属性|属性)', desc)
    if not m:
        return set()
    raw = m.group(1)
    parts = re.split(r'[、，,；;\s]+', raw)
    return {p for p in parts if p and len(p) > 1}

def check_desc_similarity(parsed, est):
    """检查：表三附1 功能描述高度重复（但 ILF 名称不同，属独立重复计取）。"""
    issues = []
    t3f1 = est.get("表三附1")
    if t3f1 is None:
        return issues
    sheet_name = est.get("表三附1_sheet", "表三附1")
    rows = _parse_t3f1_rows(t3f1)
    active = [r for r in rows if (r["ILF新增"] or 0) > 0]
    for i in range(len(active)):
        for j in range(i + 1, len(active)):
            a, b = active[i], active[j]
            if a["ILF"] == b["ILF"]:
                continue  # 已由 ILF 去重检查处理
            attrs_a = _extract_attrs(a["功能描述"])
            attrs_b = _extract_attrs(b["功能描述"])
            if not attrs_a or not attrs_b:
                continue
            union = attrs_a | attrs_b
            sim = len(attrs_a & attrs_b) / len(union) if union else 0
            if sim >= 0.6:
                issues.append(_issue(0, "可研估算书", f"{sheet_name} 序号{a['seq']}、{b['seq']}",
                                     f"功能子项'{a['功能子项']}'（序号{a['seq']}）与'{b['功能子项']}'（序号{b['seq']}）功能描述高度重叠（属性相似度 {sim:.0%}），但分别计列独立 ILF（'{a['ILF']}' / '{b['ILF']}'），建议核实删减重复项",
                                     "建议核实", "五点法"))
    return issues

def check_adjust_factor(parsed, est):

        if '影响调整因子' in _cell(vaf_sheet, r, 0) or 'VAF' in _cell(vaf_sheet, r, 0).upper():

                vaf_calc = _num(_cell(vaf_sheet, r, project_col))
            else:
                for c in range(len(vaf_sheet.columns)):
                    v = _num(_cell(vaf_sheet, r, c))
                    if v is not None and 0.5 < v < 2:
                        vaf_calc = v
                        break

    for r in range(len(cp)):
        if _cell(cp, r, 1) == '功能点调整因子':
            vaf_cp = _num(_cell(cp, r, 2)) or _num(_cell(cp, r, 3))

    if vaf_calc is not None and vaf_cp is not None and abs(vaf_calc - vaf_cp) > 0.001:

    for s in est.get("sheets", []):

    return "\n".join(L)

# -*- coding: utf-8 -*-
"""
parse_estimate_pdf.py —— 当可研估算书为 PDF（而非 xls/xlsx）时，抽取表一~表五、表三附1
并做确定性反算校验（UFP 反算、开发/集成系数反算、调节系数与计算口径比对、合计核对）。

用法：
  python parse_estimate_pdf.py "<概算书.pdf>" "<输出目录>"

输出：
  <输出目录>/pdf_tables.json   原始表格（按页）
  <输出目录>/t3_rows.json      表三附1 结构化行（33 列版列映射）
  <输出目录>/pdf_check.txt     确定性检查结果（供大模型第 3 步做语义评审）

依赖：pymupdf（pip install pymupdf）
说明：PDF 版表三附1 为 33 列（无"修改/新增"两行表头拆分子的独立列序差异），
      列映射见 references/five_point_method.md 第 2 节"PDF 版列结构"。
"""
import sys
import os
import json

try:
    import pymupdf
except ImportError:  # 兼容旧包名
    import fitz as pymupdf

SEQ_COLS = ['no', 'grp', 'm1', 'm2', 'item', 'sub', 'desc', 'type',
            'ILF', 'ILFc', 'ILFk', 'ILFn',
            'EIF', 'EIFc', 'EIFk', 'EIFn',
            'EI', 'EIc', 'EIk', 'EIn',
            'EO', 'EOc', 'EOk', 'EOn',
            'EQ', 'EQc', 'EQk', 'EQn',
            'gen', 'hr', 'fp', 'pm', 'dev']


def num(s):
    s = (s or '').strip().replace(',', '')
    if s in ('', '-', '—'):
        return None
    try:
        return float(s)
    except ValueError:
        return None


def parse_t3(cells):
    r = [(c or '').replace('\n', '').strip() for c in cells]
    if len(r) < 33:
        r = r + [''] * (33 - len(r))
    d = {}
    for i, k in enumerate(SEQ_COLS):
        v = r[i]
        d[k] = num(v) if k in ('ILFc', 'ILFk', 'ILFn', 'EIFc', 'EIFk', 'EIFn',
                               'EIc', 'EIk', 'EIn', 'EOc', 'EOk', 'EOn',
                               'EQc', 'EQk', 'EQn', 'gen', 'hr', 'fp', 'pm', 'dev') else v
    return d


def main(argv):
    if len(argv) < 3:
        print(__doc__)
        sys.exit(1)
    pdf_path, out_dir = argv[1], argv[2]
    os.makedirs(out_dir, exist_ok=True)

    doc = pymupdf.open(pdf_path)
    tables = []
    for pno in range(doc.page_count):
        for t in doc[pno].find_tables().tables:
            tables.append((pno + 1, t.extract()))
    json.dump([[p, d] for p, d in tables],
              open(os.path.join(out_dir, 'pdf_tables.json'), 'w', encoding='utf-8'),
              ensure_ascii=False, indent=1)

    rows = []
    for pn, rr in tables:
        for r in rr:
            cells = [(c or '').replace('\n', '').strip() for c in r]
            if len(cells) >= 30 and cells and cells[0].replace('.', '').isdigit():
                d = parse_t3(r)
                d['p'] = pn
                rows.append(d)
    json.dump(rows, open(os.path.join(out_dir, 't3_rows.json'), 'w', encoding='utf-8'),
              ensure_ascii=False, indent=1)

    out = []
    out.append('== 表三附1 行数: %d ==' % len(rows))
    out.append('== 合计核对 ==')
    s_fp = sum(x['fp'] or 0 for x in rows)
    s_pm = sum(x['pm'] or 0 for x in rows)
    s_dev = sum(x['dev'] or 0 for x in rows)
    out.append('  分项累加 功能点数=%.2f  功能点法预算工作量=%.2f  开发(集成)工作量=%.2f' % (s_fp, s_pm, s_dev))
    out.append('  与表内"总计"行比对（人工核对），不一致即"合计与分项不符"。')

    out.append('== A. 开发/集成工作量系数反算（dev/pm） ==')
    for x in rows:
        if x['pm'] and x['pm'] > 0:
            k = (x['dev'] or 0) / x['pm']
            if abs(k - 0.7) > 0.02:
                out.append('  序号%s %s: dev/pm=%.3f（开发类应≈0.7；集成类≈0.35，'
                           '即集成工作量调整系数取0.5） pm=%.2f dev=%.2f'
                           % (x['no'], x['sub'][:24], k, x['pm'], x['dev']))

    out.append('== B. UFP 反算（功能点数 /(1.39×通用度因子)）与要素计列比对 ==')
    for x in rows:
        if not x['fp'] or not x['gen']:
            continue
        ufp = x['fp'] / (1.39 * x['gen'])
        add = 10 * (x['ILFn'] or 0) + 7 * (x['EIFn'] or 0) + 4 * (x['EIn'] or 0) \
            + 5 * (x['EOn'] or 0) + 4 * (x['EQn'] or 0)
        chg = 10 * (x['ILFc'] or 0) + 7 * (x['EIFc'] or 0) + 4 * (x['EIc'] or 0) \
            + 5 * (x['EOc'] or 0) + 4 * (x['EQc'] or 0)
        if abs(ufp - add) > 0.6 and abs(ufp - chg) > 0.6:
            out.append('  序号%s %s: UFP需=%.2f 按新增计=%s 按更改计=%s'
                       % (x['no'], x['sub'][:24], ufp, add, chg))

    out.append('== C. 建设类型=新增功能但按"修改变更"列填报（更改数>0、新增数空） ==')
    for x in rows:
        has_chg = any(x[k] for k in ('ILFc', 'EIFc', 'EIc', 'EOc', 'EQc'))
        has_new = any(x[k] for k in ('ILFn', 'EIFn', 'EIn', 'EOn', 'EQn'))
        if x['fp'] and has_chg and not has_new and '新增' in (x['type'] or ''):
            out.append('  序号%s %s | 类型=%s' % (x['no'], x['sub'][:30], x['type']))

    out.append('== D. 新增行"调节系数"列填 0.4/0.5（填表说明要求新增类取1） ==')
    for x in rows:
        if x['ILFn'] and x['ILFk'] == 0.4:
            out.append('  序号%s %s | ILF调节系数=0.4 但ILF新增数=%s'
                       % (x['no'], x['sub'][:28], x['ILFn']))

    out.append('== E. 功能点数=0 但建设类型=新增功能（疑似漏列，需语义判断） ==')
    for x in rows:
        if (x['fp'] or 0) == 0 and '新增' in (x['type'] or ''):
            out.append('  序号%s %s | ILF=%r EIF=%r EI=%r EO=%r EQ=%r'
                       % (x['no'], x['sub'][:28], x['ILF'], x['EIF'], x['EI'], x['EO'], x['EQ']))

    txt = '\n'.join(out)
    open(os.path.join(out_dir, 'pdf_check.txt'), 'w', encoding='utf-8').write(txt)
    print(txt[:4000])
    print('\n[OK] 输出：pdf_tables.json / t3_rows.json / pdf_check.txt')


if __name__ == '__main__':
    main(sys.argv)

# -*- coding: utf-8 -*-
"""
check_quantity_consistency.py —— 货物采购类项目"设备数量前后一致性"专项核查

适用：可研报告（docx）+ 可研估算书（xls/xlsx）均为"设备采购 / 硬件软件购置"类项目
（建设费=0、无开发费/集成费/五点法），核心风险是**同一设备在报告与估算书多处数量、
单位、部署地点不一致**，以及**估算书内部小计与明细不符**。

四方比对：
  ① 可研报告 2.x 各单位"需求分析"表（列：序号|设备名称|建设类型|设备参数|单位|数量|部署地点）
  ② 可研报告 3.1.x 各单位"建设方案"表（列：序号|采购内容|设备参数|单位|数量|部署地点）
  ③ 可研估算书 表三（项目分项估算表）各单位硬件/软件明细
  ④ 可研估算书 表六（软件设备汇总表）各单位硬件/软件明细

另做估算书内部勾稽：
  A. 表三：各单位"（一）硬件设备购置"+"（二）系统软件购置"小计 vs 明细累加 vs 单位行合计
  B. 表六：同上
  C. 表一 / 表二 / 表三 / 表六 四方逐单位金额比对
  D. 表一其他费用合计 vs 表四(一)合计

用法：
  python check_quantity_consistency.py "<可研报告.docx>" "<可研估算书.xls>" [输出目录]
输出：控制台报告 + <输出目录>/quantity_check.txt
"""
from __future__ import print_function
import os
import re
import sys
import io
import difflib

import pandas as pd
from docx import Document
from docx.table import Table
from docx.text.paragraph import Paragraph

# 单位（建设单位）名单：按项目的"建设范围"改这里，或留空由脚本自动识别
UNITS = []

CJK = u"一二三四五六七八九十"


# ---------------------------------------------------------------- 通用工具
def num(v):
    if v is None:
        return 0.0
    if isinstance(v, (int, float)):
        try:
            if v != v:
                return 0.0
        except Exception:
            pass
        return float(v)
    t = str(v).strip().replace(",", "")
    try:
        return float(t)
    except Exception:
        return 0.0


def txt(v):
    return u"" if v is None else str(v).strip()


def norm(s):
    """名称归一化：去空格/括号差异，便于比对"""
    s = txt(s)
    s = s.replace(u" ", u"").replace(u"　", u"")
    s = s.replace(u"(", u"（").replace(u")", u"）")
    return s


def iter_blocks(doc):
    """按文档流顺序产出 ('p', style, text) 或 ('t', None, rows)"""
    body = doc.element.body
    for child in body.iterchildren():
        tag = child.tag.split('}')[-1]
        if tag == 'p':
            p = Paragraph(child, doc)
            yield ('p', p.style.name, p.text.strip())
        elif tag == 'tbl':
            tb = Table(child, doc)
            rows = []
            for r in tb.rows:
                rows.append([c.text.replace(u"\n", u" ").strip() for c in r.cells])
            yield ('t', None, rows)


UNIT_RE = re.compile(u"(供电局|电科院|电科院|人才发展中心|数智运营中心|中心|供电公司|局)$")


def is_unit_name(s):
    s = txt(s)
    if not s:
        return False
    if UNITS:
        return any(u in s for u in UNITS)
    return bool(UNIT_RE.search(s))


def docx_unit_tables(docx_path):
    """抽取 {单位: {'需求': [(名称,单位,数量,地点)], '方案': [...]}}

    注意：章节结构在不同报告里可能不同——
      标准可研：Heading2 = 单位名，Heading3 = 项目现状/需求分析/与上年度项目差异分析
      部分可研：Heading2 = "建设方案"，Heading3 = 单位名
    因此单位归属统一用「最近一个名称形似建设单位的 Heading2 或 Heading3」判定。
    """
    doc = Document(docx_path)
    res = {}
    unit = None
    for kind, style, payload in iter_blocks(doc):
        if kind == 'p':
            if style and (style.startswith(u'Heading 2') or style.startswith(u'Heading 3')):
                if is_unit_name(payload):
                    unit = payload
                    res.setdefault(unit, {'需求': [], '方案': []})
            continue
        rows = payload
        if not rows or unit is None:
            continue
        head = [norm(c) for c in rows[0]]
        is_demand = any(u'设备名称' in h for h in head) and any(u'建设类型' in h for h in head)
        is_plan = (any(u'采购内容' in h for h in head)
                   and (any(u'设备参数' in h for h in head) or any(u'部署地点' in h for h in head)))
        if not (is_demand or is_plan):
            continue
        if not any(u'数量' in h for h in head):
            continue
        ci_n = next(i for i, h in enumerate(head) if (u'设备名称' in h) or (u'采购内容' in h))
        ci_u = next((i for i, h in enumerate(head) if u'单位' in h), None)
        ci_q = next(i for i, h in enumerate(head) if u'数量' in h)
        ci_p = next((i for i, h in enumerate(head) if u'部署地点' in h or u'地点' in h), None)
        key = '需求' if is_demand else '方案'
        for r in rows[1:]:
            if len(r) <= max(ci_n, ci_q):
                continue
            if not r[ci_n]:
                continue
            if not re.match(u'^\\d+$', txt(r[0])):
                continue
            res[unit][key].append((
                txt(r[ci_n]),
                txt(r[ci_u]) if ci_u is not None and ci_u < len(r) else u'',
                txt(r[ci_q]),
                txt(r[ci_p]) if ci_p is not None and ci_p < len(r) else u''))
    return res


# ---------------------------------------------------------------- 估算书解析
def is_unit_row(row, col_seq=0, col_name=1):
    a = txt(row.iloc[col_seq])
    b = txt(row.iloc[col_name])
    if not re.match(u"^[%s]{1,3}$" % CJK, a):
        return False
    if not b:
        return False
    if UNITS:
        return any(u in b for u in UNITS)
    return bool(re.search(u"(供电局|电科院|中心|公司|局)$", b))


def hw_sw(key):
    if key in (u"(一)", u"（一）"):
        return "HW"
    if key in (u"(二)", u"（二）"):
        return "SW"
    return None


def parse_estimate_sheet(df, name_col, col_total, col_seq=0):
    """返回 {单位: dict(hw_sub, sw_sub, unit_total, hw_det, sw_det, items=[(名称,单位,数量,金额,段)])}"""
    idx = [i for i in range(len(df)) if is_unit_row(df.iloc[i], col_seq, 1)]
    out = {}
    for n, i in enumerate(idx):
        j = idx[n + 1] if n + 1 < len(idx) else len(df)
        u = txt(df.iloc[i].iloc[1])
        rec = dict(row=i, hw_sub=None, sw_sub=None,
                   unit_total=num(df.iloc[i].iloc[col_total]),
                   hw_det=0.0, sw_det=0.0, items=[])
        sec = None
        for k in range(i + 1, j):
            row = df.iloc[k]
            key = txt(row.iloc[col_seq])
            tag = hw_sw(key)
            if tag:
                sec = tag
                if tag == "HW":
                    rec['hw_sub'] = num(row.iloc[col_total])
                else:
                    rec['sw_sub'] = num(row.iloc[col_total])
                continue
            if re.match(u"^\\d+$", key):
                v = num(row.iloc[col_total])
                if sec == "HW":
                    rec['hw_det'] += v
                elif sec == "SW":
                    rec['sw_det'] += v
                rec['items'].append((txt(row.iloc[name_col]), v, sec, k))
        out[u] = rec
    return out


def main(argv):
    if len(argv) < 3:
        print(__doc__)
        return 1
    docx_path, xls_path = argv[1], argv[2]
    out_dir = argv[3] if len(argv) > 3 else os.path.dirname(os.path.abspath(argv[2]))

    log = []

    def P(s=u""):
        log.append(s)
        try:
            print(s)
        except Exception:
            print(s.encode("utf-8", "replace").decode("utf-8", "replace"))

    # ---------- 报告侧
    rep = docx_unit_tables(docx_path)
    units = [u for u in rep if rep[u]['需求'] or rep[u]['方案']]
    P(u"=" * 100)
    P(u"A. 可研报告：各单位 需求分析表 / 建设方案表 行数与数量合计")
    P(u"=" * 100)
    P(u"%-16s %-22s %-22s" % (u"单位", u"需求分析表", u"建设方案表"))
    for u in units:
        d, p = rep[u]['需求'], rep[u]['方案']
        P(u"%-16s %-22s %-22s%s" % (
            u, u"%d行/合计%s" % (len(d), sum(int(x[2]) for x in d if x[2].isdigit())),
            u"%d行/合计%s" % (len(p), sum(int(x[2]) for x in p if x[2].isdigit())),
            u"" if len(d) == len(p) else u"   <<< 行数不一致"))
    P(u"")
    P(u"=" * 100)
    P(u"B. 报告内部：需求分析表 vs 建设方案表 逐项比对")
    P(u"=" * 100)
    any_bad = False
    for u in units:
        d = {norm(x[0]): (x[1], x[2], x[3]) for x in rep[u]['需求']}
        p = {norm(x[0]): (x[1], x[2], x[3]) for x in rep[u]['方案']}
        only_d = [k for k in d if k not in p]
        only_p = [k for k in p if k not in d]
        # 名称近似但不同，单独提示
        near = []
        for k in only_d:
            m = difflib.get_close_matches(k, list(p.keys()), n=1, cutoff=0.6)
            if m:
                near.append((k, m[0]))
        qty_bad = [(k, d[k], p[k]) for k in d if k in p and d[k] != p[k]]
        if only_d or only_p or qty_bad:
            any_bad = True
            P(u"\n### %s" % u)
            for k in only_d:

            for a, b in near:
                P(u"   ⚠ 名称近似（疑似同一设备写法不同）: 「%s」 / 「%s」" % (a, b))

                P(u"   数量/单位不符: %s  需求=%s/%s  方案=%s/%s" % (k, a[1], a[0], b[1], b[0]))
    if not any_bad:
        P(u"（所有单位的需求分析表与建设方案表逐项一致）")

    # ---------- 估算书侧
    xl = pd.ExcelFile(xls_path)
    sh3 = next((s for s in xl.sheet_names if s.startswith(u"表三")), None)
    sh6 = next((s for s in xl.sheet_names if s.startswith(u"表六")), None)
    sh2 = next((s for s in xl.sheet_names if s.startswith(u"表二")), None)
    sh1 = next((s for s in xl.sheet_names if s.startswith(u"表一")), None)

    t3 = t6 = {}
    if sh3:
        df3 = pd.read_excel(xls_path, sheet_name=sh3, header=None, dtype=object)
        t3 = parse_estimate_sheet(df3, name_col=1, col_total=9)
    if sh6:
        df6 = pd.read_excel(xls_path, sheet_name=sh6, header=None, dtype=object)
        t6 = parse_estimate_sheet(df6, name_col=1, col_total=6)

    P(u"")
    P(u"=" * 100)
    P(u"C. 估算书 表三 内部勾稽（小计 vs 明细 vs 单位合计，单位：元）")
    P(u"=" * 100)
    for u, r in t3.items():
        hs = r['hw_sub'] or 0.0
        ss = r['sw_sub'] or 0.0
        bad = []
        if abs(hs - r['hw_det']) > 1.5:
            bad.append(u"硬件小计%.0f≠明细%.0f" % (hs, r['hw_det']))
        if abs(ss - r['sw_det']) > 1.5:
            bad.append(u"软件小计%.0f≠明细%.0f" % (ss, r['sw_det']))
        if abs(r['unit_total'] - (hs + ss)) > 1.5:
            bad.append(u"单位合计%.0f≠小计和%.0f" % (r['unit_total'], hs + ss))
        if bad:
            P(u"  %-14s %s   <<< 不符" % (u, u"；".join(bad)))

    P(u"")
    P(u"=" * 100)
    P(u"D. 估算书 表六（软件设备汇总表）内部勾稽（单位：元）")
    P(u"=" * 100)
    for u, r in t6.items():
        hs = r['hw_sub'] or 0.0
        ss = r['sw_sub'] or 0.0
        bad = []
        if abs(hs - r['hw_det']) > 1.5:

        if abs(ss - r['sw_det']) > 1.5:

        if abs(r['unit_total'] - (hs + ss)) > 1.5:
            bad.append(u"单位合计%.0f≠小计和%.0f" % (r['unit_total'], hs + ss))
        if bad:
            P(u"  %-14s %s   <<< 不符" % (u, u"；".join(bad)))

    # 四方金额比对
    m2 = {}
    if sh2:
        df2 = pd.read_excel(xls_path, sheet_name=sh2, header=None, dtype=object)
        for i in range(len(df2)):
            row = df2.iloc[i]
            if re.match(u"^\\d+$", txt(row.iloc[0])) and txt(row.iloc[1]):
                m2[txt(row.iloc[1])] = (num(row.iloc[6]), num(row.iloc[7]), num(row.iloc[14]))
    P(u"")
    P(u"=" * 100)

#!/usr/bin/env python
# -*- coding: utf-8 -*-
"""
子估算书 ↔ 整体汇总估算书：设备数量 / 价格 / 性能参数 三层核对

适用：信息化项目（尤其"安全设备采购 / 软硬件购置"这类货物采购类）中，
      建设单位分别报送了各自的"子估算书（xls）"，
      需要核对其与甲方"整体汇总估算书"（按单位分块）是否逐项对得上。

用法：
    python check_subbook_vs_master.py <汇总估算书.xls> <输出目录> <子书1.xls> [子书2.xls ...]

输出：<输出目录>/subbook_vs_master.txt   （控制台同步打印）

核对内容（A~G 七段）：
    A. 每个子书 ↔ 汇总书：表三(项目分项估算表) 逐项（名称/单位/数量/单价/金额）
    B. 每个子书 ↔ 汇总书：表六(软件设备汇总表) 逐项（+ 规格型号=性能参数、价格来源）
    C. 每个子书 ↔ 汇总书：表一(项目估算汇总表) 资本性/购置费/其他费用/合计（万元）
    D. 汇总书内部：表三/表六 小计↔明细；单价×数量↔金额；明细"单位"列空白
    E. 跨单位：同【名称 + 规格型号】而单价不一致（真正的同物异价，最值得报）
    F. 跨单位：同名称但规格不同 → 单价不同（多为不同配置，列出供判断）
    G. 汇总书单位覆盖情况：哪些单位有子书、哪些没有

表的两种常见版式（脚本均兼容）：
    版式① 汇总/多单位本：  一|大理供电局 → （一）硬件设备购置 → 1|设备名…
    版式② 单单位本：       一|建设费 → (一)开发费 → 二|购置费 → (一)硬件设备购置 → 1|设备名…
    区别只在"中文序号"后面跟的是【单位名】还是【费用类别】；脚本按第 1 列文本自动判别，
    括号中英文（(一) / （一））自动归一。

列序约定：
    表三：序号|项目名称|单位|数量|建设费单价|购置费单价|租赁费单价|运维费单价|
          建设费合计|购置费合计|租赁费合计|运维费合计      → name=1,u=2,q=3,p=5,amt=9
    表六：序号|设备名称|规格型号|单位|数量|单价|合计|价格来源 → name=1,u=3,q=4,p=5,amt=6,spec=2,src=7
    表一：序号|建设单位|项目名称|资本性|费用性|合计|建设费|购置费|租赁费|运维费|其他费用|合计
          → 资本性=3, 购置费=7, 其他费用=10, 合计=11
"""
from __future__ import print_function

import io
import os
import re
import sys
from collections import defaultdict

import pandas as pd

CN = ["一", "二", "三", "四", "五", "六", "七", "八", "九", "十",
      "十一", "十二", "十三", "十四", "十五", "十六", "十七", "十八", "十九", "二十"]
SUB_MARKS = ("（一）", "（二）", "（三）", "（四）", "（五）")
UNIT_KW = ("供电局", "电科院", "中心", "公司", "研究院", "所")

SHEET_THREE = "表三(项目分项估算表)"
SHEET_SIX = "表六（软件设备汇总表）"
SHEET_ONE = "表一(项目估算汇总表)"

COLS_THREE = dict(name=1, u=2, q=3, p=5, amt=9)
COLS_SIX = dict(name=1, u=3, q=4, p=5, amt=6, spec=2, src=7)
ONE_IDX = dict(capital=3, purchase=7, other=10, total=11)


def nz(v):
    if v is None:
        return ""
    s = str(v)
    if s == "nan":
        return ""
    s = s.replace("\r", "\n")
    s = re.sub(r"[ \t\u3000]+", "", s)
    s = re.sub(r"\n+", "\n", s)
    return s.strip()


def norm_mark(s):
    return s.replace("(", "（").replace(")", "）").strip()


def fnum(v):
    if v is None:
        return None
    s = str(v).strip().replace(",", "")
    if s in ("", "nan", "NaN", "None", "--", "-"):
        return None
    try:
        f = float(s)
    except Exception:
        return None
    return None if f != f else f  # 过滤 NaN


def fmt(x):
    if x is None:
        return "-"
    t = "%.2f" % x
    return t.rstrip("0").rstrip(".") if "." in t else t


def read_sheet(path, sheet):
    return pd.read_excel(path, sheet_name=sheet, header=None, dtype=object)


def parse_unit_blocks(path, sheet, cols):
    """
    返回 {unit: {'kinds': {标记+名称: 小计}, 'items': [...], 'total_calc': float|None}}
    无单位块行时（单单位本），全部明细归入 key '__SINGLE__'。
    """
    df = read_sheet(path, sheet)
    res = {}

    def ensure(u):
        if u not in res:
            res[u] = {"kinds": {}, "items": []}
        return res[u]

    unit = None
    for i in range(len(df)):
        row = df.iloc[i].tolist()
        a = nz(row[0]) if len(row) > 0 else ""
        b = nz(row[1]) if len(row) > 1 else ""
        if a in CN and b:
            if any(k in b for k in UNIT_KW):
                unit = b
                ensure(unit)
            else:
                # 版式②：中文序号后是"建设费/购置费/租赁费/运行维护费"等费用类别
                if unit is None:
                    unit = "__SINGLE__"
                    ensure(unit)
            continue
        if unit is None and (norm_mark(a) in SUB_MARKS or a.isdigit()):
            # 版式②的简化版：整表无任何中文序号块，直接是（一）/1 明细
            unit = "__SINGLE__"
            ensure(unit)
        if unit is None:
            continue
        mark = norm_mark(a)
        if mark in SUB_MARKS:
            val = fnum(row[cols["amt"]]) if len(row) > cols["amt"] else None
            res[unit]["kinds"][mark + b] = val
            continue
        if a.isdigit():
            it = {"no": a, "name": b,
                  "u": nz(row[cols["u"]]) if len(row) > cols["u"] else "",
                  "q": nz(row[cols["q"]]) if len(row) > cols["q"] else "",
                  "price": fnum(row[cols["p"]]) if len(row) > cols["p"] else None,
                  "amt": fnum(row[cols["amt"]]) if len(row) > cols["amt"] else None}
            if cols.get("spec") is not None:
                it["spec"] = nz(row[cols["spec"]]) if len(row) > cols["spec"] else ""
            if cols.get("src") is not None:
                it["src"] = nz(row[cols["src"]]) if len(row) > cols["src"] else ""
            # 过滤模板占位行（如 运维费/租赁费 下留空的 1|硬件运维费 等）
            if not it["name"]:
                continue
            if (it["price"] in (None, 0)) and (it["amt"] in (None, 0)):
                continue
            res[unit]["items"].append(it)
    for u, d in res.items():
        s = 0.0
        got = False
        for k, v in d["kinds"].items():
            if k.startswith("（") and v is not None:
                s += v
                got = True
        d["total_calc"] = s if got else None
    return res


def parse_unit_total_row(path, sheet):
    """表一：{单位: {'capital':,'purchase':,'other':,'total':}} 单位万元"""
    df = read_sheet(path, sheet)
    out = {}
    for i in range(len(df)):
        row = df.iloc[i].tolist()
        if len(row) < 12:
            continue
        u = nz(row[1])
        if not u or any(k in u for k in ("建设单位", "合计", "序号")):
            continue
        out[u] = {k: fnum(row[v]) for k, v in ONE_IDX.items()}
    return out


def detect_unit_name(sub_path, master_units):
    """从子书封面/编制说明/表一/表三项目名里找单位名，与汇总书单位列表求匹配"""
    txt = ""
    for sh in ("封面", "编制说明"):
        try:
            df = read_sheet(sub_path, sh)
            txt += "\n" + "\n".join(nz(x) for x in df.values.ravel().tolist())
        except Exception:
            pass
    for sh in (SHEET_THREE, SHEET_SIX, SHEET_ONE):
        try:
            df = read_sheet(sub_path, sh)
            txt += "\n" + "\n".join(nz(x) for x in df.iloc[:8].values.ravel().tolist())
        except Exception:
            pass
    for name in master_units:
        if name and name in txt:
            return name
    try:
        for k in parse_unit_total_row(sub_path, SHEET_ONE):
            if k in master_units:
                return k
    except Exception:
        pass
    try:
        blk = parse_unit_blocks(sub_path, SHEET_THREE, COLS_THREE)
        for u in blk:
            if u in master_units:
                return u
    except Exception:
        pass
    return None


def main():

        print(__doc__)
        sys.exit(1)
    master = sys.argv[1]

                    continue
                if y is None:

                    continue
                f = []

                        tag, u, it["no"], it["name"][:26], fmt(it["price"]), it["q"],

    P("  （以上无输出＝单价×数量与金额均相符；末位取整差额≤1.5 元视为正常）")

    P("[D4] 明细行『单位』列为空")
    for tag, md in (("表三", m3), ("表六", m6)):
        for u, d in md.items():

                if not it["u"]:
                    P("  ★ %s %s #%s %s（数量 %s）" % (tag, u, it["no"], it["name"][:40], it["q"]))
    P("  （以上无输出＝单位列均已填）")
    P()

    P("#" * 88)
    P("[E] 跨单位：同【名称 + 规格型号】而单价不一致（同物异价，最值得报）")
    g = defaultdict(list)
    for u in units:
        for it in m6.get(u, {"items": []})["items"]:
            g[(it["name"], it.get("spec", ""))].append((u, it))
    n = 0
    for k, v in sorted(g.items()):
        ps = {}
        for u, it in v:
            if it["price"] is not None:
                ps.setdefault(round(it["price"], 2), []).append("%s(%s)" % (u, it["q"]))
        if len(ps) > 1:
            n += 1
            P("  ★ %s" % k[0])
            P("     规格：%s" % k[1][:88])
            for p, us in sorted(ps.items()):
                P("       单价 %-12s → %s" % (fmt(p), "、".join(us)))
            P("       单价差：%s 元" % fmt(max(ps) - min(ps)))
    if not n:
        P("  （无：不存在同名称同规格而单价不同的情形）")
    P()

    P("#" * 88)
    P("[F] 跨单位：同【名称】但规格不同 → 单价不同（多为不同配置，供判断是否同物异价）")
    g2 = defaultdict(list)
    for u in units:
        for it in m6.get(u, {"items": []})["items"]:
            g2[it["name"]].append((u, it))
    for name, v in sorted(g2.items()):
        ps = {}
        for u, it in v:
            if it["price"] is not None:
                ps.setdefault(round(it["price"], 2), []).append((u, it))
        if len(v) > 1 and len(ps) > 1:
            P("  · %s" % name)
            for p, us in sorted(ps.items()):
                specs = len(set(x[1].get("spec", "") for x in us))
                P("      单价 %-12s 单位：%-30s 规格种数=%d" % (
                    fmt(p), "、".join(sorted(set(x[0] for x in us))), specs))
    P()

    P("#" * 88)
    P("[G] 汇总估算书单位覆盖情况")
    P("  已提供子估算书（%d 个）：%s" % (len(covered), "、".join(covered)))
    miss = [u for u in units if u not in covered]
    P("  未提供子估算书（%d 个）：%s" % (len(miss), "、".join(miss)))
    if problems:
        P()
        P("  ★ 投资口径问题汇总：")
        for p in problems:
            P("    - %s" % p)

    io.open(out_path, "w", encoding="utf-8").write("\n".join(buf))
    print()
    print("已写出：%s" % out_path)

# -*- coding: utf-8 -*-
"""
build_report.py —— 根据 audit_results.json 生成评审意见 docx

输入：
  1. audit_results.json（由 audit_run.py 生成，含"意见列表"）
  2. 项目名（用作文档标题）
  3. 输出 .docx 路径

输出：
  - 评审意见 docx，标题：<项目名>可行性研究报告评审意见
  - 编号 1, 2, 3 ... 列出意见
  - 每条格式：可研报告/可研估算书 [位置]：[问题]。[建议核实/建议修改]

依赖：python-docx
"""
import sys
import os
import json
from docx import Document
from docx.shared import Pt, Cm
from docx.enum.text import WD_PARAGRAPH_ALIGNMENT


def build(json_path, project_name, output_path):
    with open(json_path, "r", encoding="utf-8") as f:
        data = json.load(f)
    items = data.get("意见列表", [])

    doc = Document()

    # 标题
    title_text = f"{project_name}可行性研究报告评审意见"
    p = doc.add_paragraph()
    p.alignment = WD_PARAGRAPH_ALIGNMENT.CENTER
    run = p.add_run(title_text)
    run.font.size = Pt(18)
    run.font.bold = True

    # 副标题：项目信息
    p = doc.add_paragraph()
    p.alignment = WD_PARAGRAPH_ALIGNMENT.LEFT
    run = p.add_run(f"项目名称：{project_name}")
    run.font.size = Pt(12)

    if data.get("可研报告文件名"):
        p = doc.add_paragraph()
        run = p.add_run(f"可研报告文件：{data['可研报告文件名']}")
        run.font.size = Pt(11)
    if data.get("可研估算书文件名"):
        p = doc.add_paragraph()
        run = p.add_run(f"可研估算书文件：{data['可研估算书文件名']}")
        run.font.size = Pt(11)

    # 空行
    doc.add_paragraph()

    # 意见列表
    if not items:
        p = doc.add_paragraph()
        run = p.add_run("（自动检查未发现问题；请按 references/audit_checklist.md 人工补充错别字、语病等。）")
        run.font.italic = True
    else:
        for idx, it in enumerate(items, 1):
            seq = it.get("序号", str(idx))
            source = it.get("来源", "")
            pos = it.get("位置", "")
            problem = it.get("问题", "")
            suggestion = it.get("建议", "")
            category = it.get("类别", "")
            label = source if source else "评审发现"
            text = f"{seq}、{label}\u201c{pos}\u201d：{problem}。{suggestion}。"
            if category:
                text += f"[{category}]"
            p = doc.add_paragraph()
            run = p.add_run(text)
            run.font.size = Pt(11)
            # 首行缩进 2 字符
            p.paragraph_format.first_line_indent = Cm(0.74)

    doc.save(output_path)
    print(f"[OK] 评审意见 docx 已生成：{output_path}")


def main(argv):
    if len(argv) < 4:
        print(__doc__)
        sys.exit(1)
    json_path = argv[1]
    project_name = argv[2]
    output_path = argv[3]
    build(json_path, project_name, output_path)


if __name__ == "__main__":
    main(sys.argv)
