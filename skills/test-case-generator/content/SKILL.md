# 测试用例生成专家

专业软件测试用例生成技能，基于需求文档和策划案，使用标准测试方法论生成完整的测试用例。

## 工作流程

### 1. 需求分析

接收用户提供的需求文档后，分析以下内容：
- 功能模块划分
- 输入输出定义
- 业务规则和约束条件
- 用户角色和权限
- 系统边界条件

### 2. 测试方法选择

根据需求特性选择适当的测试方法：

| 方法 | 适用场景 | 核心关注点 |
|------|----------|------------|
| 场景法 | 用户流程、端到端测试 | 基本流、备选流、异常流 |
| 边界值分析 | 数值范围、长度限制 | 边界±1、空值、极限值 |
| 等价类划分 | 大量输入组合 | 有效类、无效类、代表性用例 |
| 错误推断法 | 常见错误模式 | 空值、null、类型错误、格式错误 |
| 因果图法 | 多条件组合 | 输入输出因果关系 |
| 判定表法 | 多条件逻辑判断 | 条件组合与对应动作 |
| 状态转换测试 | 状态机、有状态功能 | 状态流转、非法转换 |

### 3. 测试用例生成

生成标准化测试用例表格：

| 用例ID | 用例名称 | 测试方法 | 前置条件 | 测试输入 | 预期结果 | 优先级 | 备注 |
|--------|----------|----------|----------|----------|----------|--------|------|

**优先级定义：**
- P0：核心功能冒烟测试（必须通过）
- P1：高优先级功能测试（主要业务流程）
- P2：中优先级功能测试（次要功能）
- P3：低优先级探索性测试（边界情况）

### 4. 交付内容

生成完整的测试用例集，包括：
- 测试用例表格（Markdown格式）
- 测试方法说明
- 边界值详细标注
- 测试覆盖度说明

## 使用方式

**触发方式：** 用户提供需求文档并要求生成测试用例时

**输入：** 需求文档、策划案、功能说明等

**输出：** 结构化的测试用例表格

## 注意事项

1. 每个边界值用例需明确标注具体边界值
2. 异常流程必须覆盖且标注预期错误处理
3. 测试步骤需具体可执行
4. 保持测试用例的独立性和可重复性
