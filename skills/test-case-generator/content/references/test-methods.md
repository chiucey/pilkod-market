# 测试用例设计方法详解

## 1. 场景法 (Scenario Testing)

### 核心概念
基于用户实际使用场景设计测试路径，覆盖正常流程和备选流。

### 符号定义
- **基本流（Basic Flow）**：用户完成目标的最佳路径
- **备选流（Alternative Flow）**：用户选择不同操作的路径
- **异常流（Exception Flow）**：系统处理错误或异常的路径

### 设计步骤
1. 识别用户目标和关键步骤
2. 定义基本流（Happy Path）
3. 识别每个步骤的备选路径
4. 识别异常条件和错误处理
5. 为每个路径生成测试用例

### 示例
**场景：用户登录**
- 基本流：输入正确用户名和密码 → 登录成功
- 备选流1：选择"记住登录"→ 自动登录
- 备选流2：点击"忘记密码"→ 跳转密码找回
- 异常流1：输入错误密码 → 提示错误
- 异常流2：账户被锁定 → 提示联系客服

## 2. 边界值分析 (Boundary Value Analysis)

### 核心概念
测试边界条件及其相邻值，捕获边界处的缺陷。

### 边界值确定
- 对于范围 [min, max]，测试：min-1, min, min+1, max-1, max, max+1
- 对于集合测试第一个和最后一个元素

### 常见边界类型
| 类型 | 示例边界 |
|------|----------|
| 数值范围 | 0, 1, 最大值-1, 最大值, 最大值+1 |
| 字符串长度 | 空字符串, 1字符, 最大长度-1, 最大长度, 最大长度+1 |
| 数组索引 | 第一个元素, 中间元素, 最后一个元素 |
| 日期范围 | 年初, 年末, 闰年边界, 月末 |
| 百分比 | 0%, 1%, 99%, 100% |

### 特殊边界值
- **0值**：空输入、空集合、零除
- **空值**：null、空字符串、空数组
- **最大/最小**：系统限制、业务规则限制

## 3. 等价类划分 (Equivalence Partitioning)

### 核心概念
将输入域划分为有效和无效等价类，每个类选择一个代表性值。

### 划分原则
- **有效等价类**：符合需求的输入
- **无效等价类**：不符合需求的输入

### 设计步骤
1. 分析输入条件
2. 划分等价类
3. 为每个等价类选择测试数据
4. 覆盖所有有效类和无效类

### 示例
**输入：年龄字段 [18, 60]**
- 有效类1：18 ≤ 年龄 ≤ 60
- 无效类1：年龄 < 18
- 无效类2：年龄 > 60
- 无效类3：非数字输入
- 无效类4：负数

## 4. 错误推断法 (Error Guessing)

### 核心概念
基于测试人员的经验和直觉，推测容易出错的地方。

### 常见错误模式

#### 输入类错误
- 空输入
- null/undefined值
- 特殊字符：`<script>`, `';--`, emoji
- 超长输入
- 类型错误（数字字段输入字母）
- 格式错误（日期格式、邮箱格式）

#### 边界类错误
- 临界值
- 零值和负数
- 最大值溢出
- 精度丢失

#### 并发类错误
- 重复提交
- 并发修改
- 竞态条件
- 会话超时

#### 环境类错误
- 网络中断
- 服务不可用
- 缓存问题
- 时区差异

---

## 5. 因果图法 (Cause-Effect Graphing)

### 核心概念
用图形方式表示输入条件（原因）和输出结果（效果）之间的关系。

### 符号
- **恒等**：若A为真，则B为真
- **非**：若A为真，则B为假
- **或**：若A或B或C为真，则D为真
- **与**：若A和B和C都为真，则D为真

### 设计步骤
1. 识别所有输入条件（因）
2. 识别所有输出结果（果）
3. 绘制因果图
4. 转换为判定表
5. 生成测试用例

### 示例
**场景：订单折扣**
- 因：会员(A)、订单≥500(B)、促销商品(C)
- 果：9折(D)、8折(E)、不打折(F)

## 6. 判定表法 (Decision Table)

### 核心概念
列出所有条件组合和对应的动作，适用于复杂的业务规则。

### 判定表结构
| 条件 | 规则1 | 规则2 | 规则3 | ... |
|------|-------|-------|-------|-----|
| 条件1 | T/F | T/F | T/F | ... |
| 条件2 | T/F | T/F | T/F | ... |
| 动作 | 动作1 | 动作2 | 动作3 | ... |

### 设计步骤
1. 识别所有条件和动作
2. 确定条件的所有可能值
3. 计算所有可能的组合数
4. 简化（合并等效规则）
5. 生成完整判定表

### 示例
**场景：会员折扣规则**
| 会员 | 订单≥500 | 促销商品 | 结果 |
|------|----------|----------|------|
| Y | Y | Y | 8折 |
| Y | Y | N | 8.5折 |
| Y | N | Y | 9折 |
| N | Y | Y | 9折 |
| ... | ... | ... | ... |

## 7. 状态转换测试 (State Transition Testing)

### 核心概念
测试系统在不同状态之间的转换，覆盖所有合法和非法的状态转换。

### 元素
- **状态**：系统的特定条件
- **转换**：从一个状态到另一个状态的动作
- **事件**：触发转换的条件
- **动作**：转换时执行的操作

### 设计步骤
1. 识别所有状态
2. 识别所有转换和触发事件
3. 绘制状态图/状态表
4. 确定覆盖标准
5. 生成测试用例

### 覆盖标准
- **0-switch覆盖**：每个状态至少测试一次
- **1-switch覆盖**：每对状态转换至少测试一次
- **2-switch覆盖**：每两个连续转换至少测试一次

### 示例
**场景：订单状态机**
- 待支付 → 已支付 → 已发货 → 已完成
- 任何状态 → 已取消（特定条件下）

## 测试用例优先级定义

| 优先级 | 描述 | 覆盖范围 |
|--------|------|----------|
| P0 | 核心功能冒烟测试 | 基本流程、核心功能 |
| P1 | 高优先级功能测试 | 主要业务流程、关键路径 |
| P2 | 中优先级功能测试 | 次要功能、边界条件 |
| P3 | 低优先级探索性测试 | 边界情况、异常处理 |

## 测试用例模板

```
| 用例ID | 用例名称 | 测试方法 | 前置条件 | 测试输入 | 预期结果 | 优先级 | 备注 |
|--------|----------|----------|----------|----------|----------|--------|------|
| TC_001 | [用例名称] | [方法] | [条件] | [输入] | [结果] | P0 | [标注] |
```

### 标注规范
- 边界值用例：`边界：XXX`
- 异常用例：`异常处理`
- 性能相关：`性能测试`
- 安全相关：`安全测试`
