# 洞察方法框架

## 一、客户战略洞察框架

### 1.1 经营回顾分析
| 分析维度 | 具体内容 |
|---------|---------|
| 市场份额 | 市场占有率变化趋势 |
| 增长 | 收入增长、客户增长 |
| 盈利 | 利润率、EBITDA |
| 资金储备 | 现金储备、负债率 |
| 投资 | CapEx计划、投资方向 |

### 1.2 战略回顾分析
| 分析维度 | 具体内容 |
|---------|---------|
| 战略发布 | 过去三年发布的战略文档 |
| 执行回顾 | 战略执行情况和结果 |
| 高层讲话 | CEO/CTO等重要讲话 |
| 大事件 | 并购、重组、重大决策 |

### 1.3 业务规划分析
| 分析维度 | 具体内容 |
|---------|---------|
| 重点业务 | 核心业务单元 |
| 核心支撑 | 关键能力建设 |
| 组织结构 | 部门设置、汇报关系 |
| 采购决策 | 决策流程、关键决策人 |

## 二、客户痛点洞察框架

### 2.1 商业维度分析（Business）
```
- 市场份额：市场地位分析
- 单客收入：ARPU变化
- 利润率：盈利空间分析
- 投资密度：单位投资回报
- 运营费用占比：成本结构
```

### 2.2 运营维度分析（Operation）
```
- 战略方向：是否清晰聚焦
- 盈利能力：持续性如何
- 业务能力：核心能力强弱
- 发展能力：增长潜力评估
- 抗风险能力：韧性评估
- 国际化能力：海外拓展能力
```

### 2.3 网络维度分析（Network）
| 维度 | 说明 |
|-----|------|
| S - 业务（Service） | 业务类型、用户规模 |
| P - 性能（Performance） | KPI表现、网络质量 |
| A - 架构（Architecture） | 网络架构合理性 |
| C - 成本&价值（Cost & Value） | TCO结构、价值创造 |
| E - 演进（Evolution） | 技术演进路线 |

## 三、竞争分析洞察框架

### 3.1 竞争对手扫描
```
竞争对手战略 | 财务情况总结
关键战略目标调整信息
业务目标变化
业务重心与投资方向变化点
关键能力与解决方案聚焦 | 关键技术和解决方案
营销口径
商业模式
其他能力 | 人事/组织
```

### 3.2 竞争分析原则
| 原则 | 说明 |
|-----|------|
| 不是差距分析 | 关键识别差异点 |
| 商业竞争力 | 产品竞争力要的是商业竞争力，而不仅仅是技术 |
| 动机洞察 | 洞察业界解决方案规划背后的动机和逻辑 |

### 3.3 竞争策略选择
| 领域 | 策略 |
|-----|------|
| 优势领域 | 保持领先优势，实现持续领先 |
| 非优势领域 | 寻找差异化领先点，弯道超车 |

## 四、产业愿景洞察框架

### 4.1 愿景牵引模型
```
长期愿景（喜马拉雅山峰）
     ↑
     |
中期目标（山坡沿途下蛋）
     ↑
     |
短期商业变现（当下产品/方案）
```

### 4.2 产业演进规律
- **初始阶段**：从边缘应用起步
- **成长阶段**：逐步扩大应用范围
- **成熟阶段**：成为主流解决方案

|---------|---------|
| 洞察专题1 | 不限量套餐会成为运营商普遍战略吗？饮鸩止渴还是有效手段？ |
| 洞察专题2 | 客户网络容量到2019年将达到瓶颈吗？是否需要扩容？ |
| 洞察专题3 | 思科推出IBN（基于意图的网络）开放性平台，华为如何应对？ |
| 洞察专题4 | 物联网的万物互联愿景是否已过孵化早期，能够支撑运营商收入大幅增长？ |

## 五、行业阶段洞察框架

### 5.1 行业地位分类
| 行业地位 | 华为角色 | 特征 |
|---------|---------|------|
| 优势产业 | 领导者 | 带领产业发展，持续超越 |
| 追赶型产业 | 追赶者 | 增长潜力巨大，缩短成为第一的时间 |
| 开创型产业 | 开拓者 | 创新探索，开创新边疆 |

### 5.2 洞察方向匹配
| 行业地位 | 侧重洞察 | 创新驱动 |
|---------|---------|---------|
| 优势产业 | 产业愿景洞察 | 愿景驱动创新 |
| 追赶型产业 | 竞争分析洞察 | 差距驱动创新 |
| 开创型产业 | 客户痛点洞察 | 需求驱动创新 |

### 5.3 战略要求
| 行业地位 | 战略要求 |
|---------|---------|
| 领导者 | 保证效率，持续领先 |
| 追赶者 | 不能守成，不进则退 |
| 开拓者 | 敢于提出挑战目标 |

## 六、场景化洞察操作框架

### 6.1 洞察项目组织
```
专题总目标
     ↓
区域洞察 ←→ 研发互锁 ←→ 周边协同
中国 | 欧洲 | 美洲 | 亚太 | 日韩 | 中东非洲
```

### 6.2 一线调研方法
| 方法 | 说明 |
|-----|------|
| 协同洞察 | 与行销、市场代表沟通 |
| 项目深入 | 从关键项目获取现网数据 |
| 明白人访谈 | 与客户明白人深度交流 |
| 联合创新 | 与客户共同定义产品 |

### 6.3 关键项目五步法
1. **选**：选取能牵引规划方向的公司重大项目
2. **推**：向一线行销传递产品规划策略
3. **埋**：评审客户引导材料，预埋牵引策略
4. **扫**：提前识别不合理诉求，收敛客户预期
5. **识**：洞察客户痛点，识别关键信息

## 七、需求提炼决策框架

### 7.0 洞察执行检查清单
在进入正式分析前，可以用以下问题快速检查是否具备足够的洞察基础：

1. 客户是谁？是谁在买、谁在用、谁在决策？
2. 当前业务目标是什么？是增长、盈利、降本、转型，还是提升体验？
3. 现在最明显的问题是什么？是表面症状还是根因问题？
4. 现象背后是否存在更深层次的商业逻辑或结构性约束？
5. 这个问题是否足够重要，能够支撑资源投入和方案推进？
6. 是否已经有足够证据支撑结论，还是仍然停留在假设层面？
7. 结论能否转化为明确行动、优先级和下一步计划？

### 7.1 聚焦原则

### 7.1 聚焦原则
- 抓住主要矛盾
- 关注矛盾的主要方面
- 专题要聚焦在关键突破方向上
- 其他零散需求通过流程管理

### 7.2 取舍原则（十六字方针）
```
去粗取精 → 筛选关键需求
去伪存真 → 识别真实诉求
由此及彼 → 考虑关联影响
由表及里 → 深入根因分析
```

### 7.3 说不的智慧
| 场景 | 处理方式 |
|-----|---------|
| 不在主航道的需求 | 敢于说不 |
| 优先级相对较低的需求 | 在资源受限时说不 |
| 不合理的需求 | 找到更好的办法解决 |

### 7.4 说不的艺术
- 不是否定客户
- 而是找到更好的办法解决客户问题
- 通过为客户创造价值引导客户到产业发展主流方向
- 在拒绝需求的情况下还让客户满意

## 八、方案构想框架

### 8.1 双轮驱动模型
```
市场需求驱动 ←→ 研发能力驱动
        ↓
解决方案构想
```

### 8.2 目标网牵引
- 以目标网牵引方案和研发
- 基于客户视角和市场需求提出解决方案目标
- 避免基于研发能力和技术水平设置目标

### 8.3 极简原则
> 未来的胜利是极简的胜利
> 外部极简单
> 内部极复杂
> 复杂留给自己，方便留给别人
