# 需求洞察方法论

## 核心概念

需求洞察是通过系统化方法识别客户价值转移、发现重大线索和风险，带来确有实据的业务新知，并推动问题解决。

## 如何使用本 Skill

### 适用场景
- 需要进行需求洞察、客户战略分析、市场机会识别、竞争分析或产业趋势判断时
- 适合用于产品规划、解决方案定义、客户访谈、项目立项、策略讨论和选题评估
- 适合在“问题还不够清楚、但决策必须尽快做出”时使用

### 使用前准备
- 明确分析对象：客户、市场、行业、产品线还是竞争对手
- 提供背景信息：业务背景、当前问题、已有数据和约束条件
- 明确目标：是做战略判断、痛点识别、需求提炼，还是输出选题和行动建议

### 输出建议
- 优先输出“结论 — 证据 — 风险 — 建议动作”的结构
- 先给出一页结论，再补充支撑分析与可执行建议
- 对不确定信息要标注假设和风险，而不是伪装成确定结论

### 推荐使用流程
1. 明确分析对象：客户、市场、行业、产品线还是竞争对手。
2. 说明分析目标：是做战略判断、痛点识别、竞争分析、产业趋势判断，还是选题与方案建议。
3. 提供上下文信息：业务背景、现象、已有数据、约束条件和决策目标。
4. 让模型先给出核心判断，再补充证据、风险和行动建议。
5. 对关键结论进行反向质疑，确认其是否足够支撑决策。

### 适合的提问模板
```text
请基于需求洞察方法论，针对[客户/市场/行业/产品]进行分析。
背景：...
目标：...
约束：...
请输出：
1. 关键洞察结论
2. 支撑证据
3. 风险点与假设
4. 建议行动与下一步
```

### 更完整的 Prompt 结构
```text
你现在是一名需求洞察方法论专家。
任务：围绕[客户/市场/行业/产品]进行需求洞察，形成可用于决策的洞察结论。
背景信息：...
分析目标：...
约束条件：...
请遵循以下要求：
1. 先给出一句最核心结论；
2. 用“问题—原因—机会—行动”四层逻辑展开；
3. 只基于给定信息进行分析，不编造数据；
4. 对不确定信息要标注为假设，并说明风险；
5. 最终输出必须包含：结论、证据、风险、建议动作。
```

### 使用示例
```text
输入：
请基于需求洞察方法论，分析某运营商在农村市场拓展的机会。
背景：该运营商在城区市场竞争激烈，农村市场收入占比低，建设成本高。
目标：判断农村市场是否值得持续投入，并给出优先方向。
约束：时间有限，需先输出一页级结论。

期望输出：
1. 一句话结论
2. 关键洞察
3. 支撑证据
4. 风险与假设
5. 建议动作
```

### 输出约束
- 不要只停留在“问题描述”，必须给出“背后的逻辑”与“可执行建议”。
- 不要把所有信息都等同于洞察，必须区分现象、原因、机会和方案。
- 输出要有优先级，区分哪些是短期动作，哪些是中长期布局。
- 如果信息不足，必须明确说明“目前无法确认的部分”和“需要补充的数据”。

### 常见误区
- 把需求洞察等同于“听客户抱怨”——真正的洞察是要识别背后的商业逻辑和根因
- 只看到表面问题，没有追溯到根因和价值转移点
- 过早给出解决方案，缺少足够证据支撑
- 把竞争分析简单等同于差距分析，忽略了对手动机和行业逻辑
- 只做描述，不形成选择和行动建议

### 判断一个洞察是否足够好
- 是否能支撑战略或产品选择，而不只是描述现象
- 是否有明确证据和可验证的推断链条
- 是否能进一步转化为行动、资源配置或选题
- 是否清楚区分“问题、原因、机会、方案”四个层次

## 标准输出模板

当你需要产出洞察结论时，建议按以下结构输出：

```text
1. 一句话结论
   - 用一句话概括最重要的洞察结论

2. 关键洞察
   - 说明客户/市场/行业的真实变化点
   - 说明背后的商业逻辑或结构性原因

3. 支撑证据
   - 列出数据、现象、案例或可验证信息
   - 说明证据与结论之间的关联

4. 风险与假设
   - 识别哪些结论仍有不确定性
   - 标注关键假设和潜在风险

5. 建议动作
   - 给出可执行的下一步建议
   - 明确优先级、目标对象和预期价值
```

## 洞察质量检查表

在完成分析后，可以用以下问题自检：
- 结论是否真正回答了问题，而不只是概述现象？
- 是否区分了“表面问题”和“根因问题”？
- 是否有足够证据支撑主要判断？
- 是否指出了关键变化点、价值转移点或机会窗口？
- 是否能转化为明确的行动建议、优先级和下一步？

## 自我进化与业务适配

这份方法论不应该是静态的模板，而应当根据实际业务持续进化。建议在每次使用后做一次“经验沉淀”，不断补充新的观察维度、行业差异和业务特征。

### 适配原则
- 先理解业务本身，再套用方法论，而不是机械套用模板。
- 同一套方法论在不同行业、不同客户、不同阶段，重点会不同。
- 需要把“通用洞察框架”与“业务特定变量”结合起来。
- 经验越丰富，越应该把方法论变成“可进化的判断体系”，而不是一成不变的套路。

### 进化方式
- 记录每次洞察中哪些维度最有效，哪些维度无效。
- 根据业务反馈补充新的分析维度，例如行业政策、组织机制、采购逻辑、客户预算节奏等。
- 针对不同业务场景，建立自己的“变体框架”，例如：
  - 传统通信业务版
  - 数字化转型业务版
  - 解决方案销售版
  - 产业园区/行业客户版
- 将每次案例中的有效判断提炼为“经验规则”，形成自己的洞察资产。

### 自我更新提示词
```text
请基于本次业务场景，对现有需求洞察方法论进行自我进化与补充。
请分析：
1. 当前业务的特殊性是什么？
2. 哪些原有维度不够适用？
3. 还缺少哪些业务特定维度？
4. 如何把通用方法论调整为更贴近当前业务的版本？
5. 请给出一版可复用的更新后的分析框架。
```

### 业务适配建议
- 在新业务场景中，先做一次“方法论校准”：判断哪些维度必须保留，哪些可以简化。
- 对于成熟业务，重点关注“价值转移”和“竞争博弈”；对于新兴业务，重点关注“产业趋势”和“需求演化”。
- 对于高复杂度客户，除常规维度外，还需增加组织关系、预算机制、决策链条和合作模式等维度。
- 对于解决方案类业务，需把“技术能力”与“客户价值”之间的映射关系纳入分析。

## 四大洞察方向

### 1. 客户战略洞察

**定义**：在深刻理解客户的基础上，洞悉其战略及可能的变化

**分析维度**：
- 经营回顾：市场份额、增长、盈利、资金储备、投资
- 战略回顾：过去三年发布的战略及执行回顾、高层讲话、大事件
- 业务规划：重点业务、核心支撑、组织结构和人员、采购决策和流程

**关键方法**：
- 从客户经营结果识别经营痛点
- 识别客户战略及变化
- 预判客户战略方向改变

### 2. 客户痛点洞察

**定义**：从商业、运营、网络痛点中洞察机会与风险

**分析框架**：
```
看商业：市场份额、单客收入、利润率、投资密度、运营费用占比
看运营：战略方向、盈利能力、业务能力、发展能力、抗风险能力、国际化能力
看网络：S(业务)、P(性能)、A(架构)、C(成本&价值)、E(演进)
```

**核心方法**：
- 标杆对比法：横向对比、纵向对比、业界公开测评
- 围绕客户问题，识别真正问题，构筑竞争力

### 3. 竞争分析洞察

**定义**：对竞争对手整体扫描，寻找自身差距，实现超越领先

**分析内容**：
- 竞争对手战略与财务情况
- 关键战略目标调整信息
- 关键能力与解决方案聚焦
- 营销口径与商业模式

**重要原则**：
- 竞争分析 ≠ 差距分析
- 关键是识别差异点
- 洞察业界解决方案规划背后的动机和逻辑
- 优势领域保持领先，非优势领域寻找差异化领先点

### 4. 产业愿景洞察

**定义**：牵引创新，攀登珠峰的征途中沿途下蛋

**核心理念**：
- 产业愿景是目标，长期牵引产品方向
- 客户需求是驱动，决定实际产品路标
- 追求理想主义的过程中，不断孵化现实主义的产品与解决方案

**方法论**：
- 长期产业愿景和当期商业诉求共同驱动产业发展
- 不断商业变现，不断技术创新，最终实现产业愿景

## 场景化需求洞察方法

### 四步流程

#### 第一步：深入场景

**协同洞察，成立洞察项目**：
- 区域洞察：各有侧重，互锁对齐
- 研发互锁：与研发技术项目沟通，确定研究方向和目标
- 一线调研：与行销、市场代表沟通，从关键项目获取客户现网数据

**深入关键项目，牵引关键需求**：
- 选：选取能牵引规划方向的公司重大项目
- 推：向一线行销传递产品规划策略
- 埋：评审一线行销客户引导材料，预埋产品牵引策略
- 扫：提前识别客户不合理诉求，收敛客户预期
- 识：洞察客户痛点和问题，识别关键信息

**客户明白人互动**：
- 懂客户语言，提前做功课
- 与客户明白人互动，获取真实场景需求及背后故事
- 沟通需求背后的逻辑，知其然更知其所以然

**联合创新项目**：
- 与客户高层沟通，对齐战略目标
- 持续沟通，弄清高层关注点和诉求
- 通过Demo演示不断碰撞，对齐需求和方案

#### 第二步：痛点识别

**关键数据挖掘分析**：
- 项目需求、一线调研、明白人互动
- 调查问卷、咨询报告、网络数据
- 建立模型、量化分析

**刨根问底、根因分析**：
- 从客户视角看客户网络
- 从客户商业结果入手寻找痛点
- 不要只看表面，找出根因
- 客户说的不一定是真实需要的，需深挖背后真实诉求

#### 第三步：需求提炼

**聚焦重点，突破难点**：
- 抓住主要矛盾和矛盾的主要方面
- 不要西瓜芝麻一把抓
- 专题要聚焦在关键突破方向上

**去伪存真，敢于取舍**：
- 十六字方针：去粗取精、去伪存真、由此及彼、由表及里
- 需求管理最难的事情是说不
- 不在主航道的需求要敢于说不
- 不是否定客户，而是找到更好的办法解决客户问题

#### 第四步：方案构想

**双轮驱动**：
- 基于客户视角和市场需求提出解决方案目标
- 避免基于研发能力和技术水平设置目标
- 市场、研发双轮驱动解决方案构想

**目标网牵引**：
- 以目标网牵引方案和研发
- 极简网络驱动方案构想
- 未来的胜利是极简的胜利：外部极简单，内部极复杂

## 洞察选题方法

### 四大洞察方向选题

根据四大洞察方向分析数据/信息进行选题：
- 客户战略洞察专题
- 客户痛点洞察专题
- 竞争分析洞察专题
- 产业愿景洞察专题

### 不同行业阶段侧重

| 行业地位 | 洞察侧重 | 创新驱动 |
|---------|---------|---------|
| 优势产业（领导者） | 产业愿景洞察 | 愿景驱动创新 |
| 追赶型产业（追赶者） | 竞争分析洞察 | 差距驱动创新 |
| 开创型产业（开拓者） | 客户痛点洞察 | 需求驱动创新 |

### 选题原则

**大方向的模糊正确比小细节的精准更为重要**

## 洞察工作组织

### 三种洞察形式

1. **例行洞察**：周期性、持续性的信息收集和分析
2. **热点洞察**：针对突发事件或热点话题的快速响应
3. **深度洞察**：针对重大战略课题的深入研究

### 洞察信息来源

- 项目与合同信息
- 品牌活动信息
- 客户接触记录
- 创新与产品解决方案
- 财务表现数据
- 行业研究报告
- 竞争对手公开信息
