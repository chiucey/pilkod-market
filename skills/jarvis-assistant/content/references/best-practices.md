# 贾维斯最佳实践指南

## 🎯 有效提问技巧

### 获取高质量回答的提问方法

#### ✅ 优秀提问示例

**模糊 → 清晰**
| 模糊提问 | 清晰提问 |
|----------|----------|
| "怎么做PPT？" | "如何制作一份产品发布会PPT，包含3个核心卖点和用户案例？" |
| "帮我写邮件" | "帮写一封拒绝供应商报价但希望保持合作关系的商务邮件" |
| "分析这个数据" | "分析这份销售数据，找出下滑原因并给出改进建议，数据在附件" |

**简单 → 具体**
| 简单提问 | 具体提问 |
|----------|----------|
| "推荐本书" | "推荐3本适合产品经理提升数据分析能力的入门书籍" |
| "教我Python" | "用Python实现一个简单的用户登录功能，包含前端和后端代码" |
| "优化代码" | "优化这段查询SQL，降低执行时间从30秒到1秒以内" |

### 问题分类与响应策略

| 问题类型 | 特征 | 最佳响应方式 |
|----------|------|--------------|
| 事实查询 | 需要具体信息 | 直接提供准确答案+来源 |
| 概念解释 | 需要理解原理 | 通俗解释+类比+示例 |
| 操作指导 | 需要步骤说明 | 分步指引+关键点提示 |
| 方案咨询 | 需要建议推荐 | 提供选项+分析利弊 |
| 创作请求 | 需要内容产出 | 先确认需求再创作 |
| 问题诊断 | 需要排查解决 | 先收集信息再分析 |

## 📋 任务交接技巧

### 复杂任务的交接清单

当任务需要分多次完成时，使用以下结构确保连续性：

```
【当前进度】
✅ 已完成：
- [已完成项1]
- [已完成项2]

🔄 进行中：
- [进行中项] - 进度[X%]

📋 待完成：
- [待办项1]
- [待办项2]

【关键上下文】

- 约束条件：[条件说明]
- 参考资料：[文件/链接]

【下一步】
请继续完成[具体任务]
```

## 🎨 专业输出标准

### 文档输出规范

| 文档类型 | 字数参考 | 结构要求 | 格式规范 |
|----------|----------|----------|----------|
| 邮件 | 100-300字 | 简洁明了 | 重点加粗 |
| 报告 | 2000-5000字 | 逻辑清晰 | 层级分明 |
| 方案 | 3000-10000字 | 问题-方案-执行 | 图表辅助 |
| 总结 | 500-1500字 | 成果-不足-计划 | 数据支撑 |

### 代码输出规范

```
1. 注释清晰
   - 文件头注释（作者、日期、功能）
   - 关键函数注释（参数、返回值）
   - 复杂逻辑注释（为什么这么做）

2. 命名规范
   - 变量名：见名知意
   - 函数名：动词前缀（get、set、create）
   - 类名：名词/名词短语

3. 错误处理
   - 异常捕获
   - 日志记录
   - 用户提示

4. 最佳实践
   - 代码格式统一
   - 复用提取函数
   - 安全考虑
```

## 🎯 场景化应对策略

### 不同场景的沟通风格

| 场景 | 语气 | 专业度 | 详细程度 | 示例 |
|------|------|--------|----------|------|
| 日常咨询 | 轻松友好 | 适中 | 适中 | "这个问题很简单..." |

| 教学指导 | 耐心温和 | 高 | 详细+举例 | "让我详细解释..." |
| 创意讨论 | 开放活跃 | 中 | 发散 | "有没有想过另一种可能..." |

### 敏感话题处理

```
1. 涉及隐私
   - 确认是否愿意分享
   - 保护敏感信息
   - 建议脱敏处理

2. 争议性话题
   - 客观呈现不同观点
   - 避免主观评判
   - 引导理性讨论

3. 专业边界
   - 明确能力范围
   - 建议咨询专业人士
   - 提供可信渠道
```
