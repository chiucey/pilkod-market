# Python 项目深度分析器

## 核心能力

本技能提供对大型 Python 项目的全面解读与分析服务，涵盖项目结构解析、代码功能解释、实现细节追踪、函数调用链分析、程序修改建议以及代码质量检查等功能。

### 1. 项目结构分析

#### 1.1 目录结构解析
通过文件系统扫描获取项目的完整目录树结构，识别以下关键要素：

- **源代码目录**：定位 `src/`、`lib/`、`app/` 等包含主要业务逻辑的目录
- **包与模块组织**：分析 `__init__.py` 文件确定 Python 包的边界和层级关系
- **配置文件**：识别 `setup.py`、`pyproject.toml`、`setup.cfg`、`requirements.txt`、`Pipfile` 等项目配置
- **测试目录**：定位 `tests/`、`test_*.py`、`*_test.py` 等测试文件和目录
- **文档目录**：查找 `docs/`、`README.md`、`CHANGELOG.md` 等文档资源

#### 1.2 依赖关系分析
解析项目依赖的外部库和内部模块，建立依赖图谱：

```python
# 依赖分析结果示例
{
    "external": ["requests", "numpy", "pandas", "fastapi"],
    "internal": {
        "src.utils": ["src.config", "src.exceptions"],
        "src.api": ["src.models", "src.services"]
    }
}
```

### 2. 代码功能解释

#### 2.1 函数与类解析
对指定函数或类进行深度分析，包括：

- **函数签名**：参数类型、默认值、返回值类型注解
- **文档字符串**：提取并解释 docstring 中的使用说明
- **实现逻辑**：分析函数体内部的算法逻辑和业务规则
- **使用示例**：从代码库中查找该函数的调用示例

#### 2.2 模块功能概述
提供模块级别的功能描述，帮助理解代码的组织方式和职责划分：

- 模块导入路径和导出接口
- 模块内部各组件的关系
- 模块在整个项目中的角色定位

### 3. 实现细节追踪

#### 3.1 函数调用链分析
追踪函数的完整调用路径，从调用者到被调用者：

- 静态分析：解析代码结构确定调用关系
- 动态追踪：识别回调函数、异步调用、条件分支等复杂调用场景
- 调用图生成：构建可视化的函数调用关系图

#### 3.2 数据流分析
跟踪变量和数据的传递路径：

- 变量的定义位置和初始化方式
- 数据的转换和处理过程
- 返回值的传递和使用

### 4. 网络资源辅助

#### 4.1 Python 官方文档查询
利用网络搜索获取 Python 标准库和常用第三方库的官方文档：

- 内置函数和内置类型的详细说明
- 标准库模块的 API 参考
- 第三方库的官方文档和教程

#### 4.2 GitHub 资源搜索
在 GitHub 上搜索相关项目的实现参考：

- 相似功能的实现方式
- 最佳实践和设计模式
- 开源项目的代码示例

### 5. 功能解读工作流

```
用户请求 → 确定分析范围 → 收集代码信息 → 整合网络资源 → 生成分析报告
```

#### 5.1 分析请求分类
根据用户请求类型采用不同的分析策略：

| 请求类型 | 分析重点 | 输出格式 |
|---------|---------|---------|
| 结构分析 | 目录树、模块关系、依赖图 | 结构图 + 说明文档 |
| 功能解释 | 函数/类作用、参数说明、使用场景 | 解释性文档 + 示例代码 |
| 实现追踪 | 调用链、数据流、控制流 | 调用图 + 流程说明 |
| 修改建议 | 代码审查、改进方案、实施步骤 | 修改方案 + 代码 diff |

#### 5.2 信息整合流程
1. **本地代码分析**：读取和分析项目源代码
2. **文档查询**：搜索 Python 官方文档和社区资源
3. **结果整合**：将代码分析和网络资源相结合
4. **输出生成**：生成结构化的分析报告

### 6. 函数调用分析

#### 6.1 调用关系提取
分析函数之间的调用关系，包括：

- 直接调用：函数 A 中直接调用函数 B
- 间接调用：通过回调、装饰器、钩子等间接调用
- 条件调用：根据条件判断选择性地调用
- 循环调用：递归调用或循环中的调用

#### 6.2 调用深度计算
计算函数调用的深度层级：

```python

    """计算函数调用深度"""
    if visited is None:
        visited = set()
    if func in visited:
        return depth
```

### 7. 程序修改

#### 7.1 修改类型识别
根据需求确定合适的修改类型：

- **功能增强**：添加新功能或扩展现有功能
- **性能优化**：改进算法复杂度、减少资源消耗
- **代码重构**：改善代码结构和可维护性
- **错误修复**：修复已知的 bug 或异常处理

#### 7.2 修改流程
1. **影响分析**：评估修改对其他模块的影响
2. **方案设计**：制定详细的修改方案
3. **代码实现**：执行代码修改
4. **测试验证**：确保修改的正确性

#### 7.3 修改原则
- 最小化修改范围，只改动必要的代码
- 保持代码风格一致性
- 添加必要的注释和文档
- 确保向后兼容性

### 8. 程序检查

#### 8.1 静态代码检查
进行代码质量分析：

- **语法检查**：确保代码符合 Python 语法规范
- **类型检查**：验证类型注解的正确性
- **风格检查**：遵循 PEP 8 等代码规范
- **安全检查**：识别潜在的安全漏洞

#### 8.2 常用检查工具
集成以下代码检查工具的支持：

- **Pylint**：全面的代码分析
- **Flake8**：代码风格和语法检查
- **MyPy**：静态类型检查
- **Black**：代码格式化
- **Bandit**：安全漏洞扫描

#### 8.3 检查报告生成
输出结构化的检查报告：

```python
{
    "summary": {
        "total_issues": 15,
        "errors": 2,
        "warnings": 5,
        "info": 8
    },
    "issues": [
        {
            "file": "src/main.py",
            "line": 42,
            "severity": "error",
            "message": "未使用的导入语句",
            "code": "W0611"
        }
    ]
}
```

## 使用方法

### 基本分析命令

| 功能 | 命令示例 | 说明 |
|------|---------|------|
| 分析项目结构 | "分析这个项目的目录结构" | 扫描并展示项目组织方式 |
| 解释函数功能 | "解释 main.py 中的 process_data 函数" | 提供函数的详细说明 |
| 追踪调用链 | "追踪 get_user 函数的调用路径" | 展示函数的完整调用链 |
| 代码审查 | "检查项目中的代码质量问题" | 运行静态检查并生成报告 |
| 修改建议 | "如何优化这个查询函数" | 提供优化方案和实现 |

### 搜索辅助命令

| 功能 | 命令示例 | 说明 |
|------|---------|------|
| 查文档 | "查找 FastAPI 路由装饰器的用法" | 搜索官方文档 |
| 看示例 | "找一些 Python 异步编程的示例" | 搜索 GitHub 代码示例 |
| 理解模式 | "这个项目用的什么设计模式" | 分析并解释使用的设计模式 |

## 输出格式

分析结果将以结构化的 Markdown 格式呈现，包含以下部分：

1. **概述**：分析目标的简要说明
2. **详细分析**：具体的技术分析和解释
3. **代码示例**：相关的代码片段和示例
4. **建议与结论**：改进建议和总结
5. **参考资料**：相关的网络资源链接

## 注意事项

- 对于大型项目，优先分析用户指定的核心模块
- 网络资源搜索会优先使用 Python 官方文档和热门 GitHub 仓库
- 代码修改前会先征求用户确认
- 检查报告按严重程度分类，便于优先级处理
