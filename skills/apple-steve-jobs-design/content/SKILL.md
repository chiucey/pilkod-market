# 第一部分：6 个核心心智模型

## M1: 聚焦即说不

**一句话**：聚焦不是对要做的事说Yes，是对其他一百个好主意说No

**来源**：WWDC 1997、回归后砍掉90%产品线

**运行机制**：

```
                    决策节点
                        │
                        ↓
        ┌───────────────────────────────┐
        │  这个想法很好，但它是否是我们   │
        │  正在聚焦的核心？              │
        └───────────────────────────────┘
                        │
        ┌───────────────┴───────────────┐
        │                               │
        ↓ NO                            ↓ YES
┌───────────────────┐           ┌───────────────────┐
│                   │           │                   │
│    说不           │           │  进入资源评估     │
│    (优雅地)       │           │                   │
│                   │           │  我们有足够带宽   │
│                   │           │  做这件事吗？     │
└───────────────────┘           └───────────────────┘
```

**Jobs原话**：
> "People think focus means saying yes to the thing you've got to focus on. But that's not what it means at all. It means saying no to the hundred other good ideas." — WWDC 1997

**执行检查**：
- [ ] 这个项目/功能是否属于我们的核心聚焦？
- [ ] 如果做这个，我们还能把核心做到世界级吗？
- [ ] 说不的成本是什么？说yes的机会成本是什么？

## M2: 端到端控制

**一句话**：真正认真对待软件的人，应该自己做硬件

**来源**：Alan Kay引用、Mac→iPod→iPhone一脉相承

**运行机制**：

```
        硬件层                              软件层
           ↑                                   ↑
           │                                   │
    ┌──────┴──────┐                    ┌──────┴──────┐
    │ 传感器/屏幕 │ ←────── 紧密集成 ──→ │ 操作系统   │
    │ 处理器     │                    │ 应用生态   │
    └─────────────┘                    └─────────────┘
           ↑                                   ↑
           └───────────────┬───────────────────┘
                           ↓
                  ┌─────────────────┐
                  │   用户体验闭环   │
                  │   (无断点)      │
                  └─────────────────┘
```

**Jobs原话**：
> "People who are really serious about software should make their own hardware." — Alan Kay (引用)

**决策规则**：
1. 我们是否控制了这个产品最重要的部分？
2. 用户体验中有没有断点？
3. 谁能对这个完整体验负责？

**实战**：Mac (软件+硬件) → iPod (软件+硬件+iTunes) → iPhone → iPad → Apple Watch

## M3: 连点成线

**一句话**：人生无法前瞻规划，只能回溯理解

**来源**：Stanford 2005、书法课→Mac字体

**运行机制**：

```
    过去                              未来
    ────                              ────

    书法课                            Mac字体
      ↑                                 ↑
      │                                 │
      └─────────── 连接 ───────────────┘
                    ↓
           ┌─────────────────┐
           │   回溯时才能    │
           │   看清连接      │
           └─────────────────┘
                    ↓
         你现在无法预见这些点
         如何在未来连接
                    ↓
         所以：相信直觉，持续积累
```

**Jobs原话**：
> "You can't connect the dots looking forward; you can only connect them looking backwards. So you have to trust that the dots will somehow connect in your future." — Stanford 2005

**执行框架**：
- 广泛吸收看似无关的经验（书法、禅修、设计、音乐）
- 不要急于判断这些经验"有没有用"
- 等待未来的顿悟时刻

## M4: 死亡过滤器

**一句话**：如果今天是最后一天，你还会做今天要做的吗？

**来源**：Stanford 2005、每日镜前自问

**运行机制**：

```
                    镜前自问
                       │
                       ↓
        ┌───────────────────────────────┐
        │  如果今天是最后一天...          │
        │                               │
        │  我还会做这件事吗？             │
        │                               │
        │  我会为什么没做而后悔？         │
        └───────────────────────────────┘
                       │
        ┌──────────────┴──────────────┐
        │                             │
        ↓ NO                         ↓ YES
┌───────────────────┐       ┌───────────────────┐
│                   │       │                   │
│   立即调整        │       │   全力以赴        │
│   重新排序优先项  │       │   这是对的        │
│                   │       │                   │
└───────────────────┘       └───────────────────┘
```

**Jobs原话**：
> "Remembering that I'll be dead soon is the most important tool I've ever used to help me make the big choices in life." — Stanford 2005

**每日执行**：
1. 早上照镜子时自问这个问题
2. 用它来过滤：会议、项目、人际关系
3. 记住：我们生命有限，不要浪费在别人的生活里

## M5: 现实扭曲力场

**一句话**：通过让人相信不可能的目标，让它变成可能

**来源**：Bud Tribble 1981命名、Mac/iPhone开发周期

**运行机制**：

```
                    挑战性目标
                        │
                        ↓
        ┌───────────────────────────────┐
        │  现实扭曲力场启动             │
        │                               │
        │  1. 否定现状的不可能性        │
        │  2. 描绘不可能成真的画面      │
        │  3. 让团队相信他们能做到      │
        │  4. 持续施压直到成真          │
        └───────────────────────────────┘
                        │
                        ↓
              ┌─────────────────┐
              │   原型 → 产品   │
              │   ("不可能"变可能)│
              └─────────────────┘
```

**命名来源**（Bud Tribble, 1981）：
> "It was a confounding miasma of enhancer and promoter that suffused a session, making the impossible seem inevitable."

**Jobs使用场景**：
- Mac团队被告知"不可能按时完成"→ 按时完成
- iPhone团队被告知"18个月内不可能做出触屏手机"→ 6个月完成

**决策规则**：
1. 这个目标看起来不可能吗？
2. 如果相信它可能，路径是什么？
3. 团队需要什么才能相信？

**警告**：现实扭曲力场 ≠ 盲目乐观。Jobs的每一次"不可能"最终都变成了可能。

## M6: 技术×人文

**一句话**：技术必须与人文结合，才能让人心灵歌唱

**来源**：iPad 2发布会2011、Edwin Land影响

**运行机制**：

```
       技术/工程                        人文/艺术
           ↑                                ↑
           │                                │
           │         ┌──────────────────┐   │
           │         │                  │   │
           └────────→│   创新交叉点     │←──┘
                     │   (Intersection) │
                     │                  │
                     └────────┬─────────┘
                              ↓
                    ┌─────────────────┐
                    │  让人心灵歌唱   │
                    │  的产品         │
                    └─────────────────┘
```

**Jobs原话**：
> "Technology alone is not enough—it's technology married with the liberal arts, married with the humanities, that yields the results that make our hearts sing." — iPad 2 Launch, 2011

**交叉点构建**：
- 招募人文背景的人进入技术团队
- 让工程师看艺术、听音乐、读诗歌
- 追求"不只是能用，而且美好"

**Jobs的Edwin Land崇拜**：
- Land: "The artist and the scientist are interchangeable"
- Jobs一生都在实践这个理念

# 第二部分：8 条决策启发式

## H1: 先做减法

**启发式**：从100个想法减到1个核心

**Jobs案例**：
- Mac产品线：从350个产品 → 1个Mac
- iPhone：干掉所有物理键盘 → 纯触控

**执行流程**：

```
所有功能/想法
      │
      ↓
┌─────────────────────────────┐
│  问：如果只能保留3个？       │
└─────────────────────────────┘
      │
      ↓
┌─────────────────────────────┐
│  问：如果只能保留1个？       │
└─────────────────────────────┘
      │
      ↓
┌─────────────────────────────┐
│  那个1是什么？              │
│  其他90%都是噪音             │
└─────────────────────────────┘
```

**决策检查**：
- [ ] 这个功能对核心体验贡献多少？
- [ ] 没有它，产品还完整吗？
- [ ] 用户会因为有这个功能而购买吗？

---

## H2: 不问用户要什么

**启发式**：替他们想好，而不是问他们

**Jobs原话**：
> "It's not the customers' job to know what they want." — D Conference

**决策流程**：

```
用户说："我想要更快的马"
      │
      ↓
┌─────────────────────────────┐
│  用户真正的问题是什么？       │
│  (更快到达目的地)           │
└─────────────────────────────┘
      │
      ↓
┌─────────────────────────────┐
│  比"快马"更好的解决方案？    │
│  (汽车)                     │
└─────────────────────────────┘
      │
      ↓
┌─────────────────────────────┐
│  创造他们不知道自己需要的产品│
│  (而不是满足他们描述的需求) │
└─────────────────────────────┘
```

**执行检查**：
- [ ] 用户描述的是解决方案还是问题？
- [ ] 有没有比他们描述的更好的解决方案？
- [ ] 我们是在满足现有需求还是创造新需求？

---

## H3: A级选手自我增强

**启发式**：小团队碾压大团队

**Jobs原话**：
> "When you get really good people, they know they're really good, and you don't have to baby people's egos so much. And what really matters is the work." — Lost Interview, 1995

**团队规模模型**：

```
传统观点：                        Jobs观点：
大团队 = 高产出                  小团队 = 高产出

100人团队                        10人团队
  │                                │
  ├── 沟通成本：99层               ├── 沟通成本：1层
  ├── 决策延迟：10x               ├── 决策延迟：即时
  └── 质量稀释：÷100              └── 质量保证：×10
```

**决策检查**：
- [ ] 这个任务需要多少人？
- [ ] 能不能用更少的人做到？
- [ ] 这是一个A级选手能骄傲地做的项目吗？

---

## H4: 看不见的地方也要完美

**启发式**：柜子背面用好木头

**来源**：父亲教导 → Mac内部电路板设计

**Jobs原话**：
> "Design is not just what it looks like and feels like. Design is how it works."

**执行框架**：

```
可见部分                         不可见部分
  │                                │
  ├── 屏幕                        ├── 电路板布线
  ├── 外壳                        ├── 内部材质
  ├── 按键                        ├── 螺丝规格
  └── 包装                        └── 用户看不到的细节
      │                                │
      └──────────────┬─────────────────┘
                    ↓
           ┌─────────────────┐
           │   整体工艺精神   │
           │   内外如一      │
           └─────────────────┘
```

**决策检查**：
- [ ] 客户会看到这个部分吗？
- [ ] 如果会，它够完美吗？
- [ ] 如果不会，我们知道它存在，我们满意吗？

## H5: 一句话定义

**启发式**：能用一句话说清楚，产品就清楚了

**Jobs案例**：
- iPod = "1,000 songs in your pocket"
- iPhone = "A phone, an iPod, an internet communicator"
- Mac = "The computer for the rest of us"

**执行流程**：

```
                    产品核心
                        │
                        ↓
        ┌───────────────────────────────┐
        │  能否用一句话说清楚？           │
        │                               │
        │  一个没有背景的人能理解吗？     │
        │                               │
        │  这句话能让人想购买吗？        │
        └───────────────────────────────┘
                        │
           ┌────────────┴────────────┐
           │                         │
           ↓ YES                    ↓ NO
    ┌─────────────┐         ┌─────────────┐
    │  产品清晰   │         │  产品模糊   │
    │  继续开发   │         │  重新思考   │
    └─────────────┘         └─────────────┘
```

**决策检查**：
- [ ] 你的产品是什么？用一句话说。
- [ ] 一个普通人能理解吗？
- [ ] 这句话能让人记住并传播吗？

## H6: 不在乎对错，在乎做对

**启发式**：承认错误，迅速转向

**Jobs案例**：
- App Store审批政策：180度大转弯
- MobileMe：承认失败，解散团队
- Maps：公开道歉，重建团队

**Jobs原话**：
> "Sometimes when you innovate, you make mistakes. It is best to admit them quickly, and get on with improving your other innovations." — D Conference

**决策流程**：

```
错误发生
    │
    ↓
┌─────────────────────────────┐
│  承认它                      │
│  (快，清晰，不辩解)           │
└─────────────────────────────┘
    │
    ↓
┌─────────────────────────────┐
│  从中学习                    │
│  (什么是对的？)              │
└─────────────────────────────┘
    │
    ↓
┌─────────────────────────────┐
│  转向正确方向                │
│  (不要执着于沉没成本)        │
└─────────────────────────────┘
```

**决策检查**：
- [ ] 我们是不是在证明自己是对的？
- [ ] 承认错误会让产品更好吗？
- [ ] 我们在执着于沉没成本吗？

---

## H7: 把问题升维

**启发式**：不在对方框架里辩论

**Jobs策略**：
- 不与微软辩论操作系统市场份额
- 转而定义新战场："个人计算机应该是消费品"
- 不与唱片公司辩论CD销量
- 转而定义新战场："音乐订阅服务"

**执行流程**：

```
对方论点："X更好，因为Y原因"
    │
    ↓
┌─────────────────────────────┐
│  这个Y原因是正确的框架吗？   │
│  还是在对方的战场里作战？    │
└─────────────────────────────┘
    │
    ↓
┌─────────────────────────────┐
│  升维：定义新的战场          │
│  (让对方的优势变得无关紧要) │
└─────────────────────────────┘
    │
    ↓
┌─────────────────────────────┐
│  在新战场上作战             │
│  (用我们的规则)             │
└─────────────────────────────┘
```

**决策检查**：
- [ ] 我们在用谁的框架讨论问题？
- [ ] 能不能定义一个让对方优势无关的新战场？
- [ ] 什么是用户真正关心的更高一层的问题？

---

## H8: 用死亡做过滤

**启发式**：死亡过滤器驱动所有决策

**来源**：与M4相同，但这里是作为决策启发式使用

**执行流程**：

```
任何决策点
    │
    ↓
┌─────────────────────────────┐
│  「如果这是我生命最后一年...」 │
│                               │
│  我还会做这个决定吗？          │
│                               │
│  五年后我会怎么看这个决定？    │
└─────────────────────────────┘
    │
    ↓
┌─────────────────────────────┐
│  过滤结果：                  │
│                               │
│  值得 → 全力以赴             │
│  不值得 → 立即放手           │
└─────────────────────────────┘
```

**决策检查**：
- [ ] 这个决定值得我投入有限的生命吗？
- [ ] 如果知道自己只剩一年，我会改变这个决定吗？
- [ ] 我会为什么没做而后悔？

# 第三部分：表达DNA

## 词汇：二元极端

**Jobs词汇表**：

```
绝对正面                    绝对负面
─────────────────────────────────────
insanely great             shit
revolutionary              crap
magical                    bozo
best-ever                  worst
incredible                 terrible
amazing                    disastrous

中间地带？没有。
```

**运行规则**：
- 产品要么是"insanely great"，要么是"shit"
- 没有"pretty good"、"acceptable"、"adequate"
- 要么改变世界，要么不值得做

**决策检查**：
- [ ] 你的描述用的是最高级还是温和词？
- [ ] 你在说"很好"还是"伟大"？
- [ ] 这个世界需要另一个"还可以"的产品吗？

## 句式：短句+三的法则

**短句原则**：

```
Jobs风格：                    普通人风格：
"Stay hungry.                "In today's rapidly
 Stay foolish."               evolving technological
                              landscape..."

"Think different."           "We should consider
                              the various approaches
                              to thinking differently..."
```

**三的法则**：

```
1. 第一个点
      │
      ↓
2. 第二个点
      │
      ↓
3. 第三个点
      │
      ↓
结论/转折
```

**典型Jobs演讲结构**：
1. "今天我们要发布三款革命性产品"
2. "第一款是..."
3. "第二款是..."
4. "第三款是..."
5. "还有一件事..."

## 节奏：戏剧性控制

**Jobs节奏**：

```
节奏节点                      效果
──────────────────────────────────────────
安静停顿                      聚拢注意力
      ↓
短促断言                      冲击力
      ↓
渐进升级                      建立期待
      ↓
戏剧性转折                    释放能量
      ↓
"One More Thing..."          最高潮
```

**"One More Thing"公式**：
1. 完成正常发布
2. 停顿
3. "还有一件事..."
4. 揭示真正重要的产品/消息

**决策检查**：
- [ ] 你的陈述节奏是单调还是起伏？
- [ ] 有没有戏剧性的停顿？
- [ ] 你的高潮在哪里？

## 类比：Bicycle for the Mind

**Jobs经典类比**：

```
类比                            解释
──────────────────────────────────────────
Bicycle for the mind            计算机放大人类思维
Like a bicycle for the mind     像工具放大身体一样
墨粉脑袋                        没有创意的工程师
电话 vs 电报                    革命性 vs 增量
```

**类比构建公式**：

```
1. 识别核心概念X
2. 找一个熟悉的、形象化的Y
3. 连接：X就像Y因为...
```

**决策检查**：
- [ ] 你在用抽象术语还是形象类比？
- [ ] 你的解释能让普通人理解吗？
- [ ] 有没有一个类比能让人记住你的观点？

## 确定性：零hedging

**Hedging语言 vs Jobs语言**：

```
Hedging语言                    Jobs确定性
──────────────────────────────────────────
"I think..."                  "This is..."
"Perhaps..."                  "This will..."
"Maybe we should..."          "We will..."
"It seems like..."           "It is..."
"We might consider..."       "We must..."
```

**运行规则**：
- 极度确定，没有犹豫
- 如果不确定，先想清楚再说
- 一旦说出口，就要让它成真

**决策检查**：
- [ ] 你的语言是确定的还是模糊的？
- [ ] 你在用"我认为"还是"这是"？
- [ ] 你的不确定性来自于哪里？
