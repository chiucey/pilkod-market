# 源码深度架构分析技能

## 技能概述

本技能按照资深架构师标准，结合《软件工程》《人月神话》《软件测试》等经典教材理论，对源码进行结构化、工程化分析，并从 Michael Polanyi 内在知识角度分析不同水平开发者的学习路径。

## 核心工作流程

### 阶段一：项目信息收集

当用户触发此技能时，首先通过交互式表单收集以下关键信息：

**必须收集的信息：**
1. 源码语言类型（如：C/C++、Java、Python、Go、Rust、TypeScript 等）
2. 语言版本（如：C++17、Python 3.11、Go 1.21 等）
3. 目标运行平台（如：Linux x86_64、Windows、macOS、嵌入式 ARM 等）
4. 编译工具链（如：GCC、Clang、CMake、Maven、npm、cargo 等）

**信息收集方式：**
使用 GenUI 表单向用户收集上述信息，确认后开始分析。

### 阶段二：整体分析

按照以下框架执行企业级深度分析：

1. **业务功能**：实现什么场景？核心价值？
2. **技术栈与依赖**：语言、框架、库、构建方式、操作系统、工具链
3. **整体架构**：模式（MVC/分层/DDD/微服务等）
4. **模块职责与边界**是否清晰
5. **整体数据流与执行链路**
6. **代码质量**：可读性、重复代码、规范
7. **性能与资源消耗**
8. **并发安全与线程风险**
9. **异常处理与可靠性**
10. **可观测性**（日志、监控、排错友好度）
11. **安全风险**（硬编码、注入、权限、输入校验）
12. **可维护性与扩展性**，新功能开发的成本
13. **可测试性**

### 阶段三：模块/函数深度分析

对每个关键模块执行以下分析：

1. **职责定位**
2. **输入与输出**（约束、空值、格式）
3. **核心执行流程**（步骤化）
4. **分支逻辑与条件复杂度**
5. **数据结构与算法效率**
6. **设计模式使用**是否合理
7. **封装、抽象、接口稳定性**
8. **依赖关系与耦合度**
9. **并发与线程安全**
10. **异常与边界用例覆盖**
11. **白盒可测试性**
12. **代码坏味道**

### 阶段四：学习曲线分析（Michael Polanyi 视角）

从内在知识与技能习得角度分析：

**初学者视角：**
- 应关注的入口点和基础领域
- 核心概念的最低门槛
- 实践练习的推荐路径

**熟练者视角：**
- 应深入的关键模块
- 工程实践的观察重点
- 常见陷阱与最佳实践

**专家视角：**
- 架构决策的权衡分析
- 系统演进方向的判断
- 优化与重构的核心领域

### 阶段五：总结与建议

1. **优点总结**
2. **主要问题**（按优先级排列）
3. **具体可落地的重构/优化方案**
4. **上手指南**（分初学者、熟练者、专家）

## 输出格式规范

分析结果必须按以下目录与文件格式输出 Markdown：

```
docs/模块名/
├── 00_项目综述.md
├── 01_XXX模块分析.md
├── 02_XXX模块分析.md
├── ...依次递增
├── 98_优化方案.md
└── 99_使用指南.md
```

**内容要求：**
- 专业、严谨、可落地
- 不泛泛而谈，有具体数据和案例支撑
- 按综述-模块-总结的总分总格式组织
- 必要时拆分多个文档形成系列报告

## 执行原则

1. **严格按框架执行**：不省略任何分析项
2. **引用经典理论**：结合软件工程、人月神话等经典
3. **关注学习曲线**：从初学者到专家的分层指导
4. **可操作性优先**：所有建议必须可落地执行
