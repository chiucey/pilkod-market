# 服务设计方法论详解

## A. 双钻石模型深度解读

### 阶段详解

#### 1. Discover (发现)

**核心目标**：理解用户、发现机会

**方法**：

| 方法 | 说明 | 样本量建议 |
|------|------|------------|
| 深度访谈 | 一对一深入交流 | 8-15人 |
| 焦点小组 | 小组讨论激发洞察 | 4-6组 |
| 民族志观察 | 实地观察用户行为 | 持续2-4周 |
| 影子跟随 | 全程跟随用户工作 | 3-5人 |
| 日记研究 | 用户自记录使用过程 | 10-20人 |

**输出标准**：
- 访谈记录完整转录
- 行为模式归纳
- 关键洞察提炼（3-5个核心发现）
- 原始数据存档

#### 2. Define (定义)

**核心目标**：聚焦问题、明确方向

**方法**：

| 方法 | 说明 | 产出 |
|------|------|------|
| 亲和图 | 访谈数据归纳分类 | 主题聚类 |
| 5Why 分析 | 层层追问根本原因 | 问题根因 |
| How-Might-We | 问题转化为设计机会 | 设计问题 |
| 问题陈述 | 简洁定义设计挑战 | 问题声明 |

**问题陈述模板**：
```
对于 [目标用户]，
谁在 [使用场景] 中遇到了 [问题/需求]，
我们可以通过 [设计方向] 来 [期望结果]，
同时 [约束条件]。
```

#### 3. Develop (发展)

**核心目标**：生成方案、验证假设

**方法**：

| 方法 | 说明 | 适用阶段 |
|------|------|----------|
| 头脑风暴 | 大量创意发散 | 早期 |
| 6-3-5 法 | 结构化发散 | 团队协作 |
| 角色扮演 | 模拟服务场景 | 概念验证 |
| 故事板 | 可视化服务流程 | 沟通展示 |
| 低保真原型 | 快速制作体验原型 | 测试迭代 |
| A/B 测试 | 方案对比验证 | 方案选择 |

**原型分级**：

| 等级 | 形式 | 用途 | 制作时间 |
|------|------|------|----------|
| L1 | 纸质原型 | 概念验证 | 1-2小时 |
| L2 | 数字线框图 | 流程验证 | 1-2天 |
| L3 | 可交互原型 | 体验测试 | 1-2周 |
| L4 | 功能原型 | 完整测试 | 2-4周 |

#### 4. Deliver (交付)

**核心目标**：落地实施、持续优化

**产出**：

| 产出 | 内容 | 接收方 |
|------|------|--------|
| 设计规范 | 视觉/交互/内容标准 | 开发/运营 |
| 服务蓝图 | 完整服务流程图 | 全团队 |
| 培训材料 | SOP、操作指南 | 服务人员 |
| 上线计划 | 实施路径、里程碑 | 项目管理 |
| 评估指标 | KPI、监测方案 | 运营/数据 |

## B. 服务蓝图进阶指南

### 蓝图层级详解

```
┌────────────────────────────────────────────────────────────────┐
│                        物理证据层                               │
│  (Physical Evidence) - 环境、道具、文档、设施                   │
├────────────────────────────────────────────────────────────────┤
│                        顾客行为层                               │
│  (Customer Actions) - 用户完成的系列活动                        │
├─────────────── ────────────────────────────────────────────────┤
│   ↑ 可见线 (Line of Visibility)                                │
├────────────────────────────────────────────────────────────────┤
│                      前台服务层                                │
│  (Frontstage) - 用户可见的接触点                                │
├────────────────────────────────────────────────────────────────┤
│                      后台服务层                                │
│  (Backstage) - 支持前台的服务活动                               │
├────────────────────────────────────────────────────────────────┤
│                      支持流程层                                │
│  (Support Processes) - IT/HR/采购等内部支持                     │
└────────────────────────────────────────────────────────────────┘
```

### 蓝图绘制步骤

1. **识别服务场景**：确定服务范围和边界
2. **识别顾客行为**：用户完成的主要任务
3. **映射前台触点**：用户可见的服务动作
4. **映射后台支持**：支持前台的后台活动
5. **添加支持流程**：内部系统、合作伙伴
6. **添加证据层**：环境、材料、数字界面
7. **识别等待点和失败点**：潜在问题区域
8. **添加时间线**：各环节耗时估算

### 蓝图应用场景

| 场景 | 应用方式 |
|------|----------|
| 新服务设计 | 从顾客行为逆向推导 |
| 服务优化 | 对比 As-Is 和 To-Be |
| 跨部门协调 | 统一服务认知 |
| 服务人员培训 | SOP 制定依据 |
| 问题诊断 | 定位服务断点 |

## C. 用户旅程图绘制规范

### 旅程图类型

| 类型 | 说明 | 适用场景 |
|------|------|----------|
| 当前状态 (As-Is) | 描述现有体验 | 问题诊断 |
| 未来状态 (To-Be) | 规划理想体验 | 目标设定 |
| 期望状态 (Could-Be) | 探索可能方向 | 创新设计 |
| 服务蓝图结合 | 融入前后台视角 | 深度分析 |

### 绘制标准要素

| 要素 | 说明 | 必填 |
|------|------|------|
| 阶段 (Phase) | 体验的主要分段 | ✓ |
| 触点 (Touchpoint) | 用户接触的服务点 | ✓ |
| 行为 (Action) | 用户具体行为 | ✓ |
| 想法 (Thought) | 用户内心的想法 | ✓ |
| 情感 (Emotion) | 用户情感变化 | ✓ |
| 痛点 (Pain Point) | 问题和不满意 | ✓ |
| 机会 (Opportunity) | 改进和创新点 | ✓ |
| 渠道 (Channel) | 接触的渠道 | ○ |
| 负责部门 (Owner) | 对应部门 | ○ |

### 情感量化方法

```
情感分值标准 (1-10分)
─────────────────────────────
10-9  极度兴奋、惊喜
8-7   满意、愉悦
6-5   中性、无感
4-3   不适、困惑
2-1   沮丧、愤怒
─────────────────────────────
```

## D. 服务设计工作坊模板

### 标准工作坊流程 (2小时)

| 时间 | 模块 | 内容 | 产出 |
|------|------|------|------|
| 0-10min | 开场 | 目标介绍、角色分配 | 共识 |
| 10-30min | 回顾 | 调研发现分享 | 洞察 |
| 30-60min | 发散 | 头脑风暴设计机会 | 创意 |
| 60-90min | 收敛 | 方案评估与选择 | 优先级 |
| 90-110min | 深挖 | 选定方案细化 | 原型 |
| 110-120min | 总结 | 下一步计划 | 行动 |

### 常用工作坊技术

| 技术 | 人数 | 时长 | 目的 |
|------|------|------|------|
| 头脑风暴 | 5-8人 | 30-60min | 创意发散 |
| 6-3-5写作 | 6人 | 30min | 深度发散 |
| 卡片分类 | 4-10人 | 45-60min | 信息组织 |
| 角色扮演 | 5-10人 | 30-45min | 体验验证 |
| 快速原型 | 3-6人 | 60-90min | 方案具象化 |

## E. 常见问题与解答

### Q1: 服务设计与 UX 设计的区别？

| 维度 | 服务设计 | UX 设计 |
|------|----------|----------|
| 视角 | 整体组织视角 | 产品/界面视角 |
| 范围 | 端到端全链路 | 特定数字产品 |
| 产出 | 服务流程、组织变革 | 界面、交互、体验 |
| 关注 | 人、流程、证据 | 任务、效率、易用 |

### Q2: 如何处理利益相关方冲突？

1. **利益相关方地图**：识别所有相关方及其利益诉求
2. **冲突点清单**：列出各方的分歧点
3. **优先级矩阵**：按「影响力」和「关注度」分类
4. **协商策略**：对高影响力高关注度方重点协调
5. **用户价值优先**：当冲突无法调和时，以用户价值为准

### Q3: 如何衡量服务设计效果？

| 指标类型 | 指标 | 测量方式 |
|----------|------|----------|
| 体验指标 | NPS、满意度 | 问卷调查 |
| 行为指标 | 转化率、留存率 | 数据分析 |
| 效率指标 | 服务时间、错误率 | 流程监控 |
| 成本指标 | 服务成本、客户获取成本 | 财务数据 |
