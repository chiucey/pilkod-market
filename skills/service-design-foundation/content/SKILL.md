# 服务设计基础 (Service Design Foundation)

## 核心理念

**Max-De$ign 主张：要么设计，要么被设计。**

服务设计是系统性的设计方法，通过优化服务提供者与用户之间的交互，创造有价值、一致且连贯的服务体验。

---

## 1. 服务设计五项原则

| 原则 | 说明 | 设计要点 |
|------|------|----------|
| **以用户为中心** | 服务设计始终从用户需求出发 | 用户研究、 persona 构建、需求洞察 |
| **共创协作** | 利益相关方共同参与设计过程 | 工作坊、访谈、协同创作 |
| **整体性思维** | 将服务视为完整系统 | 端到端体验、全链路视角 |
| **迭代演进** | 通过原型测试持续优化 | MVP、可用性测试、快速迭代 |
| **实体与数字融合** | 线上线下体验无缝衔接 | 全渠道一致性、触点协调 |

## 2. 双钻石模型 (Double Diamond)

### 第一钻石：发现问题

```
┌─────────────────────────────────────────────────────────┐
│  DISCOVER (发现)           →  DEFINE (定义)             │
│                                                         │
│  • 用户研究                                              │
│  • 深度访谈                                              │
│  • 行为观察                                              │
│  • 竞品分析                                              │
│  • 数据洞察                                              │
│                                                         │
│  发散思维，广泛探索      →  收敛聚焦，锁定核心问题       │
└─────────────────────────────────────────────────────────┘
```

#### Discover 阶段产出

| 产出物 | 内容 | 用途 |
|--------|------|------|
| 用户访谈记录 | 原始访谈文本、录音、笔记 | 洞察挖掘基础 |
| 竞品分析报告 | 功能对比、体验差异、机会点 | 差异化定位 |
| 用户旅程图 (As-Is) | 现有触点、情感曲线、痛点 | 问题识别 |
| 用户画像 (Persona) | 典型用户特征、目标、痛点 | 需求聚焦 |
| 服务触点清单 | 物理/数字/人员触点汇总 | 系统梳理 |

### 第二钻石：解决问题

```
┌─────────────────────────────────────────────────────────┐
│  DEVELOP (发展)            →  DELIVER (交付)            │
│                                                         │
│  • 创意发散                                              │
│  • 原型制作                                              │
│  • 概念测试                                              │
│  • 方案迭代                                              │
│  • 详细设计                                              │
│                                                         │
│  发散思维，创意探索      →  收敛落地，可交付方案         │
└─────────────────────────────────────────────────────────┘
```

#### Develop 阶段产出

| 产出物 | 内容 | 用途 |
|--------|------|------|
| 设计机会点 | 优先级排序的改进方向 | 聚焦设计目标 |
| 概念草图 | 多方案快速表达 | 创意验证 |
| 服务蓝图 (Blueprint) | 前后台流程、触点、证据 | 系统设计 |
| 用户旅程图 (To-Be) | 优化后触点、情感曲线 | 期望设定 |

#### Deliver 阶段产出

| 产出物 | 内容 | 用途 |
|--------|------|------|
| 服务原型 | 可体验的服务演示 | 验证测试 |
| 设计规范 | 视觉/交互/内容标准 | 落地执行 |
| 实施路线图 | 阶段计划、资源需求 | 项目推进 |
| 效果评估指标 | NPS、满意度、使用率 | 成果衡量 |

## 3. 服务蓝图 (Service Blueprint)

### 核心结构

```
                    ↑ 可见线 (Line of Visibility)  ↑
     ┌──────────────────────────────────────────────────┐
     │              顾客行为 (Customer Actions)          │  用户可见
     ├──────────────────────────────────────────────────┤
     │  前台触点 (Frontstage - Customer Touchpoints)     │  用户可见
     ├──────────────────────────────────────────────────┤
     │  后台支持 (Backstage - Support Processes)         │  用户不可见
     ├──────────────────────────────────────────────────┤
     │  支持流程 (Support Processes - ERP/IT/HR)        │  用户不可见
     └──────────────────────────────────────────────────┘
```

### 蓝图要素

| 要素 | 说明 | 示例 |
|------|------|------|
| 物理证据 | 环境中用户接触的有形物 | 门店、App界面、纸质文档 |
| 触点 | 服务交互点 | 客服电话、自助终端、宣传册 |
| 流程 | 前后台活动序列 | 订单处理、入职流程 |
| 等待/失败点 | 潜在断点 | 长时间等待、系统错误 |
| 时间 | 各环节耗时 | 响应时间、处理时长 |

## 4. 用户旅程图 (Customer Journey Map)

### 标准模板

| 阶段 | 触点 | 用户行为 | 用户想法 | 用户情感 | 痛点 | 机会点 |
|------|------|----------|----------|----------|------|--------|
| 认知 | 官网/广告 | 了解服务 | 是否值得尝试 | 好奇/疑虑 | 信息不清晰 | 价值主张突出 |
| 考虑 | 案例/评价 | 对比选项 | 哪个最适合我 | 犹豫/比较 | 选择困难 | 差异化展示 |
| 转化 | 咨询/签约 | 完成购买 | 流程是否顺畅 | 期待/焦虑 | 步骤繁琐 | 简化流程 |
| 使用 | 产品/服务 | 体验服务 | 是否满足预期 | 满意/失望 | 操作复杂 | 引导优化 |
| 留存 | 客服/更新 | 持续使用 | 是否值得继续 | 认可/流失 | 价值递减 | 增值服务 |

### 情感曲线绘制

```
情感
  ↑
  │    😄
  │   ╱  ╲
  │  ╱    ╲
  │ ╱      ╲    😃
  │╱        ╲  ╱
  └─────────────────────→ 时间/阶段
    认知 考虑 转化 使用 留存
```

## 5. 设计决策框架

### 决策层级

```
┌─────────────────────────────────────────────────────────┐
│  战略层 (Strategic)                                      │
│  • 服务定位  • 目标用户  • 商业模式                      │
├─────────────────────────────────────────────────────────┤
│  能力层 (Capability)                                     │
│  • 核心能力  • 资源分配  • 组织架构                      │
├─────────────────────────────────────────────────────────┤
│  体验层 (Experience)                                     │
│  • 用户旅程  • 触点设计  • 情感体验                      │
├─────────────────────────────────────────────────────────┤
│  执行层 (Execution)                                      │
│  • 视觉规范  • 交互细节  • 内容呈现                     │
└─────────────────────────────────────────────────────────┘
```

### 决策原则

1. **自上而下**：战略指导体验，体验承载战略
2. **一致性**：各层级决策相互呼应
3. **可追溯**：每个决策有明确依据
4. **可验证**：建立指标评估决策效果

## 6. 服务设计工具箱

### 阶段工具

| 阶段 | 工具 | 输出 |
|------|------|------|
| 发现 | 用户访谈、焦点小组、观察法、影子跟随 | 用户洞察 |

## 9. 常用术语

| 术语 | 定义 |
|------|------|
| **服务触点 (Touchpoint)** | 用户与服务提供者交互的任一点 |
| **关键时刻 (Moment of Truth)** | 对用户感知有重大影响的关键交互 |
| **服务前 (Frontstage)** | 用户可见的服务环节 |
| **服务后 (Backstage)** | 用户不可见但支持前台的服务活动 |
| **服务蓝图 (Blueprint)** | 展示服务系统全貌的可视化工具 |
| **共创 (Co-creation)** | 与用户/利益相关方共同设计 |
| **服务设计 (Service Design)** | 规划组织资源以提升服务体验的学科 |
| **设计思维 (Design Thinking)** | 以人为本的创新方法论 |
| **双钻石模型 (Double Diamond)** | Discover-Define-Develop-Deliver 四阶段模型 |
| **NPS (净推荐值)** | 衡量用户推荐意愿的指标 |
