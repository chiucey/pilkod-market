# 查找真正的官方网站

## 技能目标

帮助用户找到真正的官方网址和官方下载地址。确保提供的每个地址都经过严格验证，避免误导用户。

## 工作流程

### 第一步：理解用户需求

分析用户请求类型：
- **类型1 - 找官网地址**：用户想知道某公司/产品的官方网站
- **类型2 - 找下载链接**：用户需要下载某软件的官方安装包
- **类型3 - 两者都要**：用户同时需要官网和下载地址

### 第二步：执行搜索验证

使用 `batch_web_search` 进行多维度搜索验证：

1. **主搜索查询**：
   - `"{产品名} 官方网站"`
   - `"{产品名} 官方下载 site:{相关官方域名}"`
   - `"{产品名} 官网地址"`

2. **交叉验证搜索**：
   - `"{产品名} 官方 正版 下载"`
   - `"{产品名} 在哪里下载"`
   - 搜索品牌母公司官网（如字节跳动官网 → 剪映官网）

### 第三步：来源分析与判断

**可信来源优先级（从高到低）**：

| 优先级 | 来源类型 | 说明 |
|--------|----------|------|
| 1 | 品牌官方网站 | 公司主域名下的产品页面 |
| 2 | 官方应用商店 | App Store、Google Play、Microsoft Store |
| 3 | 知名下载站官方页 | SourceForge、FileHippo 等有官方认证的页面 |
| 4 | 维基百科官方链接 | 需二次验证域名真实性 |

**需要排除的非官方来源**：
- 第三方下载站（下载后跳转链接）
- 软件聚合站（software-download, softonic 等）
- 竞价排名广告（搜索结果中带"广告"标签）
- 仿冒网站（域名拼写近似但不同的站点）

**判断标准**：
1. 域名是否与品牌名相关
2. 网站是否有 HTTPS 证书
3. 网站内容是否与品牌官方信息一致
4. 是否有官方认证标识（如微信认证、备案号等）
5. 页面底部是否有版权信息和公司名称

### 第四步：返回结果

根据用户需求类型返回：

**类型1 - 只找官网**：
```
✅ 官方网站地址：[URL]

判断依据：
1. 域名验证：[分析域名与品牌的关系]
2. HTTPS安全：[是否有效证书]
3. 内容一致性：[网站内容与品牌信息对比]
4. 权威认证：[备案信息/认证标识]
```

**类型2 - 只找下载**：
```
✅ 官方下载地址：[URL]
✅ 官方网站地址：[URL]

判断依据：
[同上分析]

⚠️ 确认下载：是否现在下载该软件？
```

**类型3 - 两者都要**：
```
✅ 官方网站：[URL]
✅ 官方下载：[URL]

判断依据：
[同上分析]
```

### 第五步：下载确认（仅类型2和类型3）

当用户提供下载确认后：
1. 使用 `extract_content_from_websites` 提取下载页面信息
2. 确认下载链接的有效性
3. 提供下载指引

## 特殊情况处理

### 找不到官方信息时

如果经过多轮搜索无法确认官方地址：
```
抱歉，经过多次搜索和交叉验证，我无法确认"{产品名}"的官方地址。

可能原因：
- 该产品可能已停止运营
- 该产品可能没有独立的官方网站
- 该产品可能仅通过特定渠道分发

建议：
1. 尝试在应用商店搜索该产品
2. 联系产品所属公司获取官方信息
3. 提供更多产品背景信息以便进一步查找
```

### 多个疑似官方地址

当存在多个疑似官方地址时：
```
我找到了多个疑似官方地址，请确认哪个是正确的：

1. [地址1] - 来源：[来源说明]
2. [地址2] - 来源：[来源说明]

判断依据：[分析每个地址的可信度]

建议：请查看您之前是否访问过正确地址，或联系官方客服确认。
```

## 验证脚本使用

如需自动化验证，可使用 `scripts/verify_website.py`：
```bash
python scripts/verify_website.py "产品名"
```

脚本会输出：
- 验证通过：网站可信度评分
- 验证失败：具体原因和排除依据

## 质量承诺

1. **不确认不提供**：没有足够证据时，不给出模棱两可的答案
2. **说明判断依据**：每个地址都附带判断理由
3. **承认局限**：无法找到时明确说明原因
4. **避免误导**：竞价广告和仿冒网站会被明确标注并排除
