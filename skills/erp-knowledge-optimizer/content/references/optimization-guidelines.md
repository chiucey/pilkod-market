## 二、反馈问题描述模板

### 标准格式
```
[界面名称]，[操作动作]，[问题现象/诉求]
```

### 完整示例

```
【示例】
采购订单列表界面，点击【审核】按钮，系统报错"审核人没有权限"（错误代码：AC-2001），订单无法审核通过

【带错误代码示例】
销售订单新增页面，点击【保存】按钮，弹出错误提示"FK-00982：核算维度不能为空"

【诉求型问题】
销售订单录入界面，选择客户后，期望自动带出联系人信息，实际需要手动填写
```

## 三、原因分析标准写法

### 原因分析写法

```
[问题现象及根本原因说明]
[解决思路]
```

### 正确示例

```
当前用户"张三"不属于采购订单所属的"华东采购部"组织，系统中审核权限按组织维度控制，因此触发权限校验报错。
将用户分配至对应采购组织，或在审核流中增加该用户为审核节点。
```

### 错误示例（使用禁用词）

```
❌ 可能是因为权限设置不对，需要去检查一下
❌ 好像用户没有权限，应该是在组织那边的问题
❌ 大概率是配置的问题，估计是审核流那边出了问题
```

## 四、解决方案步骤标准写法

### 步骤结构

```
序号、操作路径，找到xxx，执行xxx，确认xxx
```

### 完整示例

```
解决方案步骤：

1、系统管理 > 用户管理 > 用户列表，找到用户"张三"，查看其"所属组织"字段，确认用户当前所属组织不包含"华东采购部"。

2、系统管理 > 组织管理 > 组织列表，选择"华东采购部"组织，进入成员管理，将用户"张三"添加为组织成员，系统提示"成员添加成功"。

3、若需要在采购订单审核流中增加该用户：
   系统管理 > 审核流配置 > 采购订单审核流，找到对应审核节点，点击【编辑】，在审核人列表中增加"张三"，保存审核流配置。

4、用户"张三"重新登录系统，打开目标采购订单，点击【审核】，确认审核成功，订单状态变为"已审核"，无权限报错。
```

### 分支场景写法

```
若[条件A]，则：[处理方式]
若[条件B]，则：[处理方式]
```

### 危险操作警示

```
⚠️ 警告：修改审核流配置可能影响正在进行的审批业务，操作前请确认无进行中的审核单据
⚠️ 警告：删除组织将同时移除所有成员关联，操作不可逆
⚠️ 警告：批量删除用户将同步清除其待办任务，请提前确认
```

## 八、质量检查自检表

### 反馈问题检查
- [ ] 是否包含界面/菜单路径
- [ ] 是否包含具体操作动作
- [ ] 是否包含问题现象或期望结果
- [ ] 如有报错是否包含错误代码

### 原因概述检查
- [ ] 是否使用确定性表述（无可能/应该/估计等）
- [ ] 是否分析到系统机制层面
- [ ] 逻辑是否清晰

### 解决步骤检查
- [ ] 步骤是否使用1、2、3编号
- [ ] 是否包含入口路径
- [ ] 是否包含具体操作动作
- [ ] 是否包含验证/确认环节
- [ ] 分支场景是否使用"若A，则B"格式

### 整体规范检查
- [ ] 敏感信息是否已删除
- [ ] 口语化用语是否已去除
- [ ] 错别字是否已修正
- [ ] 术语是否使用金蝶标准

### 专业性检查
- [ ] 按钮是否使用【】包裹
- [ ] 字段是否使用""或『』包裹
