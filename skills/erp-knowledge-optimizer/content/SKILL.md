# ERP知识优化技能

## 核心能力

对ERP知识技能中的三个关键字段及整体质量进行系统性优化：
1. **反馈问题** - 问题描述的准确性、完整性和清晰度
2. **解决方案原因及概述** - 原因分析的深度和处理方案的规范性
3. **解决方案步骤** - 操作步骤的可执行性、完整性和规范性
4. **整体质量** - 规范性（敏感信息、口语化）和专业性（术语统一）

---

## 一、反馈问题优化标准

### 必须包含的三要素

| 要素 | 说明 | 示例 |
|------|------|------|
| **界面** | 在哪个界面 | 采购订单列表界面 |
| **操作/场景** | 执行了什么操作或处于什么场景 | 点击审核按钮、选单生成采购订单、保存单据时 |
| **问题/诉求** | 出现了什么现象或希望达到什么结果 | 系统报错"审核人没有权限"、字段无法保存 |

### 优化要求

1. **界面定位**：写清楚在哪个界面即可，无需完整路径
2. **操作描述**：清晰描述用户执行的具体操作动作
3. **现象说明**：准确描述系统反馈或用户期望的差异
4. **错误代码**：如有报错，必须补充具体的错误代码或错误描述

### 问题描述模板

```
【示例】
采购订单列表界面，点击【审核】按钮，系统报错"审核人没有权限"（错误代码：AC-2001），订单无法审核通过

【带错误代码示例】
销售订单新增页面，点击【保存】按钮，弹出错误提示"FK-00982：核算维度不能为空"
```

### 禁止事项

- ❌ 模糊描述："系统出问题了"、"页面打不开"
- ❌ 缺少界面信息："操作审核时报错"
- ❌ 操作不明确："选了客户之后有问题"
- ❌ 口语化表达："点那个按钮没反应"（应写：【XXX】按钮）

## 二、解决方案原因及概述优化标准

### 内容要求

结合实际场景，说明以下内容之一或同时包含：

| 类型 | 说明 |
|------|------|
| **直接原因** | 问题产生的根本原因（从系统机制层面分析） |
| **处理方案概述** | 本次问题的解决思路和方法 |

### 原因分析要求

1. **深入机制层面**：分析数据流向、权限逻辑、校验规则等系统机制
2. **区分现象与原因**：现象是用户看到的表面问题，原因需追溯到系统逻辑
3. **提供上下文**：说明问题产生的完整场景和触发条件

### 禁止使用的不确定性词汇

以下词汇**严禁**出现在原因分析中：

| 禁用词 | 说明 |
|--------|------|
| 可能 | 模糊因果关系 |
| 好像 | 缺乏确定性 |
| 应该 | 主观推测 |
| 大概率 | 非专业表述 |
| 估计 | 猜测性质 |
| 估计是 | 不确定推断 |
| 好像是因为 | 模糊归因 |

### 正确表述示例

```
【正确】
原因分析：当前用户不属于"采购部门"组织，系统中审核人权限按组织维度分配，
因此在审核采购订单时触发权限校验，报错"审核人没有权限"。

【错误】
原因分析：可能是因为用户没有权限，应该去检查一下权限设置。
```

### 概述部分结构

建议采用以下结构：
```
处理方案概述：
1. 问题根因：[简要说明根本原因]
2. 解决思路：[采用什么方法解决问题]
```

## 三、解决方案步骤优化标准

### 步骤编写规范

1. **编号格式**：使用"1、2、3"顺序编号，每步独立
2. **动作明确**：每步动作清晰可执行，避免模糊表述
3. **结果可验**：说明每步的预期结果，便于验证
4. **分支处理**：涉及多分支场景时，使用"若A，则……；若B，则……"

### 步骤模板

```
1、[操作路径] → [检查/操作内容] → [预期结果]
2、[操作路径] → [操作内容] → [预期结果]
3、若[条件A]，则[处理方式]；若[条件B]，则[处理方式]
```

### 完整步骤示例

```
解决方案步骤：

1、系统管理 > 用户管理 > 用户列表，找到用户"张三"，查看其"所属组织"字段，确认用户当前所属组织不包含"华东采购部"。

2、系统管理 > 组织管理 > 组织列表，选择"华东采购部"组织，进入成员管理，将用户"张三"添加为组织成员，系统提示"成员添加成功"。

3、若需要在采购订单审核流中增加该用户：
   系统管理 > 审核流配置 > 采购订单审核流，找到对应审核节点，点击【编辑】，在审核人列表中增加"张三"，保存审核流配置。

4、用户"张三"重新登录系统，打开目标采购订单，点击【审核】，确认审核成功，订单状态变为"已审核"，无权限报错。
```

### 危险操作警示

涉及以下操作时，必须添加警示：
- ⚠️ 数据删除操作
- ⚠️ 权限变更操作
- ⚠️ 配置修改（可能影响其他业务）

### 禁止事项

- ❌ 步骤跳跃："去设置里面改一下就行"（应写明具体路径和操作）
- ❌ 结果模糊："应该就可以了"（应写明确切的预期结果）
- ❌ 步骤不全：缺少验证或确认环节

## 四、整体规范性优化标准

### 1. 敏感信息处理

以下敏感信息必须删除：

| 敏感信息类型 | 处理方式 |
|-------------|---------|
| 客户名称 | 删除 |
| 手机号 | 删除 |
| 邮箱 | 删除 |
| IP地址 | 删除 |
| 银行卡号 | 删除 |

### 2. 口语化表达去除

以下客套用语必须去除：

| 禁止用语 | 替换说明 |
|---------|---------|
| 老师 | 直接描述问题 |
| 谢谢/感谢 | 删除 |
| 麻烦 | 删除 |
| 请问 | 直接提问 |
| 帮忙看一下 | 直接描述问题 |
| 打扰一下 | 删除 |
| 不好意思 | 删除 |

### 3. 错别字与不规范用语修正

常见错别字对照：

| 错误 | 正确 |
|------|------|
| 其它 | 其他 |
| 帐号 | 账号 |
| 登陆 | 登录 |

### 4. 逻辑通顺检查

- 语句是否通顺
- 逻辑是否连贯
- 前后表述是否一致

## 五、专业性优化标准

### 术语统一要求

必须使用金蝶云星空标准术语，常见术语对照：

| 规范术语 | 说明 |
|---------|------|
| 单据类型 | 如采购订单、销售订单 |
| 业务类型 | 如标准采购、委托代销 |
| 组织 | 如销售组织、采购组织、财务组织 |
| 核算维度 | 成本核算的维度分类 |
| 审核流/工作流 | 审批流程配置 |
| 字段 | 数据项名称 |
| 参数 | 系统配置项 |

### 禁止事项

- ❌ 使用口语化模块名："采购那边"、"财务模块"
- ❌ 使用模糊字段名："那个字段"（应写具体字段名）
- ❌ 使用非标准术语：自行创造简称或缩写

## 七、质量检查清单

优化完成后，必须逐项核对：

### 反馈问题
- [ ] 是否包含"界面/功能"要素
- [ ] 是否包含"操作/场景"要素
- [ ] 是否包含"问题/诉求"要素
- [ ] 如有报错是否补充了错误代码/描述

### 解决方案原因及概述
- [ ] 是否说明直接原因或处理方案
- [ ] 是否使用确定性表述（无"可能"、"应该"等词）
- [ ] 是否从系统机制层面分析原因

### 解决方案步骤
- [ ] 是否使用"1、2、3"顺序编号
- [ ] 是否包含操作对象、入口、检查点、处理动作
- [ ] 多分支场景是否使用"若A，则B"格式
- [ ] 是否包含验证/确认环节

### 整体规范性
- [ ] 敏感信息是否已删除
- [ ] 口语化用语是否已去除
- [ ] 错别字是否已修正
- [ ] 语句是否通顺

### 专业性
- [ ] 是否使用金蝶标准术语
- [ ] 字段名称是否准确
