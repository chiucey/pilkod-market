# 代码审查检查清单

## 安全漏洞检查清单

### SQL 注入
- [ ] 用户输入是否直接拼接到 SQL 语句
- [ ] 是否使用参数化查询/预处理语句
- [ ] ORM 使用是否正确（避免 raw SQL 注入）

### XSS 跨站脚本
- [ ] 用户输入是否直接输出到 HTML
- [ ] 是否进行了适当的转义
- [ ] 富文本输入是否使用白名单过滤

### 权限控制
- [ ] 敏感操作是否验证用户权限
- [ ] API 端点是否缺少认证
- [ ] 垂直越权和水平越权风险

### 敏感信息
- [ ] 代码中是否硬编码密码/API Keys
- [ ] 错误信息是否泄露敏感路径
- [ ] 日志是否记录敏感数据

### 输入验证
- [ ] 所有用户输入是否验证
- [ ] 类型检查是否完整
- [ ] 边界条件是否处理

## 性能检查清单

### 算法复杂度
- [ ] 嵌套循环是否可优化
- [ ] 是否使用了低效的数据结构
- [ ] 是否有 O(n²) 可降为 O(n log n)

### 数据库
- [ ] 是否存在 N+1 查询问题
- [ ] 索引是否合理
- [ ] 是否查询了不必要的字段

### 资源管理
- [ ] 连接/流是否正确关闭
- [ ] 是否存在内存泄漏
- [ ] 大文件处理是否流式

### 前端特定
- [ ] 是否有不必要的重渲染
- [ ] 图片/资源是否懒加载
- [ ] 是否缓存了可复用计算

## 代码质量检查清单

### 命名
- [ ] 变量名是否描述意图
- [ ] 函数名是否是动词
- [ ] 类名是否是名词/形容词
- [ ] 常量是否全大写

### 复杂度
- [ ] 函数是否过长（>50行需考虑拆分）
- [ ] 嵌套是否过深（>3层需重构）
- [ ] 参数是否过多（>3个考虑封装）

### 重复
- [ ] 是否有重复代码块
- [ ] 是否可提取公共函数
- [ ] 是否违反 DRY 原则

### 注释
- [ ] 复杂逻辑是否有解释
- [ ] 公共 API 是否有文档
- [ ] 是否有 TODO/FIXME 需处理

## 可维护性检查清单

### 错误处理
- [ ] 是否捕获了关键异常
- [ ] 错误信息是否有意义
- [ ] 是否正确传播错误

### 模块化
- [ ] 是否符合单一职责
- [ ] 是否依赖抽象而非实现
- [ ] 模块间耦合是否过高

### 测试
- [ ] 核心逻辑是否有测试
- [ ] 测试是否独立
- [ ] 边界条件是否覆盖

## 框架特定最佳实践

### JavaScript/TypeScript
- [ ] 是否使用 const/let 而非 var
- [ ] 异步操作是否正确处理
- [ ] 是否避免回调地狱

### Python
- [ ] 是否使用类型提示
- [ ] 是否遵循 PEP 8
- [ ] 资源是否使用 with 语句

### React
- [ ] 状态提升是否合理
- [ ] Hooks 规则是否遵循
- [ ] 是否避免不必要的重渲染

### API 设计
- [ ] RESTful 规范遵循
- [ ] 响应格式是否一致
- [ ] HTTP 状态码是否正确
