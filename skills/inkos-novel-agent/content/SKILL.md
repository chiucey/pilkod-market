# InkOS 小说智能体

专业级长篇小说、短剧剧本、网文创作引擎，集成 [InkOS](https://github.com/narcooo/inkos) 开源多智能体系统，支持文件解析、风格模仿、大纲生成、人设构建、爽点设计、续写改写。

## InkOS 技术内核

本技能调用 InkOS（Ink Operating System）开源项目，自动执行以下流水线：

| 阶段 | Agent | 功能 |
|------|-------|------|
| 1 | **Radar 雷达** | 扫描平台趋势，指导故事方向 |
| 2 | **Planner 规划师** | 读取意图 + 记忆检索，产出本章目标 |
| 3 | **Composer 编排师** | 编译规则栈和上下文 |
| 4 | **Architect 建筑师** | 规划章节结构、场景节拍 |
| 5 | **Writer 写手** | 生成正文（字数治理 + 对话引导） |
| 6 | **Observer 观察者** | 提取关键事实 |
| 7 | **Reflector 反射器** | JSON 校验输出 |
| 8 | **Normalizer 归一化器** | 压缩/扩展字数 |
| 9 | **Auditor 审计员** | 33 维度连续性审计 |
| 10 | **Reviser 修订者** | 自动修复 + 人工审核 |

**InkOS CLI 命令**：
```bash
# 初始化项目
inkos init my-novel

# 创建书籍
inkos book create --title "书名" --genre xuanhuan

# 完整管线写下一章
inkos write next my-novel

# 连续写5章
inkos write next my-novel --count 5

# 重写第N章
inkos write rewrite my-novel 5

# 审计章节
inkos audit my-novel 5

# 去AI味改写
inkos revise --mode anti-detect my-novel 5

# 风格分析
inkos style analyze reference.txt

# 导入风格到书籍
inkos style import fingerprint.json my-novel

# AIGC检测
inkos detect my-novel 5

# 导出TXT
inkos export my-novel

# 导出EPUB
inkos export my-novel --format epub
```

## 核心能力矩阵

### 一、文件解析引擎

支持 TXT、Word、PDF、图片、链接五种格式的深度解析。

**解析维度**：

- 情节结构：起承转合、章节节奏、冲突密度
- 大纲框架：主线、副线、支线、伏笔体系
- 人物体系：主角、配角、反派、工具人
- 风格特征：文风、句式、节奏、情绪表达
- 爽点分布：爽点类型、密度、铺垫-爆发节奏
- 经典反转：反转数量、类型、逻辑严密性

**输出结构**：

```

├─ 基本信息
│  ├─ 文件类型：xxx
│  ├─ 字数统计：xxx字

│  ├─ 主线脉络：xxx
│  ├─ 章节节奏：快/中/慢
│  └─ 冲突密度：高/中/低
├─ 人物图谱
│  ├─ 核心人物：xxx（性格标签+人物弧光）
│  ├─ 重要配角：xxx
│  └─ 反派设定：xxx
├─ 风格解析
│  ├─ 文风类型：简洁/华丽/幽默/虐心/热血
│  ├─ 句式特点：短句为主/长句铺陈/对话驱动
│  └─ 情绪节奏：燃/虐/甜/爽/虐爽交织
├─ 爽点设计

   └─ 适配题材方向：xxx
```

### 二、长篇小说生成引擎

**日更能力**：3000-10000字/天，支持连载节奏设计

**核心标准**：

- 逻辑严谨：情节因果链完整，无漏洞
- 人物立体：主角有成长弧光，配角有记忆点
- 冲突强烈：每个章节至少一个核心冲突
- 节奏紧凑：黄金三章法则，前三章必须抓人
- 爽点充足：每3000字一个小爽点，每15000字一个大爽点

**章节结构模板**：

```
【第X章：章节标题】（2000-3000字）
├─ 开篇钩子（100字）
│  └─ 悬念/冲突/反转/金句开头
├─ 情节推进（1500-2000字）
│  ├─ 冲突升级
│  ├─ 人物互动
│  └─ 信息释放
├─ 章节高潮（300-500字）
│  └─ 爽点/虐点/反转/关键抉择
└─ 章节结尾（100-200字）
   ├─ 悬念钩子
   └─ 引导继续阅读
```

**质量检测清单**：

- [ ] 每章至少一个核心冲突
- [ ] 主角有明确的目标/欲望
- [ ] 有即时满足的爽点设计
- [ ] 有延后满足的长线钩子
- [ ] 无逻辑漏洞和人物OOC
- [ ] 符合目标平台调性


## 工作流程

3. **需求确认**
   - 输出任务确认单

   - 先出大纲/框架

3. **质量检测**
   - 逻辑自洽性检查

### 输出交付阶段

1. **结构化输出**

2. **延伸建议**
   - 后续创作建议
   - 平台适配优化
