# Consolidated Pre-Submission Checklist
> Research Stack 通用质量核查清单。所有角色在提交最终成果前使用。

## 1. Significance & Originality
```
□ 研究问题是否重要且有充分依据？
□ 知识的空白点是什么？
□ 研究对领域有何具体贡献？
□ 是增量式贡献还是突破性贡献？
```

## 2. Scientific Rigor & Methods
```
□ 假设是否可证伪？
□ 研究设计是否适合回答该问题？
□ 方法是否充分详细，可复现？
□ 随机化/盲法（如适用）是否明确？
□ 对照组设置是否合理？
□ 所有变量是否有操作定义？
```

## 3. Statistical Reporting
```
□ 统计方法是否适合数据类型？
□ 效应量 + 置信区间 + p值三者均已报告？
□ 多重检验校正方法已说明？
□ 序贯分析（添加受试者后重跑检验）已披露为局限？
□ 数据分布特征已描述？
□ 方差齐性假设是否验证？
```

## 4. Reproducibility
```
□ 样本量/功效分析有记录？
□ 数据和代码是否可获取（如适用）？
□ 预注册 Protocol 是否有？
□ 缺失值处理方法是否报告？
□ 异常值处理方式是否披露？
```

## 5. Literature & Citations
```
□ 所有方法学声明是否有文献引用？
□ 引用文献是否为同期刊/同领域的权威来源？
□ 重要文献（高引/里程碑）是否已覆盖？
□ 是否存在自我引用偏倚？
```

## 6. Transparency & Disclosure
```
□ 局限性是否明确陈述（不省略）？
□ 资金来源是否已披露？
□ 利益冲突声明是否完整？
□ 知情同意/伦理审批是否注明？
```

## 7. Logic & Narrative
```
□ 结论是否严格从数据/文献推导得出？
□ 是否存在过度外推或因果混淆？
□ 讨论部分是否回答"那又怎样"（so what）？
□ 研究局限性是否在结论中得到合理权衡？
□ 摘要与正文结论是否一致？
```

## 8. Technical Writing
```
□ 缩写词首次使用时已定义？
□ 术语使用是否一致？
□ 图表是否自含（不读正文也能理解）？
□ 字数/格式是否符合目标期刊要求？
□ 语言是否清晰（不读两遍看不懂）？
```

## 9. Reviewer Pre-emption
```
□ 常见审稿质疑是否已在正文中主动处理？
□ 样本量小的潜在质疑是否已承认？
□ 阴性/弱结果是否已诚实呈现其意义？
□ 创新性声明是否有足够支撑？
□ 方法局限性是否已充分披露？
```

## 使用说明

**谁用：**
- PR 在审稿时逐项核查
- AW 在写作时自查
- PM 在项目收尾前做最终确认

**时机：**
- 论文/基金初稿完成后、提交前 → 全项核查
- 各章节写作时 → 对应章节自检
- PR 审稿时 → 全部核查

**输出：**
发现任何 ❌ 项 → 立即修复 → 重新核查
