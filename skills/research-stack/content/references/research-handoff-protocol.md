# Research Handoff Protocol
> Research Stack 角色间交接的完成标准。
> 每个角色在"交出"工作之前，必须确认以下条件已满足。
> 这是 gstack Phase Separation 原则在 Research Stack 的实现：
> **没有明确的完成标准，不做交接。**

---

## 为什么需要这个协议

gstack 发现：在 AI agent 工作流中，最常见的浪费是"交接不完整"——
上一个角色以为做完了，下一个角色发现缺了关键信息，还得回去问。

在 Research Stack 里，这浪费的是 用户 的时间和注意力。

**这个协议的目的是：让每一个交接都是完整的。**

---

## 通用交接检查（三问）

**在交接给下一个角色之前，输出方必须自问：**

```
□ 我交给下一个角色的信息包，是否包含了我目前知道的所有关键信息？
□ 下一个角色拿到这个包，能直接开始工作，还是需要回来问我？
□ 有什么是我"觉得不需要说"但下一个角色"需要知道"的？
```

**如果有任何不确定 → 主动问下一个角色："需要我补充什么？"**

---

## 角色间具体完成标准

### LR → ED（文献调研 → 实验设计）

**输出包必须包含：**
```
□ 研究空白（gap）清晰陈述
□ 已有方法的优缺点（至少3个主要方法）
□ 优先假设的文献依据
□ 关键参考文献列表（≥3篇高质量）
□ 用户 对假设方向的判断（Research Decision Log 记录）
```

**ED 收到包后，如果信息不足，不开始设计 → 向 LR 提出明确的信息需求。**

---

### LR → AW（文献调研 → 学术写作）

**输出包必须包含：**
```
□ 领域研究进展的叙事主线（不是堆砌文献，是有逻辑的故事）
□ 最重要的3-5篇参考文献及核心贡献
□ 已知 vs 未知的边界在哪里（用户 判断）
□ 用户 最想让读者记住的一点
□ 目标期刊（如已确定）
```

**AW 收到包后，能直接写 Introduction，不需要回头问 LR。**

---

### ED → DA（实验设计 → 数据分析）

**输出包必须包含：**
```
□ 核心假设（Hypothesis）
□ 自变量 / 因变量 / 控制变量
□ 实验设计类型（被试间/被试内/混合）
□ 预期效应量（如有）
□ 统计分析计划（如预注册）
□ 数据格式说明
```

**DA 收到包后，能直接设计分析方案，不需要回头问 ED。**

---

### DA → AW（数据分析 → 学术写作）

**输出包必须包含：**
```
□ 核心发现的陈述（≤3句，非技术语言）
□ 主要统计结果（效应量 + CI + p值）
□ 关键图表（Figure/Table）的编号和内容描述
□ 数据分布特征（如非正态）
□ DA 对结果的解读（不是说"p=0.03"，而是说"这个发现意味着……"）
□ 局限性（如有）
```

**AW 收到包后，能直接写 Results，不需要回头问 DA。**

---

### AW → PR（写作 → 审稿）

**输出包必须包含：**
```
□ 完整初稿（所有章节）
□ 用户 最关心的1-3个审稿问题
□ 用户 最想让审稿人注意到的创新点
□ 用户 知道但没写进论文的潜在弱点（如有）
□ 目标期刊及格式要求
```

**PR 收到包后，执行 Three-Stage 独立审稿，不要求 AW 提供额外背景。**

---

### 任意角色 → PM（交接完成通知）

**通知必须包含：**
```
□ 任务类型：[LR调研/ED设计/DA分析/AW写作/PR审稿]
□ 任务描述：具体是什么
□ 输出摘要：主要结论/产物
□ 状态：完成 / 暂停（有阻塞）
□ 是否需要 用户 确认？□是 / □否
   - 如果是，具体问题是什么？
□ 下一个角色是谁？（如已知）
```

---

## 完成质量的快速检查

**以下任一情况 → 不做交接，先补充：**

```
□ 下一个角色需要的信息，我在交接包里没有提供
□ 对方角色看到输出后，还需要回来问我才能开始
□ 存在我"觉得不需要说"但可能影响对方判断的事
□ 用户 还没有确认关键决策（假设选择/方向/期刊）
```

---

## 交接争议解决

**如果输出角色和接收角色对"是否完成"有分歧：**

→ PM 裁定（PM 是 Research Stack 的协调权威）

**如果 用户 对某个角色的"完成"状态有质疑：**

→ 该角色提供完成标准清单的自查记录
→ PM 协调复盘
