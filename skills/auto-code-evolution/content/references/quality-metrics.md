# 代码质量指标参考

## 圈复杂度 (Cyclomatic Complexity)

衡量代码路径复杂度，值越高越难测试和维护。

| 复杂度 | 等级 | 建议 |
|--------|------|------|
| 1-10 | 低 | 简单，可维护 |
| 11-20 | 中等 | 可接受，需关注 |
| 21-50 | 高 | 重构建议 |
| >50 | 极高 | 必须重构 |

计算公式: `M = E - N + 2P`
- E: 边数
- N: 节点数
- P: 连通分量数

## 深度嵌套 (Nesting Depth)

| 层级 | 评价 |
|------|------|
| 1-2 | 良好 |
| 3-4 | 可接受 |
| 5+ | 需要重构 |

## 代码行数指标

### 函数长度
- **理想**: <20行
- **可接受**: 20-50行
- **警告**: 50-100行
- **超标**: >100行

### 文件长度
- **小型**: <200行
- **中型**: 200-500行
- **大型**: 500-1000行
- **巨型**: >1000行（建议拆分）

## 耦合度指标

### 传入耦合 (CA) / 传出耦合 (CE)
- 衡量模块依赖关系
- 目标: 低耦合、高内聚

### 稳定度指标
```
Instability = CE / (CA + CE)
```
- 0: 完全稳定
- 1: 完全不稳定

## 可读性评分

基于以下因素综合评分 (0-100):

| 因素 | 权重 | 评估点 |
|------|------|--------|
| 命名清晰度 | 20% | 变量/函数名是否自解释 |
| 函数长度 | 20% | 是否过短/过长 |
| 注释覆盖率 | 15% | 关键逻辑是否有注释 |
| 嵌套深度 | 15% | 控制流复杂度 |
| 代码重复 | 15% | DRY原则遵守程度 |
| 格式一致 | 15% | 风格统一性 |

## 安全检查清单

### 注入漏洞
- [ ] SQL查询使用参数化
- [ ] 用户输入经过验证
- [ ] 命令执行避免shell调用

### 认证与授权
- [ ] 敏感操作需要认证
- [ ] 权限检查在业务逻辑前
- [ ] 会话管理安全

### 数据保护
- [ ] 敏感数据加密存储
- [ ] 传输使用HTTPS
- [ ] 日志不记录敏感信息

### 错误处理
- [ ] 不暴露内部错误详情
- [ ] 统一的错误响应格式
- [ ] 失败时正确清理资源

## 性能指标

### 响应时间目标
| 场景 | 目标 | 最大 |
|------|------|------|
| API响应 | <200ms | 1s |
| 页面加载 | <3s | 5s |
| 数据库查询 | <100ms | 500ms |

### 资源使用
- CPU: 峰值 <80%
- 内存: 正常 <70%，峰值 <85%
- 磁盘IO: 避免同步阻塞

## 质量达标阈值

| 指标 | 最低标准 | 良好 | 优秀 |
|------|----------|------|------|
| 圈复杂度 | <15 | <8 | <5 |
| 函数长度 | <100行 | <50行 | <30行 |
| 测试覆盖率 | 60% | 80% | 90% |
| 可读性评分 | 60 | 80 | 90 |
