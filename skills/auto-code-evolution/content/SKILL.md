# 自动迭代升级代码工程师

## 核心能力

此技能将代码工程从一次性修改转变为**持续迭代进化**过程，遵循"分析→改进→验证→迭代"的闭环工作流。

## 工作流程

### 阶段 1：代码分析

**执行深度静态分析**：
1. 读取目标代码文件
2. 解析代码结构（函数、类、依赖关系）
3. 使用启发式规则识别问题域：
   - **性能问题**：循环嵌套、N+1查询、内存泄漏风险
   - **安全漏洞**：SQL注入、XSS、硬编码凭证、弱加密
   - **代码异味**：长函数、重复代码、魔法数字、紧密耦合
   - **可维护性**：缺少文档、命名不规范、复杂度过高
4. 计算代码质量指标（圈复杂度、行数、耦合度）

**输出**：结构化问题清单，每项包含严重程度评级（Critical/High/Medium/Low）

### 阶段 2：改进规划

**制定迭代策略**：
1. 按优先级排序问题（Critical > High > Medium > Low）
2. 评估改进风险与收益比
3. 规划改进顺序（先打补丁，后重构）
4. 预估每轮迭代的影响范围

**生成改进计划**，包含：
- 具体改进措施
- 预期效果
- 潜在风险及回滚方案

### 阶段 3：实施改进

**执行代码修改**：
1. 应用单次或批量修改
2. 保持代码风格一致性
3. 添加必要的注释说明变更原因
4. 更新相关文档（如存在）

**改进类型覆盖**：
- 性能优化：算法替换、缓存策略、懒加载
- 安全加固：输入验证、加密增强、权限最小化
- 重构优化：提取方法、消除重复、解耦依赖
- 可读性提升：重命名变量、添加文档、格式化

### 阶段 4：验证闭环

**自动化验证**：
1. 语法检查与类型验证
2. 功能回归测试（如果存在测试用例）
3. 生成改进对比报告

**决策点**：
- ✅ 验证通过 → 评估是否继续下一轮迭代
- ❌ 验证失败 → 自动回滚并记录问题
- ⚠️ 部分通过 → 记录已知问题，继续改进

### 阶段 5：迭代进化

**持续改进循环**：
1. 检查是否达到预期目标
2. 评估当前代码质量是否满足阈值
3. 如需继续，重复阶段1-4
4. 记录完整的迭代历史

**终止条件**：
- 所有Critical/High问题已解决
- 代码质量指标达到预设阈值
- 用户确认满意或手动终止

## 输出格式

### 迭代报告

```
## 迭代报告 #N

### 本轮改进
| 文件 | 改动 | 类型 | 风险 |
|------|------|------|------|
| xxx.py | 优化循环 | 性能 | 低 |

### 质量变化
| 指标 | 改进前 | 改进后 | 变化 |
|------|--------|--------|------|
| 圈复杂度 | 15 | 8 | -47% |

### 问题状态
- ✅ 已解决: 3
- ⏳ 待处理: 2
```

### 总结报告

```
## 进化总结

**总迭代次数**: N
**改进文件数**: M
**解决的问题**:
- Critical: X
- High: Y
- Medium: Z

**代码质量提升**:
- 可维护性: +XX%
- 性能: +XX%
- 安全性: +XX%

**遗留问题**: (如有)
```

## 决策规则

| 场景 | 行动 |
|------|------|
| 改动风险 > 收益 | 跳过，提供人工审查建议 |
| 改动可能破坏功能 | 先添加测试，再改动 |
| 遇到无法自动修复的问题 | 标记并继续处理其他问题 |
| 用户未指定目标 | 达到"生产就绪"默认标准 |

## 使用示例

```
用户: 优化这个Python函数的性能
↓
技能自动执行:
1. 分析函数复杂度、调用链、资源使用
2. 识别瓶颈：重复计算、效率低下的数据结构
3. 实施优化：添加缓存、使用更优算法
4. 验证正确性和性能提升
5. 输出迭代报告
```

## 限制与注意事项

- 始终保留原始代码备份用于回滚
- 不自动修改未明确要求的代码区域
- 安全性关键的改动需用户确认
- 不跨越多文件进行破坏性重构
