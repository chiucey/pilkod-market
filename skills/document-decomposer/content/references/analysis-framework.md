# 文档解构分析框架

本文档提供文档解构专家技能的方法论参考和实践指南。

## 一、分析框架概述

文档解构采用"理解-提炼-重组-输出"四阶段分析框架，确保对原文的准确把握和高质量输出。

## 二、文档类型识别矩阵

| 文档类型 | 核心特征 | 分析重点 | 改写难度 |
|----------|----------|----------|----------|
| 法律合同 | 条款严谨、术语精确、责任明确 | 权利义务、违约责任、免责条款 | 高 |
| 技术文档 | 步骤清晰、参数具体、代码示例 | 操作步骤、前提条件、注意事项 | 中 |
| 学术论文 | 论证严谨、引用规范、方法明确 | 研究问题、核心结论、贡献价值 | 高 |
| 政策文件 | 目标导向、措施具体、配套完善 | 政策目标、实施路径、配套措施 | 中 |
| 商业报告 | 数据支撑、结论明确、建议可行 | 关键发现、数据依据、行动建议 | 低 |
| 新闻资讯 | 时效性强、信息集中、叙事清晰 | 核心事件、关键人物、重要影响 | 低 |

## 三、语义理解方法论

### 3.1 主题识别三步法

**第一步：标题解构**
- 分析主标题、副标题
- 识别文档性质标签（"关于...的通知"、"...管理办法"等）

**第二步：首段扫描**
- 首段通常包含写作目的和背景
- 识别引出问题、解决方案的类型

**第三步：模式匹配**
- 判断文档属于：说明型、论证型、叙事型、命令型
- 确定主导逻辑结构

### 3.2 关键信息提取规范

```
定义类信息：
  - 提取定义对象
  - 提取本质特征
  - 标注适用范围

规则类信息：
  - 提取适用条件
  - 提取行为要求
  - 提取违规后果

流程类信息：
  - 提取起点和终点
  - 提取关键步骤
  - 提取决策节点

数据类信息：
  - 提取数据来源
  - 提取统计口径
  - 标注时间范围
```

### 3.3 逻辑关系图谱

```
              ┌─────────────────┐
              │     核心论点     │
              └────────┬────────┘
                       │
       ┌───────────────┼───────────────┐
       │               │               │
       ▼               ▼               ▼
  ┌────────┐      ┌────────┐      ┌────────┐
  │ 论据1  │      │ 论据2  │      │ 论据3  │
  └───┬────┘      └───┬────┘      └───┬────┘
      │               │               │
      ▼               ▼               ▼
  ┌────────┐      ┌────────┐      ┌────────┐
  │ 细节A  │      │ 细节B  │      │ 细节C  │
  └────────┘      └────────┘      └────────┘
```

逻辑类型识别：
- **总分关系**：先总述后分述，或先分述后总结
- **递进关系**：由浅入深、由表及里
- **对比关系**：正反对比、利弊对比
- **因果关系**：原因导致结果，条件导致结论
- **例证关系**：观点加具体案例支撑

## 四、结构重组原则

### 4.1 金字塔原理应用

**结论先行**：先给出核心结论，再展开论证

```
❌ 错误示例：
"由于近年来人工智能技术快速发展，在金融、医疗、教育等领域
广泛应用，因此各大企业都在积极布局AI战略..."

✅ 正确示例：
"核心结论：企业必须尽快制定AI战略。
依据：1）AI技术已成熟... 2）应用场景已验证... 3）竞争态势已形成..."
```

**以上统下**：每个层级的论题必须是下一层级的概括

### 4.2 MECE原则检查

Mutually Exclusive, Collectively Exhaustive
- 相互独立：无重叠、无遗漏
- 完全穷尽：涵盖所有相关要素

**检查清单**：
- [ ] 分类是否相互独立？
- [ ] 是否遗漏重要类别？
- [ ] 是否有重叠分类？

### 4.3 认知友好结构

| 原结构 | 问题 | 优化后结构 |
|--------|------|------------|
| 先讲原理再讲应用 | 读者可能失去耐心 | 先讲应用场景，再解释原理 |
| 大段论述 | 信息密度过高 | 拆分要点，添加小标题 |
| 概念堆砌 | 理解负担重 | 每个概念后紧跟通俗解释 |
| 隐藏前提 | 读者困惑 | 明确标注前提条件 |

## 五、通俗化改写技巧

### 5.1 具象化方法

| 抽象概念 | 具象化表达 |
|----------|------------|
| 分布式存储 | 多个人同时保存同一份文件，修改需要多数人同意 |
| 深度学习 | 让计算机像小孩一样从大量例子中学习规律 |
| 云计算 | 用网而不是用电脑做事，就像用水电网一样用计算能力 |
| 区块链 | 一本公开的、无法篡改的账本 |

### 5.2 场景化方法

```
原文：适用于远程办公场景
改写：如果你在家、出差或在咖啡馆工作，这个功能可以帮你...
```

```
原文：本产品适用于企业级用户
改写：当你的公司有10人以上需要使用时，这个产品最合适...
```

### 5.3 问答转化方法

```
原文：
注意事项：
1. 请勿在高温环境下使用
2. 避免与腐蚀性物质接触
3. 远离儿童

改写：
常见问题：
Q：可以在厨房使用吗？
A：可以，但避免长时间接触高温（超过60°C）和清洁剂。

Q：有小朋友的家庭需要注意什么？
A：请放置在儿童接触不到的地方...
```

### 5.4 步骤化方法

```
原文：
合同签署流程：首先进行资质审核，审核通过后进入合同起草阶段，
起草完成后提交法务审核，审核通过后由双方签署。

改写：
三步完成合同签署：
第一步：提交资质 → 我们会在1-2个工作日内完成审核
第二步：起草确认 → 您可以在我们的系统中实时查看和修改
第三步：双方签署 → 支持电子签名，整个过程线上完成
```

## 六、质量控制标准

### 6.1 准确度检查

- [ ] 核心观点是否与原文一致？
- [ ] 关键数据是否准确无误？
- [ ] 专业术语是否保留或正确解释？
- [ ] 逻辑关系是否完整呈现？

### 6.2 可读性检查

- [ ] 是否有明显的专业术语堆砌？
- [ ] 段落长度是否合适（建议每段不超过5行）？
- [ ] 是否有清晰的层次结构？
- [ ] 关键信息是否有视觉强调？

### 6.3 完整性检查

- [ ] 是否有遗漏的重要信息？
- [ ] 关联条款是否已建立链接？
- [ ] 隐含前提是否已明确？
- [ ] 例外情况是否已标注？

## 七、输出质量等级

| 等级 | 描述 | 适用场景 |
|------|------|----------|
| A级 | 准确、完整、清晰、易读 | 正式汇报、重要决策参考 |
| B级 | 准确、较完整、清晰 | 一般性阅读理解 |
| C级 | 准确、要点突出 | 快速浏览、信息筛选 |
| D级 | 核心信息准确，允许细节简化 | 极简摘要 |

## 八、常见问题处理

### 8.1 文档模糊/歧义处理

**策略**：提出多种可能解释，请用户确认

```
分析发现：文档中"重大变化"未明确定义，可能指：
A. 注册资本变化超过20%
B. 主营业务范围变化超过50%
C. 控股股东变更

请确认您的理解是？
```

### 8.2 多文档关联处理

**策略**：先分别分析，再建立关联矩阵

```
文档A（主协议） + 文档B（补充协议） + 文档C（实施细则）
    ↓
关联分析：
- 优先顺序：B > A > C
- 冲突解决：以B为准
- 关键衔接点：第3.2条引用C的第5.1条
```

### 8.3 长文档处理

**策略**：分段处理 + 全局索引

```
分段处理原则：
- 每段独立分析
- 段间建立导航链接
- 结尾提供全局汇总

示例：
[上一章：合同标的] → [当前：付款条件] → [下一章：违约责任]
                  ↑
              本章小结
```
