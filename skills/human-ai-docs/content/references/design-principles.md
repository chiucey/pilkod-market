# Human-AI-Docs 设计原则

> **文档版本**: 1.0.0
> **最后更新**: 2026-03-27

---

## 概述

Human-AI-Docs 是一套**人机协作文档系统**，核心思想是将项目文档分为两层：
- **人类阅读层**: README.md - 自然语言，易于理解
- **AI上下文层**: CLAUDE.md - 结构化指令，AI友好

---

## 核心设计原则

### 1. 分离关注点

| 层次 | 文件 | 受众 | 风格 |
|------|------|------|------|
| 人类层 | README.md | 开发者、需求方 | 自然语言、快速上手 |
| AI层 | CLAUDE.md | AI助手 | 结构化、任务导向 |
| 技术层 | docs/*.md | 深度参考 | 详细、完整 |

### 2. 任务导向组织

**不推荐**（知识导向）:
```markdown
## 项目架构
本项目采用 MVC 架构...

## 技术栈
- 前端: React
- 后端: Python
```

**推荐**（任务导向）:
```markdown
## 核心操作索引

| 操作 | 详细文档 | 触发词 |
|------|----------|--------|
| 添加新API | @docs/api-workflow.md | "添加接口" |
| 运行测试 | @docs/testing.md | "测试" |
```

### 3. 最小化AI上下文

CLAUDE.md 应该保持精简（<100行），使用@import引用详细内容：

```markdown
## 技术栈详解
@docs/tech-stack.md

## 架构概览
@docs/architecture.md
```

**好处**:
- AI启动时加载更快
- 避免上下文溢出
- 详细内容易于维护

### 4. 渐进式描述变更

不依赖自动检测（Git diff），而是让用户主动描述变更：

```
用户: "我刚加了用户登录功能"
AI: "请描述主要变更：1. 新增了什么？2. 修改了什么？"
用户: "添加了 auth 模块"
AI: [分析并更新文档]
```

## 文档结构规范

### README.md 结构

```markdown
# 项目名称

> 项目一句话描述

## 快速开始
- 安装
- 运行
- 测试

## 主要功能
- 功能1
- 功能2

## 开发指南
- 环境要求
- 开发流程
- 部署说明

## 贡献指南
- 代码规范
- PR流程
```

### CLAUDE.md 结构

```markdown
# {{PROJECT_NAME}} AI Context

## 项目概览
- 项目类型
- 技术栈
- 核心模块

## 操作索引表

| 操作指令 | 详细文档 | 触发词 |
|----------|----------|--------|
| ... | ... | ... |

## 技术栈
@docs/tech-stack.md

## 架构设计
@docs/architecture.md

## 常用命令
- 构建: npm run build
- 测试: npm test
- 启动: npm run dev
```

### docs/ 目录结构

```
docs/
├── architecture.md    # 架构设计
├── workflows.md       # 开发工作流
├── tech-stack.md      # 技术栈详解
├── api.md            # API文档
├── testing.md        # 测试指南
└── deployment.md     # 部署说明
```

## @import 语法规范

### 基本语法

```markdown
@path/to/file.md
```

### 使用场景

**表格引用**:
```markdown
| 指令 | 详细文档 |
|------|----------|
| 测试 | @docs/testing.md |
```

**段落引用**:
```markdown
## 技术栈
@docs/tech-stack.md
```

**列表引用**:
```markdown
参考文档:
- 架构: @docs/architecture.md
- API: @docs/api.md
```

---

## 最佳实践

1. **保持CLAUDE.md精简**: <100行，详细内容用@import
2. **操作索引优先**: 按任务组织，非按组件
3. **README面向人类**: 关注快速上手和开发体验
4. **docs/保持完整**: 详细的技术参考
5. **及时更新**: 代码变更时同步更新文档

---

## 与传统文档的区别

| 方面 | 传统文档 | Human-AI-Docs |
|------|----------|---------------|
| AI支持 | 无 | @import + 任务索引 |
| 更新方式 | 手动 | 用户描述+AI执行 |
| 结构 | 扁平 | 分层（人/AI/技术） |
| 维护性 | 难 | 简化@import |
