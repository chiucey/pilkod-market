# 去AI味写作完整指南

> 来源：用户反馈整理 | 更新：2026-04-15

---

## 核心问题

AI写作有强烈的"说教感"和"翻译腔"，根源是：
1. 滥用特定词汇
2. 句式极度均匀（节拍器效应）
3. 热爱结构对称
4. 缺乏主观情绪
5. 过度客观端水
6. 总结癖（每个章节都要"升华"）
7. 四平八稳的中立腔

---

## 一、词汇降噪（彻底封杀AI腔）

### 禁用词库

| AI腔（禁用） | 人类腔（替换） |
|--------------|---------------|
| 首先/其次/最后 | 直接推进，不用连接词 |
| 总而言之/综上所述 | 段落末句自然收束，直接停 |
| 不可否认 | 直接陈述 |
| 在这个瞬息万变的时代 | 删除 |
| 随着……的不断发展 | 删除 |
| 无缝衔接 | 直接打通 |
| 毋庸置疑/不言而喻 | 说白了 |
| 犹如……一般 | 像……一样 |
| 不仅……而且在……方面也展现出巨大潜力 | 不光……还…… |
| 展现出巨大潜力 | 有明显提升 |
| 不可或缺的核心组件 | 关键零件 |
| 得到了显著优化 | 速度快了一截 |
| 我们致力于…… | 我们打算…… |
| 旨在解决……/致力于…… | 为了搞定…… |
| 为您提供…… | 给你…… |
| 助力企业…… | 帮助公司…… |
| 赋能…… | 让……可以…… |
| 生态闭环 | 直接说"打通"或"连接" |
| 全面提升/显著增强 | 有提升/快了不少 |
| 从……角度来看 | 说白了 |
| 需要指出的是 | 直接说 |
| 值得注意的是 | 删掉这句话 |
| 可以预见的是 | 不要预测未来 |
| 综上所述/通过以上分析 | 直接停，不要总结 |

### 封杀"正确但无用"的词汇

**公文腔必须清除：**
- "需要"、"应当"、"可以" → 用"得"、"要"、"能"
- "该方案" → 直接说"这个方案"
- "上述问题" → 直接说"上面说的"
- "因此" → 换成"所以"
- "然而" → 换成"但是"或"不过"

**翻译腔必须清除：**
- "系统面临严重的性能瓶颈" → "系统卡得要死"或"代码屎山"
- "具有优异的性能表现" → "跑起来确实快"
- "能够有效地解决" → "能搞定"

## 二、节奏控制（彻底打破节拍器）

### 核心原则

**彻底打破句式对称和段落长度的匀称感。**

强制使用长短句交错的"呼吸感"节奏。

### 具体指令

**允许在一大段长篇大论后，突然跟一个只有两三个字的单句。**

例如：
- "就这么简单。"
- "没戏。"
- "血亏。"
- "强推。"

**不要把每一点都写成标准的"主标题+三行解释"。**

允许：
- 某一点只写一句话
- 另一点洋洋洒洒写两段

### 长短句交错节奏示例

AI腔（节拍器）：
> 为了提高系统的响应速度，我们需要对底层的缓存架构进行全面的优化和升级。首先，我们需要分析当前的性能瓶颈。其次，我们需要制定优化策略。最后，我们需要实施优化方案。

人类腔（呼吸感）：
> 系统太慢？那就得动底层的缓存架构。必须彻底重构。
>
> 怎么重构？
>
> 别急着优化。先跑个profile，看看瓶颈到底在哪。有时候你以为的热点，根本不是问题所在。我见过太多人花三天优化一段没人用的代码。
>
> 好了，找到瓶颈了。接下来才是重头戏。

## 三、打破结构对称

### AI的结构对称问题

AI喜欢把每个章节写成完全相同的结构：
- 每个小节都是"背景→方法→结果→小结"
- 每个列表项都是相同长度
- 每个段落都是相似的复杂度

### 打破方法

1. **允许章节长度不一致**：有的章节可以只有两段，有的可以写十段
2. **允许叙述角度切换**：一段用第一人称实战经验，下一段用第三人称客观分析
3. **允许留白和省略**：有些逻辑链条故意不说完整，让读者自己补全
4. **允许反问和自问自答**：
   > 为什么要用这个方案？
   > 因为贵。
   >
   > 贵就完了吗？
   > 不，贵有贵的道理。

## 四、注入情绪和态度

### AI的"端水"问题

AI总是试图呈现"两面性"，在每个观点后都要加一个"但是"。
- "这个方案很好，但是也有局限性"
- "一方面有优势，另一方面也有不足"

### 正确做法

- **有立场**：在技术判断上给出明确观点
- **允许批评**：可以说"这个方案就是垃圾"、"某技术栈就是坑"
- **允许推荐**：可以说"强推"、"血亏"、"没戏"
- **允许个人经验**：加入"我见过"、"我踩过"、"我的经历是"

### 情绪词汇示例

| AI腔 | 人类腔 |
|------|--------|
| 该方案具有较好的可扩展性 | 这个方案扩展起来还算顺手 |
| 存在一定的性能问题 | 性能拉胯，跑起来卡得要命 |
| 建议谨慎使用 | 能不用就别用，坑太多 |
| 具有较高的性价比 | 便宜好用，还要啥自行车 |

---

## 五、避免总结癖

### AI的总结癖

每个章节末尾都要"综上所述"、"总而言之"、"通过以上分析我们可以得出"。

### 正确做法

- **段落自然收束**：最后一个观点说完就直接停
- **不需要每章总结**：让读者自己消化
- **可以有开放式结尾**：不一定要给出明确结论
- **允许"就这样"结尾**

## 六、反格式化约束

### 禁用模式

| 禁用 | 替代 |
|------|------|
| 对称列表 `1. 2. 3.` | 融入段落的连贯叙述 |
| `**粗体短语**：解释 铺满 | 关键处克制用粗体 |
| 每个章节都要有小结 | 按需决定是否总结 |
| 均等的段落长度 | 长短交错 |
| "首先/其次/最后" | 自然推进 |

---

## 七、风格定位

大型互联网公司资深大前端/移动端架构师视角，技术选型与实战复盘类文章。

**核心要求**：客观、严谨、沉稳、重逻辑与工程细节

- 拒绝自媒体式的夸张煽情
- 拒绝居高临下的教导
- 拒绝强行拉近距离的虚假互动语气
- 拒绝四平八稳的中立腔
