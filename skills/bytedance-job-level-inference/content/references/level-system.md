# 字节跳动岗序职级体系详解

## 一、岗序体系概述

字节跳动采用"无职位、无岗位"的设计理念，使用**通道+序列+职务**的岗序体系。

### 核心概念

| 概念 | 定义 |
|------|------|
| **通道** | 职业发展的大方向，如技术(T)、产品(P)、设计(D)等 |
| **序列** | 同一通道下的专业细分，如T通道包含前端、后端、算法、数据等序列 |
| **职务** | 具体的工作头衔，反映在该序列中的专业水平 |
| **职级** | 1-1到5-2的数字编码，反映专业深度和管理幅度 |

## 二、通道详解

### T通道（技术）

| 序列 | 说明 | 示例岗位 |
|------|------|----------|
| 前端 | 用户界面开发 | 前端工程师、Web工程师 |
| 后端 | 服务端开发 | 后端工程师、Java开发 |
| 客户端 | 移动端开发 | Android工程师、iOS工程师 |
| 算法 | 算法研发 | 算法工程师、机器学习工程师 |
| 数据 | 数据相关 | 数据工程师、数据分析师 |
| 测试 | 质量保障 | QA工程师、测试开发 |
| 运维/DevOps | 基础设施 | 运维工程师、SRE |
| 安全 | 安全领域 | 安全工程师、安全研究员 |
| 基础架构 | 平台系统 | 基础架构工程师 |

### P通道（产品）

| 序列 | 说明 |
|------|------|
| 产品经理 | 产品设计、需求管理、项目推进 |
| 产品运营 | 产品增长、用户运营、内容运营 |

### D通道（设计）

| 序列 | 说明 |
|------|------|
| UI设计 | 界面视觉设计 |
| UX设计 | 用户体验设计、交互设计 |
| 视觉设计 | 品牌、运营视觉 |

### M通道（市场）

| 序列 | 说明 |
|------|------|
| 市场 | 市场营销、品牌推广 |
| 运营 | 用户运营、活动运营 |
| 销售 | 商务拓展、客户管理 |

### G通道（职能）

| 序列 | 说明 |
|------|------|
| HR | 人力资源各模块 |
| 法务 | 法律合规 |
| 财务 | 财务核算、分析 |
| 行政 | 行政支持 |

### K通道（管理）

管理通道覆盖所有业务通道，适用于有管理职责的人员。

### 各职级特征详解

#### 1-1级（初始级）

**典型特征**：
- 刚入职或1年以内经验
- 在指导下完成明确的任务
- 学习基础技能和工具
- 需要较多反馈和指导

**工作范围**：
- 承担具体、明确的任务
- 修复简单bug
- 编写基础功能代码
- 参与团队讨论学习

#### 1-2级（入门级）

**典型特征**：
- 1-2年经验
- 能够独立完成分配的任务
- 掌握基础技术栈
- 主动学习和提问

**工作范围**：
- 独立负责小功能模块
- 编写代码和单元测试
- 参与代码评审
- 协助解决一般问题

#### 2-1级（成长级）

**典型特征**：
- 2-4年经验
- 技术能力扎实
- 能独立负责中等复杂度任务
- 开始指导他人

**工作范围**：
- 独立负责中等复杂度模块
- 设计实现方案
- 参与技术方案讨论
- 指导1-2名初级成员

#### 2-2级（熟练级）

**典型特征**：
- 4-6年经验
- 某领域专家
- 能独立负责核心模块
- 业务理解较深

**工作范围**：
- 负责核心模块/子系统
- 主导技术方案设计
- 解决复杂技术问题
- 培养初级成员

#### 3-1级（专家级）

**典型特征**：
- 6-10年经验
- 技术深度广度兼备
- 能主导方向/策略
- 跨团队影响力

**工作范围**：
- 主导团队/项目技术方向
- 设计系统级方案
- 推动技术改进
- 指导团队成员成长

#### 3-2级（高级专家）

**典型特征**：
- 10+年经验
- 领域权威
- 战略思维
- 公司级影响力

**工作范围**：
- 制定技术战略
- 主导跨BU项目
- 建立技术规范
- 培养高级人才

#### 4-1级（资深专家）

**典型特征**：
- 行业顶尖专家
- 定义技术方向
- 业务战略伙伴
- 行业影响力

**工作范围**：
- 定义BU/业务线技术战略
- 推动技术创新
- 影响产品业务决策
- 代表公司技术形象

#### 4-2级（高级资深专家）

**典型特征**：
- 行业领军人物
- 战略制定者
- 变革推动者
- 行业标杆

**工作范围**：
- 主导公司技术战略
- 推动行业标准
- 战略性技术创新
- 高管战略顾问

#### 5-1级（技术研究员/首席专家）

**典型特征**：
- 顶级专家
- 前沿探索者
- 思想领袖
- 行业定义者

**工作范围**：
- 探索前沿技术
- 制定公司长期技术愿景
- 推动技术革命
- 定义行业标准

#### 5-2级（高级技术研究员）

**典型特征**：
- 顶尖大师
- 诺贝尔奖级贡献
- 技术先知
- 永久影响

**工作范围**：
- 人类知识边界突破
- 公司百年愿景
- 技术历史改变
- 永恒知识贡献

## 四、职级评估维度

### 1. 复杂度（Complexity）

| 维度 | 描述 |
|------|------|
| 任务明确性 | 从明确任务到模糊问题 |
| 问题域范围 | 从单一模块到全局系统 |
| 技术难度 | 从常规到前沿创新 |

### 2. 影响范围（Impact）

| 维度 | 描述 |
|------|------|
| 个人产出 | 个人代码/文档产出 |
| 团队影响 | 对团队效率和质量的提升 |
| 业务影响 | 对业务指标的直接贡献 |
| 公司影响 | 对公司战略和竞争力的影响 |
| 行业影响 | 对行业标准和方向的推动 |

### 3. 自主性（Autonomy）

| 维度 | 描述 |
|------|------|
| 工作指导 | 从详细指导到自我驱动 |
| 决策权限 | 从执行决策到战略决策 |
| 创新空间 | 从优化改进到原创突破 |

### 4. 协作范围（Collaboration）

| 维度 | 描述 |
|------|------|
| 协作对象 | 团队内→跨团队→跨BU→外部 |
| 管理幅度 | 无→1-3人→10+人→更大规模 |
| 沟通复杂度 | 单一接口→多方协调→外交谈判 |

### 5. 业务理解（Business Acumen）

| 维度 | 描述 |
|------|------|
| 理解层级 | 局部功能→模块→业务→战略 |
| 商业思维 | 技术导向→商业价值导向 |
| 战略参与 | 执行层面→战略制定 |

## 五、职级推断决策树

```
输入：员工工作内容数据
    │
    ▼
提取关键信息
    │
    ├── 技术栈/专业领域
    ├── 工作复杂度
    ├── 职责范围
    ├── 成果产出
    └── 协作层级
    │
    ▼
信息完整性检查
    │
    ├─── 充足 ──→ 继续推断
    │
    └─── 不足 ──→ 要求补充信息
    │
    ▼
判断所属通道
    │
    ├── T(技术) - 技术栈、项目经历
    ├── P(产品) - 产品思维、用户导向
    ├── D(设计) - 设计技能、审美能力
    ├── M(市场) - 市场运营能力
    └── G(职能) - 职能支持属性
    │
    ▼
推断职级
    │
    ├── 1-1~1-2级：执行层，基础任务
    ├── 2-1~2-2级：独立负责模块
    ├── 3-1~3-2级：主导方向，影响团队
    ├── 4-1~4-2级：战略层面，影响BU
    └── 5-1~5-2级：行业标杆，定义方向
    │
    ▼
输出推断结果
    │
    ├── 通道：T/P/D/M/G/K
    ├── 序列：具体序列名称
    ├── 职务：对应职称
    └── 职级：1-1到5-2
```

## 六、快速参考卡

### 通道快速识别

| 输入关键词 | 推断通道 |
|-----------|----------|
| Java/Python/Go/前端/后端/算法/数据 | T通道（技术） |
| 需求/用户/产品/增长/体验 | P通道（产品） |
| UI/视觉/交互/设计稿/Figma | D通道（设计） |
| 市场/运营/销售/增长/投放 | M通道（市场） |
| HR/法务/财务/行政/合规 | G通道（职能） |
| 带领团队/管理/汇报线/下属 | K通道（管理，需结合其他通道） |

### 职级快速识别

| 关键信号 | 推断职级范围 |
|---------|--------------|
| 修复bug、基础CRUD、需指导 | 1-1~1-2 |
| 独立负责模块、有代码规范意识 | 2-1 |
| 负责核心模块、指导他人、有技术方案设计能力 | 2-2 |
| 主导技术方向、有跨团队协作、推动技术改进 | 3-1~3-2 |
| 制定技术战略、有BU级影响、培养高级人才 | 4-1~4-2 |
| 行业影响力、推动技术革命、定义方向 | 5-1~5-2 |

### 量化指标参考

| 指标 | 低级别(1-1~2-1) | 中级别(2-2~3-2) | 高级别(4-1~5-2) |
|------|-----------------|-----------------|-----------------|
| 负责代码量 | <5K行 | 5K-50K行 | 50K+行 |
| 项目规模 | 单功能/小模块 | 中等系统/子系统 | 大型系统/BU级 |
| 团队协作 | 小组内 | 跨团队 | 跨BU/外部 |
| 管理幅度 | 0人 | 1-5人 | 5+人 |
| 业务影响 | 功能级 | 产品级 | 战略级 |
