# 字节跳动岗序职级推断

## 核心能力

从员工工作内容数据中提取关键信息，匹配字节跳动岗序职级体系，输出员工的通道、序列、职务和职级。

## 输入数据类型

支持以下输入数据格式：
- **OKR文档**：包含目标、关键结果、任务描述
- **工作日志**：日常工作记录、周报、月报
- **项目文档**：项目描述、角色分工、技术栈
- **会议纪要**：讨论内容、决策事项、责任人

## 字节跳动岗序职级体系

### 通道体系

| 通道 | 说明 |
|------|------|
| T通道（技术） | 软件开发、算法、数据、基础架构、安全等技术岗位 |
| P通道（产品） | 产品经理、产品运营 |
| D通道（设计） | UI设计、UX设计、视觉设计 |
| M通道（市场） | 市场、运营、销售 |
| G通道（职能） | HR、法务、财务、行政等 |
| K通道（管理） | 各通道的管理岗位 |

### 职级序列（1-1 至 5-2）

| 级别 | 职称示例（技术） | 职称示例（产品） | 职称示例（设计） |
|------|-----------------|-----------------|-----------------|
| 1-1 | 初级工程师 | 初级产品经理 | 初级设计师 |
| 1-2 | 工程师 | 产品经理 | 设计师 |
| 2-1 | 中级工程师 | 中级产品经理 | 中级设计师 |
| 2-2 | 高级工程师 | 高级产品经理 | 高级设计师 |
| 3-1 | 专家 | 资深产品经理 | 资深设计师 |
| 3-2 | 高级专家 | 产品专家 | 设计专家 |
| 4-1 | 资深专家 | 资深产品专家 | 资深设计专家 |
| 4-2 | 高级资深专家 | 产品专家 | 设计专家 |
| 5-1 | 技术研究员/架构师 | 首席产品经理 | 首席设计师 |
| 5-2 | 高级技术研究员 | 首席产品专家 | 首席设计专家 |

## 推断流程

### 步骤1：信息提取

从输入文本中提取以下关键信息：
1. **技术栈/专业领域**：编程语言、工具、框架、业务领域
2. **工作复杂度**：项目规模、技术难度、业务影响范围
3. **职责范围**：个人贡献、团队协作、跨部门协作
4. **成果产出**：关键成果、量化指标、创新贡献
5. **协作层级**：同级协作、管理他人、跨团队协调

### 步骤2：通道识别

根据提取的专业特征判断所属通道：
- 技术特征明显 → T通道
- 产品思维、用户导向 → P通道
- 设计技能、审美能力 → D通道
- 市场运营能力 → M通道
- 职能支持属性 → G通道

### 步骤3：职级推断

根据以下维度综合判断职级：

| 维度 | 低级别特征(1-1~2-1) | 中级别特征(2-2~3-2) | 高级别特征(4-1~5-2) |
|------|---------------------|---------------------|---------------------|
| 自主性 | 需指导完成任务 | 独立负责模块 | 主导方向/战略 |
| 影响力 | 个人产出 | 团队/项目影响 | 跨BU/公司影响 |
| 复杂度 | 明确任务 | 复杂问题解决 | 前沿/未知领域 |
| 业务理解 | 了解局部 | 理解业务全貌 | 业务战略层面 |
| 人员管理 | 无 | 指导1-3人 | 团队/部门管理 |

### 步骤4：信息完整性检查

**必须收集的信息**：
1. 主要工作内容或职责
2. 使用的技术栈/工具/方法论
3. 参与的项目或成果
4. 团队规模和协作方式

**如信息不足**，必须向用户要求补充以下信息：
- 具体的工作职责和任务描述
- 使用的技术栈或专业工具
- 关键项目成果或量化指标
- 团队规模和汇报关系

## 输出格式

### 完整输出示例

```
## 岗序职级推断结果

### 推断信息
- **输入数据类型**：OKR文档
- **推断置信度**：85%（信息较完整）

### 岗序信息
- **通道**：T通道（技术）
- **序列**：后端开发
- **职务**：高级工程师

### 职级推断
- **建议职级**：2-2
- **理由**：
  - 能够独立负责后端核心模块开发
  - 熟练掌握Java/Spring技术栈
  - 参与的项目有明确的业务价值
  - 有指导初级工程师经验

### 补充说明
- 基于现有信息，职级范围可能在2-1至3-1之间
- 如有更多项目成果或管理经验信息，可进一步精确
```

### 信息不足时的输出

```
## 信息补充请求

当前输入数据不足以进行准确的岗序职级推断。

**已收集信息**：
- 工作内容描述：部分（简略）
- 技术栈：未提供
- 项目成果：未提供

**需要补充的信息**：
1. 📋 主要工作职责和日常任务
2. 🔧 使用的技术栈、开发工具或专业方法
3. 📊 参与的项目及其业务影响/成果
4. 👥 团队规模、协作方式

请补充以上信息后，我将为您推断准确的岗序职级。
```

## 注意事项

1. **保守推断原则**：信息不足时，倾向于要求补充而非强行推断
2. **多通道可能性**：员工可能横跨多个通道，优先根据核心工作内容判断
3. **职级范围**：如无法精确定位，给出合理范围而非单一值
4. **持续更新**：随着信息增加，可重新评估职级
