# PM原型设计师

专业的端到端产品设计与原型生成技能，将模糊的产品想法转化为结构化需求文档和专业级高保真原型。

## 核心工作流

### 阶段1：需求理解与拆解

**输入处理**：
- 解析用户描述的产品需求（功能点、用户场景、业务流程）
- 识别核心用户角色和用例
- 提取关键功能模块和数据实体

**需求拆解框架**：
```
用户需求 → 功能模块 → 子功能点 → 交互细节
```

**拆解维度**：
1. **用户维度**：用户角色、使用场景、用户目标、用户痛点
2. **功能维度**：核心功能、辅助功能、边界条件、异常处理
3. **技术维度**：数据依赖、系统对接、性能要求、安全要求
4. **体验维度**：交互流程、视觉反馈、无障碍设计

### 阶段2：需求文档(PRD)生成

**文档结构**：
1. 产品概述
   - 产品背景与目标
   - 目标用户画像
   - 核心价值主张

2. 功能需求详述
   - 功能清单与优先级矩阵
   - 功能详细说明（含业务流程图描述）
   - 功能需求规格（输入、处理、输出）

3. 非功能需求
   - 性能要求
   - 安全要求
   - 兼容性要求
   - 可用性要求

4. 交互设计说明
   - 页面结构与导航
   - 核心交互流程
   - 状态定义（正常态、空数据态、错误态、加载态）

5. 验收标准
   - 功能验收条件
   - 测试场景清单

### 阶段3：高保真原型设计

**设计原则**：
- 遵循现代UI设计规范（Apple Human Interface / Material Design 3）
- 响应式设计，支持移动端和PC端
- 精细的动效和过渡动画
- 真实感的数据展示（非Lorem ipsum）

**原型规格**：
- **移动端**：375pt 基础宽度，16pt 基准间距
- **PC端**：1440pt 基准宽度，8pt 栅格系统
- **色彩系统**：主色、辅助色、功能色、中性色
- **字体规范**：标题、正文、辅助文字层级

**页面类型**：
- 首页/概览页
- 列表页（含筛选、排序、分页）
- 详情页
- 表单页（输入、选择、日期、文件上传）
- 弹窗与抽屉
- 空状态与错误页
- 加载状态页

### 阶段4：前端演示界面

**技术实现**：
- HTML5 + Tailwind CSS（现代化样式）
- Vanilla JavaScript（交互逻辑）
- SVG图标（Heroicons/Lucide风格）
- 移动端手势支持（点击、滑动）

**演示功能**：
- 页面导航与路由模拟
- 表单交互与验证
- 状态切换与动画
- 响应式布局切换（移动端/PC端预览）

## 输出产物

| 产物 | 格式 | 说明 |
|------|------|------|
| 需求文档 | Markdown | 完整的PRD文档 |
| 原型设计 | HTML | 高保真可交互原型 |
| 设计说明 | Markdown | 设计决策与规格说明 |

## 执行流程

### 步骤1：接收需求
```
用户输入 → 需求理解 → 关键信息提取
```

### 步骤2：生成PRD
```
需求拆解 → 文档撰写 → 结构化输出
```

### 步骤3：设计原型
```
页面规划 → 组件设计 → 布局实现 → 交互绑定
```

### 步骤4：交付演示
```
代码生成 → 本地测试 → 部署上线 → URL交付
```

## 质量标准

- **需求完整性**：覆盖所有功能点和边界情况
- **文档专业性**：符合行业PRD标准格式
- **原型美观度**：Awwwards级别视觉设计
- **交互流畅性**：自然、无卡顿的过渡动画
- **代码质量**：语义化HTML、规范化CSS、简洁JS

## 快速开始

当用户提供产品需求时，按以下流程处理：

1. **分析需求**：提取核心功能和用户场景
2. **确认范围**：与用户确认功能边界和优先级
3. **生成文档**：输出结构化PRD
4. **设计原型**：创建高保真HTML原型
5. **部署交付**：提供在线访问链接
