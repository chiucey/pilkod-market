# 会议纪要生成器

智能会议录音转文字文档整理工具，通过六步严格流程确保信息100%不遗漏且字数至少2000字，将非结构化的原始记录转换为规范、详细、完整的结构化会议纪要。严格按照提取会议时间 → 生成结构化纪要 → 校验对比 → 补全完善 → 再次校验 → 再次完善的六步流程执行，确保最终输出完整、无遗漏、无偏差的会议纪要。

## 核心能力

- PDF/Word 文档解析
- AI 智能提取会议信息（时间、地点、参与者、主持人）
- **100%信息完整性保证** - 通过两轮校验对比确保不遗漏任何信息
- **至少2000字保证** - 强制字数要求，不足时自动补充扩展
- 六步严格处理流程（提取时间 → 首次生成 → 首次校验 → 首次完善 → 二次校验 → 二次完善）
- 按议题组织讨论内容，每个要点下保留所有数据以及对原文的归纳总结的论述语言
- 自动识别和验证公司名称、专业术语
- 支持输出 PDF 或 Word 格式，Word 文档自动排版

## 工作流程

### 阶段 1：接收输入

接受以下格式的文件：
- **PDF 文档**（.pdf）
- **Word 文档**（.docx）

### 阶段 2：文档解析

使用 `extract_pdfs_full_content` 提取 PDF 内容，或直接读取 Word 文档获取原始文本。

### 阶段 3：AI 智能处理

使用 DeepSeek API 进行严格的六步处理流程，确保信息100%不遗漏且字数至少2000字。如果传递了多个会议文件，每个会议文件都执行一遍完整流程，每个文件生成一个纪要。

#### 一、整体任务
对提供的**会议原始材料**，完成：提取会议时间 → 生成结构化纪要 → 校验对比 → 补全完善 → 再次校验 → 再次完善，共**两轮完善循环**，最终输出一份完整、无遗漏、无偏差的会议纪要。

#### 二、第一步：提取会议时间
从材料中识别并提取会议日期，格式统一为：`YYYYMMDD`，无明确日期则使用当日日期。

#### 三、第二步：首次生成会议纪要
##### 结构要求（必须严格遵守）
1. 会议标题（无编号）
【来源/类型】关于【核心议题】的讨论纪要

2. 一、会议基本信息
1. 会议时间：根据文件名称获取
2. 会议地点：根据文章内容获取
3. 参与人员：根据文章内容获取
无信息统一写"未明确"。

3. 二、讨论内容
（请基于材料内容识别和归纳主要议题，每个议题按以下格式组织）

议题1：[主题名称]
 · 要点1
 · 要点2
 · 要点3

议题2：[主题名称]
 · 要点1
 · 要点2
 · 要点3

（依此类推，根据原文内容展开更多议题）

##### 核心要求：
1. 严格按照上述结构和格式输出
2. "二、讨论内容"必须完整覆盖原始材料中的所有重要讨论点，不遗漏任何信息
3. 基于材料内容合理识别和分组议题，确保每个议题主题明确
4. 只输出会议纪要内容，不要任何说明或解释
5. 不使用任何Markdown符号（**、*、#等）
6. 严格基于材料内容，不添加额外信息
7. 纪要总字数不低于2000字
8. 不要生成"会议背景"相关描述（如"会议于XX时间开始"、"石老师安排录音"等），只保留结构化内容
9. **每个要点下保留所有数据以及对原文的归纳总结的论述语言**，确保要点不仅列出关键点，还包含对原文的归纳总结

#### 四、第三步：第一次校验对比
对照**原始材料**与**刚生成的纪要**，输出校验报告，格式固定：
【校验结果】
1. 原文总字数：XXX
2. 提取内容字数：XXX
3. 发现遗漏点：XX处
4. 发现语义偏差：XX处
5. 总体评价：通过/不通过
6. 具体缺失信息列表：
- 遗漏内容1
- 遗漏内容2
……
无遗漏则写"无"。

注意：若原文中出现公司名、机构名、专业术语等专有名词，并且怀疑是语音转写错误，需结合公开新闻、行业资料或相关背景判断名词是否应为更准确的写法；如果无法确认，则保留原始表述并在校验报告中注明"名称未明确"。

#### 五、第四步：第一次完善纪要
根据上面的校验报告，**补充所有遗漏、修正所有偏差**，保持原有结构不变，输出完善后的完整纪要。

#### 六、第五步：第二次校验对比
再次用**原始材料**对照**完善后的纪要**，输出新一轮校验报告，格式同上。

#### 七、第六步：第二次完善纪要
根据第二次校验报告，再次补充修正，形成最终版纪要。

#### 八、最终输出要求
1. 先输出：会议日期：YYYYMMDD
2. 再输出**最终版完整会议纪要**
3. 全程结构清晰、层级分明、无多余内容、无过程描述
4. 严格基于原文，不编造信息
5. 不提问、不中断、不等待补充，一次性完成全部流程

### 阶段 4：输出交付

#### 九、排版成docx文件并返回
必须要按照最终输出将内容排版到docx文件返回，文件名称格式为：日期+关于XXX的会议纪要。
- 生成一个名为 `YYYYMMDD关于XXX的会议纪要.docx` 的文件。
- docx 文件内必须包含最终版完整会议纪要内容，不可包含任何额外说明、过程描述或 Markdown 符号。
- 文档排版要求如下：
  - 标题（会议标题）采用：宋体、黑体、16 磅、居中、加粗。
  - 一级标题（如"一、会议基本信息"、"二、讨论内容"）采用：微软雅黑、14 磅、黑色、左对齐、加粗。
  - 正文段落采用：微软雅黑、12 磅、黑色，首行缩进 2 个字符，段落间距固定值6pt，行间距1.5倍行距。
  - 议题名称采用：微软雅黑、12 磅、黑色、加粗。
  - 每个要点保持清晰分行，建议使用无序列表符号或清晰的段落格式展示。
  - 文本保持统一字号和行距，版面整洁，层次分明。
- 最终返回时必须直接输出生成的 docx 文件，不要额外输出其他内容。

## 详细用法示例

### 示例 1：上传 PDF 文件整理

```
用户：请帮我整理这份会议记录，生成会议纪要
[附上 meeting_audio.pdf]
```

**AI 处理流程：**
1. 解析 PDF 文件内容
2. 提取会议时间（YYYYMMDD格式）
3. 首次生成结构化会议纪要（至少2000字）
4. 第一次校验对比，输出校验报告
5. 第一次完善纪要，补充遗漏修正偏差
6. 第二次校验对比，确保无遗漏
7. 第二次完善纪要，形成最终版
8. 输出最终版完整会议纪要，并生成规范排版的docx文件

### 示例 2：处理 Word 文档

```
用户：这是我们部门月度会议的文字记录，帮我整理成规范的会议纪要
[附上 monthly_meeting.docx]
```

**AI 处理流程：**
1. 读取 Word 文档内容
2. 提取会议时间（YYYYMMDD格式）
3. 首次生成结构化会议纪要（至少2000字，每个要点下保留所有数据及归纳总结论述语言）
4. 第一次校验对比，输出校验报告
5. 第一次完善纪要，补充遗漏修正偏差
6. 第二次校验对比，确保无遗漏
7. 第二次完善纪要，形成最终版
8. 输出最终版完整会议纪要，并生成规范排版的docx文件

### 示例 3：提取会议要点

```
用户：帮我从这份会议记录中提取关键要点和待办事项
[附上 project_review.pdf]
```

**AI 处理流程：**
1. 解析文档内容
2. 提取关键信息和决策事项
3. 归纳总结主要要点
4. 输出精简要点摘要（如需完整纪要，请使用标准会议纪要功能）

### 示例 4：批量整理

```
用户：我有5份会议录音转文字的文档，能帮我都整理成会议纪要吗？
[附上多个文件]
```

**AI 处理流程：** 逐一处理每个文档，对每个文件执行完整的六步流程，生成对应的规范会议纪要（每个文件生成一个纪要文档）。

|------|----------|------|
| PDF | 正式存档、存档留底 | 楷体、1.5倍行距、规范排版，字体大小（主标题：18；章节标题：14；正文：12）|

## 使用技巧

### 获取最佳效果

1. **上传录音转文字的原始文档**（未经整理的版本效果更佳）
2. **文件名包含日期信息**（如 `会议记录_20240315.pdf`），便于自动提取会议时间
3. **包含清晰的发言人信息**（有助于识别观点来源）
4. **系统默认输出docx格式**，自动按照规范排版，如需PDF格式可在请求中说明
5. **如需保证信息完整性和详细程度**：系统默认通过六步流程确保100%信息覆盖和至少2000字，如需调整可在请求中说明

### 常见需求表达

- "帮我整理成会议纪要" → 生成完整规范纪要（默认六步流程，100%信息覆盖+2000字+docx输出）
- "提取关键要点" → 输出精简要点摘要
- "整理成Word格式" → 输出可编辑的 Word 文档（默认已启用）
- "整理成PDF格式" → 输出PDF格式会议纪要
- "帮我检查有没有遗漏" → 进行二次校验
- "保证不遗漏任何信息" → 启用严格校验模式
- "纪要要详细，至少2000字" → 强制字数达标处理
- "既要完整又要详细" → 同时启用信息完整性和字数保证

## 注意事项

1. **输入要求**：上传录音转文字的原始文档效果最佳
2. **信息验证**：可帮助纠正语音转文字时的公司名称错误
3. **信息完整性保证**：通过六步严格流程（两轮校验完善循环）确保100%信息覆盖率，不遗漏任何信息
4. **字数保证**：强制要求至少2000字，通过多轮验证和补充确保字数达标
5. **质量保证**：通过两轮校验对比和两轮完善补充，确保最终纪要无遗漏、无偏差
6. **格式规范**：输出为标准会议纪要格式，无 Markdown 符号
7. **文档排版**：自动生成规范排版的docx文件，包含标准字体、字号、段落格式
