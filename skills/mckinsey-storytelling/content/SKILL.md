# McKinsey Storytelling Framework

Build presentations that combine McKinsey's structured storyline methodology with data-driven narrative techniques. Each slide delivers a data-backed insight with clear visual support.

## Core Philosophy

**Structure + Evidence + Impact**

A compelling data story has three layers:
1. **Storyline** - The logical backbone (from Storyline Builder)
2. **Data** - Quantitative evidence (from Data Storytelling)
3. **Visual** - Clear communication (from Data Storytelling)

The McKinsey approach ensures structure; data storytelling ensures impact.

## How to Use This Framework

**Step 1: Define the Decision**
- What decision or action does this presentation drive?
- Who is the audience and what do they care about?
- What is the single key message?

**Step 2: Build the Storyline**
- Start with the end in mind
- Each line = one slide title (action-oriented)
- Follow the Problem → Context → Analysis → Solution flow
- Use MECE principles for section organization

**Step 3: Inject Data**
- For each storyline point, identify supporting data
- Choose the most impactful metric or comparison
- Apply the "so what" test: why does this matter?

**Step 4: Design the Visual**
- Select chart type that tells the story
- Use progressive reveal if complexity builds
- Annotate key insights directly on visuals

**Step 5: Verify the Flow**
- Can someone understand the story from titles alone?
- Does each slide build on the previous?
- Is the "so what" clear at every step?

## Storyline Templates with Data Integration

### Template 1: Market Strategy + Data

**Flow: Opportunity → Evidence → Position → Strategy → Roadmap**

```
Storyline:
1. [Market] represents $XXB opportunity growing at XX% CAGR
2. We operate in [segment] worth $XXB with specific growth metrics
3. Top 3 competitors generate $XXM-XXB revenue with performance benchmarks
4. Our revenue of $XXM positions us as [rank] with XX% YoY growth
5. [Product] addresses [use case] for [target segment]
6. Customer data shows XX% enterprise vs XX% SMB split
7. Pricing benchmark: $XX ACV vs industry average of $XX
8. Competitive differentiation: [metric] vs [competitor metric]
9. Three growth opportunities ranked by ROI potential
10. Priority opportunity backed by market sizing data
11. 18-month roadmap with milestones and expected outcomes
```

### Template 2: Problem-Solving + Data

**Flow: Problem → Impact → Root Cause → Solutions → Recommendation**

```
Storyline:
1. [Problem] costs $XXM annually (XX% of revenue)
2. Problem driven by three factors with quantified contributions
3. [Factor 1]: $XXM impact, XX% of total problem
4. [Factor 2]: $XXM impact, XX% of total problem
5. [Factor 3]: $XXM impact, XX% of total problem
6. Root cause: Data reveals [key pattern or correlation]
7. Three solution approaches with impact/effort metrics
8. Solution comparison: Impact, investment, timeline data
9. Recommended solution: XX% impact at $XXM investment
10. Implementation phases with success metrics
11. Expected ROI: XX% with payback period of XX months
```

### Template 3: Quarterly Review + Data

**Flow: Headline → What's Working → What Needs Attention → Action**

```
Storyline:
1. Headline: [Key metric] changed XX% to $XX
2. Performance vs target: XX% achievement rate
3. Winning initiatives: [Metric] improvement from [Initiative A]
4. Winning initiatives: [Metric] improvement from [Initiative B]
5. Underperforming areas: XX% below target
6. Root cause: Data shows [specific pattern]
7. Recommended actions with expected impact
8. Next quarter targets: [Metric 1] = XX, [Metric 2] = XX
```

## The Three Pillars of Data Storytelling

### Pillar 1: Data (Evidence)

**Principles:**
- Lead with the insight, not the methodology
- Use specific numbers: "23%" not "significant increase"
- Compare against baselines: target, prior period, benchmark
- Show statistical significance when relevant

**Data Selection Checklist:**
- [ ] Does this number support the storyline?
- [ ] Can the audience act on this insight?
- [ ] Is this the most impactful metric?
- [ ] Have I removed irrelevant complexity?

### Pillar 2: Narrative (Meaning)

**The Narrative Arc:**
```
1. Hook: Grab attention with surprising insight
2. Context: Establish baseline and scale
3. Rising Action: Build through data points
4. Climax: The key insight or turning point
5. Resolution: Recommendations
6. Call to Action: Next steps
```

**Transition Phrases:**
```
Building narrative:
• "This leads us to ask..."
• "When we dig deeper..."
• "The pattern becomes clear when..."
• "Contrast this with..."

Introducing insights:
• "The data reveals..."
• "What surprised us was..."
• "The inflection point came when..."
• "The key finding is..."

Moving to action:
• "This insight suggests..."
• "Based on this analysis..."
• "The implication is clear..."
• "Our recommendation is..."
```

### Pillar 3: Visual (Clarity)

**Chart Selection Guide:**

| Story Need | Best Chart Type |
|------------|-----------------|
| Show trend over time | Line chart |
| Compare categories | Bar chart (horizontal for >5 items) |
| Show part-to-whole | Stacked bar or donut |
| Show correlation | Scatter plot |
| Highlight before/after | Side-by-side comparison |
| Emphasize magnitude | Big number + context |

## Visualization Techniques

### Technique 1: Progressive Reveal

Build complexity gradually:

```
Slide 1: [Headline] + simple line chart
Slide 2: Add growth rate overlay
Slide 3: Add segment breakdown
Slide 4: Add market share context
Slide 5: [Key insight] with full picture
```

### Technique 2: Contrast and Compare

Emphasize differences:

```
┌─────────────────┬─────────────────┐
│     BEFORE      │      AFTER      │
│                 │                 │
│   5-day cycle   │   1-day cycle   │
│   15% errors    │    2% errors    │
│   $50/unit      │    $20/unit     │
└─────────────────┴─────────────────┘
```

### Technique 3: Annotation and Highlight

Make insights visible on the chart:

```
• Draw attention to key data points
• Add callout boxes for insights
• Use color to emphasize vs de-emphasize
• Include threshold lines (target, benchmark)
• Annotate inflection points with context
```

### Technique 4: Big Number + Context

For executive summaries:

```
┌─────────────────────────────────────┐
│                                     │
│           $2.4M                     │
│     Annual churn cost               │
│                                     │
│  8.5% rate vs 5% industry avg      │
│  500 customers lost last quarter    │
│                                     │
└─────────────────────────────────────┘
```

## Slide Title Formula

**Bad Examples:**
- "Q4 Sales Analysis"
- "Customer Churn Report"
- "Marketing Performance"

**Good Examples:**
- "Q4 Sales Beat Target by 23% - Here's Why"
- "We're Losing $2.4M to Preventable Churn"
- "Content Marketing Delivers 4x ROI vs Paid"

**Formula:**
```
[Specific Number/Change] + [Business Impact] + [Actionable Context]
```

Each slide title should be a complete sentence that delivers the insight.

## Common Mistakes to Avoid

1. **Data dump**: Show only what supports the storyline
2. **Missing context**: Always include benchmarks or comparisons
3. **Burying the insight**: Lead with the key finding
4. **Topic titles**: Use action titles, not subject labels
5. **No ending**: End with clear recommendations and next steps
6. **Vague language**: "Improved significantly" → "Grew 23%"
7. **Chart junk**: Remove unnecessary gridlines, backgrounds, 3D
8. **Inconsistent scales**: Ensure comparisons are fair

## Best Practices Summary

**Do:**
- Start with the "so what"
- Use the rule of three (three points, three comparisons)
- Show, don't tell - let data speak
- Connect to audience goals
- End with clear action
- Use parallel structure in similar sections
- Include signposts for complex presentations

**Don't:**
- Data dump - curate ruthlessly
- Bury the insight - front-load findings
- Use jargon - match audience vocabulary
- Show methodology first - context, then method
- Forget the narrative - numbers need meaning
- Use topic titles - use action titles
