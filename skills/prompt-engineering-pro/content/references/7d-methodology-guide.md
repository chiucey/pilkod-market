# 7D提示词工程方法论详细指南

本文档提供7D方法论每个阶段的深入指导和最佳实践。

## D1: 准备 (Define) - 深度指南

### 需求澄清的艺术

需求澄清是整个提示词工程的基础。良好的开始可以避免后续大量的返工。

#### 开放式问题清单

```
基础澄清问题：
1. "你希望AI扮演什么角色？"
2. "具体要完成什么任务？"
3. "输入是什么，输出期望是什么？"
4. "使用场景是什么？（一次性/定期/产品集成）"
5. "目标用户是谁？"

深度澄清问题：
6. "之前尝试过什么方法？效果如何？"
7. "有什么绝对不能出现的内容？"
8. "成功的标准是什么？"
9. "有哪些约束条件需要遵守？"
10. "有什么参考资料可以使用？"
```

#### 用户类型识别

| 用户类型 | 特征 | 询问策略 |
|---------|------|---------|
| 技术开发者 | 熟悉API/代码 | 深入技术细节 |
| 内容创作者 | 关注创意/风格 | 强调示例和风格 |
| 业务人员 | 关注效率和结果 | 强调ROI和场景 |
| 普通用户 | 期望简单易用 | 提供模板和引导 |

#### 典型场景快速匹配

```
场景 → 推荐初始问题：
├── 写作辅助 → "什么类型的文章？目标读者是谁？"
├── 代码生成 → "什么编程语言？有什么具体要求？"
├── 数据分析 → "有什么数据？想要什么结论？"
├── 创意发散 → "需要什么类型的创意？数量要求？"
├── 翻译润色 → "什么类型的文本？什么风格？"
└── 问答系统 → "什么领域的知识？深度要求？"
```

## D2: 拆解 (Decompose) - 深度指南

### 任务分解原则

#### 黄金分割法则

```
复杂任务 = 1个核心任务 + N个辅助任务 + M个约束条件

示例：写一篇营销文案
核心任务：撰写销售文案
辅助任务：构思标题、设计结构、添加CTA
约束条件：字数限制、品牌调性、禁止承诺
```

#### 模块化设计模板

```
┌─────────────────────────────────────────┐
│            提示词结构分解               │
├─────────────────────────────────────────┤
│ [模块1] 角色设定                         │
│         - 谁来执行？                    │
│         - 具备什么能力？                │
│         - 有什么限制？                  │
├─────────────────────────────────────────┤
│ [模块2] 任务定义                        │
│         - 具体做什么？                   │
│         - 做到什么程度？                │
│         - 有什么标准？                  │
├─────────────────────────────────────────┤
│ [模块3] 上下文                          │
│         - 有什么背景？                 │
│         - 需要什么前提？               │
│         - 参考什么信息？                │
├─────────────────────────────────────────┤
│ [模块4] 输出格式                        │
│         - 什么结构？                   │
│         - 什么风格？                   │
│         - 多长合适？                    │
├─────────────────────────────────────────┤
│ [模块5] 质量要求                        │
│         - 有什么标准？                  │
│         - 禁止什么？                    │
│         - 特别注意什么？                │
└─────────────────────────────────────────┘
```

#### 依赖关系图谱

```
任务依赖分析：

[输入] → [核心处理] → [质量检查] → [输出格式化]
           ↑
      [上下文]    [约束验证]
           ↑
      [角色设定]
```

## D3: 诊断 (Diagnose) - 深度指南

### 问题诊断清单

#### 模糊性问题检测

```
检测问句：
"用户能对这句话有多种理解吗？"
"这句话中的某个词是否有多种含义？"
"代词或指示词是否指向明确？"

常见模糊表达：
- "适当的" → 什么是适当的？
- "相关的" → 什么是相关的？
- "重要的" → 什么是重要的？
- "合适的" → 什么是合适的？
- "合理的" → 什么是合理的？

修复方法：替换为具体标准或提供判定规则
```

#### 完整性检测

```
信息完整性检查：

输入信息：
[ ] 类型定义
[ ] 数量/规模
[ ] 时间范围
[ ] 质量标准

输出信息：
[ ] 格式定义
[ ] 结构要求
[ ] 长度限制
[ ] 风格定义

约束信息：
[ ] 必须包含
[ ] 必须排除
[ ] 优先级
[ ] 边界条件
```

#### 一致性检测

```
矛盾检测：
- "简洁但详细" → 矛盾
- "创新但保守" → 矛盾
- "快速但高质量" → 可能矛盾

修复策略：
1. 明确优先级：首要目标是什么？
2. 设置trade-off规则：冲突时牺牲哪个？
3. 分场景处理：不同情况不同规则
```

### 诊断报告模板

```markdown
## 诊断报告

### 问题汇总
| 序号 | 问题类型 | 严重程度 | 具体描述 | 修复建议 |
|-----|---------|---------|---------|---------|
| 1   | 模糊性  | 高      | xxx     | 替换为  |
| 2   | 缺失性  | 中      | xxx     | 添加    |
| 3   | 矛盾性  | 高      | xxx     | 明确    |

### 修复优先级
1. [P0] 必须修复（影响核心功能）
2. [P1] 建议修复（影响使用体验）
3. [P2] 可选优化（提升效果）

### 预估影响
- 修复后预计提升：XX%
- 风险等级：低/中/高
```

### 先进技术详解

#### Chain of Thought (CoT)

```
适用场景：
- 数学推理问题
- 逻辑推理任务
- 多步骤问题
- 需要解释的任务

模板：
"请逐步思考这个问题，每一步都说明理由..."

示例：
问题：如果小明有5个苹果，给了小红2个，又买了3个，现在有多少？
思考：1. 小明开始有5个
     2. 给了小红2个，5-2=3
     3. 又买了3个，3+3=6
答案：6个
```

#### Few-shot Prompting

```
适用场景：
- 需要特定格式输出
- 需要特定风格
- 需要特定领域的理解

示例结构：
输入1 → 输出1
输入2 → 输出2
输入3 → 输出3
[新输入] → ?

最佳实践：
- 提供3-5个示例
- 示例覆盖主要场景
- 示例格式一致
- 避免示例过于相似
```

## D5: 开发 (Develop) - 深度指南

### 提示词编写规范

#### 角色设定最佳实践

```markdown
# 好的角色设定
"你是一位拥有10年经验的高级数据分析师，擅长使用Python和SQL，
专注于电商行业的数据分析。你能用通俗易懂的语言解释复杂的数据概念。"

# 不好的角色设定
"你是一个分析师"
"你是AI助手"
"你很聪明"
```

#### 任务定义规范

```markdown
# 好的任务定义
"分析这份销售数据，找出：
1. 销售额最高的前5个产品
2. 环比增长超过10%的品类
3. 存在的问题和机会点

输出格式：表格+简要分析"

# 不好的任务定义
"分析一下数据"
"看看有什么问题"
"写个报告"
```

#### 约束条件设置

```markdown
# 有效约束示例
必须遵守：
- 总字数不超过500字
- 使用中文输出
- 数据必须来自提供的数据源

禁止行为：
- 不编造任何数据
- 不使用未经授权的外部数据
- 不包含主观评价（仅基于数据）
```

### 版本控制规范

```markdown
# 版本命名
v1.0 - 初始版本
v1.1 - 修复歧义
v2.0 - 增加功能
v2.1 - 优化结构

# 版本记录
| 版本 | 日期 | 修改内容 | 修改原因 |

```

#### 效果评估标准

```markdown
## 效果评分体系

| 维度 | 权重 | 评分标准 | 评估方法 |
|-----|------|---------|---------|
| 准确性 | 30% | 输出内容正确性 | 人工审核/自动化验证 |
| 完整性 | 25% | 覆盖所有要求 | 需求覆盖度检查 |
| 可读性 | 20% | 表达清晰度 | 流畅度评分 |
| 规范性 | 15% | 格式符合度 | 模板匹配度 |
| 效率 | 10% | 执行效率 | Token消耗/响应时间 |

综合评分 = Σ(维度分数 × 权重)
```

## D7: 迭代 (Iterate) - 深度指南

### 反馈收集方法

#### 用户反馈问卷

```markdown
## 提示词效果反馈问卷

1. 提示词是否清晰易懂？
   ○ 完全理解
   ○ 基本理解
   ○ 部分理解
   ○ 不理解

2. AI输出是否符合预期？
   ○ 完全符合
   ○ 大部分符合
   ○ 部分符合
   ○ 不符合

3. 有什么具体问题或建议？

4. 是否需要进一步优化？
```

#### 迭代决策树

```
收到反馈
    │
    ├── 问题类型：理解偏差
    │       │
    │       ├── 角色不清 → 强化角色设定
    │       ├── 任务不清 → 明确任务定义
    │       └── 约束不清 → 补充约束条件
    │
    ├── 问题类型：效果不达标
    │       │
    │       ├── 准确性 → 增加示例/明确标准
    │       ├── 完整性 → 补充要求清单
    │       └── 格式 → 优化输出模板
    │
    └── 问题类型：效率问题
            │
            ├── 太长 → 精简内容
            ├── 太慢 → 简化逻辑
            └── 成本高 → 优化token使用
```
