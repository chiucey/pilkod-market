# 来源与证据协议

本文件回答三个问题：用哪个来源、怎么登记来源、怎么标记证据。它配合 `quality-checks.md` 中的检查表使用，二者缺一不可。

## 1. 来源层级（自上而下）

按用户被授权访问的强度顺序，使用最强的可用来源：

1. **用户提供的来源包**：上传文件、粘贴的上下文、邮件 / 云盘 / 即时消息线索、内部研究、过往模型、笔记、演示文档、报告、工作簿摘录。
2. **可调用的连接器或用户提供的合规导出**：行情、文档、研究、事实底库、其他数据连接器；若运行时无法实际调用，不要假装直连。
3. **一手公开来源**：SEC 与公司申报材料、业绩公告、投资者演示、官网、新闻稿、可访问的评级机构报告、法院 / 监管文件。
4. **可信的标准化数据源**：优先 MiniMax Finance Data MCP；也可使用宿主平台支持的其他合规数据连接器，或用户提供的导出文件。指定数据源不可调用时，要么请求新的导出，要么明确标注替代来源。
5. **可信的二手来源**：信誉良好的新闻、行业刊物、用户自带的卖方或第三方研究、可信数据库。
6. **网页搜索兜底**：仅在上述均不可用时使用。
7. **假设**：用户自带或显式声明的推断假设，永远不要伪装成事实。

若环境另装了 `financial-source-of-truth` 技能，按它更详尽的层级与引用协议处理。

## 2. 来源台账字段

每个 brief 都要维护一份轻量 `Source_Index`：

| 字段 | 说明 |
|---|---|
| `source_id` | 唯一标识，例如 `S1`、`S2`。 |
| `source_name` | 文件、演示、导出、提供商、内部资料或网站名称。 |
| `source_type` | 用户文件 / 连接器 / 一手申报 / 提供商 / 新闻稿 / 二手来源 / 网页兜底 / 假设。 |
| `provider_or_owner` | 来源所有者、提供商或内部小组。 |
| `as_of_date` | 数据所代表的时点。 |
| `retrieved_at` | 助手实际访问的时间。 |
| `period_covered` | FY / Q / 月 / LTM / 时段。 |
| `source_location` | 页码、页签、单元格、URL、文件名、消息链接、数据对象。 |
| `freshness_status` | current / acceptable / stale / preliminary / unknown。 |
| `notes` | 局限、注记、冲突、访问限制。 |

## 3. 时效性判断

按下表判断"是不是已经过时"。无法判断时间时，统一标 `unknown`，不要默认 current。

| 数据类型 | 仍然有效的判定 | 触发 stale |
|---|---:|---:|
| 行情 / 市值 / EV | 当日或最近收盘 | 超过 1 个交易日（除非用于历史分析） |
| 公开财务 | 最近一期申报 / 已公布季度 | 已被新的业绩或申报取代 |
| 一致预期 | 最新一期 | 财报前后 7–14 天、其他情况下 30 天 |
| 信用评级 / 利差 | 最新可得 | 活跃信用 1 周；静态画像 30 天 |
| 公开发行人债务条款 / 信用指标 | 最新申报、执行协议或最新行情 | 被再融资 / 修改 / 交换 / 评级行动 / 新申报取代 |
| 上市基金 / 管理人 AUM / NAV / 持仓 / 业绩 | 最新一次公开披露周期 | 早于最新可得周期或缺失 as-of |
| 内部研究模型 / 估计 | 当前模型版本或显式 frozen 日期 | 已被新申报、新成交、指引、一致预期或模型更新取代 |

## 4. 证据标签（exact strings）

以下标签严格遵守拼写，便于 `validate_brief_json.py` 校验：

- `fact_source_reported`：直接来自一手文档或可访问的连接系统。
- `fact_provider_standardized`：来自可信数据商的标准化字段。
- `derived_calculation`：由已引用输入计算所得。
- `issuer_management_claim`：公司 / 发行人 / 管理层的陈述，仍需证据支撑。
- `management_adjusted`：公司自定义调整 / 管理层调整指标。
- `analyst_adjusted`：分析师做的标准化、加回、重分类或形式调整。
- `estimate_consensus`：一致预期或数据商预测。
- `analyst_interpretation`：基于事实的综合判断，不来自某一具体源句。
- `assumption_user_provided`：用户自带的假设。
- `assumption_inferred`：从不完整信息中推断；披露并保持低置信度。
- `missing_required_source`：需要的事实或指标尚未找到来源。
- `stale_source`：可能已被取代的来源。
- `contradicted_source`：与另一重要来源冲突。
- `unknown`：无法判断的证据类型。

## 5. 置信度标签

- `high`：一手 / 连接器来源、时效新、主体/期间/单位/标签清晰。
- `medium`：可信数据商或来源清楚，但存在轻微映射歧义或时效问题。
- `low`：陈旧 / 预披 / OCR 严重 / 推断 / 冲突 / 期间或单位不清。

## 6. 引用格式

对话回复优先使用宿主环境原生引文语法。落到文件或工件里的表格统一使用紧凑的源引用：

`Metric | Period | Value | Source | Evidence | Confidence`

其中 `Source` 通常是源 ID 加位置，例如 `S2 p.14`、`S4 tab Revenue cell D22`、`S1 FY2025 10-K Item 8`、`S5 provider pull 2026-05-07`。

## 7. 冲突处理

当来源出现冲突：

1. 若差异显著，两个值都保留。
2. 优先级：一手 > 数据商；连接器 > 复制的电子表格；终版 > 预披；审计版 > 未审计版；最新版 > 被取代版。
3. 若选定一方，说明理由。
4. 影响画像时，把冲突记入 `Risks / gaps`。
5. 未经用户明确同意并披露方法，不要平均、平滑或反推冲突值。

## 8. 事实 vs 假设

- 事实必须有来源支撑。
- 计算必须有引用过的输入和可见公式 / 解释。
- 公司 / 发行人 / 管理层的陈述即便有引用，也仍是"陈述"，不是事实。
- 假设必须标记为假设，不能混入事实表。

## 9. 公开股票的时效性专项

市值、价格、自由流通、ADV、卖空、持仓、ETF/指数成分、一致预期、因子敞口等字段，必须带来源标签和 as-of 日期。无法取得时使用"缺失证据"标签，并交接给下一道工作流，绝不脑补。
