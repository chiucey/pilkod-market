# 速览质量检查

在交付前按本清单分块自检。任何一项失败，先修后交，不要把已知的问题留给下游。

## 一、主体身份

- 确认主体确实是想要的那家公开公司 / 发行人 / 信用主体 / 证券,而不是同名相近的另一家。
- 公开公司:核对股票代码 / 交易所 / 财年截止。
- 独立信用分析流程:核对发行人 / 母公司、工具代码、评级 / 证券背景(只要重要)。
- 本技能不处理基金 / 管理人尽调;非发行人的基金 / 管理人画像应路由出 `company-brief`。

## 二、来源完整性

- 任何重要指标都需配齐 source / period / units / evidence / confidence 五项。
- 不要使用没有 as-of 日期的陈旧行情。
- 不要把营销说辞当作第三方核实事实。
- 用户提供或可调用的来源在手时,不要回退到网页摘录。
- 未审计、预披、形式调整、调整后、管理层定义的数字必须标旗。

## 三、指标一致性

- 收入、EBITDA、净债务、杠杆、利润率、AUM / NAV、股价、市值、EV、估值都必须带期间与单位。
- 不可在没有标签的情况下混用财年、自然年、LTM、季度、预测、YTD。
- 不可在缺乏明示换算的情况下混用货币或单位。
- 衍生指标必须在注释中给出输入或公式。
- 源财务材料杂乱或不一致时,先走 `financials-normalizer` 再定稿。

## 四、画像平衡

- 速览要保持精简,不要膨胀成完整 memo。
- 业务描述、指标、动态、含义、风险分块分开,避免互相挤占。
- 没有证据时不要使用 "best-in-class"、"dominant"、"high-quality"、"distressed" 之类的形容词。
- 不下投资建议,除非用户明确要求并已切换到对应分析技能。
- 公开股票投资者速览不得静默省略证券设置、持仓或头寸需求。市值、自由流通、ADV / 流动性、指数成分、ETF / 被动持股、前几大持有人、卖空、可借券 / 拥挤度、因子敞口、治理、资本配置、卖方覆盖、一致预期格局等字段,在相关时应有来源,否则纳入紧凑的来源 / as-of 证据缺口块。
- 出现成交、传闻、监管事项或其他实时事件且重要但非用户重点时,要确认该事件已在 investor read 与 catalyst / risk 中突出展示,并在 evidence-gaps 中标记缺失的一手证据;确认它没有被强行塞进 earnings drivers、估值与倍数摘要中,除非确实改变这些分析。

## 五、估值框架

- 仅有已报告历史数据与衍生 trailing 指标作为支撑时,标题使用 `Trailing Valuation Snapshot` 或 `Valuation Context`。
- 仅当有远期估计、同业证据、目标价证据或显式市场预期来支撑真正的预期讨论时,标题才能含 `Debate`。
- 不要把简化的企业价值算式呈现为完整 EV 桥或承销估值案。

## 六、HTML 呈现

- 选用 HTML 速览时,按 `visual-page` 调用协议处理,保持发行人基线紧凑,不要套上旧式标准化仪表板外壳。
- 使用面向投资者的自然语言来表达证据,不要把 `fact_source_reported`、`missing_required_source` 等内部标签裸露给读者,除非用户要求看支持细节。
- 不要把 ticker、年份、日期、数字区间、指标名、产品标签拆成多个独立带链接的引用词元。
- HTML 文件的渲染检查、响应式检查与 `<media />` 交付由 `visual-page` 完成。

## 七、冲突检查

以下情形必须标旗:

- 多个来源对 收入 / EBITDA / 债务 / AUM / NAV / 股本 / 市值 给出不同数值。
- 数据商数值与申报 / 来源包不一致。
- 公司演示或管理层 deck 与申报、新闻稿、电话会、数据商口径不一致。
- 当前来源已经覆盖了来源包内更早的版本。

## 八、最终 QA 清单(交付前确认)

1. 主体身份已确认。
2. 来源台账存在,或来源局限已显式披露。
3. 已显示 as-of 日期。
4. 指标表含 source / period / units / evidence / confidence。
5. 陈旧 / 冲突 / 缺失数据已标旗。
6. 假设与事实已分离。
7. 交接建议合理。
8. 来源材料已留存。
