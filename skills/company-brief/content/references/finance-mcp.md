# MiniMax Finance Data MCP 调用规范

本规范用于约束在制作多市场上市公司速览时，如何与 MiniMax Finance Data MCP 这条数据通道交互。

## 一、来源优先级

调用任何接口前，请先在心里排好以下优先序，并按此顺序落实事实：

1. 监管机构、交易所和上市公司的正式披露文件。
2. MiniMax Finance Data MCP 返回的结构化数据。
3. 用户自带的模型、跟踪表与研究材料。
4. 其他可独立核验的公开来源。

若 MCP 返回的结构化数据与正式披露口径不一致，以正式披露为准，并把差异原样记录到证据缺口中。

## 二、主体解析（resolve_entity）

不要凭印象猜内部 `code`。统一通过 `resolve_entity` 拿候选，再用交易所、证券代码、公司全称、行业描述四个维度去匹配正确条目。

`entity_type` 与市场的对应关系：

| 场景 | `entity_type` |
|---|---|
| A股个股 | `a_stock` |
| 港股个股 | `hk_stock` |
| 美股个股 | `us_stock` |
| 基金、债券、指数 | `fund`、`bond`、`index` |
| A股行业 / 概念 | `industry`、`sw_industry`、`concept` |
| 港股行业 | `hk_industry` |

查询时既可以用完整公司名，也可以用简称或证券代码。

## 三、数据调用（call_api / query_macro）

- 公司档案、财务、行情、估值、事件、股东、分红融资、基金/债券/指数及行业数据均统一走 `call_api(api_id=..., params=...)`。
- 宏观或产业指标先用 `query_macro(keyword=...)` 搜索，根据返回的 `indicId` 与明细参数拉取时间序列。
- 当 `call_api` 抛出业务枚举类错误时，调用 `enum_candidates` 取候选值后再重试，不要循环重试相同参数。
- 数据量较大时优先用 CSV；用于关键结论的小规模表格保留 Markdown 或 JSON。

## 四、口径登记

每次取数都要顺手登记下列字段，否则下游章节没法核对：

- 市场、交易所、交易代码、内部 `code`
- 数据截至时间（as-of）与报告期
- 单位与币种
- 会计准则
- 复权口径（前复权 / 后复权 / 不复权）

跨市场对比必须先统一币种和报告期，或者明确标记"不可直接比较"的差异；最新价格、估值、事件、宏观数据要带查询时间戳；MCP 没返回的字段一律按缺失处理，绝不脑补或推测。
