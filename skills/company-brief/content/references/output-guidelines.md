# 输出格式与平台中立规范

本文件约束所有面向读者的产物如何选择格式、密度与交付方式,不绑定任何具体平台。

## 一、意图确认

- 当用户已明确指定格式、深度、受众或重点时,直接照做,不要追问。
- 仅当缺失某项信息会"显著改变分析结果"时,在普通对话里提一个简短问题。
- 当无法交互时,采用本技能规定的默认产物:调用 `visual-page` 生成 GUI/HTML 页面,并把假设记在交付说明里。
- 不要依赖特定平台的表单、计划模式、专有 UI 或内部渲染器；GUI/HTML 必须使用 `visual-page` skill 生成。

## 二、格式选择

按请求性质对应:

- **轻量请求**:直接给结构化 Markdown。
- **完整报告 / 速览 / 表格型读者产物**:优先整理为 `visual-page brief`,调用 `visual-page` 生成独立 GUI/HTML;必须能在普通浏览器中直接打开。
- **XLSX / CSV**:仅在用户明确要求、需要导入外部系统或作为审计支持附件时输出。
- **结构化数据**:按需给出 JSON,但不要把 JSON 设为面向读者的主产物。

## 三、可移植性纪律

- 技能内部资源用相对路径引用。
- 不要引用并不存在的父插件、内部路由器或特定供应商的渲染器；GUI/HTML 交付一律调用 `visual-page`。
- 视觉约定:冰白纸背景、液态玻璃风格;不要使用 `visual-page` 默认配色方案;上涨、好事、强调色统一用中国红 `#c0322f`;下跌、坏事统一用稳绿 `#15803d`。
- 宿主平台不支持某种文件格式时,退回 Markdown,但分析结构与来源标注保持不变。
- 所有输出都要保留:数据截至时间、来源、口径、假设、缺失项。
