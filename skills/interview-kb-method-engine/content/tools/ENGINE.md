# 面经知识库 & 求职决策引擎（SKILL）

数据与结论都在本地：卡在包根的 `cards/`，命令在 `tools/`。

**推荐写法（从包根执行）**：`python tools/main.py <子命令>`
**等价写法**：`cd <包根>/tools && python main.py <子命令>`
⚠️ 在包根直接写 `python main.py …`（漏 `tools/`）会 **File not found**。

## 使用者最小契约（最重要的心智）
> **你每场只需要给三个真值**，其余由引擎接手：
> ① `outcome`：这轮过没过（pass/fail）
> ② `why_ended`（若没推进/没 offer）：横向对比 / 审批没通过 / 简历背调 / 薪资 / base / 外包无转正 …
> ③ `offer`：最终 拿到(got) / 没拿到(no) / 在走(ongoing)
> **你不填真值，它就没法替你判断。** 优先序：**实际结果 > 你的主观体感 > AI 推断**；
> 后两者只作参考、不进统计。没实际结果前 `outcome=unknown`。
>
> 给人看的完整解释（为什么要你填、什么时候填）见 `SKILL_GUIDE.md` §三；
> 填空模板见 `CONTRACT.md`。

## 做法 0（最懒，推荐）：把这场面试"全文"丢来
一段完整转写/逐字稿(PDF/txt/记事本)直接发我，并附一句：这是第几轮 + 你这场自己体感 过/没过/不确定。
我按 `tools/digest_guide.md` 自动：
- 读全 → 把面试官问的**所有问题**一条不漏拆出（含你的答/主题/自评）
- 写 reflection(强/弱/改进) + skills 并建议
- 存成 `cards/_inbox/P…yaml`（待你确认，不占正式 I 号）
- 回你"这场会影响总报的哪些点" + 下一步建议（apply/job/report）
只把 ①②③(outcome/why_ended/offer) 留给你确认——这三样臆断会有害，由你定；其余我对你负责。

## 命令速查（从**包根**执行：`python tools/main.py <子命令>`）

> 路径说明：脚本用 `__file__` 定位上级的 `cards/`，**不依赖当前工作目录**，
> 所以下面两种写法**等价**：
> `python tools/main.py report`（包根，推荐）
> `cd <包根>/tools && python main.py report`
> ⚠️ 在包根直接写 `python main.py report`（漏 `tools/`）会 File not found。
>
> **本表是「命令怎么用、口径是什么」的唯一权威来源。**
> 命令名在 `SKILL_GUIDE.md` §四 另有一份**按功能分组的名称索引**（只列名字与一句话，
> 供人一眼看全有什么），但**参数、口径、边界一律以本表为准** ——
> 两处若有不一致，改的是 `SKILL_GUIDE.md`。
>
> `SKILL.md`（给 AI agent）不列命令，只讲"要不要用我、怎么分流、边界在哪"。

### 建档与复盘（数据的来源）

| 命令 | 干什么 | 关键输出 |
|---|---|---|
| `record new --company X --position Y --round 一面 --nature 正编` | 新建一场（进 `cards/_inbox`，不占正式号）；**会问赛道** | 一张待填卡 |
| `record new … --track 内容运营` / `--no-track` | 建卡时直接指定赛道 / 跳过询问 | 同上 |
| `record ask --file P… --q "题目" [--ans … --theme … --score 4]` | **逐题追加，不限条数** | 累积 questions |
| `result --id I007 --outcome pass --reason "…"` | 回填本轮结果（**P/I 卡都能填**）；**写前自动备份**，并打印「旧 → 新」改动明细 | 结果落库 |
| `record fix I007 --offer no --why-ended "横向对比"` | **一条命令补齐三个真值**（缺哪个补哪个；卡里没这字段会自动新增） | 真值齐了 |
| `merge`（`formalize` / `--dry`） | 判重/冲突、把 `_inbox` 转正式 I###（**赛道指定随卡号迁移**） | 防覆盖 |
| `evaluate --file new.txt` | 面完复盘 | 通过可能性 + 逐题答得好/差 |
| `remind` | 找出到期未回填真值的场 **+ 结果已填但 offer/why_ended 仍空的场**（附可复制命令） | 催办清单 |

### 报告与定位

> **v3.4.0 起：报告合并成一个入口 `report`，用 `--view` 切视角。**
> 以前是 7 个独立命令，实测它们**重复输出同一批核心章节**
> （轮次通过率 / 正编外包 / 主场赛道 / 业务过但 offer=no 各算一遍），
> 且同一口径多处各写一份实现 —— 历史上因此出过"四个模块算出四个不同的正编外包拆分"。
> **旧命令名全部保留为别名，行为与输出逐字节不变**，你的老脚本不用改。

| 命令 | 干什么 | 关键输出 |
|---|---|---|
| `report` ⭐主入口 | 生成唯一《求职总报.md》—— **章节最全，日常看这个** | 轮次通过率/正编外包/主场/体量/体量×赛道/反复挂因/业务全过却offer=no/挂了但非能力原因/该投慎投/趋势/跨界告警 |
| `report --view list` | **列出所有视角**（记不住名字时用） | 视角清单 |
| `report --view 轮次 [--recent N]` | 轮次口径 + 正编/外包拆分（= 旧 `report2`） | 按性质拆的通过率 / 优势公司 / 非业务卡点 |
| `report --view 脉搏` | 动态洞察（= 旧 `pulse`） | 趋势 + 跨界告警 |
| `report --view 决策 [--recent N]` | 浓缩决策，生成两份（= 旧 `decision`） | 求职定位_v2 + pulse_v2 |
| `report --view 诊断` | 4 问自我诊断（= 旧 `diagnosis`） | 最高通过率赛道/挂因根源/能力标签/该投什么 |
| `report --view 定位` | 求职定位（= 旧 `strategy`） | 优势赛道（匹配 vs 跨界）各自通过率 |
| `report --view 痛点` | 痛点/优势体检（= 旧 `insights`） | 失分点与优势项 |
| `analyze` / `export` | 跨场统计 / 导出 CSV | 统计表 / CSV（UTF-8 BOM） |
| `backtest` | 预测基线回归 | 留一法 Acc（**用于判断这套判断可不可信**） |

> `--recent N` 控制趋势区看近 N 场（默认 20）。
> 旧名 `report2` / `pulse` / `decision` / `diagnosis` / `strategy` / `insights` 仍可直接用，
> 等价于对应的 `--view`。

### 备战与决策

| 命令 | 干什么 | 关键输出 |
|---|---|---|
| `job --file jd.txt` | 对一份 JD 备战 | 职责画像/匹配度/最匹配历史卡/预测问题 |
| `answer --jd-file jd.txt` | **应答框架 + 缺口清单**（不编答案，只复用你真过了的回答） | 作答骨架/可复用素材/缺口 |
| `answer --q "…" --exclude I007` | 二战同一家时排除那场自己的题 | 去别处找可迁移素材 |
| `apply --company X [--jd …]` | 下场决策 | 这家面过几场/通过率→投不投/历史卡点/曾 pass 高含金 Q-A |

### 图形界面（`web`）

| 命令 | 干什么 |
|---|---|
| `web` | 起本地服务并自动开浏览器（默认 `http://127.0.0.1:8765/`） |
| `web --port 9000` | 换端口 |
| `web --no-open` | 不自动开浏览器 |
| `web --export 面经台.html` | 导出**单文件** HTML（只读快照，数据内嵌） |

**为什么要有图形界面**：界面负责「**看**」，对话负责「**改**」。

当卡攒到几十上百张时，"我在某家被问过什么"这类问题，
在 AI 对话里要翻上下文才能定位，越翻越乱。界面把这些变成**可搜索、可筛选、可点开**：

| 页面 | 解决什么 |
|---|---|
| **对话** | 把想跟 AI 说的话记进 `chat/对话.md`；回 DSH 说一句「看聊天」，AI 读了就回复 |
| 卡片 | 全部卡片**全文搜索**（公司/岗位/题目/回答都能搜）+ 结果/赛道/性质三重筛选 |
| 报告 | 把《求职总报》等 `.md` **渲染成网页**，不用开编辑器 |
| 待办 | 列出缺真值的场次（缺 outcome / why_ended / offer），每条附**可复制的命令** |
| 趋势 | 按时间分段的轮次通过率 + 赛道维度对比 |
| 同类题 | 输一个关键词，看**同一类题你在各场是怎么答的** |

**关于「对话」页（方案 A：网页记录 → AI 读，自动刷新）**

网页里**没有模型**，AI 在 DSH 会话里。这一页做成**左右分栏**：

```
┌──────────────────────┬────────────────────┐
│  对话（每 2 秒自动刷新） │  卡片（可搜可筛）    │
│                      │   [搜索] [结果筛选]  │
│  你：…某家公司那几场   │   I006 某公司 挂    │
│  AI：共16场 2过14挂…  │   I022 …           │
│  [输入框]             │   点开就地看题目      │
└──────────────────────┴────────────────────┘
```

流程：你在网页打字 → 追加到 `chat/对话.md` → 回 DSH 说「**看聊天**」→
AI 读并回复（写回同一文件）→ **回复自动出现在网页**（每 2 秒轮询），不用手动刷新。

**侧栏点开卡片是"就地展开"** —— 不跳走，聊天不被打断。

> **为什么不做成"网页里直接跟 AI 聊"**：网页里没有模型。
> 要么把 API Key 塞进前端（有泄露风险、要多花钱），
> 要么把整套"读卡 / 建档"重写一遍 —— 等于把 agent 重做一次。
> 现在这样零依赖、数据不出本机。
>
> **代价（如实说明）**：**省不掉"回 DSH 说一句"这一步** ——
> AI 只在你发消息时才会动，无法主动轮询网页。
> 自动刷新解决的是"回复要手动刷新才看得到"，不是"不用触发 AI"。

`chat/` 与 `cards/` **同级敏感**（含你的原话与求职细节），
已加入 `.gitignore` 与打包排除清单，不会外泄。

**三条边界（重要）**：
1. **零额外依赖** —— 只用 Python 自带的 `http.server`，不装 flask、不联网、不上传。
2. **能改真值**（v3.6 起）—— 卡片详情页可直接改
   `outcome` / `offer` / `why_ended` / `reason`，走的是与命令行 `record fix`
   **完全同一条写入路径**：**写前自动备份到 `cards/_bak/`** + 返回「旧 → 新」改动明细。
   复杂内容（题目、reflection）仍建议用 AI / 命令行改。
3. **数据全在本机** —— 服务只监听 `127.0.0.1`，外部访问不到。
   `--export` 出来的单文件**内嵌了你的全部卡片数据**，**别外发**。

**写接口的四道防护** —— 本地服务也必须防：**你浏览器里的任何网页都能向它发请求**。

| 防护 | 作用 |
|---|---|
| 只接受**卡号**（如 I007），路径由后端自己定位 | 杜绝目录穿越（不接受任何路径片段） |
| **字段白名单**（只允许那 4 个真值字段） | 杜绝"把整张卡改烂"（实测：放开后 `skills` 会被覆盖） |
| 校验 **Origin/Referer** 为本机 + 要求自定义头 `X-Mianjing-Edit` | 防 CSRF（跨站请求带不了自定义头） |
| **写锁**串行化 | 多线程服务下避免并发互相覆盖 |

> 这四条都进了 `validate` 自检（真发 POST 断言"该拦的拦住了"），
> 并用**注入验证**确认删掉任一条都会报红。
>
> ⚠️ 一处诚实的说明：**卡号格式校验只是纵深防御的第二层**。
> 实测即使删掉它，目录穿越仍会被 `find_card`（只在 `cards/` 里 glob `I*_*.yaml`）挡住 ——
> 所以注入测试对它的期望是「**不报红**」，免得以后有人误以为它是唯一防线。

**空库会引导**：如果 `cards/` 还是空的（新装包），界面会给一屏引导，
告诉你怎么建第一张卡 —— 而不是显示一个空列表让人以为是筛错了。

## 标准动作流（对"用自己的数据"的日常）
1. `record new` 建一场 → `record ask` 把面试官问的**每一题都记上**（想答就写 ans/theme/score）。
2. 补 3 个真值：`outcome` / `why_ended` / `offer`（够就行）。
3. （可选）`validate`，确保卡干净；再准备投某家前 `apply`；临场前用 `job` 备题；
   要**成篇的答题准备**用 `answer --jd-file jd.txt`；面完 `evaluate` 复盘。
4. 过 2-3 场/每周末：`report` 刷新你的唯一总报看是否在变好、决定下步投哪儿。

## 口径（看每张卡/每份报告都要脑内保持清晰）
- `outcome` = 本轮通过与否；`offer` + `why_ended` = 最终有没有、为什么。
  「业务轮全过但 offer=no」≠ 挂了，而是非能力卡点（横向/审批/薪资…）。
- **正编 vs 外包分开看**：外包通过率常虚高，主战场看正编那一栏。
- 用"通过轮 / 总轮"衡量自己，比"拿没拿到 offer"诚实。

## 数据规模会影响的
- 样本少（<15-20 场）时报告看"方向与趋势"就行，别信 <个位数 的百分比；数据上去后统计区才稳。
- 单场"为什么挂"是逐题/语义层面的归因（evaluate 做），不是报表聚合数能回答的——两者别用错层。

## 运行时行为（引擎默认，接新卡/读报告时别混淆）
- **改卡前自动备份**：`result` 等原地改写卡片的命令，会先把原卡复制到
  `cards/_bak/<时间戳>__<原文件名>`，并打印「旧 → 新」改动明细。
  改错了就用备份复制回去。`_bak/` 不会被 `report`/`validate` 扫到（只扫 `cards/I*.yaml`），
  且随 `cards/` 一起被 `.gitignore` 挡掉，不会外泄。**备份不会互相覆盖**（同一秒也加序号）。
  > 加这条的原因是一次真实事故：在真实数据目录上跑了一句 `result --reason "验证用"`，
  > 就把某张卡原本的 reason 覆盖了，且当时**没有任何副本可还原**。
- 每正式卡应有 `interview.nature` ∈ 正编/外包/兼职/实习。报告「1)正编 vs 外包」会列出出现的都；「主场正编/该投」只看 **正编**（外包/兼职/实习不掺进正编统计）。
- `record new` 为新 pending 写 `meta.confirm_by = 记录日+7`（兜底提醒）：有实际结果请立刻回填，不必等满 7 天；`python tools/main.py remind` 列出到期仍 unknown 的场。

- **「延迟必填」：offer / why_ended 是结果型字段，不在建档时逼你填。**
  面试刚结束时本来就不知道结果，建卡时强制填只会逼出随手乱填。
  所以做法是**在到期的地方问**：`remind` 按 `outcome` 判断该要哪一项 ——
  `pass` 要 `offer`（过了≠拿到）、`fail` 要 `why_ended`（能力问题还是匹配问题，
  改进方向完全不同），并给一条可直接复制的 `record fix` 命令。
  > 实测真实卡：`outcome` 填充 **100%**（不用催），
  > 而 `offer` 缺 33 场、`why_ended` 缺 69 场 —— 旧版 `remind` 只盯 `outcome=unknown`，
  > **该催的一个都没催到**。这两个空字段正是报告里最有价值两节的数据源。
- 凡"结论"（该投/慎投/某场判断）都附 **样本 n + 置信**（样本<3 → “样本少·仅参考”）；小样本只作趋势。
- 报告「反复挂根源」下会对 top 缘由附一段**曾 pass 卡里的高分回答**做话术小抄（练说法/复盘改法，复用已有卡，不新增数据）。
- `answer` 特意**不生成答案**：它只做三件事 —— ① 从你 pass 场的高分回答里归纳你的作答骨架；
  ② 把新问题匹配到你**真答过**的素材并按质量分栏；③ 匹配不到就**如实标缺口**。
  一条回答好不好，看的是**这条回答本身**的质量分，不是"那场最后过没过"——
  一场挂了不等于那场每题都差（可能输在薪资/横向对比）。这一点如果搞错，
  会把你的好素材错误地扔进"别再这样答"，所以已用自检锁住。
- schema 约定：人自感 `meta.subjective`、模型推断 `meta.ai_guess` 只参考、不进统计；`result` 只填"实际"结果（实际 > 体感 > AI 猜）。

## 自检说明（v3.3.3 起：第 6 组改为行为验证；v3.4.0 起：扫描范围扩大）
`validate` 里的 7 组自检，作用都是**锁住曾经改错的行为**。其中赛道流程那组
（定义 / 逐卡指定 / 转正迁移 / 建卡询问 / 文件落地）**已不再读源码找字符串**，
而是真跑代码/AST：

| 检查 | 手段 |
|---|---|
| 转正时赛道随卡号迁移 | 在**临时副本**里真跑一次 `merge formalize`，断言 `card_track` 从 `P1` 迁到 `I###` |
| `record new` 支持 `--track/--no-track` | 解析 **argparse 本体**（注释里留旧名骗不过） |
| `setup` 会调用 `define_tracks` / `_scaffold_files` | **AST 调用点**检查（字符串/注释不算） |
| 落地真身不覆盖已有文件 | 真调 `_scaffold_files()`（`ROOT` 指向临时目录），断言用户内容未被改 |

> 为什么重写：旧版全是 `"card_track" in 源码` 这类存在性判断。
> 实测注入 —— 把迁移真正用的字段名改坏、只保留函数名字样 —— 旧版仍打印
> 「✓ 转正时会迁移 card_track（赛道不丢）」并 ✅ 全部通过，而**赛道实际已丢**。
> 那正是 v3.3.0 修过的 bug，等于修复没有回归防线。
> 教训：**查字符串的自检锁的是字面量，不是行为。**

**v3.4.0 补充**：作用域那组的**扫描范围**也修了。它原本用正则
`run\("X.py"\)` 从 `main.py` 抠模块名 —— 一旦某个模块的派发改成查表
（如报告合并后的 `_VIEWS`），正则就抠不到它，**该模块无声退出自检**。
实测因此漏掉 `report_all.py` 等 6 个（注入必崩的未定义变量仍全绿）。
现改为**扫 tools/ 下所有 .py**，覆盖 20 → 25 个模块；
扩大后立刻抓到 `analyzer.py` 一个潜伏 bug（用了 `sys` 却没 import，只在
"某张卡解析失败"的分支才会崩，所以一直没人碰到）。

> 这两次是同一个教训的两种形态：
> **自检"跑了"不等于"有效"** —— 前者看有没有输出，后者要看①它是否真的执行了行为、
> ②它的覆盖范围有没有静默缩水。改派发/重构时尤其要复查第二点。

## 运行边界（我按这个定位做）
- **单机、单人的本地工具**：每份 `cards/` 只属于某一个求职者、在自己机器的目录里跑。不承担多人协作/跨设备/云端同步，也不搞冲突合并 UI——`merge` 只做把 `_inbox` 转正式 + 随手判同名，不承担"多人并发修改"。
- `d+7` 只是**兜底闹钟**：有实际结果请立刻回填（outcome/why_ended/offer），不用等到第 7 天；系统到"满 7 天仍未回填"才提醒你一次。若真实知道得晚，把 `confirm_by` 顺延即可，别让它一直停在 unknown。
