# digest_guide.md — 自动消化一场面经全文的标准动作

适用场景：使用者直接丢来一份完整/较长的面试转写或逐字稿（PDF/txt/记事本），并告诉你两件事：
- 第几轮（一面/二面/HR…，能说就说）
- 他这场自己体感 过 / 没过 / 不确认

**这里是给"识别的 agent / AI"看的执行规范**，不是让人类手动敲命令的。遵循它，产物就又全又一致。

## 结果的"三级 + 优先级"（先背这句）
- **实际结果 > 人的主观体感 > AI 推断**。统计/总报只认 `result`（实际）。
- 拆卡/逐题/强弱/影响，这些是我(AI)做；但**是否真实过、最终拿没拿到、为什么没推进**唯一由"实际发生"说了算。
- 「人自感」与「AI 推断」只分别存进 `meta.subjective` / `meta.ai_guess` 作参考/待核，绝不塞进 `result`、绝不参与统计。
- 只有当某人确实拿到了真实结果回填 `result`, 它才是真值；若该场只有体感/猜测 → 卡判 `outcome=unknown`、标「待实际结果」，不要让猜测替现实做主。
- AI 明确说清它给的是推断，不预设 outcome 为 pass/fail。

## 你(AI/agent)该自动做的八步
1. **读全文**，不要只看标题。用人话把这场"发生了什么"把握住（哪家、什么岗、追问了哪些点）。
2. **提取 questions**：把面试官实际问的每一个问题都拎出来，一条不裁。（记录本意是"全题"，宁可多不强求省。）
3. **为每题填**：`theme`(主题) / `question`(原话或准原话) / `how_answered`(用面试全文里的原答精炼，保留其答的关键与数据) / `score`(给你自己看的自评 1-5)。
4. **若使用者还给了 judge truth，请填到 result**；否则一律把 `outcome` 设 `unknown`，不要替使用者臆断 pass/fail。
5. **写 reflection**：strength(做得好/可复用)、weakness(踩坑点，供今后归因)、improvement(下一次动作)。
6. **skills**：给能力标签，尽量和已有标签一致，方便 future 聚合。
7. **产出卡**到 `cards/_inbox/P…_....yaml`（Pending 不占正式 I 号；下次用 `merge formalize` 再转正）。若已有同指纹卡，别覆盖 → 走 merge 识别。
8. **回给使用者一份"一面面状"**：这场讲了哪些点、每题自评、踩了哪些坑 → 以及下一步建议（可打 `report`/`apply`）。

## 你绝不擅自动的部分（留给使用者）
- `① outcome`（过/没过）：他能给就给，给不了就 unknown。
- `② why_ended`：若他没说/没推进，让他说"为什么/卡在哪"，不要编。
- `③ offer`：got/no/ongoing，只有他定了才落。

> 一句话：**录全、判透、评价准 → 结果三把钥匙由他用嘴给**。

## 可选：使用者口述式"记一下"
若没全文，只有他复述，仍按上面思路，把每题从他讲的中提炼，同样 ①②③ 留他确认。全文存在时优先全文——可读更全更准。
