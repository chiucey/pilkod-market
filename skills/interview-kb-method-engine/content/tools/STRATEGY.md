# 求职定位方法论（tools/ 内部文档）

> 本文说明 `strategy` 命令的判断口径。入口 skill 定义在仓库根目录的 `SKILL.md`。

**定位分析模块**（strategy.py）：不是报数据，而是回答方向性问题——你是谁、该往哪投、为什么黄了。

## 核心方法（这套判断怎么来）

### 一、先算"分赛道通过率"，别被总通过率骗
- 按**公司/行业**统计 pass/fail，得出各赛道通过率。
- **你的优势赛道 = 通过率高的公司/岗位类型**；挂得多的 = 投错了的战场。
- 例：若某类主流大厂内容岗通过率明显高于跨界新行业，说明应把火力集中在匹配赛道。

### 二、判断"匹配 vs 跨界/降维"
- **匹配赛道**：与过往经历同类的业务（内容/社区/垂类/产运/策略岗）。
- **跨界/降维**：硬件/财经/汽车/本地生活/外包/AI新行业——内容方法论难复制，历史上通过率低。
- 结论：**别再造网跨行业**，把火力集中在匹配赛道。

### 三、识别"你的真实定位信号"
综合各场面试官评价/自评（由你的卡片累积得出，非预设）：
- 反复被认可的 = 你卡片里 strength 高频出现的能力标签。
- 反复被质疑的 = 你卡片里 weakness 高频出现的短板。
- → 定位：优先投能复用你**高频优势**的岗，别和陌生执行向岗位硬拼。

### 四、挖"真实卡点"（为什么有的黄了）
从过关但没拿 offer 的场次提炼非业务因素：
- 职级/薪资（对方给不到你的预期）
- 稳定性（空窗、频繁换、回流被卡）
- 外包/降维（通过了也不想去）
- 求职急切（让面试官觉得你不是非这个不可）
> 这些"软信号"常定生死，比再练方法论更重要。

## 使用
```bash
python main.py strategy        # 生成《求职定位报告.md》
python main.py strategy --plain # 终端直接看
```

## 依赖数据
- `cards/I###_*.yaml`（每场：outcome / interview / reflection）
- 需先补全 `result.outcome`（pass/fail）定位才准。

## 注意事项
- 分类用关键词启发式（STRENGTH_KEYWORDS / CROSS_INDUSTRY_KEYWORDS），可随经验更新。
- "非业务卡点"需用户在 result.reason 标注（面评高但黄 / 通过但不入职）才准。
- **最终判断由 AI 结合语义给出**；脚本提供结构化依据。
