# 方法学.md —— 不依赖脚本、本人也能心算的面试决策逻辑

这套 skill 的价值不只是能跑脚本，更希望你理解背后的判断链，自己遇到单场也能快速归位。
下面四类问题是求职最高频的决策，想清楚就能做得比大部分人细。

## 1. 判断"该投哪条赛道"（岗位预判）
做法：把你的面经按两个维度打分记录
- 横向=行业/公司（内容平台/硬件/生活服务/工具/教育/电商…）
- 纵向=岗位类型（创作者运营/垂类品类/策略中台/纯内容/产品运营…），并写 `nature`(正编/外包)。
结论看两件事：
1. 哪个(行业×岗位)交叉的 pass 占比最高 → 你"主场"，优先投这格；
2. 你现在投的岗位是不是总落在 pass 低的格子 → 若是，先别怪自己不行，是“投错地方”。
> 判别法：跨界新行业若历史上 pass 明显低，说明方法论难复制——除非 JD 非常贴你强项，否则别再造网跨。

## 2. 溯源"为什么总挂"（复盘地基）
- 单场失败别下结论，把 N 场 fail 卡的 `weakness` 高频关键词列出来：出现最多那个才是"决定性因素"。
- 拆分两类：
  a) **能力类**（某方法论不会/题没答好/硬伤没正面化）→ 可补，练。
  b) **非能力类**（职级/薪资/外包降维/稳定性/gap/base/返聘/「业务过了但后端没推进」）→ 是错配或硬卡，不是你真不行。
> 很多"业务面显得很好却拿不到 offer"的人,其实卡在 b 类。

## 3. 用"轮次口径"而不是"拿到 offer"看自己
统计 通过轮次 / 总轮次，而不只看最终有没有 offer：
- 一轮一轮记 `round_result`，标 process 归属同流程。
- 这样你能看出「面到哪一轮被卡、通常卡在第几轮」与「能力轮是不是一路过、真正卡点是不是后端职级/薪资」。
> 例：面两岗——甲岗到二面挂(二面这轮 fail)=含一面过的 1/2 轮算过一半；乙岗一面挂=0。合起来 通过轮/总轮= 一面过的那1轮 / 3 轮。

## 4. 一场面试后的"复盘四问"
1. 哪几句我给了**数据闭环 / 完整方法论 / 具体 case**？（留下，下次复用成范本）
2. 哪几句暴露**硬伤未正面化 or 口径不清 or 简历不一致**？→ 下个 action
3. 我的**自我介绍/简历**这轮有没有被追问出破绽？→ 改简历/自我介绍
4. 若这轮没推进，是能力还是**非能力(职级/薪资/外包/稳定性)**？→ 写入卡 result.why_ended。

## 5. "下场决策"速推法（给一家公司要不要投）
1. 这家你面过吗？若面过：正编通过率如何 → 高=投，低但要投就处理历史卡点。
2. 历史 fail 都卡在哪？（gap/外包/某业务方向没做过/行业跨界…）→ 预演好怎么答。
3. 找出你曾 pass 的同类题材的**高含金 Q/A** → 把它改成这次能背的答案。
4. 投前清单：base / 职级 / 薪资 / 正编或外包 / 返聘/稳定性冲突 —— 全对上再用力。

## 一句话总结
**先按赛道&轮次看清楚自己在哪格、卡在哪层能力，再决定往哪投、面试怎么发力** —— 别让"面试能力"跟"没拿 offer"混为一谈。
