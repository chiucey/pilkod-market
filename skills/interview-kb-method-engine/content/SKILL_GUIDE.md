## 一、这是什么 · 解决什么问题

跑在你自己电脑上的**本地求职助理**。从找岗到复盘，把每次面试变成越来越准的判断。
**数据全在本地，不上传、不同步。**

求职最难受的不是面试，是**看不清**：

- 面了十几家，**哪类岗我拿得下**、哪类纯属浪费时间？
- 反复挂在"不合适"，是**能力不行**还是卡在别处？
- 收到一份 JD，**要不要投**？投了准备什么？

这套东西把这些问题变成**可统计的数据** —— 每场面试记一张卡，答案自己浮出来。

它**不是**帮你自动海投的脚本，也**不是**替你回答面试的作弊器。它做三件事：

1. **收纳** —— 把你面了什么、怎么答、结果如何，结构化记下来；
2. **诊断** —— 从真实数据里看清你是哪种求职者、卡在哪、该避什么；
3. **助力** —— 围着某家公司/JD 备战、复盘。

> 一句话：**越往里喂真实的面试记录，它越懂你，结论越准。**

## 二、和常见做法有什么不同

| 常见做法 | 这套 |
|---|---|
| 记在备忘录，回想靠印象 | 结构化卡片，可统计回溯 |
| "拿 offer 率"一把抓 | **轮次口径**；正编 vs 外包**分开算** |
| 觉得"总挂 = 我不行" | 分辨**能力问题**还是**非能力卡点** |
| 投完才知道不合适 | 投前就有命中率与卡点预警 |
| AI 帮你编一份"完美答案" | **只复用你自己真答过、且真过了的回答**，没素材就如实说缺口 |

最说明价值的一个信号：**"业务面全过了，最后却没拿到 offer"** ——
这类暴露的往往不是能力，而是职级、薪资、外包、稳定性这些软卡点。

## 三、核心心智：你只需要给三个真值（最重要）

**你不需要懂 YAML 或命令。** 对每场面试，你只负责给三样，其余归纳/报告由引擎接手：

| 你要给什么 | 对应字段 | 简单说 |
|---|---|---|
| ① 这轮过没过 | `outcome` | pass / fail |
| ② 没推进的原因 | `why_ended` | 横向对比 / 审批 / 简历背调 / 薪资 / base / 外包无转正… |
| ③ 最终拿到 offer 吗 | `offer` | got(拿) / no(没拿) / ongoing(在走) |

**为什么这三样必须你填**：它们是你"现实结果"的唯一真实来源。
引擎也好、AI 也好，都不能替你当裁判 —— 所以统计只吃你给的真值。
越早填越准；`d+7` 只是兜底提醒，不用等满 7 天。

> 模板见 `tools/CONTRACT.md`。建卡也不用懂命令：**把面试转写稿丢给 AI**，
> 它会按 `tools/digest_guide.md` 自动拆成卡片。

**还有一个跟你有关的事实**（v3.3 起）：赛道（"这场属于哪类岗"）
也像上面三样一样，会在建档时**直接问你** —— 因为业务归属只有你知道，
引擎猜不准（实测被纠正过多次）。

## 四、功能全景（命令**名称索引**）

> **从包根目录执行**：`python tools/main.py <子命令>`
> （`main.py` 在 `tools/` 下。也可以 `cd tools` 后写 `python main.py …`，两种都行；
> 但**别在包根直接写 `python main.py …`** —— 会 File not found。）

> **这一节是"一眼看全有什么命令"的名称索引** —— 只有名字和一句话用途。
> **参数、口径、边界一律以 `tools/ENGINE.md` 为准**（那里是命令"怎么用"的唯一权威来源）。
> 两处若有不一致，**改这里**。

### A. 建档 & 复盘（数据的来源）

| 子命令 | 干什么 | 什么时候用 |
|---|---|---|
| `record new` | 新开一场（进草稿箱，顺便问赛道） | 面完一场 |
| `record ask` | 逐题追加，**不限条数** | 想把面试官问的都记下 |
| `result --id I007 --outcome pass` | **回填三个真值**（P/I 卡都能填） | 知道结果后立刻填 |
| `merge` | 判重 / 把草稿转正式号 | 一批草稿攒完 |
| `validate` | 校验全部卡格式 + **跑全部 7 组模块自检** | 改动后，0 告警再继续 |
| `report` ⭐ | **生成唯一《求职总报》**（主入口） | 每新增几场就刷一次 |
| `evaluate` | 面完给通过可能性 + 逐题好坏 | 单场复盘 |
| `remind` | 找出到期还没回填结果的场 | 提醒你别漏填真值 |

### B. 定位与诊断

> **报告只有一个入口：`report`**，用 `--view` 切视角（v3.4.0 起）。
> 旧名（`diagnosis`/`strategy`/`insights`/`pulse`/`decision`/`report2`）**仍可用**，等价于下表右列。

| 子命令 | 等于 | 干什么 |
|---|---|---|
| `report` ⭐ | — | **唯一《求职总报》**，章节最全，日常看这个 |
| `report --view list` | — | 列出所有视角 |
| `report --view 诊断` | `diagnosis` | 4 问：通过率最高的赛道/岗位类型？反复挂的根源？你的能力标签？该投什么？ |
| `report --view 定位` | `strategy` | 求职定位：匹配赛道 vs 跨界，各自通过率 |
| `report --view 痛点` | `insights` | 痛点/优势聚焦体检 |
| `report --view 脉搏` | `pulse` | 动态洞察（随新面经刷新） |
| `report --view 决策` | `decision` | 浓缩决策报告（定位 + 洞察二合一） |
| `report --view 轮次` | `report2` | 轮次口径 + 正编/外包拆分 |
| `analyze` | — | 跨场统计 + 导出 CSV |
| `backtest` | — | **这套判断到底准不准**（留一法回归） |

### C. 备战场（对某家公司 / JD）

| 子命令 | 干什么 |
|---|---|
| `job --file jd.txt` | JD 画像 / 简历匹配度 / 最匹配的历史卡 / 预测问题 |
| `answer --jd-file jd.txt` | **应答框架 + 缺口清单**：复用你真过了的回答，没素材的标缺口 |
| `apply --company X` | 这家要不要投（历史通过率 + 卡点 + 曾 pass 的高分回答） |

### D. 简历相关

| 子命令 | 干什么 |
|---|---|
| `resumecheck` | 校验结构化简历源（每段经历 ≥2 条成果点、要有数据对比） |
| `resumeedit` | 采纳/回退/diff 编辑（保留 baseline，可回滚） |
| `resumerender` | 渲染成单栏 HTML（可打印）+ Markdown |

个人总结的 5 条规则（写在 `tools/resume_check.py`）：
① 性格空话（"认真负责"）直接报错；② 性格可写但要与做事方式结合；
③ 做的事要有产出；④ 总结第一条 = 过往重点工作的概述；⑤ 兴趣爱好要写产出。

### E. 赛道定义（v3.3 新增）

| 子命令 | 干什么 |
|---|---|
| `tracks define` | 定义你自己的赛道（首次 `setup` 会问） |
| `tracks show` | 查看现有赛道 |
| `tracks set 某张真实卡 金融垂类内容` | 逐卡指定某一场的赛道 |

**为什么要单独做这个**：赛道归类靠业务判断，引擎猜不准。
实测被使用者连续纠正过 6 处（"浏览器海外业务"其实是内容策略不是出海、
"应用商店/画报的内容运营"也是内容岗、某体育社区影视评分算垂类…）。
所以它和"过没过""是不是外包"同级 —— **只有本人知道，就该直接问你**。

### F. 找岗（可选模块）

| 命令 | 干什么 |
|---|---|
| `node tools/boss.mjs harvest --query 内容运营 --city 北京` | 抓 Boss 岗位（约 150 条，零配置） |
| `node tools/boss_jd.mjs --file boss_jobs.json` | 抓 JD 正文 |
| `boss filter --file boss_jobs.json` | 分级筛选（A/B/C + 用工性质） |
| `bossmerge --files boss_*.json` | 合并多轮抓取 |
| `bosstojob --jd boss_jd.json` | 批量 JD 备战 |

**这是可选模块**：需要额外装 Node.js 18+ 和 Chrome/Edge。
首次运行 `python tools/main.py setup` 会说明并询问是否启用；不启用不影响其余全部功能。
细节见 `tools/BOSS.md`。

### G. 维护

| 子命令 | 干什么 |
|---|---|
| `setup` | 首次向导：介绍两个部分 / 定义赛道 / 生成 profile.yaml |
| `export` | 导出 CSV（UTF-8 BOM，Excel 直接打开不乱码） |
| `validate` | 校验全部卡**并跑全部 7 组模块自检** ← **全量质检用这个** |
| `selftest` | **只**跑 Boss 模块自检（PUA 解码 / 薪资 / 性质 / 分级） |
| `resumeselftest` | **只**跑简历模块自检（个人总结 5 条规则） |
| `contract` / `fill` | 打印最小契约（每场只填 3 样） |

> **别把 `selftest` 当全量自检** —— 它只覆盖 Boss 模块。
> 7 组 = Boss / 简历 / 赛道体量 / 应答框架 / 作用域 / 赛道流程 / 图形界面，一次跑全请用 `validate`。

> **两个老写法仍可用**：`new` = `record new`、`result` = 回填结果（等价于 `build_card` 的两个入口）。
> 它们是最早期版本的命令名，为兼容保留；**新写一律用上表里的 `record new` / `result`**。

## 五、你需要提供什么 —— 按时间线

| 阶段 | 你提供 | 工具产出 |
|---|---|---|
| **开始** | 跑一次 `setup` | 赛道定义 + profile.yaml |
| **每面完一场** | 转写稿（或口述） + 三个真值 + 赛道 | 一张结构化卡片 |
| **每 2-3 场** | 无 | `report` 刷新总报 |
| **投之前** | 公司名或 JD | 要不要投 / 备战材料 |
| **收到面试** | JD | 应答框架 + 缺口清单 |
| **面完** | 转写稿 | 通过可能性 + 逐题复盘 |

## 七、快速上手

```bash
pip install -r requirements.txt
python tools/main.py setup                        # 首次：选模块 + 定赛道
python tools/main.py record new --company 某公司 --position 内容运营 --round 一面
python tools/main.py report                       # 主入口，随喂入持续更新
```

> ⚠️ **就在包根目录跑，命令一律带 `tools/`**（`main.py` 在 `tools/` 下）。

**节奏**：挑 5-10 场建成卡 → 跑 `report` 拿定位 → 抓岗筛岗备战 → 面完复盘回填。

> 找岗命令额外需要 Node.js 18+ 与本机 Chrome/Edge（自动探测）。
> 想 5 分钟走通全流程，看 `example/开工示范.md`。

## 八、三条边界（重要）

1. **样本量决定可信度** —— 少于 15~20 场时看方向就好，别迷信百分数。
   报告里每个结论都带样本量与置信度（"样本少·仅参考"就是字面意思）。
2. **真值必须你填** —— 实际结果没人能替你确认。口径是
   **实际结果 > 你的主观体感 > AI 推断**，后者只作参考、不进统计。
3. **数据全在本地** —— 永不自动同步，可放心把干净的 skill 分享给别人
   （`.gitignore` 已挡掉 cards/、简历、配置、浏览器登录态）。
