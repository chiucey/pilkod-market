# 面试知识库 & 面试策略引擎

让任何想体系化求职的人在本地搭建自己的"面试军火库"：
**从找岗到复盘** —— 抓岗位池 → 筛出该投的 → 对着 JD 备战 → 面完复盘归档 →
出一份持续更新的《求职总报》。

> 与"纯模板"不同：它不只是记录，而是**基于你自己的真实数据**产出可执行的投递/备战策略。
> 所有数据都在本地，不上传、不同步。

---

## 0. 这个包有两部分 —— 第二部分是可选的（新用户先看这里）

| | ① 面试复盘引擎 | ② 找岗模块（可选） |
|---|---|---|
| **做什么** | 把每场面试记成卡片，自动产出《求职总报》：轮次通过率、正编vs外包、主场赛道、公司体量、反复挂的根源、该投/慎投/别投；另有对着 JD 备战、基于你自己真实回答的应答框架 | 直接从 **Boss直聘** 抓岗位：一个关键词抓回约 150 条岗位池 + JD 正文，按你的能力和用工性质分成 A/B/C 级 |
| **依赖** | 只要 **Python + pyyaml** | 额外要 **Node.js 18+** 和 **Chrome 或 Edge** |
| **不装会缺什么** | — | 只是要自己在招聘网站上翻岗位，① 完全不受影响 |

**首次运行 `python tools/main.py setup` 会主动说明这件事、检测依赖、并问你要不要启用。**

> ⚠️ **命令一律从 skill 根目录执行**（即解压出来的 `interview-kb-method-engine/`）。
> `main.py` 在 `tools/` 下，所以是 `python tools/main.py <子命令>`。
> **不要**在根目录直接写 `python main.py …`（会 File not found），
> 也不要写死绝对路径。

```bash
python tools/main.py setup              # 交互式：介绍两部分 + 检测依赖 + 问你要不要找岗模块 + 定义赛道
python tools/main.py setup --quick      # 非交互：默认只要复盘引擎
python tools/main.py setup --with-boss  # 非交互：明确要找岗模块
python tools/main.py setup --no-boss    # 非交互：明确不要
```

> **给 agent 的提示**：用户第一次用这个 skill 时，先帮他跑一次 `python tools/main.py setup`，
> 把"有个可选的 Boss 找岗模块、需要 Node + 浏览器"讲清楚再让他选。
> **不要默认帮他装** —— 有人只想复盘，不想要抓取。

## 1. 你的数据在哪、长什么样

```
<本包目录>/
├── SKILL.md                   ← 本文件（给 agent 的入口定义）
├── SKILL_GUIDE.md             ← **全局指南（给人看的唯一入口，新用户先读这个）**
├── 方法学.md                   ← 不依赖脚本、本人也能心算的决策逻辑
├── schema.yaml                ← 卡片字段定义（⚠️ 权威版本在 tools/schema.yaml）
├── config.example.yaml        ← 可配置项（复制成 config.yaml）
├── resume.example.md          ← 简历模板（复制成 resume.md）
├── resume_src.example.yaml    ← 结构化简历模板（供 resumecheck/render 用）
├── profile.yaml.example       ← 主档案模板（复制成 profile.yaml）
├── jd.txt / new.txt           ← 输入示例
├── cards/I###_*.yaml          ← 每场面试一张卡（核心资产，自己积累）
├── cards/_inbox/P###_*.yaml   ← 草稿卡（merge formalize 后转正为 I###）
├── example/                   ← 虚构示例卡（理解字段用）
└── tools/                     ← 引擎脚本（main.py 统一入口）
    ├── ENGINE.md              ← **命令口径手册（人查；命令"怎么用"的唯一权威来源）**
    ├── BOSS.md                ← 找岗模块说明
    └── CONTRACT.md            ← 最小契约
```

**核心数据字段**（详见 `schema.yaml`，每张卡 = 一场面试）：
`interview.company/position/round/nature`、`questions[]`（问法 + 我的答 + 自评分）、
`result.outcome(pass/fail)/why_ended/offer`、`reflection.strength/weakness/improvement`、`skills[]`。

## 2. 引擎能做什么（概览）

> **本表只讲能力，不列命令。** 需要命令、参数与口径时读 `tools/ENGINE.md`。

| 环节 | 能力 |
|---|---|
| **建档** | 一场一张卡；逐题追加不限条数；草稿转正式号；回填三个真值（过没过/为何没推进/是否拿到 offer） |
| **定义赛道** | 赛道**在首次 setup 时直接问你**（像"是否通过/是否外包"一样），也可逐卡改 |
| **报告** | 唯一《求职总报》：轮次通过率、正编vs外包、主场赛道、公司体量、反复挂根源、非能力卡点、该投/慎投/别投、趋势 |
| **备战** | 对 JD 出职责画像/匹配度/预测问题；对某公司看历史通过率与卡点 |
| **应答框架** | **复用你自己真答过、且真过了的回答**；没素材就如实标缺口（不生成答案） |
| **简历** | 结构化简历源校验 → 编辑（可回滚） → 渲染单栏 HTML/Markdown |
| **找岗（可选）** | 抓 Boss 岗位池 + JD → 按能力/薪资/用工性质打 A/B/C |
| **图形界面** | **本地网页**（`python tools/main.py web`，零额外依赖）：卡片全文搜索/筛选、报告可视化、待办缺口、趋势、同类题对比；**左右分栏的对话框**（左边跟 agent 对话，右边并排看卡片）；可直接改 4 个真值字段（写前自动备份）。只监听 `127.0.0.1`，不联网 |
| **质量闸** | 全量校验：卡片 YAML/字段/枚举 + **7 组模块自检**（含"定义/逐卡指定/转正迁移"链路、图形界面接口与防护，均为**实跑验证**而非查源码字符串）；自检失败时退出码非 0 |

**关于图形界面（给 agent 的提示）**

用户卡变多之后，"我在某家被问过什么"这类问题**在对话里要翻上下文**，越翻越乱。
界面把"**看**"接过去（可搜索、可筛选、可并排），对话专心管"**改**"。

- 用户说"数据太多翻不动 / 想有个界面看看"时，**主动提** `python tools/main.py web`。
- 界面里的「对话」页**不接 AI** —— 它把用户的话记进 `chat/对话.md`，
  用户会回来说「**看聊天**」；这时**去读那个文件**，把回复**追加写回同一文件**
  （格式 `## [时间] AI`），网页会每 2 秒自动刷新显示，不用用户手动刷。
- 网页能直接改 4 个真值字段（`outcome`/`offer`/`why_ended`/`reason`），
  走的是与 `record fix` **同一条写入路径**（写前备份到 `cards/_bak/`）。
- `chat/` 与 `cards/` **同级敏感**，别打包、别外发。

## 3. 给 agent 的四条约定

1. **命令细节一律去读 `tools/ENGINE.md`** —— 它是命令**怎么用**（参数、口径、边界）的唯一权威来源。
   本文件**不列命令**，只回答"要不要用我、怎么分流、边界在哪"。
   想了解"这东西是什么、怎么按节奏用"，读 `SKILL_GUIDE.md`。
   > 注：`SKILL_GUIDE.md` §四 有一份**按功能分组的命令名称索引**（给人一眼看全用）。
   > 那里只有名字和一句话，**没有参数**；要参数和口径仍然看 `ENGINE.md`。
2. **三个真值必须由用户给**：`outcome`（本轮过没过）、`why_ended`（没推进的真实原因）、
   `offer`（最终有没有）。口径是 **实际结果 > 用户主观体感 > AI 推断**，
   后两者只作参考、不进统计。不要替用户猜这三样。
3. **赛道也要问用户**。赛道归类靠业务判断，引擎猜不准
   （实测被用户连续纠正过 6 处）。建卡时会主动问；
   用户给了就写进 `config.yaml` 的 `card_track`。
4. **⚠️ 面经数据是「参考证据」，不是「需求规格」。**（最重要的一条）
   用户积累的这场面试记录，用途是**验证 skill 的行为准不准**，
   **不是**用来决定 skill 该长什么样。

   改 skill（加功能 / 改口径 / 调阈值 / 加必填）时：

   | 数据能做什么 | 数据**不能**做什么 |
   |---|---|
   | 证明某个 bug 真实存在（"实测这类卡会被漏掉"） | 决定应该加什么功能 |
   | 显示某处口径与事实不符（"算出的拆分互相矛盾"） | 决定某个字段是否必填 |
   | 作为回归测试的期望值 | 推翻用户明确提出的需求 |

   **遇到下面三种情况，停下来把矛盾抛给用户，不要自己选一个往下走**：
   - 数据现状与用户需求冲突（例：用户说"列必填字段"，
     而数据显示某字段 100% 已填 → **两者不矛盾时也可能含义不同，先问**）
   - 同一需求前后表述不一致（例：先说"尽量合并"，后说"某功能要保留"）
   - 只能靠"数据里多数是这样"来支撑一个设计决定

   > 反例（真实发生过）：用户问"要不要列出必填字段"，
   > agent 统计出 `offer` 缺 33 场 / `why_ended` 缺 69 场，
   > 就**自行决定**"只做这两个字段、赛道不必填"并直接实施。
   > 统计是对的，但**拿数据替用户做了产品决定** ——
   > 用户问的是"要不要做"，不是"数据缺什么"。

## 4. 边界（我不做什么）

- **不代投简历、不自动打招呼**。`greet_job` 会真实投递且不可撤销，不要自动化。
- **不生成"完美答案"**。应答框架只复用用户真答过的内容；没素材就如实说缺口，
  因为 AI 凭空写的答案用户到现场说不出、细节经不起追问。
- **不替用户当裁判**。统计只吃用户给的实际结果；`outcome=unknown` 不进统计。
- **不保证小样本结论**。报告里每个结论都带样本量与置信度，
  "样本少·仅参考"就是字面意思。
- **数据不上传**。抓取产物（岗位池 / JD / 浏览器登录态）默认写到本包**之外**的目录。
- **本包不含任何人的真实面经**；`example/` 内为虚构示例。
