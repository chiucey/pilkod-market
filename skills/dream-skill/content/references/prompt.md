# Dream — 四阶段记忆整合 Prompt

> 由 OpenClaw Dream Skill 的 isolated session 执行
> 严格按顺序执行四个阶段，不要跳过

---

## 准备工作

### 工具约束

- **Bash**：仅限只读命令（`ls` / `find` / `grep` / `cat` / `stat` / `wc` / `head` / `tail`）
- **Edit / Write**：仅允许写入 `~/.qclaw/workspace/memory/` 目录下的文件
- 任何写操作（重定向、管道、修改系统状态）将被拒绝

### 记忆目录

```
~/.qclaw/workspace/memory/          ← 记忆根目录
~/.qclaw/workspace/transcripts/    ← 会话转录目录（仅 grep，不读全量）
```

## Phase 1 — Orient（定向）

**目标**：了解当前记忆结构，避免重复创建。

**操作**：

1. `ls ~/.qclaw/workspace/memory/` — 列出所有现有记忆文件
2. 读取 `~/.qclaw/workspace/memory/MEMORY.md`（入口索引）— 理解当前索引结构
3. 浏览现有的 topic 文件（如 `memory/projects.md` / `memory/tech-env.md` 等）
4. 若有 `logs/YYYY/MM/YYYY-MM-DD.md` 每日日志，先浏览最近几天的

**判断标准**：完成时，你应该在脑中建立：
- 当前有哪些 topic 文件？
- 每个文件覆盖什么主题？
- 入口索引的格式规范是什么？

---

## Phase 2 — Gather（收集信号）

**目标**：找出值得持久化的新信息。不做穷举式扫描，只验证你已怀疑重要的点。

**优先级**（从高到低）：

### ① 每日日志（最新信息流）
- `~/.qclaw/workspace/memory/logs/` 下近 1-2 周的每日日志
- 这是最高质量的信息来源——记录的是用户明确要求记住的内容

### ② 已有记忆中可能过时的内容
- 搜索与代码库现状矛盾的已有记忆
- 问自己："这个记忆在今天的会话中还成立吗？"

### ③ Transcript 搜索（仅窄词 grep）
- 只有当你已经怀疑某个具体问题时，才搜索会话转录
- **只 grep 精确关键词，不读全量文件**：
  ```
  grep -rn "<narrow term>" ~/.qclaw/workspace/transcripts/ --include="*.jsonl" | tail -50
  ```

**禁止行为**：
- ❌ 读整个 .jsonl 文件
- ❌ `grep -r ".*"` 全量扫描
- ❌ "探索一下最近有什么变化"式的开放搜索

**判断标准**：完成时，你手里应该有 3-5 个具体的"值得记住的事"。

---

## Phase 3 — Consolidate（整合）

**目标**：将信号写入/更新记忆文件。

### 核心原则

| 原则 | 说明 |
|------|------|
| **合并优先** | 能更新现有文件就不创建新文件 |
| **相对日期 → 绝对日期** | "yesterday" → "2026-04-02" |
| **删除矛盾记忆** | 被推翻的旧记忆直接删除，不要标注 |
| **写入顶层文件** | 记忆写入 `~/.qclaw/workspace/memory/` 顶层 |

### 操作步骤

对于每个值得记住的事：

1. **找已有 topic 文件**：问"这个内容该写入哪个已有文件？"
   - 项目详情 → `memory/projects.md`
   - 技术环境 → `memory/tech-env.md`
   - 偏好约定 → `memory/preferences.md`
   - 当日日志 → 新建 `memory/2026-04-02.md`

2. **更新而非创建**：
   - 若 topic 文件已存在 → 在其中追加/修改，而非新建
   - 若完全无相关 topic → 新建文件

3. **处理日期**：
   - 所有相对日期替换为绝对日期
   - 新记忆写入时，用今日绝对日期（YYYY-MM-DD）

4. **删除矛盾**：
   - 若某条旧记忆被今天证实为错误 → 直接从源头删除该行/该段
   - 不要保留"已被推翻"的标注

### 文件格式规范

```
memory/YYYY-MM-DD.md   ← 每日日志
---
# YYYY-MM-DD 日志

## 今日发生的事
- [事件描述]

## 决定/结论
- [重要决策]

## 待跟进
- [未完成事项]
```

## Phase 4 — Prune & Index（修剪 + 索引）

**目标**：保持入口索引 `MEMORY.md` 精简、可快速加载。

### 索引规范

| 指标 | 上限 |
|------|------|
| 行数 | ≤ 200 行 |
| 体积 | ≤ ~25KB |
| 每条长度 | ≤ 150 字符 |
| 格式 | `→ [Title](file.md) — one-line hook` |

### 操作清单

1. **移除过时指针**
   - 某 topic 文件已删除 → 移除 MEMORY.md 中对应行
   - 某 entry 描述的内容已过期 → 移除或更新

2. **压缩过长条目**
   - 某索引行 > 200 字符 → 说明内容应在 topic 文件里，此处缩短
   - 截断原则：保留标题 + 一句话钩子，细节不要

3. **新增重要记忆**
   - 今天新建了重要 topic → 添加索引行
   - 已有 topic 有重大更新 → 更新对应索引行

4. **解决矛盾**
   - 若两个 topic 文件描述不一致 → 判断哪个正确，修正错误文件
   - 在 MEMORY.md 中反映最终结论

5. **验证 MEMORY.md 格式**
   - 确保没有超过 25KB
   - 确保所有内部链接（`[Title](file.md)`）仍然有效

```
✅ Dream 整合完成

本次整合：
- 审阅会话：N 个
- 新增/更新文件：xxx.md、yyy.md
- MEMORY.md 索引：已更新
- 入口索引行数：N 行（N KB）
```

## 注意事项

- 你是独立运行的 isolated session，**不与主会话共享上下文**
- 你只有记忆目录和转录目录的访问权，不要尝试访问其他目录
- 若某个阶段遇到问题，记录并继续下一个阶段，不要卡住
- 整合过程中出现的所有文件写入，仅限 `~/.qclaw/workspace/memory/` 目录
