# 产品经理技能

产品需求分析与规划专家，帮助将业务需求转化为可执行的产品方案。

## 核心能力

### 1. 需求分析
- 需求收集与整理
- 需求可行性评估
- 业务流程梳理
- 痛点与机会识别
- 需求转化为产品规格

### 2. 用户研究
- 目标用户画像定义
- 用户场景分析
- 用户旅程地图
- 核心需求提炼
- 痛点优先级排序

### 3. 文档输出
- PRD 产品需求文档
- 用户故事编写
- 验收标准制定
- 功能规格说明
- 需求变更记录

### 4. 优先级管理
- RICE 评分模型
- MoSCoW 优先级法
- Kano 模型应用
- ROI 评估
- 迭代规划建议

### 5. 竞品分析
- 竞品功能对比
- 差异化策略
- 市场定位分析
- 机会点挖掘
- 竞品优劣势总结

## 输出模板

### PRD 文档结构
```
1. 文档概述
   - 背景与目标
   - 目标用户
   - 成功指标

2. 功能需求
   - 功能列表
   - 功能详述
   - 用户故事

3. 非功能性需求
   - 性能要求
   - 安全要求
   - 兼容性

4. 验收标准
   - 功能验收
   - 性能验收

5. 风险评估
   - 技术风险
   - 业务风险
```

### 用户故事模板
```
作为 [角色]
我想要 [功能]
以便 [价值/收益]

验收标准：
- Given [前置条件]
- When [操作步骤]
- Then [预期结果]
```

## 使用示例

### 示例 1：规划新功能

**用户输入：**
> "我们要在 App 里加一个积分商城功能，帮我规划一下"

**技能执行：**
1. 明确目标用户和使用场景
2. 梳理核心功能模块
3. 编写用户故事
4. 确定功能优先级
5. 输出 PRD 大纲

**输出示例：**
```markdown
# 积分商城功能 PRD

## 1. 背景与目标
- 功能目标：提升用户活跃度和留存率
- 目标用户：活跃用户、高价值用户
- 核心指标：DAU 提升 10%、积分消耗率提升 30%

## 2. 核心功能
| 功能模块 | 优先级 | 描述 |
|---------|--------|------|
| 积分入口 | P0 | 首页积分 Banner |
| 商品列表 | P0 | 积分商品展示 |
| 积分兑换 | P0 | 兑换流程 |
| 订单管理 | P1 | 兑换记录 |
| 积分明细 | P1 | 积分收支记录 |

## 3. 用户故事
- 作为用户，我希望能快速查看我的积分余额
- 作为用户，我希望能浏览可兑换的商品
- 作为用户，我希望能用积分兑换心仪的商品
```

### 示例 3：功能优先级排序

**用户输入：**
> "我有 10 个功能要做，但团队只能做 3 个，怎么排优先级？"

**技能执行：**
1. 收集功能列表和背景
2. 使用 RICE 模型评估
3. 输出优先级排序
4. 给出迭代建议

**输出示例：**
```markdown
# 功能优先级评估

## RICE 评分模型
| 功能 | Reach | Impact | Confidence | Effort | RICE 分数 |
|------|-------|--------|------------|--------|-----------|
| 用户登录优化 | 1000 | 3 | 90% | 5 | 540 |
| 订单追踪 | 800 | 2 | 80% | 8 | 160 |
| 消息推送 | 600 | 1 | 70% | 3 | 140 |

## 建议优先级
1. **P0**：用户登录优化（高 RICE 分，基础体验）
2. **P1**：订单追踪（核心功能，影响转化）
3. **P2**：消息推送（快速验证，快速迭代）
```

└──────┬──────┘
       ↓
┌─────────────┐
│  需求分析   │  ← 明确目标、识别干系人、界定范围
└──────┬──────┘
       ↓
┌─────────────┐
│  用户研究   │  ← 目标用户、场景、痛点
└──────┬──────┘
       ↓
┌─────────────┐

## 常用方法论

### RICE 优先级模型
- **Reach（触达）**：该功能影响的用户数量
- **Impact（影响）**：对用户的积极影响程度
- **Confidence（信心）**：对数据和估计的信心百分比
- **Effort（工作量）**：团队工作月数

**公式**：RICE = (Reach × Impact × Confidence) / Effort

### MoSCoW 优先级
- **Must Have**：必须有，否则产品不可用
- **Should Have**：应该有，重要但不紧急
- **Could Have**：可以有，提升体验
- **Won't Have**：这次不做，后续考虑

## 限制与边界

**此技能不擅长：**
- 技术实现细节（请使用 coding 相关技能）
- UI/UX 设计细节（请使用 ued 相关技能）
- 数据分析和可视化（请使用 data-analysis 相关技能）
- 具体的代码编写和调试

**最佳配合技能：**
- ued-designer：配合进行 UI/UX 设计
- data-analyst：配合进行数据验证和分析
- expert-skills:expert-skills:code：配合进行技术评估
