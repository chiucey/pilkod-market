# 融资融券平均维持担保比例数据与图表

## Inputs to collect
- 起始日期、截止日期（YYYY-MM-DD）。用户只说"到现在"就用当天作为截止日。
- 输出目录（默认 `./output`）。
- 缓存目录（默认 `./cache`，可用 `--cache` 或环境变量 `CSDATA_MARGIN_CACHE` 覆盖）。
  **缓存目录是增量能力的载体，同一项目的多次运行必须复用同一个目录。**

用户没给区间就问一句"要哪段"，别默认拉全历史——全区间约 680 个交易日、耗时 1 分钟左右。

## Procedure

1. 跑脚本，一条命令完成抓取→解析→出表→出图：
   ```bash
   node scripts/margin_report.mjs --start 2024-01-01 --end 2026-10-27 \
        --outdir ./output --cache ./cache
   ```
   脚本零第三方依赖，只用 Node 内置模块；不装任何东西，也不依赖 LibreOffice、pandas、plotly。

2. 扩区间时**沿用同一个 `--cache` 目录**重跑。脚本会先读缓存，只对缺失的交易日发起下载，
   已有的日期直接复用；指数也会按区间增量更新。重复跑同一个区间是幂等的，缓存命中后几乎瞬时完成。

3. 读脚本 stdout 的结果行核对，交付前确认这四项：
   - `数据 : N 个交易日 (起 ~ 止)` —— N 应与区间内交易日数吻合
   - `失败 N 天` —— 必须为 0；非 0 时按下面「失败处理」处理
   - `比例 : 最新/均值/最高/最低` —— 数量级应在 150%~350% 之间，偏离说明口径解析有问题
   - `指数 : ... 日变化相关性` —— 合理区间 0.8~1.0

4. 交付时把口径讲清楚，别让用户误读数字：
   - 比例统一为「百分数数值」：255.6273 表示 255.6273%，不是 2.556273
   - 上证指数为当日收盘点位，与比例走**左右双轴**，两轴刻度独立，交叉点不代表数值相等
   - 完整性结论：交易日与交易所日历逐日比对无缺失；每个文件的「文件内统计日期」与「标题日期」一致

5. 需要改样式或加指标时改 `scripts/lib/` 下对应模块再重跑，不要手工编辑生成的 HTML/Excel——
   下次重跑会覆盖，手改会丢。

脚本内部各步骤为什么这么做，见 `references/source-notes.md`（站点结构、两种文件格式的口径差异、
列表页缓存缺陷、已知边界情况）。

## Output contract
产出两个文件（文件名带区间，便于归档多个区间）：
- `output/融资融券市场每日平均维持担保比例_<起>_<止>.xlsx`
  - Sheet「每日平均维持担保比例」：序号 / 交易日 / 平均维持担保比例(%) / 上证指数(收盘) / 备注
  - Sheet「数据源明细」：交易日 / 比例 / 指数 / 来源栏目 / 官网源文件 / 文件内统计日期 / 原始存储形式 / 备注
- `output/平均维持担保比例分析_<起>_<止>.html`
  - 自包含单文件（plotly.js 内嵌，离线可开，约 4.4MB）
  - 6 张 KPI 卡 + 双轴主图 + 归一化对比图 + 回撤图 + 月度区间图 + 年度统计表 + 可筛选逐日明细表

回复用户时给出：文件路径、交易日数与区间、关键统计量、数据来源与口径说明。

## Failure handling
- **某天失败**：脚本会跳过并打印失败清单。直接重跑同一命令即可补上（缓存里没有的才会重下）。
  若反复失败，多半是官网该日文件本身异常，核查官网原始链接后再决定是否手工补。
- **列表页条目数与预期不符**：站点列表页有陈旧缓存缺陷，脚本已做「随机 query 破缓存 + 多轮取并集 +
  交易日历兜底」三重处理。若仍提示某交易日缺失，先去官网确认该日是否已发布，不要用别处的数据顶替。
- **HTML 打开后图表空白**：plotly.js 未能下载时脚本会退回 CDN 引用，此时需联网打开。
  联网跑一次即可把 plotly.js 存进缓存目录，之后离线可用。
- **指数源不一致**：脚本会打印双源比对不一致的日期数。差异超过 0.01 点才报警，
  若真的出现，说明接口口径变了，需人工确认后再发布。

## Examples
- 「帮我取 2024 年 1 月 1 日到今天的平均维持担保比例，出个 Excel 和图」
  → `node scripts/margin_report.mjs --start 2024-01-01 --end <今天> --outdir ./output --cache ./cache`
- 「上次的表更新到最新，只补新增的部分」
  → 沿用上次的 `--cache` 与 `--outdir`，把 `--end` 改成今天重跑；stdout 会显示「下载新数据 N 天｜命中缓存 M 天」
