# 网络设备故障排查手册

## 故障排查方法论

### 分层诊断法

网络故障排查应遵循OSI七层模型从底层向高层逐层排查：

```
第7层 应用层    → 应用服务可用性、端口连接
第6层 表示层    → 数据格式、编码问题
第5层 会话层    → 会话建立、认证状态
第4层 传输层    → TCP/UDP连接、端口状态
第3层 网络层    → IP路由、TTL、ICMP
第2层 数据链路层 → MAC地址、VLAN标记、ARP
第1层 物理层    → 链路状态、灯示、线缆
```

### 五元组定位法

通过分析网络流量五元组定位问题：

1. **源IP地址** - 确认发起端
2. **目的IP地址** - 确认目标端
3. **源端口** - 识别应用程序
4. **目的端口** - 确定服务类型
5. **协议类型** - TCP/UDP/ICMP

### 时间线追溯法

结合日志时间戳和事件序列还原故障发展过程。

## 常见故障场景与排查

### 场景1：设备无法远程登录

**故障表现：** 无法通过SSH/Telnet连接到网络设备

**排查步骤：**

```
Step 1: 检查物理链路
├── 确认PC与设备间网线连接正常
├── 检查设备对应接口灯示状态
└── 尝试ping设备管理IP

Step 2: 检查管理接口配置
├── 确认管理接口已启用
├── 验证IP地址和子网掩码
└── 检查是否有访问控制限制

Step 3: 检查远程登录服务
├── 思科: show ssh / show line
├── 华为: display ssh server status
└── 确认服务已启用

Step 4: 检查认证配置
├── 验证用户名密码正确性
├── 检查AAA配置
└── 确认超时时间设置
```

**快速检查命令：**

```bash
# 思科
show users
show line
show ip ssh

# 华为
display users
display ssh server status
display aaa
```

### 场景2：网络连通性故障

**故障表现：** 两台设备间无法ping通

**排查步骤：**

```
Step 1: 基础连通性测试
├── 从源端ping目的端IP
├── 记录丢包率和延迟
└── 尝试traceroute路径追踪

Step 2: 逐跳诊断
├── ping中间每一跳网关
├── 定位具体故障节点
└── 在故障节点执行详细诊断

Step 3: 检查路由表
├── 源端是否有到目的网段的路由
├── 中间设备是否有转发路由
└── 目的端是否有回程路由

Step 4: 检查访问控制
├── ACL是否阻止ICMP
├── 防火墙是否放行流量
└── 检查策略路由
```

**快速诊断脚本：**

```bash
# 基础连通性检查
for i in {1..5}; do ping -c 1 $TARGET_IP && break; done

# Traceroute路径追踪
traceroute -n $TARGET_IP

# MTU路径发现
ping -M do -s 1400 $TARGET_IP
```

### 场景3：OSPF邻居关系不稳定

**故障表现：** OSPF邻居关系反复建立和断开

**排查步骤：**

```
Step 1: 检查物理链路
├── 确认链路两端速率和双工匹配
├── 检查光纤接口光功率
├── 验证线缆连接正确
└── 检查是否有链路震荡

Step 2: 验证OSPF配置
├── 确认区域ID一致
├── 检查网络类型匹配
├── 验证Hello/Dead计时器
└── 确认认证配置正确

Step 3: 检查区域设计
├── 检查Area 0连续性
├── 确认虚链路配置
└── 验证Stub/NSSA区域

Step 4: 网络层面排查
├── 检查是否有路由翻动
├── 确认不存在IP冲突
└── 验证带宽配置正确
```

**诊断命令参考：**

```bash
# 思科
show ip ospf neighbor detail
show ip ospf interface
show ip ospf events

# 华为
display ospf peer
display ospf interface
display ospf error
```

### 场景4：设备性能异常

**故障表现：** CPU/内存使用率过高，设备响应缓慢

**排查步骤：**

```
Step 1: 确认性能指标
├── 查看CPU使用率及进程分布
├── 检查内存使用趋势
├── 确认接口负载情况
└── 记录性能数据基线

Step 2: 识别异常进程
├── 定位占用资源最多的进程
├── 分析进程启动时间
└── 确认是否为恶意进程

Step 3: 检查网络攻击
├── 查看是否有广播风暴
├── 检查是否存在DDoS攻击
├── 验证是否有ARP攻击
└── 检查CPU保护机制触发

Step 4: 资源配置评估
├── 评估当前配置是否合理
├── 检查日志级别设置
├── 验证syslog发送配置
└── 确认是否有异常日志输出
```

**监控命令：**

```bash
# 思科 - CPU使用详情
show processes cpu sorted
show processes cpu history

# 华为 - 资源监控
display cpu-usage
display memory-usage
display cpu-usage history

# 持续监控
terminal monitor
```

### 场景5：交换机端口异常

**故障表现：** 交换机端口状态Down或频繁Up/Down

**排查步骤：**

```
Step 1: 物理层检查
├── 检查端口灯示状态
├── 更换网线测试
├── 检查水晶头线序
└── 测试光纤接口光功率

Step 2: 配置检查
├── 确认端口未shutdown
├── 检查是否启用错误禁用
├── 验证端口速率/双工配置
└── 检查是否有端口安全限制

Step 3: 链路协议检查
├── 确认链路聚合配置一致
├── 检查STP端口状态
├── 验证端口通道负载均衡
└── 检查BPDU保护设置

Step 4: 统计信息分析
├── 查看端口错误计数
├── 分析CRC错误
├── 检查冲突计数
└── 评估丢包情况
```

**诊断命令：**

```bash
# 思科 - 端口状态和统计
show interfaces GigabitEthernet0/1 status
show interfaces GigabitEthernet0/1 counters errors

# 华为 - 端口诊断
display interface GigabitEthernet0/0/1
display port GigabitEthernet0/0/1
```
