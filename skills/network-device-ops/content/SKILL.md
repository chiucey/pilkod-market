# 网络设备运维技能

## 技能概述

本技能提供全面的网络设备运维能力，涵盖配置管理、故障诊断、性能监控和安全审计等核心场景。通过标准化的工作流程和最佳实践，帮助运维人员高效完成日常网络运维任务。

## 核心能力矩阵

### 1. 配置管理

**能力范围：**
- 批量配置备份与还原
- 配置变更审计追踪
- 基线配置模板管理
- 配置文件差异比对

**执行流程：**
```
1. 设备识别 → 2. 配置采集 → 3. 变更比对 → 4. 执行部署 → 5. 验证确认
```

**常用命令参考（见 references/device-commands.md）**

### 2. 故障诊断

**诊断维度：**
- 连通性故障（物理层至应用层）
- 性能降级分析
- 配置错误排查
- 安全事件响应

**诊断方法论：**
```
分层诊断法：从物理层 → 数据链路层 → 网络层 → 传输层 → 应用层逐层排查
五元组定位：源IP、目的IP、源端口、目的端口、协议
时间线追溯：结合日志时间戳定位故障窗口
```

### 3. 性能监控

**监控指标：**
| 类别 | 关键指标 | 阈值建议 |
|------|----------|----------|
| 接口状态 | 速率、错误率、丢包率 | 错误率>1%告警 |
| CPU/内存 | 使用率趋势 | 持续>80%告警 |
| 链路带宽 | 利用率 | 峰值>70%告警 |
| 会话数 | 并发连接数 | 接近上限80%告警 |

### 4. 安全审计

**审计要素：**
- 访问控制列表审查
- 用户账户与权限检查
- 日志留存合规性
- 固件版本安全评估

## 执行工作流

### 标准运维流程

```
┌─────────────┐
│  任务接收   │ ← 用户请求或告警触发
└──────┬──────┘
       ↓
┌─────────────┐
│  需求分析   │ ← 明确设备类型、厂商、问题范围
└──────┬──────┘
       ↓
┌─────────────┐
│  信息采集   │ ← 设备状态、日志、配置
└──────┬──────┘
       ↓
┌─────────────┐
│  问题诊断   │ ← 根因分析、影响评估
└──────┬──────┘
       ↓
┌─────────────┐
│  方案制定   │ ← 制定修复/优化方案
└──────┬──────┘
       ↓
┌─────────────┐
│  实施执行   │ ← 变更审批后执行
└──────┬──────┘
       ↓
┌─────────────┐
│  验证确认   │ ← 功能验证、监控确认
└──────┬──────┘
       ↓
┌─────────────┐
│  文档归档   │ ← 记录变更、更新文档
└─────────────┘
```

### 紧急故障响应

当遇到紧急故障时，启用快速通道：

1. **影响评估**（5分钟内）
   - 确定故障范围和影响用户数
   - 识别关键业务系统

2. **快速止血**（15分钟内）
   - 隔离故障域
   - 启用备用路径
   - 临时绕过方案

3. **根因修复**
   - 按照分层诊断法定位
   - 制定永久解决方案

4. **复盘改进**
   - 编写故障报告
   - 更新应急预案
   - 完善监控告警

## 常见场景示例

### 场景1：交换机端口异常排查

```
问题描述：用户反馈某楼层网络缓慢

执行步骤：
1. 检查核心交换机CPU和内存状态
2. 查看该楼层汇聚交换机端口统计
3. 分析是否存在广播风暴或环路
4. 检查端口错误计数
5. 定位问题端口并隔离处理
```

### 场景2：路由器OSPF邻居不稳定

```
诊断流程：
1. 检查物理链路状态
2. 验证OSPF配置参数一致性
3. 分析邻居状态变化时间点
4. 检查Hello/Dead计时器
5. 排查是否存在认证不匹配
6. 评估链路过载情况
```

## 注意事项

1. **变更管理**：所有配置变更必须经过审批流程
2. **权限最小化**：仅使用完成任务所需的最小权限
3. **变更窗口**：重大变更应在业务低峰期执行
4. **双重确认**：关键操作需双人复核
5. **可回滚性**：任何变更必须支持回滚
