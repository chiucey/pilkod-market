# Benchmark 调研技能

此技能用于系统性地调研指定技术/应用领域的Benchmark（性能基准测试），并生成结构化的Markdown调研报告。

## 调研范围定义

在开始调研前，明确以下要素：

- **技术领域**：要调研的具体技术或应用场景（如：LLM推理性能、图像分类、数据库等）
- **调研深度**：全面调研（所有知名benchmark）还是聚焦调研（重点benchmark深入分析）
- **时间范围**：是否关注最新benchmark（如近1-2年发布的）
- **输出偏好**：技术细节导向还是管理摘要导向

## Benchmark调研工作流

### 阶段1：信息收集

使用网络搜索收集目标领域的信息：

1. **搜索策略**
   - 主搜索：`{领域} benchmark` + `standard benchmark` + `evaluation benchmark`
   - 辅助搜索：`{领域} leaderboard` + `{领域} ranking` + `{领域} performance evaluation`
   - 追踪搜索：`{领域} benchmark 2024` + `{领域} benchmark 2025`（获取最新动态）

2. **来源优先级**
   - 官方权威来源（官方GitHub、论文、官方网站）
   - 行业认可来源（知名研究机构、企业技术博客）
   - 社区贡献来源（GitHub issues、讨论帖）

### 阶段2：Benchmark识别与分析

对于每个发现的Benchmark，收集以下信息：

| 信息类别 | 具体内容 |
|---------|---------|
| **基本信息** | 名称、发布机构/作者、发布时间、官方链接 |
| **目的与范围** | Benchmark设计目标、适用场景、覆盖范围 |
| **评估维度** | 具体测量指标（如准确率、延迟、吞吐量、能耗等） |
| **数据集** | 使用的数据集、样本规模、数据来源 |
| **评测方法** | 评测流程、运行方式、评分机制 |
| **应用情况** | 业界采用情况、相关论文引用数 |

### 阶段3：性能数据收集

- 收集官方公布的关键性能数据
- 查找第三方对比评测结果
- 记录排行榜排名（如有）
- 标注数据时效性（日期、版本）

### 阶段4：报告生成

生成结构化的Markdown调研报告。

## 输出格式规范

调研报告必须包含以下章节：

```markdown
# {领域} Benchmark 调研报告

## 1. 执行摘要
- 调研背景与目的
- 主要发现概述（3-5条核心结论）
- 调研范围与时间

## 2. Benchmark 概览
### 2.1 领域背景
- 技术领域简介
- 为什么需要benchmark

### 2.2 Benchmark 列表
| 名称 | 发布方 | 发布时间 | 官方链接 | 评估维度 |
|-----|-------|---------|---------|---------|
| ... | ... | ... | ... | ... |

## 3. 重点Benchmark 深度分析

### 3.1 {Benchmark名称}
- **基本信息**：发布机构、时间、版本
- **设计目标**：解决什么问题
- **评估维度与指标**：
  - 指标1：定义、测量方法
  - 指标2：定义、测量方法
- **数据集说明**：数据来源、规模、特点
- **使用方法**：运行方式、API接口
- **性能表现**：关键数据点
- **业界应用**：采用情况、影响力

（重复 3.1 对每个重点Benchmark进行分析）

## 4. Benchmark 对比分析
- 评估维度对比表
- 优劣势分析
- 适用场景分析

## 5. 最新趋势与发展
- 新兴Benchmark
- 技术演进方向
- 未来展望

## 6. 结论与建议
- 总结
- 选型建议（如适用）

## 7. 参考资料
- 官方链接
- 相关论文
- 社区资源
```

## 调研质量标准

### 信息完整性
- 每个重点Benchmark必须包含基本信息、评估维度、使用方法三个核心部分
- 关键数据必须标注来源
- 链接必须验证有效性

### 信息准确性
- 优先使用官方一手信息
- 区分事实陈述与推断
- 标注信息不确定性和局限性

### 报告可读性
- 使用清晰的层级结构
- 表格用于对比展示
- 关键信息使用加粗标注
- 保持段落简洁

## 最佳实践

1. **搜索与验证交叉验证**：通过多个独立来源确认关键信息
2. **时效性标注**：明确标注数据来源的日期和版本
3. **局限性说明**：明确报告的调研局限（如只覆盖英文来源）
4. **持续更新**：如需最新信息，考虑标注数据截止日期
5. **用户确认**：在调研开始前确认调研范围和重点

## 常见问题处理

- **Benchmark数量过多**：聚焦前5-10个最重要的，简要提及其他的
- **信息冲突**：优先官方来源，标注不同来源的差异
- **信息过时**：标注信息时效，提示用户核实最新状态
- **技术细节过深**：提供摘要层级，详细内容放在附录或参考资料

## 交付物

最终交付一份完整的Markdown格式调研报告，包含：
- 结构化的章节内容
- 对比表格
- 参考资料列表
- 可执行的参考链接
