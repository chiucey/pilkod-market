# 吃啥 Skill

## 触发场景
自然语言询问吃什么，例如：
- 「吃什么」「这顿吃什么」「今天吃啥」「不知道吃啥」
- 「今晚/中午/早上/明天吃什么」
- 「帮我搭配一顿」「帮我选个菜」「随便吃点」「有啥可吃的」

## 第一步：读取菜单
**每次触发都必须**先读取同目录下的 [菜单.md](菜单.md) 获取最新可用菜品，不要靠记忆。

菜单分 5 个系列：凉拌 / 炒鸡蛋 / 碎猪肉下饭 / 炒饭 / 其他。

## 严格规则
1. ❌ **绝不能**推荐菜单以外的任何菜品（用户忌口）
2. ❌ **绝不能**编造、合并、扩展菜单里没有的食材组合
3. ✅ 同一系列内可以组合（如炒饭系列可同时选 2-3 个食材）
4. ✅ 跨系列可搭配（凉拌 + 主菜 + 主食）

## 第二步：识别餐次
从用户语境判断餐次，未明示时按当前时间推断（默认当顿）：
- **早餐**（清晨 / 「早上」）
- **午餐**（中午 / 「中午」「午饭」）
- **晚餐**（傍晚 / 「晚上」「今晚」「晚饭」）
- **宵夜**（深夜 / 「夜宵」）

## 第三步：搭配策略

### 餐次适配
| 餐次 | 分量 | 标准搭配 |
|---|---|---|
| 早餐 | 轻量 | 凉拌 1 + 炒蛋 1（+ 米饭 / 简单主食）|
| 午餐 | 均衡 | 凉拌 1 + 主菜 1（炒蛋或碎猪肉）+ 主食 |
| 晚餐 | 丰盛 | 凉拌 1 + 主菜 1 + 其他 1 + 主食 |
| 宵夜 | 简单 | 炒饭 1 / 其他 1（选 1 个即可）|
| 不明 | 均衡 | 同午餐 |

> 「主菜」= 炒鸡蛋系列 或 碎猪肉下饭系列，二选一即可。

### 主推 + 备选
- **主推 1 个**：按上述策略生成的搭配
- **备选 2 个**：与主推风格略有差异（例如一个更清淡、一个更丰盛；或主菜换系列；或主食换炒饭）

### 重复回避
- 尽量不重复上一次推荐的主菜食材
- 用户说「上次吃过的不要」时，从该系列的其他选项换

## 第四步：响应格式

```
🍽️ [早/午/晚/宵]餐推荐

【主推】
🥗 凉菜：xxx
🥘 主菜：xxx（xx 系列）
🍚 主食：xxx（米饭 / 炒饭配方：蛋+xx+xx）
🍖 加菜：xxx（其他系列，可省略）

【备选】
1. （与主推差异点）xxx + xxx + ...
2. （与主推差异点）xxx + xxx + ...

💡 想换的话告诉我「不要 XX」「加个 XX」「清淡点」「有虾吗」。
```

### 处理用户后续反馈
- 「不要 XX」→ 同系列内换另一个
- 「加个菜」→ 从「其他」系列或未选系列加
- 「清淡点」→ 避开苦瓜、洋葱、煎饺、可乐鸡翅
- 「有虾吗」→ 优先选含虾的组合（凉拌虾仁版 / 虾仁炒蛋 / 虾仁炒饭）
- 「没胃口」→ 凉拌 + 简单主食（炒饭或米饭 + 小菜）
- 「想吃炒饭」→ 跳过凉拌和主菜，直接从炒饭系列挑 3-4 个食材配炒饭

## 注意事项
- 响应开头一句话确认触发：「按你菜单搭了 X 餐 👇」
- 推荐要具体到「食材组合」并标注系列，方便用户回忆做法
- 短选项直接给推荐 + 备选；不要反复反问用户偏好
- 如果用户主动指定了食材或系列（如「今天想吃虾」），优先尊重用户意愿
