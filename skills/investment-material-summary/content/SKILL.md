# 投资材料系统化总结 Skill

## 一、Skill 目的

将各类投资与交易相关材料转化为**结构化、可复用、忠于原文**的专业报告。适用于课程笔记沉淀、研报快读、路演纪要、访谈整理、视频内容归档等场景。

## 二、核心原则（不可违背）

### 原则 1：忠实性优先
- 报告主体（核心总结、市场分析、交易策略、风险管理四大模块）**必须**严格基于原材料的内容；
- **禁止**虚构数据、人物观点、事件、机构名称、产品名称；
- **禁止**在主体模块中加入原材料未提及的策略、结论或推论；
- 若原材料中某模块信息缺失或不充分，**必须**在该模块下明确写出"原材料未充分涉及该方面"，而不是用通用知识填充；
- 若原材料中存在数据、人名、机构、产品等具体信息，引用时**必须**与原文一致，不得改写或近似化。

### 原则 2：推演内容必须隔离
- 任何超出原材料的延伸（如行业类比、术语解释、Claude 的补充看法）只能出现在**结尾的《延伸思考》模块**；
- 《延伸思考》模块开头必须有明确的免责声明：
  > "以下内容为基于原材料的延伸思考，**不属于原材料原意**，仅供参考。"
- 主体四大模块中**不得**出现任何 Claude 自己的判断、推荐或补充。

### 原则 3：客观中立的语气
- 采用金融分析师/投资顾问的专业表述；
- 不使用情绪化、夸张、营销性语言（如"绝佳机会""稳赚不赔""强烈推荐"）；
- 涉及观点时使用"原材料指出""讲师认为""研究表明"等明确归属的表述；
- 不替原作者做出主观判断或投资推荐。

### 原则 4：报告语言
- 输出语言固定为**中文**（即使原材料为英文也输出中文报告，但保留专业术语原文，如 "alpha"、"beta"、"Sharpe Ratio" 可保留英文并附中文）。

## 三、工作流程

### Step 1：识别并读取材料
1. 检查 `/mnt/user-data/uploads/` 下是否有用户上传的文件；如有，**必须先调用 `view` 读取相关 SKILL.md（如 pdf-reading、file-reading、docx 等）**再进行内容提取，避免读取错误。
2. 材料可能形态：
   - PDF / Word / Markdown / TXT 文档
   - 图片（PNG/JPG，可能为讲义截图）
   - 用户直接粘贴的文本
   - 视频/音频转录稿（口语化、有重复、有口头禅）
3. 对口语化材料，需先在内部做一次"去口水化"处理（删除"嗯""然后""那么"等填充词、合并重复表达），但**不得改变原意**。

### Step 2：内容提取与分类
通读全部材料后，按以下四个桶进行分类（这是为后续生成报告做准备，不直接输出）：

| 模块 | 内容范围 |
|---|---|
| 市场分析 | 宏观经济判断、行业趋势、市场结构、流动性、政策、估值、周期定位等 |
| 交易策略 | 具体的策略类型（趋势、均值回归、套利、CTA、多空、事件驱动等）、入场/出场逻辑、仓位管理、择时方法、组合构建思路 |
| 风险管理 | 止损规则、回撤控制、相关性管理、对冲手段、压力测试、风险预算、流动性风险、操作风险等 |
| 核心总结 | 全文最重要的 3-7 条要点，需覆盖讲师/作者最强调的内容 |

如果原材料不是按这四个维度组织的，需要从原材料中**识别并归类**相关内容，但不得添加原材料没说过的内容。

### Step 3：生成报告
按下文「报告模板」（见 §四）严格生成。

### Step 4：生成输出文件（PDF + Markdown 同时生成，不询问用户）

**默认行为**：始终同时生成 PDF 和 Markdown 两个文件，不询问用户偏好。

**生成步骤**：

1. **先生成 Markdown 文件**到 `/mnt/user-data/outputs/{报告标题}.md`
   - 严格按照"§四 报告模板"组织内容
   - 写作风格遵循下方"写作风格要求"

2. **再调用脚本生成同名 PDF**：
   ```bash
   python3 <skill-path>/scripts/build_report_pdf.py /mnt/user-data/outputs/{报告标题}.md /mnt/user-data/outputs/{报告标题}.pdf
   ```
   - 视觉特点：深蓝色标题（#1F4E79）、项目符号优先、表格表头浅蓝背景、舒适留白
   - 依赖：`pip install weasyprint mistune --break-system-packages`（如未安装需先安装）
   - 字体要求：系统需有 Noto Sans CJK SC（Ubuntu/Debian 默认已装）
   - 详细样式规范见 `references/style_guide.md`

3. **同时呈现两个文件**：使用 `present_files` 工具，**PDF 在前、Markdown 在后**：
   ```
   present_files(filepaths=[
       "/mnt/user-data/outputs/{报告标题}.pdf",
       "/mnt/user-data/outputs/{报告标题}.md"
   ])
   ```

**例外情况**：
- 用户明确要求"只要 PDF"或"只要 Markdown"时，按用户要求执行
- 用户明确要求 Word 格式时，额外调用 docx skill（参考 `/mnt/skills/public/docx/SKILL.md`）生成 .docx，三种格式同时交付

**文件命名建议**：
- 使用材料的核心标题或日期作为文件名（避免过长）
- 例：`2026年4月投资视频纪要分析报告.pdf` / `.md`

**生成后简要告知用户**：用一两句话说明报告结构与忠实性原则，不啰嗦。

## 四、报告模板（必须严格遵循结构）

### 写作风格要求（重要）

为生成专业研报样式的 PDF，写作时必须遵循以下风格规则：

1. **优先使用项目符号** `-`，避免大段连续段落（除报告说明、免责声明外）
2. **嵌套使用 2 空格缩进**（生成器使用 mistune 解析）
3. **每条项目符号尽量遵循"加粗关键词：说明"的格式**，例如：
   ```
   - **扩表几乎不可避免**：ESLR 放松监管后若金融机构仍不增持中长期美债...
   ```
4. **关键数据、关键位、关键百分比加粗**，例如 `**4400**`、`**4.5%**`
5. **多维数据用表格**（关键位汇总、引用对照、术语对比等）
6. **小节标题层级**：
   - `##` = 章（一、核心总结）
   - `###` = 节（2.1 宏观与政策环境）
   - `####` = 小节（美联储与货币政策）
   - 再细分用项目符号嵌套，不再用 `#####`

## 五、特殊情况处理

### 情况 A：材料是视频/音频转录稿
- 先去除口头禅与重复，但保留所有事实陈述；
- 转录稿常有错别字（特别是数字、人名、机构名），如发现明显矛盾或错误，标注 "[原文如此，疑为 XX]"，**不要自行替换**。

### 情况 B：材料是英文研报
- 报告输出中文；
- 关键术语保留英文并附中文（首次出现时），如 "alpha (超额收益)"；
- 引用具体数据时保留英文原文数字与单位。

### 情况 C：材料涉及多个独立主题
- 优先识别讲师/作者的主线，主线进入主体四章；
- 其他独立主题在《核心总结》最后一条简要列出，或在《延伸思考》中提示"原材料还涉及 X、Y 等其他议题，受篇幅限制未展开"。

### 情况 D：材料内容很短（如只有几段文字）
- 仍按四大模块组织，但对原材料未涉及的模块明确写"原材料未涉及"；
- 不要为了凑字数而注水。

### 情况 E：材料包含具体投资推荐/产品名称
- 在报告中**如实记录**讲师/作者的原话推荐，但用"原材料中作者推荐 XX"这样明确的归属表述；
- **不**由 Claude 自己加入额外推荐；
- 在《延伸思考》或《风险管理》中可提示"以上为讲者观点，投资决策需独立判断"。

## 六、不要做的事

- ❌ 不要在主体四章中加入"我认为""建议投资者""推荐配置"等主观表述
- ❌ 不要为了让报告"更完整"而填充原材料未涉及的内容
- ❌ 不要混淆原材料观点与 Claude 自己的延伸（混淆即视为捏造）
- ❌ 不要询问用户要 PDF 还是 Markdown — 默认两种格式都生成；只在用户明确"只要 X 格式"时遵从
- ❌ 不要省略报告开头的"内容声明"
- ❌ 不要省略《延伸思考》开头的免责声明
