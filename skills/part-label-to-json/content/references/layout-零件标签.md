# 版位对照表：零件标签

零件标签**只有这一种版式**。字段身份 100% 由版位决定，不需要靠值的形状推断。
推断类规则（`references/field-mapping.md` 第三节）对这类标签不适用。

## 版位

```
┌─────────────────────────────────────────┐
│  零件品号                  生产日期      │  ← 第 1 行
│  零件件号                  批次序号      │  ← 第 2 行
│  ┌───────────────────────┐               │
│  │      PDF417 条码       │      厂内标记 │  ← 码区 / 右下角
│  └───────────────────────┘               │
└─────────────────────────────────────────┘
```

| 版位 | 字段 key | 值的规则 |
|---|---|---|
| 左上 第 1 行 | `零件品号` | **不套任何格式**，图上印什么就是什么 |
| 左上 第 2 行 | `零件件号` | **不套任何格式**，图上印什么就是什么 |
| 右上 第 1 行 | `生产日期` | 按图上字形照抄（`20240404` / `2024-04-04` 都可能），不自行改格式 |
| 右上 第 2 行 | `批次序号` | 按图上字形照抄，大小写不动 |
| 下方码区 | — | PDF417 条码，**不解码，也不写进 `parse_note`**。一个字都不留——条码归主机厂侧消费，本技能只取印刷字符 |
| 右下角 | — | 厂内标记（例 `HC`）。**不属于这四个字段**，不新增 key，**也不写进 `parse_note`** |

## label_type

**恒为 `零件标签`。** 这是确定解，不需要判、不需要犹豫、也不需要写进备注解释。
用户模板里写的其它 `label_type` 一律按示例处理（见 SKILL.md Step 4）。

## 四个字段的产出规则

- 模板没给字段名时，默认就用上表这四个 key，顺序也照上表（品号 → 件号 → 日期 → 批次）。
- 四个字段**恒定存在**，不存在"图上没有这个字段所以不输出"的情况。版位缺了一行 → 该字段留空 `""`，并在 `parse_note` 点名该字段 + 一句留空原因。
- **版式不符要停下来**：如果拿到一张四行结构对不上的标签（行数不对、位置整体错位、明显是别家的标签），**不要硬套进这四个字段**。按 SKILL.md Failure handling 出全空文件、备注写明"版式与零件标签标准不符"，并单独提示用户——这多半是混进了另一类标签，静默套模板比不产出危害大得多。
- **判断口径是"纸上只有零件相关信息"**：除了这四行还印着车辆信息、故障描述、单据编号之类**别的类别信息** → 这不是零件标签（例：印着"维修单号"就是维修标签，交 `repair-label-to-json` 技能），更不能套。

## 复用方式

处理下一张之前先扫一眼这张的四行是否都落在预期版位上。对上了就按位置填，对不上先按上面最后一条处理。
不要拿上一张的值去套这一张——版位表固定的是**位置**，不是**值**。
