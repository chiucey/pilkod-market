# 字段映射与归一化规则

SKILL.md Step 3 / 4 / 5 的查表文件。

## 一、字符混淆表（印刷体 → 正确读法）

只在**上下文能确定**时替换，否则保留原字符，并把该字段点名进 `parse_note`。

判据要落在**图上看得见的证据**上（笔画断在哪、字宽对不对得上、同标签其他字符长什么样），不要落在"这种编码通常长什么样"上——品号件号没有固定格式，拿格式当判据就会把真实字符当成错误抹平。

| 图上看着像 | 实际可能是 | 判据（要能在图上指出来） |
|---|---|---|
| `()` `[]` `O` `o` `〇` | `0` | **笔迹有缺口**：那个字符左/右半边明显断开，像被击针打掉了墨。**字宽接近**同张标签上确定是 `0` 的字符。**没有这两条证据就原样保留**——括号完全可能是原件 |
| `l` `I` `i` `1` `│` | `1` | 字形宽度和同一行/同一张里确定是 `1` 的字符一致；或笔迹断裂方式符合 `1` 而不符合 `l`（`1` 常顶部有斜切） |
| `S` `s` | `5` | 数字段内，且上下横画位置与同张已知 `5` 一致 |
| `B` | `8` | 数字段内，左右两半的字形吻合度与同张已知 `8` 相当 |
| `Z` | `2` | 数字段内，顶部横画与斜画的连接方式与已知 `2` 相同 |
| `—` `–` `−` `ー` | `-` | 全角/长破折号统一成半角连字符（这是书写规范，不是识别判断，可以放心改） |
| 全角 `Ａ-Ｚ ０-９` | 半角 | 同上，是排版问题不是识别问题 |
| 字符间异常空隙 | 删除 | 印刷体字距不是空格；但要确认那不是标签上本来就印的分隔 |

**不要**替换的自由文本：中文、人名、公司名、备注、检验结论（`合格` / `OK` / `QC PASS`）里的字符——那里 `O` 就是 `O`。

## 二、归一化 checklist

1. 去掉首尾空格。
2. 编码内部的空格删掉（`20 - C002` → `20-C002`）。
3. 破折号统一 `-`，全角字母数字转半角。
4. 日期**保持图上原样**：`20240404` / `2024-04-04` / `2024/04/04` 都按印出来的写。用户明确要求统一格式才转换。
5. 批次号大小写照抄（`L00118` 不要改成 `l00118`）。

## 三、value 模式 → 中文 field 名

图上没有印刷字段名时，按值的形状反推。命名前先看标签上有没有中英文标题，有标题就以标题为准。

**前提：位置定身份，格式不定值。** 同一版式的标签，品号和件号的写法可以千变万化——下面的示例值只是**某一张**标签长什么样，不是判读标准。

| 值形状（示例） | 建议 field 名 | 备注 |
|---|---|---|
| `20-C002-00-7E` | `零件品号` | **值不套格式**，只是示例。靠版位识别（左上/右上第一行），不是靠匹配 `^[A-Z0-9]{2}-...` |
| `4121010-DY01-AA` | `零件件号` | **值不套格式**，同上。长数字 + 字母段只是这张的样子，不是通例 |
| `20240404` | `生产日期` | 常见形态。**不匹配这个形态不等于读错**（也可能是 `2024.04.04`、`24/04/04`）；标签写"出厂"就用 `出厂日期`，写"MFD"同理 |
| `L00118` | `批次序号` | 常见形态。同理，不匹配不作为判错依据；写"LOT"用 `批次号` |
| `合格` / `OK` / `QC` | `检验状态` | |
| `P/N` `PN` | `零件号` | 模板里已有更具体命名时用模板的 |
| 数字 + 单位（`12 PCS`） | `数量` | 单位原样保留 |
| `HG` `Q235` `ABS` | `材质` | |
| 供应商名或编码 | `供应商` / `供应商编码` | |
| 车架号 `LSV...` / VIN | `车架号` | |
| 车型号 | `车型` | |

**不要拿格式去"纠正"值。** 格式只用来在两个候选读法之间做取舍，不能用来否决你在图上看到的笔迹。举例：读到 `20-C0(2-00-7E`，正则会把你推向 `C002`；但除非 `(` 确实是被打断的 0，否则 `(` 就该原样保留。**猜格式 = 编数据。** 真拿不准就写进 `parse_note` 让人工看，别自己抹平。

**品号 vs 件号**：两个 key 同时出现就都保留，不要合并成一个。哪个是哪个靠**版位**定（先确认这批标签哪一行是品号、哪一行是件号），不靠值的长短形状——长短恰好是最容易误判的地方。图上只有一个编码时，按版位归到对应字段，并在 `parse_note` 点名该字段存疑即可。

## 四、label_type 取值参考

| label_type | 判据 |
|---|---|
| `零件标签` | 纸上**只有零件相关的信息**（品号 + 件号 + 生产日期 + 批次号）→ 就是 `零件标签`。**判据是"只有"，不是"含有"**：含品号+件号、但还印着车辆信息、故障描述、索赔单号之类**别的类别信息** → **不是** `零件标签`，按那些信息归类（例：印着"维修单号"→ 维修标签，走 `repair-label-to-json` 技能） |
| `日期标签` | 以生产/到期日期为主角，有批次号，但**没有品号和件号**。别因为"日期很醒目"就归成日期标签 |
| `条码标签` | 主体是一维/二维码 + 短编码（少于 5 个字段） |
| `质检标签` | 有检验状态、检验员、合格/不合格判定 |
| `包装标签` | 有数量、箱号、供应商、收发地址 |
| `设备铭牌` | 金属铭牌，含型号、序列号、额定参数 |
| `其他` | 都不像时用 `其他`，并在 `parse_note` 描述标签内容 |

**品号 vs 件号都能看清时，`零件标签` 是确定解，不需要犹豫。** 只有品号没有件号（或反之）时仍按 `零件标签` 处理，并在 `parse_note` 说明缺的是哪个。

拿不准就在 `parse_note` 写一句"按 X 判为 Y，可能应归为 Z"，比硬选一个不说是好。
