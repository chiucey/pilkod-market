# PRD需求文档编写助手

## 简介

本技能帮助产品经理快速生成结构化的产品需求文档（PRD）。基于成熟的PRD模板，支持Mermaid图表语法，可直接生成Markdown格式的PRD文档。

## 适用场景

- 从零开始编写新功能/新模块的PRD
- 基于用户描述的需求生成PRD草稿
- 补充完善现有PRD文档
- 模板参考与复用

## 核心原则

1. **结构清晰**：遵循标准PRD结构（核心章节+可选章节）
2. **图表可视化**：流程图、架构图使用Mermaid语法
3. **工程导向**：偏工程方案，能直接给研发使用
4. **主动补全**：对不清晰需求，主动假设并说明

## PRD模板结构

### 核心章节（必填）

| 章节 | 内容 |
|------|------|
| 0. 文档信息 | 版本记录、相关文档、名词解释 |
| 1. 需求背景与目标 | 项目概述、问题陈述、用户故事、目标价值 |
| 2. 方案概述 | 页面结构、核心实体、信息架构 |
| 3. 功能详述 | 功能目标、输入输出、处理逻辑、异常处理 |
| 4. 页面设计 | 页面布局、筛选区、表格、抽屉、交互说明 |

### 可选章节（按需补充）

| 章节 | 说明 |
|------|------|
| 5. 数据要求 | 涉及数据存储/埋点时填写 |
| 6. 异常处理 | 涉及复杂异常逻辑时填写 |
| 7. 非功能性需求 | 需技术评审时填写 |
| 8. 里程碑与排期 | 需项目化管理时填写 |
| 9. 附录 | 按需补充 |

## 使用方法

### 1. 启动PRD编写

当用户要求生成PRD时：
1. 确认需求信息是否完整
2. 如信息不完整，主动询问关键问题
3. 基于信息生成PRD
4. 输出Markdown文件

### 2. 需求信息收集

如果用户提供的信息不完整，主动询问以下问题：

| 问题类型 | 询问内容 |
|----------|----------|
| 基础信息 | 产品名称、所属系统、使用角色 |
| 数据同步 | 数据来源、同步频率、同步方式 |
| 外部依赖 | 依赖哪些系统/接口 |
| 权限控制 | 是否需要权限控制 |
| 审批流程 | 是否需要审批 |

### 3. PRD输出格式

生成的PRD保存为Markdown文件，命名格式：
```
{产品名称}PRD.md
```

## Mermaid图表规范

### 支持的图表类型

| 图表类型 | 语法 | 适用场景 |
|----------|------|----------|
| 流程图 | `graph TD/TB/LR/RL` | 业务流程、功能流程 |
| 时序图 | `sequenceDiagram` | 系统交互、接口调用 |
| 状态图 | `stateDiagram-v2` | 状态流转 |
| 甘特图 | `gantt` | 项目排期 |
| 饼图 | `pie` | 数据占比 |

### 图表命名规范

- 图表必须包含标题说明
- 节点使用中文描述
- 复杂图表使用subgraph组织

## 输出示例

### 用户输入示例

```
帮我生成一个「工位信息管理」的PRD，需求如下：
- 页面包含筛选区、工位列表、右侧抽屉
- 支持查询、同步、绑定管理功能
- 绑定类型包括接驳区绑定、产线绑定
```

### 输出结果

生成完整PRD文档，包含：
1. 文档信息（版本记录、名词解释）
2. 需求背景与目标
3. 方案概述（含Mermaid架构图）
4. 功能详述（每个功能含输入/输出/逻辑/异常）
5. 页面设计（含布局图、交互说明）
6. 需求列表（优先级表格）

## 注意事项

1. **主动询问**：信息不完整时，先询问再生成
2. **明确假设**：对不确定的内容，说明假设前提
3. **图表优先**：流程图优先使用Mermaid语法
4. **结构一致**：遵循模板结构，避免遗漏章节
5. **保存文件**：生成后保存到工作目录
