# 审稿、精修与终审

从用户表述判断只审不改、保剧情精修、允许场景大改或结构重写。已明确授权就执行，不重复问；“去 AI 味”本身不授权改变重大剧情。

## 统一次序

1. 对照用户要求、总纲、人物、前文与章纲，核必达事件、因果、信息来源、能力边界、伤势、数值、关系和伏笔。
2. 看场景是否缺少关键动作、可观察结果、主角收益和角色动机。先修硬矛盾与缺戏。
3. 看爽感、幽默、情绪和节奏是否兑现。保留原稿有效的恐惧、愤怒、得意、委屈、喜悦等，不磨成同一种冷静语气。
4. 最后修重复总结、机械转折、同质对白、无意义动作和句段节奏。
5. 改完对照原稿和章纲，确认事件、线索、所得、代价和关系证据没有无意减少；新增段落核查跨章影响。

这些步骤在内部完成；用户要求审稿报告时才展开。

## 只审不改

给最影响阅读或连续性的实际问题，按严重度排列。每条包含章号或原文位置、短引文、依据、影响和可执行改法。硬性矛盾、缺戏和个人偏好分开；资料不足标为待核，不当作肯定错误。不要为了凑十项检查而找不存在的问题。

可按十个维度检查：开篇、人物、因果与节奏、情绪、世界规则、语言、爽点回报、悬念伏笔、结尾、主题与终局。但维度是观察角度，不强制打分，不要求金句、固定高潮和格局升级。

## 精修

保剧情精修可以修改表达、对白、过渡、局部动作顺序，并补足既定事件需要的戏；不能擅删必达事件、隐去代价、改技能效果或提前用后期伏笔。用户允许大改场景时，在不改变主要因果和既定结局的边界内调整。

只要正文就直接交修订稿；发生亲密互动留白时，按技能入口的用户追加规则在正文后单列告知。用户要修改说明时，简要列实质改动与核验范围。只修某段则不自动扩大到全卷。

## 终审与多模型意见

其他 AI 的审稿或精修都是建议，逐项按本书材料裁决。不能因某建议说“不够爽”就新增打脸，也不能因某稿更短就默认更优。恢复同一作者口吻，保留原稿有效戏肉和人物情绪。

终审核对原始稿、精修稿和必须完成事件，追踪实质删改。凡是事实不合、必达事件遗漏、信息越界或所得消失，先修复再交付。涉及用户保留的重大剧情抉择时指出冲突，其余自行处理。

## 批量复盘

多章或全卷任务才检查长期重复、伏笔拖欠、情绪曲线、资源账与角色状态。抽样只说明抽样结论，不能包装成全文通读。模拟读者反应明确标为模拟，不代替实际读者反馈。

需要更多定位方法可读 [小说改良原始索引](../original/novel-improver/references/index.md) 与 [Sepia 方法](sepia-fiction.md)。平台评分权重、固定 9.0+ 目标、自动检测阈值和模型身份报告均不作为交付标准。
