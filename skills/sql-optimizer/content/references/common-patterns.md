# SQL优化检查清单

## 性能问题模式

### 高危问题（必须修复）
| 模式 | 描述 | 解决方案 |
|------|------|----------|
| SELECT * | 全字段查询 | 明确指定需要的字段 |
| 笛卡尔积 | 多表JOIN无关联条件 | 添加JOIN条件 |
| 嵌套子查询过深 | 3层以上子查询 | 改用CTE或临时表 |
| 无WHERE条件的DELETE/UPDATE | 全表操作风险 | 添加WHERE条件 |
| LIKE '%xxx%' 前置通配符 | 无法使用索引 | 考虑全文索引 |

### 中等问题（建议优化）
| 模式 | 描述 | 解决方案 |
|------|------|----------|
| OR条件过多 | 索引失效 | 改用IN或UNION |
| DISTINCT滥用 | 排序开销大 | 优化JOIN条件 |
| ORDER BY RAND() | 全表随机排序 | 使用WHERE条件筛选 |
| 隐式类型转换 | WHERE id = '123' | 使用正确类型 |
| 函数在索引列上 | WHERE YEAR(date) = 2024 | 改写条件表达式 |

### 低风险问题（可优化）
| 模式 | 描述 | 解决方案 |
|------|------|----------|
| 大字段在SELECT中 | TEXT/BLOB | 延迟加载或分离表 |
| 不必要的排序 | 无实际需要 | 移除ORDER BY |
| HAVING代替WHERE | HAVING在聚合后过滤 | 优先使用WHERE |

## 索引优化规则

1. **等值查询放前面**: `WHERE status = 1 AND date > '2024-01-01'`
2. **范围查询放最后**: 范围列尽量放组合索引末尾
3. **前缀匹配优先**: `LIKE 'prefix%'` 可用索引
4. **覆盖索引**: SELECT字段都在索引中时避免回表

## JOIN优化原则

1. 小表驱动大表（INNER JOIN时）
2. 优先使用EXISTS代替IN子查询
3. 确保JOIN字段类型一致
4. 避免在JOIN条件中使用函数
