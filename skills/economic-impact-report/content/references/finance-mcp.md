# MiniMax Finance Data MCP 使用规范

## 主体解析

调用 `resolve_entity` 时，按市场选择 `entity_type`：

- A股 → `a_stock`
- 港股 → `hk_stock`
- 美股 → `us_stock`
- 基金 / 债券 / 指数 → `fund` / `bond` / `index`
- A股行业 / 概念 → `industry` / `sw_industry` / `concept`
- 港股行业 → `hk_industry`

候选查询用公司名称、简称或证券代码；最终选哪个内部 `code`，要依据交易所、证券代码、公司全称与行业描述综合判断，不要猜。

## 数据调用

- 用 `call_api(api_id=..., params=...)` 拿公司、财务、行情、估值、事件、股东、分红 / 融资、基金、债券、指数与行业数据。
- 用 `query_macro(keyword=...)` 检索宏观与产业指标，再依据返回的 `indicId` 与明细参数取时间序列。
- `call_api` 抛业务枚举错误时，用 `enum_candidates` 修参数后重试，不要硬猜枚举值。
- 数据量大走 CSV；关键结论所需的小表用 Markdown 或 JSON 即可。

## 口径与来源

- 保留：市场、交易代码、内部 `code`、数据截至时间、报告期、单位、币种、会计准则、复权口径。
- 跨市场分析必须统一币种与报告期，或显式保留不可比差异。
- 最新价格、估值、事件、宏观数据必须记录查询时间戳。
- MCP 没返回的数据标记为缺失，不允许推测或杜撰。

来源优先级：

1. 监管机构、交易所、上市公司正式披露。
2. MiniMax Finance Data MCP 的结构化数据。
3. 用户提供的模型、跟踪器与研究材料。
4. 其他可核验的公开来源。

当结构化数据与正式披露冲突时，以正式披露为准，并记录差异。
