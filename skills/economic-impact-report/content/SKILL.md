# 多市场股票经济影响报告

## 起步动作

按下列顺序激活上下文，再开始任何检索：

1. 读取 `references/finance-mcp.md`：明确 MCP 接口的取数规范。
2. 读取 `references/market-rules.md`：建立 A/港/美股的市场口径。
3. 读取 `references/impact-framework.md`：固定时间桶、置信度、传导渠道与量化口径。

随后再做以下数据准备：

- 用 `query_macro` 拉取目标国家/地区的宏观、产业、价格、产量、进出口、政策类指标。
- 用 `resolve_entity` 解析 A 股、港股、美股个股，以及基金、指数、可调用的行业或概念主体。
- 用 `call_api` 抓取行情、财务、估值、行业成分与事件流，搭出冲击前的基线。
- 对每条传导链分门别类地落到「事实 / 假设 / 判断 / 领先指标 / 验证窗口」上。

## 市场覆盖范围

- 由用户问题决定 A股、港股、美股或它们之间的跨市场映射。
- 政策与产业数据优先映射到收入、价格、销量、成本、资本开支、现金流、估值。
- 必须分别处理各市场的交易日历、停复牌、流动性、盘前盘后与事件披露时差。
- 中国政策或产业冲击可同时落到 A、H、美三地上市公司；禁止强行只压到一个市场。

## 交付物形态确认

按 `references/output-guidelines.md` 的载体优先级判断格式。本工作流默认的成品是一份独立可读的 GUI/HTML 经济影响报告；只有当用户明确希望"轻量回复"时才退回纯聊天输出。GUI/HTML 产物必须通过 `visual-page` skill 完成，本技能只负责经济影响研究、页面 brief 与业务结构。

在为新建的、独立、面向读者的报告开始检索或开展分析之前，先加载 `references/output-guidelines.md`，并只针对会真正改变结果的格式、深度、受众、重点做澄清决定。

## 目标

输出一份达到决策级水准的公开股票经济影响报告。它不是新闻稿汇编，也不是泛跨资产宏观笔记；它要回答资深公开股票投资者关心的：

- 发生了什么变化；
- 为什么这件事对上市股票重要；
- 哪些因素会率先重定价；
- 哪些方面仍不确定；
- 哪些发行人、板块、盈利路径、估值争议、仓位风险、组合动作最为关键。

除非用户主动要求摘要、快读、单页、TL;DR 之类的压缩格式，否则按完整决策级报告交付。对新建、独立、读者向报告，先形成完整 `visual-page brief`，再调用 `visual-page` 生成独立 GUI/HTML；仅在用户明确要"轻量回复"时才用聊天形式。

## 适用场景

下列任务进入本技能：

- 某特定事件的经济或市场影响
- 一阶到四阶影响的拆解
- 从冲击到后果的传导图
- 含作用机制的赢家/输家分析
- 利率、外汇、期权、期货、商品、信用、政策、地缘、劳动力、供应链、需求或监管冲击对公开股票的影响
- 情景、催化剂、监测信号、"什么会改变观点"
- 面向公开股票资深投资者的政策/宏观/监管/地缘/供给/信用/商品/行业/盈利冲击备忘录

不要用本技能处理：

- 没有"影响"维度的纯文章摘要
- 没有事件或催化剂的泛宏观解读
- 需要先调用其他本地技能的窄工作流（如 DCF、业绩深度分析、催化剂日历、电子表格清洗）
- 一句话点评类、画因果图反而显得多余的市场短评
- 不落到上市股票发行人/板块/组合决策的独立宏观、利率、外汇、期货、期权、商品或信用策略——这类应路由出去
- 独立的宏观、利率、外汇、期货曲线、期权波动率构建、信用证券相对价值或债务证券选择——这些应交给对应的独立分析流程；其中信用工具由独立信用分析流程承接

## 不可让步的硬要求

- 先讲结论。
- 把事实、推断、假设、情景分清楚。
- 把直接影响与高阶影响分清楚。
- 把上市股票的即时影响、中期盈利/预测影响、估值/倍数影响、仓位/资金流影响、结构性后果分别成文。
- 每一条关键论断都必须挂到一条传导渠道上。
- 每一个点名的发行人、板块、国家、商品、利率、货币、信用信号或资产输入，都必须连回到公开股票的作用机制。
- 只要能给出合理区间就量化。
- 区分"真正新的变化"与"旧闻或既有预期"。
- 区分"很可能已定价"与"可能仍被错价"。
- 正面回应最强的反方论点。
- 收尾必须给出情景、监测信号、证伪条件，以及公开股票动作立场：`add`、`press`、`hold`、`trim`、`exit`、`hedge`、`watchlist`、`pass`、`wait for proof`、`re-underwrite`。
- 涉及时效性事实时，在分析前先核日期、时间戳与最新状态；把"已报道事件"与"已确认事实"分开，把商品/市场的现货、期货、收盘、盘中数值分开。

## 因果主轴

按顺序推进，不要跳步：

1. 事件 + 基线
2. 哪里真正变了
3. 传导渠道
4. 最可能率先重定价的变量
5. 直接赢家 / 输家
6. 高阶后果
7. 情景、催化剂、公开股票表达方式、组合动作

如果说不出传导渠道，先回去做来源工作，不要动笔写。展开因果图前请加载 `references/impact-framework.md`，确认时间、直接性、置信度、领域、量化口径。

## 工作流

1. 用一句话精确定义事件，标注证据状态、市场数据截止时间，以及它可能影响的公开股票决策。
2. 厘清相对于一致预期或基线的"新变量"，以及上市股票看上去已经反映了什么。
3. 在做大规模研究前，先草拟传导图，让每条渠道终点都落到发行人、板块、盈利、估值、仓位或组合维度。
4. 写下关键假设、验证信号、证伪条件。
5. 再去收证据，优先一手来源、优先时效性。
6. 按方向、幅度、时间、置信度、直接性给影响排序。只有当代表性发行人或板块共享同一传导渠道、同一首要受影响报表项、同一方向性解读时才合并入同一行；经济逻辑不同就拆开。
7. 判断在受影响个股、同业组、板块、指数或因子敞口中，哪些已定价、哪些可能仍被错价。"已定价"的结论应主要基于受影响发行人或板块的价格表现、预测修订、估值变化，或相关传导市场指标；宽基指数表现只能当背景。
8. 构建基准/上行/下行情景。
9. 写下最有力的反方论点。
10. 收尾要给监测事项、证伪条件、会改变组合动作的因素。

完整章节化报告请翻 `references/workflow.md`。

## 没有投资组合 / 观察名单时怎么办

用户没给组合、持仓清单、论点、基准、观察名单时——不要僵在原地，也不要瞎编持仓。改成构建一张通用公开股票敞口图：

- 敞口最大的行业与子行业；
- 国家、币种以及地域收入 / 成本敞口；
- 涉及的上市公司，以及对公开股票有传导影响的相关非上市公司；
- 会传导至股票预测或估值倍数的商品、利率、外汇、信用利差、波动率或需求变量；
- 可能的受益者、受损者、二阶同业、供应链上下游、拥挤交易表达；
- 用 `watchlist` / `wait for proof` / `pass` / `re-underwrite` 建立研究队列，而不是"增持/减持/退出"这种组合特定指令。

组合特定动作必须标记为 `not available without holdings / active weights / mandate`。报告仍然要落到发行人、板块/同业、盈利或预测路径、估值/倍数、仓位/资金流、下一步公开股票研究队列。

## 输出形态

- **完整经济影响报告**：默认路径，特别适用于发行人多、情景多、来源多、监测项多的请求。如果是重要且可复用的经济影响报告，或用户明确要 GUI/HTML 形式的公开股票冲击分析，将事件、传导链、情景、敞口排序、监测信号与来源状态整理成 `visual-page brief`，交给 `visual-page` 出独立 GUI/HTML。
- **标准化仪表板**：只有用户明确要"标准化仪表板""可复用模板"或"由结构化载荷驱动的渲染"时才走这条。本技能仍只负责传导逻辑、情景、发行人/板块敞口图、盈利与估值解读、仓位与组合观察事项；HTML 外壳、图表排版、响应式布局、验证与 `<media />` 交付仍由 `visual-page` 完成。
- **明确要求的快读**：仅在用户主动要"快读""简短""摘要""单页""简报""TL;DR"时走这条。包含：事件状态、公开股票核心结论、主要传导渠道、最受影响的上市敞口、已定价的部分、需要证据的部分、下一监测事项。

## 输出契约

除非用户明确要更短或更窄的格式，否则按完整报告写。前 150–250 个英文字应能独立成为执行摘要；其余部分仍要给完整的因果图与投资影响。

最低章节门槛：

- `Executive Call`
- `Event Status And Market Baseline`
- `Source And Freshness`
- `What Is New Vs. Expected`
- `Event-To-Equity Transmission Map`
- `Public Equity Framing`
- `Ranked Equity Impact Map` / `Issuer And Sector Impact`，并含发行人 / 板块敞口候选
- `What Is Priced In Vs. What Requires Proof`
- `Earnings, Valuation, And Positioning Read-Through`
- `Scenario Matrix`
- `Monitoring Triggers And Research Queue`
- `Bottom-Line Judgment`

完整结构对照 `references/report-template.md`；按领域加查清单见 `references/domain-checklists.md`；最终交付前过一遍 `references/quality-bar.md`。不要再运行旧的 economic verifier / 校验脚本；来源、时效性与缺口检查由本技能在研究内容层完成，HTML 文件验证由 `visual-page` 完成。

## HTML 交付：无损调用 visual-page

如果输出是独立 HTML 经济影响报告，必须把下列内容作为完整设计 brief 交给 `visual-page`，不要在本技能内直接写 HTML：

- **页面模式**：完整报告用 `Long-read / Report`；若用户要求筛选式冲击表、发行人排名或监控面板，用 `Data UI`。
- **视觉主题**：要求 `visual-page` 使用冰白纸背景、液态玻璃风格；不要使用 `visual-page` skill 里的默认配色方案。上涨、改善、受益、利好、盈利/估值上修等好事，以及所有强调色，统一用中国红 `#c0322f`；下跌、恶化、受损、利空、盈利/估值下修等坏事，统一用稳绿 `#15803d`。
- **输出路径意图**：若用户给路径则使用；否则要求 `visual-page` 在 `/tmp/visual-page/<economic-impact-topic>/index.html` 下创建独立目录，不覆盖旧页面。
- **首屏结构**：H1 是事件 / 冲击名称；首屏必须放 Executive Call、事件状态、research cut-off、最重要传导链、前三个受影响发行人 / 板块或研究队列。
- **组件映射（深度耦合 visual-page 组件，每个都带交互）**：
  - 事件 → 股票传导链 → **可点击 Mermaid 传导图**（4 节点以上）：节点点击平滑滚动到对应发行人 / 板块章节；2-3 节点的简单链路用 hover 增强的 flow-node。受益 / 利好路径描边中国红 `#c0322f`，受损 / 利空路径描边稳绿 `#15803d`。
  - **Ranked Equity Impact Map** → **可排序 + 可筛选表**：表头点击按方向 / 直接性 / 时序 / 置信度 / 已定价程度排序（升降箭头指示）；上方放筛选 chips（方向：受益 / 受损；直接性：一阶 / 高阶；状态：已定价 / 待证明，激活态中国红）；每行可行内展开传导机制与首先受影响报表科目；方向列用中国红（受益）/ 稳绿（受损）角标。
  - **Scenario Matrix** → **Base / Bull / Bear tabs + 概率滑块联动**：三情景做 tab 切换（激活态中国红）；顶部概率滑块调整时，三情景概率实时归一化显示、对应假设与受影响标的随之高亮；切换 / 滑动 ≤200ms 过渡。
  - 二 / 三 / 四阶影响 → **accordion 折叠组**：默认折叠，点击逐阶展开，避免高阶推演撑爆首屏。
  - 监测触发 / 研究队列 → **step timeline**，节点 hover 升起液态玻璃说明卡（监测项 + 触发阈值 + 信号方向）。
  - 发行人 / 板块影响幅度（2-8 项）→ **bench bars**，正向幅度中国红、负向稳绿，hover 显示传导渠道。
  - 来源新鲜度与缺口 → **可排序 + 行内展开表**，按 as-of 排序，行内展开 source_id 全名与时效状态。
- **交互规格（全部用内联 vanilla JS + CSS，禁止额外重依赖；继承 visual-page 的 BANNED 清单：无 AI 渐变 / 霓虹 / Inter）**：
  - 顶部 **sticky 锚点导航**：Executive Call / 传导图 / 影响排名 / 情景矩阵 / 监测，当前区块高亮中国红，点击平滑滚动。
  - **已定价 vs 待证明** 必须在详细监测前可见，用对照双栏或 toggle 呈现。
  - 所有可点击元素必须有 hover 态、`:focus-visible` 键盘可达、`cursor:pointer`；tab / 排序 / 筛选 / 滑块 / accordion 一律 ≤200ms 过渡。
  - 移动端（<768px）：Mermaid 图可横向 pan 但页面本身不横向滚动；排名表转单列卡片；tabs 与 chips 自动换行；滑块全宽。
  - 交互服务于「先结论、分清事实 / 推断 / 情景」，不得制造数据噱头；首屏一屏内给出 Executive Call、事件状态、research cut-off、最重要传导链、前三受影响发行人 / 板块。
- **图表规则**：2-8 个发行人 / 板块的影响幅度用 CSS bench bars；只有超过 8 个时间点的商品、利率、汇率、价格序列才引入 Chart.js（`font.family='Outfit'`、正向序列中国红、负向稳绿、`borderRadius:6`）；传导图 4 节点以上用可点击 Mermaid，2-3 节点用 hover 增强 flow-node。不要为少量节点引入重库。**用到 `<div class="mermaid">` 时，务必提醒 `visual-page` 在 `<head>` 加载 `mermaid.min.js`（CDN）并调用 `mermaid.initialize`，否则图不渲染。**
- **必须保留的业务语义**：事实 / 假设 / 推断 / 情景必须可见地区分（用 chips 或角标，不要靠红绿单独承载，避免与涨跌语义混淆）；已定价 vs 待证明必须在详细监测前出现；无组合时只用 watchlist / wait for proof / pass / re-underwrite 等通用公开股票姿态。
- **交付要求**：要求 `visual-page` 输出一个完整 GUI/HTML 文件，检查本地打开、响应式、无断链、每个交互元素都有 hover / focus 态，再用 `<media />` 交付。

## 边界情形

- 事件描述不充分但仍可分析：先说明你的解读，再继续。
- 用户只给文章或标题：从中抽出意外因素、基线、因果图。
- 某领域影响不重要：直接写 `not material`。
- 当前事实或市场变动有不确定：先核实再表态。
- 事件看上去很大、经济影响其实很小：明确说明。
- 影响大多在预期之中或已定价：明确说明。
- 最佳表达方式不是股票：如实说，但本技能不承担非股票交易构建的主线工作。
