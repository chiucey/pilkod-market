# PPT / Slides 生成技能

## 目标

用**稳定可复用的流程**把"零散信息/材料/数据"转成一套结构清晰、视觉一致、可直接交付的演示文稿（默认交付 `.slides`；如用户要求再导出为 PPT/PPTX）。

## 快速工作流（从 0 到交付）

```
用户需求 → 需求澄清 → 搭故事线 → 准备素材 → 生成幻灯片 → 交付前自检
```

### 1. 激活 Slides 工具

> **所有演示文稿任务的第一步**

```markdown
必须先调用 `slides_activate`，再做任何与演示文稿相关的创建/修改操作。
```

**触发示例**：
- 用户："帮我做个产品介绍PPT"
- 响应：先调用 `slides_activate`，然后继续需求澄清

---

### 2. 需求澄清（使用表单）

> **不要凭猜测开始，先问清楚关键信息**

使用 `show_form` 收集以下信息：

| 表单字段 | 说明 | 示例 |
|---------|------|------|
| 受众 | 谁会看这份PPT | 投资人/领导/客户/内部团队 |
| 目的 | 想达成什么 | 融资/审批/培训/销售 |
| 页数/时长 | 建议 10-30 页 | "15页左右" |
| 语气风格 | 正式/活泼/技术 | "偏正式" |
| 数据图表 | 是否需要图表 | "需要2-3个数据图表" |
| 品牌模板 | 是否有VI要求 | "用公司蓝白配色" |

**快速确认策略**：提供预设选项而非空白表单，让用户"选一个"而不是"填一个"

**表单示例**：
```markdown
请确认以下需求（回复数字或简短说明）：

1. 受众：①投资人 ②领导层 ③客户 ④内部团队
2. 目的：①融资 ②项目审批 ③产品销售 ④培训 ⑤其他：___
3. 页数：①5-10页 ②10-20页 ③20-30页
4. 语气：①正式商务 ②轻松活泼 ③技术专业
5. 特殊需求：___（如配色、数据图表等）
```

---

### 3. 搭故事线（先结构，后排版）

**输出物**：清晰的大纲

```
第一章：背景与问题
  - 第1页：现状描述
  - 第2页：痛点分析

第二章：解决方案
  - 第3页：方案概述
  - 第4页：核心能力

第三章：实施计划
  - 第5页：路线图
  - 第6页：资源需求

第四章：收益与风险
  - 第7页：预期收益
  - 第8页：风险对策

结尾页
  - 第9页：行动呼吁
```

**关键原则**：
- 每页只讲 **1 个核心点**
- 标题是**结论句**（如"我们的方案能降低50%成本"而非"方案介绍"）
- 不确定的内容标注"待确认/待补证据"，不要硬编数字

**确认后再继续**：把大纲发给用户确认，得到肯定后再生成具体页面

---

### 4. 准备素材

> **先备齐素材再进 Slides，避免中途返工**

#### 配图策略

| 场景 | 推荐方式 |
|------|---------|
| 真实场景/产品 | `search_image` 搜索真实照片 |
| 抽象概念/统一风格 | `generate_image` 生成插画 |
| 图标/小元素 | 使用 SVG 图标库 |

**搜索图片示例**：
```
用户需要"智能工厂"配图
→ 使用 search_image 搜索 "smart factory industrial automation"
→ 选一张符合品牌调性的真实照片
```

**生成图片示例**：
```
用户需要"数据流程图"风格配图
→ 使用 generate_image 生成统一风格的插画
→ prompt: "modern flat design illustration of data flow, blue and white color scheme"
```

#### 图表制作

| 数据类型 | 工具 | 输出格式 |
|---------|------|---------|
| 柱状图/折线图/饼图 | `anygen-chart-cli` | `.chart` |
| 复杂数据可视化 | `anygen-chart-cli` | `.chart` |
| **禁止** | matplotlib | **不要用** |

**图表制作流程**：
```
1. 整理数据到 CSV
2. 使用 anygen-chart-cli 生成 .chart
3. 将 .chart 嵌入 Slides
```

---

### 5. 生成幻灯片

#### 页面顺序（标准结构）

```
1. 封面（标题 + 副标题 + 演讲者信息）
2. 目录/议程（3-6个章节）
3. 结论先行页（Executive Summary，可选）
4. 正文（按故事线展开）
5. 结尾/致谢/CTA
```

#### 视觉一致性检查

每页需保持：
- 字号层级统一（标题/副标题/正文）
- 行距一致
- 页边距统一
- 对齐方式一致（居中/左对齐）
- 配色方案统一
- 图标风格统一

---

### 6. 交付前自检

| 检查项 | 标准 |
|-------|------|
| 每页要点 | 只讲 1 个核心点 |
| 标题 | 是结论句，不是泛泛的"介绍" |
| 数据 | 有来源/口径说明 |
| 文案 | 可朗读，无口语赘词 |
| 图表 | 有标题和注释 |

## 典型用法示例

### 示例 1：创业路演材料

```
用户：请帮我做一个AI创业项目的路演PPT

1. 调用 slides_activate
2. 用表单确认：
   - 受众：投资人
   - 目的：融资（天使轮）
   - 页数：12-15页
   - 语气：正式商务
3. 确认故事线：
   - Problem（痛点）
   - Solution（解决方案）
   - Market（市场）
   - Business Model（商业模式）
   - Traction（进展）
   - Team（团队）
   - Ask（融资需求）
4. 按顺序生成各页
5. 自检后交付
```

### 示例 2：把文档转成PPT

```
用户：把这个产品文档转成演示稿

1. 调用 slides_activate
2. 分析文档结构，提取关键信息
3. 与用户确认：
   - 受众是否正确？
   - 重点是否突出？
   - 需要增加/删减哪些内容？
4. 按确认的结构生成PPT
```

### 示例 3：修改现有PPT

```
用户：帮我优化这份汇报PPT，让它更专业

1. 调用 slides_activate
2. 明确修改目标：
   - 结构重排 / 文案精炼 / 视觉统一 / 补图表
3. 保留原有品牌元素
4. 只修改指定部分，不全盘重做
5. 交付修改后的版本
```

## 修改现有PPT（编辑型需求）

### 明确修改目标

| 类型 | 说明 |
|-----|------|
| 结构重排 | 调整页面顺序或合并/拆分页面 |
| 文案精炼 | 压缩文字，突出核心信息 |
| 视觉统一 | 统一字号/配色/对齐 |
| 补图表 | 添加数据图表或配图 |

### 保留与修复原则

- **保留**：用户的 Logo、品牌色板、字体、页脚信息
- **修复**：字号层级统一、边距统一、对齐统一、重复元素组件化

### 最小改动原则

如需替换某几页：只替换那几页内容与布局，不要全盘重做（除非用户要求）

---

## 重要约束

| 规则 | 说明 |
|-----|------|
| 必须 slides_activate | 任何PPT任务的第一步 |
| 图表用 anygen-chart-cli | 不要用 matplotlib |
| 数据不编造 | 无法确认写"数据待补/待确认" |
| 先确认再生成 | 大纲发给用户确认后再制作具体页面 |
