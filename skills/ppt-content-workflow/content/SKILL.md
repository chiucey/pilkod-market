# PPT内容生成与施工图制作一体化工作流

## 技能目标

将碎片化输入（用户提供的标题、观点、论据、数字、术语等）转化为：
1. **结构化内容文档**（Markdown格式）
2. **PPT施工图**（Word文档格式）

## 核心铁律（不可违反）

1. **绝对忠实**：100%保留用户原文，仅进行结构化整理和合规补充
2. **架构锁定**：严格遵循用户给定的页面顺序、标题、观点层级，禁止调整、合并、拆分或新增核心观点

---

## 第一阶段：内容结构化整理

### 页面标准化结构

每个页面按以下格式整理：

```markdown
## Page X：用户提供的原始页面标题

### 判断观点1：用户提供的原始判断观点
#### 论据支撑：
[用户提供的原始论据] + [补充的专业论据]

### 判断观点2：用户提供的原始判断观点
#### 论据支撑：
[用户提供的原始论据] + [补充的专业论据]

### 补充判断（仅当用户明确要求时添加）：
[按指定风格补充的深度判断，不超过2条]
```

### 论据补充规则

1. **紧贴观点**：形成"观点→数据/案例→因果"的完整逻辑链
2. **量化优先**：优先补充可量化数据（金额、增速、占比、时间）
3. **来源标注**：所有补充数据必须标注来源，格式：`（来源：XXX 报告/财报，日期）`

### 信源优先级

1. 官方财报/公告（最高优先级）
2. 头部机构报告（IDC、Gartner、摩根士丹利等）
3. 行业协会数据（SIA、IEA等）
4. 权威媒体报道（彭博社、路透社、The Information等）
5. 估算与推算（仅在无以上信源时使用，必须高亮标注"估算"并说明推算逻辑）

### 行为边界控制

| 类型 | 说明 | 动作 |
|------|------|------|
| **深化补充** | 在用户已提及的分析维度内补充更细的数据、案例 | 允许直接补充 |
| **维度延伸** | 引入用户原文未提及的全新分析维度 | **必须报批**，使用话术："建议补充[XX维度]数据以增强分析深度，是否采纳？" |

### 异常输入处理

| 异常类型 | 处理动作 | 输出形式 |
|----------|----------|----------|
| **数据矛盾** | 列出所有冲突值，提示用户核实 | 添加注释：`[待核实：用户提供的A公司增速有30%和5%两个版本，请确认正确值]` |
| **表述模糊** | 提供量化选项，请用户选择 | 添加注释：`[请确认：'增长很快'的具体阈值（如>20%或>30%）]` |
| **信息过载** | 说明拆分逻辑，请用户确认 | 在文档开头说明拆分逻辑 |

### 禁止行为清单

- 修改、删除、替换用户原始文字
- 调整用户给定的页面架构、顺序、观点层级
- 添加用户未提及的新核心观点
- 使用无来源数据或模糊、情绪化语言
- 将不同观点的论据混在一起

### 输出

**《结构化内容文档》**：`.md` 或 `.docx` 格式，包含所有页面的结构化内容

## 第二阶段：PPT施工图生成

### 输入

《结构化内容文档》

### 输出

**《PPT施工图》**：`.docx` 格式

### 阶段一：解构与框架构建

1. **解析输入**：理解每页的核心矛盾与分论点
2. **提炼主线**：从所有页面标题中归纳出贯穿全文的核心叙事线
3. **构建矩阵**：为每页创建记录，明确核心任务、核心判断、已有论据、初步视觉构思

**产出**：《叙事逻辑一页纸》 + 《页面规划矩阵》

### 阶段二：设计页面蓝图

#### 全局设计法典（置于施工图首页）

| 元素 | 规格 |
|------|------|
| **布局** | 左图右文（默认左55%，右45%） |
| **主标题** | 24pt，#333333，加粗 |
| **判断观点** | 18pt，#0073e6，加粗 |
| **正文/阐述** | 16pt，行距1.2，#333333 |
| **标注** | 14pt，#666666 |
| **主色/品牌色** | #0073e6 |
| **辅助-增长** | #00b050 |
| **辅助-下降/警示** | #ff6b6b |
| **背景/中性** | #f8f9fa, #dddddd |

#### 图表匹配指南

| 论点类型 | 首选图表 | 关键要素 |
|----------|----------|----------|
| 趋势/对比 | 多系列折线图/组合图 | 时间轴、数据系列、增速标注 |
| 构成/比例 | 堆叠柱状图/饼图 | 分类、占比、突出部分 |
| 项目排名 | 簇状柱状图/条形图 | 分类、数值、排序 |
| 流程演进 | 时间轴/漏斗图 | 阶段、节点、转化率 |
| 关系/层次 | 金字塔图/架构图 | 层级、连接、说明 |

#### 复杂度审查与备选方案

- 若图表包含超过**4个数据系列**或超过**5个时间点**，需设计一个简化版作为备选方案
- 示例：完整版为"6家公司4年趋势折线图"，备选版为"6家公司最新季度增速柱状图"
- 在施工图中并列呈现两个方案，并说明优劣

#### 右侧文案结构

- **判断观点**：直接引用
- **观点阐述**：50-100字，采用"背景/矛盾 + 核心判断 + 关键证据"公式，必须融入1-2个核心数据
- **文本论据**：以项目符号或高亮数据卡片形式呈现补充信息

**产出**：《全局设计法典》 + 《分页蓝图》（含视觉方案、备选方案、文案草稿）

### 阶段三：填充与细化

1. **构建数据底表**：为每个图表提供完整、准确的数据表格，含数值、单位、时间、来源
2. **输出"可编程"指令**：将视觉方案细化为可直接执行的指令，具体到图表类型、数据系列、颜色（HEX码）、坐标轴、图例、标注
3. **精修文案**：定稿所有观点阐述，确保逻辑流畅、数据精准
4. **统一复核**：检查术语、数据、配色的一致性

**产出**：《施工图草案》.docx

### 阶段四：自我验证与交付

#### 三明治审查法

| 层级 | 检查内容 |
|------|----------|
| **顶层** | 检查叙事连贯性 |
| **中层** | 逐页检查图文匹配度、文案篇幅 |
| **底层** | 核对数据准确性、指令清晰度、格式一致性 |

#### 交付文档结构

1. 封面与项目概要
2. 第一部分：全局设计规范
3. 第二部分：分页施工详图
4. 第三部分：附录（数据来源、待定项）

#### 命名规范

`[项目主题]_PPT施工图_YYYYMMDD_V[版本号].docx`

**产出**：最终版《PPT施工图》.docx，标注"此版本已通过所有验证，可交付制作"

## 第三部分：智能协作协议

### 决策边界与话术模板

| 决策场景 | AI动作 | 标准话术模板 |
|----------|--------|--------------|
| **维度延伸** | 暂停，请求确认 | "建议补充[XX维度]数据以增强分析深度。采纳/忽略？" |
| **视觉方案选择** | 提供A/B方案 | "方案A（信息全但复杂）vs 方案B（聚焦但简化）。推荐A/B？" |
| **数据矛盾** | 列出冲突，请求核实 | "发现数据矛盾：[值1] vs [值2]。请确认正确值？" |
| **模糊表述量化** | 提供选项 | "您提到的'[模糊词]'，具体指代：选项1 / 选项2 / 其他？" |

### 修订规范

- 每次迭代提交时，必须在文档开头用"【修订日志】"列明所有更改点
- 用户反馈需逐条回应，并在下个版本中体现修改结果
- 最终版本需标注"此版本已通过所有验证，可交付制作"

---

## 适用场景

- 用户提供了碎片化的PPT内容（标题、观点、论据、数据）
- 需要将这些内容结构化整理为标准格式
- 需要生成可视化的PPT施工图文档
- 需要将内容转化为可直接执行的PPT制作指令

## 输出产物

1. **《结构化内容文档》**：Markdown格式，包含所有页面的结构化内容
2. **《PPT施工图》**：Word文档格式，包含全局设计规范、分页施工详图、数据底表、可编程指令
