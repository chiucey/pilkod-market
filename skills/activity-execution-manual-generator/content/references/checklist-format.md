# Checklist 格式与规范

## 一、Checklist 设计原则

| 原则 | 说明 | 示例 |
|------|------|------|
| **MECE** | 不重不漏 | 任务互不重叠、全覆盖 |
| **可执行** | 明确责任人和截止时间 | "谁+何时+做什么" |
| **可验证** | 产出物清晰可检查 | 包含交付物检查项 |
| **时间线** | 有明确的时间节点 | 与里程碑对齐 |

---

## 二、Checklist 标准格式

### 2.1 表格格式

```markdown
| 序号 | 任务 | 截止时间 | 负责人 | 状态 | 交付物 |
|------|------|----------|--------|------|--------|
| 1 | [具体任务描述] | YYYY-MM-DD | [角色名] | 待确认 | [交付物名称] |
| 2 | [具体任务描述] | YYYY-MM-DD | [角色名] | 已完成 | [交付物名称] |
```

### 2.2 简洁格式

```markdown
### {{PHASE_NAME}}

- [ ] **[截止时间]** [任务描述] - [负责人]
- [ ] **[截止时间]** [任务描述] - [负责人]
```

---

## 三、阶段划分规范

### 3.1 标准阶段模板

| 阶段 | 默认时长 | 适用场景 |
|------|----------|----------|
| 筹备期 | 1-2个月 | 方案设计、资源协调 |
| 启动期 | 1-2周 | 正式启动、公告发布 |
| 执行期 | 1-N个月 | 核心活动执行 |
| 收尾期 | 1-2周 | 结果发布、复盘总结 |

### 3.2 阶段 Checklist 结构

```markdown
## {{MECHANISM_NAME}} - {{PHASE_NAME}}

### 阶段信息
- **时间范围**: {{START}} ~ {{END}}
- **阶段周期**: {{DURATION}} 天
- **核心目标**: [阶段核心目标]

### 任务清单

#### 必要任务
| 序号 | 任务 | 截止 | 负责人 | 产出 |
|------|------|------|--------|------|
| 1 | [任务] | [时间] | [角色] | [产出] |

#### 可选任务
| 序号 | 任务 | 截止 | 负责人 | 产出 |
|------|------|------|--------|------|
| 1 | [任务] | [时间] | [角色] | [产出] |

### 阶段交付物
- [ ] [交付物1]
- [ ] [交付物2]

### 阶段准入标准
- [ ] [前置条件1]
- [ ] [前置条件2]

### 阶段准出标准
- [ ] [完成条件1]
- [ ] [完成条件2]
```

## 四、任务描述规范

### 4.1 标准格式

```
[动作] + [对象] + [结果/标准]
```

| 格式 | 示例 |
|------|------|
| 动作+对象 | "确认评审标准"、"设计报名页面" |
| 包含时间 | "在XX日前完成" |
| 包含交付 | "输出XX文档" |

### 4.2 常用动词

| 类别 | 动词 |
|------|------|
| 规划 | 设计、规划、制定 |
| 确认 | 确认、审批、同意 |
| 准备 | 准备、制作、建立 |
| 通知 | 发布、通知、告知 |
| 跟进 | 跟进、监控、汇总 |
| 评审 | 评审、审查、评估 |
| 发布 | 发布、公开、公示 |
| 归档 | 归档、存档、整理 |

## 五、时间节点规范

### 5.1 时间格式

```markdown
| 格式类型 | 示例 | 说明 |
|----------|------|------|
| 绝对日期 | 2026-07-01 | 明确日期 |
| 相对日期 | T-7天 | 活动前7天 |
| 周期 | 每周五 | 定期任务 |
| 里程碑 | M1结束时 | 阶段节点 |
```

### 5.2 时间线标记

```markdown
### 关键时间节点

```
T-N    → [事件]  (活动前N天)
T      → [事件]  (活动当日)
T+N    → [事件]  (活动后N天)

示例:
T-30  → 正式启动筹备
T-7   → 最终确认截止
T      → 活动执行日
T+7   → 结果发布
T+30  → 复盘总结
```
```

## 六、交付物规范

### 6.1 交付物命名

```
[项目名]_[类型]_[版本]_[日期]
```

| 部分 | 示例 |
|------|------|
| 项目名 | InnovationContest |
| 类型 | Plan/Report/Template |
| 版本 | v1.0 |
| 日期 | 20260701 |

### 6.2 交付物检查

```markdown
### 交付物检查清单

- [ ] 文件已按命名规范命名
- [ ] 已通过审核/审批
- [ ] 已上传至指定位置
- [ ] 已在文档中更新引用
```
