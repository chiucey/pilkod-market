# 活动执行手册生成技能

通用的活动/项目执行手册生成器，基于参数化配置实现跨项目迁移。

---

## 一、架构概述

```
配置输入 → 模板选择 → 内容填充 → 评审验证 → 输出交付
```

| 层级 | 说明 | 可迁移性 |
|------|------|----------|
| **工作流程层** | 核心流程、评审标准、版本规范 | ✅ 100% |
| **模板库层** | 页面模板、Checklist格式、通知模板 | ✅ 按需选择 |
| **配置输入层** | 项目参数（名称、时间、机制等） | ✅ 参数化 |

---

## 二、核心工作流程

### 第一步：配置输入（用户提供）

```
项目名称：[活动名称]
关键时间点：[时间节点]
参与规模：[人数/范围]
机制设计：[阶段/入口，可多选]
特殊需求：[合规/特殊要求]
```

### 第二步：自动生成

| 阶段 | 自动化任务 | 用户介入 |
|------|------------|----------|
| 结构设计 | 基于配置生成文档框架 | ❌ 否 |
| 模板填充 | 根据机制选择对应模板 | ❌ 否 |
| 内容生成 | 填充各页Checklist和模板 | ❌ 否 |
| 引用校验 | 验证"见第X页"的一致性 | ❌ 否 |
| 编译验证 | 确认 X页成功, 0错误 | ❌ 否 |

### 第三步：确认与调整

```
【确认1】方案提纲是否合适？
【确认2】是否生成PPTX文件？
【确认3】文件生成后是否需要预览？
```

---

## 三、文档结构规范（通用）

### 标准结构（可配置页数）

| 部分 | 默认页码 | 内容类型 |
|------|----------|----------|
| 总纲 | 01-11 | Charter、RACI、Risk、Links |
| 机制执行 | 12-N | 阶段机制 + Checklist |
| 附录 | A1-A11 | 通知模板、报名模板、评审表 |

### 结构配置参数

```
total_pages: 26        # 总页数
general_pages: 11      # 总纲页数
mechanism_pages: 15    # 机制执行页数
appendix_pages: 11     # 附录页数
```

---

## 四、评审标准（7大重点）

| 优先级 | 检查项 | 核心问题 |
|--------|--------|----------|
| **1** | 可执行性 | Who/When/What 三要素完整？ |
| **2** | 闭环性 | 全流程交付物清晰？ |
| **3** | 模板性 | 必备模板齐全？ |
| **4** | 合规性 | 安全红线声明？ |
| **5** | 门槛性 | Go/No-Go 硬门槛明确？ |
| **6** | 治理性 | RACI + 升级链路？ |
| **7** | 引用性 | 页码引用一致？ |

### 快速评审清单

```
□ 可执行性: Who/When/What 三要素完整
□ 闭环性: 全流程交付物清晰
□ 模板性: 必备模板齐全
□ 合规性: 安全红线声明
□ 门槛性: Go/No-Go 硬门槛明确
□ 治理性: RACI + 升级链路
□ 引用性: 页码引用一致
□ 版本性: 版本号已更新
□ 编译性: X页全部成功, 0页错误
```

---

## 五、Go/No-Go 硬门槛（通用）

以下任一项仍为 **TBD**，**禁止发布**：

- [ ] 报名/参与入口
- [ ] 表单/报名页
- [ ] 沟通渠道（邮箱/工单）
- [ ] FAQ文档
- [ ] 负责人确认
- [ ] 合规审批入口
- [ ] 对接团队确认

---

## 六、版本管理规范

- **命名格式**: `v主.副` (如 v1.0 → v1.1)
- **文件夹结构**: 每个版本独立文件夹
- **变更记录**: CLI Patch List 格式

## 八、输出交付物

3. **方案提纲**: 可审阅的执行框架
