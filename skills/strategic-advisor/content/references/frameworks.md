# 战略分析师框架参考文档

## 一、BLM业务领先模型

### 起源与演进
- **IBM原始版**（1990s末-2003）：联合哈佛/斯坦福学者（Tushman、O'Reilly）开发，核心哲学"工程化社会过程"——战略必须由通用经理人亲自参与，而非委派幕僚
- **华为优化版**（2008-至今）：纳入DSTE（Develop Strategy to Execute）流程，引入"五看三定"工具集和BEM战略解码工具，从定性框架升级为数据驱动体系

### BLM完整结构

```
        ┌──────────────────────────────────────────┐
        │               领  导  力                  │
        ├──────────────────────────────────────────┤
        │  战略意图 → 市场洞察 → 创新焦点 → 业务设计  │ ← 战略制定层
        │                  ↕ 战略解码 ↕              │
        │  关键任务 → 正式组织 → 人  才 → 氛围文化    │ ← 战略执行层
        ├──────────────────────────────────────────┤
        │               价  值  观                  │
        └──────────────────────────────────────────┘
                ↑ 业绩差距 / 机会差距（驱动起点）
```

### 差距分析
| 差距类型 | 适用场景 | 成因 | 修复路径 |
|---|---|---|---|
| 业绩差距 | 现有业务扩张 | 执行力不足 | 强化执行、优化流程 |
| 机会差距 | 新项目/新业务 | 战略方向偏差或能力不足 | 战略创新+业务设计重构 |

**核心判断**：这是"能力不足"还是"方向偏差"？两者修复路径截然不同。

## 二、华为五看三定工具集

### 五看（Look at Five）

| 维度 | 核心问题 | 深度扫描内容 |
|---|---|---|
| **看趋势** | 长期演进规律？ | 技术成熟度曲线、监管方向、AI重塑路径、社会人口变化 |
| **看市场** | 市场结构与价值分布？ | TAM/SAM/SOM、成熟度、集中度（HHI/CR4）、价值池迁移方向 |
| **看客户** | 客户为什么买？ | 画像、痛点、决策路径（发起者/影响者/决策者/使用者/付款者）、TCO视角 |
| **看竞争** | 如何活下来？ | 玩家盘点、护城河、能力差距、切入缝隙、生存压力测试（对手全力反击时） |
| **看机会** | 爆发点在哪里？ | 未满足需求、技术拐点（成本↓10x/性能↑10x）、政策窗口、跨界整合 |

### 三定（Define Three）

**定战略控制点**：核心竞争力是生存基础，战略控制点才是获取超额利润的护城河。

| 控制点类型 | 强度 | 特征 |
|---|---|---|
| 价格/单一功能优势 | 弱 | 易被复制 |
| 品牌/规模效应 | 中 | 需时间积累 |
| 客户转换成本 | 强 | 迁移代价高 |
| 网络效应 | 极强 | 用户越多价值越大 |
| 关键稀缺资源（牌照/数据） | 强 | 稀缺性护城 |
| 专利/知识产权 | 强 | 法律保护 |
| 系统记录地位（SoR） | 极强 | 最后被放弃的工具 |
| 垂直整合栈 | 极强 | 软硬件/数据/算力深度打通 |
| **专有垂直数据资产** | **极强（AI时代新增）** | 极难迁移的垂直数据集群 |

**定目标**：可量化的财务/市场/能力目标，含年份和具体数字。

**定策略**：进入策略（自建/收购/合作）、增长策略、防御策略、资源配置优先级。

## 三、麦肯锡结构化方法论

### MECE原则

**定义**：相互独立（Mutually Exclusive）、完全穷尽（Collectively Exhaustive）

常用拆解维度：

| 维度 | 适用场景 |
|---|---|
| 时间 | 趋势、生命周期 |
| 空间/渠道 | 线上/线下、区域、场景 |
| 对象 | 企业/客户/竞争对手；供给侧/需求侧 |
| 性质 | 收入/成本/效率问题 |
| 流程 | 价值链（采购→生产→销售→服务） |
| 业务结构 | 核心/相邻/远期（三地平线） |

**自检三问**：有重叠吗？有遗漏吗？这种分类有商业洞察力吗？

进阶：在跨领域复杂问题中，MECE初步拆解后需识别"逻辑耦合点"（不同分支间的非线性关联）。

### 假设导向

**四步操作**：

1. 形成初始假设（项目启动48小时内必须输出）
2. 设计验证路径（验证/证伪两条证据清单）
3. 快速验证（80/20路径，先用最廉价证据触达临界判断）
4. 动态修正（假设被证伪时立即重构，绝不护盘）

**验证状态标签**：✅已验证 / ❌已证伪 / 🟡部分验证 / ⚪待验证

### 金字塔原理

**结构**：核心结论 → 支撑论点（3-5条，MECE）→ 数据/事实/案例

**三原则**：结论先行 / 以上统下（每层是下层的归纳总结）/ 归类分组（同层MECE且按重要性排序）

**SCQA叙事引出器**（源自芭芭拉·明托《金字塔原理》，非麦肯锡独创）：
- S（Situation情境）：当前稳定状态
- C（Complication冲突）：发生了什么变化/挑战
- Q（Question问题）：决策者的核心抉择
- A（Answer答案）：报告的核心结论 = 金字塔塔尖

### 七步问题解决法

| 步骤 | 名称 | 核心动作 | 关键工具 |
|---|---|---|---|
| 1 | 定义问题 | SMART一句话问题陈述 | 问题陈述模板 |
| 2 | 分解问题 | 逻辑树或假设树（选其一） | MECE检验 |
| 3 | 设定优先顺序 | 80/20 + 四维可行性测试 | 影响×可行性矩阵 |
| 4 | 制定工作计划 | 任务/人/时间/产出物表格化 | 工作计划表 |
| 5 | 关键分析 | 定性+定量，方法与数据源对应 | 价值树、情景规划 |
| 6 | 综合发现 | 事实→洞见→商业影响三部曲 | 综合卡 |
| 7 | 陈述建议 | 金字塔结构+实施路线图 | 金字塔模板 |

**逻辑树 vs 假设树**：

| | 逻辑树（Logic Tree） | 假设树（Hypothesis Tree） |
|---|---|---|
| 关注 | 是什么（诊断原因） | 为什么/如何做（选择行动） |
| 适用 | 问题归因、要素穷尽 | 增长策略、行动选择 |
| 推荐 | 利润下降归因 | 新市场进入、产品定位 |

## 四、麦肯锡经典补强框架

### 7S组织模型

| 要素 | 类型 | 诊断核心问题 |
|---|---|---|
| Strategy（战略） | 硬 | 战略是否清晰？是否被全员理解？ |
| Structure（结构） | 硬 | 架构是否支撑战略？决策链是否过长？ |
| Systems（系统） | 硬 | 关键流程是否标准化？数据流是否打通？ |
| Shared Values（价值观） | 软 | 核心价值观是否真实存在？高管是否以身作则？ |
| Style（领导风格） | 软 | 领导风格与战略转型方向是否匹配？ |
| Staff（员工） | 软 | 关键岗位是否到位？人才结构是否符合未来需求？ |
| Skills（技能） | 软 | 当前能力组合是否构成护城河？关键缺口在哪？ |

**局限性**：静态特性强，不适合急速变化环境；不告诉决策者"先动哪个S"，需叠加优先级判断；完整体检成本高，中小企业可仅做"战略-结构-技能"三项核心诊断。

### 增长三地平线

> **重要说明**：三地平线定义的是业务**生命周期阶段**，时间跨度因行业而异，无固定年数。麦肯锡原始模型强调的是业务性质分类，不是时间刻度。AI时代H3进入H2的速度大幅压缩。

| 地平线 | 定位 | 建议资源占比 | 财务特征 |
|---|---|---|---|
| H1（当前核心） | 守住并优化核心业务 | ~70% | 现金流主力，利润主贡献 |
| H2（新兴培育） | 扩展并投资新兴业务 | ~20% | 高增长但未盈利 |
| H3（远期探索） | 创建未来选项 | ~10% | 多数失败，少数颠覆 |

**警示**：H1>85% → 增长枯竭风险；H3>20% → 现金流断裂风险

### 价值树（ROIC分解）

```
ROIC
├─ 营业利润率
│    ├─ 收入（价格×销量）
│    └─ 成本（COGS+期间费用+算力成本）
└─ 资本周转率
     ├─ 营运资本周转
     └─ 固定资本周转
```

**使用规则**：至少拆到第3层，每个叶节点必须可量化、可归因；每个叶节点配套"杠杆动作"；自检建议影响哪些叶节点、ROIC提升+X个bps。

### GE-麦肯锡九宫格

```
市场吸引力 →
高  [投资] [选择] [收割]
中  [选择] [选择] [收割]
低  [选择] [收割] [剥离]
↑ 竞争地位
```

**市场吸引力评分项**（1-5分）：市场规模、增速、利润率、竞争强度、监管风险、技术变革影响

**竞争地位评分项**（1-5分）：市场份额、品牌、成本结构、渠道、技术能力、**数据资产**（AI时代新增）

### 情景规划

**三步法**：
1. 识别2个关键不确定性轴（影响大且不可控）
2. 构建2×2情景矩阵，四个象限对应四个未来世界
3. 每个情景设计应对方案（触发信号+应对动作+退出条件）

## 五、AI时代新增战略视角

### 数据飞轮战略

AI时代的核心护城河逻辑：

```
更多用户 → 更多数据 → 更好模型 → 更好产品 → 更多用户（正向飞轮）
```

**关键问题**：
- 我们的数据飞轮在哪里启动？
- 飞轮转动的临界质量是多少？
- 竞争对手进入时，飞轮转速优势能维持多久？

### AI原生商业模式特征

| 特征 | 传统模式 | AI原生模式 |
|---|---|---|
| 边际成本 | 随规模下降（硬件）或相对固定（人力） | 推理成本需单独建模（算力≠传统IT成本） |
| 护城河 | 品牌/渠道/规模为主 | 专有垂直数据+模型迭代速度 |
| 竞争节奏 | 季度/年度 | 月度/周度（模型能力更新极快） |
| 合规风险 | 相对稳定 | 动态演变（EU AI Act等法规持续更新） |

### 平台/生态战略核心指标

- **网络效应强度**：新增1个用户，现有用户价值增加X%
- **流动性密度**：单位地理/品类内的供需匹配效率
- **平台规则权力**：平台能否单方面改变规则而参与者无法退出？
- **数据垄断程度**：平台积累的数据是否已形成竞争对手无法复制的资产？

### 算力经济学基础

AI/数据类项目财务建模时必须单独考量：

| 成本类型 | 传统估算 | AI项目修正 |
|---|---|---|
| 推理成本 | 计入IT运营成本 | 按token/请求单独建模，与收入线性相关 |
| 训练成本 | 一次性资本支出 | 持续迭代，计入运营成本 |
| 合规成本 | 法务常规预算 | 高风险AI系统可占项目预算10-25% |
| 供应商风险 | 采购合同管理 | 单一闭源API依赖需建立多供应商/开源备案 |

### 综合三部曲卡

```
【事实】（含数字+时间+来源）
...
【洞见】（这意味着什么？为什么？）

```

```

```

### 麦肯锡式表达升级

| 普通表达 | 升级表达 |
|---|---|
| "我觉得问题在于…" | "初始假设：核心问题是X，待Y数据验证" |
| "需要做很多事" | "优先聚焦3个关键议题：A、B、C；明确不做D、E" |
| "数据显示销售下降了" | "销售下降15%，主因是X（贡献70%跌幅）；这意味着Y" |
| "建议加强管理" | "建议Q3前由Y负责完成X举措，预期提升Z指标N%" |
| "这个问题很复杂" | "将问题分解为三个维度：A/B/C，按80/20优先攻克A" |
| "看起来还行" | "基线情景下达成概率60%；下行情景需启动Plan B" |
