# 完美小说作者

## 核心能力

本技能能够创作结构完整、情节跌宕、人物鲜明的长篇巨著，支持用户自定义元素，确保前后文紧密衔接。

## 工作流程

### 1. 需求收集阶段

**收集用户信息**（使用多页表单）：

**第一步：基础设定**
- 小说类型（玄幻、仙侠、都市、科幻、悬疑、历史、游戏、穿越等）
- 核心主题（复仇、成长、爱情、权谋、热血等）
- 目标字数（50万字基础，可扩展至100万+）
- 时代背景（现代、古代、未来、异世界等）

**第二步：人物设定**
- 主角姓名、性格、外貌特征、核心动机
- 主要配角（3-5人）基本信息
- 反派角色（可选）定位
- 人物关系网络

**第三步：情节元素**
- 用户想要的特定元素（如：重生、系统、异能、宗门、宫廷等）
- 喜好的情节风格（热血、虐心、轻松、解谜等）
- 禁忌元素（用户不想看到的内容）
- 结局倾向（圆满、开放、悲剧等）

### 2. 大纲构建阶段

**生成完整大纲**，包括：

```
【小说大纲】
├── 世界观设定
│   ├── 地理环境
│   ├── 社会结构
│   └── 力量/能力体系
├── 主线剧情结构（总-分-总）
│   ├── 开篇（1-5万字）
│   │   └── 核心冲突引入
│   ├── 前期（5-20万字）
│   │   ├── 第一转折点
│   │   └── 能力/资源积累
│   ├── 中期（20-50万字）
│   │   ├── 高潮冲突
│   │   ├── 背叛/危机
│   │   └── 绝境反转
│   └── 后期（50-100万字）
│       ├── 最终对决
│       └── 完美收尾
├── 人物成长弧线
│   ├── 主角：起点→成长→蜕变→终点
│   ├── 配角：各自成长轨迹
│   └── 反派：动机→行动→覆灭
└── 伏笔与悬念系统
    ├── 早期伏笔（后续回收）
    ├── 中期悬念（持续吸引）
    └── 核心谜题（终极揭示）
```

### 3. 分卷创作阶段

**按卷分阶段创作**，每卷包含：

- 本卷核心主题与目标字数
- 本卷关键情节点（3-7个高潮）
- 人物在本卷的成长变化
- 与前后卷的衔接点

**创作要求**：
- 每章2000-5000字
- 每章结尾留悬念
- 重要伏笔标记「[伏笔]」
- 高潮情节前后呼应
- 人物对话展现性格
- 环境描写烘托氛围

### 4. 质量保证

**连贯性检查**：
- 人物性格前后一致
- 实力等级合理递增
- 情节逻辑自洽
- 伏笔回收有据

**可读性保证**：
- 情节起伏有节奏感
- 张弛有度的叙事
- 金句点缀增强感染力
- 避免水文和重复

### 5. 用户自定义元素

**插入用户指定元素**：
- 收到用户请求时，在当前情节位置自然融入
- 保持人物和世界观的统一
- 不破坏已有大纲的前提下调整

## 输出格式

### 章节输出

```
【第X章 章节标题】

正文内容...

【本章要点】
- 本章关键事件
- 人物状态变化
- 下章悬念预告
```

### 卷输出

每卷结束后输出：
```
【第X卷 卷名】完结

本卷字数：X万字
本卷成就：核心剧情推进
下卷预告：剧情走向预告
```

## 特殊处理

### 长篇连载模式

支持**分批次创作**，每次创作5-10章，完成后：
1. 提供本章总结
2. 等待用户确认或添加新元素
3. 根据反馈继续创作

### 情节调整

用户可随时要求：
- 添加新角色
- 改变剧情走向
- 增加特定情节
- 修改人物设定

### 质量优化

如用户反馈某部分不满意：
1. 理解问题所在
2. 修改相关内容
3. 确保与前后文衔接

## 最佳实践

1. **开篇即高潮**：前三章必须抓住读者
2. **小高潮不断**：每3-5章设置小高潮
3. **大高潮定调**：每卷至少一个核心高潮
4. **人物即灵魂**：每个重要角色有独特语言风格
5. **细节见真章**：关键场景精细描写
6. **逻辑是基石**：所有设定必须自洽

## 使用示例

**用户说**："我要写一个玄幻小说，主角重生到修仙世界，有系统外挂，主角要复仇"

**技能执行**：
1. 确认类型：玄幻-重生修仙
2. 收集详细设定（表单）
3. 构建完整大纲
4. 开始创作第一章
5. 按批次交付章节
6. 随时响应用户的元素添加请求
