# OpenClaw：第一性原理深度解析

## 核心原点

**OpenClaw 不是一个普通聊天机器人，而是一个"自托管的个人 AI 助手网关"。**

先把"一个真正能做事的 AI 助手"拆到底层。它至少要有五个部件：

| 部件 | 说明 |
|------|------|
| **入口** | 你能从常用聊天工具随时找到它 |
| **控制面** | 有一个持续运行的中枢，管理会话、路由、连接 |
| **执行力** | 不只是生成文字，还能读文件、跑命令、浏览网页、发消息 |
| **记忆与状态** | 能维持 session、上下文和任务进度 |
| **权限边界** | 知道谁能触发它、它能动哪些东西、什么需要审批 |

**OpenClaw 本质上就是把这五件事装成一个"本地优先的控制平面"。**

### 一句话定义

> **OpenClaw = 把 AI 变成"可长期在线、可跨设备、可调用工具" 的个人操作中枢**

---

## 一、What - OpenClaw 是什么

OpenClaw 是一个**自托管网关**。在自己的机器或服务器上运行它，它就成了常用聊天渠道和 AI 模型之间的桥。

官方同时把它描述成：

- "personal AI assistant you run on your own devices"
- "self-hosted gateway that connects your favorite chat apps ... to AI coding agents"

### 支持能力

- 多种聊天入口
- 会话隔离
- 多代理路由
- 本地或第三方模型提供商

### 核心架构

Gateway 是会话、路由和频道连接的单一事实来源；**工具、技能、插件三层**共同决定"它能做什么、何时做、怎么做"。

---

## 二、Why - 为什么要用 OpenClaw

### 第一性原因只有四个

#### 第一，让 AI 从"网页对话"变成"随时可叫到的助手"

普通聊天式 AI 往往困在浏览器标签页里。

OpenClaw 的价值，是把 AI 带到你已经在用的聊天入口里：Telegram、WhatsApp、Slack、Discord、Signal、iMessage 等。

#### 第二，让 AI 从"会说"变成"能做"

官方文档写得很直接：**代理做的所有超出文本生成的事，都是通过工具完成的**。

OpenClaw 内置工具可以：
- 读写文件
- 运行命令
- 控制浏览器
- 搜索网页
- 发消息
- 做定时任务
- 生成图片视频

#### 第三，让 AI 从"平台资产"变成"你的资产"

OpenClaw 的核心价值不是某一个模型，而是**控制权**。

- 工作区和会话历史保留在本地
- 按自己的需要选用 Anthropic、OpenAI、OpenRouter、本地模型等
- 避免被单一 SaaS 绑死

#### 第四，让 AI 从"一次性回答"变成"持续运行的系统"

OpenClaw 支持：
- 常驻 Gateway
- cron
- heartbeat
- 子代理
- 多代理路由
- 跨设备协调

**高频用例**：个人简报、研究与起草、提醒与跟进、浏览器自动化、跨设备协同。

### 核心价值总结

> 它解决的不是"再来一个 AI 聊天框"，而是：**如何把 AI 安装进你的日常通讯入口、工作流和设备边界里，让它长期在线并真正执行任务。**

---

## 三、Who - 谁适合用 OpenClaw

官方文档点名的对象是：**developers and power users**。

更具体说，下面几类人最适合：

- 需要跨设备随时调度 AI 的人
- 希望数据和工作区尽量保留在自己控制范围内的人
- 想把 AI 接入 Telegram、WhatsApp、Slack 这类现有沟通入口的人
- 需要浏览器自动化、文件操作、命令执行、定时任务的人
- 想为不同任务配不同代理、不同模型、不同技能的人

### 不太适合的情况

- 只是偶尔聊天、没有自动化需求
- 不想管安装和权限

> **安全边界**：官方明确说它默认是单一信任边界下的个人助手模型，不适合把共享 Gateway 暴露给互不信任的人当成多租户系统。

---

## 四、When - 什么时候最该用

最该用的场景：

### 1）你要一个"始终在线"的个人助手

- 早上自动汇总邮箱、日程、新闻
- 定时提醒和跟进

### 2）你想通过聊天入口驱动真实操作

- 开网页、填表单、收集资料
- 管理文件、发消息

### 3）你想把不同任务交给不同代理

- OpenClaw 支持多代理路由和隔离会话
- 一个代理负责快问快答，另一个负责重任务或编码任务

### 4）你不想把全部控制权交给某个闭源平台

- 本地保存
- 模型切换
- 技能自定义
- 插件扩展
- 长期可迁移性

## 六、How - 如何使用 OpenClaw

### 核心三件事

用 OpenClaw，核心不是"怎么安装"，而是先想清楚三件事：

1. **它跑在哪里**
2. **它代表你能做什么**
3. **哪些动作必须被限制或审批**

> 如果这三件事没想清楚，装上去也容易失控。

### 最合理的上手路径（七步）

#### 第一步：先选宿主机

官方建议：

| 设备类型 | 适合场景 |
|----------|----------|
| **专用主机**（VPS、Mac mini、树莓派类设备） | 适合长期在线 |
| **笔记本和台式机** | 适合测试，但会受睡眠、重启和更新影响 |

#### 第二步：先跑通最小安装

官方 Getting Started 给出的最短路径：

```bash
# 准备 Node.js，推荐 Node 24，22.14+ 也支持
# 安装 OpenClaw
# 执行 onboarding
openclaw onboard --install-daemon
# 检查 Gateway 和控制台
openclaw gateway status
openclaw dashboard
```

#### 第三步：先选模型认证方式

OpenClaw 不是绑定某一个模型。支持：Anthropic、OpenAI、OpenRouter、Google、xAI、本地模型等。

**最简单的路线**：

- 想省事：用已经有的 hosted provider
- 想更可控：用 API key
- 想本地化：接本地模型（但小模型和强量化模型更容易有注入风险）

#### 第四步：先接一个最容易成功的聊天渠道

**Telegram 是最快的入口**，因为只需要 bot token。

先让"消息进得来、结果回得去"，再去折腾更复杂的渠道。

#### 第五步：从低风险任务开始

不要一上来就让 AI 有完整 shell、浏览器、生产账号权限。

**先做这几类**：
- 收件箱 / 日程 / 新闻摘要
- 研究与草稿
- 提醒与跟进
- 低风险网页收集和表单试跑
- 跨设备发起、服务器执行、聊天返回结果

#### 第六步：把"权限"当成产品功能来配置

这是 OpenClaw 和普通聊天工具最大的区别。

官方安全文档建议：
- 定期运行 `openclaw security audit`
- 对 DM、群组、浏览器、exec、文件系统等做最小权限配置
- Exec Approvals：只有在策略、allowlist 和可选人工审批都满足时，命令才会执行

#### 第七步：把复杂能力拆成三层理解

理解 OpenClaw 的关键：

| 层级 | 说明 |
|------|------|
| **Tools** | 真正的动作能力，如 exec、browser、web_search、message |
| **Skills** | 写在 SKILL.md 里的使用说明，告诉代理什么时候、如何使用工具 |
| **Plugins** | 把渠道、模型、工具、技能等打包扩展起来 |

**高手用法**：只装必要工具，按任务加技能，用最小能力完成最确定的目标。

## 七、How much - 投入多少才能用好

### 最小投入

官方 Getting Started 说基本跑通需要：

- Node 24 推荐
- 一个模型提供商认证或 API key
- 大约 5 分钟跑完基本 onboarding

### 基础服务器配置

| 配置级别 | 最低要求 |
|----------|----------|
| **绝对最低** | 1 vCPU、1GB RAM、约 500MB 磁盘 |
| **更建议** | 1-2 vCPU、2GB RAM 以上 |

> 如果还要跑节点工具、浏览器自动化、媒体处理，资源需求会继续上升。

### 真正的成本

不是安装成本，而是三类成本：

| 成本类型 | 说明 |
|----------|------|
| **运维成本** | 保证 Gateway 常驻、日志可看、更新可控 |
| **权限成本** | 设计 allowlist、审批和访问边界 |
| **思维成本** | 把任务拆成合适的代理、技能和执行流程 |

## 八、常见三大误区

| 误区 | 正确做法 |
|------|----------|
| 把它当成另一个 ChatGPT | 价值不在"更会聊天"，而在"更接近你的真实入口和真实执行" |
| 一上来给太多权限 | 先小后大，特别是浏览器、exec、群聊和共享工作区 |
| 一开始就做太复杂的事 | 先从网站原型、文件整理、Gmail 摘要、轻量自动化入手 |

## 极简结论

### 为什么用 OpenClaw

因为它把 AI 从"网页里的聊天框"推进成**你自己掌控的、可长期在线、可跨渠道、可执行任务的个人助手系统**。

### 如何用 OpenClaw

**记住六步就够**：

1. 先选一个长期在线的宿主机
2. 先跑通最小安装和 Gateway
3. 先接一个模型提供商
4. 先接一个简单聊天渠道（比如 Telegram）
5. 先做低风险摘要和草稿类任务
6. 再逐步开放 browser、exec、cron、skills 和 plugins，并做好审批与审计
