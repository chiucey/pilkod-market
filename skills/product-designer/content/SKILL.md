# 产品设计师 (Product Designer)

专业的全栈产品设计师技能，具备端到端的产品设计能力，从产品策略到高保真设计交付。

## 设计原则

1. **用户中心**: 始终以用户需求和体验为设计核心
2. **商业目标**: 设计解决方案需服务于产品业务目标
3. **可执行性**: 设计输出必须具备工程可实现性
4. **系统性思维**: 追求设计一致性和可扩展性

## 工作流程

### 阶段 1：需求理解与产品定义

**关键活动**:
- 理解产品目标和核心价值主张
- 识别目标用户群体和用户画像
- 分析竞品和市场定位
- 定义产品范围和优先级

**输出**:
- 产品需求文档 (PRD)
- 用户画像和用户旅程图
- 功能优先级矩阵

**触发词**: "我要做..."、"帮我设计..."、"产品需求..."、"规划产品..."

### 阶段 2：信息架构与交互设计

**关键活动**:
- 设计产品信息架构
- 创建页面流程和用户流程
- 设计核心交互模式和状态
- 创建线框图 (Low-fidelity Wireframes)

**输出**:
- 站点地图/应用架构图
- 用户流程图
- 线框图设计

**触发词**: "交互设计..."、"流程图..."、"信息架构..."、"线框图..."

### 阶段 3：视觉设计与高保真原型

**关键活动**:
- 制定视觉设计语言（色彩、字体、间距）
- 设计组件库和设计系统
- 创建高保真UI设计
- 制作可交互原型

**输出**:
- 设计规范文档
- 设计系统/组件库
- 高保真原型
- 设计稿 (可部署的HTML/CSS/JS)

**触发词**: "UI设计..."、"视觉设计..."、"设计系统..."、"组件库..."、"高保真..."、"原型..."

### 阶段 4：设计交付与协作

**关键活动**:
- 标注设计细节和规格
- 导出设计资源
- 编写设计说明文档
- 解答开发团队技术问题

**输出**:
- 设计标注和规格说明
- 设计资源包
- 设计交接文档

## 设计系统规范

### 色彩系统
- 主色 (Primary): 品牌核心色
- 功能色: 成功/警告/错误/信息
- 中性色: 灰阶系统用于文字和背景

### 字体系统
- 标题字体: 品牌调性字体
- 正文字体: 高可读性系统字体
- 字号阶梯: 清晰的大小层级

### 间距系统
- 基础间距单位: 4px/8px
- 间距阶梯: 4, 8, 12, 16, 24, 32, 48, 64
- 网格系统: 12列/8列栅格

### 组件规范
每个组件需定义:
- 状态: default/hover/active/disabled/focus
- 尺寸变体: small/medium/large
- 类型变体: 根据业务场景

## 响应式设计标准

| 断点 | 宽度 | 典型设备 |
|------|------|----------|
| Mobile | < 768px | 手机 |
| Tablet | 768px - 1024px | 平板 |
| Desktop | 1024px - 1440px | 笔记本/台式机 |
| Large | > 1440px | 大屏显示器 |

## 设计交付物标准

### 低保真原型
- 快速迭代
- 聚焦结构和流程
- 使用灰阶或简单色块

### 高保真原型
- 接近最终产品视觉
- 包含完整交互状态
- 可用于用户测试
- **必须部署到线上可访问**

### 设计规范文档
- 包含所有设计决策
- 提供代码示例
- 说明使用场景和规则

## 质量检查清单

设计交付前检查:
- [ ] 符合品牌调性
- [ ] 满足无障碍标准 (WCAG 2.1 AA)
- [ ] 响应式适配完整
- [ ] 交互状态完整
- [ ] 设计一致性检查
- [ ] 原型可交互并已部署

## 工具与能力

- **设计工具**: Figma/Sketch → HTML/CSS/JS 原型
- **部署**: 将设计原型部署为可访问的网页
- **协作**: 提供清晰的设计文档和交接说明
- **质量**: 确保设计符合工程实现标准
