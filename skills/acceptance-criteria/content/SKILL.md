# Acceptance Criteria - 验收标准清单

根据需求文档，输出以业务场景触发的验收清单表格。

---

## 核心定位

```
需求文档（输入）
       ↓
业务场景梳理 → 操作步骤 → 验收标准
       ↓
研发自测/测试验收清单（输出）
```

---

## 触发词

```
"输出验收标准"
"帮我整理验收清单"
"做一个验收测试表"
"验收清单怎么写"
"给测试的验收标准"
```

---

## 输入要求

### 最小输入

```
功能名称：[名称]
功能描述：[简要描述]
核心业务场景：[场景列表]
```

### 完整输入（推荐）

```
基于以下需求文档输出验收标准：

需求名称：[名称]

核心功能：
1. [功能点A]
2. [功能点B]

业务场景：
- 场景1：[描述]
- 场景2：[描述]

优先级：P0/P1/P2
```

## 填写说明

### 功能点
- 对应需求文档中的具体功能名称
- 一个功能点可对应多个验收场景

### 业务场景
- 用户实际使用时的业务场景
- 从用户视角描述，不是系统视角
- 描述"做什么"而不是"怎么做"

### 系统操作步骤
- 具体的操作路径
- 按步骤编号
- 每个步骤简洁明了

### 预期效果
- 操作后系统应该呈现的结果
- 描述用户能看到/感受到的效果
- 包含正常情况和边界情况

### 验收结论
- ☐ 通过：功能符合预期
- ☐ 不通过：功能与预期不符

---

## 场景化验收原则

### 1. 场景覆盖完整
- 主路径：正常使用的核心流程
- 支路径：分支操作的流程
- 异常路径：出错/边界情况的处理

### 2. 操作步骤具体
- 步骤可执行
- 结果可验证
- 不产生歧义

### 3. 预期效果可衡量
- 有明确的判断标准
- 可以客观判断是否达成
- 避免主观描述

### 输入：
```

业务场景：
```

## 执行原则

1. **场景化** - 从用户业务场景出发
2. **可执行** - 操作步骤具体可执行
3. **可验证** - 预期效果有明确判断标准
4. **完整性** - 覆盖主路径、支路径、异常路径
