# 管理决策框架 v2.0

将每一次管理决策从"感性经验"转化为"理性算法"，同时保留对"非标"沟通与交涉的灵活应对能力。

---

## 模块一：决策背景层 (Contextual Inputs)

**这是 Skill 运行的起点，决定了 AI 站在什么视角看问题。**

### 1.1 决策者画像

请明确您的角色定位，我将据此调整分析视角：

| 角色 | 视角权重 | 关注重点 |
|------|----------|----------|
| 董事长/CEO | 战略+风险 | 长期价值、组织健康、股东回报 |
| 业务负责人 | 业绩+增长 | 收入、市场份额、执行效率 |
| HRD/人事 | 人效+稳定 | 人才密度、团队健康、文化建设 |
| 部门经理 | 执行+团队 | 目标达成、团队协作、资源协调 |
| 专业职能 | 规范+效率 | 专业标准、合规性、流程优化 |

### 1.2 组织文化环境

**请评估您所在组织的决策风格：**

**控制维度**：
- 集权式：决策集中于高层，执行快速但创新受限
- 民主式：广泛征询意见，执行度高但决策慢
- 授权式：责任下放，鼓励自主决策

**导向维度**：
- 结果导向：只看结果，不拘泥方式
- 过程导向：关注方法和合规性
- 平衡导向：在结果与过程间寻求平衡

### 1.3 核心目标判定

| 类型 | 判定标准 | 决策逻辑 |
|------|----------|----------|
| 生存型（危机） | 现金流紧张、市场份额急剧下滑、核心人才流失 | 先止血，后优化；速度优先于完美 |
| 发展型（战略） | 新市场拓展、组织变革、重大投资 | 系统规划，平衡短期与长期 |
| 优化型（效率） | 日常运营、流程改进、成本控制 | 渐进改良，数据驱动 |

## 模块二：决策分类逻辑 (Classification Logic)

**这是 Skill 的"分类器"，自动判断问题性质并匹配处理模式。**

### 2.1 重要性分级

**阈值判定矩阵：**

| 维度 | 业务级 | 战术级 | 战略级 |
|------|--------|--------|--------|
| 财务影响 | <50万 | 50-500万 | >500万 |
| 受影响人数 | 1-3人 | 4-20人 | >20人 |
| 时间跨度 | <1个月 | 1-6个月 | >6个月 |
| 组织影响 | 单岗位 | 单部门 | 多部门/全公司 |

### 2.2 标准度判定

**请判断当前问题属于哪种类型：**

| 类型 | 特征 | 处理模式 |
|------|------|----------|
| **程序化问题** | 有明确SOP/制度/先例可循 | 执行标准流程，快速决策 |
| **半程序化问题** | 有参考但需调整 | 在框架内做适应性修改 |
| **非程序化问题** | 无先例、涉及多方博弈、结果不确定 | 触发"博弈分析"模式，多方案评估 |

### 2.3 职能归属识别

**自动识别问题涉及的核心职能域：**

- **人力**：招聘、晋升、薪酬、绩效、裁员
- **财务**：预算、投资、成本、融资
- **运营**：流程、供应链、质量、安全
- **市场**：定价、渠道、品牌、客户
- **战略**：组织架构、业务组合、合作并购
- **跨部门**：涉及多个职能域的综合性问题

### 3.1 硬数据指标库

| 类别 | 关键指标 | 参考阈值 |
|------|----------|----------|

| 运营 | 项目交付率、缺陷率、响应时间、客户满意度 | 内部历史 |
| 市场 | 市场份额、获客成本、客户留存率 | 行业对标 |

### 3.2 软信息（非标处理关键）

**利益相关者地图：**

请识别并分析以下关键干系人：

| 干系人 | 角色 | 关注点 | 过往立场 | 利益诉求 | 影响力度 |
|--------|------|--------|----------|----------|----------|
| 【如：董事长】 | | | | | |
| 【如：业务总监】 | | | | | |
| 【如：HR负责人】 | | | | | |

**历史案例库检索：**
- 公司过去处理类似情况的成败记录
- 关键决策人对此类问题的历史态度
- 沉没成本：已投入的资源是否会绑架新决策

**政策红线清单：**
- 国家法律法规约束（如劳动法、税法、行业法规）
- 行业准入标准
- 公司内部红线（如反腐、诚信、合规要求）

## 模块四：决策方法论工具箱 (Methodology Toolkit)

**这是 Skill 的"处理器"，针对不同类型调用不同分析模型。**

### 4.1 理性分析模型库

**适用于程序化和半程序化问题：**

| 模型 | 适用场景 | 输入要素 | 输出 |
|------|----------|----------|------|
| **逻辑树** | 问题拆解、根因分析 | 问题现象 | 关键因子列表 |
| **SWOT分析** | 战略选择、方案评估 | 内外部因素 | 战略选项 |
| **决策树** | 多方案概率评估 | 方案、概率、收益 | 期望值计算 |
| **ROI计算** | 投资决策 | 投入成本、预期收益、时间 | 投资回报率 |
| **加权矩阵** | 多因素综合评估 | 因素、权重、评分 | 综合得分排序 |

### 4.2 博弈分析模型库

**适用于非程序化问题（沟通、交涉、谈判场景）：**

**双赢分析（BNA - Best Negotiation Alternative）：**

```
己方立场：【】
己方底线：【】
己方BATNA（最佳替代方案）：【】

对方立场：【】
对方底线：【】
对方BATNA：【】

潜在共赢领域：【】
价值创造机会：【】
```

**影响策略（根据对方性格类型适配）：**

| 性格类型 | 特征 | 沟通策略 | 话术要点 |
|----------|------|----------|----------|
| D型（支配型） | 结果导向、直接果断 | 简洁有力、强调收益 | "3个要点达成X结果" |
| I型（影响型） | 社交导向、热情乐观 | 情感共鸣、愿景描绘 | "这个愿景需要你" |
| S型（稳健型） | 稳定导向、耐心倾听 | 温和渐进、安全保障 | "我们有backup计划" |
| C型（谨慎型） | 精确导向、追求完美 | 数据支撑、风险提示 | "数据表明成功率X%" |

**联盟策略（跨部门交涉）：**

1. **识别潜在盟友**：谁与你的目标一致？谁会从中受益？
2. **构建攻守同盟**：找到"统一战线"，分担风险
3. **预判阻力来源**：谁会反对？他们的核心关切是什么？
4. **设计交换条件**：用什么换取关键支持？

### 5.3 执行追踪与复盘

**决策后复盘节点设定：**

| 节点 | 时间 | 检视内容 |
|------|------|----------|
| 速检 | 决策后48小时 | 执行是否启动？关键障碍？ |
| 周检 | 第1周 | 进展是否符合预期？是否需要调整？ |
| 月检 | 第1个月末 | 阶段性成果？偏差原因？ |
| 终检 | 完成后 | 目标达成度？经验沉淀？ |

**复盘四问：**
1. 预期目标达成了吗？（差距分析）
2. 与预期不符的原因是什么？（根因分析）
3. 下次如何改进？（流程优化）
4. 有哪些经验可以沉淀到组织知识库？（知识管理）

## 使用示例

**场景**：跨部门资源争夺的博弈决策

```
【第一步：背景输入】
决策者：业务负责人
组织风格：民主式决策
目标类型：优化型（效率）

【第二步：分类判定】
问题性质：非程序化（跨部门利益冲突）
重要程度：战术级（影响3个部门）
职能归属：跨部门

【第三步：信息收集】
利益相关者：
- 产品总监：关注产品按时交付
- 技术VP：关注技术债务和团队稳定
- 销售VP：关注客户满意度和收入

【第四步：博弈分析】
我的方案：方案A（产品优先）
对方可能的反击：技术债堆积，团队疲惫
联盟策略：联合销售VP，用客户价值说服技术

【第五步：行动脚本】
开场：感谢各方贡献
核心：用一个真实客户案例说明优先级
让步空间：承诺给技术团队2周"还债时间"
底线：不能在Q3前砍掉产品功能

【第六步：决策输出】
推荐：方案A（附带条件）
风险：技术团队士气可能受影响
缓解：事后奖励和认可
```
