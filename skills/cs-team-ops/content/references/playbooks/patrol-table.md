# Playbook：巡场管理表格

## 适用
现场巡检、抽检、问题发现与闭环。目标是**发现问题和闭环**，不是"检查谁"。

## 必填输入
- 是否有现成巡场记录（避免另起一套）
- 各模块可抽检的样本来源（标注结果库、配置变更记录、话术/知识库、投诉单）
- 是否有质量基线值（无基线则用相对口径：与本人上期对比、与模块均值对比）

---

## 核心设计原则

1. **必须抽样本，不打印象分。** 每次巡场要写清"抽了多少条、合格多少条"。只有印象分表的巡场会被全员认定为形式主义，一次不闭环的巡场比不巡场更伤信任。
2. **标准统一，抽样侧重差异化。** 所有人合格线相同；差别只在"重点看谁的哪几个维度"。差异化体现在关注点和整改要求深度上，不在合格线宽严。
3. **闭环优先于发现。** 表的设计要让人愿意用：字段少、判定快、整改要求可直接粘贴、闭环状态一眼可见。
4. **只对事不对人。** 表里出现"态度""配合度""责任心"这类主观描述栏，是这张表失效的开始。

## 一、巡场频次与样本量

| 层级 | 频次 | 抽检内容 | 样本量 |
|---|---|---|---|
| 日常抽检 | 每工作日 ≥1 人，轮流覆盖 | 标注/配置/话术质量 | 每次 ≥20 条标注；配置变更全量核对当周全部变更；话术/知识 ≥10 条 |
| 周度专项 | 每周 1 个维度深查 | 流程合规、变更留痕、文档沉淀 | 全量核对当周记录 |
| 月度全维度 | 每月全员 1 次 | 六个维度全覆盖 | 各模块各 ≥20 条 |
| 专项触发 | 投诉、故障、返工率异常 | 定向复盘 | 全部相关样本 |

样本量若与团队实际产能不匹配，用户应调整；量太大没人执行，等于没有。

## 二、巡场维度定义

| 维度 | 判定内容 | 合格线 | 数据来源 |
|---|---|---|---|
| 质量 | 标注准确率、意图识别正确性、配置项正确 | 合格率 ≥98% | 标注结果抽检 |
| 量 | 任务达成率 | 按模块约定口径 | 任务台账 |
| 合规 | 变更是否走四步、权限是否越界、数据是否脱敏 | 零容忍项 100% | 变更记录、系统日志 |
| 协作 | 交接是否完整、跨岗位响应、阻塞是否上报 | 无因个人原因导致的阻塞 | 交接表、群记录 |
| 改善 | 提案是否落地、效果是否验证 | 有落地即计 | 提案台账 |
| 沉淀 | 规范/SOP/复盘文档是否更新 | 每次变更同步更新 | 文档库 |

**零容忍项**（单次即判不合格，直接进 L2/L3）：数据未脱敏外发、私自变更生产配置未留痕、越权操作。

## 三、角色差异化关注矩阵（本团队专用）

差异化只体现在"重点抽哪个维度、整改要求多深、支持给多少"，合格线不变。

| 维度 | W | Z | S | T | Q | K |
|---|---|---|---|---|---|---|
| 质量·标注/配置准确率 | 中 | 高 | **最高** | 中 | 高 | 高 |
| 量·任务达成 | 低 | 中 | **低** | 中 | 高 | **最高（双阈值）** |
| 合规·变更与权限 | **最高** | 中 | 高 | **最高** | 中 | 中 |
| 协作与交接 | 中 | 中 | 中 | **硬门槛** | 中 | 中 |
| 改善提案落地 | 中 | 高 | 低 | **最高** | 中 | 低 |
| 文档与知识沉淀 | **最高** | 中 | 中 | 高 | 中 | 中 |
| 响应 SLA | 中 | 中 | 中 | 中 | 中 | 中 |

设定理由（生成方案时要一并讲清，否则会被读成"针对谁"）：
- W：事项杂且掌权限，同时被抽调支援 → 变更合规与文档沉淀是最大风险点，支援期交付单列。
- Z：培养对象 → 改善提案与独立承担能力是观察重点。
- S：细致度弱、专业低 → 质量与规范遵循权重最高，量权重最低（避免为凑量牺牲准确率）。
- T：专业中高、协作弱 → 改善是唯一能让他主动投入的维度；协作设硬门槛而非低权重。
- Q：年轻、执行强 → 量与成长曲线并重。
- K：在意工作量、专业低 → 量×质双阈值：达标量 + 返工率封顶，两者同时满足才算达标。
- S 的权重调整与 T 的硬门槛设置，必须在**公示时用"能力发展阶段"解释**，绝不能出现"因为某人能力低/某人协作差"这类表述。

## 四、表格设计

### 表 A：巡场记录主表（每次一行）

| 字段 | 填写要求 |
|---|---|
| 巡场日期 / 时段 | 精确到日 |
| 巡场人 | 执行巡检的人 |
| 被巡人 | 具体到人 |
| 所属模块 | 呼入/在线文本/提示词/外呼/综合运营/支援 |
| 抽检维度 | 单选或多选，对应维度定义 |
| 样本量 / 合格数 | 数字，可复算 |
| 合格率 | 自动计算 |
| 问题类型 | 漏标/误标/配置错/未留痕/交接缺失/响应超时…（做成下拉枚举，不自由填写） |
| 问题描述与证据 | 引用具体条目/单据号/记录位置，不写主观评价 |
| 判定 | 合格 / 提醒（L1）/ 整改（L2 及以上） |
| 整改要求 | 具体动作 + 期限，可直接粘贴给对方 |
| 整改期限 | 具体日期 |
| 复核人 / 复核日期 | 复核不与巡场同人 |
| 复核结果 | 通过 / 未通过（未通过自动升级） |
| 闭环状态 | 未开始 / 进行中 / 已闭环 |

### 表 B：人员巡场台账（按人滚动，用于看趋势）

| 字段 | 说明 |
|---|---|
| 人员 / 模块 | — |
| 累计巡场次数 | 体现抽查是否覆盖均衡 |
| 平均合格率 | 分维度列，不要只给一个总分 |
| 趋势 | 与上期对比的方向 |
| 重复问题 TOP3 | 同一问题反复出现 → 指向根因是流程/标准缺失，不是个人态度 |
| 整改闭环率 | 低于阈值说明管理动作本身失效，需改机制 |
| 已采取支持动作 | 带教、模板、示例、结对——只写实际给过的 |
| 备注 | 留痕（支援期、休假等状态说明） |

### 表 C：工作量透明台账（Q / K 语音外呼模块专用）

| 字段 | 说明 |
|---|---|
| 周期 | 月 |
| 人员 | Q / K |
| 承接会话/标注条数 | 统一口径，不含返工 |
| 返工条数 | 单独列，不计入"新增工作量" |
| 疑难/仲裁条数 | 单独列 |
| 统计口径说明 | 口径一旦确定不随意改，改动需全员知会并记录 |

这张表的存在理由：K 明确在意工作量，Q 与 K 同模块。口径不透明时，工作量争议会在月末结算时爆发，且无法自证。**提前把口径书面化，比事后解释有效。**

## 输出格式建议
- 表格用 Markdown 表格给出，同时给出可导入 Excel 的列名清单（一行一个列名，不带格式符号）
- 判定标准与闭环时限写成简明规则，不写成长文
- 差异化矩阵必须附设定理由

## 常见坑
- **只查不闭环**：表填得很漂亮，整改期限过了一周没人复核。这是巡场机制最常见的死法，所以"复核人/复核日期"必须是必填。
- **复核人 = 巡场人**：自己查自己复核，闭环就形同虚设。
- **差异化被读成针对个人**：公示时必须同时公布"合格线全员一致"这句话，并说明关注度差异来自岗位阶段而非个人评价。
- **没有抽检样本量字段**：一旦没有这个字段，表就会退化成打分表。
- **问题类型自由填写**：导致无法做趋势分析，重复问题也就看不出来。
