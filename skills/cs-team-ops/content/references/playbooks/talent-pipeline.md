# Playbook：人才培养梯队与名额候选人建议

## 适用
人才培养梯队、继任者地图、名额候选人推荐、谁值得培养、谁在备选池、带教与培养计划。

## 不适用
名额的规则制定与公示（名额由部门与公司政策决定、部门负责人拍定，用户无权制定）。这一节只管**筛选和推荐**。

## 必填输入
- 现行政策对名额的具体形式（转派遣 / 职级升等 / 二选一）——`[需确认]`，未确定时按"两种都可能"准备
- 部门负责人筛选时关注什么、有无既定维度或历史惯例
- 每个人近 3–6 个月的绩效系数与趋势
- 哪些人已知晓名额的存在，团队整体期待程度

---

## 一、先认清这个团队的特殊前提

- **名额近 2 年未发放**，且取决于部门与公司政策，不由用户决定。
- **用户的角色是筛选者与推荐者**，不是规则制定者；拍板人是部门负责人。
- 派遣（W）不在竞争池内，但会在"凭什么骨干没保障"这个问题上被反复问到。
- 团队规模只有 6 人，**梯队不是一个独立的荣誉体系，而是日常管理的副产品**。硬造梯队表会被读成形式主义。

**由此得出两个硬约束：**

1. **不要围绕名额做激励设计。** 用"明年给你名额"驱动表现，一旦名额落空，反噬的是管理者的可信度。日常激励语言只能是能力、职责、可见度、成长速度。
2. **名额越不確定，梯队的日常维护越重要。** 等名额真来了才发现"没人够格"，那是培养工作的失败，不是名额的失败。梯队要保持随时可交的状态。

---

## 二、梯队分层（三层，不要更多）

| 层 | 含义 | 本团队当前 |
|---|---|---|
| **第一梯队** | 12 个月内具备候选资格，培养动作已见效，有可查证据 | Z、Q |
| **第二梯队** | 方向明确、差距可识别，需要 1–2 个具体突破点 | K |
| **第三梯队 / 观察** | 先解决基础作业规范问题，短期不谈发展 | S |
| **特殊处理** | 不是培养对象，是留存/改造对象 | T |
| **不参与** | 已是派遣，不占名额 | W |

**层级的用途是分配培养资源和管理注意力**，不是给人贴标签。所以：**不公示**。公示梯队会立刻引发"为什么我在第二层"和针对个人的横向比较，收益远小于成本。培养动作要执行到人，梯队定位留在管理者心里和内部文档里。

---

## 三、分人培养动作与验证节点

每人的动作必须满足两条：**具体到动作**、**有可查的验证证据**。只写"加强培养"等于没写。

### Z — 语音呼入，5 年，外包 3 等，第一梯队

| 维度 | 内容 |
|---|---|
| 现状判断 | 执行力、细致度、协作性均强，专业中等，内部座席转岗。稳定性最好的人 |
| 培养动作 | ① 承接标注规范与质检复核（把"做得好"变成"能判断别人做得好"）② 带教新人（Q 或后续入职者）③ 编写本模块 SOP |
| 为什么是她 | 她已经具备稳定交付，缺的是**可迁移能力**和**可见性**。规范和带教是既能给团队产出、又能被跨模块看见的能力形态 |
| 验证证据 | 规范/文档产出数、带教完成情况、独立处理疑难的比例、绩效系数趋势 |
| 风险 | 外包身份是天花板，职级 3 等、月度奖金与全员一致。**如果 2 年内看不到任何出口信号，培养动作会变成公司的免费输出** |
| 必做动作 | 提前告诉她"名额近 2 年没发，不是我能定的"，比让她空等 2 年再解释要好得多 |

### Q — 语音外呼，1 年以上，外包 2 等，第一梯队

| 维度 | 内容 |
|---|---|
| 现状判断 | 团队最年轻、执行力强、细致、协作强，专业中等。成长斜率是全队最好的 |
| 培养动作 | ① 外呼策略与标注规范主责（从执行者到定义者）② 跨模块支援（呼入或在线文本）③ 独立值守与异常处理 |
| 为什么是他 | 成长速度是唯一能弥补资历的东西。给他"定义标准"而不是"完成任务"，成长才显著 |
| 验证证据 | 准确率/返工率的季度变化曲线、独立承担的模块跨度、跨模块支援的交付质量 |
| 风险 | **奖金已拉平，"新人期"缓冲消失**。他拿和 7 年经验的人一样的钱，产能却不在一个水平，落差由他自己承担 |
| 必做动作 | 绩效里给"改善/成长"较高权重并明确**看斜率不看绝对值**。别用"你还是新人"压他——在奖金已拉平的前提下这句话极刺耳，而且 Z/T 也会觉得资历不构成任何区别 |

### K — 语音外呼，1 年以上，外包 3 等，第二梯队

| 维度 | 内容 |
|---|---|
| 现状判断 | 执行力强、细致、协作强，专业能力低，在意自己的工作量 |
| 培养动作 | ① 从"会做"到"会判断"：疑难标注仲裁、抽检复核 ② 让他参与工作量口径的制定（不是被告知，是共同定） |
| 为什么是这条 | 他唯一的优势是细致和稳定，专业天花板在"执行"。仲裁和复核是**用他的强项打开能力空间**，成本低、见效快 |
| 验证证据 | 返工率变化、能否独立处理疑难样本、抽检复核的准确度 |
| 风险 | 能力提升慢 → 长期停在第二梯队 → 产生"我做得最多但升不上去"的怨气 |
| 必做动作 | 工作量口径必须提前书面约定并公示（见 `patrol-table.md` 表 C）。让他能自己算清楚，比事后解释有效 |

### S — 在线文本，5 年，外包 4 等，第三梯队

| 维度 | 内容 |
|---|---|
| 现状判断 | 执行力一般、细致度弱、专业能力低。职级已在最低档，月度奖金无档位差 |
| 培养动作 | ① 作业 SOP 化：把复杂判断拆成可照做的步骤 ② 一对一带教（安排 Z 或 Q，全员可见、正当、不带个人标签）③ 质量即时反馈（当日或次日给具体错例） |
| 为什么是这条 | 她的问题不是态度是精度，SOP 化对能力低的人最有效。带教安排**必须公开、正当**，不能被读成"因为关系所以给资源" |
| 验证证据 | 单批次合格率、返工率、连续达标周期数 |
| 风险 | 职级、职薪、月度奖金三条都无空间，可动的只有绩效系数。**必须把考核细到单批次粒度，否则真的没有抓手** |
| 红线 | 对外标准必须与其他人完全一致。任何特殊对待都会被 Z/Q/K 判定"规则只对别人有效" |

### T — 大模型提示词，外包 1 等（封顶），特殊处理

**T 不是培养对象，是留存/改造对象。** 她的定位和其余五人不同，直接套用梯队逻辑会出问题。

| 维度 | 内容 |
|---|---|
| 现状判断 | 专业能力中高（全队最高），但执行力一般、不细致、协作弱、比较自我。职级已最高，无升等空间。曾多次提出转部门 |
| 培养动作 | 不是加能力，是**改行为 + 建沉淀**：① 提示词变更必须留版本记录与效果复盘 ② 协作硬门槛（不达标则总分封顶）③ 给独立模块 + 明确交付标准，用结果管不用人管 |
| 为什么不是"培养" | 1 等已封顶，职级升等这条路对她关闭。加培训、加证书都不产生任何回报 |
| 验证证据 | 变更留痕完整率、协作硬门槛达标情况、提示词带来的效果变化（有数据才采信） |
| 用户的判断 | **T 目前不是名额第一优先选择。** 主因应是协作稳定性——这是可验证的失分项，不是印象评价 |
| 关键风险 | 她会对这个体系失望：职级最高、月度奖金与最低职级相同、唯一出口还被视为不确定。三者叠加，加速转部门。**她的留存价值 > 提名价值** |
| 必做动作 | ① 用"专业维度"给她高分路径（提示词效果提升的量化口径），让她看到"把活干好能拿钱" ② 转部门诉求不否定动机，用规则接住 ③ **不要用名额吊着她**——名额不确定，吊了又落空，双重失信 |

### W — 唯一骨干，派遣，不参与名额

| 维度 | 内容 |
|---|---|
| 培养动作 | ① 减负落到具体条目（把日常标注/巡检从她职责里摘出）② 支援期做成有期限的项目 + 授权移交清单 ③ 权限双人备份（她主持 + 一人副持） |
| 为什么 | 她是单点故障，被抽调支援投诉更是持续消耗。**减不给到位，其他四条培养动作都会受影响** |
| 验证证据 | 支援期起止明确、授权移交清单完成、权限季度复核记录 |
| 必做 | 任何涉及名额的沟通都要同步讲 W 的显性通道：专业职级、带教/师徒角色、专项负责人、职责升级。不讲清楚，团队会读成"骨干反而没盼头" |

## 四、梯队维护节奏

| 动作 | 频次 | 产出 |
|---|---|---|
| 内部复核分层与验证证据 | 每季度 1 次 | 更新后的梯队定位 + 每人差距项 |
| 培养动作执行检查 | 每月 | 文档产出、带教进度、专项承担情况 |
| 绩效系数趋势复盘 | 每月（随绩效） | 识别下行趋势，早干预 |
| 名额政策动向确认 | 每半年 | 政策没动就明确"仍无名额"，别让团队悬着 |

**名额 2 年没发时最容易犯的错**：为了"让团队有奔头"而暗示名额要来了。**不暗示。** 空等 2 年再解释，比一开始就说明"这两年没有"要难处理得多。

---

## 五、名额真的下来时

筛选与推荐流程见 `performance-rubric.md` 第六节。要点复述：

1. **3 个工作日内**交结论（部门负责人不会等太久）
2. **资格门槛 → 分项加权 → 推荐意见**三步，每步留痕
3. **候选排序只给 3 人以内**，全员排序等于替部门负责人做决定
4. **不预设结论但要有明确推荐**——"看情况定"在这个团队会引爆争议
5. **不承诺结果，只承诺过程**："你具备候选资格"≠"这次就是你"
6. **未入选者必须有单独沟通 + 具体下一步**。2 年没发，团队可能早就不抱期待——恰恰因此，名额真要发时落选者的反应会比预期激烈

---

## 输出格式建议

- 梯队总览（一页，**不公示**）：分层 / 每人一句话判断 / 距候选标准的差距项
- 分人培养卡：现状判断 → 培养动作 → 验证证据 → 风险 → 必做动作
- 名额筛选包（名额确定时才出）：排序 + 推荐理由 + 每人的未推荐原因 + 需部门负责人拍板事项
- 预期管理动作：什么时候对谁说什么

## 常见坑

- **公示梯队**：立刻变成横向比较的战场。动作要执行到人，分层留在内部。
- **围绕名额做激励**：名额不确定，承诺落空反噬管理者可信度。
- **对 T 用梯队逻辑**：她 1 等封顶，升等路关闭，"培养"对她没有回报，逻辑上就不成立。
- **对 S 因关系户虚高，或反过来刻意加压**：两种都会让另外四人判定"规则只对别人有效"。
- **名额来了才想起来建梯队**：那时只剩一周可用，人选只能靠印象。
- **只排前 1 名不说其余人的原因**：部门负责人会问"第二名为什么不行"，答不上来就只能靠印象。
