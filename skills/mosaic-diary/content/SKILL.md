# Mosaic Diary · 碎片拼日记

把脑子里一闪而过的句子、小情绪、小事，像拼马赛克一样攒成一篇可视化日记。

## 1. 何时使用

当用户说类似的话：

- "帮我把这些零散的话整理成日记"
- "加几句：……"
- "今天的事：xxx，xxx，xxx"
- "用情绪整理一下 / 按主题分一下"
- "看看我现在攒了哪些句子"
- "生成今天的日记吧"

任何"用户给一段零散文本 + 想要结构化整理"的场景都适用。

## 2. 核心能力

| 能力 | 说明 |
|------|------|
| 🧺 **累积输入** | 支持用户分多次追加句子，存到工作区状态文件 |
| 🌈 **双模式分类** | 用户每次生成时可自选 `mood`（情绪）或 `topic`（主题） |
| 🪟 **HTML 可视化** | 输出自包含 HTML（CSS 内联），每张卡片带颜色 / 图标 / 句子列表 |
| 📖 **日记叙述** | 在卡片之外，额外生成一段连贯、有温度的散文式日记 |
| 💾 **状态可恢复** | 句子池、生成历史都在工作区，可"撤销 / 继续 / 重置" |

## 3. 工作流状态机

整个 skill 在工作区维护 4 类状态文件：

```
/workspace/
  .skills/mosaic-diary/
    state/
      pool.jsonl          ← 累积的句子池（每行一条 JSON）
      quote_library.jsonl ← 用户的金句引文集（作者/书目）
      sessions/           ← 每次生成的输出
        diary-YYYY-MM-DD-HHMMSS.html
```

**6 个核心动作**（通过自然语言指令触发）：

| 指令关键词 | 动作 | 行为 |
|----------|------|------|
| `添加 / 加 / 追加` + 句子 | **ADD** | 解析句子，写入 pool.jsonl |
| `查看 / 看看 / 列出` + 当前/句子 | **LIST** | 读 pool.jsonl，回显已累积的所有句子 |
| `生成 / 整理 / 出` + 日记/卡片 | **GENERATE_PRE_CHECK** | **先不生成**：报告当前 N 条，问"还要补点什么吗？" |
| （用户回 `够了 / 开整 / 就这样`） | **GENERATE** | 真正跑分类 + 渲染 + 输出 HTML |
| `修改 / 改 / 调 / 换` + 内容 | **MODIFY** | 细粒度调整生成结果（见下方子命令） |
| `撤销 / 删最后 / 删第 N 条` | **REMOVE** | 从 pool.jsonl 删除指定条目 |
| `重置 / 清空` | **RESET** | 清空 pool.jsonl（带二次确认） |

### 3.1 GENERATE 两阶段流程

**默认行为：必须先 PRE_CHECK，再 CONFIRM。**

**阶段 1：PRE_CHECK**

用户说"整理 / 生成 / 出卡片" → 不直接生成，而是：

1. 读 pool.jsonl，统计 N 条
2. 给出简短摘要（**不要分类、不预览卡片**——避免太早下结论）
3. 主动问：
   > "现在累积 N 条。要再补点什么吗？要的话直接说，没有的话回我'够了' / '开整' / '就这样'。"

**跳过 PRE_CHECK 的例外**（用户明确表达不想再问）：

- 用户说："整理，别问了"
- 用户说："直接生成，够了"
- 用户说："别问了，开整"
- 当前 pool 已经有 0 条（直接拒生成，反问"我还没拿到内容呢"）

**阶段 2：GENERATE**

进入后：

1. 模式未定 → 问"用情绪还是主题？"
2. 跑分类 + 渲染
3. 输出 HTML + 散文
4. **主动留修改入口**（见 3.2）

**PRE_CHECK 循环**：用户在 PRE_CHECK 中追加了新句子后，**再次**进入 PRE_CHECK，再问一次是否继续补。最多循环 3 次，避免无限来回。

### 3.2 MODIFY 子命令

生成完后，用户可能想做这些微调（按场景触发对应子命令）：

| 用户说 | 行为 |
|------|------|
| `改第 N 条：xxx` | 修改 pool.jsonl 第 N 条原文，**重新生成** |
| `删第 N 条` | 删除该条，**重新生成** |
| `加一条：xxx` | 追加一条，**重新生成**（自动进入 PRE_CHECK 流程） |
| `换金句` / `换一句` | 同作者内换一句，**只重渲染金句板块**（不重跑分类） |
| `换作者：xxx` | 切到指定作者重新选句 |
| `用主题模式重新分` / `改用主题` | 切 mode 重新跑分类 + 渲染（不动句子池）|
| `用情绪模式重新分` / `改用情绪` | 同上 |
| `散文再短点` / `散文太长了` | 重新生成 narrative 段（不重跑分类）|
| `散文太短了` / `散文写长点` | 同上 |
| `把第 N 张卡片并到 X 类` | 调整类目归属，重新聚合（不重跑分类）|
| `标题换成：xxx` | 重渲染顶部 |
| `全部重做` | 重新跑全流程 |

**`重新生成` vs `重渲染`**：

- 重新生成 = 走完整 pipeline（分类、聚合、渲染），耗时长
- 重渲染 = 改一个局部变量，只跑对应模板替换，秒级

skill 应尽量用"重渲染"而不是"重新生成"，避免对同样的句子反复分类。

### 3.3 生成时子参数

- `mode=mood`（默认）→ 情绪分类
- `mode=topic` → 主题分类
- 用户没说时，主动追问一次："这次想用情绪分还是主题分？"
- 用户中途可改："改成主题模式重新生成"（MODIFY）

## 4. 句子解析规则

用户输入句子时，**用 `、`、`。`、`\n`、`;`、`,`、`;` 切分**。同时支持以下格式：

```text
今天加班到十点，累死了。
- 同事送了一杯奶茶，感动。
* 晚上跑步 5 公里
1. 看了会儿书
```

- 跳过空行、纯标点
- 保留每条句子的原始措辞（不要替用户"润色"）
- 单条长度建议 ≤ 80 字；超过就按句号再切

## 5. 分类规则

### 5.1 情绪模式 `mood`

**预定义情绪类目**（不强求全用，按需选用 4-7 个）：

| 情绪 | 颜色 | 图标 |
|------|------|------|
| 开心 / 雀跃 | `#FFD166` | ✨ |
| 平静 / 治愈 | `#A8DADC` | 🌿 |
| 感动 / 温暖 | `#F4A4C0` | 💗 |
| 焦虑 / 紧绷 | `#E07A5F` | 🌪️ |
| 低落 / 疲惫 | `#7B6D8D` | 🌧️ |
| 愤怒 / 烦躁 | `#D62828` | 🔥 |
| 期待 / 憧憬 | `#B5E48C` | 🌱 |
| 怀旧 / 感慨 | `#C9ADA7` | 🍂 |

→ 某条句子不强烈匹配任何情绪时，归入「日常 / 中性」类（用浅灰 `#E5E5E5` + ⚪）。

### 5.2 主题模式 `topic`

**预定义主题类目**（同样按需选用 4-7 个）：

| 主题 | 颜色 | 图标 |
|------|------|------|
| 工作 / 职场 | `#264653` | 💼 |
| 学习 / 自我提升 | `#2A9D8F` | 📚 |
| 社交 / 人际 | `#E76F51` | 👥 |
| 家庭 / 亲密关系 | `#F4A261` | 🏠 |
| 爱好 / 兴趣 | `#E9C46A` | 🎨 |
| 健康 / 身体 | `#8AB17D` | 🏃 |
| 琐事 / 日常 | `#B5B5B5` | 🧺 |
| 想法 / 灵感 | `#9D4EDD` | 💡 |

→ 不明确归入「琐事 / 日常」兜底。

### 5.3 分类策略

1. **逐句 LLM 分类**：把整批句子 + 模式传给 LLM，要求返回 `{category, reason}` 的 JSON 列表
2. **聚合同类**：把同类的句子聚合到一张卡片
3. **合并小类**：如果某个类目只有 1 条且与「日常 / 中性 / 琐事」相邻，合并到兜底类
4. **保留证据**：分类时简要记录 reason（用于日记叙述时引用细节）

## 6. HTML 渲染规范

输出文件命名：`diary-YYYY-MM-DD-HHMMSS.html`（**自包含**，所有 CSS 内联，无外部依赖）。

### 6.1 页面结构

```
┌────────────────────────────────────┐
│      顶部：日期 + 标题              │
│      副标题：模式 + 句子总数         │
├────────────────────────────────────┤
│  📖 日记正文（散文式 200-400 字）    │
├────────────────────────────────────┤
│  💭 今日一句（积极 + 哲思，引言式）   │
│     大字号居中，可名言可原创          │
├────────────────────────────────────┤
│  🪟 卡片墙（grid，自适应列数）       │
│   [卡1] [卡2] [卡3]                │
│   [卡4] [卡5]                       │
├────────────────────────────────────┤
│  页脚：生成时间 + 来源              │
└────────────────────────────────────┘
```

### 6.2 卡片视觉

- **圆角 16px**，**阴影柔和**（`box-shadow: 0 4px 16px rgba(0,0,0,0.06)`）
- **左侧色条** 8px 宽，用该类目的颜色
- **标题**：类目名 + 图标（24px）
- **副标题**：该类目句子数量
- **正文**：每条句子一行，前面加 • 项目符号；时间戳/原文标记保留

### 6.3 调色板

- **背景**：奶油白 `#FAF9F6`
- **文字主色**：墨黑 `#2B2B2B`
- **次要文字**：暖灰 `#6B6B6B`
- **卡片底色**：纯白 `#FFFFFF`
- **强调**：深绿 `#3A5A40`（仅用于顶部标题和主 CTA）

### 6.4 响应式

- `grid-template-columns: repeat(auto-fill, minmax(280px, 1fr));`
- 移动端单列，桌面端 2-3 列

### 6.5 HTML 模板

完整模板见 `templates/diary-template.html`。**生成时复制模板，把占位符替换为真实数据**。

## 7. 日记叙述生成规则

在卡片之外，额外生成一段 200-400 字的散文式日记。**调性：克制、具体、不无病呻吟**。

**硬要求：**

1. **第一人称**（"我"）
2. **简练**：少形容词、少副词、少修饰。**目标字数 200 字左右**，最多不超过 350
3. **有叙事弧线**：开篇引入 → 中段几个具体细节（从卡片里挑）→ 结尾留白（不升华）
4. **引用原句**：1-2 处直接引用用户原话（用「」或粗体），**不堆砌**
5. **情绪克制**：根据主导情绪定调，但**不要给情绪贴标签**（避免"心里很复杂""情绪低落"等直白表述）
6. **结尾留白**：不升华、不"明天会更好"、不说教。让最后一句停在某个具体画面或动作上

**禁止的"无病呻吟"腔调**（出现一次就重写）：

| ❌ 不要 | ✅ 改用 |
|--------|------|
| "被允许的松弛感" | 直接写"睡过了，不慌" |
| "对自己好点吧" | 直接写"每种拿了两个" |
| "心里很复杂" | 直接写"心里闷了一下" |
| "那是今天最像自己的决定" | 直接写"今天做得最对的一件事" |
| "空气里全是周一早晨特有的疲惫" | "地铁里挤着人，呼吸都是热的" |
| "凡是过往，皆为序章"（升华类） | 不用——金句板块负责这件事 |
| "我意识到……" 句式 | 直接陈述事实 |

**可以**用的过渡：时间词（"早上""晚上回家路上""风吹过来的时候"）、具体动作（"犹豫了两秒""眼睛累了，但停不下来"）。

## 8. 今日一句生成规则

金句板块是日记的情绪升华，必须满足：

1. **位置固定**：日记正文之后、卡片墙之前
2. **长度**：1-2 句话，30-80 字
3. **来源**：**默认真实名言**（用户偏好）。**选句原则**：
   - 优先选**与当天内容有呼应**的名言（不是随便抓一句）
   - 选**意境/情绪能承接日记结尾**的那一句
   - 名人优先：苏轼、陶渊明、汪曾祺、季羡林、木心、辛波斯卡、仓央嘉措、加缪、毛姆、海明威、王尔德、泰戈尔、罗曼·罗兰、老子、庄子、维特根斯坦、胡适……
   - **不选烂大街的"凡是过往，皆为序章"** 之类被过度引用的句子
   - **不选作者不详无法核实的句子**（写"佚名"也要确实知道是佚名）
4. **硬要求**：
   - ✅ **积极但不鸡汤**：可以是"接纳"型、"留白"型、"转念"型，**不能是"打鸡血"型**
   - ✅ **有哲理**：能让人停下来想一秒，不是空洞口号
   - ❌ **不要**："明天会更好""加油""一切都会好起来的" 这种空话
5. **作者署名**：
   - 真实名言 → 写作者真名（"—— 汪曾祺"、"—— 苏轼"）
   - 用户指定某句时，按用户给的署名来
   - 用户说"今天想原创"时，写「—— 写给今天的自己」
6. **不要重复**：同一用户 7 天内金句不重复
7. **视觉**：HTML 渲染时用引言式（上下装饰线 + 大引号 + 居中）

**金句选句示例**（仅作启发，**禁止同日重复使用**）：

| 风格 | 句子 | 作者 |
|------|------|------|
| 留白型 | "如果你来访我，我不在，请和我门外的花坐一会儿。" | 汪曾祺 |
| 接纳型 | "飘风不终朝，骤雨不终日。" | 老子 |
| 留白型 | "此心安处是吾乡。" | 苏轼 |
| 觉察型 | "凡是能够说的事情，都能够说清楚。" | 维特根斯坦 |
| 朴素型 | "怕什么真理无穷，进一寸有一寸的欢喜。" | 胡适 |
| 留白型 | "心远地自偏。" | 陶渊明 |
| 觉察型 | "我们都生活在阴沟里，但仍有人仰望星空。" | 王尔德 |
| 朴素型 | "岁月不饶人，我亦未曾饶过岁月。" | 木心 |

## 9. 金句引文集（用户书单）

用户可以**预存自己喜欢的作者/书目**，金句优先从这里挑。

### 9.1 存储

文件：`/workspace/.skills/mosaic-diary/state/quote_library.jsonl`

每行一条 JSON：

```json
{"id": 1, "type": "author", "value": "汪曾祺", "added_at": "..."}
{"id": 2, "type": "book",   "value": "《人间草木》", "added_at": "..."}
{"id": 3, "type": "author", "value": "毛姆", "added_at": "..."}
```

### 9.2 触发动作

| 用户说 | 动作 |
|------|------|
| `加书：xxx` / `加一本：xxx` / `加作者：xxx` | 追加到书单 |
| `加书单：a、b、c`（多个用顿号/逗号分隔） | 批量追加 |
| `看书单` / `看看我的书` / `我的书单` | 列出已存的书 |
| `删第 N 本` / `删：xxx` | 移除指定条目 |
| `清空书单` | 重置（需二次确认） |

**自动识别类型**：
- 含「《》」→ `book`（书名）
- 不含 → `author`（作者）

### 9.3 选句优先级

1. **用户书单**（按添加顺序轮换，避免总是用第一个）
2. **默认名言库**：苏轼、陶渊明、汪曾祺、季羡林、木心、辛波斯卡、仓央嘉措、加缪、毛姆、海明威、王尔德、泰戈尔、罗曼·罗兰、老子、庄子、维特根斯坦、胡适
3. **兜底原创**：「—— 写给今天的自己」

### 9.4 引用格式

- 仅作者 → `—— 汪曾祺`
- 有具体书 → `—— 汪曾祺《人间草木》`
- 用户临时指定某句 → `—— 汪曾祺《人间草木》·「未选过的句子」`
- 原创兜底 → `—— 写给今天的自己`

### 9.5 页面展示

HTML 顶部 meta 区域加一个 chip：

```
📚 引自：汪曾祺《人间草木》
```

（用户书单为空时，此 chip 隐藏）

## 10. 完整对话示例

### 10.1 基础流程 + PRE_CHECK

```text
用户：今天加班到 10 点，累死了。同事送了杯奶茶，感动。晚上跑了 5 公里。

Mavis：
好，加进去 ✓ 现在 3 条。要继续攒着还是开始整理？

用户：开始整理。

Mavis：
[PRE_CHECK] 现在累积了 3 条。
  1. 今天加班到 10 点，累死了
  2. 同事送了杯奶茶，感动
  3. 晚上跑了 5 公里

要再补点什么吗？要的话直接说，没有的话回我"够了 / 开整"。

用户：啊对，再加一句：和妈妈打电话聊了半小时，她最近在学插花。

Mavis：
加了 ✓ 现在 4 条。还要再补点吗？没有就回"够了"。

用户：够了。

Mavis：
用情绪分还是主题分？

用户：情绪。

Mavis：
[GENERATE] mode=mood，开始整理。
[分类 + 聚合 + 渲染 + 散文]
[交付 HTML]

搞定！今天的情绪地图 →
  🌪️ 焦虑/紧绷（1条）
  💗 感动/温暖（2条）
  ⚪ 日常/中性（1条）
  💭 今日一句：汪曾祺《人间草木》—— "如果你来访我，我不在……"

打开看看？觉得哪里要调都可以直接说。
```

### 10.2 修改流程（MODIFY）

```text
用户：第 3 条的"感动"删掉，改成"挺暖的"。
Mavis：
改好了 ✓ 第 3 条现在是"挺暖的"。我重新跑一遍分类——因为字数变化不影响分类，应该结果一样，但保险起见我还是重生成吧。
[重新生成]
更新版已就位 →

用户：散文太长了，再短点。
Mavis：
好，我重写一段更短的散文，不动卡片和金句。
[重渲染 narrative 段]
散文更新好了，其他没动 →

用户：换金句，不要汪曾祺那句。
Mavis：
好，从汪曾祺的《人间草木》里换一句别的——
"如果你是一颗糖，我宁愿是那块化在你嘴里的水。"
……不太对。再来："人生忽如寄，莫辜负茶、汤和好天气。"
我换了这一句 →

用户：用主题模式重做一份。
Mavis：
好，从头重跑（分类会完全不一样，散文也会重写）。[重生成 mode=topic]
主题版做出来了 → 要保留哪个？还是两个都留？
```

## 11. 错误处理

| 场景 | 行为 |
|------|------|
| 句子为空 / 纯标点 | 跳过，提示"已忽略 N 条空内容" |
| 全部句子加起来仍 < 1 条 | 拒绝生成，反问"我还没拿到内容呢" |
| 分类 LLM 返回 JSON 解析失败 | 重试 1 次；仍失败则降级为「琐事」单卡 |
| 用户在生成时改模式 | 重新分类，不重置已写入的句子池 |
| HTML 渲染失败 | 退化为 Markdown 卡片 + 散文，并提示用户 |

## 12. 输出与交付

- **HTML 文件**写到 `/workspace/.skills/mosaic-diary/state/sessions/`
- **用 `<deliver-assets>` 块**告诉用户文件已生成
- 附一句暖心收尾（不是客套话，是基于当天的内容给一个真实观察）
- 主动问："要不要继续加？还是先到这里？"

## 13. 风格调性

- **温度**：像一个会写日记的朋友，不是一个在分类的机器
- **节奏**：短句为主，必要时拉长
- **不滥用 emoji**：卡片内最多 1-2 个，正文尽量少
- **不要说教**：不要"你应该更开心一点"
- **可以吐槽**：但温和
