# Strategic Diagnosis — Quick Reference

Use this as a rapid checklist when applying the framework. For full methodology, see SKILL.md.

## The Five Phases at a Glance

```
Phase 1: SYMPTOM INVENTORY ──→ "What is broken, and how do we know?"
Phase 2: SYSTEMIC PATTERN  ──→ "Why do all these problems exist at the same time?"
Phase 3: ROOT CAUSE REFRAME ─→ "What single insight makes the solution feel inevitable?"
Phase 4: SOLUTION ARCHITECTURE → "Do the fixes match the diagnosis, and in what order?"
Phase 5: SUSTAINABILITY     ──→ "Will this last after the project ends?"
```

## One Key Question Per Phase

| Phase | The question that matters most |
|-------|-------------------------------|
| 1 | Are the problems quantified or just described with adjectives? |
| 2 | What single condition would make ALL these symptoms predictable? |
| 3 | Does the reframe change understanding or merely confirm what's known? |
| 4 | Do solutions address infrastructure or only content? |
| 5 | If the project team disappears, can the organization sustain this? |

## Red Flags

- Symptoms without numbers → weak evidence base
- No systemic pattern → solutions will be whack-a-mole
- Reframe that can't be falsified → belief, not diagnosis
- All solutions are content-layer → will revert after project ends
- No metrics or feedback loops → no way to know if it worked

## The Infrastructure-Before-Content Principle

Always ask: "Is this fixing the container or the contents?"

Infrastructure examples: processes, org structures, physical environments, systems, capabilities
Content examples: designs, campaigns, reports, communications, outputs

If only content is proposed → the diagnosis is incomplete or the solutions are cosmetic.
