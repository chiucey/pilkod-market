# 标准提问与上下文连续性

用于把美股、港股问题转换为可复核的分析任务卡，并在连续更新时防止标的、柜台、周期、持仓、数据时点或交易计划发生无提示漂移。具体可复制问法见 [prompt-templates.md](prompt-templates.md)。

## 一、会话类型

每次先归类，不能把三类请求混在一起：

1. **新建基线**：首次分析某标的，或用户明确要求重新建立完整基线。
2. **基线更新**：基于明确的上次报告刷新行情、图表、基本面、事件或交易计划。
3. **盘中执行观察**：关注当前报价、Level 1/Level 2、点差、深度、主动成交或订单执行条件。

若用户同时要求更新与盘中执行，仍分别保存完整日线、当前报价和盘口快照，不把它们合并成一个时点。盘中观察不能替代完整基线；新建基线也不能伪装成秒级执行建议。

## 二、字段状态协议

模板中的字段不能静默留空。用户或回复方应使用以下状态之一：

| 状态 | 含义 | 处理方式 |
|---|---|---|
| `【具体值】` | 用户已确认的事实或偏好 | 按所给单位使用并回显 |
| `【请刷新】` | 时效数据或市场规则 | 本次重新取得，不能沿用旧值 |
| `【沿用：基线编号】` | 稳定输入未改变 | 仅从指定基线沿用，列入“沿用项” |
| `【使用默认】` | 用户接受技能默认 | 回显采用的默认值及影响 |
| `【未知】` | 用户不知道或当前没有 | 判断是否阻塞；不得猜测 |
| `【不适用】` | 该字段与任务无关 | 明确跳过，不算数据缺口 |
| `【请先问我】` | 用户要求在使用前确认 | 只问会改变结论的必要问题 |

不得把 `【未知】`、空白、星号占位符或模糊的“跟上次一样”当成具体数值。百分比必须写清是账户权益、持仓还是单笔风险的百分比；数量必须写清“股”或“手”；成本必须写清“每股均价”或“总成本”及币种。

### 简短指令展开协议

用户写“其余按默认完整输出”时，不要求其继续枚举 Skill 已规定的数据和报告模块。将该短语自动展开为：

- 所有报价、完整K线、盘口、财报/业绩、估值、事件和适用市场规则均为“本次请刷新”。
- 输出采用完整报告默认值，包括任务卡、技术图、五维评分、唯一当前动作、最多两套互斥方案、仓位与风险校验、基线编号和下次更新引用块。
- 未提供的稳定用户输入分别标为“使用默认”或“未知”，不得静默推断。
- 只有证券身份、持仓数量、成本口径、精确仓位所需账户风险、港股交易路径等真正阻塞项才追问；其余缺失项说明影响后继续。
- 未取得Level 1/Level 2、市场规则不完整或交易计划校验失败时，按原门槛降级并写“未取得/等待”，不得因为问题简短而放松质量要求。

用户写“其余按默认快速输出”时，只展开为当前结论、三项核心依据、关键价位、主要风险和数据缺口，不自动承诺完整图表、精确仓位或完整交易计划。

## 三、统一分析任务卡

开始取数前，从当前问题和已经确认的会话信息提取以下字段：

| 模块 | 字段 | 记录要求 | 默认或缺失处理 |
|---|---|---|---|
| 标的身份 | 市场、公司、原生代码、数据商代码、交易所、证券类型 | 先消除同名、同代码、ADR、ETF或多柜台歧义 | 无法唯一识别时阻塞 |
| 任务状态 | 新建基线、基线更新、盘中执行观察 | 更新必须引用基线编号或可唯一定位的报告 | 无法定位且影响计划时追问 |
| 任务类型 | 快速判断、完整交易计划、持仓诊断、盘口执行、财报、长期价值、多股对比 | 按主要问题选择，不无提示扩展任务 | 未说明时按问题语义选择 |
| 数据时点 | 当前或指定日期时间、时区、盘前/盘中/盘后/收盘 | “当前”按运行日期与市场状态解释 | 报告写绝对时间和时区 |
| 分析周期 | 短线、中线、长线或自定义持有窗口 | 同时区分图表窗口与计划持有期 | 默认短线1–20个交易日、中线1–6个月、长线1–3年以上 |
| 持仓状态 | 空仓，或每股均价/总成本、币种、股数/手数、建仓目的、交易仓/投资仓 | 总成本与均价不得混用；核心仓与交易仓不得混用 | 未说明则标“持仓未知”，仅给条件方案 |
| 账户风险 | 账户权益及币种、单笔风险金额或比例、最大配置比例、组合集中度 | 比例写明分母；跨币种风险使用明确方向的汇率 | 缺少时不给个性化精确数量 |
| 事件容忍 | 是否愿意隔夜、跨财报、跨停牌/重大公告持有 | 决定跳空风险和时间止损 | 未说明则不假定可跨重大事件 |
| 数据要求 | 报价、完整K线、Level 1/Level 2/逐笔、基本面、估值、市场规则 | 每个快照分别注明刷新或不需要 | 完整交易分析默认尝试Level 1 |
| 特别关注 | 财报、估值、催化剂、行业、大盘、税务或其他限制 | 无则写不适用 | 不强行增加无关模块 |
| 输出与校验 | 图表、完整报告/仅变化、两套互斥方案、仓位及计划校验 | 指定是否要求精确执行数量 | 默认技术图+核心结论+条件计划 |
| 上次基线 | 基线编号、报告时间、旧计划状态 | 新建分析写“无” | 更新分析必填或先定位 |

任务卡应出现在完整报告顶部。快速判断可压缩为一行，但仍要覆盖标的、任务、周期、持仓、数据时点和关键缺口。

## 四、美股与港股差异字段

### 美股必核字段

- 原生 ticker、主要上市交易所、证券类型和报价币种。
- 普通股、ADR、ETF、REIT或杠杆/反向产品；ADR另核存托比例和主要上市地。
- 当前属于盘前、常规盘、盘后还是休市；盘前/盘后价不得冒充完整日线收盘。
- Level 1范围写清NBBO、聚合或单交易所；未确认范围时写“范围未知”。
- 账户币种不同于报价币种时，精确仓位需汇率与换汇/交易成本。
- 拆股、分红、并购等公司行动和适用财报/披露口径。

### 港股必核字段

- 原生五位代码、主板/GEM、证券类别、数据商代码、交易柜台与柜台币种。
- 当前每手股数、计划数量按“股/手”表达、碎股处理方式及经纪商是否支持碎股路径。
- 当前价格适用的HKEX价位、可接受订单类型和当前属于竞价、连续交易、午间休市或收市。
- 行情范围写清HKEX交易所簿、聚合或范围未知；不得称为NBBO。
- 本地港股账户、港股通或其他交易路径；同时复核当前结算安排、可交易名单和订单限制。
- 账户币种、交易币种、明确方向与时点的汇率；佣金、平台费、印花税、交易征费等成本口径。
- 双柜台、停牌、除权、供股、合股/拆细、红股、每手股数变更和公告披露频率。

这些市场规则不是盘口快照。港股新建完整计划或更新精确数量时必须本次复核，不能只因旧报告写过就沿用。

## 五、阻塞项与默认值

只在答案会因缺失信息而发生实质变化时追问，最多一次询问1–3个问题。

### 必须先确认的阻塞项

- ticker、交易所、证券类型、ADR关系或交易柜台无法唯一识别。
- 用户要求持仓精确数量动作，但成本口径、成本币种或持仓数量不明确。
- 用户要求精确仓位或最大亏损金额，但账户权益、账户币种或风险预算缺失。
- 港股要求精确整手数量，但当前每手股数、交易路径或关键成本无法核验。
- 跨币种账户要求精确风险金额，但汇率方向/时点无法取得。
- 用户要求实时Level 2、逐笔或滑点判断，但没有可靠权限、文件、截图或来源。
- 更新任务无法定位上次基线，而且旧计划状态会改变当前动作。

### 不阻塞研究的缺失项

- 未给账户规模：给风险百分比框架或每10,000账户币种单位示例，不给个性化股数。
- 未给持仓：标“持仓未知”，分别给空仓和持仓者的条件动作。
- 未指定周期：使用技能默认周期并回显。
- 港股未取得每手股数或费用：继续趋势、基本面和条件价位分析，精确执行写“等待”。
- 未取得盘口：继续OHLCV、基本面和估值分析，盘口写“未取得”，盘中执行置信度降级。
- 未指定输出：按默认技术走势图、一屏结论和交易计划输出。

不得反复询问用户已经提供或明确从某个基线沿用的信息。

## 六、数据快照协议

完整分析至少分列以下快照，任何一个都不能借另一个的时间代替：

1. **当前报价**：价格、日期时间、时区、市场状态、实时/延迟和来源。
2. **最近完整K线**：交易日、OHLCV、频率、复权口径和来源；未收盘K线只能标“临时值”。
3. **盘口**：捕获日期时间、时区、L1/L2/逐笔、市场范围、数量单位、实时/延迟和来源；未取得就明确写未取得。
4. **基本面/事件**：财报或公告期、发布日期、适用报告币种及来源。
5. **市场规则**：适用市场、规则版本/核验日期；港股另含柜台、每手股数、价位、时段、交易路径、结算和成本。

活跃交易时段的报价超过技能时效门槛、最近完整日线不是最新应有交易日、盘口过期或市场规则缺失时，相应执行门槛失败。失败不等于整个研究停止，但主动作不得包装成可立即执行；必要时写“等待”。

## 七、连续更新与基线编号

每份完整报告生成唯一基线编号，建议格式：

`市场-原生代码-YYYYMMDD-HHMM-版本`

示例：`US-AAPL-20260818-1600-v1`、`HK-00700-20260818-1608-v2`。编号中的时间使用报告明确标注的市场或报告时区。

基线编号只是版本标识，不是保证可跨会话检索的数据库键。同一会话可直接引用；开启新会话或无法访问旧报告时，用户应附上旧报告，或粘贴上次回答提供的“下次更新引用块”。不得只凭一个无法解析的编号猜测旧持仓或旧计划。

每份完整报告结尾提供可复制引用块，至少含：基线编号、标的身份与柜台、持仓数量与成本口径、交易仓/核心仓标签、稳定风险参数、计划周期、当前计划版本、旧计划状态、未解决缺口和旧快照日期。旧快照日期只用于追踪版本，不表示下次可继续使用。

更新时先把输入分为三类：

1. **沿用项**：标的身份、用户风险偏好、明确未改变的持仓目的等稳定信息。
2. **必须刷新项**：报价、市场状态、最近完整K线、指标、盘口、财报与事件日历、估值、一致预期和适用市场规则。
3. **用户变化项**：成交记录、增减仓、成本变化、风险预算、计划周期、交易路径或其他限制。

报告必须增加“与上次相比”，至少列出：基线编号；用户输入变化；数据事实变化；关键位、评分和执行门槛变化；旧计划继续有效/失效部分；新版主动作。

“沿用上次”只包括稳定输入，不包括旧报价、旧盘口、旧市场状态、旧指标、未经复核的事件或旧计划校验结果。若用户没有任何交易，最好明确写“本次无成交、持仓与风险参数不变”。

## 八、标准回复握手

完整分析先回显紧凑任务卡，不要求用户重复确认非关键字段：

~~~markdown
## 本次分析任务卡

基线状态：新建 / 更新【编号】 / 盘中观察

| 标的与市场 | 任务与周期 | 持仓与成本口径 | 账户与风险 | 数据/盘口 | 输出 |
|---|---|---|---|---|---|
| | | | | | |

沿用项：……
本次变化：……
需刷新：……
默认/未知/不适用：……
阻塞项：无 / ……
~~~

若存在阻塞项，先只问必要问题；若没有阻塞项，直接取数和分析。不要把回显任务卡变成无意义的二次确认。

## 九、质量检查

- 标的、证券类型、周期、任务目标和基线编号没有无提示漂移。
- 每个空白或占位符都被标成具体值、刷新、沿用、默认、未知或不适用。
- 成本已区分每股均价与总成本；数量已区分股与手；比例已说明分母；币种已标明。
- 美股报价范围、交易时段、ADR/ETF属性已核对。
- 港股原生代码、柜台、币种、每手股数、价位、交易路径、结算、费用和汇率已核对或明确降级。
- 用户的成本、数量、风险预算和交易仓/长期核心仓标签没有被遗漏或互换。
- 报价、完整K线、盘口、基本面和市场规则各有独立时点与来源。
- 更新报告明确区分沿用输入、刷新数据和用户变化。
- 跨会话无法读取旧报告时，已要求旧报告或引用块，没有只凭基线编号猜测。
- 旧盘口、旧当前价、旧市场状态和过期计划校验没有进入新结论。
- 结论变化能追溯到数据变化或用户输入变化，而非表述随机变化。
- 缺失信息及影响已写明；执行门槛失败时主动作明确为“等待”。
