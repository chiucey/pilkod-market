# 飞书技术面试准备助手

## 多语言与工种支持

本技能支持多种编程语言和工程师岗位的面试准备：

### 编程语言

| 语言 | 特点 | 核心考察模块 |
|------|------|-------------|
| **Java** | 生态完善、面试体系成熟 | JVM、集合框架、并发编程、Spring |
| **Go** | 简洁高效、云原生主流 | Goroutine、Channel、GC、并发模型 |
| **Python** | 简洁优雅、数据AI首选 | 语言特性、装饰器、协程、底层实现 |
| **C++** | 性能极致、系统级开发 | 内存管理、智能指针、现代C++、STL |
| **TypeScript** | 类型安全、前端工程化 | 类型系统、泛型、类型体操 |

### 前端框架

| 框架 | 特点 | 核心考察模块 |
|------|------|-------------|
| **JavaScript** | 前端核心、全栈必备 | 异步编程、事件循环、ES6+ |
| **Vue** | 渐进式框架、易学易用 | 响应式原理、Composition API |
| **React** | 生态丰富、社区活跃 | Hooks、Fiber、状态管理 |

### 工程岗位

| 岗位 | 特点 | 核心考察模块 |
|------|------|-------------|
| **DevOps** | 基础设施、自动化 | Docker、K8s、CI/CD、监控 |
| **测试开发** | 质量保障、自动化测试 | 单元测试、自动化、性能测试 |

### AI/算法岗位

| 岗位 | 特点 | 核心考察模块 |
|------|------|-------------|
| **大数据开发** | 海量数据处理、分布式计算 | Hadoop、Spark、Flink、Kafka |
| **大模型算法** | LLM、NLP、生成式AI | Transformer、RLHF、Prompt、RAG |
| **深度学习算法** | CV/NLP、模型优化 | CNN、RNN、Attention、模型部署 |

> 各语言/岗位的详细面试题库和强化训练示例见 `examples/` 目录。

## 核心能力

1. **智能生成面试题库** - 根据求职者背景和目标岗位生成针对性面试题
2. **多轮递进式面试** - 从基础到高级，逐级提升面试难度
3. **刻意训练追踪** - 记录每轮薄弱环节，持续强化直到精通
4. **飞书文档同步** - 所有面试内容实时保存到飞书 Wiki 文档

### 第二步：设计面试轮次（中大厂标准流程）

| 轮次 | 面试官 | 角色定位 | 考察重点 | 题目数量 |
|------|--------|---------|---------|---------|
| 第一面 | 直属 Leader / 同组同事 | 未来直接共事的同事 | 基础知识、编码能力、技术深度追问 | 25-30题 |
| 第二面 | 交叉团队 Leader / 分管领导 | 跨团队协作的负责人 | 系统设计、架构思维、问题解决能力 | 15-20题 |
| 第三面 | 技术 VP / 总监 / 技术负责人 | 技术决策者 | 综合素质、价值观、领导力、战略思维 | 10-15题 |
| 第四面 | HR / 薪酬谈判 | HRBP | 职业素养、薪资福利、职业规划、文化匹配 | 5-10题 |

### 第三步：执行面试

每轮面试包含两种模式：

**模式A：实战模拟（推荐新手）**
- 用户先独立回答每道题
- 大模型实时追问直到完全理解
- 记录每道题的掌握情况

**模式B：参考答案速刷**
- 直接展示参考答案
- 用户自主评级
- 针对薄弱点深入追问

### 第四步：创建掌握情况追踪表

在飞书文档开头创建表格：

| 题号 | 模块 | 掌握情况 | 备注（需加强的方面） |
|------|------|---------|---------------------|
| 001 | 数据结构 | 💪 熟练 | 树结构遍历不熟 |
| 002 | 并发编程 | ⚠️ 模糊 | 锁机制原理不清 |

**掌握情况等级定义：**
- `✅ 精通` - 底层原理清晰，可应对深度追问
- `💪 熟练` - 常用场景熟练，少量细节需提示
- `💡 一般` - 基础概念理解，复杂问题需指导
- `⚠️ 模糊` - 名词知晓，原理不清晰
- `❌ 不会` - 完全不了解，需从零学习

### 第五步：针对性强化训练

每轮结束后：

1. **识别薄弱点** - 从表格中筛选 `⚠️` 和 `❌` 项
2. **生成强化题** - 针对每个薄弱点生成 3-5 道递进式题目
3. **持续迭代** - 直到该知识点达到 `💪 熟练` 或 `✅ 精通`
4. **记录迭代** - 标注如「强化训练 001」「强化训练 002」

```
## 强化训练记录

### 强化训练 001（日期）
- 薄弱点：JVM 垃圾回收机制
- 训练题：
  1. 哪些对象会被认为是垃圾？引用计数和可达性分析的区别？
  2. Minor GC 和 Full GC 的触发条件？
  3. 对象的分配过程？TLAB 是什么？
  4. CMS 和 G1 收集器的区别？
  5. GC 停顿的原因？如何优化 GC 时间？
- 掌握情况提升：⚠️ 模糊 → 💪 熟练
```

### 第六步：晋级判断

当某一轮掌握率达到 **80% 熟练或精通** 时，可考虑：

- 进入下一轮更高级别面试
- 或继续强化当前轮次直到更高水平

```
## 晋级建议

本轮（Java 基础）第 1-15 题掌握情况：
- ✅ 精通：5 题
- 💪 熟练：10 题
- 💡 一般：8 题
- ⚠️ 模糊：4 题
- ❌ 不会：1 题

**建议**：薄弱点集中在「JVM 垃圾回收」和「并发编程」模块，建议进行一轮专项强化后再晋级。
```

## 使用示例

### 场景一：启动全新面试准备

**用户说：**
> "我是一名 3 年经验的 Java 后端工程师，想跳槽到字节跳动做后端开发，请帮我准备面试"

**技能执行：**
1. 收集用户基本信息（工作年限、技术栈、目标公司）
2. 分析目标岗位要求（从JD提取技术关键词）
3. 生成四轮面试计划
4. 在飞书文档创建求职信息和面试题库

---

### 场景二：第一面聚焦特定技术模块

**用户说：**
> "请帮我准备第一轮 Java 面试，主要考察 JVM、集合框架、并发编程，比如 HashMap 原理、JVM 内存区域、synchronized 和 ReentrantLock 区别等，生成 30 道题目到文档"

**技能执行：**
1. 按 Java 技术栈生成 30 道递进式面试题
2. 在飞书文档创建"掌握情况追踪表"
3. 每道题标注考察模块（JVM/集合/并发/Spring 等）
4. 准备参考答案供用户自评
5. 引用 `examples/java.md` 中的题库

---

### 场景三：进行实战模拟面试

**用户说：**
> "开始第一轮面试，我选择实战模拟模式，请出第一道题"

**技能执行：**
1. 展示第一道面试题
2. 用户回答后进行追问
3. 根据回答质量引导用户思考
4. 直到用户完全掌握该知识点
5. 记录该题掌握情况到追踪表

---

### 场景四：针对性强化训练

**用户说：**
> "上一轮面试中并发编程我答得很差（标记为模糊/不会），请针对这个模块进行强化训练"

**技能执行：**
1. 读取上一轮面试记录，定位薄弱点
2. 生成 5 道递进式强化题（从概念到源码）
3. 逐题讲解+追问，直到用户完全理解
4. 更新追踪表中该模块的掌握情况
5. 记录为"强化训练 001"

---

### 场景五：查看面试进度报告

**用户说：**
> "请根据之前的面试记录，生成一份掌握情况报告，并给出晋级建议"

**技能执行：**
1. 汇总所有轮次的掌握情况数据
2. 计算各模块掌握率
3. 生成可视化进度报告
4. 判断是否满足晋级条件
5. 给出下一轮面试重点建议

---

### 场景六：复盘上一轮面试

**用户说：**
> "请复盘我第一轮面试的表现，重点分析我哪些地方答得不好"

**技能执行：**
1. 回顾第一轮所有题目和回答
2. 识别所有"一般/模糊/不会"的题目
3. 分析错误原因（概念不清/理解偏差/完全不会）
4. 生成薄弱点清单
5. 制定下一轮强化训练计划

---

### 场景七：准备第二面（系统设计）

**用户说：**
> "第一面我掌握率达到了 85%，请帮我准备第二面，聚焦系统设计和架构"

**技能执行：**
1. 分析第一面薄弱点，确定是否需要强化
2. 调整面试重点到系统设计模块
3. 生成设计题（如：设计一个短链接系统）
4. 从多个维度考察（高可用、可扩展、一致性）
5. 在文档创建第二面记录区

---

### 场景八：HR面试准备

**用户说：**

**技能执行：**
1. 生成 HR 常问问题清单
2. 提供回答思路和话术建议
3. 模拟薪资谈判场景
4. 整理入职注意事项清单
