# WUION1011海信动作

## Inputs to collect

- **@Image1**:模特参考图(全程用"图1"代称,不描述五官/发型/服装/配饰)
- **@Image2**:场景参考图(全程用"图2"代称,不描述具体家具/装饰/电器)
- **参考视频**:用户上传的 .mp4 / .mov(本流程的唯一真实信源,所有时长/口播/动作/站位/电视画面均以视频本身为准)
- **目标文件名(可选)**:如用户给了"复刻<视频名>"之类的命名诉求,直接用;否则用参考视频文件名作为提示词文件主标题
- **附加约束(可选)**:用户可能在基础流程之上加新约束,必须显式落进最终提示词文件并刷新检查清单
- **基础强约束(默认必含,无需用户下达)**:
  - **强约束 12 站位精准复刻**:模特在场景中的站位严格参考视频,提供精准的 6 项站位描述(横向位置 / 纵向景别 / 身体朝向 / 与图 2 关键家具相对位置 / 是否被遮挡 / 是否变化)
  - **强约束 13 机位镜头对齐图 2**:机位和镜头必须跟场景参考图(图 2)完成对齐,百分百一致(相机位置 / 镜头焦段 / 视角高度 / 拍摄方向 / 镜头俯仰角)
  - **强约束 14 场景 100% 入框**:场景参考图(图 2)完全百分百入视频画面框内,任何家具/装饰/区域/边界不得被裁切
  - **强约束 15 电视画面满屏**:电视机播放画面必须 100% 满屏呈现于电视屏幕区域,无黑边/无信箱模式/无 UI 控件/无留白/无画中画

## Procedure

### Step 1｜探针:ffprobe 读取视频元数据

执行:
```bash
ffprobe -v error -show_format -show_streams <video>
```

记录到素材表:
- duration(format 容器级,精确到 0.01s)
- width × height
- fps(r_frame_rate)
- nb_frames
- codec(视频 + 音频)

原因:这一秒的 duration 是全篇时长锚点,所有分镜时长、口播、动作时间点必须锁死到这一刻度。**禁止沿用任何示例 / 历史 / MD 模板里的固定时长(如 5.50s、6.00s、8.00s 等)。**

### Step 2｜抽帧:逐帧观察用

执行:
```bash
ffmpeg -y -i <video> -vf "fps=2" frames/f_%03d.jpg
```

每 0.5s 一帧,共约 `duration × 2` 帧,落在 `frames/` 目录。

逐帧 `read` 图片,记录:
- 0.00s 初始站位(横向位置 / 纵向景别 / 身体朝向 / 与图2 关键家具的相对关系)
- 每个站位切换点的精确秒数
- 模特动作变化(为 0.20s 步长准备)
- 电视内画面切换点
- 任何口播同步嘴型变化(用于验证 ASR 时间戳)

原因:站位与动作变化必须由视频逐帧观察得出,任何硬编码字符串("电视正前方居中略偏右"之类)都视为反例。

### Step 3｜抽音(内部用,不交付)

执行:
```bash
ffmpeg -y -i <video> -vn -acodec pcm_s16le -ar 44100 -ac 2 /tmp/参考音频.wav
```

**注:此文件仅供 ASR 内部使用,最终交付物里不出现音频文件。** 提示词中如需引用,使用 `@参考音频.wav` 占位即可。

### Step 4｜口播转录(0.01s 精度句级时间戳)

工具(按需选择):
- `connector__matrix__listen_audio`:适合整段转录,返回单段时间戳
- `connector__matrix__audios_understand`:支持自定义 prompt 拆句,适合强制 0.01s 精度

调用流程:
1. 用 `mcode-tools upload_temp_url <wav>` 把 wav 上传,拿 temp_url
2. listen_audio / audios_understand 调一次,verbatim 中文转录
3. 若返回时间戳精度不够,二次调 audios_understand,prompt 写"按自然换气点拆段,逐句给 0.01s 起止秒"
4. 拆分原则:每个标点 / 换气点都尽量按独立子句;但若 audios_understand 自然合并了 2-3 个语义连贯的短句,保留合并版本(分镜数 = ASR 段数,无需硬拆)

**句数 N = 分镜数**,直接落表。

### Step 5｜站位复刻(独立步骤,不可省,6 项精准字段)

基于 Step 2 抽出的帧,逐帧观察并记录 **6 项精准字段**(全部基于参考视频逐帧实测,禁止硬编码):

1. **横向位置**:画面 X% 位置 / 左 1/3 / 居中 / 右 1/3 / 居中略偏左 / 居中略偏右 / 正中
2. **纵向景别**:前景 / 中景 / 中近景 / 远景 / 全景
3. **身体朝向**:正对镜头 / 侧对镜头(左/右)/ 斜对镜头 / 背对镜头
4. **与图 2 关键家具的相对位置**:电视 / 沙发 / 茶几 / 吊柜等的左/右/正前方关系 + 距离 ~X 米
5. **是否被遮挡**:完全可见 / 被家具部分遮挡(遮挡部位)/ 完全不可见
6. **是否变化**:稳定不动 / 切换点

把这套"实测站位(6 项字段齐全)"写进"画面内容"和"人物动作时间线"的 0.00s 起点行;后续时间点只写动作变化,不再重复站位(除非站位有变,此时要刷新全部 6 项字段)。

### Step 6｜生成 7 段式结构

完整结构骨架(`references/output-template.md` 含详细占位):

| 段 | 内容 |
|---|---|
| 一、素材与范围 | 视频元数据 + 音频 + 模特/场景 + 机位 + 模特动作时间点间隔 + 站位来源 + 口播段数 + 分镜数 + **E12 站位精准复刻** + **E13 机位镜头对齐图 2** + **E14 场景 100% 入框** + **E15 电视画面满屏** + 任何用户附加约束 |
| 二、镜头与电视内容拆解 | N 个分镜(等于 ASR 段数),每镜一张表:0.00s 起点站位(6 项精准字段) + 0.20s 步长时间轴 + 电视内画面(满屏) + 口播 |
| 三、元素变更与文字清理表 | E01-E16(基础 11 条强约束 E01-E11 + 新强约束 4 条 E12-E15 + 用户附加约束 E16) + T01-T15(字幕条 / 标题贴纸 / 角标 / Logo / 电视内字幕 / 电视内角标 / 闪白闪屏 / 视频内贴纸 / 字幕覆盖 / 视频内对话框 / 角标小动画 / 视频内水印 / 反光倒影 / 道具 / 装饰) |
| 四、<视频文件名>直贴版提示词 | 基础引用 / 核心参数 / 完整提示词 / **完整提示词正文(10 个子模块,可独立直接复制:@Image1 / @Image2 / 画面内容 / 人物动作时间线 / 电视画面内容时间线 / 口播音频对齐 / 运镜 / 环境细节 / 文字清理 / 精准强约束清单)**。**完整提示词正文子模块骨架已抽出为独立可复制文件 `references/complete-prompt-body.md`——代码块围栏已去掉,任何环境打开直接选中即可整段复制** |
| 五、交付检查清单 | 24 条强制勾选项(前 17 条基础 + 4 条新强约束 12-15 + 1 条独立复制 + 2 条用户附加约束占位) |

完整提示词正文必须满足的 8 条硬性写法(详见 `references/output-template.md` 与独立骨架文件 `references/complete-prompt-body.md`):
1. 全程用"图1"代称模特、"图2"代称场景
2. 站位字段必须使用 Step 5 的实测描述(6 项精准字段齐全),非硬编码
3. 口播 verbatim 转录,0.01s 时间戳
4. 模特动作时间点必须按 0.20s 步长逐点列出(0.00s–最后一档 ≤ duration)
5. 电视画面时间线 0.01s 精度,与模特动作严格对齐,且**每条电视内画面都要显式标注"满屏"**
6. 运镜段必须显式声明"机位和镜头必须跟场景参考图(图 2)完成对齐,百分百一致,固定机位无任何镜头运动";若分镜中存在画面裁切/硬切,需注明是"画面裁切变化,非运镜"
7. 文字清理段必须穷举视频原带的所有文字(旁白条、贴纸、角标、Logo、对话框、叠字、水印等),并显式声明"任务交付时一律不出现"
8. **新增**:精准强约束清单(子块 10)必须含强约束 12-15 全部 4 条,每条带子规则、覆盖范围、失败判定;**完整提示词正文必须格式自包含、可独立直接复制贴入 Sora / MiniMax-H3 / Veo / 可灵等 AI 视频生成工具使用,不依赖前文素材表/分镜表/元素表/检查清单**

## Failure handling

- **ffprobe 失败 / 视频损坏**:停止流程,告知用户视频无法读取,请重新上传
- **音频抽离成功但 ASR 失败**:重试 1 次,仍失败则用占位文字"口播内容待人工标注"并把所有分镜的口播字段留空,继续走流程但在检查清单中标记 ASR 失败
- **ASR 段数过少(整段被合并为 1 段)**:用 audios_understand 二次调用,prompt 强制"按自然换气点拆段";若仍合并,接受现状但提醒用户"分镜仅 1 镜,可能与预期不符"
- **ASR 段数过多(每字一段)**:合并相邻短句,合并后单段不超过 4 秒
- **站位描述与图2 严重冲突**(如用户在图2 是横向客厅,视频里却是竖向):以视频为准,在素材表加一行"站位来源:视频逐帧实测,可能与图2 整体构图存在差异,以视频为最终基准"
- **字数超 6800**:按 Step 7 优先级精简,绝不删除时间点 / 口播文本 / 检查清单;**优先精简"二、镜头与电视内容拆解"中重复的描述性字段,完整提示词正文 10 个子模块的核心字段(6 项站位、机位、场景入框、电视满屏、运镜、环境细节、文字清理、强约束清单)不可精简**
- **站位实测后 6 项字段无法完整判定**(如镜头遮挡无法判断相对位置):在素材表加一行"站位字段缺失:<字段名>原因:<原因>";在画面内容段对该字段显式标注"<字段名>:<因 <原因> 无法判定,以视频为最终基准>"
- **机位与图 2 偏差无法用文字描述**:在"运镜"段补一句"机位和镜头必须跟场景参考图(图 2)完成对齐,百分百一致;若图 2 与视频整体机位存在固有差异,以图 2 为最终基准"
- **场景 100% 入框但视频画幅与图 2 不一致**:在素材表加一行"画幅差异:视频画幅 <W1>×<H1>,图 2 画幅 <W2>×<H2>,以图 2 为最终基准,需在提示词中显式声明画幅比例"
- **电视画面不满屏但用户强约束要求满屏**:在"电视画面内容时间线"段每条都加"[满屏]"前缀;在"环境细节"段显式声明"电视内播放画面 100% 满屏";在"精准强约束清单"子块 15 的每条子规则都要落到具体时间点
- **新强约束 12-15 的"四同步"未刷新**:在交付前对照检查清单 4 条新约束检查项(E12 / E13 / E14 / E15)逐一验证,任何一条缺失必须回退到对应段落补齐后再交付
- **用户附加新约束**:在素材表新增一行 + 在完整提示词正文新增"XX 规则(强约束)"子块 + 在元素表新增 E16+ 行 + 在检查清单新增 ≥ 2 条;**禁止只改一处而不刷新其他三处**

### Example 2:典型失败模式(避免)

- ❌ 直接套用 5.50s 或 6.00s 固定时长(违反强约束 1)

- ❌ 站位写死"电视正前方居中略偏右"(违反 Step 5 站位复刻 6 项精准字段)

- ❌ **完整提示词正文引用前文素材表/分镜表/元素表/检查清单的变量(如"见上文"、"详见 N 镜"、"参见 E07"),违反"格式自包含、可独立直接复制"**
