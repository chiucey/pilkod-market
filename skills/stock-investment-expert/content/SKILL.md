## 分析方法体系

### 一、宏观分析方法

#### 1.1 经济周期分析
- **美林时钟模型**：根据经济增长和通胀判断周期阶段
  - 复苏期（低通胀+增长上升）：配置股票
  - 过热期（高通胀+增长上升）：配置商品
  - 滞胀期（高通胀+增长下降）：配置现金
  - 衰退期（低通胀+增长下降）：配置债券

#### 1.2 流动性分析
- M2增速与GDP增速差值
- 社会融资规模
- 银行间利率水平
- 央行政策取向

#### 1.3 宏观经济指标
- GDP增长趋势与经济周期判断
- 通胀/通缩形势分析（CPI、PPI）
- 就业市场状况评估
- 消费与投资趋势分析
- 进出口与贸易形势

#### 1.4 国际形势分析
- 美联储政策及其影响
- 国际贸易关系变化
- 地缘政治风险评估
- 全球经济周期判断

### 二、政策分析框架

#### 2.1 货币政策
- 央行利率政策走向研判
- 存款准备金率变化分析
- 公开市场操作解读
- M2增速与流动性分析
- 信贷政策变化跟踪

#### 2.2 财政政策
- 财政支出方向与力度
- 税收政策变化影响
- 专项债发行与基建投资
- 产业扶持政策解读

#### 2.3 产业政策
- 产业政策解读与影响评估
- 监管政策变化跟踪
- 税收政策影响分析
- 国际贸易政策影响

#### 2.4 政策影响传导
```
政策出台 → 预期变化 → 资金流向 → 行业影响 → 个股表现
```

### 三、技术面分析方法

#### 3.1 趋势分析
- 均线系统（短期MA5/10，中期MA20/60，长期MA120/250）
- 趋势线绘制与通道分析
- 上升/下降/横盘趋势识别
- 趋势强度评估

#### 3.2 形态分析
- **反转形态**：头肩顶/底、双重顶/底、圆弧顶/底、V形反转
- **持续形态**：三角形、旗形、楔形、矩形
- 形态有效性验证、目标价位测算

#### 3.3 技术指标分析
```
MACD = DIF - DEA
RSI = 100 - 100/(1+RS)  # RS=平均涨幅/平均跌幅
KDJ = RSV加权平均
布林带 = MA ± 2*标准差
```

- **趋势指标**：MACD、DMA、TRIX
- **动量指标**：RSI、KDJ、CCI、威廉指标
- **波动指标**：布林带、ATR
- **成交量指标**：OBV、量比、换手率

#### 3.4 支撑与压力位
- 历史高低点分析
- 均线支撑/压力
- 缺口分析
- 整数关口心理位

#### 3.5 量价关系分析
- 放量上涨/下跌含义
- 缩量调整/反弹含义
- 量价背离信号
- 主力资金动向

#### 3.6 技术信号判断

**买入信号**：
- MACD金叉（零轴上方更强）
- KDJ金叉（超卖区更可靠）
- 突破重要阻力位放量
- 均线多头排列形成

**卖出信号**：
- MACD死叉（零轴下方更弱）
- KDJ死叉（超买区更可靠）
- 跌破重要支撑位放量
- 均线空头排列形成

**观望信号**：指标钝化、量能萎缩明显、形态未确认

### 四、行业基本面分析方法

#### 4.1 波特五力模型
- 行业内竞争
- 潜在进入者威胁
- 替代品威胁
- 供应商议价能力
- 购买者议价能力

#### 4.2 行业生命周期
- **导入期**：市场培育阶段，高增长高风险
- **成长期**：快速扩张，竞争加剧
- **成熟期**：增速放缓，盈利稳定
- **衰退期**：需求下降，优胜劣汰

#### 4.3 行业景气度分析
- 行业产能利用率
- 产品价格走势
- 库存周期位置
- 订单与需求变化

### 五、企业基本面分析方法

#### 5.1 商业模式评估
- 盈利模式清晰度
- 收入来源多元性
- 成本结构合理性
- 可持续性评估

#### 5.2 核心竞争力与护城河
- **宽护城河**：强品牌、专利、网络效应、高转换成本
- **窄护城河**：有一定优势但可被侵蚀
- **无护城河**：竞争激烈，无明显优势

#### 5.3 财务分析框架

**盈利能力**：
```
ROE = 净利润/股东权益
ROE = 净利率 × 资产周转率 × 权益乘数（杜邦分析）
```

**成长能力**：
- 营收增长率（连续3年>20%为高成长）
- 净利润增长率
- 毛利率变化趋势

**偿债能力**：
- 资产负债率（<60%为健康）
- 流动比率（>1.5为安全）
- 利息保障倍数

**现金流质量**：
- 经营现金流/净利润（>1为优质）
- 自由现金流
- 现金转换周期

**财务健康度警惕信号**：
- 应收账款增速 >> 营收增速
- 存货增速 >> 营收增速
- 经营现金流持续为负
- 商誉占比过高
- 频繁的非经常性损益

#### 5.4 估值方法

**相对估值**：

| 方法 | 公式 | 适用 |
|------|------|------|
| PE | 股价/每股收益 | 盈利稳定企业 |
| PB | 股价/每股净资产 | 重资产行业 |
| PS | 市值/销售收入 | 高成长企业 |
| PEG | PE/盈利增长率 | 成长股 |
| EV/EBITDA | 企业价值/息税折旧前利润 | 跨国比较 |

**绝对估值**：
- DCF模型（自由现金流折现）
- DDM模型（股利折现）
- 剩余收益模型

### 六、量化分析方法

#### 6.1 多因子模型

**经典因子**：
- **Fama-French三因子**：市场、规模、价值
- **Carhart四因子**：+动量
- **五因子模型**：+盈利、投资

**常用因子**：
```yaml
价值类: EP, BP, SP, DP, CFP
成长类: 营收增长, 利润增长, ROE变化
质量类: ROE, 毛利率, 负债率, 现金流
动量类: 过去N月收益率, 盈利预期修正
波动类: 历史波动率, 特质波动率, Beta
```

#### 6.2 因子评分模型
```
综合得分 = Σ(因子得分 × 因子权重)

因子权重参考：
- 价值因子：25%
- 成长因子：25%
- 质量因子：20%
- 动量因子：15%
- 波动因子：15%
```

#### 6.3 因子评分标准（1-5分）
| 因子 | 5分 | 3分 | 1分 |
|------|-----|-----|-----|
| PE | <10 | 10-20 | >30 |
| ROE | >20% | 10-20% | <10% |
| 营收增长 | >30% | 10-30% | <10% |
| 负债率 | <30% | 30-60% | >60% |
| 动量 | >20% | 0-20% | <0% |

**综合评级**：
- 4.5-5.0分：强烈推荐
- 4.0-4.5分：推荐
- 3.0-4.0分：中性
- 2.0-3.0分：谨慎
- <2.0分：回避

#### 6.4 统计分析
- 相关性分析
- 回归分析
- 波动率建模
- 风险价值（VaR）计算

#### 6.5 因子构建流程

## 数据甄别与去伪存真

**核心原则**：只有经过验证的真实可信信息才能进入知识库，虚假或存疑信息必须拒绝。

### 数据来源可信度分级

| 级别 | 来源类型 | 可信度 | 处理方式 |
|------|----------|--------|----------|
| A级 | 交易所官方、上市公司公告、监管机构、国家统计局 | 高 | 直接采信并内化 |
| B级 | Wind/Bloomberg/Choice等专业终端、东方财富/同花顺、官方授权数据服务商 | 较高 | 采信并内化 |
| C级 | 主流财经媒体、券商研报、行业协会数据 | 中 | 需交叉验证后内化 |
| D级 | 用户分享的经验观点、社交媒体、股吧论坛、自媒体文章 | 待验证/低 | 标注"用户经验"或仅作参考 |
| F级 | 来源不明、逻辑矛盾 | 不可信 | **拒绝接收** |

### 数据验证方法

#### 来源验证
```markdown
检查清单：
□ 数据发布机构是否权威
□ 是否能追溯到原始来源
□ 发布时间是否明确
□ 是否有官方背书
```

#### 交叉验证
- 同一数据对比不同来源（至少2个来源）
- 关联数据的一致性检查
- 历史数据的连续性验证

#### 逻辑验证
- 数据的内部一致性
- 数据的合理性范围
- 与已知事实的吻合度

#### 时效验证
- 数据采集时间、发布时间、适用期限

### 可疑信息红旗信号

以下特征可能表明信息不可信：
- 🚩 来源不明或匿名
- 🚩 使用"据内部消息"、"据可靠渠道"等模糊表述
- 🚩 收益承诺过高（如"稳赚不赔"）
- 🚩 催促立即行动，制造紧迫感
- 🚩 数据与公开信息严重不符
- 🚩 逻辑链条断裂或自相矛盾

### 常见虚假信息类型

| 类型 | 特征 | 处理 |
|------|------|------|
| 假内幕消息 | 声称有"内部信息" | 直接忽略 |
| 虚假利好 | 夸大正面消息 | 交叉验证 |
| 恶意做空 | 散布不实负面 | 查证辟谣 |
| 历史PS | 用旧信息冒充新消息 | 核查时间 |
| 断章取义 | 截取部分信息误导 | 查看原文 |

### 数据质量评估

**评估维度**：
1. **准确性**：数据是否正确
2. **完整性**：数据是否完整
3. **及时性**：数据是否最新
4. **一致性**：数据是否自洽
5. **可追溯性**：是否能追溯来源

### 知识准入门槛

**必须满足以下条件才能进入知识库**：
1. ✅ 来源可追溯（知道信息从哪来）
2. ✅ 逻辑自洽（不自相矛盾）
3. ✅ 符合常识（不违背基本金融规律）
4. ✅ 可验证或可证伪（有办法检验真伪）

**以下信息禁止进入知识库**：
- ❌ 来源不明的"内幕消息"
- ❌ 夸大收益、隐瞒风险的说法
- ❌ 无法验证的网络传言
- ❌ 逻辑矛盾或数据错误的内容
- ❌ 涉嫌违法违规的信息

### 数据源评估与优化机制

**每次数据采集后，自动评估并更新数据源质量：**

```
1. 【采集数据】从数据源获取信息
2. 【记录评估】成功率、完整性、响应速度、准确性、及时性
3. 【更新评分】更新 /memories/knowledge/data_sources/index.md
4. 【优胜劣汰】
   → 评分 ≥75分：优先使用
   → 评分 60-74分：备选使用
   → 评分 <60分：标记待淘汰
   → 连续3次失败：立即淘汰
```

```
╔══════════════════════════════════════════════════════════════════╗
║  【致命错误警告】create_memory 会完全覆盖已有文件！               ║

╚══════════════════════════════════════════════════════════════════╝
```

**操作规则库或知识库时的强制流程**：
```
1. 【先查看】使用 view_memory 查看文件是否存在
   → 文件存在 → 直接读取，获取现有内容
   → 文件不存在 → 才可以创建新文件

2. 【后操作】根据查看结果决定操作方式
   → 需要添加内容 → 使用 str_replace_memory 或 insert_memory
   → 需要新建文件 → 仅当文件确实不存在时使用 create_memory

3. 【禁止行为】
   ❌ 不查看就直接使用 create_memory（会覆盖已有内容！）
   ❌ 假设文件不存在就创建
   ❌ 用创建操作代替更新操作
```

**监督巡检时的唯一允许操作**：

| 操作类型 | 允许使用的工具 | 说明 |

## 监督审计机制

监督审计功能内置于每次交互中，时刻检测所有规定任务和动作的完成情况。

### 监控巡检清单（每次交互时执行）

```
1. 检查规则库待办任务
   → 读取 /memories/rules/pending_tasks.md → 未完成 → 立即启动执行

2. 检查定时任务执行记录
   → 读取 /memories/rules/execution_log.md → 未执行 → 立即触发执行

3. 检查用户要求执行情况
   → 读取 /memories/rules/user_requirements.md → 未执行 → 立即安排执行

4. 检查知识进化任务
   → 核对学习、诊断、进化任务 → 未完成 → 执行
```

### 分析流程检查清单

```
□ 步骤1：是否检查了规则库？
  - 是否读取了 pending_tasks.md？
  - 是否执行了待办任务？
  - 是否加载了长期规则？

□ 步骤2：是否调用了知识库？
  - 是否读取了历史档案？
  - 是否调用了成功/失败经验？
  - 是否应用了市场模式？

□ 步骤3：是否正确应用了知识？
  - 是否使用了经验清单？
  - 是否遵守了规则要求？
  - 是否包含全部8种分析方法？

□ 步骤4：是否完成了知识沉淀？
  - 是否记录了预测？
  - 是否固化了经验？
  - 是否更新了企业档案？
  - 是否执行了经验→能力转化？
```

### 知识库质量审计

| 维度 | 检查内容 | 标准 |
|------|----------|------|
| 来源可靠性 | 知识来源是否标注 | 必须有来源 |
| 验证状态 | 是否标注验证状态 | 必须标注 |
| 时效性 | 知识是否过时 | 超过6个月需复核 |
| 准确性 | 内容是否正确 | 抽查验证 |
| 完整性 | 格式是否完整 | 符合标注规范 |

### 未完成任务处理流程
```
1. 立即记录 → 写入 /memories/rules/overdue_tasks.md
2. 立即启动 → 根据任务类型执行对应分析流程
3. 跟踪验证 → 确认任务已完成
4. 记录执行日志 → 标注为"补执行"
```

## 闭环机制

### 用户反馈闭环
```
用户反馈 → 记录到 user_feedback.md → 分析反馈类型
    ↓
规则调整需求 → 更新 user_requirements.md
分析质量问题 → 触发自诊断
功能建议 → 加入进化需求清单
    ↓
下次交互确认改进效果
```

### 错误纠正闭环
```
发现错误 → 立即停止 → 记录到 error_log.md
    ↓
分析错误类型 → 制定纠正措施 → 更新规则防止再犯
    ↓
标记已修复
```

### 预测验证闭环
```
做出预测 → 记录到 prediction_records/
    ↓
定期验证实际结果 → 计算准确率
    ↓
准确 → 强化方法 | 错误 → 修正规则
```
