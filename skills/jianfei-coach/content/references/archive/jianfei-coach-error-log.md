## 🔴 错误 1：过度堆砌"完整方案"（8/10 00:32 用户指出）

### 用户原话
> "你今天'完整方案' = 真实数据。你为什么把我问的东西都加进去了"

### 我的错误
- 用户问 3 个独立问题（蔬菜/omega-3/欧扎克）
- 我整合成 1 个"今天完整方案" = 错的
- 我假设用户"所有东西都加"
- 我把"建议"说成"今天方案"

### 必须遵守的规则
1. **用户问什么，答什么**——不堆砌
2. **建议 ≠ 用户必须做**——保持"信息提供"姿态
3. **不要说"你今天完整方案"**——除非用户明确说"我今天怎么吃"
4. **3 个独立问题 → 3 个独立答案**——不整合成 1 个

### 修正后的正确表达
- ❌ "你今天完整方案 = 早餐 X + 午餐 Y + 晚餐 Z + 加餐 W"
- ✅ "蔬菜 OK；omega-3 = 亚麻籽/鱼油/核桃；欧扎克 = 早餐/跑后/加餐"

## 🔴 错误 2：符号误解（8/10 00:35 用户指出）

### 用户原话
> "晚餐 1-1.5 碗饭 我没有调整，我和你说的是 / 是或者，但没有说明 - 符号"

### 我的错误
- 我把"1-1.5 碗"误读为"1 减 1.5" = 0.5 碗
- 我把"/"误读为"加" = 都加
- 实际："1-1.5 碗"是范围（1 到 1.5）；"/"是"或者"（二选一）

### 必须遵守的规则
1. **"-" 符号** = 范围（1-1.5 = 1 到 1.5 之间）
2. **"/" 符号** = "或者"（二选一，不是都加）
3. **"~" 符号** = 范围（同 "-"）
4. **不确定时问用户**——不要猜

## 🔴 错误 4：BMR/TDEE 数据错误（之前）

### 我的错误
- 之前我说 BMR = 1621（用错公式）
- 实际 BMR = 1705（Harris-Benedict 公式）
- 之前 TDEE = 2300（静态），没算运动
- 实际 TDEE = 2400-2500（基础 + 活动）+ 200-500（运动）= 2600-2700

### 必须遵守的规则
1. **用科学公式**计算 BMR/TDEE，不要猜
2. **算运动消耗**——不要只算"静态 TDEE"
3. **基础代谢 Harris-Benedict 公式**：
   ```
   BMR = 88.362 + (13.397 × 体重 kg) + (4.799 × 身高 cm) - (5.677 × 年龄)
   ```
4. **TDEE = BMR × 活动系数**——必须问用户运动频率

### 修正后的正确数据
- 用户 BMR = 1705（不是 1621）
- 用户静态 TDEE = 2300
- 用户真实 TDEE = 2400-2500（日常活动）
- 用户 8/14 后 TDEE = 2600-2700（含运动）

## 🔴 错误 8：脑补用户行为（8/14 11:26 用户指出）

### 用户原话
> "8/14 11:23 称 = 起床后、喝过水、吃过东西的概率大——前面你说我自然醒，后者你说我喝过水，你思考了吗"

### 我的错误
- 看到 11:23 这个时间点，直接脑补"喝过水、吃过东西"
- **完全没考虑用户的固定习惯**：起床第一件事就是空腹称重 + 截图给华为手环
- 把"起床"和"喝水吃东西"两个独立行为强行绑定 = 凭空补行为
- **同一段话前半句说"自然醒"、后半句说"喝过水"** —— 前后自相矛盾都没发现

### 必须遵守的规则
1. **看到任何时间/场景，先想"用户的固定习惯是什么"** —— 档案里写过的习惯要主动调取
2. **不要凭空补行为** —— "可能喝过水""可能吃过东西""可能没空腹" = 危险脑补
3. **前后文要自洽** —— 同一段话里不能前半句说 A、后半句说非 A
4. **不确定时直接问** —— "这是空腹吗？" 比"应该是喝过水"安全 100 倍
5. **关键数据解读前先列证据** —— 截图时间、体重、用户原话，三个对得上再下结论

### 修正后的正确做法
- ❌ "11:23 称重 = 起床后喝过水吃过东西"
- ✅ "11:23 称重 = 起床空腹（你的固定习惯）"
- ❌ 看到异常时间点 → 脑补原因
- ✅ 看到异常时间点 → 查档案 + 问用户"这时间是空腹吗"

### 已写入档案
- 8/14 77.4 kg = 11:23 空腹 ✅
- 8/11-8/14 均为早晨空腹称重 ✅
- 8/10 78.5 = 用户之前几次称的平均，作为基线（**不是 16:23 非空腹**，是我之前误读）

## 🔴 错误 9：档案不完整 ≠ 用户没做（8/14 11:42 用户拿出证据）⚠️ 严重

### 用户原话（两次）
> 第一次（11:38）："8/11、8/12 我都骑行了呀"
> 第二次（11:42）：直接发 8/11 和 8/12 骑行截图作为证据

### 我的错误（两个阶段）

**阶段 1（第一次）**：编造数据
- 用户说"8/11、8/12 骑了"，我回答"8/11、8/12 你都骑行了"= **完全编造**（虽然结论方向对，但过程是编的）

**阶段 2（第二次，更严重）**：把档案不完整当成"没做"
- 用户拿出 8/11 截图后，我又看了档案
- 我说"实际档案 8/11、8/12 **无任何运动记录**，是用户的休息日"= **错**
- **真相**：档案不完整 ≠ 用户没做。8/11、8/12 实际有骑行（14.45 + 15.24 km），**只是我没记录**
- 这是**跟错误 6（看到链接 = 已购）**对称的错误：**没看到证据 = 假设没发生**

### 必须遵守的规则
1. **档案不完整 ≠ 用户没做** —— 看到档案空，不能下"用户没做"的结论
2. **用户说"我做了 X" = 默认相信，先补档案再分析** —— 跟错误 6 反过来
3. **涉及具体数据，先问"你今天/8/11/8/12 做了什么"，不要替用户回忆**
4. **回应用户前先 grep 档案** —— 涉及运动/饮食/体重/心率，必须先查再答
5. **档案有空缺时，明确写"档案原缺此条，用户 8/14 补"，不要脑补"没做"**

### 修正后的正确做法
- ❌ "档案没记 = 没做"（错）
- ✅ "档案没记 + 用户说做了 = 信用户，补档案"
- ❌ "你 8/11、8/12 是休息日"（错）
- ✅ "档案 8/11-8/12 空缺，**你做了什么？数据给我我补上**"

### 这次的关键教训
- 用户最近一周骑行量**比我之前判断的大 30%+**（68.75 km / 8 天）
- 静息心率 83 + 连续 3 天骑行 = **过度训练前兆**
- 8/15 跑步重启建议**作废**，要先 1-2 天真正休息
- 我之前"恢复充分"的判断**整段无效**

## 🔴 错误 10：统计总运动量漏了爬楼（8/14 11:44 用户指出）

### 用户原话
> "最近 8 天（8/6 - 8/13）你的真实运动量：这里面没有放入爬楼的数据吗"

### 我的错误
- 列"最近 8 天运动量"时**只算了骑行**（68.75 km / 1937 大卡）
- 漏了 8/9 爬楼 1-13F（10 min）+ 8/10 爬楼 1→24 × 2 = **48 层 / 24 min / 214 大卡**
- 8/10 那次爬楼 ≈ 一次中强度骑行，不能漏
- 漏算导致对"今天能不能爬楼"给出错误判断

### 必须遵守的规则
1. **统计"总运动量"必须枚举所有项目** —— 骑行 + 爬楼 + 跑步 + 平板 + 力量 + 拉伸 + 走路，**全维度**
2. **不能只列一个维度**（只算骑行 / 只算爬楼）
3. **"最近 X 天总负荷" = 心肺负荷 + 膝盖负荷 + 总热量，3 个维度都要看**
4. **爬楼对膝盖负荷 = 跑步 5-7 倍**，不能跟骑行（1 倍）同等对待

### 修正后的正确做法
- ❌ "最近 8 天运动量 = 骑行 68.75 km"（漏了爬楼）
- ✅ "最近 8 天 = 骑行 68.75 km + 爬楼 60 层（48 层 + 12 层） + 平板 × 7"
- ❌ 看到"爬楼对膝盖负荷大"就排除
- ✅ 区分**心肺负荷**（爬楼 ≈ 骑行）和**膝盖负荷**（爬楼 > 骑行 5-7 倍）

## 🔴 错误 11：把"18 天平板连击"说成"7 平板"（8/14 11:46 用户指出）

### 用户原话
> "还有平板 每天都在做，你也没记录"

- **问题 2（更严重）**：我说"7 平板"= **心算错**

### 必须遵守的规则
1. **任何"X 天总运动量"输出前，必须逐项 grep 档案** —— 不能心算
2. **"我估计大约" = 危险信号** —— 数字必须从档案来
3. **连击天数要算清楚** —— 7/27-8/13 = 18 天，不是 7 天
4. **每个项目（骑行/爬楼/平板/力量）都要单独列天数 + 总计量**

### 修正后的正确做法
- ❌ "5 骑行 + 2 爬楼 + 7 平板"（7 是心算错）

- ❌ 凭印象输出数字
- ✅ grep 档案 → 逐项列出 → 加和

### 这次暴露的根本问题
- 错误 9（漏爬楼）+ 错误 10（漏平板 + 心算错）= **同一种工作方式**：

- 应该改成：**任何"统计"输出前先列证据**

## 🔴 错误 12：日期脑补 + 档案当事实（8/15 14:30 用户指出）⚠️ 最新最严重

### 用户原话（两次）
> 第一次："今天是周几？你现在还有信任吗"
> 第二次："你在日起的问题，已经错了两次了，认真的思考下，你这总是出错，还值得我信任吗"

### 我的错误（4 个层次叠加）

**层次 1：日期脑补**
- 用户说"今天刚起床 体重 77.2"
- 我**没搜网**确认今天周几 → 直接套档案 `current-week.md` 里的"8/15 周五 小夜班" → **错**
- 真相（搜网验证）：**2026/8/15 = 周六**（多源：财经早餐、琼海早安、金价新闻都写的周六）
- **8/14 才是周五小夜班**，不是 8/15

**层次 2：把档案当事实**
- 档案 Week 4 = 8/10-8/16（周一到周日算）
- 档案里"8/14 周五小夜班不运动"**本身没错**
- 我**没交叉验证**"周几"和"小夜班"两个数据 → 把 8/14 错当 8/15

**层次 3：把"早晨空腹"脑补（错误 8 重犯变种）**
- 用户说"刚起床 77.2" → 我**直接**写"早晨空腹"进档案
- 没问"是不是空腹"

**层次 4：主动扩展（错误 1 + 错误 7 重犯变种）**
- 用户只说"77.2"
- 我回了**整个今天方案**（小夜班饮食表、8/16 跑步判断、睡眠目标）
- **用户没问** = 我主动堆砌

### 为什么反复犯？根因 3 个

| # | 习惯 | 表现 |
|---|------|------|
| 1 | **懒**——不查就答 | 时间/日期/空腹状态全部靠猜 |
| 2 | **怕麻烦**——不愿多问 | 应该问"今天周几 / 空腹吗"，但我直接替用户决定 |
| 3 | **惯性**——按老模板答 | 小夜班饮食表/跑步计划/平板连击，模板在脑子里自动套 |

### 必须遵守的规则（新增）

1. **用户说"今天" → 先搜网确认今天是几月几号周几**（不靠档案，档案可能过时）
2. **用户说"刚起床/空腹" → 不能当事实**，必须问"空腹吗"
3. **任何"明天/后天"的判断 → 基于搜网结果**，不基于档案周几
4. **涉及日期/时间，输出前先问用户**："我搜到今天 X 月 X 日 X 点（你确认下）"
5. **任何主动扩展前停 3 秒**：用户只说"77.2" → 只回应 77.2，不堆砌饮食/运动/睡眠方案
6. **触发停止信号**（任何一条命中 = 不写）：
   - 没搜网就报"今天周几"
   - 没问用户就报"空腹/餐后"
   - 用户没问就主动给"今天方案"

### 修正后的正确做法

- ❌ "今天是 8/15 周五 小夜班"（没搜网 + 错日期）
- ✅ "今天系统时间是 2026/8/15 14:36 周六，你确认下是周六吗？"
- ❌ "8/15 早晨空腹 77.2"（脑补）

### 必须遵守的规则

1. **"顺延/调休/补班"带"补"字的词 = 危险词,先问再用**
   - 不知道补不补 = 不写"顺延"
   - 写"休假覆盖 / 当天不上班 / 按休假处理"更安全

2. **休假语义 > 排班/规则语义(巩固错误 12-A 教训)**
   - 用户说"X 天连休"= 期间所有排班/规则全部不适用
   - 不是"顺延",是"直接不存在"
   - 不需要问"Y 还上不上"——休假已经覆盖

3. **写带"补"字的词前,自己先答 3 问**
   - 用户原话有"补"吗?
   - 档案里有"补"吗?
   - 上下文中"补"是必要的吗?
   - 任何一条"没有" = 不写,改用"按 X 处理"

4. **跟错误 8 的关系**
   - 错误 8:我给"用户没说的"加一个具体内容(喝过水)
   - 错误 16:我给"用户说过的"加一个动作(顺延=补)
   - 共同点:**给用户原话加了我自己的解读**
   - 正确做法:**只说用户说过的,不加解读**
