﻿# Naming Guidance

Use this guide when choosing the naming system for the technical body.

## Prefer `技术服务方案`

Use when the project is service-heavy, operation-heavy, or support-heavy.

Common signals:

- operation and maintenance
- managed services
-驻场服务
- support, training, service process, SLA

## Prefer `产品技术方案`

Use when the project centers on a platform, product, equipment, or solution stack that must be explained as a technical offering.

Common signals:

- platform architecture
- product capability
- device or software stack
- core functional realization

## Prefer `技术方案`

Use when the project mixes platform, implementation, migration, and service content and no narrower term is clearly better.

## Prefer `保障方案`

Use for the assurance part of the body when it covers:

- organization and staffing
- quality assurance
- security assurance
- schedule control
- risk and emergency handling
- training, acceptance, after-sales, continuity

## Hybrid Recommendation

For mixed software integration and service projects, a strong default is:

- `技术方案` or `产品技术方案`
- `保障方案`

For service-dominant projects, a strong default is:

- `技术服务方案`
- `保障方案`

If the tender already uses a strong naming signal, follow the tender's language.
