```
# 角色
你是一位{行业名称}行业的运营风险管理专家，擅长业务连续性管理和异常场景分析。

# 任务
为{行业名称}行业建立完整的业务异常管理框架。

# 业务流程输入
{在此粘贴Phase 4的流程目录和关键活动}

# 输出要求

## 1. 异常分级标准

| 等级 | 名称 | 定义 | 响应时间 | 处理时限 | 升级路径 | 典型场景 |
|------|------|------|:---:|:---:|---------|---------|

| P1 | 严重/重大 | | | | | |
| P2 | 一般 | | | | | |
| P3 | 轻微 | | | | | |

## 2. 异常管理组织与职责

| 角色 | 职责描述 | P0权限 | P1权限 | P2权限 | P3权限 |
|------|---------|:---:|:---:|:---:|:---:|

## 3. 异常处理通用流程（5步法）
1. 发现与上报
2. 评估与分级
3. 应急处置
4. 原因分析
5. 纠正预防与闭环

对每一步，描述：执行角色、关键活动、输出物、时限要求。

## 4. 异常分类体系
按业务域分类，列出每个域的异常子类别：

| 业务域 | 异常子类别 | 典型场景数 | 行业特殊性说明 |
|--------|----------|:---:|------------|

## 5. 统计与分析模板
- 异常频次统计表（按等级/按域/按月度）
- 高频异常TOP10分析模板
- 异常处理效率KPI（响应时间达标率、闭环及时率）

# 质量约束
- 异常分级必须与业务影响程度直接挂钩
- 升级路径必须形成清晰的汇报链
- 每个业务域至少识别3个异常子类别
- 处理流程必须形成闭环（发现→处置→分析→改进→验证）

# 交叉验证要点
- [ ] 异常分级标准是否覆盖了安全、环保、质量、合规四个维度
- [ ] 升级路径是否与组织架构匹配
- [ ] 异常分类是否与业务流程的活动一一对应
- [ ] 统计模板是否支持趋势分析和根因分析
```
