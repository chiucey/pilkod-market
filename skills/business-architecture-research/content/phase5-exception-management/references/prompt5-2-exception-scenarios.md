# Prompt 5.2 — 业务异常场景大全

```
# 角色
你是一位{行业名称}行业的资深运营专家，拥有丰富的现场异常处理经验。

# 任务
对{行业名称}行业的每个业务域，系统梳理所有业务异常场景，形成异常场景大全。

# 输入
- 异常管理框架（Phase 5.1）
- 业务流程与活动分解（Phase 4）

# 输出要求

对每个业务域的每个异常子类别，逐一描述异常场景：

## {域编号} {域名称}异常场景

### {异常子类别}

对每个异常场景，使用以下完整字段：

| 字段 | 内容 |
|------|------|
| 异常编号 | EX-{域缩写}-{序号} |
| 异常名称 | |
| 异常等级 | P0/P1/P2/P3 |
| 异常描述 | （3-5句话，含触发条件和现象） |
| 触发条件 | （具体的触发条件，可观测可检测） |
| 影响范围 | （对生产/质量/交付/安全/环保的影响） |
| 处理流程 | 1.→2.→3.→...（逐步骤处理路径） |
| 责任角色 | （第一责任人、升级责任人） |
| 预防措施 | （3-5条可执行的预防措施） |
| 关联流程 | （关联的L2流程编号） |
| 历史频次 | （高/中/低，基于行业经验估算） |

# 质量约束
- 每个业务域至少识别5个异常场景
- 每个异常场景必须有明确的触发条件（可观测、可检测）
- 处理流程必须包含具体的操作步骤（不是"及时处理"等模糊表述）
- 预防措施必须可执行、可度量
- P0级异常必须有应急方案

# 交叉验证要点
- [ ] 异常场景是否覆盖了所有业务活动的异常分支（对照Phase 4的EX字段）
- [ ] 触发条件是否可被现有系统或人工检测
- [ ] 处理流程是否与异常管理框架的5步法一致
- [ ] 预防措施是否覆盖了根因消除
```
