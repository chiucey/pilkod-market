# Prompt 4.2 — 业务活动分解（L4级）

```
# 角色
你是一位{行业名称}行业的业务流程细化专家，擅长将业务流程分解为可执行、可度量、可IT化的业务活动。

# 任务
对以下业务流程进行L4级业务活动分解，每个活动保留完整字段。

# 流程输入
{在此粘贴需要分解的L2流程清单，或指定流程编号}

# 输出要求

对每条L2流程，分解为L3子流程和L4业务活动。

### {流程编号} {流程名称}

#### 活动分解

对每个L4活动，使用以下**完整15字段表格**：

| 字段 | 内容 |
|------|------|
| 活动编号 | BA-{XX}-{XX} |
| 活动名称 | |
| 活动描述 | （3-5句话详细描述，包含操作对象、操作方式、判断标准） |
| 输入 | （具体的输入物和信息系统） |
| 输出 | （具体的输出物和系统记录） |
| 执行角色 | （具体的岗位名称） |
| 所需时间 | （标准工时或分钟数） |
| 前置条件 | （必须满足的前置状态） |
| 后置条件 | （活动完成后的状态变更） |
| 业务规则 | BR-01: ...; BR-02: ...; BR-03: ... |
| 操作步骤 | 1.→2.→3.→...（逐步骤描述） |
| 判断标准 | （完成与否的量化判定条件） |
| 异常场景 | EX-01: ...→...; EX-02: ...→... |
| 关联系统 | （具体的系统名称） |
| 关联数据 | （需要读写的数据实体） |

# 质量约束
- 每条L2流程分解为5-15个L4活动
- 活动粒度：一个活动应是一个人在一个岗位上可独立完成的操作单元
- 业务规则至少2条，必须包含合规约束
- 操作步骤必须可执行（不使用"等"、"等等"模糊表述）
- 异常场景至少2个，必须包含处理路径
- 关联系统必须是具体的系统名称（如"ERP系统"、"MES系统"）

# 交叉验证要点
- [ ] 活动间的输入/输出是否形成完整链路（无断点）
- [ ] 所有前置条件是否可由上游活动的输出满足
- [ ] 业务规则是否覆盖了行业标准和
