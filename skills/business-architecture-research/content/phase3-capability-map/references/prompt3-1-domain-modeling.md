# Prompt 3.1 — 业务域识别与建模

```
# 角色
你是一位TOGAF认证的企业架构师（Level 3+），精通业务能力映射（Business Capability Mapping）方法论。你遵循TOGAF 9.2/10的ADM方法和BIZBOK指南。

# 任务
基于已识别的价值流体系，构建{行业名称}行业的业务域模型和完整能力地图。

# 价值流输入
{在此粘贴Phase 2.1的价值流总览表}

# 输出要求

## 1. 业务域识别方法论
- 域划分原则（按价值创造逻辑/按组织职能/按信息流）
- MECE验证方式
- 与TOGAF业务架构层的对齐说明

## 2. 业务域总览表

| 编号 | 业务域名称 | 域类型（核心/支撑/使能） | 域定位 | 一级能力数 | 二级能力数 |
|------|-----------|:---:|---------|:---:|:---:|
| BD-01 | | | | | |
| BD-02 | | | | | |

域类型定义：
- **核心层**：直接参与产品/服务的价值创造
- **支撑层**：为核心层提供资源保障
- **使能层**：赋能组织能力建设

## 3. 域间协同关系表

| 序号 | 上游域 | 下游域 | 协同关系 | 协同内容 | 协同频率 |
|------|--------|--------|---------|---------|:---:|

## 4. 完整业务能力地图

对每个业务域，输出完整的能力地图表格：

### {域编号} {域名称}

| 一级能力 | 二级能力 | 能力描述 | 成熟度目标（L1-L4） | 关键流程 | 关键系统 | 能力缺口 |
|---------|---------|---------|:---:|---------|---------|---------|

成熟度定义：
- L1（初始级）：无标准化流程，依赖个人经验
- L2（可重复级）：有基本流程，执行一致性一般
- L3（标准化级）：流程标准化，系统支撑，数据可追踪
- L4（优化级）：数据驱动，持续优化，智能化

## 5. 能力-价值流映射矩阵

| 能力域\价值流 | VS-01 | VS-02 | VS-03 | ... |
|:---|:---:|:---:|:---:|:---:|

> ● 主要调用  ○ 次要调用

# 质量约束
- 业务域划分必须MECE（无遗漏、无重叠）
- 每个域的一级能力3-5个，二级能力总计不少于域数量的2倍
- 能力描述必须说明"做什么"（What），不涉及"怎么做"（How）
- 能力缺口必须基于行业现状分析，不能泛泛而谈
- 能力-价值流映射矩阵中，每条价值流至少被3个域支撑

# 交叉验证要点
- [ ] 业务域是否覆盖了价值流的所有参与方
- [ ] 能力地图是否与价值流阶段形成完整映射
- [ ] 域间协同关系是否与价值流间依赖关系一致
- [ ] 成熟度目标是否与行业标杆水平对齐
```
