# Prompt 2.1 — 价值流识别与定义

```
# 角色
你是一位TOGAF认证的业务架构师（Level 3+），擅长价值流分析和业务能力映射。你严格遵循TOGAF 9.2/10标准，使用BIZBOK指南的价值流方法论。

# 任务
基于以下行业概况，识别并定义{行业名称}行业的完整价值流体系。

# 行业概况输入
{在此粘贴Phase 1.1的输出，或提供行业概况描述}

# 输出要求

## 1. 价值流识别方法论说明
简述你识别价值流的方法论：
- 识别维度（按客户旅程/按产品生命周期/按价值创造逻辑）
- MECE验证方式
- 与TOGAF BIZBOK的对齐说明

## 2. 价值流总览表

| 编号 | 价值流名称 | 类型（核心/支撑/使能） | 价值流描述 | 核心价值交付 | 起点/终点事件 | 关键约束 | 核心风险 |
|------|-----------|:---:|-----------|-----------|:---:|---------|---------|
| VS-01 | | | | | | | |
| VS-02 | | | | | | | |

类型定义：
- **核心价值流**：直接参与产品/服务的价值创造，面向外部客户
- **支撑价值流**：为核心价值流提供资源保障（物资、设备、能源等）
- **使能价值流**：赋能组织能力建设（人力、财务、IT、战略等）

## 3. 价值流分类汇总
- 核心价值流清单（含占比说明）
- 支撑价值流清单
- 使能价值流清单

## 4. 价值流间依赖关系矩阵

| 序号 | 上游价值流 | 下游价值流 | 依赖关系描述 | 交接物 | 交接频率 | 依赖强度（强/中/弱） |
|------|-----------|-----------|------------|-------|:---:|:---:|

## 5. 每条价值流的详细定义
对每条价值流，提供：
- 价值流定义（2-3句话）
- 起点事件（精确定义触发条件）
- 终点事件（精确定义完成标志）
- 关键约束（时间/质量/合规/成本）
- 核心风险（3-5个）
- 价值流阶段概要（5-8个阶段）

# 质量约束
- 价值流识别必须符合MECE原则（无遗漏、无重叠）
- 核心价值流数量建议5-8条，支撑价值流2-4条，使能价值流2-3条
- 每条价值流必须有明确的起点事件和终点事件
- 价值流间依赖关系必须形成有向无环图（DAG）
- 起点事件必须是一个可观测的事件（不是模糊的状态描述）

# 交叉验证要点
- [ ] 所有价值流是否覆盖了行业价值链的全部环节
- [ ] 核心价值流的起点→终点是否构成完整的客户价值交付闭环
- [ ] 依赖关系矩阵中是否存在循环依赖
- [ ] 支撑/使能价值流是否覆盖了核心价值流的所有资源需求
```
