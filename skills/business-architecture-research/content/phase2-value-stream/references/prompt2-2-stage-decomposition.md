# Prompt 2.2 — 价值流阶段与步骤分解

```
# 角色
你是一位资深的{行业名称}行业业务流程专家，擅长将宏观价值流分解为可执行的业务步骤。

# 任务
对以下价值流进行阶段分解和步骤细化，达到L3-L4级别的详细程度。

# 价值流输入
{在此粘贴Phase 2.1识别的价值流，或指定需要分解的价值流名称}

# 输出要求

对每条价值流，输出：

## 阶段分解

### 阶段X：{阶段名称}（N步）

对每个步骤，使用以下完整字段表格：

| 字段 | 内容 |
|------|------|
| 步骤编号 | VS{XX}-P{X}-S{XX} |
| 步骤名称 | |
| 活动描述 | （3-5句话详细描述） |
| 输入 | （具体的输入物，不是抽象概念） |
| 输出 | （具体的输出物） |
| 责任角色 | （具体的岗位名称） |
| 关键系统 | （具体的系统名称） |
| 前置条件 | （必须满足的前置状态） |
| 完成标准 | （可验证的完成标志） |
| 业务规则 | BR-01: ...; BR-02: ...; BR-03: ... |
| 异常分支 | EX-01: ...→...; EX-02: ...→...; EX-03: ...→... |
| KPI | 指标名称≥目标值（如：订单录入及时率≥99%） |

# 质量约束
- 每条价值流分解为4-7个阶段，每个阶段3-8个步骤
- 步骤粒度：一个步骤应是一个可独立执行、有明确输入输出的工作单元
- 业务规则至少3条，异常分支至少3个
- KPI必须可量化（包含具体数值目标）
- 步骤间的衔接必须逻辑连贯，无断点

# 交叉验证要点
- [ ] 各阶段的首步骤前置条件是否与前阶段的末步骤输出一致
- [ ] 所有步骤的业务规则是否覆盖了行业法规要求
- [ ] 异常分支是否覆盖了常见的故障/偏差场景
- [ ] KPI是否与价值流的核心价值交付目标对齐
```
