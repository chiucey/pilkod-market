# 自检与待完善清单

> PRD 所有章节生成完毕后加载此文件，对生成内容进行轻量自检，并输出待完善清单。

## 自检流程

### 第一步：重大风险项快扫（R1-R8）

| 风险项 | 检查内容 | 状态 |
| --- | --- | --- |
| **R1 产品定位** | 能否用一句话回答"为谁、解决什么问题、提供什么价值" | ✅已覆盖 / ⚠️需完善 |
| **R2 核心业务流程** | 能否从PRD中重建端到端的业务流程 | |
| **R3 ER模型缺陷** | 业务型/交易型产品的ER模型是否完整（不适用则标注） | |
| **R4 角色权限** | 多角色系统是否有权限设计 | |
| **R5 功能致命缺口** | 核心业务流程是否有断裂的环节 | |
| **R6 需求与业务脱节** | 功能设计是否匹配实际业务场景 | |
| **R7 合规风险** | 强监管行业是否考虑了合规要求（不适用则标注） | |
| **R8 SaaS多租户** | 商业化SaaS是否有租户隔离设计（不适用则标注） | |

### 第三步：生成待完善清单

```md
## 附：待完善清单

### 🔴 必须补充（影响PRD可评审性）

1. {最关键的缺失内容，说明缺什么、为什么重要、如何获取}

### 🟡 建议补充（提升PRD质量）

1. {重要但非阻塞的内容}

### 🟢 可选完善（锦上添花）

1. {优化类内容}

---
> 💡 建议：优先补充🔴类内容后，可使用 `/check-prd` 对完善后的 PRD 进行完整评审。
```

## 输出规则

1. 每个待完善项必须具体：缺什么、为什么重要、建议如何获取。
2. 按三级优先级分类：🔴必须 / 🟡建议 / 🟢可选。
3. 最后提示用户完善后可使用 `/check-prd` 进行完整评审。
