# 中英互译技能

## 核心原则：信达雅

1. **信 (Faithfulness)**: 忠实于原文，不增不减，准确传达原意
2. **达 (Expressiveness)**: 通顺流畅，符合中文表达习惯，让读者能看懂
3. **雅 (Elegance)**: 文辞优美，保留原文的美感与神韵，在语境和风格上得体

三者递进：信是基础，达是桥梁，雅是升华。

## 翻译工作流程

### 阶段 1：理解与准备

1. **原文解析**：识别文本类型（技术文档/论文/文学/网页等）
2. **术语识别**：标记专业术语、技术词汇、专有名词
3. **语境分析**：理解上下文、文化背景、语气风格

### 阶段 2：翻译执行

#### 一般翻译准则

1. **保持引用格式**：原样保留超链接、图片引用、脚注等引用元素
2. **专业术语处理**：
   - 使用中文专业术语（参考业界标准译法）
   - 在首次出现时以括号添加英文原文注解
   - 格式：`术语 (term)`
3. **长句拆分**：将复杂英文长句拆分为符合中文习惯的短句
4. **语序调整**：按照中文思维逻辑重组句子结构

#### 技术文档翻译要点

- 代码示例中的注释也需要翻译
- 保持 API 名称、函数名等标识符为英文（使用代码高亮格式）
- 术语表（Glossary）附录
- 版本记录保持英文

### 阶段 3：优化与审校

1. **准确性检查**：确认术语翻译准确、无遗漏
2. **流畅性检查**：阅读译文，确保符合中文表达习惯
3. **格式检查**：保持原文格式结构、超链接、图片引用
4. **术语一致性**：全文术语使用统一

## 输出格式

### 基本要求

- **Markdown 格式输出**
- **标题层级**：使用 `#` 一级标题
- **代码块**：使用三个反引号 ``` 包裹，标注语言类型
- **强调**：使用 `**粗体**` 或 `*斜体*`
- **引用**：使用 `>` 保持原文引用格式

### 附录要求

当文本包含以下内容时，添加术语表附录：

- 专业术语（计算机、电子、商务等）
- 首次出现的缩写词
- 需要特别解释的概念

## 附录格式

```markdown
## 术语表 (Glossary)

| 英文 | 中文 | 说明 |
|------|------|------|
| term | 术语 | 简要说明 |
```

## 翻译示例

### 示例 1：技术文档

**原文：**
> Protocol Buffers (protobuf) is a method of serializing structured data. It is useful for developing programs to communicate with each other or to store data efficiently.

**译文：**
> Protocol Buffers (protobuf) 是一种结构化数据的序列化(serialize)方法。它对于开发相互通信的程序或高效存储数据非常有用。

### 示例 2：文学风格

**原文：**
> "To be, or not to be, that is the question."

**译文：**
> "生存还是毁灭，这是个问题。"（保留莎士比亚戏剧的经典翻译风格）

### 示例 3：保持超链接

**原文：**
> For more information, visit [官方文档](https://example.com).

**译文：**
> 更多信息，请访问[官方文档](https://example.com)。

- [ ] 语句通顺，符合中文习惯
- [ ] 格式结构与原文一致
