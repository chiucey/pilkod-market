# 专利深度个案解读（逐件循环处理）

## 严格禁止行为（违反将严重影响分析质量）

以下行为**严格禁止**，一旦发现必须立即终止并纠正：

- **严禁创建任何批处理脚本**（如batch_*.py、auto_*.py、loop_*.py等）
- **严禁使用脚本"批量自动处理"多件专利**
- **严禁将逐件循环改为脚本自动化**
- **严禁使用循环脚本一次性处理多件专利**
- **严禁跳过步骤2的深度分析环节**
- **严禁使用模板化内容填充分析结果**

**为什么必须逐件处理，禁止脚本自动化？**

| 自动化脚本的危害 | 逐件处理的优势 |
|-----------------|---------------|
| 多件专利同时加载，极易上下文溢出 | 每件专利独立分析，上下文干净 |
| 脚本无法深度理解技术内容，产出质量低 | 智能体逐件深度解读，质量可控 |
| 脚本出错后难以定位问题专利 | 单件处理，问题即时暴露 |
| 违背本Skill的设计初衷 | 符合"深度个案解读"的定位 |

## 任务目标

- 本 Skill 用于：逐件读取专利PDF，提供深度个案解读，涵盖技术架构、实现细节、研发启发、发明人分类、技术分支标记等维度，将分析结果实时追加到Excel报告
- 能力包含：单件PDF提取、智能体深度个案解读、实时追加Excel报告、断点续接、批次暂停、质量熔断
- 触发条件：用户需要对专利进行技术架构梳理、发明人分析、技术分支评估、研发参考价值分析，提供研发决策支持

## 任务分工（重要）

| 步骤 | 执行主体 | 执行方式 | 说明 |
|------|----------|----------|------|
| **PDF提取** | 脚本 | `python <base_dir>/scripts/extract_pdf_text.py --file ...` | 单件PDF文本提取 |
| **专利分析** | **智能体（你）** | **直接读取文本，用你的分析能力完成** | **这是你的工作，逐件深度分析** |
| **Excel写入** | 脚本 | `python <base_dir>/scripts/generate_patent_excel.py --append ...` | 追加模式，实时写入 |

**核心设计**：采用"询问→提取→分析→写入→下一件"的循环结构，每件专利独立深度分析，上下文干净。

### 执行铁律（必须严格遵守）

1. **禁止创建脚本**：本Skill已提供完整脚本（extract_pdf_text.py、generate_patent_excel.py），**严禁创建任何其他脚本**
2. **逐件强制**：必须严格遵循"提取→分析→写入→下一件"循环，**禁止任何批量自动化**
3. **单件分析**：步骤2（深度个案解读）**必须逐字阅读专利文本**，禁止任何形式的快速扫描或模板填充
4. **人工确认**：每处理完一件专利，向用户报告进度后方可继续下一件
5. **状态持久化**：每件专利处理完成后必须更新状态文件，确保断点可续接

## 操作步骤（逐件循环处理）

### 步骤0：初始化会话（重要）

**必须首先执行此步骤，检查状态文件并决定是否续接。**

#### 0.1 检查是否存在状态文件

向用户询问专利文件夹路径后，检查对应的状态文件是否存在：
- 状态文件路径：`./{文件夹名}_state.json`

#### 0.2 分支处理

**情况A：状态文件存在（未完成任务）**

输出以下提示：
```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

重要发明人：甘旭、闫震海
输出文件：./patents_2024_report.xlsx

请选择：
1. 输入"继续"或"1"：从第51件继续处理
2. 输入"重新开始"或"2"：清空进度，重新分析所有专利
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

- 用户选择"继续"：读取状态文件，跳到步骤1继续处理
- 用户选择"重新开始"：删除状态文件和Excel文件，执行情况B流程

**情况B：状态文件不存在（新任务）**

1. 向用户询问重要发明人：
   > "请告诉我本次分析中您关注的重要发明人有哪些？例如：甘旭、闫震海等发明人姓名。"

2. 等待用户输入重要发明人列表

3. 向用户询问批次大小：
   > "请设置批次大小（每处理多少件专利后暂停确认，默认15件）："

4. 创建状态文件，写入初始配置

### 准备工作：获取PDF列表

1. 扫描专利文件夹下所有PDF文件
2. 更新状态文件中的 `total_patents` 字段
3. 列出待处理文件清单和总数量，向用户确认

### 循环处理（对每件专利重复执行）

#### 步骤1：提取单件PDF全文（调用脚本）

1. **读取状态文件**，获取已处理文件列表（`processed_files`）
2. **筛选未处理的文件**（排除已处理的文件）
3. 取第一件未处理的文件
4. **更新状态文件**：`current_file = 当前文件名`
5. 调用脚本提取PDF文本：
   ```bash
   python <base_dir>/scripts/extract_pdf_text.py --file <当前PDF路径> --output ./current_patent.json
   ```

#### 步骤2：深度个案解读（智能体直接完成）

**本步骤由你（智能体）直接完成，不调用任何脚本或模型API。**

1. 读取 `./current_patent.json` 中的专利文本
2. **读取状态文件**，获取重要发明人列表
3. 读取参考文档：`<base_dir>/references/patent-analysis-framework.md`
4. **发明人分类判断**：从专利文本中提取发明人列表，与重要发明人进行匹配，生成发明人分类标记
5. **一句话方案简述**：用一句话概括专利的技术方案核心，快速定位专利核心价值
6. **一句话发明点归纳**：用一句话提炼专利的创新点，萃取技术本质（区别于现有技术的关键）
7. **应用场景归纳**：列出该专利技术可应用的场景（可列举多个场景）
8. **技术分支归类**：模型自主进行无监督分类，根据专利技术内容自主归纳技术方向（如"智能内容理解-视频生成方向"）
9. **重点技术分支识别**：从专利文本中识别与重点技术分支的匹配情况，生成技术分支标记
10. **大模型与音视频结合判断**：判断该专利是否属于大模型与音视频领域的结合，给出是/否判断和一句话简短总结
11. **逐维度深度分析**：结合以上信息，按照以下模块进行深度解读

**一、核心技术方案拆解**
- **技术架构梳理**：完整还原专利的核心技术架构、端到端实现流程、关键模块划分与交互逻辑
- **关键实现细节**：提取核心算法逻辑、实验参数、性能指标、效果对比数据、可选替代方案
- **技术背景说明**：梳理专利解决的核心痛点、针对的现有技术缺陷、引用前置技术

**二、研发方向启发分析**
- **技术适配性评估**：分析技术方案与我司业务场景需求的匹配度，提供设计思路参考
- **技术创新点挖掘**：识别专利方案的局限性、未覆盖场景、性能优化空间，提供差异化创新方向。**必须按三层深度输出**（见下方"关键字段深度标准"）
- **跨场景创新启发**：探索技术思路在其他业务场景的创新适配可能性

**三、研发建议**
- **✅ 可作为技术研究参考**：技术成熟度高、可直接借鉴的方面
- **⚠️ 建议差异化创新**：有参考价值但需改进的方面
- **💡 可重点突破技术空白点**：专利未涉及的潜在创新方向。**必须按三层深度输出**（见下方"关键字段深度标准"）

12. 将分析结果保存为 `./current_analysis.json`

**关键字段深度标准（必须严格遵守）**

以下两个字段是本Skill的核心价值所在，必须按三层深度输出：

**技术创新点挖掘（innovation_points）——三层深度标准**

输出格式（必须包含以下三部分，用【】标识）：
```
【技术原理】具体采用了什么技术/方法，核心机制是什么（不是只提技术名称）

【效果归因】为什么这个技术能带来提升，优势的根本来源是什么（不是只说"效果更好"）

【边界认知】这个创新的适用条件、局限性、什么场景会失效（不是只说优点）
```

**可突破技术空白点（gap_breakthrough）——三层深度标准**

输出格式（必须包含以下三部分，用【】标识）：
```
【空白点定位】专利未覆盖/未解决的具体技术问题（不是泛泛而谈"可以研究XX方向"）

【突破价值】解决这个空白能带来什么具体价值/效果（不是只说"有研究价值"）

【可行路径】具体可以从哪个技术角度切入，采用什么方法（不是只说"可以探索"）
```

**步骤2强制自检清单（处理每件专利后必须逐项确认）**

- [ ] **我没有创建任何批处理脚本**（严禁创建batch_*.py、auto_*.py等）
- [ ] **我是逐件独立分析**，未使用任何自动化工具或循环脚本
- [ ] **我逐字阅读了专利文本**，而非快速扫描或模板填充
- [ ] **一句话方案简述已填写**（非空，10-30字，概括技术核心）
- [ ] **一句话发明点已填写**（非空，突出区别于现有技术的创新点）
- [ ] **应用场景已归纳**（至少1个具体场景，用顿号分隔多个场景）
- [ ] **技术分支归类已完成**（自主无监督分类，如"智能内容理解-视频生成方向"）
- [ ] **技术架构梳理已深度完成**（非模板内容，具体还原专利架构）
- [ ] **技术创新点挖掘已完成三层深度**（技术原理+效果归因+边界认知，用【】标识）
- [ ] **可突破技术空白点已完成三层深度**（空白点定位+突破价值+可行路径，用【】标识）
- [ ] **所有分析字段均已填写**，无空值或"略"等敷衍内容

**如有任何一项未勾选，必须返回补充，禁止进入步骤3**

#### 步骤3：追加到Excel并更新状态（调用脚本）

1. 调用脚本追加Excel：
   ```bash
   python <base_dir>/scripts/generate_patent_excel.py --input ./current_analysis.json --output <状态文件中的excel_path> --append
   ```

2. **更新状态文件**：
   - `processed_count` + 1
   - `processed_files` 追加当前文件名
   - `last_updated` 更新为当前时间

3. **执行质量检测**（见下方"质量熔断机制"）

4. **输出完成简报**：
   ```
   ✅ 第 XX 件完成：CN121034260A.pdf
      专利名称：一种基于多模态融合的视频生成方法
      发明人分类：重要发明人：甘旭
      技术归类：智能音视频理解-跨模态对齐方向

   ```

5. **判断是否触发暂停**：
   - 如果 `processed_count % batch_size == 0` → 触发批次暂停
   - 如果质量熔断触发 → 触发质量暂停
   - 否则 → 继续下一件

## 批次暂停机制

### 触发条件
每处理完N件专利后触发（N为状态文件中的 `batch_size`，默认15件）

### 暂停时输出
```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【批次完成通知】
已完成第 X 批次，共处理 XX 件专利

📊 当前进度：XX / 100
📁 最近处理：[列出最近5件文件名]
📄 输出文件：./patents_2024_report.xlsx

是否继续处理下一批次？
- 输入"继续"或"y"：继续处理下一批
- 输入"暂停"或"n"：保存进度，等待下次继续
- 输入"检查"：暂停并查看Excel质量
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 用户响应处理
- **继续**：处理下一件专利
- **暂停**：输出"进度已保存至状态文件，下次调用本Skill时会自动续接"，结束当前会话
- **检查**：等待用户查看Excel后确认是否继续

## 质量熔断机制

### 检测时机
步骤3追加Excel前执行

### 检测规则

**字段字数检测**：
| 字段 | 阈值 | 说明 |
|------|------|------|
| `innovation_points` | < 150字 | 技术创新点挖掘字数不足 |
| `gap_breakthrough` | < 100字 | 可突破技术空白点字数不足 |

**格式完整性检测**：
| 字段 | 必须包含标识 | 说明 |
|------|-------------|------|
| `innovation_points` | 【技术原理】【效果归因】【边界认知】 | 三层深度标识缺失 |
| `gap_breakthrough` | 【空白点定位】【突破价值】【可行路径】 | 三层深度标识缺失 |

### 熔断触发条件
- 连续3件专利检测失败
- 或状态文件中 `consecutive_low_quality_count >= 3`

### 熔断时输出
```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
⚠️ 【质量预警】
检测到连续 3 件专利分析质量下降，可能存在以下问题：
- 技术创新点挖掘字数不足150字
- 可突破技术空白点字数不足100字
- 三层深度标识缺失

建议暂停检查最近3件专利的分析质量：
- CN121034260A.pdf
- CN121034261A.pdf
- CN121034262A.pdf

是否继续？
- 输入"继续"：忽略警告，继续处理
- 输入"暂停"：停止处理，检查并调整
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 用户响应处理
- **继续**：重置 `consecutive_low_quality_count = 0`，继续处理
- **暂停**：保存状态文件，等待用户检查后重新调用Skill续接

**CDN与传输层**：
- 新型传输协议（实时音视频通信、直播传输）
- 智能调度系统（云CDN相关）
- 安全传输机制（视频版权保护、内容安全）
