# BookCracker 智能拆书引擎

## 使用场景

用户提供一本书的名称或文件路径，系统将其逐章拆解为结构化的知识卡片并生成选题建议。

## 前置条件

书籍文件需要先经过预处理脚本转换为纯文本并按章节拆分。预处理脚本位于：

```
~/content-workspace/scripts/book-prep.py
```

如果用户提供的书籍尚未预处理，先执行预处理命令：

```
python3 ~/content-workspace/scripts/book-prep.py ~/content-workspace/books/book-name.epub
```

预处理后的文件结构：

```
~/content-workspace/books/[book-name]/
├── full.txt          Full text (backup only, do not read entirely)
├── chapters/         Chapter files
│   ├── 00-preface.txt
│   ├── 01-chapter-01.txt
│   ├── 02-chapter-02.txt
│   └── ...
└── info.txt          Book metadata
```

## 拆书流程

### 第一步：确认书籍状态

检查书籍是否已预处理：

```bash
ls ~/content-workspace/books/
```

- 如果目标书籍的目录已存在且包含 `chapters/` 子目录，直接进入第二步
- 如果目录不存在，检查原始文件：

```bash
ls ~/content-workspace/books/*.epub ~/content-workspace/books/*.mobi ~/content-workspace/books/*.pdf ~/content-workspace/books/*.azw3 2>/dev/null
```

- 如果找到原始文件，执行预处理
- 如果原始文件也不存在，告知用户需要先将书籍文件上传到 `~/content-workspace/books/` 目录

### 第二步：读取书籍信息和章节列表

读取 `info.txt` 了解全书结构，然后列出所有章节文件，向用户展示：

```
本书共 [X] 个章节，总计 [X] 万字。

章节列表：
1. [章节名] ([X]字)
2. [章节名] ([X]字)
...

请选择拆解范围：
- 回复"全部"：逐章拆解整本书（预计需要多轮对话）
- 回复章节编号（如"1-3"）：拆解指定章节
- 回复具体章节名：拆解单个章节
```

### 第三步：逐章拆解（核心步骤）

**重要**：每次只读取一个章节的文本。绝对不要一次读取 `full.txt` 完整文件。

对用户选定的每一章，依次执行以下操作：

1. 读取该章节文件内容

2. 对该章节内容提取以下五个维度：
   - **核心论点**：每章 3-5 个，用一句大白话总结
   - **经典案例**：书中的故事、实验，用 2-3 句话概述，不大段摘抄原文
   - **金句**：可引用的精华观点，注明章节位置
   - **实操方法**：具体可执行的建议步骤
   - **适用年龄段**：这个知识点适合多大的孩子

3. 为每个提取出的知识点生成一张标准格式的知识卡片

4. 使用 write 工具将知识卡片保存到文件

### 第四步：保存知识卡片

知识卡片存储路径：`~/content-workspace/knowledge/[book-slug]/`

每张卡片保存为单独的文件，文件名格式：`[index]-[keyword].md`

**知识卡片标准格式**：

```markdown
## 知识卡片：[知识点名称]

- 来源：《[完整书名]》第[X]章 [章节名称]
- 核心观点：[一句话，大白话总结]
- 适用年龄：[X-X岁]
- 书中案例：[用2-3句话概述书中的相关案例，不照搬原文]
- 大白话解释：[像对朋友解释一样，通俗易懂，3-5句话]
- 实操建议：
  1. [第一步，具体可执行]
  2. [第二步]
  3. [第三步]
- 可关联的选题方向：
  - [选题角度1]
  - [选题角度2]
  - [选题角度3]
- 需要用户补充：[提示用户录入什么样的真实经历来搭配这个知识点]
```

### 第五步：每章拆解完成后的中间汇报

每完成一章的拆解，向用户汇报：

```
[书名] 拆书进度：第[X]章 / 共[Y]章

本章生成知识卡片：[N] 张
1. [卡片名] - [一句话]
2. [卡片名] - [一句话]

累计知识卡片：[总数] 张
存储位置：~/content-workspace/knowledge/[book-slug]/

继续拆解下一章？回复"继续"或指定章节编号。
回复"暂停"可随时中断，已完成的卡片不会丢失。
```

这个中间汇报很重要：让用户可以分多次完成拆书，不需要一次性完成。

### 第六步：生成选题建议

当用户拆解完毕（或主动要求生成选题）时，扫描 `~/content-workspace/knowledge/[book-slug]/` 目录下所有已生成的知识卡片，生成 10 个内容选题。

保存到：`~/content-workspace/topics/[date]-[book-slug]-topics.md`

**选题格式**：

```markdown
## 选题[序号]：[选题标题]

- 切入角度：[从什么场景或问题入手]
- 核心知识点：[引用哪张知识卡片，写明文件路径]
- 最适合平台：[小红书/公众号/头条，说明理由]
- 预估字数：[适合的内容长度]
- 需要的真实素材：[描述需要用户提供什么样的亲身经历]
- 标题备选：
  1. [标题选项A]
  2. [标题选项B]
  3. [标题选项C]
```

### 第七步：交叉引用

拆解完成后，检查其他书籍的知识卡片：

```bash
ls ~/content-workspace/knowledge/
```

如果存在其他书籍的卡片目录，扫描其内容。如果发现相关联的知识点（不同书对同一话题的不同观点），在当前卡片文件末尾追加：

```
- 关联知识：[其他书籍的卡片路径] - [简述关联关系]
```

### 第八步：最终汇总

全部拆解完成后推送汇总：

```
拆书完成：《[书名]》

拆解范围：[哪些章节]
生成知识卡片：[X] 张
生成选题建议：[X] 个
存储位置：
  知识卡片：~/content-workspace/knowledge/[book-slug]/
  选题建议：~/content-workspace/topics/[filename]

需要你后续补充的真实经历：
- [经历类型1]：用于搭配知识点[X]
- [经历类型2]：用于搭配知识点[Y]

回复"写[选题编号]"可以直接基于选题生成内容初稿。
```

## 注意事项

- **绝对不要**一次性读取 `full.txt`，必须逐章节读取 `chapters/` 目录下的文件
- 不要大段摘抄原文，提取核心观点后用自己的话重新表达
- 每个知识卡片都必须包含"需要用户补充的真实案例"提示
- 支持分多次拆书，已完成的章节不会重复处理
- 如果某章内容与育儿/儿童心理无直接关系（如版权页、广告页），可以跳过
- 遇到不确定是否准确的内容，标注"需要确认"
- 知识卡片和选题建议中的路径必须使用英文
