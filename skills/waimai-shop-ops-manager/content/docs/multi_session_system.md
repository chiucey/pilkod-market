# 多员工会话系统设计文档

## 概述

本系统支持用户与一位或多位AI员工同时进行沟通交流，实现跨部门协作和问题协同解决。

## 会话模式

### 1. 单人会话模式

用户只与一位员工对话，专注于该员工负责的特定领域问题。

**适用场景**：
- 只需要单一部门处理的问题
- 用户明确知道需要哪个员工处理
- 问题范围明确，不需要跨部门协调

**示例对话**：

```
用户：我看一下昨天的财务情况
系统：正在连接员工A（财务出纳专家）...
员工A：您好！以下是昨天的财务日报...
```

### 2. 多人会话模式（开会模式）

用户同时与多位员工对话，选中的员工共同响应，相互补充。

**适用场景**：
- 需要跨部门协作的复杂问题
- 一个问题的解决方案涉及多个部门
- 需要多位员工共同分析和讨论

**示例对话**：

```
用户：我最近的利润下滑了，帮我分析一下
系统：正在连接员工A（财务）、员工B（运营）、员工D（库存）...
员工A：我来分析一下成本结构...发现食材成本上升了15%
员工B：我来分析一下运营情况...发现流量下降了10%
员工D：我来分析一下库存情况...发现蔬菜损耗率偏高
员工A：综合分析，净利润下滑的主要原因是成本上升和流量下降
员工B：我建议优化投流策略，提升转化率
员工D：同时需要优化库存管理，减少损耗
系统：综合三位员工的分析，形成以下行动方案...
```

### 3. 智能调度模式

用户描述问题或需求，系统自动识别最合适的员工响应，必要时自动触发多员工协作。

**适用场景**：
- 用户不确定应该找哪个员工
- 问题涉及多个领域但用户不清楚
- 需要系统智能判断协作需求

**示例对话**：

```
用户：这个月成本有点高
系统：智能分析中...识别到您的问题涉及财务和运营两个领域
系统：正在连接员工A（财务）和员工B（运营）...
员工A：分析成本数据...发现主要成本项均有不同程度上升
员工B：结合运营数据分析，成本上升与投流效率下降相关
系统：综合分析后，建议以下优化方案...
```

## 协作机制

### 数据共享

| 数据流向 | 内容 | 说明 |
|---------|------|------|
| 员工C → 员工A | 人力成本数据、工资明细 | 工资计算完成后自动推送 |
| 员工D → 员工A | 采购成本、库存损耗数据 | 每日盘点后自动推送 |
| 员工A → 员工B | 成本数据、盈亏分析结果 | 按需提供或异常时推送 |
| 员工B → 员工A | 投流方案、运营建议 | 按需提供 |

### 协作触发条件

| 触发条件 | 协作动作 | 参与员工 |
|---------|---------|---------|
| 利润率低于15% | 分析原因，制定对策 | A + B |
| 成本异常上升 | 识别异常原因 | A + D |
| 库存预警 | 计算成本影响 | A + D |
| 工资发放完成 | 更新人力成本 | A + C |
| 投流效果下降 | 评估成本效益 | A + B |
| 新员工入职 | 完善档案、设置薪酬 | C |
| 采购计划 | 确认备货需求 | B + D |

### 冲突处理

当多位员工的建议出现冲突时：

1. **自动平衡**：系统自动权衡，给出综合建议
2. **优先级规则**：按预设优先级自动决策
3. **用户决策**：系统通知用户，由用户最终决定

## 会话控制

### 员工选择

用户可以通过以下方式选择要对话的员工：

#### 方式一：直接指定

```
用户：找员工A和员工B开会
用户：我要和财务专家聊一下
用户：只和库存专家对话
```

#### 方式二：按类型选择

```
用户：找财务相关的人
用户：找运营和人力的人
用户：我要处理库存问题
```

#### 方式三：智能识别

```
用户：帮我分析一下为什么最近利润下滑
用户：这个月的成本怎么这么高
用户：最近员工排班有点乱
```

### 会话切换

在多人会话中，用户可以：

| 操作 | 指令示例 | 说明 |
|------|---------|------|
| 切换主对话人 | 员工A主导 | 切换主要响应员工 |
| 添加成员 | 加上员工C | 邀请新成员加入 |
| 移除成员 | 让员工D先退出 | 移除某成员 |
| 单独提问 | 员工A先回答这个问题 | 指定某成员回答 |
| 结束多人会话 | 结束会议 | 退出会话模式 |

### 会话状态

| 状态 | 说明 |
|------|------|
| 单人会话 | 用户与单一员工对话 |
| 多人会话 | 用户与多位员工同时对话 |
| 协作分析 | 多员工正在协作分析问题 |
| 等待响应 | 等待某位员工响应 |

## 响应格式

### 单人响应

当用户与单一员工对话时，直接返回该员工的响应。

```
员工A：您好！根据数据分析，昨天净利润为3,230元，利润率20.6%。
主要成本构成为：食材成本36.1%，人力成本25.7%。
建议关注营销推广成本，本周环比增长5.2%。
```

### 多人响应

当用户与多位员工同时对话时，按照以下格式响应：

```
【多人会议】参与员工：员工A（财务）、员工B（运营）

【员工A发言】
根据财务数据分析，昨天净利润为3,230元，利润率20.6%。
主要问题是营销推广成本环比增长5.2%。
建议联系员工B评估投流效果。

【员工B发言】
根据运营数据分析，昨天流量环比增长3.8%，转化率稳定。
营销推广ROI为5.6，表现良好。
建议继续观察，无需大幅调整投流策略。

【综合建议】
综合两位员工的分析，当前经营状况良好。
营销成本上升属于正常波动，建议保持当前策略。
下周再评估效果，如有问题再调整。
```

### 智能调度响应

当系统智能识别问题时，响应格式如下：

```
【智能分析】识别到您的问题涉及：财务 + 运营
【协作邀请】是否需要员工A和员工B共同参与分析？
【会议说明】点击确认后将同时连接两位员工进行协作分析
```

## 最佳实践

### 什么时候使用单人会话？

- 查询单一领域的问题（如只问财务数据）
- 问题范围明确，不需要多部门协作
- 用户已清楚知道需要哪个员工处理

### 什么时候使用多人会话？

- 问题涉及多个领域（如成本+运营+库存）
- 需要综合多部门意见做出决策
- 问题原因不明确，需要多角度分析
- 需要协调多部门执行解决方案

### 什么时候使用智能调度？

- 用户不确定问题应该找谁
- 问题描述比较模糊，需要系统智能判断
- 首次与系统交互，不熟悉各员工职责

## 常见问题

### Q：多人会话时，员工之间的意见冲突怎么办？

A：系统会自动平衡各员工建议，给出综合方案。最终决策权归用户，用户可以选择采纳哪位员工的建议或综合各方意见。

### Q：可以同时开多个会议吗？

A：同一时间只能有一个进行中的会议。如需切换，请先结束当前会议。

### Q：退出多人会话后，历史记录会保存吗？

A：是的，所有会议记录都会保存，可在历史记录中查看。

### Q：员工不在线时，可以邀请吗？

A：可以邀请，离线员工将在重新上线后收到会议记录，并可补充意见。
