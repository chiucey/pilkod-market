# BD分析报告生成（分章节MD → 合并 → HTML）

## 任务目标
- 本Skill用于：为指定企业生成完整BD分析报告，采用**分章节独立生成MD → 脚本合并 → 脚本转HTML**的流水线
- 能力包含：信号识别与评分、Phase阶段判定、行业画像分析、BD紧迫性评分、13章+3附录标准报告生成
- 触发条件：用户提到"BD分析"、"公司分析报告"、"Phase判定"、"企业调研"、"竞品分析"、"BD武器库"等需求

## 前置准备
- 依赖说明：`markdown` 库用于MD→HTML转换，`merge_md.py` 用于章节合并
- 所需信息：企业名称、所属行业（至少到三级）、融资历史、高管变动、产品进展等
- 若用户仅提供企业名称，主动询问所属行业和分析日期

## 操作步骤

### 步骤1：确认输入，读取画像与格式规范

1. 确认企业名称、所属行业（一/二/三级）、分析日期
2. 清空并创建章节输出目录：`rm -rf ./chapters && mkdir -p ./chapters`
3. 按行业层级读取画像文件：
   - 读取二级画像：`references/industry-profiles/l2-{二级行业名}.md`
   - 读取三级画像：`references/industry-profiles/l3-{二级行业名}-{三级赛道名}.md`
4. 读取 `references/report-framework-v2.md` 获取完整格式模板和质量检查清单

示例：某mRNA药物企业 → 生命科学 → 创新药 → 基因与细胞疗法
- 读取 `references/industry-profiles/l2-生命科学-创新药.md`
- 读取 `references/industry-profiles/l3-生命科学-创新药-基因与细胞疗法.md`

### 步骤2：逐章生成MD文件

按顺序生成以下章节MD文件，每个文件独立写入 `./chapters/` 目录：

**章节文件名与合并顺序**：

| 文件名 | 内容 | 预估行数 |
|--------|------|---------|
| `ch00-header.md` | 报告头部（标题+meta） | 10 |
| `ch01.md` | 第一章 企业基本信息 | 100 |
| `ch02.md` | 第二章 BD评分与Phase判定 | 80 |
| `ch03.md` | 第三章 行业画像与竞争格局 | 120 |
| `ch04.md` | 第四章 创始人背景与研究院动态 | 80 |
| `ch05.md` | 第五章 公司所在地动态 | 60 |
| `ch06a.md` | 第六章 6.1企业层面评价 + 6.2产品分析 | 200 |
| `ch06b.md` | 第六章 6.3关键人物话题建议 | 150 |
| `ch06c.md` | 第六章 6.4资金层面分析 | 150 |
| `ch06d.md` | 第六章 6.5环境分析 + 6.6最新Gossip | 150 |
| `ch06e.md` | 第六章 6.7业务话题 + 6.8脑洞Gossip | 120 |
| `ch07.md` | 第七章 BD切入建议 | 120 |
| `ch08.md` | 第八章 风险提示 | 60 |
| `ch09.md` | 第九章 MNC/License-out合作策略 | 150 |
| `ch10.md` | 第十章 IPO路径与资本策略 | 120 |
| `ch11.md` | 第十一章 竞争对手深度追踪 | 100 |
| `ch12.md` | 第十二章 专利/IP策略 | 80 |
| `ch13.md` | 第十三章 CDMO/供应链策略 | 80 |
| `app-a.md` | 附录A BD交易案例库 | 60 |
| `app-b.md` | 附录B 信息来源与参考文献 | 40 |
| `app-c.md` | 附录C 监控清单 | 30 |

**注意**：第六章因内容量大（占全文40%+），必须拆分为ch06a~ch06e共5个文件。只有ch06a.md需要写`## 六、BD武器库`章节标题，ch06b~ch06e.md直接从子标题开始。

**ch00-header.md 内容**：
```markdown
# 企业BD分析范例：[企业全名]（Phase [X]）

---

> **分析日期**: YYYY-MM-DD

```

- 标题不含"Final"/"vX.X"等任何版本标签
- 第一章内含标准依据行：`> **标准依据**: 基于行业细分画像评分及输出标准完成`
- 章节从"一、"平级编号至"十三"，附录为"附录A/B/C"

**各章节核心内容**（详见 `references/report-framework-v2.md` 完整模板）：

**ch01.md**：1.1基础信息表(8维度) / 1.2核心产品管线表(4-5个产品) / 1.3核心团队表(含CFO状态) / 1.4核心技术平台表(3+个)

**ch02.md**：2.1行业画像依据 / 2.2预警信号检测表 / 2.3 BD紧迫性评分（`<pre><code>`代码块格式）/ 2.4 Phase判定表（5行+判定依据+结论）

**ch03.md**：3.1行业定位(pre代码块) / 3.2行业现状(4维度) / 3.3竞对表(5+家) / 3.4行研观点(blockquote)

**ch04.md**：4.1创始人(表格+洞察4-6条) / 4.2技术背景(如适用) / 4.3院校动态

**ch05.md**：5.1总部城市 / 5.2分支机构

**ch06a~ch06e.md — 第六章 BD武器库**（核心章节，占全文40%+篇幅）：
8个子节拆到5个文件中，每个子节用 `---` + `**[详细内容]**` 开头：
- ch06a：6.1 企业层面评价 / 6.2 产品分析(总览表+6维分析+AI评价)
- ch06b：6.3 关键人物话题(每人3话题)
- ch06c：6.4 资金分析(全景表7列+3家详细)
- ch06d：6.5 环境分析 / 6.6 最新Gossip(3-4个,固定4段式)
- ch06e：6.7 业务话题(4维度) / 6.8 脑洞Gossip(2-3个)
- **每个6.X子节末尾必须有AI提示块**：`> **AI提示：** [一句话]`

**ch07.md**：7.1时机 / 7.2策略 / 7.3开场话术(4种+禁止清单+AI提示块) / 7.4跟进策略

**ch08.md**：8.1企业风险表 / 8.2行业风险表（各5-6行）

**ch09.md**：9.1同赛道BD交易 / 9.2 MNC合作方矩阵(分优先级) / 9.3 License-out交易结构 / 9.4核心投资方深化路径

**ch10.md**：三地对比(10+维度) + 推荐路径 + 融资预测 + 估值参考

**ch11.md**：直接竞对(8+维) + 灯塔分析 + 全球版图

**ch12.md**：专利地图 + FTO风险矩阵 + IP谈判筹码

**ch13.md**：三级梯队 + 产能估算 + 供应链风险

**app-a/b/c.md**：A交易案例库(6+笔) / B信息来源 / C监控清单(9-10项)

### 步骤3：调用脚本合并所有章节MD文件

**必须调用合并脚本**，禁止手动拼接。所有章节生成完毕后执行：

```bash
python scripts/merge_md.py --dir ./chapters --output ./report.md --enterprise "企业名"
```

脚本按 `ch00-header → ch01~ch05 → ch06a~ch06e → ch07~ch13 → app-a/b/c` 的顺序拼接，章节间自动添加分隔空行，确保UTF-8编码无乱码。

### 步骤4：质量检查

打开合并后的 `report.md`，按 `references/report-framework-v2.md` 中的质量检查清单逐项核查。如发现问题，修改对应章节MD文件后重新执行步骤3合并。

### 步骤5：调用脚本生成HTML

**必须调用转换脚本**，禁止手动生成HTML。MD报告核查通过后执行：

```bash
python scripts/md2html.py --input ./report.md --output ./report.html --enterprise "企业名" --phase "Phase X"
```

脚本使用python-markdown库完整渲染表格、列表、代码块、blockquote等Markdown语法，生成带专业样式的HTML文件。

### 可选分支
- 当企业非生物医药行业：第六章BD武器库结构不变，内容适配行业特征（无临床管线替换为产品路线图，CDMO替换为供应链策略）
- 当企业为Phase 3：调整第七章切入建议的紧迫性
- 当信息不足：标注"未公开"或"信息不足"，不编造数据
- 当找不到对应行业画像文件：使用最接近的二级画像，并在报告中说明

## 注意事项
- **步骤3和步骤5必须调用脚本执行**，禁止手动拼接或自行生成HTML。脚本使用python-markdown库完整渲染表格、列表、代码块等语法，手动生成会导致内容丢失和格式错误
- BD白金时间窗口 = 上市意向公开前的几周；确认信号出现即窗口关闭
- 预警信号比确认信号更重要，越早发现预警信号，BD价值越高
- 行业画像按需读取：先读二级画像了解行业全貌，再按需读取三级画像获取细分赛道特征
- 资格认定类信号标注"—"不计入分数，CFO引入是必检项（空缺记0分）
- 信息来源需可靠，信息不足时标注"未公开"而非编造
- 报告标题禁止包含版本标签（Final/vX.X等）
- AI提示块仅放在6.X子节末尾和7.3子节末尾，其他章节不放
- 每章至少300字，第六章至少3000字
- 每个章节独立写入 `./chapters/` 目录，质量检查发现问题只需修改对应章节文件后重新合并
