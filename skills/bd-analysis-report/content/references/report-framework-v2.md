# BD分析报告生成框架 v2.0

## 零、使用方式

```
【系统指令】你是一位资深BD分析师，请基于本框架，
为以下企业生成完整的BD Phase 4分析报告：
📎 企业名称：[XXX]
📎 所属行业：[XXX]
📎 分析日期：[YYYY-MM-DD]

请严格按照框架的章节结构、写作风格、数据密度、格式规范输出。
先进行信息收集和分析，然后输出完整Markdown报告。
```

---

## 一、报告头部规范

### 1.1 MD文件头

```markdown
# 企业BD分析范例：[企业全名]（Phase [X]）

---

> **分析日期**: YYYY-MM-DD

## 一、[第一章标题]

> **标准依据**: 基于行业细分画像评分及输出标准完成
```

**规则**：
- 标题不含"Final"、"完整版"、"vX.X"等任何版本标签
- 章节从"一、"开始平级编号（一~十三），附录为"附录A/B/C"
- 标准依据行放在第一章章节标题下方、第一个子标题上方
- meta区只有2行：分析日期 + 分析师
- 不写版本号

### 1.2 HTML Header规范

```
badge: "BD Analysis / Phase [X]"
h1: "企业BD分析范例：<span>[企业名]</span>"
meta: 只显示「分析日期：YYYY-MM-DD」
footer: "本报告基于行业细分画像评分及输出标准完成 · 仅供BD决策参考"
```

**HTML样式要求**：
- 白底专业风格（`--bg:#ffffff`）
- 深色渐变Header（`#1a1a2e → #2d2d44`）
- 蓝色强调色（`#2563eb`）
- 章节用`.sec` div包裹，带编号圆角标签（`.sec-num`）
- AI提示块用`.aih`样式（蓝色左边框+淡蓝背景）
- 表格hover高亮行
- 响应式适配（`@media max-width:768px`）

| 产品代号 | 适应症 | 阶段 | 亮点 |
|---------|--------|------|------|

- 每个产品的阶段描述必须包含最新进展的具体日期

#### 1.3 核心团队表

| 姓名 | 职位 | 背景 |
|------|------|------|
| **创始人姓名** | 创始人/董事长/CEO | 学历+核心成就（**加粗最关键贡献**）+学术成果+职业经历+最新荣誉 |

**规则**：

### 第二章：BD评分与Phase判定

#### 2.1 行业画像依据

```
**所属行业**：广义分类（如基因与细胞疗法）/ 细分赛道（如小核酸药物）

**画像文件**：`03_三级行业画像_[对应行业]_vX.X.md`
```

#### 2.2 预警信号检测表

| 信号类型 | 检测结果 | 权重 | 得分 | 说明 |
|---------|---------|------|------|------|
| **信号1** | 具体事实 | 权重分值 | **得分** | 为什么得这个分 |
| **信号2** | ... | ... | **...** | ... |
| **资格认定类1** | 具体 | — | — | 政策红利说明 |
| **CFO引入** | 状态 | 权重 | 实际得分 | 说明 |

**规则**：
- 加权求和得出总分
- 资格认定类信号（孤儿药、快速通道等）列出来但标注"—"不计入分数（作为加分项参考）
- 必须有"CFO引入"这一行（通常权重10分，未引入则0分）

#### 2.3 BD紧迫性评分

```
BD紧迫性 = 预警信号加权之和
         = X1 + X2 + X3 + ...
         = 总分

评级：Phase X（BD最佳窗口/需关注/...，全力推进/保持接触/...）
```

使用`<pre><code>`代码块格式呈现公式。

#### 2.4 Phase判定表

| Phase | 定义 | [企业名]状态 |
|-------|------|-------------|
| Phase 1 | 早期，预警信号不足 | ❌/✅ 原因 |
| Phase 2 | 建立认知阶段 | ❌/✅ 原因 |
| Phase 3 | 预警信号累积中 | ❌/✅ 原因 |
| **Phase X** | **当前状态定义** | ✅ **当前阶段（XX分）** |
| Phase 5 | 窗口关闭 | ❌/✅ 原因 |

随后跟：

**判定依据**：（逐条列✅❌）
**结论**：一段话总结当前Phase + 分数 + 窗口状态 + 行动建议
**关键修正说明**：（如果有非标准判定的特殊说明）

## 三、写作风格规范

### 3.1 语言风格
- 专业、客观、有洞察力
- 数据驱动：每个论断尽量有数字支撑
- 不用空洞形容词（如"很好""优秀"），改用具体数据和对比
- 允许有判断性语言（如"极高""强烈建议"），但必须基于前面的事实分析

### 3.2 格式约定
- 章节间用 `---` 分隔
- 重点内容用 `**加粗**`
- 引用外部观点用 `> blockquote`
- 评分公式用 `<pre><code>` 代码块
- 所有表格标准Markdown格式
- 不使用emoji（除非是⚠️/❌/✅/★等功能符号）
