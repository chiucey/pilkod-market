# 游戏设计文档（GDD）项目初始化

基于标准化 GDD 大纲 + 游戏设计理论，引导用户逐步完成游戏设计文档的创建，在每个章节提供设计原理支撑，确保设计思路完整且专业。

## 触发条件

当用户表达以下意图时，调用此技能：
- "创建一个新的游戏设计文档" / "帮我写一份 GDD"
- "我要规划一个新游戏项目" / "初始化一个游戏设计项目"
- "帮我设计核心循环" / "这个游戏的难度怎么平衡"
- "分析一下我的目标玩家" / "设计一套进度系统"
- 任何游戏设计相关的咨询与规划

## 设计工具箱（随时参考）

在引导各章节时，将以下理论知识嵌入对应环节。

### 核心循环设计 — 30 秒测试

```
ACTION → FEEDBACK → REWARD → REPEAT
 玩家操作 → 游戏响应 → 玩家满足 → 循环重复
```

| 类型 | 核心循环示例 |
|------|-------------|
| 平台跳跃 | 跑 → 跳 → 落地 → 收集 |
| 射击 | 瞄准 → 射击 → 击杀 → 拾取 |
| 解谜 | 观察 → 思考 → 解谜 → 推进 |
| RPG | 探索 → 战斗 → 升级 → 装备 |

**原则**：如果 30 秒内无法让玩家感受到乐趣，核心循环需要重新设计。

### 玩家心理学 — 四种动机类型

| 类型 | 驱动力 | 设计对策 |
|------|--------|----------|
| **成就型** | 目标、完成度 | 成就系统、排行榜、100% 收集 |
| **探索型** | 发现、秘密 | 隐藏区域、彩蛋、多分支路径 |
| **社交型** | 互动、社区 | 公会、交易、协作任务 |
| **杀手型** | 竞争、统治 | PvP 天梯、排行榜、竞技场 |

### 奖励排期

| 排期 | 效果 | 适用场景 |
|------|------|----------|
| **固定** | 可预测、安全感 | 里程碑奖励、签到 |
| **可变** | 成瘾性强、惊喜感 | 战利品掉落、抽卡 |
| **比例** | 努力驱动 | 肝系游戏、进度条奖励 |

### 难度平衡 — 心流状态

```
太难 → 挫败感 → 流失
太易 → 无聊   → 流失
适中 → 心流   → 沉浸
```

| 平衡策略 | 做法 |
|----------|------|
| **动态调节** | 根据玩家表现自动调整难度 |
| **玩家自选** | 让玩家选择难度等级 |
| **无障碍选项** | 提供辅助功能覆盖各类玩家 |

### 进度系统 — 四种成长类型

| 类型 | 含义 | 示例 |
|------|------|------|
| **技能成长** | 玩家自身变强 | 操作熟练度、策略理解 |
| **数值成长** | 角色属性变强 | 等级、装备、技能树 |
| **内容解锁** | 新区域/新玩法 | 新地图、新模式 |
| **叙事推进** | 剧情发展 | 主线任务、角色弧光 |

**节奏原则**：快速给甜头 → 逐步加挑战 → 高强度间穿插休整 → 提供有意义的选择

### 设计反模式

| ❌ 错误做法 | ✅ 正确做法 |
|------------|------------|
| 闭门造车 | 持续 playtest |
| 先打磨再验证趣味 | 先做原型验证核心乐趣 |
| 强制单一玩法 | 允许多种玩家表达 |
| 过度惩罚 | 奖励进步 |

## 工作流程

### 第一步：确认项目基本信息

询问用户：
1. **项目名称** — 游戏的正式名称
2. **项目类型** — PC 单机 / 手游 / 主机 / VR / Web / 其他
3. **目标目录** — 用户希望存放 GDD 的本地路径

确认后，在目标目录下创建：

```
<项目名称>/
├── GDD.md
├── assets/
│   ├── references/
│   ├── concepts/
│   └── mockups/
└── changelog.md
```

并在 `GDD.md` 中写入完整标题框架。

### 第二步：逐章节引导填写

按以下 11 章顺序，逐章引导用户。每次只处理一个章节，融入对应设计理论辅助决策，完成后再进入下一章。

---

#### 第 1 章：文档信息

生成元信息表格，引导用户逐项填写：

| 字段 | 说明 |
|------|------|
| 项目名称 | 游戏正式名称 |
| 项目类型 | PC / 手游 / 主机 / VR / Web / 其他 |
| 项目状态 | 概念阶段 / 预制作 / 制作中 / 已发布 |
| 项目负责人 | 主要负责人姓名 |
| 项目团队 | 团队成员及角色 |
| 项目时间 | 预计开始与交付日期 |
| 项目预算 | 预算范围 |
| 项目描述 | 一段话概括游戏核心体验 |
| 项目版本 | 当前文档版本号（如 v0.1） |

---

#### 第 2 章：执行摘要（Executive Summary）

引导用户用简洁语言概括游戏全貌：

- **2.1 一句话 pitch**：公式 — `[玩家] 在 [世界] 中 [做什么] 来 [达成目标]`
- **2.2 核心卖点（Key Selling Points）**：列出 3–5 条游戏最独特的吸引力
- **2.3 目标受众**：结合**玩家心理学四种动机类型**（成就型/探索型/社交型/杀手型），分析核心玩家画像（年龄、偏好、游戏习惯），明确主要面向哪种动机类型的玩家
- **2.4 商业模型**：买断制 / 免费+内购 / 订阅制 / 广告变现 等

---

#### 第 3 章：游戏概述（Game Overview）

引导用户定义叙事与氛围：

- **3.1 世界观与背景设定**：故事发生的时代、世界规则、历史背景
- **3.2 叙事框架**：故事结构（线性 / 分支 / 开放）、叙事驱动方式
- **3.3 主题与基调**：核心主题，整体视觉与情感基调

---

#### 第 4 章：核心玩法设计（Core Gameplay）⭐

GDD 最核心章节，结合**核心循环设计理论**重点引导：

- **4.1 核心循环（Core Loop）**：
  - 先确认用户的游戏属于哪种类型（平台跳跃/射击/解谜/RPG 等），参考上方循环示例
  - 用 **30 秒测试法则** 检验：ACTION → FEEDBACK → REWARD → REPEAT
  - 用文字或流程图描述核心循环（如：探索 → 战斗 → 获取资源 → 强化 → 探索）
- **4.2 主要机制**：
  - 4.2.1 基础机制（移动、交互、战斗等基础操作）
  - 4.2.2 进阶机制（连招、建造、策略等深度系统）
- **4.3 游戏模式**：单人 / 多人合作 / PvP / 异步交互等
- **4.4 难度曲线**：结合**心流理论**和**三种平衡策略**（动态调节/玩家自选/无障碍），描述难度如何递进

---

#### 第 5 章：系统架构（System Design）

引导设计数值与逻辑系统，结合**进度设计理论**：

- **5.1 经济系统**：货币种类、获取途径、消耗出口、经济循环
- **5.2 进度系统**：结合**四种成长类型**（技能/数值/内容/叙事），设计玩家成长路径（等级 / 技能树 / 装备 / 声望）；遵循**节奏原则**（快速甜头→逐步挑战→休整→有意义选择）
- **5.3 物品系统**：结合**奖励排期理论**（固定/可变/比例），设计物品分类、稀有度、掉落方式
- **5.4 AI 系统**（如适用）：敌人行为树、NPC 日常逻辑、Boss 机制

---

#### 第 6 章：内容规划（Content）

引导评估内容量：

- **6.1 关卡/场景设计**：关卡数量、场景类型、设计原则
- **6.2 角色设计**：可玩角色、NPC、敌人数量与定位
- **6.3 任务/活动设计**：主线/支线任务数量、活动类型
- **6.4 叙事内容量**：文本字数预估、CG 数量、配音量

---

#### 第 7 章：用户体验设计（UX）

引导规划交互体验：

- **7.1 界面架构（IA）**：界面层级关系、菜单结构图
- **7.2 交互规范**：按键映射、触屏手势、手柄支持
- **7.3 新手引导（Onboarding）**：引导策略、关键教学节点；确保新玩家在 30 秒内体验到核心循环

---

#### 第 8 章：美术与视听（Art & Audio）

引导定义感官表现：

- **8.1 美术风格指南**：风格关键词、色彩方案、参考作品
- **8.2 技术美术**：渲染管线、Shader 需求、性能目标
- **8.3 音频设计**：音乐风格、音效清单、环境音策略
- **8.4 资产清单（预估）**：角色模型、场景、UI、特效、音频的数量预估

---

#### 第 9 章：技术架构（Technical）

引导确定技术选型：

- **9.1 引擎与工具**：Unity / Unreal / Godot / 自研引擎 等
- **9.2 技术需求**：平台目标、最低配置、网络方案（单机/联机）
- **9.3 数据与存档**：存档格式、云存档需求、数据结构概要

---

#### 第 10 章：运营与 Live Ops（服务型游戏）

如游戏为服务型（GaaS），引导填写；单机游戏可跳过：

- **10.1 内容更新计划**：赛季规划、DLC 计划
- **10.2 社区与社交**：社交系统、社区运营策略；对应社交型玩家需求
- **10.3 数据分析**：关键数据指标（DAU、留存、付费率等）

---

#### 第 11 章：开发计划（Production）

引导制定可执行的开发路线：

- **11.1 里程碑规划**：各阶段交付物与时间节点（概念验证 → 原型 → Alpha → Beta → 发布）；**原型阶段务必验证核心循环的 30 秒乐趣**
- **11.2 风险评估**：技术风险、设计风险、资源风险及应对方案
- **11.3 预算概览**：人力成本、外包成本、工具授权费、营销预算

---

### 第三步：审阅与迭代

全部章节完成后，结合**设计反模式清单**执行检查：

1. **一致性检查**：核心循环与系统架构对齐？内容规划与开发计划匹配？
2. **完整性检查**：每个章节有实质内容？无跳过的重要模块？
3. **可行性检查**：风险评估覆盖关键瓶颈？预算与里程碑合理？
4. **反模式检查**：是否存在闭门造车（未考虑 playtest）、先打磨后验证、强制单一玩法、过度惩罚等问题？

将检查结果附在 `GDD.md` 末尾。

### 第四步：变更管理

每次 GDD 重大修改时，在 `changelog.md` 中追加：

```
## [版本号] - YYYY-MM-DD
### 新增
- ...
### 修改
- ...
### 移除
- ...
```

## 使用示例

**场景 1 — 完整 GDD 创建**：
> 用户："帮我创建一个三国题材的策略游戏 GDD"
>
> AI：确认项目信息 → 创建目录结构 → 从第 1 章开始逐章引导 → 审阅检查

**场景 2 — 单独咨询设计理论**：
> 用户："我的 Roguelike 游戏核心循环感觉不够吸引人"
>
> AI：调用 30 秒测试法则分析，结合奖励排期（可变排期增加成瘾性）给出建议

**场景 3 — 进度系统设计**：
> 用户："给我的 RPG 设计一套成长系统"
>
> AI：结合四种成长类型和节奏原则，引导用户定义等级、技能树、装备体系
