# 开发过程回顾(从原型到模板的形成路径)

## 起点
用户给了一张参考图(5472×3072 高清 JPG),要求"用 ECharts 实现这个大屏"。第一反应是直接复刻,后续发现:
1. 参考图配色其实是奶油白底,我误判为深蓝科技风
2. 用户的屏幕是 200% 缩放,我没考虑响应式
3. echarts-gl 的 3D 散点位置计算有 bug,折腾多次

最终从一张图做成一个**可复用的可视化大屏开发方法论 + 可重跑的代码模板**。

## 迭代过程(7 个版本)

### v1 — 基础版(深蓝科技风)
- 多文件结构: 9 个 JS 文件,职责清晰
- 基础图表: TOP10/折线/表格/3D 地图/环形/柱状
- CDN 引用 ECharts + echarts-gl
- 问题: 用户反馈"empty" → CDN 被墙

### v2 — 离线化 + 修 3D bug
- 把 echarts.js 和 echarts-gl.js 下载到 `/assets/` 目录
- 多次尝试修复 3D 散点位置 bug(花了 2 小时)
  - 试过: scatter3D + geo3D → 漂到地图外
  - 试过: bar3D + geo3D → 同上
  - 试过: grid3D + cartesian3D → 太复杂
  - **最终方案: 改用 2D geo,放弃 3D 散点**
- 高亮逻辑反复折腾:
  - visualMap 覆盖 itemStyle.color
  - setOption merge 导致旧 itemStyle 残留
  - **最终方案: 用 2D geo + series[i].data[i].itemStyle.color 直接覆盖**

### v3 — 配色翻转(深渊级认知)
**关键转折**: 用户发来原图,我之前的"深蓝科技风"完全错了。
- 事实: 参考图底色是奶油白(径向渐变 #e8f1fa → #ffffff)
- 浅蓝色只是点缀(光柱/标签/边框)
- 我做了反过来的方向
- **教训: 第一步是看图,不是我以为的"标准科技风"**

### v3.1 — 细节修复
- SVG 图标: 总设备(房子 SVG)是错的 → 用风电场图标(底座 + 3 杆塔 + 3 风叶)
- 总员工: 重新画橙色人形(头 + 身体)
- 时间布局: `时:分:秒 / 日期` → `时:分:秒 | 星期四 / 2022-12-08`(右边两行)

### v3.2 — 布局对齐
- 移除独立 footer 行(grid-template-rows 3 行 → 2 行)
- Tab 内嵌到地图 panel 底部
- 左/右 column 延伸到屏幕底部
- 总设备卡片露出(原来被挤在右列下面)
- 季度/设备运行 两个 panel 与左下"浙江省"行对齐

### v3.3 — 自适应缩放
**用户反馈**: "我的屏幕分辨率设计为 200% 放大,显示出来没有对齐"
- 真相: 不是响应式的问题,是因为大屏写死了 1920×1080 像素值
- 解决: 把 #app 固定 `width:1920px height:1080px` + `transform: translate(-50%,-50%) scale(var(--scale))`
- 通过 `--scale` CSS 变量动态调整:`Math.min(innerWidth/1920, innerHeight/1080)`
- 测试通过: 1366×768 / 1920×1080 / 2560×1440 / 3840×2160 (即 200%) 全部对齐

### v4 — 最终版(本次)
- 字体加大 ~30%(标题 46, 面板标题 18, 总计 38)

## 关键方法论沉淀

### 1. 第一步永远先看参考图
我问自己"原图整体是什么风格",然后对照看具体细节(字体大小、配色比例、模块布局)。不要凭印象判断。

### 2. 自适应必须用 transform scale,不是 vw/vh
大屏设计稿是固定 1920×1080。用 vw/vh 重写所有尺寸**会让代码复杂度爆炸**。
更好的办法是: 设计稿固定 1920×1080 + transform scale = 单一变量。
200% 系统缩放下,viewport 不变,但 transform scale 自动适应到屏幕尺寸的 2 倍。

### 3. ECharts 大屏的核心是"轻图表 + 重联动"
- 每个图表本身不难(就是数据绑到配置)
- 难的是: 多图表联动 + 数据变更响应 + 视觉一致性
- 模式: 暴露 `window.xxxChart = { highlight/clear }`,统一在 syncFromXxx 桥接函数里联动

### 4. 三大坑提前知会
1. echarts-gl 2.x 的 3D 散点位置 bug,直接用 2D geo
2. visualMap 与 per-item itemStyle 冲突,用 inline
3. map3D label 不可靠,改用 tooltip + 自定义标注

### 5. 自检工作流不可省
- Playwright + chromium 截图验证是不可省的最后一步
- 多分辨率测试(1366/1920/2560/3840)保证自适应稳定
- 监听 console.error + pageerror 捕获 JS 异常
- 测试联动 API 是否被正确暴露

### 6. 用户语言解读
- "字体偏小" → 几乎每次都偏小,默认用更大字号
- "padding 不对" → 截图对比,找到具体的元素位置
- "empty" → 通常是 JS 错误或资源加载失败,先排查控制台
- "自适应" → 默认用 transform scale 方案
