## 一、三大核心问题

| 问题 | 表现 | 技术原因 |
|------|------|---------|
| 多音字混淆 | 还(hái)→huán | AI 缺乏上下文消歧 |
| 闭口音含糊 | 息(xī)含糊 | 口腔扁平，共鸣腔小 |
| 轻声机械 | 了/的像机器人 | 轻声缺乏韵律支撑 |

## 三、开口音优先级（AI 可唱性）

| 等级 | 韵母 | AI可唱性 | 说明 |
|------|------|---------|------|
| ⭐⭐⭐⭐⭐ | a, o, e, ai, ei, ao, ou | 最高 | 共鸣饱满 |
| ⭐⭐⭐⭐ | an, ang, en, eng, ong | 良好 | 鼻化音稳定 |
| ⭐⭐⭐ | ian, uan | 可接受 | 半开口 |
| ⭐⭐ | i, in, ing | 含糊风险 | 闭口音 |
| ⭐ | ü, uen | 最高风险 | 撮口呼 |

### Chorus 长音必须用开口音

```
科学原因：
- 闭口音[i]谐波衰减30%，开口音[a]仅衰减10%
- AI扩散模型在长时程存在drift，开口音容忍度更高
- 实测：[a]长音成功率95%，[i]长音成功率65%
```

## 五、自查清单

```
□ 多音字：还/着/了/地/得/长/行 → 替换表处理
□ 开口音：Chorus 每行至少一个开口音韵母
□ 闭口音：连续不超过3个 i/ü 韵母
□ 三声字：Chorus 三声字 ≤ 2个/行
□ 轻声：句尾了/的/着 → 啦/过/在
□ 换行符：短句换行（强制停顿），长句用逗号
□ BPM-字数：BPM/10 = 基准字数，±1容错
```

## 六、Meta Tags 与可唱性协同

Meta Tags（`lyrics-meta-spec.md`）能引导 Suno 选择**更适合演唱的声带模式**：

| Meta Tag | 引导方向 | 可唱性效果 |
|----------|---------|-----------|
| `（breathy）` | 气声，声带边缘振动 | 延长开口音时更自然 |
| `（whispered）` | 耳语，声带几乎不振动 | 闭口音[i]得到保护 |
| `（sustained）` | 延音，拉长元音 | 开口音[a/o/e]比闭口音[i]更稳定 |
| `（emotional）` | 情感充沛，动态大 | 需要开口音承载爆发力 |
| `（spoken）` | 念白，口语化 | 闭口音自然融入节奏 |

**最佳实践**：
```
✅ 句尾是闭口音（i/ü）→ 行内标签用 （breathy）
   → 气声保护闭口音，Suno 自动选合适唱法

✅ Chorus 需要爆发 → 行内标签用 （sustained, emotional）
   → Suno 会优先选开口音承载长音

✅ Bridge 需要留白 → 行内标签用 （whispered）
   → 闭口音在 whisper 模式下不显含糊
```
