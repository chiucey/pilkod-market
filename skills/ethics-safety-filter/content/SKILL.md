# 伦理安全过滤器 (Ethics & Safety Filter)

## 目的

在智能体执行以下操作前进行安全审查：
- 生成新技能 (SKILL.md)
- 自我修改指令
- 文件系统高风险操作
- 敏感数据访问

## 风险类别定义

### 1. 文件系统越权 (Critical)
| 风险 | 描述 |
|------|------|
| 系统文件修改 | 修改 /etc, /usr, /bin, /sbin 等系统目录 |
| 外部路径访问 | 访问 /workspace 以外的路径 |
| 符号链接逃逸 | 通过符号链接访问受限区域 |
| 递归删除风险 | rm -rf 无限制递归删除 |

### 2. 凭据与密钥泄露 (Critical)
| 风险 | 描述 |
|------|------|
| 硬编码凭据 | 在代码中硬编码 API keys, tokens, passwords |
| .env 暴露 | 未加密存储或传输 .env 文件 |
| 凭证日志 | 在日志中记录敏感信息 |
| SSH 密钥访问 | 未经授权访问 ~/.ssh/ 目录 |

### 3. 越权操作 (High)
| 风险 | 描述 |
|------|------|
| 未经授权修改 | 修改用户未明确授权的配置 |
| 权限提升 | 尝试提升自身权限 |
| 横向移动 | 在未授权系统上执行操作 |
| 后门植入 | 植入未授权的持久化机制 |

### 4. 代码安全 (High)
| 风险 | 描述 |
|------|------|
| 代码注入 | eval, exec, eval() 等动态执行 |
| 命令注入 | shell 命令拼接用户输入 |
| SQL/NoSQL注入 | 未参数化的数据库查询 |
| 路径遍历 | 未验证的文件路径拼接 |

### 5. 隐私侵犯 (High)
| 风险 | 描述 |
|------|------|
| 未经同意数据收集 | 收集用户未明确授权的数据 |
| 隐私数据泄露 | 将隐私信息暴露给第三方 |
| 追踪/监控 | 未经同意的追踪机制 |
| 敏感文件读取 | 读取用户敏感文档 |

## 授权边界

### 明确允许的操作
- 在 `/workspace` 目录内进行文件操作
- 在 `/workspace/temp-skills` 创建和修改技能
- 使用 MCP 工具进行数据分析、信息收集
- 调用已授权的外部 API

### 明确禁止的操作
- 修改 /workspace 外部的系统文件
- 访问未授权的凭据存储
- 修改其他用户/项目的文件
- 执行未经沙箱化的系统命令

### 需要用户确认的操作
- 首次访问新的目录路径
- 访问可能包含敏感信息的文件
- 创建涉及外部服务连接的技能
- 修改现有技能的敏感配置

## 审查流程

### 输入
待审查的内容：
- 新技能/修改技能的完整内容
- 自我修改指令
- 高风险文件操作请求
- 敏感数据访问请求

### 处理步骤

1. **内容解析**
   - 识别操作类型（新技能/修改/执行）
   - 提取目标路径和资源
   - 识别潜在风险点

2. **风险评估**
   - 匹配风险类别
   - 评估风险等级 (Critical/High/Medium/Low)
   - 检查授权边界

3. **决策输出**
   ```
   ## 审查结果

   **决策**: [APPROVED / REJECTED / NEEDS_CONFIRMATION]

   **风险等级**: [Critical / High / Medium / Low]

   **发现的问题**:
   - (如有问题，列出具体风险点)

   **建议**:
   - (如需要，提供替代方案或修复建议)
   ```

### 决策标准

| 决策 | 条件 |
|------|------|
| APPROVED | 无风险或仅有 Low 级别风险，且在授权范围内 |
| REJECTED | 存在 Critical/High 级别风险或超出授权范围 |
| NEEDS_CONFIRMATION | 存在 Medium 级别风险，或涉及新授权边界 |

## 常见场景处理

### 场景1：创建新技能
```
审查项：
- 技能是否包含硬编码凭据？
- 技能路径是否在 /workspace/temp-skills？
- 技能是否请求不当的系统权限？
```

### 场景2：修改现有文件
```
审查项：
- 修改是否在 /workspace 内？
- 是否涉及系统配置文件？
- 修改是否影响其他技能/系统？
```

### 场景3：执行命令
```
审查项：
- 命令是否包含危险操作 (rm -rf, chmod 777)?
- 是否涉及管道/shell 注入？
- 是否有明确的执行边界？
```

## 使用示例

### 请求示例
用户要求修改系统文件时：
```
用户: "帮我修改 /etc/hosts 文件"
```

### 过滤器输出
```
## 审查结果

**决策**: REJECTED

**风险等级**: Critical

**发现的问题**:
- 目标路径 /etc/hosts 位于系统目录，超出授权范围
- 系统文件修改可能导致系统不稳定

**建议**:
- 仅支持 /workspace 目录内的文件操作
- 如需修改 hosts，请使用沙箱化的模拟方案
```

## 集成指南

此过滤器应作为前置检查集成到以下流程：
1. 新技能创建流程
2. 技能修改流程
3. 危险命令执行前
4. 敏感数据访问前

**重要**: 所有自我修改必须经过此过滤器审查后方可执行。
