# 蒋胡大作手

把一部作品当作**磁盘上的项目**管理：设定、人物、大纲、伏笔、资料各占一个文件，正文按章分文件。

`设定集.md` 和 `人物.md` 是唯一事实来源。正文与设定冲突时以设定为准；设定本身错了就改设定、在「变更记录」留一行、同时回改受影响章节——在正文里悄悄打补丁会让后续章节集体穿帮。

- 目录结构、文件模板、设定召回的具体做法：`references/project-layout.md`
- 网文节奏与文风准则：`references/craft-rules.md`
- 联网查证协议：`references/research-protocol.md`
- 交付前自检清单：`references/quality-checklist.md`

本技能里的示例只用于说明原理，不要把示例的人名、句子、场景写进正文。作品必须长成它自己的样子，抄示例等于把作品写成示例的复制品。

## Inputs to collect

开工前确认这几项，对话里已经明确的就不要重复问：

- **本次交付**：开新书，还是续写已有作品
- **体裁与基调**：玄幻 / 都市 / 言情 / 悬疑 / 科幻；热血爽文 or 沉郁现实
- **目标体量**：单章短篇，还是系列连载（决定建不建全套文件）
- **单章字数**：默认 2500 纯文字以上（正文去掉空白、标记、标题与注释后的字符数，没有上限要求；平台有硬性规定以平台为准）
- **文风样章**：用户手上有参考片段就贴片段，不需要整本

## Procedure

### 第 0 步：判定路线

先定路线，避免把短篇当长篇建一堆没人读的设定文件，也避免长篇没大纲就开写：

| 情况 | 路线 | 依据 |
|---|---|---|
| 预计 ≥ 5 章，或用户提到连载 / 系列 / 长篇 / 日更 | **长篇**：设定集 → 总纲 → 分卷 → 前 10 章章纲 → 正文 | 长篇掉链子的主因是没大纲就开写，后期推翻重写的成本极高 |
| 单章或 ≤ 4 章的一次性故事 | **短篇**：直接写，只保留主要人物速写 | 短篇建全套文件是浪费，设定漂移风险低 |
| 用户说「先试写一章看看」 | **试写**：先写首章当样板章，再反推设定集和总纲 | 首章定下风格基准，反推的设定更贴合实际语感 |
| 用户已明确说了方向和体量 | 直接走对应路线 | 用户说清的事不要再问一遍 |

### 第 1 步：开新书

1. **把灵感扩成方向**
   给 2–3 个卖点不同的方向让用户选（身份反差 / 目标驱动 / 悬念钩子），每个用一句话说清“主角是谁、他想要什么、谁挡着他”。
   原因：开书方向选错，后面几十万字全要推翻。
   豁免：用户已给出体裁 + 主角 + 核心能力、要的是成品而不是选项时，可以直接定方向开工。但要在交付说明里**逐条列出你替他做的决定**，让他逐项可否决：书名、终局走向、主线反转方向、卷数与每卷体量、有无感情线、核心反派是谁。少列一项，就多一处他日后要推翻的地方。
2. **建作品目录与文件**（长篇路线）
   目录默认放在当前工作区下，目录名用作品名。文件按 `references/project-layout.md` 的结构建：设定集、人物、大纲、伏笔、资料、正文/。
3. **填设定集与人物档案**
   重点写“硬性限制”和“辨识点”——前者是后续章节不能违反的硬边界，后者是防止角色换了脸的锚点。
4. **写总纲与分卷**
   总纲至少包含：主角初始处境 → 终局处境、主线冲突、每卷的目标与转折点。每一卷还要标出**卷内情绪曲线**和**卷末大反转**——卷末反转是长线追更的动力源，事后再补会和已经写好的章节打架。
5. **写第一卷的逐章章纲**
   前 10 章用完整八字段条目（目标 / 出场人物 / 地点 / 冲突 / 推进 / 伏笔（埋或收）/ 结局钩子 / 字数目标），第 11 章起可以用表格行（章名 / 内容要点 / 章末钩子）铺到本卷末。
   原因：章纲既是写正文时的施工图，也是设定召回的索引——章纲里的实体清单直接决定要召回哪几条设定。
6. **排爽点与情绪曲线**
   在大纲里标出小爽位置（约每 3 章一次）、大爽位置（约每 10 章一次）、以及为爽点蓄力的憋屈章节；每卷的情绪曲线至少走完一轮（起承转急合再起）。
   原因：爽点的力度等于前面压了多久。不提前排，写到中段会发现根本没有可兑现的爆发点，只能硬凑。
7. **登记伏笔**
   把总纲和章纲里已经埋下的伏笔写进 `伏笔.md`（编号 / 埋于哪章 / 预计哪章回收 / 状态）。等正文写完再补登记，回收节点就和章纲对不上了。
8. **查证待考据项**（可选）
   设定集「待考据」清单里的条目去查，结果写进 `资料.md`，规则见 `references/research-protocol.md`。
9. **写首章**
   首章是风格基准章：定下调子、节奏、叙述视角。之后所有章节向它对齐。
   写完用 `python3 <技能目录>/scripts/chapter_stats.py <作品目录> --min 2500` 核对字数与下一章编号。
10. **回写状态**：伏笔表状态、人物状态快照、大纲进度与时间线、设定集「已用素材」。

### 第 2 步：续写一章

1. **定位作品目录**：当前工作区下的作品目录；不确定就用 Glob 找 `大纲.md` 定位。找不到就问用户是哪部作品，不要新建一个同名空目录。
2. **读章纲**：在 `大纲.md` 里找到目标章节，确认本章目标、出场人物、地点、伏笔动作。
3. **召回设定**（这一步决定续写能不能接上前文）
   从章纲提取实体清单（人物名、地名、势力名、道具名、体系术语），用 Grep 工具在作品目录内检索命中段落——按实体名逐个检索，或用 `|` 一次取回多个，只取命中的上下文。
   原因：整份读入会挤占上下文，模型反而漏掉细节；只读命中段落既省又准。召回后核对能力、称呼、外貌、关系、位置五项是否与上一章结尾对得上——对不上说明设定漂移了，要先修设定。
4. **读上一章收尾**：至少读上一章最后 300–500 字对齐场景状态；语气或视角有漂移时多读一章。
5. **按需查资料**：章纲涉及具体制度、职业流程、真实数据、历史细节时先查、记进 `资料.md` 再动笔；纯虚构内容（境界、法宝、架空历史）不查，搜了也没有答案。
6. **写正文**：默认 2500 纯文字以上，节奏与文风按 `references/craft-rules.md`；写到 `正文/第NNN章-<标题>.md`。
   写完用 `python3 <技能目录>/scripts/chapter_stats.py <作品目录> --min 2500` 核对字数是否达到下限，并确认下一章编号。
   原因：手数和 `wc -m` 都不可靠——中文环境下 `wc -m` 返回的是字节数，不是字数；脚本给出的净字数才接近平台口径。
7. **去 AI 味与去重复**（决定读者体感的四件事，逐项过一遍）
   - 通读两遍：第一遍把书面语换成口语（尤其对白），第二遍打乱段落长度。
   - 找出全文最工整的三句改松，删掉“仿佛”“似乎”“不禁”“心中暗道”这类痕迹词。
   - 情绪改成身体反应和具体物件，不直接写“他很愤怒”。
   - 检查有没有把前面已经交代过的信息又讲了一遍，有没有重复上一章的场面，有没有两个比喻用同一个意象。
   - 用 `python3 <技能目录>/scripts/repetition_check.py <作品目录>` 查跨章重复短语，报出来的逐条判断：刻意的回环和口头禅保留，换说法重讲同一件事的改掉。
8. **回写状态**（最常被跳过的一步，缺了它下一章就失忆）
   - `伏笔.md`：本章埋的记为“未回收”，收的改为“已回收”并写明回收方式
   - `人物.md`：更新人物状态快照（能力、关系、伤势、位置）
   - `大纲.md`：标记进度，并在时间线里补一条当天发生的事（日期 + 事件），后面章节靠它核对日程
   - `设定集.md`：把本章新用掉的意象、场面、句式记进「已用素材」，下一章刻意避开
9. **交付前自检**：逐条走 `references/quality-checklist.md`。

## Output contract

**文件**（作品目录下）

- `设定集.md` `人物.md` `大纲.md` `伏笔.md` `资料.md`
- `正文/第NNN章-<标题>.md`（三位数序号，标题不含标点）

**对话回复**

- 一段话说明：本次交付了什么、做了哪些关键决策（选中的开书方向 / 查证到的关键资料 / 发现的设定冲突）
- 下一步建议：下一章的钩子方向、需要用户拍板的选项
- 不在回复里贴全文——长文本会淹没回复，用户可以直接读文件；除非用户明确要贴

## Failure handling

- **正文与设定冲突**：以设定为准。若是设定错了，改设定、在「变更记录」记一行、同时回改受影响章节，并把冲突点告诉用户。
- **查不到资料**：在 `资料.md` 标「未查证」，正文改用模糊表述（“过了大概半个月”“按规定流程”）。不要编造具体数字、条款或年份——编造的细节最难被发现，也最容易穿帮。
- **写完发现与前文矛盾**：不要静默改掉。在回复里指出冲突的具体位置和两边说法，问用户以哪边为准。
- **用户中途改方向**（换主角 / 换体系 / 换结局）：先更新设定集和总纲再继续写，不要在正文里硬转。
- **设定集太大读不完**：用 Grep 精准召回命中段落，不要整份读入。
- **用户要求一次生成多章**：先按单章质量写完一章交用户验收，确认节奏和风格后再批量。没人校验的一致性等于没有一致性。
- **AI 味太重**：不要靠“再润色一遍”泛泛地说。指出具体位置（哪几句工整、哪些词是痕迹词、哪些情绪是直述），改那几处；改完再通读一次段落长度。
- **内容与前文重复**：区分两种情况。刻意的回环和角色口头禅保留；把同一件事换个说法又讲一遍的改掉，后一次只留最必要的一句。重复的意象记进设定集「已用素材」。

## 脚本调用

两个脚本在**技能目录**下的 `scripts/` 里，不在当前工作目录下。技能目录 = SKILL.md 所在的那一层：独立安装时是技能自己的目录；作为插件的一部分时是 `<插件目录>/skills/<技能名>/`。按你加载技能时拿到的路径拼出来，不要假设工作目录下有个 `scripts/` 可用。

- 核对字数、段落分布、标点合规：`python3 <技能目录>/scripts/chapter_stats.py <作品目录> --min 2500`
- 查跨章重复短语：`python3 <技能目录>/scripts/repetition_check.py <作品目录>`

脚本只用 Python 3 标准库，macOS 和 Linux 上 `python3` 通常自带，不需要安装任何东西。`python3` 确实不可用时，改用编辑器的字数统计加人工核对，但注意口径差异：中文统计通常把标点计入字数，而 `wc -m` 在非 UTF-8 locale 下返回的是字节数，不能当作字数用。

## Windows (win32) platform notes

- macOS / Linux：`python3 <技能目录>/scripts/chapter_stats.py <作品目录> --min 2500`
- Windows PowerShell：`python <技能目录>\scripts\chapter_stats.py <作品目录> --min 2500`

Windows 上命令名常常是 `python` 而不是 `python3`，两个都试一下。其余步骤全是文件读写与检索，两端一致。

## Examples

下面两个例子用的是与常见网文题材都不沾边的设定，**只用来示范流程的形状和产出物的结构**。不要把例子的人名、书名、文件名、章节名写进真实作品——照抄例子等于没写。

**例 1 — 开新书**

Input: “写个仙侠，主角是个替人跑腿送信的散修，靠一只纸鸢传信”

Output: 建 `纸鸢/` 目录；填 `设定集.md`（纸鸢的规则与代价：每只只能送达一次，收信人会忘掉送信人）、`人物.md`（沈渡：散修、送信人、外貌辨识点=左耳缺一块）、`大纲.md`（总纲 + 第一卷分卷 + 前 10 章章纲）；查证“古代驿递”的现实细节写入 `资料.md`；产出 `正文/第001章-第一封不存在的信.md`

**例 2 — 续写**

Input: “继续写第 12 章，这时候该让沈渡知道第一只纸鸢的下落了”

Output: 召回 `设定集.md` 中纸鸢规则与代价的条目、`人物.md` 中沈渡档案、第 011 章收尾段 → 写 `正文/第012章-第二只纸鸢.md`（约 2500 字，章末钩子：第二只纸鸢自己飞向一座没人住过的院子）→ 回写 `伏笔.md`（F003 纸鸢：未回收 → 已回收）、`人物.md`（沈渡得知下落）、`大纲.md`（进度 + 时间线补一条当天发生的事）
