## 我会从数据中提炼的维度(提前对齐)

每次你给数据回来,我会按下面 8 个维度做归因分析:

1. **钩子类型表现** — 痛点/反差/共鸣/悬念/视觉暴力,哪种完播最高?哪种转化最高?
2. **原创钩 vs 老梗** — 自创钩(原创场景)vs 经典款(前男友/妈系列/求求求了),数据有没有差?
3. **视频类型 ROI** — 剧情带货 vs 口播 vs vlog,转化率排序?
4. **时长 vs 完播率** — 15s / 30s / 60s 的真实完播分布
5. **笑点密度阈值** — 15s 放 1 个笑点 vs 2 个 vs 3 个,哪个数据最好?
6. **CTA 软硬** — 硬引导(点击购物车)vs 软引导(关注/评论),GMV 差多少?
7. **平台差异** — 同一脚本在抖音/视频号/快手数据有没有差?(选题/话题/节奏可能要因平台调)
8. **价格带影响** — ¥100 以下 / 100-300 / 300-1000 / 1000+,转化路径差在哪?

## 沉淀 → 升级路径(原始数据 → skill 自动沉淀)

每收到一次反馈,skill 按以下路径沉淀迭代:

```
原始数据(反馈日志)
  → 归因分析(钩子型 / 类型 / 时长 / 平台)
      → 模式识别(连续 3 次扣分维度 = 系统性问题)
              → 自动沉淀进 references/
                    → 必要时升级 SKILL.md(改 description / Procedure / 自检项)
```

**自动沉淀触发条件**:

| 模式信号 | 触发次数 | 自动动作 |
|---|---|---|
| 同一钩子型连续 3 次完播/转化数据领先 | 3+ | 在 `hook-library.md` 顶部标注"高优钩子型" |
| 同一视频型连续 3 次完播塌方 | 3+ | 在 `trending-styles.md` 标注"慎用" |
| 同一自检维度连续 3 次扣分 | 3+ | 在 SKILL.md 加新自检项 |
| 同一错误反馈 ≥ 3 次 | 3+ | 写入 SKILL.md 的 Failure handling |

**用户也可以直接说**:
- "把这条加到 references 里"
- "更新自检"
- "以后默认走剧情带货 + 8-10 个钩子"

skill 立即执行,不必等数据沉淀。

**Skill 自身的迭代信号**:
- `feedback-log.md` 累计 ≥ 10 条真实数据 → 主动发起一次季度回顾
- SKILL.md 同一段落被 patch ≥ 3 次 → 重写该段(说明原结构有问题)
- `references/hook-library.md` 高优钩子占比 > 60% → 优先推这些

```

- 出现次数:3+
- 扣分详情:[具体差在哪里]
```
