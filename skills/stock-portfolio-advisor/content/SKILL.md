## 用户持仓传递方式（核心设计）

### 方式一：券商截图解析（⭐ 推荐，最简单）

用户将券商App的持仓截图直接发给儿臣，儿臣通过AI视觉识别自动提取持仓数据：

```
您发送图片 → AI识别持仓（名称/代码/持股数/成本价）→ 调用分析引擎
```

支持的券商App：
- 国泰海通（国泰君安）、东方财富、同花顺、中信建投、华泰证券、中信证券、广发证券、招商证券等**所有券商App截图**

识别字段：股票名称、代码、持股数、成本价、当前价、盈亏额、盈亏率

### 方式二：对话中直接提供（⭐ 推荐）

```
请分析我的持仓：[{"code":"sh600519","name":"示例股票A","shares":500,"cost":1800.0},{"code":"sz000858","name":"示例股票B","shares":300,"cost":150.0}]
```

### 方式三：飞书Bitable自动获取

当用户提供飞书持仓表格URL时，自动从Bitable读取持仓数据：
- 调用 `feishu_bitable_list_records` 获取所有记录
- 解析字段：股票名称、代码、持股数、成本价
- 构造持仓列表传入分析引擎

### 方式四：配置文件（固定持仓用户）

对于持仓固定的资深用户，可提前将持仓写入配置文件：
```
~/.holdings.json
```
格式：`[{"code":"sh600519","name":"示例股票A","shares":500,"cost":1800.0},...]`

## 执行流程

### Step 1：接收并解析持仓

**优先级顺序：**
1. **券商截图**（用户发送图片）→ AI视觉识别持仓
2. `feishu_bitable_list_records`（用户提供了飞书URL）
3. 用户对话中直接提供（解析为JSON）
4. `~/.holdings.json` 配置文件
5. 内置演示数据（技能测试用）

**持仓格式（标准）：**
```json
[
  {"code": "sh600519", "name": "示例股票A", "shares": 500, "cost": 1800.0},
  {"code": "sz000858", "name": "示例股票B", "shares": 300, "cost": 150.0}
]
```

### Step 2：多数据源行情获取

脚本自动尝试以下数据源，按优先级选用：

| 优先级 | 数据源 | 速度 | 覆盖 |
|--------|--------|------|------|
| 🥇 | 腾讯财经 | 毫秒级 | A股为主 |
| 🥈 | 新浪财经 | 快 | A股为主 |
| 🥉 | 东方财富 | 中 | 全市场 |

若主要数据源失败，自动切换备用源。

### Step 3：行业分类与结构分析

通过 `INDUSTRY_MAP` 内置表进行行业归属判断，输出：
- 行业分布占比（含文字条形图）
- 市值风格分布
- 集中度指标（单只/前三/HHI）

### Step 4：六维风险评估

| 维度 | 权重 | 评估方法 |
|------|------|---------|
| 集中度风险 | 25分 | 单只仓位占比 |
| 波动性风险 | 25分 | 平均日内振幅 |
| 流动性风险 | 25分 | 总成交量 |
| 趋势风险 | 25分 | 整体浮盈方向 |
| 仓位风险 | 25分 | 持仓占总资产比 |
| 相关性风险 | 25分 | 单一行业最大占比 |

### Step 5：仓位健康度诊断

基于6项指标计算综合评分（0-100），输出：
- 健康等级（🟢优秀/🟡良好/🟠需改善/🔴较差）
- 具体问题列表及建议

### Step 6：调仓建议

按优先级生成具体操作：
1. 🔴止损（浮亏≤-10%，逻辑破坏）
2. ⚠️分批止盈（浮盈≥30%）
3. 🟢加仓机会（浮亏+技术反弹 / 趋势向上）
4. ✅继续持有

## 注意事项

- **持仓格式**：`code` 必须包含市场前缀（`sh`/`sz`），如 `sh600519`
- **数据延迟**：腾讯财经约3-5秒延迟，盘中数据仅供参考
- **行业分类**：使用内置 `INDUSTRY_MAP`，未收录股票归为"其他"
- **现金假设**：分析时默认现金储备10万元（实际有差异不影响分析逻辑）
