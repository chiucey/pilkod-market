# 数据合规风险评估框架

## 一、项目合规评估方法论

### 1.1 评估启动阶段

```
评估准备清单：
□ 明确评估范围和目标
□ 组建评估团队（法务、技术、业务）
□ 收集项目资料
  - 产品/服务说明书
  - 技术架构文档
  - 数据流程图
  - 现有隐私政策/用户协议
  - 数据存储清单
□ 制定评估计划
```

### 1.2 数据映射阶段

**数据清单模板**：

| 数据字段 | 数据类型 | 敏感程度 | 来源 | 用途 | 存储位置 | 保留期限 | 共享方 |
|---------|---------|---------|------|------|---------|---------|-------|
| 用户手机号 | 个人信息 | 一般 | 用户输入 | 账户绑定 | 数据库A | 账户存续期 | 第三方X |
| 地理位置 | 个人信息 | 敏感 | GPS采集 | 定位服务 | 数据库B | 3年 | 无 |
| 交易记录 | 个人信息 | 一般 | 系统生成 | 订单处理 | 数据库C | 5年 | 支付机构 |

### 1.3 合规分析矩阵

| 合规要求 | 分析要点 | 风险点 | 风险等级 | 建议措施 |
|---------|---------|-------|---------|---------|
| 告知同意 | 是否明确告知收集目的、方式、范围 | 高/中/低 | 高/中/低 | |
| 最小必要 | 是否收集与服务无关的信息 | 高/中/低 | 高/中/低 | |
| 存储期限 | 是否超出必要期限 | 高/中/低 | 高/中/低 | |
| 安全措施 | 是否采取必要保护措施 | 高/中/低 | 高/中/低 | |
| 权利响应 | 是否提供权利行使渠道 | 高/中/低 | 高/中/低 | |

### 1.4 风险量化模型

```
风险值 = 影响程度 × 发生可能性 × 可控性

影响程度（1-5分）：
1 - 轻微影响
2 - 有限影响
3 - 中度影响
4 - 重大影响
5 - 灾难性影响

发生可能性（1-5分）：
1 - 几乎不发生
2 - 很少发生
3 - 有时发生
4 - 经常发生
5 - 频繁发生

可控性（1-3分）：
1 - 难以控制
2 - 部分可控
3 - 容易控制

风险等级划分：
高风险：风险值 ≥ 30
中风险：风险值 15-29
低风险：风险值 < 15
```

## 二、企业合规评估方法论

### 2.1 评估维度

```
一、组织管理（20%权重）
  1.1 数据保护组织架构
  1.2 职责分工与授权机制
  1.3 数据保护官（DPO）配置

二、制度建设（25%权重）
  2.1 数据安全总则
  2.2 个人信息保护政策
  2.3 数据分类分级制度
  2.4 访问控制制度
  2.5 应急响应预案

三、技术措施（25%权重）
  3.1 身份认证与访问控制
  3.2 数据加密
  3.3 日志审计
  3.4 数据脱敏/匿名化
  3.5 安全监测

四、运营执行（20%权重）
  4.1 数据收集合规性
  4.2 数据使用合规性
  4.3 数据共享合规性
  4.4 数据跨境合规性
  4.5 主体权利响应

五、持续改进（10%权重）
  5.1 培训与意识
  5.2 审计与检查
  5.3 风险评估与改进
```

### 2.2 差距分析模板

| 评估项 | 法规要求 | 能力成熟度（1-5） | 现状描述 | 差距分析 | 整改方向 | 工作量 | 优先级 |
|-------|---------|-----------------|---------|---------|---------|-------|-------|
| 数据分类 | PIPL第21条：应进行分类管理 | 1 | 尚未建立分类机制 | 缺乏系统性分类方法 | 建立数据资产清单和分类分级标准 | 中 | 高 |

### 2.3 能力成熟度模型

```
Level 1 - 初始级：未建立相关制度流程
Level 2 - 基础级：仅有零散规定，执行不规范
Level 3 - 规范级：建立制度但需优化，执行有待加强
Level 4 - 优化级：制度完善，执行有效，持续改进
Level 5 - 卓越级：最佳实践，行业标杆
```

## 三、数据出境评估方法论

### 3.1 出境必要性评估

```
出境必要性分析框架：

1. 业务需求分析
   □ 业务功能是否必须依赖境外处理
   □ 是否有可行的境内替代方案
   □ 出境数据范围是否最小化

2. 价值链分析
   □ 总部职能是否需要全球数据
   □ 跨境服务是否涉及境外用户
   □ 供应链是否需要跨境数据传输

3. 成本效益分析
   □ 境内化改造成本
   □ 对业务连续性影响
   □ 合规风险成本
```

### 3.2 境外接收方评估

```
评估要素：

1. 基本信息
   - 公司名称、注册地
   - 主营业务、规模
   - 实际控制人

2. 法律环境
   - 所在国家/地区数据保护法律
   - 政府数据访问权规定
   - 国际合作框架

3. 数据保护能力
   - 技术安全措施
   - 管理制度
   - 过往数据安全记录

4. 合同约定
   - 数据处理目的限制
   - 安全保障义务
   - 审计配合义务
   - 数据返还/销毁义务
   - 通知和报告义务
```

### 3.3 风险评估矩阵

| 风险类型 | 风险描述 | 影响程度 | 发生可能性 | 风险值 | 应对措施 |
|---------|---------|---------|-----------|-------|---------|
| 法律合规风险 | 境外法律变化导致合规不确定性 | | | | |
| 政府访问风险 | 接收方政府可能要求提供数据 | | | | |
| 安全事件风险 | 传输或存储过程中发生数据泄露 | | | | |
| 主体权益风险 | 数据主体权利难以保障 | | | | |
| 供应链风险 | 接收方分包商管理不当 | | | | |

### 3.4 申报材料自查表

```
□ 数据出境安全评估申报表（完整填写，无遗漏）
□ 数据出境风险自评估报告（内容完整、分析充分）
□ 数据处理者营业执照（有效期内）
□ 法定代表人身份证明
□ 数据处理者授权委托书（如适用）
□ 境外接收方注册证明文件
□ 数据出境合同/协议（已签署）
□ 标准合同（如适用，需完成备案）
□ 个人信息保护影响评估报告
□ 技术安全措施说明文档
□ 应急响应预案
□ 其他支持性材料
```

## 四、整改路线图

### 4.1 短期整改（1-3个月）

```
优先级：P0（高风险）
□ 停止违规数据处理活动
□ 建立紧急响应机制
□ 完成基础隐私政策更新
□ 建立基本访问控制
```

### 4.2 中期整改（3-6个月）

```
优先级：P1（中风险）
□ 完善数据分类分级
□ 建立数据全生命周期管理
□ 优化用户权利响应机制
□ 开展全员合规培训
```

### 4.3 长期建设（6-12个月）

```
优先级：P2（低风险/合规优化）
□ 建立数据安全治理体系
□ 实施技术防护措施升级
□ 建立持续监控机制
□ 定期审计和改进
```
