# Literature Interpretation - SCI论文深度解读技能

## 功能概述

- **触发方式**：用户提供英文SCI论文（PDF文件、文本内容或链接）并要求解读、分析或深度理解时触发
- **不适用的场景**：简单摘要翻译、文献检索（请使用 literature-alert）
- **输入类型**：英文SCI论文（PDF文件、文本内容、DOI/链接）
- **输出内容**：中文结构化深度解读报告（10个部分）
- **推送目标**：解读完成后发回当前对话（飞书私聊）

---

## 操作指令

收到用户提供的论文后，按以下10个部分依次输出，**不得跳过任何部分**：

> ⚠️ **执行解读时，严格参考 references 文件夹下的「解读框架规范.md」和「术语规范.md」。**

1. **论文基本信息** — 标题/作者/期刊/出版信息
2. **科研故事大白话版** — 用通俗语言讲故事，避免术语堆砌
3. **题目解读** — 范式拆解 + 创新点提炼
4. **摘要解读** — 五步法：背景/问题/方法/结果/意义
5. **结论解读** — 核心结论提炼
6. **图表解读** — 布局逻辑 + 逐图分析 + 与创新点关联
7. **引言解读** — 起承转合分析
8. **材料与方法解读** — 方法学亮点与技术路线
9. **结果与讨论解读**（可选）— 关键发现与局限性
10. **整体评价与思考** — 亮点 + 不足 + 可借鉴之处

---

## 输出格式规范

- 使用 **Markdown 格式**，每个部分用 **二级标题（##）** 标注
- 关键数据用 **加粗**（`**数据**`）标注
- "科研故事大白话版"必须用通俗易懂的语言，避免专业术语堆砌
- "图表解读"必须说明每张图如何支撑核心创新点或分创新点

## 获取论文内容的方法

### 方法 1：PDF 文件
使用 `extract_content_from_websites` 工具读取PDF内容。

### 方法 2：DOI 链接
```
PubMed API: https://eutils.ncbi.nlm.nih.gov/entrez/eutils/esummary.fcgi?db=pubmed&id=[PMID]&retmode=json
CrossRef API: curl "https://api.crossref.org/works/[DOI]" -H "Accept: application/json"
```

### 方法 3：期刊官网
```
Nature: https://www.nature.com/articles/[DOI]
Science: https://www.science.org/doi/[DOI]
PNAS: https://www.pnas.org/doi/[DOI]
Cell: https://www.cell.com/cell/abstract/[DOI]
```

### 方法 4：OA 或 preprint
```
bioRxiv: https://www.biorxiv.org/content/10.1101/[code]
arXiv: https://arxiv.org/abs/[code]
PMC: https://pmc.ncbi.nlm.nih.gov/articles/[PMC号]/
```

## 十大输出部分详解

### 一、论文基本信息

```
- 中文标题 + 英文标题
- 第一作者 + 通讯作者（含机构）
- 发表期刊 + 年份 + 卷期页码
- DOI
- 发表时间（YYYY-MM-DD）
- 关键词（中英文）
```

### 二、科研故事大白话版

用**最通俗的语言**讲述研究故事，300–500字：
- 这篇研究的是什么（一句话）
- 为什么这个研究重要（解决了什么现实/科学问题）
- 作者如何做、用什么方法
- 最重要的发现是什么
- 这个发现意味着什么

> 目标读者：非该领域的研究者也能听懂。不要堆砌专业术语，用比喻和例子说清楚。

### 三、题目解读

**范式拆解**：解析论文题目的语言结构（主语/修饰语/核心概念）

**创新点提炼**：从题目判断本文的核心创新点（研究对象 × 方法 × 结论 三维度）

### 四、摘要解读（五步法）

| 步骤 | 内容要求 |
|------|---------|
| 背景 | 研究背景和重要性，为什么这个问题值得研究 |
| 问题 | 本文要解决的科学问题或假设 |
| 方法 | 核心实验方法、技术路线、样本/数据规模 |
| 结果 | 关键数据（**加粗显示**），最重要的1-3个发现 |
| 意义 | 理论贡献、应用价值、对领域的推动作用 |

### 五、结论解读

1–3句话概括论文的最核心结论，并说明该结论的适用范围和边界条件。

### 六、图表解读

**布局逻辑**：说明全文图表的组织结构（按什么逻辑排列：时间顺序/因果关系/对比层次）

**逐图分析**：对每张主要图表进行解读，每张图**必须同时回答以下三个问题**：

| 问题 | 要求 |
|------|------|
| 核心信息 | 一句话概括这张图展示的最主要信息 |
| 关键数据 | 必须量化，写出具体数值（如"Detection rate rose from 62% to **94%**"） |
| 创新点关联 | 明确说明这张图如何支撑核心创新点或某个分创新点，描述逻辑关联 |

> 若某张图与核心创新点关联不明显，须注明：**"这张图主要起补充说明作用。"** 不得忽略任何一张图表。

每张图的解读格式：
```
**[图号 图名]**
- 核心信息：[一句话概括]
- 关键数据：**[量化数据]**
- 支撑创新点：[说明逻辑关联；若关联弱则写"补充说明"]
```

### 七、引言解读

分析引言的"起-承-转-合"结构：
- **起**：研究背景是什么，领域知识缺口在哪里
- **承**：前人做了哪些工作，局限性是什么
- **转**：本文如何切入，提出什么假设
- **合**：本文的研究目的和创新点概述

### 八、材料与方法解读

分析论文使用的方法学和技术路线：
- 主要实验材料/样本/数据来源
- 核心分析方法和模型
- 方法学亮点（与同类研究相比有何优势）
- 技术路线的完整链条

### 九、结果与讨论解读（可选）

如果论文有独立的结果与讨论部分，进行解读：
- 主要发现及数据支撑
- 与前人研究的对比
- 本文结果的深层意义
- 研究局限性

> 若论文结构不含独立"结果与讨论"部分，可跳过此节。

### 十、整体评价与思考

| 维度 | 内容 |
|------|------|
| 亮点 | 本文最值得借鉴的1–3个优点（创新点/方法/写作） |
| 不足 | 客观指出1–2个局限性（样本量/方法适用范围/未验证假设） |
| 可借鉴之处 | 对用户研究的直接启发和可移植的方法/思路 |

### 可复用写作模板

从论文中提取值得学习的写作技巧：

| 类型 | 内容 |
|------|------|
| **引言背景引入的经典句式** | 原句 + 中文翻译 + 使用场景 |
| **问题提出的转折表达** | 原句 + 中文翻译 + 使用场景 |
| **结果讨论的逻辑结构** | 论文结构 + 适用语境 |
| **结论升华的写作技巧** | 原句 + 中文翻译 + 可迁移领域 |

> 每类提供1–2个可复用的具体句式/模板，供用户在自己的论文写作中参考。

### 引用信息

解读完成后提供以下引用信息：

**BibTeX格式**（必须生成，可直接复制到文献管理软件）：

## 批量解读模式

### 触发条件

用户一次性提供多篇论文（2篇及以上），并要求批量解读时触发。

### 执行流程

1. **逐篇深度解读**：对每篇论文分别执行 Step 1–10，生成完整深度解读
2. **汇总表格**：所有论文解读完成后，生成一份 Markdown 汇总表格

### 汇总表格格式

```markdown
# 📚 论文批量解读汇总 | [日期]

| 序号 | 论文标题 | 核心创新点 | 关键性能指标 | 研究意义 | 个人评分 |
|------|---------|-----------|------------|---------|---------|
| 1 | [标题] | [1–2句话] | [量化数据] | [理论/应用价值] | ⭐⭐⭐⭐ |
| 2 | [标题] | [1–2句话] | [量化数据] | [理论/应用价值] | ⭐⭐⭐ |
```

### 评分标准

| 评分 | 含义 |
|------|------|
| ⭐⭐⭐⭐⭐ | 顶级论文，直接影响课题方向，值得精读 |
| ⭐⭐⭐⭐ | 优秀论文，与课题高度相关，值得参考 |
| ⭐⭐⭐ | 良好论文，有参考价值，可选择性阅读 |
| ⭐⭐ | 一般论文，方法或结论有局限，浏览即可 |
| ⭐ | 不推荐，缺乏创新或方法有明显缺陷 |

### 汇总表格输出要求

- 关键性能指标栏须填写具体量化数据
- 个人评分根据论文与用户研究方向的契合度打分
- 汇总表格保存到 `literature-interpretation/reports/batch-[日期].md`
- 同时创建飞书云文档，标题为`批量解读汇总-[日期]`，保存到"文献解读"文件夹

## 注意事项

- **不适用于**：简单摘要翻译、文献检索（请用 literature-alert）
- **语言**：解读输出为中文，关键术语首次出现时附英文
- **PDF处理**：优先解析PDF，若PDF解析失败（文件损坏或环境不支持），自动尝试以下降级方案：① 从用户消息中提取DOI，使用CrossRef API（https://api.crossref.org/works/[DOI]）获取摘要和元数据；② 若无DOI，提示用户提供DOI或将摘要/正文文本直接粘贴到消息中；不得因PDF解析失败而中断解读任务
- **内容不足**：若论文信息不完整，明确告知用户哪些信息无法获取
- **内容完整**：十大部分**不得跳过**，无该部分时请注明原因
- **图表要求**：每张图表必须说明其对创新点的支撑关系

3. 文档创建完成后，用飞书 API 将 owner 转移给用户（ou_3ece79b23506d5cb111ae94ccccb3556）：
   ```
   POST https://open.feishu.cn/open-apis/drive/v1/permissions/{doc_token}/members/transfer_owner?type=docx
   ```
