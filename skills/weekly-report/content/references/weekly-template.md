# 周报格式规范

## 标准周报结构

```markdown
# 工作周报

**汇报周期：** YYYY-MM-DD 至 YYYY-MM-DD

---

## 一、本周完成工作

1. **YYYY-MM-DD** 工作内容描述（备注）
2. **YYYY-MM-DD** 工作内容描述（备注）
...

## 二、进行中任务

1. **YYYY-MM-DD** 工作内容描述 - 状态（备注）
2. **YYYY-MM-DD** 工作内容描述 - 状态（备注）
...

## 三、下周计划

（根据本周完成情况填写下周工作计划）

## 四、问题与风险

（如有问题或风险请在此说明）

---
**统计：** 本周共 X 项任务，已完成 Y 项，进行中 Z 项
```

## 字段说明

### 日期格式
- 使用 `YYYY-MM-DD` 格式
- 示例：2024-01-15

### 状态类型
- **已完成**：任务已完结
- **进行中**：任务正在执行
- **待开始**：任务尚未开始
- **已延期**：任务延期处理

### 备注说明
- 可选字段
- 用于补充任务详情、遇到的问题、协作人员等

## 任务延续性

生成周报时，需参考上月周报内容：

1. 识别上周遗留的进行中任务
2. 检查本周是否包含延续任务
3. 在周报中标注任务延续关系

## 示例

```markdown
# 工作周报

**汇报周期：** 2024-01-15 至 2024-01-21

---

## 一、本周完成工作

1. **2024-01-15** 完成项目需求评审（与产品团队确认）
2. **2024-01-16** 完成技术方案设计（已归档）
3. **2024-01-17** 完成数据库设计（已通过评审）

## 二、进行中任务

1. **2024-01-18** 开发用户登录模块 - 进行中（预计下周完成）
2. **2024-01-19** 接口联调 - 进行中（等待后端接口）

## 三、下周计划

1. 完成用户登录模块开发
2. 进行接口联调测试
3. 开始权限管理模块设计

## 四、问题与风险

- 后端接口文档尚未最终确认，可能影响联调进度

---
**统计：** 本周共 5 项任务，已完成 3 项，进行中 2 项
```
