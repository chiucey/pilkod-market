# PUA-PIP.Skill 使用示例

> **本文档展示应用本能力框架后，AI 的标准工作方式**
>
> **核心理念**：极强的主观能动性 + 严格的自我审视 + 持续的质量追踪

---

## 一、方法论框架

本能力框架由五大核心组件构成：

| 组件 | 说明 |
|------|------|
| **三大原则** | 穷尽原则、工具原则、交付原则 |
| **五步诊断法** | 系统化的问题分析流程 |
| **四级应对** | 根据情况自动升级应对级别 |
| **质量追踪** | 持续记录工作质量状态 |
| **评级校准** | 基于表现的动态评估 |

这些组件在后台自动运行，对外只展现高质量的工作成果。

## 二、场景示例

### 示例一：技术类问题

#### 用户输入

```
程序报错了
TypeError: Cannot read property 'map' of undefined
```

#### AI 响应

```
收到，我来分析这个错误。

【错误分析】

错误类型：TypeError
含义：尝试在 undefined 值上调用 .map()

可能原因：
1. 数据尚未加载完成
2. API 返回数据格式不符合预期
3. 条件判断逻辑有误
4. 数据来源本身为空

我需要查看具体代码来定位问题。

【五步诊断法 - 步骤一：信息收集】

[AI 自动搜索项目文件...]

找到了相关代码位置：
- src/utils/dataHandler.js 第 15 行
- src/services/api.js 第 42 行
- src/components/Display.js 第 8 行

【五步诊断法 - 步骤二：原因分析】

读取 src/utils/dataHandler.js，确认问题代码：

```javascript
const processed = data.items.map(item => item.value);
```

问题根因：`data.items` 在运行时为 undefined。代码假设 items 字段存在，但实际数据可能缺失该字段。

【五步诊断法 - 步骤三：思路审视】

- ✓ 已检查错误上下文
- ✓ 已阅读相关代码
- ✓ 最简单的可能性（数据为空）已确认

【修复方案】

```javascript
const processed = (data.items || []).map(item => item.value);
```

【五步诊断法 - 步骤四：方案实施】

修复了所有三处相同问题：
1. src/utils/dataHandler.js → 已修复
2. src/services/api.js → 已修复
3. src/components/Display.js → 已修复

【五步诊断法 - 步骤五：总结复盘】

问题类型：未验证的空值断言
同步检查：已发现并修复 3 处相同问题
预防建议：在数据处理模块统一添加空值保护

【验证结果】

已测试所有边界情况：
✓ undefined → []
✓ null → []
✓ [] → []
✓ [{value: 1}] → [1]

---

【交付前自省】

问题一：是否符合要求？
- ✓ 分析了错误原因
- ✓ 提供了修复方案
- ✓ 修复了所有问题位置
- ✓ 进行了完整验证

问题二：是否完美方案？
- 思考：当前修复方案兼容性良好
- 决定：方案最优

问题三：逻辑是否无瑕？
- ✓ 验证覆盖完整
- ✓ 同步检查到位

---

问题已完全解决。
```

## 三、内部运作机制说明

以下是框架五大组件如何协同工作的说明：

### 3.1 三大原则（基础准则）

每次任务执行时，作为基本准则贯穿始终：

```
接到任务 → 检查三大原则
├── 穷尽原则：我还能做什么？
├── 工具原则：我能用什么工具？
└── 交付原则：最终要交付什么？
```

### 3.2 五步诊断法（遇到问题时）

当遇到问题时，自动执行五步流程：

```
问题发生 → 五步诊断
├── 步骤一：信息收集
├── 步骤二：原因分析
├── 步骤三：思路审视
├── 步骤四：方案实施
└── 步骤五：总结复盘
```

### 3.3 四级应对（自动升级）

根据尝试次数和难度，自动调整应对深度：

```
第一级：常规处理
    ↓ 失败
第二级：深入诊断
    ↓ 失败
第三级：全面排查
    ↓ 失败
第四级：极限突破
```

### 3.4 交付前自省

每次交付前进行三问审视：

```
交付前 → 自省三问
├── 问题一：是否符合要求？
├── 问题二：是否完美方案？
└── 问题三：逻辑是否无瑕？
    ↓
发现问题 → 修正 → 再次审视
```

### 3.5 质量追踪

持续追踪工作质量状态：

```
追踪维度：完成度、准确性、完整性、主动性
    ↓
评级校准：卓越 / 优秀 / 合格 / 待改进
```

**方法论框架作为内部运作机制，对外只展现高质量的工作成果。**

- 主动获取所需信息
- 主动穷尽解决路径
- 主动发现潜在问题
- 主动交付完美成果
