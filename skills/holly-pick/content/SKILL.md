# 钱一天选股 (holly-pick)

通过 **小悟空** + **龟仙人** + **布尔玛** + **短笛** + **小林** + **贝吉塔** + **神仙** + **天津饭** 八个算法 API + **魔人布欧** 跨市场映射算法（前 8 个由服务端计算；魔人布欧基于用户提供的美股热力图截图本地解析），拉取当日"钱一天策略"命中股票。

## 算法一览

| 算法 | 核心逻辑 | 默认 | 适用场景 |
| --- | --- | --- | --- |
| **小悟空** | 趋势向上 + 交易活跃 + 站上 5 日均线 | ✓ | **顺势而为**,熊市慎用 |
| **龟仙人** | 10 日内涨停 + 最近 3 日站上 5 日线 + 20 日线向上 + 当日股价相对 5 日线 -1%~+4% | ✓ | **涨停回踩**,短线高手使用 |
| **布尔玛** | 周收盘价近 5 周均线 ±2% + 5 周均线向上 + 近 2 周 MACD 翻红 / 重新变大 | ✓ | **中长线**选股 |
| **短笛** | 最近 5 天内创 30 日新高 + 当日股价相对 5 日线 -2%~+3% | ✓ | **突破新高** |
| **小林** | 20 日线向上 + 当天股价上穿 20 日线 + 股价在 20 日线 ±2% 以内 + 高于 25 日线 | ✓ | **日线趋势突破**，中线跟进 |
| **贝吉塔** | 指定 N 天窗口内涨幅最强（默认 `rpsType=20`） | ✗ | **强者恒强** |
| **神仙** | 月线 MACD 保持红（今日 MACD ≥ 0）且仍向上放大（今日 ≥ 昨日） | ✗ | **大盘极度悲观时**使用|
| **天津饭** | 10 个交易日内 ≥1 次「股价处于近 250 日最低价 15% 以内 + 当日成交量是前一日 3 倍」 | ✓ | **底部放量**反转在即|
| **魔人布欧** | 美股个股热力图 → A 股对标 | ✗ | **美股→A股对标** |

默认触发（说「钱一天选股」/「holly-pick」/ 不指定）= 小悟空 + 龟仙人 + 布尔玛 + 短笛 + 小林 + 天津饭。贝吉塔需显式说「贝吉塔」+ 窗口；神仙需显式说「神仙」（**非默认**，仅极端悲观行情用）；魔人布欧需显式说「魔人布欧」+ 提供截图；短笛 / 小林 / 天津饭在默认范围，单独跑说「短笛」/「创新高」/「newHigh」/「小林」/「20日趋势」/「day20Trend」/「天津饭」/「低位放量」/「底部放量」/「suddenHighVolume」。覆盖 A 股主板 / 创业板 / 科创板 / 北交所。

## 算法

### 小悟空 — `/report/simplest`

筛选逻辑（来自算法设计者）：

1. **趋势向上** —— 个股中期趋势是上升的（非下跌 / 横盘）。
2. **交易活跃** —— 近期成交量活跃，非冷门死水股。
3. **当前股价站上 5 日均线** —— 短期均线之上，强势信号。

服务端 `comments`： `"符合钱一天策略的股票, 目前是每天晚上计算当天的结果, 不久的未来可以实现盘中实时计算"`

返回 JSON：

```json
{
  "comments": "符合钱一天策略的股票, 目前是每天晚上计算当天的结果，不久的未来可以实现盘中实时计算",
  "generateTime": "2026-08-18T20:09:12.090347854",
  "items": [
    { "code": "000048", "label": "流通市值: 125 亿, 换手率: 3.59%, 涨幅: +2.07%", "name": "京基智农", "url": "https://xueqiu.com/S/SZ000048" }
  ]

```

> **字段说明**：`label` 包含三段以 `, ` 分隔的信息 —— 流通市值（亿）/ 换手率（%）/ 涨幅（带符号 %）。原 `rise` 字段已废弃，涨跌幅从 `label` 中解析。

### 龟仙人 — `/report/strongDaily`

筛选逻辑（来自服务端 `comments` 原文）：

1. **最近 10 天内有涨停**（涨幅超过 10%）
2. **最近 3 天股价都大于 5 日线**（短期均线持续强势）
3. **今天 20 日线 > 昨天 20 日线**（中期趋势向上）
4. **当天股价相对 5 日线在 -1% 到 +4% 之间**（强势但未过度拉伸）

服务端 `comments`： `"符合强势日线策略的股票：最近10天内有涨停(涨幅超过10%)，最近3天股价都大于5日线，今天20日线>昨天20日线，当天股价相对5日线在-1%到+4%之间"`

### 布尔玛 — `/report/weekTrend`

周趋势策略筛选逻辑（来自服务端 `comments` 原文）：

1. **收盘价在周 5 均线附近（±2.0%）** —— 周线级别接近关键均线
2. **5 周均线向上** —— 中期趋势向上
3. **最近 2 周内 MACD 翻红，或 MACD 缩小后重新变大** —— 周线动量转正

服务端 `comments`： `"符合周趋势策略的股票：收盘价在周5均线附近(±2.0%)且5周均线向上，最近2周内MACD翻红或MACD缩小后重新变大"`

### 小林 — `/report/day20Trend`

日线 20 日趋势策略：找出**20 日均线向上 + 当天股价上穿 20 日线 + 在 20 日线附近 ±2% + 高于 25 日线**的股票 —— 适合**中线跟进**趋势启动初期的标的，是布尔玛（周趋势）的日线版本。

筛选逻辑（来自服务端 `comments` 原文）：

1. **20 日均线向上** —— 中期均线方向向上
2. **当天股价上穿 20 日线** —— 短期突破中期均线（趋势启动信号）
3. **股价在 20 日线附近 ±2% 以内** —— 刚突破，未远离均线
4. **高于 25 日线** —— 在更长均线之上确认趋势强度

服务端 `comments`： `"符合20天日线向上策略的股票：20天日线向上，当天股价上穿20天线，股价在20天线附近(±2.0%)，且高于25天线"`

### 贝吉塔 — `/rps/stocks?rpsType=N`

RPS（Relative Price Strength，相对价格强度）选股。

- **参数**：`rpsType` ∈ `{10, 20, 30, 60, 120}` —— 分别是 10/20/30/60/120 天内的相对价格强度排名。
- **逻辑**：在指定天数窗口内，找出涨幅最强的股票集合。
- **默认参数**：`rpsType=20`（用户未指定时使用）。

调用示例：`/rps/stocks?rpsType=20` 返回 20 天 RPS 排名靠前的股票。

**返回**：直接是数组，**没有**外层包装（无 `comments` / `generateTime`）：

```json
[
  { "code": "688531", "label": "流通市值: 100 亿, 换手率: 5.0%, 涨幅: +3.5%", "name": "日联科技", "url": "https://xueqiu.com/S/SH688531" }
]
```

**已知数据状态**：

- ⚠️ **当前所有 `rpsType`（10/20/30/60/120）均返回后端错误**：`{"code":100,"message":"Cannot invoke \"com.alibaba.fastjson2.JSONObject.getJSONArray(String)\" because \"jsonObject\" is null"}` —— 服务端 `rps/stocks` 端点暂不可用。
- 成功时的 item 应包含 `code` / `name` / `url` / `label`（流通市值 / 换手率 / 涨幅），**无** `rise` 字段。
- 输出时按 `rpsType` 值作为 section 标识。

### 神仙 — `/report/monthTrend`

月线级别策略：找出**月 MACD 保持红、并且还在向上**的股票。

筛选逻辑：

1. **本月 MACD ≥ 0** —— 月线 MACD 保持红（红柱未翻绿）
2. **本月 MACD ≥ 上月 MACD** —— 红柱仍在向上放大，动能没衰减

**使用前提（重要）**：

- 神仙**只在盘面最悲观、最绝望、最痛苦的时候用** —— 大盘连续暴跌 / 恐慌杀跌 / 情绪冰点。此时能保住月线 MACD 红柱且还在放大的股票，才是真正的抗跌强势股。
- **平时不要跑** —— 正常/上涨行情下命中约 200 只，池子太大，没有筛选价值。
- 用户未明确说「神仙」/「月线 MACD」/「绝望」等触发词时，**不跑**该算法；也**不**纳入「钱一天选股」默认组合。
- 若用户在明显非极端行情下要求跑神仙，正常执行，但在 section 头部加一行提示：`⚠️ 神仙适用于盘面极度悲观时；当前命中 N 只，池子较大，建议结合其它算法交叉验证。`（N ≥ 100 时提示）

返回 JSON（外层包装）：

```json
{
  "comments": "符合月趋势策略的股票：本月MACD>=0且本月MACD>=上月MACD",
  "generateTime": "2026-08-18T18:35:04.588923723",
  "items": [
    { "code": "000026", "label": "流通市值: 85 亿, 换手率: 49.27%, 涨幅: +40.56%", "name": "飞亚达", "url": "https://xueqiu.com/S/SZ000026" }
  ]
}
```

> **字段说明**：`label` 中「涨幅」形如 `+40.56%` / `-5.70%`，带符号 + %。原 `rise` 字段已废弃。

### 天津饭 — `/report/suddenHighVolume`

底部放量策略：找出**价格处于低位 + 突然放量**的股票，捕捉**底部反转**信号 —— 长期下跌/横盘后突然放量往往预示资金介入。

筛选逻辑（来自服务端 `comments` 原文）：

1. **窗口**：最近 10 个交易日内至少出现过 1 次（不是"每天"，而是窗口内出现 ≥1 次即命中）
2. **低位判定**：当日收盘价在**近 250 日最低价 15% 以内** —— 即收盘价距近 250 日新低的涨幅 ≤ 15%（说明股价已经跌到/接近长期底部）
3. **放量判定**：当日成交量 ≥ 前一日成交量的 **3 倍** —— 量能突然显著放大
4. **同时满足**：低位 + 放量必须在同一日发生；窗口内任意一日满足即入选

服务端 `comments`： `"符合低位突然放量策略的股票：在10个工作日内，发生过1次股价在低位且成交量是前一天的3.000000倍（收盘价在近250日最低价15.000000%以内）"`

**适用场景**：
- **底部反转信号** —— 长期下跌/横盘的股票，突然放量往往预示资金介入
- **回调到位准备启动** —— 主升浪前的"挖坑结束"形态
- **震荡市找异动** —— 在箱体震荡中识别可能突破的方向
- **不适合**单边下跌中段 —— "低位"在持续下行中会不断刷新，容易误判（连续阴跌中 250 日最低价每天被打破）

返回 JSON（外层包装）：

```json
{
  "comments": "符合低位突然放量策略的股票：在10个工作日内，发生过1次股价在低位且成交量是前一天的3.000000倍（收盘价在近250日最低价15.000000%以内）",
  "generateTime": "2026-08-18T18:38:24.471954694",
  "items": [
    { "code": "000019", "label": "流通市值: 29 亿, 换手率: 5.21%, 涨幅: +5.85%", "name": "深粮控股", "url": "https://xueqiu.com/S/SZ000019" }
  ]
}
```

> **字段说明**：`label` 中「涨幅」形如 `+5.85%` / `-5.00%`，带符号 + %。原 `rise` 字段已废弃。

### 魔人布欧 — 美股强势个股 → A 股对标

不同于前 8 个 API 算法，魔人布欧是**纯本地 + WebSearch** 算法：基于用户提供的美股**个股**热力图截图，识别当日（最近 1-7 天）涨幅领先的**个股**（不是板块），通过该个股所属行业映射到 A 股同行业 / 同龙头标的。

**目的**：捕捉「美股强势个股 → A 股同行业跟随上涨」的跨市场联动 —— 美股某只龙头股暴涨（如 NVDA、META），往往预示其所在行业板块强势，A 股同行业对标可能隔日跟随。提前一天知道美股哪些个股涨得猛，第二天盯 A 股对标。

**思路放开**：A 股对标**不局限于**下方静态映射表 —— 映射表作为**快速基线**（覆盖常见大行业），**WebSearch 实时补全**覆盖映射表外的子行业 / 新行业 / 同类公司（如光模块、存储芯片、创新药、CRO/CDMO、锂电池、储能、AI 算力、医疗器械、SaaS、网络安全、机器人、卫星互联网 等）。

**输入**：
- 用户提供的截图（最近 1-7 天的美股**个股热力图**——即「个股热力图」视图：板块分组 + 各板块下罗列个股及涨跌幅，来源不限：TradingView / 同花顺 / 雪球 / 东方财富 等均可）
- 可选：用户口述筛选条件（`Top N` / `涨幅 > X%`）

**Vision 解析**（用 Read 工具读取截图，提取）：
- 截图时间（顶部标题日期，如 `07/11 12:21 (美东)` → 美东 2026-07-11 当日）
- 所有可见个股的代码 / 名称 / 涨跌幅
- 每个个股所属的板块（用于查映射表 + WebSearch；个股所在板块 = 该个股上方最近一行的板块名）

**筛选规则**（用于筛出"强势美股个股"）：
- 默认：**个股涨幅 ≥ +2%**（涨幅列以"+"开头、红色系的个股）
- `Top N` / `前 N` → 取全市场涨幅最高的 N 只个股（默认 N=10）
- `涨幅 > X%` / `大于 X` / `涨幅 ≥ X%` → 个股涨幅 ≥ X% 才入选（默认 X=2）

**映射规则**（双源合并 + 思路放开）：

**源 1 - 静态映射表**（下方）：覆盖常见美股板块 → A 股对标，每行业 8-10 只，作为**快速基线**。

**源 2 - WebSearch 实时补全**：每个强势个股所属行业，WebSearch 搜索以下 query 之一：
- `"{industry} A股 龙头"`
- `"{industry} A股 同类公司"`
- `"{industry} A股 对标"`
- `"{industry} 概念股 A股"`
- `"{industry} A股 上市公司"`

从搜索结果中**提取 A 股代码**（6/0/3 开头），过滤掉港股（HK 开头）/ 美股（字母代码）。

**WebSearch 必须使用的场景**：

## 步骤

1. **判定范围 + 解析参数** —— 看用户指定哪些算法：
   - 贝吉塔：从话语中提取 `rpsType`
   - 魔人布欧：从话语中提取筛选条件（`Top N` / `涨幅 > X%`）；同时**必须**有截图（inline 或文件路径）
2. **并行调用 API** —— 用 `webfetch` GET 对应 URL（小悟空 / 龟仙人 / 布尔玛 / 短笛 / 小林 / 贝吉塔 / 神仙 / 天津饭），`format=text`。魔人布欧不调用 API。
3. **解析响应**：
   - 小悟空 / 龟仙人 / 布尔玛 / 短笛 / 小林 / 神仙 / 天津饭：外层包装对象，提取 `comments` / `generateTime` / `items`。每条 item 包含 `code` / `name` / `url` / **`label`**（`"流通市值: X 亿, 换手率: X%, 涨幅: ±X%"`）。从 `label` 中按正则 `流通市值:\s*([\d.]+)\s*亿`、`换手率:\s*([\d.]+)%`、`涨幅:\s*([+-]?[\d.]+)%` 解析三个字段；展示时 `涨幅` 去掉 `%`，保留 `+`/`-` 符号再按数值降序排。**原 `rise` 字段已废弃，不要从 `item.rise` 读取。**
   - 贝吉塔：响应正文本身就是数组（**当前所有 rpsType 均返回后端错误**）。成功时 item 含 `code` / `name` / `url` / `label`（无 `rise` 字段）。包装成 `{ items: <array>, comments: "贝吉塔 RPS {N} 天", generateTime: null }` 走统一处理。
   - 魔人布欧：用 Read 工具读取用户提供的截图 → 提取所有可见个股（代码 / 名称 / 涨跌幅 / 所属行业）→ 按筛选规则筛出强势个股 → **双源映射**：
  - 源 1：按所属行业查下方静态映射表 → 基线 A 股列表
  - 源 2：用 WebSearch 搜索 `"{industry} A股 龙头 / 同类公司 / 对标 / 概念股"` → 提取 A 股代码
  - 合并：源 1 + 源 2 → 按代码去重 → 最终 A 股对标列表（同一行业的 A 股只列一次，但标注触发该行业的所有强势美股）
4. **时间转换** —— 仅当 `generateTime` 存在时，从 UTC 转 `Asia/Shanghai`（UTC+8），格式 `YYYY-MM-DD HH:mm`。贝吉塔 / 魔人布欧无 `generateTime` → 用当前时间。魔人布欧用截图顶部标题里的日期作为数据日期。
5. **格式化输出**（见"输出契约"）。
6. **处理错误**（见"错误处理"）。

## 错误处理

按算法独立处理，**一个失败不影响另一个**：

| 场景 | 检测 | 用户提示 |
| --- | --- | --- |
| HTTP 非 200 | `webfetch` 报错 / 响应不含 JSON / 数组 | `{算法名} API 调用失败：{status}。建议稍后重试或检查服务器 82.156.107.158:8003 是否在线。` |
| JSON 解析失败 | 响应非 JSON / 非数组 | `{算法名} API 返回格式异常。原始响应（前 200 字符）：...` |
| 网络超时 | 30 秒无响应 | `{算法名} 服务器 30 秒无响应。建议错峰（盘后 19:00 后）再试。` |
| `items` 为空 | `items == []` | `{算法名} 今日（YYYY-MM-DD）无候选股票。` —— **不是错误** |
| 字段缺失 | `code` / `name` / `url` 缺失 | 跳过该 item，统计时按 `items.length - skipped` 输出，末尾加 `(已跳过 K 条字段不完整记录)` |
| `label` 字段缺失或解析失败 | 三个正则任一未匹配 | 该列显示 `?`，**不**丢股票；保留所有 `code` / `name` 完整的记录 |
| 贝吉塔 rpsType 非法 | 用户输入非 10/20/30/60/120 | 提示 `贝吉塔 rpsType 必须是 10/20/30/60/120 之一，已默认 20。` |
| 贝吉塔 API 返回后端错误 | 响应含 `jsonObject is null` / 500 错误 | 提示 `贝吉塔 API 当前服务端异常（jsonObject is null），数据待恢复后补全。` |
| 神仙命中过多 | `items.length >= 100` | section 头部提示 `⚠️ 神仙适用于盘面极度悲观时；当前命中 N 只，池子较大，建议结合其它算法交叉验证。` —— **不是错误** |

| 魔人布欧截图无法识别 | Read 后图像模糊 / 非个股热力图 / 无法提取个股 | `无法识别截图中的个股。请提供清晰的、含个股名 + 涨跌幅的热力图。` |

## 边界

- **不要**对 items 做二次筛选 / 排序 / 加权 —— 算法输出即最终结果。
  - 例外：龟仙人 / 布尔玛 / 短笛 / 神仙 / 天津饭 items 默认按 `label` 解析出的「涨幅」数值降序排（仅展示顺序，不删改）。
- **不要**逐只诊断"是否严格满足算法条件"——服务端已离线计算过，单只诊断会误导。
- **不要**合并或调用 `stock-financial-analysis` —— 两者独立。
- **不要**在 A 股结果上叠加美股 / 港股数据 —— 本 API 不覆盖。
- **贝吉塔 API 当前返回后端错误**（`jsonObject is null`）—— 不要替用户做决策推荐，明确告知"数据待完善 / 服务端暂不可用"。
- **神仙**特殊边界：
  - **不进默认组合** —— 只有用户显式说「神仙」/「月线 MACD」/「绝望」等触发词才跑。
  - 服务端 `comments` 现为"符合月趋势策略的股票：……"（已修正为月趋势）；输出标题按**神仙 · 月 MACD 保持红 + 向上**写，`comments` 原文照引不改。
  - 涨幅从 `label` 中解析（形如 `+40.56%` / `-5.70%`），去掉 `%`，保留 `+`/`-` 符号，按数值降序排。
  - 不要因为命中多就自行截断 / 只取前 N 只 —— 全量展示，命中 ≥100 只时加提示行。
- **天津饭**特殊边界：
  - **进默认组合** —— 用户说「钱一天选股」/「holly-pick」/ 不指定算法时自动跑。单独跑说「天津饭」/「低位放量」/「底部放量」/「suddenHighVolume」等触发词。
  - 涨幅从 `label` 中解析（形如 `+5.85%` / `-5.00%`），去掉 `%`，保留 `+`/`-` 符号，按数值降序排。
  - 不要因为命中多就自行截断 / 只取前 N 只 —— 全量展示。
  - **单边下跌中段慎用** —— 250 日最低价在连续阴跌中会被持续刷新，"低位 + 放量" 容易误判为反转信号；该算法更适合**震荡市 / 调整末期 / 箱体突破**时使用。
- **魔人布欧**特殊边界：
  - **不要局限于静态映射表** —— 必须配合 WebSearch 实时补全，覆盖映射表外的子行业 / 新行业 / 同类公司。
  - 不要把港股 / 美股代码塞进 A 股对标（如腾讯 00700、阿里 09988）—— A 股只列 6/0/3 开头的代码。WebSearch 结果含港股 / 美股代码 → 过滤掉。
  - 不要替用户做"买哪个"的决策推荐 —— 仅展示 A 股对标，不做二次筛选 / 排序 / 主观推荐。
  - 截图日期推断要保守：标题显示 `MM/DD HH:MM (美东)` 且 HH:MM 落在 00:00-09:30 → 视为前一交易日收盘；否则视为当日。
  - 同一行业多只强势美股 → A 股对标去重，只列一次，但列出所有触发该行业的强势美股。
  - 个股涨幅为 0 / 空 / 难以辨认 → 跳过该个股，不计入强势统计。
  - 不要做二次筛选 / 排序 / 加权 —— A 股对标列表合并去重后即最终顺序（映射表顺序在前，WebSearch 补全在后）。
  - WebSearch 无结果 → 仅用映射表（如有）；都没有则跳过该强势个股。
