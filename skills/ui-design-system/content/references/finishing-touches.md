# Finishing Touches — 收尾打磨

原书第 8 章。层级、间距、字色都定对了之后，这一章决定界面是"合格"还是"专业"。

## 1. 增强默认样式（Supercharge the defaults）

浏览器默认的东西是给"可用"设计的，不是给"好看"设计的：

- **列表**：用图标列表替换圆点列表（checkmark / 箭头），比圆点更有信息量
- **链接**：加自定义下划线样式（hover 加粗、或者用背景色高亮）
- **引用块**：自定义左边框 + 浅底，而不是默认的缩进
- **表格**：斑马纹、`tabular-nums`、hover 高亮、表头弱化
- **复选框 / 单选框**：自定义样式，别用浏览器默认的（它在不同系统上差异巨大）
- **代码块**：浅底 + 圆角 + 内边距，而不是浏览器默认的黑底
- **提示框 / alert**：语义色的左边框 + 淡底

这一条性价比极高——改动量小，用户感知强。

## 2. 用强调色边框增加个性

"Add color with accent borders." 给卡片、警示、选中项加一条彩色边（上边或左边）：

```css
.card { border-left: 3px solid var(--color-accent); }
```

投入极小，能明显提升辨识度。注意这是**增加**边框，所以更要克制——一屏里一两个就够了。

## 3. 装饰背景

"Decorate your backgrounds." 纯白背景容易呆板：

- 浅淡的渐变（**双点、从角落到中心**，不是彩虹渐变）
- 低对比度的几何形状（水波纹、圆点网格、同心弧线）
- 内容背后的柔光斑
- 一条极浅的分隔色带

**对比度要低到几乎注意不到**，它的作用是让界面"不那么空"，不是被看见。做成大色块
或高饱和渐变会立刻变廉价。

## 4. 别忽略空状态（Don't overlook empty states）

原书专门一节——空状态是最常被忽略也最容易出彩的地方。

"这里还没有数据" 是最差的做法。空状态应该：

- **解释这里将来会有什么**（告诉用户这个区域是干嘛的）
- **给一个行动入口**（按钮："新建订单"、"添加第一个项目"）
- 顺便承担**新手引导**的功能

三种典型空状态，各有不同写法：

| 类型 | 用户状态 | 写法 |
|---|---|---|
| 首次使用 | 什么都没有 | 图标 + 说明 + 主行动按钮（这是引导的最佳位置） |
| 筛选无结果 | 有数据但没匹配上 | 说明筛选条件 + "清除筛选"按钮 |
| 出错了 | 加载失败 | 错误信息 + "重试"按钮 |

空状态也是**留白和层级的练兵场**：因为内容少，很容易堆得乱七八糟。保持和正常状态一致的
字号、间距、圆角，用户才不会觉得"页面坏掉了"。

## 5. 少用边框（Use fewer borders）

见 elevation.md。要点重申：加间距 > 换背景色 > 加阴影 > 画边框。边框放最后。

## 6. 想开一点，跳出常规

"Think outside the box." 最无聊的组件重新想一遍：

- 下拉菜单可以是**多列**的
- 表格在移动端可以**变成卡片列表**
- 单选按钮可以是**可选卡片**
- 登录页的表单可以是**分段式**（第一步填邮箱，下一步设密码）而不是一次全露
- 设置页可以是**分组卡片 + 描述**，而不是一堆左对齐的 label

改之前先问：**当前用户的真实场景需要吗？** 为了"看起来有想法"而改交互是另一种错。

## 7. 状态完整性

专业和业余的差别经常在**非理想状态**上：

- 加载中（骨架屏优于转圈 spinner，形状和最终布局一致时感知更快）
- 加载失败（错误信息 + 重试按钮）
- 空（见上）
- 权限不足（不要留一个点了才报错的按钮）
- 超长文本（截断策略 + `title` / tooltip）
- 深色模式（如果产品支持）
- hover / focus-visible / disabled / 错误态

这些状态**必须在设计 token 阶段就规划**，事后补的成本是前面的好几倍。
