# Hierarchy — 层级就是一切

原书第 2 章。整本书的纲领：**界面难看的绝大多数情况不是配色问题，是层级问题**——所有元素在
同一视觉量级上抢注意力，用户不知道先看哪。当没有优先级时，就没有可读性。

## 三种颜色 + 两种字重（基础工具）

先把可选空间压缩到这个极小的集合，层级问题会自动解决大半：

| 层级 | 颜色 | 字重 |
|---|---|---|
| 主要内容 | 深色 | 600–700 |
| 次要内容 | 中灰 | 400–500 |
| 三级内容 | 浅灰 | 400 |

UI 里**不要用 400 以下（细体）的字重**。细体在标题上偶尔可用，在小字号 UI 上几乎不可读。
要弱化一个元素，用更浅的颜色或更小的字号，不要用细体。

## 关键 tactic

### 1. 突出靠弱化，不靠放大

想强调一个元素，先**弱化它周围的东西**，而不是把目标本身搞得更响。周围安静下来，目标自然
就跳出来了。这个反直觉的做法比"加大加粗加深"更有效，也更不容易失控。

### 2. 字号不是唯一手段

"Size isn't everything"。字号是最粗的手段：调大容易显得笨、破坏布局、调小牺牲可读性。
先用**字重**和**颜色深浅**，字号留到最后。当前很多界面反着用——标题全靠 32px 撑着，
一屏里三个大字互相竞争。

### 3. 彩色背景上不要用灰色文字

"灰字压在彩色底上"永远显脏显廉价。正确做法：取与背景**同一个色相**，调高明度、降饱和，
让它读起来像是背景色的浅色版本，而不是一个贴上去的灰色。

### 4. 标签是最后手段

"Labels are a last resort。" 数据本身能说话就不要贴标签：
- `库存：12` → `12 件在售`
- `卧室：3` → `3 卧室`
- `注册于：3月` → `3 月注册`

知道用户在看什么的时候，标签是多余的。已知用户会找标签的场景（表单字段名、技术规格表）
才用标签——但这时标签应该是**次要内容**，值才是主角。用户扫一眼要的是值，不是"值"这个称呼。

### 5. 视觉层级 ≠ 文档层级

`<h2>` 不等于视觉上就该大。**按角色定样式，不按标签定样式。** 需要无障碍语义但视觉上不想
抢注意的标题，可以只用 `h2` 标签 + 视觉上做成 12px 灰色，甚至可以视觉隐藏但保留给读屏软件。

反过来：用 `<div>` 承担视觉主角时，也要确认读屏顺序合理。

### 6. 字重和对比度要平衡

图标和文字相邻时，粗图标会显得很重——要么给图标调浅的颜色，要么降低它的对比度。
**加粗字重是一种廉价的加对比度手段**：某个边框太细看着发虚时，把字重从 400 提到 600，
比把边框颜色调深更雅致，因为保留了柔和感。

### 7. 语义优先，但视觉角色说了算

HTML 语义（`button` vs `div`）该用还是要用，但**样式按它在界面里的角色定**，不要让标签类型
绑架视觉层级。

## 操作按钮的三层

按**视觉层级**分级，不按语义分级：

- **主要操作**：必须显眼。实心主色按钮，一屏一个。
- **次要操作**：要清楚但不抢戏。描边按钮或低对比度底色。
- **三级操作**：可被发现但不显眼。**样式做成链接的样子。**

即使是破坏性操作（删除）也不该抢更多注意力——该抢注意力的是"确认"这一步，不是"删除"
按钮本身。给危险操作加确认弹窗，比把它做成血红色更负责任。

## 检查方法

问自己：**用户第一眼落在哪？** 如果答案是"到处都是"，层级就是失败的。把视线上移的那条
路径显式定出来，其他元素一律让路。
