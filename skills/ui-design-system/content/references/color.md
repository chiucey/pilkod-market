# Working with Color — 色彩的运用

原书第 5 章。核心：**色彩的工作量在于提前定义，不是临场挑选。**

## 1. 放弃 hex，用 HSL

hex 不直观：`#03369E` 和 `#507DD7` 看起来是两回事，实际是同一族的蓝。HSL 按三个可以思考
的维度组织：

- **H 色相** 0–360°：0 红、120 绿、240 蓝
- **S 饱和度** 0–100%：多艳
- **L 明度** 0–100%：离黑到白多远

派生一整套色阶，只需要改 S 和 L，色相不动——这是 hex 做不到的。

注意别把 HSL 和 HSB 搞混：HSB 的 100% 亮度只在饱和度为 0 时才是白色；饱和度 100% 时
HSB 等价于 HSL 的 50% 明度。浏览器里用 HSL。

## 2. 你需要的颜色比你以为的多

这是原书最反直觉的一条。调色板生成器给的 5 个色块永远不够建一个真实界面。一个可用的
界面需要：

| 类别 | 数量 | 用途 |
|---|---|---|
| 灰色系 | 8–10 档 | 背景、面板、表单——界面里几乎所有东西 |
| 主色 | 5–10 档 | 亮到暗的完整梯度 |
| 强调色 | 5–10 档 | 传达不同状态，通常要抓眼 |
| 语义色 | 红/黄/绿各 5–10 档 | 告警、状态 |

**合计 40–80 个颜色，全部提前定义。** 这个数字听着吓人，但它把"每次都要重新挑颜色"变成
"从已定好的池子里选一个"。设计速度的提升来自这里，不是来自审美。

## 3. 提前定好色阶（Define your shades up front）

**别在写的过程中调色**，那样必然调出脏色。方法：

1. 挑一个中间档——你打算拿来做按钮背景的那个色
2. 挑最暗档——深到能做浅底上的文字
3. 挑最浅档——浅到能做淡淡的底色
4. **把间隔填满**，通常 9–10 档，命名 `50 / 100 / 200 / … / 900`

灰色的色阶用同样的方法单独推一套。

## 4. 别让明度杀死饱和度

"Don't let lightness kill your saturation。" 这是最常被忽略的一条。把颜色调亮的时候，
**同时把饱和度提上去**，颜色才不会变成粉粉的塑料感。调暗时同理，反向提饱和度。

举例：想做一个更浅的蓝，`hsl(213, 71%, 25%)` 拉到 46% 明度，同时饱和度补到 85–90%，
而不是直接在原色上 lighten——后者会得到一个灰扑扑的蓝。

## 5. 灰色不必是灰的

"Greys don't have to be grey。" 给灰色加一点饱和度（3–10%，色相取主色的色相），整页会立刻
显得是一套系统而不是拼起来的。Tailwind 的 `slate` 就是这么来的——带蓝相的灰。

冷灰还是暖灰也要定下来，全站统一。带一点黄相的暖灰适合内容型产品，带蓝相的冷灰适合工具类
界面。

## 6. 每个色相的感知亮度不同

同样是 50% 明度，黄色看起来比蓝色亮。暖色相（黄、橙）要额外降明度，冷色相（蓝、紫）可以
留高一点。做色阶时必须逐色核对，不能一个公式套到底。

## 7. 好看的和可访问的不矛盾

"Accessible doesn't have to mean ugly。" 对比度要求（正文 4.5:1、大字 3:1）不必然逼你在
"丑"和"合规"之间二选一。办法是把层级拉开——该深的地方给够深，该浅的地方确认真的够淡。
很多"过不了 AA"的设计是层级没拉开，不是色值选错了。

## 8. 别只靠颜色传达信息

色盲用户看不到红绿差异。语义状态必须至少有两种编码：颜色 + 图标 / 文字 / 形状。
图表同理——系列超过 3 个就应该改用对比阶（同一色相的明度阶）而不是不同的色相。
红绿并置的状态（涨/跌）永远要配图标或符号。

## 反模式

- 10 个以上互不相关的 hex 值散落在代码里 → 色彩体系已经腐化，收敛到 2–3 个色相
- 现场 `lighten()` / `darken()` 调色 → 一定会调出脏色
- 大面积高饱和主色做底 → 饱和色适合**小面积点缀**，大面积用低饱和的同色相
- 用橙色做侧边栏选中态而底色是靛蓝 → 不相关色相看着像没配好，除非它是被显式定义的
  品牌强调色（给 token 起名字）
- 彩色底上放灰色文字 → 取同色相的高明度色
