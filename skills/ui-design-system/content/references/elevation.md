# Creating Depth — 营造层次感

原书第 6 章。核心：**阴影是在模拟现实中的光，不是加装饰。**

## 1. 模拟一个光源（Emulate a light source）

光从上方来，所以：**亮边在上，暗影在下。**

一个凸起的按钮：

```css
box-shadow:
  0 1px 1px rgba(0,0,0,.15),   /* 暗影在下方 */
  0 -1px 0   rgba(255,255,255,.15);  /* 亮边在上 */
```

反过来就是**凹陷**元素（下边亮、上边暗）——输入框、井、按下状态的按钮用这一套。
**保持简单**，一光一影就够，做多了界面会显得脏。

## 2. 投影的颜色要手选，不要用半透明白

`rgba(255,255,255,.5)` 这种不是投影色。**手选一个浅色作为投影色**（通常比背景深一档的
实色）。半透明白只该用于反色的 UI（深底上的浮层）。

**模糊半径几个像素就够了。** 大模糊半径 + 大偏移看起来"飘"，不是"浮起来"。

## 3. 用投影表达高度（Use shadows to convey elevation）

阴影应该传达这个元素比背景高多少：

| 层级 | 用途 | 参考值 |
|---|---|---|
| 小 | 按钮、贴边元素 | `0 1px 2px rgba(0,0,0,.05)` |
| 中 | 下拉、悬浮卡片 | `0 2px 4px rgba(0,0,0,.06)` |
| 大 | 模态框、需要抢注意力的层 | `0 8px 24px rgba(0,0,0,.10)` |

**一般需要 5 档**，和色阶一样：先定最小和最大，再把间隔填满。

阴影也用于**交互状态**：hover 时把阴影变大，是在用高度暗示"可点"，比变色更雅致。
拖拽时被拿起的卡片、flyout 展开的元素同理。

## 4. 阴影可以有两段（Shadows can have two parts）

这是原书专门一节，也常被忽略：

- **一段较大的弥散阴影**——模拟直接光照下来的阴影
- **一段较小的锐利阴影**——模拟环境光的遮蔽

两段叠加比单段真实得多。但**最高层（模态框）只用弥散那层**——离用户越近，锐利的接触
阴影越看不见。

## 5. 扁平设计也能有层次

"Even flat designs can have depth." 不用阴影也能造深度：

- **更浅的背景色 → 更深的边界**，反之亦然（`surface` / `surface-sunken`）
- **颜色区分**：离用户越近的元素颜色越**浅**。深色底上，最近的层用浅色，远处的用深色
  （深色模式的阴影几乎不可见，这个原理是主力手段）

## 6. 重叠元素制造层次（Overlap elements to create layers）

**最有效的造深度手段**：让元素比父容器高，至少在一侧重叠。

```css
.card { margin-bottom: -8px; }  /* 下一张卡盖住上一张的底部 */
```

多张图片重叠要注意噪音——相邻元素之间留一条"隐形边框"（1–2px 的背景色缝隙），
否则边界糊在一起。

## 少用边框（Use fewer borders）

"Use fewer borders" 是全书最出名的 tactic，也是官方首页的示例。边框是区分元素的手段，
但**用太多会让界面显得杂乱**。替代方案：

- 加 box-shadow
- 换对比的背景色
- **或者干脆加间距**

反过来确实需要边框时：输入框（用户需要明确的"这里可以输入"信号）、表格线、确实需要
"不属于同一组"信号而间距已经用尽的场合。边框 1px 就够，颜色取背景色的深一档，
不要纯黑透明。

## 圆角

定 **1 个基准值**（4px 或 6px），全站统一；只有圆形元素和全屏遮罩用 `50%` / `0`。
圆角按组件大小分档（8/6/4）是界面显得业余的高频原因。

## 层叠顺序

用 `z-index` token（`--z-header: 800` / `--z-dropdown: 900` / `--z-modal: 1000` /
`--z-toast: 1100` / `--z-tooltip: 1200`），不要散落手写数字。手写数字是层级 bug 的最大
来源，尤其是 Toast 被 Modal 盖住这种。

模态遮罩用 `rgba(0,0,0,.5)` 左右，**不要加 backdrop-filter**——性能代价明显，视觉收益很小。
