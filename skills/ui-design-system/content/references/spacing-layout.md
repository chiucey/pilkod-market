# Layout and Spacing — 布局与间距

原书第 3 章。

## 1. 留白宁多勿少，然后减

"Start with too much white space." 这是全书最容易执行也最常被违反的一条。**挤成一团的界面
永远比空一点的界面难改**——加留白需要重新想布局，减留白只要改个数字。

看起来拥挤的界面，几乎总是因为留白不足。加留白比任何装饰性修补都便宜、干净。

密集型界面有它的位置（数据密集、监屏场景），但即便如此，"先给足再收紧"仍然比反过来容易。

## 2. 建立间距和尺寸系统（Establish a spacing and sizing system）

```
4  8  12  16  24  32  48  64  96  128  192  256  384  512  640  768
```

只用这些值。**相邻档位的差异必须够明显**——16 到 20 只差 25%，肉眼基本看不出区别，
这种"档"是假的。想区分就用 16 vs 24。

任意值（7 / 9 / 11 / 13 / 18 / 23）都是红旗：看到就换成最近的档位值。

尺寸系统同理——组件高度、内边距、容器宽度都从同一套里取值。

## 3. 不必填满整个屏幕

"You don't have to fill the whole screen."

- 内容撑不满时，**留出空白是可接受的**。表单拉满整个屏幕不是大气，是没人管
- 不知道怎么处理"小内容 + 大画布"？**从移动端开始设计**
- 内容天然适合窄栏时，把它**拆成多栏**，而不是无限拉宽
- 侧边栏、导航栏：**固定宽度**，不要百分比或栅格列宽，并按内容优化

## 4. 栅格被高估了

"Grids are overrated." 响应式下比例会变形，强行用 12 栏栅格经常得到不自然的结果。
只在真的需要弹性多栏布局时才用；其他时候固定宽度 + 间距更可控。

**能用 flex/grid 的 `gap` 和自动尺寸解决，就不要引入栅格系统。**

## 5. 相对尺寸不会等比缩放

"Relative sizing doesn't scale."

- 不是所有东西都需要相对尺寸
- 大屏上很大的元素，到小屏需要**缩得比小元素更快**——小屏上"很大 vs 很小"的差距应该
  被压缩，否则布局会崩
- **不要用 rem 做标题字号**，它在移动端缩放表现很差。字号用 px

## 6. 消除模糊间距（Avoid ambiguous spacing）

"Avoid ambiguous spacing" 是一整节。

**相邻元素之间的等效空隙，应该大到足以让用户判断它们是否相关。** 两个标签和它们各自的
输入框贴在一起，但标签和输入框之间只有 8px、输入框之间有 24px——用户会以为标签和下面
另一个输入框是一组。

分组不明确时，**间距不够是唯一可靠的解法**。另外，间距含义模糊时也可以显式用分隔线——
这正是边框少数几个合理的用途之一（其他情况见 finishing-touches.md 的"少用边框"）。

## 7. 容器

- 内容区最大宽度 **960–1200px**（数据看板可到 1400+）
- 长文本段落 **20–35em** 或 `70ch`
- 表单和登录页更窄：400–500px 就够，铺满宽屏的表单是明确的反模式
- 断点保持克制：`640 / 768 / 1024 / 1280` 四档足够，不要每个组件单独发明断点

## 8. 密度调节

同一设计系统需要两套密度时，**只改间距和字号，不改颜色和阴影**。紧凑档：间距阶梯整体
乘 0.75，字号降一档（正文 14px）。

## 布局决策顺序

内容结构 → 容器宽度 → 间距 → 内部排布。反过来做（先想 flex 怎么摆、再补 padding）
是间距系统腐化最常见的路径。
