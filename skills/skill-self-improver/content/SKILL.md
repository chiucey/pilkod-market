# 技能自我优化器

自动监控对话质量，在需要时创建或优化技能的元技能。

## 触发条件

在以下任一情况下触发本技能：

1. **无技能可用**：对话涉及专业领域任务，但没有对应技能
2. **技能效果不佳**：使用了技能但输出质量不理想
3. **用户不满意**：技能执行结果未达到用户期望
4. **用户明确要求**：用户要求"创建技能"、"优化技能"、"补充能力"

## 执行流程

### 阶段 1：问题识别

分析当前对话，提取：

- **任务类型**：用户想要完成什么
- **领域范围**：属于哪个专业领域
- **技能缺口**：现有技能是否覆盖
- **优化需求**：如果已有技能，问题在哪里

### 阶段 2：信息收集

收集最新、最权威的内容：

- 使用 `mcp__matrix__batch_web_search` 搜索相关领域最佳实践
- 收集官方文档、权威教程、优质案例
- 提取关键模式、成功经验和标准流程

### 阶段 3：技能构建

基于收集的信息创建或优化技能：

- 使用 `skill-creator` 技能的工程化流程
- 确保技能结构完整（SKILL.md + _meta.json）
- 遵循目录契约：`/workspace/temp-skills/<skill-name>/`

### 阶段 4：质量验证

验证新技能：

- Frontmatter格式检查
- 命名规范检查（英文路径、连字符格式）
- 结构完整性检查
- 使用 `path-checker` 验证路径

## 输出格式

创建技能后，使用 GenUI 组件呈现：

```xml
<genui-skill-card name="skill-name" desc="技能描述" skill-id="技能ID"></genui-skill-card>
```

## 决策规则

| 情况 | 操作 |
|------|------|
| 对话无需技能 | 不创建，提示当前对话无需技能 |
| 有可用技能但效果差 | 优化现有技能而非创建新技能 |
| 缺少对应技能 | 创建新技能 |
| 用户要求提升质量 | 按用户需求重构技能 |
| 信息不足 | 主动搜索权威资料后再构建 |

## 注意事项

- **优先使用现有技能**：避免重复创建功能相似的技能
- **质量优先**：宁可少创建也要确保质量
- **收集信息再构建**：不凭空捏造，基于权威资料
- **保持简洁**：新技能内容精炼，避免过度工程化
