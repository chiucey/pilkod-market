# Skill Quality Gate (技能质量门)

技能质量门将 AIQGate 理念扩展到 Skill 开发，在将 Skill 标记为完成之前，通过两阶段验证协议验证 Skill 的格式规范和功能可用性。

## 何时使用此技能

**使用此技能当：**
- 用户创建新 Skill 并需要全面的质量保证
- AI 生成 Skill 内容但未经过验证
- 用户提到："验证这个 Skill"、"检查 Skill 规范"、"prove this Skill works"、"skill quality gate"
- 用户请求部署前的 Skill 验证
- 用户希望确保 Skill 符合平台标准

**不要使用此技能当：**
- 验证常规代码功能（使用 ai-q-gate）
- 只需要简单的语法检查
- 用户明确跳过验证
- 验证非 Skill 的 markdown 文档

## 核心原则

**"不要相信 AI 写的 Skills —— 让 AI 证明 Skills 有效。"**

每个 Skill 必须通过两阶段验证：
1. **规范验证**：自动化检查文件结构和格式
2. **功能验证**：AI 驱动的测试证明 Skill 实际可用

两个阶段都必须获得 `[PASS]`，否则 Skill 视为不完整。

## 验证协议

### 阶段 1：规范验证（自动化）

执行以下检查：

- [ ] SKILL.md 文件存在
- [ ] Frontmatter 包含必需字段（name, description, version）
- [ ] Description 遵循 "此技能用于..." 模式
- [ ] 使用第三人称描述
- [ ] 指令使用祈使语气
- [ ] 字数在推荐范围内（建议至少 1000 字）

### 阶段 2：功能验证（AI 驱动）

**步骤 1：读取并分析 SKILL.md**

加载 Skill 内容并验证：
- Frontmatter 包含必需字段（name, description）
- Description 明确说明触发条件
- Use/Do NOT use 部分提供清晰的边界
- 执行步骤可操作且具体
- 失败策略（On Failure）已定义

**步骤 2：测试触发识别**

验证 AI 能识别何时使用该 Skill：
- 创建匹配触发条件的测试场景
- 创建负面测试场景（何时不使用）
- 确认 Skill 对预期用例正确激活
- 确认 Skill 对非预期用例正确拒绝

**步骤 3：验证执行逻辑**

对于 Skill 中的每个执行步骤：
- 验证步骤具体且可操作
- 验证步骤使用祈使语气
- 验证步骤有明确的成功标准
- 验证步骤之间的依赖关系合理

**步骤 4：检查失败策略**

验证 Skill 定义了：
- 步骤失败时发生什么
- 后备机制
- 给用户的错误消息
- 替代方案

**步骤 5：生成测试结果**

产生结构化输出：
```
[PASS] 触发识别测试通过
[PASS] 执行逻辑验证通过
[PASS] 失败策略验证通过
[PASS] 所有功能检查通过 ✓
```

### 阶段 3：综合报告

**生成包含以下内容的质量报告：**

1. **规范验证结果**（来自阶段 1）
   - 文件结构检查
   - Frontmatter 验证
   - 写作风格验证
   - 平台标准合规性

2. **功能验证结果**（来自阶段 2）
   - 触发识别测试
   - 执行逻辑验证
   - 失败策略验证

3. **总体评估**
   - 总分（X/10）
   - 关键问题（必须修复）
   - 警告（建议修复）
   - 建议（锦上添花）

4. **后续步骤**
   - 如果失败：具体的修复说明
   - 如果通过：部署就绪确认

## 用户命令

复制并粘贴以下命令以触发验证：

**完整验证（两个阶段）：**
```
执行 skill-q-gate 验证协议。运行规范验证器，然后进行功能验证。显示两个阶段的完整报告和 PASS/FAIL 状态。
```

**仅规范验证：**
```
运行此 Skill 的规范验证。使用 claude-code 标准显示验证结果。
```

**仅功能验证：**
```
执行此 Skill 的功能验证。测试触发识别、执行逻辑和失败策略。显示 PASS/FAIL 结果。
```

**快速检查：**
```
快速验证此 Skill - 检查是否准备好部署。
```

**严格模式：**
```
执行严格的 skill-q-gate 验证。将警告视为错误。如果发现任何问题则验证失败。
```

## 关键原则

1. **两阶段验证必需**：规范和功能验证都必须通过
2. **仅真实证据**：不是"看起来正确"——展示实际验证输出
3. **平台标准意识**：根据正确平台验证（claude-code/trae/kimi）
4. **可操作反馈**：始终为失败提供具体的修复说明
5. **CI/CD 就绪**：退出码和结构化输出用于自动化

## 验证清单

### 规范检查（自动化）
- [ ] SKILL.md 文件存在
- [ ] Frontmatter 有必需字段（name, description, version）
- [ ] Description 遵循 "此技能用于..." 模式
- [ ] 使用第三人称视角
- [ ] 指令使用祈使语气
- [ ] 字数在推荐范围内
- [ ] README.md 存在且包含必需部分
- [ ] 满足平台特定标准

### 功能检查（AI 驱动）
- [ ] 触发条件清晰且具体
- [ ] Do NOT use 条件定义边界
- [ ] 执行步骤可操作
- [ ] 执行步骤使用祈使语气
- [ ] On Failure 部分定义错误处理
- [ ] 输入/输出定义结构化（如适用）
- [ ] Skill 目的单一职责

## 常见问题与解决方案

**问题**："Frontmatter 缺少必需字段: version"

**解决方案**：将 version 添加到 SKILL.md frontmatter：
```yaml
---
name: my-skill
description: 此技能用于...
version: 1.0.0
---
```

**问题**："未定义失败策略"

**解决方案**：添加 On Failure 部分到 SKILL.md：
```markdown
## On Failure

- **无有效输入**：提示用户输入正确格式
- **执行错误**：显示错误消息并建议重试
- **超时**：建议将任务分解为更小的步骤
```

**问题**："触发条件不清晰"

**解决方案**：明确定义 Use/Do NOT use：
```markdown
## 何时使用此技能

**使用此技能当：**
- 用户请求特定功能 X
- 上下文表明需要 Y

**不要使用此技能当：**
- 用户想要不同的功能 Z
- 用户明确跳过此步骤
```
