# 连载结构系统设计技能

实现从「写零散片段」到「写完整连载系统」的进阶，解决章节间断裂、剧情咬合度低、故事碎片化的问题。

## 核心原理

成熟的网文连载是彼此咬合的章节系统，每一章都有明确的功能定位，共同服务于主线剧情推进与读者期待管理。

## 执行流程

### 1. 单章功能前置规划

每一章动笔前，先明确本章的核心功能，可选功能包括：

| 功能类型 | 说明 |
|----------|------|
| 推进主角阶段目标 | 让主角离目标更近一步 |
| 升级核心矛盾 | 将冲突推向新高度 |
| 揭露关键新信息 | 揭示读者想知道的重要情报 |
| 深化核心人物关系 | 推进感情线/羁绊线 |
| 回收前文伏笔 | 兑现埋下的伏笔 |
| 制造下一阶段悬念 | 为后续埋下钩子 |

**单章不一定只有一个功能，但必须有主功能。**

### 2. 章节咬合设计

确保本章内容与前后章节形成**强关联**：

**承上**：
- 本章开篇承接上一章的悬念/钩子
- 完成对应期待的部分兑现
- 回应读者"后来呢？"的追问

**启下**：
- 本章结尾必须为下一章留下牵引点
- 形成"承上启下"的强咬合
- 禁止章节间出现"断档"问题

### 3. 主线锚定校验

每完成一个剧情单元，校验所有章节内容是否都围绕主角的核心主线目标展开：

**不合格情况**：
- ❌ 与主线无关的情节
- ❌ 无推进作用的冗余内容
- ❌ 自嗨式的背景介绍
- ❌ 割裂主线的水剧情

**合格要求**：
- ✅ 每个章节都服务于主线推进
- ✅ 每个情节都有存在的必要
- ✅ 读者能感受到剧情在"往前跑"

### 4. 因果链闭环检查

确保所有情节、行动都有对应的**前因后果**：

**问题诊断**：
- ❌ 事件发生后无后续影响
- ❌ 人物行动无合理动机
- ❌ 伏笔埋下后不了了之
- ❌ 冲突解决后无任何改变

**合格要求**：
- ✅ 每个事件都引发后续连锁反应
- ✅ 每个人物行动都有动机支撑
- ✅ 整个故事形成完整的因果链条

## 执行红线

| 禁止行为 | 说明 |
|----------|------|
| 禁止"想到什么写什么" | 无功能规划的随性写作 |
| 禁止章节断裂 | 剧情松散、无关联 |
| 禁止冗余情节 | 稀释故事核心牵引力 |

## 章节规划模板

```
章节名称：_________
核心功能：□推进目标 □升级矛盾 □揭露信息 □深化关系 □伏笔回收 □悬念制造
承上：上一章的______（悬念/期待）需要______（如何回应）
启下：本章结尾的钩子是______，牵引读者想看______
主线关联：本章如何推进主角的核心目标？
```

## 自检清单

- [ ] 每章是否有明确的功能定位？
- [ ] 本章是否与上一章形成强咬合？
- [ ] 本章是否为下一章留下了牵引点？
- [ ] 本章内容是否服务于主线目标？
- [ ] 是否存在与主线无关的冗余情节？
