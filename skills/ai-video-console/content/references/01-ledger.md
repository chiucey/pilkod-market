## 一、台账必填区块

1. **项目头**：项目名、版本、更新时间、作者署名与指纹
2. **立项单**：媒介、题材与核心情绪、四维决策（时长×画幅×风格×画质）、语言、平台、交付范围
3. **硬锁区**：品牌名/Logo/主色调、已注册角色核心设定、平台或赛事强制规格
4. **创意内核**：一句话故事、主题、目标受众、已锁定剧情与台词
5. **全域影调**：@FILM_SEAL 正文、负向视觉禁忌
6. **资产索引**：全部编号资产及版本、生效镜头、状态
7. **key_element 契约**：角色/场景/道具/服装/声音的视图需求与最小充分集
8. **技术偏好**：图像模型、视频模型
9. **状态区**：已确认 / 待确认 / 禁止事项
10. **流程指针**：当前工位、状态、下一解锁条件
11. **待执行清单**：要求内容、来源、归属工位、调用条件

模板见 `06-ledger-template.md`。

## 二、三域模型（判定争议的裁决依据）

| 域 | 判据 | 归属 |
|---|---|---|
| 全域 | 拿掉它，全片每个镜头都会不一样吗？是 → 全域 | 可进 @FILM_SEAL |
| 场域 | 只影响某场景、某时段、某天气？是 → 场域 | 写入场景描述 |
| 镜域 | 只属于当前这一镜的画面内容？是 → 镜域 | 写入镜头描述 |

典型误判：把参考图里出现的窗户光、火焰、逆光写成全域——那是镜域；把"黄昏暖调"写成
全域——那是场域（只有夜戏、雨戏会继承）。

@FILM_SEAL 只写：媒介工艺、摄影系统、对比逻辑、色彩分离、肤色处理、高光过渡、
暗部信息、材质响应、颗粒与锐度原则。

## 三、编号规则

| 类型 | 格式 | 示例 |
|---|---|---|
| 人物 | `@ACT_编号` | @ACT_01 |
| 服装 | `@COS_编号+版本字母` | @COS_01A |
| 场景 | `@SET_编号` | @SET_01 |
| 道具 | `@OBJ_编号` | @OBJ_01 |
| 主要分镜 | `@MK_编号` | @MK_01 |
| 连续镜头 | `@SH_三位编号` | @SH_001 |
| 人声 | `@VOX_编号` | @VOX_01 |
| 音效 | `@SFX_编号` | @SFX_01 |
| 音乐 | `@MUS_编号` | @MUS_01 |
| 全域影调 | `@FILM_SEAL` | — |

- 同一对象不得重复建号；版本用后缀，**记录从哪一镜开始生效**
- 人物外观参考与服装参考分开管理，禁止服装版本串用
- 复用用户已有媒体同样建号并验镜（复用 ≠ 免检）

## 四、硬锁字段（HARD_LOCK）

标记为硬锁的内容，任何工位不得静默覆盖——包括后续工位的"优化建议"和用户的模糊表述
（"能不能稍微调一下配色"应触发提示而非直接改）。解锁唯一方式：用户明确声明修改硬锁
字段，此时先出全链路影响报告再执行。

## 五、回退矩阵

| 修改内容 | 回退到 | 失效范围 |
|---|---|---|
| 媒介类型变更 | A1 | A2 起全部下游 |
| 剧情/结局/人物关系变更 | A1 | 受影响场次起全部下游 + 契约 diff |
| 台词修改 | A3 | 涉及该台词的分镜与镜头 |
| @FILM_SEAL 变更 | A2 | B1 起全部资产与镜头需复核 |
| 单个人物外观修改 | B1 | 该人物出镜镜头 |
| 单个场景修改 | B1 | 该场景内镜头 |
| 分镜结构调整 | A3 | 受影响镜头组 |
| 单镜验镜失败 | B2 | 仅该镜（最小回退） |
| 交付规格变更 | C3 | 仅时间线重排与输出 |
| 硬锁字段变更 | A1 | 全链路（先出影响报告） |

执行步骤：判定影响范围 → 回退最早受影响工位 → 标记失效下游 → 台账升版本 → 依序恢复。

## 六、待执行清单

越轨或延后要求一律登记，不提前执行：

```
- [ ] 要求内容 ｜ 来源（用户指令/验镜发现） ｜ 归属工位 ｜ 调用条件
```

到达对应工位时自动调取并提示用户。
