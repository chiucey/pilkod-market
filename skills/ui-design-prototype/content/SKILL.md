# UI 设计稿生成（大厂水准）

根据设计规范文档和需求文档，生成符合大厂设计系统标准的UI设计稿与交互原型。

## 核心工作流

生成设计稿涉及以下步骤：

1. 分析输入文档（读取需求 + 设计规范）
2. 确定设计系统与风格方向
3. 规划信息架构与页面结构
4. 选择布局模式（读取 layout-patterns.md）
5. 选择组件与定义交互（读取 component-library.md）
6. 定义 Design Token（读取 design-spec.md）
7. 生成设计稿（文字规范 + 视觉图片）
8. 输出完整交付物（读取 output-format.md）

## Step 1: 分析输入文档

### 需求文档分析
提取以下关键信息：

- **用户角色**：目标用户是谁（管理员/普通用户/访客）
- **核心功能**：用户需要完成什么任务
- **功能模块**：系统包含哪些模块/页面
- **数据流**：数据从哪里来，到哪里去
- **优先级**：P0核心功能 / P1重要功能 / P2扩展功能
- **平台**：PC Web / 移动端 / 响应式

### 设计规范分析
如果用户提供了设计规范文档：
- 提取品牌色、字体、Logo 等品牌元素
- 确认栅格系统、断点定义
- 确认已有组件库（Ant Design / Material Design / Element 等）
- 确认特殊交互要求或动效定义

如果用户未提供设计规范：
- 根据产品类型推荐设计系统（见下方决策表）
- 使用默认值定义基础 Token

## Step 2: 确定设计系统方向

### 设计系统选择决策表

| 产品类型 | 推荐设计系统 | 风格特点 |
|---------|-------------|---------|
| B端后台/SaaS/中后台 | Ant Design | 企业级、高效、组件丰富 |
| C端消费/社交/内容 | Material Design | 现代、卡片化、动效丰富 |
| 苹果生态/iOS 应用 | Apple HIG | 简洁、留白、注重内容 |
| Windows/生产力工具 | Microsoft Fluent | 深度感、亚克力、专业 |
| 数据驱动/AI产品 | IBM Carbon | 理性克制、可访问性强 |
| 电商/零售 | 自定义 + Material | 视觉冲击、促销氛围 |

读取 **references/design-spec.md** 获取完整设计 Token 定义。

## Step 3: 规划信息架构

### 页面结构规划
根据需求定义页面清单：

```
[系统名称]
├── [模块A]
│   ├── [列表页]
│   ├── [新增/编辑页]
│   └── [详情页]
├── [模块B]
│   └── ...
└── [全局页面]
    ├── 登录/注册
    ├── 个人中心
    └── 系统设置
```

### 导航结构
- 侧栏导航：模块 ≤7 个，层级 ≤3 层
- 顶部导航：模块 ≤5 个，扁平结构
- 混合导航：顶部一级 + 侧栏二级

## Step 4: 选择布局模式

读取 **references/layout-patterns.md** 获取完整布局定义。

### 按页面类型选择布局

| 页面类型 | 推荐布局 | 说明 |
|---------|---------|------|
| 数据列表/表格 | 侧栏导航 + 搜索筛选 + 表格 | 标准列表页模式 |
| 表单录入 | 侧栏导航 + 分组卡片表单 | 标准表单页模式 |
| 数据详情 | 侧栏导航 + 信息卡片 + Tab | 标准详情页模式 |
| 仪表盘 | 侧栏导航 + 统计卡片 + 图表 | 数据可视化布局 |
| 设置/配置 | 双栏（菜单 + 内容） | 三栏或双栏 |
| 官网/展示 | 顶部导航 + 全宽区块 | 营销页布局 |

### 响应式规划
- PC 端（≥1200px）：完整布局，所有功能可用
- 平板（≥768px）：简化布局，侧栏可收起
- 手机（< 768px）：单列布局，抽屉导航，卡片堆叠

## Step 5: 选择组件与定义交互

读取 **references/component-library.md** 获取完整组件定义和决策树。

### 组件选型原则
1. **优先使用标准组件**：复用成熟组件库的组件，不重复造轮子
2. **状态完整性**：每个组件需定义默认、hover、聚焦、禁用、加载、错误状态
3. **一致性**：同类型操作使用同类型组件（如所有删除都用红色按钮）
4. **可访问性**：颜色对比度 ≥4.5:1，支持键盘导航

### 交互定义清单
每个页面需定义：
- 页面加载行为（骨架屏/Loading/直接渲染）
- 数据操作（增删改查的触发方式和反馈）
- 状态转换（普通→编辑→保存→成功的流程）
- 异常处理（网络错误、权限不足、数据为空）

## Step 6: 定义 Design Token

读取 **references/design-spec.md** 获取 Token 定义规范。

### Token 输出要求
为每个项目输出完整的 Token 表格：
- Colors：主色 + 功能色 + 中性色（至少 12 个）
- Typography：字体栈 + 字号阶梯（至少 6 级）
- Spacing：间距阶梯（至少 5 级）
- Border Radius：圆角阶梯（至少 3 级）
- Shadows：阴影阶梯（至少 3 级）

## Step 7: 生成设计稿

### 文字设计稿
使用 **references/output-format.md** 的模板，为每个页面输出：
1. 页面概览（布局、类型、目标）
2. 区域划分（从上到下，每个区域的高度、背景、内容）
3. 组件清单（组件类型、位置、状态、数据源）
4. 交互说明（触发条件 + 响应行为）
5. 状态说明（默认/加载/空/错误）

### 视觉设计稿图片
使用 generate_image 工具生成高保真设计稿：

**Prompt 构建模板**：
```
A high-fidelity UI mockup of a [页面类型] page for a [产品类型] product.

Layout: [布局描述]
Top: [顶部区域元素]
Main: [主内容区域元素]
Style: [风格描述]
Colors: primary [主色], background [背景色], text [文字色]
Typography: [字体风格]
Components: [使用的组件]
Spacing: clean spacing with 16-24px gaps

Design system: [Ant Design / Material Design / custom]
Quality: professional, enterprise-grade, pixel-perfect
No text or watermark. Clean UI only.
```

**图片生成要求**：
- 比例：16:9（PC 页面）/ 9:16（移动端）
- 分辨率：2K
- 数量：每页至少生成 1 张，关键页面生成 2-3 个状态（默认 + 交互态）

## Step 8: 输出完整交付物

### 交付物清单

1. **design-overview.md** - 设计概览（项目信息 + 设计原则 + 页面清单）
2. **[page-name].md** - 每个页面的详细设计规范
3. **design-tokens.md** - 完整 Design Token 定义
4. **[page-name].png/jpg** - 每个页面的视觉设计稿图片
5. **user-flows.md** - 关键用户流程说明

### 质量标准

大厂水准的设计稿必须满足：

- [ ] **视觉层次清晰**：通过字号、颜色、间距建立明确的信息层级
- [ ] **色彩系统完整**：主色+功能色+中性色，无随意取色
- [ ] **间距规律统一**：基于 8px 基数系统，无随意间距
- [ ] **组件使用规范**：符合设计系统组件定义，状态完整
- [ ] **布局响应式**：至少考虑 PC + 平板 + 手机三种断点
- [ ] **交互可落地**：每个交互有明确的触发条件和响应行为
- [ ] **异常有处理**：加载、空状态、错误状态都有设计
- [ ] **可访问性**：对比度达标，支持键盘操作

## 注意事项

1. **优先确认设计规范**：如果用户提供了设计规范文件，严格遵循；未提供则使用推荐默认值
2. **避免过度设计**：B端产品注重效率，不过度使用装饰元素
3. **保持页面一致性**：同一系统的所有页面使用相同的布局结构和 Token
4. **标注中文界面**：面向中文用户的产品使用中文界面元素
5. **区分平台特性**：移动端优先触控操作，PC端优先键盘效率
