# 股市 Mini App

A Chinese equity research workspace. The Client is a static semantic HTML surface; the Node entry
owns the API, persistence, normalization, the 60-second refresh loop, and the SSE refresh channel.

## Data sources

每个来源在调用前都要通过**能力校验**（对应 Connector 工具在 hostConnector 清单中，或 CLI 可用且已登录），
校验不通过的来源直接跳过刷新、在页面「数据说明」中标注状态，绝不伪造数据。

- **行情（Host Connector `hengsheng_market`）**：本地缓存 + 增量拉取。首次全量
  `get_daily_bars`（3 年 + 249 根 warmup），此后每 60 秒仅拉最近 7 天并按日期合并进
  `<dataDir>/bars/<symbol>.json`（上限 1300 根）。分时（`get_intraday_series`，1 分钟，显式传参）
  为整日替换式缓存；报价卡使用 `get_latest_quote` 的真实价与其自身昨收（asOf 为可信行情时间）。
  盘中每 60 秒重新同步 1 分钟线；空 payload 或 stale 结果不清空本地有效数据，并标注 `intradayDate`。
- **进门财经（Host Connector `comein`）**：`searchAnalystComments` 券商点评（TTL 60 秒），
  `get_stock_details` 代码 → 简称解析（持久缓存于 names.json）。
- **知识星球（Node 直调 `zsxq-cli`，只读）**：运行时用 execFile 调 `topic +search`
  （固定参数、20s 超时、无 shell），TTL 60 秒。能力校验为 `group +list` 返回至少一个星球
  （结果缓存 10 分钟）。仅本机可用、依赖当前登录态；CLI 缺失或未登录时该来源显示"暂不可用"，
  已缓存条目继续展示。亦可通过 `POST /api/ingest/sentiments` 手工写入：

  ```json
  {
    "symbol": "600519.SH",
    "source": "知识星球",
    "items": [{"id":"zsxq-...","title":"…","summary":"…","content":"…","publishedAt":"2026-09-08T09:00:00+08:00","url":"https://wx.zsxq.com/topic/...","tags":["调研"]}]
  }
  ```

  同一 `symbol` + `source` 的写入整体替换该来源的条目。舆情不做正负面情绪判定。
- **Alpha派（Node 直连 OpenPai，用户填 API Key）**：在「数据源」页填 Key，保存前先调健康检查
  `POST /alpha/open-api/v1/sync/auth/hello` 校验，通过才写入 `<dataDir>/alphapai.json`（权限 600）；
  Key 不回传页面（只显示位数和尾号）、不写日志。行情页舆情**按 Alpha派 自己的公司打标**取（按股票代码过滤，不用名称或别名检索）：
  点评（`comments/list`）、社媒（`social/media/article/list`）最近 30 天；纪要（`summary/list`）、内资研报、外资研报（`report/list`，外资用中文标题）最近 90 天；
  每种最多 15 / 10 / 6 / 6 / 5 条。**只调列表接口**：社媒有全文，点评只有前 100 字，研报、纪要只有标题和机构（`preview`）。全文按需取——舆情详情里点「加载全文」
  （`POST /api/sentiment/full`）或 Agent 调 `research_read` 时才调详情接口，取到后写回缓存。原因：点评详情每天只有 100 条额度（`当日查询点评详情已达上限（100条）`），
  部分研报详情没有权限。列表 ID 是有时效的加密串：存在条目的 `ref` 里（不发给页面），过期了按标题重新列同一天的资料找回新 ID；条目 id 用标题 + 时间 + 机构生成，刷新后不变；
  同类型、同一天、同标题的合并成一条。每条带 `stocks`（Alpha派 打的股票标签），别的股票拉到、但标在这只股票上的也算直接提及。
  TTL 10 分钟，在后台刷、到了再推给页面；取法有版本号（`tagged-1`），旧的按名称召回的缓存会重取。所属环节、产品等扩展检索词仍用投研知识检索
  `paipai/recall-data` 语义召回，别名不再发给 Alpha派。
  业务成功以 `code === 200000` 判断，`42900` 限流时等 1.5 秒重试一次，`401000` 视为 Key 无效。
  没填 Key 时整个来源静默跳过。清除 Key 时一并清掉已抓到的 Alpha派 舆情（已存入资料库的保留）。召回结果没有原文链接。

## API

- `GET /dashboard` Client 页面；`GET /api/health` 运行状态。
- `GET /api/snapshot[?symbol=]` 当前快照；切换代码会同步向 Connector 拉取，
  未收录的代码返回 404，Connector 不可用返回 503。
- `POST /api/refresh[?symbol=]` 强制刷新当前标的的报价、日K和分时后返回最新快照；
  页面“刷新数据”按钮使用此接口，不是只读本地 snapshot。
- `GET /api/sentiment` / `GET /api/sentiment/:id` 当前标的舆情。
- `POST /api/ingest/sentiments` 见上。
- `GET /api/watchlist`、`POST /api/watchlist`（`{"symbol":"600519.SH"}`，大小写与
  `SH:600519` 等前缀会被标准化）、`DELETE /api/watchlist/:symbol`。
- `GET /api/events` SSE；行情/舆情/自选股更新后推送 `snapshot.updated`。
- `PUT /api/sources/alphapai`（`{"apiKey":"…"}`，先校验再保存，失败返回 400 / 502 和原因）、`DELETE /api/sources/alphapai`（清除 Key）。

## 图表行为

日K 默认三个月窗口，可切换 1 年 / 3 年；窗口锚定最新 `daily.date`。均线为收盘价简单移动平均
（5/10/20/60/120/250），基于全部已供历史计算后再取可见窗口，warmup 不足的区段不绘制。
顶部搜索大小写不敏感，`600519`、`600519.SH`、`SH:600519` 等解析为同一标的；
纯 6 位代码按号段推断交易所。

## 自选股与刷新

- **K线类数据（日K/分时/报价）仅在 A 股交易时段刷新**（周一至周五 09:30–11:30、13:00–15:00，
  Asia/Shanghai）。**午休和 15:00–15:05 也算今天**：午休时启动、午休手动刷新，或者手里的分时还不是今天的，
  会补拉一次今天上午盘的分时和日K（取数日期由 `market-schedule.mjs` 的 `marketDataDates` 统一决定，
  开盘前和周末才取上一个已收盘交易日）。15:05 后每只股票只做一次「收盘终刷」并在
  bars 缓存打 `finalRefreshDate` 标记，当日不再重复拉取。App 在收盘时未运行的，下次启动自动补刷至
  最近已收盘交易日。未接入交易日历，法定节假日按普通工作日近似（多刷一次无副作用）。
- **当天日K兜底**：行情源还没给出当天日K时（盘中常见），用当天报价（开、高、低、现价、成交量、成交额）
  补一根临时K线，只用于展示（快照里 `dailyProvisionalDate` 标出日期），日K和成交额图都能看到今天；
  不写进缓存，行情源给出当天日K后自然被替换。
- 舆情刷新（进门财经 / 知识星球）与用户主动操作（切换股票、首访新标的）不受时段限制。
- Node 交易时段内每 60 秒刷新当前标的与全部自选股报价（本地缓存 + 7 天增量合并）并广播 SSE；
  Client 每 60 秒轮询兜底。
- 日K全量响应必须覆盖请求起点、最新可用日期且至少包含 250 根 bar；不满足时缓存保持
  `full=false`，启动和定时刷新会继续走全量修复。`coverageComplete=false` 不会直接标记收盘终刷完成。
- 自选抽屉的展开状态只保存为本地视图偏好，不写入行情数据。
- 测试数据源说明：`hengsheng_market` 为测试库，当日分时可能缺失（回退展示最近交易日），
  部分分时成交量为空时按 0 展示；日K bar 为收盘后终值，增量合并会以新拉取值覆盖同日期旧值。

## 资产：资料库与知识图谱

顶栏「行情 / 资产 / 数据源」切换。资产页按功能分页签，页签在 `client/wiki.js` 的 `ASSET_TABS` 里登记（一个页签对应一个 panel，`server.mjs` 的 `sanitizeViewState` 白名单同步加 id），之后新增的资产功能也以页签形式加入。目前有三个：

- **资料库**（输入）：关联文件夹卡片（资料数、待整理数），以及资料文件表格（名称、状态、关联股票、大小、修改时间）。表格可按整理状态（全部 / 待整理 / 已整理，默认全部）和文件夹筛选，按文件名或关联股票搜索。资料不需要手动整理，新增或有更新的文件由后台自动整理（见「自动整理」）。已整理的文件可打开它在知识图谱里的资料摘要，关联股票可打开对应的公司节点。
- **知识图谱**（输出）：头部是概况（节点、关系、待核数）、「打开知识库文件夹」和「分析视角」。画布默认显示力导向图谱。**产业链不单独设页签，而是图谱按行业下钻的视图**，有三个入口：双击节点、节点详情里的「查看产业链 / 在产业链中定位」、工具栏的「查看「某行业」产业链」。进入后顶部是面包屑「知识图谱 / 行业 / 产业链」，点「知识图谱」或按 Esc 返回。节点详情在右侧。
- **边际变化**：和知识图谱并列，汇总所有节点相对此前资料的变化（见下文）。
- 资产页右上角是自动整理的状态和开关：「自动整理已开启 · 暂停」「自动整理已暂停 · 继续」「上次整理没有完成，HH:MM 自动重试 · 立即重试 · 暂停」。后台任务进行中或出错时，页签上方有一行任务条（进度、查看过程、停止 / 知道了），三个页签都能看到。

### 自动整理（系统主动整理，人只看结果）

- **默认开启，不需要点按钮。** 不关联任何文件夹也会扫描当前股票和自选股的舆情。触发时机：关联文件夹、存入舆情、舆情刷新、任务结束、Mini App 启动，另有每 10 分钟一次巡检。事件触发的整理在几秒到 20 秒内开始（舆情刷新后 60 秒），已经排好的整理不会被后来的事件往后推。
- **顺序**：先整理新增 / 有更新的资料（每批 4 个、单次最多 40 个，剩下的下一轮接着整理）；资料都整理完后，再扫描当前股票和自选股里还没扫过的舆情（同一只股票 30 分钟内最多自动扫一次，单次最多 30 条）。同一时间只跑一个后台任务。
- **整理后自动去重**：整理任务完成后自动合并高置信度的重复公司节点（同一股票代码、全称与简称、别名相同）；需要确认的仍在知识图谱页签提示。
- **出错和停止**：出错后 15 分钟自动重试，资产页右上角可「立即重试」。在任务条上点「停止」等于暂停自动整理，右上角「继续」恢复。开关保存在 `dataDir/wiki-settings.json` 的 `auto`，接口 `PUT /api/wiki/auto`（`{"enabled":true|false}`）；状态在 `GET /api/wiki/status` 的 `auto`（available / enabled / pausedAt / retryAt / unscanned）。
- **需要人介入时用小弹窗**：后台 Agent 请求授权时弹出授权弹窗（拒绝 / 允许一次 / 稍后），点「稍后」后顶栏标签变成提醒色，点它重新打开；Agent 停下来提问时弹窗提供「查看过程」，在对话侧栏打开后台会话。
- **进度和结果**：顶栏的整理标签在所有页面都能看到（「整理资料 2/5」「扫描舆情 3/12」「后台整理等待授权」，窄屏只显示一个圆点），点它去资产页或打开授权弹窗；任务完成用提示条告诉一声（整理了几份资料、新增几条动态和变化、更新几个节点），只提示这次打开页面之后完成的任务；行情页「最新」顶部一句话说明后台正在做什么或已暂停。
- 分析视角修改后对之后整理的资料生效，已整理的资料不会自动重整。
- 后台 Agent 不可用时（MiniMax Code 低于 3.1.2）：资料、知识图谱和已有记录照常浏览，界面说明原因。

整理方法参考 Karpathy 的 LLM-Wiki 模式：原始资料只读 → LLM 维护的页面（界面上叫知识图谱的节点）→ 规则（内置 Skill + 用户的分析视角）。界面统一用「知识图谱 / 节点」，「Wiki」只出现在给模型用的 MCP 工具名里；存储上叫「知识库」。

- **关联文件夹**：输入路径，或在对话里打开时一键关联当前对话文件夹（Agent 权限 `session.read`）。只接受用户目录下的文件夹，不能是用户目录本身、`~/Library`、顶层隐藏目录或凭据目录（当前对话文件夹例外，可在 `~/.mavis/workspace` 这类隐藏目录下）。只读扫描 PDF / Word / PPT / Excel / CSV / Markdown / 文本 / 网页，跳过隐藏目录、`node_modules` 和 `_wiki/`，不跟随符号链接；每个文件夹最多 8 层、3000 个文件。文件按 SHA-256（以 size + mtime 缓存）判断新增 / 有更新 / 已整理。
- **知识库（全局唯一，固定位置）**：不让用户选保存位置，也不写进资料文件夹，固定在 Mini App 数据目录的 `wiki/`（`dataDir/wiki/`）：`pages/*.md`（frontmatter 每行 `key: JSON`，含结构化 `relations`）、`index.md`、`log.md`、`manifest.json`、`records.json`、`clips/`、`archive/`。资料文件夹只读，可以随时关联或取消关联，不影响知识库。知识图谱页签头部「打开知识库文件夹」用默认应用打开它（`POST /api/wiki/open {"target":"wiki"}`）。
- **迁移**：旧版把知识库写在「保存位置」文件夹的 `_wiki/` 里。新版第一次启动时整体复制到 `dataDir/wiki/`（知识库里已有内容时不覆盖），旧目录保留，在它的 README 开头注明已迁移、不再更新；迁移状态记在 `wiki-settings.json` 的 `migration`，只做一次。
- **分析视角**（知识图谱页签头部）：内置产业链、供需、竞争格局（默认启用）以及财务与估值、政策与事件；每个视角是可改写的 Prompt，可停用、恢复默认、新建，另有可选的「研究目标」。保存在 `dataDir/wiki-lenses.json`。
- **后台 Agent 整理**：自动整理通过 `context.agent.run()` 跑后台 Agent（`agentConcurrency: 1`），同一会话分批续跑。**整批处理**：每轮一批，按正文体量组批——文本类资料（Markdown、TXT、网页、Word、PPT、Excel）的正文由 Node 抽取后直接放进 `wiki_job_brief`（单份最多 6000 字，一批合计约 3 万字），PDF 等按 5000 字估算、由 Agent 自己读，一批最多 10 份；`wiki_upsert_page` 用 `pages` 一次写多个页面，`wiki_mark_source` 用 `items` 一次标记整批，`wiki_add_records` 一次最多 60 条；舆情扫描一批 12 条（每条原文截到 1500 字）。Agent 先加载内置 Skill `<pluginId>:llm-wiki`，调用 `wiki_job_brief` 取文件清单、视角和现有页面，再用自己的工具读文件，只通过 MCP 工具 `wiki_upsert_page` / `wiki_mark_source` / `wiki_add_records` 写入（Node 校验类型、关系和来源后落盘，再推 SSE）。一轮没有标记任何文件就停止，避免空转。
- **视图**：知识图谱是自绘的力导向 SVG（无第三方库），节点为页面和尚未建页的关系目标，可按行业 / 类型筛选、缩放、平移；产业链视图按上游 / 中游 / 下游三列排环节卡片，卡片里挂属于该环节的公司和产品，连线为 `upstream_of` / `supplies`，虚线为待核关系。「查看产业链」默认去图谱当前筛选的行业，没有筛选时去选中节点所属的行业，再没有就去节点最多、且标注了上中下游的行业。详情面板渲染正文、关系、反向关联和来源，公司页可「看行情 / 加自选」。
- **行情页「最新 | 舆情 | 纪要」**：图表下方三个并列页签，默认「最新」，记住上次选择（localStorage `market.feed`）；行情始终在最上面。「最新」（`GET /api/wiki/latest?symbol&name`）是当前股票在知识图谱里的公司节点（按 tickers 或简称命中），以及它所属环节（`belongs_to`）、所产产品（`produces`）节点上的最新动态和边际变化，按日期倒序最多 60 条；不是公司本身的记录会标出节点名，可点进知识图谱；底部「在资产 · 边际变化里查看全部」。没有记录时说明原因（未关联文件夹 / 正在整理 / 自动整理已暂停 / 版本不支持）。原来的「个股资料 / 资料库匹配」板块已删除。
- **MCP 工具**：`wiki_status`、`wiki_search`、`wiki_get_page`、`wiki_list_pages`、`wiki_neighbors`、`wiki_pages_for_stock`、`wiki_upsert_page`，以及整理任务专用的 `wiki_job_brief`、`wiki_mark_source`。`get_view_brief` 额外返回所在页面、行情页的 `feedTab`（最新 / 舆情 / 纪要）、资产页页签（资料库 / 知识图谱 / 边际变化）、知识图谱视图（图谱 / 产业链，仅在知识图谱页签时）和选中的节点。
- **API**：`/api/wiki/status`、`files`、`folders`、`reload`、`graph`、`page`、`related`、`search`、`lenses`、`jobs`（含 `/jobs/:id/cancel`、`/jobs/:id/permission`；`kind` 为 ingest / stock / scan，scan 的 `scope` 为 current / watchlist / all）、`stock`、`minutes`、`clips`、`changes`、`open`、`latest`、`auto`、`expand`，变更后 SSE 推送 `wiki.updated`（kind：pages / files / folders / job / lenses / records / auto）。
- **版本要求**：后台 Agent（自动整理、扫描舆情）需要 MiniMax Code 3.1.2+，关联当前对话文件夹需要 3.1.4+（`session.read`）；不可用时页面说明原因。

### 文件夹选择框

资料库页签的「在访达中选择文件夹…」（Windows 为系统文件夹选择框，Linux 用 zenity / kdialog）由 Node 端拉起系统对话框，只回传用户选中的路径，再按关联规则校验。用户亲自选择时允许用户目录之外的位置（例如外接盘），但磁盘根、卷根、用户目录的上级和系统目录仍然拒绝。手动输入路径的规则不变。

### 公司节点唯一化

- 写入公司页时按「股票代码 → 证券简称 → 标题 / 别名 → 公司名归一（去掉股份有限公司等后缀）」查找已有页面，找到就并入；标题统一用证券简称，资料里的全称、简称、英文名、代码都进 aliases。
- 以代码为标题的页面（如「600519」）在查到简称后自动改名；关系目标里的「600519.SH」「茅台」也改写成规范标题，不再产生孤立节点。
- `wiki_resolve_company` 通过恒生代码搜索 / 进门简称解析把名称和代码对上，结果写入 `names.json` 供后续写入使用。
- 重复节点：高置信度的（同一代码、全称与简称、别名相同）在每次整理完成后自动合并；名称相近、需要确认的在知识图谱页签提示「发现 N 组可能重复的公司节点」，选择主页面后合并。被合并的页面移到知识库的 `archive/`，其他页面指向旧名字的关系改指主页面。

### 个股资料匹配与归集（后台能力，无单独界面）

- 不调用 LLM 的即时匹配：按文件名 / 路径、正文关键词（文本类文件和 docx / pptx / xlsx 自行读取，macOS 另用 Spotlight 覆盖 PDF 等格式）、知识图谱里已整理资料对该公司的引用，以及之前标注的相关度打分。关键词为证券简称、公司页别名和 6 位代码，另加知识图谱里的相邻节点（见「用知识图谱扩大检索」）；只靠相邻节点命中的分数更低、标为关联，个股归集不收这类资料。它现在用于把纪要对应到当前股票，以及 MCP 工具 `wiki_stock_materials`（在对话里问「我的资料里关于这只股票有什么」）。
- 个股归集任务（`POST /api/wiki/jobs`，`kind=stock`）保留接口，界面不再提供入口：后台 Agent 加载内置 Skill `<pluginId>:stock-dossier`，逐个判断候选文件的相关度（核心 / 提及 / 无关），把与该公司相关的信息整理到唯一的公司页，并给每份资料写一句说明。判为无关的文件不写入任何页面，也不会因此被标为全局「已跳过」。
- 相关度记录在 知识库 `manifest.json` 的 `stockLinks`，公司页详情显示「相关资料」，资料文件列表显示它关联的股票；文件内容变化后会重新进入候选。

### 纪要、出处、最新动态与边际变化

- **纪要**：纪要来自资料库，不是单独的数据源。资料库里文件名带“纪要、调研、交流、电话会、路演、专家、访谈、业绩会、说明会”的文件，或后台 Agent 读过后标成纪要的文件，再按文本匹配（公司名称、别名、代码，以及相邻节点）、Agent 标注和归集记录对应到当前股票，只靠相邻节点找到的标「关联 · 光模块（所属环节）」（`GET /api/wiki/minutes`）。日期依次取 Agent 识别的日期、文件名里的日期、修改时间（界面会注明）。点开可以用默认应用打开原文、在知识图谱中查看摘要；还没整理的纪要会被后台自动整理。收录的舆情不进纪要列表。
- **Agent 打标**：`wiki_mark_source` 增加 `doc_type`（纪要 / 研报 / 公告 / 新闻 / 笔记 / 舆情 / 其他）、`doc_date`、`doc_title`、`stocks`（资料里的叫法 + 相关度，Node 先查公司页再查证券简称解析成代码）；不在后台任务时用 `wiki_tag_material`。标注写在知识库 `manifest.json` 的 `files` 和 `stockLinks`（`by: agent`），资料库表格和纪要列表里会标「Agent 标注」，解析不出代码的公司记为 `unresolved`。
- **最新动态与出处**：`wiki_add_records` 给节点追加带日期、带出处的记录，保存在知识库的 `records.json`：`kind=update` 最新动态，`kind=change` 边际变化（维度、方向、from → to）。entity 必须是已有页面，date 和 sources 必填；同一节点同一天同一句话会合并出处；节点改名或合并时记录跟着走。节点详情最上面是「最新」（按日期倒序），下面才是综述；来源、关系出处、正文里出现的资料文件名和链接都能点。
- **用默认应用打开**：`POST /api/wiki/open` 由 Node 调系统命令（macOS `open`、Windows `explorer.exe`、Linux `xdg-open`，`execFile` 不经 shell）。文件只接受资料库索引里的 key（关联文件夹和收录的舆情），`target: "wiki"` 打开知识库文件夹；链接只接受 http / https；页面不能传任意路径。舆情详情里的「打开原文」也走这里，用默认浏览器打开。
- **边际变化页签**：可按方向、维度、来源（资料库 / 纪要 / 收录的舆情 / 知识星球 / 进门财经 / 腾讯文档 / 网页）、时间筛选和搜索，点对象跳到知识图谱，点出处打开原文。方向（改善 / 走弱 / 待判断）是后台 Agent 依据资料做的判断，界面上注明。舆情扫描由自动整理完成（`task=scan`：直接读行情页已经抓到的舆情原文，每批 6 条，有变化就记 `kind=change`，出处是原文链接；扫过的舆情记在 `manifest.scanned`，不会重复扫描）；有未扫描的舆情时页签上有一个「立即扫描」，可以不等排队直接扫当前股票和自选股。新闻源暂未接入，留了来源类型。
- **舆情存入资料库**：舆情详情里「存入资料库」（`POST /api/wiki/clips`，页面只传 id，原文由 Node 从已抓取的舆情里取）。每条存成 Markdown（frontmatter 记来源、链接、发布时间、股票）放在知识库的 `clips/<来源>/`（不需要先关联文件夹），资料库里显示为虚拟文件夹「收录的舆情」，存入后自动整理进知识图谱。同一条只存一次，列表上标「已存入资料库」。不需要为了扫描边际变化而存入，扫描直接读已抓到的原文；存入是为了长期保存原文、进入知识图谱。原来板块右上角的批量「收入资产」已删除。
- MCP 工具新增 `wiki_tag_material`、`wiki_add_records`、`wiki_list_changes`。

### 用知识图谱扩大检索

- **检索词**（`searchProfile`）：直接提及 = 证券简称、公司页标题、别名、6 位代码；关联 = 知识图谱里的相邻节点——公司页上的 belongs_to（所属环节）、produces（产品）、supplies（客户）、upstream_of、competes（竞争对手）、substitutes，以及别的页面指向公司的 supplies（供应商）、upstream_of（上游）、competes 等。按 所属环节 → 产品 → 竞争对手 → 客户 → 供应商 → 上下游 排序，最多 10 个节点、16 个词（含节点别名），待核关系排在同类之后；行业页、资料摘要页和太泛的词（公司、行业、龙头……）不算。页面变化后自动重算。
- **舆情**：一只股票的列表由三部分合并——按名称直接检索到的；用别名和所属环节 / 产品额外去各来源检索到的（每个词每个来源 15 分钟刷新一次，多只股票共用，存在 `sentiment-terms.json`）；其他股票舆情里提到这家公司或相邻节点的。后两类只保留文字里确实出现检索词的。每条带 `match`（direct / via / terms），列表上标「别名 Eoptolink」「关联 · 光模块（所属环节）」；说明行列出这次用到的别名和相邻节点，可以「只看直接提及」（记在 `market.scope`）。后台扫描用同一份列表，`matched_by` 告诉 Agent 关联舆情的变化应记在相邻节点上。
- **纪要**：同一套检索词，相邻节点命中算关联、分数低于直接提及，同样可以只看直接提及。
- **搜索框**：`GET /api/wiki/expand?q=`——输入对得上某个节点时，同时检索它的标题、别名和代码；环节、产品、概念节点再带上挂在它下面的产品 / 子环节和替代品（公司只带自己的叫法，不带相邻节点）。搜索框下方显示扩展了哪些词。

### 统一检索（MCP `research_search` / `research_read`）

- **一次查遍已接入的数据源**：Alpha派、进门财经、知识星球、腾讯文档、本地资料库（文件名 + 正文，macOS 另走 Spotlight），再加上行情页已经抓到的舆情。没接入的来源不调用、不出现在结果里；接入了但这次失败的列在 `failed`（超时、限流、Key 失效等），用来说明覆盖面。
- **Alpha派 用公司打标、不用别名**：公司主体按股票代码取点评、社媒、纪要、研报、公告（`alphapai_types` 里打标覆盖不到的官方路演、美股业绩会、指标、基金报告，用公司名语义召回）；有话题时再按「公司名 + 话题」语义召回一次；环节、产品、自由文本只用本名召回；发散时相邻节点各召回一次。返回的 `alphapai_queries` 写明这次怎么查的，打标命中的条目 `match` 为「公司打标」。
- **主体与别名同步检索**（其他来源）：给 `symbol`，或 `query` 里有对得上知识图谱节点的词（整句或连续的几个词，越长越优先；单个词还会试一次股票简称）时，以它为主体，用名称、别名、代码同时检索，`query` 里其余的词当话题。语义来源（Alpha派、进门财经）检索「名称 / 别名 + 话题」，关键词来源（知识星球、腾讯文档）只搜名称和别名，结果再按话题排序。
- **发散**：`neighbors=true` 时按「所属 → 上游 → 下游 → 竞争」轮流取最多 4 个相邻节点一起检索；环节 / 产品节点还会带上挂在它下面的细分和公司。返回的 `chain` 是主体的产业链地图，没开 `neighbors` 也会给，供下一步发散。
- **结果**：按 id 去重，标命中原因（直接提及、别名 X、代码 X、关联 · 节点（关系）、语义召回）；语义来源的结果都保留，其余只保留直接提及或关联到相邻节点的；外部来源按 `days`（默认 30）过滤，本地资料库不按时间过滤；各来源轮流取，避免一个来源挤掉其他来源；附相关知识图谱节点和下一步提示。
- **全文**：`research_read` 按 id 取全文（最近 400 条检索结果在内存里，另外也能读行情页已抓到的舆情）；本地资料返回正文，PDF 等读不了的返回路径。
- **研究方法**：Skill `sentiment-search`（由 Alpha派 官方 skill 的信源与数据使用规则改写，覆盖所有来源）——先沿产业链发散（上游、下游、竞争、驱动因素，资料类型分开查），再按维度收敛、交叉验证、说明覆盖面后回答。
