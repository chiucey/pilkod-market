# Choosing a visual pattern

Choose the smallest interaction that makes the central relationship observable.

| Knowledge structure | Preferred visual | Learner action | Avoid |
|---|---|---|---|
| Prerequisite or concept relationships | `concept-map` | Select nodes and trace what depends on what | Decorative webs with no readable direction |
| Continuous quantity or signed magnitude | `number-line` | Drag a value and compare position/distance | Sliders when the number has no conceptual meaning |
| Part–whole and equivalent fractions | `fraction` | Change the shaded parts and name the fraction | Pie decoration without a fixed whole |
| Ordered mechanism or life cycle | `process` | Step forward, predict the next stage, restart | Autoplay that removes learner control |
| Two or more categories | `comparison` | Inspect matching attributes and state a distinction | Unequal comparison criteria |
| Light reflection | `ray-reflection` | Change incident angle and observe symmetry about the normal | Measuring angles from the mirror surface |

## Representation rules

1. Preserve the real invariant. Show what stays the same while one input changes.
2. Make the learner predict before manipulating the control.
3. Pair the visual with one sentence that names the observed relationship.
4. Separate the model from reality. State at least one limitation for analogies or simplified simulations.
5. Use labels next to the represented object. Avoid long legends that force visual memory.
6. Do not encode the same category by color alone; pair color with text, shape, or position.

## Age adjustments

- Ages 6–9: use one control, short sentences, concrete objects, and immediate observation prompts.
- Ages 10–12: introduce named variables or terms after the intuitive model; keep one core relationship per screen.
- Ages 13–15: show assumptions, counterexamples, and a second representation when useful.
- Ages 16–18: connect the visual to formal notation, boundary conditions, and transfer questions.

## Page rhythm

Build the learner journey in this order:

1. Predict — pose the puzzle without giving the rule.
2. Manipulate — let the learner vary one meaningful input.
3. Notice — state the invariant or pattern in plain language.
4. Name — introduce formal vocabulary or notation.
5. Apply — solve a new check question.
6. Recall — hide support and ask for a concise explanation.
