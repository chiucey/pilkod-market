# 典型业务领域架构

## 一、账号与鉴权

- Token 生命周期：短 access + 长 refresh；刷新串行化（并发请求等待同一个刷新），失败统一登出。
- 多账号/切换：状态隔离，本地数据按账号分桶，切换时清理缓存与订阅。
- 设备绑定与安全：设备指纹、异地登录提示、敏感操作二次校验。
- 第三方登录：服务端换取自有会话，客户端不保存第三方 token。
- 注销与合规：账号注销后本地数据清理，服务端删除/匿名化，可提供导出。

## 二、实时通信

- 连接：WebSocket 心跳 + 指数退避重连 + 前后台切换重连；断网恢复要补拉。
- 消息可靠性：客户端生成幂等 ID，服务端去重；有序列号时检测空洞并补拉。
- 有序与去重：按会话串行处理，避免乱序覆盖。
- 离线队列：本地写入待发送队列，上线后按顺序重放，失败有上限与死信处理。
- 存储：会话消息分页落库，图片/文件走独立缓存与清理策略。
- 弱网：超时、重试次数、失败提示与手动重发。

## 三、推送与深链

- 权限：按业务时机申请；被拒后有引导路径。
- 通道：Android 厂商通道 + 自建通道兜底；iOS APNs。
- 点击路由：通知负载只放 ID，落地页再拉详情，避免过期数据。
- 冷启动深链：启动参数在首帧前解析，未登录时排队，登录后继续。
- 兜底：无效链接进首页并提示，不白屏。

### 可验证接入清单

- iOS Universal Links：托管 AASA（`apple-app-site-association`）→ 配 Associated Domains → 从 Safari 地址栏与备忘录各测一次。
- Android App Links：托管 `assetlinks.json`（包名 + SHA256 指纹）→ intent-filter 配 autoVerify → 用 `pm get-app-links` 与浏览器实测；未验证会静默落浏览器。
- Android 13+ 通知权限：运行时申请 `POST_NOTIFICATIONS`，被拒要能引导到系统设置。
- iOS 通知：首帧后再申请，拒绝后要有引导路径；前台、后台、杀进程三态都要测。
- 深链矩阵：冷启动 / 热启动 / 已登录 / 未登录 × 合法参数 / 缺失参数 / 非法链接，全部要有着陆页与兜底。

## 四、支付

- 客户端不可信：支付结果以服务端对账为准，客户端只做展示与轮询。
- 幂等：下单幂等键；重复回调去重。
- 状态机：待支付/支付中/成功/失败/关闭，异常态要能恢复（查单）。
- 恢复购买（订阅类）、退款入口、合规埋点。

## 五、离线优先与同步

- 写路径：本地先写（标记待同步）→ 队列 → 服务端确认 → 清理标记。
- 冲突策略要显式选择：服务端优先 / 本地优先 / 字段级合并 / 提示用户。
- 时钟：不要用设备时间做业务排序，用服务端时间或逻辑时钟。
- 批量与压缩：同步请求合并、差量同步、失败重试有退避与上限。

## 六、埋点与实验

- 事件模型：谁（匿名/登录 ID）、何时、在哪（页面/来源）、做了什么、结果如何。
- 命名规范：`模块_对象_动作`，参数枚举化；禁止把业务数据当参数乱塞。
- 采样与性能：高频事件采样，避免主线程做序列化。
- 隐私：敏感字段脱敏或不采，遵守最小必要。
- A/B：分流在服务端或稳定哈希；曝光与转化口径统一；实验开关可灰度、可回滚。
- 校验：埋点有验证手段（调试面板 / 事件校验 / 上线后看数据量），避免“埋了但没人看”。

## 七、列表、分页与搜索

- 分页优先游标（cursor），避免 offset 在数据变动时重复/漏项。
- 去重按稳定 ID；列表刷新要区分「首屏重拉」「增量插入」「局部更新」。
- 搜索要有防抖、取消旧请求、空结果与错误态；输入法与联想不阻塞主线程。
- 缓存失效规则明确：什么事件让哪份缓存失效。

## 八、文件与媒体

- 上传：分片、断点续传、并发上限、失败重试、进度与取消。
- 压缩：按用途定尺寸与质量，避免原图直传。
- 缓存：磁盘上限、LRU 清理、退出登录清理私有文件。
- 播放：预加载、缓冲策略、后台播放与音频焦点。
