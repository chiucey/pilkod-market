# Pilkod Bot

把 Pilkod 变成一支长期在线的 Bot 团队。你创建自己的 Bot，然后和它们私聊、拉群协作。

## 功能

- **长期 Bot**：每个 Bot 有名字、角色、指令和自己的 Agent 会话。设定、团队名单或记忆变化后，下一轮会自动带上最新上下文。
- **主 Bot（Chief）**：首次打开自动创建，负责引导你搭团队，可以创建、修改、删除 Bot 和群聊。普通 Bot 越权会被拒绝。
- **群聊**：默认由管理员接话；`@名字` 可直接点名，Bot 在回复里 `@` 其他成员会接力发言；没有补充的成员回复 `[PASS]` 被跳过。每个成员在每个群有独立会话，群里看不到私聊。默认没有固定发言次数上限，可在群设置里为该群单独设置；队列自然结束，重复交接且没有工具进展时暂停，可补充要求继续。
- **Bot 之间转交**：`message_bot` 把任务交给另一个 Bot，立即返回受理回执，做好后结果回到发起聊天；`post_group` **仅限单聊发起**，往群里发一条消息，发完立即返回，讨论按群聊的回复方式继续。单聊中的主 Bot 可以往任何群发，不需要先加入；其他 Bot 只能往自己所在的群发。群聊回合禁用 `post_group`，Chief 和管理员也不能向本群或其他群投递；群内直接在回复里 `@名字` 让成员接力，跨群任务回到单聊发起。
- **后台处理**：Bot 需要独立执行上下文时，用 `start_helper` 把工作放到后台：任务在全新的独立会话里执行，可从任务页打开完整执行过程，Bot 这一轮立即结束，用户可以继续聊天。对用户来说这叫「放到后台做」，Bot 会像同事那样自然地说「我去查查看」，不提内部术语和任务编号。任务做完，报告作为一轮新输入交回给 Bot，由 Bot 验收后用自己的话转告（群里也一样，并可继续 @ 接力）。同时最多 2 个后台任务在跑（至少留一个名额给聊天），其余排队；每个 Bot 最多 4 个排队或运行中。聊天输入框上方显示进行中的任务并提示可以继续聊，可随时停止；任务条按进度排序，正在运行的在前，其次是等待其他任务的，排队中的在最后；列出的任务超过三个时，只展开前三个，其余收起成一行「还有 N 个任务」，点任务条下方的按钮可展开整个队列；后台任务的工具审批出现在对应聊天里；Mini App 重启时运行中的任务记为中断。Bot 也可以用 `list_helpers` / `stop_helper` 管理。Bot 设置里的「允许自动使用后台助手」默认开启，关掉后只有用户明确要求才放后台。
- **每个 Bot 单独的模型和推理强度**：在 Bot 设置里选模型和推理强度（只列出该模型支持的档位，支持的模型可以关闭思考；「跟随默认」的 Bot 也能单独设推理强度），或让主 Bot 用 `create_bot` / `update_bot` 的 `model`（模型 ID、`provider/模型` 或显示名，`default` 跟随默认）和 `effort`（`low` / `high` / `off` 等，也认「低」「高」「关闭思考」）参数设置。有 thinking 档位的模型按 composer 的方式默认开启。需要支持 `agent.models()` / `run({ model })` 的 Pilkod，旧版本会提示升级。
- **图片与文件**：Bot 回复里的 `<media src="…" />` 和 `![](绝对路径)` 直接显示为图片、音视频播放器或文件卡片。点击本地 HTML / HTM 卡片会在 Mini App 内打开沙箱预览，MD / Markdown 卡片会显示排版后的阅读页（超过 2 MiB 时显示纯文本）。预览由当前 Mini App 读取文件，避免普通标签页没有宿主认证而返回 401 白页；读取失败会显示原因并可重试，超过 16 MiB 可用预览栏下载按钮保存后查看。其他文件仍下载。本地文件经 `/api/media` 读取，只提供该会话里 Bot 引用过的路径。HTML 预览允许页面脚本、HTTP(S) 样式和展示资源，但在独立沙箱中运行，不能访问 Bot 的存储、通过 fetch 调用 API 或提交表单；不会开放 HTML 引用的其他本机文件，需将本地资源内嵌。远程链接按目标网站的响应展示。
- **记忆**：每个 Bot 一份、团队共享一份，只保存用户明确的长期需求、偏好和确认的决定。调研过程、价格、候选列表与暂定推荐留在对话或文档；任务需求优先放当前 Bot，跨 Bot 都适用的长期信息才放团队。长期存储单条正文 1,200 字符、每份 100,000 字符且最多 1,000 条；Bot 与团队的本轮记忆条目共享 6,000 字符注入预算；拒绝疑似密钥、密码和证件号，所有改动记入 journal。
- **定时任务**：每天定点、按间隔或 N 分钟后一次，在指定 Bot 的私聊里自动发出任务（仅在 Mini App 服务运行时触发）。可以在设置里建，也可以直接让 Bot 安排：Bot 通过 `create_schedule` / `list_schedules` / `delete_schedule` 建的任务同样出现在设置和 Bot 详情里，不会落到 Pilkod 的全局定时任务。
- **用量**：按 24 小时 / 7 / 30 / 90 天统计各 Bot 的对话轮次、回复字数、工具调用与耗时。
- **形象**：11 种渲染好的形象（蓝色毛绒、泡泡、粉色玻璃、金色、翡翠、毛绒、华夫饼、像素、笑脸球、玩具、月岩），图片在 `miniapp/client/skins/`；Bot 名字和 @ 的文字颜色跟随所选形象。首次创建的主 Bot 用蓝色毛绒（与插件图标一致），之后新建的 Bot 默认挑一个用得最少的形象；旧数据里的配色会映射到最接近的形象。工作中会动、等待回答时显示提示，动效不变。也可以点「+」一次选择多张自己的图片（逐张居中裁成 256px 正方形），自动保存到当前 Mini App 的本地头像库，再选择一张并点保存应用。图库供所有 Bot 复用，刷新、重启、切换内置形象或删除 Bot 都不会删除已添加的头像；相同图片重复导入会去重，单张失败不会阻断其他图片，失败文件会逐项提示。已有的自定义头像文件也会出现在图库中，旧版本已经删除的图片需重新添加。也可以让主 Bot 用 `update_bot` 的 `skin` / `avatar` 参数设置。
- **任务入口**：图标栏底部的任务按钮汇总进行中、待批准、已完成和未完成的助手任务，保留最近 30 条已结束记录；可以停止任务、打开所属会话处理批准、定位结果或进入定时任务管理。
- **设置入口**：图标栏底部是你的头像，显示名字的第一个字，点击打开设置（用量也在设置里）。名字默认取系统账户全名，可在「设置 → 通用 → 你的名字」修改。
- **会话筛选**：侧栏左侧的图标栏可以切换全部消息、未读、群组、单聊，角标显示各类未读会话数；选择会被记住。筛选时主 Bot 和其他会话一样按行列出。
- **语言**：支持中文和英文，默认跟随操作系统的首选语言（页面读取 `navigator.languages`，第一个中文或英文生效，其他语言用英文），也可以在「设置 → 通用 → 语言」里固定。界面、错误提示、系统通知、Chief 的默认设定、Bot 收到的上下文和 MCP 工具说明都会跟着切换；Bot 写下的回复和你自己填写的内容保持原样。

- **表情回复**：用户可对私聊、群聊中已结束的 Bot 回复添加表情。快捷栏提供 👍、❤️、🙌、😂、😭、😮，更多表情支持分类浏览和中英文搜索。每条消息只能选择一个表情，选择新表情会替换原来的，再点同一表情取消；旧的多选记录保留最后一次选择。已选表情显示在消息框内左下角，正好位于操作栏上方，配色跟随浅色和深色主题；搜索在紧凑浮层中原位展开，结果区域保持固定高度，也可返回快捷栏。选择随消息保存在本地，刷新、重启后保留，并同步到其他已打开窗口。首期不支持回应用户消息，也不会触发 Bot 回复或将表情写入模型上下文。
- **回复操作栏**：表情、复制、引用回复和打开会话按钮放在回复左下方、最后一行文字下面。长回复读到结尾时按钮仍在手边，不会被顶出消息顶部。
- **同一回复的多段消息**：Host 会把 Bot 两次工具调用之间的每段文字记成一个片段，干了一阵活的回复会带着很多片段，页面每个片段画一个气泡。气泡保持官方的样式和顺序，相邻气泡之间留一点间距，避免连成一整块文字。

## 0.7.9 群聊可选的接力护栏

- 可以在群设置里设置跳数上限：一条接力链里最多有几个 Bot 发言。默认 `0` 表示不限制，与之前完全一致；最大 20。
- 达到上限时接力链在此停止。群里会收到提示，刚发言的 Bot 改为收尾总结，不再点名下一位。被拦下的交接不会执行，但收尾本身是单独的一轮：达到上限的一轮共运行 `上限 + 1` 个 Agent 回合，最后一个是收尾。
- 上限按这一轮里每个发言的 Bot 计数。在所有成员都回复的群里（`reply_mode: all`），已经排队成员的首次回复也计入上限。
- 群还可以把上一位的结论交给下一位 Bot：下一位的提示里带上上一条回复的结论，不必再用工具把同样的内容查一遍。上一条回复本来就在新消息里，交接时有意再重复一次结论。这只是提示文字，不增加回合、不增加工具调用，也不写记忆。
- 这两项设置属于群，只有你能修改。Bot 无法更改：MCP 工具目录里不提供这两项，夹带这两项参数的调用会被忽略。

## 0.7.8 更安全的自动重试

- 失败的回合仍会自动重试，最多两次，分别在 8 秒和 20 秒后。
- 标记为 `retryable: false` 的失败一律不自动重试，无论是抛出还是返回的，也无论错误信息写了什么。
- 结果未知的回合（`AGENT_OUTCOME_UNKNOWN`）不会自动重发：它可能已经执行过，重发可能导致重复回复或重复操作。

## 0.6.5 执行记录与错误提示

- 聊天顶部的「执行记录」打开右侧详情栏，按回复轮次查看全部工具调用与整轮失败原因。同一轮同名调用合并，展开后保留每次失败、成功和结果待确认的记录；可加载更早记录，群聊按所属 Bot 区分，完整会话入口绑定该回复的 sessionId。
- 工具失败不再逐条插入对话正文，也不弹 toast。正文保留整轮未完成的简短提示、可安全重试时的重试按钮，以及已结束回复中尚未确认的记忆保存提示和管理入口。权限审批、问卷、消息送达异常继续在原位置处理。
- 只根据同范围、同主题的明确记忆回执移除相应提示；同名调用后来成功不代表原操作已恢复。顶部轻量标记只反映每个参与 Bot 最新回复的整轮失败或记忆待确认，历史失败保留在记录中。
- Bot 回复约定同步说明最终交付影响和所需用户行动，已经恢复的过程错误无需复述。页面不会仅凭调用失败推断整个任务失败，也不会自动重放有副作用的操作。此约定不等同于真实模型验收。
- 流式更新保留已展开的轮次、调用详情与滚动位置；聊天输入草稿、媒体和问卷继续保留。窄屏复用原有全宽详情栏，可用返回、关闭或 Escape 退出。

## 运行方式

- Node 服务（`miniapp/node/server.mjs`）只依赖 Node 内置模块，通过 `context.agent` 运行 Bot 回合，数据保存在 Host 分配的 `dataDir`。
- 页面（`miniapp/client/`）是无构建的原生 ES Module，不加载任何远程资源。
- 同一 Node 进程在 `/mcp/minimax-bot` 提供 Streamable HTTP MCP，向 Bot 暴露 `list_team`、`message_bot`、`dispatch_tasks`、`get_tasks`、`cancel_tasks`、`post_group`、`start_helper`、`list_helpers`、`stop_helper`、`remember`、`forget`、`recall`、`create_bot`、`update_bot`、`delete_bot`、`create_group`、`update_group`、`delete_group`、`create_schedule`、`list_schedules`、`delete_schedule`。
- `miniapp.json` 声明 `agentAccess: ["session.run"]`，Bot 的工具审批与问卷在页面内渲染，也可在 Pilkod 侧栏打开完整会话。
- 当前 Host 的 Agent 接口不支持按会话裁剪 MCP 工具目录；群聊上下文不再推荐 `post_group`，并明确禁用，服务端保留群聊调用拒绝。共享工具目录仍可能展示该工具，其说明明确标注仅限单聊。已有群会话会在下一次 `agent.run` 时按上下文版本自动刷新说明。

## 0.7.0 可靠交接与结果回传

照常和 Bot 聊，它可以找其他 Bot 帮忙；你能继续聊天，做好后结果回到这里，也能随时叫停。

- 单个 Bot 使用 `message_bot`，多个 Bot 使用 `dispatch_tasks`，两者都立即返回持久受理回执，不要求先判断短问答还是长任务。`start_helper` 仅用于需要隔离执行上下文的工作，不再按工具次数或工作类型强制分流。
- 重试复用稳定 `request_id`：同来源、同 ID、同内容只返回原任务；内容改变则拒绝。批量派发必填，`message_bot` / `post_group` 为兼容旧调用可省略，但省略后无法去重重试。任务与去重记录保存在 `state.json`。
- 结果只回发起聊天，由发起 Bot 验收；只携带本次任务产出，不转发完整私聊。第一版不支持指定结果群、汇总人或用户时间预算。外部主会话没有 Host 回调能力，需主动用 `get_tasks` 查询。
- 被派任务再调用 helper 或子任务时，原任务释放执行名额并等待产出，验收续跑仍属于原任务。受理话术不是完成；多轮补做和问卷不会丢失最终结果。取消父任务会覆盖其子任务、helper 和验收续跑，已发生的副作用不回滚。
- 不同 Bot 可并行，同一私聊串行。后台派发最多占两个调度位置，所有聊天、任务和 helper 共用 Engine 的三个 Host 名额。排队可取消，Host 自身的调用限制继续生效。
- `post_group` 保留单聊发起和成员权限，讨论没有固定发言次数上限。精确重复交接且没有工具进展时停止空转，状态为待补充；在群里照常补充要求，或让发起 Bot 再发要求，即可继续同一讨论。没有单独的恢复工具、任务编号操作或预算耗尽流程。
- 任务页仅辅助查看谁在工作、打开所属聊天/结果和停止任务。内部区分排队、执行、等待子任务、等待回答、待补充、完成、失败、取消和结果待确认；不要求用户管理状态机。
- 重启后未开始的任务继续排队，运行中任务标为 `unknown`，不会自动重放。已持久化的子任务结果可以继续验收；丢失执行结果的依赖保留未知。回报消息有稳定 ID，已开始但未确认的验收/汇总不重复执行。
- MCP 为 SSE 客户端立即发送响应头并每 15 秒保活；断线不取消已受理任务，`cancel_tasks` 明确停止。`get_tasks` 的 `wait_ms` 最多 20000，只短等状态变化；完整产出通过单任务 `result_offset` / `next_result_offset` 读取。`create_group` 用 `name` 创建，不接受 `group`。

## 0.6.4 自定义头像与批量图库

- 修复自定义头像在列表、聊天标题、详情和设置中的尺寸溢出。
- 支持一次多选图片，逐张缩放保存到本地共享头像库；重复导入去重，单张失败单独提示。

## 0.6.2 发送补充即调整

- Bot 回复时直接发送补充，就会自动调整当前任务，无需再点按钮。等待旧回复结束期间，连续补充按顺序合并为下一轮；普通补充每批最多 20 条、正文合计 60,000 字符，超出后顺序分批。附件和原始消息各自保留。群聊按用户轮次顺序执行，点名规则保持不变。
- 发送后先保存补充，再取消当前聊天的回复，等待宿主确认该轮结束后，在原会话中处理补充。用户消息下方不显示“处理中 / Processing”，等待、调整或异常时保留简短提示。已经提交给宿主的原始请求不会重发；取消发生在原请求提交前时，会把尚未提交的内容一起交给下一轮。
- 这是“中断并继续”，不是运行中注入输入的原生 steer。已执行的操作不会回滚；独立后台任务不会因为聊天调整而停止。
- 取消或执行结果不确定时，保留补充并显示“尚未确认可以继续”，不自动重发。检查完整会话、处理待回答问卷后，可点“继续处理补充”；这只提交尚未处理的补充，不重放结果未知的原请求。
- 处理中、等待结束、已取消和结果待确认的状态随消息保存并同步到其他窗口。进程意外中断并重启后，有回复占位的处理中消息标为结果待确认，正在调整的补充保留为待确认；连续补充或网络重试不会重复中断同一轮。
- 本功能只修改 Mini App，使用已有 `agent.run`、`AbortSignal` 和 `sessionId` 能力，不要求修改 Local Runtime。

## 0.6.0 可靠性与交互

- 历史消息完整保存在本地，页面首次读取最近 200 条，可逐页加载更早记录；复制 Markdown 会遍历完整历史。旧版已经截断的记录不能凭空恢复。磁盘仍使用完整 JSON，分页控制传输和页面渲染规模，不代表已实现数据库索引或全历史缓存淘汰。
- 消息按稳定递增序号记录。群聊只推进到本次输入中实际提交给 Host 的快照，不再以回复结束时间跳过后来到达的消息；旧游标迁移时会重新带上最近的群聊上下文。
- 页面发送中按聊天防重复，失败后同内容与附件重试复用提交 ID；服务端持久查重，同 ID 的不同内容会被拒绝。Bot 回复期间仍允许发送新的消息。崩溃后只恢复明确尚未调度的请求；已有回复占位但 Host 执行结果不确定时返回 `delivery_uncertain`，保留草稿，需查看完整会话后再决定是否手动发送，避免重复执行有副作用的任务。
- MCP 在调用开始时固定来源回复。Host SDK 尚未提供可验证的调用来源，同一 Bot 同时在多个聊天回复时，无法明确归属的工具调用会被拒绝，需等其他回复结束后重试。后台任务必须来自仍在运行的明确回复；取消后迟到的调用不会再启动其他聊天或助手。
- 记忆写入使用可恢复事务，将正文与 journal 作为同一次操作恢复；中断时返回 `memory_pending`，读取、重试或重启会完成同一操作，不重复记账。消息写盘失败不会污染缓存；保存与重新加载不再依据相似文本前缀合并正文。
- 后台状态刷新保留定时任务表单、记忆编辑和焦点；重连保留输入草稿、附件和已展开历史，连接异常持续显示。流式更新保留媒体、问卷输入和工具详情的交互状态。
- 记忆面板支持原位编辑、容量与作用范围展示，来源信息可展开。工具失败收进执行记录，提供记忆管理和完整会话入口，保留每一次失败的历史含义。
- Bot 配置优先呈现职责、指令和模型，外观收起、保存操作固定可见，并说明主 Bot 管理权限。设置使用原生模态框和键盘焦点循环；窄窗口详情覆盖整个聊天区。

## 0.6.1 记忆存储与上下文

- **两个独立额度**：每个 Bot 和团队各有最多 100,000 正文字符、1,000 条长期记忆，单条新正文最多 1,200 字符；不再另计每条 40 的存储开销。构建本轮上下文时，Bot 与团队的记忆条目共用 6,000 字符，按 `pinned`、当前输入的中英文词语相关度、新近顺序选入完整条目。未选入的内容完整留在磁盘。这里按 JavaScript UTF-16 长度计数，序列化注入计入 ID、key、revision 和换行，不是模型 token；静态指令、工具结果及 Host 会话历史由各自机制管理。
- **不破坏旧数据**：沿用原 Markdown 文件、条目 ID 与 journal，没有启动时清空、裁切、重写或自动删除。第一次修改已有作用域前，原文件字节备份到 `dataDir/memory/backups/<scope>.pre-storage-v2.md`，临时复制完成后独占原子发布，已有备份不覆盖；备份失败则拒绝写入。超过新上限的旧文件仍可读取，并允许不增长的修订。journal 同时保留替换前后文本和条目元数据；原有可恢复事务继续覆盖失败、重试和重启。
- **主题更新与并发保护**：MCP `remember` 必须提供稳定 `key` 或 `replace_id`。先用 `recall` 精确查同一主题，已有条目更新须传 `expected_revision`，`text` 是保留仍有效事实的完整替换内容。相同有效内容重试返回 `unchanged`，不重复记账；旧版本或缺版本的变更返回 `memory_conflict`，不覆盖已有数据。手工新增可不填 key，编辑仍检查版本。面板保留冲突草稿，允许读取最新版本供核对；`pinned` 仅表示优先带入，不保证每条优先记忆都能放入本轮预算。
- **有限召回**：`recall` 默认返回自己的与团队记忆，显式 `scope=self` 只返回自己；其他 Bot 的权限规则保留。`key` / `entry_id` 精确查询，`query` 搜正文和主题，`offset` / `limit` 分页（默认 10 条，最多 20）。结果改为 `{entries,total,nextOffset,storage,contextBudget}`，含各作用域容量和条目 revision；序列化结果最多 6,000 字符。旧超长正文通过 `entry_id` 与 `text_offset` / `nextTextOffset` 无损分片读取，`textComplete=false` 的片段不可直接覆盖原记忆。空查询不会把全部存储一次发给模型。
- **减少重复注入**：静态指令与所选记忆分开计算指纹，相关条目变化只刷新记忆部分；相同选取不重复发送。群聊依据同次消息快照中的最新用户或转交任务选记忆；自动重试保留原检索输入。仍不承诺 Host 历史上下文只占 6,000 字符。
- **失败与恢复**：提示区分本次增加、当时剩余和实际超额。每次失败保留历史；只有后续成功回执能匹配同 scope、同 key/ID，才显示“该主题后续已保存”，不声称之前被拒的原文逐字保存。同名成功不再作为已恢复证据。MCP 在调用开始时固定工具记录；Host 只给工具名、并发归属无法确定时保留未知状态，不猜测成功。
- **恢复入口**：原始备份和 journal 均留在同一个 Host `dataDir`；本次不会自动覆盖正在使用的用户目录或重启已有运行实例。需要人工恢复时先停止对应实例、另存当前文件，核对原始备份及 journal 的完整版本后再恢复；不要直接用较旧备份覆盖新记忆。

## 已知限制

- Host 不向 Mini App 提供 token 数，用量以轮次和字数衡量。
- MCP 调用里的 `caller_bot_id` 由 Bot 自报，权限检查是行为约束，不是安全边界。
- 插件清单（名称、描述、示例查询）目前不支持多语言字段，市场里只显示中文。
