# submit_feedback 使用规则

`submit_feedback` 通过 `tencentmeeting` provider Connector 向腾讯会议提交反馈。它是一次对外写入，必须先展示完整的脱敏内容并得到用户明确同意。

## 适用情形

| category | 判定 |
|---|---|
| `tool_not_found` | 当前 Connector 确实没有用户需要的业务工具 |
| `tool_error` | 业务调用返回错误；先区分连接/鉴权错误与业务错误 |
| `tool_inadequate` | 工具存在，但参数或功能范围无法满足需求 |
| `unexpected_result` | 工具返回成功，但结果与已核实的预期不一致 |
| `suggestion` | 用户希望提出功能或体验建议 |

## 流程

1. 先查错误字典，处理能够明确恢复的问题。反馈不替代原任务；仍有可执行步骤时继续处理。
2. 从当前对话和实际工具结果整理 `category`、`intent`、`actions_tried`、`result`、`tool_name`、`error_code` 等字段。必填与条件必填以当前 Connector Schema 为准。
3. 已知的工具名、错误码从结果中取值，不重复要求用户提供；缺失且确为必填时才询问。不得编造错误码或把工具发现失败当成腾讯业务错误。
4. 按 [privacy_policy.md](privacy_policy.md) 脱敏。会议主题、会议号、成员、链接、手机号、邮箱和凭据不得明文进入反馈。
5. 展示拟提交的全部字段及上报目的，等待用户明确同意。提交内容必须与已展示内容一致；有实质修改时重新展示。
6. 用户同意后，通过实际发现的 `submit_feedback` 工具提交。成功时展示真实返回的 `feedback_id`；拒绝时说明未上报，尚未回复时保持待确认。

## 限制

- 同一会话中的同一问题只提交一次。
- 工具未暴露、连接未完成或反馈工具自身失败时，不递归上报、不切回本地代理。保留脱敏反馈供用户后续提交，并说明当前状态。
- 不把未发生的动作写成已尝试，不把推测写成已确认的根因。
