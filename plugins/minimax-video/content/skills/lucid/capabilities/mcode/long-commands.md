# MiniMax Code：长命令转到后台后怎么等

渲染、体检、配音合成和转写常常要一分钟以上。在 MiniMax Code 里，`bash` 工具在前台最多等 60 秒；命令还没结束时，工具返回一个 `task_id`，同一条命令继续在后台运行。

## 怎么做

1. **调用时把 `timeout` 设够。** `timeout` 是这条命令的总时限，转到后台后也照算。渲染、配音按片长给足，例如 1800 秒；上限是 3600 秒。时限到了命令会被终止，留下没渲完的分段。
2. **拿到 `task_id` 后，命令仍在运行。** 不要重新启动同一条命令：两次渲染会同时写同一批分段和成片，互相覆盖。
3. **先做不依赖它的事。** 例如写交付说明、核对硬约束清单、整理素材来源。渲染期间不改这个工程的 `web/`、`project.json` 和 `audio/`，改了会让正在渲的分段和你以为的版本对不上。
4. **没有别的事可做时，用 `task_output` 等结果**，`wait_ms` 写 30000（单次最多等 30 秒），省略 `offset` 就从上次读到的位置接着读。命令结束时它立刻返回，返回的输出里有体检摘要或合成结果。读输出不会停止命令。
5. **不要在命令还在跑时结束回复。** 结果出来以后才能决定下一步，读完结果接着往下做。

## 常见情况

| 现象 | 处理 |
|---|---|
| `task_output` 返回时命令还没结束 | 正常，再调用一次 `task_output`，`wait_ms` 仍写 30000 |
| 输出停在某一段很久不动 | 先看机器上是不是还有别的渲染在跑（`render.py` 整机排队，日志会提示）；不要另起一条同样的命令 |
| 命令因为 `timeout` 被终止 | 把 `timeout` 设大，重跑同一条命令；`render.py` 会复用已经渲好的分段 |
| 需要停掉一条后台命令（例如发现改错了文件） | 用 `task_stop` 停掉它，改完再重跑 |
