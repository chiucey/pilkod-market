# MiniMax Video · Lucid 代码视频

使用随附 Lucid 3.1.0 引擎。画面由 render(t) 逐帧绘制，输出 MP4；这与 H3 生成写实镜头互补。需要时间线内可直接改字的短片头时用 code-video 的 JSX 动画路径；完整代码成片使用本 Skill。

## 准备与生成

1. 先读 [原版创作指南](references/upstream-guide.md)、[引擎说明](references/engine.md) 和匹配片型的参考。用户已说明主题、风格、时长时直接做，不重复确认。画面文字、字幕和配音跟随用户语言。
2. 将本 Skill 的 template 复制到用户工作目录中的独立项目文件夹。只修改这个副本；保留源代码、project.json、配音稿及生成文件，后续修改复用它们。
3. 先检查 Python、Chrome 和 requirements.txt 中的依赖。缺失时在项目 .venv 中按需安装，不装到系统 Python、不把环境复制进插件。国内使用用户选择的国内 PyPI 镜像，海外使用 pypi.org；不按语言猜地区，不自动跨区回退。Chrome 缺失时说明前提，不悄悄安装浏览器。
4. 配音必须设置 voice.provider=mcode，先运行 tools/tts.py probe。仅使用 MiniMax Code 当前配置并授权的能力；不自动改用 edge 或其他服务，不索要聊天中的密钥。需要配音却不可用时说明，允许用户改用自己的录音或明确接受无配音版本。先生成配音并测得时长，再安排时间线。已有音频和任务结果必须复用。
5. 按原版流程编写镜头、同步时间线、合成音乐并渲染。运行 tools/render.py --final，读取体检与交付报告；失败后修复并复测，不跳过检查冒充验收完成。输出文件及项目路径必须保留。

## 导入 MiniMax Video

1. 使用本插件 MCP 绑定用户当前工程，先读取工程和已有草稿。没有目标工程时请用户打开或创建工程，不猜 ID。
2. 将真实生成的 MP4 用 import_asset 导入素材池，重新读取确认素材存在。源代码仍在上述工作目录，视频导入不会让 Canvas 图形变成编辑器的独立图层；需要改动画时修改源代码并重新渲染。
3. 通过 manual 草稿放入时间线，调用 review_edit_session 后交给用户预览。不要自动 apply，不直接修改数据库。只有 applied 才算写入正式工程。
4. 查看导入后时间线代表帧，并在用户确认后从编辑器再导出。分别报告 Lucid 渲染、素材导入、草稿应用、最终导出的实际结果。不要把静帧检查说成完整播放或听音检查。

示例：用代码做 8 秒 MiniMax Video 片头，深色背景、珊瑚红强调色、清晰大字和合成音乐，不用 H3，不配旁白；生成后导入当前工程，先给草稿预览。
