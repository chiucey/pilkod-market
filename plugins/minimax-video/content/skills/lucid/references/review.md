# 自查与体检：看什么，第一版之后改什么

你看不到动态、听不到声音。工具把画面变成图和表，用来发现问题。它们不能证明片子好看，好看要靠对照片型手册的质量标准自己判断。

## 体检的两级

**硬伤**是观众看得见、听得见的错，进终端摘要，都要改。❌ 是确定的错；⚠️ 多半是错，打开对应的图确认后改。

- 文字：出框、主要文字互相压住、线穿过文字、字小于可读下限、画面里的字或标注目标压进字幕带、标注没落在目标上、占位字（YOUR NAME、Lorem ipsum、TBD）上了画面。
- 画面：开场第一秒空画面、空帧、单帧跳变、拍点空画面、正式档重影、标了「稳」的镜头里的快抖。
- 成片：时长和 `target_sec` 差超过 10%；响度超出范围、真峰值削波（写在报告的「各项检查」里）。
- 预检：违反出片合同的写法（见下文「渲染前的预检」），有问题时不渲。

体检之外还有两处核对：字幕和配音不一致由 `timeline.py`（缺译文、条数不对）和 `tts.py` 的转写核对查出；画幅、帧率、有没有配音和字幕由 `deliver.py` 打印成交付事实，你逐条核对。

**可选提示**（ℹ️）只写进报告的「可选提示」一节，不计入终端的问题条数。它们指出画面可能偏弱的地方，是不是问题由你的设计决定：主体偏小留白多、画面停住、短句没有画面事件、「可以震」的镜头多、单次震动太长、镜头叠化和同框文字推迟、文字块用最小字号也放不下、过程标注词（「示意」「EXPLAINED」、版本号）、线的端点悬空、慢晃、闪光刷灰、最长低变化段和结尾停留、新内容和占用率这类节奏指标、直接用 `fillText` 画的字（照样检查字号、出框、压字，整片提示一次：装饰小字要用 `deco` 包起来）。

终端摘要的格式是「硬伤 N 条（❌ a、⚠️ b）；可选提示 M 条见报告」。

| 什么时候 | 工具 | 发现什么 |
|---|---|---|
| 写完主角物件 | `stills.py --props` | 物件表：每个 `PROP` 放大到约 800 像素高、画几个时刻，看部件相接、比例、线宽、轮廓 |
| 写完一个镜头 | `stills.py S03` | 这个镜头 0.3、0.6、0.9 处三帧；也可以指定时刻 |
| 写完转场、变形 | `stills.py --cuts`、`--between` | 转场和变形中途的画面 |
| 渲染前 | `render.py` 自带预检 | 违反合同的写法、JS 报错、NaN 参数；有问题就停下，不渲 |
| 渲完 | `render.py` 自动体检（也可单独跑 `checkup.py`） | 硬伤：出框、压字、字太小、空帧、跳帧、拍点空画面、抖动、时长、响度、字幕；可选提示：主体大小、短句对齐、节奏、静止段 |
| 正式档渲完 | `render.py --final` 自动和草稿档比对，再运行 `deliver.py` | 正式档重影、运动模糊的采样统计；成片事实，写出 `out/交付核对.md` |

## 读体检的顺序

1. **终端摘要。** `render.py` 渲完打印硬伤条数、排在前面的问题和图的路径。先看这里就知道要改哪几处。
2. **总览图** `frames/_view/checkup/总览.jpg`。每个镜头 2–3 帧，一张图看全片；有问题的帧画框标号，编号和报告清单对应。版面空、主体小、颜色不对，在这里一眼能看出来。
3. **报告** `frames/_view/checkup/报告.md`（多画幅时是 `checkup_<画幅>/`）。硬伤在前，可选提示在后一节。每条问题一行，格式是 `镜头 · 时刻 · 文件:行号 · 「哪句字」 · 问题和程度`，例如 `S05 · 12.3s · web/shots_05.js:27 · 「几十年内」 · 出框（右侧超出 18px）`。照文件行号去改，不用自己找是哪一行。
4. **对齐图** `对齐.jpg`（讲解片）。每个镜头一条：短句区间、`act()` 事件点、画面变化量曲线。看每个短句开头附近有没有事件，变化量的起伏是不是跟着短句走。
5. **洋葱皮图。** 报告里需要看运动的条目才会引用，按引用去看。

没有硬伤只说明没有基础错误，好不好看看总览图和片型手册的质量标准。读完整份报告再动手，把硬伤、你决定处理的可选提示和质量标准里最弱的几处一起改完再渲，比改一处渲一次省等待。改法拿不准的那一处，用 `stills.py` 看那一帧确认，不整片重渲。只读 `frames/_view/` 下缩小后的 JPEG，1080p 原图连读十几张会撑爆请求。

## 看转场和变形中途：`stills.py --cuts`、`--between`

每拍一帧的总览看不到转场中间。两层画面半透明叠在一起、内容溢出容器，只会出现在中间那几帧，所以要专门取。

```
python3 tools/stills.py 名字 --cuts [S03,S04]      # 每个镜头起点的转场，一行 7 帧
python3 tools/stills.py 名字 --between b8-b12 [n]  # 每两拍之间等距取 n 帧（默认 5），一拍一行
```

`--cuts` 的窗口从新镜头开始画（`t0 - pre`）前 0.05 秒，到旧镜头停止画（上一镜头 `t1 + post`）后 0.15 秒，至少覆盖切换点前后 0.25 秒。`pre`、`post` 不用手算，脚本从 `SHOT.<id>` 和 `transitions` 里读。`--between` 用于一镜到底、变形片，这类片子没有镜头切换，变形全在拍与拍之间。图写到 `frames/_view/名字_cuts_NN.jpg`、`名字_between_NN.jpg`，每格标时刻。

看三件事：

1. 中间格是不是两个画面各占一半透明、叠在一起。好的转场中间格应该是形状在变、遮罩在推、元素在匹配，不是叠化。
2. 内容有没有超出它的容器（卡片、窗口、圆角框）。
3. 相邻格是不是连续。跳变说明这一段缓动或弹簧写错了。

单帧的写法：`stills.py S02` 只写镜头号，出这个镜头 0.3、0.6、0.9 处三帧。指定时刻时，`S02@0.5` 是镜头 S02 时长的 50% 处（@ 后只能写 0~1）；`S02+1.2` 是镜头内 1.2 秒；`b12` 是第 12 拍；`12.5` 是绝对秒。第一个参数是输出名，直接写时刻列表时自动起名（`stills.py S02@0.5,S03+1.2`）。名字恰好像镜头号时按镜头号理解。每次都会先打印它怎么理解参数（如「理解为镜头号：S02，这个镜头取 0.3、0.6、0.9 处三帧」），和你的意图不同就换写法。

## 渲染前的预检

`render.py` 渲染前先做两件事，有问题就打印「哪个文件哪一行」或「哪个时刻、什么错」并停下：

- **扫镜头源码**，拦下违反合同的写法：未保护的 `Math.exp(-(t - …))`（改用 `decay()`）、`setTransform(1, 0, 0, 1, 0, 0)`（改用 `screen(ctx)` 或 `cam()`）、`Math.random()`、`Date.now()`、`performance.now()`（改用 `rng()` 和 `t`）、写在绘制函数里的 `EV()`。确有理由时在行尾写 `// lint-ok: 原因` 豁免这一行。
- **打开页面**，每 0.25 秒调用一次 `render(t)`，收集 JS 报错和 `console.error`，检查画布调用有没有 NaN 参数。画布遇到 NaN 参数不报错，只是这一笔不画，症状是「某个东西莫名其妙不见了」。

`timeline.py` 同步时发现 `web/` 下有不叫 `shots_*.js` 的脚本会提示：它不会被加载，共用代码请命名为 `shots_00_common.js` 这类。`theme.colors` 缺 `bg`、`ink`、`acc` 时它会停下，先在方案里定色调和背景。

## 版面检查

每个镜头取 0.3 / 0.6 / 0.9 处，节拍片再加每一拍。「级别」一栏是这条在报告里的位置。每条问题写明是哪句字或哪条线、取样时刻、文件行号、屏幕坐标，以及这一刻镜头变换的缩放和位移，用来判断是不是被镜头推出了画面。

| 问题 | 级别 | 判据 | 为什么 |
|---|---|---|---|
| 字太小 | 硬伤 | 观众要读的字（透明度 ≥ 0.6、非 deco），大写字母高度小于下限：宣传片短边 × 0.022（1080p 约 24 像素），讲解片短边 × 0.015（约 16 像素） | 宣传片在信息流里要一眼读完；讲解片观众有阅读时间，但再小在手机上就看不清 |
| 文字块放不下 | 可选提示 | `textBlock` 用最小字号也放不进它的框（`fits: false`）。引擎照常按最小字号画出来，体检提示这一条 | 字可能超出这块区域。真的出框、压到别的字时，出框和压字两项会报硬伤；要它待在区域里就删字、给更大的框，或拆成两句 |
| 文字出框 | 硬伤 | 离画面边缘不到 2.5%（已算上镜头变换） | 被裁掉的字，常发生在推镜头和竖版 |
| 文字互相压住 | 硬伤 | 两行外框明显相交，透明度都较高。字幕层的字不参与，单独查下一项 | 入场和退场重叠时最常见。同一段字的描边和填充算一行 |
| 画面内容进了字幕带 | 硬伤 | 字幕层开着时，非字幕的字或 `anchor()` 登记的目标压进字幕带（`__SUBS.box`）。背景、地面、底色进字幕带不报；没登记锚点的主体量不到，靠近底边时看静帧 | 字幕盖住要看的字或讲解的部位，两边都读不清。背景被推进字幕带没有问题，字幕带着底色光晕仍读得清。镜头从 `safeBox()` 分区就会自动避开；手填坐标、`fit` 超出分区或镜头推近时容易压进去 |
| 线穿过文字 | 硬伤 | 描边线段穿过别的文字外框 | 线把字划开，读起来像删除线 |
| 线的端点悬空 | 可选提示 | 开放路径的两端都没碰到任何元素。四个顶点以上的数据折线、曲线、轨迹不查端点，三个顶点的肘形引线照查 | 引线指向空处，观众不知道它连着什么；数据线的端点本来就悬空 |
| 标注没落在目标上 | 硬伤 | `callout()` 的终点不在目标锚点内，或目标这一帧不存在 | 引线指错了东西；改成从 `anchor()` 取目标 |
| 占位字 | 硬伤 | 画面文字里有「YOUR NAME」「LOGO HERE」「Lorem ipsum」「TBD」这类占位字（大小写不敏感） | 片子没做完：换成真实内容或删掉 |
| 过程标注词 | 可选提示 | 画面文字里有「示意」「EXPLAINED」「90 SECONDS」、版本号 | 时长、片型、示意、版本这类词观众多半用不上；是有意的标题设计就保留 |
| 主体偏小、留白多 | 可选提示 | 两个量都低：内容覆盖（画面分成 16 × 9 格，有内容的格子占比）和最大字高（这一刻观众要读的字里最大的字高，相对短边）。阈值按片型分，写在 `tools/layout.py` 开头。报告同时给出内容外框占安全区的比例、等比放大到约几倍可占满，以及最大的空白在哪一侧（例如「下半幅空」） | 主体可能没撑起来。留白是设计时不用管；要放大时可以参考给出的倍数，做法见 [craft.md](craft.md)「版面先分区，再放满」 |
| 同框文字推迟 | 可选提示 | 同一个镜头里，两段不同的字用 `textBlock` 画在几乎同一个框里（位置和尺寸相差不到短边的 2%），而且同时可见。引擎已把后一段推迟到前一段退完再入场，报告给出镜头、时刻和两段字 | 换句时两段字压在一起读不出。推迟会让后一句晚于配音出现：让前一段早点退，或把后一段放进另一个框 |

字号下限按画面短边成比例，是观众读得清的线。刻意的小字（水印、纹理）用 `txt()` 画并写 `deco: true`，报告会逐条列出这些豁免；观众要读的字标 deco 只是让体检看不见它。文字画在离屏画布再贴进来的（`appWindow` 里的截图文字）、直接用 `ctx.fillText` 画的字不在检查范围内，要自己看静帧。

## 动作与时间检查

- **画面抖动**（快抖是硬伤，慢晃是可选提示）。只量镜头矩阵（`cam()` 登记的变换）和全局位移（转场位移和震动），逐帧算速度。「稳」镜头里 1 秒内来回反向多次（快抖）报硬伤；几秒里慢慢来回（慢晃）只是提示，弹簧推拉的回弹、来回摇的镜头也会这样，看洋葱皮图判断是不是设计出来的；低于 0.5 px/帧的反向不计，`SHAKES` 登记的震动不算抖动。角色和物件自己的形变、弹跳、旋转、粒子不参与，放心做。标了「可以震」的镜头里，单次快抖超过 0.5 秒会作为可选提示列出：震屏一般要短促。
- **「可以震」的镜头多于全片三分之一**（可选提示）。多数片子只有一两处需要震。
- **这句话画面没有新事件**（讲解片，可选提示）。一个短句开头前 0.3 秒到后 0.6 秒内没有 `act()` 事件、没有新的字出现，成片里画面也没有明显变化，按镜头合并成一条。不要求每句都有动作；连着几句都报，多半是画面在等配音。
- **空帧**（草稿档，硬伤）。偏离全片背景板（每个像素在全片的中位数）的像素少于 1.5%，偏离这一帧主背景色的像素也少于 4%，持续 0.3 秒以上（片头片尾各 0.5 秒除外），⚠️，给出时间段和小图。常见于上一组内容退完、下一组还没进来，整屏只剩一张卡片或一根箭头。留白是设计（一句话前的停顿、落版的呼吸）时保留；否则让下一组提前进来，或让上一组晚点退。
- **静止段**（可选提示）。报告列出画面停住的段落。停住是为了让观众读完一句、消化一个结论，就保留；内容在空等，就让内容推进。不要为了消掉提示加和内容无关的运动。
- **开场空画面**（硬伤）。第一秒的取样点画面是空的：片子开头那一刻观众看到黑屏或空背景。
- **其他项。** 成片和 `target_sec` 差超 10%（硬伤）；镜头叠化（可选提示）；以及下面的成片指标。画幅由 `deliver.py` 打印，你对照需求核对。

## 成片指标（`review.py`）

体检会调用 `review.py`，也可以单独跑：

```
python3 tools/review.py                       # 默认检查 out/ 下的成片，片型按 project.json 的 genre
python3 tools/review.py out/xxx.mp4 --format 9x16 --genre promo
```

输出 `frames/_view/review_NN.jpg`（每 0.5 秒一帧，标了秒数和拍号）和 `out/review.json`。先看总览图，再看表。

| 指标 | 怎么算 | 宣传片 | 讲解片 | 不达标通常意味着 |
|---|---|---|---|---|
| 单帧跳变（硬伤） | 某一帧突变后马上恢复 | 0 | 0 | 几乎总是 bug：某个元素闪了一帧 |
| 拍点空画面（硬伤） | 每个镜头起点和每个半拍上（空拍段除外）画面上什么都没有；取样时刻先对齐到帧再去重，同一帧只报一次，附这个切点前 0.2 秒到后 0.3 秒的逐帧条 | 0 | 0 | 切点那一帧是空的：入场从这一拍才开始，弹簧在这一帧值为 0；或闪光盖掉了内容。看逐帧条找出空的那一帧 |
| 整帧被闪光刷灰（可选提示） | 背景亮度比 0.2 秒前、0.4 秒后都高出 20 以上，背景是中性灰，原来背景亮度的像素这一帧剩不到一半，连续 ≥ 2 帧，最高抬升 ≥ 30 | 0 | 0 | 全屏白色闪光把背景提亮、主体发白。见下 |
| 片中最长低变化段（可选提示） | 最长的一段连续低变化（不含结尾） | ≤ 2 秒 | ≤ 10 秒 | 某个镜头落位后就不动了；去总览图看那几秒是不是在给观众读字 |
| 结尾停留（可选提示） | 片尾连续低变化的长度 | ≤ 3 秒 | ≤ 7 秒 | 落版拖太久 |
| 响度（硬伤） | 整体 LUFS | -16 ~ -12 | -18 ~ -14 | 太小声或太吵；改 `music.lufs` |
| 真峰值（硬伤） | dBFS | ≤ -0.5 | ≤ -0.5 | 会削波 |
| 新内容中位数（可选提示） | 每个时刻与半秒前的画面差，取中位数 | ≥ 1.0 | ≥ 0.3 | 大部分时间画面没有新东西 |
| 低变化时间占比（可选提示） | 半秒内几乎没变化的时间比例 | ≤ 0.3 | ≤ 0.8 | 节奏松 |
| 画面占用率（可选提示） | 与底色明显不同的像素比例，每 0.5 秒取一帧的均值 | ≥ 0.06 | ≥ 0.05 | 主体太小，画面空 |

另外打印：1.5 秒以上的低变化段列表（逐段去总览图上看），切点落在半拍网格上的比例（与随机水平对比，明显不高于随机水平，说明画面没有卡上音乐）。

**第 0 帧被判空**时，宣传片先看 `post.fadeIn`：第一帧要有内容，缩略图和自动播放的首帧就是它。再看第一个镜头的入场是不是从 0 秒才开始。

**整帧被闪光刷灰**是 drop 上常见的问题：用全屏白色叠加做闪光，几帧里整个背景被提亮、对比塌掉，主体看不清。检测只认「中性灰背景被抬高后又回到原样」。换了场景（暗底切到浅底，抬高后不回落）、整屏铺有颜色的纯色面（品牌色擦过去），以及两块大色面各占一半的画面（推近后物件和纸面，背景色在两者之间来回认）不会报：后者原来的背景色还在，没有被刷。背景本身很亮的片子测不出来，要靠 `--between` 看。报出时刻后看那几帧：只有 1–2 帧、主体仍然清楚的有意闪白可以保留；主体被洗淡、灰底持续好几帧，就改用 `FLASH` 的默认 `light` 模式（只提亮内容，黑底不变），或缩短衰减、只给主体加光晕。

阈值的依据：宣传片来自热门原片，原片中位数 1.4–24、最长低变化段 0–4 秒、占用率 0.07–0.27。讲解片来自 5–10 分钟的配音片，最长低变化段约 12 秒（引语页）。闪光刷灰用热门原片和高质量成片校准：被刷灰的失败样本全部能报出；做得好的片子里，真正的闪白帧（主体仍然清楚）也会被报，所以它只是提示。

## 正式档检查

**正式档重影**（硬伤，❌）。`render.py --final` 渲完，把正式档和草稿档缩到同一尺寸逐帧比：正式档里出现、草稿档同一位置（放宽 2 像素）没有的清晰边缘多，连续 2 帧以上，而且画面在动。报告给出时间段和一张并排图（左正式档、右草稿档）。

为什么：运动模糊在快门内取几个子帧平均。位移大而采样少时，每个子帧各留下一份清晰的图像，快速平移、滚动转场、横向滑入的文字就变成 2–6 份错开的副本，读不出来。草稿档不开模糊，看不到这类问题。引擎会按画面变化自动加采样，仍报重影时，用 `FAST.push([t0, t1, 32])` 给这一段指定更高的下限，或调大 `motion_blur.max`，再重渲这一段（`render.py --final 起 止`）。

比对只在草稿档和当前代码一致时进行：草稿档早于最近一次改的镜头文件、`project.json` 或 `timeline.json` 时，打印「跳过比对」，不报错。所以全部改完先渲一次草稿档，再出正式档。

## 成片事实与交付核对：`deliver.py`

`render.py --final` 结束时自动运行，也可以单独跑 `python3 tools/deliver.py`。它读 `out/` 下每个画幅的成片，打印：时长、画幅、帧率；音轨的有无、时长和响度；字幕是否烧录、哪几种语言、有没有 SRT 和条数；画面文字的语言（引擎登记的文字里含中文的、只有英文的各多少条）。然后把 `storyboard.md` 里的硬约束清单逐条抄进 `out/交付核对.md`，每条后面留空，由你填「做到了，在第几秒」或「没做到，原因」。

填的依据是这些成片事实和成片的静帧。为什么不看工程文件：文件在不等于观众看得到。用户要「中英双语字幕」，`deliver.py` 打印「字幕：没有烧录」就是没做到；用户要「全英文画面」，画面文字里还有中文条目就是没做到。

## 读总览图

按顺序看这几件事：

1. **主体大小和留白。** 主体有没有放满它的分区；缩略图上看不清主体在哪，成片里也一样。
2. **颜色。** 色调和方案里定的一致吗？含义色有没有被挪作他用？
3. **相邻格子有没有区别。** 连续几格几乎一样，就是一段静止。先问停住有没有理由；宣传片里几乎总要改。
4. **转场处。** 总览看不到转场中间，转场用 `stills.py --cuts` 看。
5. **拍号**（节拍片）。drop 的那一拍应该是全片最强的画面；拍号整数处应该能看出动作的落点。
6. **最后几格。** 落版或收尾画面是否完整：logo、名字、网址、回答片头问题的那一句都在，没有被裁切。

草稿档是半尺寸、没有运动模糊。卡顿、拖影、小字清不清楚，要在正式档或 `render.py --final 起 止` 渲的片段上看。

## 第一版之后改什么

体检没有硬伤只说明没有明显问题。第一版渲完后，按片型手册的质量标准（讲解片见 [explainer.md](explainer.md) 第十一节，宣传片见 [promo.md](promo.md) 第六节）写下最弱的几处，和硬伤一起改掉，再渲一次。常见的修改：

| 现象 | 改法 |
|---|---|
| 某个镜头落位后不动 | 先问停住有没有理由（读字、消化、听清一句）。没有理由就让内容推进：把下一步提前、把镜头缩短；宣传片里加有含义的二次动作（数字滚动、光标点击、高光扫过主体） |
| 画面空、主体小 | 可以参考报告给的放大倍数。先分区，主体用 `fit` 或 `prop()` 放满它的区域，`fill` 调到 0.9 以上；字用 `textBlock` 放进更大的框；截图改成透视卡片并推近；讲解片里让物件本身更大、零件更多 |
| 字太小、文字块放不下 | 给 `textBlock` 更大的框，或删字、拆成两屏；不要标 deco 绕过 |
| 话和动作对不上 | 按短句给画面事件（[explainer.md](explainer.md)「分镜到短句」），时刻写 `ph(id, k)` |
| 引线、图钉指不准 | 目标用 `anchor()` 登记，引线用 `callout()`，数值标记用 `pin()`，不手填终点坐标 |
| 转场是淡化或横推 | 改成匹配剪辑、铺满再收缩、甩镜头、变形（见 promo.md 第二节） |
| drop 没力量 | drop 前加半拍空拍；drop 那一拍加砸字、震动、底鼓缩放，闪光只提亮主体，不要整屏刷白 |
| 结尾拖 | 落版动作做完后停 1.5–2.5 秒就结束 |
| 空帧 | 让下一组内容提前进来、上一组晚点退，或让同一个物件留在画面上承接 |
| 拍点空画面 | 打开报告附的逐帧条，确认切点那一帧是空的。让下一个镜头提前入场（加 `pre`，或用 `enter()` 提前起手），或让上一个镜头晚点退场（加 `post`）；加字、放大主体消不掉这一帧 |
| 画面内容进了字幕带 | 让镜头从 `safeBox()` 分区，不手填靠近底边的坐标。推近时让主体和画面里的字留在字幕带上方：推近的对准点选在要讲的部位偏下一点，背景进字幕带不用管；用 `stills.py` 看推得最近的那一帧 |
| 正式档重影 | 这一段用 `FAST` 提高采样下限，或调大 `motion_blur.max`，只重渲这一段正式档 |
| 单帧跳变 | 用 `stills.py` 在跳变时刻前后各取一帧，找出闪烁的元素（常见原因：某个镜头的绘制范围在那一帧刚好结束或开始，或 `prog` 的起止写反） |

改了画面就重跑 `render.py`：只有改过的镜头所在的段会重渲，其余复用。只改了声音时，网页代码没变，所有分段都复用，只重新混入音轨。全部改完先渲一次草稿档，再用 `--final` 出一次正式档，正式档的重影比对要用到这份草稿档。
