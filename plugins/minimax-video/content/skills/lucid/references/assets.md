# 真实素材：截图、logo、品牌色、视频帧

工具：`python3 tools/assets.py <子命令>`。产物直接落进 `web/img/`，`project.json` 的 `assets.images` 写 `"auto"` 就能用 `img(ctx, '名字', ...)`，不用再配置。

## 什么时候需要

用户点名要真实产品、真实品牌、真实界面，或片子讲的是一个现成的产品和网站：先拿素材再设计。观众认得出的东西（logo、界面、品牌色、字体）用真的，比画得再好的仿制品更可信，也省掉猜色值的时间。纯概念、抽象的片子不需要。

## 拿素材的顺序

1. `brand <url>`：logo、品牌色、字体，写入 `assets/brand.json`，并打印可直接粘进 `project.json` 的 `theme`。先拿它，因为配色和字体决定整片的设计。
2. `shot <url>`（要界面）或 `images <url>`（要产品图）：
   - `shot` 出首屏图和整页长图，自动清掉 Cookie、订阅弹窗、聊天浮窗，并滚动触发懒加载。工具先找出真正在滚动的元素：很多单页应用的 body 不滚动，内容在内部容器里，甚至在一个看起来像弹窗的浮层里（TypingMind 官网就是这样，13000 像素的官网内容全在浮层里，关掉浮层后看到的是后面的应用）。这类页面工具会在关弹窗之前先把容器长图截好，存成 `_full`（或 `_overlay_full`），终端会说明。
   - `images` 下载页面里引用的原尺寸大图，也是从头滚到底之后才收集，懒加载的功能卡片图都在。官网产品图常比截图清楚，优先用。
3. 要推近的局部用 `zoom <url> <名字> <选择器> ...`：先滚到元素、等里面的图加载完，再单独按 3 倍像素比截。底图 2 倍推到 3 到 4 倍字会糊，高清局部不会。选择器写 CSS，或写 `text=某某文字`。找不到时终端会说明匹配到几个元素、页面上有哪些相近的文字，照着改选择器；元素本身是个图片（功能卡里的界面图）时直接用 `images` 更省事。
4. 需要时 `prep` 处理单张图，`frames` 把视频拆成序列帧。用户给了参考视频时，先用 `tools/refsheet.py` 拆解，见「参考视频」一节。
5. `sheet`：生成 `frames/_view/assets_sheet.jpg`，看一遍再设计。弹窗没清干净、图是白屏、logo 底色不对，在这里发现比渲完整片再发现便宜得多。

交付时把 `assets/manifest.json` 里的来源（URL、时间、文件）整理给用户，说明哪些是官网原图，哪些是截图。

## 各命令要点

| 命令 | 产物 | 说明 |
|---|---|---|
| `shot <url> [名字]` | `<名字>.jpg`（首屏）、`<名字>_full.jpg`（整页或内部滚动容器的长图，最多 6000 CSS 像素高） | `--mobile` 用 390×844 视口；`--dark` 偏好深色；`--width/--height/--dpr` 自定义；页面不比首屏长时不出 `_full` |
| `zoom <url> <名字> <选择器>...` | 底图同 shot，加 `<名字>_z1.png`…（`--tag a,b` 改成 `<名字>_a`） | 终端打印每个局部在哪张底图（首屏图、`_full` 长图）里的归一化矩形，目标在长图里时矩形相对 `_full`；`--zdpr 3` 调像素比；`--pad 12` 多留边 |
| `brand <url> [名字]` | `<名字>_logo.png`（含文字的 logo，透明底）、`<名字>_mark.png`（只有图形的标记，透明底）、`_icon.png`（带底板的 App 图标）、`_og.jpg`、`assets/brand.json` | SVG 由浏览器渲染成透明底大图，不用正则抠；位图 logo 直接下载原文件。`_mark` 用于「logo 切碎再拼回」「巨大 logo 做背景」这类镜头，来源和是否可靠记在 `brand.json` 的 `mark` 里（见下） |
| `images <url> [名字]` | `assets/raw/` 全部原图，`web/img/<名字>_img_*` 排在前面的 12 张 | 产品大图排前，图标、徽章、客户 logo 降权；`--match "landing-page/(use|using)"` 按地址正则挑，`--max` 调数量；`--min-size 400` 过滤图标；Next.js 的 `/_next/image?url=` 会还原成原图地址 |
| `frames <视频> [名字]` | `web/img/<名字>/0001.jpg…` | `--fps 30 --start 2 --end 6 --width 1280` |
| `prep <图片> [名字]` | `web/img/<名字>.png/.jpg` | `--max 2400` 长边；`--key` 去纯色底；`--trim` 裁透明边；`--round 0.225` 给方形 App 图标做圆角；`--exposure 1.4` 提亮（倍数，默认 1）；`--contrast 1.2` 加对比（围绕中灰，默认 1；大于 1 暗部更暗，只用于发灰的图），透明度保留 |
| `sheet` | `frames/_view/assets_sheet.jpg`（超过 20 项自动分页） | 透明图画在棋盘格上，顶部显示品牌色 |

**`_mark.png` 怎么来的。** 按优先级取：页头指向首页的链接里的内联 `<svg>`（图形和文字连在一起时，按间隔把最左或最上的图形分出来）；`<link rel=icon type=image/svg+xml>`、`mask-icon`；最后是位图图标（apple-touch-icon 等），从四边泛洪去掉纯色底板和圆角底板。统一输出长边不超过 1024 像素、透明底、裁掉空白。`brand.json` 的 `mark` 记录 `source`（来源）、`reliable`（是否可靠）和 `note`。`reliable: false` 的情况：图形和文字分不开（输出的是整个 logo）、位图带渐变底板没去掉。这时在 `sheet` 总览里看这张图，不对就用 `prep` 手工处理，或自己画。位图来源的 mark 受原图尺寸限制，放大到很大会糊，`note` 会提示。

**所有开浏览器的命令**（shot、zoom、brand、images、prep 处理 svg）都有总时限，默认 120 秒，`--timeout 秒` 调整。整机同时开很多 Chrome 时 Playwright 的启动和关闭会卡住：Chrome 启动超过 35 秒自动杀掉重试（最多 3 次）；产物写盘后直接按临时目录杀 Chrome，不等它正常退出；到总时限还没完，打印卡在哪一步和已写盘的产物后退出（返回码 3）。产物齐全就直接用，不齐全错开时间重跑，不要同时跑很多个。

清不掉的遮挡：`--hide "选择器"`（直接隐藏）或 `--click "按钮文字"`，工具会在终端列出它点击和隐藏了哪些元素，对照总览确认。

## 在画面里用

**整张图**：`img(ctx, '名字', x, y, w, h, {fit:'cover', r:24, shadow:1})`。截图用 `cover` 铺满圆角卡片，logo 用 `contain` 保持比例。圆角加投影让截图从背景里浮出来，贴边的方形截图看起来像素材而不是设计。

**只取一部分**：`o.src = [sx, sy, sw, sh]`（源图像素）。整页长图用它做「向下滚动」：随时间移动 `sy`，不用动画整张大图。

**推近时叠高清局部**。底图画一次，高清局部用同样的位置再画一次，推近镜头里字依然清楚：

```js
// zoom 打印：rect [x,y,w,h] = [0.25694, 0.88444, 0.52083, 0.04889]
img(ctx, 'typingmind', X, Y, W, H, {fit:'fill', r:20});                         // 底图
img(ctx, 'typingmind_input', X + 0.25694*W, Y + 0.88444*H, 0.52083*W, 0.04889*H, {fit:'fill'}); // 高清局部
```

底图和高清局部取自同一次运行，所以位置对得上；换了视口宽度或重新 `shot` 后要重新 `zoom`。高清局部与底图是同一页面的同一状态，叠上去没有位置偏差（平均像素差约 0.6/255）。

**透视卡片**：用 `GL3D.card`，`sub` 是把整张 `img` 贴到卡片的这块子区域，用法与上面一致：

```js
GL3D.card(ctx, {img:'typingmind', x, y, w:W, h:H, rx:-8, ry:14, r:20});
GL3D.card(ctx, {img:'typingmind_input', x, y, w:W, h:H, rx:-8, ry:14, r:20, sub:[0.25694, 0.88444, 0.77777, 0.93333]}); // zoom 打印的 sub
```

**序列帧**：`frames` 拆出的视频用 `seqFrame('名字', lt, fps, loop)` 取帧，再交给 `img()`。解码后帧都在内存里：1280×720 约 3.7 MB 一帧，几百帧会拖慢加载，所以只拆需要的片段，并降 `--fps` 或 `--width`。

**logo 和品牌色**：logo 是透明底 PNG，可以直接放在任何背景上。白色 logo（深色网站常见）放浅色背景会看不见，总览里的棋盘格能提前发现。`brand` 给出的 `acc` 是主强调色，大面积用 `bg` 和 `ink`，`acc` 只做点缀，片子才像这个品牌。

## 常见失败与替代来源

| 现象 | 原因 | 处理 |
|---|---|---|
| 终端提示「几乎是纯色」 | 白屏、被反爬、需要登录、加载慢 | `--wait 8` 重试；仍然不行换来源 |
| 提示反爬或被跳转到登录页 | 站点拦截自动化浏览器或要求登录 | 换来源，不要硬刷 |
| 弹窗清不掉或误清 | 弹窗不是标准写法 | 看终端的处理记录，用 `--hide` 或 `--click` 补 |
| 整页长图被截断 | 超过 6000 CSS 像素 | `--full-max` 调大；通常只需要首屏和几个局部 |
| zoom 目标超时或没命中 | 选择器不准，或内容是懒加载、在浮层里 | 看终端列出的相近文字改选择器；功能图直接 `images` 下载原图 |
| 位图 logo 带底色 | 官网只给了位图 | 底色是纯色用 `prep --key`；满版方形图标不去底，用 `--round 0.225` |
| 深色产品截图放在深色舞台上看不见 | Linear、Notion 深色、Vercel 这类截图本身接近舞台底色 | `prep 图片 名字 --exposure 1.4`；还不够就加到 1.6，或给截图加浅色描边和投影让它从背景里浮出来。`--contrast` 围绕中灰，大于 1 会让暗部更暗，只适合发灰的图 |
| 命令超时，终端写着「超过 N 秒总时限」 | 整机同时开的 Chrome 太多，或站点太慢 | 看打印的已写盘产物；不齐全就错开时间重跑，或 `--timeout 240` |
| 页面字体不在模板里 | 网络字体 | `brand` 会列出字体文件地址；下载放进 `web/fonts/` 并写 `theme.font_files`，否则退回系统字体 |

反爬或需要登录时的替代来源：产品官网的 press / media kit 页、App Store 或 Google Play 的商店截图、官方博客和 changelog 的配图、官方 GitHub 仓库的 docs 与 README 图片。这些图是官方发布给外界使用的，版权和清晰度也更稳。

## 参考视频

用户给了一支参考视频，要「做成这种感觉」时，先拆解再动手：`python3 tools/refsheet.py <视频> [名字]`。它省掉自己写切点检测和总览图的时间，输出：

- `frames/_view/ref_<名字>_cuts.jpg`：每段一行，首、中、尾三帧，标出起止时刻和时长。
- `frames/_view/ref_<名字>_t1.jpg`…：每 0.1 秒一帧，按时间排。红框是硬切，橙框是版面里的变化点（换词、换数字、元素进场）。
- `assets/ref.json`：画幅、帧率、BPM、硬切表、分段、变化点、形态变化点、节奏统计。
- 终端：硬切数、段长中位、变化点间隔（和 BPM 换算成拍数）。

看什么：

1. **每段多长，变化点多密。** 快剪字幕片的节奏常在版面内部：同一个版面里每 0.25 秒换一个词，整片只有一两次硬切。只看硬切数会误判成「没有节奏」。变化点间隔换算成拍数，就知道它是不是踩着音乐。
2. **字体和字号关系。** 主词多大，副词多大，字重差多少。到 `_t` 总览里量，不要凭印象。
3. **转场手法。** 硬切、遮罩推入、模糊变形、整屏闪白。`_t` 里看切点前后各一两格。
4. **形态变化点。** 连续变形的片子（按钮变播放器变开关）没有硬切，终端的「形态变化点」列出每个形态换的时刻，用来拆镜头。
5. **留白和停留。** 最后一个画面停多久，每个信息出现后读多久。

不检出的东西：渐变转场、闪白、淡入淡出不是硬切，要从 `_t` 总览里看。检出太少或太多时调 `--thresh`（硬切，默认 8）和 `--ev-thresh`（变化点，默认 4）。

**借手法，不照抄设计。** 参考片告诉你节奏密度、转场类型、信息的组织方式。版式、配色、文字内容用用户自己的主题重新设计，不要复刻参考片的画面。

只读 `frames/_view/` 里缩小后的 JPEG。`web/img/` 里的整页图可能有 12000 像素高，直接读进对话会撑爆请求。
