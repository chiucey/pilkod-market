# 画面手艺：常见做法和它们解决的问题

这里收的是做讲解片和动效片时反复用到的做法。每条写它解决什么问题、怎么用、怎么看出用对了。它们是可选的参考：你有更合适这支片子的设计，就按你的设计做。体检报出「主体偏小」「留白多」，或成片看不懂、显得平淡时，回来查对应的一条。

文中的函数（`split`、`fit`、`prop`、`textBlock`、`act` 等）来自模板的工具库，签名见 [engine.md](engine.md)。不用模板函数时，做法本身照样适用。

## 一、让一个具体的物件或故事来讲

观众认得一个东西，就看得懂它的运作。常见做法是找一个观众认得的物件、场景或故事，让它的运作就是要讲的概念：概念的每一步，对应物件的一个动作。

| 要讲的 | 物件或故事 | 动作说明了什么 |
|---|---|---|
| 复利 | 一个滚下坡的雪球 | 每滚一圈沾上的雪都比上一圈多，越往后长得越快 |
| 网络丢包后重传 | 寄挂号信 | 没等到回执，就再寄一封同样的信 |
| 疫苗让身体记住病毒 | 城门卫兵拿到一张通缉照片 | 真的坏人来了，卫兵一眼认出，立刻拦下 |

它解决两种常见的失败：**太抽象**，方框、箭头、标签堆在一起，观众要先读懂图例才看得懂图；**太单薄**，一张图表配一行字，画面上没有可以看、可以发现的东西。

物件从这几处找：观众天天见的东西（门锁、快递、雪球、厨房）；题材自带的实物（真实的界面、数据、零件）；一个人或一件东西的一段旅程（一件包裹、一笔钱、一封信）。好用的物件同时满足四点：

- 目标观众不用先学就认得。题材从业者熟悉的东西（交易盘口、终端、论文图）对新手不算认得。
- 它的运作和概念一一对应，没有多余的动作。多出来的动作会让观众学错。
- 能贯穿全片。每章换一套画面，观众每章都要重新认。
- 有能动的零件。

物件世界只是一种画法。图解、数据新闻、动态排版、editorial 版式、角色故事都能讲清楚一件事，按题材和观众选。宣传片和动效片里，贯穿全片的主角元素（一个圆点、一张卡片、logo 的形状）起同样的作用。

怎么看出用对了：关掉声音只看画面，观众能说出「这个东西在做什么」。

## 二、动作就是逻辑

每个动作对应论证的一步，或故事里的一件事：数量变多就让东西一个个出现，交换就让东西从一方移到另一方，变快就让数字跳得更快。动作的先后、快慢、方向都是信息。

它解决的问题：观众把画面上的每个变化都当成信息。和内容无关的运动（飘过的柔影、扫过的光带、空转的粒子）会让他去猜含义，或者分心。停住也可以有理由：让观众读完一句、消化一个结论、听清一句原话。

需求点名的风格或氛围（未来感、电影感、可爱）也是内容。兑现它的光、粒子、纵深要做足，手法见 [promo.md](promo.md)「点名的风格」。扁平图形加平移淡入，内容讲对了，风格仍没兑现。

用模板时，每个动作用 `act()` 登记成一个画面事件，名字写这个动作说明的事；讲解片里一个短句对应一个事件，动作从这句话开始，时长默认从这句话的长短算。体检的对齐图会把短句和事件画在一起。

怎么看出用对了：对每个动作问「它在说什么」或「它在兑现哪个风格要求」，都答得出。

## 三、一份数据驱动所有数字、位置和动作

先把要讲的东西写成一份数据（数组、对象、只依赖 t 的函数）。图表、数值标签、元素的个数、引线的终点、动作的时刻都从它算出来。模板里图表用 `chartScale()`；要指向一个东西，先用 `anchor()` 登记它，再用 `callout()` 画引线、用 `pin()` 按数值标记，终点由目标算出。

它解决的问题：观众会拿标签上的数去对画面。手填的坐标在目标一动、数据一改时就脱节，「168 的柱子比 132 的矮」「引线指向空处」一眼就是错的。

怎么看出用对了：改一个数据，画面上相关的东西一起变。

## 四、版面先分区，再放满

用 `split`、`grid` 把 `safeBox()` 分成几块，每块放一样东西。主体按自己的自然尺寸画，用 `fit`（主角物件用 `prop()`）放满分到的区域；字用 `textBlock` 放进分到的框，字号由框的大小和字数决定。竖版、方形时换分区方向（`PORTRAIT ? 'col' : 'row'`），镜头代码不用改。

它解决的问题：手填坐标是主体偏小、留白多、字小的常见来源。每个坐标都是一次决定，偏保守的决定累积起来，画面就空了。分区按 `W`、`H` 计算，同一套镜头在每种画幅下都放得满。一个镜头的内容只占上半幅、下半幅整片空白，是讲解片最常见的版面问题。

可以作为起点的参数（按片子调整）：讲解片的主体区约占安全区的六成以上，单主体镜头 `fit` 的 `fill` 取 0.85–1；宣传片的主体至少占画面高度的三分之一，一个镜头只有一个主体时外形占画面高或宽的一半以上。留白本身是设计时（一句话前的停顿、落版的呼吸、编辑式版面的大片空白），按设计来。

同类内容用同一个版式：六个产品的介绍用同一套布局，只换内容。版式写成函数放进 `web/shots_00_kit.js`，函数接收一个矩形，内部再分区。

怎么看出用对了：总览图上主体占满它的分区，分区之间没有空着的一大片。体检的「主体偏小、留白多」提示会给出放大倍数，可以参考。

## 五、版式按片子定

背景、框架、版面分布（纸面、章节标记、进度条、页眉页脚）由这支片子需要什么决定。物件世界的片子，画面就是那个世界；长片、多章节才可能需要章节标记和进度条。讲解片可选的版式方向见 [explainer.md](explainer.md)「版式方向」。

它解决的问题：同一套版式套在不同题材上，片子千篇一律，框架还挤占主体的位置。

怎么看出用对了：每一样框架元素都说得出观众拿它做什么。

## 六、骨架先出，内容跟上

空框、坐标轴、连线、章节标题这类骨架可以比内容早出现，常见做法是早 0.3–0.8 秒，之后内容填进来。

它解决的问题：骨架先到，观众先看见结构；空框停久了，观众在等，画面像卡住。

怎么看出用对了：静帧里出现空容器时，看它之后不到一秒的那一帧有没有内容。

## 七、字读得清，不压字，不出画

成段的字、标题、标签用 `textBlock` 放进分到的框，它自动断行（中文避头尾）、自动取放得下的最大字号。单个短词用 `txt()`（或 `riseLine`、`typeOn` 等函数）。字放在安全区里（四边各留短边的 5%）；镜头推近、漂移用 `drift()`，它会自动收紧。刻意的小字（水印、纹理）用 `txt()` 画并标 `deco: true`。

它解决的问题：手动定字号、手动断行，字常常偏小或出框；压在一起、被切掉、太小的字读不出来。经过这些函数画的字会自动断行、定字号；直接 `ctx.fillText` 画的字体检照样量字号、出框和压字，但断行和字号要自己定。

怎么看出用对了：体检没有出框、压字、字太小。`textBlock` 用最小字号也放不下时，删字、拆成两屏，或给它更大的框。

## 八、镜头稳，物件自由

讲解、数据、图表、平滑转场的镜头运动常用慢而顺的做法：一个镜头里最多换一次方向，浮动周期不短于 2.5 秒，不用高频噪声和每帧随机位移。震屏留给撞击、惊喜、重拍，用 `SHAKES` 登记，0.5 秒内衰减完；多数片子只有一两处需要震。角色和物件自己的动作（弹跳、压扁拉伸、形变、旋转）不受影响，按内容需要做足。

它解决的问题：没有来由的镜头小晃像画面坏了；有来由、短促的震动是表现手法；物件的动作是内容本身。

用模板时，每个镜头在 `project.json` 的 `timeline.shots` 里标 `"motion": "稳"`（默认）或 `"可以震"`，体检只在「稳」镜头里量镜头矩阵和全局位移的抖动。

## 九、主角物件先单独画大，检查过再进镜头

主角物件为这支片子专门画，按自然尺寸写成 `PROP.名字`。进镜头之前用 `stills.py --props` 画成大图检查：部件相接、比例对、线宽统一、轮廓清楚、表情和姿态读得出。检查过再用 `prop(ctx, '名字', box)` 放进镜头分区，全片复用这一份。

它解决的问题：镜头里的物件往往很小，腿没接上、线宽不一这类结构错误要放大才看得出。物件画对一次，每个镜头都对；同一个角色在每个镜头里样子一致。

怎么看出用对了：物件表上每个物件都像一张完成的插画。

## 十、画面只放观众需要的内容

对需求的回应（「90 秒」「讲解」、风格名）、制作过程的标注（「示意」「草稿」、版本号）和占位字（「YOUR NAME」「LOGO HERE」）不上画面。示意数据的说明写进交付说明；真实数据可以标来源。

它解决的问题：这些字是写给委托人的，观众用不上，还会让画面看起来没做完。

怎么看出用对了：遮住这行字，观众什么都没少知道，就删。体检会报出常见的过程标注词和占位字。

## 十一、配色从场景推

模板和引擎不带任何颜色，`theme.colors` 要写 `bg`、`ink`、`acc`。一个可靠的定法是先写出画面里的具体场景（面包店、纸面笔记、夜空），再按三件事定：这个场景本身是什么颜色；观众是谁；在哪里播放（手机信息流里亮底和高对比更醒目，投影和大屏上深底不刺眼）。

| 选定的场景 | 能成立的选择 | 理由 |
|---|---|---|
| 面包店、厨房、教室 | 暖白或浅木色底，物件用饱和的暖色 | 场景本身在亮处，颜色是观众见过的 |
| 纸面笔记、账本、图纸 | 纸白或浅灰网格底，墨色线条，一两个标记色 | 纸的语言 |
| 夜空、深海、夜里的城市 | 深色底，亮色是星光、灯光 | 场景本身在暗处 |
| 儿童动画的角色世界 | 明亮、饱和的浅底，角色用纯色块 | 小观众靠颜色认角色，暗底让画面沉闷 |
| 产品的真实界面 | 品牌自己的底色和强调色（`assets.py brand`） | 观众认得品牌色 |

颜色有固定的含义时，全片不变：第一章的红色是「病毒」，最后一章的红色也只能是「病毒」。观众靠这些含义读画面，换了含义他就要重新学。

它解决的问题：「科技题材用深色」这类默认答案会让所有片子长成一个样子。颜色和物件一起决定观众看到的是什么世界。

怎么看出用对了：说得出这个底色在画面的世界里是什么（面包店的墙、笔记的纸、夜空）。「技术」「数据流」「金融」只是题材的泛称，说不出具体场景。

## 十二、常见的失败和改法

| 看到什么 | 为什么不行 | 改法 |
|---|---|---|
| **太抽象。** 讲疫苗时画三个圆角框「抗原 → B 细胞 → 记忆细胞」，用箭头连起来 | 观众只看到三个词，不知道它们长什么样、做了什么 | 换成照片、卫兵、档案室，每个箭头换成一个动作 |
| **太单薄。** 讲复利时一条指数曲线从左往右长出来，配一行「越往后越快」 | 曲线是对的，但画面上没有可以发现的东西，听一句话就够了 | 用雪球滚下坡，每一圈沾上的雪分层显示，角落的数字跟着长；曲线最后出现，作为雪球轨迹的总结 |
| **每章换一套画面。** 网格、曲线、柱图、地图轮流出现，彼此没有同一个主角 | 观众每一章都要重新认画面，章与章之间连不起来 | 一个物件或一套版式贯穿全片，每章是它的下一步 |
| **为了动而动。** 画面停住时加一层飘过的灰色柔影、一道扫过的光带 | 观众会以为它有含义，或者觉得画面脏 | 先问停住有没有理由：观众在读、在消化，就保留；内容在空等，就把下一步提前 |
| **念稿。** 一个镜头三句话，画面只有一段字逐行淡入 | 画面在复述配音，观众听就够了，看不到任何运作 | 按短句给画面一个动作；字只留关键词 |
| **小而空。** 物件画在画面中央一小块，四周大片底色，字号偏小 | 观众看不清零件和变化，缩略图里是一片空 | 先分区，物件放满主体区，字放进旁边的框 |
| **过程标注上画面。** 右上角写「90 SECONDS / EXPLAINED」，图表角落写「示意」 | 这是在回应需求、说明制作过程，观众用不上 | 删掉；示意数据写进交付说明 |
