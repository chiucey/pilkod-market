# Lucid · Your Explainer Studio（v3.1）

目的是帮观众尽快、真正看懂一件事：原理、流程、数据、一份文档、一段代码、一段历史，也可以是给小朋友的动画。产品宣传片、发布片、作品集动效片、UI 动效循环也做，这时目的是让观众记住一句话。

画面是网页里的 `render(t)`，每一帧只由时间 t 算出；声音按同一条时间轴合成；`render.py` 逐帧截图后编码成 MP4。所以结果可复现，可以只重渲一个镜头，音画天然同步。

开工时把本 Skill 的 `template/` 整个复制到用户工作区（例如 `video/`），在副本里做，不改 Skill 目录。下面的命令都在副本的根目录运行。

## 交付约定

用户拿到成片时会检查这几件事，每支片子都做到。

1. **先按需求的原话定片型。** 需求要讲清楚一件事（原理、流程、知识点、数据、文档、历史），或提到讲解、教学、旁白、配音，就是讲解片。需求只说动效、motion graphics、宣传、发布、showreel、品牌短片、UI 循环，没提讲解和旁白，就是无旁白短片。按原话判断，不按题材判断：讲相机历史的动效片仍是动效片。为什么：短片需求做成讲解片，会变长、变慢，用户要的冲击力就没了。
2. **成片是 MP4**，在 `out/` 下，只交一份。用户要单页 HTML 或网页动画时，HTML 和 MP4 一起交。
3. **讲解片默认有配音，无旁白短片不配音。** 无旁白短片用配乐、音效和画面文字。中文片默认 `Chinese (Mandarin)_Gentleman`（温润男声），英文片默认 `English_Trustworthy_Man`，没写音色时 `tts.py` 按稿子的语言选；只在另一个声音明显更合适时才换（儿童片、需求点名了语气或性别）。为什么：讲解片的观众靠听理解，只靠读画面上的字跟不上。见 [explainer.md](explainer.md)「选音色」。
4. **语言跟着需求。** 配音、字幕、画面文字默认用用户写需求的语言；用户点名语言或要双语时照办。
5. **要字幕就烧录进成片**，同时出 SRT。有 SRT 文件不等于观众看得到字幕。
6. **画幅和时长按用户说的做。** 没说画幅时出横版 16:9。没说时长时，讲解片由配音决定，无旁白短片做到 15–60 秒。
7. **交付前核对成片事实。** `render.py --final` 结束时运行 `deliver.py`：打印成片事实（时长、画幅、音轨、配音、字幕和画面文字的语言），把硬约束清单写进 `out/交付核对.md`。需求里的每个名字、数字、事实各写一条，逐条填「做到了，在第几秒」或「没做到，原因」，依据只用成片事实和静帧。
8. **交付说明**写示意数据、假设、已知的小问题，换了默认音色时写理由。如实写检查方式：你看的是静帧、总览图、波形、响度和转写，不说「看过」「听过」。

需求说清楚的、你能自己定的，不问。只在缺少拿不到的素材时问（用户自己的截图、logo、指定的歌、本地代码的位置），一次问完。从开工一直做到交出 MP4，中途不停下来确认方案。

## 三条原则

1. **先想清楚观众看完要能回答什么。** 用观众的话列出他看完要能回答的几个问题和答案要点：需求点名的概念每个至少一题，题材的核心因果链（一步怎么引起下一步）至少一题。宣传片换成观众要记住的几条信息。清单放在脑子里或写下来都可以。
   为什么：观众看懂是讲解片的成功标准。题目讲窄、漏讲，动手前就查得出；到成片才发现，要重做。
   怎么判断：只读配音稿，每题都找得到回答它的那几句；宣传片的每条信息，成片静帧里都找得到。
2. **比喻讲完回到真实机制，事实要对。** 比喻只换外形，不改机制：物件的每个动作对应一个真实发生的环节。比喻讲完，用一句配音或一个镜头说出真实名称和真实机制，点明比喻和真实不一样的地方（尺度、力从哪里来）。数字、先后、引文和一手材料一致。
   为什么：观众会照着比喻推想真实的东西，比喻没覆盖的部分他会猜错。一个数字错了，整片都不可信。
   怎么判断：拿掉比喻，稿子里仍有一句讲清真实机制；每个数字说得出来源，示意数字在配音里说明是假设。
3. **画面和配音说同一件事。** 说到一个东西时，画面上正好出现它，或者它正在动。画面上的字是配音的关键词，配音把逻辑说全。无旁白的片子换成画面和音乐的拍子：动作落在拍上。
   为什么：观众同时听和看。两边讲不同的东西，他只能顾一边；画面早于或晚于话，他要自己对时间。
   怎么判断：讲解片看体检的 `对齐.jpg`，每个短句开头附近画面有变化；字幕和配音的文字一致。

## 工具

`template/` 是一套可选的工具库：时间轴（节拍、手写时刻、配音驱动）、配音对齐（`ph(id, k)` 是第 k 个短句的时刻）、字幕层、运动模糊、文字块、版面函数、图表和标注。可以用它，也可以在镜头里用自己的方式画。出片走 `render.py`，过体检。函数和 `project.json` 的配置见 [engine.md](engine.md)。

| 命令 | 用途 |
|---|---|
| `python3 tools/timeline.py [--estimate]` | 把 `project.json` 同步到网页，打印每个镜头的起止；配音前用 `--estimate` 按音节估时 |
| `python3 tools/tts.py voices`、`tts.py audition "<一句话>" <音色1> <音色2>` | 换音色时列出候选；同一句话试读几个音色，打印时长和转写 |
| `python3 tools/tts.py full v1` | 整段合成配音并转写，打印和稿子对不上的名字、数字、英文词 |
| `python3 tools/stills.py S03` | 不渲整片，看一个镜头的静帧；`--cuts` 看转场逐帧，`--props` 看物件表 |
| `python3 tools/dump_events.py && python3 audio/synth.py` | 导出音效事件，合成声音。`render.py` 会在需要时自动跑这两步和 `timeline.py` |
| `python3 tools/render.py` | 草稿档 `out/<名字>_draft.mp4`：预检、增量渲染、体检 |
| `python3 tools/render.py --final` | 正式档 `out/<名字>.mp4`：运动模糊、重影比对，然后运行 `deliver.py` |
| `python3 tools/checkup.py` | 不重渲，单独重跑体检 |
| `python3 tools/deliver.py` | 成片事实和 `out/交付核对.md` |
| `python3 tools/assets.py <子命令>` | 网页截图、logo、品牌色、产品图、视频帧 |
| `python3 tools/srt.py` | 字幕文件 |

**体检分两级。** 硬伤是观众看得见、听得见的错：出框、压字、字太小、重影、开场或中途空帧、跳帧、时长不符。硬伤都要改。字幕和配音不一致由 `timeline.py` 和 `tts.py` 的转写核对查，画幅和帧率看 `deliver.py` 打印的成片事实。可选提示（主体偏小、画面停住、短句没有画面事件等）只供参考，按你的设计判断。没有硬伤只说明没有基础错误。读法见 [review.md](review.md)。只读 `frames/_view/` 下缩小后的图，连读十几张 1080p 原图会撑爆请求。

**出片的前提。** `render.py` 的预检会拦下违规写法并给出行号；确有理由时在行尾写 `// lint-ok: 原因`。

- 镜头只依赖 t：不用计时器，不在帧之间保存状态，随机数用 `rng(种子)`，不用 `Math.random()`、`Date.now()`。
- 变换只用 `screen(ctx)`、`cam(ctx, …)`。`setTransform(1,0,0,1,0,0)` 会丢掉转场位移和震动。
- 音效 `EV(t, '名字')` 写在镜头文件顶层，不写在绘制函数里。
- 网页只加载 `web/shots_*.js`。背景由引擎按 `theme.colors.bg` 每帧先画，镜头里不铺底，否则重叠转场时会盖掉前一个镜头。引擎不带默认配色，`bg`、`ink`、`acc` 要写。

渲染、配音、体检这类长命令转到后台时仍在运行：不要重启它，先做不依赖它的事，再等结果。宿主提供的配音、转写和长命令的等法见 [capabilities/README.md](../capabilities/README.md)；没有配音后端时，用用户的录音，或做无配音版本并在交付说明里写明。
