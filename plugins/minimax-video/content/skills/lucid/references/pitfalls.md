# 已知的坑

按「症状 → 原因 → 做法」写。

## 画面

| 症状 | 原因 | 做法 |
|---|---|---|
| `timeline.py` 停下，提示先定色调和背景；或页面报缺 `theme.colors` | 模板和引擎没有默认配色 | 按画面的场景、观众和播放环境定背景、主色、强调色（见 [craft.md](craft.md)「配色从场景推」），写进 `theme.colors` 的 `bg`、`ink`、`acc` |
| 体检报「文字块放不下」 | 框太小或字太多，最小字号也放不进 | 删字、拆成两屏，或分给它更大的区域；不要缩小字号下限，也不要标 deco |
| 前几帧是系统默认字体 | 字体没加载完就开始截图 | `main.js` 会等 `theme.fonts` 里每个字重加载完并预绘；新字体写进 `theme.font_files`。自己写页面时必须 `await document.fonts.load` |
| 字体没生效，也不报错 | `theme.font_files` 写成了字符串，或 `src` 又包了一层 `url()` | 每项写成 `{"family": "Geist", "src": "fonts/Geist-600.woff2", "weight": "600"}`，`src` 相对 `web/`；`timeline.py` 会校验格式和文件是否存在 |
| 重拍上画面是空的（体检报「拍点空画面」） | 元素从这一拍才开始入场，弹簧在这一帧值为 0；或镜头的第一帧还没画东西 | 入场提前 2–4 帧开始，让落位在拍上；见 promo.md「拍子是动作的落点」 |
| 重叠转场变成了硬切 | 后一个镜头在自己的绘制函数里铺了底色，把前一个镜头整个盖掉 | 背景交给引擎画，镜头里不铺底；只有「新画面盖住旧画面」的转场才铺 |
| 镜头提前起手的那几帧，元素被放大成怪形或拉成竖条 | `Math.exp(-(t - t0) / tau)` 在 t < t0 时是几十上百倍；镜头的 pre 重叠段和 `enter()` 提前起手都会让 t 早于 t0 | 用 `decay(t, t0, tau)`，t0 之前返回 0。`render.py` 的预检会拦下这种写法并给出行号 |
| 一整块画面无声无息地消失 | 变量名和浏览器全局名重名：`top`、`name`、`status`、`parent`、`length` 在页面里本来就有值（`top` 是 `window.top`），没声明就用，得到的是对象或字符串，坐标变成 NaN | 局部变量一律 `const` 声明，不用这几个名字；`render.py` 的预检会报出 NaN 出现的时刻 |
| 第 0 帧整帧是黑的 | `post.fadeIn` 让开头被黑色盖住 | 宣传片不开 `fadeIn`；要渐显就让第一个镜头自己做入场，并且第一帧已经有东西 |
| drop 那几帧整个画面发灰、主体发白 | 用整帧加白（`FLASH` 的 `'add'` 模式）或铺满全屏的大光晕做闪光，黑底被抬成灰 | 用 `FLASH` 默认的 `light` 模式；光晕半径不超过主体的 1.5 倍；整帧闪白只用 1–2 帧 |
| 转场中途两层画面半透明地叠在一起 | 新镜头的 pre 和旧镜头的 post 重叠时，两边都在淡入淡出 | 一边遮挡另一边：新画面盖住旧画面，或旧的先走新的再进。用 `stills.py --cuts` 看每个转场的中间帧 |
| drop 那一帧是一片灰白 | 闪光太强、太早，盖掉了还没出现的内容 | drop 那一帧先有内容，闪光叠在上面；空拍里不放闪光 |
| 转场、震动、底鼓缩放不起作用 | 镜头里用了 `ctx.setTransform(1,0,0,1,0,0)` 或 `resetTransform()`，丢掉了全局矩阵 | 只用 `screen(ctx)` 和 `cam(ctx, …)` 设变换；预检会拦下 `setTransform(1, 0, 0, 1, 0, 0)` |
| 某个镜头没画出来，显示占位字 | `SHOT.xxx` 的 id 不在时间轴里，或新建的 `shots_*.js` 没被页面引用 | 运行 `python3 tools/timeline.py`，它会同步 `index.html` 并列出「写了但不在时间轴里」和「还没写」的镜头 |
| 两个文件定义了同一个镜头，后加载的覆盖了前面的 | `shots_*.js` 按文件名排序加载 | 一个镜头只在一个文件里定义；示例镜头在 `examples/`，不要原样复制进 `web/` |
| 推镜头或平移时标题被画框切掉一半 | 只看了镜头的结尾帧 | 每个镜头至少看 30% 和 70% 两帧；`stills.py 名字 --all 0.3,0.7`。体检报告会写出这一刻镜头的缩放和位移 |
| 草稿档里看着顺，正式档出现拖影或卡顿 | 草稿档是半尺寸、不开运动模糊 | 卡顿、拖影、小字清不清楚，在正式档或 `render.py --final 起 止` 渲的片段上看 |
| 转场时进场画面是空的 | 进场镜头的元素在转场期间还没出现 | 给镜头设 `pre`，入场动画从 `S.t0 - pre` 起算 |
| 铺满转场时半个画面在一帧里突变 | 铺满的形状没有放大到超出四角，或时间太短 | 放大到对角线长度以上，用约 0.3 秒 |
| 正式档里快速移动的字出现几份错开的副本（体检报「正式档重影」） | 这一段位移大，采样数到了上限仍不够 | 用 `FAST.push([t0, t1, 32])` 提高这一段的采样下限，或调大 `motion_blur.max`，只重渲这一段 |
| 某一帧闪一下 | 镜头的绘制范围在那一帧刚好结束或开始，或 `prog` 的起止写反 | `review.py` 会列出单帧跳变时刻；用 `stills.py` 取前后各一帧对照 |
| 推近到 3–4 倍时截图里的字糊 | 原图分辨率不够 | 用 `assets.py zoom` 单独截高清局部，叠在原图对应位置上 |
| 循环片首尾接不上 | 最后一帧和第一帧的状态（包括光标位置和速度）不同 | 结尾段用和开头相同的函数算，渲第 0 帧和最后一帧对比 |
| 成片整体偏暗约 4 级 | Playwright 的 JPEG 直接按 bt709 转换 | `render.py` 已用 bt601→rgb→bt709 链路；自己写编码命令时照抄它的 `VF` |

## 对话与自查

| 症状 | 原因 | 做法 |
|---|---|---|
| 读了十几张 1080p 原图后，会话报 Request too large，之后再也恢复不了 | 一张 PNG 2–3 MB | 只读 `frames/_view/` 下缩小后的 JPEG |
| 自评写得很准，但成片平淡 | 修完错误就交付了 | 第一版之后按片型手册的质量标准再改，见 [review.md](review.md) |
| 编了一个不存在的音效名 | 凭印象写 `EV(t, '名字')` | `python3 audio/synth.py --list-fx` 查全部名字；写错时 synth.py 会报错 |

## 渲染

| 症状 | 原因 | 做法 |
|---|---|---|
| 每个进程只有 0.2 帧/秒，15 秒的片子渲了半小时 | 整台机器同时有超过 3 个使用 WebGPU 的 Chrome（shader 背景），互相抢资源 | 不需要就不开 shader；`render.py` 会整机排队，日志里出现「低于 1 帧/秒」报警时检查机器上还有什么在渲染 |
| 渲染被中断 | 外层命令超时、会话中断 | 重跑同一条命令：网页代码没变的分段会被复用 |
| 同一条渲染或配音命令跑了两遍，互相覆盖 | 命令转到后台后，以为它停了，又启动了一次 | 转到后台的命令仍在运行，等它的结果；宿主的等法见 `capabilities/` |
| 担心只改了声音也要整片重渲 | 不会发生 | 网页代码没变时 `render.py` 复用全部分段，只重新混音 |
| shader 背景某一帧卡死 | 多个 Chrome 同时用 WebGPU 偶发 | `render.py` 每帧有 30 秒看门狗，超时自动重启并从该帧续渲 |
| Chrome 进程退出很慢 | shader 逐帧渲染后要等 GPU 资源回收 | `Handle.close()` 按临时用户目录直接结束这个 Chrome，只在产物落盘后调用 |
| 成片在两个目录各存了一份 | 习惯性复制 | 只在 `out/` 交付一份 |

## 配音（讲解片）

| 症状 | 原因 | 做法 |
|---|---|---|
| 时间轴报「检出 N 处 ≥1 秒的静音，应为 M」 | 镜头内部写了 ≥1 秒的停顿标记，或某句读崩了 | 镜头内部停顿小于 1 秒；用 `tts.py asr` 看哪一段异常 |
| 英文名读错（dots 读成「到特」，生僻产品名被读成拼写相近的常见词） | 整段合成时模型把英文当拼音读 | 短句试读 → 改中文指代 → `tts_fix` 换同音字；改完整段复核 |
| 没有可用的配音后端 | `voice.provider` 是 `auto`，但宿主没有配音能力，本机也没装 edge-tts | 按 `tts.py` 打印的提示装好后端；或用用户给的录音（`provider: "file"`）；或做无配音版本 |
| 配音服务返回 500、429、temporarily unavailable | 服务端偶发 | `tts.py` 自动等待重试；不要拆分长文本。各后端的具体问题见 `capabilities/` |

## 环境

| 症状 | 原因 | 做法 |
|---|---|---|
| 跨天的项目，脚本和素材不见了 | macOS 定期清理 `/tmp` 下几天没访问的文件 | 工程放在用户工作区 |
| 机器上没有 node、ffmpeg、brew | 不需要它们 | 本流水线只用 Python（numpy、scipy、Pillow、playwright、imageio-ffmpeg）加本机 Chrome。ffmpeg 用 `imageio_ffmpeg.get_ffmpeg_exe()`；Chrome 用 `channel='chrome'`。缺包时 `pip3 install --user numpy scipy playwright imageio-ffmpeg pillow` |
| macOS 没有 `timeout` 命令 | 系统不带 | 用 Python 的 `subprocess.run(timeout=…)` |
| 音效一个都没有，合成器也不报错 | `EV()` 写在了绘制函数里；导出音效时不调用绘制函数 | 写在镜头文件顶层；`render.py` 的预检会拦下写在绘制函数里的 `EV()` |
| 新建的 .js 文件里的函数「未定义」 | 网页只加载 `web/shots_*.js` | 共用代码放进 `shots_00_common.js` 这类名字的文件；`timeline.py` 会提示不会被加载的文件 |
| `assets.py` 卡住不返回 | 整机同时开着很多 Chrome，或目标站点不通 | 命令有总时限（默认 120 秒，`--timeout` 可改），超时会打印卡在哪一步和已写盘的产物；先用 `curl -I` 确认站点能访问 |
