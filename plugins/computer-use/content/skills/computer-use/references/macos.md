# macOS 操作差异

本文件仅适用于执行主机为 macOS 的任务，与主 Skill 的通用流程一起使用。

## 后台操作与文本

- 后台点击优先使用当前窗口暴露的 AX 控件及支持的语义动作。窗口后台像素点击默认跳过；只有当前宿主明确声明支持时才使用，不通过试调用探测。需要坐标点击但无法确认后台支持时，在允许前台操作的任务中提前告知用户后转前台；仅后台任务停止该步骤。收到 `computer_background_coordinate_unavailable` 等拒绝后，不重复尝试该路径。
- 拖拽默认使用前台模式并提前告知目标应用；只有当前宿主明确支持后台拖拽时才使用后台模式。用户要求仅后台且该能力不可用时，停止该步骤。
- `computer_secondary_action` 执行原生菜单路径并管理前台激活。`path` 必须来自观察到的菜单；控件的 AX 动作通过 `computer_click` 的 token 和受支持的 action 执行。仅后台任务不调用原生菜单。
- `same_pid_keyboard_ambiguity` 表示键盘路径无法安全区分同进程窗口。`computer_key`、`computer_select_text` 即使带 token 仍受此限制；元素定向的 `computer_type` 可以通过 AX 插入文本，需单独判断。输入可能在拒绝前已部分生效，重试前检查内容；不要通过关闭无关用户窗口或更换 ref 绕过歧义。
- 地址栏、切换标签、文件导航等争取焦点的快捷键按前台操作处理，即使调用指向指定 PID。token 定向输入被拒绝时，重新观察；允许转前台后可用截图坐标明确聚焦，已有选区或光标需保留时避免额外点击。
- 标准文本编辑中，Command-Left/Right 移至行边界，Shift-Command-Left/Right 扩展选区至行边界；Home/End 有不同语义。选择子串时优先使用应用的查找/替换，`computer_select_text` 会全选字段。替换前确认选区。
- AX 文本回显可能省略首尾空白和末尾换行。局部编辑应基于已确认的选区或查找/替换；仅凭 AX 字符串相同无法证明完整文档的字节级保真。

## 窗口识别与权限

- 菜单栏与窗口内容分开定位；Help 菜单的搜索框不能当作应用内搜索。装饰性或仅水印的 AX 根节点不足以判断内容不可访问，先调整查询并确认窗口归属。
- `ax_window_unresolved` 时只能恢复并重新观察请求的精确窗口，不能借用菜单栏或其他窗口的元素。进程仍在运行但没有可用内容窗口时，可能需要重新打开应用。
- `WindowSharingSessionButton` 标识 macOS 屏幕共享指示器，窗口可能名为 `Window`。根据 AX 标签识别它，保留该系统指示器并重新定位实际内容窗口；不能把其中出现的其他字段当作输入归属证据。
- `on_current_space` 描述该窗口所在显示器的 Space；各显示器不一定共享同一 Space。`is_on_screen` 仅表示可见性，输入焦点仍需确认。
- 仅依据宿主返回的 Accessibility、Screen Recording 状态报告权限问题。空树不构成权限缺失证据，权限变更遵循系统原生授权流程。
