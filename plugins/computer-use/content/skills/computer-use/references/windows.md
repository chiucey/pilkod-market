# Windows 操作差异

本文件仅适用于执行主机为 Windows 的任务，与主 Skill 的通用流程一起使用。

## 后台操作与文本

- UI Automation（UIA）的语义动作、值与文本能力取决于应用和控件提供方。优先使用受支持的后台操作，包括后台拖拽；不要套用 macOS 的前台拖拽默认规则。
- 像素输入依赖目标点可见性，遮挡或自绘控件可能需要前台输入。消息投递成功仍需检查实际应用效果；`background_unavailable` 按主 Skill 的前台告知及仅后台约束处理。
- 前台输入可能临时激活应用后恢复原焦点，每次输入前确认目标。争取焦点的地址栏、标签切换快捷键按前台操作处理；使用 Windows 对应快捷键。
- UIA 提供方可能延迟回显；值或文本回显后还需检查应用业务状态，重试输入前重新观察，避免重复插入。

## 应用归属与系统边界

- 启动身份和路径使用工具观察结果。打包应用的内容进程和顶层窗口进程可能不同，包括 `ApplicationFrameHost.exe`；通过重新枚举确认窗口归属，不拼造 PID/window 配对。
- 冷启动后窗口可能延迟出现，进行有界重读。旧 handle、附属对话框或新文档窗口都需要重新确认归属和控件。
- 混合 DPI 下，窗口坐标、显示器逻辑边界和截图像素可能使用不同单位。遵循主 Skill 的坐标规则及 `matches_native_window_coordinates`，不使用猜测的全局比例。
- UI 自动化需要交互用户桌面。Session 0、提权边界或 UIA 提供方不可用时，报告宿主实际错误；不得自动提权、修改安全设置或安装服务。
