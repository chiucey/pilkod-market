# Pilkod For Legal

Pilkod For Legal 面向企业法务与律师，在 Pilkod 中通过自然语言任务生成可核验、可修正、可恢复的法律工作成果。

- **表格式审阅（Tabular Review）**：按统一问题比较多份材料，核对证据并导出 Excel。
- **文档编辑（Document Editor）**：编辑 DOCX，审核修改建议，使用 playbook 检查合同并交付文稿。
- **时间线分析（Timeline Analysis）**：整理事件、来源分歧与专题结论，导出 DOCX 报告。

## 安装与版本

需要支持 Mini App 的 Pilkod。插件运行在 Pilkod 内置的 Node.js 上，不需要另外安装 Node。

文档的“问问 Agent”与自由起草、修改需要宿主支持公开的对话草稿追加；主会话连续处理当前文档还需要让助手读取当前 Mini App 页面。追加成功后仍需用户在主对话发送，插件不会自动发送消息。文档“改善写作”、表格、时间线自动分析及 playbook 处理还要求宿主支持读取当前会话的模型设置、创建绑定来源会话的后台会话，以及由插件后台按指定模型继续运行会话。表格和时间线任务遇到访问授权时，还需要能够打开对应后台会话处理。能力不可用时会提示，已有成果仍可查看。

Windows 私有存储通过系统 Windows PowerShell 验证当前用户的 ACL，不以 POSIX 权限位代替；需要本地 NTFS 文件夹及当前账号的读写与权限管理能力。若工作区关联失败，页面会显示可反馈的错误码。当前 Windows 修复仍需在目标 Pilkod 上验收；请勿把 macOS/Linux 的测试结果视为 Windows 验收结果。

手动安装时，将解压得到的 `minimax-for-legal` 文件夹放入 Pilkod 数据目录的 `plugins/`（通常为 `~/.minimax/plugins/`，较早版本为 `~/.minimax/plugins/`），再刷新插件列表或重启 Pilkod。

更新时整体替换旧插件文件夹；工作成果和个人模板另行保存，不会随之删除。当前版本见 [插件清单](./.minimax-plugin/plugin.json) 的 `version` 字段。

## 打开与管理工作

在当前对话中选择 `@minimax-for-legal` 打开工作台，或发送“打开 Pilkod For Legal”继续已有工作。支持当前页面会话查询的宿主会直接关联保存位置，无需等待助手传递目录；旧宿主需要发送消息后由助手完成关联。打开不会创建成果或开始分析。

- **项目会话**：工作成果继续保存在该项目文件夹中。
- **无项目会话**：使用用户主目录下的 `Pilkod For Legal` 公共文件夹，例如 macOS 的 `~/Pilkod For Legal`、Windows 的 `C:\Users\<用户名>\Pilkod For Legal`。
  不同无项目会话打开的是同一份工作，可以继续之前的审阅、文档和分析。
  此处“公共”仅指本机这些会话共用，不代表云端发布或其他用户可访问。

首次打开公共文件夹会按需创建目录；首次创建或保存成果时，才在其中建立 `minimax-for-legal` 数据文件夹。
早期版本把公共文件夹放在系统文稿目录下；那里的 `Pilkod For Legal` 不会自动迁移，也不会被删除。
要在另一保存文件夹工作，请在 Pilkod 中打开对应项目。
材料可来自你授权读取的其他位置，添加材料不会改变成果保存位置。

工作文件夹位于 iCloud 云盘、OneDrive、Dropbox、Google Drive、Box 等同步目录时，首页会持续显示提示，但不阻止你继续工作。
同步客户端可能在使用中复制或替换数据库文件，产生冲突副本甚至损坏数据；客户材料也会经由该云服务上传，可能不符合所在机构的保密要求。
建议在本机未同步的文件夹中保存工作。
插件只按路径识别 macOS 与 Windows 上常见客户端的位置，Linux 不识别同步盘；没有提示不代表文件夹一定不在同步盘，例如 macOS 开启 iCloud“桌面与文稿”后，放在文稿或桌面中的项目无法被识别。

首次关联时，页面通过宿主公开能力读取它所属的当前对话，使用项目目录及是否为无项目会话来确定保存位置，并使用会话标识向助手提供简短的页面就绪回执，无需为打开确认读取整页。就绪状态仅在运行期间使用，不保存到工作成果。此能力需要宿主的会话读取权限，插件不列举其他对话，也不使用或保存对话正文；权限被拒绝时保留未关联页面。旧宿主不支持此能力时，由主助手查询当前会话后打开对应位置。重复打开已关联的工作台会保留当前成果与未保存输入。无法确定位置时会说明原因，不会把项目成果误存到公共目录。

连接暂时中断时，页面保留当前内容和输入并持续自动重试；返回页面或点击“立即重试”也会检查连接。同一插件服务恢复后，页面重新核对连接和任务状态，不自动重复提交保存、导入或分析。

工作台页面不能自行启动已停止的插件服务。若 Pilkod 顶部显示“已停止”，请先复制需要保留的未保存内容，再点击顶部启动按钮；若插件已停用，请在“插件 · 技能”中启用。服务已重启、更新或原连接失效时，按页面提示关闭旧工作台标签，在原对话中发送 `@minimax-for-legal` 重新打开。已保存的数据仍在原工作文件夹中；未保存输入只保留在旧页面内存中，重开不会自动带回。

断连提示会展示当前页面可读取的待保存文字，便于复制；文字不包含完整文档格式，也不代替保存。对于结果不明的操作，重新连接后先核对原操作结果，避免重复提交。重开不会自动重新分析已有成果；数据不兼容时按下方版本兼容说明处理。

工作台顶栏右侧以“Pilkod M3(high)”的格式显示主会话模型和思考强度，悬停提示“当前所选模型，修改请在会话中切换”；只读，不修改会话设置。页面可见时约每秒同步，返回页面时立即刷新；读取失败时显示配置暂不可用并自动重试。新分析仍在发起时读取主会话配置，正在运行的任务与历史结果保留各自的模型记录。

首页提供表格式审阅、文档编辑和时间线分析三个新建入口，下方按功能列出已有成果，可按工作类型筛选，也可按名称搜索全部历史任务。
各类成果可展开或收起，标题旁显示数量，默认从 5 条开始展示，置顶成果优先；“查看更多”会提示剩余条数。
搜索结果同样支持置顶和继续加载；清空搜索会恢复原来的分组折叠状态和已展开数量。
点击成果名称继续工作，三类成果的行末更多菜单统一提供“重命名、置顶、删除”。
置顶后成果优先显示，刷新页面后仍保留；可随时取消置顶恢复最近修改顺序。
置顶只保存在本机浏览器，按工作文件夹和成果类型独立记录，每类最多 100 项，不修改成果内容或版本。
任务页面顶部的“首页”面包屑会恢复本次浏览的筛选、搜索、分组折叠状态和滚动位置。
点击功能类别会清空搜索、展开并显示该类成果；返回前仍须处理未保存内容和结果不明的操作。
已保存任务也可从面包屑中的当前标题直接改名。
从同一工作文件夹新开会话，也能从首页恢复已保存成果；可直接请 Agent 按名称查找或询问已有结果。

切换或删除成果前，请先处理未保存内容。改名不改变内容或已有下载，新准备的导出使用新名称。**删除需确认且不可撤销**，会移除该成果及其结果、引用和历史；本机原件、已下载文件、个人模板和其他成果不受影响。

“添加到对话”或“发到对话”只把要求放入主对话输入框，**检查并发送后 Agent 才处理**。文档的完整讨论和连续修改沿用这份主对话。“问问 Agent”携带当时捕获的选区；直接在主对话提及当前文档或继续修改时，每轮重新读取当前页面、正文和选区，无需复制正文或提供文档编号。文档“改善写作”、表格和时间线的结构化分析、playbook 整理和检查从工作区直接启动后台任务，不需要再发送聊天消息。表格式审阅中的“与 AI 讨论”可引用未保存的修改，但讨论本身不会保存修改或启动重新分析。

## 导入材料

通过界面选择、拖拽文件，或请 Agent 导入明确指定的本机文件。文件须位于插件所在机器且可读取；远程或无法直接读取的材料请通过界面上传。Agent 只处理你指定的材料。

| 格式 | 导入与预览 |
| --- | --- |
| DOCX | 正文提取与原件预览；文档编辑支持此格式 |
| PDF | 支持文字层；扫描件需先做文字识别 |
| DOC | 正文提取与文本预览，不还原分页和版式 |
| TXT / Markdown | 纯文本导入与预览 |
| XLSX / CSV | 时间线材料；保留工作表、原始行及单元格证据定位 |

单个文件最多 15 MiB；界面每批最多 16 个文件、合计最多 15 MiB。本机路径导入不支持符号链接、硬链接及非普通文件。加密、损坏、超限或解析超时可能导致导入失败；缺页和缺失附件会影响分析与证据定位。

## 表格式审阅

点击“添加文档”直接选择 DOC、DOCX、PDF 文件，或将这些文件及其所在文件夹拖入表格。上传面板中也可点击“选择文件夹”，批量导入该目录及子目录内支持的文件。选定后会显示上传与解析进度；解析完成后可移除不需要的文件，再确认添加。取消文件选择不会打开进度窗口。

### 开始审阅

说明材料范围、代表哪一方以及要比较的内容，例如：

```text
审阅 ./contracts 里的供应商合同。我代表采购方，
比较合同主体、生效日期、期限与续展、责任限制、适用法律与争议解决。
```

也可以打开空工作台，再添加文件、列或模板。

- **文件**：添加后可查看解析进度和失败原因；移除不会删除本机原件。调整后的文件顺序随审阅保存，导出沿用此顺序。
- **列**：通过“新增列”设置名称、结果格式和审阅要求，从列菜单修改、插入或移除。列的显示顺序、宽度和固定状态只保存在本机浏览器，不改变分析或导出顺序。
- **模板**：通过“使用模板”选择审阅问题；模板卡片底部展示列名与格式，可横向滚动预览。选中的列按模板顺序加入审阅。左栏顶部的“新增模板”打开独立表单，从零列开始配置；点击个人模板标题旁的“编辑”，直接在模板库右侧修改；删除入口位于旁边的“⋯”菜单，需再次确认。预设和个人模板均可点击“复制”，修改副本并保存为新的个人模板，取消则不创建。模板列使用单层列表，可拖拽调整顺序，再保存修改。“保存为模板”按当前表格显示顺序，将审阅列配置保存为新模板；新建时如有同名个人模板，需换一个名称。个人模板跨工作文件夹复用，更新或删除模板不影响已应用的列和结果；预设模板只读。

新增或编辑表格列、模板列时，填写列名和格式后可使用 **AI 生成** 根据列名及已有要求起草简短的审阅要求，保留分析意图，说明该项要分析的内容和关注点。生成内容直接填入编辑框，覆盖已有要求，可继续修改或撤销。生成期间修改输入、取消生成或关闭弹窗会取消本次生成。确认列配置后修改才生效；此功能使用当前会话的模型，需要支持原生 Agent 的 Host。

新增模板列时，“再添加一个”将当前列加入模板草稿，并清空表单继续添加；“完成”提交当前列并关闭，直接关闭弹窗则丢弃本列未提交的内容。编辑已有模板列时，点击“完成”更新草稿并关闭。最后仍需保存模板以保留修改。

标签列可配置预设标签和颜色，并随个人模板保存。分析优先使用匹配的预设，材料支持的新标签仍可保留；如果只允许特定选项，请在审阅要求中写明。未预设的标签自动分配稳定颜色，无法确定时结论显示“-”，原因放在推理中。编辑结论时可勾选预设或添加新标签。新标签只属于单元格结果，不自动添加到列预设或个人模板。

确认配置后保存变更，取消不会应用。

### 分析与继续处理

已有审阅确认新增文件、列或应用模板后会自动分析：新增文件只处理新文件，新增列只处理新列，结果逐格显示。尚未正式加入的内容不计入结果和导出。打开或刷新页面会继续此前已确认的新增请求，无需重复配置。

分析任务沿用发起时的主会话模型与思考强度。切换主会话配置后重新发起分析或 AI 生成，会读取新配置；恢复原任务仍沿用原配置。详情的结论和推理不常驻展示模型，打开“历史记录”后，当前结论下方显示该结果的模型名；人工结果显示“人工修改”及修改时间。每条分析记录的推理或引用展开区内显示该版本的模型；两者均无内容时，可展开“模型信息”查看。原分析来源不归属于人工结论。悬停或点击模型名可查看生成模型（或请求模型）、推理强度和上下文窗口，后两项未知时省略。模型配置属于对应版本的结果，优先展示 Host 回报的实际配置；未回报时明确标为“请求配置”，未记录时不推断。详情中人工修改结论的细线铅笔图标保留在结论标题旁，悬停保持透明背景并显示修改时间。列的 AI 生成来源仍使用信息图标，悬停可查看对应模型配置；来源浮层均可点击保持展开，按 Esc 或点击外部关闭。列的 AI 生成来源随列和个人模板保存，手动修改审阅要求会清除该段文字的 AI 来源，撤销生成则恢复上一版来源。

顶部显示分析进度和用时，点击可查看历史记录。记录默认按开始时间倒序排列，点击开始、首格或结束时间表头可切换排序；暂无时间的记录排在最后。排序只改变记录顺序，不影响顶部和累计用时。“最近用时”对应最近发起的分析事件；仍有分析进行时，显示最近发起且未结束的事件用时。顶部与对应记录均从该事件开始计时至结束（进行中则计至当前时刻）。首格时间表示本次首次保存可读新结果的时刻，不计已有结果及人工修改，可能早于结果最终完成。用时包含分析期间的等待，不含此前的导入和配置；累计用时对并发重叠只计一次，排除事件间空闲。

后台不继承主会话的聊天历史，请把必要背景写入审阅要求。所需宿主能力见[安装与版本](#安装与版本)。

宿主要求文件访问授权时，分析会等待，并提供“查看会话”入口。打开后在宿主的授权卡中核对请求；允许后继续同一次分析，无需重新运行。无项目会话的公共文件夹位于用户主目录，不在宿主后台会话的默认目录内，因此也可能出现授权请求。插件不会自动批准；关闭插件内的提示只收起提醒，不代表已处理授权。拒绝请求、运行超时或中断可能使对应文件未完成，已保存结果保留。

“分析中”包含准备、排队和执行。已有结论、引文仍待定位或正在重新分析时，表格保留结论，并用一个加载图标表示尚未完成。刷新或关闭页面不等于取消已交给后台的分析；退出 Pilkod、停用插件或运行中断仍可能导致未完成，请重新打开工作台核对结果。

推理中的引用按首次出现顺序编号，重复引用同一来源时复用编号；折叠区显示这些引用的去重列表。待定位的引用保留编号并显示加载状态，定位完成后可点击跳转到原文，编号不变。PDF 高亮使用已核验的原文范围；无法在预览中可靠还原该范围时，会提示无法精确高亮，可结合原文引文人工核对。

表格引用和 Excel 证据明细以导入材料中的原文为依据。

修改列要求后保留原结论等待更新。暂时性故障会有限自动重试，仍未完成时在对应单元格显示分析失败，可进入详情重试该项；点击顶部进度入口可批量重试失败内容。排队和启动中的单元格统一显示分析中；没有正常启动时可从列菜单重新分析，页面内部会核对原启动请求，避免重复启动。尚未正式加入的文件或列在其文件行或表头提供确认、重试和撤销入口；撤销后的内容可从新增操作旁重新添加。单个文件失败不会中止其他文件，重试保留已完成结果；尚未收到新结果不一定表示失败。工作台目前不提供手动停止分析入口。

### 核验与修正

每行是一份文档，每列是一个审阅问题。单击单元格显示完整结论：文本缩略模式可展开宽度，文本换行模式保持原单元格宽度。上方操作栏可编辑、核验、锁定或查看历史记录；展开项跟随表格滚动，固定文档列和表头保持在其上方，点击外部或按 Escape 收起。点击“查看详情”进入详细审阅，默认展开目标审阅项的推理，结合引用和原文核验；可手动折叠。重新分析期间，上次推理默认收起，仍可手动展开查看。也可点击文件名直接进入详细审阅，按文件逐项审阅、按列对比，或点击顶部提醒图标旁的数字，集中查看AI不太自信的结果；悬停该数字可查看这类结果的数量。详情中间列标题旁的搜索可按名称、当前结论和推理内容实时筛选，支持部分关键词、空格分隔的多个关键词及忽略大小写；清空搜索恢复原筛选范围。搜索、排序和筛选只改变阅读视图；文件或列的批量操作仍覆盖其完整范围，包括隐藏的结果。

没有结论时统一显示“-”，无法判断或无法按列格式表达的原因保留在推理中；这仍可以是已完成的分析结果。文本列可简洁表达有依据的“未约定”或“不适用”，是否类的明确否定显示为“否”；未知与否定应区分。限定选项均不匹配时可以没有结论，不应强选。没有引用不等于答案为否；已有结论也需结合证据完整性判断。编辑时直接使用列格式填写值，空值保存为无结论，日期、金额和是否类的补充说明保留在推理中。

**标记已核验不代表风险已解决，也不会消除“AI对这个结果不太自信”的提示。** 修改结论、重新分析、提交反馈或改变列要求后，需要重新核验受影响结果。可对单格、所选文件或整列核验及撤销核验，未完成结果不受影响。

选中多行后，底部操作栏直接提供核验、锁定、解锁、重新分析和移除操作。操作栏中的全选框与表头同步：部分选中时显示半选态，点击可全选；全部选中后再次点击可清空选择。

排队或分析中的单元格禁止人工编辑，即使仍显示旧结论，也需等待该单元格分析完成后再修改；其他已完成单元格不受影响。

点击单元格操作栏的“编辑结论”、双击单元格或聚焦后按 F2，可按列格式就地编辑结论。编辑框也随表格滚动，离屏时保留输入，滚回原位置继续编辑。是否类选择后立即保存；日期在一个输入框内自动识别 YYYY、YYYY-MM 或 YYYY-MM-DD，按原值保留年、年月或年月日精度；可打开日历选择完整日期，缺少的月或日不会自动补齐，确认后保存；点击日期弹层的“清除”会立即保存为无结论。金额在一个文本框内编辑完整结果，保留已有币种文字和精度，不自动补币种。未识别或含糊的币种在编辑和详情中提示，仍可按原文保存，不因此拒绝 Agent 提交或要求重新分析；金额基本格式校验仍然保留。其他格式点击“保存”或按 Ctrl/Cmd+Enter 提交，Escape 取消尚未提交的编辑并返回结论阅读。右键单元格或按 Shift+F10 仍可编辑结论或查看历史记录。单元格操作栏直接显示“查看详情”，时钟图标悬停显示“历史记录”。表格中的铅笔、核验和低置信度图标分别提供状态提示，组合图标可逐个悬停查看；铅笔图标表示当前结果经过人工修改，提示中保留编辑时间；它与核验状态独立，人工结果不沿用原 Agent 的“AI对这个结果不太自信”提示。人工修改不会自动标记为已核验；原 Agent 结论、说明和引用仍保留，但不意味着它们支持修正后的结论。表格和详情中的“历史记录”都打开独立侧边抽屉，顶部显示当前结论，下面由新到旧保留历次人工修改和分析结果，点击“历史记录”整行可折叠或展开；推理与引用在每条分析记录内按需展开，可滚动阅读并加载较早记录。每条分析记录保留保存时的推理片段、引用原文、编号关系和模型配置；后续补齐引用或重新分析会新增记录，不改写旧版本。历史引用展示该版本保存的摘录，不跳转到当前证据。抽屉左边缘可拖拽调整宽度，双击恢复默认宽度；聚焦边缘后也可用左右方向键调整。历史结论按保存时的格式和标签颜色显示，后续修改列设置不会改变旧记录的展示；每条非空历史结论均可复制。尚无结果或人工操作时显示空记录，不生成虚构的初始结果。保存时若已有新结果，应先核对冲突。

已完成结果可锁定。锁定后仍可核验，但不能编辑、提交反馈或重新分析；修改列要求及批量重新分析会跳过锁定格。锁定不等于核验，解锁不会自动开始分析。

通过对话让 Agent 重析、提交反馈或修改列要求时，若目标仍属于未结束的后台分析批次，需要先等待该批次结束；其中某格先完成也不提前重排。界面操作仍按各入口的确认和可处理范围执行。

“重新分析”需确认处理范围及结果替换，处理未锁定的已完成、分析失败或尚未正常启动的内容，跳过已有任务正在排队或分析的内容。确认启动后，受影响结果的原核验失效；处理中保留当前结论及来源，详细审阅卡片会提示当前显示上次结果。重新分析、重试、反馈处理或列要求更新的**新结果被接受后，会替换人工修改**。尚未写入新结果的失败或取消保留原结果；已接受的新结果即使仍待补证，也不会因后续失败或取消而回退。新增文件或列只分析新增范围，保留原有结果。

新建审阅默认命名为“未命名”，同一项目内依次使用“未命名（1）”“未命名（2）”等可用名称。可在首页成果列表或当前任务标题处重命名；增删文件不改变名称。

### 导出 Excel

点击“导出为 Excel”，核对未人工核验的结果单元格数量及尚无结果数量后确认。默认文件名为“审阅名称_用户本地时间.xlsx”（时间格式 `YYYY-MM-DD_HH-mm-ss`），可在导出窗口修改文件名，不影响审阅名称。有未完成或AI不太自信的结果时仍可导出；导出不会标记已核验或结束审阅。

Excel 包含审阅矩阵、概览和证据明细。第一张审阅矩阵只展示结论；尚无结果留空，明确无结论显示“-”。概览区分已核验、未人工核验的已有结果和尚无结果单元格；推理、原文引用、来源、完成与核验状态保留在第三张证据明细表。导出界面及文件概览均提示“AI 生成结果不构成法律意见，需人工核实”。人工修改后的原 Agent 说明仍带来源标记；引用编号与对应单元格的证据明细一致。

单元格文字超过 Excel 的 32,767 字符上限时，导出文件中该格会截断，并在末尾注明“（内容过长，完整内容请在工作台查看）”。
单个 Excel 文件最大 32 MiB。
生成前另有两道安全上限，以下典型规模按 100 份文档 × 200 列的满容量估算，仅供参考：

- 证据明细最多约 300 万个单元格（每条引用占一行、每行 16 格），约 18.6 万行；引文与说明都较短时，平均每格约 9 条引用。
- 文字总量约 128 MiB（重复文字只计一次，`&`、`<`、`>`、引号等需转义的字符按更高成本计），约合 4,000 万个不重复的汉字或 1.2 亿个英文字符，平均每格约 2,000 个汉字。每条引用附约 120 字原文和 150 字说明时，每格约 7 到 9 条引用就会先达到这道上限；内容更长时可容纳的引用更少。

超出任一上限时无法导出，提示会说明触发的是哪一项及其数值；重试不会改变结果，完整内容仍可在工作台查看。
在会话中让 Agent 导出时，超过 6 MiB 的文件不提供会话资源链接，请在表格式审阅工作台中下载。

## 文档编辑

进入文档编辑会直接显示空白草稿，首次保存时才创建文档记录，导出时生成 DOCX 文件。
点击工具栏“导入 DOCX”可选择 DOCX（最大 15 MiB）。
成功导入后会新建并打开一份独立文档；当前已保存的文档仍可从首页成果列表重新打开，同名文件也不会覆盖。
导入及后续编辑不会改写本机原文件。
文件检查通过后，如有未保存的更改，可选择“保存并打开”“不保存并打开”或取消；导入失败时保留当前内容。
PDF 等其他格式可作为参考材料，不能作为可编辑文档。

通过“插入 → 目录”生成的目录，可点击目录将其整体选中，再按 Delete 或 Backspace 移除；按 Esc 或点击正文取消选中，删除支持撤销和重做。

双击页眉或页脚区域可编辑内容；处理全部待审核建议后，在该区域的“选项”菜单中选择“删除页眉”或“删除页脚”可移除，删除支持撤销和重做。仅清空文字会保留页眉页脚结构；删除也不会自动关闭“首页不同”或“奇偶页不同”等版式选项。

正文停输后自动保存，也可按 ⌘/Ctrl + S 立即保存。保存失败时保留当前文字并提供重试，悬停可查看原因。保存尚未完成时，切换或关闭页面请按提示处理；刷新或关闭不能代替重试。

底部状态栏显示当前页与总页数，当前页随可视区域滚动更新。

### 修改与审核

选中正文后，浮条直接提供“问问 Agent”和“改善写作”，旁边可调整正文或标题样式、加粗、斜体、下划线、删除线及链接。段落样式作用于选中内容所在的段落，字符格式作用于选中文字。移除链接会清除整条链接及其颜色、下划线，保留文字和加粗、斜体、删除线等其他格式；一次撤销即可同时恢复链接和原有样式，也可一次重做。

点击“问问 Agent”输入问题，将当时选中的内容和问题添加到宿主主对话。它可引用未保存的文字和红线建议，讨论交接本身不保存正文或启动修改；追加成功后仍需在主对话发送。

空段落旁的“起草与修改”、正文右键菜单和 ⌘/Ctrl + J 可打开自由起草与修改输入。根据选区、光标和要求判断起草或修改位置；选中正文时默认针对选区，明确要求时也可处理全文。打开输入框不会提交要求或启动任务，收起会保留已输入的要求。

“起草与修改”中的“发到对话”会先保存当前正文，空白草稿首次创建文档记录，再把要求、文档和选区的简短信息添加到宿主主对话。Host 确认追加后仍需在主对话发送；追加不代表模型已经处理，也不会启动后台改善。助手收到后重新读取该页面的当前正文与精确选区，编辑前再保存并核对位置，生成可审核的建议。空白文档也可起草多段文稿。

建议提交格式错误会先尝试修正；同类错误持续存在时，助手应报告失败并停止本轮写入。它不会通过直接向编辑器输入正文或替你接受建议来完成起草。

Host 取消追加时保留输入；结果不明时先核对目标主对话，避免重复添加。缺少公开追加能力时保留输入并说明原因，不自动改用隐藏任务或剪贴板。

点击“改善写作”会直接保存并固定当次选区，按点击时的模型与思考设置启动后台优化，不向主对话添加消息。结果以待审核建议返回，限于选中的文字；不会自动扩大到全文或接受修改。后台不继承主对话历史，有特定立场或复杂修改要求时可使用“问问 Agent”。运行中可停止，已返回建议保留；结果不明时核对原操作，能力不可用时显示原因，不改走主对话追加。

对已有建议可使用“按反馈修改”，将该条建议和反馈要求发到主对话；检查并发送后再处理。原建议保留到新建议成功返回，是否接受仍由你决定。

也可直接在宿主主对话中说“修改选中的内容”或继续追问。每轮都会重新读取当前打开文档及光标、选区，不沿用聊天记录中的旧位置。行内要求已经附带的文档或选区发生变化时，会先重新核对，避免静默改到另一处。明确要求修改时先保存当前正文，再提交待审核建议。改善写作或规则任务仍在运行、收尾时需等待；页面关闭或不可读时不会猜测目标。此能力依赖宿主允许助手读取当前 Mini App 页面，不需要添加另一套聊天框。

建议以红线和评论呈现，**由你决定接受或拒绝**，Agent 保存建议不等于正文已修改。“待处理修改要求”可继续尚未发送的建议反馈，沿用原要求，不重复创建。后台请求和暂停请求不能从这里续跑，请先处理当前结果，再提出新要求；仍在运行的任务可停止，结果不明时可核对原操作。历史可预览并还原为新的当前版本，还原不会自动重新分析。

### playbook

在文档编辑的“playbook 审查”中，可直接浏览已保存的 playbook，点击“管理”即可在侧栏内新建、编辑或删除，无需先上传文档。点击“导入 playbook”上传已有审查指引，后台 Agent 会将内容填入可编辑表单；也可粘贴标准或手动填写。后台整理不向主对话添加消息，退出管理后仍可回来查看进展。材料中没有明确的立场不会自动补成你的政策，AI 补充的建议须明确采用。

生成后直接进入可编辑的审查项总览，名称、用途和整体说明在此调整。拖动审查项左侧把手可排序，也可使用键盘或位置菜单；进入单项编辑要求、适用条件和立场后，返回总览保留位置。单项编辑页可直接删除该项；“批量操作”可选择多项删除；保存前可在“待删除”中逐项或全部恢复。保存会生成新版本，离开时可放弃未保存的修改。资料库支持搜索、排序与批量删除整本 playbook；永久删除前会确认名称、数量及历史删除范围，已有审查仍保留规则快照。整理完成不等于保存或应用规则，未保存草稿不会替换选择器中的已保存信息。

检查 DOCX 时，在右侧直接选择 playbook、预览并勾选审查项，再点击“开始审查”，无需打开选择弹窗。可只检查，也可同时生成修改建议；补充要求可展开填写。保存或选择 playbook 不会自动开始；空白文档可浏览和管理，添加正文后才能开始审查。管理返回或切换页签会保留当前选择和补充要求，库的新版本不会替换已经选定的版本。点击“编辑 playbook”直接进入总览，“保存并用于本次审查”返回准备页；同一本的新版本保留原有勾选，新增项默认不选。也可从更多保存操作中选择仅保存到库。资料库中的保存不改变审查选择。

结果逐项展示，可查看原文和规则依据；对具体问题还可补充首选或退让立场的建议，仍由你接受或拒绝。“新审查”先展示完整 playbook 列表，点选后再进入审查项预览；尚未提交的补充要求仍保留。“使用最新版准备新审查”按原规则勾选预填新审查，不会自动开始；新增项默认不选。“审查记录”可切换已有结果。每次检查固定当时的正文和规则版本，库的后续修改不会悄悄改变结果。正文变化后需要重新检查，接受修改不等于自动符合规则。

整理、检查或补建议期间可以“停止”，已返回内容保留；后台收尾后，可继续尚未完成且仍有效的部分。提交结果不明时核对原操作，避免重复创建。打开或刷新页面不会自动重新分析；后台能力不可用时保留输入并说明原因，不改为向主对话追加要求。

### 恢复文档

导入或打开结果不明时，在原标签页使用“核对原操作”，按提示继续打开。
需要重传时，重新选择内容一致的原文件。
关闭标签页后，已创建文档可从首页成果列表找回，未提交输入不保证恢复。

### 交付 DOCX

点击“导出 DOCX”，选择“当前文稿”或“修订稿”。
默认选择当前文稿，同一文档在本次会话中保留你明确选择的类型；类型暂时不可用时仍保留选择，不会自动下载另一种文件。

- **当前文稿**：导出已确认的正文，不显示修订标记，保留已保存的段落、表格、图片和分页等修改。
  有未保存正文时可“保存并导出当前文稿”；有待审核建议时须先点击“去审核”，明确接受或拒绝，再导出。
- **修订稿**：与导入时的原稿比较，将文字增删标为 Word 修订，格式和结构变化直接应用。拒绝全部修订不会恢复原版式。
  人工编辑、已接受建议和导出时的待审核建议均纳入比较；待审核建议在工作台中仍保持待审核，已拒绝或已替代建议不进入结果。内部接受建议不会消除其相对原稿的文字修改。

选择修订稿后，可填写“修订作者”。优先使用上次成功导出时的作者；尚未保存过作者时，中文界面默认“审阅者”，英文界面默认 `Reviewer`。可改为你的姓名或团队名，去除首尾空白后须为 1–80 个字符，不能包含控制字符。这个姓名会显示在对外 Word 修订中，同样用于人工和 AI 产生的文字净修改，不改变正文或工作台中的审阅身份。

修订稿成功导出后会记住本次作者，包括你确认使用的默认名；同一本机工作台的所有文档和工作文件夹共用，重启后仍保留。只修改输入、关闭浮层或导出失败不会保存为全局偏好。更换已保存作者不影响先前导出的文件及其重试。

字符和段落格式、段落与表格结构、图片、页眉页脚、页面版式及分页等变化直接保留在修订稿中，不会仅因这些变化导致整份修订稿不可用。
页码、目录等域的计算结果及以对象保存的特殊符号也直接应用，不生成文字修订。
保留区域中的文字增删供收件人在 Word 中接受或拒绝；格式和结构变化不生成相应修订，也不能靠拒绝文字修订撤回。页眉页脚等区域整体移除属于结构变化，直接应用，其中的文字不另留修订。

正文和建议状态保存后，导出入口附近会显示修订稿检查状态。
检查对应已保存的正文与建议版本；尚未保存时，修订稿需先保存并完成检查。
文字修改无法可靠定位或对应、完整性校验失败或超出处理上限时，不生成可能遗漏文字修改的文件；已保存的内容仍然保留。
检查失败可点击“重试检查”。能够确定段落位置时，可“查看受限修改”；涉及文档整体的问题不能定位到单个段落。
当前显示首先发现的限制，处理后还需重新检查，不表示其他修改都已通过。你也可以主动改选当前文稿，有待审核建议时仍需先处理。
导出结果不明时，“核对原导出”沿用原名称、正文与建议版本、文稿类型和修订作者，不会因后续输入或选择变化而替换原请求。核对原导出时，作者显示并锁定为该请求的冻结值。缓存过期后重新生成，也保留原导出的作者。

对外文件只使用本次导出选定的修订作者；原文件中的身份元数据不会用来填充作者。详细理由、依据、反馈和中间过程保留在工作台。
收到文件后请核对版式；导出修订稿时也请在 Word 中核对标记及接受、拒绝后的文字结果。

## 时间线分析

时间线分析把材料摘录组织成可核对的事件，再围绕具体问题生成带依据的专题建议，保留来源分歧与人工修订。上传材料不会自动启动分析。

### 创建与分析

进入时间线分析直接展示事实时间线工作区，尚无材料时不会创建成果记录。点击“添加材料”，核对解析结果后选择“创建时间线”。首次最多 64 份材料，创建后可继续添加；全部解析失败时不能创建。创建后直接回到工作区，可确认分析要求并发起分析。顶部“材料”入口按需打开材料面板；主要阅读区保留给事实时间线或当前问题的分析报告。

支持 XLSX、CSV 银行流水等表格材料。XLSX 包括隐藏工作表和隐藏行，保留原始行号及单元格地址；合并单元格仅保留左上角原值。CSV 的单一表名为 CSV，保留逻辑行号及记录起始物理行，支持 UTF-8（含 BOM）、GB18030 和带 BOM 的 UTF-16。账号等文本不转成数字；Excel 已丢失的数字精度无法恢复。公式只读取文件保存的缓存结果，不重新计算或访问外部链接；无缓存结果会明确标注，不能据此认定交易金额。

表格以横向网格预览，可切换工作表并查看原始行号和列字母。点击表格引文会切换到对应工作表、滚动至证据单元格并高亮，同时保留交易行上下文；文档搜索可跨工作表定位。讨论与导出报告保留同一定位。分析银行流水时应区分交易日期与记账日期、收支金额与余额、交易对手与本方账户，结合其他材料判断付款归属。

单个表格上限为 500,000 个规范正文字符、20,000 个非空单元格、10,000 个非空行和 128 张工作表，另受 15 MB 文件及解压大小限制。超过限制时整份文件导入失败，需按日期或工作表拆分，不会静默舍弃后续交易。暂不支持旧版 XLS。

时间线分析默认纳入当前工作区的全部有效材料。确认提取或更新要求后，后台直接运行并逐批写回结果；补充材料后再次分析，会结合当前材料更新已有时间线。时间线和每个专题分别显示各自任务的排队、运行、完成或失败状态，以及实际用时和已保存批次。“查看任务”先展示目标、固定材料范围与分析要求；高级项可打开后台会话查看执行与授权请求。失败保留已有结果与人工修订，可在对应时间线或专题中重试。每次任务固定材料范围与当次模型设置，后来新增材料不会自动混入正在运行的任务。来源集合变化时原任务中断，已有结果保留，可确认当前材料后重新分析。原问题和人工修订不会被后台提案覆盖。

可在任务详情中“停止分析”，阻止该任务继续写回；已保存结果和人工修订保留。停止结果未确认时核对原任务，不用新任务替代原回执。

材料面板可添加、查看原文，或通过材料菜单“移除材料”。移除只改变当前时间线的材料范围，不删除原文件及已保存引用；仅依赖该材料的提取事件退出当前阅读，混合来源事件只保留有效材料的摘录。人工记录与历史分析仍保留；含已移除依据的原人工修订需恢复材料后再修改，也可补录独立事件。重新添加同一原件会恢复材料关联，仍需按当前范围重新确认分析。

点击“补录事件”可记录已知事实，时间和关联材料均可选；材料关联只提供上下文，不生成已核验引文。删除事件后，该事件退出当前时间线，原材料及历史分析、讨论中的依据仍保留。后台分析不能覆盖人工事件，也不能恢复已删除事件。

事件标题由 Agent 概括，用于浏览；点击事件在右侧核验面板查看绑定的原文摘录、分歧和人工修订。查看全文使用同一侧面板，关闭全文后回到此前的核验或材料内容。通用 AI 整理说明集中在页面底部，不在每个事件和引文前重复；当事人主张保留简短的“主张方”标注，具体冲突、证据不足和判断边界继续就地展示。材料中的一方主张不能视为已确认事实。事件时间必须有自身摘录中的原话，但日期解释、归属和上下文仍需人工核对；引文匹配成功只证明原文存在。

产出事件后可点击“新建专题”，填写关注问题；材料默认全选，需要时再调整，范围随专题保存，重新分析和失败重试沿用该范围。通过顶部“专题列表”打开已有专题分析；需要改变问题或材料时，选择“调整并新建专题”，原专题与原范围保留，已移除材料不会选入新专题。同一时间线同时只运行一个分析任务；有任务运行时仍保留正在填写的问题，待任务结束后再由用户发起，不自动排队。

分析报告直接占据主要阅读区，按结论要点、判断依据和待核事项分组，并显示该报告的材料范围。每项区分材料记载摘要、主张归属摘要、分析推论或待核问题，标明有引用依据、存在争议或证据不足。点击该项文件名，在右侧阅读器定位并核对所引原文；同一文件有多处引文时，可在阅读器逐处切换。有推理前提时，可展开并跳转到该前提。待核事项可以没有引文，但须说明缺什么材料或条件，不以无关引文凑数。这些摘要、分类、归属和状态均由 Agent 生成，不是逐字原文或法律认证；前提检查只能约束 Agent 已声明的依赖，仍可能遗漏前提或推断错误。

报告中的相关经过可跳回事实时间线，并打开对应事件的核验面板；可通过“返回专题分析”回到原问题。时间线的搜索与筛选只影响阅读，不改变报告选材或分析范围。报告内混合来源事件仅展示所选材料的摘录；材料子集不继承全局问题综合文字，因为所附引文不能证明其完整审查范围。未继承不表示问题已解决，完整问题与人工记录仍在事实时间线核对和编辑。跳回全量时间线查看或修改事件，不会把范围外材料补入原报告。覆盖全部材料的专题可查看原问题，新判断仍须对应具体原文。专题的讨论与导出也遵循相同材料边界。

可通过铅笔编辑专题结论，保存后明确标为“人工修订”。首次编辑会冻结当时的完整 Agent 建议及其逐项依据；后续 Agent 新建议独立保留，可展开阅读，不覆盖人工正文或冻结基准。原保存记录保留修订前内容和依据，整体报告仅纳入当前有效范围；历史专题须单独选择导出。若冻结依据涉及本专题不能继承的全局问题，页面会提示需复核，不能以新编辑、讨论或专题导出绕过；原记录及人工依据仍保留，历史专题的单独导出也不能绕过复核；不承诺重新分析自动恢复人工正文。

解释矛盾或开放式追问可通过“询问 Agent”图标，将已保存的事件、专题、问题或引文添加到对话，检查并发送后再处理；讨论本身不启动结构化更新。相关操作集中在当前阅读或核验内容附近，以图标和悬浮说明呈现。编辑弹窗用于取消或保存修改；关闭弹窗后未提交的输入及结果未明的原请求仍可恢复，不能把刷新后的内容视为保存回执。后台任务管理的时间线通过工作区新任务更新结果。

事件按材料记载的日期浏览，保留日期精度、时区不明和区间重叠等不确定性，不把同日排列等同于确定先后。

首次尚无事件或专题时，暂不展示专题和导出入口；已有专题仍可直接查看。

可将问题标记为“已解决”或“已忽略”，也可重新打开。“已忽略”只表示暂不处理，不表示问题已经排除。

每份时间线的成果数据上限为 8 MiB，包含分析内容、依据及修订，不含原件正文。超限时本次修改不会保存，也不会自动删减历史；请缩小范围或另建独立时间线，分批提交不会扩大总容量。

### 导出报告

点击“导出报告”，选择整体报告或所需专题；每个专题独立成文，单份下载 DOCX，多份下载 ZIP。导出范围不继承搜索或页面筛选。

整体报告采用当前有效材料和未删除事件；含已移除材料或已删除事件的历史分析不混入当前整体报告，可单独选择该分析导出，保留原范围与引用并注明历史状态。

报告使用所选版本的已保存内容，逐项保留判断、依据状态、引用、限制与已声明前提，以及来源分歧、人工修订、材料覆盖和待核实信息，不额外调用模型补写。只引用某一片段时，不将同组其他摘录冒充该片段的支持。结构标签使用中文，业务内容保留原文。

同一导出窗口内可按原范围和版本重试下载；关闭后重新打开默认使用最新已保存内容。临时文件过期后需重新导出。

## 界面语言

三项功能支持中英文界面，语言偏好跨功能和工作文件夹共用，首次默认跟随浏览器。切换界面语言不会翻译材料、规则或已生成的交付物。

## 数据、隐私与版本兼容

工作数据保存在选定工作文件夹的 `minimax-for-legal/` 内，包含成果、材料副本和临时导出，与插件程序包分离。该目录使用可见名称，初始化时自带 `README.md` 说明内容与分享注意事项。整体压缩或对外分享工作文件夹时，也可能带上材料副本和内部分析；仅交付成果时，请优先导出并分享所需文件。界面语言和个人列模板独立保存、跨工作文件夹共用，清理工作成果不会清除它们。

备份或复制前，请先保存输入并关闭所有使用该文件夹的工作台与插件进程，再完整复制工作文件夹，包含 `minimax-for-legal/`。副本独立保存，后续修改互不联动。

插件不自建云端业务存储，但 Agent 分析时 Pilkod 可能将材料发送到模型服务。请遵守组织保密政策，仅处理获准使用或外发的内容。

当前开发版本不保证读取旧版数据，也不自动迁移、清空或备份。页面提示工作数据与当前版本不匹配时，重试或重启不会改变数据结构；请保留原目录和错误码，旧成果使用对应的插件版本打开，体验新版则选择新的工作文件夹，不要覆盖有价值的旧数据。临时连接失败仍可通过页面上的“重试”恢复原工作区。

## 遇到问题

保存、导入、改名或分析的结果不明时，使用页面的核对或恢复入口继续**原操作**，避免重复提交。断连时请先保留未保存输入；页面保留的文字不是完整文档备份，关闭或刷新前请确认内容已保存。

| 问题 | 可以先做什么 |
| --- | --- |
| 表格式审阅新增内容长时间显示分析中 | 任务可能在排队；有恢复提示时核对原请求，不重复配置 |
| 后台分析不可用 | 保留已有成果，反馈 Pilkod 与插件版本及错误信息 |
| 工作区尚未关联 | 若尚未发送消息，在当前会话发送任务或“打开 Pilkod For Legal”；发送后仍停留于此，可请 Agent 继续打开工作台。项目会话恢复项目文件夹中的工作，无项目会话共用用户主目录中的个人工作区 |
| 工作台断连 | 页面持续自动重试，也可点击“立即重试”。顶部显示“已停止”时，保留未保存内容后点击顶部启动按钮；插件停用时先启用。页面明确提示需要重开，或顶部运行中仍无法连接时，保留内容并关闭旧标签，再从原对话发送 `@minimax-for-legal`。刷新页面不能启动已停止的服务 |
| 列表或导入进度读取失败 | 重试读取，保留已成功解析的材料；不要重复创建成果或导入同一批文件 |
| 导入失败 / PDF 没有高亮 | 检查加密、损坏、缺页和文字层，记录错误与页码 |
| 结论与材料不符 | 核对引用、补齐材料，编辑结论或反馈后继续分析 |
| 添加到对话后没有分析 | 检查是否已发送，输入框中的草稿尚未交给 Agent |
| 没有得到导出文件 | 检查 Pilkod 或浏览器的下载提示、保存位置，必要时重试导出；发起下载不代表文件已保存 |

反馈问题请提供 Pilkod/插件版本、操作系统、复现步骤、错误及脱敏截图；文件问题附格式、页码和是否扫描件。连接异常可复制诊断信息，不要附敏感全文、个人信息或凭据。

## 如何维护此文件

本文件是随插件交付的用户手册，回答“能做什么、怎样操作、如何理解结果、遇到问题怎么办”。读者可能只持有安装包，没有源码或内部系统权限。请保留本节。

- 按用户任务说明当前可用行为，功能变化时重写对应段落，合并重复说明。
- 保留影响用户选择的限制、数据后果和恢复办法；交互细节仅在帮助找到操作或理解状态时说明。
- 不记录内部实现、设计决策、迭代进展或验收日志，不引用安装包以外的内部文档。
- 按安装包读者的实际条件核对操作和链接，普通使用不依赖源码、内部权限或开发工具；以用户能确认的结果描述成功，不把提交请求等同于处理完成。
