# 交付 DOCX

仅在用户要求导出时读取本页。沿用[工作文件夹绑定](../../../references/work-folder-binding.md)的 `workRef`。

## 先确认保存与导出入口

工作台导出提供“当前文稿”和“修订稿”，按用户意图选择。正文停输后自动保存，⌘/Ctrl + S 可立即保存；失败时保留输入并重试。只有已确认保存才能准备导出，不能凭没有失败提示推断成功。只要该文档仍有活动工作台，导出权就属于工作台，让用户在工作台导出；不关闭、刷新或绕过活动页面来跳过尚未保存的正文。

保存后会检查对应正文与名称版本的修订稿可用性；失败可重试，受限则说明具体原因。诊断只报告首先发现的限制，不是完整问题清单；仅返回可靠段落位置时引导定位，否则说明是文档级限制。

没有活动工作台时，调用前重新读取最新状态，并用 `check_document_editor_export` 检查该文档的导出条件，携带当前 `editorId`、`expectedRevision` 和 `expectedMetadataRevision`。准备导出时按用户意图明确传入 `kind`：普通导出使用 `clean`，用户要求保留修订时使用 `redline`；不传 baseline，修订比较起点固定为首次上传的原始 DOCX。

## 当前文稿与修订稿

`clean` 导出已保存的当前正文，保留人工编辑和已接受建议，包括段落、表格、图片等结构修改。存在待审核建议时必须先由用户接受或拒绝，不能临时应用、静默忽略建议或代用户决定来完成导出。

`redline` 相对首次上传文件保留文字增删的 Word Track Changes，格式和结构直接应用，拒绝全部修订不会恢复原版式。人工编辑、已接受建议和冻结快照中的待审核建议一起形成拟议目标：文字净变化标为修订，字符与段落格式、段落与表格结构、图片、页眉页脚、分页及页面版式等变化保留目标状态，不生成对应的格式或结构修订。页码、目录等域的计算结果及以对象保存的特殊符号也直接应用，不生成文字修订。待审核建议在工作台中仍保持 pending；已拒绝或已替代建议不进入结果。页眉页脚等区域整体移除属于结构变化，直接应用，其中的文字不另留修订；保留区域中的文字增删继续生成修订。不能因为格式或结构变化就要求用户改用 `clean`。

文字修改无法可靠定位或对应、完整性校验失败或超出处理上限时仍不交付文件。说明返回的简洁原因，按诊断处理后重新检查；用户可以主动选择先处理待审核建议，再导出当前文稿，但不能悄悄改用 `clean` 交付用户要求的修订稿。

`prepare_document_editor_export` 的 `revisionAuthor` 只用于 `redline`，`clean` 不传此字段。修订作者用于对外 Word 文件。工作台优先使用已保存的全局作者；尚未保存时，中文默认“审阅者”，英文默认 `Reviewer`。工作台修订稿成功导出后保存本次确认的作者（包括默认名），所有文档、工作目录及重启后继续沿用；仅编辑输入或导出失败不保存。API 省略此字段时仍使用“审阅者”。用户可显式指定个人或团队名，通过 `revisionAuthor` 传入；去除首尾空白后须为 1–80 个字符，禁止控制字符。不从账号、原文档元数据、文件名或 Agent 身份推断作者，也不把正文、理由、依据或反馈写入作者或 comments。同一次导出对人工和 Agent 的文字净修改使用同一作者，不改变正文及工作台内部的审阅身份。原文件的身份元数据继续净化，仅放行本次明确选择的修订作者。

修订只表达原始上传文件到拟议目标的文字净变化；中间建议、接受动作和人工覆盖从工作台历史读取，不能声称它们仍在外部 DOCX 的接受记录中。程序化检查不等于 Microsoft Word 原生兼容性验证，未实际执行的 Word 操作不能报告为已验证。

## 冻结计划与交付

调用 `prepare_document_editor_export` 时使用唯一 `idempotencyKey`，同时携带已读取的 `expectedRevision` 和 `expectedMetadataRevision`（来自 `get_document_editor.metadata.metadataRevision`），服务端同事务冻结正文、名称和修订作者。改名不改变正文 revision；名称冲突时重新读取后建立新请求。旧请求重试始终保留原 kind、metadataRevision、幂等键、文件名和修订作者，不能改写原导出意图；缓存过期后的重建也使用原作者，之后保存的新全局作者不得改写原计划。改用另一个作者须建立新的导出请求，不能用新作者重放旧幂等键。

准备成功后再调用 `export_document_editor_docx` 获取冻结 revision 的短期资源。相同逻辑请求响应不确定时，保持全部参数和同一个幂等键重试；过期也用该冻结计划重新准备。宿主安全传输上限内会附资源链接；超限时 `export` 不含资源 URI 而是 `delivery: "workbench"`，只会提示用户从文档工作台下载，重复准备不会缩小文件。获取链接或发起下载都不等于用户已经保存文件；导出也不会自动接受或拒绝工作台中的建议。
