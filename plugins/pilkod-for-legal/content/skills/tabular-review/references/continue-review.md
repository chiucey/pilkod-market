# 继续已有审阅

本页用于用户在聊天中明确委托的续审。工作台确认的分析由原生后台执行器处理，其不可用、失败或尚无结果都不构成主 Agent 接管的委托；已被后台执行占用的范围不重复派发。用户自行发送的讨论引用仍按只读讨论处理，不转换为写入授权。保留交接中的原 workRef、source 与 reviewId，先核对绑定，不另选目录或猜测同名审阅。

## 收到新增列或文件的 requestId

UI 中的新增内容此时可能只是预览，正式审阅还没有这些列、文档或 Cell。请求以插件业务数据保存；不要从预览或提示文本另建一份配置。

用户明确委托主会话处理、且未被后台执行占用时，用 `get_review_change_request` 携带 reviewId、requestId 读取本次请求，核对其中的新增范围：

- pending：用 `accept_review_change_request` 接收原请求。插件在同一事务提交正式结构与对应工作项；无须再用 `enqueue_review_work` 创建这些文件或列。
- accepted：复用 request.receipt，不重复新增。接收回执只说明结构已提交，完成情况仍须查询业务 Cell。
- cancelled：停止处理，不能绕过撤回而重新建列、导入或接收另一请求。

接收后固定 receipt.workItemIds，只处理其中仍有效的未完成目标；空数组表示本次结构变更没有分析目标，不改为查询全表。接收结果不明时读取原请求，或用相同 reviewId/requestId 重试；不生成新请求代替。若依赖配置已改变或服务明确拒绝，说明阻碍，保留用户的原配置供重新确认，不自行扩展范围或覆盖当前修改。

接单后按 [后台分析交接](dispatch.md) 一次提交原 receipt.workItemIds。插件核对固定范围并按文档调度；不要逐文档派发 Host task，不需要为交接读取整表 Cell。

## 收到已保存工作项或用户直接提出的续审要求

列编辑、反馈和重新分析使用已有工作项流程。请求携带 reviewId、workItemIds 时，读取指定审阅并核对这些工作项，只处理仍有效的未完成目标；已完成、已移除或被取代的目标不重建。未限定工作项且用户要求“继续所有待处理项”时，以本次请求中已有的待办为范围。仅存在待办或暂存请求，不构成开始分析的委托。

已知本次 workItemIds 时按 [后台分析交接](dispatch.md) 交给插件原生执行器。主 Agent 查询原请求的实际状态，不重复派发相同目标；新增列、反馈和重新分析只提交本次工作项。文档版本与上下文能否复用、未完成范围的有限重试及任务包回收均由执行器维护。后台失败时报告回执，不静默转为脚本、Host task 或主 Agent 代写。

尚未产出结果或遇到处理阻碍时，保留正式结构与已经保存的结果，说明未完成范围和具体阻碍，不把尚无结果描述为分析失败，也不自动删除文件或列。用户反馈通过 `enqueue_review_work` 创建重新分析目标；重新分析、提交反馈或修改列要求会使受影响结果的原人工核验失效。锁定结果不可编辑或重析，列更新会跳过这些结果；收到锁定拒绝时说明并停止该格，不自行解锁或换路径写入。重新分析、重试、反馈及列要求更新在新结果被接受后替换目标格的人工修正；尚未接受新结果时，排队、失败或取消保留原结果。已接受的新结果即使仍待补证，也不会因后续失败或取消而回退。历史修改保留在审阅记录中。沿回执限定的工作项执行，不重建被跳过的目标。

用户明确给出的结论修正文案用 `update_tabular_review` 的 `correct_cell` 记录；Agent 调用该命令不标记人工核验，也不能用它绕过分析写回验证。人工修正保留原 Agent 的推理与引用，不表示这些内容支持修正后的结论；原 Agent 的低置信度不再作为当前人工结果的提示或计入统计。文件和列的移除由用户在工作台二次确认完成。

用户直接在对话中要求追加材料时，用 `enqueue_review_work` 的 add_documents 命令，传已导入的 assetVersionIds、当前 expectedRevision 与稳定幂等键；不回传 documents、正文或页码映射。该路径不重新经过 UI 暂存或 append。
