# 邮箱工作台独立插件

本项目将邮箱业务、加密存储、IMAP/SMTP、MCP和MiniApp一起打包。安装后不依赖MCode邮箱代码、Electron邮箱IPC、local-email连接器或开发仓库。

## 开发

官方源码位于 `minimax-plugin-marketplace/sources/email-workbench`，分发目录为 `plugins/email-workbench`。从源码目录构建并打包后，将 `dist/package` 的完整产物同步到分发目录，再执行仓库 validator 与 Publisher dry-run。当前测试版增加云端邮箱连接同步，必须配套启用 Connector 的 `email_workbench_credentials`。本地草稿的主密钥保存在当前用户的系统凭据库：macOS 使用钥匙串，Windows 使用 Credential Manager；包内不携带原生模块。

构建需要Node.js 22.13或更新版本，运行需要Node.js 20或更新版本；打ZIP的构建脚本需要Python 3。依赖固定在package-lock.json：

```sh
npm ci --ignore-scripts
npm run typecheck
npm test
npm run test:packaging
npm run build
npm run package
npm run check:package
```

CI 会对邮箱相关改动执行上述检查；`check:package` 将本次源码生成的 `dist/package` 与 `plugins/email-workbench` 完整逐字节比较，不排除代码或资源。同步分发目录后再运行此项。

交付包位于dist。只有打包阶段复制的manifest、Skill、MiniApp静态资源、已捆绑Node入口及许可证进入ZIP；源代码、测试、node_modules及用户数据不随包分发。

## 首次使用

安装不会自动弹出邮箱连接页，这是现有通用插件接口的边界。打开无账号工作台自动进入统一连接表单，或在会话中引用插件发起同一连接流程。授权码由 MiniApp 表单交给插件 Node 验证，经加密工具通道写入现有 Connector 凭据库，按 MCode 账号恢复。授权码不再写入新版的本地业务库。

用户主动切换的具体邮箱即默认邮箱，每次保存到云端连接配置。Agent单封指定其他邮箱、打开旧草稿不改变默认。

连接表单“自动获取授权码”会将邮箱地址、已确认的服务商、官方邮箱入口和当前连接操作交给同插件的 `email-account-setup` skill。请求不包含表单里的授权码、发信授权码或其他草稿内容。当前宿主只提供 `miniapp.message.append`：用户在宿主确认追加后，还需在会话输入框发送，Agent 才开始 computer use / browser use；没有 bridge 的独立浏览器显示明确提示，保留手动填写和官方教程。插件不绕过宿主调用私有发送接口。

Agent 打开官方邮箱，用户自行登录和完成短信/扫码验证，随后 Agent 获取并回填原表单，最后由用户验证并连接。自动获取过程中浏览器工具可能看到新生成的授权码，不能沿用“授权码从不经过助手”的承诺；凭据仍不经过聊天追加或 MCP 参数传输。地址、服务商已改变或表单已取消时停止回填。未知服务商、疑似后缀拼错、当前不支持的 OAuth/Bridge 账号不启动获取。此按钮不授权发送邮件。

发送默认由用户在 MiniApp 核对后点击“发送”。用户明确选择会话审阅时，单封可在完整固定 review 展示后，凭新确认调用共享批准工具；批量仍在 MiniApp 确认。会话仍在运行时可查询结果；已经结束的会话不能被插件自动唤醒。

本次标准客户端验收基线为 macOS Apple Silicon `3.0.73-test.8`。完整流程使用已有通用 MiniApp、managed MCP、`open.path` 和回会话输入桥接，不需要邮箱专用宿主补丁。已检查的旧 `3.0.70-test.29447` 只有基础 MiniApp 承载，缺少定向打开和回会话能力，不能作为完整流程验收基线。1.2.7 增加 Windows 凭据适配；Windows 真机验证使用下述显式 smoke 入口，验证结果须单独记录，不能把模拟测试当作真机验收。Linux 凭据适配暂未提供，会明确拒绝连接，不会降级为明文密钥文件。

## 界面语言

工作台提供简体中文与英文，覆盖连接和授权、邮件列表与阅读、写信和格式菜单、草稿与恢复、单封与批量确认、名单导入、附件/PDF、账号与签名、本地空间及错误反馈。时间展示沿用共享时间组件并传入当前语言。服务商预设使用已有的中英文连接说明。

左下角“界面语言”可以选择跟随浏览器、简体中文或 English。未手动选择时按浏览器语言检测；目前 MiniApp 没有已确认的宿主语言通知接口，因此不承诺跟随宿主设置实时变化。手动选择仅写浏览器的非敏感偏好，在当前工作台 origin 内记住；运行端口变化时重新按浏览器语言选择。切换前使用现有未保存编辑保护，连接或清除弹窗打开时不切换；保存偏好成功后重载。

`i18n.js` 与 `messages.en.js` 使用明确的 UI 文案入口，静态 HTML 仅在启动、填入业务数据之前翻译一次。用户邮件、主题、姓名、签名、CSV 列名和文件名不会被整页扫描替换。中文模板字段继续兼容，并提供 `name` / `email` 字段。清除本机数据的确认文案可以翻译，服务端确认 token 和所有错误码保持不变。

## 刷新与查询状态

切换列表先切换标题并显示加载反馈；超过 50 ms 的列表读取在后台继续，不占用全局编辑/提交锁。每次列表加载绑定独立的请求代次与取消信号，导航、账号切换和页面销毁后，旧的结果与错误不能覆盖当前列表。短时间反复聚焦窗口不重复同步账号；超过 30 秒后才允许后台同步，用户主动刷新仍立即读取最新配置。

账号、偏好与历史草稿并行读取。Node 只合并同时进行的云端配置读取，不缓存完成后的凭据新鲜度；写入和实际 IMAP/SMTP 操作形成隔离边界。每次实际协议操作仍重新校验云端身份、连接版本及撤销状态，失败继续拒绝执行，SMTP 结果不明不自动重发。`get_message`、`list_messages`、`list_folders` 三个纯读取工具由 `accountForTransport` 完成这次新鲜校验，不再在工具入口串行重复同步；其他工具及写操作仍保留入口检查。

工作台顶部刷新按钮从账号同步开始显示“刷新中…”，持续到当前查询的真实请求结束；处理中不重复发起刷新，结束后显示“刷新完成”，悬停状态可查看最近刷新时间。请求失败会显示“刷新未完成，可重试”，并保留邮箱查询的错误说明与重试入口。

慢查询超过短暂交互锁后，仍可切换邮箱、文件夹和筛选条件；同一查询范围刷新时，已载入邮件可以继续阅读。切换范围会取消旧查询，迟到结果不能覆盖新页面或结束新查询的刷新状态。

邮件正文使用独立的有界内存缓存：页面保留最近 12 封、最多约 4 MiB、60 秒有效，按账号、文件夹、UIDVALIDITY 和 UID 隔离。重复打开及同一封邮件的并发读取复用结果。列表空闲 500 ms 后预加载前 3 封，打开正文后准备后 2 封及前 1 封；每轮最多 3 封、合计 512 KiB，只读取已知不超过 256 KiB 的邮件，串行执行。悬停或键盘聚焦 300 ms 后仍支持单封意图预取。用户发起操作、离开收件箱、打开写信窗口或页面不可见时停止继续排队，当前选择优先。预取不标已读、不展示正文、不下载外部图片。实际打开并渲染正文成功后才同步已读标记。主动刷新、账号连接变化、身份失效、移动邮件与页面离开会清理缓存；迟到结果不能覆盖新的选择。

页面放弃正文请求时，取消信号传到插件内的 IMAP 读取：排队中的只读请求不再执行，正在执行的只读请求关闭其占用的连接，让新选择继续。取消仅适用于页面 `get_message`；发送、标记、移动等写操作和 MCP 调用不随页面断开取消或重试。新读取仍需完成服务商连接与认证，取消不承诺消除网络耗时。

Node 复用解析后的 MIME 内容（最多 8 封、16 MiB、60 秒），减少长正文分页和附件读取时重复下载、解析整封邮件。缓存键包含连接版本和凭据指纹；每次实际读取仍重新校验云端身份，并在邮箱锁内核对 UIDVALIDITY、邮件存在性和最新标记。缓存不落盘，账号失效及服务退出时清理。首次读取未预取的大邮件仍受 IMAP 下载与解析耗时影响；内存缓存不等于离线邮箱同步。该策略参考 [TanStack Query 的缓存与意图预取模式](https://tanstack.com/query/latest/docs/framework/react/guides/prefetching)，未引入新的前端请求框架。

## 数据与凭证

只使用 Host 提供的 `context.dataDir`，在 `owners/<云端身份范围的 SHA-256>` 下隔离各登录账号的本地数据。系统凭证库只保存本地草稿库的随机主密钥，`vault.json` 保存非秘密初始化标识；macOS 使用固定 `/usr/bin/security`；Windows 使用系统目录中的 Windows PowerShell 5.1 调用 `CredReadW` / `CredWriteW` / `CredDeleteW`，以 `CRED_TYPE_GENERIC` 保存原始 32 字节密钥。凭据按插件与 vault keyId 隔离，`CRED_PERSIST_LOCAL_MACHINE` 仅供同一 Windows 用户在本机跨登录使用，不漫游。主密钥只经标准输入/输出管道传递，由固定 C# 入口直接读取、解析和写出，不绑定到会记录参数值的 PowerShell cmdlet；PowerShell 参数只有固定程序，不加载 profile、不修改执行策略或审计设置。`mailbox.enc` 是业务检查点，`state-journal` 按事务记录变化实体，附件独立加密；每 128 个事务或 8 MiB 日志在下次提交前压缩。云端模式下本地 journal 只存公开账号配置，不接受授权码记录，连接时从 Node 内存中的最新云端配置按账号取凭据。

云端配置仅包含邮箱 UUID、地址、显示名称、IMAP/SMTP 连接参数、授权码、连接版本和默认邮箱，上限 4096 UTF-8 字节。草稿、签名、附件、工作标记、批次和发送记录仍在本机。使用现有 Host Connector list/call，不读取宿主登录 token、不修改 MCode。云端已有的认证和静态加密被复用，新增的 X25519 + AES-GCM 封装防止普通工具通道出现凭据明文；不宣称强于现有按用户/provider 隔离的插件身份认证。

连接成功验证后才按 expectedVersion 保存云端。冲突、断网或丢失响应不会自动重写配置；保留页面输入，刷新核对后重试。每次真实 IMAP/SMTP 操作前刷新配置，失效/身份变化停止使用旧连接池。SMTP 前的凭据失败退回草稿重新审核，SMTP 提交后的不确定结果仍禁止自动重发。

本地事务同时持久化草稿、批次和附件引用；提交结果不确定时封锁后续写入，重开后核对磁盘状态，不自动重发邮件。日志或检查点验证失败会保留原文件并停止启动；当前仍不提供任意文件损坏的自动局部恢复。缺密钥、文件损坏或拒绝授权时不会明文降级、换key或自动清空数据。主密钥永久丢失无法通过重新连接远端邮箱恢复本机草稿。

用户交给Agent分析的附件会在dataDir/exports生成临时明文副本，这不属于加密附件库。副本24小时过期；运行期间每5分钟及下次启动时清理过期文件。导出接口不接受任意目标路径。

“邮箱设置 → 本机空间与维护 → 重置与清除”提供“清除本机邮箱数据”，失钥或解锁失败时也可进入同一流程。输入完整确认短语后，才删除当前登录账号的本机草稿、发送记录、附件、临时导出和本机加密密钥；云端邮箱连接、其他账号和远端邮件不受影响，本地删除不可恢复。重新打开可恢复云端连接，不能恢复已清除的本机草稿。它与“断开单个邮箱”“清理闲置附件”不同，Agent MCP 采用同一作用范围和精确确认短语；须先展示影响并取得明确授权，脏页面阻止操作。仍有邮箱操作或投递进行时会拒绝清理；清理中断后保留状态，只能显式重试，不自动创建新邮箱库。元信息损坏且无法确定对应凭证时拒绝猜测删除。

新版目录按后端认证得到的用户与业务域隔离。旧版根目录完整保留，本期不迁移旧本地凭据或草稿，也不自动把它们归给新登录账号；旧用户需重新连接邮箱。新版同账号换设备恢复邮箱连接及默认邮箱，不恢复本机草稿。

## Windows 凭据与 1.2.6 升级恢复

1.2.6 在 Windows 上会于首次凭据读取时失败。升级后，`initializing / prepared` 状态使用原 vaultId/keyId 继续初始化；仅当未提交任何邮箱数据且系统确认凭据不存在时创建密钥。已存在的数据若失钥、损坏或无法访问，仍停止打开，不生成替代密钥。

旧版清除失败留下 `vault-clearing.json` 时，界面显示“重试清除”。用户重新进入清除确认流程后，适配器把 Windows `ERROR_NOT_FOUND` 视为幂等删除成功，完成原清除事务，再允许重新初始化。启动、状态查询和重试解锁都不会自动删除数据或移除清除标记；拒绝删除和系统错误仍保留标记与原文件。

Windows PowerShell 或 Credential Manager 被系统策略禁用时，明确返回不可用；不修改系统策略或降级到明文文件。网络登录会话可能没有凭据集，因此真机 smoke 应在与 Desktop 相同的交互式 Windows 用户下运行：

```powershell
$env:EMAIL_WINDOWS_CREDENTIAL_SMOKE = '1'
npm test -- test/credential-system-smoke.test.ts test/windows-vault-system-smoke.test.ts test/windows-credential-audit.test.ts
Remove-Item Env:EMAIL_WINDOWS_CREDENTIAL_SMOKE
```

这些测试只访问随机 UUID 命名的临时测试凭据，并在清理阶段删除；覆盖不存在、二进制密钥、覆盖写入、跨 helper 读取、删除和重复删除。`windows-vault-system-smoke` 还用真实 Windows 凭据与临时加密存储覆盖 1.2.6 的 prepared/clear-pending 升级、密文草稿重开、失钥保护和失败后重试；仅邮件传输和刻意注入的删除拒绝使用模拟实现。`windows-credential-audit` 使用合成密钥、真实 WinCred 和带阳性对照的参数绑定 trace，检查密钥不进入 PowerShell cmdlet 参数日志；它不读取真实 4103 事件或企业日志平台。完成上述检查后仍应在 Windows Desktop 验证插件安装、首次打开、重启解锁与清除后重建。

Windows 真机发现原有目录 `fsync` 返回 `EPERM`，即使系统凭据正常也会阻断邮箱存储。原子写入仍先同步临时文件再 rename；发布后 Windows 以可写句柄同步目标文件，POSIX 继续同步父目录。同步错误继续上抛，journal 提交结果不确定时仍封锁后续写入。此处验证的是正常运行与进程重开，不是硬件断电保证。依据：[Microsoft 文件缓存与元数据](https://learn.microsoft.com/en-us/windows/win32/fileio/file-caching)、[FlushFileBuffers 写权限要求](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers)。详细结果见仓库 `docs/email-workbench-windows-validation-2026-10-19.md`。

实现依据：[Windows CREDENTIALW](https://learn.microsoft.com/en-us/windows/win32/api/wincred/ns-wincred-credentialw)、[CredWriteW](https://learn.microsoft.com/en-us/windows/win32/api/wincred/nf-wincred-credwritew)、[Windows PowerShell 启动参数](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_powershell_exe?view=powershell-5.1)。

## 模拟验收

```sh
node scripts/build-mock.mjs
```

生成独立email-workbench-plugin-mock包，与生产验收包隔离。仅模拟包包含固定假凭证库与模拟邮件服务；不会连接真实IMAP/SMTP或发送邮件。它使用相同UI、HTTP、MCP与邮箱核心。模拟通过不能替代真实邮箱认证或实际Agent打开流程的验证。

2026-09-24 用户已确认真实流程和自动获取授权码验收通过。2026-10-19 在 Windows Desktop 又验证了真实飞书 IMAP 读取、SMTP 认证、生产 Host Connector 配置恢复和本地加密草稿重开；没有发送邮件，详见仓库验收报告。实测发现服务商 STATUS 未读总数与 FETCH 标记矛盾时，工作台会隐藏不可信的总数，保留已加载邮件的实际未读数；不把分页数量冒充文件夹总数。

平台实测、未覆盖项和截图由独立验收报告记录。本项目不自动合入或发布市场。

## 新版交互与共享状态

顶部是唯一常驻账号切换入口。搜索仅在当前邮箱、当前文件夹匹配主题或正文；空扫描窗口可继续，失败保留已有结果并标记不完整。在工作台成功打开完整正文后同步已读；焦点变化、单独的图片加载和 MCP 读取不改已读状态。同一账号的IMAP操作串行复用连接，不同账号可并行；空闲60秒关闭，断开或重连账号时失效旧连接。网络失败只返回结果，不自动重放读取、标记或移动操作。

收信使用脚本禁用的 sandbox 文档。主页面 CSP 不放宽；经白名单校验的颜色、字体、表格和间距在阅读文档内重建。CID 与外图走校验/代理并自动加载，失败可逐图重试，切换时取消请求、回收资源。

MCP 修改页面草稿遵循 get_ui_context → flush → ACK → 最新 revision 的 CAS 保存 → 页面刷新。ACK 后有短暂编辑锁，用户可以撤回协作许可后继续手动编辑。离线、上传中或无效地址保留输入/恢复副本并阻止覆盖。

逐人名单统一用结构化行，保留来源行、自定义 fields 和逐人附件。CSV/表格/逐行邮箱先预览再加入；重复地址、坏地址和变量缺失阻止整批生成。准备使用持久 requestId，响应丢失先核对原请求。

本地模拟测试覆盖同账号多客户端恢复、不同账号隔离、断网、版本冲突、丢失保存响应、清除本机数据仍保留云端连接和 SMTP 前失败。Connector 仓库含真实 Node 客户端与 Go Handler 的 loopback 互通测试。测试环境部署和标准客户端真实登录链路尚需部署后验证，本地测试不等于已经上线。插件先装而后端未启用时明确显示未同步，不静默降级成本地授权码存储。

## 工作台视觉规范

Client 是独立 HTML 页面，不直接继承宿主 Tailwind、React 基础组件或字体偏好。`miniapp/client/theme.css` 以 agent-archon `389bef923d2f` 的 `packages/ui/src/configs/tailwind/colorPlugin.ts` 为来源，集中映射工作台所需的语义颜色；浅色、深色跟随 `prefers-color-scheme`。产品选择器只消费已有 `--mcode-*` 变量，不在组件中另配颜色。文字采用 Desktop 标准档的 12/13/14/16px 辅助、小字、正文和标题层级；宿主四档字号和独立主题偏好尚无 Client bridge，不能宣称已联动。来信正文仍使用隔离文档，不套用工作台文字层级。

图标来自同版本 `packages/ui/src/assets/icons/` 中由 `sync-figma-icons` 生成并从 `assets/index.ts` 导出的官方组件。`mcode-icons.js` 仅把已有 SVG 元素树转换为静态 DOM 描述，不修改路径，不增加 React 依赖；`icon.js` 只读取此受信任资源，不解析来信 HTML。除导航图标外，阅读和写信工具栏复用 Bold / Italic / Link / Image / Archive / Folder / Delete / Info / Download / Edit / Revert / Redo / Star / Starred / ArrowDown16 等官方图标；图标按钮保留无障碍名称与悬停说明。后续更新应从官方生成组件重新导出，不手改几何或引入第三方图标。

布局分隔使用 0.5px，表单控件保留 1px 边框；窄侧面板继续采用列表与详情切换。刷新中只显示按钮进度，保留屏幕阅读器播报；结果显示在按钮下方。状态栏允许长错误换行，窄面板列表拥有独立滚动区。

## 邮件工作区交互

收件列表持续显示“全部 / 未读 / 星标”快捷筛选，选择邮件后仍可切换筛选；切换会清除旧范围的批量选择，在工作台成功打开完整正文后自动同步为已读；同步失败保留未读并提供重试，正文加载失败或快速切换产生的过期响应不改变状态。未读以列表左侧蓝点与加粗文字显示；待处理工作状态单独放在主题下方，收件列表不重复展示已检查，工作视图和邮件详情保留完整状态。两类状态分别保存。移动邮件沿用原有目标文件夹弹窗。

写信窗口固定标题和保存／发送区，中间表单、正文与附件共用滚动区，避免低高度窗口把操作按钮推出视口。窄窗口将发件说明与抄送／密送入口换行。格式、筛选及次要操作菜单使用浏览器顶层浮层，随窗口边界翻转、限高并支持滚动，避免被正文容器裁切；不支持 Popover API 时回退为展开式菜单。Escape 优先关闭菜单并将焦点还给入口。

写信窗口将发件说明、附件大小限制和次要操作收进各自入口；附件数量与文件列表单独显示。原邮件引用默认折叠，展开可编辑；折叠只影响显示，完整引用、嵌套引用和正文图片引用仍参与草稿保存和发送。离开未保存的单封邮件时可保存并关闭；保存失败、结果待核实或上传未完成时保留窗口与内容。批量准备等页面离开时只提供继续编辑或放弃，不能套用单封保存。

批量准备依次展示名单、邮件内容、逐人预览。步骤切换保留输入；名单或模板改变会使原预览失效，须再次核对。逐人预览左侧选择收件人和勾选发送范围，右侧只展示当前收件人的最终主题、正文和附件；字段差异默认折叠。保存仍只创建草稿，进入固定清单确认后才允许投递。发送记录将状态紧随主题，服务器反馈、邮件编号和服务商副本核验合并在默认折叠的“发送技术详情”中；结果不确定的提醒保持可见，不提供自动重发。

### 完整页面与窄窗口

邮箱设置分为常用、签名、连接：常用与签名保留各自保存入口，连接页只管理授权与断开；切换标签保留未保存输入。签名、服务器参数和本机空间沿用相同语义颜色与控件状态。连接表单固定标题与底部验证区，中间内容独立滚动，认证失败保留可修正的输入。让助手协助获取授权码会把请求追加到会话输入框，由用户发送后才开始协助。

编辑器“更多格式”按文字与段落、表格、编辑分组；不适用的表格命令及撤销/重做禁用，链接支持取消与 Escape。菜单在视口和弹窗范围内定位，内容超过可用高度时纵向滚动。空结果提供清除筛选，未选中的阅读区随当前列表视图和初次加载/失败状态变化；已有打开的邮件不被刷新空态替换。批量准备进入下一步后清除上一阶段的错误反馈。单封确认已接受、后台仍等待投递时锁定重复发送与编辑，保留查询状态入口。批量发送期间列表与详情同步展示状态和已接受数量；全部收件人均被接受时不重复列出地址，部分接受时保留明细。

邮箱切换使用紧凑的账号按钮，菜单展示各邮箱名称与地址，并保留添加邮箱入口；默认邮箱保存成功后才完成切换。无连接、无本地历史时展示独立的首次连接页。多选区用全选复选框、数量、标记菜单和移动按钮组织，保留快捷筛选与原移动弹窗。阅读附件采用文件类型、大小和就近操作的紧凑列表。图片加载失败时仅替换工作台生成的提示与重试控件，来信正文排版保持原样；控件样式内联进入禁用脚本的正文 iframe，原 CSP 和图片代理限制不变。

### 阅读状态同步

打开邮件并显示正文后，界面立即更新已读标记，后台同步 IMAP；图片下载、解码或失败重试不阻塞已读。正文读取失败或显示前已切走的邮件保持原状态；仅预加载不会标记已读。同步失败恢复最近确认的状态并提供重试，重新打开同一封邮件复用正在进行的同步。未读筛选中的行在同步成功后移除，避免失败时丢失原列表条目。

### 阅读与操作反馈

邮件正文可见后立即更新本地已读状态，图片加载不阻塞；IMAP 同步失败时恢复未读并提示。草稿列表通过 `list_drafts` 返回的 `to` 显示收件人，未提交的草稿隐藏发送状态查询。单封与批量统一显示“已提交邮件服务器”，不将 SMTP 接受解释为送达。批量准备区独立滚动，底部导航和状态栏保留各自空间；语言选择在独立菜单中展开。
