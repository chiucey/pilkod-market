---
name: scroll-world-local
description: 构建“滚动控制视频时间轴”的沉浸式品牌或产品落地页。用户提供完整视频时，自动分析内容、提取关键帧、提出章节分段并把视频映射到滚动；用户没有视频时，使用 MiniMax Code 的 image_synthesize 与 gen_videos 从关键场景生成连续飞行或章节式素材。适用于滚动视频官网、scrollytelling、一镜到底、镜头穿越、电影式产品页，以及“给你视频，帮我做成滚动网页”。不适用于普通静态落地页、只剪视频不做网页、已有设计稿的像素级还原。
---

# scroll-world-local

把视频当作视觉渲染层，把网页当作滚动控制器和内容层。最终体验应满足：用户滚多少，视频走多少；往回滚时状态可逆；文案、章节、CTA 与视频处于同一条时间轴。

## 运行依赖与降级

- 已有视频的自动抽帧、编码和接缝检查需要 `python3`，并需要 PATH 中的 `ffmpeg` 或当前 Python 环境可导入 `imageio-ffmpeg`。`seamdiff` 额外需要 Pillow。先检查现有能力，不要自行安装依赖。
- 从零生成前先确认 `image_synthesize` 和 `gen_videos` 可用；缺少时保留分镜、页面结构和用户已有素材流程，不要声称已生成媒体。
- `scripts/cdp_verify.js` 是可选的零 npm 依赖 CDP 检查器，需要 `node` 和一个已开启远程调试端口的 Chromium 浏览器。条件不满足时，使用宿主提供的浏览器能力完成同一组检查。
- `website_deploy` 只在工具可用且用户明确确认公开发布后调用；否则交付本地站点文件。

## 先选择工作模式

根据用户已有素材自动选择，不要让用户先理解技术架构。

### 模式 A：用户已有视频，默认优先

适用于用户直接提供完整视频、成片、动效录屏或多个视频片段。Skill 负责分析并提出分段，用户不需要自己标精确时间点。

### 模式 B：从零生成

适用于用户只有品牌、故事、风格参考或关键帧。先做滚动分镜，再用 `image_synthesize` 和 `gen_videos` 生成视频素材。

模式 B 再分为：

- **连续飞行**：镜头始终向前，使用首帧锁串联。
- **章节叙事**：每章可以独立构图，使用遮挡、色块、静帧或 DOM 排版连接，适合编辑式品牌故事。

## 用户需要提供什么

最低输入：

- 品牌或产品是什么。
- 想让用户理解的核心故事。
- 一段已有视频，或一句视觉风格描述。
- 最终 CTA。

可选输入：

- 关键帧图片、指定时间点或章节顺序。
- Logo、产品图、字体、颜色和参考网站。
- 哪些人物、产品外观或文字绝对不能改变。

能从素材和上下文推断的内容不要重复询问。用户只提供视频时，先自动分析并给出一版分段提案；只有存在会明显改变结果的歧义时，才集中确认一次。

## 交付结构

```text
work/
├── analysis/          # 视频元数据、联系表、候选关键帧
├── storyboard.md      # 滚动分镜与时间轴
├── raw/               # 原始或生成的视频
├── frames/            # 首尾帧、poster、验缝帧
└── qa/                # 桌面/移动端/接缝验证
site/
├── index.html
├── scrub-engine.js
└── assets/{vid,img}/
```

所有中间产物和最终站点都写入当前任务工作区。调用生成工具时使用该工作区内可解析的输出路径；每次生成后检查真实文件是否存在，不把工具返回的 saved 数量当作落盘证明。

## Step 1：建立视觉与叙事规则

在处理视频前先写一页简短规则：

- **核心母题**：贯穿所有章节的品牌对象或视觉符号。
- **颜色与材质**：3–5 个主色、主要材质、光线方向。
- **镜头语言**：推进、横移、俯冲、静止或混合。
- **转场语法**：只选择 2–4 种与内容有关的转场。
- **节奏**：明确哪些章节运动，哪些章节停下来让用户阅读。

动画应服务于内容。不要因为工具支持某种效果就加入它。

## Step 2A：已有视频自动分析

先运行：

```bash
python3 scripts/media.py probe <input-video>
python3 scripts/media.py contact <input-video> <workspace>/work/analysis/contact.jpg 16
python3 scripts/media.py scene-detect <input-video> <workspace>/work/analysis/scenes 0.28
```

1. 读取视频时长、尺寸、帧率、编码和音轨信息。
2. 生成早/中/晚联系表，再在疑似转场附近提取更密集的候选帧。
3. 根据以下信号识别章节边界：
   - 主体、场景或背景色发生明显变化。
   - 遮挡物覆盖画面，适合隐藏切换。
   - 镜头停稳、画面留白或出现阅读窗口。
   - 动作完成、产品落定或叙事语义改变。
4. 默认提出 4–8 个章节，不按固定时长机械切割。
5. 输出滚动分镜表，并向用户集中确认一次。

连续飞行视频可能没有明显硬切，`scene-detect` 返回空结果并不表示视频不可分段；此时以联系表中的语义变化、动作落点和阅读窗口为主。

滚动分镜表至少包含：

| 字段 | 说明 |
|---|---|
| id | 章节标识 |
| source_range | 原视频起止时间 |
| scroll_range | 页面滚动区间 |
| focal_point | 桌面和移动端的视觉焦点 |
| motion | 播放、减速、停帧或倒放 |
| overlay | DOM 文案、按钮和出现时机 |
| transition | 进入与离开方式 |
| preload | 何时开始加载素材 |

视频时间不必与滚动线性对应。重要画面可以延长滚动区间或停帧，快速过渡可以压缩。

默认保留用户的完整源视频，通过 `source_range` 映射不同章节，不为“分段显示”而重复切割和编码。只有当单文件过大、移动端需要独立素材或章节预加载明显更高效时，才输出物理分段视频，并保留原文件不变。

## Step 2B：从零生成滚动分镜

先为每章定义三张概念帧：

- **进入帧**：承接上一章。
- **核心帧**：本章最重要的品牌画面。
- **离开帧**：为下一章提供遮挡、门、洞口、主体特写或其他过渡入口。

再生成场景静图。逐章复用统一的风格描述，但不要只依赖文字保持一致；同时固定主体、材质、镜头视角、光源和调色板。

```text
<style bible>
SCENE: <本章主体与动作>
COMPOSITION: <构图、焦点、留白、镜头方向>
CONTINUITY: <必须延续的主体、材质和光线>
EXIT: <离开帧需要形成的转场入口>
```

关键帧不是必需输入，但当产品外观、人物或最终落点必须准确时，应建议用户提供。

## Step 3B：生成视频素材

### 连续飞行

第一段使用首张静图作为首帧。之后每段的首帧使用上一段视频的真实末帧：

```text
leg0 first frame = still_scene0
leg1 first frame = leg0 real last frame
leg2 first frame = leg1 real last frame
```

`gen_videos` 只能锁定一端时，首帧锁只证明接缝连续，不能证明视频抵达了目标场景。因此每段生成后都要同时检查：

1. 新首帧是否与上一段末帧一致。
2. 末帧是否接近下一章的目标构图。
3. 主体、运动方向和视觉风格是否仍然正确。

如果末帧没有形成下一章入口，缩短镜头任务、调整提示词或重生当前段，不要把漂移继续传给后续所有段。

### 章节叙事

各章可以独立生成。使用以下方式隐藏不可避免的不连续：

- 主体或布料遮满画面。
- 门、窗口、洞口或产品特写。
- 单色页面、静帧和 DOM 排版作为呼吸段。
- 运动方向一致的 match cut。

不要把“无剪辑”当成质量目标。叙事清楚、转场有动机、用户能阅读，比强行伪装一镜到底更重要。

## Step 4：编码与素材策略

- 使用适合 seek 的短 GOP、恒定帧率、`+faststart` 和无音轨网页版本。
- 为每章提供 poster。
- 默认只预加载当前章和下一章；不要无条件把所有长视频 fetch 成 blob 占满内存。
- 生产版本至少准备桌面和移动端构图策略。移动端可以使用独立视频、重新裁切或静态降级。
- 页面切到后台时停止不必要的更新，恢复时重新同步滚动进度与视频时间。

帧锁模式继续使用 `scripts/media.py seamdiff` 验证编码接缝。该指标只证明像素接缝，不代替叙事和构图验收。

## Step 5：组装滚动时间轴

页面配置至少包含：

```js
{
  id,
  source,
  scrollStart,
  scrollEnd,
  videoStart,
  videoEnd,
  holdStart,
  holdEnd,
  overlayEnter,
  overlayExit,
  poster,
  preload
}
```

引擎应支持：

- 滚动进度映射到视频时间。
- 平滑但不过度滞后的 seek。
- 正向和反向滚动。
- 播放区间与停帧区间。
- DOM 文案和 CTA 的显隐。
- 视频未就绪、加载失败和 poster 降级。
- `prefers-reduced-motion` 静态体验。

不要把 `scrub-engine.js` 视为永远不可修改的黑盒。保留稳定核心，但让时间轴、预加载和降级策略可配置。

## Step 6：浏览器验证

本地验证至少覆盖：

1. 首屏无需等待全部视频即可看到有效内容。
2. 每个章节中点与边界前后都显示正确画面和文案。
3. 从顶部滚到底部，再从底部滚回顶部，状态可逆。
4. 快速滚动不会出现长时间黑帧、错误章节或按钮残留。
5. 桌面端和移动端主体没有被错误裁掉。
6. 慢网或视频加载失败时仍有 poster、文案和 CTA。
7. reduced-motion 模式不依赖视频 scrub 才能理解内容。

固定的五张截图只适合冒烟检查。接缝验证应在真实章节边界前后分别取样，而不是假设页面 45% 就是接缝。

## Step 7：部署

部署会产生公开链接。发布前告诉用户并确认。部署后检查：

- `index.html`、引擎、视频和 poster 均返回 200。
- 线上首屏、一个中段边界和最终 CTA 可用。
- 线上素材路径与本地配置一致。

## 完成标准

- 用户确认过滚动分镜，或明确授权直接执行。
- 视频、文案和 CTA 使用同一条章节时间轴。
- 正向、反向和快速滚动均验证。
- 帧锁项目通过像素接缝检查，同时通过人工叙事检查。
- 有移动端与 reduced-motion 策略。
- 没有把未生成、未验证或未部署的能力描述成已完成。
