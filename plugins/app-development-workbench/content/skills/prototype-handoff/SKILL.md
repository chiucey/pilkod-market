# 原型到前后端实施契约


读取 [交付契约](../../references/delivery-contract.md)、当前原型和适用规则。先确认真正被选定的版本；保留未选页面为待定，不默认最新文件就是确认基线。

## 逐页提取
为每页建立一行：页面 ID、原型入口、入口/返回、数据字段、主次动作、系统能力、空/加载/失败状态、持久化与恢复。区分原型示例与真实业务事实；原型中的评分、订阅权益或测试账号不能直接写进生产业务。

## 拆出共用约定
- 视觉：Foundation Token、基础组件及语义变体；列出锁定数值与可调整项，不把行业配色变成插件默认。
- 状态：谁拥有、谁读取、谁写入，导航与弹层如何表达，取消或切账号如何处理。
- API：方法、路径、鉴权、输入/返回/错误、分页、版本冲突和幂等需求。以实际后端能力核对，缺接口就明确补齐计划。
- 数据：记录归属、稳定 ID、时间语义、上传资源引用、删除范围与跨页联动。
- 系统：权限、登录、文件选择、相机、深链、快捷指令及最低 OS，标明设备验证要求。

接口约定可使用项目已有 OpenAPI/schema。原型与现有 API 冲突时列出具体差异和选项，不能私自把原型缩成现有接口的样子或伪造后端字段。

## 实施顺序
先用一条有业务意义的闭环串通 UI → API → 存储 → 读回，再扩展其余页面。前端与后端共享同一契约版本；变更字段同步更新双方。未明确要求并行 Agent 时不自行创建多个 Agent。

## 验收定义
逐页视觉对照与业务链路分开：相同视口和状态下对照截图；业务另验登录、提交、保存、读取与重启恢复。写明 Mock、真实网络、模拟器和实体设备各自负责的检查。

交付一份可直接驱动 ios-feature-build / backend-service-build 的实施材料，包含差异表、顺序、具体检查点和未决问题。用户只要求交接文档时不自动改业务代码。
