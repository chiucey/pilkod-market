# 构建 App 后端服务


先读 [后端实施](../../references/backend-workflow.md)、[项目规则](../../references/project-rules.md) 和接口契约。识别运行入口、配置加载、数据库版本、已有迁移、外部 Provider 和线上/本地区别；不默认改框架或数据库。

## 由闭环建立边界
选一个真实用户任务串通客户端请求、身份、输入校验、业务条件、外部依赖、存储及读回。路由负责协议和输入，service 负责业务与用户归属，provider 负责外部系统；用项目现有惯例实现，不强制层数。

先明确每个资源的 owner、稳定 ID、版本和删除范围。用户 A 不能读写用户 B 的对象；外部图片 key 或记录 ID 不是授权。密码/令牌不写客户端或产物，示例配置只列变量名与用途。

## 共用能力
重复上传、模型调用、输出校验和错误追踪集中复用；领域任务保留自己的提示词、schema、转换和执行次序。不要把所有场景塞进大量布尔参数的巨型执行器。

模型成功返回还需解析、归一化与业务校验。记录可脱敏关联的 requestId、任务版本和供应商响应标识，避免输出原始密钥或完整敏感用户内容。是否自动重试依据幂等性和业务要求，不能默认无限重试收费请求。

## 失败、竞态和持久化
检查上传后 AI/DB 失败、取消、重复提交、版本冲突、旧请求覆盖、进程重启。新数据提交前保留旧资源；清理失败记录并按既有机制补偿，不覆盖原业务错误；已成功提交不因非关键清理失败假报业务失败。

数据库迁移写明适用版本、备份与回滚，破坏性迁移等待明确授权。同步接口不足以支持长任务恢复时提出具体方案，不把现有同步调用描述为已有任务队列。

## 验证与运行
用隔离测试库和明确 fixture 验证契约、归属、错误/回滚及数据重读。替身测试与真实 AI/存储/登录分开；涉及收费或真实数据的验证需符合本轮已有授权。

启动服务前识别端口和进程，复用正确实例或只停止已确认属于本任务的残留。验证 health 与 readiness 的含义，创建记录后读回，再在允许重启的环境验证恢复。部署严格按已授权环境执行，提供版本、检查、回滚和运行日志。

交付可运行命令、配置说明、API 差异、测试与真实服务边界；交由 app-integration-delivery 从原生界面验证完整链路。
