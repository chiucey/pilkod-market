# SwiftUI 组件与规则复用


读取 [共享组件规则](../../references/design-system.md) 和项目现行规范。先建立受影响页面、重复结构、状态和调用方清单；不从某个页面开始逐页美化。

## 从现状到共享边界
1. 搜索 Token、卡片、按钮、Header、Tab、输入框与状态组件。已有基础组件不足时增加语义变体，不创建 New/Custom/V2 副本。
2. 建立“现有实现 → 基础组件 → 语义变体 → 所有调用方”映射。布局强绑定的一次性业务组合可以保留，品牌外观和交互状态下沉。
3. Foundation 只提供颜色、字体、间距、圆角、阴影与动效值；共享组件负责结构和状态。业务调用方接收 primary/secondary/selected 等角色，不传任意 RGB 或圆角。
4. 先修改 Token 和基础组件，再迁移调用方，最后删除已无引用的旧实现。保留用户已有改动；不把历史资料当作可删除代码。

## 视图与状态
将有独立职责、状态或预览价值的区域提取为 View 类型，传最小数据/Binding/动作。复杂按钮逻辑、任务和数据变换移到有名称的方法或服务。选好所有权再决定 Observable/Environment，不盲目取消已有 ViewModel。

维持语义稳定的视图身份，减少无必要的根节点替换；真正互斥的登录/空态等分支可以保留。不要用 opacity 隐藏仍响应操作或被辅助功能读取的旧界面。列表 ID 由数据身份决定，不能每次 render 生成随机值。

## 复用验收
搜索业务文件中的硬编码颜色、私有渐变、重复圆角/阴影和样式链，逐项判断语义色例外。建立当前未提交 diff 快照，临时改一个共享主题值和一个基础组件表面，实际观察所有使用场景是否同步，再只恢复自己的探针改动并核对。

如果全局外观还必须改两个以上业务页面才能一致，应修正组件边界。覆盖默认、按下、选中、禁用、加载和错误状态，检查动态字体与点击区域。交付复用映射、运行证据与未迁移项，创建共享文件本身不算复用成立。
