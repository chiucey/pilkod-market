# 共享视觉与复用验证

## 分层与边界

Foundation 是颜色、字体、间距、圆角、阴影和动效数值的唯一来源。通用组件是卡片、按钮、Header、Tab、输入框、标签及状态视图的结构来源。业务页面负责业务内容布局与绑定。

颜色角色表达结构、强调、承载、文字层级和真实语义状态；品牌取值从当前项目读取，不内置固定紫色。锁定全局背景时使用唯一共享背景，组件改造不能改其颜色、位置、透明度或覆盖范围。标题、图标和按钮遵循统一层级，一页保持清晰最高焦点。

组件用少量 enum 语义变体和内容插槽扩展。不能给页面暴露无限颜色/圆角/阴影参数，也不能将所有行为堆成十几个布尔值。普通卡片只有一个基础实现，页面专用副本需要先证明不可组合。

## 迁移顺序

1. 搜索硬编码、页面私有渐变、重复容器和状态外观，列出原实现与调用方。
2. 确定现有 Token 是否能表达需求；确需新增时说明语义和使用范围。
3. 完善共享组件，覆盖默认/按下/选中/禁用/加载/错误以及必要辅助功能。
4. 批量替换调用方，保持本轮范围外的导航、接口与数据流。
5. 根据引用删除被替代实现；不能保留两套都在生效的主题。
6. 再搜索业务目录 Color(red:、十六进制、LinearGradient、cornerRadius、shadow；布局数值、真实语义色和一次性业务结构逐项判断，不机械清空。

## 一处修改验收

保存探针前目标文件 hash/diff，临时调整一个品牌 Token 与一个基础组件表面，实际查看所有受影响场景是否同步，不需要业务文件配合。只恢复自己的临时 patch，再核对文件与正常运行画面。用户已有改动不能用 git checkout 一并丢弃。

报告映射表、状态覆盖与证据。如果全局修改仍需逐页改外观，先修复边界，不能因组件文件存在就宣告完成。
